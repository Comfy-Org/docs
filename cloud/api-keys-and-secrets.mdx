## Overview

**API Keys & Secrets** is the Comfy Cloud settings panel where you store the provider API keys Comfy Cloud uses on your behalf. Secret values are encrypted when you save them, and the value itself is never shown again.

The panel holds two kinds of credentials:

- **Model provider credentials**: a Hugging Face or Civitai token, used to download private and gated models during import. See [Import models](/cloud/import-models) for the full import flow.
- **BYOK provider keys**: a Runway or Google Gemini key, so that partner node calls run on your own provider account. See [BYOK provider keys](#byok-provider-keys).

## Open the Secrets panel

1. Sign in to [Comfy Cloud](https://cloud.comfy.org).
2. Open the settings dialog with `Ctrl + ,` (on macOS `Cmd + ,`), or click **Settings** in the Comfy Cloud menu.
3. Select **Secrets** in the settings sidebar.

The panel appears for signed-in accounts when secrets are enabled.

![The Secrets section of the Comfy Cloud settings dialog](/images/cloud/import_model/setting_secerts-1.png)

The list shows every stored secret with its name, provider, creation date, and the date it was last used, when that information is available.

## Add a secret

<Steps>
  <Step title="Start a new secret">
    Click **Add Secret**.
  </Step>
  <Step title="Choose the provider">
    Select the provider from the **Provider** dropdown. The list is loaded from Comfy Cloud, so providers added later appear here automatically. Selecting a provider shows its own guidance, for example where to find your Runway API key or how to generate a Google Gemini key in Google AI Studio.
  </Step>
  <Step title="Choose the credential type">
    Providers that accept more than one kind of credential show a **Credential Type** selector. Most providers take a single API key as text. Some take a JSON credential instead: paste the JSON or upload the file, which must be a JSON object of up to 1 MB.
  </Step>
  <Step title="Name the secret">
    Enter a name of your choice, up to 255 characters. Names must be unique, and each provider can hold one secret.
  </Step>
  <Step title="Enter the value">
    Paste the key or credential. The value is encrypted on save and cannot be viewed again, so keep your own copy.
  </Step>
  <Step title="Save">
    Click **Save**. Comfy Cloud can use the credential immediately.
  </Step>
</Steps>

![The Add Secret dialog with name, provider, and secret value fields](/images/cloud/import_model/setting_secerts-2.png)

## Manage secrets

- **Edit**: click the edit icon on a secret to rename it or replace its value. Leaving the value blank keeps the current one, and neither the provider nor the credential type can be changed after the secret is created. To move a credential to another provider, delete the secret and add a new one.
- **Delete**: click the delete icon and confirm. Deleting a secret is permanent and cannot be undone.

## BYOK provider keys {#byok-provider-keys}

Bring your own key (BYOK) runs partner nodes on your own provider account instead of on Comfy credits.

- For partner nodes in Comfy Cloud, Comfy supports BYOK for **Runway** and **Google Gemini** today. Other providers can be added on request for Enterprise customers.
- BYOK is turned on per workspace, and partner node calls that run on your own key are billed by that provider directly instead of drawing your Comfy credits.
- To enable BYOK for a workspace, [submit an Enterprise request](https://www.comfy.org/contact).

Once BYOK is enabled for a workspace, add the provider's API key in the Secrets panel. Partner node calls for that provider in the workspace then run on your key.

## Credentials for private models

A Hugging Face or Civitai token stored in Secrets is used automatically when you import a model, which is how private and gated repositories are downloaded. The token needs read access to the repository you are importing from, and only `.safetensors` files can be imported. The step-by-step flow, the supported model folders, and the import limits are on [Import models](/cloud/import-models).

<Note>
  The Secrets panel stores credentials for third-party providers. It is separate from your Comfy API key, which authenticates calls to the Comfy Cloud API. See [Getting an API Key](/development/api-development/getting-an-api-key).
</Note>

## FAQ

<AccordionGroup>
  <Accordion title="Does using my own key still spend Comfy credits?">
    No. Partner node calls that run on your own BYOK key are billed by that provider directly, so they do not draw your Comfy credits.
  </Accordion>

  <Accordion title="Which providers can I use with BYOK?">
    For partner nodes in Comfy Cloud: Runway and Google Gemini today. Other providers can be added on request for Enterprise customers through the [Enterprise request form](https://www.comfy.org/contact).
  </Accordion>

  <Accordion title="How do I turn on BYOK for my workspace?">
    BYOK is enabled per workspace. [Submit an Enterprise request](https://www.comfy.org/contact) and we will set it up, then add your provider key in the Secrets panel.
  </Accordion>

  <Accordion title="Can I read a secret value after saving it?">
    No. Secrets are encrypted, and the stored value is never returned to the interface, so store your own copy of the key. You can replace the value at any time with **Edit**, or delete the secret and add a new one.
  </Accordion>

  <Accordion title="Why can I not add a second key for the same provider?">
    Each provider holds one secret. Add the new key by editing the existing secret for that provider, or delete it first if you want a separate entry.
  </Accordion>

  <Accordion title="Why does my credential fail to save?">
    Common causes are a missing name, a name longer than 255 characters, a name that is already in use, or a provider that already has a secret. For a JSON credential, the content must parse as a JSON object and stay within 1 MB.
  </Accordion>

  <Accordion title="My token is saved but the private model import still fails. What now?">
    Check that the token has read access to the exact repository you are importing from. A token without access to a private or gated repository cannot download it.
  </Accordion>
</AccordionGroup>
