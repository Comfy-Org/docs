## Entradas ocultas

Además de las entradas `required` y `optional`, que crean las entradas o widgets correspondientes en el lado del cliente, existen tres opciones de entrada `hidden` que permiten al nodo personalizado solicitar cierta información al servidor.

Se accede a ellas devolviendo un valor para `hidden` en el `dict` de `INPUT_TYPES`, con la firma `dict[str,str]`, que contenga uno o más de `PROMPT`, `EXTRA_PNGINFO` o `UNIQUE_ID`.

```python
@classmethod
def INPUT_TYPES(s):
    return {
        "required": {...},
        "optional": {...},
        "hidden": {
            "unique_id": "UNIQUE_ID",
            "prompt": "PROMPT", 
            "extra_pnginfo": "EXTRA_PNGINFO",
        }
    }
```

### UNIQUE_ID
`UNIQUE_ID` es el identificador único del nodo y coincide con la propiedad `id` del nodo en el lado del cliente.
Se usa comúnmente en las comunicaciones cliente-servidor (consulta [messages](/development/comfyui-server/comms_messages#getting-node-id)).

### PROMPT
`PROMPT` es el prompt completo enviado por el cliente al servidor.
Consulta [el objeto prompt](/es/custom-nodes/js/javascript_objects_and_hijacking#tipos-de-widget) para obtener una descripción completa.

### EXTRA_PNGINFO
`EXTRA_PNGINFO` es un diccionario que se copiará en los metadatos de los archivos `.png` que se guarden. Los nodos personalizados pueden almacenar información adicional en este diccionario para guardarla (o como una forma de comunicarse con un nodo posterior).

<Tip>Ten en cuenta que si Comfy se inicia con la opción `disable_metadata`, estos datos no se guardarán.</Tip>

### DYNPROMPT
`DYNPROMPT` es una instancia de `comfy_execution.graph.DynamicPrompt`. Se diferencia de `PROMPT` en que puede mutar durante el transcurso de la ejecución en respuesta a la [Node Expansion](/es/custom-nodes/backend/expansion).
<Tip>`DYNPROMPT` solo debe usarse para casos avanzados (como implementar bucles en nodos personalizados).</Tip>

## Entradas flexibles

### Tipos de datos personalizados

Si quieres pasar datos entre tus propios Nodos Personalizados, puede resultarte útil definir un tipo de datos personalizado. Esto es (casi) tan sencillo como elegir un nombre para el tipo de datos, que debe ser una cadena única en mayúsculas, como `CHEESE`.

Después puedes usar `CHEESE` en los `INPUT_TYPES` y `RETURN_TYPES` de tu nodo, y el cliente de Comfy solo permitirá que las Salidas `CHEESE` se conecten a una Entrada `CHEESE`. `CHEESE` puede ser cualquier Objeto de python.

El único punto a tener en cuenta es que, como el cliente de Comfy no conoce `CHEESE`, necesitas (a menos que definas un widget personalizado para `CHEESE`, que es un tema para otro día) forzarlo para que sea una Entrada en lugar de un widget. Esto se puede hacer con la opción `forceInput` en el diccionario de opciones de la Entrada:

```python
@classmethod
def INPUT_TYPES(s):
    return {
        "required": { "my_cheese": ("CHEESE", {"forceInput":True}) }
    }
```

### Entradas comodín

```python
@classmethod
def INPUT_TYPES(s):
    return {
        "required": { "anything": ("*",{})},
    }

@classmethod
def VALIDATE_INPUTS(s, input_types):
    return True
```

El frontend permite usar `*` para indicar que una Entrada se puede conectar a cualquier Fuente. Como el backend no lo admite oficialmente, puedes Saltar la Validación de tipos del backend si aceptas un parámetro llamado `input_types` en tu función `VALIDATE_INPUTS`. (Consulta [VALIDATE_INPUTS](./server_overview#validate_inputs) para obtener más información.)
Depende del nodo dar sentido a los datos que recibe.

### Entradas creadas dinámicamente

Si las Entradas se crean dinámicamente en el lado del cliente, no se pueden definir en el código fuente de Python.
Para acceder a estos datos necesitamos un DICCIONARIO `optional` que permita a Comfy pasar datos con nombres arbitrarios. Dado que el Servidor de Comfy

```python
class ContainsAnyDict(dict):
    def __contains__(self, key):
        return True
...

@classmethod
def INPUT_TYPES(s):
    return {
        "required": {},
        "optional": ContainsAnyDict()
    }
...

def main_method(self, **kwargs):
    # los datos de Entrada creados dinámicamente estarán en el DICCIONARIO kwargs

```
