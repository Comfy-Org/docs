## ¿Qué es un nodo personalizado?

Una de las grandes ventajas de Comfy es que su enfoque basado en nodos te permite desarrollar nuevos flujos de trabajo conectando los nodos disponibles de distintas maneras. Los nodos integrados ofrecen una amplia variedad de funciones, pero puede que necesites una característica que ningún nodo principal proporciona.

Los nodos personalizados son nodos desarrollados por la comunidad. Te permiten implementar nuevas funciones y compartirlas con toda la comunidad. Si te interesa desarrollar nodos personalizados, puedes leer más [aquí](/es/custom-nodes/overview).

## ComfyUI Manager

Aunque puedes instalar los nodos personalizados manualmente, la mayoría de la gente usa
[ComfyUI Manager](https://github.com/Comfy-Org/ComfyUI-Manager) para instalarlos. **ComfyUI Manager** se encarga de instalar,
actualizar y eliminar nodos personalizados, además de sus dependencias. Pero no forma parte
del núcleo de Comfy, así que debes instalarlo manualmente.

### Instalar ComfyUI Manager

```bash
cd ComfyUI/custom_nodes
git clone https://github.com/Comfy-Org/ComfyUI-Manager.git
```

Reinicia Comfy después.
Consulta [Instalación de ComfyUI Manager](https://github.com/Comfy-Org/ComfyUI-Manager?tab=readme-ov-file#installation) para ver los detalles o los casos especiales.

### Usar ComfyUI Manager

Para que tu nodo personalizado esté disponible a través de **ComfyUI Manager**, debes guardarlo como un repositorio Git (generalmente en `github.com`)
y luego enviar un Pull Request en el repositorio Git de **ComfyUI Manager**, en el que hayas editado `custom-node-list.json` para agregar tu nodo.
[Más detalles](https://github.com/Comfy-Org/ComfyUI-Manager?tab=readme-ov-file#how-to-register-your-custom-node-into-comfyui-manager).

Cuando un usuario instala el nodo, **ComfyUI Manager** hará lo siguiente:

<Steps>
<Step title="Clonar el repositorio">
clona el repositorio,
</Step>
<Step title="Instalar dependencias de Python">
instala las dependencias de pip que se enumeran en el repositorio del nodo personalizado en `requirements.txt` (si existe),
```
pip install -r requirements.txt
```
<Tip>Como siempre ocurre con `pip`, es posible que los requisitos de tu nodo entren en conflicto con los de otros
nodos personalizados. No hagas que tu `requirements.txt` sea más restrictivo de lo necesario.</Tip>
</Step>
<Step title="Ejecutar script de instalación">
ejecuta `install.py`, si existe en el repositorio del nodo personalizado.
<Tip>`install.py` se ejecuta desde la ruta raíz del nodo personalizado</Tip>
</Step>
</Steps>

### Archivos de ComfyUI Manager

Como se indicó antes, hay varios archivos y scripts que **ComfyUI Manager** usa para administrar el ciclo de vida de
un nodo personalizado. Todos son opcionales.

- `requirements.txt`: dependencias de Python como se mencionó antes
- `install.py`, `uninstall.py`: se ejecutan cuando instalas o desinstalas el nodo personalizado
<Tip>Los usuarios pueden simplemente eliminar el directorio, así que no puedes contar con que `uninstall.py` se ejecute</Tip>
- `disable.py`, `enable.py`: se ejecutan cuando deshabilitas o vuelves a habilitar un nodo personalizado
<Tip>`enable.py` solo se ejecuta cuando se vuelve a habilitar un nodo deshabilitado; solo debe revertir cualquier cambio hecho en `disable.py`</Tip>
<Tip>Los subdirectorios de los nodos personalizados deshabilitados llevan `.disabled` agregado a sus nombres, y Comfy ignora esos módulos</Tip>
- `node_list.json`: solo se requiere si el patrón de `NODE_CLASS_MAPPINGS` de los nodos personalizados no es convencional.

Consulta la [guía de ComfyUI Manager](https://github.com/Comfy-Org/ComfyUI-Manager?tab=readme-ov-file#custom-node-support-guide) para ver los detalles oficiales.
