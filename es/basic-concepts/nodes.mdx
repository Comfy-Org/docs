En ComfyUI, los nodos son los bloques de construcción fundamentales para ejecutar tareas. Cada nodo es un módulo construido de forma independiente, ya sea un nodo **Comfy Core** o un **nodo personalizado**, con su propia funcionalidad única. Los nodos se enlazan entre sí mediante conexiones, lo que nos permite construir funcionalidades complejas como si ensamblaras bloques LEGO.
Las combinaciones de diferentes nodos crean las posibilidades ilimitadas de ComfyUI.

![Nodo K-Sampler de Comfy Core](/images/comfy_core/sampling/k_sampler.png)

Por ejemplo, en el nodo K-Sampler, puedes ver que tiene múltiples entradas y salidas, y también incluye múltiples configuraciones de parámetros. Estos parámetros determinan la lógica de ejecución del nodo. Detrás de cada nodo hay una lógica de Python bien escrita, que te permite lograr la funcionalidad correspondiente sin tener que escribir código tú mismo.

</Note>

## Los nodos realizan operaciones

En ciencias de la computación, un **_nodo_** es un contenedor de información, que normalmente incluye instrucciones programadas para realizar alguna tarea. Los nodos casi nunca existen de forma aislada, casi siempre están conectados a otros nodos en un gráfico de red. En ComfyUI, los nodos toman la forma visual de cajas que se conectan entre sí.

Los nodos de ComfyUI suelen ser **_operadores de función_**. Esto significa que operan sobre ciertos datos para realizar una función. Una función es un proceso que acepta datos de entrada, realiza alguna operación sobre ellos y produce datos de salida. En otras palabras, los nodos hacen un trabajo y contribuyen a completar una tarea, como generar una imagen. Por eso los nodos de ComfyUI casi siempre tienen al menos una entrada o una salida, y normalmente tienen múltiples entradas y salidas.

## Diferentes estados de los nodos

![Estados de los nodos](/images/concepts/node/status.jpg)

En ComfyUI, los nodos tienen múltiples estados. Estos son algunos de los estados más comunes:

1. **Estado normal**: el estado predeterminado
2. **Estado en ejecución**: el estado de ejecución, que normalmente se muestra cuando un nodo se está ejecutando después de que inicias la ejecución del flujo de trabajo
3. **Estado de error**: error del nodo, que normalmente se muestra después de ejecutar el flujo de trabajo si hay un problema con la entrada del nodo, indicado por el marcado en rojo del nodo de entrada erróneo. Debes corregir la entrada problemática para asegurarte de que el flujo de trabajo se ejecute correctamente
4. **Estado faltante**: este estado suele aparecer después de importar flujos de trabajo, con dos posibilidades:
    - Falta un nodo nativo de Comfy Core: esto suele ocurrir porque ComfyUI se ha actualizado y estás usando una versión anterior de ComfyUI. Debes actualizar ComfyUI para resolver este problema
    - Falta un nodo personalizado: el flujo de trabajo usa nodos personalizados desarrollados por autores de terceros, pero tu versión local de ComfyUI no tiene estos nodos personalizados instalados. Puedes usar [ComfyUI Manager](/es/manager/overview) para encontrarlos e instalarlos, o seguir [Cómo instalar nodos personalizados](/es/installation/install_custom_node) para conocer otros métodos

## Conexiones entre nodos

En ComfyUI, los nodos se conectan mediante [enlaces](/es/basic-concepts/links), lo que permite que datos del mismo tipo fluyan entre distintas unidades de procesamiento para lograr el resultado final.

![Enlaces de nodos de ComfyUI](/images/concepts/node/inpaint.jpg)

Cada nodo recibe una entrada, la procesa a través de su módulo y la convierte en la salida correspondiente. Las conexiones entre distintos nodos deben cumplir con los requisitos del tipo de datos. En ComfyUI, usamos diferentes colores para distinguir los tipos de datos de los nodos. A continuación se muestran algunos tipos de datos básicos:

![Tipos de datos de nodos de ComfyUI](/images/concepts/node/data_type.jpg)

| Tipo de datos                      | Color                                                                                                              |
|------------------------------------|--------------------------------------------------------------------------------------------------------------------|
| modelo de difusión                 | lavanda                                                                                                           |
| modelo CLIP                        | amarillo                                                                                                             |
| modelo VAE                         | rosado                                                                                                               |
| acondicionamiento                  | naranja                                                                                                             |
| imagen latente                     | rosa                                                                                                               |
| imagen de píxeles                  | azul                                                                                                               |
| máscara                            | verde                                                                                                              |
| número (entero o flotante)         | verde claro                                                                                                        |
| malla                              | verde brillante                                                                                                       |

A medida que ComfyUI evoluciona, es posible que ampliemos a más tipos de datos para satisfacer las necesidades de más escenarios.

### Conectar y desconectar nodos

![Conexión de nodos de ComfyUI](/images/concepts/node/link_nodes.gif)

**Conectar**: Arrastra desde el punto de salida de un nodo hasta la entrada del mismo color en otro nodo para conectarlos
**Desconectar**: Haz clic en el punto de entrada y arrastra con el botón izquierdo del ratón para desconectar, o cancela la conexión mediante el menú del punto medio del enlace

## Menús contextuales de nodos

Los menús contextuales de nodos se dividen principalmente en dos tipos:
- El menú contextual del propio nodo
- El menú contextual de las entradas y salidas

### Menú contextual del nodo

Al hacer clic derecho sobre un nodo, puedes expandir el menú contextual correspondiente:
![Menú contextual del nodo](/images/concepts/node/context_menus_1.jpg)

En el menú contextual del botón derecho del nodo, puedes:
- Ajustar el estilo de color del nodo
- Modificar el título
- Clonar, copiar o eliminar el nodo
- Establecer el modo del nodo

En este menú, además de la configuración relacionada con la apariencia, las siguientes operaciones del menú son importantes:

- **Modo**: Establece el modo del nodo: Siempre, Nunca, Omitir

#### Modo
En cuanto a los modos, es posible que notes que actualmente ofrecemos cuatro: Siempre, Nunca, En evento y En disparador, pero en realidad solo **Siempre** y **Nunca** son efectivos. **En evento** y **En disparador** no son efectivos por ahora, ya que aún no hemos implementado esta función por completo. Además, puedes entender **Omitir** como un modo. A continuación se explica los modos disponibles:

- **Siempre**: El modo predeterminado del nodo. El nodo se ejecutará cada vez que se ejecute por primera vez o cuando cualquiera de sus entradas cambie desde la última ejecución
- **Nunca**: El nodo nunca se ejecutará bajo ninguna circunstancia, como si se hubiera eliminado. Los nodos posteriores no pueden leer ni recibir ningún dato de él
- **Omitir**: El nodo nunca se ejecutará bajo ninguna circunstancia, pero los nodos posteriores aún pueden intentar obtener datos que no han sido procesados por este nodo

A continuación se muestra una comparación entre los modos Nunca y Omitir:

![Comparación entre los modos Nunca y Omitir](/images/concepts/node/never_vs_bypass.jpg)

En este ejemplo de comparación, puedes ver que ambos flujos de trabajo aplican dos modelos LoRA de forma simultánea, con la diferencia de que un nodo `Load LoRA` está configurado en modo `Never` mientras que el otro está configurado en modo `Bypass`.
- El nodo configurado en modo `Never` hace que los nodos posteriores muestren errores, porque no reciben ningún dato de entrada
- El nodo configurado en modo `Bypass` todavía permite que los nodos posteriores reciban datos sin procesar, por lo que cargan los datos de salida del primer nodo `Load LoRA`, lo que permite que el flujo de trabajo posterior continúe ejecutándose con normalidad

## Caja de herramientas de selección de nodos

<video
  controls
  className="w-full aspect-video"
  src="/images/concepts/node/selection_toolbox.mp4"
></video>

La **Caja de herramientas de selección de nodos** es una herramienta flotante que proporciona operaciones rápidas para los nodos. Cuando seleccionas un nodo, esta aparece flotando sobre el nodo seleccionado. A través de esta caja de herramientas, puedes:
- Cambiar el color del nodo
- Establecer rápidamente el nodo en modo Omitir (no se ejecuta durante el runtime)
- Bloquear el nodo
- Eliminar el nodo

Por supuesto, estas funciones también se encuentran en el menú de clic derecho del nodo correspondiente. La caja de herramientas de selección de nodos solo proporciona una operación rápida. Si quieres desactivar esta función, puedes hacerlo en las configuraciones.

![Desactivar la caja de herramientas de selección de nodos](/images/concepts/node/setting_selection_toolbox.jpg)

## Nodos Personalizados

ComfyUI incluye muchos nodos de **Comfy Core** en la instalación base. La comunidad también mantiene un amplio catálogo de [**nodos personalizados**](https://registry.comfy.org) para flujos de trabajo especializados.

Para ver un resumen completo de cómo instalar nodos personalizados (ComfyUI Manager, clonación con Git, descarga de ZIP, dependencias y consejos de seguridad), consulta [Cómo instalar nodos personalizados](/es/installation/install_custom_node).

### ComfyUI Manager

Usa **ComfyUI Manager** para el trabajo diario con nodos personalizados: busca e instala desde el registro, actualiza o desactiva paquetes, detecta nodos faltantes en flujos de trabajo importados y administra modelos y snapshots junto con las extensiones. Las compilaciones de escritorio lo incluyen habilitado; las instalaciones portátiles y manuales pueden necesitar activarlo primero.
