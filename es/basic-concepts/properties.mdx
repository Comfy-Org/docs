## Los nodos son contenedores de propiedades

Los nodos suelen tener **_propiedades_**. También conocidas como **_parámetros_** o **_atributos_**, las propiedades de un nodo son variables que se pueden cambiar. Algunas propiedades se pueden ajustar manualmente por el usuario mediante un campo de entrada de datos llamado **_widget_**. Otras propiedades se pueden controlar automáticamente desde otros nodos conectados a la **_ranura de entrada_** o puerto de la propiedad. Normalmente, una propiedad se puede convertir de widget a entrada y viceversa, lo que permite a los usuarios controlar los valores de las propiedades de forma manual o automática.

Las propiedades pueden adoptar muchas formas y contener muchos tipos distintos de información. Por ejemplo, un nodo **Cargar punto de control** tiene una sola propiedad: la ruta de archivo del archivo de punto de control del modelo generativo. Un nodo **KSampler** tiene varias propiedades, como el número de **pasos** de muestreo, la escala **CFG**, **sampler\_name**, etc.

## Tipos de datos

La información puede presentarse de muchas formas distintas, llamadas **_tipos de datos_**. Por ejemplo, el texto alfanumérico se conoce como **_string_**, un número entero es un **_integer_** y un número con punto decimal se conoce como número de **_punto flotante_** o **_float_**. Constantemente se añaden nuevos tipos de datos a ComfyUI.

ComfyUI está escrito en el lenguaje de programación Python, que es muy permisivo con los tipos de datos. En cambio, el entorno de ComfyUI está muy **_fuertemente tipado_**. Esto significa que los distintos tipos de datos no se pueden mezclar. Por ejemplo, no podemos conectar una salida de imagen a una entrada de tipo entero. Esto es una gran ventaja para los usuarios, ya que les guía hacia una construcción correcta del flujo de trabajo y evita errores del programa.
