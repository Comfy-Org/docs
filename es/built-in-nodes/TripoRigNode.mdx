Este nodo toma un modelo 3D existente de Tripo y crea una versión con rigging de él, lo que significa que el modelo obtiene un esqueleto para poder animarlo. Proporcionas el ID de tarea del modelo al que se le aplicará rigging, eliges la versión del rig, el tipo de esqueleto, el estilo de nombres de huesos y el formato del archivo de salida; luego el nodo envía el trabajo a Tripo, espera hasta que termina y devuelve el resultado descargado.

## Entradas

| Parámetro | Descripción | Tipo de datos | Obligatorio | Rango |
|-----------|-------------|---------------|-------------|-------|
| `ID_de_tarea_del_modelo_original` | El ID de tarea del modelo 3D original al que se le aplicará rigging. Normalmente es el ID producido por un nodo anterior de generación de modelos de Tripo. | MODEL_TASK_ID | Sí | - |
| `model_version` | Versión del modelo de rigging que se va a usar. v1.0: solo personajes humanoides (bípedos), más de 90 preajustes de animación. v2.5: criaturas no humanoides (cuadrúpedos, hexápodos, octópodos, aviares, serpentinos, acuáticos). Predeterminado: `v1.0-20240301`. | COMBO | No | "v1.0-20240301"<br />"v2.5-20260210" |
| `rig_type` | Tipo de esqueleto. "auto" ejecuta primero la comprobación gratuita de rigging de Tripo y usa el tipo recomendado. Predeterminado: "auto". | COMBO | No | "auto"<br />"biped"<br />"quadruped"<br />"hexapod"<br />"octopod"<br />"avian"<br />"serpentine"<br />"aquatic" |
| `spec` | Nomenclatura de huesos: nativa de Tripo o compatible con Mixamo. Tripo no puede retargetizar sus preajustes de animación a un rig v1.0 hecho con la especificación mixamo; usa tripo para Tripo: Retarget rigged model. Predeterminado: "tripo". | COMBO | No | "tripo"<br />"mixamo" |
| `out_format` | Formato del archivo de salida; el resultado llega a la salida correspondiente. Predeterminado: "glb". | COMBO | No | "glb"<br />"fbx" |

**Nota:** La versión de modelo v1.0 (`v1.0-20240301`) solo admite esqueletos bípedos. Si se usa un `rig_type` no bípedo con esta versión, el nodo lanza un error e indica que se use `v2.5-20260210` en su lugar.

**Nota:** Cuando `rig_type` es "auto", Tripo primero comprueba si se le puede aplicar rigging al modelo y elige el tipo de esqueleto recomendado. Si Tripo informa que no se le puede aplicar rigging al modelo, el nodo falla con un error.

**Nota:** El nodo espera que Tripo devuelva un archivo GLB o FBX. Si Tripo devuelve cualquier otro tipo de archivo, el nodo lanza un error.

**Nota:** Solo se rellena la salida que coincide con `out_format`: `GLB` cuando `out_format` es "glb", y `FBX` cuando `out_format` es "fbx". La otra salida 3D está vacía.

## Salidas

| Nombre de salida | Descripción | Tipo de datos |
|------------------|-------------|---------------|
| `model_file` | El nombre del archivo de modelo con rigging generado (ID de tarea más extensión de formato). Se conserva solo por compatibilidad hacia atrás. | STRING |
| `rig task_id` | El ID de tarea para hacer seguimiento del proceso de generación de rigging. | RIG_TASK_ID |
| `GLB` | El modelo con rigging como archivo 3D GLB. Se rellena cuando `out_format` es "glb". | FILE3DGLB |
| `FBX` | El modelo con rigging como archivo 3D FBX. Se rellena cuando `out_format` es "fbx". | FILE3DFBX |
