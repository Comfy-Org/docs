El nodo **GLSL Shader** te permite escribir fragment shaders personalizados en **GLSL ES 3.00** (compatible con WebGL 2.0) para procesar imágenes directamente en la GPU. Puedes crear efectos de imagen como desenfoques, corrección de color, grano de película, resplandor y mucho más, todo a velocidad de GPU.

<Note>
El nodo GLSL Shader está actualmente marcado como **experimental**, por lo que el nodo puede actualizarse y ampliarse en futuras versiones.
</Note>

## Shader mínimo

El shader más sencillo posible: un passthrough que devuelve la imagen de entrada sin cambios:

```glsl
#version 300 es
precision highp float;

uniform sampler2D u_image0;

in vec2 v_texCoord;
layout(location = 0) out vec4 fragColor0;

void main() {
    fragColor0 = texture(u_image0, v_texCoord);
}
```

<Note>
**¿Por qué GLSL ES 3.00?** Los shaders deben ejecutarse en dos entornos: el **navegador** (mediante WebGL 2.0, que solo admite GLSL ES 3.00) para la vista previa en vivo en el frontend de ComfyUI, y el **backend de Python** (mediante OpenGL de escritorio) cuando se ejecuta el flujo de trabajo. GLSL ES 3.00 es el denominador común que funciona en ambos lugares.
</Note>

## Uniformes disponibles

ComfyUI establece estos uniformes automáticamente. No necesitas declararlos todos: declara solo los que uses.

### Imágenes

| Uniforme | Descripción | Tipo |
| --- | --- | --- |
| `u_image0` – `u_image4` | Imágenes de entrada (hasta 5). Se muestrean con `texture(u_image0, v_texCoord)`. Las imágenes son texturas float RGBA con filtrado lineal y wrapping de tipo clamp-to-edge. | `sampler2D` |

### Flotantes

| Uniforme | Descripción | Tipo |
| --- | --- | --- |
| `u_float0` – `u_float19` | Hasta 20 valores float controlados por el usuario. Se asignan desde el grupo de entradas **floats** del nodo. | `float` |

### Enteros

| Uniforme | Descripción | Tipo |
| --- | --- | --- |
| `u_int0` – `u_int19` | Hasta 20 valores enteros controlados por el usuario. Se asignan desde el grupo de entradas **ints** del nodo. | `int` |

<Note>
**Usar uniformes int como desplegables:** Los uniformes int se combinan bien con la salida de índice del nodo **Custom Combo**: los usuarios eligen una opción de un desplegable y el shader recibe el índice del elemento seleccionado.

```glsl
const int BLEND_SCREEN  = 0;
const int BLEND_OVERLAY = 1;
const int BLEND_MULTIPLY = 2;

// ...

if (u_int0 == BLEND_SCREEN) {
    // ...
}
```
</Note>

### Booleanos

| Uniforme | Descripción | Tipo |
| --- | --- | --- |
| `u_bool0` – `u_bool9` | Hasta 10 valores booleanos controlados por el usuario. Se asignan desde el grupo de entradas **bools** del nodo. | `bool` |

### Curvas (LUT 1D)

| Uniforme | Descripción | Tipo |
| --- | --- | --- |
| `u_curve0` – `u_curve3` | Hasta 4 LUT de curva editables por el usuario desde el grupo de entradas **curves**. Cada curva es una tabla de búsqueda 1D almacenada como una textura de una sola fila. | `sampler2D` |

<Note>
**Usar uniformes de curva:** Las curvas permiten a los usuarios dibujar gráficas de mapeo tonal arbitrarias en la interfaz (por ejemplo, para contraste, gamma, gradación por canal o cualquier remapeo `input → output` personalizado). Muestrea la curva usando tu valor de entrada como coordenada X; recuerda limitarlo primero a `[0, 1]`:

```glsl
float applyCurve(sampler2D curve, float value) {
    return texture(curve, vec2(clamp(value, 0.0, 1.0), 0.5)).r;
}

// Usage: remap each RGB channel through a master curve
color.r = applyCurve(u_curve0, color.r);
color.g = applyCurve(u_curve0, color.g);
color.b = applyCurve(u_curve0, color.b);
```

Usos habituales: curvas RGB maestras, curvas R/G/B por canal, remapeos basados en luminancia, gamma personalizado y cualquier efecto en el que quieras que el usuario dé forma visual a una curva de respuesta.
</Note>

### Resolución

| Uniforme | Descripción | Tipo |
| --- | --- | --- |
| `u_resolution` | Dimensiones en píxeles del framebuffer de **salida** (`width, height`). Este es el tamaño al que escribes, que puede diferir del tamaño de cualquier imagen de entrada cuando `size_mode` es `"custom"`. | `vec2` |

<Note>
**Calcular el tamaño de texel para muestrear:** No uses `1.0 / u_resolution` para avanzar un píxel en una textura de entrada. `u_resolution` es el tamaño de *salida*, que puede no coincidir con el tamaño de la entrada. En su lugar, usa `textureSize()` sobre la textura real que estás muestreando:

```glsl
vec2 texel = 1.0 / vec2(textureSize(u_image0, 0));
```

Usa `u_resolution` solo cuando necesites las dimensiones del framebuffer de salida en sí (por ejemplo, para calcular `gl_FragCoord.xy / u_resolution` y obtener UV en espacio de pantalla).
</Note>

### Multipaso

| Uniforme | Descripción | Tipo |
| --- | --- | --- |
| `u_pass` | Índice del pase actual (base 0). Solo tiene sentido cuando usas `#pragma passes`; consulta [Renderizado ping-pong multipaso](#multi-pass-ping-pong-rendering) para más detalles. | `int` |

### Salida del vertex shader

| Varying | Descripción | Tipo |
| --- | --- | --- |
| `v_texCoord` | Coordenadas de textura que van de (0,0) en la esquina inferior izquierda a (1,1) en la esquina superior derecha. | `vec2` |

## Salidas múltiples (MRT)

El nodo admite hasta **4 salidas simultáneas** usando Multiple Render Targets. Declara salidas adicionales con ubicaciones explícitas:

```glsl
#version 300 es
precision highp float;

uniform sampler2D u_image0;

in vec2 v_texCoord;
layout(location = 0) out vec4 fragColor0;
layout(location = 1) out vec4 fragColor1;
layout(location = 2) out vec4 fragColor2;
layout(location = 3) out vec4 fragColor3;

void main() {
    vec4 color = texture(u_image0, v_texCoord);
    fragColor0 = vec4(vec3(color.r), 1.0);  // Red channel
    fragColor1 = vec4(vec3(color.g), 1.0);  // Green channel
    fragColor2 = vec4(vec3(color.b), 1.0);  // Blue channel
    fragColor3 = vec4(vec3(color.a), 1.0);  // Alpha channel
}
```

Cada `fragColor` se asigna a la salida `IMAGE` correspondiente del nodo. ComfyUI detecta automáticamente qué salidas usas; las salidas sin usar serán negras.

## Renderizado ping-pong multipaso {#multi-pass-ping-pong-rendering}

Algunos efectos (como el desenfoque separable) necesitan varios pases sobre la imagen. Usa la directiva `#pragma passes N` para habilitarlo:

```glsl
#version 300 es
#pragma passes 2
precision highp float;

uniform sampler2D u_image0;
uniform float u_float0;  // Blur radius
uniform int u_pass;

in vec2 v_texCoord;
layout(location = 0) out vec4 fragColor0;

void main() {
    vec2 texel = 1.0 / vec2(textureSize(u_image0, 0));
    int radius = int(ceil(u_float0));

    // Pass 0 = horizontal blur, Pass 1 = vertical blur
    vec2 dir = (u_pass == 0) ? vec2(1.0, 0.0) : vec2(0.0, 1.0);

    vec4 color = vec4(0.0);
    float total = 0.0;

    for (int i = -radius; i <= radius; i++) {
        vec2 offset = dir * float(i) * texel;
        float w = 1.0;  // box blur weight
        color += texture(u_image0, v_texCoord + offset) * w;
        total += w;
    }

    fragColor0 = color / total;
}
```

### Cómo funciona el ping-pong

1. **Pase 0**: Lee de la entrada original `u_image0` y escribe en una textura ping-pong interna.
2. **Pases 1–N**: Lee de la *salida del pase anterior* mediante `u_image0` (el binding se intercambia automáticamente) y escribe en la otra textura ping-pong.
3. **Pase final**: Escribe en el framebuffer de salida real (`fragColor0`).

<Note>
Cuando usas multipaso con MRT (varias salidas), solo la primera salida (`fragColor0`) participa en el ping-pong. El pase final escribe todas las salidas.
</Note>

## Ejemplos

### Conversión a escala de grises

```glsl
#version 300 es
precision highp float;

uniform sampler2D u_image0;
in vec2 v_texCoord;
layout(location = 0) out vec4 fragColor0;

void main() {
    vec4 color = texture(u_image0, v_texCoord);
    float gray = dot(color.rgb, vec3(0.2126, 0.7152, 0.0722));
    fragColor0 = vec4(vec3(gray), color.a);
}
```

### Mezcla de imágenes

Mezcla dos imágenes de entrada usando un parámetro float como factor de mezcla:

```glsl
#version 300 es
precision highp float;

uniform sampler2D u_image0;
uniform sampler2D u_image1;
uniform float u_float0;  // mix factor [0.0 – 1.0]

in vec2 v_texCoord;
layout(location = 0) out vec4 fragColor0;

void main() {
    vec4 a = texture(u_image0, v_texCoord);
    vec4 b = texture(u_image1, v_texCoord);
    fragColor0 = mix(a, b, clamp(u_float0, 0.0, 1.0));
}
```

## Usar un LLM para generar shaders

Puedes usar cualquier LLM (Claude, ChatGPT, etc.) para que escriba shaders GLSL por ti. Copia el siguiente prompt y rellena el efecto que deseas:

````markdown
Write a GLSL ES 3.00 fragment shader for ComfyUI's GLSLShader node.

**Effect I want:** [DESCRIBE YOUR DESIRED EFFECT HERE]

**Requirements:**
- Must start with `#version 300 es`
- Use `precision highp float;`
- The vertex shader provides `in vec2 v_texCoord` (0–1 UV coordinates, bottom-left origin)
- Output to `layout(location = 0) out vec4 fragColor0` (RGBA)
- Additional outputs available: `fragColor1`, `fragColor2`, `fragColor3` at locations 1–3

**Template to follow (minimal passthrough shader - use this exact structure):**

```glsl
#version 300 es
precision highp float;

uniform sampler2D u_image0;

in vec2 v_texCoord;
layout(location = 0) out vec4 fragColor0;

void main() &#123;
    fragColor0 = texture(u_image0, v_texCoord);
&#125;
```

**Available uniforms (declare only what you use):**
- `uniform sampler2D u_image0;` through `u_image4` - up to 5 input images (RGBA float, linear filtering, clamp-to-edge)
- `uniform vec2 u_resolution;` - **output framebuffer** width and height in pixels. This is NOT the input texture size (they can differ when the user sets a custom output size). **To step one pixel in an input texture, use `vec2 texel = 1.0 / vec2(textureSize(u_image0, 0));` - do NOT use `1.0 / u_resolution` for this.**
- `uniform float u_float0;` through `u_float19;` - up to 20 user-controlled float parameters
- `uniform int u_int0;` through `u_int19;` - up to 20 user-controlled integer parameters. Tip: int uniforms can be wired from a **Custom Combo** node's index output, so users select from a dropdown and the shader receives the index. Use this for mode selection (e.g. blend mode, blur type). Define named constants for each option and branch on those - do NOT compare against raw integer literals. For example: `const int BLUR_GAUSSIAN = 0; const int BLUR_BOX = 1; ... if (u_int0 == BLUR_GAUSSIAN) { ... }`.
- `uniform bool u_bool0;` through `u_bool9;` - up to 10 user-controlled boolean parameters (use for feature toggles)
- `uniform sampler2D u_curve0;` through `u_curve3;` - up to 4 user-editable 1D LUT curves. Sample with `texture(u_curve0, vec2(clamp(x, 0.0, 1.0), 0.5)).r` where `x` is 0–1. Use for tone curves, remapping, etc.
- `uniform int u_pass;` - current pass index (when using multi-pass)

**Multi-pass rendering:**
- Add `#pragma passes N` on the second line to enable N passes
- On pass 0, `u_image0` is the original input; on subsequent passes it contains the previous pass output
- Use `u_pass` to vary behavior per pass (e.g., horizontal vs. vertical blur)

**Important constraints:**
- GLSL ES 3.00 only - no GLSL 1.x `varying`/`attribute`, no `gl_FragColor`
- No `#include`, no external textures, no custom vertex shader
- Document each uniform with a comment showing its purpose and expected range
````

### Ejemplo de prompt rellenado

> **Efecto que quiero:** Un efecto de aberración cromática que separa los canales RGB hacia afuera desde el centro de la imagen. u_float0 controla la intensidad del desplazamiento (0 = sin efecto, 10 = extremadamente fuerte). El desplazamiento debe escalar con la distancia desde el centro.
