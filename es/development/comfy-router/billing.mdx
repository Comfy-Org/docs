Se te cobra cuando el proveedor factura a Comfy. La misma regla se aplica a las llamadas síncronas y [en cola](/es/development/comfy-router/queue#idempotencia-y-facturación), y un [reintento](/es/development/comfy-router/errors#resultados-de-reintento) con la misma clave que reproduce un resultado no genera un segundo cargo.

## Datos de facturación de los modelos

`GET /v2/models` y la respuesta de detalle del modelo incluyen `billing.charges_on_policy_rejection`. Este campo describe un rechazo de política, no cualquier fallo ni una estimación de precio.

| Valor | Significado |
| --- | --- |
| `yes` | Un rechazo de política genera cargo. |
| `no` | Un rechazo de política no genera cargo. |
| `unknown` | Nadie ha establecido todavía el comportamiento. Trátalo como si quizá se cobrara. |

Compara estas cadenas de forma explícita: `"no"` se evalúa como verdadero en Python y JavaScript. Trata cualquier valor no reconocido como `unknown`. Una solicitud rechazada por falta de créditos reporta `insufficient_credits`.

## Conciliar los cargos

Los datos que devuelve el proveedor pueden incluir sus propias cifras de costo o uso; esas no son el cargo de Comfy. `X-Comfy-Credits-Used` solo está disponible para algunos modelos y en respuestas exitosas. Cuando Router reproduce un resultado para la misma `Idempotency-Key`, repite el encabezado original con `Idempotent-Replayed: true`. La llamada se cobra una sola vez, así que no vuelvas a contar un encabezado reproducido. Que falte el encabezado no significa que la llamada haya sido gratis. Usa el [uso y las facturas del espacio de trabajo](https://platform.comfy.org) para conciliar, y conserva el ID de solicitud cuando investigues un cargo.
