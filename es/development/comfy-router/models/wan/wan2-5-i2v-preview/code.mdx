Referencia de API de Wan 2.5 I2V Preview. Wan 2.5 imagen a video convierte un primer fotograma fijo en un video corto, con el movimiento y el desplazamiento de cámara descritos por el prompt.

**Entrada:** Imagen, Audio, Texto · **Salida:** Video + Audio

## Inicio rápido

Crea una clave en [tu espacio de trabajo de Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) y expórtala como `COMFY_API_KEY`. Los fragmentos de Python y TypeScript usan los SDK de Comfy (`pip install comfy-sdk` y `npm install @comfyorg/sdk`); el fragmento de cURL es la misma llamada sobre HTTP sin procesar.

**ID del modelo:** `wan/wan2.5-i2v-preview`

**Endpoint:** `POST https://api.comfy.org/v2/models/wan/wan2.5-i2v-preview`

El mismo cuerpo, enviado a `POST https://api.comfy.org/v2/models/wan/wan2.5-i2v-preview/requests`. El Router responde `201` con un `request_id` en cuanto se admite la ejecución, y el resultado se recopila cuando está listo, desde este proceso o desde otro. [Entrega en cola](/es/development/comfy-router/queue) repasa el estado, la cancelación y la recopilación.

<CodeGroup>
```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Lee COMFY_API_KEY del entorno.
# Cada llamada a submit() genera su propia Idempotency-Key y la reutiliza en los reintentos automáticos.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/wan2.5-i2v-preview",
            {
                "input": {
                    "prompt": "the robot lowers its raised arm and steps toward the camera, the flat orange backdrop holds steady",
                    "img_url": "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # con el ID del modelo, todo lo que necesita otro proceso

        # Consulta hasta que la solicitud se complete, esperando el Retry-After que indica el servidor.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # El payload propio del proveedor, el mismo valor que devuelve models.run().
        # Una solicitud que falló o se canceló lanza aquí el error tipado del Router.
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Lee COMFY_API_KEY del entorno.
// Cada llamada a submit() genera su propia Idempotency-Key y la reutiliza en los reintentos automáticos.
type Result = { output: { video_url: string } };
const handle = await comfy.models.submit<Result>("wan/wan2.5-i2v-preview", {
  input: {
    prompt: "the robot lowers its raised arm and steps toward the camera, the flat orange backdrop holds steady",
    img_url: "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
  },
  parameters: {
    resolution: "720P",
    duration: 5,
  },
});
console.log("requestId:", handle.requestId); // con el ID del modelo, todo lo que necesita otro proceso

// Consulta hasta que la solicitud se complete, esperando el Retry-After que indica el servidor.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// El mismo resultado que devuelve models.run(). Una solicitud que falló o se canceló rechaza aquí.
const result = await handle.get();
if (result.kind !== "json") throw new Error("expected a JSON result");

console.log("video:", result.data.output.video_url);
```

# 3. Recopila. 200 con la salida nativa del modelo, 202 con el cuerpo de estado mientras sigue en ejecución.

  -H "X-API-Key: $COMFY_API_KEY"

<ParamField body="input.img_url" type="string">
  URL de la imagen del primer fotograma o datos codificados en Base64. Requerido para los modelos wan2.5-i2v-preview y
wan2.6-i2v. Las variantes i2v de happyhorse-1.x NO toman aquí su primer fotograma:
lo toman como un elemento de medios de tipo first_frame (consulta media más abajo), y
un cuerpo img_url que funciona en wan2.6-i2v es rechazado por el proveedor en
happyhorse-1.0-i2v y happyhorse-1.1-i2v; además, las variantes wan2.7/wan3.0 también
toman sus recursos de referencia en media. Formatos de imagen: JPEG, JPG, PNG, BMP, WEBP.
Resolución: 360-2000 píxeles. Tamaño del archivo: máx. 10MB.
</ParamField>

<ParamField body="input.media" type="object[]">
  Lista de recursos de medios. Especifica los materiales de referencia (imagen, audio, video) para la
generación de video. Cada elemento contiene un campo type y un campo url. Este campo lo comparten todos los
modelos servidos desde este componente, y qué valores de type acepta un modelo dado, y
si lleva su entrada de imagen o video aquí en lugar de en img_url o
reference_video_urls, varía según el modelo. Valores de type compatibles, por modelo:
- wan2.7-i2v: first_frame, last_frame, driving_audio, first_clip. first_frame y
  last_frame: JPEG/JPG/PNG/BMP/WEBP, 240-8000 píxeles por lado, relación de aspecto entre 1:8
  y 8:1, como máximo 20MB, una URL pública o una URL data:\{MIME_type};base64,....
  driving_audio (WAV/MP3, 2-30 segundos, como máximo 15MB) y first_clip (MP4/MOV, 2-10
  segundos, 240-4096 píxeles por lado, como máximo 100MB): una URL HTTP/HTTPS pública; no se acepta una
  URL data: en línea.
- wan2.7-r2v: first_frame (opcional, máx. 1), reference_image, reference_video. Se requiere al menos
  un reference_image o reference_video, y las imágenes de referencia más
  los videos de referencia suman como máximo 5. first_frame y reference_image: JPEG/JPG/PNG/BMP/WEBP
  (sin canal alfa), 240-8000 píxeles por lado, relación de aspecto entre 1:8 y 8:1, como máximo
  20MB, una URL pública o una URL data:\{MIME_type};base64,.... reference_video: una URL
  HTTP/HTTPS pública; no se acepta una URL data: en línea.
- wan2.7-videoedit: video (exactamente 1, el clip que se edita: MP4/MOV, 2-10 segundos,
  240-4096 píxeles por lado, como máximo 100MB, una URL HTTP/HTTPS pública; no se acepta una URL data:
  en línea) más un reference_image opcional de 0 a 4 (JPEG/JPG/PNG/BMP/WEBP,
  240-8000 píxeles por lado, relación de aspecto entre 1:8 y 8:1, como máximo 20MB, una URL pública
  o una URL data:\{MIME_type};base64,...).
- wan3.0-video, wan3.0-video-prime: first_frame (máx. 1), last_frame (máx. 1),
  reference_image (máx. 10), reference_video (máx. 5 clips, duración total \<= 15s),
  reference_audio (máx. 5 clips, duración total \<= 15s), file (máx. 1, no se puede usar
  con link), link (máx. 1, no se puede usar con file). Los tipos reference_*/file/link
  y los tipos first_frame/last_frame son mutuamente excluyentes dentro de la misma solicitud. El
  orden del arreglo define el orden de referencia de los recursos en el prompt (Imagen 1, Video 1,
  Audio 1, ...). first_frame, last_frame y reference_image: JPEG/JPG/PNG/BMP/WEBP,
  240-8000 píxeles por lado, relación de aspecto como máximo 8:1, como máximo 20MB, una URL pública o una
  URL data:\{MIME_type};base64,.... reference_video, reference_audio, file y link: una
  URL HTTP/HTTPS pública; no se acepta una URL data: en línea.
- happyhorse-1.0-i2v, happyhorse-1.1-i2v: solo first_frame, exactamente 1. Estas variantes
  toman su primer fotograma AQUÍ y no en img_url. Al menos 300x300 píxeles, relación de aspecto
  entre 1:2.5 y 2.5:1, JPEG/JPG/PNG/WEBP, como máximo 20MB, una URL pública o una
  URL data:\{MIME_type};base64,....
- happyhorse-1.0-r2v, happyhorse-1.1-r2v: solo reference_image, de 1 a 9. Esta es
  la única entrada de referencia del modelo. El lado más corto debe tener al menos 400 píxeles, JPEG/JPG/PNG/WEBP,
  como máximo 20MB, una URL pública o una URL data:\{MIME_type};base64,.... reference_video
  no es un tipo de entrada para esta operación.
- happyhorse-1.0-video-edit: video (exactamente 1, el clip que se edita: MP4/MOV, 3-60
  segundos, el lado más largo como máximo 4096 píxeles, el lado más corto al menos 360 píxeles, relación
  de aspecto entre 1:2.5 y 2.5:1, como máximo 100MB, una URL HTTP/HTTPS pública; no se acepta una URL data:
  en línea) más un reference_image opcional de 0 a 5 (JPEG/JPG/PNG/WEBP, al
  menos 300x300 píxeles, relación de aspecto entre 1:2.5 y 2.5:1, como máximo 20MB, una URL pública
  o una URL data:\{MIME_type};base64,...).
- happyhorse-1.0-t2v, happyhorse-1.1-t2v, wan2.7-t2v, wan2.6-t2v, wan2.5-t2v-preview:
  operaciones de texto a video. Sus referencias asociadas no documentan ninguna entrada de medios, así que deja
  este campo sin establecer.
- wan2.5-i2v-preview, wan2.6-i2v, wan2.6-r2v: este componente no enumera ningún vocabulario
  de media para estas variantes. wan2.5-i2v-preview y wan2.6-i2v toman su primer
  fotograma en img_url; wan2.6-r2v toma sus clips de referencia en reference_video_urls.
Los conteos por modelo anteriores son las restricciones del socio, no las de este esquema: no se
declara minItems/maxItems en media, porque los tipos admisibles y sus límites
difieren según el modelo. Que el esquema acepte no implica que el proveedor acepte y, en la
otra dirección, las cifras de "como máximo 20MB" por recurso anteriores (el techo de las entradas
de imagen, las únicas entradas que pueden enviarse en línea) son el techo del socio sobre
el recurso con el que termina, y se aplican tal como están escritas cuando el recurso es una URL pública,
porque esos bytes nunca viajan a través de Comfy. Una URL data:\{MIME_type};base64,...
en línea sí viaja a través de Comfy y además se topa con un techo de transporte: el cuerpo de un
POST de Comfy Router está limitado a 100 MiB en total y se responde 413 al superarlo, y base64 infla una
carga útil en aproximadamente 4/3, así que un único recurso en línea de más de unos 75 MB se rechaza antes de
llegar a cualquiera de las reglas del socio indicadas aquí. Con ese tamaño, un único recurso en el propio
El límite de 20MB permite el envío en línea sin problemas, así que para un solo recurso lo que aplica es la regla del socio; el límite de transporte aplica cuando hay varios recursos, ya que el tope de 100 MiB de Router acota TODA la solicitud y no cada elemento. Envía como URL pública cualquier contenido que se acerque a estos límites.
