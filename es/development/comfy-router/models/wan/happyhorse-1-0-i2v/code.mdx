// Lee COMFY_API_KEY del entorno.
// Cada llamada a submit() genera su propia Idempotency-Key y la reutiliza para los reintentos automáticos.
type Result = { output: { video_url: string } };
const handle = await comfy.models.submit<Result>("wan/happyhorse-1.0-i2v", {
  input: {
    prompt: "the robot lowers its raised arm and steps toward the camera, the flat orange backdrop holds steady",
    media: [
      {
        type: "first_frame",

      },
    ],
  },
  parameters: {
    resolution: "720P",
    duration: 5,
  },
});
console.log("requestId:", handle.requestId); // con el ID del modelo, todo lo que necesita otro proceso

// Consulta hasta que la solicitud se complete, esperando el Retry-After que indica el servidor.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// El mismo resultado que devuelve models.run(). Una solicitud que falló o se canceló se rechaza aquí.
const result = await handle.get();
if (result.kind !== "json") throw new Error("expected a JSON result");

console.log("video:", result.data.output.video_url);

<ParamField body="input.media" type="object[]">
  Lista de recursos multimedia. Especifica materiales de referencia (imagen, audio,
video) para la generación de video. Cada elemento contiene un campo type y un campo url.
Este campo lo comparten todos los modelos servidos desde este componente, y qué valores
de type acepta un modelo dado (y si lleva su entrada de imagen o video aquí en lugar de

modelo:

  máximo 100MB): una URL pública HTTP/HTTPS; no se acepta una URL data: en línea.

  requiere al menos un reference_image o un reference_video, y la suma de imágenes de
  referencia y videos de referencia es como máximo 5. first_frame y reference_image:
  JPEG/JPG/PNG/BMP/WEBP (sin canal alfa), 240-8000 píxeles por lado, relación de aspecto
  entre 1:8 y 8:1, como máximo 20MB, una URL pública o una URL
  data:\{MIME_type};base64,... reference_video: una URL pública HTTP/HTTPS; no se acepta
  una URL data: en línea.
- wan2.7-videoedit: video (exactamente 1, el clip que se edita: MP4/MOV, de 2 a 10
  segundos, 240-4096 píxeles por lado, como máximo 100MB, una URL pública HTTP/HTTPS; no
  se acepta una URL data: en línea) más un reference_image opcional, de 0 a 4
  (JPEG/JPG/PNG/BMP/WEBP, 240-8000 píxeles por lado, relación de aspecto entre 1:8 y
  8:1, como máximo 20MB, una URL pública o una URL data:\{MIME_type};base64,...).
- wan3.0-video, wan3.0-video-prime: first_frame (máx. 1), last_frame (máx. 1),
  reference_image (máx. 10), reference_video (máx. 5 clips, duración total \<= 15s),
  reference_audio (máx. 5 clips, duración total \<= 15s), file (máx. 1, no se puede usar
  con link), link (máx. 1, no se puede usar con file). Los tipos reference_*/file/link y
  los tipos first_frame/last_frame son mutuamente excluyentes dentro de una misma
  solicitud. El orden del array define el orden de referencia de los recursos en el

- happyhorse-1.0-i2v, happyhorse-1.1-i2v: solo first_frame, exactamente 1. Estas
  variantes toman su primer fotograma AQUÍ y no en img_url. Al menos 300x300 píxeles,
  relación de aspecto entre 1:2.5 y 2.5:1, JPEG/JPG/PNG/WEBP, como máximo 20MB, una URL
  pública o una URL data:\{MIME_type};base64,...
- happyhorse-1.0-r2v, happyhorse-1.1-r2v: solo reference_image, de 1 a 9. Esta es la
  única entrada de referencia del modelo. El lado más corto debe medir al menos 400
  píxeles, JPEG/JPG/PNG/WEBP, como máximo 20MB, una URL pública o una URL
  data:\{MIME_type};base64,... reference_video no es un tipo de entrada para esta
  operación.
- happyhorse-1.0-video-edit: video (exactamente 1, el clip que se edita: MP4/MOV, de 3 a
  60 segundos, lado más largo como máximo 4096 píxeles, lado más corto al menos 360
  píxeles, relación de aspecto entre 1:2.5 y 2.5:1, como máximo 100MB, una URL pública
  HTTP/HTTPS; no se acepta una URL data: en línea) más un reference_image opcional, de 0
  a 5 (JPEG/JPG/PNG/BMP/WEBP, al menos 300x300 píxeles, relación de aspecto entre 1:2.5
  y 2.5:1, como máximo 20MB, una URL pública o una URL data:\{MIME_type};base64,...).
- happyhorse-1.0-t2v, happyhorse-1.1-t2v, wan2.7-t2v, wan2.6-t2v, wan2.5-t2v-preview:
operaciones de texto a video. Sus referencias del socio no documentan ninguna entrada de
medios, así que deja este campo sin definir.
- wan2.5-i2v-preview, wan2.6-i2v, wan2.6-r2v: este componente no enumera ningún
  vocabulario de medios para estas variantes. wan2.5-i2v-preview y wan2.6-i2v toman su
  primer fotograma en img_url; wan2.6-r2v toma sus clips de referencia en
  reference_video_urls. Los recuentos por modelo anteriores son restricciones del socio,
  no de este esquema: no se declara minItems/maxItems en media, porque los tipos
  admisibles y sus límites difieren según el modelo. Que el esquema acepte un valor no
  implica que el proveedor lo acepte; y, en la otra dirección, las cifras de "como
  máximo 20MB" por recurso anteriores (el techo de las entradas de imagen, las únicas
  entradas que pueden enviarse en línea) son el techo del socio sobre el recurso que
  acaba recibiendo, y se aplican tal como están escritas cuando el recurso es una URL
  pública, porque esos bytes nunca pasan por Comfy. Una URL data:\{MIME_type};base64,...
  en línea sí pasa por Comfy y también se topa con un techo de transporte: el cuerpo de
  un POST de Comfy Router está limitado a 100 MiB en total y se responde 413 por encima
  de eso, y base64 infla una carga útil en aproximadamente 4/3, así que un solo recurso
  en línea de más de unos 75 MB se rechaza antes de llegar a cualquiera de las reglas
  del socio que aparecen aquí. Con ese tamaño, un solo recurso en el propio techo de
  20MB del socio cabe en línea sin problema, así que para un solo recurso lo que obliga
  es la regla del socio; el techo de transporte obliga cuando son varios, ya que el
  límite de 100 MiB del Router acota TODA la solicitud y no cada elemento. Envía como
  URL pública cualquier cosa que se acerque a estos techos.

Para wan2.6 T2V/R2V (sin 480P):
  720P: 1280*720, 720*1280, 960*960, 1088*832, 832*1088
  1080P: 1920*1080, 1080*1920, 1440*1440, 1632*1248, 1248*1632
Cuando se envían size y resolution juntos, size selecciona el nivel facturado, y resolution debe seguir siendo un valor que este proxy acepte para el modelo. Un size de 480P devuelve 400 en todos los modelos que la descripción de resolution indica como sin 480P.
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  Si se agrega un logotipo de marca de agua; la marca de agua se ubica en la esquina inferior derecha
</ParamField>
