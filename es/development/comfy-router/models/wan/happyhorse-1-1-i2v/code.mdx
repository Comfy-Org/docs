Referencia de API para HappyHorse 1.1 I2V. HappyHorse 1.1 imagen a video anima un primer fotograma fijo y renderiza diálogo, efectos y música sincronizados en una sola pasada.

**Entrada:** Image, Text · **Salida:** Video

## Inicio rápido

Crea una clave en [tu espacio de trabajo de Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) y expórtala como `COMFY_API_KEY`. Los fragmentos de Python y TypeScript usan los SDK de Comfy (`pip install comfy-sdk` y `npm install @comfyorg/sdk`); el fragmento de cURL es la misma llamada mediante HTTP sin procesar.

**ID del modelo:** `wan/happyhorse-1.1-i2v`

**Endpoint:** `POST https://api.comfy.org/v2/models/wan/happyhorse-1.1-i2v`

Router responde `201` con un `request_id` en cuanto se admite la ejecución, y el resultado se recoge cuando está listo, desde este proceso o desde otro. import asyncio
```python Python
from comfy_sdk import AsyncComfy

# Lee COMFY_API_KEY del entorno.
# Cada llamada a submit() genera su propia Idempotency-Key y la reutiliza para los reintentos automáticos.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/happyhorse-1.1-i2v",
            {
                "input": {
                    "prompt": "the robot lowers its raised arm and steps toward the camera, the flat orange backdrop holds steady",
                    "media": [
                        {
                            "type": "first_frame",
                            "url": "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # junto con el ID del modelo, es todo lo que necesita otro proceso

        # Consulta hasta que la solicitud se complete, esperando el Retry-After que indica el servidor.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # La carga propia del proveedor, el mismo valor que devuelve models.run().
        # Una solicitud que falló o se canceló lanza aquí el error tipado de Router.
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Lee COMFY_API_KEY del entorno.
// Cada llamada a submit() genera su propia Idempotency-Key y la reutiliza para los reintentos automáticos.
type Result = { output: { video_url: string } };
const handle = await comfy.models.submit<Result>("wan/happyhorse-1.1-i2v", {
  input: {
    prompt: "the robot lowers its raised arm and steps toward the camera, the flat orange backdrop holds steady",
    media: [
      {
        type: "first_frame",
        url: "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
      },
    ],
  },
  parameters: {
    resolution: "720P",
    duration: 5,
  },
});
console.log("requestId:", handle.requestId); // junto con el ID del modelo, es todo lo que necesita otro proceso

// Consulta hasta que la solicitud se complete, esperando el Retry-After que indica el servidor.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// El mismo resultado que devuelve models.run(). Una solicitud que falló o se canceló se rechaza aquí.
const result = await handle.get();
if (result.kind !== "json") throw new Error("expected a JSON result");

console.log("video:", result.data.output.video_url);
```

<ParamField body="input.img_url" type="string">
  URL de la imagen del primer fotograma o datos codificados en Base64. Requerido para los
modelos wan2.5-i2v-preview y wan2.6-i2v. Las variantes i2v de happyhorse-1.x NO toman aquí
su primer fotograma: lo toman como un elemento de medios de tipo first_frame
(consulta media más abajo), y un cuerpo img_url que funciona en wan2.6-i2v es rechazado
por el proveedor en happyhorse-1.0-i2v y happyhorse-1.1-i2v; además, las variantes

<ParamField body="input.media" type="object[]">
  Lista de recursos de medios. Especifica los materiales de referencia (imagen, audio, video)
para la generación de video. Cada elemento contiene un campo type y un campo url. Este
campo lo comparten todos los modelos servidos desde este componente, y qué valores de type
acepta un modelo dado, y si lleva aquí su entrada de imagen o video en lugar de en img_url
o en reference_video_urls, varía según el modelo. Valores de type compatibles, por modelo:
- wan2.7-i2v: first_frame, last_frame, driving_audio, first_clip. first_frame y
  last_frame: JPEG/JPG/PNG/BMP/WEBP, 240-8000 píxeles por lado, relación de aspecto entre

  driving_audio (WAV/MP3, 2-30 segundos, como máximo 15MB) y first_clip (MP4/MOV, 2-10
  segundos, 240-4096 píxeles por lado, como máximo 100MB): una URL HTTP/HTTPS pública; no
  se acepta una URL data: en línea.
- wan2.7-r2v: first_frame (opcional, máx. 1), reference_image, reference_video. Se requiere
  al menos un reference_image o un reference_video, y las imágenes de referencia más los
  videos de referencia suman como máximo 5. first_frame y reference_image:
  JPEG/JPG/PNG/BMP/WEBP (sin canal alfa), 240-8000 píxeles por lado, relación de aspecto
  entre 1:8 y 8:1, como máximo 20MB, una URL pública o una URL data:\{MIME_type};base64,....
  reference_video: una URL HTTP/HTTPS pública; no se acepta una URL data: en línea.
- wan2.7-videoedit: video (exactamente 1, el clip que se edita: MP4/MOV, 2-10 segundos,
  240-4096 píxeles por lado, como máximo 100MB, una URL HTTP/HTTPS pública; no se acepta
  una URL data: en línea) más un reference_image opcional de 0 a 4 (JPEG/JPG/PNG/BMP/WEBP,
  240-8000 píxeles por lado, relación de aspecto entre 1:8 y 8:1, como máximo 20MB, una URL
  pública o una URL data:\{MIME_type};base64,...).
- wan3.0-video, wan3.0-video-prime: first_frame (máx. 1), last_frame (máx. 1),
  reference_image (máx. 10), reference_video (máx. 5 clips, duración total \<= 15s),
  reference_audio (máx. 5 clips, duración total \<= 15s), file (máx. 1, no se puede usar
  con link), link (máx. 1, no se puede usar con file). Los tipos reference_*/file/link y
  los tipos first_frame/last_frame son mutuamente excluyentes dentro de la misma solicitud.
  El orden del array define el orden de referencia de los recursos en el prompt (Imagen 1,
  Video 1, Audio 1, ...). first_frame, last_frame y reference_image:
  JPEG/JPG/PNG/BMP/WEBP, 240-8000 píxeles por lado, relación de aspecto como máximo 8:1,
  como máximo 20MB, una URL pública o una URL data:\{MIME_type};base64,....
  reference_video, reference_audio, file y link: una URL HTTP/HTTPS pública; no se acepta
  una URL data: en línea.
- happyhorse-1.0-i2v, happyhorse-1.1-i2v: solo first_frame, exactamente 1. Estas variantes
  toman su primer fotograma AQUÍ y no en img_url. Al menos 300x300 píxeles, relación de
  aspecto entre 1:2.5 y 2.5:1, JPEG/JPG/PNG/WEBP, como máximo 20MB, una URL pública o una
  URL data:\{MIME_type};base64,....
- happyhorse-1.0-r2v, happyhorse-1.1-r2v: solo reference_image, de 1 a 9. Esta es la única
  entrada de referencia del modelo. El lado más corto debe medir al menos 400 píxeles,
  JPEG/JPG/PNG/WEBP, como máximo 20MB, una URL pública o una URL
  data:\{MIME_type};base64,.... reference_video no es un tipo de entrada para esta
  operación.
- happyhorse-1.0-video-edit: video (exactamente 1, el clip que se edita: MP4/MOV, 3-60
  segundos, lado más largo como máximo 4096 píxeles, lado más corto al menos 360 píxeles,
  relación de aspecto entre 1:2.5 y 2.5:1, como máximo 100MB, una URL HTTP/HTTPS pública;
  no se acepta una URL data: en línea) más un reference_image opcional de 0 a 5
  (JPEG/JPG/PNG/WEBP, al menos 300x300 píxeles, relación de aspecto entre 1:2.5 y 2.5:1,
  como máximo 20MB, una URL pública o una URL data:\{MIME_type};base64,...).
- happyhorse-1.0-t2v, happyhorse-1.1-t2v, wan2.7-t2v, wan2.6-t2v, wan2.5-t2v-preview:
  operaciones de texto a video. Sus referencias asociadas no documentan ninguna entrada de
  medios, así que deja este campo sin definir.
- wan2.5-i2v-preview, wan2.6-i2v, wan2.6-r2v: este componente no enumera ningún vocabulario
  de medios para estas variantes. wan2.5-i2v-preview y wan2.6-i2v toman su primer fotograma
  en img_url; wan2.6-r2v toma sus clips de referencia en reference_video_urls.
Los recuentos por modelo anteriores son las restricciones del socio, no las de este esquema:
no se declara ningún minItems/maxItems en media, porque los tipos admisibles y sus límites
difieren según el modelo. Que el esquema lo acepte no implica que el proveedor lo acepte; y,
en la otra dirección, las cifras de “como máximo 20MB” por recurso anteriores (el techo de
las entradas de imagen, las únicas entradas que pueden enviarse en línea) son el techo del
socio sobre el recurso con el que termina, y se aplican tal como se escriben cuando el
recurso es una URL pública, porque esos bytes nunca viajan a través de Comfy. Una URL
data:\{MIME_type};base64,... en línea sí viaja a través de Comfy y también encuentra un
techo de transporte: el cuerpo de un POST de Comfy Router está limitado a 100 MiB en total
y se responde 413 al superarlo, y base64 infla una carga útil en aproximadamente 4/3, así
que un único recurso en línea por encima de unos 75 MB se rechaza antes de que se llegue a
cualquiera de las reglas del socio indicadas aquí. Con ese tamaño, un único recurso con el
propio20MB de margen permite el envío en línea sin problema, así que con un solo recurso lo que condiciona es la regla del socio;
con varios recursos condiciona el límite de transporte, ya que el tope de 100 MiB del Router limita
TODA la solicitud y no cada elemento. Envía como URL pública
cualquier cosa que se acerque a estos límites.

Para wan2.5 T2V: tamaños 480P (480*832, 832*480, 624*624), 720P y 1080P
Para wan2.6 T2V/R2V (sin 480P):
  720P: 1280*720, 720*1280, 960*960, 1088*832, 832*1088
  1080P: 1920*1080, 1080*1920, 1440*1440, 1632*1248, 1248*1632
Cuando se envían tanto el tamaño como la resolución, el tamaño selecciona el nivel facturado y la resolución aún debe ser un valor que este proxy acepte para el modelo. Un tamaño de 480P devuelve 400 en todos los modelos que la descripción de la resolución enumera como sin 480P.
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  Indica si se debe agregar un logotipo de marca de agua; la marca de agua se ubica en la esquina inferior derecha
</ParamField>
