```python Python
        # Consulta hasta que la solicitud se complete, esperando el Retry-After que indica el servidor.
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Lee COMFY_API_KEY desde el entorno.
// Cada llamada a submit() genera su propia Idempotency-Key y la reutiliza para los reintentos automáticos.
const handle = await comfy.models.submit("openai/o1", {
  input: "Reply with the single word: ok",
  max_output_tokens: 1024,
});
console.log("requestId:", handle.requestId); // junto con el ID del modelo, es todo lo que necesita otro proceso

// Consulta hasta que la solicitud se complete, esperando el Retry-After que indica el servidor.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// El mismo resultado que devuelve models.run(). Una solicitud que falló o se canceló se rechaza aquí.
const result = await handle.get();

console.log(result.data);
```

<ParamField body="stream" type="boolean">
  Declarado para que no se rechace a quien lo envíe, pero INERTE en esta superficie: Router lo FIJA en `false` antes del despacho, porque captura la respuesta del proveedor en lugar de retransmitir un `text/event-stream`, que no puede decodificar; por eso OpenAI facturaría una generación transmitida y nadie mediría su consumo. Ninguna superficie de Comfy ofrece el stream: el punto de entrada v1 `POST /proxy/openai/v1/responses` rechaza `stream: true` con un 400 y nunca reenvía la solicitud al proveedor, así que omite el campo o envía `false` en cualquiera de las dos superficies y lee la respuesta completada como un único cuerpo JSON.

Router no lo rechaza para ellos (consulta la nota de este componente sobre por qué los dos niveles comparten un esquema), así que OpenAI responde a una llamada de razonamiento que lo envíe con su propio error.

<ParamField body="tools" type="object[]">

<ParamField body="top_p" type="number">
