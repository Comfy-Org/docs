El mismo cuerpo, enviado a `POST https://api.comfy.org/v2/models/kling/kling-3.0-turbo/requests`. Router responde `201` con un `request_id` en cuanto se admite la ejecución, y el resultado se recopila cuando está listo, desde este proceso o desde otro. [Entrega en cola](/es/development/comfy-router/queue) recorre el estado, la cancelación y la recopilación.

<CodeGroup>
```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Lee COMFY_API_KEY del entorno.
# Cada llamada a submit() genera su propia Idempotency-Key y la reutiliza en los reintentos automáticos.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "kling/kling-3.0-turbo",
            {
                "prompt": "A neon-lit alley in the rain, slow dolly forward.",
                "settings": {
                    "aspect_ratio": "16:9",
                    "duration": 5,
                    "resolution": "1080p",
                },
            },
        )
        print("request_id:", handle.request_id)  # junto con el ID del modelo, es todo lo que necesita otro proceso

        # Sondea hasta que la solicitud se complete, esperando el Retry-After que indique el servidor.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # La carga útil propia del proveedor, el mismo valor que devuelve models.run().
        # Una solicitud que falló o se canceló lanza aquí el error tipado de Router.
        result = await handle.get()

    print(result)

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Lee COMFY_API_KEY del entorno.
// Cada llamada a submit() genera su propia Idempotency-Key y la reutiliza en los reintentos automáticos.
const handle = await comfy.models.submit("kling/kling-3.0-turbo", {
  prompt: "A neon-lit alley in the rain, slow dolly forward.",
  settings: {
    aspect_ratio: "16:9",
    duration: 5,
    resolution: "1080p",
  },
});
console.log("requestId:", handle.requestId); // junto con el ID del modelo, es todo lo que necesita otro proceso

// Sondea hasta que la solicitud se complete, esperando el Retry-After que indique el servidor.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// El mismo resultado que devuelve models.run(). Una solicitud que falló o se canceló se rechaza aquí.
const result = await handle.get();

console.log(result.data);
```

## Proveedores de servicio

Comfy Router sirve este modelo directamente, a menos que la solicitud indique otro proveedor. Los proveedores siguientes también lo sirven, en el mismo endpoint y con el mismo ID de modelo, y se seleccionan con el parámetro de consulta `model_provider`.

- **Comfy** (predeterminado): `POST https://api.comfy.org/v2/models/kling/kling-3.0-turbo`
- **Higgsfield**, como `higgsfield/higgsfield-kling-3-turbo`: `POST https://api.comfy.org/v2/models/kling/kling-3.0-turbo?model_provider=higgsfield`

`strict_mode` tiene el valor predeterminado false, por lo que Router traduce el cuerpo de la solicitud nativo documentado en esta página al esquema propio del proveedor y traduce la respuesta de vuelta. Consulta [`model_provider`, `strict_mode` y `fallback_provider`](/es/development/comfy-router/reference#post-v2modelsprovidermodel) en la Referencia de la API, y [Proveedores de servicio](/es/development/comfy-router/providers) para conocer todos los modelos que se enrutan de esta forma.
