Cada modelo de Router se identifica con un ID con el formato `{provider}/{model}`. Usa el catálogo para encontrar ese ID y luego llama a `POST /v2/models/{provider}/{model}`.

## Descubrir el catálogo

Lista los modelos con la misma clave API que usas para generar:

```bash
curl -H "X-API-Key: $COMFY_API_KEY" \
  "https://api.comfy.org/v2/models?limit=50"
```

Una respuesta abreviada del catálogo:

```json
{
  "data": [
    {
      "id": "bfl/flux-2-pro",
      "provider": "bfl",
      "model": "flux-2-pro",
      "billing": { "charges_on_policy_rejection": "no" }
    }
  ],
  "has_more": true,
  "next_cursor": "example-cursor",
  "limit": 50
}
```

Usa `id` en la ruta de invocación. El objeto `billing` contiene datos de facturación, no un precio. Lee [facturación por rechazo de política](/es/development/comfy-router/billing#datos-de-facturación-de-los-modelos) antes de basarte en él.

### Paginación

- Cuando `has_more` es `true`, pasa el `next_cursor` devuelto como `cursor`. Detente cuando `has_more` sea `false`, incluso si una página anterior fue más corta de lo solicitado.
- Trata los cursores como opacos. Codifica el valor para URL, por ejemplo con cURL `--get --data-urlencode "cursor=$NEXT_CURSOR"`; no calcules desplazamientos ni modifiques el cursor.
- `limit` tiene un valor predeterminado de 20 y un máximo de 100. Los valores por encima del máximo se ajustan; los valores cero y negativos seleccionan el predeterminado. La respuesta informa el límite que realmente se usó.
- Un cursor no válido devuelve `400` / `invalid_input`. No reinicia la lista de forma silenciosa.
- Un cursor puede seguir siendo válido entre actualizaciones del catálogo, pero el recorrido no es una instantánea: un modelo agregado antes de tu posición actual puede no aparecer en ese recorrido.

`503` / `service_unavailable` es temporal. Reintenta con retroceso exponencial; no lo trates como un catálogo vacío. Los métodos run del SDK llaman directamente al modelo seleccionado.

## Leer un modelo

Obtén una entrada del catálogo directamente cuando conozcas el ID del modelo:

```bash
curl -H "X-API-Key: $COMFY_API_KEY" \
  https://api.comfy.org/v2/models/bfl/flux-2-pro
```

El endpoint de detalle de modelo evita recorrer todo el catálogo. Consulta la [referencia de la API](/es/development/comfy-router/reference) para ver todos los campos de la entrada.
