<Warning>
  **Obsoleto:** La API de Cloud v1 está obsoleta en favor de [Comfy API v2](/es/api-reference/v2/overview). Sigue disponible para las integraciones existentes y para las capacidades de Cloud que v2 aún no expone, pero los endpoints y el comportamiento pueden cambiar sin previo aviso.
</Warning>

La API de Cloud v1 proporciona acceso programático a [Comfy Cloud](/es/development/deploy/cloud), el servicio administrado de Comfy para ejecutar flujos de trabajo en infraestructura en la nube.

Comfy Cloud es una aplicación con estado. Tu cuenta mantiene un estado que persiste entre tareas: créditos y nivel de suscripción, recursos subidos y salidas generadas, la cola de trabajos y el conjunto de modelos y nodos instalados. La API v1 es la superficie de toda esa aplicación, así que incluye funcionalidad que la portable [Comfy API v2](/es/api-reference/v2/overview) no admite, como la gestión de la cola, la exploración de modelos, las definiciones de nodos y los endpoints de cuenta. Usa v2 (o los SDK que la envuelven) para enviar flujos de trabajo y obtener resultados de una forma que también funcione con despliegues de Comfy API y con ComfyUI autoalojado. Usa v1 para las capacidades específicas de Cloud a su alrededor.

Para ejecutar flujos de trabajo, empieza con la [Guía de inicio rápido de Comfy Cloud](/es/development/deploy/cloud) y los [SDK de Comfy](/es/development/api-development/sdks). Los créditos y los límites de concurrencia se tratan en [Uso y límites](/es/development/deploy/cloud-usage); los ejemplos ejecutables de v1 están en la [Referencia de la API de Cloud](/es/development/cloud/api-reference). Esta página cubre la superficie específica de v1: la autenticación y los endpoints que v2 no expone.

<Note>
  **Suscripción requerida:** El acceso a la API requiere una suscripción de pago a Comfy Cloud; el nivel Gratis no lo incluye. Consulta los [planes de precios](https://www.comfy.org/cloud/pricing?utm_source=docs&utm_campaign=cloud-api).
</Note>

## Base URL

```
https://cloud.comfy.org
```

## Autenticación

Todas las solicitudes v1 requieren una clave API enviada en el encabezado `X-API-Key`:

```bash
curl -X GET "https://cloud.comfy.org/api/user" \
  -H "X-API-Key: $COMFY_CLOUD_API_KEY"
```

Consulta [Obtener una clave API](/es/development/api-development/getting-an-api-key) para ver las instrucciones sobre cómo crear y administrar claves. Una clave no válida o faltante devuelve `401`. Una clave con una suscripción inactiva devuelve `429`.

La misma clave se usa para los [Nodos asociados](/es/tutorials/partner-nodes/overview). Por HTTP la vuelves a pasar en `extra_data.api_key_comfy_org`; consulta [Usar Nodos asociados](/es/development/cloud/api-reference#using-partner-nodes) para ver ejemplos.

## Lo que los SDK aún no cubren

Los SDK cubren la ejecución de un flujo de trabajo, la obtención de los resultados y la cancelación de una tarea. El resto de las funciones de Cloud solo está disponible por HTTP, así que llama a estos endpoints directamente aunque uses un SDK para la ejecución.

| Funcionalidad | Endpoint | Referencia |
|---|---|---|
| Estado de la cola, tareas en ejecución y pendientes | `GET /api/queue` | [Gestión de la cola](/es/development/cloud/api-reference#gestion-de-la-cola) |
| Interrumpir la ejecución actual | `POST /api/interrupt` | [Gestión de la cola](/es/development/cloud/api-reference#gestion-de-la-cola) |
| Definiciones de nodos y especificaciones de entrada | `GET /api/object_info` | [Información de objetos](/es/development/cloud/api-reference#informacion-de-objetos) |
| Explorar los modelos disponibles | Endpoints de modelos | [Especificación OpenAPI](/es/development/cloud/openapi) |
| Información de la cuenta y del usuario | `GET /api/user` | [Especificación OpenAPI](/es/development/cloud/openapi) |
| Subir máscaras que hacen referencia a una imagen existente | `POST /api/upload/mask` | [Subir entradas](/es/development/cloud/api-reference#subir-entradas) |

La cancelación de una tarea está cubierta por ambas vías: los SDK cancelan una tarea para la que tienes un handle, y `POST /api/queue` cancela por ID.

## Manejo de errores

Los endpoints REST devuelven los códigos de estado HTTP estándar:

| Estado | Descripción |
|--------|-------------|
| `400` | Solicitud inválida (flujo de trabajo incorrecto, campos faltantes) |
| `401` | No autorizado (clave API inválida o faltante) |
| `402` | Créditos insuficientes |
| `429` | Suscripción inactiva |
| `500` | Error interno del servidor |

En su lugar, los SDK lanzan estas situaciones como excepciones tipadas, entre ellas `Unauthorized`, `InvalidWorkflow`, `InsufficientCredits`, `QueueFull` y `JobFailed`, y todas heredan de `ComfyError`.

Las fallas de ejecución son independientes de los errores HTTP. Consulta [Manejo de errores](/es/development/cloud/api-reference#error-handling) para conocer los valores de `exception_type` que se entregan durante la ejecución.
