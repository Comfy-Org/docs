Los [SDK de Comfy](/es/development/api-development/sdks) hablan [Comfy API v2](/es/api-reference/v2/overview). Un ComfyUI autoalojado sirve la v2 mediante [comfy-api-proxy](https://github.com/Comfy-Org/comfy-api-proxy), un pequeño servicio de código abierto que se ejecuta junto a tu instancia.

## Instalar y ejecutar

```bash
pip install comfy-api-proxy
comfy-api-proxy
```

De forma predeterminada, hace de proxy del ComfyUI en `127.0.0.1:8188` y sirve la API v2 en `127.0.0.1:8189`. Usa `--comfyui` y `--port` para cambiar cualquiera de los dos.

Ejecútalo con `--comfyui-base-dir /path/to/ComfyUI` si además quieres subir archivos de modelo a tu instalación.

## Apuntar el SDK al proxy

Establece la URL base y crea el cliente como de costumbre:

```bash
export COMFY_BASE_URL="http://127.0.0.1:8189"
```

<CodeGroup>
```python Python
from comfy_sdk import Comfy

client = Comfy()
```

```typescript TypeScript
import { Comfy } from "@comfyorg/sdk";

const client = new Comfy();
```
</CodeGroup>

Todo lo que aparece en la [guía del SDK](/es/development/api-development/sdks) funciona igual con el proxy que con Comfy Cloud.

## Autenticación

La autenticación no es requerida de forma predeterminada. Si el proxy está configurado con un token de portador estático, pasa ese token como la clave API del SDK: `Comfy(api_key="...")`.

<Warning>
  El proxy se enlaza solo a loopback de forma predeterminada. Si lo expones más allá de loopback, por ejemplo frente a un ComfyUI en una GPU alquilada, configura un token de portador o coloca un proxy inverso con autenticación delante de él.
</Warning>
