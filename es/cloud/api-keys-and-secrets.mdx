## Descripción general

**Claves de API y secretos** es el panel de ajustes de Comfy Cloud donde guardas las claves de API de proveedores que Comfy Cloud usa en tu nombre. Los valores de los secretos se cifran al guardarlos y el valor en sí nunca se vuelve a mostrar.

El panel guarda dos tipos de credenciales:

- **Credenciales de proveedores de modelos**: un token de Hugging Face o Civitai, que se usa para descargar modelos privados y con acceso restringido durante la importación. Consulta [Importar modelos](/es/cloud/import-models) para ver el flujo de importación completo.
- **Claves de proveedor BYOK**: una clave de Runway o Google Gemini, para que las llamadas de los nodos de partners se ejecuten en tu propia cuenta del proveedor. Consulta [Claves de proveedor BYOK](#byok-provider-keys).

## Abrir el panel de secretos

1. Inicia sesión en [Comfy Cloud](https://cloud.comfy.org).
2. Abre el diálogo de ajustes con `Ctrl + ,` (en macOS `Cmd + ,`), o haz clic en **Settings** en el menú de Comfy Cloud.
3. Selecciona **Secrets** en la barra lateral de ajustes.

El panel aparece para las cuentas con sesión iniciada cuando los secretos están activados.

![La sección Secrets del diálogo de ajustes de Comfy Cloud](/images/cloud/import_model/setting_secerts-1.png)

La lista muestra cada secreto guardado con su nombre, proveedor, fecha de creación y la fecha en que se usó por última vez, cuando esa información está disponible.

## Añadir un secreto

<Steps>
  <Step title="Inicia un secreto nuevo">
    Haz clic en **Add Secret**.
  </Step>
  <Step title="Elige el proveedor">
    Selecciona el proveedor en el desplegable **Provider**. La lista se carga desde Comfy Cloud, así que los proveedores añadidos más adelante aparecen aquí automáticamente. Al seleccionar un proveedor se muestra su propia guía, por ejemplo dónde encontrar tu clave de API de Runway o cómo generar una clave de Google Gemini en Google AI Studio.
  </Step>
  <Step title="Elige el tipo de credencial">
    Los proveedores que aceptan más de un tipo de credencial muestran un selector **Credential Type**. La mayoría de los proveedores toman una sola clave de API como texto. Algunos toman en cambio una credencial JSON: pega el JSON o sube el archivo, que debe ser un objeto JSON de hasta 1 MB.
  </Step>
  <Step title="Pon nombre al secreto">
    Escribe el nombre que quieras, de hasta 255 caracteres. Los nombres deben ser únicos y cada proveedor puede tener un solo secreto.
  </Step>
  <Step title="Introduce el valor">
    Pega la clave o la credencial. El valor se cifra al guardar y no se puede volver a ver, así que conserva tu propia copia.
  </Step>
  <Step title="Guarda">
    Haz clic en **Save**. Comfy Cloud puede usar la credencial de inmediato.
  </Step>
</Steps>

![El diálogo Add Secret con los campos de nombre, proveedor y valor del secreto](/images/cloud/import_model/setting_secerts-2.png)

## Gestionar secretos

- **Editar**: haz clic en el icono de edición de un secreto para cambiar su nombre o reemplazar su valor. Si dejas el valor en blanco se mantiene el actual, y ni el proveedor ni el tipo de credencial se pueden cambiar una vez creado el secreto. Para pasar una credencial a otro proveedor, elimina el secreto y añade uno nuevo.
- **Eliminar**: haz clic en el icono de eliminación y confirma. Eliminar un secreto es permanente y no se puede deshacer.

## Claves de proveedor BYOK {#byok-provider-keys}

Bring your own key (BYOK) ejecuta los nodos de partners en tu propia cuenta del proveedor en lugar de usar créditos de Comfy.

- Para los nodos de partners en Comfy Cloud, Comfy admite hoy BYOK para **Runway** y **Google Gemini**. Otros proveedores se pueden añadir a petición para clientes Enterprise.
- BYOK se activa por workspace, y las llamadas de nodos de partners que se ejecutan con tu propia clave se facturan directamente a ese proveedor en lugar de descontar tus créditos de Comfy.
- Para activar BYOK en un workspace, [envía una solicitud Enterprise](https://www.comfy.org/contact).

Una vez activado BYOK para un workspace, añade la clave de API del proveedor en el panel de secretos. Las llamadas de nodos de partners de ese proveedor en el workspace pasan entonces a usar tu clave.

## Credenciales para modelos privados

Un token de Hugging Face o Civitai guardado en secretos se usa automáticamente al importar un modelo, que es como se descargan los repositorios privados y con acceso restringido. El token necesita permiso de lectura sobre el repositorio desde el que importas, y solo se pueden importar archivos `.safetensors`. El flujo paso a paso, las carpetas de modelos admitidas y los límites de importación están en [Importar modelos](/es/cloud/import-models).

<Note>
  El panel de secretos guarda credenciales de proveedores externos. Es independiente de tu clave de API de Comfy, que autentica las llamadas a la API de Comfy Cloud. Consulta [Obtener una clave de API](/es/development/api-development/getting-an-api-key).
</Note>

## Preguntas frecuentes

<AccordionGroup>
  <Accordion title="¿Usar mi propia clave sigue gastando créditos de Comfy?">
    No. Las llamadas de nodos de partners que se ejecutan con tu propia clave BYOK se facturan directamente a ese proveedor, así que no descuentan tus créditos de Comfy.
  </Accordion>

  <Accordion title="¿Qué proveedores puedo usar con BYOK?">
    Para los nodos de partners en Comfy Cloud: Runway y Google Gemini hoy. Otros proveedores se pueden añadir a petición para clientes Enterprise a través del [formulario de solicitud Enterprise](https://www.comfy.org/contact).
  </Accordion>

  <Accordion title="¿Cómo activo BYOK en mi workspace?">
    BYOK se activa por workspace. [Envía una solicitud Enterprise](https://www.comfy.org/contact) y lo configuramos, después añade la clave de tu proveedor en el panel de secretos.
  </Accordion>

  <Accordion title="¿Puedo leer el valor de un secreto después de guardarlo?">
    No. Los secretos están cifrados y el valor almacenado nunca se devuelve a la interfaz, así que guarda tu propia copia de la clave. Puedes reemplazar el valor en cualquier momento con **Edit**, o eliminar el secreto y añadir uno nuevo.
  </Accordion>

  <Accordion title="¿Por qué no puedo añadir una segunda clave para el mismo proveedor?">
    Cada proveedor tiene un solo secreto. Añade la nueva clave editando el secreto existente de ese proveedor, o elimínalo primero si quieres una entrada aparte.
  </Accordion>

  <Accordion title="¿Por qué no se guarda mi credencial?">
    Las causas más comunes son un nombre ausente, un nombre de más de 255 caracteres, un nombre que ya está en uso o un proveedor que ya tiene un secreto. En el caso de una credencial JSON, el contenido debe ser un objeto JSON válido y no superar 1 MB.
  </Accordion>

  <Accordion title="Mi token está guardado pero la importación del modelo privado sigue fallando. ¿Qué hago?">
    Comprueba que el token tiene permiso de lectura sobre el repositorio exacto desde el que importas. Un token sin acceso a un repositorio privado o con acceso restringido no puede descargarlo.
  </Accordion>
</AccordionGroup>
