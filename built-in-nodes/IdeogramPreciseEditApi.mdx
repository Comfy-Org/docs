Edit an image guided by a text prompt with Ideogram 4.6 or 4.5 precise editing: only what the prompt asks for changes. A region edit keeps image 1 at its exact size and resolution. A whole-image edit scales image 1 down before upload when it is above the model's limit, so the result can be smaller than the input: 16.7 MP or 8192 pixels per side on 4.6, about 4 MP or 4608 pixels per side on 4.5. Image 1 is the image to edit and up to 4 further images can be connected as references. A single region of image 1 can also be edited on its own, selected by a mask or by bounding boxes, which returns the image at full size.

## Inputs

Selecting a `model` determines which inputs appear. Both models edit a region through `context_window`, but 4.6 takes its mask on `mask` while 4.5 takes it on `context_window_mask`, and 4.6 defaults to `"auto"` instead of `"none"`.

| Parameter | Description | Data Type | Required | Range |
|-----------|-------------|-----------|----------|-------|
| `context_window` | Region of image 1 to edit. `"auto"` edits the region around the mask and keeps image 1 at full size, or the whole image when no mask is connected; `"none"` edits the whole image; `"custom"` edits the region from `context_window_bboxes` and keeps image 1 at full size (default: `"auto"`). A connected `mask` is sent in all three modes, including `"none"`. | COMBO | No | `"none"`<br />`"auto"`<br />`"custom"` |
| `context_window_bboxes` | Region of image 1 to edit, for example the output of Create Bounding Boxes. Required when `context_window` is `"custom"`; not used otherwise. ### Parameter Constraints

- **Image count:** at least 1 and at most 5 images; a batched input counts once per image. When the node uses a mask, at most 4 images are accepted, that is image 1 and 3 references. On 4.6 a connected `mask` is used in every mode; on 4.5 the mask is `context_window_mask` and is used only in `"auto"`, so `"none"` and `"custom"` still accept 5 images with a mask connected.
- **Output size:** the node has no size, width or height inputs. A region edit returns the full image at the size of image 1. A whole-image edit returns the size of image 1 as uploaded: on 4.6 an image above 16.7 MP or 8192 pixels per side is scaled down first, and on 4.5 the same happens above about 4 MP or 4608 pixels per side, and its area is measured after each side is rounded up to a multiple of 32, so an image just under 4 MP, such as 2049x2047, is scaled down as well.
- **Region source size:** with a context window in use, image 1 may be up to 67,108,864 pixels in total (about 67 MP), for example 8192x8192 or 10000x5000; the limit is on the area, not on one side.
- **Region limits:** a region from `context_window_bboxes` can be up to 8192 pixels per side and about 16.7 MP on 4.6, and up to 4608 pixels per side and about 4 MP on 4.5. Boxes raise an error when the merged region falls outside image 1 or exceeds the side, area or 6:1 aspect limit of the model, so a 4096x4096 box fails on 4.5 even inside an 8192x8192 image. One box left of the image and another right of it merge into a region that spans the image, which is fine.
- **Prompt tags:** `@ImageN` is matched case-insensitively and must not exceed the number of connected images; the prompt must be non-whitespace and at most 10000 characters.
- **Upload limit:** image 1, the mask and the references together must fit in Ideogram's 50 MB upload. A 4.6 edit and a 4.5 region edit re-encode image 1 as JPEG when the files do not fit and raise an error if it still does not fit; a 4.5 whole-image edit always sends PNG and has no such fallback.
- **Content safety:** if Ideogram's content safety filter blocks the result, the node raises an error instead of returning an image.
