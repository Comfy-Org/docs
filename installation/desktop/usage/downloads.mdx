Comfy Desktop downloads the files your builds need and tracks every transfer in one place, whether it is a model the app fetches for you or a file you save yourself. When ComfyUI asks for a model that is not on disk and offers a download link, Comfy Desktop runs the transfer and saves the file in the matching model folder, so you do not have to place it by hand.

Click the **Downloads** button in the **title bar** to follow active transfers, pause or retry one, or open the folder a finished file landed in.

## What appears in the downloads list

- **Missing models**: when ComfyUI reports a missing model that has a download link, in the missing-models dialog or in the **Errors** tab of the right side panel, the download runs through Comfy Desktop. The file is saved into the matching model folder, such as `checkpoints`, `diffusion_models`, `text_encoders`, `loras`, or `vae`. Supported model file types are `.safetensors`, `.sft`, `.ckpt`, `.pth`, and `.pt`.
- **Models for apps**: when an [app](/installation/desktop/usage/apps) runs on this computer and needs a model that is not on disk, Comfy Desktop downloads it and the transfer appears in the tray.
- **Outputs from Comfy Cloud and remote builds**: when **Auto-download outputs** is on, finished outputs are saved to your output folder automatically. See [Set output options for remote and Comfy Cloud builds](/installation/desktop/usage/build-folders#set-output-options-for-remote-and-comfy-cloud-builds).
- **Files you download yourself**: assets you save from the **Assets** page. See [Download from Comfy Cloud](/installation/desktop/usage/assets#download-from-comfy-cloud).

## The Downloads tray

Click the **Downloads** button in the title bar to open the tray.

![Downloads tray opened from the title bar, numbered 1-5: 1 the model folder and file name, 2 transferred size, percentage, speed, and time left, 3 cancel, 4 View all, 5 the tray button with its count](/images/desktop/usage/comfy-desktop-downloads.png)

The button carries a badge with the number of active downloads. When nothing is downloading, it instead flags failed downloads you have not seen yet, or finished ones you have not opened.

Downloads are listed newest first, labeled with the model folder and the file name. An active row shows the transferred size and percentage, and the speed and time remaining once Comfy Desktop can estimate them. Each row offers:

- **Try again** on a failed or cancelled download.
- A folder button on a finished row opens the folder that holds the file. Its tooltip reads **Show in Finder**, **Show in Explorer**, or **Show in Folder**.
- **✕** cancels an active download and drops the partial file, or removes a finished row from the list.

**View all downloads** at the bottom of the tray opens the full downloads view, which is where you pause a transfer or resume one.

## The full downloads view

The full view keeps the download history and adds the controls that do not fit in the tray:

- Filter the list by status: **All**, **Active**, **Completed**, or **Failed**. The chips appear once more than one status has rows, and **Failed** also holds cancelled downloads.
- **Pause** an active download, and **Resume** a paused one.
- **Try again** on a failed or cancelled download.
- Open the file's folder, or remove a single row.
- **Clear finished** to remove every finished row at once.

The footer counts the active, completed, failed, and cancelled downloads in the list.

## Quitting with downloads in progress

Model downloads are resumable. If you quit Comfy Desktop while a model transfer is running, the bytes already received are kept, and on the next launch the transfer returns as a paused row in the **Downloads** tray. Open **View all downloads** to **Resume** it from where it stopped, or cancel it to drop the partial file.

Output downloads from Comfy Cloud and remote builds transfer on a separate path and do not resume after you quit.

**Quit Desktop** in the **title bar** **Menu** closes every window at once. While a window that runs ComfyUI is open, Comfy Desktop asks first, and the confirmation lists the builds and any in-progress operations it closes.

## Where downloads are saved

Model files are written to the models folder marked **Downloads** in [Desktop settings → Folders](/installation/desktop/usage/settings#storage) when the build includes the shared folders, otherwise to the build's own `models` folder. To send new downloads to another shared models folder, click **Use for downloads** on its row in the same tab. Each build can turn the shared folders off on its [Folders tab](/installation/desktop/usage/build-folders#choose-which-folders-the-build-uses).

Outputs downloaded from Comfy Cloud or a remote build go to the build's output folder, or to the shared output folder when the build uses it. A remote connection can turn automatic output downloads off with **Auto-download outputs** on its **Startup arguments** tab.

Files you download yourself from **Assets** are the exception: they go wherever you point the save dialog, so they can sit outside the build entirely.
