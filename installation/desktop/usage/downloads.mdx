Comfy Desktop downloads the models your builds need and tracks every transfer in one place. When a build asks for a model that is not on disk and ComfyUI has a download link for it, Desktop downloads it and saves the file in a model folder, so you do not place that file by hand.

Click the **Downloads** icon in the title bar to follow progress, retry a failed transfer, or open the folder a finished file landed in.

## What appears in the downloads list

- **Missing models**: when ComfyUI reports a missing model that comes with a download link, the download runs through Comfy Desktop and the file is saved into the matching model folder, such as `checkpoints`, `diffusion_models`, `text_encoders`, `loras`, or `vae`. Desktop accepts `.safetensors`, `.sft`, `.ckpt`, `.pth`, and `.pt` files. A model with no download link has to be placed in its folder by hand.
- **Example workflow models**: in **Performance tests**, an example workflow downloads the models it needs in the background, and those transfers appear in the tray like any other download.
- **Outputs from Cloud and remote builds**: when you save an output in a Cloud or remote build, Desktop downloads it to your local output folder. **Auto-download outputs** turns this off.
- **Assets you download yourself**: resources from a Cloud build that you save from the **Assets** page. See [Downloading assets](#downloading-assets).

## Downloading assets

The **Assets** page lists resources from your Cloud build and from the builds on this computer. A Cloud asset is not on your disk yet, so it downloads to a folder you choose; a local asset is already there, and the same menu opens it.

1. Open **Assets** in the sidebar and select the item you want.
2. For a Cloud asset, choose **Download** in its details panel or in its right-click menu.
3. Pick a folder in the save dialog. It opens in the folder you saved to last, and in your system Downloads folder the first time.
4. Follow the transfer in the **Downloads** tray, where **✕** cancels it.

Each asset downloads on its own, so repeat this for every file you want to keep.

## The Downloads tray

Rows are listed newest first, labeled with the model folder and file name. Active rows show the transferred size and percentage, plus the speed and remaining time once those are known.

![Downloads tray opened from the Comfy Desktop title bar, listing model downloads with their folder and progress](/images/desktop/usage/downloads_01_tray.png)

The badge on the icon counts the transfers that have not finished, including paused ones. When nothing is downloading, it switches to transfers you have not looked at since they finished (green) or failed (red), and a red dot appears while active downloads and unseen failures exist at the same time.

Hover a row for its actions:

- **Try again** restarts a failed or cancelled transfer.
- The folder button opens the folder that holds a finished file. Clicking the finished row does the same (Show in Finder, Show in Explorer, or Show in folder).
- **✕** cancels an active transfer or removes a finished row from the list.

**View all** at the top of the tray opens the full downloads view.

## The full downloads view

The full view keeps the download history and adds the controls that do not fit in the tray:

- Filter by status. The bar offers **All**, plus **Active**, **Completed**, and **Failed** for the statuses that have rows, and stays hidden while fewer than two do. Cancelled downloads are listed under **Failed**.
- Rows that have a main action show it as a single button: **Pause**, **Resume**, **Try again**, or open the folder.
- **✕** cancels an active transfer or removes the row.
- The footer counts the active, completed, failed, and cancelled downloads in the list.
- **Clear finished** removes every finished row at once.

![Full Downloads view listing two paused downloads, each with a Resume action, and the active count in the footer](/images/desktop/usage/downloads_02_full_view.png)

## Quitting with downloads in progress

Model downloads resume. The bytes already received are kept, and the next launch shows the transfer as a paused row: open **View all** and choose **Resume**. Cancelling instead deletes the partial file.

Output and asset downloads follow a separate path and do not resume after you quit.

While example workflow models are still downloading, Comfy Desktop asks you to confirm the quit:

- **Quit anyway**: pauses the downloads and quits. They come back as paused rows on the next launch.
- **Keep downloading**: cancels the quit and leaves Comfy Desktop running. This is the default.

Quits that Comfy Desktop starts itself, such as installing an update or restarting, skip this prompt. So does **Quit Desktop** in the ☰ menu, which closes every window at once. That path asks in a **Quit Desktop** dialog instead, listing the local builds it will stop and any active downloads; a Cloud or remote window alone does not trigger it, and from Home, with no build window open, it quits without asking.

## Where downloads are saved

Model files go to the shared models folder tagged **Downloads**. Set which folder that is with **Use for downloads** in [Desktop settings](/installation/desktop/usage/settings#storage). A build that does not use shared model folders downloads into its own `models` folder, and a build can add more model folders in its **Manage** panel.

Outputs from a Cloud or remote build go to the shared output folder when the build uses it, otherwise to that build's output folder, and to the shared output folder when that field is empty. A remote build can turn automatic output downloads off with **Auto-download outputs** under **Launch settings** on its **Startup arguments** tab.

Assets you download go wherever you point the save dialog, so they can sit outside the build entirely.
