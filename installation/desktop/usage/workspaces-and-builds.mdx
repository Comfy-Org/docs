Comfy Desktop can connect to your Comfy account. Signing in adds workspace features to the Chooser: switch between your Personal workspace and any team workspace you belong to, see the instances that belong to the selected workspace, and install ComfyUI Builds published to it. You can also turn a local instance into a Build that other members of the workspace can install.

Signing in is optional. Local instances, snapshots, and settings work without an account.

## Signing in

The account chip sits at the top right of the Chooser.

- **Signed out**: the chip shows a **Log in** button. Click it to open the browser sign-in flow, then return to the app.
- **Signed in**: the chip shows your avatar and email. Click it to open a menu with **Sign out**.

Signing out ends the session only. Your instances stay in place. If an installation is in progress, Comfy Desktop warns you that signing out cancels it before it continues.

## Switching workspaces

A workspace bar sits above the instance grid:

- **Workspace switcher**: your **Personal** space and every team workspace you belong to. Click it to switch.
- **Refresh workspaces**: appears once you are signed in. It reloads the workspace list and the Builds catalog for the selected workspace.
- **INSTANCES**: the number of instances that belong to the selected workspace.

The selected workspace scopes the Chooser. The grid shows only the instances that belong to it, and the New Instance flow offers that workspace's Builds. Comfy Desktop remembers the workspace you selected and restores it the next time you open the app.

## Installing a Build

A Build is a packaged ComfyUI environment published to a workspace. The New Instance wizard shows the Build's release version, creator, hardware target, and an estimate of the disk space it needs. Installing a Build gives you that exact environment as a local instance, instead of a plain ComfyUI install.

1. Click the **+** card in the Chooser to open the New Instance wizard.
2. In the method row, select **Managed Builds**. If you are not signed in yet, Comfy Desktop asks you to sign in first.
3. Under **Release**, pick the Build to install. Only Builds that are ready to install and compatible with your machine are listed. Use **View builds online** to open the Builds page in your browser, or the refresh button to reload the list.
4. Under **Hardware**, pick the release target for your machine, for example Windows with NVIDIA (CUDA 12.8). The recommended target for your hardware is preselected.
5. Continue through the wizard to install the instance.

When you are signed in, the wizard opens on **Managed Builds** and falls back to **Public Builds** when the selected workspace has no compatible Build. **Public Builds** is the standard ComfyUI install for your detected hardware.

## Updating a Build

A Build install stays on the environment its author published, so it does not follow a ComfyUI release channel. What moves forward is the build version.

Open the instance's [Manage panel](/installation/desktop/usage/manage) and switch to the **Update** tab. The **Build Version** card shows the version this instance runs, with an **Update available** badge once the workspace publishes a newer one, or **Up to date** when Comfy Desktop has read the published versions and yours is the newest. Under the headline the card lists:

- **Installed**: the build version on disk, for example `v7`
- **Latest Published**: the newest published version
- **Last Checked**: when Comfy Desktop last read the published versions

Below the card:

- **Check for updates** re-reads the published versions of this build from Comfy Developer Platform.
- **Update to v...** appears only when a newer version exists, and names the version it moves to (for example **Update to v8**). The confirmation repeats both versions and says the update replaces the managed environment: your workflows and the models already staged are kept.

Comfy Desktop installs the new version in place, in the same folder. It downloads the artifact built for your machine. A newer version that has no build for your hardware still appears in the list, and choosing it stops with a message that the version has no build for this machine, leaving the instance as it was. The update can be cancelled while it runs, and the instance keeps the environment it had until the new one is in place. Models the new version needs are staged in the background, and an unfinished download picks up at the next launch.

The version list comes from the workspace catalog. Before the app has read that catalog, the card shows the installed version and **Check for updates**, without a latest version.

### Manage Panel Tabs on a Build

A Build install shows four of the six Manage panel tabs, in this order: **Update**, **Startup Args**, **Terminal**, and **About**. **Snapshots** and **Storage** are deliberately absent:

- A Build ships its own model set and its own environment, so there are no shared model folders or per-instance input and output paths to configure.
- Comfy Desktop shows no Snapshots tab on a Build install, so there is no snapshot list to browse or restore from. The Update tab offers only newer published versions, so it has no way to take a Build back to an earlier one.

**Startup Args** carries the same controls as on a standalone install: launch arguments, ComfyUI-Manager policy, launch mode, browser cache, port behavior, and environment variables. A Build can be published with a fixed model allowlist, and such a Build launches without ComfyUI-Manager, so the Manager rows have no effect on it.

## Creating a Build from an instance

You can publish a local instance as a Build so that other members of its workspace can install it.

1. Sign in to your Comfy account.
2. In the Chooser, open the instance's **⋮ menu** and select **Create Build**.
3. Comfy Desktop creates a draft Build from that instance in Comfy Developer Platform. The draft belongs to the workspace the instance belongs to.

**Create Build** is offered for local instances that are installed and have an installation path on disk. It is not offered for Cloud or remote instances. The Build starts as a draft, so you can review its contents before releasing it.

For the full Build workflow, including how to create a Build from a Desktop snapshot or a workflow JSON file, see [Other Ways to Create a Comfy API Build](/development/serverless/build-sources).
