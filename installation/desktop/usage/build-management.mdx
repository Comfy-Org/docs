Each build has its own page, and that page is where you manage one build. To install, add, or connect the build, see [Builds](/installation/desktop/usage/instance-management).

Open the build page in one of these ways:

- In the **sidebar**, click the build under **Builds**.
- In the [quick actions](/installation/desktop/usage/instance-management#quick-actions-from-the-build-list), select **Manage**.

## The build page

The header tells you what the build is and whether it runs. From left to right:

- **Name**: click it, or click the pencil (**Edit build name**), to rename the build. Type the new name, then press `Enter`, or press `Esc` to keep the old one. You can rename Standalone, Portable, git, and remote builds, but not Comfy Cloud or Legacy Desktop builds. Each build needs a name no other build uses.
- **Status chip**: **Running**, **Starting…**, or **Stopping…**, or a failure label when the build crashed or didn't start. Click a failure label to see the error.
- **Meta line**: where the build runs (**This computer**, **Cloud**, or **Remote**), its type, and its version, separated by dots.
- **Primary button**: **Start** when a local build is stopped, **Open** while it runs, **Open Cloud** for Comfy Cloud, and **Open remote** for a remote build.
- **More** (**⋯**): actions for the whole build. See [Use the More menu](#use-the-more-menu).

Below the header, each tab holds one kind of setting. A tab appears only when the build has settings for it:

| Build | Tabs |
| --- | --- |
| Standalone | **Overview**, **Folders**, **Startup arguments**, **Snapshots**, **Terminal** |
| Remote | **Overview**, **Startup arguments** |
| Comfy Cloud | **Overview**, **Storage** |

Other local builds, such as Portable and git builds, show the tabs they have settings for, plus **Terminal**. Each tab has its own section, on this page or on the page the Section column names:

| Tab | What you do there | Section |
| --- | --- | --- |
| **Overview** | See what the build runs, update ComfyUI, switch the update channel, change PyTorch, change a remote build's URL | [Update ComfyUI](#update-comfyui) |
| **Folders** | Choose model, input, and output folders | [Choose which folders the build uses](/installation/desktop/usage/build-folders#choose-which-folders-the-build-uses) |
| **Startup arguments** | Set flags, ComfyUI Manager policy, window, port, and environment variables | [Set startup arguments](/installation/desktop/usage/build-startup-arguments#set-startup-arguments) |
| **Snapshots** | Save and restore the build's setup | [Save and restore snapshots](/installation/desktop/usage/build-snapshots#save-and-restore-snapshots) |
| **Terminal** | Run commands in the build's Python environment | [Run commands in the terminal](/installation/desktop/usage/build-terminal#run-commands-in-the-terminal) |
| **Storage** (Comfy Cloud) | Browser cache and output downloads | [Set output options](/installation/desktop/usage/build-folders#set-output-options-for-remote-and-comfy-cloud-builds) |

## Use the More menu

The **More** (**⋯**) button next to **Start** or **Open** holds actions for the whole build. On a Standalone build, it lists:

- **Stop**, while the build runs.
- **Rename**, which selects the name in the header.
- **Duplicate**. See [Duplicate a build](/installation/desktop/usage/build-duplicate-and-remove#duplicate-a-build).
- **Show in Finder**, **Show in Explorer**, or **Show in folder**, named for your operating system.
- **Export snapshot**. See [Snapshots](/installation/desktop/usage/build-snapshots#save-and-restore-snapshots).
- **Forget** and **Uninstall**. See [Remove a build](/installation/desktop/usage/build-duplicate-and-remove#remove-a-build).

On a remote build, it lists **Rename** and **Forget**, plus **Stop** while it runs. On a Comfy Cloud build, the **More** button is grayed out.

## Update ComfyUI

**Overview** shows what the build runs and where you update it. On a Standalone build, it shows a **ComfyUI** card and a row of tiles:

- **PyTorch**: the installed PyTorch version, the hardware it targets, and a **Change** menu. See [Change PyTorch](#change-pytorch).
- **On disk**: the space the build uses, with `{size} free` below it.
- **Python**: the Python version and the build type.
- A details tile: the build's **Location**, with buttons to open the folder and to **Copy path**, and the port while the build runs. A build copied from another one also shows where it came from, such as **Copied from**.

On other builds, **Overview** lists the build's facts in groups: **Build details**, **Running details** (while the build runs), **Location & storage** (local builds only), and **Lineage** (builds copied from another one).

Updating brings the build to the newest ComfyUI on its channel. A dot on the **Overview** tab means an update is available. The row at the bottom of the **ComfyUI** card shows where the build stands:

| Row reads | Meaning | Button |
| --- | --- | --- |
| **{version} available**, with **Saves a snapshot first · Checked {time}** | A newer version is on this channel. | **Update** |
| **Up to date**, with **Checked {time}** | The build has the newest version on this channel. | **Check for updates** |
| **Not checked yet** | Comfy Desktop has no version info for this channel. | **Check for updates** |

To update the build:

1. On **Overview**, click **Update**. You can also select **Update** in the [quick actions menu](/installation/desktop/usage/instance-management#quick-actions-from-the-build-list).
2. In the **Update ComfyUI** dialog, check the versions the build moves between and any **Release notes**, then click **Update now**.

While the update runs, a progress card replaces the tabs. If it fails, the card offers **Try again** and **Dismiss**.

Comfy Desktop saves a snapshot before it updates. If the update breaks a Custom Node, restore that snapshot from the **Snapshots** tab. See [Snapshots](/installation/desktop/usage/build-snapshots#save-and-restore-snapshots).

To try a new version without touching this build, update a copy instead:

1. Click the arrow beside **Update** (**More update options**) and select **Copy & update**.
2. Enter a name for the copy, then click **Copy & update**.

### Switch the update channel

The channel decides where updates come from.

<Warning>
  Selecting **Stable** on a build that runs ahead of the stable release rolls the build back and removes the newer commits.
</Warning>

On the **ComfyUI** card, click the channel name to open the **Update channel** dropdown, then select one:

- **Stable**: tested releases. Use it for most builds. Builds use this channel by default.
- **Latest on GitHub**: the newest commits from the master branch.

When you select a channel the build isn't on, the row reads **Switch to {channel}**:

- If that channel has a newer version, click **Update** to move the build to it.
- If it has nothing newer, click **Switch channel** to move the build without updating it.
- If Comfy Desktop has no version info for that channel, the row reads **Select this channel and check for updates to see version info.** Click **Check for updates**.

### Change PyTorch

Changing PyTorch lets the build use a different PyTorch version or backend, such as a newer CUDA version. The **Change** menu appears on the **PyTorch** tile once Comfy Desktop knows which versions it can install for the build. Before you change PyTorch, make sure the disk has free space for a full copy of the build's environment.

<Warning>
  Changing to a version without torchaudio removes torchaudio, and Custom Nodes that need it stop working. The menu labels these versions.
</Warning>

1. On **Overview**, click **Change** on the **PyTorch** tile.
2. Hold the pointer over the version you want.
3. Select one of these:
   - **Change PyTorch**: changes this build. The **Change PyTorch** dialog shows the change and, for a bundle, its download size. Comfy Desktop backs up the current environment during the change and restores it if anything fails.
   - **Copy & change PyTorch**: makes the change on a copy of this build and leaves the original as it is. Enter a name for the copy, then click **Copy & change PyTorch**.

In the **Change** menu, versions are grouped by backend, and the installed version shows **In use**. Nightly versions sit under a heading that ends in **Nightly (unstable)**, and older nightly versions drop off the menu.

### Change a remote build's URL

A remote build connects to a ComfyUI server at a URL. To point it at a different address:

1. On **Overview**, under **Build details**, click the **URL**, or click the pencil (**Edit connection URL**) beside it.
2. Type the new address, then press `Enter` or click anywhere else.

If you leave out the scheme, Comfy Desktop uses `http://`. If Comfy Desktop can't read the address, it keeps the previous one. While the build is connected, the row shows **Restart to apply**, and the running session keeps the old address until you restart.
