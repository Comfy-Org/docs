In Comfy Desktop, you can time how long a Workflow takes on one of your builds, such as an example video Workflow or your own image Workflow, and compare the result with runs on another GPU or another build. A timing only means something when nothing else competes for the GPU and you know which hardware produced it, so a performance test runs the Workflow alone on the build, repeats it, and saves each result with the system information. You run a test in **Performance tests**, read its results, and compare saved runs in **Benchmarks**.

## Open Performance tests or Benchmarks

Both pages open from the **Menu** in the **title bar**. See [Use the title bar](/installation/desktop/usage/overview#use-the-title-bar) for the other buttons there.

1. On **Home**, click **Menu** at the right end of the **title bar**.
2. Select **Performance tests** or **Benchmarks**.

The page opens in the **Home** window, next to the **sidebar**. In a window that runs ComfyUI, the same **Menu** items open the page in a new Comfy Desktop window.

![Benchmarks page with no results yet, offering Refresh sessions and Open performance test](/images/desktop/usage/comfy-desktop-performance-and-benchmark.png)

**1. Refresh sessions**: reload the list of finished runs from disk.
**2. Open performance test**: start a new run with the Performance test workflow.
**3. Select folder**: change where benchmark results are stored.

## Run a performance test

A performance test starts the build in a session of its own, runs your Workflow several times, and stops the build when it finishes. You set it up from left to right in the toolbar at the top of **Performance tests**: **Build**, **Workflow**, **Warm-up runs**, **Measured runs**, and **Run**.

Before you pick anything, **Build** reads **Select a build**, **Workflow** reads **Choose a workflow**, and **Results** reads **No results yet**.

![Performance tests page before a test: the toolbar with Build reading Select a build, Workflow reading Choose a workflow, Warm-up runs 1, Measured runs 5, and Run, the Results card reading No results yet, and the collapsed Logs row reading Build logs will appear here.](/images/desktop/usage/comfy-desktop-performance.png)

### Choose a build

The build you pick is the one the test starts and times, and its name is saved with the results.

- Click **Build** (it reads **Select a build** until you pick one), and then select a build.

Each build in the list shows its name, with its type and version underneath. The list holds the builds in the workspace selected in the **sidebar**. To test a build from another workspace, switch workspace first, as [Use your workspace menu](/installation/desktop/usage/overview#use-your-workspace-menu) describes. Switching workspace clears the build you picked.

<Note>
  Comfy Cloud builds aren't listed, because a test needs a build that Comfy Desktop starts. When you're logged out, the list shows only installed builds.
</Note>

### Choose a Workflow

Once you've picked a build, choose the Workflow to time. Use an example Workflow that comes with Comfy Desktop, or import your own.

#### Use an example Workflow

Example Workflows are ready to run: Comfy Desktop downloads the models each one needs.

1. Click **Workflow**, and then select **Choose an example workflow**.
2. In **Choose an example workflow**, select the **Video**, **Image**, or **Audio** tab, and then select a card. Each card shows the Workflow's name, its task, and the approximate size of the models it downloads. A hard drive icon instead of a size means the models are already on disk. Hold the pointer over it to see **Downloaded** and the size.
3. Click **Use workflow**.

Comfy Desktop downloads the models that aren't on disk. A status line under the toolbar reads **Preparing workflow and downloading required models…**, and then shows the download with a progress bar and **Cancel download**. The downloads also appear in the **Downloads** tray in the **title bar**. See [Downloads in Comfy Desktop](/installation/desktop/usage/downloads) to follow them there. When the download finishes, **Workflow** shows the example's name with an **Example** tag.

If something stops the example from loading, a red line appears under the toolbar, or in the dialog:

| Message | What to do |
| --- | --- |
| **Finish installing this build to use example workflows.** | Pick an installed build, or finish installing this one. |
| **You need to be connected to the internet to download example workflows.** | Connect to the internet and try again. |
| **Needs ~X, only Y free. Free up space or pick a lighter workflow.** (in the dialog, with **Use workflow** unavailable) | Free up disk space, or select a card with smaller models. |
| **Could not download every model required by this workflow.** | Choose the example again. Comfy Desktop removes an example whose download fails. |

An example belongs to the build you picked it for. If you pick another build, Comfy Desktop removes the example from **Performance tests**. Its files stay on disk if a test already used it.

#### Import your own Workflow

A Workflow you import must be in [API format](/development/api-development/workflow-api-format). Export it from ComfyUI in that format first.

- Click **Workflow**, select **Import API workflow**, and then select the `.json` file. You can also drop the `.json` file onto **Workflow**.

**Workflow** shows the file name with an **API** tag. If the file isn't in API format, the red line under the toolbar reads **The selected file is not a ComfyUI API-format workflow.** A file named `jobs.json` or `results.json` is refused, because those names are reserved for results.

Comfy Desktop copies the file into a new session folder (see [Where results are stored](#where-results-are-stored)), so the test runs the copy even after you move or edit the original.

#### Remove a Workflow

- Click **Workflow**, select **Delete workflow**, and then click **Delete workflow** to confirm.

This removes the Workflow from **Performance tests**. Comfy Desktop deletes its copy if no run has used it yet. Your original file and results from earlier runs are kept. While an example downloads, the same menu item reads **Cancel download**.

### Set the number of runs

Warm-up runs load the models before the timing starts, so the first slow run doesn't skew the results.

| Setting | Range | Default | What it does |
| --- | --- | --- | --- |
| **Warm-up runs** | 0 to 5 | 1 | Runs first to load models and warm up caches. They aren't included in the results. Set it to 0 to skip the warm-up. |
| **Measured runs** | 1 to 100 | 5 | Runs timed after the warm-up runs. Their durations make up the results. |

When you click **Run**, a value outside the range changes to the nearest limit. Each run adds one to every seed input in the Workflow, so ComfyUI doesn't return a cached result.

### Start the test

Other work that keeps the GPU busy, such as a game or a video export, still affects the numbers, so stop it before you run a test.

1. Click **Run**.

   If **Run** is unavailable, hold the pointer over it for the reason: **Select a build first.**, **Choose a workflow first.**, **Wait for the workflow to be ready.**, or **Wait for the build to finish starting.**

2. Follow the test in **Results**. It reads **Starting the build…**, and then **Run N of M** with **warm-up run** or **measured run X of Y** under a progress bar. **Logs** opens to show the build's output.

While the test runs, **Stop** takes the place of **Run**. Click **Stop** to cancel the test. It reads **Stopping…** until the build stops.

When every run finishes, Comfy Desktop stops the build and shows the results. If the runs haven't finished 4 hours after Comfy Desktop sends them, the test stops with **Timed out waiting for performance test jobs.**

### Stop builds that block a test

A test runs alone, so nothing else competes for the GPU and memory. If another build on this computer is running, starting, or stopping, the test doesn't start. This includes the build you're testing when it's open in ComfyUI, and a performance test on another build. Remote and Comfy Cloud builds run elsewhere and never block a test.

**Results** then reads **The performance test did not start** and lists each build in the way. A performance test in the list reads **Performance test:** followed by the build's name.

<Warning>
  Stopping a build loses any unsaved work in its ComfyUI window. Save your Workflows first.
</Warning>

1. Click **Stop** next to a build in the list.
2. In **Stop ComfyUI**, click **Stop**. The row reads **Stopped**.
3. Repeat for each build in the list, and then click **Run** again.

You can also stop a build from its build page. See [Stop or restart](/installation/desktop/usage/instance-management#stop-or-restart).

### Read the results

Results show how long the Workflow took on this build, so you can compare it with other builds and GPUs.

- The header names the Workflow and the build the test ran on.
- The large number is the median run, in seconds. Under it, **Median run · N measured · N failed** counts the runs that produced a duration and the runs that failed.
- **Run duration** compares **Fastest run**, **Median run**, **Average run**, and **Slowest run** as bars.
- **System information** lists **Compute device**, **VRAM**, **RAM**, **PyTorch version**, **xFormers version**, **CPU**, **CPU cores**, **Operating system**, and **Architecture**.

A run's duration is the time ComfyUI spent executing the job, from start to end of execution, not the time you waited for it. Failed runs are left out of the durations.

Two buttons sit at the right of the results header:

- **Show in Finder** on macOS, **Show in Explorer** on Windows, or **Show in folder** on Linux opens the session folder.
- **Export results** asks for a folder. Click **Export here** to save the results as `performance-test-results-<timestamp>.png`.

If the test fails, **Results** reads **The test didn't finish** with the error, followed by **See the logs below for details.** Expand **Logs** to read the build's output. A Workflow that needs a Node or model the build doesn't have fails this way.

The results stay on the page until your next run. To see them again later, open **Benchmarks**.

## Compare runs in Benchmarks

Benchmarks reads every saved test in the results folder and lists them in one table, so you can see how much faster one GPU, Workflow, or build is than another. Until a test finishes, it reads **No performance test results yet**. Click **Open performance test** to run one, or **Refresh sessions** after a test finishes.

![Benchmarks page with no results: Select folder at the top right, and the message No performance test results yet with Run a performance test to see it here., Refresh sessions, and Open performance test](/images/desktop/usage/comfy-desktop-benchmark.png)

### Filter and sort the runs

Narrow the table to the runs you want to compare with the toolbar:

- **Workspace**, **Build**, **Hardware**, and **Workflow**: show only the runs that match. Each reads **All** by default.
- **Compare by**: the duration the table compares, **Fastest**, **Average**, **Median**, or **Slowest**. The default is **Median**.
- **Refresh sessions** (the circular arrow): reloads the results folder after a test finishes.
- **Search runs…**: matches the session, Workflow, build, workspace, and hardware.
- **Columns**: choose what the table shows. **Measures** adds duration columns, and **Columns to display** adds columns such as **Workspace**, **Date / time**, **Runs**, and **GPU / hardware**.

By default, the table shows **Session**, **Workflow**, **Build**, **Median and range**, **Median**, and **Compared to baseline**. The two **Median** columns follow **Compare by**. Runs are sorted by the **Compare by** duration, fastest first.

- To sort by a column, click its heading. Click it again to reverse the order.
- To move a run, drag its grip at the left of the row, or focus the grip and press `Alt+Up` or `Alt+Down`.
- To move a column you added, drag its heading, or focus it and press `Alt+Left` or `Alt+Right`.

If no run matches, the page reads **Nothing matches**. Click **Clear filters** to see every run.

### Compare against a baseline

Each run is compared with one reference run. By default, that's the fastest run by the **Compare by** duration, marked **Fastest**.

The **Compared to baseline** column reads, for each other run:

- **N× faster**: the run took 1/N of the baseline's time.
- **N× slower**: the run took N times as long as the baseline.
- **Same speed**: the run is within 0.5% of the baseline.
- **Unavailable**: the run has no duration to compare.

To compare with a run of your choice:

- Hold the pointer over the row, and click the flag (**Set as baseline**). You can also click **⋯** at the end of the row and select **Set as baseline**.

The run is marked **Baseline**. To go back to the fastest run, click the flag again (**Reset baseline**). If the filters hide the baseline, a note under the table reads **Compared with session N, which the filters hide.**

### Export a comparison

Export a comparison to share it as an image.

1. Select the checkbox at the left of each run to export. A bar at the bottom shows how many runs are selected.
2. Click **Export results** in the bar.
3. Select a folder, and then click **Export here**.

Comfy Desktop saves `benchmark-comparison-<timestamp>.png` in that folder. The image includes a relative speed chart only when you've set a baseline. You can export up to 20 runs. With more selected, **Export results** is unavailable and reads **Up to 20 runs** when you hold the pointer over it. To clear the selection, click **Clear selection** (**✕**) in the bar.

### Rename or delete a session

Each test is saved as a session, named by default with the time you added its Workflow. Give a session a name you'll recognize, or delete one you no longer need.

To rename a session:

1. Click the session name in the **Session** column. A pencil icon shows when you hold the pointer over it. You can also click **⋯** at the end of the row and select **Rename session**.
2. Type the new name, and then press `Enter`. Press `Escape` to cancel.

Renaming a session renames its folder. If another session already has that name, the session isn't renamed.

To delete a session:

1. Click **⋯** at the end of the row, and then select **Delete files**.
2. Click **Delete files** to confirm.

Deleting removes every file in the session folder. You can't undo it.

### Compare results from another computer

Benchmarks reads the `results.json` file in each session folder it finds. To compare runs from another computer, copy their session folders into one folder.

1. Click **Select folder** at the top of **Benchmarks**.
2. Select the folder that holds the session folders.

## Where results are stored

Performance tests creates a session folder when you add a Workflow, named with that moment's timestamp (`YYYYMMDDHHMMSS`):

```text
ComfyUI-Shared/
└── benchmarks/
    ├── 20260930141522/
    │   ├── my_workflow.json
    │   ├── jobs.json
    │   ├── results.json
    │   └── logs.txt
    └── 20260930163005/
        └── ...
```

| Platform | Default results folder |
| --- | --- |
| Windows | `%LOCALAPPDATA%\Comfy-Desktop\ComfyUI-Shared\benchmarks` |
| macOS and Linux | `~/ComfyUI-Shared/benchmarks` |

Each session folder holds:

- `my_workflow.json` (the name of your file): the copy of the Workflow the test runs
- `jobs.json`: the job details ComfyUI returned for the runs
- `results.json`: the summary that Benchmarks reads
- `logs.txt`: the build's output during the test

Running the same Workflow again writes into the same session folder and replaces the results stored there. To keep a result for comparison, choose or import the Workflow again before the next test. That creates a new session folder.
