**1つのパッケージ、2つのサーフェス。** `comfy-sdk`（PyPI）と `@comfyorg/sdk`（npm）は、2つの異なるサービスと通信する2つのクライアントを提供します。メソッド名は両者で重複して登場し（`run`、`submit`、`events`）、それぞれで意味が異なるため、スニペットをコピーする前に、それがどちらのクライアントを構築するものかを確認してください。

| サーフェス | 機能 | アクセス方法 | ベースURL | 認証 |
|---|---|---|---|---|
| **[Comfy Router](/ja/development/comfy-router/quickstart)** | パートナーモデル（Flux、Veo、Gemini、Kling）をそのプロバイダー自身のリクエストボディで呼び出し、ネイティブのレスポンスを返します | Python: `Comfy()` の `client.models`。TypeScript: モジュールレベルの `comfy` 名前空間の `comfy.models` | `https://api.comfy.org`、ルート `/v2/models/{provider}/{model}` | `COMFY_API_KEY`、または `comfy.config({ credentials })` |
| **[Comfy Cloud と Comfy API v2](/ja/development/api-development/sdks)** | API形式の ComfyUI ワークフローをエンドツーエンドで実行します: アセットのアップロード、グラフの送信、ジョブの追跡、出力のダウンロード | `Comfy(api_key=...)` / `new Comfy({ apiKey })`、続いて `client.workflows`、`client.assets`、`client.jobs` | デフォルトでは `https://cloud.comfy.org`、または `COMFY_BASE_URL` が指定するもの | コンストラクターの `api_key` / `apiKey` |

どちらのサーフェスも他方をラップしておらず、[あなたの Comfy ワークスペース](https://platform.comfy.org/profile/api-keys)で作成した1つの APIキーが両方で機能します。

<Note>
  2つの言語では Router サーフェスの公開の仕方が異なります。Python では `Comfy()` が両方を担います。Router には `client.models.run(...)`、Cloud には `client.workflows` / `client.assets` / `client.jobs` です。TypeScript ではこれらは意図的に似た名前を持つ別々のエクスポートです。`comfy`（小文字、モジュールレベルの名前空間）が `comfy.models` を持ち、一方 `Comfy`（クラス）は Cloud クライアントであり `.models` を持ちません。
</Note>
