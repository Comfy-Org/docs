**Один пакет, две поверхности.** `comfy-sdk` (PyPI) и `@comfyorg/sdk` (npm) поставляют два клиента, которые обращаются к двум разным сервисам. Имена методов повторяются в обоих (`run`, `submit`, `events`) и в каждом означают своё, поэтому проверьте, какой клиент создаёт фрагмент кода, прежде чем его копировать.

| Поверхность | Что делает | Как получить к ней доступ | Базовый URL | Аутентификация |
|---|---|---|---|---|
| **[Comfy Router](/development/comfy-router/quickstart)** | Вызывает модель партнёра (FLUX, Veo, Gemini, Kling) с телом запроса, свойственным этому провайдеру, и возвращает его нативный ответ | Python: `client.models` у `Comfy()`. TypeScript: `comfy.models` в модульном пространстве имён `comfy` | `https://api.comfy.org`, маршрут `/v2/models/{provider}/{model}` | `COMFY_API_KEY` или `comfy.config({ credentials })` |
| **[Comfy Cloud и Comfy API v2](/development/api-development/sdks)** | Запускает рабочий процесс ComfyUI в формате API от начала до конца: загружает ассеты, отправляет граф, отслеживает задачу, скачивает выходы | `Comfy(api_key=...)` / `new Comfy({ apiKey })`, затем `client.workflows`, `client.assets`, `client.jobs` | `https://cloud.comfy.org` по умолчанию или адрес, указанный в `COMFY_BASE_URL` | `api_key` / `apiKey` в конструкторе |

Ни одна поверхность не оборачивает другую, и один API-ключ, созданный в [вашем рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys), подходит для обеих.

<Note>
  Два языка предоставляют поверхность Router по-разному. В Python `Comfy()` содержит обе: `client.models.run(...)` для Router и `client.workflows` / `client.assets` / `client.jobs` для Cloud. В TypeScript это отдельные экспорты с намеренно похожими именами: `comfy` (в нижнем регистре, модульное пространство имён) содержит `comfy.models`, а `Comfy` (класс) является клиентом Cloud и не имеет `.models`.
</Note>
