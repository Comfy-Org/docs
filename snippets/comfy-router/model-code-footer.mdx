## Before you ship

The snippets above are the shortest working call. The SDKs already handle most of what changes between a first call and production code; if you call Router over raw HTTP, as the cURL tab does, you take these on yourself. All four are covered in depth in the [Comfy Router quickstart](/api-reference/comfy-router/quickstart):

- **Fields come from the model's own schema.** Append `/openapi.json` to the model's invocation path to read the exact input schema the server validates against. It is the same document Router enforces, so it cannot drift from what is documented here.
- **Retry with the same `Idempotency-Key`.** The SDKs mint one per call and reuse it across their own retries, so a lost response replays the original result instead of billing a second generation. To retry a call *you* lost, pass the key back (`idempotency_key=` in Python, `idempotencyKey` in TypeScript); the SDK exposes it on the error. Over raw HTTP, send the header yourself and persist the key before the request goes out.
- **Expect the connection to be held.** Router returns once the generation is finished, up to its 10 minute server deadline, and answers `504` / `deadline_exceeded` at that bound. The SDKs default to that deadline; a raw HTTP client needs a timeout above it, or it drops the typed error and the request id.
- **Keep `X-Comfy-Request-Id`.** It is on every response, success and error alike, and is the id to quote in a support request. The TypeScript SDK returns it as `requestId`; the Python SDK exposes `request_id` on every error. On failure, `X-Comfy-Error-Type` names one of fifteen buckets (the SDKs raise a typed error per bucket); a `422` means the body failed the model's schema and was never billed.
