`Select Model Device` 节点允许你手动选择扩散模型在哪个设备（CPU 或特定 GPU）上运行。它可以将模型移动到其他设备，并自动处理与其他多 GPU 节点的冲突。选择 `"default"` 会恢复模型加载器最初选择的设备。

## 输入

| 参数 | 描述 | 数据类型 | 必填 | 范围 |
| --- | --- | --- | --- | --- |
| `model` | 要放置在指定设备上的扩散模型。 | MODEL | 是 |  |
| `device` | 模型的目标设备。选项会根据当前机器上可用的设备动态生成。（默认值：`"default"`） | COMBO | 是 | `"default"`<br />`"cpu"`<br />`"gpu:0"`<br />`"gpu:1"`<br />...（每检测到一个 GPU 对应一个 `"gpu:N"` 条目） |

**参数详情：**
- `"default"`：恢复模型加载器分配的加载设备和卸载设备，即使之前调用过 `Select Model Device` 也是如此。
- `"cpu"`：将加载设备和卸载设备都固定到 CPU。
- `"gpu:N"`：将加载设备固定到第 N 个可用 GPU（例如，第一个 GPU 使用 `"gpu:0"`）。卸载设备会恢复为加载器最初的选择。

**重要说明：**
- 如果当前机器上不存在所请求的设备（例如，在 2-GPU 机器上创建的工作流在 1-GPU 机器上打开），该节点会原样传递模型并记录一条消息，而不是报错。输入验证期间允许未知的 `gpu:N` 值，因此可移植工作流不会过早报错。
- 如果模型已经在所请求的设备上，该节点会使用快速路径，不会重新加载模型。
- 当所请求的设备与输入模型当前所在的设备不同时，会使用加载器的重新加载工厂生成一个新模型，以便新的 patcher 在新设备上拥有独立的权重。
- 如果模型加载器不支持多 GPU（没有重新加载工厂），该节点会原样传递模型并记录一条警告。
- 当 MultiGPU CFG Split 克隆已经占用所选设备时，该克隆会被移除，以免两个模型绑定到同一设备。
- 当选择非默认设备（CPU 或 GPU）时，该节点还会将模型的计算 dtype 调整为该设备支持的类型。
- 不建议将此节点放在已经使用过该模型的节点（例如 KSampler）之后，因为如果设备与原始设备匹配，前一个节点更改的任何状态都会被观察到。

## 输出

| 输出名称 | 描述 | 数据类型 |
| --- | --- | --- |
| `model` | 扩散模型，现在放置在所选设备上。如果设备无效或不可用，则模型会原样传递。 | MODEL |
