CLIPTextEncodeHiDream 节点使用不同的语言模型（CLIP-L、CLIP-G、T5-XXL 和 LLaMA）处理四个独立的文本输入，并将它们组合成单个 conditioning 输出。它使用相应的模型对每个文本输入进行分词，并通过调度编码方法将它们一起编码，从而同时利用多个语言模型实现更复杂的文本 conditioning。

## 输入
| 参数 | 描述 | 数据类型 | 必需 | 范围 |
| --- | --- | --- | --- | --- |
| `clip` | 用于分词和编码的 CLIP 模型 | CLIP | 是 | - |
| `clip_l` | 供 CLIP-L 模型处理的文本输入。支持多行文本和动态提示词。 | STRING | 是 | - |
| `clip_g` | 供 CLIP-G 模型处理的文本输入。支持多行文本和动态提示词。 | STRING | 是 | - |
| `t5xxl` | 供 T5-XXL 模型处理的文本输入。支持多行文本和动态提示词。 | STRING | 是 | - |
| `llama` | 供 LLaMA 模型处理的文本输入。支持多行文本和动态提示词。 | STRING | 是 | - |

**注意：** 所有四个文本输入（`clip_l`、`clip_g`、`t5xxl` 和 `llama`）都是正常运行所必需的，因为每个输入都会通过调度编码过程为最终的 conditioning 输出做出贡献。

## 输出
| 输出名称 | 描述 | 数据类型 |
| --- | --- | --- |
| `CONDITIONING` | 所有已处理文本输入经调度编码方法编码后合并而成的 conditioning 输出 | CONDITIONING |
