此节点根据姿态数据构建一个可直接保存的 3D 动画文件。您可以导出多种视觉样式的动画 GLB —— 全身网格、仅关节预览、OpenPose 骨架或 SCAIL 胶囊绑定 —— 也可以改为保存 BVH 动作捕捉片段。输出可接入文件保存节点（如 Save 3D Model）以将文件写入磁盘。

## 输入

### 通用输入

| 参数 | 描述 | 数据类型 | 必填 | 范围 |
|-----------|-------------|-----------|----------|-------|
| `pose_data` | 3D 姿态数据。接受 MHR 姿态数据（模型/形状/表情参数、MHR70 关键点、规范颜色、手部顶点遮罩）或 Kimodo 姿态数据（外部 Y 轴朝上的绑定，带有逐帧预测的顶点和相机）。 | MHR_POSE_DATA / KIMODO_POSE_DATA | 是 | — |
| `格式` | 输出格式，将传入 Save 3D Model 以写入磁盘。'glb' = 动画 GLB（mesh / bones / openpose / scail）。'bvh' = BVH 动作捕捉片段（一个骨架；需要模型）。（默认：glb） | DYNAMIC_COMBO | 是 | "glb"<br />"bvh" |
| `sam3d_body_model` | 可选的 SAM3D 身体模型。对于 'bvh'、'body_mesh' 和 'bones_only' 格式是必需的，除非姿态数据带有骨架覆盖。 | SAM3D_BODY_MODEL | 否 | — |

**注意：**

- `bvh` 格式以及 `body_mesh` 和 `bones_only` 网格样式需要 `sam3d_body_model` 输入，除非 `pose_data` 自身带有骨架覆盖（例如来自 KimodoSample 节点的 `_skeleton_override` 字典）。如果两者均不可用，节点将引发错误。`openpose` 和 `scail` 样式与绑定无关，可直接基于关键点工作，无需身体模型。
- 在 `bvh` 格式中，输出包含单个骨架。当 `track_index` 为 -1（所有轨道）时，使用第一条轨道。
- `face_style` 的 `full` 和 `eyes_mouth` 选项要求姿态数据带有 `canonical_colors`；当姿态数据与身体模型一同来自 MHR 流程时，该数据即存在。
- `bone_smooth_window` 在 0 到 51 之间以 2 为步长递增。
