Comfy Desktop 可以连接到你的 Comfy 账户。登录后会为 Chooser 添加工作区功能：在个人工作区和所属的任意团队工作区之间切换，查看属于已选择工作区的实例，并安装发布到该工作区的 ComfyUI Build。你还可以将本地实例转换为 Build，供工作区的其他成员安装。

登录是可选的。本地实例、快照和设置无需账户即可使用。

## 登录

账户标签位于 Chooser 的右上角。

- **未登录**：标签显示 **登录** 按钮。点击它会打开浏览器登录流程，然后返回应用。
- **登录成功**：标签显示你的头像和电子邮件。点击它会打开一个包含 **退出登录** 的菜单。

退出登录只会结束会话。你的实例仍会保留在原处。如果安装正在进行中，Comfy Desktop 会先警告你退出登录会取消该安装，然后才继续。

## 切换工作区

登录成功后，实例网格上方有一个工作区栏：

- **工作区切换器**：你的**个人**空间以及你所属的每个团队工作区。点击即可切换。
- **刷新工作区**：登录后出现。重新加载工作区列表以及所选工作区的 Builds 目录。
- **INSTANCES**：属于所选工作区的实例数量。

所选工作区限定了 Chooser 的范围。网格中只显示属于该工作区的实例，新建实例流程也只会提供该工作区的 Builds。Comfy Desktop 会记住你选择的工作区，并在下次打开应用时恢复它。

## 安装 Build

Build 是发布到工作区的打包 ComfyUI 环境。新建实例向导会显示该 Build 的发布版本、创建者、硬件目标，以及所需磁盘空间的估算值。安装 Build 可以让你以本地实例的形式获得完全相同的环境，而不是普通的 ComfyUI 安装。

1. 在 Chooser 中点击 **+** 卡片，打开新建实例向导。
2. 在方法一行中，选择 **Managed Builds**。如果你尚未登录，Comfy Desktop 会要求你先登录。
3. 在 **Release** 下，选择要安装的 Build。列表中只会显示可以安装且与你的机器兼容的 Build。使用 **View builds online** 在浏览器中打开 Builds 页面，或使用刷新按钮重新加载列表。
4. 在 **Hardware** 下，选择适合你机器的发布目标，例如 Windows 搭配 NVIDIA（CUDA 12.8）。系统会预先选择推荐用于你硬件的目标。
5. 继续完成向导以安装实例。

登录成功后，向导会打开 **Managed Builds**，当所选工作区没有兼容的 Build 时，则回退到 **Public Builds**。**Public Builds** 是针对检测到的硬件进行的标准 ComfyUI 安装。

## 更新 Build

Build 安装会停留在其作者发布的环境上，因此它不跟随 ComfyUI 的发布通道。往前推进的是 Build 版本本身。

打开实例的[管理面板](/zh/installation/desktop/usage/manage)，切换到**更新**标签页。**构建版本**（Build Version）卡片显示该实例正在运行的版本：工作区发布了更新的版本后，卡片会带上**有可用更新**标记；当 Comfy Desktop 已读取已发布的版本、而你用的就是最新版本时，显示**已是最新**。卡片标题下方列出：

- **已安装**：磁盘上的 Build 版本，例如 `v7`
- **最新发布**：最新发布的版本
- **上次检查**：Comfy Desktop 上次读取已发布版本的时间

卡片下方：

- **检查更新**：从 Comfy Developer Platform 重新读取该 Build 已发布的版本。
- **更新到 v...**：仅在有更新版本时出现，按钮上写明目标版本（例如**更新到 v8**）。确认框会重复这两个版本，并说明更新会替换托管环境：你的工作流和已暂存的模型会被保留。

Comfy Desktop 在原位置安装新版本，仍在同一个文件夹里。它下载的是为你的机器构建的产物。没有为你的硬件构建的更新版本仍会出现在列表中，选择它时会停下并提示该版本没有适用于此设备的构建，实例保持不变。更新过程中可以取消，在新环境就位之前实例会保持原来的环境。新版本需要的模型会在后台暂存，未完成的下载会在下次启动时继续。

版本列表来自工作区目录。在应用读取该目录之前，卡片只显示已安装的版本和**检查更新**，不显示最新版本。

### Build 的管理面板标签页

Build 安装会显示六个管理面板标签页中的四个，顺序为：**更新**、**启动参数**、**终端**和**关于**。**快照**和**存储**是有意不提供的：

- Build 自带模型集合和自带环境，因此没有共享模型目录，也没有需要配置的实例级输入、输出路径。
- Comfy Desktop 不会在 Build 安装中显示快照标签页，因此没有可浏览或恢复的快照列表。更新标签页只提供更新的已发布版本，无法把 Build 退回更早的版本。

**启动参数**提供的控件与独立安装相同：启动参数、ComfyUI-Manager 策略、启动模式、浏览器缓存、端口行为和环境变量。Build 可以带着固定的模型允许列表发布，这类 Build 会在不启用 ComfyUI-Manager 的情况下启动，因此 Manager 相关选项对它没有作用。

## 从实例创建 Build

你可以将本地实例发布为 Build，这样其工作区的其他成员就能安装它。

1. 登录你的 Comfy 账户。
2. 在 Chooser 中，打开实例的 **⋮ 菜单**，然后选择 **Create Build**。
3. Comfy Desktop 会在 Comfy Developer Platform 中基于该实例创建一个草稿 Build。该草稿归属于实例所在的工作区。

**Create Build** 仅适用于已安装且在磁盘上有安装路径的本地实例。云端实例或远程实例不会提供该选项。Build 最初是草稿状态，因此你可以在发布之前查看其内容。

关于完整的 Build 工作流，包括如何从 Desktop 快照或工作流 JSON 文件创建 Build，请参阅[其他创建 Comfy API Build 的方式](/zh/development/serverless/build-sources)。
