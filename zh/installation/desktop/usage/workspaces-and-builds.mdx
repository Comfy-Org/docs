Comfy Desktop 可以安装你的团队在 Comfy Developer Platform 上共享的 ComfyUI 配置，例如一个包含选定模型和自定义节点的已批准 Build。在 Developer Platform 上，此配置称为 Developer Platform Build，由你的工作区按编号版本发布，Comfy Desktop 会将其中一个版本作为团队 Build 安装到你的计算机上。你可以选择工作区、安装其 Build、在团队发布较新版本时进行更新，并将你自己的 Build 上传到 Developer Platform。

要在 Developer Platform 上创建 Build 并发布其版本，请参阅[向 Comfy Cloud 添加自定义 Build](/zh/development/deploy/cloud-custom-builds)。

## 选择要查看哪个工作区的构建

每个工作区都有各自的 Developer Platform Builds，而 Comfy Desktop 一次只显示一个工作区。要查看团队的构建，请先登录。请按照[登录并打开 Comfy Cloud](/zh/installation/desktop/overview#log-in-and-open-comfy-cloud)操作。

在**侧边栏**底部选择的工作区决定了你能看到的内容：

- **首页**、**侧边栏**、**构建**页面以及各个构建页面只列出该工作区中的构建。
- **新建构建**会在**你的团队的构建**下提供该工作区的 Developer Platform Builds。你的**个人**工作区也有自己的构建。

要切换工作区，请参阅[使用你的工作区菜单](/zh/installation/desktop/usage/overview#use-your-workspace-menu)。Comfy Desktop 会记住你选择的工作区，并在下次打开时进入该工作区。

<Tip>
  当你的团队在 Comfy Desktop 打开期间发布构建时，请在**构建**页面点击**刷新工作区**。它会重新加载你的工作区及其 Developer Platform Builds。
</Tip>

## 从团队安装构建

当 Developer Platform 构建有了已发布的版本，且该版本包含适用于你计算机操作系统和 GPU 的构建后，它就会出现在 Comfy Desktop 中。安装它会在本机上添加一个团队构建。关于**新建构建**对话框中所有构建共有的部分，例如**名称**和**位置**，请参阅[安装新构建](/zh/installation/desktop/usage/instance-management#install-a-new-build)。

<Steps>
  <Step title="打开新建构建对话框">
    在**构建**页面，点击**新建构建**。

    登录后，对话框会打开你工作区的构建，并已选择第一个构建。如果该工作区没有可安装的构建，则改为打开**官方发布**。
  </Step>
  <Step title="检查构建和硬件">
    摘要会显示将要安装的内容：

    - **发布**：构建的名称，以及它的描述、**发布 v{version}** 和**作者 {creator}**。
    - **硬件**：适用于本机操作系统和 GPU 的构建目标，例如 NVIDIA with CUDA 12.8，及其发布版本。

    **名称**框会建议使用该构建的名称。
  </Step>
  <Step title="选择其他构建（可选）">
    点击**更改**打开**更改设置**。

    - **来源**：选择**你团队的构建**。如果你未登录，浏览器会打开以便你登录，此时对话框会显示**在浏览器中继续**。
    - **发布**：选择一个构建。列表中只显示可安装到本机的构建。点击**在线查看构建**可在浏览器中打开 Developer Platform 上你工作区的构建，或点击**刷新构建**重新加载列表。
    - **硬件**：选择一个构建目标。系统会自动为你选中本机的推荐目标。

    在 Comfy Desktop 切换到工作区的过程中，对话框会显示**正在等待工作区授权…… 如果系统提示，请在浏览器中完成授权。**

    点击**保存更改**返回摘要。
  </Step>
  <Step title="安装构建">
    点击**安装**。要跟进安装进度，请参阅[安装新构建](/zh/installation/desktop/usage/instance-management#install-a-new-build)。
  </Step>
</Steps>

安装完成后，**构建**页面上该构建的卡片会显示**构建 v{version}**，即你安装的版本。如果列表中找不到该构建，请参阅[故障排除](#troubleshoot)。

## 更新团队构建

团队构建只会在其 Developer Platform Build 的各个版本之间迁移。当你的团队发布较新的版本时，更新该构建即可获取。其构建页面会在 **概览** 选项卡上显示 **构建版本** 部分。

1. 在 **侧边栏** 中，点击团队构建以打开其构建页面。当有更新可用时，**概览** 选项卡会显示一个圆点，构建的磁贴会显示 **有更新可用**。
2. 在 **概览** 中，查看 **构建版本** 部分：**已安装**、**最新发布** 和 **上次检查**，并显示 **有更新可用** 或 **已是最新**。如需再次检查，请点击 **检查更新**。
3. 点击 **更新到 v{version}**。你也可以在[快捷操作菜单](/zh/installation/desktop/usage/instance-management#quick-actions-from-the-build-list)中选择 **更新**。
4. 在 **更新构建** 对话框中，确认它会在哪些版本之间切换，然后点击 **立即更新**。

更新会用新版本替换构建的环境，并保留你的工作流和已暂存的模型。运行期间，其进度显示为 **正在更新到 v{version}**。完成后，**已安装**会显示新版本。

## 将构建上传到开发者平台 {#upload-a-build-to-the-developer-platform}

**上传构建**会以本电脑上的一个构建为基础，在开发者平台上启动一个构建，这样你的工作区就能将它发布，你的团队也能安装它。你需要处于登录状态，并且该构建必须已安装在本电脑上。无法上传 Comfy Cloud 和远程构建。

1. 在**侧边栏**中右键点击该构建，或者在**构建**页面上右键点击它的磁贴，或者在**主页**上右键点击它的卡片。
2. 选择**上传构建**。它的提示为 **Upload this build to Comfy Developer Platform.**

在它运行期间，该项目显示为**创建中…**。随后 Comfy Desktop 会：

1. 保存该构建的手动快照。它会显示在构建的**快照**标签页上。参见[保存和恢复快照](/zh/installation/desktop/usage/instance-management#save-and-restore-snapshots)。
2. 以草稿形式将快照发送到开发者平台，并放入该构建所属的工作区。位于你的**个人**工作区中的构建会发送到你的**个人**工作区。
3. 在浏览器中打开该草稿，构建页面会显示**草稿**和**已收到 Desktop 快照**。

在该草稿的某个版本发布并在开发者平台上完成构建之前，草稿不会出现在**你团队的构建**下。要发布它，参见[发布构建](/zh/development/deploy/cloud-custom-builds#发布-build)。

如果该构建上正在运行其他任务，**上传构建**会变灰。将指针悬停在它上面，可查看**请等待此构建上的当前任务完成。**

## 故障排除

<AccordionGroup>
  <Accordion title="Release 显示“No compatible Builds are available to install.”">
    Comfy Desktop 只有在 Developer Platform 构建的最新已发布版本已完成构建，并且存在适用于本计算机操作系统和 GPU 的构建时，才会列出该构建。请检查**侧边栏**中选择的工作区是否为团队所发布的工作区。点击 **View builds online** 查看 Developer Platform 上的构建，然后点击 **Refresh builds**。
  </Accordion>
  <Accordion title="对话框显示“Couldn't load builds. Retry”">
    Comfy Desktop 无法加载你的工作区的构建。点击 **Couldn't load builds. Retry** 重新加载。
  </Accordion>
  <Accordion title="无法上传构建（Could not upload build）">
    **Could not upload build** 警报会说明原因，例如 **Could not create a draft in Comfy Developer Platform.** 再次选择 **Upload build**。
  </Accordion>
</AccordionGroup>
