Comfy Desktop 可以安装你的团队在 Comfy Developer Platform 上共享的 ComfyUI 配置，例如一个包含选定模型和自定义节点的已批准 Build。在 Developer Platform 上，这个配置就是由你的工作区以带编号的版本发布的开发者平台 Build，而 Comfy Desktop 会把其中一个版本作为团队 Build 安装到你的电脑上。你可以选择工作区、安装其 Build、在团队发布新版本时进行更新，并将你自己的 Build 上传到 Developer Platform。

如需在 Developer Platform 上创建 Build 并发布其版本，请参阅[向 Comfy Cloud 添加自定义 Build](/zh/development/deploy/cloud-custom-builds)。

## 选择要查看哪个工作区的构建

每个工作区都有自己的 Developer Platform 构建，并且 Comfy Desktop 一次只显示一个工作区。要查看你团队的构建，请先登录。请按照[登录并打开 Comfy Cloud](/zh/installation/desktop/overview#登录并打开-comfy-cloud)操作。

在**侧边栏**底部选择的工作区决定你看到的内容：

- **主页**、**侧边栏**、**构建**页面以及各个构建页面只列出该工作区中的构建。
- **新建构建**会在**你团队的构建**下提供该工作区的 Developer Platform 构建。你的**个人**工作区有自己的构建。

要切换工作区，请参阅[使用工作区菜单](/zh/installation/desktop/usage/overview#使用工作区菜单)。Comfy Desktop 会记住你选择的工作区，并在下次打开时进入该工作区。

<Tip>
  当 Comfy Desktop 处于打开状态时，如果你的团队发布了构建，请在**构建**页面点击**刷新工作区**。它会重新加载你的工作区及其 Developer Platform 构建。
</Tip>

## 从团队安装构建

当 Developer Platform 构建拥有已发布版本，且该版本包含适用于你计算机操作系统和 GPU 的构建时，它就会显示在 Comfy Desktop 中。安装它会在本计算机上添加一个团队构建。关于 **新建构建** 对话框中所有构建共有的部分，例如 **名称** 和 **位置**，请参见[安装新构建](/zh/installation/desktop/usage/instance-management#安装新构建)。

<Steps>
  <Step title="打开新建构建对话框">
    在 **构建** 页面中，点击 **新建构建**。

    登录后，对话框会打开到你工作区的构建列表，且第一个构建已选择。如果工作区没有可安装的构建，则会改为打开 **官方版本**。
  </Step>
  <Step title="检查构建和硬件">
    摘要会显示将要安装的内容：

    - **发布版本**：构建的名称，以及它的描述、**发布版本 v{version}** 和 **由 {creator} 提供**。
    - **硬件**：适用于本计算机操作系统和 GPU 的构建目标，例如 NVIDIA 搭配 CUDA 12.8，并显示其发布版本。

    **名称** 输入框会建议构建的名称。
  </Step>
  <Step title="选择其他构建（可选）">
    点击 **更改** 以打开 **更改设置**。

    - **来源**：选择 **你团队的构建**。如果你尚未登录，浏览器会打开以便你登录，同时对话框会显示 **在浏览器中继续**。
    - **发布版本**：选择一个构建。列表只显示可安装在本计算机上的构建。点击 **在线查看构建**，在浏览器中打开 Developer Platform 上你工作区的构建，或点击 **刷新构建** 重新加载列表。
    - **硬件**：选择一个构建目标。系统会为你选择推荐用于本计算机的目标。

    在 Comfy Desktop 切换到工作区时，对话框会显示 **正在等待工作区授权……如果出现提示，请在浏览器中完成授权。**

    点击 **保存更改** 返回摘要。
  </Step>
  <Step title="安装构建">
    点击 **安装**。要查看安装进度，请参见[安装新构建](/zh/installation/desktop/usage/instance-management#安装新构建)。
  </Step>
</Steps>

安装完成后，**构建** 页面上的构建卡片会显示 **构建 v{version}**，即你安装的版本。如果该构建不在列表中，请参见[故障排除](#故障排除)。

## 更新团队构建

团队构建只会在其 Developer Platform Build 的各个版本之间迁移。当你的团队发布了更新的版本时，更新该构建即可获取该版本。其构建页面的**概览**标签页上会显示**构建版本**区域。

1. 在**侧边栏**中，点击团队构建以打开其构建页面。当有更新可用时，**概览**标签页会显示一个圆点，该构建的磁贴会显示**有更新可用**。
2. 在**概览**上，查看**构建版本**区域：**已安装**、**最新发布**、**上次检查**，以及**有更新可用**或**已是最新**。要再次检查，请点击**检查更新**。
3. 点击**更新至 v{version}**。你也可以在[快捷操作菜单](/zh/installation/desktop/usage/instance-management#从构建列表执行快捷操作)中选择**更新**。
4. 在**更新构建**对话框中，查看它将要迁移的版本，然后点击**立即更新**。

更新会用新版本替换该构建的环境，并保留你的工作流以及已经暂存的模型。更新运行期间，其进度会显示为**正在更新至 v{version}**。完成之后，**已安装**会显示新版本。

## 将构建上传到开发者平台

**Upload build**（上传构建）会基于此计算机上的构建启动开发者平台构建，这样你的工作区就可以发布它，你的团队也可以安装它。你需要先登录，并且该构建必须已安装在此计算机上。Comfy Cloud 和远程构建无法上传。

1. 在**侧边栏**中右键点击该构建，或者在 **Builds** 页面右键点击它的卡片，或在 **Home** 页面右键点击它的卡片。
2. 选择 **Upload build**。其提示文字为 **Upload this build to Comfy Developer Platform.**

在运行期间，该项目会显示为 **Creating…**。随后 Comfy Desktop 将会：

1. 保存该构建的手动快照。它会显示在构建的 **Snapshots** 标签页中。请参阅[保存和恢复快照](/zh/installation/desktop/usage/instance-management#保存和还原快照)。
2. 将快照作为草稿发送到开发者平台，存放在该构建所属的工作区中。位于**个人**工作区中的构建会被发送到你的**个人**工作区。
3. 在浏览器中打开该草稿，其中构建页面会显示 **Draft** 和 **Desktop snapshot received**。

在该草稿的某个版本被发布、并在开发者平台上完成构建之前，它不会出现在 **Your team's builds** 下。要发布它，请参阅[发布构建](/zh/development/deploy/cloud-custom-builds#发布-build)。

如果该构建上正在运行其他任务，**Upload build** 会呈灰色不可用。将指针悬停在其上可看到 **Wait for the current task on this build to finish.**

## 故障排除

<AccordionGroup>
  <Accordion title="发布版本显示 No compatible Builds are available to install.">
    Comfy Desktop 只有在 Developer Platform 构建的最新已发布版本已完成构建，并且存在适用于此计算机操作系统和 GPU 的构建时，才会列出该构建。请检查**侧边栏**中选定的工作区是否为你的团队所发布的工作区。点击**View builds online** 查看 Developer Platform 上的构建，然后点击**Refresh builds**。
  </Accordion>
  <Accordion title="对话框显示 Couldn't load builds. Retry">
    Comfy Desktop 无法加载你的工作区的构建。点击**Couldn't load builds. Retry** 以重新加载。
  </Accordion>
  <Accordion title="Could not upload build">
    **Could not upload build** 警报会说明原因，例如 **Could not create a draft in Comfy Developer Platform.**。再次选择**Upload build**。
  </Accordion>
</AccordionGroup>
