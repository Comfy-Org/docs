                },

上文中按模型给出的数量是合作伙伴的约束，而非本 Schema 的约束：media 上未声明
minItems/maxItems，因为每个模型允许的类型及其上限各不相同。Schema 接受并不
意味着提供商接受。反过来说，上文每项资产“最大 20MB”的数值（这是图像输入的上限，
而图像是唯一可以内联发送的输入）是合作伙伴对其最终获得的资产设定的上限，当资产
是公开 URL 时，这些数值按原样适用，因为这些字节从不经过 Comfy。内联的
data:\{MIME_type};base64,... URL 则会经过 Comfy，同时还要面对传输层上限：Comfy Router
POST 请求体总计上限为 100 MiB，超过即返回 413，而 base64 会让负载膨胀约 4/3，
因此单个内联资产只要超过约 75 MB，就会在触达此处任何合作伙伴规则之前被拒绝。
在这种大小下，单个资产按合作伙伴自身的20MB 的上限可以轻松容纳内联内容，因此对于单个资产，起约束作用的是合作伙伴规则。传输上限会约束多个资产，因为 100 MiB 的 Router 上限限制的是整个请求，而不是每个元素。接近这些上限的任何内容，请以公共 URL 发送。

<ParamField body="parameters.resolution" type="string">
  分辨率档位。支持的值因模型而异：
- wan2.5-i2v-preview：480P、720P、1080P
- wan2.6 模型（t2v、i2v、r2v）：仅 720P、1080P（不支持 480P）
- wan2.7 模型（i2v、t2v、r2v、videoedit）：720P、1080P（默认 1080P）
- wan3.0-video、wan3.0-video-prime：480P、720P、1080P（上游默认 1080P）
- happyhorse-1.0-*（t2v、i2v、r2v、video-edit）：720P、1080P
- happyhorse-1.1-*（t2v、i2v、r2v）：480P、720P、1080P
此代理会拒绝既未提供 resolution 也未提供 size 的视频生成请求，因为分辨率档位决定计费率。它会在检查前将 resolution 转为大写，并转发转为大写后的值，返回 400对于此枚举之外的值，并在上述列为不支持 480P 的 wan2.6、wan2.7 和 happyhorse-1.0 模型上，对 480P（无论是以 resolution 还是以 480P 的 size 发送）返回 400。

  可能的值：`480P`、`720P`、`1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  随机数种子，用于控制模型生成内容的随机性

  范围：`0` 到 `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  智能多镜头控制。仅在启用 prompt_extend 时生效。
适用于 wan2.6 和 wan2.7-r2v 模型。
- single：单镜头视频（默认）
- multi：多镜头视频

  可能的值：`multi`、`single`
</ParamField>

<ParamField body="parameters.size" type="string">
  视频分辨率，格式为宽度*高度。支持的分辨率因模型而异：
对于 wan2.5 T2V：480P（480*832、832*480、624*624）、720P、1080P 尺寸
对于 wan2.6 T2V/R2V（无 480P）：
  720P：1280*720、720*1280、960*960、1088*832、832*1088
  1080P：1920*1080、1080*1920、1440*1440、1632*1248、1248*1632
当同时发送 size 和 resolution 时，size 决定计费档位，而
resolution 仍必须是此代理针对该模型接受的值。对于 resolution 描述中列为不支持 480P 的每个模型，480P 的 size 会返回 400。
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  是否添加水印标识，水印位于右下角
</ParamField>
