<ParamField body="input.media" type="object[]">
  媒体资产列表。指定用于视频生成的参考资料（图像、音频、视频）。每个元素包含 type 和 url 字段。此字段由此组件提供的每个模型共享，而给定模型接受哪些 type 值，以及它是将图像或视频输入放在此处而不是放在 img_url 或 reference_video_urls 中，都因模型而异。各模型支持的 type 值：

- wan2.7-r2v：first_frame（可选，最大值 1）、reference_image、reference_video。至少需要一个 reference_image 或 reference_video，且参考图像加参考视频总共最多 5 个。first_frame 和 reference_image：JPEG/JPG/PNG/BMP/WEBP（无透明度通道），每边 240-8000 像素，宽高比在 1:8 到 8:1 之间，最多 20MB，可以是公开网址或 data:\{MIME_type};base64,... 网址。reference_video：公开 HTTP/HTTPS 网址；不接受内联 data: 网址。
- wan2.7-videoedit：video（恰好 1 个，即正在编辑的片段：MP4/MOV，2-10 秒，每边 240-4096 像素，最多 100MB，公开 HTTP/HTTPS 网址；不接受内联 data: 网址），外加可选的 0 到 4 个 reference_image（JPEG/JPG/PNG/BMP/WEBP，每边 240-8000 像素，宽高比在 1:8 到 8:1 之间，最多 20MB，可以是公开网址或 data:\{MIME_type};base64,... 网址）。
- wan3.0-video、wan3.0-video-prime：first_frame（最大值 1）、last_frame（最大值 1）、reference_image（最大值 10）、reference_video（最多 5 个片段，总时长 \<= 15 秒）、reference_audio（最多 5 个片段，总时长 \<= 15 秒）、file（最大值 1，不能与 link 一起使用）、link（最大值 1，不能与 file 一起使用）。reference_*/file/link 类型与 first_frame/last_frame 类型在同一请求中互斥。数组顺序决定提示中资产的参考顺序（Image 1、Video 1、Audio 1、...）。first_frame、last_frame 和 reference_image：JPEG/JPG/PNG/BMP/WEBP，每边 240-8000 像素，宽高比最大 8:1，最多 20MB，可以是公开网址或 data:\{MIME_type};base64,... 网址。reference_video、reference_audio、file 和 link：公开 HTTP/HTTPS 网址；不接受内联 data: 网址。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v：仅 first_frame，恰好 1 个。这些拼写在此处接收其首帧，而不是在 img_url 中。至少 300x300 像素，宽高比在 1:2.5 到 2.5:1 之间，JPEG/JPG/PNG/WEBP，最多 20MB，可以是公开网址或 data:\{MIME_type};base64,... 网址。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v：仅 reference_image，1 到 9 个。这是该模型唯一的参考输入。最短边至少 400 像素，JPEG/JPG/PNG/WEBP，最多 20MB，可以是公开网址或 data:\{MIME_type};base64,... 网址。reference_video 不是此操作的输入类型。
- happyhorse-1.0-video-edit：video（恰好 1 个，即正在编辑的片段：MP4/MOV，3-60 秒，长边最大 4096 像素，短边至少 360 像素，宽高比在 1:2.5 到 2.5:1 之间，最多 100MB，公开 HTTP/HTTPS 网址；不接受内联 data: 网址），外加可选的 0 到 5 个 reference_image（JPEG/JPG/PNG/WEBP，至少 300x300 像素，宽高比在 1:2.5 到 2.5:1 之间，最多 20MB，可以是公开网址或 data:\{MIME_type};base64,... 网址）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview：文生视频操作。其合作伙伴参考文档未记录任何媒体输入，因此请不要设置此字段。

上述各模型的数量是合作伙伴的约束，而非本 schema 的约束：media 上未声明 minItems/maxItems，因为可接受的类型及其上限因模型而异。Schema 接受并不意味着提供商接受。反过来说，上述每个资产的“最多 20MB”数值（图像输入的上限，也是唯一可以内联发送的输入）是合作伙伴对其最终获得的资产所设的上限，当资产是公开网址时，这些数值按字面适用，因为这些字节从不经过 Comfy。内联 data:\{MIME_type};base64,... 网址确实会经过 Comfy，并且也会遇到传输上限：Comfy Router POST 请求体总计上限为 100 MiB，超过则返回 413，而 base64 会使负载膨胀约 4/3，因此任何单个内联资产只要超过约 75 MB，就会在触达此处任何合作伙伴规则之前被拒绝。在该大小下，单个资产在合作伙伴自身的20MB 上限可轻松容纳内联数据，因此对于单个资产而言，真正起约束作用的是合作伙伴规则；而在多个资产的情况下，起约束作用的则是传输上限，因为 100 MiB 的 Router 上限约束的是整个请求，而不是每个元素。任何接近这些上限的内容，请以公开 URL 的形式发送。

<ParamField body="parameters.ratio" type="string">
  已生成视频的宽高比。仅适用于 wan2.7 和 wan3.0 模型。
对于 wan2.7 模型，若未提供，则根据分辨率档位取默认值。
对于 wan3.0-video，adaptive（默认值）会根据输入媒体的比例和意图自动推荐合适的宽高比。

  可选值：`adaptive`、`16:9`、`9:16`、`1:1`、`4:3`、`3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  分辨率档位。支持的值因模型而异：
- wan2.5-i2v-preview：480P、720P、1080P
- wan2.6 模型（t2v、i2v、r2v）：仅 720P、1080P（不支持 480P）
- wan2.7 模型（i2v、t2v、r2v、videoedit）：720P、1080P（默认 1080P）
- wan3.0-video、wan3.0-video-prime: 480P、720P、1080P（上游默认 1080P）
- happyhorse-1.0-*（t2v、i2v、r2v、video-edit）: 720P、1080P
- happyhorse-1.1-*（t2v、i2v、r2v）: 480P、720P、1080P

该代理会拒绝既未提供 resolution 也未提供 size 的视频生成请求，因为分辨率档位决定了计费费率。它会在检查之前将 resolution 转为大写，并转发大写后的值；对于超出该枚举范围的值返回 400；对于上文中列为不支持 480P 的 wan2.6、wan2.7 和 happyhorse-1.0 模型，请求 480P（无论以 resolution 还是以 480P 的 size 发送）时返回 400。

  可选值: `480P`, `720P`, `1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  随机数种子，用于控制模型生成内容的随机性

  范围: `0` 到 `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  智能多镜头控制。仅在启用 prompt_extend 时生效。适用于 wan2.6 和 wan2.7-r2v 模型。
- single: 单镜头视频（默认）
- multi: 多镜头视频

  可选值: `multi`, `single`
</ParamField>

<ParamField body="parameters.size" type="string">
  视频分辨率，格式为 width*height。支持的分辨率因模型而异：
对于 wan2.5 T2V：480P（480*832、832*480、624*624）、720P、1080P 尺寸
对于 wan2.6 T2V/R2V（无 480P）：
  720P: 1280*720, 720*1280, 960*960, 1088*832, 832*1088
  1080P: 1920*1080, 1080*1920, 1440*1440, 1632*1248, 1248*1632
当同时发送 size 和 resolution 时，由 size 决定计费档位，而 resolution 仍必须是该代理针对该模型接受的值。在任何被 resolution 描述列为不支持 480P 的模型上，480P 的 size 都会返回 400。
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  是否添加水印标识，水印位于右下角
</ParamField>

由 Router 在 `GET /v2/models/wan/wan3.0-video/openapi.json` 提供的 schema 生成，该 schema 也是它在请求到达提供商之前用于校验调用的同一份文档。
