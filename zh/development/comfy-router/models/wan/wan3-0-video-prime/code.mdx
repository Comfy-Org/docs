import asyncio
from comfy_sdk import AsyncComfy

# 从环境变量中读取 COMFY_API_KEY。
# 每次 submit() 调用都会生成自己的 Idempotency-Key，并在自动重试时复用它。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/wan3.0-video-prime",
            {
                "input": {
                    "prompt": "a single red maple leaf falling onto still water, slow motion, shallow depth of field",
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # 配合模型 ID，这就是另一个进程所需的全部信息

        # 轮询直到请求完成，每次等待服务器指定的 Retry-After。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # 提供商自己的负载，与 models.run() 返回的值相同。
        # 失败或已取消的请求会在这里抛出类型化的 Router 错误。
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())

minItems/maxItems，因为可接受的类型及其上限因模型而异。接受 schema 并不代表提供商接受；
反过来说，上面每个资产“最多 20MB”的数字（即图像输入的上限，而图像输入是唯一可以内联发送的
输入）是合作伙伴对其最终获得资产的上限，当资产是公开 URL 时这些限制按字面生效，因为那些字节
从不经过 Comfy。内联的 data:\{MIME_type};base64,... URL 则确实会经过 Comfy，并且还会遇到传输
上限：Comfy Router 的 POST 请求体总量上限为 100 MiB，超过则返回 413，而 base64 会将负载膨胀约
4/3，因此单个超过约 75 MB 的内联资产会在触及这里任何合作伙伴规则之前就被拒绝。在这一大小下，
单个资产按合作伙伴自身的
20MB 上限能轻松容纳内联内容，因此对于单个资产而言，起约束作用的是合作伙伴规则；
而当涉及多个资产时，起约束作用的则是传输上限，因为 100 MiB 的 Router 上限约束的是
整个请求，而不是其中的每个元素。凡接近这些上限的内容，请以
公开 URL 的形式发送。

resolution 仍必须是此代理为该模型接受的值。若 size 为 480P，则在上文 resolution
