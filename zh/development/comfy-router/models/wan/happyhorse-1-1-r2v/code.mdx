<ParamField body="input.img_url" type="string">
  首帧图像的 URL 或 Base64 编码数据。对于 wan2.5-i2v-preview 和
wan2.6-i2v 模型为必填。happyhorse-1.x 的 i2v 拼写不在这里取首帧，
它们将首帧作为类型为 first_frame 的媒体元素传入（见下文 media），并且在
wan2.6-i2v 上能成功的 img_url 请求体，在 happyhorse-1.0-i2v 和
happyhorse-1.1-i2v 上会被提供商拒绝；而 wan2.7/wan3.0 的拼写同样在
media 中传入它们的参考资产。图像格式：JPEG、JPG、PNG、BMP、WEBP。
分辨率：360-2000 像素。文件大小：最大 10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  媒体资产列表。指定用于视频生成的参考素材（图像、音频、视频）。
每个元素包含一个 type 字段和一个 url 字段。该字段由此组件所服务的每个
模型共用，而某个给定模型接受哪些 type 值，以及它究竟是在这里承载其图像或视频
输入而不是放在 img_url 或 reference_video_urls 中，都因模型而异。各模型支持的
type 值如下：
- wan2.7-i2v：first_frame、last_frame、driving_audio、first_clip。first_frame 和
  last_frame：JPEG/JPG/PNG/BMP/WEBP，每边 240-8000 像素，宽高比在 1:8
  与 8:1 之间，最大 20MB，公开 URL 或 data:\{MIME_type};base64,... URL。
  driving_audio（WAV/MP3，2-30 秒，最大 15MB）和 first_clip（MP4/MOV，2-10
  秒，每边 240-4096 像素，最大 100MB）：公开 HTTP/HTTPS URL；不接受内联
  data: URL。
- wan2.7-r2v：first_frame（可选，最多 1 个）、reference_image、reference_video。至少
  需要一个 reference_image 或 reference_video，且参考图像加上
  参考视频总共最多 5 个。first_frame 和 reference_image：JPEG/JPG/PNG/BMP/WEBP
  （无 alpha 通道），每边 240-8000 像素，宽高比在 1:8 与 8:1 之间，最大
  20MB，公开 URL 或 data:\{MIME_type};base64,... URL。reference_video：公开
  HTTP/HTTPS URL；不接受内联 data: URL。
- wan2.7-videoedit：video（正好 1 个，即正在编辑的片段：MP4/MOV，2-10 秒，
  每边 240-4096 像素，最大 100MB，公开 HTTP/HTTPS URL；不接受内联 data: URL）
  外加可选的 0 到 4 个 reference_image（JPEG/JPG/PNG/BMP/WEBP，
  每边 240-8000 像素，宽高比在 1:8 与 8:1 之间，最大 20MB，公开 URL
  或 data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime：first_frame（最多 1 个）、last_frame（最多 1 个）、
  reference_image（最多 10 个）、reference_video（最多 5 段，总时长 \<= 15s）、
  reference_audio（最多 5 段，总时长 \<= 15s）、file（最多 1 个，不能
  与 link 一起使用）、link（最多 1 个，不能与 file 一起使用）。reference_*/file/link
  类型与 first_frame/last_frame 类型在同一请求中互斥。数组顺序
  决定提示中资产的参考顺序（Image 1、Video 1、Audio 1 等）。first_frame、
  last_frame 和 reference_image：JPEG/JPG/PNG/BMP/WEBP，
  每边 240-8000 像素，宽高比至多 8:1，最大 20MB，公开 URL 或
  data:\{MIME_type};base64,... URL。reference_video、reference_audio、file 和 link：公开
  HTTP/HTTPS URL；不接受内联 data: URL。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v：仅 first_frame，且正好 1 个。这些拼写
  在这里取首帧，而不是在 img_url 中。至少 300x300 像素，宽高比
  在 1:2.5 与 2.5:1 之间，JPEG/JPG/PNG/WEBP，最大 20MB，公开 URL 或
  data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v：仅 reference_image，1 到 9 个。这是
  该模型唯一的参考输入。最短边至少 400 像素，JPEG/JPG/PNG/WEBP，
  最大 20MB，公开 URL 或 data:\{MIME_type};base64,... URL。reference_video
  不是此操作的输入类型。
- happyhorse-1.0-video-edit：video（正好 1 个，即正在编辑的片段：MP4/MOV，3-60
  秒，长边最多 4096 像素，短边至少 360 像素，宽高
  比在 1:2.5 与 2.5:1 之间，最大 100MB，公开 HTTP/HTTPS URL；不接受内联 data:
  URL）外加可选的 0 到 5 个 reference_image（JPEG/JPG/PNG/WEBP，至少
  300x300 像素，宽高比在 1:2.5 与 2.5:1 之间，最大 20MB，公开 URL
  或 data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview：
  文生视频操作。其对应的合作伙伴参考文档未记录任何媒体输入，因此请
  不要设置此字段。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v：此组件未为这些拼写枚举任何媒体
  词汇。wan2.5-i2v-preview 和 wan2.6-i2v 在 img_url 中取
  首帧；wan2.6-r2v 在 reference_video_urls 中取参考片段。
上文按模型列出的数量是合作伙伴的限制，而不是本 schema 的限制：media 上
未声明 minItems/maxItems，因为可接受的类型及其上限因模型而异。schema 接受
并不意味着提供商接受；反过来说，上文每项资产“最大 20MB”的数字
（图像输入的上限，而图像输入是唯一可以内联发送的输入）是合作伙伴对其最终
得到的资产所设的上限，当资产是公开 URL 时，这些数字按字面适用，
因为这些字节从不经过 Comfy 传输。内联的 data:\{MIME_type};base64,...
URL 确实要经过 Comfy 传输，并且也会遇到传输上限：Comfy Router
POST 正文总计上限为 100 MiB，超过则返回 413，而 base64 会使载荷膨胀
约 4/3，因此单个内联资产一旦超过大约 75 MB，就会在触及这里的任何
合作伙伴规则之前被拒绝。在该大小下，单个资产按合作伙伴自身的20MB 的上限足以轻松容纳内联数据，因此对于单个资产而言，真正起约束作用的是合作伙伴侧的规则；而涉及多个资产时，约束则来自传输上限，因为 Router 的 100 MiB 上限限制的是整个请求，而不是其中的每个元素。任何接近这些上限的内容，请以公共 URL 发送。

- happyhorse-1.0-*（t2v、i2v、r2v、video-edit）：720P、1080P
- happyhorse-1.1-*（t2v、i2v、r2v）：480P、720P、1080P

本代理会拒绝既未提供 resolution 也未提供 size 的视频生成请求，因为分辨率档位决定计费费率。它会在检查之前将 resolution 转为大写并转发大写后的值；对于超出该枚举范围的值返回 400；对于上方列出的、标注为不支持 480P 的 wan2.6、wan2.7 和 happyhorse-1.0 模型，只要传入 480P（无论以 resolution 还是 480P 的 size 形式传入）就返回 400。

  可选值：`480P`、`720P`、`1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  随机数种子，用于控制模型生成内容的随机性

  范围：`0` 到 `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  智能多镜头控制。仅在启用 prompt_extend 时生效。适用于 wan2.6 和 wan2.7-r2v 模型。
- single：单镜头视频（默认）
- multi：多镜头视频

  可选值：`multi`、`single`
</ParamField>

<ParamField body="parameters.size" type="string">
  视频分辨率，格式为宽度*高度。支持的分辨率因模型而异：
对于 wan2.5 T2V：480P（480*832、832*480、624*624）、720P、1080P 尺寸
对于 wan2.6 T2V/R2V（无 480P）：
  720P：1280*720、720*1280、960*960、1088*832、832*1088
  1080P：1920*1080、1080*1920、1440*1440、1632*1248、1248*1632
当同时发送 size 和 resolution 时，由 size 决定计费档位，而 resolution 仍必须是本代理为该模型接受的值。对于分辨率说明中列出为不支持 480P 的每个模型，480P 的 size 都会返回 400。
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  是否添加水印 logo，水印位于右下角
</ParamField>
