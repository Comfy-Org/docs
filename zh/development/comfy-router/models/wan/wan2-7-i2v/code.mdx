        handle = await client.models.submit(

                    ],
                },

                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )

        # 轮询直到请求完成，按服务器给出的 Retry-After 等待。
        async for update in handle.iter_events():

        # 失败或已取消的请求会在此处抛出类型化的 Router 错误。
        result = await handle.get()

<ParamField body="input.img_url" type="string">
  首帧图像 URL 或 Base64 编码数据。对于 wan2.5-i2v-preview 和 wan2.6-i2v 模型为必填。happyhorse-1.x 的 i2v 写法**不**在这里传入首帧：它们将首帧作为 type 为 first_frame 的媒体元素传入（见下方 media），并且在 wan2.6-i2v 上能够成功的 img_url 请求体，在 happyhorse-1.0-i2v 和 happyhorse-1.1-i2v 上会被提供商拒绝；wan2.7/wan3.0 的写法同样在 media 中传入其参考资产。图像格式：JPEG、JPG、PNG、BMP、WEBP。分辨率：360-2000 像素。文件大小：最大 10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  媒体资产列表。指定用于视频生成的参考资料（图像、音频、视频）。每个元素包含 type 和 url 字段。该字段由本组件提供的所有模型共用，而某个模型接受哪些 type 值，以及它是将图像或视频输入放在这里，还是放在 img_url 或 reference_video_urls 中，均因模型而异。各模型支持的 type 值：
- wan2.7-i2v：first_frame、last_frame、driving_audio、first_clip。first_frame 和 last_frame：JPEG/JPG/PNG/BMP/WEBP，每边 240-8000 像素，宽高比在 1:8 到 8:1 之间，最大 20MB，支持公网 URL 或 data:\{MIME_type};base64,... URL。driving_audio（WAV/MP3，2-30 秒，最大 15MB）和 first_clip（MP4/MOV，2-10 秒，每边 240-4096 像素，最大 100MB）：公网 HTTP/HTTPS URL；不接受内联 data: URL。
- wan2.7-r2v：first_frame（可选，最多 1 个）、reference_image、reference_video。至少需要 1 个 reference_image 或 reference_video，且参考图像加参考视频总计最多 5 个。first_frame 和 reference_image：JPEG/JPG/PNG/BMP/WEBP（无透明度通道），每边 240-8000 像素，宽高比在 1:8 到 8:1 之间，最大 20MB，支持公网 URL 或 data:\{MIME_type};base64,... URL。reference_video：公网 HTTP/HTTPS URL；不接受内联 data: URL。
- wan2.7-videoedit：video（恰好 1 个，即被编辑的片段：MP4/MOV，2-10 秒，每边 240-4096 像素，最大 100MB，公网 HTTP/HTTPS URL；不接受内联 data: URL），外加可选的 0 到 4 个 reference_image（JPEG/JPG/PNG/BMP/WEBP，每边 240-8000 像素，宽高比在 1:8 到 8:1 之间，最大 20MB，支持公网 URL 或 data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime：first_frame（最多 1 个）、last_frame（最多 1 个）、reference_image（最多 10 个）、reference_video（最多 5 个片段，总时长 \<= 15s）、reference_audio（最多 5 个片段，总时长 \<= 15s）、file（最多 1 个，不能与 link 同时使用）、link（最多 1 个，不能与 file 同时使用）。在同一请求中，reference_*/file/link 类型与 first_frame/last_frame 类型互斥。数组顺序决定提示词中资产的参考顺序（Image 1、Video 1、Audio 1……）。first_frame、last_frame 和 reference_image：JPEG/JPG/PNG/BMP/WEBP，每边 240-8000 像素，宽高比最大 8:1，最大 20MB，支持公网 URL 或 data:\{MIME_type};base64,... URL。reference_video、reference_audio、file 和 link：公网 HTTP/HTTPS URL；不接受内联 data: URL。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v：仅 first_frame，恰好 1 个。这些写法在这里传入首帧，而不是在 img_url 中传入。至少 300x300 像素，宽高比在 1:2.5 到 2.5:1 之间，JPEG/JPG/PNG/WEBP，最大 20MB，支持公网 URL 或 data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v：仅 reference_image，数量为 1 到 9 个。这是该模型唯一的参考输入。最短边至少 400 像素，JPEG/JPG/PNG/WEBP，最大 20MB，支持公网 URL 或 data:\{MIME_type};base64,... URL。对于该操作，reference_video 不是输入类型。
- happyhorse-1.0-video-edit：video（恰好 1 个，即被编辑的片段：MP4/MOV，3-60 秒，长边最大 4096 像素，短边至少 360 像素，宽高比在 1:2.5 到 2.5:1 之间，最大 100MB，公网 HTTP/HTTPS URL；不接受内联 data: URL），外加可选的 0 到 5 个 reference_image（JPEG/JPG/PNG/WEBP，至少 300x300 像素，宽高比在 1:2.5 到 2.5:1 之间，最大 20MB，支持公网 URL 或 data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview：文生视频操作。其对应的合作伙伴参考文档未记载任何媒体输入，因此请勿设置该字段。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v：本组件未为这些写法列举任何媒体词汇。wan2.5-i2v-preview 和 wan2.6-i2v 在 img_url 中传入其首帧；wan2.6-r2v 在 reference_video_urls 中传入其参考片段。
上述各模型的数量限制属于合作伙伴的约束，而非本 Schema 的约束：media 上未声明 minItems/maxItems，因为可接受的类型及其上限因模型而异。Schema 校验通过并不意味着提供商会接受；反过来，上述每个资产"最大 20MB"的数值（图像输入即唯一可能以内联方式发送的输入的上限）是合作伙伴对其最终收到的资产所设的上限，当资产是公网 URL 时，这些限制按字面生效，因为这些字节从不经过 Comfy 传输。内联 data:\{MIME_type};base64,... URL 确实会经过 Comfy 传输，因此还要面对一层传输上限：Comfy Router 的 POST 请求体总计上限为 100 MiB，超过即返回 413，而 base64 会使载荷膨胀约 4/3，因此单个内联资产若超过约 75 MB，就会在触及此处任何合作伙伴规则之前被拒绝。在这种大小下，单个资产按合作伙伴自身20MB 的上限单靠内联方式就能轻松容纳，因此对于单个资产来说，真正起约束作用的是合作伙伴的规则；而跨多个资产时，起约束作用的则是传输上限，因为 100 MiB 的 Router 上限约束的是整个请求，而不是其中每个元素。接近这些上限的任何内容都请以公共 URL 发送。

<ParamField body="parameters.resolution" type="string">

- wan2.5-i2v-preview: 480P、720P、1080P
- wan2.6 模型（t2v、i2v、r2v）：仅 720P、1080P（不支持 480P）
- wan2.7 模型（i2v、t2v、r2v、videoedit）：720P、1080P（默认 1080P）
- wan3.0-video、wan3.0-video-prime：480P、720P、1080P（上游默认 1080P）
- happyhorse-1.0-*（t2v、i2v、r2v、video-edit）：720P、1080P
- happyhorse-1.1-*（t2v、i2v、r2v）：480P、720P、1080P
该代理会拒绝既未提供 resolution 也未提供 size 的视频生成请求，因为分辨率档位决定计费费率。它在检查前会先将 resolution 转为大写，并转发大写形式的值；对于超出该枚举范围的取值返回 400，并且对于上文列为不支持 480P 的 wan2.6、wan2.7 和 happyhorse-1.0 模型，会针对 480P 返回 400（无论是以 resolution 还是以 480P 的 size 形式发送）。

  可选值：`480P`、`720P`、`1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  随机数种子，用于控制模型生成内容的随机性

  范围：`0` 到 `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  智能多镜头控制。仅在启用 prompt_extend 时生效。
适用于 wan2.6 和 wan2.7-r2v 模型。
- single: 单镜头视频（默认）
- multi: 多镜头视频

  可选值：`multi`、`single`
</ParamField>

<ParamField body="parameters.size" type="string">
  视频分辨率，格式为 宽*高。支持的分辨率因模型而异：
wan2.5 T2V：480P（480*832、832*480、624*624）、720P、1080P 尺寸
wan2.6 T2V/R2V（无 480P）：
  720P：1280*720、720*1280、960*960、1088*832、832*1088
  1080P：1920*1080、1080*1920、1440*1440、1632*1248、1248*1632
当同时发送 size 和 resolution 时，由 size 决定计费档位，而 resolution 仍必须是该代理针对该模型接受的取值。对于分辨率描述中列为不支持 480P 的每个模型，480P 的 size 都会返回 400。
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  是否添加水印 logo，水印位于右下角
</ParamField>
