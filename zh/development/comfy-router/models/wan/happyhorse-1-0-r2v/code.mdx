  媒体资产列表。指定用于视频生成的参考素材（图像、音频、视频）。
每个元素包含 type 和 url 字段。此字段由此组件提供的每个
模型共享，而某个模型接受哪些 type 值（以及它是否在此处而非

  HTTP/HTTPS 网址；内联 data: 网址不被接受。
- wan2.7-videoedit：video（恰好 1 个，即正在编辑的片段：MP4/MOV，2-10 秒，

  不被接受），外加可选的 0 到 4 个 reference_image（JPEG/JPG/PNG/BMP/WEBP，
  每边 240-8000 像素，宽高比在 1:8 到 8:1 之间，最大 20MB，公共网址
  或 data:\{MIME_type};base64,... 网址）。
- wan3.0-video、wan3.0-video-prime：first_frame（最多 1 个）、last_frame（最多 1 个）、
  reference_image（最多 10 个）、reference_video（最多 5 个片段，总时长 \<= 15s）、
  reference_audio（最多 5 个片段，总时长 \<= 15s）、file（最多 1 个，不能
  与 link 一起使用）、link（最多 1 个，不能与 file 一起使用）。reference_*/file/link 类型
  与 first_frame/last_frame 类型在同一请求中互斥。数组
  顺序定义提示词中资产的参考顺序（Image 1、Video 1、
  Audio 1、...）。first_frame、last_frame 和 reference_image：JPEG/JPG/PNG/BMP/WEBP，
  每边 240-8000 像素，宽高比最多 8:1，最大 20MB，公共网址或

  data:\{MIME_type};base64,... 网址。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v：仅 reference_image，1 到 9 个。这是
  该模型唯一的参考输入。最短边至少 400 像素，JPEG/JPG/PNG/WEBP，
  最大 20MB，公共网址或 data:\{MIME_type};base64,... 网址。reference_video
  不是此操作的输入类型。
- happyhorse-1.0-video-edit：video（恰好 1 个，即正在编辑的片段：MP4/MOV，3-60
  秒，较长边最多 4096 像素，较短边至少 360 像素，宽高比
  在 1:2.5 到 2.5:1 之间，最大 100MB，公共 HTTP/HTTPS 网址；内联 data:
  网址不被接受），外加可选的 0 到 5 个 reference_image（JPEG/JPG/PNG/WEBP，至少
  300x300 像素，宽高比在 1:2.5 到 2.5:1 之间，最大 20MB，公共网址
  或 data:\{MIME_type};base64,... 网址）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview：
  文生视频操作。它们的合作伙伴参考文档未记录任何 media 输入，因此请保持
  此字段未设置。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v：此组件未为这些写法列举任何 media
  词汇。wan2.5-i2v-preview 和 wan2.6-i2v 在 img_url 中接收其首帧；
  wan2.6-r2v 在 reference_video_urls 中接收其参考片段。
上述按模型列出的数量是合作伙伴的约束，而不是此 schema 的约束：media 上
未声明任何 minItems/maxItems，因为可接受的类型及其上限
因模型而异。Schema 接受并不意味着提供商接受；反过来说，
上述每项资产“最大 20MB”的数值（图像输入的上限，也是唯一
可以内联发送的输入）是合作伙伴对其最终获得的资产所设的上限，
当资产是公共网址时它们按原文适用，因为这些字节从不经过 Comfy 传输。
内联的 data:\{MIME_type};base64,... 网址确实会经过 Comfy 传输，并且同样会遇到传输上限：
Comfy Router 的 POST 请求体总计上限为 100 MiB，超过即返回 413，
而 base64 会使负载膨胀约 4/3，因此单个内联资产超过约 75 MB 时，
会在触及此处任何合作伙伴规则之前就被拒绝。在该大小下，单个资产按合作伙伴自身的20MB 的上限可以轻松容纳内联数据，因此对于单个资产而言，真正起约束作用的是合作伙伴规则；而涉及多个资产时则受传输上限约束，因为 100 MiB 的 Router 上限约束的是整个请求，而不是其中的每个元素。接近这些上限的任何内容都应以公共 URL 的形式发送。

  分辨率档位。支持的值因模型而异：
- wan2.5-i2v-preview：480P、720P、1080P
- wan2.6 模型（t2v、i2v、r2v）：仅 720P、1080P（不支持 480P）
- wan2.7 模型（i2v、t2v、r2v、videoedit）：720P、1080P（默认 1080P）
- wan3.0-video, wan3.0-video-prime: 480P, 720P, 1080P（上游默认 1080P）
- happyhorse-1.0-*（t2v、i2v、r2v、video-edit）: 720P, 1080P
- happyhorse-1.1-*（t2v、i2v、r2v）: 480P, 720P, 1080P

该代理会拒绝既未提供 resolution 也未提供 size 的视频生成请求，因为分辨率档位决定计费费率。它会在检查之前将 resolution 转换为大写，并转发大写后的值；对于不在此枚举范围内的值返回 400；对于上方列出、说明不支持 480P 的 wan2.6、wan2.7 和 happyhorse-1.0 模型，无论是以 resolution 还是以 480P 的 size 形式发送，均返回 400。

  可选值：`480P`、`720P`、`1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  随机数种子，用于控制模型所生成内容的随机性

  范围：`0` 到 `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  智能多镜头控制。仅在启用 prompt_extend 时生效。适用于 wan2.6 和 wan2.7-r2v 模型。
- single: 单镜头视频（默认）
- multi: 多镜头视频

  可选值：`multi`、`single`
</ParamField>

<ParamField body="parameters.size" type="string">
  视频分辨率，格式为 宽度*高度。支持的分辨率因模型而异：
对于 wan2.5 T2V：480P（480*832、832*480、624*624）、720P、1080P 尺寸
对于 wan2.6 T2V/R2V（不支持 480P）：
  720P：1280*720、720*1280、960*960、1088*832、832*1088
  1080P：1920*1080、1080*1920、1440*1440、1632*1248、1248*1632
同时发送 size 和 resolution 时，由 size 决定计费档位，而 resolution 仍必须是该代理为此模型接受的值。在 resolution 描述中列为不支持 480P 的每个模型上，480P 的 size 都会返回 400。
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">

</ParamField>
