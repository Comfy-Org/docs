import asyncio
from comfy_sdk import AsyncComfy

# 从环境变量中读取 COMFY_API_KEY。
# 每次 submit() 调用都会生成自己的 Idempotency-Key，并在自动重试时复用它。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/wan2.6-r2v",
            {
                "input": {
                    "prompt": "character1 walks in from the left, turns to the camera and waves, plain orange backdrop",
                    "reference_video_urls": ["https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/street_dancer.mp4"],
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # 加上模型 ID，就是另一个进程所需的全部内容

        # 轮询直到请求完成，每轮按服务器指定的 Retry-After 等待。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # 提供商自身的响应载荷，与 models.run() 返回的值相同。
        # 失败或已取消的请求会在此处抛出类型化的 Router 错误。
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())

  音频文件下载 URL。支持的格式：mp3 和 wav。不能与 reference_video_urls 一起使用。
</ParamField>

<ParamField body="input.img_url" type="string">
  首帧图像 URL 或 Base64 编码数据。wan2.5-i2v-preview 和
wan2.6-i2v 模型必填。happyhorse-1.x 的 i2v 拼写并不在此处传入首帧：它们将其作为
类型为 first_frame 的媒体元素传入（参见下面的 media），并且在
wan2.6-i2v 上能成功的 img_url 请求体，会被提供商在
happyhorse-1.0-i2v 和 happyhorse-1.1-i2v 上拒绝；而 wan2.7/wan3.0 的拼写同样在
media 中传入其参考资产。图像格式：JPEG、JPG、PNG、BMP、WEBP。
分辨率：360-2000 像素。文件大小：最大 10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  媒体资产列表。用于指定视频生成的参考素材（图像、音频、视频）。
每个元素包含 type 和 url 字段。该字段由此组件提供的所有
模型共用，而某个模型接受哪些 type 值，以及它的图像或视频输入是否完全在此处
而非在 img_url 或 reference_video_urls 中传入，都因模型而异。各模型支持的
type 值如下：
- wan2.7-i2v：first_frame、last_frame、driving_audio、first_clip。first_frame 和
  last_frame：JPEG/JPG/PNG/BMP/WEBP，每边 240-8000 像素，宽高比在 1:8
  到 8:1 之间，最大 20MB，可使用公开 URL 或 data:\{MIME_type};base64,... URL。
  driving_audio（WAV/MP3，2-30 秒，最大 15MB）和 first_clip（MP4/MOV，2-10
  秒，每边 240-4096 像素，最大 100MB）：公开 HTTP/HTTPS URL；不接受
  内联的 data: URL。
- wan2.7-r2v：first_frame（可选，最多 1 个）、reference_image、reference_video。至少
  需要提供 1 个 reference_image 或 reference_video，并且参考图像加
  参考视频总计最多 5 个。first_frame 和 reference_image：JPEG/JPG/PNG/BMP/WEBP
  （无透明度通道），每边 240-8000 像素，宽高比在 1:8 到 8:1 之间，最大
  20MB，可使用公开 URL 或 data:\{MIME_type};base64,... URL。reference_video：公开
  HTTP/HTTPS URL；不接受内联的 data: URL。
- wan2.7-videoedit：video（恰好 1 个，即被编辑的片段：MP4/MOV，2-10 秒，
  每边 240-4096 像素，最大 100MB，公开 HTTP/HTTPS URL；不接受内联的 data: URL）
  外加可选的 0 到 4 个 reference_image（JPEG/JPG/PNG/BMP/WEBP，
  每边 240-8000 像素，宽高比在 1:8 到 8:1 之间，最大 20MB，可使用公开 URL
  或 data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime：first_frame（最多 1 个）、last_frame（最多 1 个）、
  reference_image（最多 10 个）、reference_video（最多 5 个片段，总时长 \<= 15s）、
  reference_audio（最多 5 个片段，总时长 \<= 15s）、file（最多 1 个，不能
  与 link 一起使用）、link（最多 1 个，不能与 file 一起使用）。reference_*/file/link
  类型与 first_frame/last_frame 类型在同一请求中互斥。
  数组顺序定义了提示词中资产的参考顺序（Image 1、Video 1、
  Audio 1……）。first_frame、last_frame 和 reference_image：JPEG/JPG/PNG/BMP/WEBP，
  每边 240-8000 像素，宽高比最多 8:1，最大 20MB，可使用公开 URL 或
  data:\{MIME_type};base64,... URL。reference_video、reference_audio、file 和 link：
  公开 HTTP/HTTPS URL；不接受内联的 data: URL。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v：仅 first_frame，恰好 1 个。这些拼写
  在此处传入其首帧，而不是在 img_url 中。至少 300x300 像素，宽高比
  在 1:2.5 到 2.5:1 之间，JPEG/JPG/PNG/WEBP，最大 20MB，可使用公开 URL 或
  data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v：仅 reference_image，1 到 9 个。这是
  该模型唯一的参考输入。最短边至少 400 像素，JPEG/JPG/PNG/WEBP，
  最大 20MB，可使用公开 URL 或 data:\{MIME_type};base64,... URL。reference_video
  不是此操作的输入类型。
- happyhorse-1.0-video-edit：video（恰好 1 个，即被编辑的片段：MP4/MOV，3-60
  秒，较长边最多 4096 像素，较短边至少 360 像素，宽高比
  在 1:2.5 到 2.5:1 之间，最大 100MB，公开 HTTP/HTTPS URL；不接受内联的 data:
  URL）外加可选的 0 到 5 个 reference_image（JPEG/JPG/PNG/WEBP，至少
  300x300 像素，宽高比在 1:2.5 到 2.5:1 之间，最大 20MB，可使用公开 URL
  或 data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview：
  文生视频操作。其合作伙伴参考文档未记载任何 media 输入，因此请
  不要设置此字段。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v：本组件未为这些拼写列举任何 media
  词汇。wan2.5-i2v-preview 和 wan2.6-i2v 在 img_url 中传入其首帧；
  wan2.6-r2v 在 reference_video_urls 中传入其参考片段。
上文中各模型的数量限制是合作伙伴的约束，而不是本 schema 的约束：media 上未声明
minItems/maxItems，因为可接受的类型及其上限因模型而异。schema 接受并不
意味着提供商接受；反过来，上文中每个资产“最大 20MB”的数值（即
图像输入的上限，也是唯一可以内联发送的输入）是合作伙伴对其最终获得的
资产设定的上限；当资产是公开 URL 时，这些数值按字面适用，
因为这些字节从不经过 Comfy。内联的 data:\{MIME_type};base64,...
URL 确实会经过 Comfy，并且也会遇到传输上限：Comfy Router 的
POST 请求体总计上限为 100 MiB，超过即返回 413，而 base64 会将
载荷膨胀约 4/3，因此单个内联资产若超过约 75 MB，就会在触及这里的任何
合作伙伴规则之前被拒绝。在达到该大小时，单个资产按合作伙伴自身的20MB 的上限可以轻松容纳内联内容，因此对于单个资产而言，真正起约束作用的是合作伙伴规则；而跨多个资产时，起约束作用的则是传输上限，因为 100 MiB 的 Router 上限约束的是整个请求，而不是其中的每个元素。凡是接近这些上限的内容，请以公开 URL 的形式发送。
