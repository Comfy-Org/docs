</ParamField>

<ParamField body="input.audio_url" type="string">
  音频文件下载网址。支持的格式：mp3 和 wav。不能与 reference_video_urls 一起使用。
</ParamField>

<ParamField body="input.img_url" type="string">
  首帧图像网址或 Base64 编码数据。
仅 wan2.5-i2v-preview 和 wan2.6-i2v 模型必填。happyhorse-1.x 的 i2v
拼写不在此处接收首帧：它们将首帧作为类型为 `first_frame` 的 `media`
元素传入（参见下方的 `media`），而在 wan2.6-i2v 上能够成功提交的
`img_url` 请求体，在 happyhorse-1.0-i2v 和 happyhorse-1.1-i2v 上会被
提供商拒绝。
图像格式：JPEG、JPG、PNG、BMP、WEBP。分辨率：360-2000 像素。
文件大小：最大值 10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  用于 wan2.7、wan3.0 和 happyhorse-1.x 模型的媒体资产列表。指定用于视频生成
的参考素材（图像、音频、视频）。每个元素包含一个 type 和
url 字段。
支持的 type 值因模型而异：
- wan2.7-i2v：first_frame、last_frame、driving_audio、first_clip
- wan2.7-r2v：reference_image、reference_video
- wan2.7-videoedit：video、reference_image
- wan3.0-video：first_frame（最大值 1）、last_frame（最大值 1）、reference_image（最大值 10）、
  reference_video（最大值 5 个片段，总时长 \<= 15s）、reference_audio（最大值 5 个片段，
  总时长 \<= 15s）、file（最大值 1，不能与 link 一起使用）、link（最大值 1，不能
  与 file 一起使用）。在同一请求中，reference_*/file/link 类型与 first_frame/last_frame
  类型互斥。数组的顺序定义了提示中资产的参考
  顺序（Image 1、Video 1、Audio 1……）。
- happyhorse-1.x-i2v：仅 first_frame，且必须恰好 1 个。至少 300x300 像素，
  JPEG/JPG/PNG/WEBP，最大值 20MB，公共 URL 或 data:\{MIME_type};base64,... URL。
  这些拼写不使用 img_url；首帧放在这里。
- happyhorse-1.x-r2v：仅 reference_image，1 到 9 个。最短边至少
  400 像素，最大值 20MB，公共 URL 或 data: URL。reference_video 不是此操作的
  输入类型。
- happyhorse-1.x-video-edit：video
上述每个资产“最大值 20MB”的数字是合作伙伴对其最终得到的图像设定的上限，
当资产是公共 URL 时按字面适用，因为这些字节从不经过 Comfy。内联的
data: URL 确实会经过 Comfy，并且也会受到传输上限的约束：Comfy Router 的 POST 请求体
总计上限为 100 MiB，超过则返回 413，而 base64 会将载荷膨胀约 4/3，
因此单个内联资产若超过约 75 MB，就会在触及此处任何合作伙伴规则之前
被拒绝。在该规模下，单个资产即便达到
合作伙伴自身的 20MB 上限，内联也完全放得下，因此对单个资产而言起约束作用的是
合作伙伴规则。而传输上限会在有多个资产时起约束作用，因为
100 MiB 的 Router 上限约束的是整个请求，而不是每个元素。凡接近这些上限的
内容，请以公共 URL 形式发送。
</ParamField>

</ParamField>

<ParamField body="input.media[].url" type="string" required>
