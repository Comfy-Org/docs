<ParamField body="input.img_url" type="string">
  首帧图像网址或 Base64 编码数据。对于 wan2.5-i2v-preview 和 wan2.6-i2v
模型为必填。happyhorse-1.x i2v 拼写不在此处传入首帧：它们以类型为
first_frame 的 media 元素传入首帧（见下方 media），并且在 wan2.6-i2v 上成功的

<ParamField body="input.media" type="object[]">
  媒体资产列表。指定用于视频生成的参考素材（图像、音频、视频）。每个元素包含
一个 type 和一个 url 字段。此字段由该组件所服务的所有模型共用，而某个给定模型
接受哪些 type 值（以及它究竟是在此处还是在 img_url 或 reference_video_urls 中
传入其图像或视频输入）都因模型而异。各模型支持的 type 值如下：
- wan2.7-i2v：first_frame、last_frame、driving_audio、first_clip。first_frame 和
  last_frame：JPEG/JPG/PNG/BMP/WEBP，每边 240-8000 像素，宽高比在 1:8
  到 8:1 之间，最大 20MB，公开 URL 或 data:\{MIME_type};base64,... URL。
  driving_audio（WAV/MP3，2-30 秒，最大 15MB）和 first_clip（MP4/MOV，2-10
  秒，每边 240-4096 像素，最大 100MB）：公开 HTTP/HTTPS URL；不接受内联
  data: URL。
- wan2.7-r2v：first_frame（可选，最多 1 个）、reference_image、reference_video。至少
  需要 1 个 reference_image 或 reference_video，且参考图像加上
  参考视频总计最多 5 个。first_frame 和 reference_image：JPEG/JPG/PNG/BMP/WEBP
  （无透明度通道），每边 240-8000 像素，宽高比在 1:8 到 8:1 之间，最大
  20MB，公开 URL 或 data:\{MIME_type};base64,... URL。reference_video：公开
  HTTP/HTTPS URL；不接受内联 data: URL。
- wan2.7-videoedit：video（恰好 1 个，即被编辑的片段：MP4/MOV，2-10 秒，
  每边 240-4096 像素，最大 100MB，公开 HTTP/HTTPS URL；不接受内联 data: URL），
  外加可选的 0 到 4 个 reference_image（JPEG/JPG/PNG/BMP/WEBP，
  每边 240-8000 像素，宽高比在 1:8 到 8:1 之间，最大 20MB，公开 URL
  或 data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime：first_frame（最多 1 个）、last_frame（最多 1 个）、
  reference_image（最多 10 个）、reference_video（最多 5 个片段，总时长 \<= 15s）、
  reference_audio（最多 5 个片段，总时长 \<= 15s）、file（最多 1 个，不能与 link
  同时使用）、link（最多 1 个，不能与 file 同时使用）。reference_*/file/link 类型
  与 first_frame/last_frame 类型在同一请求中互斥。数组顺序定义了提示中
  资产的参考顺序（Image 1、Video 1、Audio 1……）。first_frame、last_frame 和
  reference_image：JPEG/JPG/PNG/BMP/WEBP，每边 240-8000 像素，宽高比最大
  8:1，最大 20MB，公开 URL 或 data:\{MIME_type};base64,... URL。
  reference_video、reference_audio、file 和 link：公开 HTTP/HTTPS URL；不接受内联
  data: URL。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v：仅 first_frame，恰好 1 个。这些拼写
  在此处传入其首帧，而不是在 img_url 中传入。至少 300x300 像素，宽高比
  在 1:2.5 到 2.5:1 之间，JPEG/JPG/PNG/WEBP，最大 20MB，公开 URL 或
  data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v：仅 reference_image，1 到 9 个。这是
  该模型唯一的参考输入。最短边至少 400 像素，JPEG/JPG/PNG/WEBP，
  最大 20MB，公开 URL 或 data:\{MIME_type};base64,... URL。reference_video
  不是此操作的输入类型。
- happyhorse-1.0-video-edit：video（恰好 1 个，即被编辑的片段：MP4/MOV，3-60
  秒，长边最大 4096 像素，短边至少 360 像素，宽高比在 1:2.5 到 2.5:1
  之间，最大 100MB，公开 HTTP/HTTPS URL；不接受内联 data:
  URL），外加可选的 0 到 5 个 reference_image（JPEG/JPG/PNG/WEBP，至少
  300x300 像素，宽高比在 1:2.5 到 2.5:1 之间，最大 20MB，公开 URL
  或 data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview：
  文生视频操作。其合作伙伴参考文档未记录任何 media 输入，因此请勿设置
  此字段。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v：本组件未为这些拼写列举任何 media
  词汇。wan2.5-i2v-preview 和 wan2.6-i2v 在 img_url 中传入其首帧；
  wan2.6-r2v 在 reference_video_urls 中传入其参考片段。
上述各模型的计数是合作伙伴的限制，而非本 Schema 的限制：media 上未声明
minItems/maxItems，因为可接受的类型及其上限因模型而异。Schema 接受
并不意味着提供商接受；反过来说，上述每项资产“最多 20MB”的数值（即图像
输入的上限，也是唯一可以内联发送的输入）是合作伙伴对其最终获得的
资产所设的上限，当资产是公开 URL 时，这些限制按字面适用，
因为这些字节从不经过 Comfy 传输。内联的 data:\{MIME_type};base64,...
URL 则会经过 Comfy 传输，并且同样会遇到传输上限：Comfy Router
POST 请求体总上限为 100 MiB，超过即返回 413，而 base64 会使
负载增大约 4/3，因此单个内联资产超过约 75 MB 就会在任何
此处所列的合作伙伴规则生效之前被拒绝。在该大小下，单个资产在合作伙伴自身的
20MB 上限可以轻松容纳内联数据，因此对单个资产而言，起约束作用的是合作伙伴规则；而当涉及多个资产时，起约束作用的则是传输上限，因为 100 MiB 的 Router 上限约束的是整个请求，而不是每个元素。任何接近这些上限的内容都应以公共 URL 形式发送。

- happyhorse-1.1-*（t2v、i2v、r2v）：480P, 720P, 1080P
该代理会拒绝既未提供分辨率、也未提供尺寸的视频生成请求，因为分辨率档位决定计费费率。它会在检查之前将分辨率转为大写，并转发大写后的值；对于不在该枚举中的值返回 400；对于上文列为不支持 480P 的 wan2.6、wan2.7 和 happyhorse-1.0 模型，传入 480P（无论是作为分辨率传入，还是作为 480P 的尺寸传入）都会返回 400。

  可选值：`480P`, `720P`, `1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  随机数种子，用于控制模型生成内容的随机性

  范围：`0` 到 `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">

适用于 wan2.6 和 wan2.7-r2v 模型。
- single: 单镜头视频（默认）
- multi: 多镜头视频

  可选值：`multi`, `single`
</ParamField>

<ParamField body="parameters.size" type="string">
  视频分辨率，格式为 宽度*高度。支持的分辨率因模型而异：
对于 wan2.5 T2V：480P（480*832, 832*480, 624*624）、720P、1080P 尺寸
对于 wan2.6 T2V/R2V（无 480P）：
  720P: 1280*720, 720*1280, 960*960, 1088*832, 832*1088
  1080P: 1920*1080, 1080*1920, 1440*1440, 1632*1248, 1248*1632
当同时传入尺寸和分辨率时，由尺寸决定计费档位，而
分辨率仍必须是该代理为相应模型接受的值。对于分辨率描述中
列为不支持 480P 的每个模型，传入 480P 的尺寸都会返回 400。
</ParamField>
