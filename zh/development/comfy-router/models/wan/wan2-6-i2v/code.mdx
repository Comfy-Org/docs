<ParamField body="input.audio_url" type="string">
  音频文件下载 URL。支持的格式：mp3 和 wav。不能与 reference_video_urls 一起使用。
</ParamField>

<ParamField body="input.img_url" type="string">
  首帧图像 URL 或 Base64 编码数据。
仅 wan2.5-i2v-preview 和 wan2.6-i2v 模型必填。happyhorse-1.x 的 i2v 写法
不在此处传入首帧：它们将首帧作为类型为 `first_frame` 的 `media` 元素传入
（参见下方的 `media`），而在 wan2.6-i2v 上成功的 `img_url` 请求体，
会被提供商在 happyhorse-1.0-i2v 和 happyhorse-1.1-i2v 上拒绝。
图像格式：JPEG、JPG、PNG、BMP、WEBP。分辨率：360-2000 像素。
文件大小：最大 10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  wan2.7、wan3.0 和 happyhorse-1.x 模型的媒体资产列表。用于指定视频生成所需的
参考素材（图像、音频、视频）。每个元素包含 type 和 url 字段。
支持的 type 取值因模型而异：
- wan2.7-i2v：first_frame、last_frame、driving_audio、first_clip
- wan2.7-r2v：reference_image、reference_video
- wan2.7-videoedit：video、reference_image
- wan3.0-video：first_frame（最多 1 个）、last_frame（最多 1 个）、reference_image（最多 10 个）、
  reference_video（最多 5 个片段，总时长 \<= 15 秒）、reference_audio（最多 5 个片段，
  总时长 \<= 15 秒）、file（最多 1 个，不能与 link 一起使用）、link（最多 1 个，不能
  与 file 一起使用）。在同一请求中，reference_*/file/link 类型与 first_frame/last_frame 类型
  互斥。数组顺序决定提示词中资产的引用顺序（Image 1、Video 1、Audio 1……）。
- happyhorse-1.x-i2v：仅支持 first_frame，且必须正好 1 个。至少 300x300 像素，
  JPEG/JPG/PNG/WEBP，最大 20MB，可以是公开 URL 或 data:\{MIME_type};base64,... URL。
  这些写法不接受 img_url；首帧在此处传入。
- happyhorse-1.x-r2v：仅支持 reference_image，1 到 9 个。最短边至少
  400 像素，最大 20MB，可以是公开 URL 或 data: URL。reference_video 不是此操作的
  输入类型。
- happyhorse-1.x-video-edit：video
上面每个资产“最大 20MB”的数字是合作伙伴对其最终获得的图像所设的上限，
当资产是公开 URL 时按字面适用，因为这些字节从不经过 Comfy。而内联的
data: URL 会经过 Comfy，会先遇到更低的传输上限：Comfy Router 的 POST 请求体
总上限为 20 MiB，超过即返回 413，而 base64 会使负载膨胀约 4/3，因此单个内联
资产若超过大约 15 MB，就会在这里的任何合作伙伴规则被触及之前先被拒绝。若请求体中
携带多个此类资产，则更早被拒绝，因为 20 MiB 的 Router 上限约束的是整个请求，
而不是每个元素。凡接近这些上限的内容，请以公开 URL 形式发送。
