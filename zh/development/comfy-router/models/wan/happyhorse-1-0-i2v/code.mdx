</ParamField>

<ParamField body="input.img_url" type="string">
  首帧图像网址或 Base64 编码数据。
仅 wan2.5-i2v-preview 和 wan2.6-i2v 模型必填。happyhorse-1.x i2v
拼写不在此处传入首帧：它们将首帧作为类型为 `first_frame` 的 `media`
元素传入（见下方 `media`），而在 wan2.6-i2v 上可以成功的 `img_url`
请求体，在 happyhorse-1.0-i2v 和 happyhorse-1.1-i2v 上会被提供商拒绝。
图像格式：JPEG、JPG、PNG、BMP、WEBP。分辨率：360-2000 像素。
文件大小：最大值 10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  用于 wan2.7、wan3.0 和 happyhorse-1.x 模型的媒体资产列表。指定用于视频生成的参考
素材（图像、音频、视频）。每个元素包含 type 和 url 字段。
支持的 type 取值因模型而异：
- wan2.7-i2v：first_frame、last_frame、driving_audio、first_clip
- wan2.7-r2v：reference_image、reference_video
- wan2.7-videoedit：video、reference_image
- wan3.0-video：first_frame（最多 1 个）、last_frame（最多 1 个）、reference_image（最多 10 个）、
  reference_video（最多 5 段，总时长 \<= 15s）、reference_audio（最多 5 段，
  总时长 \<= 15s）、file（最多 1 个，不能与 link 一起使用）、link（最多 1 个，不能
  与 file 一起使用）。reference_*/file/link 类型与 first_frame/last_frame 类型
  在同一请求中互斥。数组顺序决定了提示中资产的引用顺序
  （Image 1、Video 1、Audio 1……）。
- happyhorse-1.x-i2v：仅支持 first_frame，且必须恰好 1 个。至少 300x300 像素，
  JPEG/JPG/PNG/WEBP，最大值 20MB，公开网址或 data:\{MIME_type};base64,... 网址。
  这些拼写不使用 img_url；首帧在此传入。
- happyhorse-1.x-r2v：仅支持 reference_image，数量为 1 到 9 个。最短边至少
  400 像素，最大值 20MB，公开网址或 data: 网址。reference_video 不是此操作
  的输入类型。
- happyhorse-1.x-video-edit：video
上述每项资产的“最大值 20MB”是合作伙伴对其最终获得的图像设定的上限，
当资产是公开网址时按字面适用，因为这些字节从不经由 Comfy 传输。
内联的 data: 网址确实会经由 Comfy 传输，并会先遇到更低的传输上限：
Comfy Router 的 POST 请求体总计上限为 20 MiB，超过即返回 413；而 base64
会使负载膨胀约 4/3，因此单个内联资产若超过约 15 MB，在触及此处任何
合作伙伴规则之前就会被拒绝。当请求体中包含多个此类资产时还会更早被拒，
因为 20 MiB 的 Router 上限约束的是整个请求，而不是每个元素。凡是接近
这些上限的内容，都应以公开网址发送。
