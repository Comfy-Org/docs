同一个请求体，发送到 `POST https://api.comfy.org/v2/models/bria/image/requests`。运行一旦被接纳，Router 就会以 `201` 应答并返回 `request_id`，结果准备就绪后即可收集，既可以由当前进程收集，也可以由另一个进程收集。[队列投递](/zh/development/comfy-router/queue) 详细介绍了状态、取消与收集的流程。

<CodeGroup>
```python Python
import asyncio
from comfy_sdk import AsyncComfy

# 从环境变量读取 COMFY_API_KEY。
# 每次 submit() 调用都会生成自己的 Idempotency-Key，并在自动重试时复用它。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "bria/image",
            {
                "prompt": "A red vintage bicycle leaning against a brick wall in soft morning light",
            },
        )
        print("request_id:", handle.request_id)  # 加上模型 ID，就是另一个进程所需的全部信息

        # 轮询直到请求完成，按服务器给出的 Retry-After 等待。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # 提供商自己的负载，与 models.run() 返回的值相同。
        # 失败或已取消的请求会在这里抛出带类型的 Router 错误。
        result = await handle.get()

    print(result)

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// 从环境变量读取 COMFY_API_KEY。
// 每次 submit() 调用都会生成自己的 Idempotency-Key，并在自动重试时复用它。
const handle = await comfy.models.submit("bria/image", {
  prompt: "A red vintage bicycle leaning against a brick wall in soft morning light",
});
console.log("requestId:", handle.requestId); // 加上模型 ID，就是另一个进程所需的全部信息

// 轮询直到请求完成，按服务器给出的 Retry-After 等待。
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// 与 models.run() 返回的结果相同。失败或已取消的请求会在此处被拒绝。
const result = await handle.get();

console.log(result.data);
```

```bash cURL
# 1. 提交。Router 返回 201，并带有 request_id、status_url、response_url 和 cancel_url。
curl https://api.comfy.org/v2/models/bria/image/requests \
  -H "X-API-Key: $COMFY_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d "{\"prompt\": \"A red vintage bicycle leaning against a brick wall in soft morning light\"}"

# 2. 轮询直到状态为 COMPLETED，每次响应按其给出的 Retry-After 秒数等待。
REQUEST_ID="<request_id from the 201 body>"
curl -i https://api.comfy.org/v2/models/bria/image/requests/$REQUEST_ID/status \
  -H "X-API-Key: $COMFY_API_KEY"

# 3. 收集。返回 200 时带有模型的原始输出，仍在运行时则返回 202 及状态响应体。
curl https://api.comfy.org/v2/models/bria/image/requests/$REQUEST_ID \
  -H "X-API-Key: $COMFY_API_KEY"
```

## Schema

### 输入

<ParamField body="aspect_ratio" type="string" default="&quot;1:1&quot;">
  输出图像比例，取值为 "1:1"、"2:3"、"3:2"、"3:4"、"4:3"、"4:5"、"5:4"、"9:16"、"16:9"、"16:10"、"10:16"、"2:1"、"1:2"、"21:9"、"9:21"、"3:1"、"1:3"、"4:1"、"1:4"、"5:1" 或 "1:5" 之一。使用 "4MP" 时，使用同时发送 prompt 和 structured_prompt 的细化请求时，或使用没有提示词的图像时，Bria 会拒绝从 "16:10" 起的比例。
</ParamField>

<ParamField body="images" type="string[]">
  用于启发新图像的参考图像。可以是公开可访问的 URL 或 Base64 编码。接受的格式为 JPEG、JPG、PNG、WEBP。必须恰好包含一项。
</ParamField>

<ParamField body="ip_signal" type="boolean" default="false">
  如果为 true，则针对提示词中可能存在的 IP 内容返回警告。
</ParamField>

<ParamField body="model_version" type="string">
  要使用的模型版本。仅接受 "FIBO"；省略它则运行同一模型。
</ParamField>

<ParamField body="output_type" type="string" default="&quot;png&quot;">
  输出图像格式，"png" 或 "jpeg"。
</ParamField>

<ParamField body="prompt" type="string">
  基于文本的指令。可单独使用以生成新图像，也可与 images 或 structured_prompt 一起使用来引导或细化结果。
</ParamField>

<ParamField body="prompt_content_moderation" type="boolean" default="true">
  如果为 true，则在提示词审核失败时返回 422。
</ParamField>

<ParamField body="resolution" type="string" default="&quot;1MP&quot;">
  输出图像分辨率，"1MP" 或 "4MP"。"4MP" 可改善图像细节，但会使延迟增加约 30 秒。
</ParamField>

<ParamField body="seed" type="integer">
  用于确定性生成的种子。如果省略，则使用随机种子。
</ParamField>

<ParamField body="structured_prompt" type="string">
  一个包含 JSON 格式结构化提示词的字符串，来自先前生成的结果。将其与相同的种子一起使用可重现该图像，或者更改其中一部分来细化图像。
</ParamField>

<ParamField body="visual_input_content_moderation" type="boolean" default="true">
  如果为 true，则在图像审核失败时返回 422。
</ParamField>

<ParamField body="visual_output_content_moderation" type="boolean" default="true">
  如果为 true，则在视觉输出审核失败时返回 422。
</ParamField>
