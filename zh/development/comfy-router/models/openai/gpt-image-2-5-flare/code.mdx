<ParamField body="mask" type="string">

优先使用 URL 形式。base64 负载大约会膨胀至 4/3，而整个请求体被限制在 100 MiB，因此内联形式的上限约为 75 MB 的来源图像；URL 则完全绕开这一点。本描述末尾声明的单张图像和单次请求的媒体上限比请求体上限更严格，所以对于任何实际尺寸的图像，你首先会遇到的是它们。
该 URL 必须在不携带你的凭据的情况下也能解析。Router 在服务器端获取它，并且不会随请求发送任何调用方凭据，因此支持的是预签名 URL，即签名位于查询字符串中的 URL。像 `/api/assets/{id}/content` 这样的认证端点会向 Router 返回 401 而不是图像；请自行请求该 URL，然后传入它重定向到的已签名 URL。
获取仅限一组具名的主机，而不是开放的互联网，而且相同的列表会重新应用于每一个重定向跳转以及你发送的 URL：因此，位于任何其他主机上的 URL，或者重定向离开该列表的 URL，都会在联系任何提供商之前被拒绝。目前该列表仅为 Comfy 自己的资产交付：Comfy 资产桶下的已签名 `storage.googleapis.com` URL，也就是 `/api/assets/{id}/content` 重定向你到的形式。合作伙伴 CDN 或普通的 https 主机不在该列表上。
两项放宽正在逐步推出，目前两者默认都处于关闭状态。它们位于同一个切换开关之后并一起启用，因此请将下面的一切视为即将推出，而不是现在就可以依赖的东西：在依赖其中任何一项之前请先询问。
第一项是 `POST /customers/storage` 将你的上传签名到的桶。在推出到达你的环境之前，来自该端点的上传 URL 会在此处被拒绝，即使该桶是 Comfy 自己的，且主机也相同：所以“上传到 Comfy，然后传入 URL”目前还不行，可行的形式是 `/api/assets/{id}/content` 重定向到的已签名 URL。
第二项是按账户启用，而不是一次性对所有人启用，因为这些主机背后的桶是你的而非我们的：即使上面的开关已打开，尚未启用第三方入站媒体的账户也会被拒绝，并且会用这些原话告知，而不是告知主机不受支持。请联系你的 Comfy 联系人，为你的账户启用它。它还会额外接受以下第三方对象存储主机，其中桶是你的，Router 对其不作任何所属声明：Cloudflare R2（`<account>.r2.cloudflarestorage.com`、`pub-<hash>.r2.dev`）、Amazon S3（`s3.amazonaws.com` 和 `s3.<region>.amazonaws.com`，可以是路径风格或 `<bucket>.` 前缀形式）、Azure Blob Storage（`<account>.blob.core.windows.net`）以及阿里云 OSS（`<bucket>.oss-<region>.aliyuncs.com`，包括 `oss-accelerate` 端点）。这些具体是对象存储端点：同一提供商域名上的通用端点，例如阿里云函数计算触发器，不在列表上，会被拒绝。
匹配的是主机名形式，而不是提供商：所以在上文点名某个提供商，并不意味着该提供商能签发的每个 URL 都会被接受，有三个近似情形值得直接说明，因为调用方有理由会带来其中的每一个。R2 自定义域名（`cdn.example.com`）不被接受：Cloudflare 将 `pub-<hash>.r2.dev` 记录为受速率限制的调试主机名，并将生产流量指向自定义域名，但自定义域名的主机名中没有任何能标识其为 R2 的信息，因此 Router 无法将其与任何其他主机区分开，会予以拒绝：请对 `<account>.r2.cloudflarestorage.com` 端点进行预签名，或使用 `pub-<hash>.r2.dev` 形式。S3 的 IPv6 dualstack 端点（`s3.dualstack.<region>.amazonaws.com`）也不被接受；请使用普通的区域端点。Azure Blob 的备用 DNS 区域（`<account>.z<N>.blob.storage.azure.net`）同样不被接受；请使用 `<account>.blob.core.windows.net`。你收到的拒绝信息会列出这些相同的形式，因此你不必到这里来阅读它们。
