模型已发布的示例是生成调用，其中省略了此字段。添加 `image` 即是两种模式之间的全部差异（相同的端点、相同的模型 id），只不过编辑 prompt 描述的是你想要的变化而不是场景，因此即便结构上只有此字段是新增的，下面的编辑请求体读起来也与生成示例不同。
它可以原样复制使用：`{"prompt": "give the rocketship rainbow coloring", "image": ["data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="], "size": "1024x1024"}`。payload 是一个完整的 1x1 PNG，而不是一个缩写，并且此请求体在 Router 自身的请求验证测试中被顶固为已接受的用例。请替换为你自己图像的字节。

</ParamField>

<ParamField body="mask" type="string">
  一张图像，可以是 Router 代表调用方获取的 https URL，也可以是内联携带字节的 `data:image/<format>;base64,<payload>` URI。接受的图像类型为 png、webp 和 jpeg，且该集合在解析阶段即被强制执行，而不是留给提供商：svg、gif、avif 或 tiff 会在此被拒绝，并指出你发送的图像，而不是在距离根因两跳之外变成合作伙伴错误。
优先使用 URL 形式。base64 payload 大约膨胀 4/3，而整个请求体上限为 20 MiB，因此内联形式在来源图像接近 15 MB 时就会达到上限；而 URL 则完全避开了这一点。
该 URL 必须在不使用你的凭据的情况下即可解析。Router 会在服务器端获取它，并且随请求不发送调用方凭据，因此受支持的形式是预签名 URL（即签名位于查询字符串中的 URL）。诸如 `/api/assets/{id}/content` 这类需要身份验证的端点会向 Router 返回 401 而不是图像；请自行请求该 URL，并传入它重定向到的已签名 URL。
该获取被限制在一组指定的主机范围内，而不是开放互联网，并且同一份列表会重新应用于每一次重定向跳转以及你发送的 URL：因此位于任何其他主机上的 URL，或者重定向到列表之外的主机上的 URL，会在联系任何提供商之前被拒绝。目前该列表仅包含 Comfy 自有的资产交付：Comfy 资产桶下的已签名 `storage.googleapis.com` URL，即 `/api/assets/{id}/content` 将你重定向到的形式。合作伙伴 CDN 或普通 https 主机并不在该列表上。
两项放宽正在逐步推出，且今天默认均为关闭状态。它们通过同一个切换发布并一起启用，因此请把下面的一切视为即将推出，而不是目前可以基于其构建的东西：在依赖其中任何一项之前请先询问。
第一项是 `POST /customers/storage` 将你的上传签名到的桶。在推出到达你的环境之前，来自该端点的上传 URL 会在此被拒绝，即便该桶是 Comfy 自有的且主机相同：因此"上传到 Comfy，然后传入 URL"目前不可行，可行的形式是 `/api/assets/{id}/content` 重定向到的已签名 URL。
第二项额外允许这些第三方对象存储主机，其中桶属于你，Router 对其不作所属声明：Cloudflare R2（`<account>.r2.cloudflarestorage.com`、`<id>.r2.dev`）、Amazon S3（`s3.amazonaws.com` 和 `s3.<region>.amazonaws.com`，无论是路径式还是带 `<bucket>.` 前缀的形式）、Azure Blob Storage（`<account>.blob.core.windows.net`）和 Alibaba Cloud OSS（`<bucket>.oss-<region>.aliyuncs.com`，包括 `oss-accelerate` 端点）。这些专门是对象存储端点：同一提供商域名上的通用端点，例如 Alibaba Function Compute 触发器，不在该列表上，会被拒绝。
下面的示例仅展示形状：真实的值还带有签名查询参数，此处有意省略这些参数，因为已发布的示例会永远留在规范中，而真实的签名既是被泄露的凭据，也是一个会失效的链接。
每张图像上限为 25 MiB，单个请求的图像总量上限为 64 MiB。
