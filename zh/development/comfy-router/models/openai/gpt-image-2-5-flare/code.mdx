<ParamField body="mask" type="string">
  单张图像，可以是 Router 代调用方获取的 https URL，也可以是内联携带字节的 `data:image/<format>;base64,<payload>` URI。接受的图像类型为 png、webp 和 jpeg，该集合在解析时即强制执行，而不是留给提供商。svg、gif、avif 或 tiff 会在此处被拒绝，并会指明你发送的图像，而不会变成距根因两跳之外的合作伙伴错误。
优先使用 URL 形式。base64 载荷大约会膨胀 4/3，而整个请求体上限为 100 MiB，因此内联形式最多只能承载约 75 MB 的来源图像；使用 URL 则可完全绕开这一点。本描述末尾说明的每张图像和每请求的媒体上限比请求体上限更严格，因此对于任何实际尺寸的图像，你首先遇到的是这些限制。
该 URL 必须在不使用你的凭据的情况下即可解析。Router 在服务器端获取它，且不会随请求发送任何调用方凭据，因此支持的形式是预签名 URL，即签名位于查询字符串中的 URL。诸如 `/api/assets/{id}/content` 这类需要身份验证的端点会向 Router 返回 401 而不是图像；请自行请求该 URL，并传入它重定向到的已签名 URL。
抓取仅限于一组具名主机，而不是整个开放互联网，并且同一份列表会重新应用于每一次重定向跳转以及你发送的 URL。因此，位于任何其他主机上的 URL，或者会重定向到列表之外的主机，都会在联系任何提供商之前被拒绝。目前该列表仅包含 Comfy 自己的资产分发：Comfy 资产桶下已签名的 `storage.googleapis.com` URL，也就是 `/api/assets/{id}/content` 重定向你前往的形式。合作伙伴 CDN 或普通 https 主机不在该列表中。
有两项放宽正在逐步推出，且目前两者默认均处于关闭状态。它们由同一个切换项控制并一同启用，因此请将以下所有内容视为即将推出，而不是现在就可以依赖的功能；在依赖其中任何一项之前请先咨询。
第一项是 `POST /customers/storage` 为你的上传签名的目标桶。在该推出到达你的环境之前，来自该端点的上传 URL 会在此处被拒绝，即使该桶是 Comfy 自己的、主机也是同一个。因此“上传到 Comfy，再传入 URL”目前行不通，可行的形式是 `/api/assets/{id}/content` 重定向到的已签名 URL。
第二项是按账号启用，而不是对所有人一次性启用，因为这些主机背后的桶是你的而非我们的：即使上面的切换项已开启，未启用第三方入站媒体的账号仍会被拒绝，并且提示会明确说明这一点，而不是告诉你该主机不受支持。请联系你的 Comfy 对接人为你的账号启用它。它还额外接受以下第三方对象存储主机，这些主机上的桶属于你，Router 不对其主张所属权：Cloudflare R2（`<account>.r2.cloudflarestorage.com`、`<id>.r2.dev`）、Amazon S3（`s3.amazonaws.com` 和 `s3.<region>.amazonaws.com`，路径样式或 `<bucket>.` 前缀形式均可）、Azure Blob Storage（`<account>.blob.core.windows.net`）以及阿里云 OSS（`<bucket>.oss-<region>.aliyuncs.com`，包括 `oss-accelerate` 端点）。这些具体指对象存储端点：同一提供商域名上的常规端点，例如阿里云函数计算触发器，不在列表中，会被拒绝。
