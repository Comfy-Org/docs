<ParamField body="mask" type="string">
  一张图像，可以是 Router 代表调用方抓取的 https URL，也可以是内联携带字节的 `data:image/<format>;base64,<payload>` URI。可接受的图像类型为 png、webp 和 jpeg，并且该集合会在解析时强制执行，而不是留给提供商处理：svg、gif、avif 或 tiff 会在这里被拒绝，并会指明你发送的图像，而不会在距原因两跳之外变成一个合作伙伴错误。
优先使用 URL 形式。base64 载荷大约会膨胀 4/3，而整个请求体上限为 100 MiB，因此内联形式的上限约为 75 MB 的来源图像；URL 则完全绕开这一点。本描述末尾列出的每张图像以及每个请求的媒体上限比请求体上限更严格，因此对于任何实际尺寸的图像，你会先遇到这些限制。
该 URL 必须无需你的凭据即可访问。Router 在服务器端抓取它，并且不会随请求发送调用方凭据，因此受支持的形态是预签名 URL，即签名位于查询字符串中的 URL。诸如 `/api/assets/{id}/content` 这类需要认证的端点会向 Router 返回 401 而不是图像；请自行请求该 URL，并传入它重定向到的已签名 URL。
抓取仅限于一组具名主机，而不是开放的互联网；同一列表会同时应用于你发送的 URL 以及每一次重定向跳转，因此任何其他主机上的 URL，或重定向到列表之外主机的 URL，都会在联系任何提供商之前被拒绝。目前该列表仅包含 Comfy 自己的资产投递：Comfy 资产桶下经过签名的 `storage.googleapis.com` URL，也就是 `/api/assets/{id}/content` 重定向你前往的形态。合作伙伴 CDN 或普通 https 主机不在列表上。
有两项放宽正在逐步推出，目前二者都默认关闭。它们通过同一个切换开关发布并一起启用，因此请把以下内容视为即将推出，而不是现在就可以依赖的东西：在依赖其中任何一项之前，请先咨询。
第一项是 `POST /customers/storage` 为你的上传签发目标所用的桶。在推出覆盖到你的环境之前，来自该端点的上传 URL 会在这里被拒绝，即使该桶属于 Comfy 自己、主机也是同一个：因此“上传到 Comfy，然后传入 URL”目前并不可行，可行的是 `/api/assets/{id}/content` 重定向到的已签名 URL。
第二项按账户启用，而不是一次性对所有人启用，因为这些主机背后的桶是你的而不是我们的：即使上述开关已打开，未启用第三方入站媒体的账户仍会被拒绝，并且会明确告知这一点，而不是被告知该主机不受支持。请联系你的 Comfy 联系人，为你的账户启用它。它还会额外允许这些第三方对象存储主机，在这些主机上桶属于你，Router 不对其主张任何所属权：Cloudflare R2（`<account>.r2.cloudflarestorage.com`、`<id>.r2.dev`）、Amazon S3（`s3.amazonaws.com` 和 `s3.<region>.amazonaws.com`，路径式或带 `<bucket>.` 前缀的形式均可）、Azure Blob Storage（`<account>.blob.core.windows.net`）和阿里云 OSS（`<bucket>.oss-<region>.aliyuncs.com`，包括 `oss-accelerate` 端点）。这些专门是对象存储端点：同一提供方域上的通用端点，例如阿里云函数计算触发器，不在列表上，会被拒绝。
