### 输入

<ParamField body="background" type="string">
  背景透明度。`auto` 让模型自行选择。

  可选值：`transparent`、`opaque`、`auto`
</ParamField>

<ParamField body="image" type="string | string[]">
  要编辑的来源图像。此字段是否存在即表明选择了编辑操作：要进行文生图，就完全省略它。
模型公布的示例是生成调用，其中省略了此字段。添加 `image` 就是两种模式之间的全部差异（相同的端点、相同的模型 ID），只不过编辑提示词描述的是你想要的更改，而不是场景本身，因此下面的编辑请求体读起来与生成示例不同，尽管从结构上看新增的只有这一个字段。
它可以按打印出的样子原样复制：`{"prompt": "give the rocketship rainbow coloring", "image": ["data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="], "size": "1024x1024"}`：其中的载荷是一个完整的 1x1 PNG，并非缩写形式，而且这个请求体在 Router 自身的请求验证测试中被固定为可接受的用例。请替换为你自己图像的字节。
接受一张图像或一个图像数组；gpt-image-1 及更高版本最多接受 16 张，Router 会在派发之前依据此 schema 强制执行该限制。
</ParamField>

<ParamField body="mask" type="string">
  一张图像，可以是 Router 代表调用方获取的 https URL，也可以是内联携带字节的 `data:image/<format>;base64,<payload>` URI。可接受的图像类型为 png、webp 和 jpeg，并且该集合是在解析时强制执行的，而不是交给提供商判断：svg、gif、avif 或 tiff 会在这里被拒绝，并指出你发送的图像，而不会变成与根因相隔两跳的合作伙伴错误。
优先使用 URL 形式。base64 载荷大约会膨胀到 4/3，而整个请求体上限为 100 MiB，因此内联形式在来源图像接近 75 MB 时就会到顶；使用 URL 则可以完全避开这一点。本描述末尾给出的单张图像与单次请求的媒体上限比请求体上限更严格，因此对于任何实际尺寸的图像，你首先遇到的会是这些上限。
该 URL 必须在没有你的凭据的情况下也能解析。Router 在服务器端获取它，并且不会随请求发送任何调用方凭据，因此受支持的形式是预签名 URL，即签名位于查询字符串中的 URL。像 `/api/assets/{id}/content` 这样的需要认证的端点会向 Router 返回 401，而不是图像；请你自己请求该 URL，并传入它重定向到的已签名 URL。
该获取操作被限定在一组指定的主机之内，而不是开放的互联网，并且同一份列表既会应用于你发送的 URL，也会重新应用于每一个重定向跳转：因此位于任何其他主机上的 URL，或者重定向到列表之外的主机的 URL，都会在任何提供商被联系之前就被拒绝。目前该列表仅包含 Comfy 自己的资产分发：Comfy 资产存储桶下已签名的 `storage.googleapis.com` URL，也就是 `/api/assets/{id}/content` 重定向你到的形式。合作伙伴 CDN 或普通 https 主机不在此列表中。
两项放宽正在逐步推出，而且目前默认都处于关闭状态。它们由同一个切换开关控制并一同启用，因此请将下面的所有内容视为即将推出，而不是现在就能依赖的东西：在你依赖其中任何一项之前，请先咨询。
第一项是 `POST /customers/storage` 为你的上传签名所指向的存储桶。在推出覆盖到你的环境之前，来自该端点的上传 URL 在这里会被拒绝，即使该存储桶属于 Comfy 自己、主机也是同一个：所以“先上传到 Comfy，再传入 URL”目前尚不可行，可行的形式是 `/api/assets/{id}/content` 重定向到的那个已签名 URL。
第二项是按账户启用的，而不是一次性对所有人启用，因为这些主机背后的存储桶属于你而不是我们：即使上面的开关已经打开，未启用第三方入站媒体的账户仍会被拒绝，并且会明确告知这一点，而不是被告知该主机不受支持。请联系你的 Comfy 对接人，为你的账户启用它。它还额外允许以下第三方对象存储主机，其中存储桶属于你，Router 不对其主张所属权：Cloudflare R2（`<account>.r2.cloudflarestorage.com`、`pub-<hash>.r2.dev`）、Amazon S3（`s3.amazonaws.com` 和 `s3.<region>.amazonaws.com`，路径风格或带 `<bucket>.` 前缀的形式均可）、Azure Blob Storage（`<account>.blob.core.windows.net`）以及阿里云 OSS（`<bucket>.oss-<region>.aliyuncs.com`，包括 `oss-accelerate` 端点）。这些特指对象存储端点：同一提供商域名上的常规用途端点，例如阿里云函数计算的触发器，不在列表中，会被拒绝。
匹配的是主机名形式，而不是提供商：因此上面列出某个提供商，并不意味着该提供商能签发的每个 URL 都可接受，有三种近似情况值得直接说明，因为调用方有理由带着它们中的每一种到来。R2 的自定义域名（`cdn.example.com`）不被接受：Cloudflare 将 `pub-<hash>.r2.dev` 记录为受速率限制的调试主机名，并把生产流量指向自定义域名，但自定义域名的主机名中没有任何内容能表明它属于 R2，因此 Router 无法将其与其他主机区分开来，于是拒绝它：请对 `<account>.r2.cloudflarestorage.com` 端点做预签名，或使用 `pub-<hash>.r2.dev` 形式。S3 的 IPv6 dualstack 端点（`s3.dualstack.<region>.amazonaws.com`）同样不被接受；请使用普通的区域端点。Azure Blob 的备用 DNS 区域（`<account>.z<N>.blob.storage.azure.net`）也不被接受；请使用 `<account>.blob.core.windows.net`。你收到的拒绝信息中会列出这些同样的形式，因此你不必特意来这里阅读它们。
上面的 `<account>` 和 `pub-<hash>` 占位符展示的是你通常提交的形式；它们并不是对层级的限制。匹配依据的是对象存储的域名后缀，因此同一命名空间下更深的名称（`a.b.pub-<hash>.r2.dev`）也会被接受。这并未放宽命名空间本身：后缀仍然必须是所列出的其中之一。
