模型公布的示例是生成调用，其中省略了此字段。添加 `image` 就是两种模式之间的全部差异：相同的端点、相同的模型 id。只不过编辑提示词描述的是你想要的更改，而不是场景，因此下面的编辑请求体读起来会与生成示例不同，尽管从结构上看只有这个字段是新增的。

</ParamField>

<ParamField body="mask" type="string">
  一张图像，可以是 Router 代表调用方获取的 https URL，也可以是内联携带字节的 `data:image/<format>;base64,<payload>` URI。接受的图像类型为 png、webp 和 jpeg，并且该集合会在解析时强制执行，而不是留给提供商处理。svg、gif、avif 或 tiff 会在这里被拒绝，并会指明你发送的图像，而不是在距离原因两跳之外变成一个合作伙伴错误。
优先使用 URL 形式。base64 载荷大约会膨胀 4/3，而整个请求体上限为 100 MiB，因此内联形式的上限约为 75 MB 的来源图像；而 URL 完全绕过了这一点。本描述末尾所述的每图像和每请求媒体上限比请求体上限更严格，因此对于任何实际尺寸的图像，你首先会遇到的是这些限制。
URL 必须在不使用你的凭据的情况下完成解析。Router 会在服务器端获取它，并且不会随请求发送调用方凭据，因此受支持的形式是预签名 URL，即签名位于查询字符串中的 URL。诸如 `/api/assets/{id}/content` 之类的需要认证的端点会向 Router 返回 401，而不是返回图像；请自行请求该 URL，并传入它重定向到的签名 URL。
获取操作仅限于一组具名主机，而不是开放互联网；同一列表既会应用于你发送的 URL，也会重新应用于每一次重定向跳转。因此，位于任何其他主机上的 URL，或者会重定向到列表之外的 URL，都会在联系任何提供商之前被拒绝。目前，该列表仅包含 Comfy 自己的资产交付：位于 Comfy 资产存储桶下的已签名 `storage.googleapis.com` URL，也就是 `/api/assets/{id}/content` 将你重定向到的形式。合作伙伴 CDN 或普通的 https 主机不在列表中。
两项扩展正在逐步推出，并且目前两者都默认关闭。它们通过一个切换项发布并一起启用，因此请将下面的所有内容视为即将推出的功能，而不是现在就能作为开发依据的内容：在依赖其中任何一项之前，请先询问。
第一项是 `POST /customers/storage` 为你的上传签发指向的存储桶。在该推广覆盖你的环境之前，来自该端点的上传 URL 会在这里被拒绝，即使该存储桶属于 Comfy 且主机相同也是如此。因此，“上传到 Comfy，然后传入 URL”目前并不可行；可行的形式是由 `/api/assets/{id}/content` 重定向到的签名 URL。
第二项按账户启用，而不是一次性对所有人启用，因为这些主机背后的存储桶属于你而不是我们：即使上面的切换项已打开，未启用第三方入站媒体的账户仍会被拒绝，并且会以这些字样告知这一点，而不是告知该主机不受支持。请联系你的 Comfy 联系人，为你的账户启用它。它还额外允许以下第三方对象存储主机；在这些主机中，存储桶属于你，Router 不对其提出所有权主张：Cloudflare R2（`<account>.r2.cloudflarestorage.com`、`pub-<hash>.r2.dev`）、Amazon S3（`s3.amazonaws.com` 和 `s3.<region>.amazonaws.com`，采用路径风格或带 `<bucket>.` 前缀的形式均可）、Azure Blob Storage（`<account>.blob.core.windows.net`）和 Alibaba Cloud OSS（`<bucket>.oss-<region>.aliyuncs.com`，包括 `oss-accelerate` 端点）。这些具体是对象存储端点：同一提供商域上的常规端点（例如阿里云函数计算触发器）不在列表中，会被拒绝。
匹配的是主机名形式，而不是提供商。因此，上面提到某个提供商并不意味着该提供商能够签发的每个 URL 都会被接受；有三种近似但不匹配的形式值得直接说明，因为调用方有理由可能遇到其中每一种。R2 自定义域名（`cdn.example.com`）不被接受：Cloudflare 将 `pub-<hash>.r2.dev` 记录为受速率限制的调试主机名，并将生产流量改为指向自定义域名，但自定义域名的主机名中不包含任何可将其标识为 R2 的内容，因此 Router 无法将其与任何其他主机区分开，并会拒绝它。请对 `<account>.r2.cloudflarestorage.com` 端点进行预签名，或使用 `pub-<hash>.r2.dev` 形式。S3 的 IPv6 双栈端点（`s3.dualstack.<region>.amazonaws.com`）也不被接受；请使用普通的区域端点。Azure Blob 的备用 DNS 区域（`<account>.z<N>.blob.storage.azure.net`）同样不被接受；请使用 `<account>.blob.core.windows.net`。你收到的拒绝信息会列出这些相同的形式，因此你不必回到这里阅读它们。
上面的 `<account>` 和 `pub-<hash>` 占位符展示的是你通常拿到的形式，它们并不是对层级的限制。匹配针对的是对象存储的域名后缀，因此在同一命名空间下更深的名称（`a.b.pub-<hash>.r2.dev`）也同样会被接受。这一点并未扩大命名空间本身：后缀仍然必须是所列出的后缀之一。
