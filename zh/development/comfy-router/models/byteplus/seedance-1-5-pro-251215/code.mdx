</ResponseField>

<ResponseField name="content.last_frame_url" type="string">
  生成视频最后一帧的下载 URL，当请求设置了 `return_last_frame` 时返回。不要根据此 URL 推断图像格式：BytePlus 在请求侧将最后一帧记录为 PNG，Router 会重新托管其收到的任意字节，并根据上游 Content-Type 或内容嗅探来确定类型，`image/jpeg` 只是在两者都失败时的最后兜底。Router 会将最后一帧重新托管到 Comfy 存储并重写此字段，所以它通常是 Comfy 签名的 URL，有效期最长 24 小时：签发时按 24 小时签名，并从 23 小时缓存中重放，因此后续轮询可能返回一个仅剩一小时有效期的 URL。无法执行重新托管时，该字段会保留 BytePlus 自己的 URL，而 BytePlus 会在任务结束 24 小时后清除它。无论哪种方式，链接都会过期，因此请下载该帧，而不是存储 URL。
</ResponseField>

<ResponseField name="content.output_format" type="string">
  生成视频的容器格式（mp4 或 mov），前提是 BytePlus 将其嵌套在 `content` 中。Seedance 模型更常将其作为 `content` 的顶层同级字段返回，参见顶层 `output_format` 字段，Router 会读取两者中存在的那个。
</ResponseField>

<ResponseField name="content.upstream_expires_at" type="string (date-time)">
  上游 URL 停止工作的 RFC 3339 时间：最早签名时间加上 URL 自身携带的有效期；当 `updated_at` 存在时，绝不晚于任务的 `updated_at` 加 24 小时（BytePlus 文档所述的 URL 生命周期）；否则为任务的 `updated_at` 加 24 小时。仅当存在 `upstream_video_url` 或 `upstream_last_frame_url` 时出现；当两个来源都不提供时间时省略。与重新托管的 `video_url` / `last_frame_url` 的生命周期无关。

  格式：`date-time`
</ResponseField>

<ResponseField name="content.upstream_last_frame_url" type="string">

</ResponseField>

<ResponseField name="content.upstream_video_url" type="string">
  BytePlus 自己的输出视频下载 URL，与重新托管的 `video_url` 并列逐字节返回。仅对由 Comfy 在服务器端已选择加入的工作区轮询的 Seedance 2.x 任务出现（没有请求参数）；对其他所有情况均不出现，包括解析不到任何工作区的凭证（例如未限定到某个工作区的传统 API 密钥）；并且在 BytePlus 于生成 24 小时后清除其 URL 后也不出现。它是预签名的对象存储 URL，因此也是持有者凭证：任何持有它的人都能在过期前下载视频，所以请像对待机密一样对待它。它在 `upstream_expires_at` 过期；在 Seedance 2.5 上，BytePlus 将其限制为 100 次下载，其中一次会被 Router 自身的重新托管消耗。
</ResponseField>

<ResponseField name="content.video_url" type="string">
  输出视频的下载 URL。Router 会将视频重新托管到 Comfy 存储并重写此字段，所以它通常是 Comfy 签名的 URL，有效期最长 24 小时：签发时按 24 小时签名，并从 23 小时缓存中重放，因此后续轮询可能返回一个仅剩一小时有效期的 URL。无法执行重新托管时，该字段会保留 BytePlus 自己的 URL，BytePlus 会在任务结束 24 小时后清除它，并在某些模型上限制为 100 次下载。无论哪种方式，链接都会过期，因此请下载视频，而不是存储 URL。
</ResponseField>

<ResponseField name="created_at" type="integer">
  任务创建时间。该值为 UNIX 时间戳，单位为秒。
</ResponseField>

<ResponseField name="duration" type="number">
  生成视频的时长，单位为秒。声明为数字而不是整数，因为 BytePlus 对此并不一致：已观察到视频任务返回整秒，而其他 BytePlus 接口会报告小数时长，因此客户端不得假定其为整数值。这是 BytePlus 自有字段，在成功的视频任务上返回并原样转发。
</ResponseField>

<ResponseField name="error" type="object">
  错误信息。如果任务成功，则返回 null；如果任务失败，则返回错误信息。
</ResponseField>

<ResponseField name="error.code" type="string">
  上游 ModelArk 错误代码。SensitiveContentDetected、InputTextSensitiveContentDetected、InputImageSensitiveContentDetected、InputVideoSensitiveContentDetected、InputAudioSensitiveContentDetected、OutputTextSensitiveContentDetected、OutputImageSensitiveContentDetected、OutputVideoSensitiveContentDetected 和 OutputAudioSensitiveContentDetected 表示内容策略拒绝。某个系列可能带有以点分隔的原因，例如 InputImageSensitiveContentDetected.PrivacyInformation、OutputVideoSensitiveContentDetected.PolicyViolation 或 OutputImageSensitiveContentDetected.DeepFake。这是一个开放字符串，不是枚举：其他代码描述验证和提供商故障。Router 会在 HTTP 400 错误响应包和 HTTP 200 失败任务响应中识别策略系列，而不会覆盖传输失败。
</ResponseField>

<ResponseField name="error.message" type="string">
  报错信息
</ResponseField>

<ResponseField name="id" type="string">
  The ID of the video generation task
</ResponseField>

<ResponseField name="model" type="string">
  任务所使用的模型名称和版本
</ResponseField>

<ResponseField name="output_format" type="string">
  生成视频的容器格式（mp4 或 mov），在顶层作为 `content` 的同级字段返回，Seedance 视频任务查询就是在这里返回该字段。BytePlus 自有字段，原样转发。
</ResponseField>

<ResponseField name="resolution" type="string">
  生成视频的分辨率，例如 `1080p`。BytePlus 自有字段，在成功的视频任务中返回并原样转发。
</ResponseField>

<ResponseField name="seed" type="integer">
  任务实际使用的生成种子。BytePlus 自有字段，在成功的视频任务中返回并原样转发。

  格式：`int64`
</ResponseField>

<ResponseField name="status" type="string">
  任务的状态

  可能的值：`queued`, `running`, `cancelled`, `succeeded`, `failed`, `expired`
</ResponseField>

<ResponseField name="updated_at" type="integer">
  任务最后更新的时间。该值为 UNIX 时间戳，单位为秒。
</ResponseField>

<ResponseField name="usage" type="object">
  请求的 token 使用量
</ResponseField>

<ResponseField name="usage.completion_tokens" type="integer">
  模型生成的 token 数量
</ResponseField>

<ResponseField name="usage.total_tokens" type="integer">
  对于视频生成模型，不计算输入 token 数量，默认为 0。因此，total_tokens = completion_tokens。
</ResponseField>
