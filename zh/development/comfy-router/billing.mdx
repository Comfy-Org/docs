当提供商向 Comfy 收费时，你才会被计费。同一规则适用于同步调用和[排队](/zh/development/comfy-router/queue#幂等性与计费)调用，使用相同 key 并重放结果的[重试](/zh/development/comfy-router/errors#重试结果)不会产生第二笔费用。

## 模型计费事实

`GET /v2/models` 和模型详情响应中都包含 `billing.charges_on_policy_rejection`。该字段描述的是策略拒绝，而不是所有失败情况或价格估算。

| 值 | 含义 |
| --- | --- |
| `yes` | 策略拒绝会收费。 |
| `no` | 策略拒绝不收费。 |
| `unknown` | 尚无人确认该行为。请按可能收费来处理。 |

请显式比较这些字符串：`"no"` 在 Python 和 JavaScript 中为真值。将任何无法识别的值视为 `unknown`。因积分不足而被拒绝的请求会返回 `insufficient_credits`。

## 对账费用

提供商的载荷中可能带有其自己的成本或用量数字；这些并不是 Comfy 的收费。`X-Comfy-Credits-Used` 可能对允许列表中的提供商出现，但它并非普遍适用，也不会被重放。请使用[工作区用量和发票](https://platform.comfy.org)进行对账。排查收费问题时，请保留请求 ID。
