Comfy Router 通过 fal 提供的 xAI Grok Voice 中转实时语音到语音会话。你只需使用自己的 Comfy API 密钥，与 Router 建立一个 WebSocket 连接。Router 会校验你的账户和积分，在上游开启会话，然后在两个方向上中转事件。会话费用按秒从你的 Comfy 积分中扣除。

## 端点

```text
wss://api.comfy.org/v2/realtime/fal/xai/grok-voice/realtime
```

该请求属于 WebSocket 升级请求（`GET`，并带有 `Connection: Upgrade` 和 `Upgrade: websocket`）。其他任何请求都会被拒绝，并返回 `426`。

## 身份验证

在升级请求的请求头中发送你的 Comfy API 密钥，可以使用 `X-API-Key: comfyui-...` 或 `Authorization: Bearer comfyui-...`。Router 不会从查询字符串或 WebSocket 子协议中读取密钥。

<Warning>
浏览器无法为 WebSocket 设置请求头，而且 Comfy API 密钥绝不能传到浏览器。请从服务器打开会话，并自行将音频转发到浏览器。
</Warning>

## 连接

升级成功后，即可收发 xAI 为 Grok Voice 文档中记录的实时事件。下面的示例会配置会话、发送一轮文本对话，并打印它收到的每个事件类型。

<CodeGroup>

```python Python
# pip install websockets msgpack
import asyncio
import os

import msgpack
import websockets

URL = "wss://api.comfy.org/v2/realtime/fal/xai/grok-voice/realtime"


async def send(ws, event):
    await ws.send(msgpack.packb(event))


async def main():
    async with websockets.connect(
        URL,
        additional_headers={"X-API-Key": os.environ["COMFY_API_KEY"]},
    ) as ws:
        await send(ws, {
            "type": "session.update",
            "session": {
                "voice": "eve",
                "instructions": "You are a helpful assistant.",
                "turn_detection": {"type": "server_vad"},
            },
        })
        await send(ws, {
            "type": "conversation.item.create",
            "item": {
                "type": "message",
                "role": "user",
                "content": [{"type": "input_text", "text": "Hello!"}],
            },
        })
        await send(ws, {"type": "response.create"})

        async for message in ws:
            if isinstance(message, str):
                continue  # fal 自己的 x-fal-message 帧
            event = msgpack.unpackb(message)
            print(event["type"])
            if event["type"] == "response.done":
                break


asyncio.run(main())
```

```javascript Node.js
// npm install ws @msgpack/msgpack
import WebSocket from "ws";
import { encode, decode } from "@msgpack/msgpack";

const ws = new WebSocket(
  "wss://api.comfy.org/v2/realtime/fal/xai/grok-voice/realtime",
  { headers: { "X-API-Key": process.env.COMFY_API_KEY } },
);

ws.on("unexpected-response", (req, res) => {
  // 升级被拒绝。JSON 响应体会说明原因。
  let body = "";
  res.on("data", (chunk) => (body += chunk));
  res.on("end", () => console.error(res.statusCode, body));
});

const send = (event) => ws.send(encode(event));

ws.on("open", () => {
  send({
    type: "session.update",
    session: {
      voice: "eve",
      instructions: "You are a helpful assistant.",
      turn_detection: { type: "server_vad" },
    },
  });
  send({
    type: "conversation.item.create",
    item: {
      type: "message",
      role: "user",
      content: [{ type: "input_text", text: "Hello!" }],
    },
  });
  send({ type: "response.create" });
});

ws.on("message", (data, isBinary) => {
  if (!isBinary) return; // fal 自己的 x-fal-message 帧
  const event = decode(data);
  console.log(event.type);
  if (event.type === "response.done") ws.close();
});

ws.on("close", (code) => console.log("closed", code));
```

</CodeGroup>

完成后请立即关闭 socket。计费会持续到会话关闭为止，而不是到最后一个响应结束。

## 事件

Router 不定义自己的事件协议。服务器事件会完全按照 fal 发送的原样抵达你这边，Router 接受的客户端事件也会被原样转发。关于事件列表、会话字段、音色和音频格式，请参阅：

- [xAI Speech to Speech](https://docs.x.ai/developers/model-capabilities/audio/speech-to-speech) 以及 xAI 的 [realtime 事件 schema](https://docs.x.ai/voice-realtime.ws.json)
- fal 的 [Grok Voice realtime 模型页面](https://fal.ai/models/xai/grok-voice/realtime)及其 [API 页面](https://fal.ai/models/xai/grok-voice/realtime/api)

请像示例中那样，把每个客户端事件作为单条 msgpack 二进制消息发送。这是 fal 的 realtime 客户端所用的封装方式，模型的事件也会以同样的方式返回，即从 `session.created` 开始的 msgpack 二进制消息。fal 还会发送自己的 JSON 文本消息，类型为 `x-fal-message`（计时信息）；你可以跳过它们。Router 的检查也接受把客户端事件作为单条 JSON 文本消息发送，但除非你已用你的客户端测试过 JSON，否则请使用 msgpack。

Router 在转发每个客户端事件之前都会进行检查：

- **事件类型：**`session.update`、`input_audio_buffer.append`、`input_audio_buffer.commit`、`input_audio_buffer.clear`、`conversation.item.create`、`conversation.item.delete`、`conversation.item.truncate`、`response.create`、`response.cancel`，以及 fal 的 `x-fal-session.configure`。
- **模型：**`session.update` 中的 `model` 必须是 `grok-voice-latest`、`grok-voice-3.0` 或 `grok-voice-2.0`。
- **工具：**由你的客户端执行的函数工具是允许的。服务器端工具（搜索、X 搜索、文件搜索和 MCP）会被拒绝。
- **媒体：**图像和视频输入会被拒绝。会话仅支持语音和文本。
- **大小：**单条客户端消息最大为 1 MiB。

被拒绝的事件不会被转发，并且 Router 会以关闭码 `1008` 关闭会话。

## 定价

一次会话的费用为**每秒 $0.0011869**（约每分钟 $0.0712，或每秒 0.2504 积分、约每分钟 15.0 积分，按 211 积分 = 1 美元计算）。会话开启期间按 15 秒的增量计费，最后不足 15 秒的部分按秒计费并向上取整。计费从升级开始，直到 socket 关闭为止，无论音频是否在传输。

## 限制

| 限制 | 值 |
| --- | --- |
| 每账户会话数 | 同一时间只能有一个打开的会话。打开第二个会话会返回 `429`，错误码为 `router.realtime.session_already_live`。 |
| 会话时长 | 最长 30 分钟，且绝不会超过连接时您的积分余额所能覆盖的时长。 |
| 会话期间的积分 | Router 每 15 秒重新检查一次您的余额，当余额不足以覆盖下一秒时便结束会话。 |
| 连接速率 | 每次升级尝试都计入您的[按调用方计算的请求速率](/zh/development/comfy-router/limitations#请求按调用方进行速率限制)，并与其他 Router 调用共享该速率。 |

当会话达到时间上限或积分已用完时，连接可能会在没有关闭帧的情况下关闭（通常表现为关闭码 `1006`）。请仅在上限充值之后重新连接，或者如果需要更长时间，请开启新会话。

## 错误

### 升级之前

如果 Router 拒绝连接，它不会切换协议，而是返回 HTTP 状态码和 JSON 响应体：

```json
{
  "detail": "Insufficient credits to open a realtime session.",
  "error_type": "insufficient_credits",
  "code": "router.realtime.insufficient_credits"
}
```

请根据 `code` 进行判断；`detail` 供人阅读。

| 状态 | `code` | 原因 | 处理方法 |
| --- | --- | --- | --- |
| `426` | `router.realtime.upgrade_required` | 该请求不是 WebSocket 升级请求。 | 使用 WebSocket 客户端连接。 |
| `401` | `router.realtime.unauthorized` | API 密钥缺失或无效。 | 在 `X-API-Key` 或 `Authorization: Bearer` 中发送有效的密钥。 |
| `402` | `router.realtime.insufficient_credits` | 你的余额不足以支付至少一秒的会话。 | 添加积分，然后重新连接。 |
| `402` | `router.realtime.spend_denied` | 会话将要计费的钱包没有可用资金。响应体中的 `denied_reason` 和 `billed_workspace` 会指明是哪个钱包。 | 向该工作区添加积分，然后重新连接。 |
| `403` | `router.realtime.provider_disabled` | 你的工作区的合作伙伴提供商策略不允许此提供商。 | 请工作区管理员允许该提供商。 |
| `404` | `router.realtime.model_not_allowed` | URL 中的模型不可用于实时会话。 | 检查 URL。 |
| `429` | `router.realtime.rate_limited` | 你已超出请求速率。 | 等待 `Retry-After`，然后重试。 |
| `429` | `router.realtime.session_already_live` | 你的账号已打开另一个会话。 | 请先关闭它。 |
| `429` | `router.realtime.concurrency_limit` | 合作伙伴模型的并发调用过多。 | 减少并发工作，然后重试。 |
| `502` | `router.realtime.upstream_refused`、`router.realtime.token_mint_failed` | 上游提供商未能打开会话。 | 使用退避策略重试。 |
| `503` | 任何其他 `router.realtime.*` 代码 | 实时会话暂时不可用。 | 使用退避策略重试。 |

### 升级之后

| 关闭代码 | 含义 | 处理方法 |
| --- | --- | --- |
| `1008` | 某个客户端事件被拒绝（参见[事件](#事件)）。 | 修复该事件。会话已结束。 |
| `1012` | Router 正在重启。 | 重新连接。将启动新会话，并从新的升级开始计费。 |
| `1006`（无关闭帧） | 通常是会话达到时间限制或积分已用完时客户端报告的结果。网络中断看起来也一样。 | 添加积分或启动新会话。 |

任何其他关闭代码都来自 fal 或 xAI。请参阅[事件](#事件)中链接的文档。
