### `POST /v2/models/{provider}/{model}`

**通过规范模型 ID 同步运行合作伙伴模型。**

运行模型，并在同一响应中接收其已完成的结果。

**参数**

<ParamField path="provider" type="RouterProviderSegment" required>
  规范 `{provider}/{model}` 模型 ID 中的提供商部分。

  类型：[`RouterProviderSegment`](#routerprovidersegment)；字母数字 slug，例如 `anthropic`，最多 64 个字符
</ParamField>

<ParamField path="model" type="RouterModelSegment" required>
  规范 `{provider}/{model}` 模型 ID 中的模型部分。

  类型：[`RouterModelSegment`](#routermodelsegment)；字母数字 slug，例如 `claude-opus-4-6`，最多 128 个字符
</ParamField>

<ParamField header="Idempotency-Key" type="string">
  由调用方生成的密钥，使重试同一次逻辑调用变得安全。

  1–255 个字符
</ParamField>

<ParamField query="model_provider" type="string">
  选择另一个提供商来服务此模型，而不是使用其当前默认提供商；`fal`、`wavespeed`、`runware` 和 `higgsfield` 是备选提供商，`GET /v2/models/{provider}/{model}` 会报告给定模型支持其中哪些。其拒绝会按固定顺序检查，较早的拒绝无论后面的拒绝是否也会触发，都会作出响应：无法识别的值（根本不是已注册的提供商）会以 `400` 拒绝；然后，在请求体选择 multipart 操作（编辑）的请求上，备用提供商会被以 `409` 拒绝，其 `detail` 以 "this request's `image` selects the edit operation" 开头，但仅当该提供商针对此模型的转换器无法服务该操作时才会如此：若某个通道的转换器确实能承载该媒体，则会正常继续；然后，在解析到自带密钥凭据的请求上，任何备用提供商都会被以 `409` 拒绝，其 `detail` 以 `this request resolved a BYOK credential` 开头（参见该响应），无论该提供商是否服务此模型；然后是所指定提供商自身的准入检查：当该提供商未为你启用时，它会以 `error_type: not_enabled` 拒绝并返回 `403`；当无法评估该检查时，则会以 `error_type: service_unavailable` 拒绝并返回 `503`；只有通过以上四道检查后，真实提供商若没有适用于此模型的通道，才会以 `error_type: invalid_input` 拒绝并返回 `400`，这与无法识别值的响应相同。在自带密钥请求、请求体选择 multipart 操作的请求以及 `strict_mode=true` 时，`fallback_provider` 不起作用，而不是被拒绝。
</ParamField>

<ParamField query="strict_mode" type="boolean">
  仅与 `model_provider` 一起使用时才有意义。

  默认值：False
</ParamField>

<ParamField query="fallback_provider" type="string">
  控制当首次尝试因可归因于 Router 或所尝试提供商的原因而失败时，Router 是否针对该模型的其他已注册提供商重试此调用。省略此参数，或使用除 `false` 以外的任何值，都会保持回退开启；`false` 会将其关闭。成功的回退响应会携带 `X-Comfy-Router-Fallback-Provider`。在解析到自带密钥凭据的请求上，无论此参数取什么值，回退都不可用：不会进行尝试，首次失败会原样到达你这里，这属于不起作用，而不是被拒绝：此处不会产生 `409`。同样地，出于相同原因，在请求体选择 multipart 操作的请求上以及 `strict_mode=true` 时也是如此：每种情况都会将调用绑定到一个提供商，而该调用无法被如实地对另一个提供商重放，因此回退会被直接跳过，而不是被拒绝。只有显式指定 `model_provider` 时，才会以该 `409` 被拒绝；与这种无条件跳过不同，其 multipart `409` 仅适用于转换器无法服务该操作的通道。
</ParamField>

<ParamField query="reject_unknown_fields" type="boolean">
  选择拒绝此模型输入 schema 未声明的顶层请求体字段，而不是接受它；不会检查嵌套字段，并且对于 schema 允许未声明字段或没有编写 schema 的模型，不会拒绝任何内容；对于使用 `strict_mode=true` 发送的排队提交，也是如此。

  默认值：False
</ParamField>

**请求体**

`application/json`：[`RouterModelInput`](#routermodelinput)（必填）合作伙伴模型的原生 JSON 输入。未指定 `model_provider` 时，该 body 就是模型自身的原生 schema；当由模型自己的提供商处理该调用时，调用方的 `strict_mode` 不会带来任何改变；当 Comfy Router 本身把这类调用路由到另一个提供商时，Router 会为该提供商转换 body，而 `strict_mode` 在那里如何生效不属于本约定的范围。使用 `model_provider` 选择替代提供商且 `strict_mode=false`（默认值）时，body 在发送之前会被转换为该提供商的真实 schema：任何无法精确表达的原生字段都会被丢弃，并通过响应的 `X-Comfy-Router-Dropped-Params` 响应头披露，绝不会静默处理。使用 `model_provider` 选择替代提供商且 `strict_mode=true` 时不会执行任何转换：body 必须已经是该替代提供商自己的真实 schema，而不是本模型的原生 schema（参见 `strict_mode`），并会原样转发。body 自身的字段还会决定 Router 在支持多种操作的模型上运行哪一种操作：对于可编辑的图像模型，包含输入图像会把它从文生图切换为图生图（编辑）操作，该操作可能按各自的费率计费；对于 Seedance 视频模型，`content[].role` 决定操作（首帧图像选择图生视频，参考图像或视频片段选择参考生视频）。当由模型自己的提供商处理该调用时，Seedance 计费依据的是 `content` 中的媒体类型，而不是角色：任何包含视频输入的请求都按视频转视频计费，否则包含图像即按图生视频计费，再否则按文生视频计费；例外是来自 `draft_task` 条目的最终渲染按其渲染的 Draft 所属操作计费；某些模型对文生视频和图生视频收取相同的费率。当 `model_provider` 选择替代提供商，或 Comfy Router 在另一个提供商上处理该调用时，每个带条件的操作可能按该提供商自己的费率计费。

**响应**

  Body: [`RouterModelOutput`](#routermodeloutput) 或原始字节（`*/*`） -- Headers: `X-Comfy-Request-Id`、`X-Content-Type-Options`、`X-Comfy-Router-Fallback-Provider`、`X-Comfy-Router-Provider`、`X-Comfy-Router-Dropped-Params`、`X-Comfy-Credits-Used`、`Idempotent-Replayed`、`X-Committed-Spend-Limit`、`X-Committed-Spend-Current`、`X-Committed-Spend-Remaining`

### `POST /v2/models/{provider}/{model}/estimate`

**在运行模型调用之前先为其定价，而无需实际运行它。**

以美元返回一次预检估算，说明在此模型上运行该请求正文将会产生多少费用，并按 Comfy 的标准标价计价（对于按其供应商上报的成本计费的模型，则改为根据供应商公布的价格表进行估算）。它不反映合同费率或客户特定费率：已协商定价的工作区会按标准标价报价，并按合同费率计费，此时 `source: exact` 表示按标准标价精确，而不是该工作区的实际费用。它只是估算，不是最终费用：你实际支付的是工作区用量与账单记录中的结算费用。请求正文会先按模型的输入 schema 校验，校验方式与默认运行（不传 `strict_mode`、不传 `reject_unknown_fields`）相同，因此未通过模型 schema 的正文在这里和在运行时一样返回同一个 `422`；不会向任何提供商派发请求，也不会产生费用。该结果不是价格锁定：它按 `pricing_as_of` 时点生效的费率计价，而运行则按其计费时点生效的费率收费。如果某个部署关闭了估算功能，该路由会返回 `403`，并带有 `error_type: not_enabled`；Router 尚无法运行的模型会返回同样的 `403`，但 `detail` 来自运行路由自身，因此要读取 `detail` 来区分这两种情况。请求正文按 Router 实际派发的方式定价：针对其指定的 `model_provider` 分支进行转换，并重定向到它实际执行的操作，顺序与已入队提交的 `201` 响应中的 `estimate` 相同。不过那个 `estimate` 并不是预检价格：它只有在运行被接受并入队之后才会返回，且该运行除非在派发前被取消，否则会产生费用。

**参数**

<ParamField path="provider" type="RouterProviderSegment" required>
  规范 `{provider}/{model}` 模型 ID 中的小写提供商段，即正在运行其模型的合作伙伴。

  类型：[`RouterProviderSegment`](#routerprovidersegment) -- 字母数字 slug，例如 `anthropic`，最多 64 个字符
</ParamField>

### `POST /v2/models/{provider}/{model}/requests`

**将合作伙伴模型的一次运行提交到队列并立即返回。**

Comfy Router 的队列投递模式。请求体与该模型的同步路由 `POST /v2/models/{provider}/{model}` 所接受的合作伙伴原生 JSON 输入相同：一种请求体形状、一份按模型定义的 schema、两种投递模式，但这条路由不会为了结果而保持连接。它接纳该次运行，返回 `201` 和一个句柄，调用方随后通过下面的三个读取接口取回结果。

<ParamField path="model" type="RouterModelSegment" required>

  类型：[`RouterModelSegment`](#routermodelsegment)，字母数字 slug，例如 `claude-opus-4-6`，最多 128 个字符
</ParamField>

<ParamField query="model_provider" type="string">

</ParamField>

<ParamField query="strict_mode" type="boolean">

  默认值：False
</ParamField>

<ParamField header="Idempotency-Key" type="string">

</ParamField>

`application/json`：[`RouterModelInput`](#routermodelinput)（必填）

### `PUT /v2/models/{provider}/{model}/requests/{request_id}/cancel`

**请求取消一个已提交的请求。**

请求 Comfy 停止一个尚未完成的请求。这只是一个请求，而非保证，`202` 表达的正是这个意思：`CANCELLATION_REQUESTED` 表示该请求已被接受，而并不表示该运行已经停止。合作伙伴处已经在传输途中的运行可能仍会完成，而合作伙伴完成的生成会被计费，无论是否有人取走结果。因此，需要知道实际发生了什么的调用方应在之后读取状态端点，在那里，已生效的取消是 `COMPLETED`，并带有 `error_type`，与其他所有终态结果一样。

**参数**

<ParamField path="provider" type="RouterProviderSegment" required>
  规范 `{provider}/{model}` 模型 ID 中的小写提供商段，即正在运行其模型的合作伙伴。

  类型：[`RouterProviderSegment`](#routerprovidersegment) -- 字母数字 slug，例如 `anthropic`，最多 64 个字符
</ParamField>

## 错误分类

Router 错误的机器可读类别，同时也会在 `X-Comfy-Error-Type` 响应头中发送。

### 请求级分类

针对 Router 已接受但随后无法完成的请求抛出。

| `error_type` | 含义 |
| --- | --- |
| `invalid_input` | 请求在到达模型之前就被拒绝：请求体格式错误、分页游标格式错误或已过期、模型自身的 schema 不接受的输入，或无法用于此请求的 `Idempotency-Key`（已用于其他请求，即方法、路径与查询或请求体不同；或已被某个其响应无法重放的调用消耗）。 |
| `content_policy_violation` | 提供商以内容政策为由拒绝了请求。 |
| `provider_error` | 合作伙伴提供商报告了其自身的故障，或返回了 Router 无法解释为结果的响应。 |
| `provider_timeout` | 合作伙伴提供商未在其截止时间内应答。 |
| `insufficient_credits` | 发起调用的工作区没有足够的积分来运行该模型。 |
| `model_not_found` | `{provider}/{model}` ID 未指向任何 Router 可运行的模型：提供商未知、ID 未登记、目录已在其停用日期之后将其退役，或提供商当前未为 Comfy 提供某个已编目 ID 的服务。 |
| `byok_credential_rejected` | 提供商拒绝了为此调用提供的密钥。 |

### 传输级分类

由 Router 自身抛出，发生在调用模型之前或调用过程之中。

| `error_type` | 含义 |
| --- | --- |
| `unauthorized` | 请求未携带可用的凭据。 |
| `forbidden` | 凭据有效，但无权访问此模型或执行此操作。 |
| `concurrency_limit_exceeded` | 工作区正在进行的调用数量已达到允许的上限；请等待其中一项调用完成后重试。 |
| `client_disconnected` | 调用方在 Router 能够返回结果之前关闭了连接。 |
| `internal_error` | Router 自身发生故障。 |
| `deadline_exceeded` | 在应答到达之前，Comfy 已按自身配置的时限停止保持连接。 |
| `not_enabled` | Comfy Router 尚未为该调用方启用。 |
| `service_unavailable` | Comfy Router 依赖的某个服务暂时不可用，调用方没有任何过错。 |
| `rate_limited` | 调用方已用尽按窗口计量的配额，必须等待该窗口滚动更新；或模型提供商在开始任何生成之前对该调用进行了限流。 |
| `cancelled` | 已排队的请求在产生结果之前被撤回，无论是通过取消路由还是由操作员操作；它处于终态，本身并不构成关于计费的说明。 |
| `queue_timeout` | 已排队的请求等待超过了其队列超时时间，始终未被准入。 |
| `request_not_found` | `request_id` 未指向该调用方在此模型下的任何请求。 |
| `queue_backlog_full` | 调用方已有过多等待运行的排队请求，因此此次提交被拒绝。 |
| `result_expired` | 请求确实存在且已完成，但其结果已不再存储，因此收集操作没有可返回的内容。 |

## 预检成本估算

`POST /v2/models/{provider}/{model}/estimate` 可在不运行请求体的情况下为其定价，而已排队的提交（`POST /v2/models/{provider}/{model}/requests`）会在其 `201` 响应中返回与 `estimate` 相同的 [`RouterCostEstimate`](#routercostestimate)。两者均按 Comfy 的标准标价定价，但按供应商报告的成本计费的模型除外，该成本会根据供应商公布的价格表估算（`estimated`）。两者都不反映合同费率或客户特定费率：具有协商定价的工作区会按标价报价，但按其合同费率收费，此时 `source: exact` 表示在标价上精确，而不是该工作区的实际收费。两个接口返回的每个数字都是估算值，而不是最终费用：工作区使用情况和账单记录中的结算费用才是最终费用。使用自己的提供商密钥进行的运行不会由 Comfy 计费（见下文）。如果某个部署关闭了估算功能，该路由会返回 `403`，并带有 `error_type: not_enabled`，且提交响应会省略 `estimate`。两者都会按照 Router 分发请求体的方式为其定价（针对 `model_provider` 分支进行转换，并重定向到其实际运行的操作），但提交响应中的 `estimate` 不是预检价格：它只有在运行被接纳并排队后才会出现，而且除非在分发前被取消，否则该运行会被计费。目录仍然不包含价格。

在关注任何金额之前，请先读取 `source`。缺失的数值绝不意味着免费。

| `source` | 携带内容 | 如何解读 |
| --- | --- | --- |
| `exact` | `amount`、`amount_cents`、`credits` | 一个估算值，等于该请求体按 `pricing_as_of` 中所列费率应收取的费用；最终以你工作区用量与账单记录中的结算费用为准。 |
| `estimated` | `min_amount`、`max_amount` 及其 `_cents` 形式，不含 `amount` | 一个估算值，其费用取决于提供商回传的某个数量，而请求体为该数量给出了边界；预期费用落在该边界之间，最终以你工作区用量与账单记录中的结算费用为准。 |
| `free` | `amount` "0"，`amount_cents` 与 `credits` 为 `0` | 费率卡将该请求定价为零，因此估算值为 `0`；最终以你工作区用量与账单记录中的结算费用为准。只有 `free` 报价才读作 `0`。 |
| `unknown` | `reason`，不含任何数值 | 运行前无法给出价格。将任何其他 `source` 值都视为 `unknown`。 |

`unknown` 估算的 `reason` 为以下之一：

- `not_quotable`：Router 无法在运行前为这次调用定价，因为它按提供商回传、而请求体未加限定的数量计费，或者请求体无法按其发送的内容定价。将任何无法识别的 `reason` 都视为 `not_quotable`。
- `unpriced_model`：费率卡未对该请求定价。
- `byok`（仅排队提交）：该次运行使用你自己的提供商密钥，因此 Comfy 不为其计费。
- `pricing_unavailable`（仅排队提交）：请求被接受时无法读取费率卡。提交仍会被接受，运行照常计费。

Router 尚无法在运行前定价的模型列在[没有预检估算的模型](/zh/development/comfy-router/limitations#无法预先估算的模型)中。未列在该处的模型针对特定请求体仍可能返回 `unknown`，因此请对每个估算都读取 `source`。

估算采用失败关闭（fail closed）的情形：

- 当某个数值需要费率卡，而费率卡未加载或已过期时，`/estimate` 会返回 `503`，而不是给出猜测。排队提交绝不会因为其估算而被拒绝；它会携带 `source: unknown` 和 `reason: pricing_unavailable`。完全无法在运行前定价的调用（`not_quotable`），或使用自有提供商密钥的排队提交（`byok`），会在不读取费率卡的情况下作答，因此那个 `200` 并不说明费率卡是否最新。
- `/estimate` 会像默认运行那样，按模型自身的输入 schema 校验请求体，因此不符合模型 schema 的请求体会得到与该次运行相同的 `422`，以及相同的 `detail[]` 形状。此时不会定价，也不会派发。
- 排队提交的幂等重放（`Idempotent-Replayed: true`）会省略 `estimate`，因为原始报价未被存储。

估算的局限。一个 `200` 的数字并不代表该次运行一定会被接受，也不代表一定按该金额收费：

- `/estimate` 不接受 `strict_mode` 或 `reject_unknown_fields`，因此只校验模型的原生约定：一个在 `strict_mode=true` 运行中按备用提供商自身 schema 可以接受的请求体，在这里可能得到 `422`；而某个未声明的顶层字段，在 `reject_unknown_fields=true` 的运行中会被拒绝，在这里却会被定价。Anthropic Messages 模型是例外：其 schema 允许未声明字段，因此 `reject_unknown_fields=true` 的运行不会拒绝任何字段，而估算只会为未声明的顶层字段 `tools`、`tool_choice`、`temperature`、`top_p`、`top_k`、`stop_sequences`、`metadata`、`thinking` 以及空的 `mcp_servers` 定价。任何其他未声明的顶层字段都会使其返回 `unknown`，并带有 `reason: not_quotable`。
- `pricing_as_of` 是费率卡的获取时间。取自供应商公布价格表的 `estimated` 报价携带的是读取该价格表的日期。计费数量由供应商公布的调度表预测、再按费率卡定价的 `exact` 或 `estimated` 报价，在该调度表的读取日期早于费率卡时携带该调度表的读取日期。费率卡与调度表都未读取时，它则是估算作答的时间。它不是价格锁定：运行按其被计费评级时生效的费率收费。
- `/estimate` 为 `model_provider` 指定的分支报价，或为原生提供商报价。它不接受 `fallback_provider` 或 `strict_mode` 参数。同步运行的回退重试落到另一个提供商时，按该提供商的费率计费，而该费率并非估算所报的费率；运行响应上的 `X-Comfy-Router-Fallback-Provider` 表明发生了这种情况。排队提交没有回退，因此其 `estimate` 报的就是实际运行的分支。
- `/estimate` 始终报出平台费用。使用自有提供商密钥的运行不由 Comfy 计费，但 `/estimate` 不会检测这一点，仍会返回一个数值；只有排队提交才会返回 `reason: byok`。
- 美元金额由未舍入的美分渲染，最多保留 8 位小数，可计费的不足 1 美分的 `amount` 绝不会显示为 `0`。`credits` 为 `round(amount × 211, 2)`，这与 `X-Comfy-Credits-Used` 对一次收费所采用的换算相同，因此对于极小的非零价格，`credits` 可能舍入为 `0`；在这一点很重要时，请按 `amount` 或 `amount_cents` 编制预算，而不是按 `credits`。该响应头仍是某次运行结束后的事后数值；余额保存在 Comfy 平台上。

## 结果资产

模型可以返回资产 URL、内联字节，或两者兼有。下面的提供商会将已选择的资产复制到 Comfy 存储上并替换其 URL。此行为取决于模型；没有任何请求头能选择它。

| 模型 | 复制到 Comfy 存储的内容 | Comfy 托管 URL 的最长有效期 |
| --- | --- | --- |
| `bfl/*` | 已完成资产，以及结果中携带的草稿缓存资产（如有） | 24 小时 |
| `byteplus/*` 视频模型（`seedance`、`dreamina-seedance`） | 已完成视频，以及结果中携带的末帧图像（如有） | 24 小时 |
| `minimax/*` | 已完成视频 | 12 小时 |
| `xai/*` | 每一张已生成的图像，以及已完成视频 | 24 小时 |

这些有效期从 URL 签名时开始计算，而不是从你打开它时开始。缓存或重放的 URL 可能剩余时间更少；重放不会为其续期。一条 `Idempotency-Key` 记录的有效期可能长于它所保存的 URL，因此在这样的 URL 到期前一小时起，使用同一键重试会得到 `409 invalid_input`，而不是记录中的响应；若某条响应在送达时就已如此接近到期，则它在 5 分钟内仍可重放。请及时下载资产。只有每一行中列出的资产会被复制：`byteplus/seedream-*` 和 `byteplus/seededit-*` 图像不在 BytePlus 视频行的覆盖范围内。

复制只由模型的原生提供商执行。由替代提供商提供服务的运行会返回该提供商自己的 URL，这些 URL 遵循提供商的过期时间，且不会被复制。此类运行包括：`model_provider` 指定了某个替代提供商；未指定 `model_provider` 但由 Comfy Router 在另一个提供商上提供服务的运行（在同步运行路由上通过 `X-Comfy-Router-Provider` 报告）；以及回退重试落到替代提供商上的原生运行（通过 `X-Comfy-Router-Fallback-Provider` 披露）。`model_provider` 取值 `default`、`comfy` 和 `comfyui` 时不指定替代提供商，因此这些运行属于原生运行，并如上所述进行复制；`model_provider` 运行的回退重试落回原生提供商时也同样如此。

**Veo（`veo/*`）有单独的存储路径。** 在 `response.videos[]` 中，读取其中存在的成员：`bytesBase64Encoded` 内联包含视频片段，而当环境配置为提供商直接写入 Comfy 存储时，`gcsUri` 包含一个 Comfy 签名的 HTTPS 链接。该链接自响应起 24 小时内有效。后一种情况是直接写入资产而非复制，因此 Veo 不在重新托管表中。

其他模型返回提供商资产引用或内联字节。提供商 URL 遵循提供商的过期时间，这可能比上述有效期短得多，且 Router 契约未对此作出规定。

**原始 BytePlus URL（Seedance 2.x，需选择启用）。** 对于 Comfy 已在服务器端选择启用的工作区，Seedance 2.x 的结果还会在已复制的 URL 之外，于 `content.upstream_video_url` 和 `content.upstream_last_frame_url` 中携带 BytePlus 自己的 URL，以及 `content.upstream_expires_at`。没有请求参数，且默认没有任何工作区被选择启用。这些 URL 在生成后 24 小时过期，一旦 BytePlus 清除它们便不再出现；在 Seedance 2.5 上，BytePlus 将每个 URL 的上限设为 100 次下载，而 Router 自己的副本会占用其中一次。每个 URL 都是其对象的持有者凭证：任何持有者在过期前都可以下载该资产。

**零数据保留的工作区。** 对于 Comfy 配置为零数据保留的工作区，BytePlus 的结果不会复制到 Comfy 存储：上文中的 `byteplus/*` 视频行不适用，`content.video_url` 和 `content.last_frame_url` 就是 BytePlus 自己的提供商 URL，按 BytePlus 发送时的原样返回。这些 URL 有效期为 24 小时，并且在 Seedance 2.5 上 BytePlus 将每个 URL 限制为 100 次下载，因此请尽快下载资产。此类结果不会从其 `Idempotency-Key` 记录重放。

复制是按资产尽力而为的。如果某个复制失败，该条目会保留其提供商引用；响应可以同时包含 Comfy 和提供商 URL，且没有明确的按资产复制状态字段。生成仍会成功并计费。不要根据一个成功重新托管的资产来推断每个 URL 的有效期。

结果是否由 Comfy 托管也决定了已完成的调用以后是否仍能从其 `Idempotency-Key` 记录中重放；上面的 `Idempotency-Key` 参数说明了无法重放时重试会得到怎样的回应。

## 各模型的输入和输出架构

每个模型的字段可通过 `GET /v2/models/{provider}/{model}/openapi.json` 读取。该调用需要 API 密钥。对于每个具有已编写架构的模型，同一文档也在本站点上公开发布，无需密钥，地址为 `/router-schemas/{provider}/{model}.json`。该副本是上次文档更新时生成的快照，因此当两者不一致时，以端点为准。该操作的 `requestBody` 描述输入验证；在已编写的情况下，其 `200` 响应描述输出形状和媒体类型。当 `x-comfy-input-schema-authored` 为 false 时，Router 接受任意 JSON 对象，而不进行特定于模型的预验证。提供商依赖项仍然适用。输出架构描述的是结果；Router 不会依据它们验证提供商返回的载荷。未编写的输出可能使用 `*/*` 而非 `application/json`；在解码之前，请检查响应的内容类型。

### RouterCostEstimate

对本次调用费用的预检估算，单位为美元；在派发前按 Comfy 的标准标价计算，或者对于按提供商报告的费用计费的模型，则根据提供商公布的价目表计算。对于这种按提供商报告费用的情况，`source: exact` 仅对一小组选择加入的模型返回，并且仅当公布的价目表能完全确定该数字时才会返回（每个影响价格的字段都已明确给出，或保留在不会改变该数字的默认值上）；其他所有按提供商报告费用的报价都是 `estimated`，包括某些价目表本可完全确定的报价。无论哪种情况，运行结束后仍按提供商报告的金额计费，绝不会完全照报价数字收费。它不反映合同费率或客户特定费率：拥有协商定价的工作区会按标价报价，并按合同费率收费，此时 `source: exact` 表示按标价精确，而不是该工作区的实际收费。它不是最终费用：你支付的费用以工作区用量和账单记录中的结算费用为准。运行结束后报告的 `X-Comfy-Credits-Used` 是四舍五入后的事后数字，不是收据。`source` 表示该数字的可信程度：`exact` 包含 `amount`；`free` 包含 `amount` "0"（费率卡将此请求定价为零）；`estimated` 包含 `min_amount` 和 `max_amount`，不包含 `amount`；`unknown` 两者都不包含，并包含 `reason`。绝不要将缺失的 `amount` 理解为免费。它不是价格锁定：请参见 `pricing_as_of`。

### RouterErrorResponse

认证、访问、模型查找、配额以及提供商传输失败时的错误响应体。

**字段**

<ResponseField name="detail" type="string" required>
  对失败的可读描述，可安全地呈现给最终用户。此字段不做机器解析，请改为根据 `error_type` 分支处理。对于已退役模型上的 `model_not_found`，当存在后继模型且对调用方可见时，`detail` 读作 `<id> was retired on <YYYY-MM-DD>; use <successor>`；当不存在时，仅读作 `<id> was retired on <YYYY-MM-DD>`，而不是通常的建议列表。此处指名的后继模型始终是目录中有效的 ID，调用可以重新指向它。日落日期仍在未来的模型不算已退役：它仍会被 `GET /v2/models` 列出，并在该日期之前保持可运行。与 `detail` 的其余内容一样，这段退役措辞仅用于展示，不附带任何兼容性保证。关于“不做机器解析”规则有两个已记录的例外：在 `POST /v2/models/{provider}/{model}` 上，`409` 会针对三种不相关但同属 `invalid_input` 分类的情况返回，只有 `detail` 能区分它们：以 “this request's `image` selects the edit operation” 开头的 `detail` 是 multipart `model_provider` 拒绝，以 `this request resolved a BYOK credential` 开头的 `detail` 是 BYOK `model_provider` 拒绝；两者都不会因新的 `Idempotency-Key` 而消除。该路由上任何其他 `invalid_input` 的 `409` 都是密钥冲突。这两个前缀是稳定的契约条款，可以被匹配。除此之外，任何地方根据 `detail` 分支都不带兼容性保证。

<ResponseField name="error_type" type="RouterErrorType" required>

### RouterQueueSubmitFields

`RouterQueueSubmitResponse` 中除 URL 块之外的另一半内容：新请求的身份标识，以及它在被接纳那一刻的状态。

**字段**

<ResponseField name="request_id" type="RouterQueueRequestId" required>
  一个已排队 Router 请求的标识符，也是调用方用来轮询、取消并获取结果的句柄。

  类型：[`RouterQueueRequestId`](#routerqueuerequestid) -- `pattern: ^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$`、uuid、最多 36 个字符
</ResponseField>

<ResponseField name="status" type="RouterQueueStatus" required>
  已排队 Router 请求的状态。它恰好有三个值，并且与 `RouterErrorType` 不同，这一项是封闭的 `enum`，因为这两个 schema 是故意朝相反方向封闭的。`RouterErrorType` 用于对失败进行分类，其集合预期会增长，因此，如果一个已生成的客户端硬性拒绝无法识别的分类桶，那么它恰恰会在已经出问题的时候失败得最严重。这一项是一个生命周期，而日后为生命周期增加第四个状态，无论是否声明为 enum，都会对每一个针对它编写的轮询循环构成破坏性变更。因此它被声明为一个 enum，并把这一约束写在客户端能看到的地方。

  类型：[`RouterQueueStatus`](#routerqueuestatus)
</ResponseField>

<ResponseField name="queue_position" type="RouterQueuePosition">
  在响应生成的那一刻，队列中排在此请求前面的请求数量。零表示此请求位于队首。

  类型：[`RouterQueuePosition`](#routerqueueposition) -- 至少 0
</ResponseField>

<ResponseField name="estimate" type="RouterCostEstimate">
  此请求的预检成本估算。当调用方启用了成本估算时，在全新接纳时会提供该字段。它给出的是此请求所固定到的提供商分支（队列没有回退循环，因此 `fallback_provider` 从不改变实际执行的那条分支）。当无法给出具体数字时，该字段仍然存在，值为 `source: unknown`；提交绝不会因为估算而失败。在幂等重放时会省略该字段（`Idempotent-Replayed: true`），因为原始报价不会被存储。它只是估算，不是最终费用，也不是价格锁定：运行会按计费时生效的费率收费，而你的工作区用量与账单记录中结算后的费用才是最终结果。

  类型：[`RouterCostEstimate`](#routercostestimate)
</ResponseField>

### RouterQueueSubmitResponse

当一次运行被接纳进入队列时返回的句柄：包含该请求的身份与状态，并与三个用于访问其生命周期其余部分的 URL 组合在一起。

组合 [`RouterQueueUrls`](#routerqueueurls) 与 [`RouterQueueSubmitFields`](#routerqueuesubmitfields)。

类型：`object`

### RouterQueueUrls

这三个 URL 用于寻址某个排队请求剩余生命周期中的各项资源，它们会在每个携带有效句柄的响应中返回，因此客户端无需自行拼接队列 URL。

**字段**

<ResponseField name="status_url" type="string" required>
  读取此请求状态的绝对 URL。

  URI
</ResponseField>

<ResponseField name="response_url" type="string" required>
  用于收集此请求结果的绝对 URL。

  URI
</ResponseField>

<ResponseField name="cancel_url" type="string" required>
  发起取消请求时使用的绝对 URL。

  URI
</ResponseField>

### RouterValidationErrorContext

提供商提供的关于验证失败的规则的详情。

类型：`object`

### RouterValidationErrorDetail

单个字段级验证失败。

**字段**

<ResponseField name="loc" type="array of any" required>
  出错字段的路径，最外层片段在前，例如 `["body", "image_url"]`，或 `["body", "images", 0]`，其中整数表示数组中的索引。
</ResponseField>

<ResponseField name="msg" type="string" required>
  对本次单个失败的可读描述。
</ResponseField>

<ResponseField name="type" type="string" required>
  本次失败的具体、机器可读的原因，由提供商原样传入。这是类型化 SDK 异常层级据此分支的值；响应头中的 `error_type` 只是它粗略的归类。
</ResponseField>

<ResponseField name="ctx" type="RouterValidationErrorContext">
  单个 `RouterValidationErrorDetail` 所违反的界限，由提供商逐字携带，例如与 `greater_than` 搭配的 `{"limit_value": 8}`、与 `image_too_small` 搭配的 `{"min_width": 512}`，或与 `file_too_large` 搭配的 `{"max_size_bytes": 10485760}`。键集合取决于具体的提供商和错误类型，因此这里有意采用开放对象：将其收窄为固定字段列表，或将其合并进 `msg` 字符串，恰恰会导致移植过来的集成虽然能编译通过，却悄然丢失了原本读取该界限的分支。当错误类型不携带界限时，该字段不存在。

  类型：[`RouterValidationErrorContext`](#routervalidationerrorcontext)
</ResponseField>

<ResponseField name="input" type="RouterValidationErrorInput">
  出错的输入值，原样回传，使调用方无需再从 `loc` 推导就能看到被拒绝的内容。可以是任意 JSON 类型（字符串、数字、布尔、数组、对象或 null），因此此 schema 有意不做类型限定，而不是收窄为对象。当提供商不回传输入时，该字段不存在。

  类型：[`RouterValidationErrorInput`](#routervalidationerrorinput)
</ResponseField>

### RouterValidationErrorInput

被拒绝的输入值，前提是提供商提供了该值。

### RouterValidationErrorResponse

`422` 验证错误响应体，其类别请读取 `X-Comfy-Error-Type`。

**字段**

<ResponseField name="detail" type="array of RouterValidationErrorDetail" required>
  请求中发现的全部验证失败项，每个出错的字段对应一项。

  类型：由 [`RouterValidationErrorDetail`](#routervalidationerrordetail) 组成的数组
</ResponseField>
