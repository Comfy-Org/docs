### `POST /v2/models/{provider}/{model}`

**通过规范模型 ID 同步运行合作伙伴模型。**

运行模型，并在同一响应中接收其已完成的结果。

**参数**

<ParamField path="provider" type="RouterProviderSegment" required>
  规范 `{provider}/{model}` 模型 ID 中的提供商部分。

  类型：[`RouterProviderSegment`](#routerprovidersegment)，字母数字 slug，例如 `anthropic`，最多 64 个字符
</ParamField>

<ParamField path="model" type="RouterModelSegment" required>
  规范 `{provider}/{model}` 模型 ID 中的模型部分。

  类型：[`RouterModelSegment`](#routermodelsegment)，字母数字 slug，例如 `claude-opus-4-6`，最多 128 个字符
</ParamField>

<ParamField header="Idempotency-Key" type="string">
  调用方生成的密钥，使重试同一逻辑调用变得安全。

  1–255 个字符
</ParamField>

<ParamField query="model_provider" type="string">
  选择一个替代提供商来为此模型提供服务，而非其当前默认提供商；`fal`、`wavespeed`、`runware` 和 `higgsfield` 是替代提供商，`GET /v2/models/{provider}/{model}` 会报告给定模型支持它们中的哪些。其拒绝按固定顺序检查，较早的检查无论较晚的检查是否会触发都会作出答复：无法识别的值（完全不是已注册的提供商）会被拒绝并返回 `400`；然后，在主体选择 multipart 操作（编辑）的请求上，替代提供商会被拒绝并返回 `409`，`detail` 以 "this request's `image` selects the edit operation" 开头，但仅当该提供商针对此模型的转换器无法提供该操作时；转换器确实携带媒体的分支会正常进行；然后，在解析了自带密钥（BYOK）凭据的请求上，任何替代提供商都会被拒绝并返回 `409`，`detail` 以 `this request resolved a BYOK credential` 开头（见该响应），无论该提供商是否为此模型提供服务；然后是命名提供商自身的门控，当该提供商未为你启用时，会拒绝并返回 `403`，`error_type: not_enabled`，当无法评估门控时，会拒绝并返回 `503`，`error_type: service_unavailable`；只有在通过全部四项检查之后，真正没有此模型分支的提供商才会被拒绝并返回 `400`，`error_type: invalid_input`，与无法识别的值得到相同的答复。在自带密钥请求、主体选择 multipart 操作的请求以及 `strict_mode=true` 下，`fallback_provider` 不起作用，而非被拒绝。
</ParamField>

<ParamField query="strict_mode" type="boolean">
  仅与 `model_provider` 一起使用时才有意义。

  默认值：False
</ParamField>

<ParamField query="fallback_provider" type="string">
  控制当首次尝试因可归属于 Router 或所尝试提供商的原因而失败时，Router 是否针对该模型的其他已注册提供商重试此调用。省略，或任何非 `false` 的值，都会保持回退开启；`false` 会将其关闭。成功的回退响应会带有 `X-Comfy-Router-Fallback-Provider`。在解析了自带密钥凭据的请求上，无论此参数说什么，回退都不可用：不会进行该尝试，首次失败会原样到达你这里，这是不起作用的，而非被拒绝：这里不会产生 `409`。出于同样的原因，在主体选择 multipart 操作的请求以及 `strict_mode=true` 下也是如此：每一种都将调用绑定到单个提供商，无法在另一个提供商上忠实重放，因此回退会被直接跳过，而非被拒绝。只有显式的 `model_provider` 会被拒绝并返回该 `409`，而且不同于这种无条件跳过，其 multipart `409` 仅适用于转换器无法提供该操作的分支。
</ParamField>

<ParamField query="reject_unknown_fields" type="boolean">
  选择拒绝此模型输入 schema 未声明的顶层请求体字段，而不是接受它；不检查嵌套字段，对于其 schema 允许未声明字段或没有已编写 schema 的模型，或者对于使用 `strict_mode=true` 发送的已执行提交，都不会拒绝任何内容。

  默认值：False
</ParamField>

**请求体**

`application/json` -- [`RouterModelInput`](#routermodelinput)（必填）

合作伙伴模型的原生 JSON 输入。不带 `model_provider` 时，请求会在模型的默认提供商上运行原生分发，此主体就是模型自身的原生 schema，原样转发（`strict_mode` 在那里没有意义，不会改变任何东西）。当 `model_provider` 选择一个替代提供商且 `strict_mode=false`（默认值）时，主体在发送之前会转换为该提供商的真实 schema：任何无法精确表达的原生字段都会被丢弃，并通过响应的 `X-Comfy-Router-Dropped-Params` 标头披露，绝不会静默丢弃。当 `model_provider` 选择一个替代提供商且 `strict_mode=true` 时，不会运行任何转换：主体必须已经是该替代提供商自身的真实 schema，而不是此模型的原生 schema（参见 `strict_mode`），并会原样转发。主体自身的字段还会选择 Router 在支持多种操作的模型上运行哪种操作：对于可编辑的图像模型，包含输入图像会将其从文生图切换为图生图（编辑）操作，该操作可能会按其自身的费率计费；对于 Seedance 视频模型，`content[].role` 选择操作（首帧图像选择图生视频，参考图像或视频片段选择参考生视频）。在原生分发下，Seedance 计费遵循 `content` 中的媒体类型，而不是角色：任何带有视频输入的请求按视频转视频计费，否则任何带有图像的请求按图生视频计费，否则按文生视频计费，除了来自 `draft_task` 项的最终渲染按其渲染的 Draft 的操作计费；某些模型对文生视频和图生视频收取相同费率。当 `model_provider` 选择一个替代提供商时，每个带条件的操作可能会按该提供商自身的费率计费。

  响应体：[`RouterModelOutput`](#routermodeloutput) 或原始字节（`*/*`） -- 响应头：`X-Comfy-Request-Id`、`X-Content-Type-Options`、`X-Comfy-Router-Fallback-Provider`、`X-Comfy-Router-Provider`、`X-Comfy-Router-Dropped-Params`、`X-Comfy-Credits-Used`、`Idempotent-Replayed`、`X-Committed-Spend-Limit`、`X-Committed-Spend-Current`、`X-Committed-Spend-Remaining`
</ResponseField>

  响应体：[`RouterErrorResponse`](#routererrorresponse) -- 响应头：`X-Comfy-Error-Type`、`X-Comfy-Request-Id`、`X-Comfy-Upstream-Status`、`X-Comfy-Upstream-Detail`、`X-Comfy-Refusal-Subject`、`X-Comfy-Credits-Used`、`Idempotent-Replayed`

### `POST /v2/models/{provider}/{model}/estimate`

**在真正运行之前预估一次模型调用的价格，而无需运行它。**

返回预检估算，单位为美元，说明在此模型上运行该请求体将产生多少费用；其定价依据与运行计费相同的费率表（对于按供应商所报告成本计费的模型，则改为根据供应商公布的价格表进行估算）。这是估算值，并非最终费用：你实际支付的是工作区使用情况和账单记录中的结算费用。请求体会先按模型的输入 schema 进行校验，校验方式与默认运行（不启用 `strict_mode`，也不启用 `reject_unknown_fields`）相同，因此未能通过模型 schema 的请求体在此处与在运行路由上一样会返回 `422`；不会向提供商派发任何内容，也不会产生任何费用。该结果不构成价格锁定：它按 `pricing_as_of` 时生效的费率计价，而运行则按计费评级时生效的费率收费。在该功能逐步推出期间，此路由会返回 `403`，并带有 `error_type: not_enabled`；对于 Router 尚无法运行的模型，会返回同样的 `403`，但带有运行路由自己的 `detail`，因此请阅读 `detail` 来区分两者。

**参数**

<ParamField path="provider" type="RouterProviderSegment" required>
  规范 `{provider}/{model}` 模型 ID 中的小写提供商段，即正在运行其模型的合作伙伴。

  类型：[`RouterProviderSegment`](#routerprovidersegment)：字母数字短标识，例如 `anthropic`，最长 64 个字符
</ParamField>

<ParamField path="model" type="RouterModelSegment" required>
  规范 `{provider}/{model}` 模型 ID 中的小写模型段，即该提供商下要运行的模型。

  类型：[`RouterModelSegment`](#routermodelsegment)：字母数字短标识，例如 `claude-opus-4-6`，最长 128 个字符
</ParamField>

<ParamField query="model_provider" type="string">
  选择一个备用提供商来提供此模型，而不是使用其当前默认提供商。
</ParamField>

**请求体**

`application/json`： [`RouterModelInput`](#routermodelinput)（必填）

合作伙伴模型的原生 JSON 输入，与同步路由为此模型接受的请求体相同。它会按模型自身的输入 schema 进行校验，校验方式与默认运行相同（此路由不接受 `strict_mode` 或 `reject_unknown_fields`），而请求体自身的字段（输出数量、输入图像所选的操作）决定对哪些内容计价。

### `POST /v2/models/{provider}/{model}/requests`

**将合作伙伴模型运行提交到队列并立即返回。**

<ParamField path="model" type="RouterModelSegment" required>

<ParamField query="strict_mode" type="boolean">

</ParamField>

**请求体**

## 错误分类桶

Router 错误的机器可读类别，同时也会在 `X-Comfy-Error-Type` 响应头中发送。

### 请求级分类桶

针对 Router 已接受但随后无法完成的请求抛出。

| `error_type` | 含义 |
| --- | --- |
| `invalid_input` | 请求在到达模型之前就被拒绝：请求体格式错误、分页游标格式错误或已过期、模型自身 schema 不接受的输入，或无法用于此请求的 `Idempotency-Key`（已用于其他请求，即方法、路径与查询或请求体不同；或已被某个其响应无法重放的调用消耗）。 |
| `content_policy_violation` | 提供商基于内容政策理由拒绝了请求。 |
| `provider_error` | 合作伙伴提供商报告了其自身的故障，或返回了 Router 无法解释为结果的响应。 |
| `provider_timeout` | 合作伙伴提供商未在其截止时间内应答。 |
| `insufficient_credits` | 发起调用的工作区没有足够的积分来运行该模型。 |
| `model_not_found` | `{provider}/{model}` ID 未指向任何 Router 可运行的模型：提供商未知、ID 未登记、该 ID 已被目录在其停用日期之后退役，或该已编目的 ID 当前未由其提供商为 Comfy 提供。 |

### 传输级分类桶

由 Router 自身抛出，发生在调用模型之前或调用过程之中。

| `error_type` | 含义 |
| --- | --- |
| `unauthorized` | 请求未携带可用的凭据。 |
| `forbidden` | 凭据有效，但无权访问此模型或执行此操作。 |
| `concurrency_limit_exceeded` | 工作区已在进行中的调用数量已达到允许的上限；等待其中一项调用完成后重试。 |
| `client_disconnected` | 在 Router 能够返回结果之前，调用方关闭了连接。 |
| `internal_error` | Router 自身失败。 |
| `deadline_exceeded` | 在应答到达之前，Comfy 已在自身配置的时限处停止保持连接。 |
| `not_enabled` | Comfy Router 尚未为该调用方启用。 |
| `service_unavailable` | Comfy Router 依赖的某个服务暂时不可用，调用方没有任何过错。 |
| `rate_limited` | 调用方已用尽按窗口计量的配额，必须等待该窗口滚动过去。 |
| `cancelled` | 已排队的请求在产生结果之前被撤回（通过取消路由，或由操作员撤回）；它处于终态，其本身并不代表关于计费的说法。 |
| `queue_timeout` | 已排队的请求等待超过了其队列超时时间，始终未被准入。 |
| `request_not_found` | `request_id` 未指向该调用方在此模型下的任何请求。 |
| `queue_backlog_full` | 调用方已有过多等待运行的排队请求，因此此次提交被拒绝。 |
| `result_expired` | 请求确实存在且已完成，但其结果已不再存储，因此收集操作没有可返回的内容。 |

## 运行前成本估算

`POST /v2/models/{provider}/{model}/estimate` 会在不运行的情况下为一个请求体定价，而排队提交（`POST /v2/models/{provider}/{model}/requests`）会在其 `201` 响应中返回与 `estimate` 相同的 [`RouterCostEstimate`](#routercostestimate)。二者都依据 Comfy 为该次运行计费时所使用的费率卡定价，例外是按供应商报告的成本计费的模型，此类模型依据供应商公布的价格表给出 `estimated`。两者返回的任何数字都是估算值，而不是最终费用：以你工作区的用量和账单记录中的结算费用为准。使用你自己的提供商密钥的运行不由 Comfy 计费（见下文）。在估算功能逐步推出期间，该路由会返回 `403` 并附带 `error_type: not_enabled`，而提交响应会省略 `estimate`。目录中仍然不包含任何价格。

在查看任何金额之前先读取 `source`。缺失的数字绝不意味着免费。

| `source` | 携带的字段 | 如何解读 |
| --- | --- | --- |
| `exact` | `amount`、`amount_cents`、`credits` | 等于按 `pricing_as_of` 中的费率对该请求体计费的估算值；以你工作区的用量和账单记录中的结算费用为准。 |
| `estimated` | `min_amount`、`max_amount` 及其 `_cents` 形式，没有 `amount` | 费用取决于供应商回报的某个量的估算值，而请求体为其设定了边界；预期费用落在该边界之内，以你工作区的用量和账单记录中的结算费用为准。 |
| `free` | `amount` 为 "0"，`amount_cents` 和 `credits` 为 `0` | 费率卡将此次请求定价为零，因此估算值为 `0`；以你工作区的用量和账单记录中的结算费用为准。只有 `free` 的报价才会显示 `0`。 |
| `unknown` | `reason`，没有数字 | 在运行之前无法给出价格。任何其他 `source` 值都视为 `unknown`。 |

`unknown` 估算值的 `reason` 为以下之一：

- `not_quotable`：路由器无法在运行前为此调用定价，因为它的计费基于供应商回报的某个量，而请求体并未为其设定边界；或者无法对按原样发送的请求体定价。任何无法识别的 `reason` 都视为 `not_quotable`。
- `unpriced_model`：费率卡没有为此请求定价。
- `byok`（仅排队提交）：该次运行使用你自己的提供商密钥，因此 Comfy 不为其收取任何费用。
- `pricing_unavailable`（仅排队提交）：在请求被接纳时无法读取费率卡。提交仍会被接受，运行也照常计费。

路由器目前还无法在运行前定价的模型列在[无法在运行前估算的模型](/zh/development/comfy-router/limitations#无法预先估算的模型)中。未列在该处的模型针对某个特定请求体仍可能返回 `unknown`，因此请对每个估算值都读取 `source`。

估算的失败关闭行为如下：

- 当某个数字需要费率卡，而卡片未加载或已过期时，`/estimate` 会返回 `503`，而不是给出猜测。排队提交绝不会因为其估算而被拒绝；它会改为携带 `source: unknown` 和 `reason: pricing_unavailable`。完全无法在运行前定价的调用（`not_quotable`），或使用你自己的提供商密钥的排队提交（`byok`），会在不读取费率卡的情况下得到响应，因此该 `200` 并不能说明卡片是否为最新。
- `/estimate` 会像默认运行那样，依据模型自身的输入 schema 校验请求体，因此不符合模型 schema 的请求体会得到与运行相同的 `422`，`detail[]` 形状也相同。不会进行任何定价或派发。
- 排队提交的幂等重放（`Idempotent-Replayed: true`）会省略 `estimate`，因为原始报价不会被存储。

估算的局限。`200` 返回的数字并不承诺该次运行会被接受，也不承诺会正好按此金额计费：

- `/estimate` 不接受 `strict_mode` 或 `reject_unknown_fields`，因此它只检查模型的原生契约：某个请求体在 `strict_mode=true` 的运行中按备用提供商自身的 schema 可以通过，在这里却可能得到 `422`；而 `reject_unknown_fields=true` 的运行会拒绝的未声明顶层字段，在这里却会被定价。Anthropic Messages 模型是例外：其 schema 允许未声明字段，因此 `reject_unknown_fields=true` 的运行不会拒绝任何字段，估算只会为未声明的顶层字段 `tools`、`tool_choice`、`temperature`、`top_p`、`top_k`、`stop_sequences`、`metadata`、`thinking` 以及空的 `mcp_servers` 定价。任何其他未声明的顶层字段都会使其返回 `unknown` 和 `reason: not_quotable`。
- `pricing_as_of` 是费率卡被获取的时间。取自供应商公布价格表的 `estimated` 报价会携带该价格表被读取的日期。计费数量依据供应商公布的费率表预测的 `exact` 或 `estimated` 报价，在该费率表的读取日期早于费率卡时，会携带该读取日期。既未读取费率卡也未读取费率表时，它是估算值被返回的时间。它不是价格锁定：运行会按其被计价时生效的费率计费。
- `/estimate` 为 `model_provider` 指定的那一段（或原生提供商）报价。它不接受 `fallback_provider` 或 `strict_mode` 参数。同步运行的兜底重试如果落到另一个提供商，就会按该提供商的费率计费，而估算并未对此报价；运行响应中的 `X-Comfy-Router-Fallback-Provider` 会说明发生了这种情况。排队提交没有兜底，因此其 `estimate` 报价的就是实际运行的那一段。
- 对于 `model_provider` 段上的同一个请求体，或对于在同级操作上运行的请求体，`/estimate` 与排队提交的 `estimate` 可能对略有差异的文档定价。提交的 `estimate` 是按运行实际发送的文档定价的。
- `/estimate` 始终按平台费用报价。使用你自己的提供商密钥的运行不由 Comfy 计费，但 `/estimate` 不会检测到这一点，仍会返回一个数字；只有排队提交才会返回 `reason: byok`。- 美元金额由未舍入的美分换算渲染而来，最多保留 8 位小数，可计费的、不足一美分的 `amount` 绝不会显示为 `0`。`credits` 为 `round(amount × 211, 2)`，与 `X-Comfy-Credits-Used` 对一次扣费所采用的换算相同，因此当价格极小而并非为零时，`credits` 可能舍入为 `0`；在这种情况下，请以 `amount` 或 `amount_cents` 做预算，而不是 `credits`。该响应头仍是某次运行结束后的事后数值；余额保存在 Comfy 平台上。

模型可以返回资产 URL、内联字节，或两者兼有。下面的提供商会将已选择的资产复制到 Comfy 存储上并替换其 URL。此行为取决于模型；没有任何请求头能选择它。

| 模型 | 复制到 Comfy 存储的内容 | Comfy 托管 URL 的最长有效期 |
| --- | --- | --- |
| `bfl/*` | 已完成资产，以及结果中携带的草稿缓存资产（如有） | 24 小时 |
| `byteplus/*` 视频模型（`seedance`、`dreamina-seedance`） | 已完成视频，以及结果中携带的末帧图像（如有） | 24 小时 |
| `minimax/*` | 已完成视频 | 12 小时 |
| `xai/*` | 每一张已生成的图像，以及已完成视频 | 24 小时 |

这些有效期从 URL 签名时开始计算，而不是从你打开它时开始。缓存或重放的 URL 可能剩余时间更少；重放不会为其续期。`Idempotency-Key` 记录的存在时间可能长于它所保存的 URL，因此从这类 URL 过期前一小时起，使用相同键的重试会得到 `409 invalid_input`，而不是已记录下来的响应；而在被返回时就已经如此接近过期的响应，仍可在 5 分钟内重放。请及时下载资产。只有每一行中列出的资产会被复制：`byteplus/seedream-*` 和 `byteplus/seededit-*` 图像不在 BytePlus 视频行的覆盖范围内。

复制只由模型的原生提供商执行。由替代提供商提供服务的运行（`model_provider` 指定了某个替代提供商，或原生运行的回退重试落到了替代提供商上，并通过 `X-Comfy-Router-Fallback-Provider` 披露）会返回该提供商自己的 URL，这些 URL 遵循提供商的过期时间，不会被复制。`model_provider` 取值 `default`、`comfy` 和 `comfyui` 时不指定替代提供商，因此这些运行属于原生运行并按上述方式复制；`model_provider` 运行的回退重试落回原生提供商时也同样如此。

**Veo（`veo/*`）有单独的存储路径。** 在 `response.videos[]` 中，读取其中存在的成员：`bytesBase64Encoded` 内联包含视频片段，而当环境配置为提供商直接写入 Comfy 存储时，`gcsUri` 包含一个 Comfy 签名的 HTTPS 链接。该链接自响应起 24 小时内有效。后一种情况是直接写入资产而非复制，因此 Veo 不在重新托管表中。

其他模型返回提供商资产引用或内联字节。提供商 URL 遵循提供商的过期时间，这可能比上述有效期短得多，且 Router 契约未对此作出规定。

**原始 BytePlus URL（Seedance 2.x，需选择启用）。** 对于 Comfy 已在服务器端选择启用的工作区，Seedance 2.x 的结果还会在已复制的 URL 之外，于 `content.upstream_video_url` 和 `content.upstream_last_frame_url` 中携带 BytePlus 自己的 URL，以及 `content.upstream_expires_at`。没有请求参数，且默认没有任何工作区被选择启用。这些 URL 在生成后 24 小时过期，一旦 BytePlus 清除它们便不再出现；在 Seedance 2.5 上，BytePlus 将每个 URL 的上限设为 100 次下载，而 Router 自己的副本会占用其中一次。每个 URL 都是其对象的持有者凭证：任何持有者在过期前都可以下载该资产。

复制是按资产尽力而为的。如果某个复制失败，该条目会保留其提供商引用；响应可以同时包含 Comfy 和提供商 URL，且没有明确的按资产复制状态字段。生成仍会成功并计费。不要根据一个成功重新托管的资产来推断每个 URL 的有效期。

结果是否由 Comfy 托管也决定了已完成的调用以后是否仍能从其 `Idempotency-Key` 记录中重放；上面的 `Idempotency-Key` 参数说明了无法重放时重试会得到怎样的回应。

## 各模型的输入和输出架构

每个模型的字段可通过 `GET /v2/models/{provider}/{model}/openapi.json` 读取。该调用需要 API 密钥。对于每个具有已编写架构的模型，同一文档也在本站点上公开发布，无需密钥，地址为 `/router-schemas/{provider}/{model}.json`。该副本是上次文档更新时生成的快照，因此当两者不一致时，以端点为准。该操作的 `requestBody` 描述输入验证；在已编写的情况下，其 `200` 响应描述输出形状和媒体类型。当 `x-comfy-input-schema-authored` 为 false 时，Router 接受任意 JSON 对象，而不进行特定于模型的预验证。提供商依赖项仍然适用。输出架构描述的是结果；Router 不会依据它们验证提供商返回的载荷。未编写的输出可能使用 `*/*` 而非 `application/json`；在解码之前，请检查响应的内容类型。

### RouterCostEstimate

本次调用将会花费多少美元的预检估算。它在派发之前，依据与运行计费相同的费率卡定价（对于按供应商报告的费用计费的模型，则依据供应商公布的价格表估算）。它不是最终扣费：你实际支付的是工作区用量与账单记录中的结算金额。运行结束后报告的 `X-Comfy-Credits-Used` 是一个四舍五入的事后数字，不是收据。`source` 表示该数字的可信程度：`exact` 带 `amount`；`free` 带 `amount` "0"（费率卡将本次请求定价为零）；`estimated` 带 `min_amount` 和 `max_amount`，不带 `amount`；`unknown` 两者都不带，并带一个 `reason`。切勿把缺失的 `amount` 读作免费。它不是价格锁定：见 `pricing_as_of`。

**字段**

<ResponseField name="source" type="string" required>

</ResponseField>

<ResponseField name="currency" type="string" required>

</ResponseField>

<ResponseField name="amount" type="string">

</ResponseField>

<ResponseField name="min_amount" type="string">

</ResponseField>

<ResponseField name="max_amount" type="string">

</ResponseField>

<ResponseField name="amount_cents" type="number">
  同一数字以美分表示，不取整，用于算术运算。与 `amount` 一同出现。

  double
</ResponseField>

<ResponseField name="min_amount_cents" type="number">
  `min_amount` 以美分表示，不取整。与 `min_amount` 一同出现。

  double
</ResponseField>

<ResponseField name="max_amount_cents" type="number">
  `max_amount` 以美分表示。与 `max_amount` 一同出现。

  double
</ResponseField>

<ResponseField name="credits" type="number">
  `amount` 按平台换算（$1 = 211 积分）折算为 Comfy 积分，四舍五入到 2 位小数，即 `exact` 报价下 `X-Comfy-Credits-Used` 预期携带的数字。该响应头是四舍五入的事后数字，不是收据；工作区用量与账单记录中的结算金额才是最终结果。

</ResponseField>

<ResponseField name="provider" type="string" required>
  本报价对应的提供商分支。在排队提交中，它就是要运行的那个分支。
</ResponseField>

<ResponseField name="model" type="RouterModelId" required>
  规范的 Comfy Router 模型 ID，格式为 `{provider}/{model}`，正是用于在 `POST /v2/models/{provider}/{model}` 上寻址该模型的那个值，因此调用方可以直接把它插入该路径，而无需从任何其他内容重新推导。它的 `pattern` 由 `RouterProviderSegment` 和 `RouterModelSegment` 以单个 `/` 连接而成，`maxLength` 为两者长度之和再加上这个分隔符。

  类型：[`RouterModelId`](#routermodelid)：模型 ID，例如 `anthropic/claude-opus-4-6`，最多 193 个字符
</ResponseField>

<ResponseField name="pricing_as_of" type="string" required>

</ResponseField>

<ResponseField name="reason" type="string">

</ResponseField>

### RouterErrorResponse

用于身份验证、访问、模型查找、配额以及提供商传输失败的错误响应体。

**字段**

<ResponseField name="detail" type="string" required>
  人类可读的失败描述，可以安全地展示给最终用户。不要对其做机器解析，而应改为根据 `error_type` 分支。对于已停用模型上的 `model_not_found`，当记录了后继模型且对调用方可见时，`detail` 会显示 `<id> was retired on <YYYY-MM-DD>; use <successor>`；否则只显示 `<id> was retired on <YYYY-MM-DD>`，而不是通常的建议列表。此处指定的后继模型始终是一个有效目录 ID，调用可以重新指向它。停用日期尚在未来的模型不算已停用：在到达该日期之前，它仍会出现在 `GET /v2/models` 中并可继续运行。与 `detail` 的其余内容一样，这段停用措辞仅用于展示，不附带任何兼容性保证。不对其做机器解析这一规则有两个有文档记录的例外：在 `POST /v2/models/{provider}/{model}` 上，`409` 会因三种互不相关但同属 `invalid_input` 分类的情况而返回，且只有 `detail` 能区分它们。以“this request's `image` selects the edit operation”开头的 `detail` 是 multipart `model_provider` 拒绝，以 `this request resolved a BYOK credential` 开头的 `detail` 是 BYOK `model_provider` 拒绝；两者都无法通过新的 `Idempotency-Key` 消除。该路由上任何其他 `invalid_input` 的 `409` 都是密钥冲突。这两个前缀都是稳定的合约术语，可以进行匹配。在其他任何地方，基于 `detail` 分支都不提供兼容性保证。
</ResponseField>

<ResponseField name="error_type" type="RouterErrorType" required>
  Router 故障的粗粒度、机器可读分类，会同步到 `X-Comfy-Error-Type` 响应头，以便调用方无需解析响应体即可分支。该集合封闭为二十个值：六个请求级分类 `invalid_input`、`content_policy_violation`、`provider_error`、`provider_timeout`、`insufficient_credits` 和 `model_not_found`，以及传输级的 `unauthorized`、`forbidden`、`concurrency_limit_exceeded`、`client_disconnected`、`internal_error`、`deadline_exceeded`、`not_enabled`、`service_unavailable`、`rate_limited`、`cancelled`、`queue_timeout`、`request_not_found`、`queue_backlog_full` 和 `result_expired`。“封闭”描述的是当前文档所记录的状态，而不是一个永远成立的限制：该集合预计会增长，因此这里特意使用普通字符串而非 `enum`，客户端必须将无法识别的值视为 `internal_error`，而不是对上述列表做穷举式 switch 并在下一次新增时出错。

  类型：[`RouterErrorType`](#routererrortype)
</ResponseField>

<ResponseField name="upstream_detail" type="string">
  模型提供商给出的、有长度限制且经过脱敏的拒绝请求原因，仅在 `error_type` 为 `invalid_input` 且 `X-Comfy-Upstream-Status` 为提供商的 `4xx` 或 `2xx` 时出现，即提供商以请求格式错误为由拒绝请求并说明了原因。通常该状态是 `4xx`；对于在成功信封内报告生成被拒绝的提供商，则为 `2xx`（BytePlus 的失败任务轮询是 HTTP `200`，原因位于响应体中）。在其他所有失败情形中均不出现，包括提供商 `5xx`、传输失败、内容策略拒绝以及 Router 自身提出的任何拒绝。它与 `X-Comfy-Upstream-Detail` 头对应。
</ResponseField>

<ResponseField name="refusal_subject" type="string">
  内容策略拒绝所针对的输入或输出，采用 Router 层面的封闭词汇表：`input`、`output`、`input_text`、`input_image`、`input_video`、`input_audio`、`output_text`、`output_image`、`output_video`、`output_audio`。当提供商未指明模态时，仅用 `input` / `output` 值来表示是哪一侧。仅当 `error_type` 为 `content_policy_violation` 且提供商使用机器可读代码指明了被拒绝的对象时出现；否则不出现。绝不是提供商文本。目前会为 BytePlus、Runway、BFL、Gemini、Veo、Vertex、xAI 和 Wan 的拒绝给出该字段，也会为 MiniMax Router 的 Nano Banana 链路中的 Gemini 拒绝给出该字段；如果提供商的拒绝未说明涉及哪一侧，则该字段不出现。它与 `X-Comfy-Refusal-Subject` 头对应。
</ResponseField>

<ResponseField name="denied_reason" type="string">
  计费系统针对合作伙伴节点支出拒绝的策略分支：当被计费钱包为空时为 `no_funds`，当调用被拒绝但没有资金读取结果说明原因时为 `unspecified`。仅当 `error_type` 为 `insufficient_credits` 且部署上报钱包相关信息时出现；否则不出现。它是机器可读代码，而非展示文本：请展示 `detail`，并基于此字段分支。
</ResponseField>

<ResponseField name="billed_workspace" type="RouterBilledWorkspace">
  被拒绝调用原本会扣款的钱包，位于 `RouterErrorResponse.billed_workspace`。它回答“哪个钱包为空？”这个问题：它不一定是调用方 UI 当前选择的工作区，而且即使当前打开的是资金充足的团队，团队成员的个人凭证在这里也会指向其个人钱包。仅与 `denied_reason` 一同出现。

  类型：[`RouterBilledWorkspace`](#routerbilledworkspace)
</ResponseField>

<ResponseField name="credential_kind" type="string">
  被拒绝请求的身份验证方式：`personal_api_key`、`team_api_key`、`personal_session` 或 `team_session`。它回答“我应该切换到哪个凭证，才能向另一个钱包计费？”这个问题。它不是权限，也不授予任何权限。仅与 `denied_reason` 一同出现。
</ResponseField>
