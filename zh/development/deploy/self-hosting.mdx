自托管意味着由你自己运行 ComfyUI，并将其作为 API 调用。硬件、模型和自定义节点均由你管理，作为回报，你将获得完全的控制权：任意 GPU、任意模型、任意节点包，而且你的数据永远不会离开你自己的基础设施。

ComfyUI 默认以 HTTP 服务器的方式运行，因此任何可正常运行的安装本身就已经是一个 API 端点。下面这些选项的区别仅在于该安装所处的位置。

## 你自己的硬件

最简单的部署方式就是你面前这台机器。安装 ComfyUI 后，它开箱即用，默认在 `http://127.0.0.1:8188` 提供服务：

- 适用于 Linux、macOS 和 Windows 的[手动安装](/zh/installation/manual_install)，也是服务器的标准选择
- 用于本地开发的 [Comfy Desktop](/zh/installation/desktop/overview) 或 [Windows 便携版](/zh/installation/comfyui_portable_windows)

若要以无头模式运行（不使用浏览器），或监听非默认地址，请参阅[服务器启动参数](/zh/development/comfyui-server/startup-flags)。例如：

```bash
python main.py --listen 0.0.0.0 --port 8188
```

<Warning>
  ComfyUI 服务器默认没有任何身份验证。请仅在可信网络中绑定非回环地址，或在其前端部署带身份验证的反向代理。
</Warning>

## GPU 云服务提供商

如果你没有自己的 GPU，可以租用一块并在上面运行 ComfyUI。社区常用的服务商包括：

- **[Runpod](https://www.runpod.io)**：提供 GPU pod，并附带预先配置好的社区 ComfyUI 模板。
- **[Vast.ai](https://vast.ai)**：一个 GPU 交易市场，这里同样提供社区 ComfyUI 模板。

在这些服务商上，你通常从一个社区模板或镜像开始，然后添加自己的模型和自定义节点。最终得到的是一个普通的自托管 ComfyUI，前面加一个公开 URL 或 SSH 隧道。

<Note>
  这些模板由社区维护，并非由 ComfyUI 团队发布或提供支持。在向模板中放入凭据或私有模型之前，请先了解该模板会安装哪些内容。
</Note>

如果你想要这一工作流的托管版本，由服务方为你处理构建、发布和自动扩缩容，请使用[在开发者平台上部署 Comfy API](/zh/development/serverless/overview)。

## 社区 Docker 镜像

<DockerNotice />

容器化的 ComfyUI 与其他任何自托管安装的行为完全一致：只需暴露服务器端口，然后照常调用即可。

## 下一步：对它运行工作流

自托管部署可以通过两种方式调用：
