Comfy API 将环境定义与运行环境的端点分开。**Build** 描述 ComfyUI 环境。**发布版本**会针对受支持的目标打包 Build。**部署**则将发布版本作为托管端点运行。

## 选择运行方式

| 选择 | 适用场景 | 需要管理的内容 |
| --- | --- | --- |
| [Comfy Cloud](/zh/development/deploy/cloud) | 想在浏览器中使用托管版 ComfyUI，或无需设置端点即可运行工作流。 | 工作流和 API 调用。无需创建 Build 或部署。 |
| [Comfy API](/zh/development/serverless/quickstart) | 需要托管端点，并使用指定的 ComfyUI 环境、模型、自定义节点和依赖项。 | Build、对应的发布版本，以及一个或多个部署。 |
| [自托管](/zh/development/deploy/self-hosting) | 想自行选择和管理机器、软件、模型及自定义节点。 | 自己的 ComfyUI 安装和基础设施。 |

如果工作流需要 Comfy Cloud 中不可用的自定义节点或依赖项，请使用 Comfy API 或自托管 ComfyUI。Comfy API 会根据打包好的环境创建托管端点。它不是用于试验更改的交互式 Sandbox。

## Comfy API 各部分如何配合

```text
工作区 → 本地项目 → Build → 发布版本 → 部署 → 工作流请求
```

1. **工作区**：团队管理访问权限、Build、部署和使用限额的账户范围。
2. **本地项目文件夹**：你在电脑上存放 `comfy-build.yaml` 以及相关工作流或资源文件的文件夹。该文件描述 Build，并跟踪已知的远程状态。它不包含模型文件。这是本地文件夹，不是在线资源。
3. **Build**：ComfyUI 环境的定义，包括 ComfyUI 版本、模型、自定义节点和设置。推送后即可在 Developer Platform 上使用。
4. **发布版本**：针对受支持目标构建的 Build 版本，例如 `linux/nvidia`。更改 Build 或需要适配其他目标时，请创建新的发布版本。
5. **部署**：由某个发布版本创建的运行中端点。部署有自己的计算设置，例如 GPU、区域和工作进程数量范围。同一个 Build 可以运行多个部署，例如使用不同的 GPU 类型。

使用 [Comfy SDK](/zh/development/api-development/sdks) 或 CLI，向部署端点发送 API 格式的工作流请求。部署会使用其发布版本中打包的环境运行请求。

## 更新内容时会发生什么？

- **更改环境**：更新 Build 定义并推送，然后创建新的发布版本。准备好后，将部署切换到该发布版本。
- **更改容量**：扩缩或停止部署。这会更改计算设置，不会更改 Build 或发布版本。
- **运行其他工作流**：向端点发送其他 API 格式的工作流。如果 Build 已包含所需模型和节点，就无需创建新的发布版本。

**实例**是 ComfyUI 环境，例如由 Comfy Desktop 管理的环境。在 Comfy API 中，用户创建和管理的对象是部署。你无需管理其底层运行时实例。
