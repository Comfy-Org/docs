Comfy API 会运行来自你工作区库中的模型，即使部署的 Release 不包含这些模型。将 LoRA 或其他 `.safetensors` 模型上传到库中，即可在部署上运行它，而无需新的 Build、Release 或重新部署。

使用工作区库，可以在部署上试用你训练好的 LoRA，或者通过修改工作流中的一个文件名，为每个 API 请求选用不同的 LoRA。

## 开始之前

在上传模型到工作区库之前，请确保满足以下要求：

- **套餐**：你的工作区需要有效的 Pro、Creator、Team 或企业版套餐。
- **模型文件**：文件必须是大小不超过 2 GB 的 `.safetensors` 文件。较大的基础模型（例如 SDXL 或 Flux）仍应放在 Build 中。
- **有效部署**：该部署必须与库位于同一工作区。

<Warning>
  部分在工作区库模型可用之前创建的部署无法加载这些模型。要使用工作区库模型，请创建新部署。在较旧的部署上，任务可能会失败，并显示 `Library model "<file name>" is unavailable on this deployment. Retry the job. If it still fails, contact support with the job ID.`
</Warning>

## 将模型上传到工作区模型库

你可以使用以下任意三种工具上传模型：

- **云端编辑器**：上传文件，或从 Civitai 或 Hugging Face 链接导入。
- **comfy-cli**：从终端或脚本上传。
- **开发者平台**：从 Build 的模型步骤上传。

选择你所使用工具对应的标签页。

<Tabs>
  <Tab title="云端编辑器">
    1. 在 **运行** 左侧的部署菜单中，确保 **运行于** 下已选择 **Comfy Cloud**。
    2. 在**左侧边栏**中，点击 **模型库**，然后点击 **导入**。
    3. 点击 **选择文件**，或将 `.safetensors` 文件拖入对话框。
    4. 在 **这是什么类型的模型？** 下，如果文件是 LoRA，请保留 **LoRA**，或选择与该文件匹配的类型。
    5. 点击 **上传**。上传完成后，点击 **完成**。

    ![导入模型对话框，已选择 my_style_lora_9e2417.safetensors（97.37 MB），这是什么类型的模型？设为 LoRA，并显示返回和上传按钮](/images/development/serverless/library-models-editor-import.png)

    若要改为从 Civitai 或 Hugging Face 链接导入模型：

    1. 在 **导入** 对话框中，将模型的链接粘贴到 **粘贴链接到此** 中。
    2. 点击 **继续**。
    3. 在 **这是什么类型的模型？** 下，选择模型类型。
    4. 点击 **导入**。

    只有 `.safetensors` 文件才能在部署上运行。以其他格式（例如 `.ckpt`）通过链接导入的模型会导入到模型库中，但无法在部署上运行。
  </Tab>
  <Tab title="comfy-cli">
    上传文件，并使用 `--type` 设置其模型类型：

    ```bash
    comfy assets library upload my_style.safetensors --type loras
    ```

    检查文件是否已在模型库中：

    ```bash
    comfy assets library ls --tags models,loras
    ```
  </Tab>
  <Tab title="开发者平台">
    1. 在开发者平台上，打开某个 Build 的模型步骤，然后点击 **上传模型**。
    2. 选择 **工作区模型库**。
    3. 将 `.safetensors` 文件拖到拖放区域，或点击该区域进行浏览。
    4. 在 **模型类型** 下，如果文件是 LoRA，请保留 **LoRA**，或选择与该文件匹配的类型。
    5. 点击 **上传**。

    ![Build 的“哪些模型随构建发布？”步骤上的上传模型对话框，包含公开、私有和工作区模型库标签页，已选择工作区模型库，显示拖放区域，模型类型设为 LoRA，一行文字说明文件已在你的工作区模型库中，以及取消和上传按钮](/images/development/serverless/library-models-platform-upload.png)
  </Tab>
</Tabs>

模型进入模型库后，工作区的每位成员都可以使用它。模型库接受任何模型类型，不仅限于 LoRA。选择与加载器节点所读取的文件夹相匹配的类型，例如 LoRA 使用 `loras`，VAE 使用 `vae`。

## 在您的部署上运行模型

模型进入模型库后，您可以从云端编辑器或通过 API 在您的部署上运行它。请根据您提交任务的方式选择对应的选项卡。

<Tabs>
  <Tab title="云端编辑器">
    1. 点击 **Run** 左侧的部署菜单。在 **Run on** 下，选择您的部署。编辑器会重新加载，选项卡会保持打开。
    2. 添加 `Load LoRA (Model and CLIP)` 节点，或打开包含该节点的工作流。
    3. 在该节点的 `lora_name` 列表中，选择您的文件。列表会将模型库中的模型与 Release 的模型并列显示。
    4. 点击 **Run**。

    首次运行时，队列中该任务所在的行会显示 `Downloading my_style.safetensors`，同时 worker 正在下载该文件。当任务下载多个模型时，该行会显示 `Downloading <file name> (<n> of <total>)`。

    ![包含 Load Checkpoint 和 Load LoRA (Model and CLIP) 节点的工作流，在 lora_name 中已选择上传的 LoRA，且队列面板的顶行显示 Downloading my_style_lora_9e2417.safetensors 0 B of 97.37 MB](/images/development/serverless/library-models-editor-downloading.png)
  </Tab>
  <Tab title="API">
    在 [API 格式的工作流](/zh/development/api-development/workflow-api-format) 中，将 `LoraLoader` 节点的 `lora_name` 输入设置为模型库中的文件名，包括 `.safetensors`：

    ```json
    "10": {
      "class_type": "LoraLoader",
      "inputs": {
        "lora_name": "my_style.safetensors",
        "strength_model": 1.0,
        "strength_clip": 1.0,
        "model": ["4", 0],
        "clip": ["4", 1]
      }
    }
    ```

    使用 `comfy deploy run`、[Comfy SDKs](/zh/development/api-development/sdks) 或 [Comfy API v2](/zh/api-reference/v2/overview) 发送工作流：

    ```bash
    comfy deploy run --deployment <deployment-id> --workflow workflow_api.json
    ```

    要使用其他 LoRA，请在下一个请求中将 `lora_name` 更改为模型库中的另一个文件名。您无需创建新的 Build 或 Release，也无需重新部署。
  </Tab>
</Tabs>

<Tip>
  使用模型库中的模型时，worker 上的首个任务会耗时更长，因为 worker 会先下载该模型。同一 worker 上的后续任务会使用缓存副本。新的 worker 会再次下载该模型；已将模型从缓存中移除以为其他模型腾出空间的 worker 也会如此。要跳过下载，请将模型添加到 Build。
</Tip>

## 遵守限制和命名规则

除了 [开始之前](#开始之前) 中的文件大小和格式限制外，以下限制同样适用：

| 限制 | 值 |
| --- | --- |
| 工作区存储 | 每个工作区 1 TB 模型，包括通过链接导入的模型 |
| 每个工作流的库模型名称数 | 100 |

如果加载器引用第 101 个库模型，就会像该文件不在库中一样失败。

遵循以下规则，以便任务找到正确的文件：

- **使用加载器读取的文件夹。** 加载器只会找到其自身模型类型的库文件。`Load LoRA` 节点会找到以 `loras` 上传的文件，而不是以 `checkpoints` 上传的文件。
- **使用纯文件名。** 将加载器输入仅设置为文件名，例如 `my_style.safetensors`，且文件名前面不带文件夹。
- **不要复用发布版本中的模型名称。** 如果发布版本已有同名文件，工作进程会使用发布版本的文件，而不是你的库文件。
- **确保名称在不同文件夹中保持唯一。** 如果库在两个文件夹中有同名文件，而同一个加载器会读取这两个文件夹，那么通过 API 发送的任务不会加载其中任何一个文件。
- **预期最新文件会胜出。** 如果库在一个文件夹中有两个同名文件，任务会使用最后添加的那个文件。
- **匹配基础模型。** LoRA 必须与工作流加载的基础模型匹配。
- **使用部署中提供的加载器。** 加载器节点必须在部署中可用。库模型只能通过 Comfy Cloud 提供的加载器节点加载。如果你的加载器来自 Comfy Cloud 没有的自定义节点，请将其模型添加到 Build 中。

## 更改或删除模型库中的模型

当在 **运行于** 下选择了部署时，**模型库**只列出该 Release 的模型。要更改或删除模型库中的模型，请先切换回 Comfy Cloud：

1. 点击 **运行** 左侧的部署菜单。在 **运行于** 下，选择 **Comfy Cloud**。
2. 在**左侧边栏**中，点击**模型库**。

要更改模型类型：

- 将鼠标悬停在模型卡片上，点击**模型信息**，然后选择新的**模型类型**。

<Warning>
  删除模型会将其从所有成员的工作区模型库中移除。仍引用该文件的任务或 API 请求会在加载器输入处失败，并报 `Value not in list` 错误。
</Warning>

要删除模型：

1. 将鼠标悬停在模型卡片上，点击**更多**，然后点击**删除**。
2. 在**删除此模型？**中，点击**删除**。
