工作流模板是 ComfyUI 中原生支持的模型工作流及自定义节点提供的模型工作流的浏览窗口。

在 ComfyUI 的工作流模板功能中，你可以找到以下内容：

- 原生支持的模型工作流
- 自定义节点提供的示例工作流

![Template](/images/interface/features/template/template_library.png)

## 如何打开 ComfyUI 的模板

在侧边栏点击 **Templates** 图标即可打开工作流模板。你也可以通过菜单 **工作流** → **浏览工作流模板** 打开。
![Template](/images/interface/features/template/template.png)

## 如何使用模板

1. 加载模板： 点击你需要使用的任意模板以加载对应的模板工作流
2. 下载模型： 在加载模板时，ComfyUI 会自动检查模型文件是否存在，如果模型文件不完整，则会提示你下载模型
3. 使用工作流： 确定工作流的需要的各种要素如模型、输入图片、提示词等是完整的，即可点击运行按钮开始使用工作流

### 桌面版的模型安装界面

每个工作流模板都嵌入了所需模型的链接。在桌面版里，加载一个模型尚未安装的模板时，ComfyUI 会先打开 **Template requirements**（模板所需资源）界面，再加载工作流，因此在开始运行之前就能看到缺什么。

这个界面以 **Models**（模型）列表开头：模板会加载的每个模型文件，包含文件名、应放入的 `ComfyUI/models` 子目录、文件大小，以及用到它的节点。当所有文件都有大小时，列表标题会显示总量。自带示例素材的模板还会多一个 **Input Assets**（输入素材）列表，列出示例图片、视频或音频，方便你在运行前了解工作流需要什么输入。

每个模型行会显示以下状态之一：

| 行状态 | 含义 | 你需要做什么 |
| --- | --- | --- |
| **Installed**（已安装） | 文件已经在对应目录里 | 无需操作，该行已完成 |
| **Download model**（下载模型） | 模板带有可下载的 Hugging Face 或 Civitai 链接 | 点击后把该文件下载到行内显示的目录 |
| **Get it manually**（手动获取） | 文件位于需要授权的仓库 | 打开仓库链接，接受许可，下载文件后放入行内显示的目录 |
| **Unavailable**（不可用） | 文件缺失，且模板没有 ComfyUI 能下载的链接，例如不支持的格式 | 自行下载文件并放入行内显示的目录 |
| **Unknown**（未知） | ComfyUI 尚未完成模型目录扫描，或读不到文件大小与来源 | 先打开模板检查加载节点，或等扫描完成后再看 |

界面底部的按钮决定接下来的动作：

- **Open now**（现在打开）：不下载任何文件，直接加载工作流，缺失文件保持未解决。
- **Download models & open**（下载模型并打开）：开始下载缺失文件并立即加载工作流，下载会在后台继续进行。当所有待下载文件都有大小时，按钮会显示将要传输的量，例如 **Download models & open (6.46 GB)**。这个数字只统计本次点击会下载的文件，已安装的模型不计入。只有至少一个缺失文件可以下载时才会出现这个按钮；如果需要手动获取全部缺失文件，就只会提供 **Open now**。

下载过程中，对应行会显示 **Queued**（排队）、**Starting**（开始）、**Downloading**（下载中）、**Paused**（已暂停）、**Downloaded**（已下载）、**Download failed**（下载失败）或 **Download cancelled**（已取消）。失败的行会保留失败原因并提供 **Retry**（重试）。下载完成的文件会写入对应的 `ComfyUI/models/...` 目录。

如果示例输入素材无法准备好，工作流仍会打开，你可以在输入节点上选择自己的文件。

### 浏览器版的缺失模型提示

自托管浏览器版没有这个安装界面。加载缺少模型的模板会直接打开工作流，随后 ComfyUI 会：

1. 在画布上把相关加载节点标红。
2. 显示类似 **发现 5 个问题** 的提示，并提供 **View details**。
3. 在 [右侧面板](/zh/interface/right-side-panel) 的 **问题** 标签页里展开 **Setup required**（设置待完成）下的 **Missing Models**（缺失模型）列表。

![模板缺少的模型：Setup required 列出每个文件的文件夹与大小，每行 Download，底部 Download all](/images/interface/features/template/missing_models.jpg)

在这个列表里可以按文件 **Download**、**Download all**、**Refresh**，或用定位按钮跳到需要该模型的节点。工作过程中，右侧面板问题页里的 **Missing models** 分组会一直可用。

在自托管浏览器版里，点 **Download** 会在有 URL 时走浏览器下载。请把文件放到对应文件夹。截图中的 Qwen Image 模板示例：

```
📂 ComfyUI/
├── 📂 models/
│   ├── 📂 loras/
│   │   └── Qwen-Image-Lightning-8steps-V1.0.safetensors
│   ├── 📂 diffusion_models/
│   │   └── qwen_image_fp8_e4m3fn.safetensors
│   ├── 📂 vae/
│   │   └── qwen_image_vae.safetensors
│   └── 📂 text_encoders/
│       └── qwen_2.5_vl_7b_fp8_scaled.safetensors
```

当前缺失检测只看对应一级目录下有没有同名文件（例如必须直接在 `ComfyUI/models/diffusion_models`）。
如果模型已经放在子目录（如 `ComfyUI/models/diffusion_models/wan_video`），可以关掉提示，在加载节点里手动选中该文件即可。

如果你好奇我们是如何做到嵌入模型链接的，我们在对应节点的 `properties` 中添加了 `models` 信息， 下面是嵌入了模型信息的 `DualCLIPLoader` 节点的完整片段：
```json
    {
      "id": 40,
      "type": "DualCLIPLoader",
      "pos": [
        -320,
        290
      ],
      "size": [
        270,
        130
      ],
      "flags": {},
      "order": 0,
      "mode": 0,
      "inputs": [],
      "outputs": [
        {
          "name": "CLIP",
          "type": "CLIP",
          "links": [
            64
          ]
        }
      ],
      "properties": {
        "Node name for S&R": "DualCLIPLoader",
        "cnr_id": "comfy-core",
        "ver": "0.3.40",
        "models": [
          {
            "name": "clip_l.safetensors",
            "url": "https://huggingface.co/comfyanonymous/flux_text_encoders/resolve/main/clip_l.safetensors",
            "directory": "text_encoders"
          },
          {
            "name": "t5xxl_fp16.safetensors",
            "url": "https://huggingface.co/comfyanonymous/flux_text_encoders/resolve/main/t5xxl_fp16.safetensors",
            "directory": "text_encoders"
          }
        ]
      },
      "widgets_values": [
        "clip_l.safetensors",
        "t5xxl_fp16.safetensors",
        "flux",
        "default"
      ]
    }
```

在 `properties` 中新增了 `models`, 对应的模型信息包含了对应的 `name`、`url` 以及 `directory` 信息。

- `name` 对应了模型文件的名称
- `url` 对应了模型文件的下载链接(可直接下载的文件链接，而不是仓库地址)
- `directory` 对应了模型文件的下载后应存储到的 ComfyUI/models 目录下的哪个子目录， 如 `vae` 则对应 `ComfyUI/models/vae` 目录

目前模型链接仅支持 huggingface 和 civitai 来源的链接，并且要求模型格式为安全的模型格式如 `.safetensors`, `.sft` 格式等，类似  `.gguf`, 不安全格式在嵌入后会提示不安全并不显示链接  

你可以使用[这个工具](https://comfyui-wiki.github.io/ComfyUI-Workflow-JSON-Editor/)来编辑工作流模板中的模型信息，但目前 [@ComfyUI-Wiki](https://github.com/ComfyUI-Wiki) 仅对原生的节点增加了支持。

## 如何更新模板？

目前模板是通过一个单独依赖的形式进行管理和更新的，对应的地址为：[comfyui-workflow-templates](https://pypi.org/project/comfyui-workflow-templates/)

如果你在更新 ComfyUI 后发现没有文档或者我们的更新说明中新增的模板，那么可能是你没有在更新 ComfyUI 之后更新对应的依赖, 你可以访问 [ComfyUI/requirements.txt](https://github.com/Comfy-Org/ComfyUI/blob/master/requirements.txt) 来查看对应的依赖版本

通常下面的三个依赖是每次更新 ComfyUI 时我们也可能会同时升级的

```
comfyui-frontend-package==1.24.4
comfyui-workflow-templates==0.1.52
comfyui-embedded-docs==0.2.4
```

如果你不了解如何正确更新，请参考 [更新 ComfyUI](/zh/installation/update_comfyui) 章节了解如何更新 ComfyUI 和对应的依赖

## 如何向 ComfyUI 官方贡献模板？

目前所有的模板都托管在 [workflow_templates](https://github.com/Comfy-Org/workflow_templates/) 仓库中，你可以通过提交 PR 的方式来贡献模板，对于官方模板我们要求如下：

1. 不使用任何的第三方节点（避免用户因为缺失节点导致需要额外的安装）
2. 对应的模板不与已有模板重复， 需要是已支持的相关模型功能
3. 你可以在对应的仓库提交 issue 进行提问

## 自定义节点模板

如果自定义节点作者有提供了模板和示例工作流，你也可以在模板浏览里找到，通常只需要找到对应的节点名称的分类即可看到作者提供的所有目录。

如果你是自定义节点作者，请注意目前我们仅支持模板文件夹下的一级目录，并不支持多级目录，且仅支持 JSON 格式的模板

## 如何为自定义节点添加模板？

[自定义节点模板](/zh/custom-nodes/workflow_templates) 中介绍了如何为你开发的自定义节点添加工作流模板，你也可以向自定义节点作者提交 PR 来贡献自定义节点模板
