WeVisOne-VL 是一个紧凑的视觉语言模型，它以形状而非文字段落来给出答案。给它一张图像和一段简短的文本查询，它就能在一次推理中返回边框、点，或每个实例的 alpha 遮罩：无需标注，也无需逐对象提示。

在 ComfyUI 中，它以 **WeVisOne-VL Detect** 节点运行。下面的模板将它封装在一个子图中，并预览遮罩、绘制在来源图像上的边框，以及前景和背景抠图，因此该遮罩可以直接接入背景移除、蒙版或合成流程。

权重为腾讯发布的 Apache-2.0 版本，已在 [Comfy-Org/WeVisOne-VL](https://huggingface.co/Comfy-Org/WeVisOne-VL) 中为 ComfyUI 重新打包。支持已随 [ComfyUI #17632](https://github.com/Comfy-Org/ComfyUI/pull/17632) 合入，该模板需要 ComfyUI 0.45.0 或更高版本。

## 任务

`task` 控件会将查询改写为 checkpoint 训练时所使用的指令。每种任务接受的查询形式略有不同：

| `task` | 查询形式 | 返回 |
| :--- | :--- | :--- |
| `segmentation` | 一个简短的名词短语，例如 `human` | 透明度遮罩和盒子（未开启 `individual_masks` 时为一张合并遮罩） |
| `detection` | 每行一个标签 | 仅盒子 |
| `referring` | 一个描述性短语，例如 `the cup on the left` | 盒子 |
| `point` | 每行一个标签 | 以 JSON 表示的中心点 |
| `count_box` | 要计数的对象 | 一个计数，每个实例带一个盒子 |
| `count_point` | 要计数的对象 | 一个计数，每个实例带一个点 |
| `ocr` | 无 | 图像中每个单词上的盒子 |
| `ocr_grounding` | 要查找的精确字符串 | 该字符串周围的盒子 |
| `visual_prompt` | 无，使用 `bboxes` 输入 | 与参考盒子相似的对象的盒子 |
| `freeform` | 任意内容 | 原始回答，查询作为完整 prompt |

保持查询简短。完整句子会让 `segmentation` 输出冗长，而直接点明目标的短语比对其进行描述效果更好。

## 模型

该工作流加载的是 2B INT8 文本编码器。其余三个文件可直接替换 `CLIPLoader` 节点中的 `clip_name`（类型为 `stable_diffusion`）：两个 4B 文件体积更大、速度更慢，而 BF16 文件则以体积换取精度。

## 对节点进行更多控制

- **`individual_masks`**：on 时，每个边界框一个遮罩；off 时，每帧一个并集遮罩
- **`max_length`**：回答长度上限，默认为 4096 个 token，最高为 32768 个 token
- **输出**：`masks`、`bboxes`、`points`（包含 x、y、label 和 frame 的 JSON）以及 `text`（原始回答）
