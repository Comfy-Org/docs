**MiniMax-H3-Image** 是 MiniMax 的开放权重图像模型，一个 checkpoint 同时覆盖文生图与图像编辑。其扩散 Transformer 为 33.1B 参数，采用 BF16 精度，并蒸馏为无需 CFG 的 6 步采样器。原生输出约为 16 MP，因此 4096 x 4096 的图像只需一次生成，而无需经过 upscale 链路。

- [Comfy-Org/MiniMax-H3 (Hugging Face)](https://huggingface.co/Comfy-Org/MiniMax-H3)：该模型使用的 Qwen3-VL-32B 文本编码器
- [MiniMaxAI/MiniMax-H3-Image-PE (Hugging Face)](https://huggingface.co/MiniMaxAI/MiniMax-H3-Image-PE)：官方提示词扩展器

## 主要特性

- **在一个 checkpoint 中完成文生图与图像编辑**：无需加载单独的编辑模型或适配器
- **6 步采样**：引导固定为 1，因此没有 CFG 计算，也不需要负面提示词
- **原生约 16 MP**：4096 x 4096 至 6272 x 2688，无需额外的放大流程
- **多参考图**：最多 16 张输入图像，在提示词中从 `<Picture 1>` 起依次引用
- **可选的提示词扩展器**：将简短的请求转换为模型最容易理解的详细描述
- **开放权重**：在 ComfyUI 中完全本地可控

## 采样与画布尺寸 {#sampling-and-canvas-size}

两个模板均采用蒸馏调度方案：

| 设置 | 值 |
| --- | --- |
| 采样器 | euler |
| 调度器 | simple |
| 步数 | 6 |
| 引导（CFG） | 1 |
| 降噪 | 1 |

引导值为 1 时不存在无分类器引导（classifier-free guidance）过程，因此模板中不携带负面提示词。请把所有你想要的内容，包括需要避免的内容，都写进正向提示词中。

原生输出约为 16 MP。每条边都生成于 32 px 的倍数，任意宽度和高度均可接受。以下尺寸覆盖了常见的比例：

| 宽高比 | 尺寸（宽度 x 高度） |
| --- | --- |
| 1:1 | 4096 x 4096 |
| 4:3 | 4736 x 3552 |
| 3:4 | 3552 x 4736 |
| 3:2 | 5024 x 3360 |
| 2:3 | 3360 x 5024 |
| 16:9 | 5472 x 3072 |
| 9:16 | 3072 x 5472 |
| 21:9 | 6272 x 2688 |

更小的画布同样可行，且耗时更少。在文生图模板中，分辨率选择器分别设置宽高比和目标百万像素数，因此从 4 MP 起、直到选择器上限 16 MP 的任意尺寸，都只需调整一处设置。

## 图像编辑中的参考图像

图像编辑模板会将来源图像作为 `<Picture 1>` 发送给模型。额外图像会按顺序标记为 `<Picture 2>`、`<Picture 3>`，最多支持 16 个参考图像，提示词通过各自的标签来引用。第一张图像是待编辑的图像，其余图像提供身份、道具、材质或构图，因此简短的指令就够了：把 `<Picture 1>` 中的车辆换成 `<Picture 2>` 中的车辆。

要添加参考图像，请在工作流中再放置一个 `Load Image` 节点，并将其同时连接到提示词生成步骤和条件节点。请保持条件节点上的 VAE 输入已连接：模板已经接好，接入 VAE 时参考图还会作为图像 latent 参与条件，编辑结果更贴合来源图像。参考图的短边至少要有 1024 px，需要保住身份时用 2048 px：节点会自行缩放，低于 1024 px 的图像会被放大（多出来的像素只是插值），超过 2048 px 的细节会被丢弃。

不启用缩放节点时，编辑结果与来源图像同样大小。启用后可以按设定的目标尺寸生成：在当前模板包中是 16 MP，而模板包 0.11.104 中它处于旁路状态、目标值为 1 MP，需要选中后按 `Ctrl-B` 启用再设置目标值。内存不足时在采样前降低目标值。

模型读取要编辑的图像时短边最多 2048 px，相当于 1:1 约 4 MP、16:9 约 7 MP。目标尺寸超过这个范围时，多出来的是模型生成的细节，而不是来源图像的细节；需要细节时把目标设成这个大小，之后再放大结果。

### 编写编辑提示词

扩展器开着时，一句简短指令就够了：它会把你的文字改写成模型最好读的结构。关掉扩展器自己写时，沿用同样的结构。

1. **先讲元素，再给它编号**：`The woman in a red coat in <Picture 1> is <Subject 1>`，带上足够指认出她的可见细节。每个定义都要写明对应的 `<Picture N>`。
2. **描述目标图像，再逐个说明主体的结果**：`<Subject 1> is fully preserved`，或 `<Subject 1> is partially preserved; her face and coat remain, while her pose changes to a lean toward <Subject 2>`。
3. **只写改动的和新增的内容**：被删除对象留下的表面写在这里，编辑要加的文字也写在这里。

参考图里没有来源的内容不占主体编号。被删除的元素用 `<Picture N>` 在目标描述里提一次，然后写它留下的区域。

`<Subject N>` 只是文本编码器读到的措辞，采样器并不强制执行，真正约束编辑的是描述本身。要写明什么改、什么不变，不要指望参考图自动带过去。官方编辑示例展示了完整结构：[revised_prompt.edit.txt](https://github.com/MiniMax-AI/MiniMax-H3-Image/blob/main/examples/revised_prompt.edit.txt)。

### 放大与修复图片

编辑工作流也能自己完成第二遍放大，不需要另加放大模型。在带 `scale total pixels` 的 `Resize Image/Mask` 节点上设置目标尺寸（模板里是 16 MP），并关掉 `Boolean (Enable PE?)` 节点的开关。如果你的模板包把这个节点设为旁路，先选中它按 `Ctrl-B` 启用。

```text
Re-render and sharpen as if the photo were taken with a 50 mm lens. Remove noise and compression artifacts. Improve skin, hair, eye and fabric detail while keeping pose, identity, and colors.
```

镜头描述按原图的拍摄条件来写。关闭扩展器后指令原样送进模型；开启时扩展器会写出一张新图的描述，还会加入你没有要求的内容。

整帧是重新生成而不是局部修补，所以这是带新增细节的放大，不是忠实复制。目标尺寸接近模型读取原图的大小（1:1 约 4 MP）时，姿态、身份和颜色更容易保住，因为超过 2048 px 短边的部分都是生成的。提示词没写到的部分都可能变化，目标尺寸大时皮肤质感可能变得油亮、显老。

## 提示词扩展器

两个模板都在采样器之前放置了一个文本生成步骤。在文生图模板中，它会把提示词改写为一段详细的英文描述。在图像编辑模板中，它会把简短的指令转换为一段带有参考信息的、对已完成图像的描述。

MiniMax-H3-Image 的官方扩展器是一个 Qwen3.8-27B FP4 模型，发布在 [MiniMaxAI/MiniMax-H3-Image-PE](https://huggingface.co/MiniMaxAI/MiniMax-H3-Image-PE)。模板使用的是更轻量的 Qwen3.5 9B W4A8 版本，因此扩展器可以与 21 GB 的 diffusion 模型一起装在单张 GPU 上。

两个模板默认都开启扩展器，因此提示词会在采样前被改写。关闭扩展器，提示词就会按原样送入模型。
