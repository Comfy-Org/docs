## 关于 MOSS-Image

MOSS-Image 是 OpenMOSS 的开放权重文生图模型：一个 5B 单流 DiT，可将完整的场景描述转换为一张成品图像。它在文字与排版至关重要的场景中表现最出色，因为它能渲染英文与中文字体，可接受约 4K token 的提示词，并且能读取描述每个对象和每行文字所在位置的 JSON 布局。权重以 Apache 2.0 发布，因此只需下载一次，即可在自己的 GPU 上运行，无需 API 密钥，也没有按图像计费的积分。

该系列包含两个模型。模板加载的是经过指令微调的 **SFT** 模型：它对文本的分组和场景的排布更整洁。**Base** 模型没有经过后训练，也没有进行 CFG 蒸馏，因此成为社区 LoRA 的起点。两者在同一节点图中运行，因此切换模型只需更换一个加载器。

在 ComfyUI 中，该模型以 int8 和 bf16 的单文件模型运行，文本编码器使用以 `moss_image` 类型加载的 Qwen3.5 9B，VAE 使用 FLUX.2 small VAE。文生图模板还内置了提示词上采样器，它会在采样之前把简短的请求改写为完整的描述，所使用的正是模型本身已经需要的那个文本编码器。

**模型亮点：**

- 5B 单流 DiT，支持英文与中文双语文字渲染
- 原生布局引导：画出盒子，为每个盒子指定文字，文字盒子会渲染出自身的文字
- 文生图模板内置提示词上采样器，一句话的想法就足够
- 两个模型：SFT 适合更整洁的布局，Base 适合微调与 LoRA 工作
- 约 4K token 的长提示词，以及 16 的任意倍数宽高比

**许可证**：[Apache 2.0](https://github.com/OpenMOSS/MOSS-Image)

**相关链接：**

- [GitHub](https://github.com/OpenMOSS/MOSS-Image)
- [模型指南（USERGUIDE）](https://github.com/OpenMOSS/MOSS-Image/blob/main/USERGUIDE.md)
- [Hugging Face（Comfy-Org）](https://huggingface.co/Comfy-Org/MOSS-Image)

**版本要求**：MOSS-Image 模板需要 ComfyUI 0.42.0 或更高版本。

## 提示技巧

- **描述最终图像，而不是提出请求。** 该模型是在描述文本上训练的，因此请写出画面看起来是什么样，而不是写“帮我做一张海报”这样的指令。上采样器遵循同一规则，所以简短提示词仍然有效。
- **关闭上采样器以控制措辞。** 在子图节点上将 `enable_prompt_upsampler` 设为 `false`，提示词就会原样传给模型。两种设置都会在 `Preview Any` 中显示结果，因此可以对比。
- **自行控制换行。** 自动换行可能不会落在你期望的位置。当换行位置很重要时，在要渲染的文本中放入实际换行符或 `\n`。
- **位置很重要时，使用布局工作流。** 框会为每个元素和每个文本块向模型提供明确的位置，这比用文字描述位置更可靠。
- **将画布保持在推荐范围内。** `ResolutionSelector` 选择宽高比和像素数（默认 1 MP）。MOSS-Image 针对 1 MP 至 2 MP 训练，并可在约 0.25 MP 至 4 MP 的范围内外推；宽度和高度必须是 16 的倍数。
- **从模板设置开始，然后为官方效果放慢速度。** 模板使用 `er_sde` 采样器、以 CFG 2.5 运行 25 步，以求速度。官方设置是 CFG 3、50 步，因此如果结果效果不足，可以尝试这些设置。
- **保持负面提示词简短。** 模板默认附带 `nsfw, worst quality, bad anatomy, watermark, jpeg artifact`。
- **跳过层引导默认开启，位于第 22 层。** 子图节点上有一个 `SLG` 开关，引导使用官方的第 22 层。关闭它可能看起来更真实，但可能丢失细节；其他层只能在子图内部调整。
- **基础模型用于微调。** 在 MOSS-Image 上训练 LoRA 时，请冻结文本编码器。
