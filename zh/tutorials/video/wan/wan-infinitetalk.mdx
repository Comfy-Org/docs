**Wan2.1 InfiniteTalk** 是一个基于 Wan2.1 构建的开源音频驱动视频生成模型，由 [MeiGen-AI](https://github.com/MeiGen-AI/InfiniteTalk) 开发。它支持根据单张参考图像和音频输入生成全身说话视频。角色的口型动作和身体动作会自动同步，以匹配所提供的音频。

**主要功能**：
- **音频驱动口型同步**：生成与输入音频相匹配的自然口型动作
- **全身动作**：在保留身份、背景和相机运动的同时，添加同步的身体动作
- **双模式**：同时支持单角色和多角色场景
- **ComfyUI 原生支持**：内置 `WanInfiniteTalkToVideo` 节点，无需自定义节点

## 工作流步骤

1. **加载输入图像**：将角色参考图像拖拽到 `Load Image` 节点。对于多角色场景，使用遮罩编辑器为每个角色绘制遮罩。
2. **加载音频轨道**：将音频文件连接到 `Load Audio` 节点（每个角色一个）。
3. **加载扩散模型**：确保 `Load Diffusion Model` 节点使用的是 `Wan2_1-I2V-14B-480p_fp8_e4m3fn_scaled_KJ.safetensors`。
4. **加载模型补丁**：通过 `ModelPatchLoader` 节点加载相应的 InfiniteTalk 补丁（`single` 或 `multi` 变体）。
5. **配置 InfiniteTalk**：调整 `WanInfiniteTalkToVideo` 节点的参数，例如 `length`（视频长度，以帧为单位）、`motion_frame_count`（用作运动上下文的之前帧数）以及 `audio_scale`。
6. **生成**：运行工作流。模型将生成与输入音频同步的全身说话视频。

### 扩展视频长度

每个 **Video Extend** 组会将视频延长约 3.24 秒（25 fps 下的 81 帧）。如果你的音频更长，可以：

1. 框选 "Video Extend" 组
2. 按 `Ctrl-C`（复制），然后按 `Ctrl-Shift-V`（带连线粘贴）
3. 将上一个 `InfiniteTalk (Base Generation)` 节点的 `IMAGE` 输出连接到新的 `WanInfiniteTalkToVideo` 节点的 `previous_frames` 输入
4. 将 `Batch Images` 节点的 `IMAGE` 输出连接到新的 `Batch Images` 节点的图像输入

## 常见问题

<AccordionGroup>
  <Accordion title="为什么 ComfyUI 提示 &quot;Not enough GPU memory&quot;？">
    这是 ComfyUI 通用的内存不足提示。该模板没有 batch size 设置，因此没有批次数可以降低。它加载的模型文件合计约 30 GB：`Wan2_1-I2V-14B-480p_fp8_e4m3fn_scaled_KJ` 扩散模型（16.6 GB）、`umt5_xxl_fp8` 文本编码器（6.7 GB）以及 InfiniteTalk 补丁（5.1 GB）。在默认的 832 x 480、81 帧下，留给采样缓冲的余量很小，运行就会在这里中止。
  </Accordion>
  <Accordion title="应该先降低什么？">
    先降低对内存影响最大的两个值，然后重新运行。**Width** 和 **Height** 是 InfiniteTalk 组上方的 `PrimitiveInt` 节点，默认 832 x 480，两者都必须能被 16 整除，因此 640 x 368 是有效的小尺寸组合。`WanInfiniteTalkToVideo` 上的 **length** 默认 81 帧，以 4 为步长，有效值为 4n+1，例如 49。如果仍然不够，可以降低 `motion_frame_count`（默认 9，最大 33）以减少作为运动上下文的帧数，并在测试时移除多余的 **Video Extend** 组。
  </Accordion>
  <Accordion title="换成 single 补丁能省内存吗？">
    单看补丁不会：两个补丁文件体积几乎相同（`single` 为 5.13 GB，`multi` 为 5.12 GB）。真正省下来的是只跑一个说话人，少了第二个音频编码器输出和两个遮罩输入。只有在把节点模式改为 `single_speaker` 时，才把 `ModelPatchLoader` 换成 `single`，因为补丁必须与模式匹配。
  </Accordion>
  <Accordion title="Mac 上能跑这个工作流吗？">
    可以，但 Apple Silicon 的 CPU 和 GPU 共用同一个统一内存池，没有独立的显存可以占满或释放。ComfyUI 会把整机内存总量视为设备可用内存，其他正在运行的应用也从同一个池中取用。32 GB 的 Mac 需要容纳约 30 GB 模型文件再加上采样缓冲，因此在默认设置下会内存不足。[系统要求](/zh/installation/system_requirements) 介绍了 MPS 后端。
  </Accordion>
  <Accordion title="在 macOS 上显存相关的启动参数有用吗？">
    没有。在 Apple Silicon 上 ComfyUI 会把显存模式强制设为共享内存（`comfy/model_management.py`），这会覆盖 `--lowvram`、`--novram` 和 `--highvram`。这些参数无法把权重移出统一内存池，因为没有别的地方可以放。在 Nvidia 显卡以及 ROCm 7.14 及更高版本上，dynamic VRAM 默认开启，开启期间 `--lowvram` 不起作用，因此在这类平台上它也很少有用。参见 [启动参数](/zh/development/comfyui-server/startup-flags)。Mac 上有效的做法是：退出占用内存较多的其他应用、按上面的方法降低分辨率和帧数，以及用 `--cache-none` 启动 ComfyUI，使节点输出不会在两次运行之间被缓存。
  </Accordion>
  <Accordion title="还是内存不足怎么办？">
    在 macOS 上，PyTorch 会拒绝超过设备建议工作集大小 1.7 倍的 MPS 内存分配，运行往往就卡在这个上限。`PYTORCH_MPS_HIGH_WATERMARK_RATIO=0.0` 会去掉该上限，但可能让 Mac 进入交换内存或卡住其他应用，所以只作为最后手段。
  </Accordion>
  <Accordion title="在 Apple Silicon 上用 fp8 模型能省内存吗？">
    不能像在 NVIDIA 显卡上那样省。MPS 上没有 PyTorch 的 fp8 计算内核，权重需要转成 bf16 参与计算。bf16 副本放得下时，ComfyUI 会在加载时展开模型，fp8 文件最终占用的内存与 bf16 版本差不多；放不下时，权重在内存中保持 fp8、计算时即时转换，用速度换内存。Mac 上真正有效的仍然是分辨率和帧数。
  </Accordion>
</AccordionGroup>
