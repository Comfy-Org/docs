[MiniMax H3](https://www.minimax.io/blog/minimax-h3) 是 MiniMax 的开放权重全模态模型，在单一上下文中理解文本、图像、视频与音频，并在单次前向中生成带**原生立体声音频**的视频（语音、音效、音乐一体）。开放权重约以 100 万像素（短边 768px）、24fps 生成最长约 15 秒。2K 来自托管服务，在 ComfyUI 中需单独放大。

## 主要功能

- **原生立体声音频**：对话、音效、音乐同一 MP4
- **多模态上下文**：组合文本、图像、视频、音频参考
- **参考驱动生成**：从参考锁定身份、风格、动作、运镜或声音
- **指令遵循**：用自然语言描述参考与目标镜头关系
- **准确文本渲染**：清晰拼写与品牌元素
- **开放权重**：ComfyUI 本地全参数控制

## 入门

1. 更新 ComfyUI：基础 T2V/I2V/R2V 模板需 **0.30.0+**；多帧参考 **0.34.0+**；Fun ControlNet Union、稀疏注意力与 Model Attention Backend **0.35.0+**；FastH3 **0.36.0+**
2. **模板库** > **视频** > 选择 MiniMax H3 工作流
3. 按弹窗下载模型（数十 GB，预留时间与磁盘）

权重托管于 [Comfy-Org/MiniMax-H3](https://huggingface.co/Comfy-Org/MiniMax-H3)。

<Note>
仓库同时提供完整与 pruned 构建时，请用 **pruned**。pruned 将 adaln 存入共享曲线表（`adaln_t_table`），ComfyUI 从文件读取；模板加载 `minimax_h3_*_pruned_int8_convrot.safetensors`。在**完整**构建上蒸馏的 LoRA 含 adaln 张量，pruned 无对应项（形状不匹配，权重被跳过）。Turbo LoRA 无 adaln 张量，两种构建均可加载。
</Note>

## 选择检查点精度

选能放进显存的最小构建。仅改 `UNETLoader` 文件即可；量化由 checkpoint 声明。LoRA 须与构建系列匹配（完整构建 LoRA 在 pruned 上会丢失 adaln）。

| 构建（fl2va / ref2va） | 大小 | 说明 |
| --- | --- | --- |
| [`pruned_w6a8`](https://huggingface.co/Comfy-Org/MiniMax-H3/blob/main/diffusion_models/minimax_h3_fl2va_pruned_w6a8.safetensors) | 16 GB | 最小；INT8 路径；ComfyUI 0.38.0+ |
| [`pruned_int8_convrot`](https://huggingface.co/Comfy-Org/MiniMax-H3/blob/main/diffusion_models/minimax_h3_fl2va_pruned_int8_convrot.safetensors) | 21 GB | 模板默认 |
| [`pruned_fp8_scaled`](https://huggingface.co/Comfy-Org/MiniMax-H3/blob/main/diffusion_models/minimax_h3_fl2va_pruned_fp8_scaled.safetensors) | 21 GB | 与 INT8 同尺寸 |
| [`pruned_bf16`](https://huggingface.co/Comfy-Org/MiniMax-H3/blob/main/diffusion_models/minimax_h3_fl2va_pruned_bf16.safetensors) | 40 GB | 未量化 pruned |
| [`bf16`](https://huggingface.co/Comfy-Org/MiniMax-H3/blob/main/diffusion_models/minimax_h3_fl2va_bf16.safetensors) | 66 GB | 完整未量化构建 |

链接为 T2V/I2V 的 `fl2va`；`ref2va` 同目录同尺寸。**Comfy Kitchen attention 无法运行 `int8_convrot` checkpoint**，使用该后端时请选 `bf16`。

显存不足请降一档：CPU offload 比精度取舍更慢。RTX 30 系上 INT8 矩阵约 2× FP16，且无 FP8 路径，同尺寸下 INT8 常快于 FP8。

还需视频与音频 VAE：[视频 fp16/int8_convrot](https://huggingface.co/Comfy-Org/MiniMax-H3/tree/main/vae) 与 [音频 fp32](https://huggingface.co/Comfy-Org/MiniMax-H3/blob/main/vae/minimax_h3_audio_vae_fp32.safetensors)。模板为 int8 视频 + fp32 音频；int8 视频在 ComfyUI 0.36.0+ 解码约快 2 倍。在 `VAELoader` 上换文件即可。

## 设置输出分辨率

**Resolution Selector** 设置 H3 节点的 `width`/`height`：

- **Aspect ratio**：如 `16:9 (Widescreen)`、`9:16 (Portrait Widescreen)`、`1:1 (Square)`
- **Megapixels**：总像素（越大越慢）
- **Multiple**：对齐网格；H3 保持 **32**

模板默认 **Megapixels** 为 **0.4**：16:9 下 **864×480**，1:1 下 **640×640**（I2V 默认）。0.4 MP 出片快，适合草稿；正式出片前请调高 **Megapixels**。

16:9 原生画质：设 **0.98**（约 1344×768）或在节点填 **1344 × 768**。避免 **1.0** MP（1376×768 超出 768×1344 上限）。训练约 1 MP，放大画布不会增加细节；2K 请原生生成后单独放大。

### 放大到更高分辨率

对 24 通道视频 latent 使用 **latent 放大器**，避免 VAE 往返鬼影。[Minimax_h3_latent_Upscaler](https://huggingface.co/LBH-123-AI/Minimax_h3_latent_Upscaler)（非官方）需 [权重文件](https://huggingface.co/LBH-123-AI/Minimax_h3_latent_Upscaler/blob/main/minimax_h3_latent_upscaler_3d_conv_v1/minimax_h3_latent_upscaler_3d_conv_v1_bf16.safetensors) 与 [自定义节点](https://github.com/LBH-123-AI/Comfyui_Minimax_h3_latent_Upscaler)。低分辨率生成后接 **Minimax H3 Latent Upscaler (3D)**（`scale` 1.0–4.0，默认 2.0），再按目标分辨率重采样。

Latent 放大省时间不省峰值显存。精修作部分去噪：`denoise` **0.1–0.5** 保留构图；仅首段需大改时提高。精修采样器需足够步数以重建多步历史（见「采样器与调度器」）。

视频与音频 latent 分离（24+32 通道）。放大器只放大视频空间；精修会同时去噪音频。低 `denoise` 可保留首段音频。若要完全一致，精修前用 `VAEDecodeAudio` 解码首段音频并接到最终 `CreateVideo`（可用 `SaveAudioAdvanced` 导出无损）。

## 片段时长

H3 在短片段上训练；节点接受更宽范围且不阻止超长请求。

模板以秒设置 `duration`，在 24fps 下换算为 **17k+5** 帧网格。

| 设置 | 范围 |
| --- | --- |
| `length` 输入 | 5–3600 帧（约 0.2 s–150 s） |
| 训练范围 | 约 124–362 帧（约 5–15 s） |
| 帧网格 | 24fps 下 `17k+5`（124 帧 = 5 s） |
| 模板默认 | 5 s → 124 帧 |

长片段在满分辨率下先耗尽显存；可降低 Megapixels。

### 链接片段

超出训练范围时用 I2V 续接上一段末帧。误差会累积（面部纹理先劣化）；turbo/蒸馏步数更早出现「烧片」。

使用 `video_minimax_h3_i2v_continuation`（空提示词）：载入末帧并描述下一段。连续镜头宜短，烧片前切镜。更长链可在首段之后加载 [H3-Anti-Burn-LoRA](https://huggingface.co/Imagineer13/H3-Anti-Burn-LoRA/blob/main/h3_antiburn_universal_v1.safetensors)，`strength_model` 约 0.5（按续接方式微调）。

## 步数

默认（关闭 Lightning LoRA）：**20** 步。开启 turbo：T2V/I2V（含续接）**8** 步；R2V、多帧、Fun ControlNet **4** 步。T2V/I2V 子图用 `turbo_mode`、`turbo_steps`、`turbo_model_strength`。另有 4 步 fl2va 文件：[`minimax_h3_fl2v_turbo_4step_v1.0_768p_comfyui_bf16.safetensors`](https://huggingface.co/Comfy-Org/MiniMax-H3/blob/main/loras/minimax_h3_fl2v_turbo_4step_v1.0_768p_comfyui_bf16.safetensors)，`turbo_steps` 设为 **4**。

参考镜头需更多步数：参考 token 每步都参与，4 步 turbo 可能几乎贴不上参考（姿态/面部漂移）。需紧贴参考时关闭 turbo 或提高到约 **25**。

蒸馏步数比 20 步基线更平滑细节。各 turbo 文件按模式训练；叠风格 LoRA 前请固定种子测试。可提高 `turbo_steps` 并降低 `turbo_model_strength`（小于 1）换回基线质感。例：4 步文件用 6–8 步、强度约 0.8。

Turbo 缩短的是 schedule，不是单步耗时（加载时合并）。4 步 LoRA 跑 20 步约等于基线 20 步耗时。

按内容：

- 简单镜头：**12–16** 步常够
- 高频细节（链甲、花纹、大量小物体）：可改善至约 **50**；更低易出现运动下三角网格伪影（turbo 更严重）
- 运动/提示词收益多在 **16** 步前；**50** 步后差异很小
- 原生分辨率下画面发软多为分辨率问题，而非步数

音频在联合去噪中比画面收敛慢。语音与音色建议 **12+** 步；**8** 步时音频常为弱项。

## 采样器与调度器

模板使用 **`res_multistep`** + **`simple`**。T2V/I2V/FastH3 在子图内；R2V、多帧、Fun ControlNet 在画布暴露 `KSamplerSelect` 与 `BasicScheduler`。

`res_multistep` 为二阶多步（首步为 Euler）。拆成两个采样器会丢失多步历史，第二段首步又变一阶。尽量单段采样，或给第二段足够步数预热。

默认 shift：**12**，`audio_shift`：**3**（模型定义）。FastH3 模板 **ModelSamplingMiniMaxH3** 为 `shift_video` **10**、`shift_audio` **3**。蒸馏构建上错误的 video shift（如 8 步用 **3** 而非 **10**）可能出现网格伪影。自定义微调见模型卡。[DMAD 4-step LoRA](https://huggingface.co/ZhengmingYu/DMAD/blob/main/minimax_h3/dmad_minimax_h3_4step_full_critic_comfyui.safetensors) 用 shift **12**、`audio_shift` **2**，采样器 **`lcm`** + **`simple`**。

## 使用 Sage Attention 加速生成

[Sage Attention](https://github.com/woct0rdho/SageAttention) 约可 **2×** 加速，画质影响通常较小（需自行安装）：

1. 从 [releases](https://github.com/woct0rdho/SageAttention/releases) 安装匹配 PyTorch/CUDA 的 wheel
2. 安装 [KJNodes](https://github.com/kijai/ComfyUI-KJNodes) 的 `Patch Sage Attention KJ`
3. 插在 `UNETLoader` 与 `BasicGuider` 之间，`sage_attention` 设为 `auto`
4. 或启动参数 `--use-sage-attention`

部分 H3 层非 float16/bfloat16 会回退 PyTorch attention（控制台警告正常）。

### 使用 INT8 attention 时的画质下降

片段末尾形变或屏幕文字损坏，常见原因为 INT8 attention 量化。

- 模板为 **`int8_convrot`**。**Comfy Kitchen 不支持**（[issue #15529](https://github.com/Comfy-Org/ComfyUI/issues/15529)）。用默认 attention，或换 **`pruned_bf16`** 后再改后端。
- **bf16** 上 **Comfy Kitchen attention**（量化前通道旋转）可消除伪影，速度相近。

在通向 `BasicGuider` 的模型链添加 **Model Attention Backend**（`comfy kitchen attention`），或 `--use-ck-attention`（0.32.0+）。需硬件支持 `comfy-kitchen` INT8 内核。

## 使用稀疏注意力加速生成

**Model Sparse Attention**（0.35.0+，实验性）降低长片段 attention 成本。基座 H3 用 **`sol-attn`**（`sla`/`vsa` 需匹配权重）。需 CUDA 与 `comfy-kitchen` 的 `sol_attn`，否则保持稠密。

- 默认 `start_percent` **0.2**、`end_percent` **1.0**。可约 **0.4** 起、**0.9** 止以保护首尾帧。
- H3 保持 **`sink_conditioning`** 为 **`exact_kv_and_rows`**。
- **`tau`** 越大越稀疏越快（`1.0` 约 16% 精确块，`1.3` 默认，`2.0` 约 2.7%）。
- 短于 `min_tokens`（默认 **12288**）收益很小。

FastH3 用 **`vsa`**、`keep_percent` **10**；见 [FastH3 页面](/zh/tutorials/video/minimax/minimax-h3-fastvideo)。

### 稀疏注意力是否生效

基座 H3 模板不含此节点。在 `UNETLoader` 与 `BasicGuider` 之间加入 **Model Sparse Attention**，再打开 **`verbose`**（高级选项，默认关闭），每个 attention 形状会输出一行日志。

保持稠密的调用会输出 `dense (<n> tokens): <reason>` 或 `dense (<b>, <n>, <h>, <d>): <reason>`，只报告第一个不满足的条件：

| 日志原因 | 处理方式 |
| --- | --- |
| `no compiled sol_attn kernel for this GPU` | 已安装的 `comfy-kitchen` 没有该 GPU 的 kernel。更新它，或在该机器上不使用此节点。 |
| `<n> tokens < min_tokens <value>` | 提高分辨率或片段长度，或调低 `min_tokens`（默认 **12288**）。 |
| `sigma <x> outside the start/end window` | 放宽 `start_percent` 与 `end_percent`。 |
| `block <i> in dense_blocks` | 从 `dense_blocks` 中移除该 block 序号。 |
| `no H3 layout for this call` | 仅 `vsa` 会出现。改用 `sol-attn`。 |

成功的调用输出 `sparse (<b>, <n>, <h>, <d>), sinks <k>/<q>` 或 `sparse producer path: <n> tokens, <mode>`。

有三种情况即使打开 `verbose` 也不会输出日志：H3 路径上的激活值不是 bfloat16、`head_dim` 不是 **128**、缺少 rope 频率，都会静默退回稠密。

`vsa` 绑定在 FastH3 检查点上。它要读取只有该权重才有的 `to_gate_compress` 层提供的粗粒度分支，所以在其他 H3 检查点上节点会输出 `VSA: the model has no to_gate_compress layers; running the fine stage without the coarse branch`，只跑细粒度阶段。该警告不受 `verbose` 控制。
