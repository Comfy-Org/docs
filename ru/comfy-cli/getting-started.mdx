## Обзор

`comfy-cli` — это [инструмент командной строки](https://github.com/Comfy-Org/comfy-cli), который упрощает установку Comfy и управление ею, а также даёт вам скриптовый доступ ко всей экосистеме ComfyUI одной командой, локально или в облаке.

Он выполняет три основные функции:

1. **Управлять локальной установкой ComfyUI**: устанавливать, запускать, обновлять, создавать снимки и выполнять бисекцию ComfyUI и пользовательских узлов.
2. **Получать доступ к размещённым партнёрским узлам**: генерировать изображения, видео, аудио и 3D от таких провайдеров, как Seedance, Nano Banana (Gemini), Grok, Flux, Ideogram, DALL·E, Recraft, Stability, Kling, Luma, Runway, Pika, Vidu, Hailuo, Moonvalley и других, одной командой.
3. **Запускать полные рабочие процессы в Comfy Cloud**: отправлять графы рабочих процессов, просматривать галерею отобранных шаблонов, редактировать рабочие процессы по слотам и отслеживать задания до завершения без локального GPU.

## Запуск ComfyUI (локально)

```bash
comfy launch
```

```bash
comfy launch --background
comfy stop
```

Проверьте, какое рабочее пространство выбрано и что установлено:

```bash
comfy which
comfy env
```

## Запустить рабочие процессы {#comfy run}

Помимо одиночных вызовов партнёрских узлов, `comfy run` отправляет полный граф рабочего процесса ComfyUI. Команда принимает JSON как в формате API, так и в экспортированном UI-формате (UI-рабочие процессы преобразуются в формат API на стороне клиента), и, как и любая другая команда, направляет запрос локально или в облако. По умолчанию она работает **асинхронно**: возвращает `prompt_id` за миллисекунды, а фоновый наблюдатель отслеживает прогресс. Передайте `--wait`, чтобы вместо этого дождаться завершения.

```bash
# Отправить; сразу возвращает prompt_id
RES=$(comfy --json run --workflow my_workflow.json)
PROMPT_ID=$(echo "$RES" | jq -r .data.prompt_id)

# Отслеживать до конечного состояния, затем собрать выходы
comfy --json jobs watch "$PROMPT_ID" | comfy download
```

Нужен один блокирующий вызов? Используйте `--wait`:

```bash
comfy run --workflow my_workflow.json --wait | comfy download
```

Отслеживание заданий и управление ими:

```bash
comfy jobs ls                 # локальные асинхронные отправки + очередь и история сервера
comfy jobs status <prompt_id> # одна задача
comfy jobs wait <id1> <id2>   # блокироваться, пока ВСЕ не достигнут конечного состояния
comfy jobs cancel <prompt_id> # идемпотентно
```

<Tip>
  Проверяйте перед отправкой. Отлавливайте неизвестные узлы, отсутствующие модели и ошибки в соединениях между узлами до того, как потратите облачные ресурсы:

  ```bash
  comfy validate --workflow my_workflow.json
  ```
</Tip>

## Начать с шаблона

Подобранная галерея `Comfy-Org/workflow_templates` — самый быстрый способ получить проверенный рабочий процесс для конкретной задачи. Строить с нуля не нужно.

```bash
comfy templates ls --type image --tag "Text to Image"   # просмотреть
comfy templates show <name>                              # полные метаданные
comfy templates fetch <name> --out my.json               # получить JSON рабочего процесса
```

Скачанный JSON имеет формат интерфейса. `comfy run --where cloud` автоматически преобразует его в формат API при отправке.

## Редактирование рабочих процессов на месте

`comfy workflow` открывает доступ к слотам, которые может менять агент, в любом рабочем процессе фронтенд-формата и позволяет переопределять их. Без ручной правки JSON.

```bash
comfy workflow slots my.json                 # список адресуемых слотов
comfy workflow set-slot my.json 6.text="a fox in the snow"
comfy workflow vary my.json \
    --slot positive.text='["a cat","a dog","a fox"]' \
    --out-dir ./variants                     # разветвить на N вариантов
```

Сохранённые рабочие процессы в Comfy Cloud:

```bash
comfy workflow list                          # ваши сохранённые рабочие процессы
comfy workflow get <id> --out my.json
comfy workflow save my.json --name "My Flow"
comfy workflow delete <id>
```

Для сложных многошаговых конвейеров собирайте небольшие переиспользуемые фрагменты в один граф:

```bash
comfy workflow compose blueprints/my_pipeline.yaml -o workflows/my_pipeline.json
comfy workflow decompose my.json             # обратная операция: спроецировать рабочий процесс в фрагмент
```
## Поиск узлов и моделей

Просматривайте всё, что доступно на выбранном бэкенде.

**Узлы:**

```bash
comfy nodes search "checkpoint"              # нечёткий поиск
comfy nodes show KSampler                    # полная схема: входы, выходы, значения по умолчанию
comfy nodes ls --produces IMAGE --limit 10   # фильтр по типу выхода
comfy nodes ls --api-only                    # только узлы партнёрского API
```

**Модели:**

```bash
comfy models list-folders                    # все папки моделей
comfy models search --text "wan2.2" --type lora
comfy models show wan2.2_vae.safetensors     # полные метаданные
```
## Загрузить и скачать файлы

```bash
comfy upload photo.png video.mp4             # → входной каталог сервера
comfy download <prompt_id>                   # → ./outputs/
```

<Tip>
  **Идиоматический конвейер:**

  ```bash
  comfy run --workflow flux.json --wait | comfy download
  ```

  `comfy download` автоматически читает prompt_id и URL-адреса выходов из stdin конвейера. Извлекать ключи вручную не нужно, `jq` тоже не понадобится.

## JSON-вывод для скриптов и агентов

Каждая команда принимает `--json` и возвращает конверт одинаковой формы, поэтому CLI полностью пригоден для скриптов и агентов:

```json
{
  "ok": true,
  "command": "...",
  "version": "1.11.1",
  "where": "local | cloud | null",
  "data": { },
  "error": null
}
```

Если присутствует `error`, прочитайте `hint` и действуйте по нему:

```bash
comfy --json run --workflow my.json | jq '.error.hint'
```

Интерфейс для агентов полностью самоописываемый. Выгрузите всё дерево команд, схемы вывода и коды ошибок:

```bash
comfy --json discover
```

## Аналитика

Отслеживание использования помогает улучшать CLI. Отключить его можно так:

```bash
comfy tracking disable
```

Снова включить отслеживание:

```bash
comfy tracking enable
```

Также можно полностью отказаться от отслеживания с помощью переменных окружения `DO_NOT_TRACK` или `COMFY_NO_TELEMETRY`.
