## Обзор

`comfy-cli` — это [инструмент командной строки](https://github.com/Comfy-Org/comfy-cli), который упрощает установку Comfy и управление ею, а также даёт скриптовый доступ ко всей экосистеме ComfyUI одной командой, локально или в облаке.

Он выполняет три основные функции:

1. **Управление локальной установкой ComfyUI** — установка, запуск, обновление, создание снимков и бисекция ComfyUI и пользовательских узлов.
2. **Доступ к размещённым партнёрским узлам** — генерируйте изображения, видео, аудио и 3D от таких провайдеров, как Seedance, Nano Banana (Gemini), Grok, Flux, Ideogram, DALL·E, Recraft, Stability, Kling, Luma, Runway, Pika, Vidu, Hailuo, Moonvalley и других, одной командой.
3. **Запуск полных рабочих процессов в Comfy Cloud** — отправляйте графы рабочих процессов, просматривайте кураторскую галерею шаблонов, редактируйте рабочие процессы по слотам и отслеживайте задания до завершения без локального GPU.


## Запустить рабочие процессы {#comfy run}

Помимо одиночных вызовов партнёров, `comfy run` отправляет полный граф рабочего процесса ComfyUI. Он принимает JSON как в формате API, так и в экспортированном формате UI (рабочие процессы UI преобразуются в формат API на стороне клиента) и направляет запрос локально или в облако, как и любая другая команда. По умолчанию он работает **асинхронно**. Он возвращает `prompt_id` за миллисекунды, а прогресс отслеживает фоновый наблюдатель. Передайте `--wait`, чтобы вместо этого дождаться завершения.

```bash
# Отправить; сразу возвращает prompt_id
RES=$(comfy --json run --workflow my_workflow.json)
PROMPT_ID=$(echo "$RES" | jq -r .data.prompt_id)

# Отслеживать до терминального состояния, затем собрать выходы
comfy --json jobs watch "$PROMPT_ID" | comfy download
```

Нужен один блокирующий вызов? Используйте `--wait`:

```bash
comfy run --workflow my_workflow.json --wait | comfy download
```

Отслеживание и управление заданиями:

```bash
comfy jobs ls                 # локальные асинхронные отправки + очередь и история сервера
comfy jobs status <prompt_id> # одна задача
comfy jobs wait <id1> <id2>   # блокировать, пока ВСЕ не достигнут терминального состояния
comfy jobs cancel <prompt_id> # идемпотентно
```

<Tip>
  Проверьте перед отправкой. Отлавливайте неизвестные узлы, отсутствующие модели и ошибки в связях до того, как потратите облачные ресурсы:

  ```bash
  comfy validate --workflow my_workflow.json
  ```
</Tip>

## Начать с шаблона

Галерея `Comfy-Org/workflow_templates` с тщательно подобранными шаблонами: самый быстрый способ получить проверенный рабочий процесс для конкретной задачи. Собирать с нуля не нужно.

```bash
comfy templates ls --type image --tag "Text to Image"   # просмотреть
comfy templates show <name>                              # полные метаданные
comfy templates fetch <name> --out my.json               # получить JSON рабочего процесса
```

Скачанный JSON имеет формат фронтенда. `comfy run --where cloud` автоматически преобразует его в формат API при отправке.

## Редактирование рабочих процессов на месте

`comfy workflow` открывает слоты, которые агент может изменять, в любом рабочем процессе в формате фронтенда и позволяет переопределять их. Никаких ручных правок JSON.

```bash
comfy workflow slots my.json                 # list addressable slots
comfy workflow set-slot my.json 6.text="a fox in the snow"
comfy workflow vary my.json \
    --slot positive.text='["a cat","a dog","a fox"]' \
    --out-dir ./variants                     # fan out N variants
```

Сохранённые рабочие процессы в Comfy Cloud:

```bash
comfy workflow list                          # your saved workflows
comfy workflow get <id> --out my.json
comfy workflow save my.json --name "My Flow"
comfy workflow delete <id>
```

Для сложных многоэтапных пайплайнов объединяйте небольшие переиспользуемые фрагменты в один граф:

```bash
comfy workflow compose blueprints/my_pipeline.yaml -o workflows/my_pipeline.json
comfy workflow decompose my.json             # inverse: project a workflow into a fragment
```

## Поиск узлов и моделей

Выполните интроспекцию всего, что доступно на разрешённом бэкенде.

**Nodes:**

```bash
comfy nodes search "checkpoint"              # fuzzy search
comfy nodes show KSampler                    # full schema: inputs, outputs, defaults
comfy nodes ls --produces IMAGE --limit 10   # filter by output type
comfy nodes ls --api-only                    # partner-API nodes only
```

**Models:**

```bash
comfy models list-folders                    # every model folder
comfy models search --text "wan2.2" --type lora
comfy models show wan2.2_vae.safetensors     # full metadata
```

## Загрузить и скачать файлы

```bash
comfy upload photo.png video.mp4             # → входной каталог сервера
comfy download <prompt_id>                   # → ./outputs/
```

<Tip>
  **Идиоматичное использование конвейера:**

  ```bash
  comfy run --workflow flux.json --wait | comfy download
  ```

  `comfy download` автоматически читает prompt_id и URL выходных файлов из stdin конвейера. Не нужно вручную извлекать ключи, не нужен `jq`.
</Tip>

## Вывод JSON для скриптов и агентов

Каждая команда принимает `--json` и выдаёт одну и ту же структуру конверта, что делает CLI полностью пригодным для скриптов и удобным для агентов:

```json
{
  "ok": true,
  "command": "...",
  "version": "1.11.1",
  "where": "local | cloud | null",
  "data": { },
  "error": null
}
```

Когда присутствует `error`, прочитайте `hint` и действуйте в соответствии с ним:

```bash
comfy --json run --workflow my.json | jq '.error.hint'
```

Интерфейс, обращённый к агенту, полностью самоописываем. Выгрузите всё дерево команд, схемы вывода и коды ошибок:

```bash
comfy --json discover
```

## Аналитика

Отслеживание использования помогает улучшать CLI. Отключить его можно так:

```bash
comfy tracking disable
```

Снова включить отслеживание:

```bash
comfy tracking enable
```

Также можно полностью отказаться от отслеживания с помощью переменных окружения `DO_NOT_TRACK` или `COMFY_NO_TELEMETRY`.
