## Базовые стандарты


### 1. Ценность для сообщества
Пользовательские узлы должны предоставлять полезную функциональность сообществу ComfyUI

Избегайте:
- Чрезмерного самопродвижения
- Выдачи себя за других или вводящего в заблуждение поведения
- Вредоносного поведения
- Самопродвижение разрешено только в предназначенном для этого разделе меню настроек
- Верхние и боковые меню должны содержать только полезную функциональность

### 2. Совместимость узлов
Не вмешивайтесь в работу других пользовательских узлов (установка, обновления, удаление)
- Для зависимостей от других пользовательских узлов:
  - Показывайте понятные предупреждения при использовании зависимой функциональности
  - Предоставляйте примеры рабочих процессов, демонстрирующие необходимые узлы

### 3. Соблюдение законодательства
Необходимо соблюдать все применимые законы и нормативные требования

### 5. Требования к качеству
Узлы должны быть полностью работоспособными, хорошо документированными и активно поддерживаться.

### 6. Правила для форков
Форки узлов должны:
  - Иметь явно отличающиеся от оригинала названия
  - Иметь существенные различия в функциональности или коде

Ниже приведены стандарты, которым необходимо соответствовать для публикации пользовательских узлов в Comfy Registry.

## Стандарты безопасности

Пользовательские узлы должны быть безопасными. Мы начнём работу с авторами пользовательских узлов, нарушающих эти стандарты, чтобы переписать их. Если какая-то важная функциональность должна предоставляться ядром, запросите её в [репозитории rfcs](https://github.com/comfy-org/rfcs).

### Вызовы eval/exec

#### Политика
Использование функций `eval` и `exec` запрещено в пользовательских узлах по соображениям безопасности.

#### Обоснование
Эти функции могут обеспечивать выполнение произвольного кода, создавая потенциальные уязвимости удалённого выполнения кода (RCE) при обработке пользовательских входов. Рабочие процессы с узлами, которые передают пользовательские входы в `eval` или `exec`, могут быть использованы для различных кибератак, включая:
- Кейлоггинг
- Программы-вымогатели
- Иное выполнение вредоносного кода

### subprocess для pip install

#### Политика
Установка пакетов во время выполнения через вызовы subprocess не разрешена.

#### Обоснование
- Первый пункт
ComfyUI Manager будет поставляться вместе с ComfyUI и позволит пользователю устанавливать зависимости
- Централизованное управление зависимостями повышает безопасность и улучшает пользовательский опыт
- Помогает предотвращать потенциальные атаки на цепочки поставок
- Устраняет необходимость в многократной перезагрузке ComfyUI

### Обфускация кода

#### Политика
Обфускация кода запрещена в пользовательских узлах.

#### Обоснование
Обфусцированный код:
- Невозможно проверить, и, скорее всего, он вредоносный
