Каждый запрос к партнёрскому узлу создаёт данные, которые хранятся на нашей платформе: входы (изображения, видео, 3D-ассеты, аудио) и выходы, созданные моделью. На этой странице описано, как долго хранится каждый тип данных. Информация о том, где каждый провайдер обрабатывает эти данные по умолчанию, приведена отдельно на странице [Провайдеры моделей](/ru/tutorials/partner-nodes/model-providers).

## Что хранится

При запуске партнёрского узла сохраняются файлы двух видов:

- **Входные файлы**: референсные изображения, аудио и другие медиафайлы, которые вы передаёте узлу. Входы загружаются в хранилище вашей учётной записи.
- **Выходные файлы**: изображения, видео, аудио и другие медиафайлы, которые создаёт узел. Выходы записываются в хранилище под управлением Comfy и возвращаются вам в виде URL для скачивания.

И входные, и выходные файлы хранятся в бакетах облачного хранилища под управлением Comfy.

## Сколько хранятся файлы

Все медиафайлы партнёрских узлов автоматически удаляются через **24 часа** после создания. Удаление применяется как к входным, так и к выходным файлам.

| Тип файла | Удаляется через |
| --- | --- |
| Входные файлы | 24 часа |
| Выходные файлы | 24 часа |

<Note>
  24-часовое окно удаления является настройкой платформы по умолчанию и применяется ко всем вызовам партнёрских узлов. Если вам нужно хранить файлы дольше, скачайте их в собственное хранилище до истечения срока.
</Note>

## Что происходит после удаления

После удаления файла его URL для скачивания возвращает ошибку. Удалённые файлы невозможно восстановить, и если они понадобятся снова, те же медиафайлы придётся загрузить заново или сгенерировать повторно.

Удаление входного файла также удаляет соответствующую запись файла из хранилища вашей учётной записи, поэтому этот вход нельзя повторно использовать в последующих вызовах.

## Записи задач провайдера

Некоторые партнёрские узлы отправляют провайдеру ID задачи, а не медиафайл, и провайдер работает с записью, которая стоит за этим ID. Узлы продолжения Tripo устроены именно так: `Tripo: Texture model`, `Tripo: Rig model`, `Tripo: Retarget rigged model`, `Tripo: Convert model`, `Tripo: Edit Multiview`, `Tripo: Segment Model`, `Tripo: Retopology` и `Tripo: Complete Mesh Parts` принимают на вход такие значения, как `model_task_id` или `multiview_task_id`.

На сгенерированный файл модели это не влияет. Он скачивается сразу после завершения задачи и сохраняется в ваш выходной каталог.

Записи задач провайдера подчиняются собственным правилам хранения провайдера, а не 24-часовому окну, описанному выше. Tripo хранит запись задачи 7 дней после её завершения (действует с 1 декабря 2026 года). ID задачи старше этого срока больше не разрешается, поэтому повторный запуск сохранённого рабочего процесса с истёкшим `model_task_id` завершается ошибкой в узле продолжения.

Чтобы восстановить работу, повторно импортируйте файл модели, который вы уже скачали, с помощью `Tripo: Import Model`. Он возвращает новый `model_task_id`, который принимают узлы текстурирования, риггинга и конвертации, поэтому платить за базовую модель снова не придётся.

## Как хранить файлы дольше

Если рабочему процессу требуется, чтобы входной файл оставался доступным дольше 24 часов, повторно загружайте файл перед каждой задачей. Для длительных конвейеров повторно загружайте файл непосредственно перед вызовом, которому он нужен.

Выходы, которые вы хотите сохранить, скачивайте в собственное хранилище в течение 24-часового окна.
