### Советы по промптам

1. **Сначала сцена**: общая сцена, затем отдельные планы с таймингом
2. **Один блок**: планы, камера, диалоги, SFX и музыка вместе
3. **Разрешение**: нативный формат 16:9 составляет **1344×768** (768 px по короткой стороне); округляйте до значений, кратных **32**
4. **Длительность**: привязывается к **17k+5** кадрам при 24 fps
5. **Первый/последний кадр**: подключите изображения к `first_frame` / `last_frame` узла `MiniMaxH3ImageToVideo` для FL2VA
6. **Turbo**: по умолчанию **20** шагов; включите `turbo_mode` для 8-шагового Lightning LoRA (быстрее, немного мягче движение и аудио). Увеличьте число шагов (например, до **25**) для лучшего качества движения

Официальное базовое руководство: [руководство по промптам](/ru/tutorials/video/minimax/minimax-h3-prompt-guide).

### Советы по промптам

1. **Ключевые кадры**: необязательные `first_frame` / `last_frame`; движение генерируется между ними
2. **Промпт**: кадры, движение и аудио в одном блоке
3. **Разрешение / длительность**: те же правила, что и для T2V (нативная цель **1344×768**, сетка **17k+5**)
4. **Turbo**: `turbo_mode` использует `turbo_steps` (по умолчанию **8**) и `turbo_model_strength` (по умолчанию **1.0**) вместо 20 шагов

`first_frame` масштабируется под холст без сохранения соотношения сторон, поэтому изображение с другим соотношением получится растянутым. `last_frame`, наоборот, обрезается по центру. Шаблон I2V открывается с соотношением **1:1** и **0.4** MP (**640×640**), поэтому установите соотношение сторон своего изображения и увеличьте Megapixels для финального рендера.

Официальное базовое руководство: [руководство по промптам](/ru/tutorials/video/minimax/minimax-h3-prompt-guide).

### Советы по составлению промптов

1. **Теги**: ссылайтесь на входы как `<Picture 1>`, `<Video 1>`, `<Audio 1>` (`ref_image_0` → `<Picture 1>`). Порядок узлов: изображения, затем видео, затем аудио
2. **Назначьте роли**: укажите, какой референс задаёт идентичность, стиль, движение, камеру или голос
3. **Ограничения**: до **9** изображений, **3** видео, **3** отдельных аудиоклипов
4. **FPS видео**: референсное видео читается как **24fps** без метаданных. Перед загрузкой приведите другие частоты кадров к 24fps
5. **Звук видео**: изображение и звуковая дорожка — отдельные референсы. Подключите `ref_video_audio_N` в соответствии с `ref_video_N`, иначе аудио из файла не будет использовано как `<Audio N>`
6. **Нумерация аудио**: звуковые дорожки видео получают `<Audio N>` первыми (в порядке видео), затем идут отдельные клипы. Индексы видео и изображений независимы
7. **Подключение VAE**: звуковой дорожке видео нужны `vae` + `audio_vae`; отдельному аудио нужен только `audio_vae`
8. **Роли аудио**: например, `use <Audio 1> exactly as it is` против `follow the timbre of <Audio 2>`
9. **Голос**: аудио передаёт тембр, а не слова. Уточняйте манеру подачи; используйте один аудиореференс на говорящего, когда соответствие должно быть точным
10. **`ref_image_size`**: по умолчанию **`match`** (вписать в холст). **`max`** сохраняет короткую сторону 2048px и работает гораздо медленнее; он не увеличивает маленькие файлы (стороны округляются до 32). При необходимости заранее масштабируйте до короткой стороны 2048
11. **Веса**: R2V использует **`ref2va`**, а не модель **`fl2va`** для T2V/I2V
12. **Turbo**: необязательная Lightning LoRA на **4** шага (быстрее, но слабее референс и аудио). Предпочитайте **20–25** шагов, когда референсы должны сохраняться
13. **Style LoRA**: конкурируют с референсами; используйте низкую силу (~**0.5**) на базовом расписании, когда важна точность следования референсу

Официальное руководство по референсам: [руководство по промптам](/ru/tutorials/video/minimax/minimax-h3-prompt-guide).

## Расширенные рабочие процессы с нативными узлами

Для описанных ниже возможностей требуется актуальная сборка ComfyUI.

### Закрепление гайдов на любом кадре (#15439)

[`MiniMaxH3AddGuide`](https://github.com/Comfy-Org/ComfyUI/pull/15439) закрепляет гайд на любом `frame_idx` (отрицательное значение = с конца), а не только на первом или последнем кадре.

Подключите `positive` и латент из узла H3 к `MiniMaxH3AddGuide`. Входы:

- **image**: неподвижное изображение или клип (многокадровые пакеты обрезаются до допустимых длин **17k+5**; при &lt;5 кадрах используется только первое изображение)
- **audio**: звуковая дорожка с тем же индексом кадра, обрезанная до оставшейся длительности
- **frame_idx**: положение якоря

Подключите `vae` для графических гайдов и `audio_vae` для аудио. Для нескольких якорей соединяйте узлы в цепочку.

Пример: первые **22** кадра клипа на кадре **0** продолжают оба потока; неподвижное изображение на кадре **60** заставляет кадр пройти через эту позу.

Это условие, а не видео-в-видео: выборка по-прежнему начинается с пустого латента рабочего процесса. `denoise` не масштабирует силу гайда, как в V2V. Чтобы изменить стиль всего клипа, используйте R2V; чтобы редактировать области, используйте маски [Fun ControlNet Union](/ru/tutorials/video/minimax/minimax-h3-fun-controlnet).

См. шаблон [Multiframe Reference](/ru/tutorials/video/minimax/minimax-h3-multiframe).

### Инпейтинг и расширение с помощью масок шума латента (#15375)

[Маски шума по токенам](https://github.com/Comfy-Org/ComfyUI/pull/15375) на латентах видео и аудио позволяют перегенерировать часть клипа.

Подключите маску к входу `denoise_mask` сэмплера: **0** = оставить, **1** = перегенерировать. Маски видео выравниваются по сетке латентных патчей 2×2, а маски аудио по целым латентным кадрам. Используйте для инпейтинга, удаления или расширения, сохраняя остальное неизменным.
