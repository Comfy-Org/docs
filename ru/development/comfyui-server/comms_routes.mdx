## Маршруты

Сервер определяет набор методов `get` и `post`, которые можно найти, выполнив поиск `@routes` в `server.py`. Когда вы отправляете рабочий процесс в веб-клиенте, он передаётся в `/prompt`, который валидирует промпт и добавляет его в очередь выполнения, возвращая либо `prompt_id` и `number` (позицию в очереди), либо `error` и `node_errors`, если валидация не прошла.
Очередь промптов определена в `execution.py`, где также определён класс `PromptExecutor`.

### Встроенные маршруты

`server.py` определяет следующие маршруты:

#### Основные маршруты API

| путь                           | get/post/ws | назначение                                                                        |
| ------------------------------ | ----------- | --------------------------------------------------------------------------------- |
| `/`                            | get         | загрузить веб-страницу ComfyUI                                                    |
| `/ws`                          | websocket   | эндпоинт WebSocket для обмена данными с сервером в реальном времени               |
| `/embeddings`                  | get         | получить список имён доступных embedding                                          |
| `/extensions`                  | get         | получить список расширений, регистрирующих `WEB_DIRECTORY`                        |
| `/features`                    | get         | получить функции и возможности сервера                                            |
| `/models`                      | get         | получить список доступных типов моделей                                           |
| `/models/{folder}`             | get         | получить модели в указанной папке                                                 |
| `/workflow_templates`          | get         | получить карту модулей пользовательских узлов и связанных шаблонов рабочих процессов |
| `/upload/image`                | post        | загрузить изображение                                                             |
| `/upload/mask`                 | post        | загрузить маску                                                                   |
| `/view`                        | get         | просмотреть изображение. Много параметров, см. `@routes.get("/view")` в `server.py` |
| `/view_metadata`/{folder_name} | get         | получить метаданные модели                                                        |
| `/system_stats`                | get         | получить сведения о системе (версия Python, устройства, vram и т. д.)             |
| `/prompt`                      | get         | получить текущий статус очереди и сведения о выполнении                           |
| `/prompt`                      | post        | отправить промпт в очередь                                                        |
| `/object_info`                 | get         | получить сведения обо всех типах узлов                                            |
| `/object_info/{node_class}`    | get         | получить сведения об одном типе узла                                              |
| `/history`                     | get         | получить историю очереди                                                          |
| `/history/{prompt_id}`         | get         | получить историю очереди для конкретного промпта                                  |
| `/history`                     | post        | очистить историю или удалить запись истории                                       |
| `/queue`                       | get         | получить текущее состояние очереди выполнения                                     |
| `/queue`                       | post        | управлять операциями очереди (очистить ожидающие/выполняющиеся)                   |
| `/interrupt`                   | post        | остановить текущее выполнение рабочего процесса                                   |
| `/free`                        | post        | освободить память, выгрузив указанные модели                                      |
| `/userdata`                    | get         | вывести список файлов пользовательских данных в указанном каталоге                |
| `/v2/userdata`                 | get         | расширенная версия, которая выводит файлы и каталоги в структурированном формате  |
| `/userdata/{file}`             | get         | получить конкретный файл пользовательских данных                                  |
| `/userdata/{file}`             | post        | загрузить или обновить файл пользовательских данных                               |
| `/userdata/{file}`             | delete      | удалить конкретный файл пользовательских данных                                   |
| `/userdata/{file}/move/{dest}` | post        | переместить или переименовать файл пользовательских данных                        |
| `/users`                       | get         | получить информацию о пользователях                                               |
| `/users`                       | post        | создать нового пользователя (только в многопользовательском режиме)               |

### Обмен данными через WebSocket

Эндпоинт `/ws` обеспечивает двусторонний обмен данными между клиентом и сервером в реальном времени. Он используется для:
- получения обновлений хода выполнения
- получения статуса выполнения узлов в реальном времени
- получения сообщений об ошибках и отладочной информации
- оповещения об изменениях статуса очереди в реальном времени

Соединение WebSocket отправляет сообщения JSON различных типов, например:
- `status`: обновления общего статуса системы
- `execution_start`: когда начинается выполнение промпта
- `execution_cached`: когда используются кэшированные результаты
- `executing`: обновления во время выполнения узлов
- `progress`: обновления хода выполнения длительных операций
- `executed`: когда узел завершает выполнение

### Пользовательские маршруты

Если вы хотите отправить сообщение с клиента на сервер во время выполнения, вам нужно добавить пользовательский маршрут на сервер.
Для всего сложного придётся обратиться к [документации фреймворка aiohttp](https://docs.aiohttp.org/), но в большинстве случаев можно обойтись так:

```Python
from server import PromptServer
from aiohttp import web
routes = PromptServer.instance.routes
@routes.post('/my_new_path')
async def my_function(request):
    the_data = await request.post()
    # теперь the_data содержит словарь отправленных значений
    MyClass.handle_my_message(the_data)
    return web.json_response({})
```

<Tip>Если вы точно не знаете, что делаете, не пытайтесь определять `my_function` внутри класса.
Декоратор `@routes.post` делает много работы! Вместо этого определите функцию, как показано выше,
а затем вызовите метод класса.</Tip>

<Tip>Вы также можете определить `@routes.get`, если ничего не изменяете.</Tip>

Клиент может использовать этот новый маршрут, отправив объект `FormData` с помощью примерно такого кода;
в результате в приведённом выше коде `the_data` будет содержать ключи `message` и `node_id`:

```Javascript
import { api } from "../../scripts/api.js";
function send_message(node_id, message) {
    const body = new FormData();
    body.append('message',message);
    body.append('node_id', node_id);
    api.fetchApi("/my_new_path", { method: "POST", body, });
}
```
