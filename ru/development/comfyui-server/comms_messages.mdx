## Сообщения

Во время выполнения (или при изменении состояния очереди) `PromptExecutor` отправляет сообщения клиенту через метод `send_sync` объекта `PromptServer`.

Эти сообщения принимает обработчик событий сокета, определённый в `api.js` (на момент написания примерно на строке 90, или найдите `this.socket.addEventListener`), который создаёт объект `CustomEvent` для любого известного типа сообщений и передаёт его всем зарегистрированным обработчикам.

Расширение может зарегистрироваться для получения событий (обычно это делается в функции `setup()`), следуя стандартному приёму JavaScript:

```Javascript
api.addEventListener(message_type, messageHandler);
```

Если `message_type` не входит во встроенные типы, он автоматически добавляется в список известных типов сообщений. Функция `messageHandler` будет вызвана с объектом `CustomEvent`, который расширяет событие, созданное сокетом, добавляя свойство `.detail`, представляющее собой словарь данных, отправленных сервером. Поэтому использование обычно выглядит примерно так:

```Javascript
function messageHandler(event) {
    if (event.detail.node == aNodeIdThatIsInteresting) {
        // сделать что-то с event.detail.other_things
    }
}
```

### Встроенные типы сообщений

Во время выполнения (или при изменении состояния очереди) `PromptExecutor` отправляет клиенту следующие сообщения через метод `send_sync` объекта `PromptServer`. Расширение может зарегистрироваться как обработчик любого из них.

| событие                 | когда                                                                      | данные                                                                                                  |
| ----------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `execution_start`       | Когда промпт вот-вот начнёт выполняться                                    | `prompt_id`                                                                                             |
| `execution_error`       | Когда во время выполнения возникает ошибка                                  | `prompt_id` и дополнительная информация                                                                 |
| `execution_interrupted` | Когда выполнение останавливается узлом, вызывающим `InterruptProcessingException` | `prompt_id`, `node_id`, `node_type` и `executed` (список выполненных узлов)                             |
| `execution_cached`      | В начале выполнения                                                        | `prompt_id`, `nodes` (список узлов, которые пропускаются, потому что можно использовать их кэшированные выходы) |
| `execution_success`     | Когда все узлы из промпта успешно выполнены                                | `prompt_id`, `timestamp`                                                                                |
| `executing`             | Когда новый узел вот-вот начнёт выполняться                                | `node` (id узла или `None`, чтобы обозначить завершение), `prompt_id`                                   |
| `executed`              | Когда узел возвращает элемент ui                                           | `node` (id узла), `prompt_id`, `output`                                                                 |
| `progress`              | Во время выполнения узла, реализующего требуемый хук                        | `node` (id узла), `prompt_id`, `value`, `max`                                                           |
| `status`                | При изменении состояния очереди                                            | `exec_info`, словарь с `queue_remaining`, количеством записей в очереди                                 |

### Использование executed

Несмотря на название, сообщение `executed` отправляется не при каждом завершении выполнения узла (в отличие от `executing`), а только когда узел возвращает обновление ui.

Для этого главная функция должна вернуть словарь вместо кортежа:

```python
# в конце моего главного метода
        return { "ui":a_new_dictionary, "result": the_tuple_of_output_values }
```

`a_new_dictionary` затем будет отправлен как значение `output` в сообщении `executed`. Ключ `result` можно опустить, если у узла нет выходов (см., например, код `SaveImage` в `nodes.py`).

### Пользовательские типы сообщений

Как указано выше, на стороне клиента пользовательский тип сообщений можно добавить, просто зарегистрировавшись как обработчик уникального имени типа сообщений.

```Javascript
api.addEventListener("my.custom.message", messageHandler);
```

На сервере код столь же прост:

```Python
from server import PromptServer
# затем в вашей основной функции выполнения (обычно)
        PromptServer.instance.send_sync("my.custom.message", a_dictionary)
```

#### Получение node\_id

Большинство встроенных сообщений содержат id текущего узла в значении `node`. Вероятно, вы захотите сделать то же самое.

node\_id доступен на стороне сервера через скрытый вход, который получается с помощью ключа `hidden` в словаре `INPUT_TYPES`:

```Python
    @classmethod    
    def INPUT_TYPES(s):
        return {"required" : { }, # какими бы ни были ваши обязательные входы 
                "hidden": { "node_id": "UNIQUE_ID" } } # Добавьте скрытый ключ

    def my_main_function(self, required_inputs, node_id):
        # сделать что-то
        PromptServer.instance.send_sync("my.custom.message", {"node": node_id, "other_things": etc})
```
