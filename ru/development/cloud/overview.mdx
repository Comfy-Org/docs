<Warning>
  **Устаревший:** Cloud API v1 объявлен устаревшим в пользу [Comfy API v2](/api-reference/v2/overview). Он остаётся доступным для существующих интеграций и для возможностей Cloud, которые v2 пока не предоставляет, но эндпоинты и поведение могут измениться без предупреждения.
</Warning>

Cloud API v1 предоставляет программный доступ к [Comfy Cloud](/ru/development/deploy/cloud), управляемому сервису Comfy для запуска рабочих процессов в облачной инфраструктуре.

Comfy Cloud является приложением с сохранением состояния. С вашим аккаунтом связано состояние, которое сохраняется между задачами: кредиты и уровень подписки, загруженные ассеты и сгенерированные выходы, очередь заданий, а также набор установленных моделей и узлов. API v1 является интерфейсом всего приложения целиком, поэтому он содержит функциональность, не поддерживаемую в портативном [Comfy API v2](/api-reference/v2/overview), например, управление очередью, просмотр моделей, определения узлов и эндпоинты аккаунта. Используйте v2 (или SDK, которые его оборачивают), чтобы отправлять рабочие процессы и получать результаты способом, который также работает с развёртываниями Comfy API и самостоятельно размещённым ComfyUI. Используйте v1 для специфичных для Cloud возможностей, связанных с этой средой.

Чтобы запускать рабочие процессы, начните с [развёртывания в Comfy Cloud](/ru/development/deploy/cloud) и [Comfy SDK](/ru/development/api-development/sdks). Кредиты и ограничения параллелизма описаны в разделе [Использование и лимиты](/ru/development/deploy/cloud-usage); готовые к запуску примеры v1 приведены в [Справочнике Cloud API](/ru/development/cloud/api-reference). Эта страница описывает функциональность, специфичную для v1: аутентификацию и эндпоинты, которые не предоставляет v2.

<Note>
  **Требуется подписка:** доступ к API требует платной подписки Comfy Cloud; бесплатный тариф его не включает. См. [тарифные планы](https://www.comfy.org/cloud/pricing?utm_source=docs&utm_campaign=cloud-api).
</Note>

## Base URL

```
https://cloud.comfy.org
```

## Аутентификация

Все запросы версии v1 требуют API-ключ, передаваемый в заголовке `X-API-Key`:

```bash
curl -X GET "https://cloud.comfy.org/api/user" \
  -H "X-API-Key: $COMFY_CLOUD_API_KEY"
```

Инструкции по созданию ключей и управлению ими приведены в разделе [Получение API-ключа](/ru/development/api-development/getting-an-api-key). При неверном или отсутствующем ключе возвращается `401`. При ключе, привязанном к неактивной подписке, возвращается `429`.

Тот же ключ используется для [Партнёрских узлов](/ru/tutorials/partner-nodes/overview). При работе по HTTP вы передаёте его ещё раз в `extra_data.api_key_comfy_org`; примеры см. в разделе [Использование партнёрских узлов](/ru/development/cloud/api-reference#использование-партнёрских-узлов).

## Что пока не покрывают SDK

SDK покрывают запуск рабочего процесса, получение результатов и отмену задачи. Остальная часть функционала Cloud доступна только по HTTP, поэтому вызывайте эти эндпоинты напрямую, даже если используете SDK для выполнения.

| Возможность | Эндпоинт | Ссылка |
|---|---|---|
| Статус очереди, выполняемые и ожидающие задания | `GET /api/queue` | [Управление очередью](/ru/development/cloud/api-reference#управление-очередью) |
| Прервать текущее выполнение | `POST /api/interrupt` | [Управление очередью](/ru/development/cloud/api-reference#управление-очередью) |
| Определения узлов и спецификации входов | `GET /api/object_info` | [Информация об объектах](/ru/development/cloud/api-reference#информация-об-объектах) |
| Просмотреть доступные модели | Эндпоинты моделей | [Спецификация OpenAPI](/ru/development/cloud/openapi) |
| Информация об аккаунте и пользователе | `GET /api/user` | [Спецификация OpenAPI](/ru/development/cloud/openapi) |
| Загрузка масок, ссылающихся на существующее изображение | `POST /api/upload/mask` | [Загрузка входов](/ru/development/cloud/api-reference#загрузка-входов) |

Отмена задачи поддерживается обоими способами: SDK отменяют задачу, для которой у вас есть дескриптор, а `POST /api/queue` отменяет по ID.

## Обработка ошибок

REST-эндпоинты возвращают стандартные HTTP-коды состояния:

| Статус | Описание |
|--------|-------------|
| `400` | Некорректный запрос (неверный рабочий процесс, отсутствуют поля) |
| `401` | Несанкционированный доступ (недействительный или отсутствующий API-ключ) |
| `402` | Недостаточно кредитов |
| `429` | Подписка неактивна |
| `500` | Ошибка сервера |

Вместо этого SDK вызывают типизированные исключения, включая `Unauthorized`, `InvalidWorkflow`, `InsufficientCredits`, `QueueFull` и `JobFailed`, все они наследуются от `ComfyError`.

Сбои выполнения отличаются от HTTP-ошибок. См. раздел [Обработка ошибок](/ru/development/cloud/api-reference#обработка-ошибок) о значениях `exception_type`, передаваемых во время выполнения.
