## Быстрый старт

Создайте ключ в [вашем рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. Фрагменты на Python и TypeScript используют Comfy SDK (`pip install comfy-sdk` и `npm install @comfyorg/sdk`); фрагмент cURL представляет собой тот же вызов через обычный HTTP.

**Model ID:** `elevenlabs/eleven_sfx_v3`

**Endpoint:** `POST https://api.comfy.org/v2/models/elevenlabs/eleven_sfx_v3`

То же тело запроса, отправленное на `POST https://api.comfy.org/v2/models/elevenlabs/eleven_sfx_v3/requests`. Router отвечает `201` с `request_id`, как только запуск принят, а результат забирается, когда он готов, из этого процесса или из другого. Страница [Доставка через очередь](/ru/development/comfy-router/queue) описывает статус, отмену и получение результата.

<CodeGroup>
```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменной окружения.
# Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его при автоматических повторах.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "elevenlabs/eleven_sfx_v3",
            {
                "duration_seconds": 5,
                "text": "A distant rumble of thunder rolling across a valley.",
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивает сервер, пока запрос не завершится, выжидая Retry-After, который указывает сервер.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственный payload провайдера, то же значение, что возвращает models.run().
        # Запрос, завершившийся ошибкой или отменённый, вызывает здесь типизированную ошибку Router.
        result = await handle.get()

    print(result)

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Читает COMFY_API_KEY из переменной окружения.
// Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его при автоматических повторах.
const handle = await comfy.models.submit("elevenlabs/eleven_sfx_v3", {
  duration_seconds: 5,
  text: "A distant rumble of thunder rolling across a valley.",
});
console.log("requestId:", handle.requestId); // вместе с ID модели это всё, что нужно другому процессу

// Опрашивает сервер, пока запрос не завершится, выжидая Retry-After, который указывает сервер.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// Тот же результат, который возвращает models.run(). Запрос, завершившийся ошибкой или отменённый, отклоняется здесь.
const result = await handle.get();

console.log(result.data);
```

```bash cURL
# 1. Отправка. Router отвечает 201 с request_id, status_url, response_url и cancel_url.
curl https://api.comfy.org/v2/models/elevenlabs/eleven_sfx_v3/requests \
  -H "X-API-Key: $COMFY_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d "{\"duration_seconds\": 5, \"text\": \"A distant rumble of thunder rolling across a valley.\"}"

# 2. Опрос, пока статус не станет COMPLETED, с ожиданием Retry-After секунд из каждого ответа.
REQUEST_ID="<request_id from the 201 body>"
curl -i https://api.comfy.org/v2/models/elevenlabs/eleven_sfx_v3/requests/$REQUEST_ID/status \
  -H "X-API-Key: $COMFY_API_KEY"

# 3. Получение. 200 с собственным выводом модели, 202 с телом статуса, пока запрос ещё выполняется.
curl https://api.comfy.org/v2/models/elevenlabs/eleven_sfx_v3/requests/$REQUEST_ID \
  -H "X-API-Key: $COMFY_API_KEY"
```

## Схема

### Входы

<ParamField body="duration_seconds" type="number" required>
  Длительность генерируемого звука в секундах.
Должна быть не менее 0.5 и не более 30.
ОБЯЗАТЕЛЬНО на этом маршруте: в отличие от исходного API ElevenLabs,
который подбирает оптимальную длительность, когда поле равно null,
этот маршрут отклоняет запрос, в котором оно опущено, с ошибкой 400 «Duration is required».
Поле остаётся nullable только для того, чтобы явный null оставался корректным
документом; такой запрос всё равно отклоняется.
Именно это значение является величиной, по которой тарифицируется запрос.

  Диапазон: от `0.5` до `30`

  Формат: `double`
</ParamField>

<ParamField body="loop" type="boolean" default="false">
  Создавать ли звуковой эффект, который зацикливается плавно.
</ParamField>

<ParamField body="model_id" type="string">
  Идентификатор модели, который используется для генерации звука. Этот маршрут принимает
только Comfy-id из перечисления в запросе v1; любое другое значение
отклоняется с ошибкой 400 до того, как запрос достигнет ElevenLabs. Каждое из них
является id Comfy для модели ElevenLabs (модель 'eleven_sfx_v2' это та,
которую ElevenLabs называет 'eleven_text_to_sound_v2'). Прокси переписывает
передаваемое тело в написание вендора, которого требует собственное перечисление
ElevenLabs (оно отклоняет 'eleven_sfx_v2' с ошибкой 422), поэтому вызывающая сторона
никогда не отправляет id вендора. Его НЕТ в списке
`required` этой схемы, потому что Comfy Router заполняет его из
сегмента пути `{model}` в /v2/models/elevenlabs/\{model}, поэтому вызывающая сторона Router
его опускает.
</ParamField>

<ParamField body="prompt_influence" type="number">
  Более высокое влияние промпта заставляет генерацию точнее следовать промпту,
а также делает генерации менее вариативными.
Должно быть значением от 0 до 1. По умолчанию 0.3.

  Диапазон: от `0` до `1`

  Формат: `double`
</ParamField>

<ParamField body="text" type="string" required>
  Текст, который будет преобразован в звуковой эффект.
</ParamField>

Создано из схемы, которую Router отдаёт по адресу `GET /v2/models/elevenlabs/eleven_sfx_v3/openapi.json`, того же документа, по которому он проверяет вызов до того, как запрос достигнет провайдера.

### Выходы

<ResponseField name="*/*" type="string (binary)">
  Необработанные байты аудио. Content-Type и кодировка соответствуют запрошенному output_format и передаются от ElevenLabs. Пример является заполнителем для бинарного тела, а не JSON или base64.
</ResponseField>

## Примеры

### Входы

```json
{
  "duration_seconds": 5,
  "text": "A distant rumble of thunder rolling across a valley."
}
```

### Выходы

Двоичное тело: необработанные байты, а не JSON-документ, возвращается как `*/*`, поэтому примера JSON нет. `Content-Type` ответа и кодировка соответствуют запросу, как описано в схеме выходов выше.
