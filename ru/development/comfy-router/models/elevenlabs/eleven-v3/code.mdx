Справочник по API для `elevenlabs/eleven_v3`, предоставляемый Comfy Router от Elevenlabs.

**Вход:** текст · **Выход:** аудио

## Быстрый старт

Создайте ключ в [своём рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. Фрагменты для Python и TypeScript используют Comfy SDK (`pip install comfy-sdk` и `npm install @comfyorg/sdk`); фрагмент cURL это тот же вызов по «сырому» HTTP.

**ID модели:** `elevenlabs/eleven_v3`

**Эндпоинт:** `POST https://api.comfy.org/v2/models/elevenlabs/eleven_v3`

То же тело запроса, отправленное на `POST https://api.comfy.org/v2/models/elevenlabs/eleven_v3/requests`. Router отвечает `201` с `request_id`, как только запуск принят, а результат забирается, когда он готов, из этого процесса или из другого. [Доставка через очередь](/ru/development/comfy-router/queue) описывает статус, отмену и получение результата.

<CodeGroup>
```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменной окружения.
# Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его для автоматических повторов.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "elevenlabs/eleven_v3",
            {
                "inputs": [
                    {
                        "text": "Hello from Comfy Router.",
                        "voice_id": "21m00Tcm4TlvDq8ikWAM",
                    },
                ],
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивайте, пока запрос не завершится, выдерживая Retry-After, который называет сервер.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственный payload провайдера, то же значение, что возвращает models.run().
        # Запрос, который завершился ошибкой или был отменён, вызывает здесь типизированную ошибку Router.
        result = await handle.get()

    print(result)

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Читает COMFY_API_KEY из переменной окружения.
// Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его для автоматических повторов.
const handle = await comfy.models.submit("elevenlabs/eleven_v3", {
  inputs: [
    {
      text: "Hello from Comfy Router.",
      voice_id: "21m00Tcm4TlvDq8ikWAM",
    },
  ],
});
console.log("requestId:", handle.requestId); // вместе с ID модели это всё, что нужно другому процессу

// Опрашивайте, пока запрос не завершится, выдерживая Retry-After, который называет сервер.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// Тот же результат, что возвращает models.run(). Запрос, который завершился ошибкой или был отменён, отклоняется здесь.
const result = await handle.get();

console.log(result.data);
```

```bash cURL
# 1. Отправка. Router отвечает 201 с request_id, status_url, response_url и cancel_url.
curl https://api.comfy.org/v2/models/elevenlabs/eleven_v3/requests \
  -H "X-API-Key: $COMFY_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d "{\"inputs\": [{\"text\":\"Hello from Comfy Router.\",\"voice_id\":\"21m00Tcm4TlvDq8ikWAM\"}]}"

# 2. Опрашивайте, пока статус не станет COMPLETED, выдерживая Retry-After секунд, указанные в каждом ответе.
REQUEST_ID="<request_id from the 201 body>"
curl -i https://api.comfy.org/v2/models/elevenlabs/eleven_v3/requests/$REQUEST_ID/status \
  -H "X-API-Key: $COMFY_API_KEY"

# 3. Получение. 200 с собственным выводом модели, 202 с телом статуса, пока запрос ещё выполняется.
curl https://api.comfy.org/v2/models/elevenlabs/eleven_v3/requests/$REQUEST_ID \
  -H "X-API-Key: $COMFY_API_KEY"
```

## Схема

### Входы

<ParamField body="apply_text_normalization" type="string" default="&quot;auto&quot;">
  Управляет нормализацией текста с помощью трёх режимов:
'auto' — система сама решает, применять ли нормализацию текста
'on' — нормализация текста применяется всегда
'off' — нормализация текста пропускается

  Возможные значения: `auto`, `on`, `off`
</ParamField>

<ParamField body="inputs" type="object[]" required>
  Список входов диалога, каждый из которых содержит текст и ID голоса, которые будут преобразованы в речь.
Максимальное количество уникальных ID голосов — 10.
</ParamField>

<ParamField body="inputs[].text" type="string" required>
  Текст, который нужно преобразовать в речь.
</ParamField>

<ParamField body="inputs[].voice_id" type="string" required>
  ID голоса, используемого для генерации.
</ParamField>

<ParamField body="language_code" type="string">
  Код языка (ISO 639-1), используемый для задания языка модели и нормализации текста.
Если модель не поддерживает указанный код языка, будет возвращена ошибка.
</ParamField>

<ParamField body="model_id" type="string">
  Идентификатор используемой модели. Этот маршрут принимает
'eleven_v3', 'eleven_v4' и 'eleven_v4_turbo' и ничего больше;
любое другое значение отклоняется с кодом 400 до того, как запрос
дойдёт до ElevenLabs.
Рекомендация ElevenLabs запрашивать GET /v1/models для получения
доступного набора НЕ описывает этот маршрут, который обслуживает только
эти модели.
Поле НЕ входит в список `required` этой схемы, потому что Comfy Router
заполняет его из сегмента пути `{model}` в
/v2/models/elevenlabs/\{model}, поэтому вызывающая сторона Router его опускает.
</ParamField>

<ParamField body="pronunciation_dictionary_locators" type="object[]">
  Список локаторов словарей произношения (id, version_id), которые нужно применить к тексту.
Они применяются по порядку. На один запрос допускается до 3 локаторов.
</ParamField>

<ParamField body="pronunciation_dictionary_locators[].pronunciation_dictionary_id" type="string" required>
  ID словаря произношения
</ParamField>

<ParamField body="pronunciation_dictionary_locators[].version_id" type="string" required>
  ID версии словаря произношения
</ParamField>

<ParamField body="seed" type="integer">
  Если указано, система постарается выполнить сэмплирование детерминированно.
Повторные запросы с одинаковыми seed и параметрами должны возвращать одинаковый результат.
Должно быть целым числом от 0 до 4294967295.

  Диапазон: от `0` до `4294967295`
</ParamField>

<ParamField body="settings" type="object">
  Настройки, управляющие генерацией диалога
</ParamField>

<ParamField body="settings.stability" type="number" default="0.5">
  Определяет, насколько стабилен голос и какова случайность между генерациями.
Более низкие значения дают голосу более широкий эмоциональный диапазон.
Более высокие значения могут привести к монотонному голосу с ограниченной эмоциональностью.

  Формат: `double`
</ParamField>

Сгенерировано из схемы, которую Router отдаёт по адресу `GET /v2/models/elevenlabs/eleven_v3/openapi.json`, — того же документа, по которому он проверяет вызов, прежде чем запрос дойдёт до провайдера.

### Выходы

<ResponseField name="*/*" type="string (binary)">
  Необработанные байты аудио. Content-Type и кодировка соответствуют запрошенному output_format и передаются от ElevenLabs. Пример — это заполнитель для бинарного тела, а не JSON или base64.
</ResponseField>
