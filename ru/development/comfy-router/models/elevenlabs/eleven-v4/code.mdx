Ссылка на API для `elevenlabs/eleven_v4`, предоставляемого Comfy Router от Elevenlabs.

**Вход:** текст · **Выход:** аудио

## Быстрый старт

Создайте ключ в [вашем рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. Фрагменты на Python и TypeScript используют SDK Comfy (`pip install comfy-sdk` и `npm install @comfyorg/sdk`); фрагмент на cURL выполняет тот же вызов напрямую по HTTP.

**ID модели:** `elevenlabs/eleven_v4`

**Эндпоинт:** `POST https://api.comfy.org/v2/models/elevenlabs/eleven_v4`

То же тело, отправленное на `POST https://api.comfy.org/v2/models/elevenlabs/eleven_v4/requests`. Router отвечает `201` с `request_id`, как только запуск принят, а результат забирается, когда он готов, из этого или другого процесса. [Доставка через очередь](/ru/development/comfy-router/queue) описывает статус, отмену и получение результата.

<CodeGroup>
```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменных окружения.
# Каждый вызов submit() создаёт свой Idempotency-Key и переиспользует его при автоматических повторах.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "elevenlabs/eleven_v4",
            {
                "inputs": [
                    {
                        "text": "Hello from Comfy Router.",
                        "voice_id": "21m00Tcm4TlvDq8ikWAM",
                    },
                ],
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивайте, пока запрос не завершится, выдерживая Retry-After, который указывает сервер.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственный payload провайдера, то же значение, что возвращает models.run().
        # Запрос, который завершился ошибкой или был отменён, вызывает здесь типизированную ошибку Router.
        result = await handle.get()

    print(result)

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Читает COMFY_API_KEY из переменных окружения.
// Каждый вызов submit() создаёт свой Idempotency-Key и переиспользует его при автоматических повторах.
const handle = await comfy.models.submit("elevenlabs/eleven_v4", {
  inputs: [
    {
      text: "Hello from Comfy Router.",
      voice_id: "21m00Tcm4TlvDq8ikWAM",
    },
  ],
});
console.log("requestId:", handle.requestId); // вместе с ID модели это всё, что нужно другому процессу

// Опрашивайте, пока запрос не завершится, выдерживая Retry-After, который указывает сервер.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// Тот же результат, что возвращает models.run(). Запрос, который завершился ошибкой или был отменён, отклоняется здесь.
const result = await handle.get();

console.log(result.data);
```

```bash cURL
# 1. Отправка. Router отвечает 201 с request_id, status_url, response_url и cancel_url.
curl https://api.comfy.org/v2/models/elevenlabs/eleven_v4/requests \
  -H "X-API-Key: $COMFY_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d "{\"inputs\": [{\"text\":\"Hello from Comfy Router.\",\"voice_id\":\"21m00Tcm4TlvDq8ikWAM\"}]}"

# 2. Опрашивайте, пока status не станет COMPLETED, выдерживая Retry-After секунд, указанные в каждом ответе.
REQUEST_ID="<request_id from the 201 body>"
curl -i https://api.comfy.org/v2/models/elevenlabs/eleven_v4/requests/$REQUEST_ID/status \
  -H "X-API-Key: $COMFY_API_KEY"

# 3. Получение. 200 с нативным выводом модели, 202 с телом статуса, пока запрос ещё выполняется.
curl https://api.comfy.org/v2/models/elevenlabs/eleven_v4/requests/$REQUEST_ID \
  -H "X-API-Key: $COMFY_API_KEY"
```

## Схема

### Входы

<ParamField body="apply_text_normalization" type="string" default="&quot;auto&quot;">
  Управляет нормализацией текста с помощью трёх режимов:
'auto' - система автоматически решает, применять ли нормализацию текста
'on' - нормализация текста применяется всегда
'off' - нормализация текста пропускается

  Возможные значения: `auto`, `on`, `off`
</ParamField>

<ParamField body="inputs" type="object[]" required>
  Список входов диалога, каждый из которых содержит текст и ID голоса, который будет преобразован в речь.
Максимальное число уникальных ID голосов: 10.
</ParamField>

<ParamField body="inputs[].text" type="string" required>
  Текст, который будет преобразован в речь.
</ParamField>

<ParamField body="inputs[].voice_id" type="string" required>
  ID голоса, который будет использоваться для генерации.
</ParamField>

<ParamField body="language_code" type="string">
  Код языка (ISO 639-1), используемый, чтобы задать язык для модели и нормализации текста.
Если модель не поддерживает указанный код языка, будет возвращена ошибка.
</ParamField>

<ParamField body="model_id" type="string">
  Идентификатор модели, которая будет использоваться. Этот маршрут принимает
'eleven_v3', 'eleven_v4' и 'eleven_v4_turbo' и ничего кроме них;
любое другое значение отклоняется с кодом 400 до того, как запрос
достигнет ElevenLabs.
Рекомендация ElevenLabs запрашивать GET /v1/models, чтобы получить
доступный набор, НЕ описывает этот маршрут, который обслуживает только эти
модели.
Он НЕ входит в список `required` этой схемы, поскольку Comfy Router
заполняет его из сегмента пути `{model}` в
/v2/models/elevenlabs/\{model}, поэтому вызывающая сторона Router его опускает.
</ParamField>

<ParamField body="pronunciation_dictionary_locators" type="object[]">
  Список локаторов словарей произношения (id, version_id), которые нужно применить к тексту.
Они применяются по порядку. В одном запросе можно использовать до 3 локаторов.
</ParamField>

<ParamField body="pronunciation_dictionary_locators[].pronunciation_dictionary_id" type="string" required>
  ID словаря произношения
</ParamField>

<ParamField body="pronunciation_dictionary_locators[].version_id" type="string" required>
  ID версии словаря произношения
</ParamField>

<ParamField body="seed" type="integer">
  Если указан, система приложит максимум усилий для детерминированной выборки.
Повторные запросы с тем же seed и параметрами должны возвращать одинаковый результат.
Должно быть целым числом от 0 до 4294967295.

  Диапазон: `0` до `4294967295`
</ParamField>

<ParamField body="settings" type="object">
  Настройки, управляющие генерацией диалога
</ParamField>

<ParamField body="settings.stability" type="number" default="0.5">
  Определяет, насколько стабилен голос и какова случайность между генерациями.
Более низкие значения дают голосу более широкий эмоциональный диапазон.
Более высокие значения могут привести к монотонному голосу с ограниченной эмоциональностью.

  Формат: `double`
</ParamField>

Сгенерировано из схемы, которую Router отдаёт по адресу `GET /v2/models/elevenlabs/eleven_v4/openapi.json`, того же документа, по которому он проверяет вызов, прежде чем запрос достигнет провайдера.

### Выходы

<ResponseField name="*/*" type="string (binary)">
  Необработанные аудиобайты. Content-Type и кодировка соответствуют запрошенному output_format и передаются из ElevenLabs. Пример является заполнителем для бинарного тела, а не JSON или base64.
</ResponseField>
