Ссылка на API для `krea/krea-3`, предоставляемого Comfy Router от Krea.

**Вход:** текст, изображение · **Выход:** изображение

## Быстрый старт

Создайте ключ в [вашем рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. Фрагменты для Python и TypeScript используют Comfy SDK (`pip install comfy-sdk` и `npm install @comfyorg/sdk`); фрагмент cURL выполняет тот же вызов напрямую по HTTP.

**ID модели:** `krea/krea-3`

**Эндпоинт:** `POST https://api.comfy.org/v2/models/krea/krea-3`

То же тело запроса, отправленное на `POST https://api.comfy.org/v2/models/krea/krea-3/requests`. Router отвечает `201` с `request_id`, как только запуск принят, а результат забирается, когда он готов, из этого или другого процесса. [Доставка через очередь](/ru/development/comfy-router/queue) описывает статус, отмену и получение результата.

<CodeGroup>
```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменной окружения.
# Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его при автоматических повторах.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "krea/krea-3",
            {
                "prompt": "A ceramic coffee mug on a clean studio background",
                "resolution": "1k",
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивайте, пока запрос не завершится, выжидая Retry-After, указанный сервером.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственная полезная нагрузка провайдера, то же значение, что возвращает models.run().
        # Запрос, который завершился ошибкой или был отменён, вызывает здесь типизированную ошибку Router.
        result = await handle.get()

    print(result)

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Читает COMFY_API_KEY из переменной окружения.
// Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его при автоматических повторах.
const handle = await comfy.models.submit("krea/krea-3", {
  prompt: "A ceramic coffee mug on a clean studio background",
  resolution: "1k",
});
console.log("requestId:", handle.requestId); // вместе с ID модели это всё, что нужно другому процессу

// Опрашивайте, пока запрос не завершится, выжидая Retry-After, указанный сервером.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// Тот же результат, что возвращает models.run(). Запрос, который завершился ошибкой или был отменён, отклоняется здесь.
const result = await handle.get();

console.log(result.data);
```

## Схема

### Входы

<ParamField body="aspect_ratio" type="string">
  1:1, 4:5, 3:4, 2:3, 9:16, 5:4, 4:3, 3:2, 16:9 или 21:9. Используйте вместе с resolution; опустите для автоматического кадрирования.
</ParamField>

<ParamField body="image_urls" type="string[]">
  URL-адреса входных изображений, до 8. Более 8 элементов отклоняется ещё до любой загрузки (400 на /proxy/krea; проверка схемы Comfy Router сначала отвечает 422). image_url, возвращённый при загрузке изображения в POST /proxy/krea/assets (поле multipart-формы `file`), принимается всегда. Принимаются ли другие публичные https URL, зависит от окружения: там, где они не принимаются, любая ссылка, которая не является https URL на хосте app-uploads.krea.ai, отклоняется с 400 и сообщением 'image_urls must be image_url values returned by POST /proxy/krea/assets', поэтому вместо этого загрузите изображение; там, где они принимаются, любой публичный https URL изображения принимается, а URL, который сформирован неверно или не является https, отклоняется с 400 (URL, порт которого числовой, но вне диапазона, этой проверкой не отлавливается и может вместо этого завершиться ошибкой 502). В этом случае запрос, любой элемент image_urls которого не является ссылкой app-uploads.krea.ai (публичный https URL или base64 data: URI там, где они принимаются), также отклоняется с 400 ещё до любой загрузки, если только всё тело запроса не отправлено как application/json, а не multipart, является корректным UTF-8, имеет размер не более 25100288 байт и содержит только поля, объявленные этой схемой. Для корректно сформированного https URL в этом случае ссылка, которую вызывающая сторона может исправить, отклоняется с 400 с указанием её хоста: её хост не разрешается или не является публично доступным при проверке перед загрузкой, она перенаправляет больше разрешённого числа раз, на URL, который не является https, или на хост, который не является публично доступным, она возвращает 4xx, отличный от 408 или 429, она не является изображением, она является изображением в формате, который невозможно прочитать, её заголовок размера изображения не находится в первых 2 MiB, или ответ без объявленной длины или с chunked-кодированием заканчивается раньше её заголовка размера изображения. Любая другая ошибка при её загрузке завершается ошибкой 502 на POST /proxy/krea (Comfy Router отвечает на неё 500 internal_error): кратковременный сбой DNS, TLS или соединения, тайм-аут, статус 408, 429, 5xx или другой не-200 от источника, или хост, который прошёл ту проверку, но не разрешается или не является публично доступным, когда загрузка устанавливает соединение. Некоторые из них проходят при повторе (ошибка резолвера, тайм-аут, разорванное соединение, источник, отвечающий 5xx, 408 или 429, или хост, чей DNS-ответ переключается на непубличный адрес между проверкой хоста и соединением, что при повторе может как увенчаться успехом, так и дать 400 для непубличного хоста); другие завершаются одинаково каждый раз, например TLS-сертификат, которому загрузка не доверяет (самоподписанный, просроченный или для неверного имени хоста), или источник, отвечающий 2xx, отличным от 200, или 3xx, за которым загрузка не следует (таким как 204, 206, 300, 304 или 305, или 301, 302, 303, 307 или 308 без Location), поэтому если повтор завершается так же, загрузите изображение вместо этого. Запрос, поставленный в очередь через Comfy Router, не повторяет такую ошибку, когда любой из его image_urls не является ссылкой app-uploads.krea.ai, поэтому отправьте его повторно сами, если причина может исчезнуть. Там, где другие URL не принимаются, ссылка app-uploads.krea.ai, которая не является живой загрузкой, завершается ошибкой 5xx; там, где они принимаются, она отклоняется с 400, как и любая другая недоступная ссылка. Пока сервер ещё не определил, какой вариант действует, любой https URL, хост которого не является ссылкой app-uploads.krea.ai, публичный или нет, завершается ошибкой 503, которую безопасно повторять (запрос в очереди повторяется при ней автоматически). Ответ 400 для запроса в очереди содержит только общий detail invalid_input, поэтому он не показывает ни хост, ни приведённую выше формулировку, и очередь его не повторяет. Ответ 400 в очереди может прийти от любого поля, не только image_urls (например, неподдерживаемое разрешение или thinking_mode), поэтому сначала проверьте остальные поля. Если они корректны, загрузите каждое изображение в POST /proxy/krea/assets и отправьте повторно с этими значениями image_url и новым Idempotency-Key (или без него): повторное использование ключа с изменённым телом отклоняется с 409 invalid_input, что ничего не говорит об изображениях, а повторное использование его с тем же телом получает ответ 201 с исходным request_id и Idempotent-Replayed: true, поэтому новый запуск не начинается, а URL результата возвращает тот же 400 (URL статуса отвечает 200 с error_type invalid_input). Там, где другие публичные https URL принимаются, если эта повторная отправка тоже завершается 400, проблема в самом изображении (например, это неподдерживаемое изображение или его заголовок размера изображения не находится в первых 2 MiB). Там, где они не принимаются, то же загруженное изображение завершается ошибкой 5xx (500 internal_error на Comfy Router) вместо этого 400, и проблема по-прежнему в изображении, поэтому повторная загрузка его не поможет. Для поиска размера читаются только первые 2 MiB каждого изображения, поэтому изображение, информацию о размере которого невозможно прочитать в этом окне (например, JPEG с более чем 2 MiB встроенных метаданных или палитровый PNG, данные о прозрачности которого, а при их отсутствии начало его первого чанка данных изображения, находятся за пределами 2 MiB, например после более чем 2 MiB текстовых чанков или чанков цветового профиля), отклоняется с 400 и сообщением, что его заголовок размера изображения не находится в первых 2 MiB, независимо от того, загружено оно или нет; сохраните его заново без больших метаданных или сохраните палитровый PNG как непалитровый PNG. Отправляйте интернационализированный хост в его ASCII-форме (punycode); имя хоста с не-ASCII символами отклоняется как несуществующее. Опустите при работе в режиме текст в изображение.

<ResponseField name="result.style_id" type="string">

</ResponseField>

  В этом документе всегда `completed`: это единственный статус, который Router сообщает как успех, а словарь Krea сопоставляется без нормализации регистра.

  Возможные значения: `completed`
</ResponseField>
