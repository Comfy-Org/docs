Справочник по API для `pika/pika-2.5-text-to-video`, предоставляемый Comfy Router от Pika.

**Вход:** Текст · **Выход:** Видео

## Быстрый старт

Создайте ключ в [вашем рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. В примерах на Python и TypeScript используются SDK Comfy (`pip install comfy-sdk` и `npm install @comfyorg/sdk`); пример cURL это тот же вызов по чистому HTTP.

**ID модели:** `pika/pika-2.5-text-to-video`

**Эндпоинт:** `POST https://api.comfy.org/v2/models/pika/pika-2.5-text-to-video`

from comfy_sdk import Comfy

То же тело запроса, отправленное на `POST https://api.comfy.org/v2/models/pika/pika-2.5-text-to-video/requests`. Router отвечает `201` с `request_id`, как только запуск принят, а результат забирается, когда он готов, из этого или другого процесса. [Доставка через очередь](/ru/development/comfy-router/queue) описывает статус, отмену и получение результата.

<CodeGroup>
```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменной окружения.
# Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его при автоматических повторах.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "pika/pika-2.5-text-to-video",
            {
                "duration_s": 5,
                "prompt": "A paper boat drifting down a rain-soaked city street at dusk",
                "resolution": "720p",
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивайте, пока запрос не завершится, выжидая Retry-After, указанный сервером.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственные данные провайдера, то же значение, что возвращает models.run().
        # Запрос, который завершился ошибкой или был отменён, вызывает здесь типизированную ошибку Router.
        result = await handle.get()

    print(result)

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Читает COMFY_API_KEY из переменной окружения.
// Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его при автоматических повторах.
const handle = await comfy.models.submit("pika/pika-2.5-text-to-video", {
  duration_s: 5,
  prompt: "A paper boat drifting down a rain-soaked city street at dusk",
  resolution: "720p",
});
console.log("requestId:", handle.requestId); // вместе с ID модели это всё, что нужно другому процессу

// Опрашивайте, пока запрос не завершится, выжидая Retry-After, указанный сервером.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// Тот же результат, что возвращает models.run(). Запрос, завершившийся ошибкой или отменённый, отклоняется здесь.
const result = await handle.get();

console.log(result.data);
```

```bash cURL
# 1. Отправка. Router отвечает 201 с request_id, status_url, response_url и cancel_url.
curl https://api.comfy.org/v2/models/pika/pika-2.5-text-to-video/requests \
  -H "X-API-Key: $COMFY_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d "{\"duration_s\": 5, \"prompt\": \"A paper boat drifting down a rain-soaked city street at dusk\", \"resolution\": \"720p\"}"

# 2. Опрашивайте, пока статус не станет COMPLETED, выжидая указанные в каждом ответе секунды Retry-After.
REQUEST_ID="<request_id from the 201 body>"
curl -i https://api.comfy.org/v2/models/pika/pika-2.5-text-to-video/requests/$REQUEST_ID/status \
  -H "X-API-Key: $COMFY_API_KEY"

# 3. Получение. 200 с собственным выводом модели, 202 с телом статуса, пока запрос ещё выполняется.
curl https://api.comfy.org/v2/models/pika/pika-2.5-text-to-video/requests/$REQUEST_ID \
  -H "X-API-Key: $COMFY_API_KEY"
```

## Схема

### Входы

<ParamField body="duration_s" type="integer" default="5">
  Длина видео в секундах. Функция текст в видео создаёт только пятисекундные клипы.

  Возможные значения: `5`
</ParamField>

<ParamField body="negative_prompt" type="string">
  Текст, описывающий, чего следует избегать в видео.
</ParamField>

<ParamField body="prompt" type="string" required>
  Текстовый промпт с описанием видео для генерации.
</ParamField>

<ParamField body="resolution" type="string" default="&quot;1080p&quot;">
  Разрешение выходного видео.

  Возможные значения: `720p`, `1080p`
</ParamField>

<ParamField body="seed" type="integer">
  Seed для воспроизводимой генерации. Не указывайте его (или отправьте null), чтобы получить случайный seed.
</ParamField>

Схема сгенерирована из документа, который Router предоставляет по адресу `GET /v2/models/pika/pika-2.5-text-to-video/openapi.json`; этот же документ используется для проверки вызова перед тем, как запрос достигнет провайдера.

### Выходы

<ResponseField name="error" type="object">
  Структурированная запись ошибки Pika, устанавливаемая для задачи со статусом `failed`. Router отвечает на задачу со статусом `failed` собственным ответом об ошибке, поэтому тело, которое возвращает Router, её не содержит. Поле объявлено, потому что является частью документа задачи Pika.
</ResponseField>

<ResponseField name="error.code" type="string" required>
  Возможные значения: `invalid_input`, `content_moderation`, `provider_error`, `provider_timeout`, `provider_unavailable`, `rate_limited`, `insufficient_balance`, `membership_required`, `cycle_limit_exceeded`, `admission_suspended`, `usage_limit_exceeded`, `timed_out`, `internal`
</ResponseField>

<ResponseField name="error.message" type="string" required>
   
</ResponseField>

<ResponseField name="id" type="string" required>
  ID задачи Pika.
</ResponseField>

<ResponseField name="model_id" type="string">
  Запись каталога Pika, по которой выполнялась задача.
</ResponseField>

<ResponseField name="output" type="object">
  Медиафайлы завершённой задачи, устанавливаются, когда `status` равен `completed`. Поле `media_type` указывает, в каком поле они находятся: `image` заполняет `images`, `video` заполняет `video`, а `videos` заполняет `videos`.
</ResponseField>

<ResponseField name="output.images" type="object[]">
  Сгенерированные изображения для модели изображений.
</ResponseField>

<ResponseField name="output.images[].content_type" type="string">
  MIME-тип файла.
</ResponseField>

<ResponseField name="output.images[].height" type="integer">
  Высота в пикселях.
</ResponseField>

<ResponseField name="output.images[].url" type="string">
  URL для скачивания сгенерированного файла.
</ResponseField>

<ResponseField name="output.images[].width" type="integer">
  Ширина в пикселях.
</ResponseField>

<ResponseField name="output.media_type" type="string">
  Возможные значения: `image`, `video`, `videos`

  Сгенерированные видео, когда результатом является несколько видео.
</ResponseField>

<ResponseField name="output.videos[].content_type" type="string">
  MIME-тип файла.
</ResponseField>

<ResponseField name="output.videos[].height" type="integer">
  Высота в пикселях.

<ResponseField name="output.videos[].url" type="string">

<ResponseField name="runtime_s" type="number">
  Сколько секунд заняла генерация, от запуска до завершения. Значение приблизительное; может быть null.
</ResponseField>

<ResponseField name="status" type="string" required>
  Состояние жизненного цикла. В теле, которое возвращает Router, всегда указано `completed`; для задачи со статусом `failed` вместо этого возвращается ответ об ошибке Router.

  Возможные значения: `queued`, `running`, `completed`, `failed`
</ResponseField>

<ResponseField name="usage" type="object">
  Единицы, сообщённые провайдером для задачи. Ключи неполные: присутствуют только те единицы, которые сообщает задача.
</ResponseField>
