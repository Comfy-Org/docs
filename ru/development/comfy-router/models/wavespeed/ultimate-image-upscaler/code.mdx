## Быстрый старт

Создайте ключ в [вашем рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. То же тело запроса, отправленное на `POST https://api.comfy.org/v2/models/wavespeed/ultimate-image-upscaler/requests`. Router отвечает `201` с `request_id`, как только запуск принят, а результат забирается, когда он готов, из этого процесса или из другого. Раздел [Доставка через очередь](/ru/development/comfy-router/queue) описывает статус, отмену и получение результата.

<CodeGroup>
```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменной окружения.
# Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его для автоматических повторов.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wavespeed/ultimate-image-upscaler",
            {
                "image": "https://images.pexels.com/photos/346529/pexels-photo-346529.jpeg",
                "target_resolution": "4k",
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивайте, пока запрос не завершится, выжидая Retry-After, указанный сервером.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственный payload провайдера, то же значение, которое возвращает models.run().
        # Запрос, который завершился ошибкой или был отменён, вызывает здесь типизированную ошибку Router.
        result = await handle.get()

    print(result)

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Читает COMFY_API_KEY из переменной окружения.
// Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его для автоматических повторов.
const handle = await comfy.models.submit("wavespeed/ultimate-image-upscaler", {
  image: "https://images.pexels.com/photos/346529/pexels-photo-346529.jpeg",
  target_resolution: "4k",
});
console.log("requestId:", handle.requestId); // вместе с ID модели это всё, что нужно другому процессу

// Опрашивайте, пока запрос не завершится, выжидая Retry-After, указанный сервером.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// Тот же результат, который возвращает models.run(). Запрос, который завершился ошибкой или был отменён, отклоняется здесь.
const result = await handle.get();

console.log(result.data);
```

```bash cURL
# 1. Отправка. Router отвечает 201 с request_id, status_url, response_url и cancel_url.
curl https://api.comfy.org/v2/models/wavespeed/ultimate-image-upscaler/requests \
  -H "X-API-Key: $COMFY_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d "{\"image\": \"https://images.pexels.com/photos/346529/pexels-photo-346529.jpeg\", \"target_resolution\": \"4k\"}"

# 2. Опрашивайте, пока статус не станет COMPLETED, выжидая Retry-After секунд, указанные в каждом ответе.
REQUEST_ID="<request_id from the 201 body>"
curl -i https://api.comfy.org/v2/models/wavespeed/ultimate-image-upscaler/requests/$REQUEST_ID/status \
  -H "X-API-Key: $COMFY_API_KEY"

# 3. Получение. 200 с собственным выводом модели, 202 с телом статуса, пока запрос ещё выполняется.
curl https://api.comfy.org/v2/models/wavespeed/ultimate-image-upscaler/requests/$REQUEST_ID \
  -H "X-API-Key: $COMFY_API_KEY"
```

### Выходы

<ResponseField name="code" type="integer">
  Собственный код статуса конверта WavespeedAI, повторяющий HTTP-статус (200 в документе, который описывает эта схема). О некоторых сбоях Wavespeed сообщает здесь, а не в транспортном статусе.
</ResponseField>

<ResponseField name="data" type="object" required>
   
</ResponseField>

<ResponseField name="data.created_at" type="string">
  Отметка времени ISO-8601, когда Wavespeed создал прогноз.
</ResponseField>

<ResponseField name="data.error" type="string">
  Текстовая причина сбоя от Wavespeed, пустая строка при её отсутствии. Прогноз, который действительно завершился сбоем, приходит вызывающему Router как ошибка Comfy Router, а не как этот документ.
</ResponseField>

<ResponseField name="data.id" type="string">
  Идентификатор Wavespeed для прогноза, который Router отправил и опрашивал.
</ResponseField>

<ResponseField name="data.model" type="string">
  Идентификатор модели Wavespeed, на которой выполнялся прогноз.
</ResponseField>

<ResponseField name="data.outputs" type="string[]" required>
  Завершённая генерация. Присутствует и не пуста в документе, который возвращает Router; этот список И ЕСТЬ результат. Каждый элемент: URL к сгенерированному содержимому (MP4 для `wavespeed/flashvsr`, изображение для двух апскейлеров) или, для двух идентификаторов изображений, когда запрос задал `enable_base64_output`, сами байты в кодировке base64. Ссылки принадлежат Wavespeed и истекают.
</ResponseField>

<ResponseField name="data.status" type="string" required>
  Терминальное состояние прогноза в том виде, как его записал Wavespeed. Здесь оно не сужается до перечисления: Router пересылает значение без изменений, а классификатор опроса приводит его к нижнему регистру перед сравнением, поэтому успех может законно прийти как `completed`, `succeeded`, `success` или `done` в любом регистре.
</ResponseField>

<ResponseField name="data.timings" type="object">
  Собственные измерения времени Wavespeed.
</ResponseField>

<ResponseField name="data.timings.inference" type="integer">
  Время вывода в миллисекундах. Число Wavespeed, а не списание средств Comfy.
</ResponseField>

<ResponseField name="data.urls" type="object">
  Собственные ссылки Wavespeed для прогноза.
</ResponseField>

<ResponseField name="data.urls.get" type="string">
  URL результата прогноза, который опрашивал Router.
</ResponseField>

<ResponseField name="message" type="string">
  Сообщение о статусе конверта, например `success`.
</ResponseField>
