То же тело запроса, отправленное на `POST https://api.comfy.org/v2/models/kling/kling-long-image-4.0/requests`. Router отвечает `201` с `request_id`, как только запуск принят, а результат забирается, когда он готов, из этого процесса или из другого. [Доставка через очередь](/ru/development/comfy-router/queue) описывает статус, отмену и получение результата.

```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменных окружения.
# Каждый вызов submit() создаёт свой Idempotency-Key и переиспользует его при автоматических повторах.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "kling/kling-long-image-4.0",
            {
                "contents": [
                    {
                        "text": "A landing page for a specialty coffee roaster: hero, product showcase, roasting story and footer.",
                        "type": "prompt",
                    },
                ],
                "settings": {
                    "resolution": "1k",
                    "skill": "webpage",
                },
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивайте, пока запрос не завершится, выдерживая Retry-After, указанный сервером.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственный payload провайдера, то же значение, что возвращает models.run().
        # Запрос, который завершился ошибкой или был отменён, здесь вызывает типизированную ошибку Router.
        result = await handle.get()

    print(result)

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Читает COMFY_API_KEY из переменных окружения.
// Каждый вызов submit() создаёт свой Idempotency-Key и переиспользует его при автоматических повторах.
const handle = await comfy.models.submit("kling/kling-long-image-4.0", {
  contents: [
    {
      text: "A landing page for a specialty coffee roaster: hero, product showcase, roasting story and footer.",
      type: "prompt",
    },
  ],
  settings: {
    resolution: "1k",
    skill: "webpage",
  },
});
console.log("requestId:", handle.requestId); // вместе с ID модели это всё, что нужно другому процессу

// Опрашивайте, пока запрос не завершится, выдерживая Retry-After, указанный сервером.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// Тот же результат, что возвращает models.run(). Запрос, который завершился ошибкой или был отменён, здесь отклоняется.
const result = await handle.get();

console.log(result.data);
```

## Схема

### Входы

<ParamField body="contents" type="object[]" required>
  Промпт и до 3 референсных изображений.
</ParamField>

<ParamField body="contents[].id" type="string">
  Идентификатор референса для этого входа, используется как @id в промпте. Должен быть уникальным в пределах задачи.
</ParamField>

<ParamField body="contents[].text" type="string">
  Текстовый промпт, когда type равен "prompt". До 166 000 символов на английском или 71 000 символов на других языках. Референсные изображения указываются как @id.
</ParamField>

<ParamField body="contents[].type" type="string" required>
  Тип входа. Требуется ровно один элемент "prompt". Навык "webpage" принимает не более одного "style_refer_image" и не более одного "subject_refer_image". Навык "ecommerce" принимает от 1 до 3 элементов "refer_image" (фотографии товара). Элементы не поддерживаются.

  Возможные значения: `prompt`, `refer_image`, `style_refer_image`, `subject_refer_image`
</ParamField>

<ParamField body="contents[].url" type="string">
  URL изображения или данные Base64, когда type является референсным изображением. Изображения в форматах .jpg, .jpeg или .png размером до 30 МБ, не менее 300 px по каждой стороне, с соотношением сторон от 2:5 до 5:2.
</ParamField>

<ParamField body="options" type="object">
  Общие параметры конфигурации, например настройки водяного знака. `options.callback_url` и `options.external_task_id` не поддерживаются в Kling 4.0; Comfy Router отклоняет запрос, в котором любой из них задан внутри `options`. `callback_url` или `external_task_id` верхнего уровня не входят в эту схему и удаляются до того, как запрос достигнет Kling.
</ParamField>

<ParamField body="options.watermark_info" type="object">
  Нужно ли одновременно генерировать результаты с водяным знаком. Пользовательские водяные знаки не поддерживаются. Явно указанный null считается отсутствующим, как и в проверке /proxy для Kling 4.0 и в самом Kling.
</ParamField>

<ParamField body="options.watermark_info.enabled" type="boolean">
  true означает генерировать результат с водяным знаком, false означает не генерировать. По умолчанию false.
</ParamField>

<ParamField body="settings" type="object" required>
  Параметры вывода, такие как навык, разрешение и длина страницы.
</ParamField>

<ParamField body="settings.length" type="string">
  Длина страницы для навыка "ecommerce": одно из значений "short", "medium" или "long". По умолчанию "medium". Игнорируется для "webpage".

  Возможные значения: `short`, `medium`, `long`
</ParamField>

<ParamField body="settings.resolution" type="string">
  Разрешение вывода. Одно из значений "1k" или "2k". По умолчанию "1k".

  Возможные значения: `1k`, `2k`
</ParamField>

<ParamField body="settings.skill" type="string" required>
  Одно из значений: "webpage" (дизайн веб-страницы) или "ecommerce" (страница с подробным описанием товара для интернет-магазина). Обязательно.

  Возможные значения: `webpage`, `ecommerce`
</ParamField>

Сгенерировано из схемы, которую Router отдаёт по адресу `GET /v2/models/kling/kling-long-image-4.0/openapi.json`, того же документа, по которому он проверяет вызов до того, как запрос достигнет провайдера.
