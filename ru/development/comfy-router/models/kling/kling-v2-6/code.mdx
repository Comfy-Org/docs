Справочник по API для `kling/kling-v2-6`, предоставляемого Comfy Router от Kling.

**Вход:** изображение, текст · **Выход:** видео

## Быстрый старт

Создайте ключ в [вашем рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. Фрагменты Python и TypeScript используют Comfy SDK (`pip install comfy-sdk` и `npm install @comfyorg/sdk`); фрагмент cURL делает тот же вызов по обычному HTTP.

**ID модели:** `kling/kling-v2-6`

**Эндпоинт:** `POST https://api.comfy.org/v2/models/kling/kling-v2-6`

from comfy_sdk import Comfy

# Читает COMFY_API_KEY из переменных окружения.
# SDK автоматически создаёт ключ идемпотентности и переиспользует его для автоматических повторов.

То же тело запроса, отправленное на `POST https://api.comfy.org/v2/models/kling/kling-v2-6/requests`. Router отвечает `201` с `request_id` сразу после того, как запуск принят, а результат забирается, когда он готов, из этого процесса или из другого. [Доставка через очередь](/ru/development/comfy-router/queue) описывает статус, отмену и получение результата.

<CodeGroup>
```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменных окружения.
# Каждый вызов submit() создаёт свой Idempotency-Key и переиспользует его для автоматических повторов.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "kling/kling-v2-6",
            {
                "aspect_ratio": "16:9",
                "duration": "5",
                "mode": "std",
                "prompt": "A red fox trotting through falling snow, cinematic lighting.",
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивайте, пока запрос не завершится, выжидая Retry-After, указанный сервером.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственный payload провайдера, то же значение, что возвращает models.run().
        # Запрос, который завершился ошибкой или был отменён, вызывает здесь типизированную ошибку Router.
        result = await handle.get()

    print(result)

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Читает COMFY_API_KEY из переменных окружения.
// Каждый вызов submit() создаёт свой Idempotency-Key и переиспользует его для автоматических повторов.
const handle = await comfy.models.submit("kling/kling-v2-6", {
  aspect_ratio: "16:9",
  duration: "5",
  mode: "std",
  prompt: "A red fox trotting through falling snow, cinematic lighting.",
});
console.log("requestId:", handle.requestId); // вместе с ID модели это всё, что нужно другому процессу

// Опрашивайте, пока запрос не завершится, выжидая Retry-After, указанный сервером.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// Тот же результат, что возвращает models.run(). Запрос, который завершился ошибкой или был отменён, отклоняется здесь.
const result = await handle.get();

console.log(result.data);
```

```bash cURL
# 1. Отправка. Router отвечает 201 с request_id, status_url, response_url и cancel_url.
curl https://api.comfy.org/v2/models/kling/kling-v2-6/requests \
  -H "X-API-Key: $COMFY_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d "{\"aspect_ratio\": \"16:9\", \"duration\": \"5\", \"mode\": \"std\", \"prompt\": \"A red fox trotting through falling snow, cinematic lighting.\"}"

# 2. Опрашивайте, пока статус не станет COMPLETED, выжидая Retry-After секунд, указанные в каждом ответе.
REQUEST_ID="<request_id from the 201 body>"
curl -i https://api.comfy.org/v2/models/kling/kling-v2-6/requests/$REQUEST_ID/status \
  -H "X-API-Key: $COMFY_API_KEY"

# 3. Получение. 200 с нативным выводом модели, 202 с телом статуса, пока запрос ещё выполняется.
curl https://api.comfy.org/v2/models/kling/kling-v2-6/requests/$REQUEST_ID \
  -H "X-API-Key: $COMFY_API_KEY"
```

</ParamField>

<ParamField body="multi_shot" type="boolean" default="false">
  Генерировать ли видео с несколькими кадрами. Если true, параметр prompt недопустим. Если false, параметры shot_type и multi_prompt недопустимы.
</ParamField>

<ParamField body="negative_prompt" type="string">
  Негативный текстовый промпт. Рекомендуется дополнять информацию негативного промпта отрицательными предложениями непосредственно внутри положительных промптов.
</ParamField>

<ParamField body="prompt" type="string">
  Положительный текстовый промпт. Используйте \<\<\<voice_1>>>, чтобы указать голос, соответствующий порядку в параметре voice_list. В одной задаче можно указать до 2 голосов. При указании голоса значение параметра sound должно быть on.
</ParamField>

<ParamField body="shot_type" type="string">
  Метод раскадровки. Обязательно, когда параметр multi_shot установлен в true.

  Возможные значения: `customize`, `intelligence`
</ParamField>

<ParamField body="sound" type="string" default="&quot;off&quot;">
  Генерировать ли звук одновременно с видео. Этот параметр поддерживают только V2.6 и последующие версии модели.

  Возможные значения: `on`, `off`
</ParamField>

<ParamField body="voice_list" type="object[]">
  Список голосов, на которые ссылаются при генерации видео. Поддерживается до 2 голосов; ссылайтесь на них в `prompt` как \<\<\<voice_1>>> и \<\<\<voice_2>>> в порядке списка. Требуется, чтобы `sound` был установлен в «on»; это поддерживают только V2.6 и последующие версии модели. На более ранней модели или если `sound` оставлен в значении по умолчанию «off», голоса не применяются.
</ParamField>

<ParamField body="voice_list[].voice_id" type="string" required>
  ID голоса, полученный через API пользовательских голосов, или ID системного предустановленного голоса.
</ParamField>

<ParamField body="watermark_info" type="object">
  Генерировать ли результаты с водяным знаком одновременно. Пользовательский водяной знак пока не поддерживается.
</ParamField>

<ParamField body="watermark_info.enabled" type="boolean">
  true означает, что водяной знак генерируется, false означает, что он не генерируется.
</ParamField>

<ParamField body="image" type="string">
  Референсное изображение: URL или строка в кодировке Base64, не может превышать 10MB, разрешение не менее 300*300px, соотношение сторон в диапазоне 1:2.5 ~ 2.5:1. Base64 не должен включать префикс data:image.
</ParamField>

<ParamField body="image_tail" type="string">
  Референсное изображение: управление конечным кадром. URL или строка в кодировке Base64, не может превышать 10MB, разрешение не менее 300*300px. Base64 не должен включать префикс data:image. Нельзя использовать одновременно с dynamic_masks/static_mask или camera_control.
</ParamField>

<ParamField body="mode" type="string" default="&quot;std&quot;">
  Режим генерации видео. std: стандартный режим, экономичный. pro: профессиональный режим, генерирует видео большей длительности, но с более высоким качеством.

  Возможные значения: `std`, `pro`
</ParamField>
