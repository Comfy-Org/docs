Справочник по API для HappyHorse 1.1 R2V. HappyHorse 1.1 reference-to-video сохраняет субъектов из девяти референсных изображений согласованными в новой сцене; в промпте к ним обращаются как character1, character2 и так далее.

**Вход:** Image, Text · **Выход:** Video

## Быстрый старт

Создайте ключ в [вашем рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. Фрагменты кода Python и TypeScript используют Comfy SDK (`pip install comfy-sdk` и `npm install @comfyorg/sdk`); фрагмент cURL выполняет тот же вызов через обычный HTTP.

**ID модели:** `wan/happyhorse-1.1-r2v`

**Эндпоинт:** `POST https://api.comfy.org/v2/models/wan/happyhorse-1.1-r2v`

```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменной окружения.
# SDK автоматически создаёт ключ идемпотентности и повторно использует его при автоматических повторах.
async def main():
    async with AsyncComfy() as client:
        result = await client.models.run(
            "wan/happyhorse-1.1-r2v",
            {
                "input": {
                    "prompt": "character1 walks in from the left, turns to the camera and waves, plain orange backdrop",
                    "media": [
                        {
                            "type": "reference_image",
                            "url": "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )

    print("video:", result["output"]["video_url"])

asyncio.run(main())
```

То же тело запроса, отправленное на `POST https://api.comfy.org/v2/models/wan/happyhorse-1.1-r2v/requests`. Router отвечает `201` с `request_id`, как только запуск принят, а результат забирается, когда он готов, из этого процесса или из любого другого. [Доставка через очередь](/ru/development/comfy-router/queue) описывает статус, отмену и получение результата.

<CodeGroup>
```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменных окружения.
# Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его при автоматических повторах.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/happyhorse-1.1-r2v",
            {
                "input": {
                    "prompt": "character1 walks in from the left, turns to the camera and waves, plain orange backdrop",
                    "media": [
                        {
                            "type": "reference_image",
                            "url": "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивайте, пока запрос не завершится, выдерживая Retry-After, указанный сервером.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственный payload провайдера, то же значение, что возвращает models.run().
        # Запрос, завершившийся ошибкой или отменённый, вызывает здесь типизированную ошибку Router.
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Читает COMFY_API_KEY из переменных окружения.
// Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его при автоматических повторах.
type Result = { output: { video_url: string } };
const handle = await comfy.models.submit<Result>("wan/happyhorse-1.1-r2v", {
  input: {
    prompt: "character1 walks in from the left, turns to the camera and waves, plain orange backdrop",
    media: [
      {
        type: "reference_image",
        url: "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
      },
    ],
  },
  parameters: {
    resolution: "720P",
    duration: 5,
  },
});
console.log("requestId:", handle.requestId); // вместе с ID модели это всё, что нужно другому процессу

// Опрашивайте, пока запрос не завершится, выдерживая Retry-After, указанный сервером.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// Тот же результат, что возвращает models.run(). Запрос, завершившийся ошибкой или отменённый, отклоняется здесь.
const result = await handle.get();
if (result.kind !== "json") throw new Error("expected a JSON result");

console.log("video:", result.data.output.video_url);
```

```bash cURL
  -H "X-API-Key: $COMFY_API_KEY" \
```

## Схема

### Входы

<ParamField body="input" type="object" required>
  Укажите базовую информацию: промпт и т. п.
</ParamField>

<ParamField body="input.audio_url" type="string">
  URL для скачивания аудиофайла. Поддерживаемые форматы: mp3 и wav. Нельзя использовать
вместе с reference_video_urls.
</ParamField>

<ParamField body="input.img_url" type="string">
  URL изображения первого кадра или данные в кодировке Base64. Обязателен для моделей
wan2.5-i2v-preview и wan2.6-i2v. Варианты happyhorse-1.x i2v НЕ принимают первый кадр
здесь: они передают его как медиаэлемент типа first_frame (см. media ниже). Кроме того,
тело запроса с img_url, которое успешно проходит на wan2.6-i2v, отклоняется провайдером
на happyhorse-1.0-i2v и happyhorse-1.1-i2v, а варианты wan2.7/wan3.0 также передают свои
референсные ассеты в media. Форматы изображений: JPEG, JPG, PNG, BMP, WEBP.
Разрешение: 360-2000 пикселей. Размер файла: макс. 10MB.
</ParamField>

<ParamField body="input.media" type="object[]">
  Список медиаассетов. Задаёт референсные материалы (изображение, аудио, видео) для
генерации видео. Каждый элемент содержит поля type и url. Это поле общее для всех
моделей, обслуживаемых данным компонентом, а то, какие значения type принимает
конкретная модель и передаёт ли она вообще свой ввод изображения или видео здесь, а не
в img_url или reference_video_urls, зависит от модели. Поддерживаемые значения type по
моделям:
- wan2.7-i2v: first_frame, last_frame, driving_audio, first_clip. first_frame и
  last_frame: JPEG/JPG/PNG/BMP/WEBP, 240-8000 пикселей по каждой стороне, соотношение
  сторон от 1:8 до 8:1, не более 20MB, публичный URL или URL вида
  data:\{MIME_type};base64,... . driving_audio (WAV/MP3, 2-30 секунд, не более 15MB) и
  first_clip (MP4/MOV, 2-10 секунд, 240-4096 пикселей по каждой стороне, не более
  100MB): публичный HTTP/HTTPS URL; встроенный data: URL не принимается.
- wan2.7-r2v: first_frame (необязательно, макс. 1), reference_image, reference_video.
  Требуется как минимум один reference_image или reference_video, а референсные
  изображения и референсные видео в сумме дают не более 5. first_frame и reference_image:
  JPEG/JPG/PNG/BMP/WEBP (без альфа-канала), 240-8000 пикселей по каждой стороне,
  соотношение сторон от 1:8 до 8:1, не более 20MB, публичный URL или URL вида
  data:\{MIME_type};base64,... . reference_video: публичный HTTP/HTTPS URL; встроенный
  data: URL не принимается.
- wan2.7-videoedit: video (ровно 1, редактируемый клип: MP4/MOV, 2-10 секунд,
  240-4096 пикселей по каждой стороне, не более 100MB, публичный HTTP/HTTPS URL;
  встроенный data: URL не принимается) плюс необязательные от 0 до 4 reference_image
  (JPEG/JPG/PNG/BMP/WEBP, 240-8000 пикселей по каждой стороне, соотношение сторон от 1:8
  до 8:1, не более 20MB, публичный URL или URL вида data:\{MIME_type};base64,... ).
- wan3.0-video, wan3.0-video-prime: first_frame (макс. 1), last_frame (макс. 1),
  reference_image (макс. 10), reference_video (макс. 5 клипов, суммарная длительность
  \<= 15s), reference_audio (макс. 5 клипов, суммарная длительность \<= 15s), file
  (макс. 1, нельзя использовать вместе с link), link (макс. 1, нельзя использовать
  вместе с file). Типы reference_*/file/link и типы first_frame/last_frame взаимно
  исключают друг друга в одном запросе. Порядок в массиве задаёт порядок референсов
  ассетов в промпте (Image 1, Video 1, Audio 1, ...). first_frame, last_frame и
  reference_image: JPEG/JPG/PNG/BMP/WEBP, 240-8000 пикселей по каждой стороне,
  соотношение сторон не более 8:1, не более 20MB, публичный URL или URL вида
  data:\{MIME_type};base64,... . reference_video, reference_audio, file и link:
  публичный HTTP/HTTPS URL; встроенный data: URL не принимается.
- happyhorse-1.0-i2v, happyhorse-1.1-i2v: только first_frame, ровно 1. Эти варианты
  принимают первый кадр ЗДЕСЬ, а не в img_url. Не менее 300x300 пикселей, соотношение
  сторон от 1:2.5 до 2.5:1, JPEG/JPG/PNG/WEBP, не более 20MB, публичный URL или URL вида
  data:\{MIME_type};base64,... .
- happyhorse-1.0-r2v, happyhorse-1.1-r2v: только reference_image, от 1 до 9 штук. Это
  единственный референсный ввод данной модели. Наименьшая сторона не менее 400 пикселей,
  JPEG/JPG/PNG/WEBP, не более 20MB, публичный URL или URL вида
  data:\{MIME_type};base64,... . reference_video не является типом ввода для этой
  операции.
- happyhorse-1.0-video-edit: video (ровно 1, редактируемый клип: MP4/MOV, 3-60 секунд,
  большая сторона не более 4096 пикселей, меньшая сторона не менее 360 пикселей,
  соотношение сторон от 1:2.5 до 2.5:1, не более 100MB, публичный HTTP/HTTPS URL;
  встроенный data: URL не принимается) плюс необязательные от 0 до 5 reference_image
  (JPEG/JPG/PNG/WEBP, не менее 300x300 пикселей, соотношение сторон от 1:2.5 до 2.5:1,
  не более 20MB, публичный URL или URL вида data:\{MIME_type};base64,... ).
- happyhorse-1.0-t2v, happyhorse-1.1-t2v, wan2.7-t2v, wan2.6-t2v, wan2.5-t2v-preview:
  операции текст в видео. В документации партнёра для них не описан ввод media, поэтому
  оставьте это поле незаданным.
- wan2.5-i2v-preview, wan2.6-i2v, wan2.6-r2v: для этих вариантов данный компонент не
  перечисляет никакого набора медиатипов. wan2.5-i2v-preview и wan2.6-i2v принимают
  первый кадр в img_url; wan2.6-r2v принимает свои референсные клипы в
  reference_video_urls.
Приведённые выше количества для каждой модели: это ограничения партнёра, а не данной
схемы. На media не объявлены minItems/maxItems, поскольку допустимые типы и их лимиты
различаются по моделям. Принятие схемой не означает принятия провайдером. И в обратную
сторону: указанные выше для каждого ассета значения «не более 20MB» (предел для входов
изображений, единственных входов, которые можно передавать встроенно) являются пределом
партнёра для ассета, который он в итоге получает, и действуют в точности так, когда
ассет задан публичным URL, потому что эти байты никогда не проходят через Comfy.
Встроенный URL data:\{MIME_type};base64,... проходит через Comfy и тоже упирается в
транспортный предел: тело POST-запроса Comfy Router ограничено 100 MiB в сумме, и при
превышении возвращается ответ 413, а base64 увеличивает полезную нагрузку примерно в
4/3 раза, поэтому один встроенный ассет размером более примерно 75 MB отклоняется ещё
до того, как сработает любое из правил партнёра, описанных здесь. При таком размере
один ассет при собственном пределе партнёраЛимит в 20MB позволяет комфортно передавать данные inline, поэтому для одного ассета ограничивающим становится правило партнёра. Транспортный лимит действует при нескольких ассетах, поскольку ограничение Router в 100 MiB ограничивает ВЕСЬ запрос, а не каждый элемент. Отправляйте всё, что близко к этим лимитам, как публичный URL.
</ParamField>

<ParamField body="input.media[].url" type="string" required>
  URL медиафайла: публичный HTTP/HTTPS URL или, ровно для тех IMAGE-входов, которые описание `media` выше перечисляет для каждой модели: first_frame и last_frame для wan2.7-i2v; first_frame и reference_image для wan2.7-r2v; reference_image для wan2.7-videoedit; first_frame, last_frame и reference_image для wan3.0-video и wan3.0-video-prime; first_frame для happyhorse-1.0-i2v и happyhorse-1.1-i2v; reference_image для happyhorse-1.0-r2v и happyhorse-1.1-r2v; и reference_image для happyhorse-1.0-video-edit, встроенный URL `data:{MIME_type};base64,...`. Ни один вход video, audio, file или link ни в одной из этих моделей не принимает встроенный data: URL. Временный URL `oss://dashscope-instant` из собственного сервиса загрузки партнёра или (на wan2.7-videoedit) asset_id из Asset Center действителен только для той учётной записи Alibaba Cloud, которая его загрузила; Comfy выполняет вызов модели со своим ключом и не предоставляет маршрут загрузки, поэтому собственный URL `oss://` или asset_id вызывающей стороны не является поддерживаемым входом. Это поле не проверяет схему URL, поэтому такое значение передаётся партнёру как есть, а не отклоняется здесь. См. описание `media`, чтобы узнать ограничения размера и пикселей для каждой модели, а также лимит тела запроса Router в 100 MiB, который в совокупности ограничивает встроенную полезную нагрузку.
</ParamField>

<ParamField body="input.negative_prompt" type="string">
  Слова обратного промпта используются для описания содержимого, которое вы не хотите видеть на экране видео. После 500 символов модель wan обрезает его, а не отклоняет. Оно учитывается в том же бюджете ввода, что и prompt.
</ParamField>

<ParamField body="input.prompt" type="string">
  Текстовые слова промпта. Поддерживаются китайский и английский языки. После собственной документированной длины модель wan2.x обрезает промпт, а не отклоняет его: 1,500 символов для wan2.5 и wan2.6 и 5,000 для wan2.7. wan3.0-video и wan3.0-video-prime принимают не более 20,000 символов. Провайдер отклоняет запрос, в котором prompt и negative_prompt вместе длиннее примерно 60,850 байт текста UTF-8 (около 20,000 китайских символов), отвечая InvalidParameter `Range of input length should be [1, 61440]`.
Для wan2.6-r2v с несколькими референсными видео используйте 'character1', 'character2' и т. д., чтобы ссылаться на субъектов в порядке референсных видео. Пример: «Character1 поёт на обочине, Character2 танцует рядом»
Для режима reference в wan3.0-video используйте 'Image 1', 'Video 1', 'Audio 1' и т. д., чтобы ссылаться на медиафайлы в соответствующем порядке в массиве media.
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  URL референсных видео только для модели wan2.6-r2v. Массив из 1-3 URL видео.
Ограничения входа:
- Формат: mp4, mov
- Количество: 1-3 видео
- Длительность одного видео: 2-30 секунд
- Размер одного файла: максимум 30MB
- Нельзя использовать с audio_url
Длительность референса: одно видео максимум 5s, два видео максимум по 2.5s каждое, три видео пропорционально меньше.
Выставление счетов: на основе фактически использованной длительности референса.
</ParamField>

<ParamField body="input.template" type="string">

- wan2.6-r2v: только 5 или 10 секунд (без поддержки 15s)

<ParamField body="parameters.resolution" type="string">

- wan2.5-i2v-preview: 480P, 720P, 1080P
- модели wan2.6 (t2v, i2v, r2v): только 720P, 1080P (без поддержки 480P)
- модели wan2.7 (i2v, t2v, r2v, videoedit): 720P, 1080P (по умолчанию 1080P)
- wan3.0-video, wan3.0-video-prime: 480P, 720P, 1080P (по умолчанию на стороне провайдера 1080P)

- happyhorse-1.1-* (t2v, i2v, r2v): 480P, 720P, 1080P

регистре, возвращает 400 для значения вне этого перечисления и возвращает 400 для 480P
(независимо от того, передано ли оно как resolution или как size со значением 480P)
для моделей wan2.6, wan2.7 и happyhorse-1.0, перечисленных выше как не поддерживающие 480P.

  Possible values: `480P`, `720P`, `1080P`

Для моделей wan2.6 и wan2.7-r2v.
- single: видео одним планом (по умолчанию)
- multi: видео из нескольких планов

  Possible values: `multi`, `single`
</ParamField>

<ParamField body="parameters.size" type="string">
  Разрешение видео в формате width*height. Поддерживаемые разрешения зависят от модели:
Для wan2.5 T2V: размеры 480P (480*832, 832*480, 624*624), 720P, 1080P
Для wan2.6 T2V/R2V (без 480P):

  1080P: 1920*1080, 1080*1920, 1440*1440, 1632*1248, 1248*1632
Если переданы и size, и resolution, то тарифицируемый уровень выбирает size,
а resolution всё равно должно быть значением, которое этот прокси принимает для модели.
Размер 480P возвращает 400 для каждой модели, которая в описании resolution указана

</ParamField>
