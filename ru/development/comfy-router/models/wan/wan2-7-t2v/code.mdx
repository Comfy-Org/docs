Справочник по API для Wan 2.7 T2V. Wan 2.7 в режиме текст в видео создаёт короткое видео только по промпту, в разрешении 720P или 1080P и длительностью от 2 до 15 секунд.

**Вход:** Текст · **Выход:** Видео + Аудио

## Быстрый старт

Создайте ключ в [вашем рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. Фрагменты на Python и TypeScript используют SDK Comfy (`pip install comfy-sdk` и `npm install @comfyorg/sdk`), а фрагмент cURL выполняет тот же вызов напрямую по HTTP.

**ID модели:** `wan/wan2.7-t2v`

**Эндпоинт:** `POST https://api.comfy.org/v2/models/wan/wan2.7-t2v`

То же тело запроса, отправленное на `POST https://api.comfy.org/v2/models/wan/wan2.7-t2v/requests`. Router отвечает `201` с `request_id` сразу после того, как запуск принят, а результат забирается, когда он готов, из этого процесса или из другого. ```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменной окружения.
# Каждый вызов submit() создаёт свой Idempotency-Key и переиспользует его при автоматических повторах.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/wan2.7-t2v",
            {
                "input": {
                    "prompt": "a single red maple leaf falling onto still water, slow motion, shallow depth of field",
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивайте, пока запрос не завершится, выдерживая Retry-After, указанный сервером.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственный ответ провайдера, то же значение, которое возвращает models.run().
        # Запрос, завершившийся ошибкой или отменённый, здесь вызывает типизированную ошибку Router.
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())
```

import { comfy } from "@comfyorg/sdk";

// Читает COMFY_API_KEY из переменной окружения.
// Каждый вызов submit() создаёт свой Idempotency-Key и переиспользует его при автоматических повторах.
type Result = { output: { video_url: string } };
const handle = await comfy.models.submit<Result>("wan/wan2.7-t2v", {
  input: {
    prompt: "a single red maple leaf falling onto still water, slow motion, shallow depth of field",
  },
  parameters: {
    resolution: "720P",
    duration: 5,
  },
});
console.log("requestId:", handle.requestId); // вместе с ID модели это всё, что нужно другому процессу

// Опрашивайте, пока запрос не завершится, выдерживая Retry-After, указанный сервером.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// Тот же результат, который возвращает models.run(). Запрос, завершившийся ошибкой или отменённый, отклоняется здесь.
const result = await handle.get();
if (result.kind !== "json") throw new Error("expected a JSON result");

console.log("video:", result.data.output.video_url);
```

### Входы

<ParamField body="input" type="object" required>
  Введите базовую информацию, например промпт и т. д.
</ParamField>

<ParamField body="input.audio_url" type="string">
  URL для скачивания аудиофайла. Поддерживаемые форматы: mp3 и wav. Нельзя использовать вместе с reference_video_urls.
</ParamField>

<ParamField body="input.img_url" type="string">
  URL изображения первого кадра или данные в кодировке Base64. Обязательно для моделей wan2.5-i2v-preview и wan2.6-i2v. Варианты написания happyhorse-1.x i2v НЕ принимают первый кадр здесь: они принимают его как медиаэлемент типа first_frame (см. media ниже), а тело запроса с img_url, которое успешно проходит на wan2.6-i2v, отклоняется провайдером на happyhorse-1.0-i2v и happyhorse-1.1-i2v. Варианты wan2.7/wan3.0 также принимают свои референсные ассеты в media. Форматы изображений: JPEG, JPG, PNG, BMP, WEBP. Разрешение: 360-2000 пикселей. Размер файла: макс. 10MB.
</ParamField>

<ParamField body="input.media" type="object[]">
  Список медиаассетов. Задаёт референсные материалы (изображение, аудио, видео) для генерации видео. Каждый элемент содержит поля type и url. Это поле используется всеми моделями, которые обслуживает данный компонент, а то, какие значения type принимает конкретная модель и передаёт ли она вообще свой ввод изображения или видео здесь, а не в img_url или reference_video_urls, зависит от модели. Поддерживаемые значения type по моделям:
- wan2.7-i2v: first_frame, last_frame, driving_audio, first_clip. first_frame и last_frame: JPEG/JPG/PNG/BMP/WEBP, 240-8000 пикселей на сторону, соотношение сторон от 1:8 до 8:1, не более 20MB, публичный URL или URL вида data:\{MIME_type};base64,.... driving_audio (WAV/MP3, 2-30 секунд, не более 15MB) и first_clip (MP4/MOV, 2-10 секунд, 240-4096 пикселей на сторону, не более 100MB): публичный URL HTTP/HTTPS; встроенный data: URL не принимается.
- wan2.7-r2v: first_frame (необязательно, макс. 1), reference_image, reference_video. Требуется хотя бы один reference_image или reference_video, а референсные изображения и референсные видео в сумме дают не более 5. first_frame и reference_image: JPEG/JPG/PNG/BMP/WEBP (без альфа-канала), 240-8000 пикселей на сторону, соотношение сторон от 1:8 до 8:1, не более 20MB, публичный URL или URL вида data:\{MIME_type};base64,.... reference_video: публичный URL HTTP/HTTPS; встроенный data: URL не принимается.
- wan2.7-videoedit: video (ровно 1, клип, который редактируется: MP4/MOV, 2-10 секунд, 240-4096 пикселей на сторону, не более 100MB, публичный URL HTTP/HTTPS; встроенный data: URL не принимается) плюс необязательные от 0 до 4 reference_image (JPEG/JPG/PNG/BMP/WEBP, 240-8000 пикселей на сторону, соотношение сторон от 1:8 до 8:1, не более 20MB, публичный URL или URL вида data:\{MIME_type};base64,...).
- wan3.0-video, wan3.0-video-prime: first_frame (макс. 1), last_frame (макс. 1), reference_image (макс. 10), reference_video (макс. 5 клипов, суммарная длительность \<= 15s), reference_audio (макс. 5 клипов, суммарная длительность \<= 15s), file (макс. 1, нельзя использовать вместе с link), link (макс. 1, нельзя использовать вместе с file). Типы reference_*/file/link и типы first_frame/last_frame взаимоисключающие в одном запросе. Порядок в массиве задаёт порядок референсных ассетов в промпте (Изображение 1, Видео 1, Аудио 1, ...). first_frame, last_frame и reference_image: JPEG/JPG/PNG/BMP/WEBP, 240-8000 пикселей на сторону, соотношение сторон не более 8:1, не более 20MB, публичный URL или URL вида data:\{MIME_type};base64,.... reference_video, reference_audio, file и link: публичный URL HTTP/HTTPS; встроенный data: URL не принимается.
- happyhorse-1.0-i2v, happyhorse-1.1-i2v: только first_frame, ровно 1. Эти варианты написания принимают первый кадр ЗДЕСЬ, а не в img_url. Не менее 300x300 пикселей, соотношение сторон от 1:2.5 до 2.5:1, JPEG/JPG/PNG/WEBP, не более 20MB, публичный URL или URL вида data:\{MIME_type};base64,....
- happyhorse-1.0-r2v, happyhorse-1.1-r2v: только reference_image, от 1 до 9. Это единственный референсный ввод модели. Наименьшая сторона не менее 400 пикселей, JPEG/JPG/PNG/WEBP, не более 20MB, публичный URL или URL вида data:\{MIME_type};base64,.... reference_video не является типом ввода для этой операции.
- happyhorse-1.0-video-edit: video (ровно 1, клип, который редактируется: MP4/MOV, 3-60 секунд, длинная сторона не более 4096 пикселей, короткая сторона не менее 360 пикселей, соотношение сторон от 1:2.5 до 2.5:1, не более 100MB, публичный URL HTTP/HTTPS; встроенный data: URL не принимается) плюс необязательные от 0 до 5 reference_image (JPEG/JPG/PNG/WEBP, не менее 300x300 пикселей, соотношение сторон от 1:2.5 до 2.5:1, не более 20MB, публичный URL или URL вида data:\{MIME_type};base64,...).
- happyhorse-1.0-t2v, happyhorse-1.1-t2v, wan2.7-t2v, wan2.6-t2v, wan2.5-t2v-preview: операции текст в видео. В документации партнёра для них не описан ввод media, поэтому оставьте это поле незаданным.
- wan2.5-i2v-preview, wan2.6-i2v, wan2.6-r2v: для этих вариантов написания данный компонент не перечисляет словарь media. wan2.5-i2v-preview и wan2.6-i2v принимают первый кадр в img_url; wan2.6-r2v принимает свои референсные клипы в reference_video_urls.
Приведённые выше счётчики по моделям являются ограничениями партнёра, а не этой схемы: в media не объявлены minItems/maxItems, потому что допустимые типы и их лимиты различаются по моделям. Принятие схемой не означает принятия провайдером. И наоборот: указанные выше для каждого ассета значения «не более 20MB» (потолок для входов-изображений, единственных входов, которые можно передавать встроенно) представляют собой потолок партнёра для ассета, который он в итоге получает, и они действуют в указанном виде, когда ассет является публичным URL, поскольку эти байты никогда не проходят через Comfy. Встроенный URL data:\{MIME_type};base64,... проходит через Comfy и тоже сталкивается с транспортным потолком: тело POST-запроса к Comfy Router ограничено 100 MiB в сумме, и при превышении возвращается 413, а base64 увеличивает полезную нагрузку примерно в 4/3 раза, поэтому одиночный встроенный ассет размером примерно выше 75 MB отклоняется ещё до того, как сработает какое-либо из правил партнёра. При таком размере одиночный ассет при собственном 20MB укладывается в inline с запасом, поэтому для одного ассета ограничивающим становится правило партнёра, а при нескольких ассетах связывает транспортный потолок: лимит Router в 100 MiB ограничивает ВЕСЬ запрос, а не каждый элемент. Всё, что близко к этим потолкам, отправляйте как публичный URL.

<ParamField body="input.media[].url" type="string" required>
  URL медиафайла: публичный HTTP/HTTPS URL либо, строго для тех IMAGE-входов, которые перечислены выше в описании `media` для каждой модели: first_frame и last_frame у wan2.7-i2v; first_frame и reference_image у wan2.7-r2v; reference_image у wan2.7-videoedit; first_frame, last_frame и reference_image у wan3.0-video и wan3.0-video-prime; first_frame у happyhorse-1.0-i2v и happyhorse-1.1-i2v; reference_image у happyhorse-1.0-r2v и happyhorse-1.1-r2v; и reference_image у happyhorse-1.0-video-edit: inline-URL вида `data:{MIME_type};base64,...`. Ни один вход video, audio, file или link ни у одной из этих моделей не принимает inline data: URL. Временный URL oss://dashscope-instant из собственного сервиса загрузки партнёра или (для wan2.7-videoedit) asset_id из Asset Center разрешается только в той учётной записи Alibaba Cloud, которая его загрузила; Comfy выполняет вызов модели своим ключом и не предоставляет маршрут загрузки, поэтому собственный oss:// URL или asset_id вызывающего не является поддерживаемым входом. Это поле не проверяет схему URL, поэтому такое значение передаётся партнёру как есть, а не отклоняется здесь. См. описание `media`, чтобы узнать ограничения по размеру и пикселям для каждой модели и лимит Router в 100 MiB на тело запроса, который суммарно ограничивает inline-нагрузку.
</ParamField>

<ParamField body="input.negative_prompt" type="string">
  Слова обратного промпта описывают содержимое, которое вы не хотите видеть на экране видео. После 500 символов модель wan обрезает его, а не отклоняет. Он учитывается в том же бюджете входа, что и промпт.
</ParamField>

<ParamField body="input.prompt" type="string">
  Текст промпта. Поддерживает китайский и английский. После собственной документированной длины модель wan2.x обрезает промпт, а не отклоняет его: 1,500 символов для wan2.5 и wan2.6 и 5,000 для wan2.7. wan3.0-video и wan3.0-video-prime принимают не более 20,000 символов. Провайдер отклоняет запрос, у которого prompt и negative_prompt вместе длиннее примерно 60,850 байт текста UTF-8 (около 20,000 китайских символов), отвечая InvalidParameter `Range of input length should be [1, 61440]`.
Для wan2.6-r2v с несколькими референсными видео используйте 'character1', 'character2' и т. д., чтобы ссылаться на субъектов в порядке референсных видео. Пример: «Character1 sings on the roadside, Character2 dances beside it»
Для режима reference у wan3.0-video используйте 'Image 1', 'Video 1', 'Audio 1' и т. д., чтобы ссылаться на медиафайлы в соответствующем порядке внутри массива media.
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  URL референсных видео только для модели wan2.6-r2v. Массив из 1-3 URL видео.
Ограничения входа:
- Формат: mp4, mov
- Количество: 1-3 видео
- Длительность одного видео: 2-30 секунд
- Размер одного файла: максимум 30MB
- Нельзя использовать вместе с audio_url
Длительность референса: одно видео максимум 5 с, два видео максимум по 2.5 с, три видео пропорционально меньше.
Выставление счетов: на основе фактически использованной длительности референса.
</ParamField>

<ParamField body="input.template" type="string">
  Имя шаблона видеоэффекта. Необязательно. Сейчас поддерживаются: squish, flying, carousel. При использовании параметр prompt игнорируется.
</ParamField>

- wan2.6-t2v, wan2.6-i2v: 5, 10 или 15 секунд
- wan2.6-r2v: только 5 или 10 секунд (15s не поддерживается)
- wan2.7-i2v, wan2.7-t2v: целое число в [2, 15]
- wan2.7-r2v, wan2.7-videoedit: целое число в [2, 10]
- wan3.0-video: целое число в [2, 30] без видео на входе; при наличии видео на входе суммарная
  длительность входного видео + длительность выходного видео не должна превышать 30 секунд; -1 включает
  режим умной длительности, в котором модель подбирает подходящую длительность
Этот прокси возвращает 400 для длительности вне [-1, 30].

  Диапазон: от `-1` до `30`
</ParamField>

<ParamField body="parameters.prompt_extend" type="boolean" default="true">
  Включено ли интеллектуальное переписывание промпта. По умолчанию true
</ParamField>

<ParamField body="parameters.ratio" type="string">
  Соотношение сторон сгенерированного видео. Только для моделей wan2.7 и wan3.0.
Для моделей wan2.7 при отсутствии значения используется значение по умолчанию на основе уровня разрешения.
Для wan3.0-video значение adaptive (по умолчанию) автоматически рекомендует подходящеесоотношение сторон на основе пропорций и назначения входного медиа.

  Возможные значения: `adaptive`, `16:9`, `9:16`, `1:1`, `4:3`, `3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  Уровень разрешения. Поддерживаемые значения зависят от модели:
- wan2.5-i2v-preview: 480P, 720P, 1080P
- модели wan2.6 (t2v, i2v, r2v): только 720P, 1080P (без поддержки 480P)
- модели wan2.7 (i2v, t2v, r2v, videoedit): 720P, 1080P (по умолчанию 1080P)
- wan3.0-video, wan3.0-video-prime: 480P, 720P, 1080P (по умолчанию у провайдера 1080P)
- happyhorse-1.0-* (t2v, i2v, r2v, video-edit): 720P, 1080P
- happyhorse-1.1-* (t2v, i2v, r2v): 480P, 720P, 1080P
Этот прокси отклоняет запросы на генерацию видео, в которых не указаны ни resolution, ни size, поскольку уровень разрешения определяет тариф выставления счетов. Перед проверкой он приводит resolution к верхнему регистру и передаёт значение в верхнем регистре, возвращает 400 для значения вне этого перечисления и возвращает 400 для 480P (независимо от того, передано ли оно как resolution или как size со значением 480P) для моделей wan2.6, wan2.7 и happyhorse-1.0, перечисленных выше как не поддерживающие 480P.

  Возможные значения: `480P`, `720P`, `1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  Сид генератора случайных чисел, управляет случайностью содержимого, сгенерированного моделью

  Диапазон: от `0` до `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  Интеллектуальное управление несколькими планами. Активно только при включённом prompt_extend.
Для моделей wan2.6 и wan2.7-r2v.
- single: видео одним планом (по умолчанию)
- multi: видео из нескольких планов

  Возможные значения: `multi`, `single`
</ParamField>

<ParamField body="parameters.size" type="string">
  Разрешение видео в формате width*height. Поддерживаемые разрешения зависят от модели:
Для wan2.5 T2V: размеры 480P (480*832, 832*480, 624*624), 720P, 1080P
Для wan2.6 T2V/R2V (без 480P):
  720P: 1280*720, 720*1280, 960*960, 1088*832, 832*1088
  1080P: 1920*1080, 1080*1920, 1440*1440, 1632*1248, 1248*1632
Если переданы и size, и resolution, то тариф определяет size, а resolution всё равно должно быть значением, которое этот прокси принимает для модели. Size со значением 480P возвращает 400 для каждой модели, которая в описании resolution указана как не поддерживающая 480P.
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  Добавлять ли логотип-водяной знак; водяной знак располагается в правом нижнем углу
</ParamField>

Создано из схемы, которую Router отдаёт по `GET /v2/models/wan/wan2.7-t2v/openapi.json`, того же документа, по которому он проверяет вызов до того, как запрос достигнет провайдера.
