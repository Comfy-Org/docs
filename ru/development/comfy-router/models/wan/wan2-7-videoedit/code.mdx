Справочник по API для Wan 2.7 Video Edit. Wan 2.7 video edit перезаписывает существующий клип по текстовой инструкции, при необходимости ориентируясь на референсные изображения.

**Вход:** Видео, Изображение, Текст · **Выход:** Видео

## Быстрый старт

Создайте ключ в [вашем рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. Фрагменты кода Python и TypeScript используют SDK Comfy (`pip install comfy-sdk` и `npm install @comfyorg/sdk`); фрагмент cURL выполняет тот же вызов по обычному HTTP.

**ID модели:** `wan/wan2.7-videoedit`

**Конечная точка:** `POST https://api.comfy.org/v2/models/wan/wan2.7-videoedit`

```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменных окружения.
# Каждый вызов submit() создаёт свой Idempotency-Key и переиспользует его при автоматических повторах.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/wan2.7-videoedit",
            {
                "input": {
                    "prompt": "restyle the clip as a hand-drawn ink sketch, keep the dancer's movement unchanged",
                    "media": [
                        {
                            "type": "video",
                            "url": "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/street_dancer.mp4",
                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                    "audio_setting": "origin",
                },
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивайте, пока запрос не завершится, выжидая Retry-After, который укажет сервер.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственный payload провайдера, то же значение, которое возвращает models.run().
        # Запрос с ошибкой или отменённый вызывает здесь типизированную ошибку Router.
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())
```

</ParamField>

<ParamField body="input.img_url" type="string">
  URL изображения первого кадра или данные в кодировке Base64. Обязательно для моделей
wan2.5-i2v-preview и wan2.6-i2v. Варианты happyhorse-1.x i2v НЕ принимают первый кадр
здесь: они принимают его как медиаэлемент типа first_frame (см. media ниже), а тело с
img_url, которое успешно проходит на wan2.6-i2v, отклоняется провайдером на
happyhorse-1.0-i2v и happyhorse-1.1-i2v. Варианты wan2.7/wan3.0 также принимают свои
референсные ассеты в media. Форматы изображений: JPEG, JPG, PNG, BMP, WEBP.
Разрешение: 360-2000 пикселей. Размер файла: не более 10MB.
</ParamField>

<ParamField body="input.media" type="object[]">
  Список медиаассетов. Задаёт референсные материалы (изображение, аудио, видео) для
генерации видео. Каждый элемент содержит поля type и url. Это поле используется всеми
моделями, которые обслуживает этот компонент, а то, какие значения type принимает
конкретная модель (и передаёт ли она вообще свой ввод изображения или видео здесь, а
не в img_url или reference_video_urls), зависит от модели. Поддерживаемые значения
type по моделям:
- wan2.7-i2v: first_frame, last_frame, driving_audio, first_clip. first_frame и
  last_frame: JPEG/JPG/PNG/BMP/WEBP, 240-8000 пикселей по стороне, соотношение сторон
  от 1:8 до 8:1, не более 20MB, публичный URL или data:\{MIME_type};base64,... URL.
  driving_audio (WAV/MP3, 2-30 секунд, не более 15MB) и first_clip (MP4/MOV, 2-10
  секунд, 240-4096 пикселей по стороне, не более 100MB): публичный HTTP/HTTPS URL;
  встроенный data: URL не принимается.
- wan2.7-r2v: first_frame (необязательно, макс. 1), reference_image, reference_video.
  Требуется хотя бы один reference_image или reference_video, а reference_image и
  reference_video в сумме дают не более 5. first_frame и reference_image:
  JPEG/JPG/PNG/BMP/WEBP (без альфа-канала), 240-8000 пикселей по стороне, соотношение
  сторон от 1:8 до 8:1, не более 20MB, публичный URL или data:\{MIME_type};base64,...
  URL. reference_video: публичный HTTP/HTTPS URL; встроенный data: URL не принимается.
- wan2.7-videoedit: video (ровно 1, редактируемый клип: MP4/MOV, 2-10 секунд,
  240-4096 пикселей по стороне, не более 100MB, публичный HTTP/HTTPS URL; встроенный
  data: URL не принимается) плюс необязательные от 0 до 4 reference_image
  (JPEG/JPG/PNG/BMP/WEBP, 240-8000 пикселей по стороне, соотношение сторон от 1:8 до
  8:1, не более 20MB, публичный URL или data:\{MIME_type};base64,... URL).
- wan3.0-video, wan3.0-video-prime: first_frame (макс. 1), last_frame (макс. 1),
  reference_image (макс. 10), reference_video (макс. 5 клипов, суммарная длительность
  \<= 15s), reference_audio (макс. 5 клипов, суммарная длительность \<= 15s), file
  (макс. 1, нельзя использовать вместе с link), link (макс. 1, нельзя использовать
  вместе с file). Типы reference_*/file/link и типы first_frame/last_frame взаимно
  исключают друг друга в одном запросе. Порядок в массиве задаёт порядок ссылок на
  ассеты в промпте (Image 1, Video 1, Audio 1, ...). first_frame, last_frame и
  reference_image: JPEG/JPG/PNG/BMP/WEBP, 240-8000 пикселей по стороне, соотношение
  сторон не более 8:1, не более 20MB, публичный URL или
  data:\{MIME_type};base64,... URL. reference_video, reference_audio, file и link:
  публичный HTTP/HTTPS URL; встроенный data: URL не принимается.
- happyhorse-1.0-i2v, happyhorse-1.1-i2v: только first_frame, ровно 1. Эти варианты
  принимают первый кадр ЗДЕСЬ, а не в img_url. Не менее 300x300 пикселей, соотношение
  сторон от 1:2.5 до 2.5:1, JPEG/JPG/PNG/WEBP, не более 20MB, публичный URL или
  data:\{MIME_type};base64,... URL.
- happyhorse-1.0-r2v, happyhorse-1.1-r2v: только reference_image, от 1 до 9 штук. Это
  единственный референсный ввод модели. Короткая сторона не менее 400 пикселей,
  JPEG/JPG/PNG/WEBP, не более 20MB, публичный URL или data:\{MIME_type};base64,...
  URL. reference_video не является типом ввода для этой операции.
- happyhorse-1.0-video-edit: video (ровно 1, редактируемый клип: MP4/MOV, 3-60
  секунд, длинная сторона не более 4096 пикселей, короткая сторона не менее 360
  пикселей, соотношение сторон от 1:2.5 до 2.5:1, не более 100MB, публичный
  HTTP/HTTPS URL; встроенный data: URL не принимается) плюс необязательные от 0 до 5
  reference_image (JPEG/JPG/PNG/WEBP, не менее 300x300 пикселей, соотношение сторон от
  1:2.5 до 2.5:1, не более 20MB, публичный URL или
  data:\{MIME_type};base64,... URL).
- happyhorse-1.0-t2v, happyhorse-1.1-t2v, wan2.7-t2v, wan2.6-t2v, wan2.5-t2v-preview:
  операции текст в видео. В документации партнёра для них не описан ввод media,
  поэтому оставьте это поле незаданным.
- wan2.5-i2v-preview, wan2.6-i2v, wan2.6-r2v: этот компонент не перечисляет словарь
  media для этих вариантов. wan2.5-i2v-preview и wan2.6-i2v принимают первый кадр в
  img_url; wan2.6-r2v принимает свои референсные клипы в reference_video_urls.
Приведённые выше значения по моделям являются ограничениями партнёра, а не этой схемы:
на media не объявлены minItems/maxItems, потому что допустимые типы и их пределы
различаются по моделям. Принятие схемой не означает принятия провайдером, а в обратную
сторону: приведённые выше значения «не более 20MB» для каждого ассета (предел для
входов изображений, единственных входов, которые можно отправлять встроенными)
являются пределом партнёра для ассета, который он в итоге получает, и они действуют в
точности так, когда ассет является публичным URL, потому что эти байты никогда не
проходят через Comfy. Встроенный data:\{MIME_type};base64,... URL проходит через Comfy
и тоже сталкивается с транспортным пределом: тело POST-запроса в Comfy Router
ограничено 100 MiB в сумме, а при превышении возвращается ответ 413, и base64
увеличивает полезную нагрузку примерно в 4/3 раза, поэтому один встроенный ассет
размером примерно выше 75 MB отклоняется ещё до того, как сработает любое из
описанных здесь правил партнёра. При таком размере один ассет при собственном лимите
партнёра20MB свободно укладывается в inline, поэтому для одного ассета ограничивающим оказывается правило партнёра. А при нескольких ассетах ограничивает транспортный потолок: лимит Router в 100 MiB ограничивает ВЕСЬ запрос, а не каждый элемент. Всё, что приближается к этим потолкам, отправляйте как публичный URL.
</ParamField>

<ParamField body="input.media[].url" type="string" required>
  URL медиафайла: публичный HTTP/HTTPS URL или, строго для тех входов IMAGE, которые перечислены для каждой модели в описании `media` выше (first_frame и last_frame у wan2.7-i2v; first_frame и reference_image у wan2.7-r2v; reference_image у wan2.7-videoedit; first_frame, last_frame и reference_image у wan3.0-video и wan3.0-video-prime; first_frame у happyhorse-1.0-i2v и happyhorse-1.1-i2v; reference_image у happyhorse-1.0-r2v и happyhorse-1.1-r2v; и reference_image у happyhorse-1.0-video-edit), встроенный URL `data:{MIME_type};base64,...`. Ни один вход video, audio, file или link ни в одной из этих моделей не принимает встроенный URL data:. Временный URL oss://dashscope-instant из собственного сервиса загрузки партнёра или (в wan2.7-videoedit) asset_id из Asset Center разрешается только для той учётной записи Alibaba Cloud, которая его загрузила; Comfy вызывает модель со своим ключом и не предоставляет маршрута загрузки, поэтому собственный oss:// URL или asset_id вызывающей стороны не поддерживается как вход. Это поле не проверяет схему URL, поэтому такое значение передаётся партнёру как есть, а не отклоняется здесь. Ограничения размера и пикселей для каждой модели, а также лимит тела запроса Router в 100 MiB, который в совокупности ограничивает встроенную нагрузку, см. в описании `media`.
</ParamField>

<ParamField body="input.negative_prompt" type="string">
  Слова обратного промпта описывают содержимое, которое вы не хотите видеть на экране видео. После 500 символов модель wan обрезает его, а не отклоняет запрос. Они учитываются в том же бюджете входа, что и промпт.
</ParamField>

<ParamField body="input.prompt" type="string">
  Текстовые слова промпта. Поддерживаются китайский и английский. После собственной документированной длины модель wan2.x обрезает промпт, а не отклоняет его: 1,500 символов для wan2.5 и wan2.6 и 5,000 для wan2.7. wan3.0-video и wan3.0-video-prime принимают не более 20,000 символов. Провайдер отклоняет запрос, у которого prompt и negative_prompt вместе длиннее примерно 60,850 байт текста UTF-8 (около 20,000 китайских символов), отвечая InvalidParameter `Range of input length should be [1, 61440]`.
Для wan2.6-r2v с несколькими референсными видео используйте 'character1', 'character2' и т. д., чтобы ссылаться на субъекты в порядке референсных видео. Пример: «Character1 sings on the roadside, Character2 dances beside it»
Для режима reference у wan3.0-video используйте 'Image 1', 'Video 1', 'Audio 1' и т. д., чтобы ссылаться на медиафайлы в соответствующем порядке внутри массива media.
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  URL референсных видео только для модели wan2.6-r2v. Массив из 1-3 URL видео.
Ограничения входа:
- Формат: mp4, mov
- Количество: 1-3 видео
- Длина одного видео: 2-30 секунд
- Размер одного файла: максимум 30MB
- Нельзя использовать вместе с audio_url
Длительность референса: одно видео максимум 5s, два видео максимум по 2.5s каждое, три видео пропорционально меньше.
Выставление счетов: исходя из фактически использованной длительности референса.
</ParamField>

<ParamField body="input.template" type="string">
  Название шаблона видеоэффекта. Необязательно. Сейчас поддерживаются: squish, flying, carousel. При использовании параметр prompt игнорируется.
</ParamField>

<ParamField body="model" type="string">

<ParamField body="parameters.duration" type="integer" default="5">

- модели wan2.5: 5 или 10 секунд
- wan2.6-t2v, wan2.6-i2v: 5, 10 или 15 секунд
- wan2.6-r2v: только 5 или 10 секунд (без поддержки 15s)
- wan2.7-i2v, wan2.7-t2v: целое число в [2, 15]
- wan2.7-r2v, wan2.7-videoedit: целое число в [2, 10]
- wan3.0-video: целое число в [2, 30] без видео на входе; с видео на входе суммарная

  режим умной длительности, в котором модель сама подбирает подходящую длительность

</ParamField>

Для моделей wan2.7 по умолчанию определяется уровнем разрешения, если не указано.
Для wan3.0-video adaptive (по умолчанию) автоматически рекомендует подходящеесоотношение сторон на основе пропорций входного медиафайла и замысла.

  Возможные значения: `adaptive`, `16:9`, `9:16`, `1:1`, `4:3`, `3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  Уровень разрешения. Поддерживаемые значения зависят от модели:
- wan2.5-i2v-preview: 480P, 720P, 1080P
- модели wan2.6 (t2v, i2v, r2v): только 720P, 1080P (без поддержки 480P)
- модели wan2.7 (i2v, t2v, r2v, videoedit): 720P, 1080P (по умолчанию 1080P)
- wan3.0-video, wan3.0-video-prime: 480P, 720P, 1080P (по умолчанию у провайдера 1080P)
- happyhorse-1.0-* (t2v, i2v, r2v, video-edit): 720P, 1080P
- happyhorse-1.1-* (t2v, i2v, r2v): 480P, 720P, 1080P
Этот прокси отклоняет запросы на генерацию видео, в которых не указаны ни
resolution, ни size, поскольку уровень разрешения определяет тариф выставления
счетов. Он приводит resolution к верхнему регистру перед проверкой и передаёт
значение в верхнем регистре, возвращает 400 для значения вне этого перечисления
и возвращает 400 для 480P (независимо от того, передано ли оно как resolution
или как size 480P) для моделей wan2.6, wan2.7 и happyhorse-1.0, перечисленных
выше как не поддерживающие 480P.

  Возможные значения: `480P`, `720P`, `1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">

</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">

Для моделей wan2.6 и wan2.7-r2v.
- single: видео с одним планом (по умолчанию)
- multi: видео с несколькими планами

  Возможные значения: `multi`, `single`
</ParamField>

<ParamField body="parameters.size" type="string">
  Разрешение видео в формате ширина*высота. Поддерживаемые разрешения зависят от модели:
Для wan2.5 T2V: размеры 480P (480*832, 832*480, 624*624), 720P, 1080P
Для wan2.6 T2V/R2V (без 480P):
  720P: 1280*720, 720*1280, 960*960, 1088*832, 832*1088
  1080P: 1920*1080, 1080*1920, 1440*1440, 1632*1248, 1248*1632
Когда переданы и size, и resolution, тариф определяет size, а
resolution всё равно должно быть значением, которое этот прокси принимает для
модели. Size 480P возвращает 400 на каждой модели, для которой в описании
resolution указано отсутствие 480P.
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">

</ParamField>
