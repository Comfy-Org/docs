Справочник по API для Wan 2.6 I2V. Wan 2.6 в режиме изображение в видео анимирует статичный первый кадр в разрешении 720P или 1080P и длительностью до 15 секунд.

**Вход:** Изображение, Аудио, Текст · **Выход:** Видео + Аудио

## Быстрый старт

Создайте ключ в [вашем рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. Фрагменты Python и TypeScript используют Comfy SDK (`pip install comfy-sdk` и `npm install @comfyorg/sdk`); фрагмент cURL выполняет тот же вызов по обычному HTTP.

**ID модели:** `wan/wan2.6-i2v`

**Эндпоинт:** `POST https://api.comfy.org/v2/models/wan/wan2.6-i2v`

Тот же текст запроса, отправленный на `POST https://api.comfy.org/v2/models/wan/wan2.6-i2v/requests`. Router отвечает `201` с `request_id`, как только запуск принят, а результат забирается, когда он готов, из этого или другого процесса. [Доставка через очередь](/ru/development/comfy-router/queue) описывает статус, отмену и получение результата.

<CodeGroup>
```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменных окружения.
# Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его при автоматических повторах.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/wan2.6-i2v",
            {
                "input": {
                    "prompt": "the robot lowers its raised arm and steps toward the camera, the flat orange backdrop holds steady",
                    "img_url": "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивать до завершения запроса, выдерживая Retry-After, который указывает сервер.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственный payload провайдера, то же значение, что возвращает models.run().
        # Запрос, который завершился ошибкой или был отменён, вызывает здесь типизированную ошибку Router.
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Читает COMFY_API_KEY из переменных окружения.
// Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его при автоматических повторах.
type Result = { output: { video_url: string } };
const handle = await comfy.models.submit<Result>("wan/wan2.6-i2v", {
  input: {
    prompt: "the robot lowers its raised arm and steps toward the camera, the flat orange backdrop holds steady",
    img_url: "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
  },
  parameters: {
    resolution: "720P",
    duration: 5,
  },
});
console.log("requestId:", handle.requestId); // вместе с ID модели это всё, что нужно другому процессу

// Опрашивать до завершения запроса, выдерживая Retry-After, который указывает сервер.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// Тот же результат, что возвращает models.run(). Запрос, который завершился ошибкой или был отменён, отклоняется здесь.
const result = await handle.get();
if (result.kind !== "json") throw new Error("expected a JSON result");

console.log("video:", result.data.output.video_url);
```

# 3. Получение. 200 с собственным выводом модели, 202 с телом статуса, пока запрос ещё выполняется.

### Входы

<ParamField body="input" type="object" required>
  Введите основную информацию, например промпт, и т. д.
</ParamField>

<ParamField body="input.audio_url" type="string">
  URL для скачивания аудиофайла. Поддерживаемые форматы: mp3 и wav. Нельзя использовать вместе с reference_video_urls.
</ParamField>

<ParamField body="input.img_url" type="string">
  URL изображения первого кадра или данные в кодировке Base64. Обязательно для моделей wan2.5-i2v-preview и
wan2.6-i2v. Варианты happyhorse-1.x i2v НЕ принимают первый кадр здесь:
они принимают его как медиаэлемент типа first_frame (см. media ниже), а тело запроса с
img_url, которое успешно работает на wan2.6-i2v, отклоняется провайдером на
happyhorse-1.0-i2v и happyhorse-1.1-i2v; варианты wan2.7/wan3.0 также принимают свои
референсные ассеты в media. Форматы изображений: JPEG, JPG, PNG, BMP, WEBP.
Разрешение: 360-2000 пикселей. Размер файла: не более 10MB.
</ParamField>

<ParamField body="input.media" type="object[]">
  Список медиаассетов. Задаёт референсные материалы (изображение, аудио, видео) для
генерации видео. Каждый элемент содержит поля type и url. Это поле используется всеми
моделями, которые обслуживает данный компонент, а то, какие значения type принимает
конкретная модель и передаёт ли она вообще свой ввод изображения или видео здесь, а не
в img_url или reference_video_urls, зависит от модели. Поддерживаемые значения type по
моделям:
- wan2.7-i2v: first_frame, last_frame, driving_audio, first_clip. first_frame и
  last_frame: JPEG/JPG/PNG/BMP/WEBP, 240-8000 пикселей по каждой стороне, соотношение сторон от 1:8
  до 8:1, не более 20MB, публичный URL или URL вида data:\{MIME_type};base64,....
  driving_audio (WAV/MP3, 2-30 секунд, не более 15MB) и first_clip (MP4/MOV, 2-10
  секунд, 240-4096 пикселей по каждой стороне, не более 100MB): публичный URL HTTP/HTTPS; встроенный
  data: URL не принимается.
- wan2.7-r2v: first_frame (необязательно, макс. 1), reference_image, reference_video. Требуется хотя бы
  один reference_image или reference_video, а суммарно референсных изображений и
  референсных видео не более 5. first_frame и reference_image: JPEG/JPG/PNG/BMP/WEBP
  (без альфа-канала), 240-8000 пикселей по каждой стороне, соотношение сторон от 1:8 до 8:1, не более
  20MB, публичный URL или URL вида data:\{MIME_type};base64,.... reference_video: публичный
  URL HTTP/HTTPS; встроенный data: URL не принимается.
- wan2.7-videoedit: video (ровно 1, редактируемый клип: MP4/MOV, 2-10 секунд,
  240-4096 пикселей по каждой стороне, не более 100MB, публичный URL HTTP/HTTPS; встроенный data: URL
  не принимается) плюс необязательный набор от 0 до 4 reference_image (JPEG/JPG/PNG/BMP/WEBP,
  240-8000 пикселей по каждой стороне, соотношение сторон от 1:8 до 8:1, не более 20MB, публичный URL
  или URL вида data:\{MIME_type};base64,...).
- wan3.0-video, wan3.0-video-prime: first_frame (макс. 1), last_frame (макс. 1),
  reference_image (макс. 10), reference_video (макс. 5 клипов, суммарная длительность \<= 15s),
  reference_audio (макс. 5 клипов, суммарная длительность \<= 15s), file (макс. 1, нельзя использовать
  вместе с link), link (макс. 1, нельзя использовать вместе с file). Типы reference_*/file/link
  и типы first_frame/last_frame взаимно исключают друг друга в одном запросе. Порядок
  в массиве задаёт порядок референсных ассетов в промпте (Image 1, Video 1,
  Audio 1, ...). first_frame, last_frame и reference_image: JPEG/JPG/PNG/BMP/WEBP,
  240-8000 пикселей по каждой стороне, соотношение сторон не более 8:1, не более 20MB, публичный URL или
  URL вида data:\{MIME_type};base64,.... reference_video, reference_audio, file и link: публичный
  URL HTTP/HTTPS; встроенный data: URL не принимается.
- happyhorse-1.0-i2v, happyhorse-1.1-i2v: только first_frame, ровно 1. Эти варианты
  принимают первый кадр ЗДЕСЬ, а не в img_url. Не менее 300x300 пикселей, соотношение сторон
  от 1:2.5 до 2.5:1, JPEG/JPG/PNG/WEBP, не более 20MB, публичный URL или URL вида
  data:\{MIME_type};base64,....
- happyhorse-1.0-r2v, happyhorse-1.1-r2v: только reference_image, от 1 до 9 штук. Это
  единственный референсный ввод модели. Наименьшая сторона не менее 400 пикселей, JPEG/JPG/PNG/WEBP,
  не более 20MB, публичный URL или URL вида data:\{MIME_type};base64,.... reference_video
  не является типом ввода для этой операции.
- happyhorse-1.0-video-edit: video (ровно 1, редактируемый клип: MP4/MOV, 3-60
  секунд, длинная сторона не более 4096 пикселей, короткая сторона не менее 360 пикселей, соотношение
  сторон от 1:2.5 до 2.5:1, не более 100MB, публичный URL HTTP/HTTPS; встроенный data:
  URL не принимается) плюс необязательный набор от 0 до 5 reference_image (JPEG/JPG/PNG/WEBP, не
  менее 300x300 пикселей, соотношение сторон от 1:2.5 до 2.5:1, не более 20MB, публичный URL
  или URL вида data:\{MIME_type};base64,...).
- happyhorse-1.0-t2v, happyhorse-1.1-t2v, wan2.7-t2v, wan2.6-t2v, wan2.5-t2v-preview:
  операции текст в видео. В документации партнёра для них не описан медиавход, поэтому оставьте
  это поле незаданным.
- wan2.5-i2v-preview, wan2.6-i2v, wan2.6-r2v: для этих вариантов компонент не перечисляет
  никакого набора медиатипов. wan2.5-i2v-preview и wan2.6-i2v принимают первый
  кадр в img_url; wan2.6-r2v принимает референсные клипы в reference_video_urls.
Приведённые выше ограничения по моделям являются ограничениями партнёра, а не этой схемы: для
media не объявлены minItems/maxItems, поскольку допустимые типы и их лимиты
различаются по моделям. Принятие схемой не означает принятия провайдером. И наоборот:
указанные выше для каждого ассета значения «не более 20MB» (потолок для входов-изображений,
единственных входов, которые можно передавать встроенно) являются потолком партнёра для
ассета, который к нему в итоге попадает, и они действуют в указанном виде, когда ассет задан публичным URL,
поскольку эти байты никогда не проходят через Comfy. Встроенный URL вида data:\{MIME_type};base64,...
проходит через Comfy и тоже встречает транспортный потолок: тело POST-запроса в Comfy Router
ограничено 100 MiB в сумме, и при превышении возвращается 413, а base64 увеличивает
полезную нагрузку примерно в 4/3 раза, поэтому один встроенный ассет размером примерно выше 75 MB отклоняется ещё до того, как
начинают действовать какие-либо из правил партнёра. При таком размере один ассет при собственном20MB потолок спокойно вмещает inline-данные, поэтому для одного актива ограничивающим становится правило партнёра: транспортный потолок начинает действовать, когда активов несколько, так как лимит Router в 100 MiB ограничивает ВЕСЬ запрос, а не каждый элемент. Всё, что близко к этим потолкам, отправляйте в виде публичного URL.
</ParamField>

  Тип медиафайла

  Возможные значения: `first_frame`, `last_frame`, `driving_audio`, `first_clip`, `reference_image`, `reference_video`, `reference_audio`, `video`, `file`, `link`

<ParamField body="input.media[].url" type="string" required>
  URL медиафайла: публичный HTTP/HTTPS URL или, ровно для тех ВХОДОВ ИЗОБРАЖЕНИЙ, которые перечислены в описании `media` выше для каждой модели: first_frame и last_frame на wan2.7-i2v; first_frame и reference_image на wan2.7-r2v; reference_image на wan2.7-videoedit; first_frame, last_frame и reference_image на wan3.0-video и wan3.0-video-prime; first_frame на happyhorse-1.0-i2v и happyhorse-1.1-i2v; reference_image на happyhorse-1.0-r2v и happyhorse-1.1-r2v; и reference_image на happyhorse-1.0-video-edit, inline-URL `data:{MIME_type};base64,...`. Ни один вход видео, аудио, файла или ссылки ни в одной из этих моделей не принимает inline data: URL. Временный URL `oss://dashscope-instant` из собственного сервиса загрузки партнёра или (на wan2.7-videoedit) asset_id из Asset Center разрешается только в том аккаунте Alibaba Cloud, который его загрузил; Comfy вызывает модель своим собственным ключом и не предоставляет маршрут загрузки, поэтому собственный URL oss:// или asset_id вызывающей стороны не является поддерживаемым входом. Это поле не проверяет схему URL, поэтому такое значение передаётся партнёру как есть, а не отклоняется здесь. См. описание `media` для ограничений по размеру и пикселям для каждой модели, а также для лимита Router в 100 MiB на тело запроса, который ограничивает inline-полезную нагрузку в совокупности.
</ParamField>

<ParamField body="input.negative_prompt" type="string">
  Слова обратного промпта описывают содержимое, которое вы не хотите видеть на экране видео. После 500 символов модель wan обрезает их, а не отклоняет. Они учитываются в том же бюджете входа, что и промпт.
</ParamField>

<ParamField body="input.prompt" type="string">
  Текст промпта. Поддерживаются китайский и английский. После собственной документированной длины модель wan2.x обрезает промпт, а не отклоняет его: 1 500 символов для wan2.5 и wan2.6 и 5 000 для wan2.7. wan3.0-video и wan3.0-video-prime принимают не более 20 000 символов. Провайдер отклоняет запрос, в котором prompt и negative_prompt вместе длиннее примерно 60 850 байт текста UTF-8 (около 20 000 китайских символов), отвечая InvalidParameter `Range of input length should be [1, 61440]`.
Для wan2.6-r2v с несколькими референсными видео используйте 'character1', 'character2' и т.д., чтобы ссылаться на субъекты в порядке референсных видео. Пример: «Character1 поёт у дороги, Character2 танцует рядом»
Для режима reference у wan3.0-video используйте 'Image 1', 'Video 1', 'Audio 1' и т.д., чтобы ссылаться на медиафайлы в соответствующем порядке внутри массива media.
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  URL референсных видео только для модели wan2.6-r2v. Массив из 1-3 URL видео.
Ограничения на вход:
- Формат: mp4, mov
- Количество: 1-3 видео
- Длительность одного видео: 2-30 секунд
- Размер одного файла: не более 30MB
- Нельзя использовать вместе с audio_url
Длительность референса: одно видео максимум 5s, два видео максимум 2.5s каждое, три видео пропорционально меньше.
Выставление счетов: на основе фактически использованной длительности референса.
</ParamField>

<ParamField body="input.template" type="string">
  Название шаблона видеоэффекта. Необязательно. Сейчас поддерживаются: squish, flying, carousel. При использовании параметр prompt игнорируется.
</ParamField>

<ParamField body="model" type="string">
  ID вызываемой модели. НЕ ограничен на этом компоненте: Comfy Router заполняет его из сегмента пути `{model}` запроса `POST /v2/models/wan/{model}`, поэтому вызывающая сторона Router его опускает. Прямой вызов v1 на `POST /proxy/wan/api/v1/services/aigc/video-generation/video-synthesis` ОБЯЗАН его передавать, а перечисление допустимых написаний находится в собственном компоненте этой операции, `WanVideoGenerationRequest`.
</ParamField>

<ParamField body="parameters" type="object">
  Параметры обработки видео
</ParamField>

<ParamField body="parameters.audio" type="boolean" default="true">
  Добавлять ли аудио к видео. Поддерживается только для wan3.0-video и wan3.0-video-prime; для остальных моделей wan провайдер такой переключатель не документирует.
</ParamField>

<ParamField body="parameters.audio_setting" type="string" default="&quot;auto&quot;">
  Настройка аудио видео для модели wan2.7-videoedit.
- auto (по умолчанию): модель разумно определяет на основе содержимого промпта
- origin: принудительно сохранить оригинальное аудио из входного видео

  Возможные значения: `auto`, `origin`
</ParamField>

<ParamField body="parameters.duration" type="integer" default="5">
  Длительность сгенерированного видео в секундах:
- модели wan2.5: 5 или 10 секунд
- wan2.6-t2v, wan2.6-i2v: 5, 10 или 15 секунд
- wan2.6-r2v: только 5 или 10 секунд (без поддержки 15s)
- wan2.7-i2v, wan2.7-t2v: целое число в [2, 15]
- wan2.7-r2v, wan2.7-videoedit: целое число в [2, 10]
- wan3.0-video: целое число в [2, 30] без видео на входе; с видео на входе суммарная
  длительность входного видео + длительность выходного видео не должна превышать 30 секунд; -1 включает
  режим умной длительности, когда модель выбирает подходящую длительность
Этот прокси возвращает 400 для длительности вне [-1, 30].

  Диапазон: от `-1` до `30`
</ParamField>

<ParamField body="parameters.prompt_extend" type="boolean" default="true">
  Включено ли интеллектуальное переписывание промпта. По умолчанию true
</ParamField>

<ParamField body="parameters.ratio" type="string">
  Соотношение сторон сгенерированного видео. Только для моделей wan2.7 и wan3.0.
Для моделей wan2.7, если не указано, значение по умолчанию основано на уровне разрешения.
Для wan3.0-video значение adaptive (по умолчанию) автоматически рекомендует подходящееaspect ratio based on the input media proportions and intent.

  Возможные значения: `adaptive`, `16:9`, `9:16`, `1:1`, `4:3`, `3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  Уровень разрешения. Поддерживаемые значения зависят от модели:
- wan2.5-i2v-preview: 480P, 720P, 1080P
- модели wan2.6 (t2v, i2v, r2v): только 720P, 1080P (480P не поддерживается)
- модели wan2.7 (i2v, t2v, r2v, videoedit): 720P, 1080P (по умолчанию 1080P)
- wan3.0-video, wan3.0-video-prime: 480P, 720P, 1080P (по умолчанию у провайдера 1080P)
- happyhorse-1.0-* (t2v, i2v, r2v, video-edit): 720P, 1080P
- happyhorse-1.1-* (t2v, i2v, r2v): 480P, 720P, 1080P
Этот прокси отклоняет запросы на генерацию видео, в которых не указаны ни
resolution, ни size, поскольку уровень разрешения определяет тариф
выставления счетов. Перед проверкой он переводит resolution в верхний регистр
и передаёт значение в верхнем регистре, возвращает 400 для значения вне этого
перечисления и возвращает 400 для 480P (независимо от того, передан ли он как
resolution или как size 480P) для моделей wan2.6, wan2.7 и happyhorse-1.0,
перечисленных выше как не поддерживающие 480P.

  Возможные значения: `480P`, `720P`, `1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  Зерно случайного числа, используется для управления случайностью
сгенерированного моделью содержимого

  Диапазон: от `0` до `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  Интеллектуальное управление несколькими ракурсами. Активно только при
включённом prompt_extend. Для моделей wan2.6 и wan2.7-r2v.
- single: видео с одним планом (по умолчанию)
- multi: видео с несколькими планами

  Возможные значения: `multi`, `single`
</ParamField>

<ParamField body="parameters.size" type="string">
  Разрешение видео в формате ширина*высота. Поддерживаемые разрешения зависят
от модели:
Для wan2.5 T2V: размеры 480P (480*832, 832*480, 624*624), 720P, 1080P
Для wan2.6 T2V/R2V (без 480P):
  720P: 1280*720, 720*1280, 960*960, 1088*832, 832*1088
  1080P: 1920*1080, 1080*1920, 1440*1440, 1632*1248, 1248*1632
Если переданы и size, и resolution, то тариф для выставления счетов выбирает
size, а resolution всё равно должен быть значением, которое этот прокси
принимает для модели. Size 480P возвращает 400 на каждой модели, которая в
описании resolution указана как не поддерживающая 480P.
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  Добавлять ли логотип водяного знака; водяной знак располагается в правом
нижнем углу
</ParamField>

Сгенерировано из схемы, которую Router предоставляет по адресу `GET /v2/models/wan/wan2.6-i2v/openapi.json`, того же документа, по которому он проверяет вызов перед тем, как запрос доходит до провайдера.
