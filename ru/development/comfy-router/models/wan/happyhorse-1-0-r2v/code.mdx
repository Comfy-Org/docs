Справочник по API для HappyHorse 1.0 R2V. Режим reference-to-video в HappyHorse 1.0 сохраняет субъектов одного или нескольких референсных изображений неизменными в новой сцене; в промпте к ним обращаются как character1, character2 и так далее.

**Вход:** изображение, текст · **Выход:** видео

## Быстрый старт

Создайте ключ в [вашем рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. Фрагменты для Python и TypeScript используют Comfy SDK (`pip install comfy-sdk` и `npm install @comfyorg/sdk`); фрагмент cURL выполняет тот же вызов по обычному HTTP.

**ID модели:** `wan/happyhorse-1.0-r2v`

**Эндпоинт:** `POST https://api.comfy.org/v2/models/wan/happyhorse-1.0-r2v`

```python Python
# Читает COMFY_API_KEY из переменной окружения.

async def main():

            {

                        {
                            "type": "reference_image",

                    ],
                },

                    "duration": 5,
                },
            },
        )

    print("video:", result["output"]["video_url"])

asyncio.run(main())
```

То же самое тело запроса, отправленное на `POST https://api.comfy.org/v2/models/wan/happyhorse-1.0-r2v/requests`. Router отвечает `201` с `request_id`, как только запуск принят, а результат забирается, когда он готов, из этого процесса или из любого другого. Раздел [Доставка через очередь](/ru/development/comfy-router/queue) описывает статус, отмену и получение результата.

<CodeGroup>
```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменных окружения.
# Каждый вызов submit() создаёт свой Idempotency-Key и переиспользует его при автоматических повторах.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/happyhorse-1.0-r2v",
            {
                "input": {
                    "prompt": "character1 walks in from the left, turns to the camera and waves, plain orange backdrop",
                    "media": [
                        {
                            "type": "reference_image",
                            "url": "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивайте, пока запрос не завершится, выдерживая Retry-After, указанный сервером.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственный ответ провайдера, то же значение, что возвращает models.run().
        # Запрос, который завершился ошибкой или был отменён, вызывает здесь типизированную ошибку Router.
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Читает COMFY_API_KEY из переменных окружения.
// Каждый вызов submit() создаёт свой Idempotency-Key и переиспользует его при автоматических повторах.
type Result = { output: { video_url: string } };
const handle = await comfy.models.submit<Result>("wan/happyhorse-1.0-r2v", {
  input: {
    prompt: "character1 walks in from the left, turns to the camera and waves, plain orange backdrop",
    media: [
      {
        type: "reference_image",
        url: "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
      },
    ],
  },
  parameters: {
    resolution: "720P",
    duration: 5,
  },
});
console.log("requestId:", handle.requestId); // вместе с ID модели это всё, что нужно другому процессу

// Опрашивайте, пока запрос не завершится, выдерживая Retry-After, указанный сервером.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// Тот же результат, что возвращает models.run(). Запрос, который завершился ошибкой или был отменён, отклоняется здесь.
const result = await handle.get();
if (result.kind !== "json") throw new Error("expected a JSON result");

console.log("video:", result.data.output.video_url);
```

```bash cURL
# 1. Отправка. Router отвечает 201 с request_id, status_url, response_url и cancel_url.
curl https://api.comfy.org/v2/models/wan/happyhorse-1.0-r2v/requests \
  -H "X-API-Key: $COMFY_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d "{\"input\": {\"prompt\":\"character1 walks in from the left, turns to the camera and waves, plain orange backdrop\",\"media\":[{\"type\":\"reference_image\",\"url\":\"https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png\"}]}, \"parameters\": {\"resolution\":\"720P\",\"duration\":5}}"

# 2. Опрашивайте, пока статус не станет COMPLETED, выдерживая Retry-After секунд, указанные в каждом ответе.
REQUEST_ID="<request_id from the 201 body>"
curl -i https://api.comfy.org/v2/models/wan/happyhorse-1.0-r2v/requests/$REQUEST_ID/status \
  -H "X-API-Key: $COMFY_API_KEY"

# 3. Получение. 200 с нативным выводом модели, 202 с телом статуса, пока запрос ещё выполняется.
curl https://api.comfy.org/v2/models/wan/happyhorse-1.0-r2v/requests/$REQUEST_ID \
  -H "X-API-Key: $COMFY_API_KEY"
```

## Схема

### Входы

<ParamField body="input" type="object" required>
  Введите базовую информацию, например промпт и т. п.
</ParamField>

<ParamField body="input.audio_url" type="string">
  URL для скачивания аудиофайла. Поддерживаемые форматы: mp3 и wav. Нельзя использовать вместе с reference_video_urls.
</ParamField>

<ParamField body="input.img_url" type="string">
  URL изображения первого кадра или данные в кодировке Base64. Обязательно для моделей wan2.5-i2v-preview и
wan2.6-i2v. Варианты happyhorse-1.x i2v НЕ принимают первый кадр здесь:
они принимают его как медиаэлемент типа first_frame (см. media ниже), а тело запроса
с img_url, которое успешно проходит на wan2.6-i2v, провайдер отклоняет на
happyhorse-1.0-i2v и happyhorse-1.1-i2v; варианты wan2.7/wan3.0 также принимают свои
референсные ассеты в media. Форматы изображений: JPEG, JPG, PNG, BMP, WEBP.
Разрешение: 360-2000 пикселей. Размер файла: макс. 10 МБ.
</ParamField>

<ParamField body="input.media" type="object[]">
  Список медиаассетов. Задаёт референсные материалы (изображение, аудио, видео) для
генерации видео. Каждый элемент содержит поля type и url. Это поле общее для всех
моделей, обслуживаемых этим компонентом, а то, какие значения type принимает
конкретная модель и передаёт ли она свой ввод изображения или видео именно здесь, а
не в img_url или reference_video_urls, зависит от модели. Поддерживаемые значения
type, по моделям:
- wan2.7-i2v: first_frame, last_frame, driving_audio, first_clip. first_frame и
  last_frame: JPEG/JPG/PNG/BMP/WEBP, 240-8000 пикселей по каждой стороне, соотношение
  сторон от 1:8 до 8:1, максимум 20 МБ, публичный URL или URL вида
  data:\{MIME_type};base64,... . driving_audio (WAV/MP3, 2-30 секунд, максимум 15 МБ)
  и first_clip (MP4/MOV, 2-10 секунд, 240-4096 пикселей по каждой стороне, максимум
  100 МБ): публичный URL HTTP/HTTPS; встроенный URL data: не принимается.
- wan2.7-r2v: first_frame (необязательно, макс. 1), reference_image, reference_video.
  Требуется хотя бы один reference_image или reference_video, а референсные
  изображения и референсные видео в сумме дают не более 5. first_frame и
  reference_image: JPEG/JPG/PNG/BMP/WEBP (без альфа-канала), 240-8000 пикселей по
  каждой стороне, соотношение сторон от 1:8 до 8:1, максимум 20 МБ, публичный URL или
  URL вида data:\{MIME_type};base64,... . reference_video: публичный URL
  HTTP/HTTPS; встроенный URL data: не принимается.
- wan2.7-videoedit: video (ровно 1, редактируемый клип: MP4/MOV, 2-10 секунд,
  240-4096 пикселей по каждой стороне, максимум 100 МБ, публичный URL HTTP/HTTPS;
  встроенный URL data: не принимается) плюс необязательные от 0 до 4 reference_image
  (JPEG/JPG/PNG/BMP/WEBP, 240-8000 пикселей по каждой стороне, соотношение сторон от
  1:8 до 8:1, максимум 20 МБ, публичный URL или URL вида data:\{MIME_type};base64,...).
- wan3.0-video, wan3.0-video-prime: first_frame (макс. 1), last_frame (макс. 1),
  reference_image (макс. 10), reference_video (макс. 5 клипов, суммарная длительность
  \<= 15 с), reference_audio (макс. 5 клипов, суммарная длительность \<= 15 с), file
  (макс. 1, нельзя использовать вместе с link), link (макс. 1, нельзя использовать
  вместе с file). Типы reference_*/file/link и типы first_frame/last_frame взаимно
  исключают друг друга в одном запросе. Порядок в массиве задаёт порядок референсов
  ассетов в промпте (Image 1, Video 1, Audio 1, ...). first_frame, last_frame и
  reference_image: JPEG/JPG/PNG/BMP/WEBP, 240-8000 пикселей по каждой стороне,
  соотношение сторон не более 8:1, максимум 20 МБ, публичный URL или URL вида
  data:\{MIME_type};base64,... . reference_video, reference_audio, file и link:
  публичный URL HTTP/HTTPS; встроенный URL data: не принимается.
- happyhorse-1.0-i2v, happyhorse-1.1-i2v: только first_frame, ровно 1. Эти варианты
  принимают первый кадр ЗДЕСЬ, а не в img_url. Не менее 300x300 пикселей, соотношение
  сторон от 1:2.5 до 2.5:1, JPEG/JPG/PNG/WEBP, максимум 20 МБ, публичный URL или URL
  вида data:\{MIME_type};base64,... .
- happyhorse-1.0-r2v, happyhorse-1.1-r2v: только reference_image, от 1 до 9. Это
  единственный референсный ввод модели. Наименьшая сторона не менее 400 пикселей,
  JPEG/JPG/PNG/WEBP, максимум 20 МБ, публичный URL или URL вида
  data:\{MIME_type};base64,... . reference_video не является типом ввода для этой
  операции.
- happyhorse-1.0-video-edit: video (ровно 1, редактируемый клип: MP4/MOV, 3-60
  секунд, длинная сторона не более 4096 пикселей, короткая сторона не менее 360
  пикселей, соотношение сторон от 1:2.5 до 2.5:1, максимум 100 МБ, публичный URL
  HTTP/HTTPS; встроенный URL data: не принимается) плюс необязательные от 0 до 5
  reference_image (JPEG/JPG/PNG/WEBP, не менее 300x300 пикселей, соотношение сторон от
  1:2.5 до 2.5:1, максимум 20 МБ, публичный URL или URL вида
  data:\{MIME_type};base64,...).
- happyhorse-1.0-t2v, happyhorse-1.1-t2v, wan2.7-t2v, wan2.6-t2v, wan2.5-t2v-preview:
  операции текст в видео. В документации партнёра для них не описан ввод media,
  поэтому оставьте это поле незаданным.
- wan2.5-i2v-preview, wan2.6-i2v, wan2.6-r2v: для этих вариантов данный компонент не
  перечисляет никакого словаря media. wan2.5-i2v-preview и wan2.6-i2v принимают
  первый кадр в img_url; wan2.6-r2v принимает референсные клипы в
  reference_video_urls.
Приведённые выше значения количества для каждой модели относятся к ограничениям
партнёра, а не этой схемы: для media не объявлены ни minItems, ни maxItems, поскольку
допустимые типы и их лимиты различаются по моделям. Принятие схемой не означает
принятия провайдером; и, в обратную сторону, указанные выше для каждого ассета
значения «не более 20 МБ» (потолок для вводов изображений, единственных вводов,
которые можно передавать встроенно) являются потолком партнёра для ассета, который он
в итоге получает, и они действуют в том виде, в каком записаны, когда ассет является
публичным URL, потому что эти байты никогда не проходят через Comfy. Встроенный URL
data:\{MIME_type};base64,... проходит через Comfy и тоже упирается в транспортный
потолок: тело POST-запроса Comfy Router ограничено 100 МиБ в общей сложности, а при
превышении возвращается ответ 413, и base64 увеличивает полезную нагрузку примерно в
4/3 раза, поэтому один встроенный ассет размером свыше примерно 75 МБ отклоняется
ещё до того, как сработает какое-либо из описанных здесь правил партнёра. При таком
размере один ассет при собственном20MB ceiling fits inline comfortably, so the partner rule is what binds for one asset --
the transport ceiling binds across several of them, since the 100 MiB Router cap bounds
the WHOLE request rather than each element. Send anything near these ceilings as a
public URL.
</ParamField>

  Возможные значения: `first_frame`, `last_frame`, `driving_audio`, `first_clip`, `reference_image`, `reference_video`, `reference_audio`, `video`, `file`, `link`

<ParamField body="input.media[].url" type="string" required>
  URL медиафайла: публичный HTTP/HTTPS URL или, только для ВХОДОВ типа IMAGE, которые перечислены в описании `media` выше для каждой модели (first_frame и last_frame у wan2.7-i2v; first_frame и reference_image у wan2.7-r2v; reference_image у wan2.7-videoedit; first_frame, last_frame и reference_image у wan3.0-video и wan3.0-video-prime; first_frame у happyhorse-1.0-i2v и happyhorse-1.1-i2v; reference_image у happyhorse-1.0-r2v и happyhorse-1.1-r2v; и reference_image у happyhorse-1.0-video-edit), inline-URL `data:{MIME_type};base64,...`. Ни один вход video, audio, file или link ни в одной из этих моделей не принимает inline data: URL. Временный URL oss://dashscope-instant из собственного сервиса загрузки партнёра или (в wan2.7-videoedit) asset_id из Asset Center разрешается только для той учётной записи Alibaba Cloud, которая его загрузила; Comfy вызывает модель со своим ключом и не предоставляет маршрута для загрузки, поэтому собственный oss:// URL или asset_id вызывающей стороны не поддерживается как вход. Это поле не проверяет схему URL, поэтому такое значение передаётся партнёру как есть, а не отклоняется здесь. См. описание `media` для ограничений размера и пикселей по каждой модели и для лимита тела запроса Router в 100 MiB, который ограничивает inline-нагрузку в совокупности.
</ParamField>

<ParamField body="input.negative_prompt" type="string">
  Слова обратного промпта используются для описания содержимого, которое вы не хотите видеть в кадре видео. После 500 символов модель wan обрезает его, а не отклоняет запрос. Оно учитывается в том же бюджете ввода, что и prompt.
</ParamField>

<ParamField body="input.prompt" type="string">
  Текстовые слова промпта. Поддерживаются китайский и английский. После собственной документированной длины модель wan2.x обрезает промпт, а не отклоняет его: 1500 символов для wan2.5 и wan2.6 и 5000 для wan2.7. wan3.0-video и wan3.0-video-prime принимают не более 20 000 символов. Провайдер отклоняет запрос, у которого prompt и negative_prompt вместе длиннее примерно 60 850 байт текста UTF-8 (около 20 000 китайских символов), отвечая InvalidParameter `Range of input length should be [1, 61440]`.
Для wan2.6-r2v с несколькими референсными видео используйте 'character1', 'character2' и т. д., чтобы ссылаться на субъекты в порядке референсных видео. Пример: «Character1 поёт у дороги, Character2 танцует рядом».
Для режима reference у wan3.0-video используйте 'Image 1', 'Video 1', 'Audio 1' и т. д., чтобы ссылаться на медиафайлы в соответствующем порядке внутри массива media.
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  URL референсных видео только для модели wan2.6-r2v. Массив из 1-3 URL видео.
Ограничения ввода:
- Формат: mp4, mov
- Количество: 1-3 видео
- Длительность одного видео: 2-30 секунд
- Размер одного файла: не более 30 МБ
- Нельзя использовать вместе с audio_url
Длительность референса: одно видео не более 5 с, два видео не более 2,5 с каждое, три видео пропорционально меньше.
Выставление счетов: по фактически использованной длительности референса.
</ParamField>

<ParamField body="input.template" type="string">
  Имя шаблона видеоэффекта. Необязательно. Сейчас поддерживаются: squish, flying, carousel. При использовании параметр prompt игнорируется.
</ParamField>

<ParamField body="model" type="string">
  ID модели для вызова. <ParamField body="parameters.duration" type="integer" default="5">
  Длительность сгенерированного видео в секундах:
- модели wan2.5: 5 или 10 секунд
- wan2.6-t2v, wan2.6-i2v: 5, 10 или 15 секунд
- wan2.6-r2v: только 5 или 10 секунд (15 с не поддерживается)
- wan2.7-i2v, wan2.7-t2v: целое число в [2, 15]
- wan2.7-r2v, wan2.7-videoedit: целое число в [2, 10]
- wan3.0-video: целое число в [2, 30] без видеовхода; с видеовходом суммарная

  режим умной длительности, в котором модель подбирает подходящую длительность

Для моделей wan2.7 значение по умолчанию зависит от уровня разрешения, если оно не указано.
Для wan3.0-video значение adaptive (по умолчанию) автоматически рекомендует подходящееaspect ratio based on the input media proportions and intent.

  Возможные значения: `adaptive`, `16:9`, `9:16`, `1:1`, `4:3`, `3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  Уровень разрешения. Поддерживаемые значения зависят от модели:
- wan2.5-i2v-preview: 480P, 720P, 1080P
- модели wan2.6 (t2v, i2v, r2v): только 720P, 1080P (без поддержки 480P)
- модели wan2.7 (i2v, t2v, r2v, videoedit): 720P, 1080P (по умолчанию 1080P)
- wan3.0-video, wan3.0-video-prime: 480P, 720P, 1080P (по умолчанию у провайдера 1080P)
- happyhorse-1.0-* (t2v, i2v, r2v, video-edit): 720P, 1080P
- happyhorse-1.1-* (t2v, i2v, r2v): 480P, 720P, 1080P
Этот прокси отклоняет запросы на генерацию видео, в которых не указаны ни
resolution, ни size, поскольку уровень разрешения определяет тариф
выставления счетов. Он приводит resolution к верхнему регистру перед проверкой
и передаёт значение в верхнем регистре, возвращает 400 для значения вне этого
перечисления и возвращает 400 для 480P (независимо от того, передан ли он как
resolution или как size 480P) для моделей wan2.6, wan2.7 и happyhorse-1.0,
перечисленных выше как не поддерживающие 480P.

  Возможные значения: `480P`, `720P`, `1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  Зерно случайного числа, используется для управления случайностью

  Диапазон: `0` до `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  Интеллектуальное управление несколькими ракурсами. Активно только при
включённом prompt_extend. Для моделей wan2.6 и wan2.7-r2v.
- single: видео с одним кадром (по умолчанию)
- multi: видео с несколькими кадрами

  Возможные значения: `multi`, `single`
</ParamField>

<ParamField body="parameters.size" type="string">
  Разрешение видео в формате width*height. Поддерживаемые разрешения зависят от модели:
Для wan2.5 T2V: размеры 480P (480*832, 832*480, 624*624), 720P, 1080P
Для wan2.6 T2V/R2V (без 480P):
  720P: 1280*720, 720*1280, 960*960, 1088*832, 832*1088
  1080P: 1920*1080, 1080*1920, 1440*1440, 1632*1248, 1248*1632
Если переданы и size, и resolution, то тариф определяет size, а
resolution всё равно должен быть значением, которое этот прокси принимает
для модели. Size 480P возвращает 400 для каждой модели, которая в описании
resolution указана как не поддерживающая 480P.
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
