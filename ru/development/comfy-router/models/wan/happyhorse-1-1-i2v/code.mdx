Справочник по API для HappyHorse 1.1 I2V. Модель HappyHorse 1.1 для изображения в видео оживляет статичный первый кадр и за один проход создаёт синхронизированные диалоги, эффекты и музыку.

**Вход:** изображение, текст · **Выход:** видео

## Быстрый старт

Создайте ключ в [вашем рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. Примеры на Python и TypeScript используют Comfy SDK (`pip install comfy-sdk` и `npm install @comfyorg/sdk`); пример cURL выполняет тот же вызов напрямую через HTTP.

**ID модели:** `wan/happyhorse-1.1-i2v`

**Эндпоинт:** `POST https://api.comfy.org/v2/models/wan/happyhorse-1.1-i2v`

```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменных окружения.
# Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его при автоматических повторах.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/happyhorse-1.1-i2v",
            {
                "input": {
                    "prompt": "the robot lowers its raised arm and steps toward the camera, the flat orange backdrop holds steady",
                    "media": [
                        {
                            "type": "first_frame",
                            "url": "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивайте, пока запрос не завершится, выдерживая Retry-After, который указывает сервер.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственный payload провайдера, то же значение, которое возвращает models.run().
        # Запрос, который завершился ошибкой или был отменён, вызывает здесь типизированную ошибку Router.
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())
```

  кадр в img_url; wan2.6-r2v принимает свои референсные клипы в reference_video_urls.
Приведённые выше количественные ограничения по моделям относятся к партнёру, а не к этой схеме: на media не объявлены
minItems/maxItems, поскольку допустимые типы и их лимиты
различаются по моделям. Принятие схемой не означает принятия провайдером. И наоборот:
указанные выше для каждого ассета цифры «не более 20MB» (потолок для входов
изображений, единственных входов, которые можно передавать встроенно) являются потолком партнёра
для ассета, который он в итоге получает, и они действуют в том виде, как написано, когда ассет
является публичным URL, потому что эти байты никогда не проходят через Comfy. Встроенный
URL вида data:\{MIME_type};base64,... действительно проходит через Comfy и тоже упирается
в транспортный потолок: тело POST-запроса Comfy Router ограничено 100 MiB в сумме, а при его превышении
возвращается 413, и base64 увеличивает объём данных примерно в 4/3, поэтому один встроенный ассет
размером выше примерно 75 MB отклоняется ещё до того, как сработают какие-либо из правил партнёра
здесь. При таком размере один ассет при собственномПотолок в 20 МБ спокойно укладывается в inline, поэтому для одного ассета ограничивающим становится правило партнёра, а при нескольких ассетах начинает действовать потолок транспорта: лимит Router в 100 MiB ограничивает ВЕСЬ запрос, а не каждый элемент. Всё, что близко к этим потолкам, отправляйте как публичный URL.

<ParamField body="input.media[].url" type="string" required>
  URL медиафайла: публичный HTTP/HTTPS URL или, строго для тех ВХОДОВ ИЗОБРАЖЕНИЙ, которые перечислены выше в описании `media` для каждой модели: first_frame и last_frame на wan2.7-i2v; first_frame и reference_image на wan2.7-r2v; reference_image на wan2.7-videoedit; first_frame, last_frame и reference_image на wan3.0-video и wan3.0-video-prime; first_frame на happyhorse-1.0-i2v и happyhorse-1.1-i2v; reference_image на happyhorse-1.0-r2v и happyhorse-1.1-r2v; и reference_image на happyhorse-1.0-video-edit, inline-URL вида `data:{MIME_type};base64,...`. Ни один вход `video`, `audio`, `file` или `link` ни в одной из этих моделей не принимает inline data: URL. Временный URL oss://dashscope-instant из собственного сервиса загрузки партнёра или (в wan2.7-videoedit) asset_id из Asset Center разрешается только в той учётной записи Alibaba Cloud, которая его загрузила; Comfy вызывает модель со своим ключом и не предоставляет маршрут загрузки, поэтому собственный oss:// URL или asset_id вызывающей стороны не является поддерживаемым входом. Это поле не проверяет схему URL, поэтому такое значение передаётся партнёру как есть, а не отклоняется здесь. См. описание `media`, чтобы узнать ограничения по размеру и пикселям для каждой модели, а также лимит Router в 100 MiB на тело запроса, который суммарно ограничивает inline-нагрузку.

<ParamField body="input.prompt" type="string">
  Текст промпта. Поддерживаются китайский и английский. После собственной задокументированной длины модель wan2.x обрезает промпт, а не отклоняет его: 1 500 символов для wan2.5 и wan2.6 и 5 000 для wan2.7. wan3.0-video и wan3.0-video-prime принимают не более 20 000 символов. Провайдер отклоняет запрос, в котором промпт и negative_prompt вместе длиннее примерно 60 850 байт текста UTF-8 (около 20 000 китайских символов), отвечая InvalidParameter `Range of input length should be [1, 61440]`.
Для wan2.6-r2v с несколькими референсными видео используйте «character1», «character2» и т. д., чтобы ссылаться на субъекты в порядке референсных видео. Пример: «Character1 поёт на обочине, Character2 танцует рядом»
В режиме референса wan3.0-video используйте «Image 1», «Video 1», «Audio 1» и т. д., чтобы ссылаться на медиафайлы в соответствующем порядке внутри массива media.
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  URL референсных видео только для модели wan2.6-r2v. Массив из 1-3 URL видео.
Ограничения входа:
- Формат: mp4, mov
- Количество: 1-3 видео
- Длительность одного видео: 2-30 секунд
- Размер одного файла: не более 30MB
- Нельзя использовать вместе с audio_url
Референсная длительность: одно видео не более 5s, два видео не более 2.5s каждое, три видео пропорционально меньше.
Выставление счетов: исходя из фактически использованной референсной длительности.
</ParamField>

<ParamField body="input.template" type="string">

- модели wan2.6 (t2v, i2v, r2v): только 720P, 1080P (без поддержки 480P)
- модели wan2.7 (i2v, t2v, r2v, videoedit): 720P, 1080P (по умолчанию 1080P)
- wan3.0-video, wan3.0-video-prime: 480P, 720P, 1080P (по умолчанию у провайдера 1080P)

<ParamField body="parameters.size" type="string">

Для wan2.5 T2V: размеры 480P (480*832, 832*480, 624*624), 720P, 1080P
Для wan2.6 T2V/R2V (без 480P):
