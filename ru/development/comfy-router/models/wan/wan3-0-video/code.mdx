Справочник по API для Wan 3.0 Video. Wan 3.0 Video создаёт видео по одному промпту или по списку медиа: первый и последний кадры, референсные изображения, видео и аудио, на которые в промпте ссылаются как на Image 1, Video 1 и Audio 1.

**Вход:** текст, изображение, видео, аудио · **Выход:** видео + аудио

## Быстрый старт

Создайте ключ в [вашем рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. В фрагментах для Python и TypeScript используются Comfy SDK (`pip install comfy-sdk` и `npm install @comfyorg/sdk`); фрагмент cURL выполняет тот же вызов напрямую по HTTP.

**ID модели:** `wan/wan3.0-video`

**Эндпоинт:** `POST https://api.comfy.org/v2/models/wan/wan3.0-video`

# Читает COMFY_API_KEY из переменной окружения.

То же тело запроса, отправленное на `POST https://api.comfy.org/v2/models/wan/wan3.0-video/requests`. Router отвечает `201` с `request_id`, как только запуск принят, а результат забирается, когда он готов, из этого процесса или из другого. В разделе [Доставка через очередь](/ru/development/comfy-router/queue) разобраны статус, отмена и получение результата.

<CodeGroup>
```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменных окружения.
# Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его при автоматических повторах.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/wan3.0-video",
            {
                "input": {
                    "prompt": "the robot lowers its raised arm and steps toward the camera, the flat orange backdrop holds steady",
                    "media": [
                        {
                            "type": "first_frame",
                            "url": "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивайте, пока запрос не завершится, выдерживая Retry-After, указанный сервером.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственный payload провайдера, то же значение, которое возвращает models.run().
        # Запрос, который завершился ошибкой или был отменён, здесь возбуждает типизированную ошибку Router.
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Читает COMFY_API_KEY из переменных окружения.
// Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его при автоматических повторах.
type Result = { output: { video_url: string } };
const handle = await comfy.models.submit<Result>("wan/wan3.0-video", {
  input: {
    prompt: "the robot lowers its raised arm and steps toward the camera, the flat orange backdrop holds steady",
    media: [
      {
        type: "first_frame",
        url: "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
      },
    ],
  },
  parameters: {
    resolution: "720P",
    duration: 5,
  },
});
console.log("requestId:", handle.requestId); // вместе с ID модели это всё, что нужно другому процессу

// Опрашивайте, пока запрос не завершится, выдерживая Retry-After, указанный сервером.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// Тот же результат, который возвращает models.run(). Запрос, который завершился ошибкой или был отменён, отклоняется здесь.
const result = await handle.get();
if (result.kind !== "json") throw new Error("expected a JSON result");

console.log("video:", result.data.output.video_url);
```

## Провайдеры, обслуживающие модель

Эта модель обслуживается Comfy Router напрямую, если в запросе не указан другой провайдер. Приведённые ниже провайдеры также обслуживают её через ту же конечную точку и с тем же ID модели; провайдер выбирается параметром запроса `model_provider`.

- **Comfy** (по умолчанию): `POST https://api.comfy.org/v2/models/wan/wan3.0-video`
- **Higgsfield**, под именем `higgsfield/higgsfield-wan-3`: `POST https://api.comfy.org/v2/models/wan/wan3.0-video?model_provider=higgsfield`

`strict_mode` по умолчанию имеет значение false, поэтому Router преобразует нативное тело запроса, документированное на этой странице, в собственную схему провайдера и преобразует ответ обратно. См. [`model_provider`, `strict_mode` и `fallback_provider`](/ru/development/comfy-router/reference#post-v2modelsprovidermodel) в справочнике API, а также [Провайдеры, обслуживающие модель](/ru/development/comfy-router/providers), где перечислены все модели, маршрутизируемые таким образом.

### Входы

<ParamField body="input" type="object" required>
  Введите базовую информацию: промпт и т. д.
</ParamField>

<ParamField body="input.audio_url" type="string">
  URL для скачивания аудиофайла. Поддерживаемые форматы: mp3 и wav. Нельзя использовать вместе с reference_video_urls.
</ParamField>

<ParamField body="input.img_url" type="string">
  URL изображения первого кадра или данные в кодировке Base64. Обязателен для моделей
wan2.5-i2v-preview и wan2.6-i2v. Варианты happyhorse-1.x i2v НЕ принимают первый кадр
здесь: они принимают его как медиаэлемент типа first_frame (см. media ниже), а тело
запроса с img_url, которое успешно проходит на wan2.6-i2v, отклоняется провайдером на
happyhorse-1.0-i2v и happyhorse-1.1-i2v. Варианты wan2.7/wan3.0 также передают свои
референсные ассеты в media. Форматы изображений: JPEG, JPG, PNG, BMP, WEBP.
Разрешение: 360-2000 пикселей. Размер файла: макс. 10MB.
</ParamField>

<ParamField body="input.media" type="object[]">
  Список медиаассетов. Задаёт референсные материалы (изображение, аудио, видео) для
генерации видео. Каждый элемент содержит поля type и url. Это поле используется всеми
моделями, которые обслуживает данный компонент, а то, какие значения type принимает
конкретная модель и передаёт ли она вообще свой ввод изображения или видео здесь, а не
в img_url или reference_video_urls, зависит от модели. Поддерживаемые значения type по
моделям:
- wan2.7-i2v: first_frame, last_frame, driving_audio, first_clip. first_frame и
  last_frame: JPEG/JPG/PNG/BMP/WEBP, 240-8000 пикселей по каждой стороне, соотношение
  сторон от 1:8 до 8:1, не более 20MB, публичный URL или URL вида
  data:\{MIME_type};base64,... . driving_audio (WAV/MP3, 2-30 секунд, не более 15MB) и
  first_clip (MP4/MOV, 2-10 секунд, 240-4096 пикселей по каждой стороне, не более
  100MB): публичный URL HTTP/HTTPS; встроенный data: URL не принимается.
- wan2.7-r2v: first_frame (необязательно, макс. 1), reference_image, reference_video.
  Требуется хотя бы один reference_image или reference_video, а референсные изображения
  и референсные видео в сумме дают не более 5. first_frame и reference_image:
  JPEG/JPG/PNG/BMP/WEBP (без альфа-канала), 240-8000 пикселей по каждой стороне,
  соотношение сторон от 1:8 до 8:1, не более 20MB, публичный URL или URL вида
  data:\{MIME_type};base64,... . reference_video: публичный URL HTTP/HTTPS; встроенный
  data: URL не принимается.
- wan2.7-videoedit: video (ровно 1, редактируемый клип: MP4/MOV, 2-10 секунд,
  240-4096 пикселей по каждой стороне, не более 100MB, публичный URL HTTP/HTTPS;
  встроенный data: URL не принимается) плюс необязательный от 0 до 4 reference_image
  (JPEG/JPG/PNG/BMP/WEBP, 240-8000 пикселей по каждой стороне, соотношение сторон от
  1:8 до 8:1, не более 20MB, публичный URL или URL вида data:\{MIME_type};base64,... ).
- wan3.0-video, wan3.0-video-prime: first_frame (макс. 1), last_frame (макс. 1),
  reference_image (макс. 10), reference_video (макс. 5 клипов, суммарная длительность
  \<= 15s), reference_audio (макс. 5 клипов, суммарная длительность \<= 15s), file
  (макс. 1, нельзя использовать с link), link (макс. 1, нельзя использовать с file).
  Типы reference_*/file/link и first_frame/last_frame взаимоисключающие в рамках одного
  запроса. Порядок в массиве задаёт порядок референсов ассетов в промпте (Image 1,
  Video 1, Audio 1, ...). first_frame, last_frame и reference_image:
  JPEG/JPG/PNG/BMP/WEBP, 240-8000 пикселей по каждой стороне, соотношение сторон не
  более 8:1, не более 20MB, публичный URL или URL вида data:\{MIME_type};base64,... .
  reference_video, reference_audio, file и link: публичный URL HTTP/HTTPS; встроенный
  data: URL не принимается.
- happyhorse-1.0-i2v, happyhorse-1.1-i2v: только first_frame, ровно 1. Эти варианты
  принимают первый кадр ЗДЕСЬ, а не в img_url. Не менее 300x300 пикселей, соотношение
  сторон от 1:2.5 до 2.5:1, JPEG/JPG/PNG/WEBP, не более 20MB, публичный URL или URL
  вида data:\{MIME_type};base64,... .
- happyhorse-1.0-r2v, happyhorse-1.1-r2v: только reference_image, от 1 до 9 штук. Это
  единственный референсный ввод модели. Наименьшая сторона не менее 400 пикселей,
  JPEG/JPG/PNG/WEBP, не более 20MB, публичный URL или URL вида
  data:\{MIME_type};base64,... . reference_video не является типом ввода для этой
  операции.
- happyhorse-1.0-video-edit: video (ровно 1, редактируемый клип: MP4/MOV, 3-60
  секунд, длинная сторона не более 4096 пикселей, короткая сторона не менее
  360 пикселей, соотношение сторон от 1:2.5 до 2.5:1, не более 100MB, публичный URL
  HTTP/HTTPS; встроенный data: URL не принимается) плюс необязательный от 0 до 5
  reference_image (JPEG/JPG/PNG/WEBP, не менее 300x300 пикселей, соотношение сторон от
  1:2.5 до 2.5:1, не более 20MB, публичный URL или URL вида
  data:\{MIME_type};base64,... ).
- happyhorse-1.0-t2v, happyhorse-1.1-t2v, wan2.7-t2v, wan2.6-t2v, wan2.5-t2v-preview:
  операции текст в видео. В справочной документации партнёра для них не описан ввод
  media, поэтому оставьте это поле незаданным.
- wan2.5-i2v-preview, wan2.6-i2v, wan2.6-r2v: для этих вариантов данный компонент не
  перечисляет никакого словаря media. wan2.5-i2v-preview и wan2.6-i2v принимают первый
  кадр в img_url; wan2.6-r2v принимает свои референсные клипы в reference_video_urls.
Приведённые выше ограничения по количеству для каждой модели являются ограничениями
партнёра, а не этой схемы: для media не объявлены minItems/maxItems, потому что
допустимые типы и их пределы различаются по моделям. Принятие схемой не означает
принятия провайдером. И в обратную сторону: указанные выше значения «не более 20MB» на
каждый ассет (потолок для вводов изображений, единственных вводов, которые можно
отправить встроенными) являются потолком партнёра для ассета, который он в итоге
получает, и они действуют в точности так, как написано, когда ассет является публичным
URL, поскольку эти байты никогда не проходят через Comfy. Встроенный URL вида
data:\{MIME_type};base64,... действительно проходит через Comfy и тоже упирается в
транспортный потолок: тело POST-запроса Comfy Router ограничено 100 MiB в сумме и при
превышении получает ответ 413, а base64 увеличивает полезную нагрузку примерно в 4/3,
поэтому один встроенный ассет размером свыше примерно 75 MB отклоняется ещё до того,
как сработает любое из правил партнёра, описанных здесь. При таком размере один ассет
при собственном20MB спокойно укладывается в inline-вставку, поэтому для одного ассета ограничивающим оказывается правило партнёра, а для нескольких ассетов действует транспортный предел: лимит Router в 100 MiB ограничивает ВЕСЬ запрос, а не каждый элемент. Всё, что приближается к этим пределам, отправляйте в виде публичного URL.
</ParamField>

<ParamField body="input.media[].type" type="string" required>
  Тип медиафайла

  Возможные значения: `first_frame`, `last_frame`, `driving_audio`, `first_clip`, `reference_image`, `reference_video`, `reference_audio`, `video`, `file`, `link`
</ParamField>

<ParamField body="input.media[].url" type="string" required>
  URL медиафайла: публичный HTTP/HTTPS URL или, строго для тех входов IMAGE, которые перечислены выше в описании `media` для каждой модели: first_frame и last_frame на wan2.7-i2v; first_frame и reference_image на wan2.7-r2v; reference_image на wan2.7-videoedit; first_frame, last_frame и reference_image на wan3.0-video и wan3.0-video-prime; first_frame на happyhorse-1.0-i2v и happyhorse-1.1-i2v; reference_image на happyhorse-1.0-r2v и happyhorse-1.1-r2v; и reference_image на happyhorse-1.0-video-edit: inline-URL вида `data:{MIME_type};base64,...`. Ни один вход видео, аудио, файла или link ни на одной из этих моделей не принимает inline data: URL. Временный URL oss://dashscope-instant из собственного сервиса загрузки партнёра или (на wan2.7-videoedit) asset_id из Asset Center разрешается только в том аккаунте Alibaba Cloud, который его загрузил; Comfy вызывает модель своим ключом и не предоставляет маршрута для загрузки, поэтому собственный oss:// URL или asset_id вызывающей стороны не является поддерживаемым входом. Это поле не проверяет схему URL, поэтому такое значение передаётся партнёру как есть, а не отклоняется здесь. Сведения об ограничениях по размеру и пикселям для каждой модели, а также о лимите Router в 100 MiB на тело запроса, который ограничивает inline-полезную нагрузку в совокупности, см. в описании `media`.
</ParamField>

<ParamField body="input.negative_prompt" type="string">
  Слова обратного промпта используются для описания содержимого, которое вы не хотите видеть в кадре видео. После 500 символов модель wan усекает его, а не отклоняет. Оно учитывается в том же бюджете ввода, что и prompt.
</ParamField>

<ParamField body="input.prompt" type="string">
  Текстовые промпт-слова. Поддерживает китайский и английский. wan3.0-video и wan3.0-video-prime принимают не более
20,000 символов. Используйте 'Image 1', 'Video 1', 'Audio 1' и т. д., чтобы ссылаться на медиафайлы в
соответствующем порядке в массиве media.
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  URL референсных видео только для модели wan2.6-r2v. Массив из 1-3 URL видео.
Ограничения ввода:
- Формат: mp4, mov
- Количество: 1-3 видео
- Длительность одного видео: 2-30 секунд
- Размер одного файла: не более 30MB
- Нельзя использовать с audio_url
Референсная длительность: одно видео не более 5s, два видео не более 2.5s каждое, три видео пропорционально меньше.
Выставление счетов: по фактически использованной референсной длительности.
</ParamField>

<ParamField body="input.template" type="string">
  Название шаблона видеоэффекта. Необязательно. Сейчас поддерживаются: squish, flying, carousel. При использовании параметр prompt игнорируется.
</ParamField>

<ParamField body="model" type="string">
  ID вызываемой модели. НЕ ограничен на этом компоненте: Comfy Router заполняет его из сегмента пути `{model}` в `POST /v2/models/wan/{model}`, поэтому вызывающая сторона Router его не передаёт.
</ParamField>

<ParamField body="parameters" type="object">
  Параметры обработки видео
</ParamField>

<ParamField body="parameters.audio" type="boolean" default="true">
  Добавлять ли аудио к видео. Поддерживается только для wan3.0-video и wan3.0-video-prime; для остальных моделей wan провайдер не документирует такого переключателя.
</ParamField>

<ParamField body="parameters.audio_setting" type="string" default="&quot;auto&quot;">
  Настройка аудио видео для модели wan2.7-videoedit.
- auto (по умолчанию): модель интеллектуально оценивает по содержимому промпта
- origin: принудительно сохраняет оригинальное аудио из входного видео

  Возможные значения: `auto`, `origin`
</ParamField>

<ParamField body="parameters.duration" type="integer" default="5">
  Длительность сгенерированного видео в секундах:
- модели wan2.5: 5 или 10 секунд
- wan2.6-t2v, wan2.6-i2v: 5, 10 или 15 секунд
- wan2.6-r2v: только 5 или 10 секунд (поддержки 15s нет)
- wan2.7-i2v, wan2.7-t2v: целое число в [2, 15]
- wan2.7-r2v, wan2.7-videoedit: целое число в [2, 10]
- wan3.0-video: целое число в [2, 30] без входного видео; при наличии входного видео суммарная
  длительность входного видео + длительность выходного видео не должна превышать 30 секунд; -1 включает
  режим умной длительности, когда модель подбирает подходящую длительность
Этот прокси возвращает 400 для длительности вне [-1, 30].

  Диапазон: `-1` до `30`
</ParamField>

<ParamField body="parameters.prompt_extend" type="boolean" default="true">
  Включено ли интеллектуальное переписывание промпта. По умолчанию true
</ParamField>

<ParamField body="parameters.ratio" type="string">
  Соотношение сторон сгенерированного видео. Только для моделей wan2.7 и wan3.0.
Для моделей wan2.7 по умолчанию определяется уровнем разрешения, если не указано.
Для wan3.0-video значение adaptive (по умолчанию) автоматически рекомендует подходящее
соотношение сторон на основе пропорций входных медиафайлов и замысла.

  Возможные значения: `adaptive`, `16:9`, `9:16`, `1:1`, `4:3`, `3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  Уровень разрешения. Поддерживаемые значения зависят от модели:
- wan2.5-i2v-preview: 480P, 720P, 1080P
- модели wan2.6 (t2v, i2v, r2v): только 720P, 1080P (поддержки 480P нет)
- модели wan2.7 (i2v, t2v, r2v, videoedit): 720P, 1080P (по умолчанию 1080P)
- wan3.0-video, wan3.0-video-prime: 480P, 720P, 1080P (по умолчанию у провайдера 1080P)
- happyhorse-1.0-* (t2v, i2v, r2v, video-edit): 720P, 1080P
- happyhorse-1.1-* (t2v, i2v, r2v): 480P, 720P, 1080P
Этот прокси отклоняет запросы на генерацию видео, в которых не указаны ни resolution,
ни size, поскольку уровень разрешения определяет тариф выставления счетов. Он переводит
resolution в верхний регистр перед проверкой и передаёт значение в верхнем регистре, возвращает 400для значения вне этого перечисления, а также возвращает 400 для 480P (передано ли оно как resolution или как размер 480P) для моделей wan2.6, wan2.7 и happyhorse-1.0, перечисленных выше как не поддерживающие 480P.

  Возможные значения: `480P`, `720P`, `1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  Случайное зерно, используемое для управления случайностью содержимого, генерируемого моделью

  Диапазон: от `0` до `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  Интеллектуальное управление несколькими планами. Активно только при включённом prompt_extend.
Для моделей wan2.6 и wan2.7-r2v.
- single: видео из одного плана (по умолчанию)
- multi: видео из нескольких планов

  Возможные значения: `multi`, `single`
</ParamField>

<ParamField body="parameters.size" type="string">
  Разрешение видео в формате ширина*высота. Поддерживаемые разрешения зависят от модели:
Для wan2.5 T2V: размеры 480P (480*832, 832*480, 624*624), 720P, 1080P
Для wan2.6 T2V/R2V (без 480P):
  720P: 1280*720, 720*1280, 960*960, 1088*832, 832*1088
  1080P: 1920*1080, 1080*1920, 1440*1440, 1632*1248, 1248*1632
Если переданы и size, и resolution, то size выбирает тарифицируемый уровень,
а resolution всё равно должно быть значением, которое этот прокси принимает для модели. Размер 480P
возвращает 400 на каждой модели, для которой в описании resolution указано отсутствие 480P.
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  Добавлять ли логотип-водяной знак; водяной знак располагается в правом нижнем углу
</ParamField>

Сгенерировано из схемы, которую Router отдаёт по `GET /v2/models/wan/wan3.0-video/openapi.json`. Это тот же документ, по которому проверяется вызов, прежде чем запрос дойдёт до провайдера.
