Справочник по API для HappyHorse 1.0 Video Edit. HappyHorse 1.0 Video Edit перезаписывает существующий клип по текстовой инструкции, при необходимости ориентируясь на референсные изображения.

**Вход:** Видео, Изображение, Текст · **Выход:** Видео

## Быстрый старт

Создайте ключ в [вашем рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. Фрагменты на Python и TypeScript используют Comfy SDK (`pip install comfy-sdk` и `npm install @comfyorg/sdk`); фрагмент cURL выполняет тот же вызов по обычному HTTP.

**ID модели:** `wan/happyhorse-1.0-video-edit`

**Endpoint:** `POST https://api.comfy.org/v2/models/wan/happyhorse-1.0-video-edit`

```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменных окружения.
# SDK автоматически создаёт ключ идемпотентности и переиспользует его при автоматических повторах.
async def main():
    async with AsyncComfy() as client:
        result = await client.models.run(
            "wan/happyhorse-1.0-video-edit",
            {
                "input": {
                    "prompt": "restyle the clip as a hand-drawn ink sketch, keep the dancer's movement unchanged",

                        {

                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                },
            },
        )

    print("video:", result["output"]["video_url"])

asyncio.run(main())
```

То же самое тело, отправленное на `POST https://api.comfy.org/v2/models/wan/happyhorse-1.0-video-edit/requests`. Router отвечает `201` с `request_id` сразу после того, как запуск принят, а результат забирается, когда он готов, из этого процесса или из любого другого. [Доставка через очередь](/ru/development/comfy-router/queue) описывает статус, отмену и получение результата.

<CodeGroup>
```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменных окружения.
# Каждый вызов submit() создаёт свой Idempotency-Key и переиспользует его при автоматических повторах.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/happyhorse-1.0-video-edit",
            {
                "input": {
                    "prompt": "restyle the clip as a hand-drawn ink sketch, keep the dancer's movement unchanged",
                    "media": [
                        {
                            "type": "video",
                            "url": "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/street_dancer.mp4",
                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                },
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивайте, пока запрос не завершится, выдерживая Retry-After, который называет сервер.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственный payload провайдера, то же значение, что возвращает models.run().
        # Запрос, который завершился ошибкой или был отменён, вызывает здесь типизированную ошибку Router.
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Читает COMFY_API_KEY из переменных окружения.
// Каждый вызов submit() создаёт свой Idempotency-Key и переиспользует его при автоматических повторах.
type Result = { output: { video_url: string } };
const handle = await comfy.models.submit<Result>("wan/happyhorse-1.0-video-edit", {
  input: {
    prompt: "restyle the clip as a hand-drawn ink sketch, keep the dancer's movement unchanged",
    media: [
      {
        type: "video",
        url: "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/street_dancer.mp4",
      },
    ],
  },
  parameters: {
    resolution: "720P",
  },
});
console.log("requestId:", handle.requestId); // вместе с ID модели это всё, что нужно другому процессу

// Опрашивайте, пока запрос не завершится, выдерживая Retry-After, который называет сервер.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// Тот же результат, что возвращает models.run(). Запрос, который завершился ошибкой или был отменён, отклоняется здесь.
const result = await handle.get();
if (result.kind !== "json") throw new Error("expected a JSON result");

console.log("video:", result.data.output.video_url);
```

```bash cURL
# 1. Отправка. Router отвечает 201 с request_id, status_url, response_url и cancel_url.
curl https://api.comfy.org/v2/models/wan/happyhorse-1.0-video-edit/requests \
  -H "X-API-Key: $COMFY_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d "{\"input\": {\"prompt\":\"restyle the clip as a hand-drawn ink sketch, keep the dancer's movement unchanged\",\"media\":[{\"type\":\"video\",\"url\":\"https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/street_dancer.mp4\"}]}, \"parameters\": {\"resolution\":\"720P\"}}"

# 2. Опрашивайте, пока статус не станет COMPLETED, выдерживая Retry-After секунд, указанный в каждом ответе.
REQUEST_ID="<request_id from the 201 body>"
curl -i https://api.comfy.org/v2/models/wan/happyhorse-1.0-video-edit/requests/$REQUEST_ID/status \
  -H "X-API-Key: $COMFY_API_KEY"

# 3. Получение. 200 с нативным выводом модели, 202 с телом статуса, пока запрос ещё выполняется.
curl https://api.comfy.org/v2/models/wan/happyhorse-1.0-video-edit/requests/$REQUEST_ID \
  -H "X-API-Key: $COMFY_API_KEY"
```

## Схема

### Входы

<ParamField body="input" type="object" required>
  Введите базовую информацию: промпт и т. п.
</ParamField>

<ParamField body="input.audio_url" type="string">
  URL для скачивания аудиофайла. Поддерживаемые форматы: mp3 и wav. Нельзя использовать вместе с reference_video_urls.
</ParamField>

<ParamField body="input.img_url" type="string">
  URL изображения первого кадра или данные в кодировке Base64. Обязательно для моделей wan2.5-i2v-preview и
wan2.6-i2v. Варианты happyhorse-1.x i2v НЕ принимают первый кадр здесь:
они передают его как медиаэлемент с типом first_frame (см. media ниже), а
тело img_url, которое успешно работает на wan2.6-i2v, отклоняется провайдером на
happyhorse-1.0-i2v и happyhorse-1.1-i2v. Варианты wan2.7/wan3.0
также передают свои референсные ассеты в media. Форматы изображений: JPEG, JPG, PNG, BMP, WEBP.
Разрешение: 360-2000 пикселей. Размер файла: макс. 10MB.
</ParamField>

<ParamField body="input.media" type="object[]">
  Список медиаассетов. Задаёт референсные материалы (изображение, аудио, видео) для
генерации видео. Каждый элемент содержит поля type и url. Это поле
используется всеми моделями, которые обслуживает данный компонент, а то, какие
значения type принимает конкретная модель (и передаёт ли она вообще свой вход изображения или видео
здесь, а не в img_url или reference_video_urls), зависит от модели. Поддерживаемые значения type по моделям:
- wan2.7-i2v: first_frame, last_frame, driving_audio, first_clip. first_frame и
  last_frame: JPEG/JPG/PNG/BMP/WEBP, 240-8000 пикселей по каждой стороне, соотношение сторон от 1:8
  до 8:1, не более 20MB, публичный URL или data:\{MIME_type};base64,... URL.
  driving_audio (WAV/MP3, 2-30 секунд, не более 15MB) и first_clip (MP4/MOV, 2-10
  секунд, 240-4096 пикселей по каждой стороне, не более 100MB): публичный HTTP/HTTPS URL; встроенный
  data: URL не принимается.
- wan2.7-r2v: first_frame (необязательно, макс. 1), reference_image, reference_video. Требуется
  хотя бы один reference_image или reference_video, а референсные изображения и
  референсные видео в сумме дают не более 5. first_frame и reference_image: JPEG/JPG/PNG/BMP/WEBP
  (без альфа-канала), 240-8000 пикселей по каждой стороне, соотношение сторон от 1:8 до 8:1, не более
  20MB, публичный URL или data:\{MIME_type};base64,... URL. reference_video: публичный
  HTTP/HTTPS URL; встроенный data: URL не принимается.
- wan2.7-videoedit: video (ровно 1, редактируемый клип: MP4/MOV, 2-10 секунд,
  240-4096 пикселей по каждой стороне, не более 100MB, публичный HTTP/HTTPS URL; встроенный data: URL
  не принимается) плюс необязательные от 0 до 4 reference_image (JPEG/JPG/PNG/BMP/WEBP,
  240-8000 пикселей по каждой стороне, соотношение сторон от 1:8 до 8:1, не более 20MB, публичный URL
  или data:\{MIME_type};base64,... URL).
- wan3.0-video, wan3.0-video-prime: first_frame (макс. 1), last_frame (макс. 1),
  reference_image (макс. 10), reference_video (макс. 5 клипов, суммарная длительность \<= 15s),
  reference_audio (макс. 5 клипов, суммарная длительность \<= 15s), file (макс. 1, нельзя использовать
  вместе с link), link (макс. 1, нельзя использовать вместе с file). Типы reference_*/file/link
  и типы first_frame/last_frame взаимно исключают друг друга в пределах одного запроса.
  Порядок массива задаёт порядок референсов ассетов в промпте (Image 1, Video 1,
  Audio 1, ...). first_frame, last_frame и reference_image: JPEG/JPG/PNG/BMP/WEBP,
  240-8000 пикселей по каждой стороне, соотношение сторон не более 8:1, не более 20MB, публичный URL или
  data:\{MIME_type};base64,... URL. reference_video, reference_audio, file и link: публичный
  HTTP/HTTPS URL; встроенный data: URL не принимается.
- happyhorse-1.0-i2v, happyhorse-1.1-i2v: только first_frame, ровно 1. Эти варианты
  принимают первый кадр ЗДЕСЬ, а не в img_url. Не менее 300x300 пикселей, соотношение сторон
  от 1:2.5 до 2.5:1, JPEG/JPG/PNG/WEBP, не более 20MB, публичный URL или
  data:\{MIME_type};base64,... URL.
- happyhorse-1.0-r2v, happyhorse-1.1-r2v: только reference_image, от 1 до 9 штук. Это
  единственный референсный вход модели. Наименьшая сторона не менее 400 пикселей, JPEG/JPG/PNG/WEBP,
  не более 20MB, публичный URL или data:\{MIME_type};base64,... URL. reference_video
  не является типом входа для этой операции.
- happyhorse-1.0-video-edit: video (ровно 1, редактируемый клип: MP4/MOV, 3-60
  секунд, длинная сторона не более 4096 пикселей, короткая сторона не менее 360 пикселей, соотношение
  сторон от 1:2.5 до 2.5:1, не более 100MB, публичный HTTP/HTTPS URL; встроенный data:
  URL не принимается) плюс необязательные от 0 до 5 reference_image (JPEG/JPG/PNG/BMP/WEBP, не
  менее 300x300 пикселей, соотношение сторон от 1:2.5 до 2.5:1, не более 20MB, публичный URL
  или data:\{MIME_type};base64,... URL).
- happyhorse-1.0-t2v, happyhorse-1.1-t2v, wan2.7-t2v, wan2.6-t2v, wan2.5-t2v-preview:
  операции текст в видео. В документации партнёра для них не описан вход media, поэтому оставьте
  это поле незаданным.
- wan2.5-i2v-preview, wan2.6-i2v, wan2.6-r2v: для этих вариантов данный компонент не перечисляет
  никакого словаря media. wan2.5-i2v-preview и wan2.6-i2v принимают первый
  кадр в img_url; wan2.6-r2v принимает свои референсные клипы в reference_video_urls.
Приведённые выше количества по каждой модели это ограничения партнёра, а не этой схемы: на
media не объявлены minItems/maxItems, потому что допустимые типы и их лимиты
различаются по моделям. Принятие схемой не означает принятия провайдером. И в
обратную сторону: указанные выше для каждого ассета значения «не более 20MB» (потолок для
входов изображений, единственных входов, которые можно передавать встроенно) это потолок партнёра для
ассета, который он в итоге получает, и они действуют ровно так, как написано, когда ассет задан публичным URL,
поскольку эти байты никогда не проходят через Comfy. Встроенный data:\{MIME_type};base64,...
URL проходит через Comfy и тоже упирается в транспортный потолок: тело POST-запроса
Comfy Router ограничено 100 MiB в сумме, и при превышении возвращается ответ 413, а base64 увеличивает
полезную нагрузку примерно в 4/3 раза, поэтому один встроенный ассет размером примерно выше 75 MB
отклоняется ещё до того, как сработает хоть одно из здешних правил партнёра. При таком размере один ассет на собственном20MB ceiling fits inline comfortably, so the partner rule is what binds for one asset -- the transport ceiling binds across several of them, since the 100 MiB Router cap bounds the WHOLE request rather than each element. Send anything near these ceilings as a public URL.

Потолок в 20 МБ спокойно вмещает встроенную передачу, поэтому для одного ассета ограничивающим становится правило партнёра, а при нескольких ассетах ограничивающим становится транспортный потолок: лимит Router в 100 MiB ограничивает ВЕСЬ запрос, а не каждый элемент. Всё, что близко к этим потолкам, отправляйте в виде публичного URL.
</ParamField>

<ParamField body="input.media[].url" type="string" required>
  URL медиафайла: публичный HTTP/HTTPS URL или, только для тех IMAGE-входов, которые перечислены для каждой модели в описании `media` выше (first_frame и last_frame на wan2.7-i2v; first_frame и reference_image на wan2.7-r2v; reference_image на wan2.7-videoedit; first_frame, last_frame и reference_image на wan3.0-video и wan3.0-video-prime; first_frame на happyhorse-1.0-i2v и happyhorse-1.1-i2v; reference_image на happyhorse-1.0-r2v и happyhorse-1.1-r2v; и reference_image на happyhorse-1.0-video-edit), встроенный URL `data:{MIME_type};base64,...`. Ни один вход video, audio, file или link ни на одной из этих моделей не принимает встроенный data: URL. Временный URL oss://dashscope-instant из собственного сервиса загрузки партнёра или (на wan2.7-videoedit) asset_id из Asset Center разрешается только для той учётной записи Alibaba Cloud, которая его загрузила; Comfy вызывает модель со своим ключом и не предоставляет маршрута для загрузки, поэтому собственный oss:// URL или asset_id вызывающей стороны не является поддерживаемым входом. Это поле не проверяет схему URL, поэтому такое значение передаётся партнёру как есть, а не отклоняется здесь. См. описание `media`, чтобы узнать ограничения размера и пикселей для каждой модели, а также лимит тела запроса Router в 100 MiB, который ограничивает встроенные данные в совокупности.
</ParamField>

<ParamField body="input.negative_prompt" type="string">
  Обратный промпт описывает содержимое, которое вы не хотите видеть на экране видео. После 500 символов модель wan обрезает его, а не отклоняет запрос. Он учитывается в том же бюджете ввода, что и prompt.
</ParamField>

<ParamField body="input.prompt" type="string">
  Текст промпта. Поддерживает китайский и английский. После собственной документированной длины модель wan2.x обрезает промпт, а не отклоняет его: 1,500 символов для wan2.5 и wan2.6 и 5,000 для wan2.7. wan3.0-video и wan3.0-video-prime принимают не более 20,000 символов. Провайдер отклоняет запрос, в котором prompt и negative_prompt вместе длиннее примерно 60,850 байт текста UTF-8 (около 20,000 китайских символов), отвечая InvalidParameter `Range of input length should be [1, 61440]`. Для wan2.6-r2v с несколькими референсными видео используйте 'character1', 'character2' и т. д., чтобы ссылаться на субъектов в порядке референсных видео. Пример: "Character1 sings on the roadside, Character2 dances beside it" Для режима reference у wan3.0-video используйте 'Image 1', 'Video 1', 'Audio 1' и т. д., чтобы ссылаться на медиафайлы в соответствующем порядке внутри массива media.
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  URL референсных видео только для модели wan2.6-r2v. Массив из 1-3 URL видео.
Ограничения входа:
- Формат: mp4, mov
- Количество: 1-3 видео
- Длительность одного видео: 2-30 секунд
- Размер одного файла: макс. 30MB
- Нельзя использовать с audio_url
Длительность референса: одно видео макс. 5 с, два видео макс. 2.5 с каждое, три видео пропорционально меньше.
Выставление счетов: на основе фактически использованной длительности референса.
</ParamField>

<ParamField body="input.template" type="string">
  Название шаблона видеоэффекта. Необязательно. Сейчас поддерживаются: squish, flying, carousel. При использовании параметр prompt игнорируется.
</ParamField>

<ParamField body="model" type="string">
  Идентификатор вызываемой модели. НЕ ограничивается на этом компоненте: Comfy Router подставляет его из сегмента пути `{model}` запроса `POST /v2/models/wan/{model}`, поэтому вызывающая сторона Router его не указывает. Прямой вызов v1 `POST /proxy/wan/api/v1/services/aigc/video-generation/video-synthesis` ОБЯЗАН его передавать, а перечисление допустимых написаний находится на собственном компоненте этой операции, `WanVideoGenerationRequest`.

<ParamField body="parameters.duration" type="integer" default="5">
  Длительность сгенерированного видео в секундах:
- модели wan2.5: 5 или 10 секунд
- wan2.6-t2v, wan2.6-i2v: 5, 10 или 15 секунд
- wan2.6-r2v: только 5 или 10 секунд (15 с не поддерживается)
- wan2.7-i2v, wan2.7-t2v: целое число в диапазоне [2, 15]
- wan2.7-r2v, wan2.7-videoedit: целое число в диапазоне [2, 10]
- wan3.0-video: целое число в диапазоне [2, 30] без видео на входе; при наличии видео на входе суммарная длительность входного видео + длительность выходного видео не должна превышать 30 секунд; -1 включает режим умной длительности, в котором модель подбирает подходящую длительность

  Соотношение сторон сгенерированного видео. Только для моделей wan2.7 и wan3.0.
Для моделей wan2.7, если значение не указано, оно выбирается по умолчанию на основе уровня разрешения.
Для wan3.0-video значение adaptive (по умолчанию) автоматически рекомендует подходящеесоотношение сторон на основе пропорций входного медиафайла и замысла.

  Возможные значения: `adaptive`, `16:9`, `9:16`, `1:1`, `4:3`, `3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  Уровень разрешения. Поддерживаемые значения зависят от модели:
- wan2.5-i2v-preview: 480P, 720P, 1080P
- модели wan2.6 (t2v, i2v, r2v): только 720P, 1080P (без поддержки 480P)
- модели wan2.7 (i2v, t2v, r2v, videoedit): 720P, 1080P (по умолчанию 1080P)
- wan3.0-video, wan3.0-video-prime: 480P, 720P, 1080P (по умолчанию у провайдера 1080P)
- happyhorse-1.0-* (t2v, i2v, r2v, video-edit): 720P, 1080P
- happyhorse-1.1-* (t2v, i2v, r2v): 480P, 720P, 1080P
Этот прокси отклоняет запросы на генерацию видео, в которых не указаны ни resolution, ни size, поскольку уровень разрешения определяет тариф выставления счетов. Перед проверкой он переводит resolution в верхний регистр и передаёт значение в верхнем регистре, возвращает 400 для значения вне этого перечисления и возвращает 400 для 480P (независимо от того, передан ли он как resolution или как size со значением 480P) для моделей wan2.6, wan2.7 и happyhorse-1.0, перечисленных выше как не поддерживающие 480P.

  Возможные значения: `480P`, `720P`, `1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  Зерно случайного числа, используется для управления случайностью сгенерированного моделью содержимого

  Диапазон: от `0` до `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  Интеллектуальное управление с несколькими ракурсами. Активно только при включённом prompt_extend.
Для моделей wan2.6 и wan2.7-r2v.
- single: видео с одним кадром (по умолчанию)
- multi: видео с несколькими кадрами

  Возможные значения: `multi`, `single`
</ParamField>

<ParamField body="parameters.size" type="string">
  Разрешение видео в формате ширина*высота. Поддерживаемые разрешения зависят от модели:
Для wan2.5 T2V: размеры 480P (480*832, 832*480, 624*624), 720P, 1080P
Для wan2.6 T2V/R2V (без 480P):
  720P: 1280*720, 720*1280, 960*960, 1088*832, 832*1088
  1080P: 1920*1080, 1080*1920, 1440*1440, 1632*1248, 1248*1632
Если переданы и size, и resolution, тарифный уровень выбирает size, а resolution всё равно должен быть значением, которое этот прокси принимает для модели. Size со значением 480P возвращает 400 для каждой модели, которая в описании resolution указана как не поддерживающая 480P.
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">

</ParamField>
