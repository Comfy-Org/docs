Справочник по API для Wan 2.7 I2V. Wan 2.7 в режиме «изображение в видео» анимирует первый кадр, переданный через список медиа, который также принимает последний кадр, управляющую аудиодорожку и вступительный клип.

**Вход:** Изображение, Видео, Аудио, Текст · **Выход:** Видео + Аудио

## Быстрый старт

Создайте ключ в [вашем рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. Фрагменты кода на Python и TypeScript используют Comfy SDK (`pip install comfy-sdk` и `npm install @comfyorg/sdk`); фрагмент cURL выполняет тот же вызов через обычный HTTP.

**ID модели:** `wan/wan2.7-i2v`

**Эндпоинт:** `POST https://api.comfy.org/v2/models/wan/wan2.7-i2v`

Router отвечает `201` с `request_id` сразу после того, как запуск принят, а результат забирается, когда он готов, из этого процесса или из другого.
```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменных окружения.
# Каждый вызов submit() создаёт свой Idempotency-Key и переиспользует его для автоматических повторов.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/wan2.7-i2v",
            {
                "input": {
                    "prompt": "the robot lowers its raised arm and steps toward the camera, the flat orange backdrop holds steady",
                    "media": [
                        {
                            "type": "first_frame",
                            "url": "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивайте, пока запрос не завершится, выдерживая Retry-After, указанный сервером.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственный payload провайдера, то же значение, что возвращает models.run().
        # Запрос, который завершился ошибкой или был отменён, вызывает здесь типизированную ошибку Router.
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())
```

```typescript TypeScript
const handle = await comfy.models.submit<Result>("wan/wan2.7-i2v", {

// Опрашивайте, пока запрос не завершится, выдерживая Retry-After, указанный сервером.
for await (const update of handle.events()) {

}

// То же результат, что возвращает models.run(). Запрос, который завершился ошибкой или был отменён, отклоняется здесь.
```

</ParamField>

<ParamField body="input.img_url" type="string">
  URL изображения первого кадра или данные в кодировке Base64. Обязательно для моделей wan2.5-i2v-preview и
wan2.6-i2v. Варианты написания happyhorse-1.x i2v НЕ принимают здесь первый кадр:
они принимают его как медиаэлемент типа first_frame (см. media ниже), а тело с
img_url, которое успешно работает на wan2.6-i2v, отклоняется провайдером на
happyhorse-1.0-i2v и happyhorse-1.1-i2v; а варианты wan2.7/wan3.0 передают свои
референсные ассеты тоже в media. Форматы изображений: JPEG, JPG, PNG, BMP, WEBP.
Разрешение: 360-2000 пикселей. Размер файла: не более 10MB.
</ParamField>

<ParamField body="input.media" type="object[]">
  Список медиаассетов. Задаёт референсные материалы (изображение, аудио, видео) для
генерации видео. Каждый элемент содержит поля type и url. Это поле используется всеми
моделями, обслуживаемыми данным компонентом, а то, какие значения type принимает
конкретная модель и передаёт ли она свой ввод изображения или видео здесь, а не в
img_url или reference_video_urls, зависит от модели. Поддерживаемые значения type по
моделям:
- wan2.7-i2v: first_frame, last_frame, driving_audio, first_clip. first_frame и
  last_frame: JPEG/JPG/PNG/BMP/WEBP, 240-8000 пикселей по каждой стороне, соотношение
  сторон от 1:8 до 8:1, не более 20MB, публичный URL или URL вида
  data:\{MIME_type};base64,... . driving_audio (WAV/MP3, 2-30 секунд, не более 15MB)
  и first_clip (MP4/MOV, 2-10 секунд, 240-4096 пикселей по каждой стороне, не более
  100MB): публичный URL HTTP/HTTPS; встроенный data: URL не принимается.
- wan2.7-r2v: first_frame (необязательно, макс. 1), reference_image, reference_video.
  Требуется хотя бы один reference_image или reference_video, а изображения и
  видео-референсы в сумме составляют не более 5. first_frame и reference_image:
  JPEG/JPG/PNG/BMP/WEBP (без альфа-канала), 240-8000 пикселей по каждой стороне,
  соотношение сторон от 1:8 до 8:1, не более 20MB, публичный URL или URL вида
  data:\{MIME_type};base64,... . reference_video: публичный URL HTTP/HTTPS;
  встроенный data: URL не принимается.
- wan2.7-videoedit: video (ровно 1, редактируемый клип: MP4/MOV, 2-10 секунд,
  240-4096 пикселей по каждой стороне, не более 100MB, публичный URL HTTP/HTTPS;
  встроенный data: URL не принимается) плюс необязательный 0-4 reference_image
  (JPEG/JPG/PNG/BMP/WEBP, 240-8000 пикселей по каждой стороне, соотношение сторон от
  1:8 до 8:1, не более 20MB, публичный URL или URL вида data:\{MIME_type};base64,...).
- wan3.0-video, wan3.0-video-prime: first_frame (макс. 1), last_frame (макс. 1),
  reference_image (макс. 10), reference_video (макс. 5 клипов, суммарная длительность
  \<= 15s), reference_audio (макс. 5 клипов, суммарная длительность \<= 15s), file
  (макс. 1, нельзя использовать с link), link (макс. 1, нельзя использовать с file).
  Типы reference_*/file/link и типы first_frame/last_frame взаимно исключают друг
  друга в рамках одного запроса. Порядок элементов в массиве задаёт порядок
  референсов в промпте (Image 1, Video 1, Audio 1, ...). first_frame, last_frame и
  reference_image: JPEG/JPG/PNG/BMP/WEBP, 240-8000 пикселей по каждой стороне,
  соотношение сторон не более 8:1, не более 20MB, публичный URL или URL вида
  data:\{MIME_type};base64,... . reference_video, reference_audio, file и link:
  публичный URL HTTP/HTTPS; встроенный data: URL не принимается.
- happyhorse-1.0-i2v, happyhorse-1.1-i2v: только first_frame, ровно 1. Эти варианты
  написания принимают первый кадр ЗДЕСЬ, а не в img_url. Не менее 300x300 пикселей,
  соотношение сторон от 1:2.5 до 2.5:1, JPEG/JPG/PNG/WEBP, не более 20MB, публичный
  URL или URL вида data:\{MIME_type};base64,... .
- happyhorse-1.0-r2v, happyhorse-1.1-r2v: только reference_image, от 1 до 9 штук. Это
  единственный референсный ввод модели. Наименьшая сторона не менее 400 пикселей,
  JPEG/JPG/PNG/WEBP, не более 20MB, публичный URL или URL вида
  data:\{MIME_type};base64,... . reference_video не является типом ввода для этой
  операции.
- happyhorse-1.0-video-edit: video (ровно 1, редактируемый клип: MP4/MOV, 3-60
  секунд, бо́льшая сторона не более 4096 пикселей, меньшая сторона не менее 360
  пикселей, соотношение сторон от 1:2.5 до 2.5:1, не более 100MB, публичный URL
  HTTP/HTTPS; встроенный data: URL не принимается) плюс необязательный 0-5
  reference_image (JPEG/JPG/PNG/WEBP, не менее 300x300 пикселей, соотношение сторон от
  1:2.5 до 2.5:1, не более 20MB, публичный URL или URL вида data:\{MIME_type};base64,...).
- happyhorse-1.0-t2v, happyhorse-1.1-t2v, wan2.7-t2v, wan2.6-t2v, wan2.5-t2v-preview:
  операции «текст в видео». В документации партнёра для них не описан медиаввод,
  поэтому оставьте это поле незаданным.
- wan2.5-i2v-preview, wan2.6-i2v, wan2.6-r2v: данный компонент не перечисляет
  медиасловарь для этих вариантов написания. wan2.5-i2v-preview и wan2.6-i2v
  принимают первый кадр в img_url; wan2.6-r2v принимает референсные клипы в
  reference_video_urls.
Приведённые выше количества по моделям являются ограничениями партнёра, а не данной
схемы: в media не объявлены minItems/maxItems, поскольку допустимые типы и их пределы
различаются по моделям. Принятие схемой не означает принятия провайдером, а, с другой
стороны, приведённые выше значения «не более 20MB» для каждого ассета (предел для
входов-изображений, единственных входов, которые можно передавать inline) являются
пределом партнёра для ассета, который он в итоге получает, и они действуют в точности
так, как записано, если ассет задан публичным URL, поскольку эти байты никогда не
проходят через Comfy. Встроенный URL data:\{MIME_type};base64,... действительно
проходит через Comfy и тоже упирается в транспортный предел: тело POST-запроса Comfy
Router ограничено 100 MiB в сумме, и при превышении возвращается 413, а base64
увеличивает размер полезной нагрузки примерно в 4/3 раза, поэтому один встроенный
ассет размером примерно выше 75 MB отклоняется ещё до того, как сработает какое-либо
из здешних правил партнёра. При таком размере один ассет при собственном20MB потолок спокойно помещается в inline, поэтому для одного ассета ограничивающим становится правило партнёра. При нескольких ассетах начинает действовать ограничение транспорта, поскольку лимит Router в 100 MiB ограничивает ВЕСЬ запрос, а не каждый элемент. Всё, что приближается к этим потолкам, отправляйте публичным URL.
</ParamField>

<ParamField body="input.media[].url" type="string" required>
  URL медиафайла: публичный HTTP/HTTPS URL или (ровно для тех IMAGE-входов, которые перечислены выше в описании `media` для каждой модели: first_frame и last_frame на wan2.7-i2v; first_frame и reference_image на wan2.7-r2v; reference_image на wan2.7-videoedit; first_frame, last_frame и reference_image на wan3.0-video и wan3.0-video-prime; first_frame на happyhorse-1.0-i2v и happyhorse-1.1-i2v; reference_image на happyhorse-1.0-r2v и happyhorse-1.1-r2v; и reference_image на happyhorse-1.0-video-edit) inline-URL `data:{MIME_type};base64,...`. Ни один вход video, audio, file или link ни в одной из этих моделей не принимает inline data: URL. Временный URL oss://dashscope-instant из собственного сервиса загрузки партнёра или (в wan2.7-videoedit) asset_id из Asset Center разрешается только для той учётной записи Alibaba Cloud, которая его загрузила; Comfy вызывает модель со своим ключом и не предоставляет маршрут загрузки, поэтому собственный oss:// URL или asset_id вызывающей стороны не является поддерживаемым входом. Это поле не проверяет схему URL, поэтому такое значение передаётся партнёру как есть, а не отклоняется здесь. См. описание `media`, чтобы узнать ограничения размера и пикселей для каждой модели и лимит Router в 100 MiB на тело запроса, который ограничивает inline-пейлоад в совокупности.
</ParamField>

<ParamField body="input.negative_prompt" type="string">
  Слова обратного промпта используются для описания содержимого, которое вы не хотите видеть на экране видео. После 500 символов wan-модель обрезает его, а не отклоняет. Оно учитывается в том же бюджете входа, что и prompt.
</ParamField>

<ParamField body="input.prompt" type="string">
  Текстовые слова промпта. Поддерживаются китайский и английский. После собственной документированной длины wan2.x-модель
обрезает промпт, а не отклоняет его: 1,500 символов для wan2.5 и wan2.6 и 5,000 для
wan2.7. wan3.0-video и wan3.0-video-prime принимают не более 20,000 символов. Провайдер отклоняет запрос,
у которого prompt и negative_prompt вместе длиннее примерно 60,850 байт текста UTF-8 (около
20,000 китайских символов), отвечая InvalidParameter `Range of input length should be [1, 61440]`.
Для wan2.6-r2v с несколькими референсными видео используйте 'character1', 'character2' и т. д., чтобы ссылаться на субъектов
в порядке референсных видео. Пример: «Character1 sings on the roadside, Character2 dances beside it»
В режиме reference для wan3.0-video используйте 'Image 1', 'Video 1', 'Audio 1' и т. д., чтобы ссылаться на медиафайлы
в соответствующем порядке внутри массива media.
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  URL референсных видео только для модели wan2.6-r2v. Массив из 1-3 URL видео.
Ограничения входа:
- Формат: mp4, mov
- Количество: 1-3 видео
- Длительность одного видео: 2-30 секунд
- Размер одного файла: не более 30MB
- Нельзя использовать вместе с audio_url
Референсная длительность: одно видео не более 5s, два видео не более 2.5s каждое, три видео пропорционально меньше.
Выставление счетов: на основе фактически использованной референсной длительности.
</ParamField>

<ParamField body="input.template" type="string">
  Имя шаблона видеоэффекта. Необязательно. Сейчас поддерживаются: squish, flying, carousel. При использовании параметр prompt игнорируется.
</ParamField>

<ParamField body="model" type="string">

Прямой вызов v1 `POST /proxy/wan/api/v1/services/aigc/video-generation/video-synthesis` ОБЯЗАН его передавать, а перечисление допустимых написаний находится в собственном компоненте этой операции, `WanVideoGenerationRequest`.
</ParamField>

  Параметры обработки видео

<ParamField body="parameters.audio" type="boolean" default="true">

</ParamField>

<ParamField body="parameters.audio_setting" type="string" default="&quot;auto&quot;">
  Настройка аудио видео для модели wan2.7-videoedit.
- auto (по умолчанию): модель разумно определяет по содержимому промпта
- origin: принудительно сохранить оригинальное аудио из входного видео

  Возможные значения: `auto`, `origin`
</ParamField>

<ParamField body="parameters.duration" type="integer" default="5">
  Длительность сгенерированного видео в секундах:
- модели wan2.5: 5 или 10 секунд
- wan2.6-t2v, wan2.6-i2v: 5, 10 или 15 секунд
- wan2.6-r2v: только 5 или 10 секунд (без поддержки 15s)
- wan2.7-i2v, wan2.7-t2v: целое число в [2, 15]
- wan2.7-r2v, wan2.7-videoedit: целое число в [2, 10]
- wan3.0-video: целое число в [2, 30] без входного видео; с входным видео суммарная
  длительность входного видео + длительность выходного видео не должна превышать 30 секунд; -1 включает
  режим умной длительности, в котором модель выбирает подходящую длительность
Этот прокси возвращает 400 для длительности вне [-1, 30].

  Диапазон: `-1` до `30`
</ParamField>

<ParamField body="parameters.ratio" type="string">
  Соотношение сторон сгенерированного видео. Только для моделей wan2.7 и wan3.0.
Для моделей wan2.7 по умолчанию определяется по уровню разрешения, если не указано.
Для wan3.0-video значение adaptive (по умолчанию) автоматически рекомендует подходящеесоотношение сторон на основе пропорций входного медиа и замысла.

  Возможные значения: `adaptive`, `16:9`, `9:16`, `1:1`, `4:3`, `3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  Уровень разрешения. Поддерживаемые значения зависят от модели:
- wan2.5-i2v-preview: 480P, 720P, 1080P
- модели wan2.6 (t2v, i2v, r2v): только 720P, 1080P (без поддержки 480P)
- модели wan2.7 (i2v, t2v, r2v, videoedit): 720P, 1080P (по умолчанию 1080P)
- wan3.0-video, wan3.0-video-prime: 480P, 720P, 1080P (по умолчанию у провайдера 1080P)
- happyhorse-1.0-* (t2v, i2v, r2v, video-edit): 720P, 1080P
- happyhorse-1.1-* (t2v, i2v, r2v): 480P, 720P, 1080P
Этот прокси отклоняет запросы на генерацию видео, в которых не указаны ни resolution, ни size, поскольку уровень разрешения определяет тариф выставления счетов. Он приводит resolution к верхнему регистру перед проверкой и передаёт значение в верхнем регистре, возвращает 400 для значения вне этого перечисления и возвращает 400 для 480P (независимо от того, передано ли оно как resolution или как size со значением 480P) для моделей wan2.6, wan2.7 и happyhorse-1.0, перечисленных выше как не поддерживающих 480P.

  Возможные значения: `480P`, `720P`, `1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  Сид случайного числа, используется для управления случайностью сгенерированного моделью содержимого

  Диапазон: от `0` до `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  Интеллектуальное управление многокамерной съёмкой. Активно только при включённом prompt_extend.
Для моделей wan2.6 и wan2.7-r2v.
- single: видео с одним планом (по умолчанию)
- multi: видео с несколькими планами

  Возможные значения: `multi`, `single`
</ParamField>

<ParamField body="parameters.size" type="string">
  Разрешение видео в формате ширина*высота. Поддерживаемые разрешения зависят от модели:
Для wan2.5 T2V: размеры 480P (480*832, 832*480, 624*624), 720P, 1080P
Для wan2.6 T2V/R2V (без 480P):
  720P: 1280*720, 720*1280, 960*960, 1088*832, 832*1088
  1080P: 1920*1080, 1080*1920, 1440*1440, 1632*1248, 1248*1632
Если переданы и size, и resolution, то size определяет тарифицируемый уровень, а resolution всё равно должно быть значением, которое этот прокси принимает для модели. Size со значением 480P возвращает 400 для каждой модели, которая в описании resolution указана как не поддерживающая 480P.
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  Добавлять ли логотип водяного знака; водяной знак располагается в правом нижнем углу
</ParamField>
