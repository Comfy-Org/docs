Справочник по API для Nano Banana Pro. Nano Banana Pro (Gemini 3 Pro Image) представляет собой уровень Pro семейства моделей генерации изображений Nano Banana от Google и ориентирован на сложные сцены и разборчивый текст.

**Вход:** текст, изображение · **Выход:** изображение + текст

Создайте ключ в [вашем рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. **Эндпоинт:** `POST https://api.comfy.org/v2/models/vertexai/gemini-3-pro-image`

## Провайдеры, обслуживающие модель

Эту модель обслуживает непосредственно Comfy Router, если в запросе не указан другой провайдер. Приведённые ниже провайдеры также обслуживают её на том же эндпоинте и с тем же идентификатором модели, они выбираются с помощью параметра запроса `model_provider`.

- **Comfy** (по умолчанию): `POST https://api.comfy.org/v2/models/vertexai/gemini-3-pro-image`
- **fal**, как `fal/fal-nano-banana-pro`: `POST https://api.comfy.org/v2/models/vertexai/gemini-3-pro-image?model_provider=fal`
- **MiniMax**, как `minimax/minimax-nano-banana-pro`: `POST https://api.comfy.org/v2/models/vertexai/gemini-3-pro-image?model_provider=minimax`
- **Pika**, как `pika/pika-nano-banana-pro`: `POST https://api.comfy.org/v2/models/vertexai/gemini-3-pro-image?model_provider=pika`
- **Runware**, как `runware/runware-nano-banana-pro`: `POST https://api.comfy.org/v2/models/vertexai/gemini-3-pro-image?model_provider=runware`
- **WaveSpeed**, как `wavespeed/wavespeed-nano-banana-pro`: `POST https://api.comfy.org/v2/models/vertexai/gemini-3-pro-image?model_provider=wavespeed`

`strict_mode` по умолчанию имеет значение false, поэтому Router преобразует нативное тело запроса, описанное на этой странице, в собственную схему провайдера и преобразует ответ обратно. См. [`model_provider`, `strict_mode` и `fallback_provider`](/ru/development/comfy-router/reference#post-v2modelsprovidermodel) в справочнике API и раздел [Провайдеры, обслуживающие модель](/ru/development/comfy-router/providers), где перечислены все модели, маршрутизируемые таким образом.

### Чтение частей

По умолчанию части с сгенерированным изображением содержат байты base64 в `inlineData.data` и тип медиа в `inlineData.mimeType`. Декодируйте байты и сохраните их в файл. При `uploadImagesToStorage: true` загруженные изображения вместо этого используют `fileData.fileUri` для подписанного URL и `fileData.mimeType` для типа медиа. Скачайте эти изображения до истечения срока действия URL, который наступает через 24 часа после их создания.

**`fileData` может появиться в ответе, который его не запрашивал.** Эти две формы задаются для каждой части, а не для ответа целиком: если задано `uploadImagesToStorage: true`, изображение, загрузка которого не удалась, остаётся в виде `inlineData`, поэтому один ответ может смешивать обе формы. Ориентируйтесь на то, какой ключ присутствует, а не на то, что вы запрашивали. Невозможен только обратный случай: если поле не задано или равно false, каждое сгенерированное изображение возвращается как `inlineData`, и ни одна часть изображения с `fileData` не создаётся. Текстовые части тоже могут появляться, и изображение не гарантированно будет первой частью, поэтому выбирайте часть по нужному полю, а не по индексу. Путь `candidates[0].content.parts[0].inlineData.data` в примерах быстрого старта выше читает единственную inline-часть образца ответа на этой странице; при работе с реальным ответом просматривайте `parts` в поисках нужного ключа, а не обращайтесь по индексу 0.

**`thoughtSignature` также является полем части и имеет большой размер.** Часть может содержать `thoughtSignature`: непрозрачную подпись base64 с рассуждением модели, которая нужна, чтобы это рассуждение можно было воспроизвести в более позднем запросе. Её нет в сгенерированной схеме выше, которая следует документу запроса/ответа, публикуемому Router. По измерениям на реальных ответах она занимает примерно от 1 до 2 МБ на часть, что сопоставимо с самим изображением, поэтому стоит закладывать на неё бюджет или явно отбрасывать, если вы логируете ответы, пересылаете их через serverless-функцию или сохраняете.

### `imageSize` задаёт класс, а не ширину

`generationConfig.imageConfig.imageSize` принимает значения `1K`, `2K` или `4K`, и каждая следующая ступень удваивает обе стороны, а не задаёт ширину. Запрос с соотношением 16:9 показал 1376x768 при примерно 1.35 МБ в режиме `1K` и 2752x1536 при примерно 5.6 МБ в режиме `2K`: то же соотношение сторон, в четыре раза больше пикселей и примерно в четыре раза больше байт. Поэтому `2K` не означает изображение шириной 2048 пикселей, и если рассчитывать путь загрузки, лимит тела ответа или бакет хранилища исходя из `2K` как из ширины, вы занизите их примерно в четыре раза.

### Цепочка референсов

Если передать ранее сгенерированное изображение сразу обратно на вход, получится новый ракурс того же объекта, поэтому серия кадров одной сцены представляет собой цепочку вызовов, а не один промпт, который должен описать всё сразу. Архитектура, материалы и освещение часто сохраняются вдоль цепочки, но модель этого не гарантирует; считайте согласованность вероятным результатом, который нужно проверять, а не свойством, на которое можно полагаться.

Отправляйте изображение обратно в той форме, которую использовал предыдущий ответ. Для части `inlineData` возьмите байты base64 из `inlineData.data` и отправьте их без изменений как `inlineData`, как показано ниже. Для части, которая вернулась как `fileData` при `uploadImagesToStorage: true`, вместо этого отправьте её `fileData.fileUri` и `fileData.mimeType` как часть `fileData`, пока подписанный URL ещё действителен; повторная загрузка байтов как `inlineData` тоже работает и не имеет срока действия. Затем попросите нужное изменение:

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [
        {
          "inlineData": {
            "mimeType": "image/png",
            "data": "<the base64 from candidates[0].content.parts[].inlineData.data of the previous response>"
          }
        },
        { "text": "the same room, viewed from the opposite corner at eye level" }
      ]
    }
  ],
  "generationConfig": {
    "responseModalities": ["IMAGE"],
    "imageConfig": { "aspectRatio": "16:9" }
  }
}
```

Каждый вызов независим, поэтому передавайте изображение, на основе которого хотите продолжить, а не полагайтесь на историю диалога. Следите за размером тела запроса при построении цепочки: inline-изображение учитывается в [лимите тела запроса](/ru/development/comfy-router/limitations#request-bodies-are-capped) Router, а изображение `2K` примерно в четыре раза больше по количеству байт, чем `1K`.
