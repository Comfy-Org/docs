Справочник по API для `pruna/p-video-upscale`, предоставляемый Comfy Router от Pruna.

**Вход:** Видео · **Выход:** Видео + Аудио

## Быстрый старт

Создайте ключ в [вашем рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. Фрагменты на Python и TypeScript используют Comfy SDK (`pip install comfy-sdk` и `npm install @comfyorg/sdk`); фрагмент cURL выполняет тот же вызов напрямую по HTTP.

**ID модели:** `pruna/p-video-upscale`

**Эндпоинт:** `POST https://api.comfy.org/v2/models/pruna/p-video-upscale`

То же тело запроса, отправленное на `POST https://api.comfy.org/v2/models/pruna/p-video-upscale/requests`. Router отвечает `201` с `request_id`, как только запуск принят, а результат забирается, когда он готов, из этого или другого процесса. [Доставка через очередь](/ru/development/comfy-router/queue) подробно описывает статус, отмену и получение результата.

<CodeGroup>
```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменных окружения.
# Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его при автоматических повторах.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "pruna/p-video-upscale",
            {
                "input": {
                    "target": "1080p",
                    "video": "https://example.com/source.mp4",
                },
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивайте, пока запрос не завершится, выдерживая Retry-After, указанный сервером.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственная полезная нагрузка провайдера, то же значение, которое возвращает models.run().
        # Запрос, завершившийся ошибкой или отменённый, вызывает здесь типизированную ошибку Router.
        result = await handle.get()

    print(result)

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Читает COMFY_API_KEY из переменных окружения.
// Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его при автоматических повторах.
const handle = await comfy.models.submit("pruna/p-video-upscale", {
  input: {
    target: "1080p",
    video: "https://example.com/source.mp4",
  },
});
console.log("requestId:", handle.requestId); // вместе с ID модели это всё, что нужно другому процессу

// Опрашивайте, пока запрос не завершится, выдерживая Retry-After, указанный сервером.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// Тот же результат, который возвращает models.run(). Запрос, завершившийся ошибкой или отменённый, отклоняется здесь.
const result = await handle.get();

console.log(result.data);
```

```bash cURL
# 1. Отправьте запрос. Router отвечает 201 с request_id, status_url, response_url и cancel_url.
curl https://api.comfy.org/v2/models/pruna/p-video-upscale/requests \
  -H "X-API-Key: $COMFY_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d "{\"input\": {\"target\":\"1080p\",\"video\":\"https://example.com/source.mp4\"}}"

# 2. Опрашивайте, пока статус не станет COMPLETED, выдерживая указанное в каждом ответе число секунд Retry-After.
REQUEST_ID="<request_id from the 201 body>"
curl -i https://api.comfy.org/v2/models/pruna/p-video-upscale/requests/$REQUEST_ID/status \
  -H "X-API-Key: $COMFY_API_KEY"

# 3. Получите результат. 200 с нативным выводом модели, 202 с телом статуса, пока запрос ещё выполняется.
curl https://api.comfy.org/v2/models/pruna/p-video-upscale/requests/$REQUEST_ID \
  -H "X-API-Key: $COMFY_API_KEY"
```

## Схема

### Входы

<ParamField body="input" type="object" required>
  Параметры P-Video-Upscale. Задача оплачивается за каждую секунду возвращённого видео: длительность измеряется по возвращённому файлу и округляется вверх до целой секунды. Тариф определяется `target` и тем, превышает ли частота кадров выходного видео 30 fps. Если `fps` не указан, выходное видео сохраняет частоту кадров `video`, и именно эта частота определяет тариф. Задача с `turbo` оплачивается по тарифу turbo для своего `target` при любой частоте кадров. Фильтр безопасности всегда включён; значение `enable_safety_filter` в запросе игнорируется.
</ParamField>

<ParamField body="input.fps" type="integer">
  Частота кадров выходного видео (16-60). Частота выше исходной интерполируется. Если параметр не указан, выходное видео сохраняет исходную частоту.

  Диапазон: от `16` до `60`
</ParamField>

<ParamField body="input.target" type="string" default="&quot;1080p&quot;">
  Пресет разрешения выходного видео: 720p, 1080p, 2k или 4k. Пресет задаёт площадь в пикселях; видео с соотношением сторон не 16:9 сохраняет свои пропорции. Видео, которое уже больше целевого разрешения, не уменьшается.

  Возможные значения: `720p`, `1080p`, `2k`, `4k`
</ParamField>

<ParamField body="input.turbo" type="boolean" default="false">
  Более быстрая задача с немного более низким качеством, оплачивается по тарифу turbo (около трети стандартного тарифа) при любой частоте кадров.
</ParamField>

<ParamField body="input.video" type="string" required>
  URI входного видео, не более 512 MiB. Если `fps` не указан, это должен быть публично доступный URL http(s), поскольку частота кадров считывается до отправки задачи.
</ParamField>

Сгенерировано из схемы, которую Router отдаёт по адресу `GET /v2/models/pruna/p-video-upscale/openapi.json`, того же документа, по которому он проверяет вызов до того, как запрос доходит до провайдера.

### Выходы

<ResponseField name="error" type="string">
  Сообщение об ошибке. Присутствует, когда статус равен failed.
</ResponseField>

<ResponseField name="generation_url" type="string">
  URL готового видео. Присутствует, когда статус равен succeeded.
</ResponseField>

<ResponseField name="message" type="string">
  Понятное человеку сообщение о ходе выполнения.
</ResponseField>

<ResponseField name="moderation" type="object">
  Вердикт проверки безопасности Pruna. Присутствует при статусе failed, если модерация содержимого заблокировала предсказание.
</ResponseField>

<ResponseField name="moderation.blocked" type="boolean">
  Заблокировала ли проверка безопасности предсказание.
</ResponseField>

<ResponseField name="moderation.can_disable" type="boolean">
  Связана ли блокировка с фильтром безопасности, который запрос мог бы отключить.
</ResponseField>

<ResponseField name="moderation.categories" type="string[]">
  Категории политики содержимого, вызвавшие блокировку, например sexual.
</ResponseField>

<ResponseField name="moderation.message" type="string">
  Понятное человеку описание блокировки.
</ResponseField>

<ResponseField name="moderation.phase" type="string">
  Что проверялось: input (отправленный запрос) или output (сгенерированное видео).
</ResponseField>

<ResponseField name="moderation.reason" type="string">
  Понятная человеку причина блокировки.
</ResponseField>

<ResponseField name="status" type="string">
  Статус предсказания: starting, processing, succeeded, failed или canceled.
</ResponseField>
