Параметры (необязательно): добавьте --[параметры] после текстового промпта, чтобы управлять характеристиками видео:
- --resolution (--rs): 480p, 720p, 1080p (по умолчанию: 720p)

Ограничение на стороне Comfy, а не ограничение BytePlus. BytePlus не публикует
ограничение длины текста и принял 40 000 символов в тесте (2026-09-17).
Оно считает символы, а не байты, поэтому многобайтовый промпт при передаче может быть
в несколько раз больше. Оно ограничивает только это поле, а не запрос:
`content` является массивом, а весь документ ограничивает лимит размера тела запроса.

при прямом вызове v1 /proxy вместо него отвечает собственный валидатор BytePlus.
Значение задано намного выше реального трафика, чтобы оно никогда не решало судьбу
настоящего промпта. Повышайте его, если вызывающей стороне нужно больше.

<ParamField body="generate_audio" type="boolean" default="true">
  Поддерживается Seedance 2.5, 2.0, 2.0 fast, 2.0 mini и 1.5 pro. Включает ли сгенерированное видео аудио, синхронизированное с визуальным рядом.
true: модель выводит видео с синхронизированным аудио.
false: модель выводит видео без звука.На моделях, которые это поддерживают, сгенерированная аудиодорожка проверяется провайдером на содержимое отдельно от видео; отказ по ней возвращается как `content_policy_violation` и, поскольку аудио отличается при каждом запуске, может проявляться непостоянно для входа, который провайдер в остальном принимает. В этом случае отправьте `false` для видео без звука; это помогает, только если отклонённой модальностью было именно аудио, что синхронный ответ Router указывает как `refusal_subject: output_audio` (запрос в очереди пока этого не определяет). Финальный рендер Seedance 2.5 наследует `generate_audio` от своей задачи Draft, поэтому вместо этого пересоздайте Draft с `false`.

<ParamField body="omni_reference_task_type" type="string">
  Только для Seedance 2.5. Задача, для которой используется референсный материал. Если поле не указано, используется авто: модель определяет задачу по промпту и референсному материалу, а настройка, противоречащая её трактовке (например, `duration` или `ratio` для того, что она считает редактированием), применяется только после начала генерации, которая тарифицируется.
reference: создаёт новое видео запрошенной `duration` на основе референсных изображений, видео и аудио.
edit: изменяет прикреплённое референсное видео. Выходные данные сохраняют длину и соотношение сторон исходного клипа, поэтому отправьте `duration: -1` и не указывайте `ratio` (или отправьте `adaptive`).
extend: продолжает референсное видео. Выходные данные: только вновь сгенерированный сегмент запрошенной `duration`; его соотношение сторон следует за клипом.
Явное значение проверяется провайдером при отправке (`InvalidParameter.TaskTypeConstraint` / `TaskTypeMismatch`), поэтому значение, не подходящее к запросу, завершается ошибкой до начала генерации и не тарифицируется; у авто такой проверки нет. Эта проверка выполняется только на нативной ветке BytePlus: у альтернативной ветки провайдера (при fallback или выбранной через `model_provider`) нет поля типа задачи, значение отбрасывается, и этот провайдер сам определяет задачу, как и в случае с авто. Об отбрасывании сообщается в `X-Comfy-Router-Dropped-Params`: в ответе синхронного маршрута запуска и в ответе `201` на постановку в очередь. У маршрута с очередью нет fallback, поэтому альтернативной ветки он достигает только через `model_provider`.

  Возможные значения: `reference`, `edit`, `extend`
</ParamField>

mov: профессиональный контейнер (H.264 High 4:4:4 Predictive/PCM, yuv444p) с высокой точностью цвета, подходит для постпродакшна; больший размер файла.

Генерация по первому кадру / первому и последнему кадру в Seedance 2.5: выходные данные следуют соотношению сторон первого кадра, поэтому принимается только `adaptive` (или отсутствие поля), а конкретное соотношение отклоняется с кодом 400 до отправки. Seedance 2.0 принимает конкретное соотношение в этих режимах.

<ParamField body="resolution" type="string">

Примечание: Seedance 2.0, 2.0 fast и 2.0 mini не поддерживают 1080p. Seedance 2.5 поддерживает 480p, 720p, 1080p и 4k.

<ParamField body="return_last_frame" type="boolean" default="false">
  Возвращать ли изображение последнего кадра сгенерированного видео.
true: возвращает изображение последнего кадра сгенерированного видео. После установки этого параметра в true вы можете получить изображение последнего кадра, вызвав запрос информации о задаче генерации видео. Изображение последнего кадра имеет формат PNG, его ширина и высота в пикселях совпадают с размерами сгенерированного видео, и оно не содержит водяных знаков. Этот параметр позволяет генерировать несколько последовательных видео: последний кадр ранее сгенерированного видео используется как первый кадр следующей задачи, что позволяет быстро создавать несколько последовательных видео.

</ParamField>

### Выходы

<ResponseField name="content" type="object">
  Результат после завершения задачи генерации видео: содержит URL для скачивания выходного видео и, если BytePlus его возвращает, URL для скачивания последнего кадра. И `video_url`, и `last_frame_url` ПОВТОРНО РАЗМЕЩАЮТСЯ на хранилище Comfy; все остальные поля здесь принадлежат BytePlus. Может быть null: BytePlus очищает URL через 24 часа после задачи, и документ со статусом succeeded, запрошенный позже, может содержать `content` отсутствующим или null.
</ResponseField>

<ResponseField name="content.last_frame_url" type="string">
  URL для скачивания последнего кадра сгенерированного видео, возвращается, когда в запросе задан `return_last_frame`. Не выводите формат изображения из этого URL: BytePlus документирует последний кадр как PNG на стороне запроса, Router повторно размещает те байты, которые ему отдали, и определяет их тип по upstream-заголовку Content-Type или по анализу содержимого, а `image/jpeg` является лишь крайним запасным вариантом, когда не сработало ни то, ни другое. Router повторно размещает последний кадр на хранилище Comfy и переписывает это поле, поэтому обычно это подписанный Comfy URL, действительный до 24 часов: он подписывается на 24 часа при создании и воспроизводится из 23-часового мемо, поэтому более поздний запрос может вернуть URL, у которого осталось всего около часа. Когда повторное размещение выполнить не удалось, поле сохраняет собственный URL BytePlus, который BytePlus очищает через 24 часа после задачи. В любом случае ссылка истекает, поэтому скачайте кадр, а не сохраняйте URL.
</ResponseField>

<ResponseField name="content.output_format" type="string">
  Формат контейнера сгенерированного видео (mp4 или mov), когда BytePlus вкладывает его внутрь `content`. Модели Seedance чаще возвращают его как ВЕРХНЕУРОВНЕВОГО соседа `content`: см. поле `output_format` верхнего уровня, и Router читает то из двух, которое присутствует.
</ResponseField>

<ResponseField name="content.upstream_expires_at" type="string (date-time)">
  Время в формате RFC 3339, когда upstream-URL перестают работать: самое раннее время подписи плюс срок действия, который несут сами URL, но не позже, чем `updated_at` задачи плюс 24 часа (задокументированный BytePlus срок жизни URL), когда `updated_at` присутствует; иначе `updated_at` задачи плюс 24 часа. Присутствует только когда присутствует `upstream_video_url` или `upstream_last_frame_url`, и опускается, когда ни один источник не даёт времени. Не связано со сроком жизни повторно размещённых `video_url` / `last_frame_url`.

  Формат: `date-time`
</ResponseField>

<ResponseField name="content.upstream_last_frame_url" type="string">
  Собственный URL BytePlus для скачивания последнего кадра, возвращается байт в байт рядом с повторно размещённым `last_frame_url` на тех же условиях, что и `upstream_video_url`: только для рабочих пространств, включивших эту возможность, только для Seedance 2.x, отсутствует, как только BytePlus его очищает, и является bearer-учётными данными до `upstream_expires_at`.
</ResponseField>

<ResponseField name="content.upstream_video_url" type="string">
  Собственный URL BytePlus для скачивания выходного видео, возвращается байт в байт рядом с повторно размещённым `video_url`. Присутствует ТОЛЬКО для задач Seedance 2.x, запрошенных рабочим пространством, которое Comfy включил на стороне сервера (параметра запроса нет); отсутствует для всех остальных, включая учётные данные, не соответствующие ни одному рабочему пространству (например, классический API-ключ без привязки к рабочему пространству), и отсутствует, как только BytePlus очищает свои URL через 24 часа после генерации. Это presigned URL объектного хранилища, а значит bearer-учётные данные: любой, у кого он есть, может скачать видео до истечения срока, поэтому обращайтесь с ним как с секретом. Он истекает в `upstream_expires_at`, а на Seedance 2.5 BytePlus ограничивает его 100 загрузками, одну из которых расходует собственное повторное размещение Router.
</ResponseField>

<ResponseField name="content.video_url" type="string">

В любом случае ссылка истекает, поэтому скачайте видео, а не сохраняйте URL.
</ResponseField>

<ResponseField name="created_at" type="integer">

<ResponseField name="duration" type="number">

Объявлена как number, а не integer, потому что BytePlus непостоянен в этом: наблюдалось, что задачи видео возвращают целые секунды, а смежные интерфейсы BytePlus сообщают дробные длительности, поэтому клиент не должен предполагать целочисленное значение.
