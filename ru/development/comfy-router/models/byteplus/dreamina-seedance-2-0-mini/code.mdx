        # Собственный payload провайдера, то же значение, что возвращает models.run().

<ParamField body="content[].text" type="string">
  Входная текстовая информация для модели. Включает текстовый промпт и необязательные параметры.

Текстовый промпт (обязательно): описание видео, которое нужно сгенерировать, с использованием китайских и английских символов.

Параметры (необязательно): добавьте --[parameters] после текстового промпта, чтобы управлять характеристиками видео:
- --resolution (--rs): 480p, 720p, 1080p (по умолчанию: 720p)
- --ratio (--rt): 21:9, 16:9, 4:3, 1:1, 3:4, 9:16, 9:21, adaptive (по умолчанию: 16:9 или adaptive)
- --duration (--dur): 3-12 секунд (по умолчанию: 5)
- --framepersecond (--fps): 24 (по умолчанию: 24)
- --watermark (--wm): true/false (по умолчанию: false)
- --seed (--seed): -1 до 2^32-1 (по умолчанию: -1)
- --camerafixed (--cf): true/false (по умолчанию: false)

Пример: "A beautiful landscape --ratio 16:9 --resolution 720p --duration 5"

Ограничение на стороне Comfy, а не ограничение BytePlus. BytePlus не публикует
ограничение длины текста и принял 40 000 символов при тестировании (2026-09-17).
Считаются символы, а не байты, поэтому многобайтовый промпт может занимать
в передаче в несколько раз больше. Оно ограничивает только это одно поле,
а не запрос: `content` это массив, и весь документ ограничивает лимит тела запроса.
Comfy Router (/v2/models/byteplus/\{model}) это поверхность, которая его применяет;
при прямом вызове v1 /proxy вместо него отвечает собственный валидатор BytePlus.
Значение задано намного выше реального трафика, чтобы оно никогда не затрагивало
настоящий промпт: увеличьте его, если вызывающей стороне нужно больше.

<ParamField body="generate_audio" type="boolean" default="true">
  Поддерживается Seedance 2.5, 2.0, 2.0 fast и 2.0 mini. Включает ли сгенерированное видео аудио, синхронизированное с изображением.
true: модель выводит видео с синхронизированным аудио.
false: модель выводит видео без звука.На моделях, где это поддерживается, сгенерированная аудиодорожка проверяется провайдером на содержимое отдельно от видео; отказ в этом случае возвращается как `content_policy_violation` и, поскольку аудио отличается при каждом запуске, может проявляться нестабильно для входа, который провайдер в остальном принимает. Если так произошло, отправьте `false`, чтобы получить видео без звука; это помогает только тогда, когда отказанной модальностью было именно аудио, что синхронный ответ Router указывает как `refusal_subject: output_audio` (запрос в очереди пока этого не сообщает). Финальный рендер Seedance 2.5 наследует `generate_audio` от своей задачи Draft, поэтому пересоздайте Draft с `false`.
</ParamField>

<ParamField body="model" type="string">
  ID вызываемой модели. Поддерживаемые модели: seedance-1-0-pro-250528, seedance-1-0-pro-fast-251015, dreamina-seedance-2-0-260128, dreamina-seedance-2-0-fast-260128, dreamina-seedance-2-0-mini и dreamina-seedance-2-5-260628. Прямой вызов v1 к POST /proxy/byteplus/api/v3/contents/generations/tasks ОБЯЗАН его передавать: прокси отклоняет с кодом 400 любое другое значение, а также его отсутствие. Его НЕТ в списке `required` этой схемы, потому что Comfy Router подставляет его из сегмента пути `{model}` в /v2/models/byteplus/\{model}, поэтому вызывающий через Router его опускает.
</ParamField>

<ParamField body="omni_reference_task_type" type="string">
  Только Seedance 2.5. Задача, для которой используется референсный медиафайл. Если параметр опущен, используется авто: модель определяет задачу по промпту и референсным медиа, а настройка, противоречащая её трактовке (например, `duration` или `ratio` при том, что она распознала как редактирование), применяется только после начала генерации, которая тарифицируется.
reference: Создаёт новое видео заданного `duration` на основе референсных изображений, видео и аудио.
edit: Изменяет прикреплённое референсное видео. Результат сохраняет собственную длину и соотношение сторон исходного клипа, поэтому отправьте `duration: -1` и опустите `ratio` (или отправьте `adaptive`).
extend: Продолжает референсное видео. Результат содержит только вновь сгенерированный сегмент заданного `duration`; его соотношение сторон следует за клипом.
Явное значение проверяется провайдером при отправке (`InvalidParameter.TaskTypeConstraint` / `TaskTypeMismatch`), поэтому значение, не соответствующее запросу, отклоняется до начала генерации и не тарифицируется; для авто такой проверки нет. Эта проверка выполняется только на нативной ветке BytePlus: у альтернативной ветки провайдера (при fallback или выбранной через `model_provider`) нет поля типа задачи, она отбрасывает значение, и этот провайдер сам определяет задачу, как при авто. Об отбрасывании сообщается в `X-Comfy-Router-Dropped-Params`, в ответе синхронного маршрута запуска и в ответе `201` на постановку в очередь. У очереди нет fallback, поэтому до альтернативной ветки она доходит только через `model_provider`.

  Возможные значения: `reference`, `edit`, `extend`
</ParamField>

<ParamField body="output_format" type="string" default="&quot;mp4&quot;">

mp4: Универсальный контейнер (H.264/AAC, yuv420p) с широкой совместимостью и меньшим размером файла.
mov: Профессиональный контейнер (H.264 High 4:4:4 Predictive/PCM, yuv444p) с высокой точностью цвета, подходит для постпродакшена; больший размер файла.

  Возможные значения: `mp4`, `mov`

<ParamField body="ratio" type="string">
  Соотношение сторон сгенерированного видео. По умолчанию для Seedance 2.0, 2.0 fast и 2.0 mini: adaptive.
Генерация по первому кадру / первому и последнему кадру в Seedance 2.5: результат следует соотношению сторон первого кадра, поэтому принимается только `adaptive` (или отсутствие поля); конкретное соотношение отклоняется с кодом 400 до отправки. Seedance 2.0 принимает конкретное соотношение в этих режимах.

  Возможные значения: `16:9`, `4:3`, `1:1`, `3:4`, `9:16`, `21:9`, `9:21`, `adaptive`
</ParamField>

<ParamField body="resolution" type="string">
  Разрешение видео. По умолчанию для Seedance 2.5, 2.0, 2.0 fast, 2.0 mini и 1.0 lite: 720p. По умолчанию для Seedance 1.0 pro и pro-fast: 1080p.
Примечание: Seedance 2.0, 2.0 fast и 2.0 mini не поддерживают 1080p. Seedance 2.5 поддерживает 480p, 720p, 1080p и 4k.

  Возможные значения: `480p`, `720p`, `1080p`, `4k`
</ParamField>

<ParamField body="return_last_frame" type="boolean" default="false">
  Возвращать ли изображение последнего кадра сгенерированного видео.
true: Возвращает изображение последнего кадра сгенерированного видео. Установив этот параметр в true, вы можете получить изображение последнего кадра, запросив информацию о задаче генерации видео. Изображение последнего кадра имеет формат PNG, его ширина и высота в пикселях совпадают с размерами сгенерированного видео, и оно не содержит водяных знаков. Этот параметр позволяет генерировать несколько последовательных видео: последний кадр предыдущего видео используется как первый кадр следующей задачи генерации видео, что обеспечивает быструю генерацию нескольких последовательных видео.
false: Не возвращает изображение последнего кадра сгенерированного видео.
</ParamField>

<ResponseField name="content.last_frame_url" type="string">

Не определяйте формат изображения по этому URL: BytePlus документирует последний кадр как PNG на стороне запроса, Router размещает заново те байты, которые ему передали, и определяет тип по заголовку Content-Type от upstream или по анализу содержимого, а `image/jpeg` это лишь крайний запасной вариант, когда не сработало ни то, ни другое. <ResponseField name="content.upstream_video_url" type="string">
