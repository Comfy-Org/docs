Создайте ключ в [вашем рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. **Эндпоинт:** `POST https://api.comfy.org/v2/models/byteplus/dreamina-seedance-2-0-mini`

import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменных окружения.
# Каждый вызов submit() создаёт свой Idempotency-Key и переиспользует его для автоматических повторов.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "byteplus/dreamina-seedance-2-0-mini",
            {
                "content": [
                    {
                        "text": "A red fox trotting through a snowy pine forest",

        # Опрашивайте до завершения запроса, ожидая Retry-After, который указывает сервер.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственный payload провайдера, то же значение, что возвращает models.run().
        # Запрос, который завершился ошибкой или был отменён, здесь вызывает типизированную ошибку Router.
        result = await handle.get()

    print(result)

asyncio.run(main())

<ParamField body="content[].text" type="string">
  Входная текстовая информация для модели. Включает текстовый промпт и необязательные параметры.

Текстовый промпт (обязательно): описание видео, которое нужно сгенерировать, китайскими и английскими символами.

Параметры (необязательно): добавьте --[parameters] после текстового промпта, чтобы управлять характеристиками видео:
- --resolution (--rs): 480p, 720p, 1080p (по умолчанию: 720p)
- --ratio (--rt): 21:9, 16:9, 4:3, 1:1, 3:4, 9:16, 9:21, adaptive (по умолчанию: 16:9 или adaptive)
- --duration (--dur): 3-12 секунд (по умолчанию: 5)
- --framepersecond (--fps): 24 (по умолчанию: 24)
- --watermark (--wm): true/false (по умолчанию: false)
- --seed (--seed): от -1 до 2^32-1 (по умолчанию: -1)
- --camerafixed (--cf): true/false (по умолчанию: false)

Пример: "A beautiful landscape --ratio 16:9 --resolution 720p --duration 5"

Ограничение на стороне Comfy, а не ограничение BytePlus. BytePlus не публикует ограничение длины текста и принял 40 000 символов в тесте (2026-09-17).
Считаются символы, а не байты, поэтому многобайтовый промпт при передаче может быть в несколько раз больше.
Оно ограничивает только это поле, а не запрос:
`content` — это массив, и именно ограничение тела запроса ограничивает
весь документ. Comfy Router (/v2/models/byteplus/\{model}) — это поверхность,
которая его применяет; при прямом вызове v1 /proxy вместо этого отвечает
собственный валидатор BytePlus. Значение задано намного выше реального
трафика, поэтому оно никогда не отклоняет настоящий промпт; увеличьте его, если вызывающей стороне нужно больше.

<ParamField body="generate_audio" type="boolean" default="true">
  Поддерживается Seedance 2.5, 2.0, 2.0 fast, 2.0 mini и 1.5 pro. Включает ли сгенерированное видео аудио, синхронизированное с изображением.
true: модель выдаёт видео с синхронизированным аудио.
false: модель выдаёт видео без звука.На моделях, где это поддерживается, провайдер отдельно от видео проверяет содержимое сгенерированной аудиодорожки; отказ по ней возвращается как `content_policy_violation` и, поскольку аудио отличается при каждом запуске, может проявляться нестабильно для входа, который провайдер в остальном принимает. В таком случае отправьте `false`, чтобы получить видео без звука; это помогает только тогда, когда отклонённой модальностью было именно аудио, что синхронный ответ Router указывает как `refusal_subject: output_audio` (запрос в очереди пока этого не определяет). Финальный рендер Seedance 2.5 наследует `generate_audio` от своей задачи Draft, поэтому вместо этого пересоздайте Draft с `false`.
</ParamField>

<ParamField body="model" type="string">
  ID модели для вызова. Поддерживаемые модели: seedance-1-5-pro-251215, seedance-1-0-pro-250528, seedance-1-0-pro-fast-251015, dreamina-seedance-2-0-260128, dreamina-seedance-2-0-fast-260128, dreamina-seedance-2-0-mini и dreamina-seedance-2-5-260628. Прямой вызов v1 к POST /proxy/byteplus/api/v3/contents/generations/tasks ОБЯЗАН передавать его: прокси отклоняет с кодом 400 любое другое значение, а также его отсутствие. Его НЕТ в списке `required` этой схемы, потому что Comfy Router подставляет его из сегмента пути `{model}` в /v2/models/byteplus/\{model}, поэтому вызывающая сторона Router его не передаёт.
</ParamField>

<ParamField body="omni_reference_task_type" type="string">
  Только для Seedance 2.5. Задача, для которой используются референсные материалы. Если параметр не указан, применяется auto: модель определяет задачу по промпту и референсным материалам, а настройка, противоречащая её трактовке (например, `duration` или `ratio` при том, что модель считает это редактированием), разрешается только после запуска генерации, которая тарифицируется.
reference: создаёт новое видео запрошенной `duration` под управлением референсных изображений, видео и аудио.
edit: изменяет прикреплённое референсное видео. Результат сохраняет собственную длительность и соотношение сторон исходного клипа, поэтому отправьте `duration: -1` и не указывайте `ratio` (или отправьте `adaptive`).
extend: продолжает референсное видео. Результат содержит только вновь сгенерированный фрагмент запрошенной `duration`; его соотношение сторон соответствует клипу.
Явно заданное значение проверяется провайдером при отправке (`InvalidParameter.TaskTypeConstraint` / `TaskTypeMismatch`), поэтому значение, не подходящее к запросу, завершается ошибкой до запуска генерации и не тарифицируется; для auto такой проверки нет. Эта проверка выполняется только на собственном плече BytePlus: альтернативное плечо провайдера (при fallback или выбранное через `model_provider`) не имеет поля типа задачи, отбрасывает значение, и такой провайдер определяет задачу сам, как при auto. Отбрасывание раскрывается в `X-Comfy-Router-Dropped-Params`, в ответе синхронного маршрута запуска и в ответе `201` на постановку в очередь. У маршрута с очередью нет fallback, поэтому он попадает на альтернативное плечо только через `model_provider`.

  Возможные значения: `reference`, `edit`, `extend`
</ParamField>

<ParamField body="output_format" type="string" default="&quot;mp4&quot;">
  Только для Seedance 2.5. Формат контейнера выходного видео.
mp4: универсальный контейнер (H.264/AAC, yuv420p) с широкой совместимостью и меньшим размером файла.
mov: профессиональный контейнер (H.264 High 4:4:4 Predictive/PCM, yuv444p) с высокой точностью цвета, подходит для пост-продакшена; больший размер файла.

  Возможные значения: `mp4`, `mov`
</ParamField>

<ParamField body="ratio" type="string">
  Соотношение сторон сгенерированного видео. По умолчанию для Seedance 2.0, 2.0 fast и 2.0 mini, 1.5 pro: adaptive.
Генерация Seedance 2.5 по первому кадру / по первому и последнему кадру: результат следует соотношению сторон первого кадра, поэтому принимается только `adaptive` (или отсутствие поля); конкретное соотношение отклоняется с кодом 400 до отправки. Seedance 2.0 принимает конкретное соотношение в этих режимах.

  Возможные значения: `16:9`, `4:3`, `1:1`, `3:4`, `9:16`, `21:9`, `9:21`, `adaptive`
</ParamField>

<ParamField body="resolution" type="string">
  Разрешение видео. По умолчанию для Seedance 2.5, 2.0, 2.0 fast и 2.0 mini, 1.5 pro, 1.0 lite: 720p. По умолчанию для Seedance 1.0 pro и pro-fast: 1080p.
Примечание: Seedance 2.0, 2.0 fast и 2.0 mini не поддерживают 1080p. Seedance 2.5 поддерживает 480p, 720p, 1080p и 4k.

  Возможные значения: `480p`, `720p`, `1080p`, `4k`
</ParamField>

<ParamField body="return_last_frame" type="boolean" default="false">
  Возвращать ли изображение последнего кадра сгенерированного видео.
true: возвращает изображение последнего кадра сгенерированного видео. После установки этого параметра в true вы можете получить изображение последнего кадра, вызвав операцию Querying the information about a video generation task. Изображение последнего кадра имеет формат PNG, его ширина и высота в пикселях совпадают с размерами сгенерированного видео, и оно не содержит водяных знаков. Использование этого параметра позволяет генерировать несколько последовательных видео: последний кадр предыдущего сгенерированного видео используется как первый кадр следующей задачи генерации видео, что позволяет быстро создавать несколько последовательных видео.
false: не возвращает изображение последнего кадра сгенерированного видео.
</ParamField>

  Включает ли сгенерированное видео водяной знак.

Сгенерировано из схемы, которую Router отдаёт по `GET /v2/models/byteplus/dreamina-seedance-2-0-mini/openapi.json`; это тот же документ, по которому он проверяет вызов до того, как запрос достигнет провайдера.

### Выходы

<ResponseField name="content" type="object">
  Результат после завершения задачи генерации видео: содержит URL для скачивания выходного видео и, если BytePlus его возвращает, URL для скачивания последнего кадра. И `video_url`, и `last_frame_url` ПЕРЕЗАЛИТЫ в хранилище Comfy; все остальные поля здесь принадлежат BytePlus. Может быть null: BytePlus очищает URL через 24 часа после задачи, и документ со статусом succeeded, запрошенный позже, может содержать отсутствующий или равный null `content`.
</ResponseField>

<ResponseField name="content.last_frame_url" type="string">
  URL для скачивания последнего кадра сгенерированного видео, возвращается, когда в запросе задан `return_last_frame`. Не выводите формат изображения из этого URL: BytePlus документирует последний кадр как PNG на стороне запроса, Router перезаливает те байты, которые ему отдали, и определяет тип по Content-Type от апстрима или по содержимому, а `image/jpeg` это лишь крайний запасной вариант, когда не сработало ни то, ни другое. Router перезаливает последний кадр в хранилище Comfy и переписывает это поле, поэтому обычно это URL с подписью Comfy, действительный до 24 часов: подписан на 24 часа при создании и воспроизводится из 23-часового кэша, так что более поздний запрос может вернуть URL, которому остался всего час. Если перезалив выполнить не удалось, поле сохраняет собственный URL BytePlus, который BytePlus очищает через 24 часа после задачи. В любом случае ссылка истекает, поэтому скачайте кадр, а не сохраняйте URL.
</ResponseField>

<ResponseField name="content.output_format" type="string">
  Формат контейнера сгенерированного видео (mp4 или mov), когда BytePlus вкладывает его внутрь `content`. Модели Seedance чаще возвращают его как СОСЕДНЕЕ ПОЛЕ ВЕРХНЕГО УРОВНЯ рядом с `content`: см. поле `output_format` верхнего уровня, и Router читает то из двух, которое присутствует.
</ResponseField>

<ResponseField name="content.upstream_expires_at" type="string (date-time)">
  Время в формате RFC 3339, когда URL апстрима перестают работать: самое раннее время подписи плюс срок действия, который несут сами URL, но никогда не позже `updated_at` задачи плюс 24 часа (задокументированный BytePlus срок жизни URL), когда `updated_at` присутствует; иначе `updated_at` задачи плюс 24 часа. Присутствует только когда присутствует `upstream_video_url` или `upstream_last_frame_url`, и опускается, когда ни один источник не даёт времени. Не связано со сроком жизни перезалитых `video_url` / `last_frame_url`.

  Формат: `date-time`
</ResponseField>

<ResponseField name="content.upstream_last_frame_url" type="string">
  Собственный URL BytePlus для скачивания последнего кадра, возвращается байт в байт рядом с перезалитым `last_frame_url` на тех же условиях, что и `upstream_video_url`: только для рабочих пространств, где это включено, только Seedance 2.x, отсутствует, как только BytePlus его очищает, и является bearer-учётными данными до `upstream_expires_at`.
</ResponseField>

<ResponseField name="content.upstream_video_url" type="string">
  Собственный URL BytePlus для скачивания выходного видео, возвращается байт в байт рядом с перезалитым `video_url`. Присутствует ТОЛЬКО для задач Seedance 2.x, запрошенных рабочим пространством, которое Comfy включило на стороне сервера (параметра запроса нет); отсутствует у всех остальных, включая учётные данные, которые не соответствуют ни одному рабочему пространству (например, классический API-ключ без привязки к рабочему пространству), и отсутствует, как только BytePlus очищает свои URL через 24 часа после генерации. Это предварительно подписанный URL объектного хранилища, а значит bearer-учётные данные: любой, у кого он есть, может скачать видео, пока он не истечёт, поэтому обращайтесь с ним как с секретом. Он истекает в `upstream_expires_at`, а на Seedance 2.5 BytePlus ограничивает его 100 загрузками, одну из которых расходует собственный перезалив Router.
</ResponseField>

<ResponseField name="content.video_url" type="string">

Если перезалив выполнить не удалось, поле сохраняет собственный URL BytePlus, который BytePlus очищает через 24 часа после задачи и на некоторых моделях ограничивает 100 загрузками. В любом случае ссылка истекает, поэтому скачайте видео, а не сохраняйте URL.
</ResponseField>

<ResponseField name="duration" type="number">
