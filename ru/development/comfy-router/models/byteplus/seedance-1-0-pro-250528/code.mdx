Создано из схемы, которую Router отдаёт по адресу `GET /v2/models/byteplus/seedance-1-0-pro-250528/openapi.json`, того же документа, по которому он проверяет вызов, прежде чем запрос доходит до провайдера.

<ResponseField name="content" type="object">

И `video_url`, и `last_frame_url` переразмещаются в хранилище Comfy; все остальные поля здесь принадлежат BytePlus. Может быть null: BytePlus очищает URL через 24 часа после задачи, и документ успешно выполненной задачи, запрошенный после этого, может содержать `content` отсутствующим или равным null.
</ResponseField>

<ResponseField name="content.last_frame_url" type="string">
  URL для скачивания последнего кадра сгенерированного видео, возвращается, когда в запросе указан `return_last_frame`. Не выводите формат изображения из этого URL: BytePlus документирует последний кадр как PNG на стороне запроса, Router переразмещает те байты, которые ему передали, и определяет их тип по Content-Type от источника или по анализу содержимого, а `image/jpeg` используется только как крайний запасной вариант, если не сработало ни то, ни другое. Router переразмещает последний кадр в хранилище Comfy и перезаписывает это поле, поэтому обычно это подписанный Comfy URL, действительный до 24 часов: при создании он подписывается на 24 часа и переиспользуется из 23-часового кэша, так что при более позднем запросе может вернуться ссылка, которой осталось всего час. Если переразмещение выполнить не удалось, поле сохраняет собственный URL BytePlus, который BytePlus очищает через 24 часа после задачи. В любом случае ссылка истекает, поэтому скачайте кадр, а не сохраняйте URL.

<ResponseField name="content.output_format" type="string">

</ResponseField>

<ResponseField name="content.upstream_expires_at" type="string (date-time)">

Присутствует только когда присутствует `upstream_video_url` или `upstream_last_frame_url`, и опускается, когда ни один источник не даёт времени. <ResponseField name="content.upstream_last_frame_url" type="string">
  Собственный URL BytePlus для скачивания последнего кадра, возвращаемый байт в байт рядом с переразмещённым `last_frame_url` на тех же условиях, что и `upstream_video_url`: только для рабочих пространств, включивших эту возможность, только для Seedance 2.x, отсутствует после того, как BytePlus его очистит, и является bearer-учётными данными до `upstream_expires_at`.
</ResponseField>

<ResponseField name="content.upstream_video_url" type="string">
  Собственный URL BytePlus для скачивания выходного видео, возвращаемый байт в байт рядом с переразмещённым `video_url`. Присутствует ТОЛЬКО для задач Seedance 2.x, которые опрашиваются рабочим пространством, включённым на стороне сервера Comfy (параметра запроса нет); отсутствует для всех остальных, включая учётные данные, не привязанные ни к одному рабочему пространству (например, классический API-ключ без привязки к рабочему пространству), и отсутствует после того, как BytePlus очищает свои URL через 24 часа после генерации. Это presigned URL объектного хранилища, а значит bearer-учётные данные: любой, у кого он есть, может скачать видео до истечения срока, поэтому обращайтесь с ним как с секретом. Он истекает в `upstream_expires_at`, а в Seedance 2.5 BytePlus ограничивает его 100 загрузками, одну из которых расходует собственное переразмещение Router.
