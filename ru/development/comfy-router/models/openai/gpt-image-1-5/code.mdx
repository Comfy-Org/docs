## Быстрый старт

Создайте ключ в [своём рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. **Эндпоинт:** `POST https://api.comfy.org/v2/models/openai/gpt-image-1.5`

Router отвечает `201` с `request_id`, как только запуск принят, а результат забирается, когда он готов, из этого или любого другого процесса. [Доставка через очередь](/ru/development/comfy-router/queue) описывает статус, отмену и получение результата.

```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменной окружения.
# Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его при автоматических повторах.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "openai/gpt-image-1.5",
            {
                "prompt": "a rocketship on a launchpad",
                "quality": "low",
                "size": "1024x1024",
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели этого достаточно любому другому процессу

        # Опрашивайте статус, пока запрос не завершится, выдерживая Retry-After, указанный сервером.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственный payload провайдера, то же значение, что возвращает models.run().
        # Запрос, который завершился ошибкой или был отменён, выбрасывает здесь типизированную ошибку Router.
        result = await handle.get()

    print(result)

asyncio.run(main())
```

import { comfy } from "@comfyorg/sdk";

// Читает COMFY_API_KEY из переменной окружения.
// Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его при автоматических повторах.

  quality: "low",
  size: "1024x1024",
});

// Опрашивайте статус, пока запрос не завершится, выдерживая Retry-After, указанный сервером.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// Тот же результат, что возвращает models.run(). Запрос, который завершился ошибкой или был отменён, отклоняется здесь.
const result = await handle.get();

console.log(result.data);

## Схема

### Входы

<ParamField body="background" type="string">
  Прозрачность фона. `auto` позволяет модели выбрать.

  Возможные значения: `transparent`, `opaque`, `auto`
</ParamField>

<ParamField body="image" type="string | string[]">
  Исходное изображение (или несколько) для редактирования. НАЛИЧИЕ ЭТОГО ПОЛЯ ВЫБИРАЕТ ОПЕРАЦИЮ РЕДАКТИРОВАНИЯ: полностью опустите его для генерации из текста в изображение.
Опубликованный пример модели это вызов ГЕНЕРАЦИИ, в котором это поле опущено. Добавление `image` составляет всю разницу между двумя режимами: тот же эндпоинт, тот же id модели, за исключением того, что промпт редактирования описывает ИЗМЕНЕНИЕ, которое вы хотите, а не сцену, поэтому тело редактирования ниже читается иначе, чем пример генерации, хотя структурно новым является только это поле.
Его можно скопировать в точности как напечатано: `{"prompt": "give the rocketship rainbow coloring", "image": ["data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="], "size": "1024x1024"}` -- полезная нагрузка это полный PNG 1x1, а не сокращение, и это тело закреплено как принятый случай в собственных тестах валидации запросов Router. Подставьте байты своего изображения.
Принимает одно изображение или массив из них; gpt-image-1 и более поздние принимают до 16, что Router проверяет по этой схеме перед отправкой.
</ParamField>

<ParamField body="mask" type="string">
  Одно изображение, либо как https URL, который Router загружает от имени вызывающей стороны, либо как URI `data:image/<format>;base64,<payload>`, несущий байты встроенно. Принимаемые типы изображений: png, webp и jpeg, и этот набор ПРОВЕРЯЕТСЯ на этапе разрешения, а не передан провайдеру: svg, gif, avif или tiff отклоняется здесь, с указанием отправленного вами изображения, вместо того чтобы стать ошибкой партнёра в двух шагах от причины.
Предпочитайте форму с URL. Полезная нагрузка base64 раздувается примерно в 4/3, а всё тело запроса ограничено 100 MiB, поэтому встроенная форма упирается в потолок около исходного изображения 75 MB; URL полностью обходит это. Ограничения на изображение и на запрос, указанные в конце этого описания, строже ограничения тела, поэтому для изображения любого реального размера именно они встретятся первыми.
URL ДОЛЖЕН РАЗРЕШАТЬСЯ БЕЗ ВАШИХ УЧЁТНЫХ ДАННЫХ. Router загружает его на стороне сервера и не отправляет учётные данные вызывающей стороны с запросом, поэтому поддерживается presigned URL, тот, чья подпись находится в строке запроса. Аутентифицированный эндпоинт, такой как `/api/assets/{id}/content`, отвечает Router 401 вместо изображения; запросите этот URL сами и передайте подписанный URL, на который он перенаправляет.
ЗАГРУЗКА ОГРАНИЧЕНА ИМЕНОВАННЫМ НАБОРОМ ХОСТОВ, а не открытым интернетом, и тот же список повторно применяется к каждому шагу перенаправления, а также к URL, который вы отправляете: поэтому URL на любом другом хосте или тот, что перенаправляет за пределы списка, отклоняется до обращения к какому-либо провайдеру. Сегодня этот список это только собственная доставка ассетов Comfy: подписанный URL `storage.googleapis.com` в бакете ассетов Comfy, в форму которого `/api/assets/{id}/content` вас перенаправляет. Партнёрский CDN или обычный https-хост НЕ входит в список.
ДВА РАСШИРЕНИЯ ВНЕДРЯЮТСЯ, И ОБА ПО УМОЛЧАНИЮ ВЫКЛЮЧЕНЫ СЕГОДНЯ. Они поставляются за ОДНИМ переключателем и включаются вместе, поэтому считайте всё ниже предстоящим, а не тем, на что можно опираться уже сейчас: спросите, прежде чем полагаться на любое из них.
ПЕРВОЕ это бакет, в который `POST /customers/storage` подписывает вашу загрузку. Пока внедрение не достигнет вашей среды, URL загрузки из этого эндпоинта отклоняется здесь, хотя бакет принадлежит Comfy и хост тот же самый: поэтому «загрузить в Comfy, затем передать URL» пока НЕ работает, а работающая форма это подписанный URL, на который перенаправляет `/api/assets/{id}/content`.
ВТОРОЕ ВКЛЮЧАЕТСЯ ДЛЯ КАЖДОГО АККАУНТА ОТДЕЛЬНО, а не для всех сразу, потому что бакет за этими хостами ваш, а не наш: даже когда переключатель выше включён, аккаунт, для которого не включены входящие сторонние медиа, отклоняется, и ему сообщают об этом именно такими словами, а не говорят, что хост не поддерживается. Попросите вашего контакта в Comfy включить это для вашего аккаунта. Дополнительно он допускает эти хосты стороннего объектного хранилища, где бакет ваш и Router не заявляет на него прав владения: Cloudflare R2 (`<account>.r2.cloudflarestorage.com`, `pub-<hash>.r2.dev`), Amazon S3 (`s3.amazonaws.com` и `s3.<region>.amazonaws.com`, в форме как с путём, так и с префиксом `<bucket>.`), Azure Blob Storage (`<account>.blob.core.windows.net`) и Alibaba Cloud OSS (`<bucket>.oss-<region>.aliyuncs.com`, включая эндпоинт `oss-accelerate`). Это именно эндпоинты объектного хранилища: универсальный эндпоинт на том же домене провайдера, такой как триггер Alibaba Function Compute, не входит в список и отклоняется.
СОПОСТАВЛЯЕТСЯ ФОРМА ИМЕНИ ХОСТА, А НЕ ПРОВАЙДЕР: поэтому упоминание провайдера выше НЕ означает, что принимается каждый URL, который этот провайдер может выдать, и три почти промаха стоит назвать прямо, потому что вызывающая сторона может разумно прийти с каждым из них. ПОЛЬЗОВАТЕЛЬСКИЙ ДОМЕН R2 (`cdn.example.com`) НЕ принимается: Cloudflare описывает `pub-<hash>.r2.dev` как хостнейм для отладки с ограничением скорости и направляет продуктовый трафик на пользовательский домен вместо него, но пользовательский домен не несёт в своём хостнейме ничего, что идентифицировало бы его как R2, поэтому Router не может отличить его от любого другого хоста и отклоняет его: подпишите эндпоинт `<account>.r2.cloudflarestorage.com` или используйте форму `pub-<hash>.r2.dev`. IPv6 dualstack эндпоинт S3 (`s3.dualstack.<region>.amazonaws.com`) тоже не принимается; используйте обычный региональный эндпоинт. Не принимается и альтернативная зона DNS Azure Blob (`<account>.z<N>.blob.storage.azure.net`); используйте `<account>.blob.core.windows.net`. Отказ, который вы получите, называет эти же формы, так что вам не нужно приходить сюда, чтобы их прочитать.
</ParamField>

Плейсхолдеры `<account>` и `pub-<hash>` выше показывают форму, с которой вы обычно придёте; это не ограничение глубины. Сопоставление идёт по суффиксу домена объектного хранилища, поэтому более глубокое имя в том же пространстве имён (`a.b.pub-<hash>.r2.dev`) тоже принимается. Что этим НЕ расширяется, так это само пространство имён: суффикс всё равно должен быть одним из перечисленных.
Пример ниже показывает только форму: реальное значение также несёт параметры запроса подписи, которые здесь намеренно опущены, потому что опубликованный пример навсегда остаётся в спецификации, а настоящая подпись это и утёкшие учётные данные, и ссылка, которая перестаёт работать.
Каждое изображение ограничено 25 MiB, а изображения одного запроса: 64 MiB в сумме. Единственное исключение: ideogram/ideogram-4-5 Precise Edit (вызов, который отправляет `image`), где доступен `context_window`: там каждое изображение может быть размером до 50 MB (50,000,000 байт) и 67,108,864 пикселей, а изображения одного запроса: до 128 MiB в сумме.

<ParamField body="stream" type="boolean">

Ни одна поверхность Comfy не обслуживает потоковую передачу частичных изображений gpt-image: вход `POST /proxy/openai/images/generations` в v1 отклоняет `stream: true` с 400 и никогда не пересылает запрос вышестоящему, поэтому опустите поле и читайте завершённый ответ как одно тело JSON. Поскольку поток никогда не открывается, ограничение OpenAI на сочетание `stream: true` с `n` больше 1 здесь не применяется; `n` пересылается как отправлено.

  Метка времени Unix, в секундах, момента завершения генерации. Это единственный участник, который OpenAI объявляет как Обязательно в ответе генерации изображения, поэтому он присутствует всегда, когда ответ формирует OpenAI; ответ, сформированный fal, minimax, wavespeed или runware на любом из id с альтернативным бэкендом, опускает его полностью, как и остальных четырёх участников, отражающих фактические значения параметров. Объявлен как `int64`, потому что текущее значение эпохи достаточно близко к 2^31, чтобы неформатированный `integer` порождал 32-битное поле во многих генераторах SDK.

  Формат: `int64`
</ResponseField>

<ResponseField name="output_format" type="string">
  Кодировка байтов в `data[].b64_json`: `png`, `webp` или `jpeg`. Это формат, в котором OpenAI фактически закодировала изображение: он совпадает с `output_format` запроса, если тот был передан, и равен `png`, если не был, поэтому декодер может ориентироваться на него, а не выводить формат из запроса заново.
</ResponseField>

<ResponseField name="quality" type="string">
  Уровень качества, на котором фактически выполнялась генерация: OpenAI сообщает один из `low`, `medium`, `high`, `xhigh` или `max`. Это ФАКТИЧЕСКИЙ уровень, а не эхо запроса, в котором собственный `quality` по умолчанию равен `auto`.
</ResponseField>

<ResponseField name="size" type="string">
  Размеры в пикселях, на которых фактически выполнялась генерация, в виде `<width>x<height>`. Это ФАКТИЧЕСКИЙ размер: `size` в запросе по умолчанию равен `auto` и явно допускает `auto`, поэтому это единственное место, где сообщаются фактически использованные размеры.
</ResponseField>
