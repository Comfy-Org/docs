## Быстрый старт

Создайте ключ в [своём рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. Фрагменты Python и TypeScript используют Comfy SDK (`pip install comfy-sdk` и `npm install @comfyorg/sdk`); фрагмент cURL делает тот же вызов напрямую по HTTP.

**ID модели:** `openai/gpt-6.2-astra`

**Эндпоинт:** `POST https://api.comfy.org/v2/models/openai/gpt-6.2-astra`

То же тело, отправленное на `POST https://api.comfy.org/v2/models/openai/gpt-6.2-astra/requests`. Router отвечает `201` с `request_id` сразу после того, как запуск принят, а результат забирается, когда он готов, из этого процесса или из любого другого. [Доставка через очередь](/ru/development/comfy-router/queue) описывает статус, отмену и получение результата.

<CodeGroup>
```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменных окружения.
# Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его при автоматических повторах.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "openai/gpt-6.2-astra",
            {
                "input": "Reply with the single word: ok",
                "max_output_tokens": 1024,
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивайте до завершения запроса, выдерживая Retry-After, указанный сервером.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственный ответ провайдера, то же значение, которое возвращает models.run().
        # Запрос, завершившийся ошибкой или отменённый, вызывает здесь типизированную ошибку Router.
        result = await handle.get()

    print(result)

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Читает COMFY_API_KEY из переменных окружения.
// Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его при автоматических повторах.
const handle = await comfy.models.submit("openai/gpt-6.2-astra", {
  input: "Reply with the single word: ok",
  max_output_tokens: 1024,
});
console.log("requestId:", handle.requestId); // вместе с ID модели это всё, что нужно другому процессу

// Опрашивайте до завершения запроса, выдерживая Retry-After, указанный сервером.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// Тот же результат, который возвращает models.run(). Запрос, завершившийся ошибкой или отменённый, отклоняется здесь.
const result = await handle.get();

console.log(result.data);
```

# 3. Получение. 200 с нативным выводом модели, 202 с телом статуса, пока запрос ещё выполняется.

  -H "X-API-Key: $COMFY_API_KEY"

</ParamField>

<ParamField body="input" type="string | object[]" required>
  Текстовые, графические или файловые входы для модели, используемые для генерации ответа. Единственное поле этого контракта, которое Router не может заполнить, и единственная запись в `required` ниже.
</ParamField>

<ParamField body="instructions" type="string">
  Вставляет системное (или developer) сообщение первым элементом в контекст модели.
</ParamField>

<ParamField body="max_output_tokens" type="integer">
  Верхняя граница числа токенов, сгенерированных для ответа, включая видимые выходные токены и токены рассуждений. Для reasoning-id этот потолок делится со скрытыми токенами рассуждений, поэтому небольшое значение может израсходовать весь бюджет ещё до появления любого видимого текста. Именно поэтому smoke-тесты рассуждений отправляют 1024, а чат-тесты 16.

  Диапазон: `1` до `…`
</ParamField>

<ParamField body="model" type="string">
  Идентификатор модели OpenAI. В Comfy Router это поле НЕОБЯЗАТЕЛЬНО, и Router заполняет его из сегмента пути `{model}`; явный `null` заменяется тем же способом. Отправка значения, не совпадающего с путём, отклоняется.
</ParamField>

<ParamField body="parallel_tool_calls" type="boolean">
  Разрешать ли модели выполнять вызовы инструментов параллельно.
</ParamField>

<ParamField body="previous_response_id" type="string">
  ID предыдущего ответа для многоходовых диалогов.
</ParamField>

<ParamField body="reasoning" type="object">
  ТОЛЬКО ДЛЯ REASONING-УРОВНЯ. Конфигурация для reasoning-моделей, например `{"effort": "medium"}`. Передаётся без изменений; принимаемые ключи см. в руководстве OpenAI по reasoning. Id чат-уровня её игнорирует.
</ParamField>

<ParamField body="store" type="boolean">
  Сохраняет ли OpenAI сгенерированный ответ для последующего извлечения.
</ParamField>

<ParamField body="stream" type="boolean">
  Объявлено, чтобы вызывающая сторона, отправившая его, не получила отказ, но на этой поверхности поле ИНЕРТНО: Router ПРИВОДИТ его к `false` перед отправкой, поскольку он сохраняет ответ провайдера, а не ретранслирует `text/event-stream`, который он не может декодировать, поэтому стриминговая генерация была бы оплачена OpenAI и ни для кого не учтена в тарификации. Ни одна поверхность Comfy не отдаёт поток: вход `POST /proxy/openai/v1/responses` в v1 отклоняет `stream: true` с 400 и никогда не пересылает запрос провайдеру, поэтому опустите поле или отправьте `false` на любой из поверхностей и читайте завершённый ответ как одно JSON-тело.
</ParamField>

<ParamField body="temperature" type="number">
  Температура выборки. ТОЛЬКО ДЛЯ ЧАТ-УРОВНЯ: reasoning-id серии o (`o1`, `o1-pro`, `o3`, `o4-mini`) отклоняют этот параметр в OpenAI. Router не отклоняет его за них (см. примечание этого компонента о том, почему два уровня используют одну схему), поэтому вызов reasoning, отправивший его, получает в ответ ошибку самого OpenAI.

  Диапазон: `0` до `2`
</ParamField>

<ParamField body="text" type="object">
  Конфигурация формата вывода, например `{"format": {"type": "json_schema", ...}}` для Structured Outputs. Передаётся без изменений.
</ParamField>

<ParamField body="tool_choice" type="string | object">
  Как модель должна выбирать, какой инструмент использовать. Либо строковый режим, либо объект, называющий инструмент.
</ParamField>

<ParamField body="tools" type="object[]">
  Определения инструментов, которые модель может вызывать. Router не сужает таксономию инструментов; принимаемые формы см. в справочнике OpenAI по Responses API.
</ParamField>

<ParamField body="top_p" type="number">
  Порог нуклеусной выборки. ТОЛЬКО ДЛЯ ЧАТ-УРОВНЯ, на тех же условиях, что и `temperature`.

  Диапазон: `0` до `1`
</ParamField>

<ParamField body="truncation" type="string">
  Стратегия усечения, когда контекст превышает окно модели. Перечисление здесь ДЕЙСТВИТЕЛЬНО проверяется, в отличие от трёх словарей выше, потому что эти два значения составляют полный набор, документированный OpenAI, и он не расширялся. Явный `null` по-прежнему принимается на тех же условиях, что и поля выше.

  Возможные значения: `auto`, `disabled`
</ParamField>

<ParamField body="usage" type="object">
  Обёртка использования токенов. Присутствует в этом контракте, потому что операция v1 объявляет её в теле запроса; OpenAI заполняет её в ОТВЕТЕ, поэтому у вызывающей стороны нет причин её отправлять.
</ParamField>
