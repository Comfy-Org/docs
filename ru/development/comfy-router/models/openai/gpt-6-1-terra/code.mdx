## Быстрый старт

Создайте ключ в [своём рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. Фрагменты для Python и TypeScript используют Comfy SDK (`pip install comfy-sdk` и `npm install @comfyorg/sdk`), а фрагмент cURL выполняет тот же вызов напрямую по HTTP.

**Эндпоинт:** `POST https://api.comfy.org/v2/models/openai/gpt-6.1-terra`

То же тело запроса, отправленное на `POST https://api.comfy.org/v2/models/openai/gpt-6.1-terra/requests`. Router отвечает `201` с `request_id`, как только запуск принят, а результат забирается, когда он готов, из этого процесса или из другого. [Доставка через очередь](/ru/development/comfy-router/queue) описывает статус, отмену и получение результата.

```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменной окружения.
# Каждый вызов submit() создаёт свой Idempotency-Key и переиспользует его при автоматических повторах.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "openai/gpt-6.1-terra",
            {
                "input": "Reply with the single word: ok",
                "max_output_tokens": 1024,
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивайте, пока запрос не завершится, выжидая Retry-After, указанный сервером.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственный payload провайдера, то же значение, которое возвращает models.run().
        # Запрос, завершившийся ошибкой или отменённый, вызывает здесь типизированную ошибку Router.
        result = await handle.get()

    print(result)

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Читает COMFY_API_KEY из переменной окружения.
// Каждый вызов submit() создаёт свой Idempotency-Key и переиспользует его при автоматических повторах.
const handle = await comfy.models.submit("openai/gpt-6.1-terra", {
  input: "Reply with the single word: ok",
  max_output_tokens: 1024,
});
console.log("requestId:", handle.requestId); // вместе с ID модели это всё, что нужно другому процессу

// Опрашивайте, пока запрос не завершится, выжидая Retry-After, указанный сервером.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// То же значение, которое возвращает models.run(). Запрос, завершившийся ошибкой или отменённый, отклоняется здесь.
const result = await handle.get();

console.log(result.data);
```

## Схема

### Входы

<ParamField body="include" type="string[]">
  Дополнительные выходные данные, которые нужно включить в ответ модели.
</ParamField>

<ParamField body="input" type="string | object[]" required>
  Текстовые, графические или файловые входы для модели, используемые для генерации ответа. Единственное поле этого контракта, которое Router не может заполнить, и единственная запись в `required` ниже.
</ParamField>

<ParamField body="instructions" type="string">
  Вставляет системное сообщение (или сообщение разработчика) первым элементом в контекст модели.
</ParamField>

<ParamField body="max_output_tokens" type="integer">
  Верхняя граница числа токенов, генерируемых для ответа, включая видимые токены вывода и токены рассуждения. Для reasoning-id этот потолок делится со скрытыми токенами рассуждения, поэтому небольшое значение может израсходовать весь бюджет ещё до появления любого видимого текста. Именно поэтому в смоук-тестах reasoning отправляют 1024, а в чат-тестах: 16.

  Диапазон: `1` до `…`
</ParamField>

<ParamField body="model" type="string">
  Идентификатор модели OpenAI. В Comfy Router это поле НЕОБЯЗАТЕЛЬНО, и Router заполняет его из сегмента пути `{model}`; явный `null` заменяется так же. Отправка значения, не совпадающего с путём, отклоняется.
</ParamField>

<ParamField body="parallel_tool_calls" type="boolean">
  Разрешать ли модели выполнять вызовы инструментов параллельно.
</ParamField>

<ParamField body="previous_response_id" type="string">
  ID предыдущего ответа для многоходовых диалогов.
</ParamField>

<ParamField body="reasoning" type="object">
  ТОЛЬКО УРОВЕНЬ REASONING. Конфигурация для моделей рассуждения, например `{"effort": "medium"}`. Передаётся без изменений; допустимые ключи см. в руководстве OpenAI по reasoning. Чат-id её игнорирует.
</ParamField>

<ParamField body="store" type="boolean">
  Сохраняет ли OpenAI сгенерированный ответ для последующего получения.
</ParamField>

<ParamField body="stream" type="boolean">
  Объявлено, чтобы вызывающая сторона, отправившая его, не получила отказ, но на этой поверхности поле БЕЗ ЭФФЕКТА: Router УСТАНАВЛИВАЕТ его в `false` перед отправкой, поскольку он захватывает ответ провайдера, а не ретранслирует `text/event-stream`, который не может декодировать. Поэтому потоковая генерация была бы оплачена OpenAI и не учтена никем. Ни одна поверхность Comfy не обслуживает поток: вход v1 `POST /proxy/openai/v1/responses` отклоняет `stream: true` с ошибкой 400 и никогда не передаёт запрос вышестоящему провайдеру, поэтому опустите поле или отправьте `false` на любой поверхности и читайте завершённый ответ как одно JSON-тело.
</ParamField>

<ParamField body="temperature" type="number">
  Температура выборки. ТОЛЬКО ЧАТ-УРОВЕНЬ: id рассуждения серии o (`o1`, `o1-pro`, `o3`, `o4-mini`) отклоняют этот параметр в OpenAI. Router не отклоняет его для них: см. примечание этого компонента о том, почему два уровня используют одну схему. Поэтому вызов reasoning, отправляющий его, получает в ответ собственную ошибку OpenAI.

  Диапазон: `0` до `2`
</ParamField>

<ParamField body="text" type="object">
  Конфигурация формата вывода, например `{"format": {"type": "json_schema", ...}}` для Structured Outputs. Передаётся без изменений.
</ParamField>

<ParamField body="tool_choice" type="string | object">
  Как модель должна выбирать инструмент. Либо строковый режим, либо объект, называющий инструмент.
</ParamField>

<ParamField body="tools" type="object[]">
  Определения инструментов, которые модель может вызвать. Router не сужает таксономию инструментов; допустимые формы см. в справочнике OpenAI по Responses API.
</ParamField>

<ParamField body="top_p" type="number">
  Порог нуклеусной выборки. ТОЛЬКО ЧАТ-УРОВЕНЬ, на тех же условиях, что и `temperature`.

  Диапазон: `0` до `1`
</ParamField>

<ParamField body="truncation" type="string">
  Стратегия усечения, когда контекст превышает окно модели. Здесь перечисление ПРОВЕРЯЕТСЯ, в отличие от трёх словарей выше, потому что эти два значения составляют полный набор, задокументированный OpenAI, и он не расширялся. Явный `null` по-прежнему принимается на тех же условиях, что и поля выше.

  Возможные значения: `auto`, `disabled`
</ParamField>

<ParamField body="usage" type="object">
  Обёртка использования токенов. Присутствует в этом контракте, потому что операция v1 объявляет её в теле запроса; OpenAI заполняет её в ОТВЕТЕ, поэтому у вызывающей стороны нет причин её отправлять.
</ParamField>
