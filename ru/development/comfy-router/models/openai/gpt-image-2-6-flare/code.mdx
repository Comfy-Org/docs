```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменных окружения.
# Каждый вызов submit() создаёт свой Idempotency-Key и переиспользует его при автоматических повторах.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "openai/gpt-image-2.6-flare",
            {
                "prompt": "a rocketship on a launchpad",
                "quality": "low",
                "size": "1024x1024",
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивайте, пока запрос не завершится, выжидая Retry-After, указанный сервером.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственный payload провайдера, то же значение, которое возвращает models.run().
        # Запрос, который завершился ошибкой или был отменён, вызывает здесь типизированную ошибку Router.
        result = await handle.get()

    print(result)

asyncio.run(main())
```

## Провайдеры, обслуживающие модель

Эту модель напрямую обслуживает Comfy Router, если только в запросе не указан другой провайдер. Провайдеры, перечисленные ниже, также обслуживают её через ту же конечную точку и с тем же ID модели; они выбираются с помощью параметра запроса `model_provider`.

- **Comfy** (по умолчанию): `POST https://api.comfy.org/v2/models/openai/gpt-image-2.6-flare`
- **MiniMax**, как `minimax/minimax-gpt-image-2.6-flare`: `POST https://api.comfy.org/v2/models/openai/gpt-image-2.6-flare?model_provider=minimax`

`strict_mode` по умолчанию имеет значение false, поэтому Router переводит нативное тело запроса, описанное на этой странице, в собственную схему провайдера и переводит ответ обратно. См. [`model_provider`, `strict_mode` и `fallback_provider`](/ru/development/comfy-router/reference#post-v2modelsprovidermodel) в справочнике API и [Провайдеры, обслуживающие модель](/ru/development/comfy-router/providers) для каждой модели, маршрутизируемой таким образом.

### Входы

<ParamField body="background" type="string">
  Прозрачность фона. `auto` позволяет модели выбрать самостоятельно.

  Возможные значения: `transparent`, `opaque`, `auto`
</ParamField>

<ParamField body="frame_count" type="integer">
  Количество кадров в анимированном GIF (2-16, собственный диапазон OpenAI). Имеет смысл только при `output_format: "gif"`: отклоняется вместе с любым другим `output_format`. Если поле не указано в GIF-запросе, используется собственное значение OpenAI по умолчанию, равное 9, ЗА ИСКЛЮЧЕНИЕМ того, что Comfy дополнительно ограничивает это поле в зависимости от окружения (ROUTER_OPENAI_IMAGE_GIF_MAX_FRAMES, но никогда не выше собственного максимума поля, равного 16): значение выше заданного ограничения отклоняется, а неуказанный `frame_count` отклоняется, а не понижается молча, когда само значение по умолчанию 9 превышает заданное ограничение, поэтому вызывающей стороне сообщают о необходимости задать `frame_count` явно, вместо того чтобы получить тихо уменьшенную анимацию по сравнению с умолчанием OpenAI. Количество кадров также ограничивает предварительную оценку стоимости и предел результата в 64 MiB, и оба масштабируются вместе с ним.

  Диапазон: от `2` до `16`
</ParamField>

<ParamField body="frame_duration_ms" type="integer">
  Время в миллисекундах, в течение которого отображается каждый кадр (собственный диапазон OpenAI 20-2000, округляется до 10 мс). Имеет смысл только при `output_format: "gif"`: отклоняется вместе с любым другим `output_format`. Если не указано в GIF-запросе, берётся собственное значение OpenAI по умолчанию, равное 200.

  Диапазон: от `20` до `2000`
</ParamField>

<ParamField body="image" type="string | string[]">
  Исходное изображение (изображения) для редактирования. НАЛИЧИЕ ЭТОГО ПОЛЯ ВЫБИРАЕТ ОПЕРАЦИЮ РЕДАКТИРОВАНИЯ: полностью опустите его для генерации из текста в изображение.
Опубликованный пример модели это вызов ГЕНЕРАЦИИ, в котором данное поле отсутствует. Добавление `image` и составляет всю разницу между двумя режимами: тот же эндпоинт, тот же id модели, за исключением того, что промпт редактирования описывает ИЗМЕНЕНИЕ, которое вы хотите, а не сцену, поэтому тело запроса редактирования ниже читается иначе, чем пример генерации, хотя структурно новым является только это поле.
Его можно скопировать ровно как напечатано: `{"prompt": "give the rocketship rainbow coloring", "image": ["data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="], "size": "1024x1024"}`: полезная нагрузка представляет собой полный PNG 1x1, а не сокращение, и это тело закреплено как принятый случай в собственных тестах валидации запросов Router. Подставьте байты своего изображения.
Принимает одно изображение или массив из них; gpt-image-1 и более поздние принимают до 16, что Router проверяет по этой схеме перед отправкой.
</ParamField>

<ParamField body="mask" type="string">
  Одно изображение, в виде либо https URL, который Router загружает от имени вызывающей стороны, либо URI `data:image/<format>;base64,<payload>` с байтами внутри. Принимаемые типы изображений: png, webp и jpeg, и этот набор ПРОВЕРЯЕТСЯ на этапе разрешения, а не оставляется провайдеру: svg, gif, avif или tiff отклоняется здесь с указанием отправленного вами изображения, вместо того чтобы стать ошибкой партнёра через два шага от причины.
Предпочитайте форму с URL. Полезная нагрузка base64 раздувается примерно в 4/3, а всё тело запроса ограничено 100 MiB, поэтому встроенная форма упирается в потолок при исходном изображении около 75 МБ; URL полностью обходит это. Ограничения медиа на каждое изображение и на каждый запрос, указанные в конце этого описания, строже ограничения тела, поэтому для изображения любого реального размера именно они срабатывают первыми.
URL ДОЛЖЕН РАЗРЕШАТЬСЯ БЕЗ ВАШИХ УЧЁТНЫХ ДАННЫХ. Router загружает его на сервере и не отправляет с запросом учётные данные вызывающей стороны, поэтому поддерживаемой формой является presigned URL, то есть URL, подпись которого находится в строке запроса. Аутентифицированный эндпоинт вроде `/api/assets/{id}/content` отвечает Router кодом 401 вместо изображения; запросите этот URL сами и передайте подписанный URL, на который он перенаправляет.
ЗАГРУЗКА ОГРАНИЧЕНА ИМЕНОВАННЫМ НАБОРОМ ХОСТОВ, а не открытым интернетом, и тот же список повторно применяется к каждому шагу перенаправления, а также к отправляемому вами URL, поэтому URL на любом другом хосте или URL, который перенаправляет за пределы списка, отклоняется до обращения к какому-либо провайдеру. Сегодня этот список включает только собственную доставку ассетов Comfy: подписанный URL `storage.googleapis.com` в бакете ассетов Comfy, то есть форма, на которую перенаправляет `/api/assets/{id}/content`. CDN партнёра или обычный https-хост в список НЕ входят.
ДВА РАСШИРЕНИЯ ВНЕДРЯЮТСЯ, И ОБА СЕГОДНЯ ВЫКЛЮЧЕНЫ ПО УМОЛЧАНИЮ. Они поставляются за ОДНИМ переключателем и включаются вместе, поэтому относитесь ко всему ниже как к предстоящему, а не как к тому, на что уже можно опираться: спрашивайте, прежде чем полагаться на любое из них.
ПЕРВОЕ: это бакет, в который `POST /customers/storage` подписывает вашу загрузку. Пока внедрение не дойдёт до вашего окружения, URL загрузки из этого эндпоинта отклоняется здесь, хотя бакет принадлежит Comfy и хост тот же самый, поэтому «загрузить в Comfy, а затем передать URL» ПОКА НЕ РАБОТАЕТ, а рабочая форма это подписанный URL, на который перенаправляет `/api/assets/{id}/content`.
ВТОРОЕ ВКЛЮЧАЕТСЯ ДЛЯ КАЖДОЙ УЧЁТНОЙ ЗАПИСИ ОТДЕЛЬНО, а не для всех сразу, потому что бакет за этими хостами принадлежит вам, а не нам: даже когда переключатель выше включён, учётная запись, для которой не включены входящие медиа от третьих сторон, отклоняется, и ей сообщают именно это, а не то, что хост не поддерживается. Попросите своего контакта в Comfy включить это для вашей учётной записи. Дополнительно это допускает следующие хосты объектного хранилища третьих сторон, где бакет ваш и Router не заявляет на него прав собственности: Cloudflare R2 (`<account>.r2.cloudflarestorage.com`, `pub-<hash>.r2.dev`), Amazon S3 (`s3.amazonaws.com` и `s3.<region>.amazonaws.com`, в форме path-style или с префиксом `<bucket>.`), Azure Blob Storage (`<account>.blob.core.windows.net`) и Alibaba Cloud OSS (`<bucket>.oss-<region>.aliyuncs.com`, включая эндпоинт `oss-accelerate`). Это именно эндпоинты объектного хранилища: универсальный эндпоинт на том же домене провайдера, например триггер Alibaba Function Compute, в список не входит и отклоняется.
</ParamField>

СОПОСТАВЛЯЕТСЯ ФОРМА ИМЕНИ ХОСТА, А НЕ ПРОВАЙДЕР, поэтому указание провайдера выше НЕ означает, что принимается любой URL, который этот провайдер может выдать; и три близких случая стоит назвать прямо, потому что вызывающая сторона может обоснованно прийти с любым из них. ПОЛЬЗОВАТЕЛЬСКИЙ ДОМЕН R2 (`cdn.example.com`) НЕ принимается: Cloudflare описывает `pub-<hash>.r2.dev` как отладочное имя хоста с ограниченной частотой запросов и направляет продакшен-трафик на пользовательский домен, но пользовательский домен не содержит в своём имени хоста ничего, что указывало бы на R2, поэтому Router не может отличить его от любого другого хоста и отклоняет его: сформируйте presigned URL для эндпоинта `<account>.r2.cloudflarestorage.com` или используйте форму `pub-<hash>.r2.dev`. IPv6-эндпоинт dualstack для S3 (`s3.dualstack.<region>.amazonaws.com`) тоже не принимается; используйте обычный региональный эндпоинт. Не принимается и альтернативная зона DNS Azure Blob (`<account>.z<N>.blob.storage.azure.net`); используйте `<account>.blob.core.windows.net`. В отказе, который вы получите, перечислены эти же формы, так что читать их здесь не обязательно.
Заполнители `<account>` и `pub-<hash>` выше показывают форму, с которой вы обычно придёте; это не ограничение по глубине. Сопоставление идёт по суффиксу домена объектного хранилища, поэтому более глубокое имя в том же пространстве имён (`a.b.pub-<hash>.r2.dev`) также принимается. Что при этом НЕ расширяется, так это само пространство имён: суффикс по-прежнему должен быть одним из перечисленных.
Пример ниже показывает только форму: реальное значение также содержит параметры запроса подписи, которые здесь намеренно опущены, потому что опубликованный пример живёт в спецификации вечно, а реальная подпись это одновременно и утёкшие учётные данные, и ссылка, которая перестаёт работать.
Каждое изображение ограничено 25 MiB, а изображения одного запроса в сумме 64 MiB. Единственное исключение это ideogram/ideogram-4-5 Precise Edit (вызов, который отправляет `image`), где доступен `context_window`: там каждое изображение может быть до 50 MB (50,000,000 байт) и 67,108,864 пикселей, а изображения одного запроса до 128 MiB в сумме.

</ParamField>

<ResponseField name="created" type="integer">
  Unix-временная метка в секундах, указывающая момент завершения генерации. Это единственный участник, который OpenAI объявляет как REQUIRED в ответе на генерацию изображения, поэтому он присутствует всегда, когда производителем выступает OpenAI; ответ, полученный от fal, minimax, wavespeed или runware на любом из id с альтернативным бэкендом, опускает его полностью, как и остальные четыре участника с разрешёнными параметрами.
