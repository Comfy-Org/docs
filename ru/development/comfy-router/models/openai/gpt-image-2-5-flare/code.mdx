Создайте ключ в [своём рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. **Эндпоинт:** `POST https://api.comfy.org/v2/models/openai/gpt-image-2.5-flare`

Router отвечает `201` с `request_id`, как только запуск принят, а результат забирается, когда он готов, из этого или другого процесса.
```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменной окружения.
# Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его при автоматических повторах.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "openai/gpt-image-2.5-flare",
            {
                "prompt": "a rocketship on a launchpad",
                "quality": "low",
                "size": "1024x1024",
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивайте, пока запрос не завершится, выдерживая Retry-After, указанный сервером.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственный ответ провайдера, то же значение, которое возвращает models.run().
        # Запрос, завершившийся ошибкой или отменённый, вызывает здесь типизированную ошибку Router.
        result = await handle.get()

    print(result)

asyncio.run(main())
```

## Провайдеры, обслуживающие модель

Эта модель обслуживается напрямую через Comfy Router, если в запросе не указан другой провайдер. Перечисленные ниже провайдеры также обслуживают её на том же эндпоинте и с тем же ID модели, а выбор выполняется параметром запроса `model_provider`.

- **Comfy** (по умолчанию): `POST https://api.comfy.org/v2/models/openai/gpt-image-2.5-flare`
- **fal** под именем `fal/fal-gpt-image-2.5-flare`: `POST https://api.comfy.org/v2/models/openai/gpt-image-2.5-flare?model_provider=fal`
- **MiniMax** под именем `minimax/minimax-gpt-image-2.5-flare`: `POST https://api.comfy.org/v2/models/openai/gpt-image-2.5-flare?model_provider=minimax`
- **Runware** под именем `runware/runware-gpt-image-2.5-flare`: `POST https://api.comfy.org/v2/models/openai/gpt-image-2.5-flare?model_provider=runware`
- **WaveSpeed** под именем `wavespeed/wavespeed-gpt-image-2.5-flare`: `POST https://api.comfy.org/v2/models/openai/gpt-image-2.5-flare?model_provider=wavespeed`

`strict_mode` по умолчанию имеет значение false, поэтому Comfy Router переводит нативное тело запроса, описанное на этой странице, в собственную схему провайдера и переводит ответ обратно. См. [`model_provider`, `strict_mode` и `fallback_provider`](/ru/development/comfy-router/reference#post-v2modelsprovidermodel) в справочнике API, а также раздел [Провайдеры, обслуживающие модель](/ru/development/comfy-router/providers) для всех моделей, маршрутизируемых таким образом.

### Входы

<ParamField body="background" type="string">
  Прозрачность фона. `auto` позволяет модели выбрать самостоятельно.

  Возможные значения: `transparent`, `opaque`, `auto`
</ParamField>

<ParamField body="image" type="string | string[]">
  Исходное изображение (или изображения) для редактирования. НАЛИЧИЕ ЭТОГО ПОЛЯ ВЫБИРАЕТ ОПЕРАЦИЮ РЕДАКТИРОВАНИЯ: полностью опустите его для генерации текст в изображение.
Опубликованный пример модели это вызов ГЕНЕРАЦИИ, в котором это поле опущено. Добавление `image` составляет всю разницу между двумя режимами: тот же эндпоинт, тот же id модели, за тем исключением, что промпт редактирования описывает ИЗМЕНЕНИЕ, которое вы хотите, а не сцену, поэтому тело запроса редактирования ниже выглядит иначе, чем пример генерации, хотя структурно новым является только это поле.
Его можно скопировать ровно как напечатано: `{"prompt": "give the rocketship rainbow coloring", "image": ["data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="], "size": "1024x1024"}` -- полезная нагрузка это полноценный PNG 1x1, а не сокращение, и это тело закреплено как принятый случай в собственных тестах валидации запросов Router. Подставьте байты своего изображения.
Принимает одно изображение или массив из них; gpt-image-1 и более поздние принимают до 16, и Router проверяет это по данной схеме перед отправкой.
</ParamField>

<ParamField body="mask" type="string">
  Одно изображение: либо https-URL, который Router загружает от имени вызывающей стороны, либо URI `data:image/<format>;base64,<payload>` с байтами внутри. Принимаемые типы изображений: png, webp и jpeg, и этот набор ПРОВЕРЯЕТСЯ на этапе разрешения, а не оставляется провайдеру: svg, gif, avif или tiff отклоняется здесь, с указанием отправленного вами изображения, вместо того чтобы стать ошибкой партнёра через два шага от причины.
Предпочитайте форму с URL. Полезная нагрузка base64 увеличивается примерно в 4/3, а всё тело запроса ограничено 100 MiB, поэтому встроенная форма упирается в потолок около 75 MB исходного изображения; URL полностью обходит это. Ограничения на медиа для одного изображения и одного запроса, указанные в конце этого описания, строже ограничения тела запроса, поэтому для изображения любого реального размера именно они встретятся первыми.
URL ДОЛЖЕН РАЗРЕШАТЬСЯ БЕЗ ВАШИХ УЧЁТНЫХ ДАННЫХ. Router загружает его на сервере и не отправляет учётные данные вызывающей стороны с запросом, поэтому поддерживаемая форма это presigned URL, то есть URL, подпись которого находится в строке запроса. Аутентифицированный эндпоинт, такой как `/api/assets/{id}/content`, отвечает Router кодом 401 вместо изображения; запросите этот URL сами и передайте подписанный URL, на который он перенаправляет.
ЗАГРУЗКА ОГРАНИЧЕНА ИМЕНОВАННЫМ НАБОРОМ ХОСТОВ, а не открытым интернетом, и один и тот же список повторно применяется к каждому шагу перенаправления, а также к отправляемому вами URL: поэтому URL на любом другом хосте или URL, который перенаправляет за пределы списка, отклоняется до обращения к какому-либо провайдеру. Сегодня этот список это только собственная доставка ассетов Comfy: подписанный URL `storage.googleapis.com` в бакете ассетов Comfy, то есть та форма, на которую перенаправляет `/api/assets/{id}/content`. Партнёрский CDN или обычный https-хост в список НЕ входят.
ДВА РАСШИРЕНИЯ СЕЙЧАС ВНЕДРЯЮТСЯ, И ОБА ПО УМОЛЧАНИЮ ВЫКЛЮЧЕНЫ. Они поставляются за ОДНИМ переключателем и включаются вместе, поэтому считайте всё нижеизложенное предстоящим, а не тем, на что уже можно опираться в разработке: спросите, прежде чем полагаться на любое из них.
ПЕРВОЕ это бакет, в который `POST /customers/storage` подписывает вашу загрузку. Пока внедрение не дойдёт до вашей среды, URL загрузки из этого эндпоинта отклоняется здесь, хотя бакет принадлежит Comfy и хост тот же самый: поэтому схема «загрузить в Comfy, затем передать URL» пока НЕ работает, а работающая форма это подписанный URL, на который перенаправляет `/api/assets/{id}/content`.
ВТОРОЕ ВКЛЮЧАЕТСЯ ДЛЯ КАЖДОЙ УЧЁТНОЙ ЗАПИСИ ОТДЕЛЬНО, а не для всех сразу, потому что бакет за этими хостами ваш, а не наш: даже когда переключатель выше включён, учётная запись, для которой не включены входящие сторонние медиа, получает отказ, и ей сообщают именно это, а не то, что хост не поддерживается. Попросите своего контактного представителя Comfy включить это для вашей учётной записи. Дополнительно это допускает следующие хосты сторонних объектных хранилищ, где бакет ваш и Router не заявляет на него прав владения: Cloudflare R2 (`<account>.r2.cloudflarestorage.com`, `pub-<hash>.r2.dev`), Amazon S3 (`s3.amazonaws.com` и `s3.<region>.amazonaws.com`, в форме path-style или с префиксом `<bucket>.`), Azure Blob Storage (`<account>.blob.core.windows.net`) и Alibaba Cloud OSS (`<bucket>.oss-<region>.aliyuncs.com`, включая эндпоинт `oss-accelerate`). Это именно эндпоинты объектных хранилищ: эндпоинт общего назначения в том же домене провайдера, например триггер Alibaba Function Compute, в список не входит и отклоняется.
СОПОСТАВЛЯЕТСЯ ФОРМА ИМЕНИ ХОСТА, А НЕ ПРОВАЙДЕР, поэтому упоминание провайдера выше НЕ означает, что принимается любой URL, который этот провайдер может выдать, и о трёх близких случаях стоит сказать прямо, потому что вызывающая сторона вполне может прийти с каждым из них. ПОЛЬЗОВАТЕЛЬСКИЙ ДОМЕН R2 (`cdn.example.com`) НЕ принимается: Cloudflare описывает `pub-<hash>.r2.dev` как отладочное имя хоста с ограничением частоты и направляет продакшен-трафик вместо него на пользовательский домен, но пользовательский домен не содержит в своём имени хоста ничего, что идентифицировало бы его как R2, поэтому Router не может отличить его от любого другого хоста и отклоняет: подпишите эндпоинт `<account>.r2.cloudflarestorage.com` или используйте форму `pub-<hash>.r2.dev`. Эндпоинт IPv6 dualstack для S3 (`s3.dualstack.<region>.amazonaws.com`) также не принимается; используйте обычный региональный эндпоинт. Как и альтернативная зона DNS Azure Blob (`<account>.z<N>.blob.storage.azure.net`); используйте `<account>.blob.core.windows.net`. В отказе, который вы получите, перечислены эти же формы, так что вам не нужно заходить сюда, чтобы их прочитать.
</ParamField>

Плейсхолдеры `<account>` и `pub-<hash>` выше показывают форму, с которой вы обычно придёте; это не ограничение глубины. Сопоставление идёт по суффиксу домена объектного хранилища, поэтому более глубокое имя в том же пространстве имён (`a.b.pub-<hash>.r2.dev`) тоже принимается. Что этим НЕ расширяется, так это само пространство имён: суффикс всё равно должен быть одним из перечисленных.
Пример ниже показывает только форму: реальное значение также несёт параметры запроса подписи, которые здесь намеренно опущены, потому что опубликованный пример остаётся в спецификации навсегда, а настоящая подпись это и утёкшие учётные данные, и ссылка, которая перестаёт работать.
Каждое изображение ограничено 25 MiB, а изображения одного запроса: 64 MiB в сумме. Единственное исключение это ideogram/ideogram-4-5 Precise Edit (вызов, который отправляет `image`), где доступен `context_window`: там каждое изображение может быть до 50 MB (50,000,000 байт) и 67,108,864 пикселей, а изображения одного запроса: до 128 MiB в сумме.

<ResponseField name="background" type="string">
  Каким получился фон сгенерированного изображения: `opaque` или `transparent`, как это определил OpenAI для данной генерации. Параметр запроса по умолчанию равен `auto`, поэтому именно здесь вызывающий код, который его не закрепил, узнаёт, какой вариант был получен.
</ResponseField>

<ResponseField name="created" type="integer">
  Unix-время в секундах, когда генерация завершилась. Это единственный участник, который OpenAI объявляет как REQUIRED в ответе генерации изображения, поэтому он присутствует всегда, когда производителем является OpenAI; ответ, обслуживаемый fal, minimax, wavespeed или runware для любого из id с альтернативным бэкендом, полностью его опускает, как и остальные четыре участника с разрешёнными параметрами. Объявлен как `int64`, потому что текущее значение эпохи достаточно близко к 2^31, и неформатированный `integer` создаёт 32-битное поле во многих генераторах SDK.

  Формат: `int64`
</ResponseField>

<ResponseField name="output_format" type="string">
  Кодировка байтов в `data[].b64_json`: `png`, `webp` или `jpeg`. Это формат, в котором OpenAI фактически закодировал изображение: он совпадает с `output_format` запроса, если тот был передан, и равен `png`, если не был, поэтому декодер может ориентироваться на него, а не выводить формат из запроса заново.
</ResponseField>

<ResponseField name="quality" type="string">
  Уровень качества, на котором фактически выполнялась генерация: OpenAI сообщает один из `low`, `medium`, `high`, `xhigh` или `max`. Это РАЗРЕШЁННЫЙ уровень, а не эхо запроса, собственный `quality` которого по умолчанию равен `auto`.
</ResponseField>

<ResponseField name="size" type="string">
  Размеры в пикселях, на которых фактически выполнялась генерация, в виде `<width>x<height>`. Это РАЗРЕШЁННЫЙ размер: `size` запроса по умолчанию равен `auto` и явно допускает `auto`, поэтому только здесь сообщаются фактически использованные размеры.
</ResponseField>
