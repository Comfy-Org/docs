**Вход:** текст, изображение · **Выход:** изображение

## Быстрый старт

Создайте ключ в [своём рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. Фрагменты на Python и TypeScript используют Comfy SDK (`pip install comfy-sdk` и `npm install @comfyorg/sdk`); фрагмент cURL это тот же вызов по чистому HTTP.

**ID модели:** `ideogram/ideogram-4-5`

**Эндпоинт:** `POST https://api.comfy.org/v2/models/ideogram/ideogram-4-5`

То же тело запроса, отправленное на `POST https://api.comfy.org/v2/models/ideogram/ideogram-4-5/requests`. Router отвечает `201` с `request_id` сразу после приёма запуска, а результат забирается, когда он готов, из этого процесса или любого другого. [Доставка через очередь](/ru/development/comfy-router/queue) описывает статус, отмену и получение результата.

<CodeGroup>
```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменных окружения.
# Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его при автоматических повторах.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "ideogram/ideogram-4-5",
            {
                "prompt": "A poster for a jazz festival, bold typography, warm colours",
                "quality": "low",
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивайте, пока запрос не завершится, выдерживая Retry-After, указанный сервером.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственный payload провайдера, то же значение, что возвращает models.run().
        # Запрос, который завершился ошибкой или был отменён, вызывает здесь типизированную ошибку Router.
        result = await handle.get()

    print(result)

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Читает COMFY_API_KEY из переменных окружения.
// Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его при автоматических повторах.
const handle = await comfy.models.submit("ideogram/ideogram-4-5", {
  prompt: "A poster for a jazz festival, bold typography, warm colours",
  quality: "low",
});
console.log("requestId:", handle.requestId); // вместе с ID модели это всё, что нужно другому процессу

// Опрашивайте, пока запрос не завершится, выдерживая Retry-After, указанный сервером.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// То же результат, что возвращает models.run(). Запрос, который завершился ошибкой или был отменён, отклоняется здесь.
const result = await handle.get();

console.log(result.data);
```

## Схема

### Входы

<ParamField body="context_window" type="string">
  Только для Precise Edit; требует `image`. Область исходного изображения, с которой работает редактирование, поэтому очень большое изображение можно отредактировать в одном месте и вернуть в полном размере, оставив остальное нетронутым. `none` (значение по умолчанию) редактирует всё изображение. `auto` подгоняет область вокруг `mask` и требует её наличия. В остальных случаях отправьте `y_min,x_min,y_max,x_max` как четыре неотрицательных целочисленных края в пикселях, где `y_max` больше `y_min`, а `x_max` больше `x_min`, не менее 256 пикселей на сторону, соотношение сторон от 1:6 до 6:1 и не более 4,194,304 пикселей по площади. Значение, отличное от `none`, в запросе без `image` отклоняется. `context_window` принимается только там, где включён шлюз контекстного окна; там, где он не включён, любое значение, отличное от `none`, отклоняется с 422.
</ParamField>

<ParamField body="enable_copyright_detection" type="boolean">
  Включить детекцию нарушения авторских прав после генерации.
</ParamField>

<ParamField body="image" type="string">
  Одно изображение: либо https-URL, который Router загружает от имени вызывающей стороны, либо URI `data:image/<format>;base64,<payload>`, несущий байты внутри. Принимаемые типы изображений: png, webp и jpeg, и этот набор ПРОВЕРЯЕТСЯ на этапе resolve, а не оставляется провайдеру: svg, gif, avif или tiff отклоняется здесь, с указанием отправленного вами изображения, вместо того чтобы стать ошибкой партнёра в двух шагах от причины.
Предпочитайте форму с URL. Payload в base64 увеличивается примерно в 4/3 раза, а всё тело запроса ограничено 100 MiB, поэтому встраиваемая форма упирается в исходное изображение около 75 MB; URL полностью это обходит. Ограничения на медиа для одного изображения и для одного запроса, указанные в конце этого описания, жёстче ограничения тела, поэтому для изображения любого реального размера именно они встретятся первыми.
URL ДОЛЖЕН ЗАГРУЖАТЬСЯ БЕЗ ВАШИХ УЧЁТНЫХ ДАННЫХ. Router загружает его на стороне сервера и не отправляет с запросом учётные данные вызывающей стороны, поэтому поддерживаемая форма: presigned URL, то есть URL, подпись которого находится в строке запроса. Аутентифицированная конечная точка вроде `/api/assets/{id}/content` вернёт Router 401 вместо изображения; запросите этот URL сами и передайте подписанный URL, на который она перенаправляет.
ЗАГРУЗКА ОГРАНИЧЕНА ИМЕНОВАННЫМ НАБОРОМ ХОСТОВ, а не открытым интернетом, и тот же список заново применяется к каждому шагу перенаправления, как и к отправленному вами URL: поэтому URL на любом другом хосте или URL, который перенаправляет за пределы списка, отклоняется до того, как будет установлен контакт с каким-либо провайдером. Сегодня этот список: только собственная доставка ассетов Comfy, а именно подписанный URL `storage.googleapis.com` в бакете ассетов Comfy, то есть та форма, на которую перенаправляет `/api/assets/{id}/content`. Партнёрского CDN или обычного https-хоста в списке НЕТ.
ДВА РАСШИРЕНИЯ СЕЙЧАС ВНЕДРЯЮТСЯ, И ОБА СЕГОДНЯ ПО УМОЛЧАНИЮ ВЫКЛЮЧЕНЫ. Они поставляются за ОДНИМ переключателем и включаются вместе, поэтому считайте всё нижеследующее предстоящим, а не тем, на что уже можно опираться: спрашивайте, прежде чем полагаться на любое из них.
ПЕРВОЕ: бакет, в который `POST /customers/storage` подписывает вашу загрузку. Пока внедрение не дойдёт до вашей среды, URL загрузки от этой конечной точки отклоняется здесь, хотя бакет принадлежит Comfy и хост тот же самый, поэтому «загрузить в Comfy, затем передать URL» пока НЕ работает, а работающая форма: подписанный URL, на который перенаправляет `/api/assets/{id}/content`.
ВТОРОЕ ВКЛЮЧАЕТСЯ ДЛЯ КАЖДОГО АККАУНТА ОТДЕЛЬНО, а не для всех сразу, потому что бакет за этими хостами ваш, а не наш: даже когда переключатель выше включён, аккаунт, для которого не включены входящие медиа от третьих сторон, получает отказ и сообщение именно об этом, а не о том, что хост не поддерживается. Попросите вашего контакта в Comfy включить это для вашего аккаунта. Дополнительно это допускает следующие хосты объектного хранилища третьих сторон, где бакет ваш и Router не заявляет на него прав владения: Cloudflare R2 (`<account>.r2.cloudflarestorage.com`, `pub-<hash>.r2.dev`), Amazon S3 (`s3.amazonaws.com` и `s3.<region>.amazonaws.com`, в форме path-style или с префиксом `<bucket>.`), Azure Blob Storage (`<account>.blob.core.windows.net`) и Alibaba Cloud OSS (`<bucket>.oss-<region>.aliyuncs.com`, включая конечную точку `oss-accelerate`). Это именно конечные точки объектного хранилища: универсальная конечная точка на том же домене провайдера, например триггер Alibaba Function Compute, в список не входит и отклоняется.
СОПОСТАВЛЯЕТСЯ ФОРМА ИМЕНИ ХОСТА, А НЕ ПРОВАЙДЕР, поэтому упоминание провайдера выше НЕ означает, что принимается любой URL, который этот провайдер может выдать, и три близких варианта стоит назвать прямо, потому что вызывающая сторона вполне может прийти с каждым из них. ПОЛЬЗОВАТЕЛЬСКИЙ ДОМЕН R2 (`cdn.example.com`) НЕ принимается: Cloudflare документирует `pub-<hash>.r2.dev` как отладочное имя хоста с ограничением частоты запросов и направляет продакшен-трафик на пользовательский домен, но пользовательский домен ничего в своём имени хоста не содержит, что указывало бы на R2, поэтому Router не может отличить его от любого другого хоста и отклоняет: подпишите конечную точку `<account>.r2.cloudflarestorage.com` или используйте форму `pub-<hash>.r2.dev`. Конечная точка IPv6 dualstack у S3 (`s3.dualstack.<region>.amazonaws.com`) тоже не принимается; используйте обычную региональную конечную точку. Как и альтернативная зона DNS у Azure Blob (`<account>.z<N>.blob.storage.azure.net`); используйте `<account>.blob.core.windows.net`. В отказе, который вы получите, перечислены эти же формы, так что читать их здесь не обязательно.
Плейсхолдеры `<account>` и `pub-<hash>` выше показывают форму, с которой вы обычно придёте; это не ограничение глубины. Сопоставление идёт по суффиксу домена объектного хранилища, поэтому более глубокое имя в том же пространстве имён (`a.b.pub-<hash>.r2.dev`) тоже принимается. Что при этом НЕ расширяется, так это само пространство имён: суффикс всё равно должен быть одним из перечисленных.
Пример ниже показывает только форму: реальное значение также несёт параметры запроса подписи, которые здесь намеренно опущены, потому что опубликованный пример живёт в спецификации вечно, а реальная подпись это и утёкшие учётные данные, и ссылка, которая перестаёт работать.
</ParamField>

Размер каждого изображения ограничен 25 MiB, а суммарный объём изображений в одном запросе составляет 64 MiB. Единственное исключение: ideogram/ideogram-4-5 Precise Edit (вызов, который передаёт `image`), где доступен `context_window`. Там каждое изображение может быть до 50 MB (50,000,000 байт) и 67,108,864 пикселей, а суммарный объём изображений одного запроса до 128 MiB.
</ParamField>

Подпишите конечную точку `<account>.r2.cloudflarestorage.com` или используйте форму `pub-<hash>.r2.dev`. Конечная точка IPv6 dualstack для S3 (`s3.dualstack.<region>.amazonaws.com`) также не принимается; используйте обычную региональную конечную точку. Альтернативная зона DNS Azure Blob (`<account>.z<N>.blob.storage.azure.net`) тоже не принимается; используйте `<account>.blob.core.windows.net`. В полученном отказе перечислены эти же формы, так что вам не обязательно заходить сюда, чтобы их прочитать.
Заполнители `<account>` и `pub-<hash>` выше показывают форму, с которой вы обычно придёте; это не ограничение глубины. Сопоставление идёт по суффиксу домена объектного хранилища, поэтому более глубокое имя в том же пространстве имён (`a.b.pub-<hash>.r2.dev`) тоже принимается. Что этим НЕ расширяется, так это само пространство имён: суффикс всё равно должен быть одним из перечисленных.
Пример ниже показывает только форму: реальное значение также несёт параметры подписи в строке запроса, которые здесь намеренно опущены, потому что опубликованный пример остаётся в спецификации навсегда, а реальная подпись представляет собой одновременно утёкшие учётные данные и ссылку, которая перестаёт работать.Размер каждого изображения ограничен 25 MiB, а изображений в одном запросе: 64 MiB в сумме. Единственное исключение: ideogram/ideogram-4-5 Precise Edit (вызов, который отправляет `image`), где доступен `context_window`. Там каждое изображение может быть размером до 50 MB (50,000,000 байт) и 67,108,864 пикселей, а изображения одного запроса: до 128 MiB в сумме.
