Справочник по API для `bfl/flux-3-image`, предоставляемого Comfy Router от Black Forest Labs.

**Вход:** текст, изображение · **Выход:** изображение

## Быстрый старт

Создайте ключ в [своём рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. Фрагменты для Python и TypeScript используют Comfy SDK (`pip install comfy-sdk` и `npm install @comfyorg/sdk`); фрагмент cURL представляет собой тот же вызов по «сырому» HTTP.

**Model ID:** `bfl/flux-3-image`

**Endpoint:** `POST https://api.comfy.org/v2/models/bfl/flux-3-image`

from comfy_sdk import Comfy

# Читает COMFY_API_KEY из переменной окружения.
# SDK автоматически создаёт ключ идемпотентности и переиспользует его при автоматических повторах.

    result = client.models.run(

            "prompt": "A mountain landscape at sunset",

    )

То же тело запроса, отправленное на `POST https://api.comfy.org/v2/models/bfl/flux-3-image/requests`. Router отвечает `201` с `request_id`, как только запуск принят, а результат забирается, когда он готов, из этого процесса или из другого. В разделе [Доставка через очередь](/development/comfy-router/queue) описаны статус, отмена и получение результата.

<CodeGroup>
```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменной окружения.
# Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его при автоматических повторах.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "bfl/flux-3-image",
            {
                "aspect_ratio": "16:9",
                "prompt": "A mountain landscape at sunset",
                "resolution": "1k",
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивать до завершения запроса, выдерживая Retry-After, который называет сервер.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственный payload провайдера, то же значение, что возвращает models.run().
        # Запрос, который завершился ошибкой или был отменён, вызовет здесь типизированную ошибку Router.
        result = await handle.get()

    print(result)

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Читает COMFY_API_KEY из переменной окружения.
// Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его при автоматических повторах.
const handle = await comfy.models.submit("bfl/flux-3-image", {
  aspect_ratio: "16:9",
  prompt: "A mountain landscape at sunset",
  resolution: "1k",
});
console.log("requestId:", handle.requestId); // вместе с ID модели это всё, что нужно другому процессу

// Опрашивать до завершения запроса, выдерживая Retry-After, который называет сервер.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// То же результат, что возвращает models.run(). Запрос, который завершился ошибкой или был отменён, отклоняется здесь.
const result = await handle.get();

console.log(result.data);
```

```bash cURL
# 1. Отправка. Router отвечает 201 с request_id, status_url, response_url и cancel_url.
curl https://api.comfy.org/v2/models/bfl/flux-3-image/requests \
  -H "X-API-Key: $COMFY_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d "{\"aspect_ratio\": \"16:9\", \"prompt\": \"A mountain landscape at sunset\", \"resolution\": \"1k\"}"

# 2. Опрос до статуса COMPLETED с ожиданием Retry-After секунд, указанных в каждом ответе.
REQUEST_ID="<request_id from the 201 body>"
curl -i https://api.comfy.org/v2/models/bfl/flux-3-image/requests/$REQUEST_ID/status \
  -H "X-API-Key: $COMFY_API_KEY"

# 3. Получение. 200 с собственным выводом модели, 202 с телом статуса, пока запрос ещё выполняется.
curl https://api.comfy.org/v2/models/bfl/flux-3-image/requests/$REQUEST_ID \
  -H "X-API-Key: $COMFY_API_KEY"
```

## Схема

### Входы

<ParamField body="aspect_ratio" type="string" default="&quot;auto&quot;">
  Соотношение сторон вывода: auto, 21:9, 2:1, 16:9, 3:2, 7:5, 4:3, 5:4, 1:1, 4:5, 3:4, 5:7, 2:3, 9:16, 1:2 или 9:21. Значение auto следует за первым референсным изображением, если оно передано.
</ParamField>

<ParamField body="grounding" type="boolean" default="true">
  Разрешить модели исследовать промпт с помощью веб-поиска и поиска изображений перед генерацией. Установите false, чтобы отключить оба.
</ParamField>

<ParamField body="images" type="string | string[]">
  От одного до десяти референсных изображений, которые промпт редактирует или использует как основу; каждое из них это URL http(s) или строка base64. Одна строка рассматривается как список из одного элемента. Каждое изображение должно быть не меньше 256x256 пикселей и не больше 16 мегапикселей, а полезная нагрузка base64 не больше 20 МБ; входы масштабируются до ближайшей корзины разрешений, вплоть до 2k.
</ParamField>

<ParamField body="prompt" type="string" required>
  Текстовое описание изображения для генерации или правки, которую нужно применить к референсным изображениям.
</ParamField>

<ParamField body="resolution" type="string" default="&quot;1k&quot;">
  Класс разрешения вывода: 768sq, 1k, 1.5k, 2k или 4k.
</ParamField>

<ParamField body="safety_tolerance" type="integer" default="2">
  Уровень допуска для модерации входов и выходов, где 0 это самый строгий.

  Диапазон: от `0` до `4`
</ParamField>

<ParamField body="version" type="string" default="&quot;latest&quot;">
  Версия эндпоинта. latest обслуживает текущий релиз; датированные закрепляемые теги релизов добавляются по мере их публикации.
</ParamField>

Сгенерировано из схемы, которую Router отдаёт по адресу `GET /v2/models/bfl/flux-3-image/openapi.json`, того же документа, по которому он проверяет вызов, прежде чем запрос дойдёт до провайдера.

### Выходы

<ResponseField name="cost" type="number">
  Стоимость в кредитах, сообщаемая провайдером; заполняется, когда задача переходит в статус Ready.

  Формат: `float`
</ResponseField>

<ResponseField name="id" type="string" required>
  Идентификатор задачи BFL.
</ResponseField>

<ResponseField name="progress" type="number">
  Необязательный прогресс генерации, сообщаемый BFL.

  Диапазон: от `0` до `1`

  Формат: `float`
</ResponseField>

<ResponseField name="result" type="object" required>
  Завершённая генерация. Здесь значение не может быть null: запись `required` этого компонента это обещание, что ответ `200` несёт результат, а nullable-поле `result` свело бы её к проверке наличия ключа.
</ResponseField>

<ResponseField name="result.cost" type="number">
  Стоимость генерации, сообщаемая провайдером. Это число BFL, а не списание Comfy.

  Формат: `double`
</ResponseField>

<ResponseField name="result.duration" type="number">
  Длительность генерации в секундах, сообщаемая провайдером.

  Формат: `double`
</ResponseField>

<ResponseField name="result.end_time" type="number">
  Сообщаемое провайдером время завершения генерации в секундах с начала эпохи Unix. `double` по той же причине, что и `start_time`.

  Формат: `double`
</ResponseField>

<ResponseField name="result.prompt" type="string">
  Промпт, с которым генерация фактически выполнялась, после любого апсэмплинга промпта.
</ResponseField>

<ResponseField name="result.sample" type="string (uri)">
  Подписанный URL сгенерированного ресурса. Router переносит ресурс в хранилище Comfy и переписывает это поле, поэтому обычно это URL на хостинге Comfy, действительный до 24 часов: он подписывается на 24 часа в момент создания и воспроизводится из 23-часового кэша, так что при более позднем опросе может вернуться URL, у которого остался всего час; лист, для которого не удалось выполнить перенос, вместо этого сохраняет собственный короткоживущий URL доставки BFL: примерно два часа для видео и примерно десять минут для изображений. В любом случае ссылка истекает, поэтому скачайте ресурс, а не сохраняйте URL.

  Формат: `uri`
</ResponseField>

<ResponseField name="result.seed" type="integer">
  Начальное значение (seed), которое использовала генерация, независимо от того, было оно задано или выбрано провайдером. Объявлено как `int64`, потому что BFL возвращает seed больше 2^31 (например, 2784347701), а неформатированный `integer` во многих генераторах SDK порождает 32-битное поле.

  Формат: `int64`
</ResponseField>

<ResponseField name="result.start_time" type="number">
  Сообщаемое провайдером время начала генерации в секундах с начала эпохи Unix. `double`, а не `float`: шаг float32 около современного значения эпохи составляет ~128 секунд, что схлопывает весь интервал генерации в одно декодированное значение.

  Формат: `double`
</ResponseField>

<ResponseField name="status" type="string" required>
  Статус задачи: Pending, Reasoning, Generating, Ready, Request Moderated, Content Moderated, Error или Task not found.
</ResponseField>
