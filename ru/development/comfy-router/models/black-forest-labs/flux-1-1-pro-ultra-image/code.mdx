Справочник по API для Flux 1.1 Pro Ultra Image. FLUX 1.1 [pro]: модель текст в изображение от Black Forest Labs. Режим Ultra генерирует изображения разрешением до 4MP.

**Вход:** Текст, Изображение · **Выход:** Изображение

## Быстрый старт

Создайте ключ в [вашем рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. Сниппеты Python и TypeScript используют Comfy SDK (`pip install comfy-sdk` и `npm install @comfyorg/sdk`); сниппет cURL выполняет тот же вызов по чистому HTTP.

Выберите модель, которую хотите вызвать. Всё ниже, от сниппетов до схемы и примеров, следует вашему выбору.

```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из окружения.
# SDK автоматически создаёт ключ идемпотентности и переиспользует его для автоматических повторов.
async def main():
    async with AsyncComfy() as client:
        result = await client.models.run(
            "bfl/flux-pro-1.1-ultra",
            {
                "prompt": "a single red maple leaf on a plain white background, studio lighting",
                "aspect_ratio": "16:9",
                "raw": False,
            },
        )

    print("image:", result["result"]["sample"])

asyncio.run(main())
```

То же тело, отправленное на `POST https://api.comfy.org/v2/models/bfl/flux-pro-1.1-ultra/requests`. Router отвечает `201` с `request_id`, как только запуск принят, а результат забирается, когда он готов, из этого процесса или из другого. [Доставка через очередь](/development/comfy-router/queue) описывает статус, отмену и получение результата.

<CodeGroup>
```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из окружения.
# Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его для автоматических повторов.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "bfl/flux-pro-1.1-ultra",
            {
                "prompt": "a single red maple leaf on a plain white background, studio lighting",
                "aspect_ratio": "16:9",
                "raw": False,
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивайте до завершения запроса, выжидая Retry-After, указанный сервером.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственный ответ провайдера, то же значение, что возвращает models.run().
        # Запрос, который завершился ошибкой или был отменён, здесь вызывает типизированную ошибку Router.
        result = await handle.get()

    print("image:", result["result"]["sample"])

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Читает COMFY_API_KEY из окружения.
// Каждый вызов submit() создаёт собственный Idempotency-Key и переиспользует его для автоматических повторов.
type Result = { result: { sample: string } };
const handle = await comfy.models.submit<Result>("bfl/flux-pro-1.1-ultra", {
  prompt: "a single red maple leaf on a plain white background, studio lighting",
  aspect_ratio: "16:9",
  raw: false,
});
console.log("requestId:", handle.requestId); // вместе с ID модели это всё, что нужно другому процессу

// Опрашивайте до завершения запроса, выжидая Retry-After, указанный сервером.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// Тот же результат, что возвращает models.run(). Запрос, который завершился ошибкой или был отменён, здесь отклоняется.
const result = await handle.get();
if (result.kind !== "json") throw new Error("expected a JSON result");

console.log("image:", result.data.result.sample);
```

```bash cURL
# 1. Отправка. Router отвечает 201 с request_id, status_url, response_url и cancel_url.
curl https://api.comfy.org/v2/models/bfl/flux-pro-1.1-ultra/requests \
  -H "X-API-Key: $COMFY_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d "{\"prompt\": \"a single red maple leaf on a plain white background, studio lighting\", \"aspect_ratio\": \"16:9\", \"raw\": false}"

# 2. Опрашивайте, пока статус не станет COMPLETED, выжидая Retry-After секунд, указанные в каждом ответе.
REQUEST_ID="<request_id from the 201 body>"
curl -i https://api.comfy.org/v2/models/bfl/flux-pro-1.1-ultra/requests/$REQUEST_ID/status \
  -H "X-API-Key: $COMFY_API_KEY"

# 3. Получение. 200 с родным выводом модели, 202 с телом статуса, пока задача ещё выполняется.
curl https://api.comfy.org/v2/models/bfl/flux-pro-1.1-ultra/requests/$REQUEST_ID \
  -H "X-API-Key: $COMFY_API_KEY"
```

<h2>Схема</h2>

<h3>Входы</h3>

<ParamField body="aspect_ratio" type="string" default="&quot;16:9&quot;">
  Соотношение сторон изображения от 21:9 до 9:21, например 16:9.
</ParamField>

<ParamField body="image_prompt" type="string">
  Необязательное изображение в кодировке base64 для ремикса.
</ParamField>

<ParamField body="image_prompt_strength" type="number" default="0.1">
  Смешивание промпта и промпта-изображения: от 0 (только промпт) до 1 (только промпт-изображение).

  Диапазон: от `0` до `1`
</ParamField>

<ParamField body="output_format" type="string" default="&quot;jpeg&quot;">
  Формат выходного изображения.

  Возможные значения: `jpeg`, `png`, `webp`
</ParamField>

<ParamField body="prompt" type="string" required>
  Текстовый промпт для генерации изображения.
</ParamField>

<ParamField body="prompt_upsampling" type="boolean" default="false">
  Нужно ли выполнять upsampling промпта. Если включено, промпт автоматически изменяется для более творческой генерации.
</ParamField>

<ParamField body="raw" type="boolean" default="false">
  Генерировать менее обработанные, более естественно выглядящие изображения.
</ParamField>

<ParamField body="safety_tolerance" type="integer" default="2">
  Уровень допуска при модерации входа и выхода: от 0 (самый строгий) до 6 (самый мягкий).

  Диапазон: от `0` до `6`
</ParamField>

<ParamField body="seed" type="integer">
  Необязательный seed для воспроизводимости. Если он не указан, используется случайный seed.
</ParamField>

<ParamField body="webhook_secret" type="string">
  Необязательный секрет для проверки подписи вебхука.
</ParamField>

<ParamField body="webhook_url" type="string (uri)">
  URL для получения уведомлений вебхука.

  Формат: `uri`
</ParamField>

Сгенерировано из схемы, которую Router отдаёт по адресу `GET /v2/models/bfl/flux-pro-1.1-ultra/openapi.json`: по этому же документу он проверяет вызов, ДО того как запрос дойдёт до провайдера.

<h3>Выходы</h3>

<ResponseField name="cost" type="number">
  Стоимость в кредитах по данным провайдера, заполняется, когда задача находится в статусе Ready.

  Формат: `float`
</ResponseField>

<ResponseField name="id" type="string" required>
  Идентификатор задачи BFL.
</ResponseField>

<ResponseField name="progress" type="number">
  Необязательный прогресс генерации по данным BFL.

  Диапазон: от `0` до `1`

  Формат: `float`
</ResponseField>

<ResponseField name="result" type="object" required>
  Завершённая генерация. Здесь значение не может быть null: запись `required` этого компонента гарантирует, что `200` содержит результат, а допускающий null `result` свёл бы проверку к наличию ключа.
</ResponseField>

<ResponseField name="result.cost" type="number">
  Стоимость генерации по данным провайдера. Это значение BFL, а не списание Comfy.

  Формат: `double`
</ResponseField>

<ResponseField name="result.duration" type="number">
  Длительность генерации в секундах по данным провайдера.

  Формат: `double`
</ResponseField>

<ResponseField name="result.end_time" type="number">
  Время завершения генерации по данным провайдера, в секундах с начала эпохи Unix. `double` по той же причине, что и `start_time`.

  Формат: `double`
</ResponseField>

<ResponseField name="result.prompt" type="string">
  Промпт, с которым генерация фактически выполнялась, после возможного upsampling промпта.
</ResponseField>

<ResponseField name="result.sample" type="string (uri)">
  Подписанный URL сгенерированного файла. Router переносит файл в хранилище Comfy и перезаписывает это поле, поэтому обычно это URL на хранилище Comfy, действующий до 24 часов: при создании он подписывается на 24 часа и воспроизводится из 23-часового кэша, так что при более позднем опросе может вернуться URL, которому остался всего час; а файл, для которого перенос выполнить не удалось, сохраняет собственный короткоживущий URL выдачи BFL: примерно два часа для видео и примерно десять минут для изображений. В любом случае ссылка истекает, поэтому скачайте файл, а не сохраняйте URL.

  Формат: `uri`
</ResponseField>

<ResponseField name="result.seed" type="integer">
  Seed, который использовала генерация, независимо от того, был он задан или выбран провайдером. Объявлен как `int64`, поскольку BFL возвращает seed больше 2^31 (например, 2784347701), а неформатированный `integer` во многих генераторах SDK создаёт 32-битное поле.

  Формат: `int64`
</ResponseField>

<ResponseField name="result.start_time" type="number">
  Время начала генерации по данным провайдера, в секундах с начала эпохи Unix. `double`, а не `float`: шаг float32 вблизи сегодняшнего значения эпохи составляет ~128 секунд, из-за чего весь интервал генерации схлопывается в одно декодированное значение.

  Формат: `double`
</ResponseField>

<ResponseField name="status" type="string" required>
  Статус задачи: Pending, Reasoning, Generating, Ready, Request Moderated, Content Moderated, Error или Task not found.
</ResponseField>

  Диапазон: от `0` до `1`

  Формат: `float`
</ResponseField>

<ResponseField name="result" type="object" required>
  Завершённая генерация. Здесь значение не может быть null: запись `required` этого компонента гарантирует, что `200` содержит результат, а допускающий null `result` свёл бы проверку к наличию ключа.
</ResponseField>

<ResponseField name="result.cost" type="number">
  Стоимость генерации по данным провайдера. Это значение BFL, а не списание Comfy.

  Формат: `double`
</ResponseField>

<ResponseField name="result.duration" type="number">
  Длительность генерации в секундах по данным провайдера.

  Формат: `double`
</ResponseField>

<ResponseField name="result.end_time" type="number">
  Время завершения генерации по данным провайдера, в секундах с начала эпохи Unix. `double` по той же причине, что и `start_time`.

  Формат: `double`
</ResponseField>

<ResponseField name="result.prompt" type="string">
  Промпт, с которым генерация фактически выполнялась, после возможного upsampling промпта.
</ResponseField>

<ResponseField name="result.sample" type="string (uri)">
  Подписанный URL сгенерированного файла. Router переносит файл в хранилище Comfy и перезаписывает это поле, поэтому обычно это URL на хранилище Comfy, действующий до 24 часов: при создании он подписывается на 24 часа и воспроизводится из 23-часового кэша, так что при более позднем опросе может вернуться URL, которому остался всего час; а файл, для которого перенос выполнить не удалось, сохраняет собственный короткоживущий URL выдачи BFL: примерно два часа для видео и примерно десять минут для изображений. В любом случае ссылка истекает, поэтому скачайте файл, а не сохраняйте URL.

  Формат: `uri`
</ResponseField>

<ResponseField name="result.seed" type="integer">
  Seed, который использовала генерация, независимо от того, был он задан или выбран провайдером. Объявлен как `int64`, поскольку BFL возвращает seed больше 2^31 (например, 2784347701), а неформатированный `integer` во многих генераторах SDK создаёт 32-битное поле.

  Формат: `int64`
</ResponseField>

<ResponseField name="result.start_time" type="number">
  Время начала генерации по данным провайдера, в секундах с начала эпохи Unix. `double`, а не `float`: шаг float32 вблизи сегодняшнего значения эпохи составляет ~128 секунд, из-за чего весь интервал генерации схлопывается в одно декодированное значение.

  Формат: `double`
</ResponseField>

<ResponseField name="status" type="string" required>
  Статус задачи: Pending, Reasoning, Generating, Ready, Request Moderated, Content Moderated, Error или Task not found.
</ResponseField>
