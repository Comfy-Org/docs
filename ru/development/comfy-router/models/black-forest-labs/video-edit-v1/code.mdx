Справочник по API для `bfl/video-edit-v1`, предоставляемый Comfy Router от Black Forest Labs.

**Вход:** Видео, Текст · **Выход:** Видео

## Быстрый старт

Создайте ключ в [своём рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router) и экспортируйте его как `COMFY_API_KEY`. Фрагменты для Python и TypeScript используют Comfy SDK (`pip install comfy-sdk` и `npm install @comfyorg/sdk`); фрагмент cURL выполняет тот же вызов по raw HTTP.

**Model ID:** `bfl/video-edit-v1`

**Endpoint:** `POST https://api.comfy.org/v2/models/bfl/video-edit-v1`

То же тело запроса, отправленное на `POST https://api.comfy.org/v2/models/bfl/video-edit-v1/requests`. Router отвечает `201` с `request_id` сразу после того, как запуск принят, а результат забирается, когда он готов, из этого или другого процесса. В разделе [Доставка через очередь](/development/comfy-router/queue) описаны статус, отмена и получение результата.

<CodeGroup>
```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Читает COMFY_API_KEY из переменных окружения.
# Каждый вызов submit() создаёт свой Idempotency-Key и переиспользует его для автоматических повторов.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "bfl/video-edit-v1",
            {
                "prompt": "Remove the orange bucket.",
                "video": "https://example.com/clip.mp4",
            },
        )
        print("request_id:", handle.request_id)  # вместе с ID модели это всё, что нужно другому процессу

        # Опрашивает статус, пока запрос не завершится, выдерживая Retry-After, указанный сервером.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Собственные данные провайдера, то же значение, что возвращает models.run().
        # Запрос, который завершился ошибкой или был отменён, возбуждает здесь типизированную ошибку Router.
        result = await handle.get()

    print(result)

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Читает COMFY_API_KEY из переменных окружения.
// Каждый вызов submit() создаёт свой Idempotency-Key и переиспользует его для автоматических повторов.
const handle = await comfy.models.submit("bfl/video-edit-v1", {
  prompt: "Remove the orange bucket.",
  video: "https://example.com/clip.mp4",
});
console.log("requestId:", handle.requestId); // вместе с ID модели это всё, что нужно другому процессу

// Опрашивает статус, пока запрос не завершится, выдерживая Retry-After, указанный сервером.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// Тот же результат, который возвращает models.run(). Запрос, который завершился ошибкой или был отменён, отклоняется здесь.
const result = await handle.get();

console.log(result.data);
```

```bash cURL
# 1. Отправка. Router отвечает 201 с request_id, status_url, response_url и cancel_url.
curl https://api.comfy.org/v2/models/bfl/video-edit-v1/requests \
  -H "X-API-Key: $COMFY_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d "{\"prompt\": \"Remove the orange bucket.\", \"video\": \"https://example.com/clip.mp4\"}"

# 2. Опрос, пока статус не станет COMPLETED, с ожиданием Retry-After секунд, указанных в каждом ответе.
REQUEST_ID="<request_id from the 201 body>"
curl -i https://api.comfy.org/v2/models/bfl/video-edit-v1/requests/$REQUEST_ID/status \
  -H "X-API-Key: $COMFY_API_KEY"

# 3. Получение. 200 с нативным выводом модели, 202 с телом статуса, пока запрос ещё выполняется.
curl https://api.comfy.org/v2/models/bfl/video-edit-v1/requests/$REQUEST_ID \
  -H "X-API-Key: $COMFY_API_KEY"
```

## Схема

### Входы

<ParamField body="prompt" type="string" required>
  Инструкция к редактированию. Указывает объекты, обстановку, стиль, текст на экране или диалог, которые нужно изменить; всё, что не указано, сохраняется.
</ParamField>

<ParamField body="safety_tolerance" type="integer" default="2">
  Уровень допуска для модерации входа и выхода, `0` соответствует самой строгой модерации.

  Диапазон: от `0` до `4`
</ParamField>

<ParamField body="video" type="string" required>
  Видео для редактирования: HTTP(S) URL или MP4 в кодировке base64. Не более 15 секунд исходного материала и 50 MiB, каждая сторона не менее 160 пикселей; источники выше 720p уменьшаются до 720p.
</ParamField>

Сгенерировано из схемы, которую Router отдаёт по адресу `GET /v2/models/bfl/video-edit-v1/openapi.json`, того же документа, по которому он валидирует вызов, прежде чем запрос дойдёт до провайдера.

### Выходы

<ResponseField name="cost" type="number">
  Стоимость в кредитах, сообщённая провайдером; заполняется, когда задача переходит в состояние Готов.

  Формат: `float`
</ResponseField>

<ResponseField name="id" type="string" required>
  Идентификатор задачи BFL.
</ResponseField>

<ResponseField name="progress" type="number">
  Необязательный прогресс генерации, сообщаемый BFL.

  Диапазон: от `0` до `1`

  Формат: `float`
</ResponseField>

<ResponseField name="result" type="object" required>
  Завершённая генерация. Здесь не может быть null: запись `required` этого компонента обещает, что ответ `200` содержит результат, а nullable `result` свёл бы её к проверке одного лишь наличия ключа.
</ResponseField>

<ResponseField name="result.cost" type="number">
  Стоимость генерации, сообщённая провайдером. Это число BFL, а не списание Comfy.

  Формат: `double`
</ResponseField>

<ResponseField name="result.duration" type="number">
  Длительность генерации в секундах, сообщённая провайдером.

  Формат: `double`
</ResponseField>

<ResponseField name="result.end_time" type="number">
  Время завершения генерации, сообщённое провайдером, в секундах с начала эпохи Unix. `double` по той же причине, что и `start_time`.

  Формат: `double`
</ResponseField>

<ResponseField name="result.prompt" type="string">
  Промпт, с которым генерация фактически выполнялась, после любого апсэмплинга промпта.
</ResponseField>

<ResponseField name="result.sample" type="string (uri)">
  Подписанный URL сгенерированного ресурса. Router переносит ресурс в хранилище Comfy и переписывает это поле, поэтому обычно здесь URL на хосте Comfy, действительный до 24 часов: подписан на 24 часа при создании и переиспользуется из 23-часового кэша, так что более поздний опрос может вернуть ссылку, которой остался всего час; лист, для которого перенос выполнить не удалось, вместо этого сохраняет собственный короткоживущий URL доставки BFL: примерно два часа для видео и примерно десять минут для изображений. В любом случае ссылка истекает, поэтому скачайте ресурс, а не сохраняйте URL.

  Формат: `uri`
</ResponseField>

<ResponseField name="result.seed" type="integer">
  Сид, использованный генерацией, переданный или выбранный провайдером. Объявлен как `int64`, потому что BFL возвращает сиды больше 2^31 (например, 2784347701), которые неформатированный `integer` во многих генераторах SDK создаёт как 32-битное поле.

  Формат: `int64`
</ResponseField>

<ResponseField name="result.start_time" type="number">
  Время начала генерации, сообщённое провайдером, в секундах с начала эпохи Unix. `double`, а не `float`: шаг float32 около современного значения эпохи составляет ~128 секунд, что схлопывает весь интервал генерации в одно декодированное значение.

  Формат: `double`
</ResponseField>

<ResponseField name="status" type="string" required>
  Статус задачи: Pending, Reasoning, Generating, Ready, Request Moderated, Content Moderated, Error или Task not found.
</ResponseField>
