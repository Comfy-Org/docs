Вызов Router, завершившийся ошибкой, возвращает HTTP-статус, категорию ошибки в `X-Comfy-Error-Type` и ID запроса в `X-Comfy-Request-Id`. Оставьте все три значения и отправленный вами `Idempotency-Key`, прежде чем решать, повторять ли запрос.

## Читать ошибки с защитой

Запрос с ошибкой может вернуть HTML-страницу ошибки прокси, усечённый JSON или простой текст. Не позволяйте ошибке разбора JSON скрыть HTTP-статус или ID запроса. Эти вспомогательные функции используют `httpx.Response` в Python и Fetch `Response` в TypeScript; SDK уже предоставляют поля ошибок для обычных вызовов SDK.

<CodeGroup>

```python
def read_router_error(response):
    body = None
    if response.headers.get("content-type", "").startswith("application/json"):
        try:
            body = response.json()
        except ValueError:
            body = None

    detail = body.get("detail") if isinstance(body, dict) else None
    return {
        "status": response.status_code,
        "request_id": response.headers.get("X-Comfy-Request-Id"),
        "error_type": response.headers.get("X-Comfy-Error-Type", "internal_error"),
        "message": detail if isinstance(detail, str) else f"HTTP {response.status_code}",
        "validation": detail if isinstance(detail, list) else [],
    }
```

```typescript
async function readRouterError(response: Response) {
  let body: unknown;
  try {
    body = JSON.parse(await response.text());
  } catch {
    body = undefined;
  }

  const detail =
    typeof body === "object" && body !== null ? (body as { detail?: unknown }).detail : undefined;

  return {
    status: response.status,
    requestId: response.headers.get("X-Comfy-Request-Id"),
    errorType: response.headers.get("X-Comfy-Error-Type") ?? "internal_error",
    message: typeof detail === "string" ? detail : `HTTP ${response.status}`,
    validation: Array.isArray(detail) ? detail : [],
  };
}
```

```swift
// Добавьте в ваш Package.swift:
//   .package(url: "https://github.com/Comfy-Org/comfy-swift-sdk.git", from: "0.5.0")
import ComfySwiftSDK

// SDK сам безопасно читает ответ: сбой Router выбрасывается как
// ComfyError.router с уже извлечёнными HTTP-статусом, ID запроса,
// категорией ошибки и деталями валидации по каждому полю, даже если
// тело ответа было HTML-страницей ошибки или усечённым JSON. Перехватывайте его из любого вызова client.models.
struct RouterErrorInfo {
    let status: Int
    let requestId: String?
    let errorType: String
    let message: String
    let validation: [RouterValidationErrorDetail]
}

// `client.models.run` объявлен как `async throws`, поэтому необработанный `catch` связывает `Error`.
// Принимайте здесь `Error`, чтобы перехваченное значение можно было передать сразу.
func readRouterError(_ error: Error) -> RouterErrorInfo? {
    guard let comfyError = error as? ComfyError,
          case .router(let router) = comfyError else { return nil }
    return RouterErrorInfo(
        status: router.httpStatus,
        requestId: router.requestId,
        errorType: router.errorType.rawValue,
        message: router.detail,
        validation: router.validationErrors
    )
}
```

</CodeGroup>

## Ошибки валидации

Ответ Router `422` означает, что валидация не прошла до вызова провайдера, и такой запрос не тарифицируется. В его теле есть массив `detail[]` с одной записью на каждое отклонённое поле. Категория ошибки находится в `X-Comfy-Error-Type`, а не в теле. Например:

```json
{"detail": [{"loc": ["body", "prompt"], "msg": "Field required", "type": "missing"}]}
```

Это пример формы. Модели с разрешающей схемой входа могут передать отсутствующее поле провайдеру вместо возврата Router `422`.

| Поле | Значение |
| --- | --- |
| `loc` | Путь к отклонённому полю, начиная с самого внешнего сегмента. |
| `msg` | Понятная человеку причина сбоя. |
| `type` | Причина, зависящая от провайдера, например `missing`, `greater_than` или `image_too_small`. |
| `ctx` | Необязательная граница или дополнительные данные для этой ошибки провайдера. |

`400` описывает проблему уровня запроса, например некорректный курсор, а не это тело валидации по полям. [Ссылка на ошибки](/ru/development/comfy-router/reference#error-buckets) перечисляет поддерживаемые категории. Для управления потоком считайте неизвестную категорию `internal_error`, но сохраняйте оригинальное значение для диагностики. Не отклоняйте жёстко новое значение ошибки и не реализуйте прогнозируемые категории ошибок так, будто они уже возникают.

## Безопасно повторить

Сохраните ключ вместе с ID модели и телом запроса **до отправки**. Используйте его повторно для каждой попытки этого логического вызова. Router не возвращает вам `Idempotency-Key` в ответе. Python SDK включает свой ключ в возбуждаемые исключения; в TypeScript храните переданный вами ключ самостоятельно.

Ключи являются общими в пределах рабочего пространства, задаваемого учётными данными, или привязаны к пользователю, если учётные данные не содержат рабочего пространства. Используйте UUID, уникальный в пределах этой области, и повторяйте попытки с теми же учётными данными. Повторное использование ключа другого участника рабочего пространства может вернуть его записанный результат или конфликт; смена учётных данных может запустить отдельный оплачиваемый вызов.

Router хранит состояние ответа или коллекции, связанное с ключом, в течение 24 часов; повторная попытка не открывает новое окно хранения. После истечения этого состояния не рассчитывайте, что старый ключ восстановит результат или предотвратит новую отправку. Ключ также не делает просроченный URL ресурса снова доступным.

## Результаты повторных попыток

| Статус | Категория | Что это означает | Что делать |
| --- | --- | --- | --- |
| `200` | заголовок `Idempotent-Replayed: true` | Router повторил результат или вернул уже собранную генерацию. | Используйте результат; повтор не является вторым списанием средств Comfy. |
| `409` | `concurrency_limit_exceeded` | Исходный вызов для этого ключа всё ещё выполняется. | Подождите `Retry-After`, затем отправьте тот же ключ снова. |
| `504` | `deadline_exceeded`, с `Retry-After` | Router сохранил дескриптор принятой работы провайдера. | Подождите указанный интервал и отправьте тот же запрос и ключ снова, чтобы забрать результат. Работа может всё ещё выполняться. |
| `429` | `rate_limited` | Лимит запросов исчерпан. | Подождите `Retry-After`, затем повторите с тем же ключом. |
| `429` | `concurrency_limit_exceeded` | Лимит одновременных вызовов или зарезервированных расходов отклонил запрос. | Снизьте параллелизм и повторите с тем же ключом. Проверьте заголовки расходов. |
| `409` | `invalid_input` | Запрос отличается от исходного запроса для этого ключа, или его запись невозможно воспроизвести. | Проверьте конфликт. Восстановите исходный запрос, если он изменился. Создавайте новый ключ, только если намерены сделать новый, потенциально оплачиваемый вызов. |
| `504` без подсказки о сборе, другой `5xx` или отсутствие ответа | Зависит | Статус сам по себе не указывает, была ли работа принята, сохранена или освобождена. | Сохраняйте тот же ключ и запрос. Используйте политику повторных попыток с ограничением; восстановление не гарантируется. |

Конфликты сравнивают метод, путь модели, параметры запроса и тело. Ключ может стать невоспроизводимым после слишком большого ответа, ошибки записи ответа или актива, который нельзя безопасно воспроизвести. Ожидание не восстанавливает уже израсходованный результат. Новый ключ запускает новый вызов; он не извлекает старый вывод.

Отказ до отправки провайдеру освобождает ключ. Отправленный вызов может сохранить дескриптор провайдера или стать невоспроизводимым. Не выводите состояние ключа или выставление счетов только из кода статуса.

Не создавайте совершенно новый ключ только потому, что вызов превысил время ожидания или соединение оборвалось. Если Router уже принял генерацию, новый ключ может создать второй логический запуск и, следовательно, второй оплачиваемый результат. Используйте повторно тот же ключ, пока не убедитесь, что исходный вызов невозможно восстановить.

## Тайм-ауты и сбор результата

Один вызов Router по умолчанию может удерживать соединение до 10 минут. Задайте тайм-аут клиента больше этого значения, чтобы получить типизированный `504` и ID запроса, а не непрозрачное локальное прерывание. Если ваше приложение не может удерживать соединение так долго, [доставка через очередь](/ru/development/comfy-router/queue) сразу возвращает `request_id` и позволяет получить результат позже.

`deadline_exceeded` обозначает лимит ожидания Router; `provider_timeout` обозначает дедлайн провайдера. Завершившаяся генерация у провайдера может быть оплачена, даже если вызывающая сторона получила тайм-аут или отключилась. Отмена на стороне клиента останавливает ожидание и повторы SDK, но не обязательно отменяет принятую провайдером работу.

Для провайдеров со схемой «отправить и опросить» сохранённый хэндл позволяет запросу с тем же ключом продолжить сбор оригинальной генерации. Вызовы, отправленные и прерванные без восстановимого хэндла, могут израсходовать ключ без воспроизводимого результата; повтор с тем же ключом тогда вернёт `409`. Временные сбои, отнесённые к провайдеру, без зафиксированного успеха всё ещё могут освободить ключ для новой попытки. Само по себе отсутствие хэндла не говорит о том, какой из исходов имеет место.

SDK повторяют некоторые сбои в пределах ограниченного бюджета. Как только они вернули ошибку, сохраняйте запрос и ключ, а не создавайте новые. Для чистого HTTP этот пример повторяет только два явных сигнала о сборе результата:

```python
import os
import time

import httpx


def collect(model, arguments, key, attempts=3):
    with httpx.Client(timeout=httpx.Timeout(660.0, connect=10.0)) as client:
        for attempt in range(attempts):
            response = client.post(
                f"https://api.comfy.org/v2/models/{model}",
                headers={"X-API-Key": os.environ["COMFY_API_KEY"],
                         "Idempotency-Key": key},
                json=arguments,
            )
            if response.is_success:
                return response.json()

            category = response.headers.get("X-Comfy-Error-Type")
            collecting = (response.status_code, category) in {
                (409, "concurrency_limit_exceeded"),
                (504, "deadline_exceeded"),
            }
            delay = response.headers.get("Retry-After", "")
            if not collecting or not delay.isdigit() or attempt == attempts - 1:
                response.raise_for_status()
            time.sleep(int(delay))
    raise ValueError("attempts must be positive")
```

Передайте оригинальную модель, тело запроса и сохранённый ключ. Это ограничивает число попыток, а не общее время: каждый вызов может длиться до тайм-аута клиента, и каждая пауза следует значению `Retry-After`. Ошибки HTTP сохраняют ответ для проверки; транспортные ошибки распространяются, не заменяя ключ. Если вашему приложению нужно более длительное окно восстановления, запланируйте более поздний сбор результата с сохранённым ключом.
