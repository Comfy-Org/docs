Каждая модель Router принимает собственное нативное тело запроса и возвращает собственный нативный результат. Изучите схему модели, чтобы узнать и то, и другое.

## Чтение схем входа и выхода

Каждая модель предоставляет отдельный документ OpenAPI:

```bash
curl --dump-header schema-headers.txt \
  -H "X-API-Key: $COMFY_API_KEY" \
  https://api.comfy.org/v2/models/bfl/flux-2-pro/openapi.json
```

В операции модели `requestBody` описывает вход, а ответ `200` описывает выход, если схема выхода была составлена. Валидация входа и документация выхода различаются: Router проверяет запрос по схеме входа, но не проверяет возвращённый результат провайдера по схеме выхода.

Проверьте тип медиа выхода, а также его поля. У несозданного выхода может быть `*/*`, а некоторые модели возвращают двоичные данные вместо JSON.

### Кэширование схемы

Сохраните схему и её `ETag`. При следующем запросе схемы передайте этот ETag в `If-None-Match`. Ответ `304` не имеет тела; оставьте кэшированный документ. Ответ `200` предоставляет документ замены и ETag.

```bash
curl -H "X-API-Key: $COMFY_API_KEY" \
  -H 'If-None-Match: "previous-etag-value"' \
  https://api.comfy.org/v2/models/bfl/flux-2-pro/openapi.json
```

Маршрут схемы использует `Cache-Control: private, must-revalidate`. Держите аутентифицированные ответы вне общих кэшей. Это поведение ETag/304 относится только к эндпоинту схемы.

## Валидация и резервные схемы

Составленная схема входа отклоняет недопустимые поля до вызова провайдера с кодом `422` и массивом `detail[]`. Прочитайте пути полей в `loc`; см. [ошибки валидации](/ru/development/comfy-router/errors#ошибки-валидации).

Некоторые схемы принимают любой объект JSON и устанавливают `x-comfy-input-schema-authored: false`. Router передаёт такие запросы без валидации для конкретной модели, поэтому провайдер всё равно может их отклонить.

## Чтение результата

Router возвращает терминальную форму результата каждой модели. Общей обёртки для изображений, видео или текста нет: вывод изображения BFL использует `result.sample`, тогда как другие модели могут возвращать списки URL или встроенные байты.

Некоторые URL ассетов переразмещаются Comfy; другие остаются URL провайдера или встроенными байтами. См. [ассеты результата](/ru/development/comfy-router/reference#ассеты-результатов) и своевременно скачивайте ассеты с истекающим сроком. Повторные воспроизведения не продлевают URL.
