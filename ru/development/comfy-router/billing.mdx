Средства списываются тогда, когда провайдер выставляет счёт Comfy. То же правило действует для синхронных вызовов и вызовов [в очереди](/ru/development/comfy-router/queue#idempotency-and-billing), а [повтор](/ru/development/comfy-router/errors#retry-outcomes) с тем же ключом, который воспроизводит результат, не приводит к повторному списанию.

## Сведения о списании средств за модели

`GET /v2/models` и ответ с подробными данными о модели содержат поле `billing.charges_on_policy_rejection`. Оно описывает отказ по политике, а не любую ошибку и не оценку цены.

| Значение | Что означает |
| --- | --- |
| `yes` | За отказ по политике средства списываются. |
| `no` | За отказ по политике средства не списываются. |
| `unknown` | Пока никому не известно, как ведёт себя система. Считайте, что средства могут быть списаны. |

Сравнивайте эти строки явно: `"no"` в Python и JavaScript считается истинным значением. Любое нераспознанное значение считайте `unknown`. Запрос, отклонённый из-за нехватки кредитов, возвращает `insufficient_credits`.

## Сверка списаний

Ответы провайдера могут содержать собственные данные о стоимости или использовании; это не списание Comfy. `X-Comfy-Credits-Used` доступен только для некоторых моделей и только в успешных ответах. Когда Router воспроизводит результат для того же `Idempotency-Key`, он повторяет исходный заголовок с `Idempotent-Replayed: true`. Вызов всё равно списывается один раз, поэтому не учитывайте воспроизведённый заголовок повторно. Отсутствие заголовка не означает, что вызов был бесплатным. Для сверки используйте [использование рабочего пространства и счета](https://platform.comfy.org/settings/billing), а при разборе списания сохраняйте ID запроса.
