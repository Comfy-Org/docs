Канонические маршруты Comfy Router с адресацией по идентификатору модели.

Базовый URL: `https://api.comfy.org`

Все эндпоинты ниже требуют аутентификации. Отправляйте `X-API-Key: <api-key>` или `Authorization: Bearer <jwt>`.

Ключи Comfy API также можно отправлять как Bearer-токены. Если переданы оба заголовка учётных данных, приоритет имеет `X-API-Key`. См. раздел [Заголовки аутентификации](/ru/development/comfy-router/headers#заголовки-запроса), где объясняется разница между ключом и JWT, и [краткое руководство](/ru/development/comfy-router/quickstart), где описаны требования доступа.

## Эндпоинты

### `POST /v2/models/{provider}/{model}`

**Синхронно запустить партнёрскую модель по каноническому ID модели.**

Запустите модель и получите её готовый результат в том же ответе.

**Параметры**

<ParamField path="provider" type="RouterProviderSegment" required>
  Часть канонического ID модели `{provider}/{model}`, обозначающая провайдера.

  Тип: [`RouterProviderSegment`](#routerprovidersegment). Буквенно-цифровой slug, например `anthropic`. До 64 символов
</ParamField>

<ParamField path="model" type="RouterModelSegment" required>
  Часть канонического ID модели `{provider}/{model}`, обозначающая модель.

  Тип: [`RouterModelSegment`](#routermodelsegment). Буквенно-цифровой slug, например `claude-opus-4-6`. До 128 символов
</ParamField>

<ParamField header="Idempotency-Key" type="string">
  Ключ, создаваемый вызывающей стороной, который делает безопасным повторный вызов одного логического запроса.

  1–255 символов
</ParamField>

<ParamField query="model_provider" type="string">
  Выбирает альтернативного провайдера для обслуживания этой модели вместо текущего провайдера по умолчанию; `fal`, `wavespeed`, `runware` и `higgsfield` являются альтернативными провайдерами, а `GET /v2/models/{provider}/{model}` сообщает, каких из них поддерживает данная модель. Отказы по этому параметру проверяются в фиксированном порядке, и более ранние возвращаются независимо от того, сработали бы более поздние: нераспознанное значение, которое вообще не является зарегистрированным провайдером, отклоняется с `400`; затем запрос с альтернативным провайдером, тело которого выбирает multipart-операцию (редактирование), отклоняется с `409` и `detail`, начинающимся с «this request's `image` selects the edit operation», но только если транслятор этого провайдера для данной модели не может обслужить операцию: ветка, чей транслятор передаёт медиаданные, обрабатывается как обычно; затем любой запрос с альтернативным провайдером, для которого были определены учётные данные BYOK (bring-your-own-key), отклоняется с `409` и `detail`, начинающимся с `this request resolved a BYOK credential` (см. этот ответ), независимо от того, обслуживает ли этот провайдер данную модель; затем собственная проверка доступа указанного провайдера, которая возвращает отказ `403` с `error_type: not_enabled`, если этот провайдер не включён для вас, и `503` с `error_type: service_unavailable`, если проверку невозможно выполнить; и только после всех четырёх проверок реальный провайдер без ветки для этой модели отклоняется с `400` и `error_type: invalid_input`, тем же ответом, что и нераспознанное значение. Параметр `fallback_provider` неактивен, но не отклоняется, в запросе с учётными данными BYOK, в запросе, тело которого выбирает multipart-операцию, и при `strict_mode=true`.
</ParamField>

<ParamField query="strict_mode" type="boolean">
  Имеет смысл только вместе с `model_provider`.

  По умолчанию: False
</ParamField>

<ParamField query="fallback_provider" type="string">
  Управляет тем, будет ли Router повторять этот вызов у другого зарегистрированного провайдера модели, если первая попытка завершится неудачей по причине, относящейся к Router или к испробованному провайдеру. Если параметр опущен или имеет любое значение, кроме `false`, резервный вариант остаётся включённым; `false` отключает его. Успешный ответ после переключения на резервный вариант содержит `X-Comfy-Router-Fallback-Provider`. В запросе, для которого были определены учётные данные BYOK, резервный вариант недоступен независимо от значения этого параметра: попытка просто не выполняется, и первая ошибка доходит до вас без изменений, то есть это неактивное поведение, а не отказ: `409` здесь не возникает. То же самое по той же причине верно для запроса, тело которого выбирает multipart-операцию, и при `strict_mode=true`: каждый из них привязывает вызов к одному провайдеру, которого нельзя достоверно воспроизвести у другого, поэтому резервный вариант просто пропускается, а не отклоняется. Только явно указанный `model_provider` отклоняется с этим `409`, и, в отличие от этого безусловного пропуска, его multipart-`409` применяется только к ветке, чей транслятор не может обслужить операцию.
</ParamField>

<ParamField query="reject_unknown_fields" type="boolean">
  Включите отклонение поля тела запроса верхнего уровня, которое не объявлено во входной схеме этой модели, вместо его принятия; вложенные поля не проверяются, и ничего не отклоняется для модели, чья схема допускает необъявленные поля или не имеет составленной схемы, а также при отправке в очередь с `strict_mode=true`.

  По умолчанию: False
</ParamField>

**Тело запроса**

`application/json` -- [`RouterModelInput`](#routermodelinput) (обязательно)

Собственный нативный JSON-вход партнёрской модели. Без `model_provider` это тело является собственной нативной схемой модели, и `strict_mode` вызывающего ничего не меняет, когда вызов обслуживает собственный провайдер модели; когда Comfy Router сам направляет такой вызов другому провайдеру, Router переводит тело для этого провайдера, а то, как там применяется `strict_mode`, в этот контракт не входит. Когда `model_provider` выбирает альтернативного провайдера и `strict_mode=false` (значение по умолчанию), тело переводится в реальную схему этого провайдера перед отправкой: любое нативное поле, которое нельзя выразить точно, отбрасывается и раскрывается через заголовок ответа `X-Comfy-Router-Dropped-Params`, но никогда не молча. Когда `model_provider` выбирает альтернативного провайдера и `strict_mode=true`, перевод не выполняется: тело уже должно быть собственной реальной схемой этого альтернативного провайдера, а не нативной схемой этой модели (см. `strict_mode`), и пересылается без изменений. Поля самого тела также выбирают, какую операцию Router выполняет для модели, поддерживающей несколько: для редактируемой модели изображений наличие входного изображения переключает её с операции «текст в изображение» на операцию «изображение в изображение» (редактирование), которая может тарифицироваться по собственному тарифу; для видеомодели Seedance операцию выбирает `content[].role` (изображение первого кадра выбирает «изображение в видео», референсное изображение или клип выбирает reference-to-video). Когда вызов обслуживает собственный провайдер модели, выставление счетов Seedance следует типам медиа в `content`, а не ролям: запрос с любым видео на входе списывается как видео в видео, иначе запрос с любым изображением списывается как изображение в видео, иначе как текст в видео, за исключением того, что финальный рендер из элемента `draft_task` списывается как операция того Draft, который он рендерит; некоторые модели берут одинаковый тариф за текст в видео и изображение в видео. Когда `model_provider` выбирает альтернативного провайдера или когда Comfy Router обслуживает вызов у другого провайдера, каждая операция с условиями может тарифицироваться по собственному тарифу этого провайдера.

**Ответы**

<ResponseField name="200" type="RouterModelOutput">
  OK: без `model_provider` или с `model_provider` и `strict_mode=false` (значение по умолчанию; при возможности переводится обратно в нативный контракт этой модели, а при сбое перевода используется собственный сырой ответ альтернативного провайдера, что логируется и никогда не происходит молча) форма является собственным нативным выходом этой модели; при `strict_mode=true` это ответ альтернативного провайдера, возвращённый без изменений. Для модели, чей партнёр отвечает на генерацию напрямую байтами, тело составляют эти байты с собственным `Content-Type` партнёра, а не `application/json`; ориентируйтесь на `Content-Type` ответа и не предполагайте наличие JSON-документа.

  Тело: [`RouterModelOutput`](#routermodeloutput) или необработанные байты (`*/*`). Заголовки: `X-Comfy-Request-Id`, `X-Content-Type-Options`, `X-Comfy-Router-Fallback-Provider`, `X-Comfy-Router-Provider`, `X-Comfy-Router-Dropped-Params`, `X-Comfy-Credits-Used`, `Idempotent-Replayed`, `X-Committed-Spend-Limit`, `X-Committed-Spend-Current`, `X-Committed-Spend-Remaining`
</ResponseField>

<ResponseField name="409" type="RouterErrorResponse">
  Проверьте `X-Comfy-Error-Type`: `concurrency_limit_exceeded` означает, что исходный вызов всё ещё выполняется, поэтому дождитесь `Retry-After` и используйте тот же ключ; `invalid_input` требует нового ключа. Два конфликта `invalid_input` на этом маршруте вовсе не связаны с ключом, и никакой новый ключ не устраняет ни один из них: `model_provider`, указывающий альтернативного провайдера, отклоняется, когда тело запроса выбирает multipart-операцию (редактирование), которую транслятор этого провайдера для данной модели не может обслужить, причём его `detail` начинается с «this request's `image` selects the edit operation»; и, проверяемое после этого, когда запрос уже разрешил учётные данные bring-your-own-key для провайдера в пути, причём его `detail` начинается с `this request resolved a BYOK credential`. Уберите `model_provider` или отправьте запрос без учётных данных BYOK и (для случая multipart) без редактирования.

  Тело: [`RouterErrorResponse`](#routererrorresponse). Заголовки: `X-Comfy-Error-Type`, `X-Comfy-Request-Id`, `Retry-After` (при `concurrency_limit_exceeded`)
</ResponseField>

</ResponseField>

<ResponseField name="429" type="RouterErrorResponse">
  Проверьте `X-Comfy-Error-Type`: `concurrency_limit_exceeded` означает, что нужно сократить число одновременных вызовов; `rate_limited` означает, что нужно дождаться `Retry-After`, который при лимите провайдера (`X-Comfy-Upstream-Status` равен `429`) представляет собой собственное время ожидания провайдера и передаётся только тогда, когда провайдер его передал.

  Тело: [`RouterErrorResponse`](#routererrorresponse). Заголовки: `X-Comfy-Error-Type`, `X-Comfy-Request-Id`, `X-Committed-Spend-Limit`, `X-Committed-Spend-Current`, `X-Committed-Spend-Remaining`, `X-Model-Concurrency-Limit`, `X-Model-Concurrency-Current`, `X-Model-Concurrency-Remaining`, `Retry-After` (при `rate_limited`)
</ResponseField>

### `POST /v2/models/{provider}/{model}/estimate`

**Рассчитайте цену вызова модели до его запуска, не запуская его.**

Возвращает предварительную оценку в долларах США того, во сколько обойдётся запуск этого тела запроса на этой модели, рассчитанную по стандартному прайс-листу Comfy (для модели, с которой списывается стоимость, указанная её поставщиком, оценка вместо этого строится по опубликованному прайс-листу поставщика). Оценка не отражает договорные или индивидуальные тарифы: рабочему пространству с согласованными ценами выставляется цена по прайс-листу, а списание идёт по его договорному тарифу, и `source: exact` в таком случае означает точность по прайс-листу, а не фактическое списание этого рабочего пространства. Это оценка, а не итоговое списание: платите вы по окончательному списанию в записях использования и выставления счетов вашего рабочего пространства. Сначала тело запроса проверяется по входной схеме модели так же, как его проверяет запуск по умолчанию (без `strict_mode`, без `reject_unknown_fields`), поэтому тело, не проходящее схему модели, даёт здесь тот же `422`, что и при запуске; провайдеру ничего не отправляется, и средства не списываются. Ответ не фиксирует цену: он рассчитан по тарифам, действующим на `pricing_as_of`, а запуск списывается по тарифам, действующим на момент его тарификации. Если оценки отключены для развёртывания, маршрут отвечает `403` с `error_type: not_enabled`; модель, которую Router пока не может запустить, отвечает тем же `403` с собственным `detail` маршрута запуска, поэтому читайте `detail`, чтобы различить эти два случая. Однако этот `estimate` не является предварительной ценой: он появляется только после того, как запуск принят и поставлен в очередь, и такой запуск списывается, если его не отменить до отправки.

### `POST /v2/models/{provider}/{model}/requests`

`application/json` -- [`RouterModelInput`](#routermodelinput) (обязательно)

Когда вызов обслуживает собственный провайдер модели, запрос Seedance тарифицируется по типам медиа в `content`, а не по ролям: любой видео-вход тарифицируется как «видео в видео», иначе любое изображение тарифицируется как «изображение в видео», иначе как «текст в видео», за исключением того, что финальный рендер из элемента `draft_task` тарифицируется как операция черновика Draft, который он рендерит, причём некоторые модели берут одинаковый тариф за «текст в видео» и «изображение в видео»; если `model_provider` выбирает альтернативного провайдера или Comfy Router обслуживает вызов у другого провайдера, каждая обусловленная операция может тарифицироваться по собственному тарифу этого провайдера. Тот же контракт выбора провайдера действует при диспетчеризации: без `model_provider` или с `model_provider` и `strict_mode=false` (по умолчанию) тело является нативным документом модели и валидируется по собственной входной схеме модели до того, как запуск будет принят, поэтому тело, которое модель отклонила бы, здесь даёт `422`, а не запрос в очереди, который упадёт через несколько минут; тело для альтернативного провайдера в нестрогом режиме дополнительно переводится в реальную схему этого провайдера при диспетчеризации. При `strict_mode=true` тело уже должно соответствовать собственной схеме альтернативного провайдера и передаётся без изменений: валидация по нативной схеме пропускается, точно как на синхронном маршруте (см. `model_provider` и `strict_mode`).

### `PUT /v2/models/{provider}/{model}/requests/{request_id}/cancel`

**Запросить отмену одного отправленного запроса.**

Просит Comfy остановить запрос, который ещё не завершён. Это просьба, а не гарантия, и `202` говорит именно об этом: `CANCELLATION_REQUESTED` означает, что просьба принята, а не что выполнение остановлено. Запуск, который уже выполняется у партнёра, может всё равно завершиться, а завершённая генерация у партнёра оплачивается независимо от того, забрал ли её кто-нибудь. ## Категории ошибок

Машиночитаемая категория ошибки Router, которая также передаётся в заголовке `X-Comfy-Error-Type`.

### Категории уровня запроса

Возникают для запроса, который Router принял, но не смог выполнить.

| `error_type` | Значение |
| --- | --- |
| `invalid_input` | Запрос был отклонён до того, как дошёл до модели: некорректное тело, некорректный или просроченный курсор пагинации, вход, который не принимает собственная схема модели, или `Idempotency-Key`, который не может обслужить этот запрос (уже использован для другого запроса, где отличаются метод, путь и query или тело, либо уже израсходован вызовом, ответ которого невозможно воспроизвести). |
| `content_policy_violation` | Провайдер отказал в запросе по причинам политики содержимого. |
| `provider_error` | Партнёрский провайдер сообщил о собственной ошибке или вернул ответ, который Router не смог интерпретировать как результат. |
| `provider_timeout` | Партнёрский провайдер не ответил в отведённый ему срок. |
| `insufficient_credits` | У вызывающего рабочего пространства недостаточно кредитов для запуска модели. |
| `budget_exceeded` | Достигнут жёсткий предел расходов. |
| `model_not_found` | Идентификатор `{provider}/{model}` не указывает ни на одну модель, которую может запустить Router: неизвестный провайдер, незарегистрированный id, id, выведенный из каталога после даты окончания поддержки, или id из каталога, который провайдер сейчас не обслуживает для Comfy. |
| `byok_credential_rejected` | Провайдер отклонил ключ, переданный для этого вызова. |

### Категории транспортного уровня

Возникают в самом Router, до или вокруг вызова модели.

| `error_type` | Значение |
| --- | --- |
| `unauthorized` | Запрос не содержал пригодных учётных данных. |
| `forbidden` | Учётные данные действительны, но не дают прав на эту модель или эту операцию. |
| `concurrency_limit_exceeded` | В рабочем пространстве уже столько одновременных вызовов, сколько разрешено. Повторите попытку, когда один из них завершится. |
| `client_disconnected` | Вызывающая сторона закрыла соединение до того, как Router смог вернуть результат. |
| `internal_error` | Сбой в самом Router. |
| `deadline_exceeded` | Comfy перестал удерживать соединение по достижении собственного настроенного предела, так и не дождавшись ответа. |
| `not_enabled` | Comfy Router ещё не включён для этой вызывающей стороны. |
| `service_unavailable` | Служба, от которой зависит Comfy Router, временно недоступна, и вызывающая сторона не сделала ничего неправильного. |
| `budget_check_unavailable` | Не удалось проверить жёсткий предел расходов. |
| `rate_limited` | Вызывающая сторона израсходовала лимит, измеряемый за окно, и должна дождаться сдвига этого окна; либо провайдер модели ограничил вызов ещё до начала генерации. |
| `cancelled` | Запрос из очереди был отозван (через маршрут отмены или оператором) до того, как он дал результат. Это терминальное состояние, и само по себе оно ничего не говорит о списании средств. |
| `queue_timeout` | Запрос в очереди прождал дольше своего таймаута в очереди и так и не был допущен к выполнению. |
| `request_not_found` | `request_id` не указывает ни на один запрос вызывающей стороны для этой модели. |
| `queue_backlog_full` | У вызывающей стороны уже слишком много запросов в очереди, поэтому эта отправка была отклонена. |
| `result_expired` | Запрос существовал и завершился, но его результат больше не хранится, поэтому при сборе результата возвращать нечего. |

  Отправляется только при чтении статуса, пока `status` равен `IN_PROGRESS`, рядом с `X-Comfy-Estimated-Duration-Seconds`: откуда взялась эта оценка длительности генерации (не `source` оценки стоимости): `historical` (измерено на недавних запусках) или `default` (запасное значение для каждого типа медиа, используется, пока записано слишком мало недавних запусков).
</ResponseField>

<ResponseField name="X-Comfy-Estimated-Duration-P90-Seconds" type="integer">
  Отправляется только при чтении статуса, пока `status` равен `IN_PROGRESS`, рядом с `X-Comfy-Estimated-Duration-Seconds`: 90-й процентиль этой оценки длительности генерации, в целых секундах.
</ResponseField>

<ResponseField name="X-Comfy-Estimated-Duration-Seconds" type="integer">
  Отправляется только при чтении статуса, пока `status` равен `IN_PROGRESS`: оценка Router в целых секундах для всего запуска генерации после того, как провайдер её принял (не оставшееся время и никогда не время, проведённое в `IN_QUEUE`).
</ResponseField>

<ResponseField name="X-Comfy-Refusal-Subject" type="string">
  Ко входу или выходу какого типа относился отказ по политике содержимого, в виде закрытого словаря уровня Router: `input`, `output`, `input_text`, `input_image`, `input_video`, `input_audio`, `output_text`, `output_image`, `output_video`, `output_audio`.
</ResponseField>

<ResponseField name="X-Comfy-Request-Id" type="string">
  Сгенерированный сервером идентификатор этого вызова, присутствует в каждом ответе Router, включая успешные ответы, 4xx и 5xx, потому что ответ с ошибкой это как раз тот случай, когда пользователю нужен id, чтобы указать его в запросе в поддержку.
</ResponseField>

<ResponseField name="X-Comfy-Router-Dropped-Params" type="string">

Присутствует всегда, когда перевод сформировал тело запроса этого вызова и не смог точно выразить одно или несколько нативных полей на провайдере, который его обслуживал, с указанием каждого отброшенного поля и причины; независимо от того, запросил ли вызывающий этот перевод через `model_provider` (`strict_mode=false`, значение по умолчанию) или его выполнила автоматическая повторная попытка `fallback_provider`.
</ResponseField>

<ResponseField name="X-Comfy-Router-Fallback-Provider" type="string">

</ResponseField>

<ResponseField name="X-Comfy-Router-Provider" type="string">

</ResponseField>

<ResponseField name="X-Committed-Spend-Current" type="integer">

</ResponseField>

<ResponseField name="X-Committed-Spend-Limit" type="integer">

</ResponseField>

<ResponseField name="X-Committed-Spend-Remaining" type="integer">

<ResponseField name="X-Content-Type-Options" type="string">

<ResponseField name="X-Model-Concurrency-Remaining" type="integer">

## Оценка стоимости перед запуском

`POST /v2/models/{provider}/{model}/estimate` рассчитывает стоимость тела запроса, не выполняя его, а поставленная в очередь отправка (`POST /v2/models/{provider}/{model}/requests`) возвращает тот же [`RouterCostEstimate`](#routercostestimate), что и `estimate`, в своём ответе `201`. Оба оцениваются по стандартному прайс-листу Comfy, кроме модели, с которой списывается стоимость, сообщаемая её вендором, и для которой цена `estimated` берётся из опубликованного прайс-листа вендора. Ни одна из них не отражает контрактные или индивидуальные ставки: рабочему пространству с договорными ценами выставляется по прайс-листу, а списывается по его контрактной ставке, и `source: exact` тогда означает точность по прайс-листу, а не сумму списания для этого рабочего пространства. Любая возвращённая цифра является оценкой, а не итоговым списанием: окончательным является списание, зафиксированное в записях об использовании и выставлении счетов вашего рабочего пространства. Запуск на вашем собственном ключе провайдера не тарифицируется Comfy (см. ниже). Если оценки отключены для развёртывания, маршрут отвечает `403` с `error_type: not_enabled`, а ответ на отправку не содержит `estimate`. Оба оценивают тело так, как Router его отправил бы (с переводом для плеча `model_provider`, с перенацеливанием на операцию, в которой он выполняется), но `estimate` в ответе на отправку не является предварительной ценой: он появляется только после того, как запуск принят и поставлен в очередь, и этот запуск тарифицируется, если только он не был отменён до отправки. Каталог по-прежнему не содержит цен.

Читайте `source` до любой суммы. Отсутствующая цифра никогда не означает «бесплатно».

| `source` | Содержит | Как читать |
| --- | --- | --- |
| `exact` | `amount`, `amount_cents`, `credits` | Оценка, равная списанию за это тело по ставкам в `pricing_as_of`; окончательным является списание, зафиксированное в записях об использовании и выставлении счетов вашего рабочего пространства. |
| `estimated` | `min_amount`, `max_amount` и их формы `_cents`, без `amount` | Оценка, списание по которой зависит от количества, которое сообщает провайдер, а тело задаёт его границы; ожидается, что списание окажется между границами, а окончательным является списание, зафиксированное в записях об использовании и выставлении счетов вашего рабочего пространства. |
| `free` | `amount` "0", `amount_cents` и `credits` `0` | Тарифная карточка оценивает этот запрос в ноль, поэтому оценка равна `0`; окончательным является списание, зафиксированное в записях об использовании и выставлении счетов вашего рабочего пространства. Только оценка `free` показывает `0`. |
| `unknown` | `reason`, без цифры | До запуска нельзя было указать цену. Любое другое значение `source` следует трактовать как `unknown`. |

`reason` оценки `unknown` может быть одним из следующих:

- `not_quotable`: Router не может оценить этот вызов до его выполнения, потому что тарификация идёт по количеству, которое сообщает провайдер и которое тело не ограничивает, либо тело нельзя оценить в отправленном виде. Любой нераспознанный `reason` следует трактовать как `not_quotable`.
- `unpriced_model`: тарифная карточка не оценивает этот запрос.
- `byok` (только для поставленной в очередь отправки): запуск использует ваш собственный ключ провайдера, поэтому Comfy ничего за него не списывает.
- `pricing_unavailable` (только для поставленной в очередь отправки): тарифную карточку не удалось прочитать, когда запрос был принят. Отправка всё равно принимается, а запуск тарифицируется как обычно.

Модели, которые Router пока не может оценить до запуска, перечислены в разделе [модели без предварительной оценки стоимости](/ru/development/comfy-router/limitations#модели-без-предварительной-оценки). Модель, не указанная там, всё равно может вернуть `unknown` для конкретного тела, поэтому читайте `source` в каждой оценке.

Где оценка отказывает, а не угадывает:

- Когда для цифры нужна тарифная карточка, а карточка не загружена или устарела, `/estimate` отвечает `503`, а не догадкой. Поставленная в очередь отправка никогда не отклоняется из-за своей оценки; вместо этого она несёт `source: unknown` с `reason: pricing_unavailable`. Вызов, который нельзя оценить до запуска в принципе (`not_quotable`), или поставленная в очередь отправка на вашем собственном ключе провайдера (`byok`) получают ответ без чтения карточки, поэтому такой `200` ничего не говорит о том, свежая ли карточка.
- `/estimate` проверяет тело по собственной входной схеме модели так же, как и запуск по умолчанию, поэтому тело, не проходящее схему модели, получает тот же `422` с той же формой `detail[]`, что вернул бы запуск. Ничего не оценивается и не отправляется.
- Идемпотентный повтор поставленной в очередь отправки (`Idempotent-Replayed: true`) не содержит `estimate`, потому что исходная оценка не сохраняется.

Ограничения оценки. Цифра в ответе `200` не является обещанием, что запуск будет принят или что списание составит ровно эту сумму:

- `/estimate` не принимает `strict_mode` или `reject_unknown_fields`, поэтому проверяет только нативный контракт модели: тело, которое запуск с `strict_mode=true` принимает в собственной схеме альтернативного провайдера, здесь может получить `422`, а необъявленное поле верхнего уровня, которое запуск с `reject_unknown_fields=true` отклонил бы, здесь оценивается. Модель Anthropic Messages является исключением: её схема допускает необъявленные поля, поэтому запуск с `reject_unknown_fields=true` ничего не отклоняет, а оценка учитывает только необъявленные поля верхнего уровня `tools`, `tool_choice`, `temperature`, `top_p`, `top_k`, `stop_sequences`, `metadata`, `thinking` и пустой `mcp_servers`. Любое другое необъявленное поле верхнего уровня заставляет её вернуть `unknown` с `reason: not_quotable`.
- `pricing_as_of` обозначает момент, когда была получена тарифная карточка. Оценка `estimated`, взятая из опубликованного прайс-листа вендора, несёт дату, когда этот список был прочитан. Оценка `exact` или `estimated`, чьё тарифицируемое количество предсказано по опубликованному графику вендора, несёт дату чтения этого графика, если она старше карточки. Когда не читались ни карточка, ни график, это момент, когда была выдана оценка. Это не фиксация цены: списание выполняется по ставкам, действующим на момент тарификации.
- `/estimate` оценивает плечо, указанное `model_provider`, или нативного провайдера. Он не принимает параметр `fallback_provider` или `strict_mode`. Синхронный запуск, повтор с резервным провайдером которого попадает на другого провайдера, тарифицируется по ставке этого провайдера, которую оценка не указала; `X-Comfy-Router-Fallback-Provider` в ответе запуска сообщает, что это произошло. У поставленной в очередь отправки нет резервного провайдера, поэтому её `estimate` оценивает то плечо, которое выполняется.- `/estimate` всегда указывает сумму списания платформы. Запуск с вашим собственным ключом провайдера не тарифицируется Comfy, но `/estimate` этого не определяет и всё равно возвращает значение; только отправка, поставленная в очередь, отвечает `reason: byok`.
- Доллары отображаются из неокруглённых центов с точностью до 8 знаков после запятой, а подлежащая списанию сумма `amount` меньше цента никогда не отображается как `0`. `credits` рассчитывается как `round(amount × 211, 2)`, та же конверсия, которую `X-Comfy-Credits-Used` применяет при списании, поэтому `credits` может округлиться до `0` при очень маленькой ненулевой цене; если это важно, рассчитывайте бюджет по `amount` или `amount_cents`, а не по `credits`. Этот заголовок остаётся фактическим значением после запуска; балансы находятся на платформе Comfy.

## Ассеты результатов

Модель может возвращать URL-адреса ассетов, встроенные байты или и то, и другое. Провайдеры, перечисленные ниже, копируют выбранные ассеты в хранилище Comfy и заменяют их URL-адреса. Это поведение зависит от модели; заголовка запроса, который его выбирает, не существует.

| Модели | Что копируется в хранилище Comfy | Максимальный срок жизни URL-адреса, размещённого в Comfy |
| --- | --- | --- |
| `bfl/*` | готовый ассет, а также ассет чернового кэша, если результат его содержит | 24 часа |
| `byteplus/*` видео-модели (`seedance`, `dreamina-seedance`) | готовое видео, а также изображение последнего кадра, если результат его содержит | 24 часа |
| `fal/h3-max`, `fal/h3-max-turbo` | готовое видео | 24 часа |
| `minimax/*` | готовое видео | 12 часов |
| `xai/*` | каждое сгенерированное изображение и готовое видео | 24 часа |

Эти сроки отсчитываются с момента подписания URL-адреса, а не с момента его открытия. У кэшированных или воспроизведённых URL-адресов может оставаться меньше времени; воспроизведение их не продлевает. Запись `Idempotency-Key` может существовать дольше, чем хранящиеся в ней URL-адреса, поэтому за час до истечения такого URL-адреса повторная попытка с тем же ключом получает ответ `409 invalid_input` вместо записанного ответа; ответ, который уже был настолько близок к истечению в момент выдачи, остаётся воспроизводимым в течение 5 минут. Скачивайте ассет сразу. Копируются только ассеты, указанные в каждой строке: изображения `byteplus/seedream-*` и `byteplus/seededit-*` не покрываются строкой про видео BytePlus, а модели `fal/fal-*` не покрываются строкой про fal.

Копирование выполняет только нативный провайдер модели. Запуск, обслуженный альтернативным провайдером, возвращает собственные URL-адреса этого провайдера, которые подчиняются срокам истечения провайдера и не копируются. К таким запускам относятся: запуск с `model_provider`, указывающим на альтернативного провайдера; запуск без указания `model_provider`, который Comfy Router обслужил на другом провайдере (это сообщается в `X-Comfy-Router-Provider` на синхронном маршруте запуска); нативный запуск, повторная попытка с фолбэком которого попала на такого провайдера (раскрывается в `X-Comfy-Router-Fallback-Provider`). Значения `model_provider` `default`, `comfy` и `comfyui` не указывают альтернативного провайдера, поэтому такие запуски являются нативными и копируются, как описано выше, как и запуск с `model_provider`, повторная попытка с фолбэком которого вернулась к нативному провайдеру.

**У Veo (`veo/*`) отдельный путь хранения.** В `response.videos[]` читайте тот элемент, который присутствует: `bytesBase64Encoded` содержит клип встроенно, а `gcsUri` содержит подписанную Comfy HTTPS-ссылку, когда окружение настроено на прямую запись провайдером в хранилище Comfy. Эта ссылка действительна 24 часа с момента ответа. В последнем случае ассет записывается напрямую, а не копируется, поэтому Veo отсутствует в таблице переразмещения.

Другие модели возвращают ссылки на ассеты провайдера или встроенные байты. URL-адреса провайдера подчиняются срокам истечения провайдера, которые могут быть намного короче указанных выше сроков и не определяются контрактом Router.

**Оригинальные URL-адреса BytePlus (Seedance 2.x, при включении).** Для рабочего пространства, в котором Comfy включил эту возможность на стороне сервера, результат Seedance 2.x также содержит собственные URL-адреса BytePlus в `content.upstream_video_url` и `content.upstream_last_frame_url` рядом со скопированными, а также `content.upstream_expires_at`. Ни параметра запроса, ни рабочего пространства, включённого по умолчанию, нет. Эти URL-адреса истекают через 24 часа после генерации и отсутствуют, как только BytePlus их очистит; в Seedance 2.5 BytePlus ограничивает каждый из них 100 загрузками, и собственная копия Router использует одну из них. Каждый из них является bearer-учётными данными для своего объекта: любой, у кого он есть, может скачать ассет до истечения срока.

**Рабочие пространства с нулевым хранением данных.** Для рабочего пространства, которое Comfy настроил на нулевое хранение данных, результаты BytePlus не копируются в хранилище Comfy: строка про видео `byteplus/*` выше не применяется, а `content.video_url` и `content.last_frame_url` являются собственными URL-адресами провайдера BytePlus, возвращёнными в том виде, в каком их отправил BytePlus. Они действительны 24 часа, а в Seedance 2.5 BytePlus ограничивает каждый из них 100 загрузками, поэтому скачивайте ассет сразу. Такой результат не воспроизводится из его записи `Idempotency-Key`.

Копирование выполняется по мере возможности для каждого ассета. Если копирование одного из них не удалось, эта запись сохраняет ссылку на провайдера; ответ может содержать как URL-адреса Comfy, так и URL-адреса провайдера, без явного поля статуса копирования для каждого ассета. Генерация при этом завершается успешно и тарифицируется. Не выводите срок жизни всех URL-адресов из одного успешно переразмещённого ассета.

От того, размещён ли результат в Comfy, также зависит, можно ли позже воспроизвести завершённый вызов из его записи `Idempotency-Key`; параметр `Idempotency-Key` выше описывает, что возвращается при повторной попытке, когда это невозможно.

## Схемы входа и выхода для каждой модели

Поля каждой модели можно прочитать из `GET /v2/models/{provider}/{model}/openapi.json`. Для этого запроса нужен API-ключ. Тот же документ для каждой модели с описанной схемой также опубликован на этом сайте без ключа по адресу `/router-schemas/{provider}/{model}.json`. Эта копия является снимком на момент последнего обновления документации, поэтому при расхождениях приоритет имеет эндпоинт. `requestBody` операции описывает валидацию входа; ответ `200` описывает форму и тип медиа выхода, если схема выхода задана. Если `x-comfy-input-schema-authored` равно false, Router принимает любой объект JSON без предварительной валидации для конкретной модели. Требования провайдера по-прежнему действуют. Схемы выхода описывают результаты; Router не проверяет возвращённые провайдером данные на соответствие им. Для неописанного выхода может использоваться `*/*` вместо `application/json`; перед декодированием проверьте тип содержимого ответа.

</ResponseField>

### RouterCostEstimate

Предварительная оценка того, во сколько обойдётся этот вызов, в долларах США, рассчитанная до отправки по стандартному прайс-листу Comfy, или, для модели, оплачиваемой по стоимости, которую сообщает её поставщик, по опубликованному прайс-листу поставщика. В этом случае с ценой от поставщика `source: exact` возвращается только для небольшого набора моделей, подключённых к этой опции, и только когда опубликованный прайс-лист полностью определяет величину (каждое поле, влияющее на цену, было указано или оставлено со значением по умолчанию, которое не может её изменить); любая другая цена от поставщика помечается как `estimated`, включая некоторые случаи, которые список мог бы полностью определить. В любом случае с запуска всё равно списывается сумма, которую сообщает поставщик после его завершения, а не указанная в котировке величина дословно. Оценка не отражает договорные или индивидуальные тарифы: рабочему пространству с согласованными ценами выставляется прайсовая цена, а списывается его договорной тариф, и тогда `source: exact` означает точность по прайс-листу, а не фактическое списание этого рабочего пространства. Это не итоговое списание: вы платите то, что зафиксировано в записях об использовании и выставлении счетов вашего рабочего пространства. `X-Comfy-Credits-Used`, возвращаемый после запуска, это округлённая величина, рассчитанная постфактум, а не квитанция. `source` показывает, насколько можно доверять числу: `exact` содержит `amount`; `free` содержит `amount` "0" (тарифная карточка оценивает этот запрос в ноль); `estimated` содержит `min_amount` и `max_amount` и не содержит `amount`; `unknown` не содержит ни того, ни другого, но содержит `reason`. Никогда не считайте отсутствующий `amount` признаком бесплатности. Это не фиксация цены: см. `pricing_as_of`.

**Поля**

<ResponseField name="source" type="string" required>
  `exact` | `estimated` | `free` | `unknown`; любое другое значение считайте `unknown`. `exact` и `estimated` оба обозначают оценку; ни то, ни другое не является итоговым списанием. `free` означает, что тарифная карточка оценивает этот запрос в ноль, поэтому `amount` равно "0". `unknown` не содержит числовой величины.
</ResponseField>

<ResponseField name="currency" type="string" required>
  Всегда `USD`.
</ResponseField>

<ResponseField name="amount" type="string">
  Оценочная стоимость в долларах в виде десятичной строки, например "0.04", с точностью до 8 знаков после запятой и без экспоненты. Списываемая цена меньше цента никогда не отображается как "0"; только у котировки `free` значение равно "0". Присутствует, только когда `source` имеет значение `exact` или `free`. Это не итоговое списание: итоговым является списание, зафиксированное в записях вашего рабочего пространства.
</ResponseField>

<ResponseField name="min_amount" type="string">
  Нижняя граница оценки в долларах в виде десятичной строки. Это оценка, а не гарантированный минимум: с вызова может быть списано меньше, например когда провайдер вернул меньше, чем запрашивалось (например, ни одного изображения), когда оценка является типичной ценой, полученной из прошлых вызовов, или когда цена не растёт монотонно с запрошенным объёмом. Присутствует, только когда `source` имеет значение `estimated`.
</ResponseField>

<ResponseField name="max_amount" type="string">
  Верхняя граница оценки в долларах в виде десятичной строки. Это оценка, а не гарантированный потолок: с вызова может быть списано больше, например когда провайдер вернул больше, чем запрашивалось (например, больше изображений, чем было запрошено), когда оценка получена из прошлых вызовов, или когда цена не растёт монотонно с запрошенным объёмом. Присутствует, только когда `source` имеет значение `estimated`.
</ResponseField>

<ResponseField name="amount_cents" type="number">
  Та же величина в центах США, без округления, для арифметических операций. Присутствует вместе с `amount`.

  double
</ResponseField>

<ResponseField name="min_amount_cents" type="number">
  `min_amount` в центах США, без округления. Присутствует вместе с `min_amount`.

  double
</ResponseField>

<ResponseField name="max_amount_cents" type="number">
  `max_amount` в центах США. Присутствует вместе с `max_amount`.

  double
</ResponseField>

<ResponseField name="credits" type="number">
  `amount` в кредитах Comfy по платформенному курсу ($1 = 211 кредитов), округлённое до 2 знаков: именно эту величину ожидается увидеть в `X-Comfy-Credits-Used` для котировки `exact`. Этот заголовок является округлённой величиной, рассчитанной постфактум, а не квитанцией; окончательным является списание, зафиксированное в записях об использовании и выставлении счетов вашего рабочего пространства.

  double
</ResponseField>

<ResponseField name="provider" type="string" required>
  Провайдерская часть, к которой относится эта котировка. При постановке в очередь это та часть, которая будет выполнена. Если вызывающая сторона не указала `model_provider`, Comfy Router выбирает обслуживающего провайдера, и это значение может быть `comfy`, что означает, что Comfy Router выбрал эту часть, а не конкретное имя провайдера.
</ResponseField>

<ResponseField name="model" type="RouterModelId" required>
  Канонический ID модели Comfy Router, `{provider}/{model}`, ровно то значение, которое адресует модель в `POST /v2/models/{provider}/{model}`, поэтому вызывающая сторона может подставить его в этот путь, не выводя его заново из чего-либо. Его `pattern` это `RouterProviderSegment` и `RouterModelSegment`, соединённые одним `/`, а `maxLength` равна их сумме плюс этот разделитель.

  Тип: [`RouterModelId`](#routermodelid) -- ID модели, например `anthropic/claude-opus-4-6`, до 193 символов
</ResponseField>

<ResponseField name="pricing_as_of" type="string" required>
  Момент, когда была получена тарифная карточка, по которой рассчитана эта котировка. Оценка не является фиксацией цены: с запуска списывается по тарифам, действующим в момент расчёта, а не в этот момент. Котировка `estimated`, взятая из опубликованного прайс-листа поставщика (модель, оплачиваемая по стоимости, которую сообщает поставщик), вместо этого содержит дату, когда этот список был прочитан. Котировка, у которой оплачиваемый объём предсказан по опубликованному графику поставщика, а затем оценён по тарифной карточке, содержит более раннюю из двух дат: дату чтения этого графика и время получения карточки, одинаково для ответа `exact` и для `estimated` (модель, оплачиваемая по кредитам, которые сообщает поставщик, относится к случаю `estimated`). Если тарифная карточка не читалась (`reason: pricing_unavailable`, `byok` или вызов `not_quotable`, который нельзя оценить ни по одной карточке), здесь указывается момент, когда был дан ответ на котировку.

  date-time
</ResponseField>

<ResponseField name="reason" type="string">
  Присутствует, только если `source` имеет значение `unknown`: `not_quotable` (Router не может оценить стоимость этого вызова до его запуска: его цена зависит от того, что сообщит провайдер, или тело запроса не ограничивает оплачиваемый объём), `unpriced_model` (карточка тарифов не содержит цены для этого запроса), `byok` (только при отправке в очереди: запуск использует ваш собственный ключ провайдера, поэтому Comfy не выставляет за него счёт) или `pricing_unavailable` (только при отправке в очереди: карточку тарифов не удалось прочитать при приёме запроса; это временное явление, и запуск по-прежнему оплачивается как обычно). Любое другое значение следует интерпретировать как `not_quotable`.
</ResponseField>

### RouterErrorResponse

Тело ошибки при сбоях аутентификации, доступа, поиска модели, квоты и транспорта провайдера.

**Поля**

<ResponseField name="detail" type="string" required>
  Понятное человеку описание сбоя, которое безопасно показывать конечному пользователю. Не предназначено для машинного разбора: вместо этого ветвитесь по `error_type`. Для `model_not_found` на выведенной из эксплуатации модели `detail` содержит `<id> was retired on <YYYY-MM-DD>; use <successor>`, когда преемник записан и виден вызывающей стороне, или просто `<id> was retired on <YYYY-MM-DD>`, когда он не виден, вместо обычного списка предложений. Названный здесь преемник всегда является действующим ID каталога, на который можно перенаправить вызов. Модель, дата вывода которой ещё в будущем, не считается выведенной: она остаётся в списке `GET /v2/models` и остаётся работоспособной до этой даты. Как и остальная часть `detail`, эта формулировка о выводе предназначена для отображения и не даёт гарантий совместимости. Два документированных исключения из правила о машинном разборе: на `POST /v2/models/{provider}/{model}` ответ `409` возвращается для трёх несвязанных условий, которые попадают в одну категорию `invalid_input`, и только `detail` их различает: если `detail` начинается с «this request's `image` selects the edit operation», это отказ multipart `model_provider`, а если `detail` начинается с «this request resolved a BYOK credential», это отказ BYOK `model_provider`; ни один из них не снимается новым `Idempotency-Key`. Любой другой `invalid_input` `409` на этом маршруте это конфликт ключей. Оба префикса являются стабильными условиями контракта, и по ним можно сопоставлять. Больше нигде ветвление по `detail` не даёт гарантии совместимости.
</ResponseField>

<ResponseField name="error_type" type="RouterErrorType" required>
  Грубая, машиночитаемая категория сбоя Router, дублируемая в заголовке ответа `X-Comfy-Error-Type`, чтобы вызывающая сторона могла ветвиться без разбора тела. Набор закрыт и содержит двадцать три значения: семь категорий уровня запроса `invalid_input`, `content_policy_violation`, `provider_error`, `provider_timeout`, `insufficient_credits`, `budget_exceeded` и `model_not_found`, а также транспортные `unauthorized`, `forbidden`, `concurrency_limit_exceeded`, `client_disconnected`, `internal_error`, `deadline_exceeded`, `not_enabled`, `service_unavailable`, `budget_check_unavailable`, `rate_limited`, `cancelled`, `queue_timeout`, `request_not_found`, `queue_backlog_full` и `result_expired`, плюс категорию уровня запроса `byok_credential_rejected`. Закрытость описывает набор в том виде, в каком он документирован сегодня, а не предел, действующий вечно: ожидается, что набор будет расти, поэтому здесь намеренно используется обычная строка, а не `enum`, так что клиент должен трактовать нераспознанное значение как `internal_error`, а не перебирать исчерпывающе список выше и ломаться при следующем добавлении.

  Тип: [`RouterErrorType`](#routererrortype)
</ResponseField>

<ResponseField name="upstream_detail" type="string">
Ограниченная и очищенная причина отказа `invalid_input` либо модерационное предложение провайдера для `content_policy_violation`. На синхронном маршруте это причина, которую указал провайдер модели, и она присутствует только тогда, когда `X-Comfy-Upstream-Status` провайдера равен `4xx` или `2xx` и выполняется одно из двух условий. Либо `error_type` равен `invalid_input`, то есть провайдер отклонил запрос как некорректный и объяснил причину, либо `error_type` равен `content_policy_violation`, а отказ провайдера входит в фиксированный набор модерационных предложений, которые Router распознаёт, например `Azure MAI blocked this request through content moderation.`; произвольный текст отказа Router не пересылает. Обычно этот статус `4xx`; он `2xx` у провайдера, который сообщает об отклонённой генерации внутри успешного ответа (опрос неудачной задачи BytePlus это HTTP `200` с причиной в теле). Router читает причину только у некоторых провайдеров, поэтому опирайтесь на её наличие. Она отсутствует при любых других сбоях, включая `5xx` провайдера, транспортные сбои, другие отказы по политике контента и любой отказ, который Router выставил самому себе, и повторяет заголовок `X-Comfy-Upstream-Detail`. Очередной сбор (`GET /v2/models/{provider}/{model}/requests/{request_id}`) запуска, завершившегося `invalid_input` или `content_policy_violation`, несёт ту же причину в этом поле при первом сборе, после чего удаляет её из запроса: последующий сбор обычно отвечает тем же `error_type` и `detail` без неё, поэтому читайте её из первого сбора. Этот запрос не отправляет ни одного из заголовков. Очередной сбор также использует это поле для собственной причины Router, когда Router отклонил запрос до отправки провайдеру и может изложить причину одним предложением, что синхронный маршрут отвечает в `detail`; отказ, называющий отдельные поля, её не несёт.
</ResponseField>

<ResponseField name="refusal_subject" type="string">
  О каком входе или выходе шла речь в отказе по политике содержимого, в виде закрытого словаря уровня Router: `input`, `output`, `input_text`, `input_image`, `input_video`, `input_audio`, `output_text`, `output_image`, `output_video`, `output_audio`. Значения `input` / `output` без уточнения называют сторону, когда провайдер не назвал модальность. Присутствует только когда `error_type` равен `content_policy_violation` и провайдер назвал отклонённый субъект машиночитаемым кодом; в остальных случаях отсутствует. Никогда не текст провайдера. Сегодня именуется для отказов BytePlus, Runway, BFL, Gemini, Veo, Vertex, xAI и Wan, а также для отказов Gemini на сегментах Nano Banana MiniMax Router; провайдер, чей отказ не говорит, о какой стороне шла речь, оставляет поле отсутствующим. Оно дублирует заголовок `X-Comfy-Refusal-Subject`.
</ResponseField>

<ResponseField name="budget" type="RouterSpendBudgetDetail">
  Исчерпанный бюджет. Идентификаторы, режим и суммы видны владельцам рабочего пространства.

  Тип: [`RouterSpendBudgetDetail`](#routerspendbudgetdetail)
</ResponseField>

<ResponseField name="blocking_budgets" type="array of RouterSpendBudgetDetail">
  Все исчерпанные жёсткие бюджеты, видимые владельцу рабочего пространства.

  Тип: массив [`RouterSpendBudgetDetail`](#routerspendbudgetdetail)
</ResponseField>

<ResponseField name="denied_reason" type="string">
  Ветвь политики выставления счетов для отказа в тратах партнёрского узла: `no_funds`, когда оплачиваемый кошелёк пуст, `unspecified`, когда в вызове отказано без указания на это в показаниях средств. Присутствует только когда `error_type` равен `insufficient_credits` и развёртывание сообщает сведения о кошельке; в остальных случаях отсутствует. Машиночитаемый код, а не текст для отображения: показывайте `detail`, ветвитесь по этому полю.
</ResponseField>

<ResponseField name="billed_workspace" type="RouterBilledWorkspace">
  Кошелёк, с которого был бы списан отклонённый вызов, в `RouterErrorResponse.billed_workspace`. Отвечает на вопрос «какой кошелёк пуст?»: это не обязательно то рабочее пространство, которое сейчас выбрано в интерфейсе вызывающей стороны, и личные учётные данные участника команды указывают здесь его личный кошелёк, даже когда открыта команда с достаточными средствами. Присутствует только вместе с `denied_reason`.

  Тип: [`RouterBilledWorkspace`](#routerbilledworkspace)

  Тип: [`RouterQueueStatus`](#routerqueuestatus)
</ResponseField>

<ResponseField name="queue_position" type="RouterQueuePosition">
  Сколько запросов стоит перед этим в очереди на момент формирования ответа. Ноль означает, что этот запрос находится в начале очереди.

  Тип: [`RouterQueuePosition`](#routerqueueposition) -- не менее 0
</ResponseField>

<ResponseField name="estimate" type="RouterCostEstimate">
  Предварительная оценка стоимости для этого запроса; присутствует при новом приёме, когда оценка стоимости включена для вызывающей стороны. В ней указывается плечо провайдера, к которому был закреплён этот запрос (в очереди нет цикла резервных вариантов, поэтому `fallback_provider` никогда не меняет выполняемое плечо). Когда цифру привести невозможно, поле всё равно присутствует, со значением `source: unknown`; отправка никогда не завершается ошибкой из-за оценки. Отсутствует при идемпотентном повторе (`Idempotent-Replayed: true`), потому что исходная котировка не сохраняется. Это оценка, а не итоговое списание и не фиксация цены: выполнение оплачивается по тарифам, действующим на момент расчёта, а окончательное списание в записях об использовании и выставлении счетов вашего рабочего пространства является окончательным.

  Тип: [`RouterCostEstimate`](#routercostestimate)
</ResponseField>

### RouterValidationErrorDetail

Одна ошибка валидации на уровне поля.

**Поля**

<ResponseField name="loc" type="array of any" required>
  Путь к некорректному полю, начиная с самого внешнего сегмента. Например, `["body", "image_url"]` или `["body", "images", 0]`, где целое число задаёт индекс в массиве.
</ResponseField>

<ResponseField name="msg" type="string" required>
  Понятное человеку описание этой отдельной ошибки.
</ResponseField>

<ResponseField name="type" type="string" required>
  Конкретная машиночитаемая причина этой ошибки, передаваемая от провайдера без изменений. Именно по этому значению ветвится иерархия типизированных исключений SDK, а `error_type` в заголовке ответа является лишь его укрупнённой категорией.
</ResponseField>

<ResponseField name="ctx" type="RouterValidationErrorContext">
  Нарушенная граница для одного `RouterValidationErrorDetail`, перенесённая от провайдера дословно. Например, `{"limit_value": 8}` вместе с `greater_than`, `{"min_width": 512}` вместе с `image_too_small` или `{"max_size_bytes": 10485760}` вместе с `file_too_large`. Набор ключей зависит от провайдера и типа ошибки, поэтому это намеренно открытый объект: сузить его до фиксированного списка полей или вложить в строку `msg` означает, что портированная интеграция скомпилируется и затем молча потеряет ветвь, которая читала эту границу. Отсутствует, если тип ошибки не несёт границы.

  Type: [`RouterValidationErrorContext`](#routervalidationerrorcontext)
</ResponseField>

<ResponseField name="input" type="RouterValidationErrorInput">
  Некорректное значение входа, возвращаемое дословно, чтобы вызывающий код видел, что было отклонено, не выводя это заново из `loc`. Любой тип JSON: строка, число, булево значение, массив, объект или null, поэтому эта схема намеренно оставлена без типа, а не сужена до объекта. Отсутствует, если провайдер не возвращает вход обратно.

  Type: [`RouterValidationErrorInput`](#routervalidationerrorinput)
</ResponseField>
