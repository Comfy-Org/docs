Если вы уже отслеживаете расходы с помощью [LiteLLM Proxy](https://docs.litellm.ai/docs/proxy/pass_through), можно добавить Comfy Router как ещё один pass-through-эндпоинт. Вызывающий код продолжает использовать свои ключи LiteLLM, а ваш Comfy API-ключ остаётся на прокси.

Router сообщает стоимость запуска в долларах США в заголовке ответа `x-litellm-response-cost` (в ответе на запуск для синхронного запуска и в ответе на получение результата для запуска [в очереди](#доставка-через-очередь)) для тех моделей, у которых указана цена в кредитах Comfy за запуск (см. [Запуски без отчёта о стоимости](#запуски-которые-не-сообщают-стоимость)). LiteLLM читает этот заголовок в каждом pass-through-ответе и записывает его как расход по запросу, так что вам не нужно вести таблицу цен для этих моделей.

<Note>
  Встроенный провайдер `fal_ai/` в LiteLLM поддерживает только генерацию изображений. Чтобы направлять через LiteLLM общие задачи, используйте pass-through-эндпоинт, как показано здесь, а не нативный провайдер.
</Note>

## Настроить pass-through

<Steps>
  <Step title="Создать Comfy API-ключ">
    Создайте ключ в [вашем рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys) и сделайте его доступным процессу LiteLLM Proxy:

    ```bash
    export COMFY_API_KEY="comfyui-..."
    ```
  </Step>

  <Step title="Добавить Router в config.yaml">
    ```yaml config.yaml
    general_settings:
      pass_through_endpoints:
        # Запуски и постановки в очередь. Синхронные запуски сообщают точную стоимость,
        # которая заменяет cost_per_request для этой строки. При постановке в очередь
        # это не так; см. «Доставка через очередь» ниже.
        - path: "/comfy/v2/models"
          target: "https://api.comfy.org/v2/models"
          include_subpath: true
          methods: ["POST"]
          headers:
            X-API-Key: "os.environ/COMFY_API_KEY"
            content-type: application/json
          cost_per_request: 0.10   # ваша запасная оценка в USD
          timeout: 660             # больше предельного срока запуска Router (по умолчанию 10 минут)

        # Каталог моделей, опрос статуса очереди и сбор результатов. Сбор результатов
        # запуска из очереди сообщает точную стоимость, которая заменяет
        # 0 ниже для этой строки.
        - path: "/comfy/v2/models"
          target: "https://api.comfy.org/v2/models"
          include_subpath: true
          methods: ["GET"]
          headers:
            X-API-Key: "os.environ/COMFY_API_KEY"
          cost_per_request: 0
    ```

    - `include_subpath: true` перенаправляет `/comfy/v2/models/{provider}/{model}` на `https://api.comfy.org/v2/models/{provider}/{model}`, поэтому одна пара записей охватывает все модели Router.
    - Оставляйте `path` и `target` в пределах `/v2/models`. Если направить pass-through на корень API, любой вызывающий с ключом LiteLLM сможет использовать ваш ключ Comfy на всех остальных маршрутах Comfy API вне учёта расходов LiteLLM.
    - `methods` разделяет две записи на одном пути. Нужен выпуск LiteLLM Proxy, в котором сквозные эндпоинты поддерживают `methods`; эта страница проверена на v1.103.0.
    - `X-API-Key` передаёт ваш ключ `comfyui-`. Router также принимает тот же ключ как `Authorization: Bearer comfyui-...`.
    - Оставьте `forward_headers` выключенным. Когда он включён, LiteLLM пересылает в Router каждый входящий заголовок, включая ключ LiteLLM вызывающего. Когда он выключен, вызывающие передают `Idempotency-Key` как `x-pass-Idempotency-Key`: LiteLLM отбрасывает префикс `x-pass-` и пересылает заголовок. Заголовок `Idempotency-Key` без префикса до Router не доходит, поэтому повторный запрос запустит и оплатит вторую генерацию.
    - Задайте `timeout` больше [предельного срока запуска](/ru/development/comfy-router/limitations) Router, чтобы Router успел вернуть собственный `504` и идентификатор запроса до того, как LiteLLM сдастся. По умолчанию срок составляет 10 минут, как и стандартный тайм-аут pass-through в LiteLLM, равный 600 секундам.
  </Step>

  <Step title="Вызвать Router через прокси">
    Вызывающие аутентифицируются своим ключом LiteLLM. Тело запроса это собственные входные данные модели, точно как в [справочнике Comfy Router](/ru/development/comfy-router/reference):

    ```bash
    curl --max-time 660 \
      http://localhost:4000/comfy/v2/models/byteplus/dreamina-seedance-2-5-260628 \
      -H "Authorization: Bearer $LITELLM_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{"content": [{"text": "A red fox trotting through a snowy pine forest", "type": "text"}], "duration": 5, "ratio": "16:9", "resolution": "720p"}'
    ```
  </Step>
</Steps>

## Как учитываются расходы

Запуск, для которого сообщается стоимость, содержит следующие заголовки ответа: в ответе на запуск для синхронного запуска и в коллекции результатов для запуска в очереди:

```http
X-Comfy-Credits-Used: 12.5
X-Litellm-Response-Cost: 0.0592417062
X-Litellm-Total-Tokens: 0
```

`X-Comfy-Credits-Used` это цена запуска в кредитах Comfy, округлённая до двух знаков после запятой. `X-Litellm-Response-Cost` это та же цена, пересчитанная в USD из неокруглённой суммы кредитов, поэтому деление отображённых кредитов на курс может дать отличие в последних знаках. Имена заголовков нечувствительны к регистру, поэтому LiteLLM читает его как `x-litellm-response-cost`. LiteLLM записывает его точно в том виде, в каком он отправлен, и использует вместо вашего `cost_per_request`. `x-litellm-total-tokens` всегда равно `0`, поскольку медиа-запуски не измеряются в токенах.

Как и `X-Comfy-Credits-Used`, этот заголовок сообщает цену, а не окончательно списанную сумму. Сверяйтесь с [выставлением счетов рабочего пространства](https://platform.comfy.org/settings/billing), а не с итогами LiteLLM.

### Запуски, которые не сообщают стоимость

Некоторые запуски не содержат `x-litellm-response-cost`. В большинстве таких случаев `X-Comfy-Credits-Used` тоже отсутствует:

- запуск, списанный с вашего собственного ключа провайдера, а не с ваших кредитов Comfy
- модель, которой ещё нет в списке моделей Router, сообщающих цену за запуск в кредитах. Этот список консервативен, и некоторые провайдеры в него вообще не входят
- списание, которое не дошло до выставления счетов Comfy

Один случай отличается: ответ с ошибкой. Синхронный `content_policy_violation` от модели, у которой `billing.charges_on_policy_rejection` равен `yes`, может содержать `X-Comfy-Credits-Used` с тем использованием, которое Comfy записал для отклонённой генерации; но и в этом случае он никогда не содержит `x-litellm-response-cost`, потому что ошибка не является результатом, который LiteLLM должен учитывать.

Он также отсутствует, когда Router повторно отдаёт сохранённый результат при повторе с тем же `Idempotency-Key` (передаётся через прокси как `x-pass-Idempotency-Key`). Этот повтор не списывается заново, поэтому повторная отдача не сообщает точную стоимость запуска второй раз. По той же причине его содержит только одна коллекция результатов запуска в очереди: первая после того, как цена запуска записана. Повторное получение того же результата по-прежнему возвращает `X-Comfy-Credits-Used`, но не `x-litellm-response-cost`.

Когда заголовка нет, LiteLLM использует `cost_per_request` эндпоинта. Это относится ко всем случаям выше. Поэтому ответы с ошибкой, запуски, списанные с вашего собственного ключа провайдера, и идемпотентные повторы записываются по вашей оценке. Большинство из них не были списаны с ваших кредитов, но не все: отказ по политике содержимого, содержащий `X-Comfy-Credits-Used`, был оценён, поэтому читайте его стоимость из этого заголовка, а некоторые другие сбои, например генерация, которую Router не смог вам вернуть, могут быть списаны без сообщения стоимости. Сверяйтесь с записями об использовании вашего рабочего пространства. Задайте разумную оценку типичного запуска вместо `0`, чтобы запуск, который не сообщает стоимость, не выглядел бесплатным в ваших отчётах о расходах, и учитывайте, что такие строки уведут итоги LiteLLM выше вашего счёта Comfy. Запуск, который был оценён и действительно ничего не стоил, возвращает `x-litellm-response-cost: 0`, и LiteLLM записывает его как ноль.

## Доставка через очередь

При [доставке через очередь](/ru/development/comfy-router/queue) одна генерация приходит в LiteLLM как несколько запросов, и каждый из них образует отдельную строку расходов:

| Запрос | Метод | Стоимость строки с конфигурацией выше |
| --- | --- | --- |
| Отправить: `/v2/models/{provider}/{model}/requests` | `POST` | ваша оценка `cost_per_request` |
| Каждый опрос статуса: `.../requests/{request_id}/status` | `GET` | `0` |
| Получение результата: `.../requests/{request_id}` | `GET` | точная цена запуска, при первом получении, которое её сообщает |
| Отмена: `.../requests/{request_id}/cancel` | `POST` | ваша оценка `cost_per_request` |

Поля `status_url`, `response_url` и `cancel_url` в ответе на отправку содержат абсолютные URL `https://api.comfy.org/...`, и LiteLLM не переписывает тела ответов. Обращайтесь к ним через прокси, заменив `https://api.comfy.org` на префикс `/comfy` вашего прокси, например `http://localhost:4000/comfy/v2/models/...`. При прямой отправке в Comfy ваш ключ LiteLLM отклоняется.

Получение результата содержит `x-litellm-response-cost` один раз, при первом получении после того, как цена запуска записана. Для большинства моделей это первое получение. Для некоторых моделей цена записывается после того, как результат готов, поэтому раннее получение может вернуться без неё, а более позднее получение того же запроса её сообщает.

Router помечает цену как сообщённую, когда отвечает на это получение. Если ответ не доходит до LiteLLM, например из-за тайм-аута запроса или обрыва соединения, последующее получение тоже не содержит `x-litellm-response-cost`, и LiteLLM записывает этот запуск по стоимости записи `GET`.

Строка отправки по-прежнему фиксирует вашу оценку `cost_per_request`, поэтому при конфигурации выше запуск в очереди учитывается дважды: один раз по вашей оценке и один раз по его точной цене. Если вы используете только доставку через очередь, задайте `cost_per_request` записи `POST` равным `0`, чтобы каждый запуск в очереди записывался один раз, по своей точной цене. Запуск, результат которого вы никогда не получаете, тогда не появляется в итогах LiteLLM, хотя он всё равно тарифицируется в вашем рабочем пространстве. Если обе записи равны `0`, запуск, который не сообщает цену, записывается как `0`. Это включает запуск, цена которого записывается после того, как его результат готов, если вы получаете этот результат только один раз, до того как цена станет известна, а также случаи выше, когда получение её не сообщает. Если ваш клиент получает каждый результат только один раз, сразу как он готов, оставьте оценку `POST`.

## Примечания

- LiteLLM учитывает расходы, но не изменяет выставление счетов. Comfy выставляет счёт вашему рабочему пространству точно так же, как и без прокси.
- Полные схемы запросов и ответов для каждой модели приведены в [справочнике Comfy Router](/ru/development/comfy-router/reference). Сроки выполнения, повторные попытки и другие ограничения описаны в разделе [Возможности и ограничения](/ru/development/comfy-router/limitations).
