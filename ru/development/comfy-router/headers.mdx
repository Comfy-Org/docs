Каждая модель Router использует `POST /v2/models/{provider}/{model}` со своим телом JSON. На этой странице описаны заголовки, общие для всех моделей; [ссылка на API](/development/comfy-router/reference) содержит сгенерированный контракт.

Comfy SDK (`comfy-sdk` для Python, `@comfyorg/sdk` для TypeScript) обрабатывают аутентификацию и генерируют ключи идемпотентности. Они предоставляют выбранные метаданные ответа, как описано ниже. Клиенты, работающие с HTTP напрямую, должны сами отправлять и читать заголовки.

## Заголовки запроса

<ParamField header="X-API-Key" type="string">
  Comfy API-ключ, `comfyui-...`, созданный в [вашем рабочем пространстве Comfy](https://platform.comfy.org/profile/api-keys?onboarding=router). Он использует доступ к моделям и баланс кредитов вашего рабочего пространства. Вы также можете отправить его как `Authorization: Bearer comfyui-...`; если присутствуют оба заголовка, приоритет у `X-API-Key`.
</ParamField>

<ParamField header="Authorization" type="string">
  `Bearer <token>`. Значение с префиксом `comfyui-` является API-ключом. Любое другое значение рассматривается как JWT Comfy Cloud.
</ParamField>

<ParamField header="Idempotency-Key" type="string">
  Идентифицирует одну логическую генерацию. Сгенерируйте UUID и сохраните его до вызова, а затем используйте повторно при повторах неизменённого запроса. Ключ позволяет воспроизвести результат или собрать принятую работу в течение до 24 часов. SDK генерируют ключи и позволяют указать собственный (`idempotency_key=` в Python, `idempotencyKey` в TypeScript). О конфликтах, истечении срока и невоспроизводимых результатах см. [исходы повторов](/ru/development/comfy-router/errors#результаты-повторных-попыток).
</ParamField>

<ParamField header="Content-Type" type="string">
  `application/json`. Отправьте нативный JSON-вход модели. Поля и требования к валидации зависят от модели; см. [Использование Router API](/ru/development/comfy-router/api).
</ParamField>

<ParamField header="If-None-Match" type="string">
  Только для `GET /v2/models/{provider}/{model}/openapi.json`. Отправьте `ETag`, полученный от более раннего ответа `200`; если он всё ещё совпадает, ответом будет `304` без тела с тем же `ETag`. Кэшируйте схему модели на всё время жизни процесса и перепроверяйте её этим способом, а не перечитывайте перед каждым вызовом.
</ParamField>

## Заголовки ответа

<ResponseField name="X-Comfy-Request-Id" type="string" required>
  Идентифицирует этот HTTP-запрос. Указывайте его при обращении в поддержку. TypeScript предоставляет его как `requestId`; Python предоставляет `request_id` в ошибках.
</ResponseField>

<ResponseField name="X-Comfy-Error-Type" type="string">
  Машиночитаемая категория ошибки. При `422` используйте этот заголовок, поскольку тело валидации содержит `detail[]` и не содержит `error_type`. Объедините его со статусом HTTP, чтобы решить, что делать. Считайте неизвестное значение значением `internal_error` для управления потоком выполнения и сохраняйте его для диагностики.
</ResponseField>

<ResponseField name="Idempotent-Replayed" type="boolean">
  Присутствует и равен `true`, когда Router отдаёт сохранённый результат вместо повторного запуска модели. При новом запуске он отсутствует. На маршруте отправки в очередь повторный ответ `201` возвращает исходный дескриптор запроса вместо постановки в очередь второго запуска.
</ResponseField>

<ResponseField name="Retry-After" type="integer">
  Количество секунд ожидания перед повтором. При `409` / `concurrency_limit_exceeded` или `504` / `deadline_exceeded` повторите тот же запрос и тот же ключ после ожидания. При `429` / `rate_limited` он сообщает, когда сбросится ограничение частоты. При чтении статуса запроса в очереди и при чтении его результата `202` это подсказка Router о том, когда повторный опрос оправдывает сетевой обмен.
</ResponseField>

<ResponseField name="X-Committed-Spend-Limit" type="integer">
  Потолок расходов партнёра, зарезервированных под ещё выполняющиеся вызовы, в центах USD. Шлюз контроля расходов в режиме проверки может возвращать его в допущенных ответах и в своих отказах `429`. Он отсутствует, когда шлюз не выполняет проверку или запрос отклонил другой механизм контроля.
</ResponseField>

<ResponseField name="X-Committed-Spend-Current" type="integer">
  Центы USD, в настоящее время зарезервированные за выполняющимися вызовами. Допущенный ответ включает собственный вызов; ответ `429` не включает отклонённый вызов. Передаётся вместе с `X-Committed-Spend-Limit`.
</ResponseField>

<ResponseField name="X-Committed-Spend-Remaining" type="integer">
  Остаток в центах USD до потолка зарезервированных расходов. Он может быть положительным при отказе, если запрошенный вызов стоит больше оставшейся суммы.
</ResponseField>

<ResponseField name="ETag" type="string">
  Возвращается в ответе на `GET /v2/models/{provider}/{model}/openapi.json`. Сохраните его и отправьте обратно как `If-None-Match`, чтобы повторно проверить кэшированную схему.
</ResponseField>

<ResponseField name="Cache-Control" type="string">
  На маршруте схемы: `private, must-revalidate`. Храните ответ в частном кэше и повторно проверяйте устаревшие копии с помощью `ETag`.
</ResponseField>

## Коды статуса с двумя значениями

Три статуса встречаются в двух группах, и различить их помогает заголовок:

| Статус | `X-Comfy-Error-Type` | Что делать |
| --- | --- | --- |
| `409` | `concurrency_limit_exceeded` | Исходный вызов для этого ключа всё ещё выполняется. Дождитесь `Retry-After` и отправьте тот же ключ повторно. |
| `409` | `invalid_input` | Проверьте конфликт. Восстановите исходный запрос, если вы его изменили. Использованный ключ, который нельзя воспроизвести повторно, не позволяет получить результат; используйте новый ключ, только если вам нужна новая генерация, которая может быть платной. |
| `429` | `concurrency_limit_exceeded` | Слишком много вызовов в работе или достигнут потолок обязательных расходов (см. заголовки `X-Committed-Spend-*`). Ограничение снимается, когда завершается один из ваших собственных вызовов. |
| `429` | `rate_limited` | Перед повтором дождитесь `Retry-After`. |
| `504` | `deadline_exceeded` | Собственное 10-минутное ограничение роутера. При наличии `Retry-After` отправьте тот же ключ повторно, чтобы забрать результат выполняющейся генерации. |
| `504` | `provider_timeout` | Партнёр превысил время ожидания. Следуйте [указаниям по повторам и выставлению счетов](/ru/development/comfy-router/errors#результаты-повторных-попыток); не считайте это гарантией того, что средства не будут списаны. |
