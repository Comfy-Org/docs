Эта страница описывает вторую строку: клиент Comfy Cloud и Comfy API v2. Для маршрутизатора моделей начните с [краткого руководства Comfy Router](/ru/development/comfy-router/quickstart).

Comfy SDK позволяют вашему приложению запускать рабочие процессы ComfyUI и получать результаты. Вы отправляете рабочий процесс, ComfyUI выполняет его, а вы скачиваете выходы. Один и тот же код работает как с Comfy Cloud, так и с экземпляром ComfyUI, который вы размещаете сами. Меняется только базовый URL, за исключением [меток задач](#добавить-метки-к-задачам-и-найти-их-позже), которые работают только в развёртывании Comfy API, и списка задач, который Comfy Cloud пока не предлагает.

SDK являются клиентами для [Comfy API v2](/api-reference/v2/overview), версионированного HTTP API, который мы намерены поддерживать в долгосрочной перспективе. Новые релизы ComfyUI не нарушат интеграции, построенные на нём.

Что обычно создают таким образом:

- Плагины, которые генерируют содержимое внутри другого приложения, например в Blender или Krita
- Пользовательские приложения, запускающие генерацию от имени своих пользователей
- Пакетные конвейеры, например запуск одного рабочего процесса для каждого кадра видео
- Серверные сервисы, которым нужно много одновременно выполняющихся рабочих процессов

<Note>
  Эти SDK управляют ComfyUI **извне**. Если вы пишете пользовательские узлы или расширения фронтенда, которые работают **внутри** ComfyUI, вам нужна страница [Разработка пользовательских узлов](/custom-nodes/overview). Это отдельный набор API.
</Note>

## Агенты для программирования

Если агент для программирования создаёт вашу интеграцию с Comfy Router, передайте ему навык `comfy-sdk`.

Навык охватывает то, в чём агенты обычно ошибаются:

- Какой клиент использовать
- Хранение API-ключа на сервере
- Поиск модели перед её вызовом
- `run` в сравнении с `submit`
- Тайм-ауты
- Ветвление по категориям ошибок

Он не охватывает рабочие процессы ComfyUI. Для клиента рабочих процессов на этой странице укажите агенту на это руководство и [справочник по Comfy API v2](/api-reference/v2/overview).

## Быстрый старт

Загрузите входное изображение, запустите рабочий процесс и запишите результаты на диск.

<CodeGroup>
```python Python
from comfy_sdk import Comfy

# Comfy Cloud
client = Comfy(api_key="comfyui-...")

wf = client.workflows.from_file("workflow_api.json")

asset = client.assets.from_file("photo.png")
wf.set_input("10", "image", asset)

job = client.run(wf)
for output in job.get_outputs("9"):
    output.to_file(output.name)
```

```typescript TypeScript
import { Comfy } from "@comfyorg/sdk";

// Comfy Cloud
const client = new Comfy({ apiKey: "comfyui-..." });

const wf = await client.workflows.fromFile("workflow_api.json");

const asset = client.assets.fromFile("photo.png");
wf.setInput("10", "image", asset);

const job = await client.run(wf);
await job.getOutputs("9")[0].toFile("out.png");
```
</CodeGroup>

`workflow_api.json` представляет собой рабочий процесс, сохранённый в [формате API](/ru/development/api-development/workflow-api-format). Значения `"10"` и `"9"` это идентификаторы узлов из этого файла: узел, в который подаётся входное изображение, и выходной узел, результаты которого вам нужны.

Дескрипторы ассетов работают лениво. Файл `photo.png` хешируется локально и загружается, только если на сервере ещё нет этих байтов, поэтому повторный запуск с тем же входом ничего не стоит.

`run()` отправляет задачу и ждёт, пока она не перейдёт в терминальное состояние. Чтобы выполнять работу во время её выполнения, используйте `submit()` и следите за [потоком событий](#отслеживание-выполнения-задачи).

Чтобы запускать на своём собственном ComfyUI, задайте `COMFY_BASE_URL` и уберите ключ. Подробнее ниже.

## Выбор базового URL

| Вариант | Базовый URL | API-ключ |
|---|---|---|
| **Comfy Cloud** | `https://cloud.comfy.org` (по умолчанию) | Обязательно |
| **Развёртывание Comfy API** | `https://<deployment>.run.comfy.app` | Обязательно |
| **Свой ComfyUI** | `http://127.0.0.1:8189` (локальный прокси) | По умолчанию нет. Опционально статический bearer-токен |

Базовый URL берётся из переменной окружения `COMFY_BASE_URL`, а не из аргумента конструктора:

```bash
export COMFY_BASE_URL="https://<deployment>.run.comfy.app"  # Развёртывание Comfy API
export COMFY_BASE_URL="http://127.0.0.1:8189"               # локальный прокси
```

Она читается при каждом создании клиента, должна быть URL-адресом `http(s)`, а если она не задана или пуста, используется Comfy Cloud. Поэтому сам клиент везде одинаков:

<CodeGroup>
```python Python
client = Comfy(api_key="comfyui-...")
```

```typescript TypeScript
const client = new Comfy({ apiKey: "comfyui-..." });
```
</CodeGroup>

<Note>
  Обновляетесь с ранней сборки? Вызов `Comfy("<url>", "<key>")` теперь записывается как `Comfy(api_key="<key>")` с заданной `COMFY_BASE_URL`. Параметр `api_key` передаётся только по имени, поэтому старый позиционный вызов вызовет `TypeError`, а не молча примет URL за ключ.
</Note>

Работает сразу, без дополнительной настройки. Создайте [API-ключ](/ru/development/api-development/getting-an-api-key) и передайте его клиенту.

<Note>
  Доступ к API требует платной подписки Comfy Cloud. Бесплатный тариф её не включает. Сколько задач можно запускать одновременно, зависит от вашего тарифа. См. [Ограничения параллелизма](/ru/development/deploy/cloud-usage#concurrency-limits).
</Note>

### Развёртывание Comfy API

Рабочий процесс, развёрнутый через [платформу для разработчиков](https://platform.comfy.org), получает собственную конечную точку. Укажите её в `COMFY_BASE_URL` и используйте свой API-ключ, как и с Comfy Cloud. Всё в этом руководстве работает так же, кроме [меток заданий и списка заданий](#добавить-метки-к-задачам-и-найти-их-позже), которые Comfy Cloud пока не поддерживает.

Развёртывание Comfy API может выполнять несколько рабочих процессов с моделями и пользовательскими узлами, включёнными в его сборку. Для каждой задачи `get_workflow()` возвращает ответ рабочего процесса с `format: "api"` и выполненный граф в свойстве `.graph`.

### Свой ComfyUI

В самостоятельно размещённом ComfyUI API v2 предоставляется сервисом [comfy-api-proxy](https://github.com/Comfy-Org/comfy-api-proxy), небольшим open-source сервисом, который работает вместе с вашим ComfyUI. Установите его, запустите и задайте `COMFY_BASE_URL="http://127.0.0.1:8189"`:

```bash
pip install comfy-api-proxy
comfy-api-proxy
export COMFY_BASE_URL="http://127.0.0.1:8189"
```

Подробности о настройке и аутентификации см. в разделе [Прокси API для самостоятельно размещённого ComfyUI](/ru/development/comfyui-server/api-proxy).

## Повторная отправка: ключ идемпотентности

`submit()` и `run()` отправляют `Idempotency-Key` с каждой отправкой, и контракт Comfy API v2 для этого ключа таков: **отклонение при дублировании, а не запись и воспроизведение**. Прочитайте это прежде, чем обернёте отправку в цикл повторов.

- **Каждый вызов создаёт новый ключ.** Два вызова `submit()` с одним и тем же рабочим процессом это две отправки, две задачи и две оплаты. Наивный `for attempt in range(3)` вокруг `submit()` даст двойное списание, а не повтор.
- **Повторно использованный ключ отклоняется, а не воспроизводится.** Передайте собственный `idempotency_key` (`idempotencyKey` в TypeScript), чтобы сделать повтор идемпотентным: тогда второй запрос с этим ключом завершится с `422 idempotency_key_reuse` вместо возврата первой задачи. SDK выбрасывают `IdempotencyKeyReuse`. Это противоположно тому, что обычно понимают под «идемпотентным повтором», поэтому обрабатывайте это явно.
- **Восстановление означает найти задачу, а не отправить заново.** При `IdempotencyKeyReuse` первая попытка вполне могла создать задачу. Получите её через `client.jobs.get(job_id)`. Этому поиску нужен ID, который вы уже сохранили, поэтому он восстанавливает только тот случай, когда отправка вернула результат и вы сохранили ID до сбоя. Если соединение оборвалось до записи ID, искать нечего и автоматического восстановления нет: примеры ниже пробрасывают исключение дальше для ручной обработки, а не отправляют повторно под занятым ключом.
- **Ключ освобождается, когда отправка окончательно завершилась ошибкой.** Ошибка валидации, отказ из-за нехватки кредитов или отказ из-за переполненной очереди не создают задачу и освобождают ключ, поэтому повторная отправка под ним допустима. После *неоднозначной* ошибки (тайм-аут чтения, обрыв соединения посреди запроса) ключ остаётся занятым: ищите задачу, а не отправляйте заново.
- **Ключи истекают через 24 часа**, должны быть непустыми, состоять из печатных символов ASCII и укладываться в ограничение длины. Неверный ключ вызывает `ValueError` ещё до выполнения запроса, поэтому явный `""` никогда не подменяется автоматически созданным ключом.

Значит, повтор, который безопасно выполнять больше одного раза, должен переносить между попытками две вещи: ключ, чтобы сервер отличал повтор от новой отправки, и ID задачи, чтобы можно было найти задачу, уже созданную занятым ключом.

<CodeGroup>
```python Python
import uuid
from comfy_sdk import IdempotencyKeyReuse

# Оба значения должны храниться в вашем собственном хранилище с ключом,
# соответствующим смыслу запроса. `key` создаётся один раз, при первой попытке;
# `job_id` заполняется сразу после того, как отправка вернула результат.
state = load_submission_state()  # {"key": ..., "job_id": ...} or {}
key = state.get("key") or str(uuid.uuid4())
save_submission_state(key=key)

try:
    job = client.submit(wf, idempotency_key=key)
    save_submission_state(key=key, job_id=job.id)
except IdempotencyKeyReuse:
    # Более ранняя попытка с этим ключом уже дошла до отправки, поэтому задача
    # могла быть создана. Не отправляйте повторно: найдите её.
    job_id = state.get("job_id")
    if job_id is None:
        raise  # ничего не записано, искать нечего; нужен человек
    job = client.jobs.get(job_id)
```

```typescript TypeScript
import { IdempotencyKeyReuse } from "@comfyorg/sdk";

// Оба значения должны храниться в вашем собственном хранилище с ключом,
// соответствующим смыслу запроса. `key` создаётся один раз, при первой попытке;
// `jobId` заполняется сразу после того, как отправка вернула результат.
const state = await loadSubmissionState(); // { key?, jobId? }
const key = state.key ?? crypto.randomUUID();
await saveSubmissionState({ key });

let job;
try {
  job = await client.submit(wf, { idempotencyKey: key });
  await saveSubmissionState({ key, jobId: job.id });
} catch (err) {
  // Более ранняя попытка с этим ключом уже дошла до отправки, поэтому задача
  // могла быть создана. Не отправляйте повторно: найдите её.
  if (!(err instanceof IdempotencyKeyReuse) || !state.jobId) throw err;
  job = await client.jobs.get(state.jobId);
}
```
</CodeGroup>

`client.jobs.get(job_id)` это путь восстановления в SDK, и ему нужен ID. Именно поэтому запись ID в момент, когда отправка возвращает результат, и делает восстановление вообще возможным. Полный контракт ключа для `POST /api/v2/jobs` см. в [Comfy API v2](/api-reference/v2/overview).

<Note>
  `Idempotency-Key` в Comfy Router ведёт себя **иначе**. В Router ключ это дескриптор воспроизведения, а не одноразовый токен: повторная отправка уже поставленного в очередь запроса под тем же ключом возвращает оригинальный запрос вместо постановки в очередь второго. См. [идемпотентность в очереди и выставление счетов](/ru/development/comfy-router/queue#idempotency-and-billing) и [результаты повторов в Router](/ru/development/comfy-router/errors#результаты-повторных-попыток). Эти две поверхности разделяют только имя заголовка, но не контракт.
</Note>

## Отслеживание выполнения задачи

`job.events()` даёт вам живой поток состояния задачи: прогресс узлов и шагов, кадры предпросмотра и каждый выходной файл в момент его фиксации. При обрыве соединения поток переподключается автоматически.

<CodeGroup>
```python Python
from comfy_sdk import Progress, Preview, OutputReady, StatusChange

job = client.submit(wf)

for event in job.events():
    match event:
        case Progress() as p:
            print(f"{p.value:.0%} {p.message}")
        case Preview() as pv:
            image = pv.to_pil()
        case OutputReady() as o:
            o.output.to_file(f"partial/{o.output.name}")
        case StatusChange(status="succeeded"):
            break

result = job.result()
```

```typescript TypeScript
const job = await client.submit(wf);

// Метка обязательна: одиночный `break` внутри switch выходит из switch,
// а не из цикла.
eventLoop: for await (const event of job.events()) {
  switch (event.kind) {
    case "progress":
      console.log(event.value);
      break;
    case "outputReady":
      await event.output.toFile(`${event.output.name}`);
      break;
    case "statusChange":
      if (event.status === "succeeded") break eventLoop;
  }
}
```
</CodeGroup>

Для `Preview.to_pil()` требуется необязательное дополнение Pillow: `pip install "comfy-sdk[pil]"`.

`result()` возвращает завершённую задачу или вызывает `JobFailed` с подробностями на уровне узла, если выполнение завершилось ошибкой. Полный каталог событий см. в [SDK README](#справочник) для вашего языка.

### `events()` — это не `subscribe()`

На двух поверхностях существуют три похожих по названию вещи, и только одна из них есть на этой странице:

| Вызов | Поверхность | Что возвращает |
|---|---|---|
| `job.events()` | Comfy Cloud (эта страница) | Живой поток SSE для одной задачи рабочего процесса: `Progress`, `Preview`, `OutputReady`, `StatusChange`. Переподключается автоматически, при сбое переходит на опрос. |
| `handle.events()` (TypeScript) / `handle.iter_events()` (Python) | [Доставка через очередь Comfy Router](/ru/development/comfy-router/queue) | Наблюдения очереди для одного запроса Router: статус и позиция в очереди. Опрашивает маршрут статуса; потока нет, событий прогресса и предпросмотра тоже нет. |
| `comfy.models.subscribe(...)` | [Доставка через очередь Comfy Router](/ru/development/comfy-router/queue) | Не итератор. Отправляет, опрашивает и собирает результат одним вызовом с колбэком `on_queue_update` / `onQueueUpdate`, возвращая результат. |

На клиенте Comfy Cloud нет `subscribe()`, и `job.subscribe()` не существует нигде. Аналог `subscribe` в Cloud — это `run()`: отправить и дождаться терминального состояния.

Поток — это живая лента, а не журнал для воспроизведения. Он нужен, чтобы вы могли отображать прогресс, а не чтобы полагаться на него в получении результатов. Авторитетным является опрос задачи, а `run()`, `wait()` и `result()` автоматически переходят на опрос. Почему так, см. в разделе [Заметки о дизайне](/ru/development/api-development/sdks-design#сначала-опрос-поток-для-прогресса).

## Категории ошибок

Когда задача завершается ошибкой, `error.category` одним словом сообщает причину, чтобы ваш код мог выбрать дальнейшие действия без разбора `error.message`. Поле присутствует только у задач в [развёртывании Comfy API](#развёртывание-comfy-api). Comfy Cloud его не задаёт.

| Категория | Что произошло |
|---|---|
| `invalid_input` | Значение входа или файл отклонены либо превышен лимит. |
| `content_refused` | Модерация узла партнёра отклонила содержимое. |
| `out_of_gpu_memory` | Недостаточно памяти GPU. |
| `missing_model_or_node` | Рабочему процессу нужен файл модели, класс узла или пакет Python, которых нет в развёртывании. |
| `workflow_logic` | Ошибка в самом рабочем процессе: несовпадение типа, связи или формы, отсутствие выходного узла или цикл зависимостей. |
| `other` | Ничего из перечисленного. Сбой провайдера или тайм-аут сам по себе тоже попадает сюда. |

Категория присваивается задаче, только если сбой вызван её рабочим процессом или её входами.

**Поле находится в объекте `error` задачи** в ответах на submit, get и cancel. В списке задач его нет: элементы списка содержат только сообщение об ошибке и подробности, поэтому читайте задачу по её id. После статуса `failed` в потоке событий также читайте задачу по её id.

**Поле отсутствует, когда:**

- Задача не завершилась ошибкой.
- Сбой вызван платформой или его не удалось связать с вашим рабочим процессом или входами.
- Задача завершилась ошибкой до появления категорий.
- Содержимое задач аккаунта было очищено.
- Задача выполнялась в Comfy Cloud.

**Считайте неизвестное значение равным `other`.** Набор категорий может расширяться в пределах v2. Отсутствие категории означает, что у задачи её нет, и это тоже можно обрабатывать как `other`.

**Категория описывает отчёт о сбое, сохранённый вместе с задачей.** Повторное чтение задачи никогда не классифицирует её заново, а категория является приблизительной меткой, а не гарантией точности. Используйте её, чтобы выбрать следующий шаг, например попросить пользователя исправить вход.

Текущий выпуск SDK пока не предоставляет это поле. Python SDK отбрасывает его из `JobFailed.error`, поэтому читайте задачу по HTTP. TypeScript SDK передаёт его во время выполнения, но не типизирует, поэтому приведите тип ошибки:

<CodeGroup>
```python Python
import os
import httpx
from comfy_sdk import JobFailed

KNOWN_CATEGORIES = {
    "invalid_input",
    "content_refused",
    "out_of_gpu_memory",
    "missing_model_or_node",
    "workflow_logic",
    "other",
}

api_key = "comfyui-..."  # тот же ключ, который вы передаёте в Comfy(api_key=...)
base_url = os.environ.get("COMFY_BASE_URL") or "https://cloud.comfy.org"  # не задано или пусто означает Comfy Cloud, как и для клиента

job = client.submit(wf)
try:
    job.result()
except JobFailed:
    response = httpx.get(
        f"{base_url}/api/v2/jobs/{job.id}",
        headers={"Authorization": f"Bearer {api_key}"},
    )
    response.raise_for_status()
    category = (response.json().get("error") or {}).get("category")
    if category not in KNOWN_CATEGORIES:
        category = "other"  # отсутствует или неизвестно
```

```typescript TypeScript
import { JobFailed } from "@comfyorg/sdk";

const KNOWN_CATEGORIES = new Set([
  "invalid_input",
  "content_refused",
  "out_of_gpu_memory",
  "missing_model_or_node",
  "workflow_logic",
  "other",
]);

try {
  await client.run(wf);
} catch (err) {
  if (!(err instanceof JobFailed)) throw err;
  const raw = (err.error as { category?: string } | null)?.category;
  const category =
    raw !== undefined && KNOWN_CATEGORIES.has(raw) ? raw : "other"; // отсутствует или неизвестно
}
```
</CodeGroup>

## Отследить выход до его рабочего процесса

Выходы содержат идентификатор задачи, создавшей их, поэтому можно начать с файла и пойти в обратном направлении, не ведя вспомогательную таблицу.

<CodeGroup>
```python Python
output = job.outputs[0]
output.job_id          # задача, создавшая этот файл
```

```typescript TypeScript
const output = job.outputs[0];
output.jobId; // задача, создавшая этот файл
```
</CodeGroup>

Тот же идентификатор есть у ресурса, полученного отдельно, поэтому файл, найденный позже, всё равно приведёт к своей задаче. Для ресурса, который вы загрузили, он равен `None` (в TypeScript: `undefined`), поскольку у такого ресурса нет создавшей его задачи.

У задачи можно запросить рабочий процесс, лежащий в её основе. Это работает и для задачи, которую вы не отправляли в этом процессе, а восстановили по id:

<CodeGroup>
```python Python
wf = job.get_workflow()

if wf.format == "save":
    ...  # рабочий процесс в авторском виде, раскладка холста и узлы Note не тронуты
else:
    ...  # исполненный граф в формате API
```

```typescript TypeScript
const wf = await job.getWorkflow();

if (wf.format === "save") {
  // рабочий процесс в авторском виде, раскладка холста и узлы Note не тронуты
} else {
  // исполненный граф в формате API
}
```
</CodeGroup>

**Всегда проверяйте `format`.** Какая форма вернётся, зависит от того, как задача была отправлена, а не от чего-либо, что вы задаёте в отдельном запросе:

| `format` | Что вы получите | Когда |
|---|---|---|
| `save` | Рабочий процесс в авторском виде на той версии, на которой выполнялась задача, с раскладкой холста и узлами только для редактора, например Note | Задачи, отправленные из редактора Comfy Cloud, который привязывает версию рабочего процесса |
| `api` | Исполненный граф. Конструкции только для редактора удалены, а узлы Get/Set развёрнуты | Всё остальное, включая все задачи, отправленные через эти SDK на сегодня |

Задачи, отправленные через SDK, всегда возвращают `api`, потому что в отправке v2 пока нет полей для привязки версии. Это изменится; дискриминатор нужен, чтобы вашему коду не пришлось об этом беспокоиться.

## Добавить метки к задачам и найти их позже

Метка состоит из ключа и значения, которые вы прикрепляете к задаче при отправке, например `client: acme` или `project: spring`. Используйте метки, чтобы отмечать, для какого из ваших клиентов или проектов выполнялась задача. Затем вы можете вывести список задач для одного клиента, не храня собственную таблицу идентификаторов задач. Для меток и списка задач нужна текущая версия SDK, указанная в примечании о версии в разделе [Установить](#установить).

Метки работают для задач, отправленных в [развертывание Comfy API](#развёртывание-comfy-api), поэтому укажите в `COMFY_BASE_URL` адрес развертывания, как показано в разделе [Выбор базового URL](#выбор-базового-url). Comfy Cloud пока отклоняет их и на запрос списка задач отвечает `501` с кодом `not_implemented`. Самостоятельно размещенный [comfy-api-proxy](#свой-comfyui) тоже не сохраняет их: его собственное поле `metadata` представляет собой одну текстовую строку, поэтому он отклоняет набор меток. Его список задач игнорирует фильтры по меткам, поэтому вызов списка через SDK с метками не вернет ни одной задачи, а те же фильтры по HTTP вернут все задачи.

Ограничения:

- До 16 меток на задачу.
- Ключ: от 1 до 40 символов, буквы, цифры, `_`, `-` и `.`.
- Значение: строка длиной до 256 байт (UTF-8).
- Метки задаются при отправке задачи и не могут быть изменены позже.

Отправка, нарушающая ограничение, завершается ошибкой `422` с кодом `metadata_invalid`, и задача не создается. Сообщение об ошибке указывает ключ, нарушивший правило, или сообщает количество, если меток больше 16. SDK не проверяют ограничения самостоятельно. Они вызывают ошибку, содержащую код и сообщение сервера.

<Warning>
  Любой участник вашего рабочего пространства, который видит задачу, видит и ее метки. Не помещайте в них секреты или личные данные.
</Warning>

Передайте `metadata` при отправке. При последующем чтении задача будет содержать метки:

<CodeGroup>
```python Python
job = client.submit(wf, metadata={"client": "acme", "project": "spring"})
job.metadata  # {"client": "acme", "project": "spring"}
```

```typescript TypeScript
const job = await client.submit(wf, {
  metadata: { client: "acme", project: "spring" },
});
job.metadata; // { client: "acme", project: "spring" }
```
</CodeGroup>

У задачи, отправленной без меток, `metadata` пустое.

Чтобы найти задачи для одного клиента, выведите список задач с фильтрацией по меткам. Список охватывает только задачи, отправленные в развертывание по адресу вашего базового URL. Сначала возвращаются самые новые результаты, а SDK загружает следующую страницу по мере перебора:

<CodeGroup>
```python Python
for job in client.list_jobs(metadata={"client": "acme"}):
    print(job.id, job.status)
```

```typescript TypeScript
for await (const job of client.listJobs({ metadata: { client: "acme" } })) {
  console.log(job.id, job.status);
}
```
</CodeGroup>

Можно фильтровать не более чем по 3 меткам одновременно, при этом задача должна точно совпадать по всем указанным меткам. Элементы списка не содержат выходов. Чтобы получить выходы задачи, прочитайте задачу по ее идентификатору с помощью `client.jobs.get(job.id)`.

### По HTTP

Передайте `metadata` в теле запроса `POST /api/v2/jobs`:

```bash
curl -X POST "https://<deployment>.run.comfy.app/api/v2/jobs" \
  -H "Authorization: Bearer $COMFY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "workflow": { ... },
    "metadata": { "client": "acme", "project": "spring" }
  }'
```

Фильтруйте `GET /api/v2/jobs` с помощью одного параметра запроса `metadata[<key>]=<value>` для каждой метки. Флаг `-g` не дает curl воспринимать квадратные скобки как шаблон:

```bash
curl -g "https://<deployment>.run.comfy.app/api/v2/jobs?metadata[client]=acme" \
  -H "Authorization: Bearer $COMFY_API_KEY"
```

Ответ содержит страницу задач и, если существуют дополнительные страницы, поле `next_cursor`. Передайте его обратно как `cursor` вместе с теми же фильтрами `metadata[...]`, чтобы получить следующую страницу. Курсор, отправленный без своих фильтров, возвращает задачи без фильтрации. Используйте `limit`, чтобы задать размер страницы (не более 500).

```json
{
  "jobs": [
    {
      "id": "6f1c2b9e-...",
      "status": "succeeded",
      "metadata": { "client": "acme", "project": "spring" }
    }
  ],
  "next_cursor": "eyJ..."
}
```

Если указано более 3 фильтров по меткам или ключ нарушает правило ключа, запрос завершается ошибкой `400` с кодом `invalid_metadata_filter`. См. [справочник Comfy API v2](/api-reference/v2/overview), где описаны все поля задачи и списка.

## Что SDK покрывают сегодня

Первая версия хорошо делает одну вещь: запускает рабочий процесс и возвращает результаты.

- **Ассеты.** Создавайте входные handle из файла, байтов, потока или URL. Handle ленивые и адресуются по содержимому, поэтому при повторном запуске с тем же входом он не загружается заново.
- **Отправка.** Отправьте граф в формате API. Отправка идемпотентна, а при заполненной очереди повтор выполняется автоматически в пределах заданного бюджета попыток.
- **Выполнение.** Опрашивайте через `wait()` или следите за `events()` для отслеживания прогресса в реальном времени.
- **Выходы.** Записывайте на диск, буферизуйте в память, получайте диапазон байтов или короткоживущий URL для скачивания. `getDownloadUrl()` возвращает подписанный URL, который может прочитать любой человек без API-ключа, срок действия примерно 6 часов. Прочитайте раздел [URL выходов и срок их действия](/api-reference/v2/overview#output-urls-and-how-long-they-last), прежде чем сохранять такой URL: чтобы показать выход позже, разместите байты заново или перевыпустите URL по запросу.
- **Прослеживаемость.** Каждый выход несёт id задачи, которая его создала, а задача может вернуть рабочий процесс, лежащий в её основе.
- **Удаление ассетов.** Удалите загруженный ассет по handle или по id.
- **Ошибки.** Типизированные исключения, такие как `JobFailed`, `Unauthorized`, `InsufficientCredits` и `QueueFull`, вместо необработанных кодов статуса.
- **Отмена.** Задачи можно отменить во время выполнения. TypeScript дополнительно принимает `AbortSignal` в любом вызове.

Python предоставляет как синхронный клиент `Comfy`, так и клиент `AsyncComfy` с одинаковым набором методов. TypeScript доступен только в асинхронном варианте.

Чего нет в этой версии: управления сохранёнными рабочими процессами, библиотеки моделей, интроспекции узлов и именованных параметров рабочих процессов. Раздел [Заметки о проектировании](/ru/development/api-development/sdks-design#объём-первой-версии) объясняет, почему набор функций начинается с такого малого.
