После того как ComfyUI [развернут](/ru/development/deploy/overview), ваше приложение запускает на нем рабочие процессы: отправляет рабочий процесс, ожидает выполнения и скачивает выходы. На этой странице описано, какой клиент использовать для каждого варианта развертывания.

## Начните здесь: Comfy SDKs

Для новой интеграции используйте официальные **Comfy SDKs** (Python и TypeScript) и [Comfy API v2](/api-reference/v2/overview), к которому они обращаются. Один и тот же код работает с каждой целью развёртывания; меняется только базовый URL.

## Что с чем работает

| Развёртывание | Comfy SDKs / API v2 | Примечания |
|---|---|---|
| **Развёртывание Comfy API** | Да | Укажите в `COMFY_BASE_URL` адрес `https://<deployment>.run.comfy.app` и передайте свой API-ключ |
| **Comfy Cloud** | Да | Базовый URL по умолчанию. Требует API-ключ и платную подписку |
| **Собственный хостинг** | Да, через [API Proxy](/ru/development/comfyui-server/api-proxy) | Небольшой сервис рядом с ComfyUI предоставляет API v2 |

Инстансы на собственном хостинге могут также вовсе обойтись без SDK и использовать напрямую [ComfyUI Server API](/ru/development/comfyui-server/comms_overview) (REST + WebSocket). Он открывает весь локальный функционал, включая очередь и информацию о нодах, но совместимость между релизами не гарантируется.

## Какой API использовать?

| | Comfy API v2 + SDK | v1 Cloud API | ComfyUI Server API |
|---|---|---|---|
| **Где работает** | Развёртывания Comfy API, Comfy Cloud или собственный сервер через API Proxy | Только Comfy Cloud | Только при самостоятельном размещении |
| **Совместимость** | Версионирование, в пределах v2 только добавляющие изменения | Устаревший, может меняться без предупреждения | Гарантий совместимости между релизами нет |
| **Аутентификация** | `Authorization: Bearer` в Comfy Cloud и развёртываниях Comfy API. Самостоятельное размещение: по умолчанию без аутентификации, опционально статический bearer-токен | Заголовок `X-API-Key` (аккаунт Comfy Cloud) | Нет (локально) или API-ключ для Партнёрских узлов |
| **Официальные клиенты** | SDK для Python и TypeScript | Нет, вызовы по HTTP | Нет, вызовы по HTTP |
| **Протокол** | REST + SSE | REST + WebSocket | REST + WebSocket |
| **Область применения** | Запуск рабочего процесса и получение результатов | Полный функционал Cloud, включая модели и аккаунт | Полный локальный функционал, включая очередь и информацию об узлах |
| **Лучше всего подходит для** | Новых интеграций, которые должны продолжать работать | Существующих интеграций и функций Cloud, которые v2 пока не покрывает | Полного контроля и собственных инструментов для своего экземпляра |

Все они принимают один и тот же формат рабочего процесса ([формат API](/ru/development/api-development/workflow-api-format)), поэтому вы можете разрабатывать и тестировать рабочие процессы локально и без изменений переносить их в другое развёртывание.

## Предварительные требования

- [API-ключ](/ru/development/api-development/getting-an-api-key) для всего, что связано с Comfy Cloud, развёртыванием Comfy API или партнёрскими узлами. Чисто локальному ComfyUI он не нужен.
- Рабочий процесс, экспортированный в [формате API](/ru/development/api-development/workflow-api-format).
