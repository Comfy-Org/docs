## LiteGraph

ComfyUI построен на основе [LiteGraph](https://github.com/jagenjo/litegraph.js). 
Большая часть функциональности ComfyUI обеспечивается LiteGraph, поэтому при разработке более сложных
узлов вам, вероятно, будет полезно клонировать этот репозиторий и просмотреть документацию,
которую можно найти в `doc/index.html`.

## ComfyApp

Объект `app` (всегда доступный через `import { app } from "../../scripts/app.js";`) представляет приложение Comfy, работающее в браузере, и содержит ряд полезных свойств и функций, некоторые из которых перечислены ниже.

<Note>
**Устарело:** перехват и monkey-patching функций объекта `app` или прототипов считается устаревшим и может измениться в любой момент в ближайшем будущем. Используйте вместо этого официальные [хуки расширений](/ru/custom-nodes/js/javascript_hooks) и [API контекстного меню](/ru/custom-nodes/js/context-menu-migration).
</Note>

<Warning>Перехватывать функции `app` не рекомендуется, так как Comfy постоянно развивается и поведение ядра может измениться.</Warning>

### Свойства

К важным свойствам `app` относятся (список не исчерпывающий):

| свойство        | содержимое                                                                                                                                                        |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `canvas`        | Объект LGraphCanvas, представляющий текущий пользовательский интерфейс. Содержит некоторые потенциально интересные свойства, например `node_over` и `selected_nodes`. |
| `canvasEl`      | DOM-элемент `<canvas>`                                                                                                                                      |
| `graph`         | Ссылка на объект LGraph, описывающий текущий граф                                                                                                   |
| `runningNodeId` | Во время выполнения: узел, который выполняется в данный момент                                                                                                             |
| `ui`            | Даёт доступ к некоторым элементам интерфейса, таким как очередь, меню и диалоги                                                                                       |

Скорее всего, чаще всего вам понадобятся `canvas` (для графических элементов) и `graph` (для логических соединений).

### Функции

Их тоже много. Несколько важных:

| функция          | примечания                                                                 |
| ----------------- | --------------------------------------------------------------------- |
| graphToPrompt     | Преобразует граф в промпт, который можно отправить на сервер Python |
| loadGraphData     | Загружает граф                                                          |
| queuePrompt       | Отправляет промпт в очередь                                          |
| registerExtension | Вы уже видели эту функцию: она используется для добавления расширения                       |

## LGraph

Объект `LGraph` является частью фреймворка LiteGraph и представляет текущее логическое состояние графа (узлы и связи). 
Если вы хотите манипулировать графом, документация LiteGraph (в `doc/index.html`, если вы клонируете `https://github.com/jagenjo/litegraph.js`) 
описывает функции, которые вам понадобятся.

Вы можете использовать `graph`, чтобы получить сведения об узлах и связях, например:

```Javascript
const ComfyNode_object_for_my_node = app.graph._nodes_by_id(my_node_id) 
ComfyNode_object_for_my_node.inputs.forEach(input => {
    const link_id = input.link;
    if (link_id) {
        const LLink_object = app.graph.links[link_id]
        const id_of_upstream_node = LLink_object.origin_id
        // etc
    }
});
```

## LLink

Объект `LLink`, доступный через `graph.links`, представляет собой отдельную связь в графе: от выходного слота `link.origin_slot` узла `link.origin_id` к слоту `link.target_slot` узла `link.target_id`. У него также есть строка, представляющая тип данных, в `link.type`, и `link.id`.

Объекты `LLink` создаются в методе `connect` объекта `LGraphNode` (`ComfyNode` является его подклассом).

<Tip>Не создавайте собственные объекты LLink, вместо этого используйте функции LiteGraph.</Tip>

## ComfyNode

`ComfyNode` является подклассом `LGraphNode`, поэтому документация LiteGraph полезна для более общих операций. Однако Comfy значительно расширил поведение ядра LiteGraph, а также не использует всю функциональность LiteGraph.

<Tip>Описанное ниже относится к обычному узлу. Групповые узлы, примитивные узлы, заметки и перенаправляющие узлы имеют другие свойства.</Tip>

Объект `ComfyNode` представляет узел в текущем рабочем процессе. У него есть ряд важных свойств, которые вы, возможно, захотите использовать, и очень большое число функций, которые можно использовать или перехватить, чтобы изменить поведение.

<Note>
**Устарело:** перехват методов прототипа `ComfyNode` или `LGraphNode` устарел и может измениться в любой момент в ближайшем будущем. Используйте официальные [хуки расширений](/ru/custom-nodes/js/javascript_hooks), где они доступны, например `getNodeMenuItems` для контекстных меню. Примеры см. в [руководстве по миграции контекстных меню](/ru/custom-nodes/js/context-menu-migration).
</Note> 

Чтобы лучше понять объект узла, полезно вставить следующий код в ваше расширение и поставить точку останова на команду `console.log`. Затем при создании нового узла вы можете использовать свой любимый отладчик, чтобы исследовать узел.

```Javascript
async nodeCreated(node) {
    console.log("nodeCreated")
}
```

## Входы и виджеты

Входы и виджеты представляют собой два способа передачи данных в узел. Как правило, виджет можно преобразовать во вход, но не все входы можно преобразовать в виджет (так как многие типы данных нельзя ввести через элемент интерфейса).

`node.inputs` представляет собой список текущих входов (цветные точки в левой части узла) с указанием их `.name`, `.type` и `.link` (ссылка на подключённый `LLink` в `app.graph.links`).

Если вход является преобразованным виджетом, он также хранит ссылку на теперь неактивный виджет в `.widget`.

`node.widgets` представляет собой список всех виджетов, независимо от того, были ли они преобразованы во вход. Виджет имеет:

| Свойство/функция | Примечания                                                                 |
| ----------------- | ------------------------------------------------------------------------- |
| `callback`        | Функция, вызываемая при изменении значения виджета                        |
| `last_y`          | Вертикальное положение виджета в узле                                     |
| `name`            | Имя виджета (уникальное в пределах узла)                                  |
| `options`         | Как указано в коде Python (например, default, min и max)                  |
| `type`            | Имя типа виджета (см. ниже) в нижнем регистре                             |
| `value`           | Текущее значение виджета. Это свойство с методами `get` и `set`            |

### Типы виджетов

`app.widgets` представляет собой словарь зарегистрированных в данный момент типов виджетов, ключами в котором служит имя типа в ВЕРХНЕМ РЕГИСТРЕ. 
Встроенные типы виджетов Comfy включают очевидные `BOOLEAN`, `INT` и `FLOAT`, 
а также `STRING` (в двух вариантах: однострочный и многострочный),
`COMBO` для выбора из раскрывающегося списка и `IMAGEUPLOAD`, используемый в узлах `Load Image`.

Пользовательские типы виджетов можно добавить, реализовав метод `getCustomWidgets` в вашем расширении.

## Промпт

Когда вы нажимаете кнопку `Queue Prompt` в Comfy, вызывается метод `app.graphToPrompt()`, который преобразует
текущий граф в промпт, который можно отправить на сервер.

`app.graphToPrompt` возвращает объект (далее именуемый `prompt`) с двумя свойствами: `output` и `workflow`.

### Выход

`prompt.output` сопоставляет `node_id` каждого узла графа с объектом, имеющим два свойства.

- `prompt.output[node_id].class_type` — уникальное имя класса пользовательского узла, как оно определено в коде Python
- `prompt.output[node_id].inputs` — содержит значение каждого входа (или виджета) как отображение имени входа на:
    - выбранное значение, если это виджет, или
    - массив, содержащий (`upstream_node_id`, `upstream_node_output_slot`), если к входу подключена связь, или
    - undefined, если это виджет, преобразованный во вход и не подключённый
    - другие неподключённые входы не включаются в `.inputs`

<Tip>Обратите внимание, что `upstream_node_id` в массиве, описывающем подключённый вход, представлен как строка, а не как целое число.</Tip>

### Рабочий процесс

`prompt.workflow` содержит следующие свойства:

- `config` — словарь дополнительных параметров конфигурации (по умолчанию пуст)
- `extra` — словарь, содержащий дополнительную информацию о рабочем процессе. По умолчанию он содержит:
    - `extra.ds` — описывает текущий вид графа (`scale` и `offset`)
- `groups` — все группы в рабочем процессе
- `last_link_id` — идентификатор последней добавленной связи
- `last_node_id` — идентификатор последнего добавленного узла
- `links` — список всех связей в графе. Каждый элемент — массив из пяти целых чисел и одной строки:
    - (`link_id`, `upstream_node_id`, `upstream_node_output_slot`, `downstream_node_id`, `downstream_node_input_slot`, `data type`)
- `nodes` — список всех узлов в графе. Каждый элемент — отображение подмножества свойств узла, описанных [выше](#comfynode)
    - Включены следующие свойства: `flags`, `id`, `inputs`, `mode`, `order`, `pos`, `properties`, `size`, `type`, `widgets_values`
    - Кроме того, если у узла есть выходы, присутствует свойство `outputs` — список выходов узла, каждый из которых содержит:
        - `name` — имя выхода
        - `type` — тип данных выхода
        - `links` — список `link_id` всех связей от этого выхода (если связей нет, может быть пустым списком или null)
        - `shape` — форма, используемая для отрисовки выхода (по умолчанию 3 для точки)
        - `slot_index` — номер слота выхода
- `version` — номер версии LiteGraph (на момент написания — `0.4`)

<Tip>`nodes.output` отсутствует у узлов без выходов, а не является пустым списком.</Tip>
