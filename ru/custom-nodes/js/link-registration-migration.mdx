`LinkNetwork.addFloatingLink(link)` теперь возвращает `LLink | undefined`.

Для новой runtime-ссылки передайте неназначенный id ссылки и используйте возвращённую ссылку:

```ts
const registeredLink = graph.addFloatingLink(link)
if (!registeredLink) return
```

Регистрация возвращает сохранённую ссылку при успехе или когда та же ссылка
уже присутствует в хранилище топологии. Если другая runtime-ссылка уже владеет
id, регистрация записывает ошибку в журнал, оставляет входящую ссылку
отсоединённой и возвращает `undefined`. Она не заменяет живую ссылку молча и не
назначает входящей ссылке другую идентичность. `graph.floatingLinks` остаётся
отфильтрованным представлением совместимости для ссылок с одним концом.

`graph.links` и `graph.floatingLinks` являются отфильтрованными по владельцу
представлениями совместимости на основе хранилища, а не независимым нативным
хранилищем `Map`. Их обычные методы чтения `Map` используют кэшированный
снимок состава; после изменения состава топологии получайте новый итератор
вместо сохранения существующего итератора. Оба представления требуют активного
Pinia и больше не представляют отсутствующее хранилище как пустой граф.

Как и нативный `Map.set()`, `view.set(id, link)` возвращает представление, а не
результат регистрации. Регистрация может отклонить коллизию ID или целевого
объекта, сохраняя текущую ссылку, поэтому расширения, которые вставляют через
представление, должны подтверждать успех с помощью `view.get(link.id) === link`.
После коллизии ID со ссылкой в том же представлении `has()` возвращает `true`,
а `get()` возвращает текущую ссылку. Предпочитайте API подключения графа и
плавающих ссылок, когда они покрывают операцию, поскольку эти API согласуют
окружающий жизненный цикл. Не вызывайте методы `Map.prototype` напрямую для
любого из представлений и не полагайтесь на внутреннее хранилище нативного
`Map`.

Замена входа фиксирует новую ссылку до обратных вызовов отключения старой
ссылки, поэтому запросы в обратных вызовах видят замену, а не пустой вход.
Затем следуют обычные обратные вызовы подключения.

Расширения, которые ранее игнорировали возвращаемое значение, должны
обрабатывать `undefined` до сохранения, отрисовки или изменения входящей ссылки.
Не выбирайте заранее положительный id ссылки для новой runtime-ссылки;
позвольте графу создать его.

Исправление коллизий сохраняемых id относится к импорту и десериализации
рабочего процесса. Расширения, импортирующие сериализованную топологию, должны
нормализовать конфликтующие id на этой границе перед использованием API
регистрации времени выполнения.

Создание корневого `LGraph` или его настройка из сериализованных данных требует
активного Pinia, поскольку топология графа на протяжении всего её жизненного
цикла хранится в хранилище.
