Значения виджетов теперь хранятся в хранилище на основе Pinia, а не непосредственно в экземпляре виджета. Имена виджетов должны быть уникальными в пределах узла, а переименование виджета проходит успешно, только если новое имя свободно. Кроме того, `node.widgets` может быть `undefined`, пока свойство не будет впервые задано.

## Значения галереи после замены PrimeVue

Виджет Vue `galleria` принимает массив строк с URL изображений, соответствующий схеме входа `GALLERIA`. При наличии нескольких изображений отображаются миниатюры и кнопки перехода «Назад» и «Вперёд». Навигация останавливается на первом и последнем изображении.

Объекты изображений PrimeVue с `itemImageSrc` или `thumbnailImageSrc` больше не поддерживаются. Преобразуйте их в строки URL. Виджет больше не читает параметры PrimeVue, такие как `showThumbnails`, `showItemNavigators`, `circular`, `autoPlay`, `transitionInterval`, `showIndicators`, `numVisible` или `responsiveOptions`. Расширения, которым нужны эти элементы управления, должны предоставить собственный виджет галереи.

## Имена виджетов должны быть уникальными и стабильными

Два виджета на одном узле не могут иметь одинаковое имя. Если вы добавите второй виджет с уже используемым именем, фронтенд переименует новый виджет, добавив числовой суффикс, например `strength#1`, когда узел находится в графе. Поиск по исходному имени находит только первый виджет:

```js
node.addWidget('number', 'strength', 0, () => {})
const second = node.addWidget('number', 'strength', 1, () => {})
second.name // 'strength#1', когда узел находится в графе
```

Дайте каждому виджету уникальное имя.

Присвоение нового `widget.name` зарегистрированному виджету переносит сохранённое значение на новое имя. Если другой виджет на узле уже использует это имя, присваивание игнорируется, и `widget.name` сохраняет старое значение, поэтому после этого проверьте `widget.name`. Слоты входов, которые ссылаются на виджет по имени, не обновляются. Не удаляйте виджет и не добавляйте новый, чтобы переименовать его: `removeWidget()` удаляет сохранённое значение и очищает слоты входов, привязанные напрямую к виджету. Слоты входов, которые ссылаются на него только по имени, сохраняют это имя.

## `node.widgets` может быть undefined

`node.widgets` возвращает `undefined`, пока ему не будет присвоено значение хотя бы один раз.
Инициализируйте массив перед добавлением виджетов:

```ts
export function nodeCreated(node: LGraphNode) {
  node.widgets ??= []
  node.widgets.push(myWidget)
}
```

Проверяйте чтение так же:

```ts
const widgetCount = node.widgets?.length ?? 0
```

**Присвоение `node.widgets = undefined` очищает его.** Последующее чтение снова возвращает
`undefined`, а не `[]`.

**Изменения, сделанные до добавления узла в граф, подхватываются
автоматически.** Вам не нужно ничего вызывать самостоятельно в обычном
случае создания виджетов в конструкторе или `onNodeCreated`.

`node.widgets` отображается в `Object.keys(node)` и при spread-копировании
объекта, например `{...node}`.

## Предпочитайте `node.addCustomWidget()` добавлению в `node.widgets`

Виджеты, добавленные с помощью `node.addWidget()`, `node.addCustomWidget()` или
`node.addDOMWidget()`, автоматически регистрируются в хранилище. Обычный объект,
добавленный напрямую в `node.widgets`, также преобразуется в экземпляр виджета
и регистрируется, как только узел оказывается в графе. Обычно преобразование
происходит на месте, но замороженный объект или объект с неконфигурируемыми
свойствами заменяется отдельным виджетом, поэтому сохраняйте виджет, который
возвращает `addCustomWidget()`, или считывайте его из `node.widgets`.
`addCustomWidget()` по-прежнему остаётся рекомендуемым вызовом: он возвращает
виджет и восстанавливает сохранённое значение виджета при загрузке рабочего
процесса.

```js
node.addCustomWidget({
  name: 'my_widget',
  type: 'custom',
  value: '',
  options: {},
  draw(ctx, node, width, y, height) {},
  mouse(event, pos, node) {}
})
```

Если вы читаете или записываете `widget.value` до того, как узел присоединён к графу,
значение хранится локально и синхронизируется с хранилищем при присоединении. Ни одно значение
не теряется, но интерфейс, управляемый хранилищем (например, правая боковая панель), не увидит
значение до этого момента.

## Удалить виджеты с помощью `node.removeWidget()`

Используйте `node.removeWidget(widget)`, чтобы удалить виджет. Прямое изменение `node.widgets` через splice пропускает очистку слотов, и значение удалённого виджета остаётся в хранилище, пока сам узел не будет удалён из графа.

## Изменения, вносимые агентом, вызывают `setValue` без события указателя

Когда встроенный Agent изменяет виджет, являющийся экземпляром `BaseWidget`, фронтенд вызывает
`widget.setValue(value, { node, canvas })`, то есть тот же метод, через который проходит изменение, сделанное пользователем. Раньше он
напрямую присваивал `widget.value`, а затем сам вызывал `callback` и `onWidgetChanged`. Это касается и простых объектов,
добавленных с помощью `addCustomWidget()` или помещённых в `node.widgets`, поскольку фронтенд преобразует их в экземпляры
`BaseWidget`. Контроллеры количества строк DynamicGroup и виджеты, вынесенные на хост подграфа, по-прежнему записываются напрямую.

Если вы переопределяете `setValue`, принимайте options в форме `{ node, e?, canvas? }`: `e`
для этих вызовов никогда не задаётся, а `canvas` тоже может отсутствовать. Не читайте `options.e`
или `options.canvas`, предварительно не проверив их. Обёртка, которая вызывает
исходный `setValue` только со значением, по-прежнему работает: options
по умолчанию имеют вид `{ node: widget.node }`.

`callback` и `onWidgetChanged` теперь получают значение, которое принял виджет, а не
значение, отправленное Agent. Числовой виджет ограничивается `min`/`max` и преобразует
числовую строку в число. В `callback` `e` равно `undefined`, как и `pos`, когда холст отсутствует.

`setValue` возвращает управление без изменений, когда значение после того, как виджет числа
ограничивает и преобразует его, уже идентично (`===`) текущему значению, поэтому
`'5'` в виджете числа со значением `5` ничего не меняет. Он также возвращает управление, когда виджет числа
получает значение, для которого `Number(value)` равно `NaN`. Ни `callback`,
ни `onWidgetChanged` не срабатывают, и версия графа не меняется. Числовая
строка, такая как `'7'`, преобразуется и применяется.

## Не вызывайте `useWidgetValueStore()` из кода расширений

Не вызывайте `useWidgetValueStore()` из расширений. Вместо этого используйте `node.widgets`, `node.addWidget()` / `addCustomWidget()` / `removeWidget()` и `widget.value`. Внутренняя схема ключей хранилища и его зависимость от Pinia не входят в поддерживаемый интерфейс расширений.
