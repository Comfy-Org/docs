## Контрольный список миграции

1. Продолжайте использовать `node.pos`, `node.size`, `boundingRect`, `getBounding()`,
   `setPos()`, `setSize()`: изменения сигнатур не требуются.
2. Замените вызовы `repositionNodesVueMode()` на `applyNodePositions()`.
3. Если вы полагались на то, что `node.size` отражает измеренное или отрисованное
   содержимое, переключитесь на `getBounding()` / `boundingRect`. В рендерере Vue
   `size` теперь строго отражает запрошенное значение. Классический рендерер
   по-прежнему увеличивает `size`, чтобы вместить виджеты.
4. Используйте API геометрии узлов и групп, а не резервное хранилище; не импортируйте
   `layoutStore` и не полагайтесь на его внутренний формат.
5. Запись через удалённую ссылку обновляет отсоединённый объект, а не общее
   состояние раскладки.

## Что изменилось

`LGraphNode.pos`, `size`, `boundingRect`, `getBounding()`, `setPos()` и
`setSize()` сохраняют те же сигнатуры. Эти вызовы остаются совместимыми на уровне
исходного кода. Поведение изменилось в трёх случаях, описанных ниже.

```ts
node.pos = [100, 200]
node.pos[0] += 50
node.setSize([320, 200])
node.updateArea()
const box = node.getBounding()
```

Геометрия узлов и групп теперь хранится в общем хранилище компоновки, а не в
полях отдельных экземпляров. Используйте перечисленные выше API, а не хранилище
напрямую: это внутренняя деталь реализации.

### `size` и отрисованные границы

`node.size` это размер, который вы запросили, и именно он сериализуется. При
использовании Vue-рендерера рендеринг никогда его не меняет. `getBounding()` и
`boundingRect` возвращают отрисованные границы, которые могут быть больше
`size`, если содержимому виджетов нужно больше места. В классическом
холсте-рендерере узел по-прежнему увеличивается под свои виджеты, вызывая
`setSize()`, поэтому `node.size` и сохранённый размер могут измениться после
отрисовки. Используйте отрисованные границы, когда вам нужны фактические размеры
узла на экране.

Холст пересчитывает `getBounding()` и `boundingRect` в начале каждого кадра.
После изменения `pos` или `size` вызовите `node.updateArea()`, прежде чем читать
их в том же кадре. При использовании Vue-рендерера рост из-за содержимого DOM
появляется только после того, как узел был измерен.

```ts
// ДО: изменение размера по отрисованному содержимому могло перезаписать size,
// поэтому сворачивание узла и повторное разворачивание теряло оригинальный размер.
node.size // мог незаметно стать отрисованным размером

// ПОСЛЕ (Vue-рендерер): size остаётся тем, что вы задали; запрашивайте отрисованные границы явно.
node.size // запрошенный размер, не изменённый рендерингом
node.getBounding() // фактические отрисованные границы, могут быть больше
```

### `repositionNodesVueMode()` переименован в `applyNodePositions()`

```ts
// ДО
canvas.repositionNodesVueMode(newPositions)
// ПОСЛЕ
canvas.applyNodePositions(newPositions)
```

`repositionNodesVueMode()` остаётся доступным для вызова как устаревший
псевдоним.

### Порядок наложения теперь однозначен

Раньше порядок наложения (Z-order) определялся из двух источников, которые могли
расходиться: положения узла в списке узлов и порядка его выполнения. Теперь это
всегда порядок отрисовки. Если ваше расширение выводило порядок наложения или
порядок проверки попадания из порядка выполнения, переключитесь на порядок
отрисовки.

## Записи через удалённые ссылки остаются локальными

После удаления сеттеры геометрии обновляют только отсоединённый узел, группу или объект перенаправления. Они не обновляют общее состояние макета или другую сущность, которая теперь владеет тем же ID.
