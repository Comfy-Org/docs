## Ленивые вычисления

По умолчанию все `required` и `optional` входы вычисляются до того, как узел может быть запущен. Однако иногда
вход не обязательно будет использован, и его вычисление приведёт к ненужной обработке. Вот несколько примеров
узлов, где ленивое вычисление может быть полезным:
1. Узел `ModelMergeSimple`, в котором коэффициент равен либо `0.0` (в этом случае первую модель не нужно загружать),
либо `1.0` (в этом случае вторую модель не нужно загружать).
2. Интерполяция между двумя изображениями, где коэффициент (или маска) полностью равен `0.0` или полностью `1.0`.
3. Узел Switch, в котором один вход определяет, какой из остальных входов будет передан.

<Tip>Сделать вход ленивым почти ничего не стоит. Если это возможно, обычно так и стоит делать.</Tip>

### Создание ленивых входов

Чтобы превратить вход в «ленивый» вход, нужно выполнить два шага. Вот они:

1. Отметьте вход как lazy в словаре, который возвращает `INPUT_TYPES`
2. Определите метод с именем `check_lazy_status` (обратите внимание: *не* метод класса), который будет вызван перед вычислением, чтобы определить, необходимы ли ещё какие-либо входы.

Чтобы продемонстрировать это, мы создадим узел «MixImages», который интерполирует между двумя изображениями в соответствии с маской. Если вся маска равна `0.0`, нам не нужно вычислять ни одну часть дерева, ведущую ко второму изображению. Если вся маска равна `1.0`, мы можем пропустить вычисление первого изображения.

#### Определение `INPUT_TYPES`

Объявить вход ленивым так же просто, как добавить пару ключ-значение `lazy: True` в словарь опций входа.

```python
@classmethod
def INPUT_TYPES(cls):
    return {
        "required": {
            "image1": ("IMAGE",{"lazy": True}),
            "image2": ("IMAGE",{"lazy": True}),
            "mask": ("MASK",),
        },
    }
```

В этом примере `image1` и `image2` оба отмечены как ленивые входы, но `mask` всегда будет вычисляться.

#### Определение `check_lazy_status`

Метод `check_lazy_status` вызывается, если есть один или несколько ленивых входов, которые ещё не доступны. Этот метод получает те же аргументы, что и стандартная функция выполнения. Все доступные входы передаются с их итоговыми значениями, а недоступные ленивые входы имеют значение `None`.

Задача функции `check_lazy_status` состоит в том, чтобы вернуть список имён ленивых входов, которые нужны для продолжения работы. Если все ленивые входы доступны, функция должна вернуть пустой список.

Обратите внимание, что `check_lazy_status` может вызываться несколько раз. (Например, после вычисления одного ленивого входа может выясниться, что нужно вычислить ещё один.)

<Tip>Обратите внимание: функция использует фактические значения входов, поэтому это *не* метод класса.</Tip>
```python
def check_lazy_status(self, mask, image1, image2):
    mask_min = mask.min()
    mask_max = mask.max()
    needed = []
    if image1 is None and (mask_min != 1.0 or mask_max != 1.0):
        needed.append("image1")
    if image2 is None and (mask_min != 0.0 or mask_max != 0.0):
        needed.append("image2")
    return needed
```

### Полный пример


```python
class LazyMixImages:
    @classmethod
    def INPUT_TYPES(cls):
        return {
            "required": {
                "image1": ("IMAGE",{"lazy": True}),
                "image2": ("IMAGE",{"lazy": True}),
                "mask": ("MASK",),
            },
        }

    RETURN_TYPES = ("IMAGE",)
    FUNCTION = "mix"

    CATEGORY = "Examples"

    def check_lazy_status(self, mask, image1, image2):
        mask_min = mask.min()
        mask_max = mask.max()
        needed = []
        if image1 is None and (mask_min != 1.0 or mask_max != 1.0):
            needed.append("image1")
        if image2 is None and (mask_min != 0.0 or mask_max != 0.0):
            needed.append("image2")
        return needed

    # Not trying to handle different batch sizes here just to keep the demo simple
    def mix(self, mask, image1, image2):
        mask_min = mask.min()
        mask_max = mask.max()
        if mask_min == 0.0 and mask_max == 0.0:
            return (image1,)
        elif mask_min == 1.0 and mask_max == 1.0:
            return (image2,)

        result = image1 * (1. - mask) + image2 * mask,
        return (result[0],)
```

## Блокировка выполнения

Хотя ленивое вычисление (Lazy Evaluation) является рекомендуемым способом «отключить» часть графа, иногда требуется отключить узел `OUTPUT`, который сам не реализует ленивое вычисление. Если это выходной узел, разработанный вами, вам следует просто добавить ленивое вычисление следующим образом:

1. Добавьте обязательный (если это новый узел) или необязательный (если важна обратная совместимость) вход `enabled` со значением по умолчанию `True`
2. Сделайте все остальные входы `lazy`-входами
3. Вычисляйте остальные входы только если `enabled` равно `True`

Если это не узел, которым вы управляете, можно воспользоваться `comfy_execution.graph.ExecutionBlocker`. Этот особый объект можно вернуть как выход любого сокета. Любые узлы, получающие `ExecutionBlocker` на вход, пропускают выполнение и возвращают этот `ExecutionBlocker` для всех своих выходов.

<Tip>**Намеренно не существует способа остановить распространение ExecutionBlocker вперёд.** Если вам кажется, что это нужно, вам, скорее всего, нужны ленивые вычисления.</Tip>

### Использование

Существует два способа создать и использовать `ExecutionBlocker`

1. Передайте `None` в конструктор, чтобы молча заблокировать выполнение. Это полезно в случаях, когда блокировка выполнения является частью успешного запуска, например, при отключении выхода.
```python
def silent_passthrough(self, passthrough, blocked):
    if blocked:
        return (ExecutionBlocker(None),)
    else:
        return (passthrough,)
```

2. Передайте строку в конструктор, чтобы отображать сообщение об ошибке, когда узел блокируется из-за получения объекта. Это может быть полезно, если вы хотите показать содержательное сообщение об ошибке, когда кто-то использует бессмысленный выход. Например, выход `VAE` при загрузке модели, которая не содержит VAE.

```python
def load_checkpoint(self, ckpt_name):
    ckpt_path = folder_paths.get_full_path("checkpoints", ckpt_name)
    model, clip, vae = load_checkpoint(ckpt_path)
    if vae is None:
        # This error is more useful than a "'NoneType' has no attribute" error
        # in a later node
        vae = ExecutionBlocker(f"No VAE contained in the loaded model {ckpt_name}")
    return (model, clip, vae)
```
