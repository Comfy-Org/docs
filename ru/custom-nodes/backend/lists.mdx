## Обработка данных длины 1

На внутреннем уровне сервер Comfy представляет данные, передаваемые от одного узла к другому, как Python `list` соответствующего типа данных, обычно длины 1.
В обычном режиме работы, когда узел возвращает выходные данные, каждый элемент выходного `tuple` отдельно оборачивается в список (длины 1); затем при вызове следующего узла данные разворачиваются и передаются в основную функцию.

<Tip>Обычно вам не нужно об этом беспокоиться, поскольку Comfy выполняет оборачивание и разворачивание.</Tip>

<Tip>Это не про пакеты. Пакет (например, латентов или изображений) является *единственной записью* в списке (см. [типы данных tensor](./images_and_masks)).</Tip>

## Обработка списков

В некоторых случаях в одном рабочем процессе обрабатывается несколько экземпляров данных, и тогда внутренние данные представляют собой список, содержащий эти экземпляры.
Пример: обработка серии изображений по одному, чтобы не исчерпать VRAM, или работа с изображениями разного размера.

По умолчанию Comfy обрабатывает значения в списке последовательно:
- если входы представляют собой `list` разной длины, более короткие дополняются повторением последнего значения
- основной метод вызывается один раз для каждого значения во входных списках
- выходы являются `list`, каждый из которых имеет ту же длину, что и самый длинный вход

Соответствующий код можно найти в методе `map_node_over_list` в `execution.py`.

Однако, поскольку Comfy оборачивает выходы узлов в `list` длиной один, если `tuple`, возвращаемый пользовательским узлом, содержит `list`, этот `list` будет обёрнут и воспринят как единый фрагмент данных.
Чтобы сообщить Comfy, что возвращаемый список не нужно оборачивать, а следует обрабатывать его как серию данных для последовательной обработки, узел должен предоставить атрибут класса `OUTPUT_IS_LIST`, который является `tuple[bool]` той же длины, что и `RETURN_TYPES`, и указывает, какие выходы следует обрабатывать таким образом.

Узел также может переопределить поведение входов по умолчанию и получить весь список за один вызов. Для этого нужно задать атрибуту класса `INPUT_IS_LIST` значение `True`.

Вот (с небольшими комментариями) пример из встроенных узлов: `ImageRebatch` принимает один или несколько пакетов изображений (получает их как список, поскольку `INPUT_IS_LIST - True`) и пересобирает их в пакеты заданного размера.

<Tip>`INPUT_IS_LIST` действует на уровне узла: все входы обрабатываются одинаково. Поэтому значение виджета `batch_size` берётся из `batch_size[0]`.</Tip>

```Python

class ImageRebatch:
    @classmethod
    def INPUT_TYPES(s):
        return {"required": { "images": ("IMAGE",),
                              "batch_size": ("INT", {"default": 1, "min": 1, "max": 4096}) }}
    RETURN_TYPES = ("IMAGE",)
    INPUT_IS_LIST = True
    OUTPUT_IS_LIST = (True, )
    FUNCTION = "rebatch"
    CATEGORY = "image/batch"

    def rebatch(self, images, batch_size):
        batch_size = batch_size[0]    # всё приходит списком, поэтому batch_size - это list[int]

        output_list = []
        all_images = []
        for img in images:                    # каждый img - пакет изображений
            for i in range(img.shape[0]):     # каждый i - одно изображение
                all_images.append(img[i:i+1])

        for i in range(0, len(all_images), batch_size): # берём куски по batch_size и превращаем каждый в новый пакет
            output_list.append(torch.cat(all_images[i:i+batch_size], dim=0))  # упадёт с ужасной ошибкой, если пакеты изображений имели разную ширину или высоту!

        return (output_list,)
```
