Это наиболее важные встроенные типы данных. Вы также можете [определить собственные типы данных]( ./more_on_inputs#пользовательские-типы-данных).

Типы данных используются на стороне клиента, чтобы рабочий процесс не мог передать в узел данные неправильного вида: отчасти это похоже на строгую типизацию.
Клиентский код JavaScript, как правило, не позволяет подключать выход узла ко входу с другим типом данных,
хотя ниже отмечено несколько исключений.

## Типы данных ComfyUI

### КОМБО

* В `INPUT_TYPES` нет дополнительных параметров

* Тип данных Python: определяется как `list[str]`, выходное значение имеет тип `str`

Представляет собой виджет выпадающего меню.
В отличие от других типов данных, `COMBO` задаётся в `INPUT_TYPES` не с помощью `str`, а с помощью `list[str]`, где перечислены варианты из выпадающего списка, при этом первый вариант выбран по умолчанию.

Входы типа `COMBO` часто динамически генерируются во время выполнения. Например, во встроенном узле `CheckpointLoaderSimple` можно найти

```
"ckpt_name": (folder_paths.get_filename_list("checkpoints"), )
```

или они могут быть просто фиксированным списком вариантов,

```
"play_sound": (["no","yes"], {}),
```

### Примитив и перенаправление

Узлы примитивов и перенаправления существуют только на стороне клиента. У них нет собственного типа данных, но при подключении они принимают тип данных того входа или выхода, к которому подключены (поэтому они не могут подключаться к входу `*`...)

## Типы данных Python

### ЦЕЛОЕ

* Дополнительные параметры в `INPUT_TYPES`:

  * `default` обязателен

  * `min` и `max` необязательны

* Тип данных Python: `int`

### ПЛАВАЮЩИЙ

* Дополнительные параметры в `INPUT_TYPES`:

  * `default` обязателен

  * `min`, `max`, `step` необязательны

* Тип данных Python: `float`

### СТРОКА

* Дополнительные параметры в `INPUT_TYPES`:

  * `default` обязателен

* Тип данных Python: `str`

### БУЛЕВО

* Дополнительные параметры в `INPUT_TYPES`:

  * `default` обязателен

* Тип данных Python: `bool`

## Типы данных тензоров

### IMAGE

* Нет дополнительных параметров в `INPUT_TYPES`

* Python-тип `torch.Tensor` с *формой* \[B,H,W,C]

Пакет из `B` изображений высотой `H`, шириной `W` и с `C` каналами (обычно `C=3` для `RGB`).

### LATENT

* Нет дополнительных параметров в `INPUT_TYPES`

* Python-тип `dict`, содержащий `torch.Tensor` с *формой* \[B,C,H,W]

Передаваемый `dict` содержит ключ `samples`, который является `torch.Tensor` с *формой* \[B,C,H,W] и представляет
пакет из `B` латентов с `C` каналами (обычно `C=4` для существующих моделей stable diffusion), высотой `H` и шириной `W`.

Высота и ширина составляют 1/8 соответствующего размера изображения (это значение, которое вы задаёте в узле Empty Latent Image).

### MASK

* Нет дополнительных параметров в `INPUT_TYPES`

* Python-тип `torch.Tensor` с *формой* \[H,W] или \[B,C,H,W]

### AUDIO

* Нет дополнительных параметров в `INPUT_TYPES`

* Python-тип `dict`, содержащий `torch.Tensor` с *формой* \[B, C, T] и частоту дискретизации.

Передаваемый `dict` содержит ключ `waveform`, который является `torch.Tensor` с *формой* \[B, C, T] и представляет пакет из `B` аудиосэмплов с `C` каналами (`C=2` для стерео и `C=1` для моно) и `T` шагами по времени (то есть количеством аудиосэмплов).

`dict` содержит ещё один ключ `sample_rate`, который указывает частоту дискретизации аудио.

## Пользовательские типы данных сэмплирования

### Шум

Тип данных `NOISE` представляет *источник* шума (а не сам шум). Его может представлять любой объект Python, предоставляющий метод генерации шума с сигнатурой `generate_noise(self, input_latent:Tensor) -> Tensor`, и свойство `seed:Optional[int]`.

<Tip>`seed` передаётся в метод `sample` гида в `SamplerCustomAdvanced`, но, судя по всему, ни один из стандартных гидов его не использует. Он необязателен, поэтому обычно можно задать его как None.</Tip>

Когда требуется добавить шум, в этот метод передаётся латент. Метод должен вернуть `Tensor` той же формы, содержащий шум.

См. [пример смешивания шума](./snippets#создание-вариаций-шума)

### Сэмплер

Тип данных `SAMPLER` представляет сэмплер, который, в свою очередь, представляется объектом Python, предоставляющим метод `sample`. Выборка в Stable Diffusion выходит за рамки этого руководства; см. `comfy/samplers.py`, если хотите углубиться в эту часть кода.

### Сигмы

Тип данных `SIGMAS` представляет значения сигмы до и после каждого шага процесса выборки, создаваемые scheduler. Они представляются одномерным тензором длины `steps+1`, где каждый элемент задаёт шум, который ожидается перед соответствующим шагом, а последнее значение задаёт шум после финального шага.

`normal` scheduler с 20 шагами и denoise, равным 1, для модели SDXL выдаёт:

```
tensor([14.6146, 10.7468,  8.0815,  6.2049,  4.8557,  
         3.8654,  3.1238,  2.5572,  2.1157,  1.7648,  
         1.4806,  1.2458,  1.0481,  0.8784,  0.7297,  
         0.5964,  0.4736,  0.3555,  0.2322,  0.0292,  0.0000])
```

<Tip>Начальное значение сигмы зависит от модели, поэтому узлу scheduler требуется вход `MODEL`, чтобы получить выход SIGMAS</Tip>

### Гид

`GUIDER` представляет собой обобщение процесса удаления шума, «направляемого» промптом или любой другой формой условия. В Comfy гид представляется `callable`-объектом Python, предоставляющим метод `__call__(*args, **kwargs)`, который вызывается в процессе выборки.

Метод `__call__` принимает (в `args[0]`) пакет зашумлённых латентов (тензор `[B,C,H,W]`) и возвращает предсказание шума (тензор той же формы).
