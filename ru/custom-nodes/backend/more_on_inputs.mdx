## Скрытые входы

Помимо входов `required` и `optional`, которые создают соответствующие входы или виджеты на стороне клиента, существуют три варианта `hidden`-входов, позволяющих пользовательскому узлу запросить у сервера определённую информацию.

Доступ к ним осуществляется путём возврата значения для `hidden` в `dict` `INPUT_TYPES` с сигнатурой `dict[str,str]`, содержащего один или несколько элементов из `PROMPT`, `EXTRA_PNGINFO` или `UNIQUE_ID`.

```python
@classmethod
def INPUT_TYPES(s):
    return {
        "required": {...},
        "optional": {...},
        "hidden": {
            "unique_id": "UNIQUE_ID",
            "prompt": "PROMPT", 
            "extra_pnginfo": "EXTRA_PNGINFO",
        }
    }
```

### UNIQUE_ID 
`UNIQUE_ID` представляет собой уникальный идентификатор узла и совпадает со свойством `id` узла на стороне клиента. 
Обычно он используется при обмене данными между клиентом и сервером (см. [messages](/ru/development/comfyui-server/comms_messages#получение-node-id)).

### PROMPT
`PROMPT` представляет собой полный промпт, отправленный клиентом на сервер. 
Полное описание см. в разделе [объект промпта](/ru/custom-nodes/js/javascript_objects_and_hijacking#prompt).

### EXTRA_PNGINFO
`EXTRA_PNGINFO` представляет собой словарь, который копируется в метаданные любого сохраняемого файла `.png`. Пользовательские узлы могут хранить в этом словаре дополнительную
информацию для сохранения (или как способ связи с последующим узлом).

<Tip>Обратите внимание: если Comfy запущен с опцией `disable_metadata`, эти данные не будут сохранены.</Tip>

### DYNPROMPT
`DYNPROMPT` представляет собой экземпляр `comfy_execution.graph.DynamicPrompt`. Он отличается от `PROMPT` тем, что может изменяться в ходе выполнения в ответ на [Node Expansion](/ru/custom-nodes/backend/expansion).
<Tip>`DYNPROMPT` следует использовать только в расширенных случаях (например, при реализации циклов в пользовательских узлах).</Tip>

## Гибкие входы

### Пользовательские типы данных

Если вы хотите передавать данные между своими пользовательскими узлами, вам может быть полезно определить пользовательский тип данных. Это (почти) так же просто, как выбрать имя для типа данных, которое должно быть уникальной строкой в верхнем регистре, например `CHEESE`.

Затем вы можете использовать `CHEESE` в `INPUT_TYPES` и `RETURN_TYPES` вашего узла, и клиент Comfy разрешит подключать выходы `CHEESE` только ко входу `CHEESE`. `CHEESE` может быть любым объектом Python.

Единственное, что стоит отметить: поскольку клиент Comfy ничего не знает о `CHEESE`, вам нужно (если только вы не определите пользовательский виджет для `CHEESE`, но это тема для другого раза) заставить его быть входом, а не виджетом. Это можно сделать с помощью параметра `forceInput` в словаре опций входа:

```python
@classmethod
def INPUT_TYPES(s):
    return {
        "required": { "my_cheese": ("CHEESE", {"forceInput":True}) }
    }
```

### Входы с подстановочным знаком

```python
@classmethod
def INPUT_TYPES(s):
    return {
        "required": { "anything": ("*",{})},
    }

@classmethod
def VALIDATE_INPUTS(s, input_types):
    return True
```

Фронтенд позволяет использовать `*`, чтобы указать, что вход можно подключить к любому источнику. Поскольку бэкенд официально это не поддерживает, вы можете пропустить валидацию типов на стороне бэкенда, приняв параметр с именем `input_types` в своей функции `VALIDATE_INPUTS`. (Дополнительную информацию см. в разделе [VALIDATE_INPUTS](./server_overview#validate_inputs).)
Разбираться в переданных данных должен сам узел.

### Динамически создаваемые входы

Если входы создаются динамически на стороне клиента, их нельзя определить в исходном коде Python.
Чтобы получить доступ к этим данным, нам нужен словарь `optional`, который позволяет Comfy передавать данные с произвольными именами. Поскольку сервер Comfy

```python
class ContainsAnyDict(dict):
    def __contains__(self, key):
        return True
...

@classmethod
def INPUT_TYPES(s):
    return {
        "required": {},
        "optional": ContainsAnyDict()
    }
...

def main_method(self, **kwargs):
    # динамически созданные входные данные будут в словаре kwargs

```
