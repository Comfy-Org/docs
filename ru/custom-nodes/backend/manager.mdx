## Что такое пользовательский узел?

Одна из сильных сторон Comfy заключается в том, что подход на основе узлов позволяет создавать новые рабочие процессы, по-разному соединяя предоставленные узлы. Встроенные узлы предоставляют широкий набор функций, но может оказаться, что вам нужна функция, которой нет среди базовых узлов.

Пользовательские узлы создаются сообществом. Они позволяют реализовывать новые функции и делиться ими с более широким сообществом. Если вы заинтересованы в разработке пользовательских узлов, подробнее об этом можно прочитать [здесь](/ru/custom-nodes/overview).

## ComfyUI Manager

Хотя пользовательские узлы можно устанавливать вручную, большинство использует для этого
[ComfyUI Manager](https://github.com/Comfy-Org/ComfyUI-Manager). **ComfyUI Manager** берёт на себя установку,
обновление и удаление пользовательских узлов и всех зависимостей. Но он не входит в ядро Comfy,
поэтому установить его нужно вручную.

### Установка ComfyUI Manager

```bash
cd ComfyUI/custom_nodes
git clone https://github.com/Comfy-Org/ComfyUI-Manager.git
```

После этого перезапустите Comfy.
Подробности и особые случаи смотрите в разделе [ComfyUI Manager Install](https://github.com/Comfy-Org/ComfyUI-Manager?tab=readme-ov-file#installation).

### Использование ComfyUI Manager

Чтобы ваш пользовательский узел стал доступен через **ComfyUI Manager**, сохраните его как git-репозиторий (обычно на `github.com`),
а затем отправьте Pull Request в репозиторий **ComfyUI Manager**, в котором вы отредактировали `custom-node-list.json`, добавив свой узел.
[Подробнее](https://github.com/Comfy-Org/ComfyUI-Manager?tab=readme-ov-file#how-to-register-your-custom-node-into-comfyui-manager).

Когда пользователь устанавливает узел, **ComfyUI Manager**:

<Steps>
<Step title="Клонировать репозиторий">
выполняет git clone репозитория,
</Step>
<Step title="Установить зависимости Python">
устанавливает зависимости pip, перечисленные в репозитории пользовательского узла в файле `requirements.txt` (если он есть),
```
pip install -r requirements.txt
```
<Tip>Как всегда бывает с `pip`, требования вашего узла могут конфликтовать с другими
пользовательскими узлами. Не делайте свой `requirements.txt` строже, чем нужно.</Tip>
</Step>
<Step title="Выполнить скрипт установки">
выполняет `install.py`, если он присутствует в репозитории пользовательского узла.
<Tip>`install.py` выполняется из корневого каталога пользовательского узла</Tip>
</Step>
</Steps>

### Файлы ComfyUI Manager

Как указано выше, есть ряд файлов и скриптов, которые **ComfyUI Manager** использует для управления жизненным циклом
пользовательского узла. Все они необязательны.

- `requirements.txt`: зависимости Python, как указано выше
- `install.py`, `uninstall.py`: выполняются при установке или удалении пользовательского узла
<Tip>Пользователи могут просто удалить каталог, поэтому нельзя рассчитывать на то, что `uninstall.py` будет выполнен</Tip>
- `disable.py`, `enable.py`: необязательные хуки. Только классический сценарий с git clone запускает их при отключении или повторном включении узла. Текущие действия отключения и включения просто перемещают папку, поэтому не полагайтесь на эти скрипты
<Tip>`enable.py` выполняется только при повторном включении отключённого узла. Он должен лишь отменять всё, что сделано в `disable.py`</Tip>
<Tip>При отключении пользовательского узла его папка перемещается в `ComfyUI/custom_nodes/.disabled/`, и Comfy игнорирует её, пока она там находится</Tip>
- `node_list.json`: требуется, только если схема NODE_CLASS_MAPPINGS пользовательских узлов отличается от стандартной.

Официальные детали смотрите в [руководстве ComfyUI Manager](https://github.com/Comfy-Org/ComfyUI-Manager?tab=readme-ov-file#custom-node-support-guide).
