<Note>
  Comfy API v2 представляет собой версионируемый API. Изменения в пределах v2 носят аддитивный характер; критические изменения выпускаются в v3.
</Note>

Официальный версионируемый HTTP API для запуска рабочих процессов ComfyUI из внешних приложений: загрузить входы, отправить рабочий процесс, наблюдать за выполнением и получать результаты.

Большинству пользователей следует начать с [Comfy SDKs](/ru/development/api-development/sdks), которые служат обёрткой для этого API на Python и TypeScript. Вызывайте эти эндпоинты напрямую, если работаете на другом языке. Полная документация по эндпоинтам находится на страницах API Reference этого раздела, сгенерированных на основе спецификации OpenAPI.

## Где работает v2

Один и тот же API предоставляется в трёх вариантах, поэтому одну интеграцию можно переносить между ними, меняя только базовый URL.

**Comfy Cloud.** Управляемый мультитенантный сервис по адресу `https://cloud.comfy.org`. Создайте [API-ключ](/ru/development/api-development/getting-an-api-key), и вы сможете отправлять любой рабочий процесс. Функции, специфичные для Cloud, такие как кредиты, просмотр моделей и управление очередью, доступны в [v1 Cloud API](/ru/development/cloud/overview), а не в v2.

**Развёртывания Comfy API.** Среда, которую вы развёртываете через [Developer Platform](https://platform.comfy.org), получает собственный выделенный эндпоинт по адресу `https://{deployment}.run.comfy.app`, который обслуживает тот же v2 API с тем же API-ключом. Развёртывание Comfy API выполняет рабочие процессы в одном закреплённом окружении, поэтому масштабируется независимо, а `GET /workflow` возвращает выполненный граф. См. [руководство по развёртыванию Comfy API](/ru/development/serverless/overview), чтобы узнать о сборке и развёртывании.

**ComfyUI с открытым исходным кодом, через прокси.** Самостоятельно размещённый ComfyUI работает с v2 через [comfy-api-proxy](https://github.com/Comfy-Org/comfy-api-proxy), небольшой сервис с открытым исходным кодом, который запускается рядом с ним:

```bash
pip install comfy-api-proxy
comfy-api-proxy
```

По умолчанию он проксирует ComfyUI на `127.0.0.1:8188` и обслуживает v2 API на `127.0.0.1:8189`, привязываясь только к loopback-интерфейсу. Аутентификация по умолчанию отключена, при необходимости можно задать статический bearer-токен. Подробности настройки см. в разделе [Собственный ComfyUI](/ru/development/api-development/sdks#свой-comfyui) руководства по SDK.

## Принципы проектирования

- **Сначала опрос.** Каждая возможность доступна через обычный GET-опрос. Поток SSE является живым дополнением, но никогда не источником истины.
- **Всё возобновляемо.** Отправка идемпотентна, а состояние задачи и выходы можно получить по ID до `expires_at`. URL, который вы получаете для выхода, живёт меньше: см. [URL выходов и как долго они живут](#url-адреса-выходов-и-сроки-их-действия).
- **Ассеты с адресацией по содержимому.** Ассеты представляют собой записи, идентифицируемые UUID, поверх блобов, ключом которых является вычисленный сервером хеш blake3, поэтому идентичные входы не загружаются дважды.
- **Следуйте ссылкам, не создавайте URL.** Ответы содержат свои URL для последующих действий.

См. [Заметки о проектировании](/ru/development/api-development/sdks-design), чтобы узнать обоснование этого.

## Базовые URL

| Вариант | URL | Аутентификация |
|---------|-----|----------------|
| Comfy Cloud | `https://cloud.comfy.org` | `Authorization: Bearer <api-key>` |
| Развёртывание Comfy API | `https://{deployment}.run.comfy.app` | `Authorization: Bearer <api-key>` |
| Самостоятельное развёртывание через [comfy-api-proxy](https://github.com/Comfy-Org/comfy-api-proxy) | `http://127.0.0.1:8189` | По умолчанию отсутствует, при необходимости можно указать статический bearer-токен |

## Категории эндпоинтов

| Категория | Описание |
|----------|-------------|
| Ассеты | Записи, идентифицируемые по UUID, поверх blob-объектов с адресацией по содержимому. Загружайте входы, скачивайте выходы. |
| Задания | Одно выполнение рабочего процесса. Долговечные, с возможностью опроса и отмены. |

## URL-адреса выходов и сроки их действия

«URL для моего выхода» подчиняется трём разным срокам жизни, и это не одно и то же число. Любое приложение, которое показывает выходы своим пользователям, должно учитывать все три.

### Две формы URL

| Форма | Где вы её получаете | Может ли третья сторона открыть её? | Как долго она действует |
|-------|------------------|----------------------------|-------------------|
| Эндпоинт содержимого, `{base}/api/v2/assets/{id}/content` | `url` у каждой записи `outputs` задачи | Нет. Это аутентифицированный маршрут, и без вашего API-ключа он отвечает `401`. | Стабильный. Он разрешается, пока существует ассет. |
| Подписанный URL хранилища | `url` в ответе `Asset`, `Location` ответа `302`, на который перенаправляет эндпоинт содержимого, и `getDownloadUrl()` в обоих SDK | Да. Он несёт собственную авторизацию, поэтому браузер или другой сервис читает его без собственного ключа. | Короткий. Сегодня в Comfy Cloud это примерно 6 часов. |

Практическое следствие: `Output.url` не является ссылкой, которой можно поделиться. Если поместить его в `<img src>`, который загружают браузеры ваших пользователей, они получат `401`, потому что их браузер не несёт ваш API-ключ. Именно подписанный URL вы можете выдать.

У ComfyUI, размещённого самостоятельно за [comfy-api-proxy](https://github.com/Comfy-Org/comfy-api-proxy), подписанных URL нет вообще. Прокси отдаёт байты из эндпоинта содержимого, применяется обычная аутентификация, а SDK сообщают срок истечения как `null` (в Python: `None`).

### Как узнать срок истечения подписанного URL

В развёртываниях Comfy Cloud и Comfy API подписанный URL создаётся со сроком действия **примерно 6 часов**. Это число является серверной настройкой, а не частью контракта API, поэтому воспринимайте его как порядок величины и никогда не жёстко кодируйте. Берите срок истечения из полученного ответа:

- `url_expires_at` в ответе `Asset` задаёт реальный срок истечения `url` в этом же ответе.
- `getDownloadUrl()` возвращает его вместе с URL: как `expiresAt` в TypeScript и `expires_at` в Python.

### `url_expires_at` у выхода задачи: другое число

`url_expires_at` у записи `outputs` задачи это **не** срок истечения подписанного URL. В Comfy Cloud он повторяет собственный `expires_at` задачи, который сегодня равен `created_at` задачи плюс фиксированное окно в 30 дней.

Это окно служит заглушкой. За ним пока нет политики хранения задач или сборки мусора, поэтому 30 дней это подстановка, позволяющая полю быть отличным от null, а не обязательство о том, как долго выход остаётся доступным. Не воспринимайте его как обещание и не стройте на нём кэш. Эта страница будет обновлена, если его заменит настоящая политика хранения.

### Как показывать выход в своём продукте

Чтобы показывать выход и день спустя, сделайте одно из следующего:

- **Разместите байты заново.** Скачайте выход один раз и скопируйте его в собственное хранилище. Большинство приложений приходит именно к этому.
- **Перевыпускайте по требованию.** Сохраните `id` ассета, затем в момент отрисовки получите по нему свежий URL (`GET /api/v2/assets/{id}` или `getDownloadUrl()`) и сразу используйте этот URL.
- **Проксируйте.** Запрашивайте `Output.url` из собственного бэкенда, в котором уже есть API-ключ, и передавайте байты пользователю потоком.

Что не работает, так это сохранение подписанного URL. Он годен часами, а не днями, поэтому сохранённая копия продолжает работать во время локального тестирования, а затем перестаёт работать у ваших пользователей, как только истекает.

## Comfy Router

Comfy API v2 выполняет рабочие процессы в виде долговременных заданий, которые вы отправляете и опрашиваете. Для прямых вызовов моделей (одна модель партнёра, один запрос, нативные входные и выходные данные модели) см. [Comfy Router](/ru/development/comfy-router/quickstart). Сначала ознакомьтесь с [ограничениями Router](/ru/development/comfy-router/limitations).
