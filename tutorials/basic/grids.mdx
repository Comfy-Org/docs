A **settings grid** renders the same prompt many times and changes one or two settings per cell, so you can see what each setting does to the image. **Batch generation** is the broader skill underneath it: running one workflow many times with different inputs.

This guide covers:

1. What a settings grid is and why the seed stays fixed
2. Batch generation in the ComfyUI interface: batch count, `batch_size`, lists and loops
3. Scripting bigger grids with the Comfy API
4. Laying the results out as a single grid image

![A CFG sweep at one seed: CFG 3, 6 and 9 with SDXL, labelled and arranged by the Make Image Grid node](/images/tutorial/basic/grids/cfg-sweep-grid-labeled.png)

## What a Settings Grid Is

The four `KSampler` settings that change an image the most, apart from the prompt and the model, are:

| Setting | What it changes |
|---------|-----------------|
| `cfg` | How strictly the model follows the prompt. Low values look loose and soft; high values look saturated and over-sharpened. |
| `steps` | How many denoising steps the sampler takes. More steps add detail up to a point, then only add time. |
| `sampler_name` | The algorithm that removes noise at each step (`euler`, `dpmpp_2m`, and so on). |
| `scheduler` | How the noise level drops from step to step (`normal`, `karras`, `simple`, and so on). |

A grid holds the prompt, the model and the **seed** constant, and changes only these settings. The seed decides the starting noise, so with a fixed seed every cell starts from the same noise and any difference between two cells comes from the setting you changed. With a random seed, each cell also gets a different composition, and you can no longer tell whether a change came from the setting or from the noise.

A full sweep multiplies quickly: 4 CFG values × 3 step counts × 3 samplers × 2 schedulers is 72 images. Start with one or two axes, find the range that looks good, then narrow it.

<Tip>
Open-model workflow pages on the [Comfy Hub](https://www.comfy.org/hub/workflows) have a **Grid** tab with a pre-rendered CFG × steps × sampler × scheduler sweep at one seed. You can browse it to find good settings for that model, then re-run the cells you choose on Comfy Cloud with your own prompt.
</Tip>

## Batch Generation in the ComfyUI Interface

The interface has several ways to run a workflow more than once. They differ in what changes between runs.

| Method | What changes between runs | Use it for |
|--------|---------------------------|------------|
| Batch count | Only the values the widget controls change (usually the seed) | Many variations of one prompt |
| `batch_size` | The noise of each image in the batch | Several variations in one sampling pass |
| Lists | Any input you feed from a list | A grid along one axis, or a set of prompts |
| Start Loop / End Loop | Any input, one iteration at a time | Grids along one axis, iterations that build on each other |

### Batch Count

**Batch count** sits in the run bar next to the **Run** button. It sets how many times the workflow is queued per click. See [the run bar](/interface/overview) for where it is.

1. Set `control after generate` on the `KSampler` seed to `randomize` or `increment`.
2. Set **Batch count** to the number of images you want.
3. Click **Run**. Each queued run gets the next seed.

Batch count does not change `cfg`, `steps`, `sampler_name` or `scheduler`. If the seed is set to `fixed`, every queued run is identical and gives the same image. For a settings grid, use one of the methods below.

### batch_size on the Latent

`batch_size` on the `Empty Latent Image` node creates several latents at once, and the `KSampler` denoises them together in one pass. Each image in the batch gets different noise, so you get variations of one prompt with one set of settings.

1. On `Empty Latent Image`, set `batch_size` to the number of images, for example `4`.
2. Click **Run**. `Save Image` saves all of them.

A larger batch uses more VRAM, since all images are sampled at the same time. Because every image in the batch shares the same `KSampler` settings, `batch_size` cannot make a settings grid either.

### Lists: One Run per Value

When a node receives a **list**, ComfyUI runs it once for each item and passes every result downstream. You can build a list with the [Create List](/built-in-nodes/CreateList) node, which joins its inputs, in order, into one list.

This is the quickest way to sweep one setting. To sweep CFG:

1. Add a [Float](/built-in-nodes/PrimitiveFloat) node for each CFG value, for example `3`, `6` and `9`.
2. Add a `Create List` node and connect each `Float` to its next free input. New inputs appear as you connect.
3. Connect the `list` output of `Create List` to the `cfg` input of the `KSampler`.
4. Keep the seed fixed: set `control after generate` on the seed to `fixed`.
5. Connect `VAE Decode` to a `Make Image Grid` node (see [Laying Out the Results](#laying-out-the-results-as-a-grid)) and then to `Save Image`.
6. Click **Run**. The `KSampler` and `VAE Decode` run once per CFG value, and `Make Image Grid` receives all the images.

`steps` works the same way with [Int](/built-in-nodes/PrimitiveInt) nodes.

**One prompt per input.** Lists also work for prompts. Add a [Text (Multiline)](/built-in-nodes/PrimitiveStringMultiline) node for each prompt, join them with `Create List`, and connect the list to the `text` input of `CLIP Text Encode`. Each prompt is encoded and sampled as its own run. ComfyUI's built-in nodes do not split one text box into a list by line, so put each prompt in its own text node. To run a long file with one prompt per line, use a script instead (see [Scripting Bigger Grids](#scripting-bigger-grids-with-the-comfy-api)).

<Warning>
When a node gets **more than one list**, ComfyUI pairs the items by position: the first with the first, the second with the second, and the last item of the shorter list repeats. It does not make every combination. A list of three CFG values and a list of three step counts gives three images, not nine. To cross two settings, use a script or nested loops.
</Warning>

**Samplers and schedulers.** `sampler_name` and `scheduler` are dropdowns, which a list of text values cannot feed directly. To compare a few samplers or schedulers in the interface, copy the `KSampler` and `VAE Decode` nodes once per value, connect them to the same model, prompts and latent, set each copy to a different sampler, and collect the images with `Make Image Grid`. For more than a handful, script it.

### Start Loop and End Loop

The [Start Loop](/built-in-nodes/StartLoop) and [End Loop](/built-in-nodes/EndLoop) nodes run the nodes between them once per iteration. `Start Loop` has three modes:

| Mode | Iterations |
|------|------------|
| `simple` | `num_iterations` times, with `iteration_index` running from 0 |
| `For` | From `start_iteration_index` up to (not including) `max_iteration`, in steps of `step` |
| `List` | Once per item of the connected `list`; the current item comes out of `list_item` |

To sweep CFG with a loop:

1. Build the CFG list with `Float` nodes and `Create List`, as above.
2. Add a `Start Loop` node, set `mode` to `List`, and connect the CFG list to its `list` input.
3. Connect `list_item` from `Start Loop` to the `cfg` input of the `KSampler`.
4. Add an `End Loop` node. Connect the `IMAGE` output of `VAE Decode` to `output_value`, and turn on `accumulate` so End Loop returns the image from every iteration, not only the last one.
5. Connect the `outputs` of `End Loop` to `Make Image Grid`, then to `Save Image`.
6. Click **Run**.

For a list sweep, a loop and a plain list give the same images. A loop also lets one iteration pass a value to the next (`next_iteration_value` on End Loop, `current_iteration_value` on Start Loop), and a loop can be nested inside another by connecting the outer loop's `iteration_index` to the inner loop's `parent_iteration`.

<Note>
Start Loop and End Loop are recent core nodes. If you can't find them, [update ComfyUI](/installation/update_comfyui). Comfy Cloud updates after each ComfyUI stable release.
</Note>

## Scripting Bigger Grids with the Comfy API

Past one or two axes, a script is simpler than a graph. It builds every combination, submits each one as its own job, and saves the results with names you can sort.

### 1. Export the Workflow in API Format

1. Build and test the workflow for one cell in ComfyUI, with a fixed seed.
2. Open the workflow menu and choose **Export (API)**. This saves the graph in [API format](/development/api-development/workflow-api-format), where every node is keyed by its ID.
3. Open the JSON and find the ID of your `KSampler` node: the key whose `class_type` is `KSampler`. In the default text-to-image workflow it is `"3"`.

### 2. Queue One Job per Cell

[Comfy API v2](/api-reference/v2/overview) accepts the API-format graph at `POST /api/v2/jobs` and returns a job you can poll at `GET /api/v2/jobs/{id}`. The same API runs on Comfy Cloud and, through [comfy-api-proxy](https://github.com/Comfy-Org/comfy-api-proxy), on your own ComfyUI, so the script below works on both by changing `BASE_URL`.

Comfy Cloud runs a set number of jobs at a time per plan and holds the rest in a queue:

| Plan | Jobs running at a time |
|------|------------------------|
| Standard | 1 |
| Creator | 3 |
| Pro | 5 |

You can have up to 100 jobs queued. Running more than one job at a time needs the API and a paid plan. See [Cloud concurrency limits](/development/deploy/cloud-usage#concurrency-limits) for details.

The script keeps at most `MAX_IN_FLIGHT` jobs submitted at a time, so a large grid never fills the queue, and it backs off when the server answers `429`. It needs Python 3.9 or newer and `pip install requests`. Set `COMFY_API_KEY` to your [API key](/development/api-development/getting-an-api-key) first.

```python grid.py
import itertools, json, os, time
import requests

BASE_URL = "https://cloud.comfy.org"  # own ComfyUI via comfy-api-proxy: "http://127.0.0.1:8189"
API_KEY = os.environ.get("COMFY_API_KEY", "")
HEADERS = {"Authorization": f"Bearer {API_KEY}"} if API_KEY else {}

WORKFLOW_FILE = "workflow_api.json"  # from Export (API)
KSAMPLER_ID = "3"                    # the KSampler's key in that file
SEED = 42
MAX_IN_FLIGHT = 5                    # match your plan's running limit; never above 100
OUT_DIR = "grid"

AXES = {
    "cfg": [3.0, 5.0, 7.0],
    "steps": [20, 30],
    "sampler_name": ["euler", "dpmpp_2m"],
    "scheduler": ["normal", "karras"],
}

def cell_name(cell):
    return "_".join(f"{k}-{v}" for k, v in cell.items())

def submit(graph):
    while True:
        r = requests.post(f"{BASE_URL}/api/v2/jobs", headers=HEADERS, json={"workflow": graph})
        if r.status_code == 429:  # queue full or rate limited: wait and retry
            time.sleep(int(r.headers.get("Retry-After", "10")))
            continue
        r.raise_for_status()
        return r.json()["id"]

def save_outputs(job, name):
    for i, output in enumerate(o for o in job["outputs"] if o["type"] == "image"):
        data = requests.get(output["url"], headers=HEADERS).content  # follows the redirect to storage
        ext = os.path.splitext(output["name"])[1] or ".png"
        with open(os.path.join(OUT_DIR, f"{name}_{i}{ext}"), "wb") as f:
            f.write(data)

def main():
    os.makedirs(OUT_DIR, exist_ok=True)
    with open(WORKFLOW_FILE) as f:
        base = json.load(f)

    cells = [dict(zip(AXES, values)) for values in itertools.product(*AXES.values())]
    pending = list(cells)
    in_flight = {}  # job id -> cell

    while pending or in_flight:
        while pending and len(in_flight) < MAX_IN_FLIGHT:
            cell = pending.pop(0)
            graph = json.loads(json.dumps(base))
            graph[KSAMPLER_ID]["inputs"].update(cell, seed=SEED)
            in_flight[submit(graph)] = cell

        time.sleep(3)
        for job_id, cell in list(in_flight.items()):
            r = requests.get(f"{BASE_URL}/api/v2/jobs/{job_id}", headers=HEADERS)
            if r.status_code != 200:
                continue  # rate limited or a transient error: check again next round
            job = r.json()
            if job["status"] == "succeeded":
                save_outputs(job, cell_name(cell))
            elif job["status"] not in ("failed", "canceled", "expired"):
                continue  # still queued or running
            else:
                print(f"{cell_name(cell)}: {job['status']} {job.get('error')}")
            del in_flight[job_id]
            print(f"{len(cells) - len(pending) - len(in_flight)}/{len(cells)} done")

if __name__ == "__main__":
    main()
```

The cells' file names carry their settings, for example `cfg-5.0_steps-30_sampler_name-euler_scheduler-karras_0.png`, so you can find and compare any cell later.

**One prompt per line.** To batch prompts instead of settings, read them from a text file and set the prompt node's text in each graph. Replace `cells` with one entry per line, and in the submit loop set `graph[PROMPT_NODE_ID]["inputs"]["text"]` to the line, where `PROMPT_NODE_ID` is the key of your positive `CLIP Text Encode` node:

```python
with open("prompts.txt", encoding="utf-8") as f:
    prompts = [line.strip() for line in f if line.strip()]
```

<Tip>
The [Comfy SDKs](/development/api-development/sdks) for Python and TypeScript wrap these endpoints, including uploads, waiting for jobs and retrying when the queue is full.
</Tip>

## Laying Out the Results as a Grid

### Inside ComfyUI

The [Make Image Grid](/built-in-nodes/ImageGrid) node takes a list or batch of images and arranges them in rows, left to right and top to bottom.

| Input | What it does |
|-------|--------------|
| `columns` | Images per row. Set it to the number of values on your horizontal axis. |
| `cell_width`, `cell_height` | The size each image is resized to. |
| `padding` | Pixels between cells. |

To label each cell, put a [Draw Text Overlay](/built-in-nodes/TextOverlay) node between `VAE Decode` and `Make Image Grid`. Build a second list of labels, such as `CFG 3`, `CFG 6` and `CFG 9`, with `Text` nodes and `Create List`, and connect it to the `text` input. Because the images and the labels are both lists, each image gets the label at the same position. The grid at the top of this page was made this way.

### From Script Outputs

For a scripted sweep, assemble the saved files with a few lines of [Pillow](https://pillow.readthedocs.io/) (`pip install pillow`). This example puts one setting on the columns and another on the rows, and writes the values along the edges:

```python make_grid.py
from PIL import Image, ImageDraw

COLS = ("cfg", [3.0, 5.0, 7.0])
ROWS = ("steps", [20, 30])
FIXED = {"sampler_name": "euler", "scheduler": "karras"}
CELL, LABEL = 384, 40

def path(col, row):
    cell = {COLS[0]: col, ROWS[0]: row, **FIXED}
    order = ["cfg", "steps", "sampler_name", "scheduler"]
    return "grid/" + "_".join(f"{k}-{cell[k]}" for k in order) + "_0.png"

sheet = Image.new("RGB", (LABEL + CELL * len(COLS[1]), LABEL + CELL * len(ROWS[1])), "white")
draw = ImageDraw.Draw(sheet)
for x, col in enumerate(COLS[1]):
    draw.text((LABEL + x * CELL + 8, 12), f"{COLS[0]} {col}", fill="black")
for y, row in enumerate(ROWS[1]):
    draw.text((6, LABEL + y * CELL + 8), f"{row}", fill="black")
    for x, col in enumerate(COLS[1]):
        img = Image.open(path(col, row)).convert("RGB").resize((CELL, CELL))
        sheet.paste(img, (LABEL + x * CELL, LABEL + y * CELL))
sheet.save("grid_cfg_x_steps.png")
```

Make one sheet per combination of the remaining settings, for example one CFG × steps sheet for each sampler.

## Try It Yourself

1. Download the grid image at the top of this page and drag it into ComfyUI. It loads the CFG sweep workflow (it uses `sd_xl_base_1.0.safetensors`).
2. Change the CFG values, or replace the `Float` nodes with `Int` nodes and connect the list to `steps` instead.
3. When you have found a good range in the interface, export the workflow with **Export (API)** and run a full sampler × scheduler sweep with the script.
