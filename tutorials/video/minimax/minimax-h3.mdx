[MiniMax H3](https://www.minimax.io/blog/minimax-h3) is MiniMax's open-weights omni-modal model. It understands text, images, video, and audio in one context and generates video with **native stereo audio** (voice, SFX, and music in a single pass). Open weights target about 1 megapixel (768px short edge) at 24fps for up to ~15 seconds. 2K is a hosted-service output and needs a separate upscale pass in ComfyUI.

Documentation is split across six pages:

- **Overview** (this page): capabilities, checkpoints, workflow index, resolution, clip length, steps, sampler, speedups
- **[Native workflows](/tutorials/video/minimax/minimax-h3-native)**: T2V, I2V, R2V, and native-node techniques
- **[Multiframe Reference](/tutorials/video/minimax/minimax-h3-multiframe)**: anchor reference frames on the timeline
- **[Fun ControlNet Union](/tutorials/video/minimax/minimax-h3-fun-controlnet)**: control video or inpainting with a mask
- **[Prompt guide](/tutorials/video/minimax/minimax-h3-prompt-guide)**: official guides, tips, embeddings
- **[FastH3](/tutorials/video/minimax/minimax-h3-fastvideo)**: FastVideo sparse-attention checkpoints

## Key features

- **Native stereo audio**: Dialogue, SFX, and music in one MP4
- **Multimodal context**: Combine text, image, video, and audio references
- **Reference-driven generation**: Lock identity, style, motion, camera, or voice from references
- **Instruction following**: Describe reference-to-shot relationships in natural language
- **Accurate text rendering**: Clean spelled-out text and brand elements
- **Open weights**: Full local control in ComfyUI

## Getting started

1. Update ComfyUI: base T2V/I2V/R2V templates need **0.30.0+**; Multiframe Reference **0.34.0+**; Fun ControlNet Union, sparse attention, and Model Attention Backend **0.35.0+**; FastH3 **0.36.0+**
2. **Template Library** > **Video** > pick a MiniMax H3 workflow
3. Download models from the pop-up (tens of GB; allow time and disk space)

Weights live on Hugging Face: [Comfy-Org/MiniMax-H3](https://huggingface.co/Comfy-Org/MiniMax-H3).

<Note>
Use **pruned** checkpoints when both full and pruned builds exist. Pruned builds store adaln in a shared curve table (`adaln_t_table`) that ComfyUI reads from the file; templates load `minimax_h3_*_pruned_int8_convrot.safetensors`. LoRAs distilled on **full** builds carry adaln tensors that do not exist on pruned builds (shape mismatch; those weights are skipped). Turbo LoRAs have no adaln tensors and work on either build.
</Note>

## Choosing the checkpoint precision

Pick the smallest build that fits in VRAM. Change only the `UNETLoader` file; ComfyUI reads quantization from the checkpoint. LoRAs must match the build family (full-build LoRAs lose adaln on pruned).

| Build (fl2va / ref2va) | Size | Notes |
| --- | --- | --- |
| [`pruned_w6a8`](https://huggingface.co/Comfy-Org/MiniMax-H3/blob/main/diffusion_models/minimax_h3_fl2va_pruned_w6a8.safetensors) | 16 GB | Smallest; INT8 path; ComfyUI 0.38.0+ |
| [`pruned_int8_convrot`](https://huggingface.co/Comfy-Org/MiniMax-H3/blob/main/diffusion_models/minimax_h3_fl2va_pruned_int8_convrot.safetensors) | 21 GB | Default in templates |
| [`pruned_fp8_scaled`](https://huggingface.co/Comfy-Org/MiniMax-H3/blob/main/diffusion_models/minimax_h3_fl2va_pruned_fp8_scaled.safetensors) | 21 GB | Same size as INT8 |
| [`pruned_bf16`](https://huggingface.co/Comfy-Org/MiniMax-H3/blob/main/diffusion_models/minimax_h3_fl2va_pruned_bf16.safetensors) | 40 GB | Unquantized pruned |
| [`bf16`](https://huggingface.co/Comfy-Org/MiniMax-H3/blob/main/diffusion_models/minimax_h3_fl2va_bf16.safetensors) | 66 GB | Full unquantized build |

Links are `fl2va` (T2V/I2V); `ref2va` files are in the same folder at the same sizes. **Comfy Kitchen attention cannot run `int8_convrot` checkpoints**; use a `bf16` build with that backend.

If VRAM is tight, step down a size: CPU offload costs more than precision tradeoffs. On RTX 30-series, INT8 matrix ops are ~2× FP16 and there is no FP8 path, so INT8 often beats FP8 at the same file size.

H3 also needs video and audio VAEs: [video fp16 / int8_convrot](https://huggingface.co/Comfy-Org/MiniMax-H3/tree/main/vae) and [audio fp32](https://huggingface.co/Comfy-Org/MiniMax-H3/blob/main/vae/minimax_h3_audio_vae_fp32.safetensors). Templates use int8 video + fp32 audio; int8 video decodes ~2× faster on ComfyUI 0.36.0+. Swap files on `VAELoader` like the diffusion model.

## Setting the output resolution

**Resolution Selector** sets `width` and `height` on the H3 node:

- **Aspect ratio**: Presets such as `16:9 (Widescreen)`, `9:16 (Portrait Widescreen)`, `1:1 (Square)`
- **Megapixels**: Total pixel count (higher = larger, slower)
- **Multiple**: Round to this grid; keep **32** for H3

Templates open at **Megapixels** **0.4**: **864×480** at 16:9, **640×640** at 1:1 (the I2V default). A 0.4 MP render is fast and fine for drafts; raise **Megapixels** before a final render.

For 16:9 native quality, set **0.98** (~1344×768) or enter **1344 × 768** on the node. Avoid **1.0** MP (1376×768 exceeds the 768×1344 cap). H3 is trained near 1 MP; oversizing does not add detail. For 2K, generate at native size and upscale separately.

### Upscaling to higher resolution

Use a **latent upscaler** on the 24-channel video latent to avoid VAE round-trip ghosting. [Minimax_h3_latent_Upscaler](https://huggingface.co/LBH-123-AI/Minimax_h3_latent_Upscaler) (unofficial) needs [minimax_h3_latent_upscaler_3d_conv_v1_bf16.safetensors](https://huggingface.co/LBH-123-AI/Minimax_h3_latent_Upscaler/blob/main/minimax_h3_latent_upscaler_3d_conv_v1/minimax_h3_latent_upscaler_3d_conv_v1_bf16.safetensors) in `ComfyUI/models/latent_upscale_models/` and its [custom node](https://github.com/LBH-123-AI/Comfyui_Minimax_h3_latent_Upscaler). Chain **Minimax H3 Latent Upscaler (3D)** after a low-res pass (`scale` 1.0–4.0, default 2.0), then re-sample at target resolution.

Latent upscale saves time, not peak VRAM (refine still runs at target size). Treat refine as partial denoise: `denoise` **0.1–0.5** keeps composition; go higher only to rework the first pass. Give the refine sampler enough steps to rebuild multistep history (see Sampler and scheduler).

Video and audio latents are separate (24 + 32 channels). The upscaler only spatially enlarges video; audio is unchanged until refine denoises both. Low refine `denoise` preserves first-pass audio. To keep audio exactly, decode the first pass with `VAEDecodeAudio` before refine and wire that track into final `CreateVideo` (add `SaveAudioAdvanced` for a lossless export).

## Clip length

H3 is trained on short clips; native nodes accept a wider range without blocking over-length requests.

Templates expose `duration` in seconds, converted to frames on the `17k+5` grid at 24fps.

| Setting | Range |
| --- | --- |
| `length` input | 5–3600 frames (~0.2 s–150 s) |
| Trained range | ~124–362 frames (~5–15 s) |
| Frame grid | `17k+5` at 24 fps (124 frames ≈ 5.2 s) |
| Template default | 5 s → 124 frames |

`duration` and `length` round **up** to the next `17k+5` value: a 5 s request renders 124 frames (5.17 s), and a `length` of 120 also renders 124. Frames pack from frame 0 in 17-frame blocks, so the leftover 5 frames are the last block, not the first. Requests that fall between the same two grid points render the same clip.

Long clips at full resolution exhaust VRAM first; lower megapixels to fit.

### Chaining clips

Beyond the trained range, chain I2V continuations from each clip's last frame. Errors compound (faces lose texture first); turbo/distilled schedules show burn sooner.

Use `video_minimax_h3_i2v_continuation` (empty prompt): load the previous last frame, describe the next segment. Prefer short continuous shots and cut before burn shows. For longer chains, [H3-Anti-Burn-LoRA](https://huggingface.co/Imagineer13/H3-Anti-Burn-LoRA/blob/main/h3_antiburn_universal_v1.safetensors) on clips after the first at `strength_model` ~0.5 (tune for your continuation style).

## Step count

Defaults (Lightning LoRA **off**): **20 steps**. With turbo on: **8** for T2V/I2V (and continuation), **4** for R2V, Multiframe, and Fun ControlNet. On T2V/I2V subgraphs, `turbo_mode`, `turbo_steps`, and `turbo_model_strength` control the distilled LoRA. A 4-step fl2va file is also listed: [`minimax_h3_fl2v_turbo_4step_v1.0_768p_comfyui_bf16.safetensors`](https://huggingface.co/Comfy-Org/MiniMax-H3/blob/main/loras/minimax_h3_fl2v_turbo_4step_v1.0_768p_comfyui_bf16.safetensors) with `turbo_steps` **4**.

Reference shots need more steps: reference tokens ride every step, so 4-step turbo can barely apply references (pose/face drift). For tight reference match, keep turbo off or raise toward **25**.

Distilled schedules smooth fine detail (skin, fabric, hair) vs 20-step base. Each turbo file is mode-specific; test at a fixed seed before stacking style LoRAs. `turbo_steps` and `turbo_model_strength` are adjustable: higher steps + lower strength (less than 1) move back toward base quality and cost time. Example: 4-step file at 6–8 steps, strength ~0.8.

Turbo LoRAs shorten the schedule, not per-step time (merged at load). Running a 4-step LoRA at 20 steps takes about as long as base 20 steps.

Guidance by content:

- Simple shots: **12–16** steps often enough
- High-frequency detail (chainmail, filigree, many small objects): improves up to ~**50**; below that, triangular grid artifacts under motion (worse with turbo)
- Most motion/prompt gains by step **16**; little visible change past **50**
- Soft frames at native resolution are usually a resolution issue, not steps

Audio converges later than video in the joint denoise. Speech and timbre need **12+** steps; at **8** steps audio is often the weak link.

## Sampler and scheduler

Templates use **`res_multistep`** + **`simple`**. T2V/I2V/FastH3 hide these inside the subgraph; R2V, Multiframe, and Fun ControlNet expose `KSamplerSelect` and `BasicScheduler` on canvas.

`res_multistep` is second-order multistep (first step is Euler). Splitting the schedule across two samplers drops multistep history: the second sampler's first step is first-order again. Keep one sampler run, or give the second enough steps to warm up.

Default H3 shifts are `shift` **12** and `audio_shift` **3** from the model definition (no extra node). FastH3 templates set **ModelSamplingMiniMaxH3** to `shift_video` **10**, `shift_audio` **3**. Wrong video shift on distilled builds (e.g. **3** instead of **10** on 8-step) can show grid artifacts. Custom finetunes may need their own pair on **ModelSamplingMiniMaxH3** (see the file's model card). [DMAD 4-step LoRA](https://huggingface.co/ZhengmingYu/DMAD/blob/main/minimax_h3/dmad_minimax_h3_4step_full_critic_comfyui.safetensors) uses `shift` **12**, `audio_shift` **2**, **`lcm`** + **`simple`**.

## Speeding up generation with Sage Attention

[Sage Attention](https://github.com/woct0rdho/SageAttention) can roughly **2×** speed with small quality impact (optional install):

1. `pip install` the wheel matching your PyTorch/CUDA from [releases](https://github.com/woct0rdho/SageAttention/releases)
2. Install [KJNodes](https://github.com/kijai/ComfyUI-KJNodes) for `Patch Sage Attention KJ`
3. Insert between `UNETLoader` and `BasicGuider`; set `sage_attention` to `auto`
4. Or launch with `--use-sage-attention`

Sage needs float16/bfloat16; some H3 layers use other dtypes and fall back to PyTorch attention (console warnings are normal).

### Quality degradation with INT8 attention

End-of-clip morphing or garbled on-screen text with Sage often comes from INT8 attention quantization (hot channels in late blocks).

- Templates use **`int8_convrot`** checkpoints. **Comfy Kitchen does not support them** ([issue #15529](https://github.com/Comfy-Org/ComfyUI/issues/15529)). Use default attention, or switch `UNETLoader` to **`pruned_bf16`** then change backend.
- On **bf16** checkpoints, **Comfy Kitchen attention** (channel rotation before quantize) clears artifacts at similar speed.

Add **Model Attention Backend** (`comfy kitchen attention`) on the model path to `BasicGuider` (after LoRA/turbo), or use `--use-ck-attention` (0.32.0+). Requires `comfy-kitchen` INT8 kernels on your hardware.

## Speeding up generation with sparse attention

**Model Sparse Attention** (0.35.0+, experimental) cuts attention cost on long clips. For base H3 use `method` **`sol-attn`** (`sla`/`vsa` need matching weights). Needs CUDA + `sol_attn` from `comfy-kitchen`; otherwise layers stay dense.

- Defaults `start_percent` **0.2**, `end_percent` **1.0**. Later start (~**0.4**) and earlier end (~**0.9**) protect opening/closing frames.
- Keep **`sink_conditioning`** at **`exact_kv_and_rows`** on H3 (protects packed text/audio/reference rows).
- **`tau`**: higher = sparser/faster (`1.0` ~16% exact blocks, `1.3` default, `2.0` ~2.7%).
- Short sequences below `min_tokens` (default **12288**) see little gain.

FastH3 uses **`vsa`** at `keep_percent` **10**; see [FastH3 page](/tutorials/video/minimax/minimax-h3-fastvideo).

### Checking whether sparse attention is active

Base H3 templates do not include the node. Add **Model Sparse Attention** between `UNETLoader` and `BasicGuider`, then turn on **`verbose`** (Advanced, off by default) to log one line per attention shape.

Calls that stay dense log `dense (<n> tokens): <reason>` or `dense (<b>, <n>, <h>, <d>): <reason>`. Only the first failing condition is reported:

| Logged reason | What to change |
| --- | --- |
| `no compiled sol_attn kernel for this GPU` | The installed `comfy-kitchen` has no kernel for your GPU. Update it, or leave the node out on that machine. |
| `<n> tokens < min_tokens <value>` | Raise the resolution or clip length, or lower `min_tokens` (default **12288**). |
| `sigma <x> outside the start/end window` | Widen `start_percent` and `end_percent`. |
| `block <i> in dense_blocks` | Remove that block index from `dense_blocks`. |
| `no H3 layout for this call` | `vsa` only. Select `sol-attn`. |

Calls that succeed log `sparse (<b>, <n>, <h>, <d>), sinks <k>/<q>` or `sparse producer path: <n> tokens, <mode>`.

Three conditions never log, even with `verbose` on: activations that are not bfloat16 on the H3 path, a `head_dim` other than **128**, and missing rope frequencies all fall back silently.

`vsa` is bound to the FastH3 checkpoint. It reads a learned coarse branch from `to_gate_compress` layers that only those weights carry, so on any other H3 checkpoint the node prints `VSA: the model has no to_gate_compress layers; running the fine stage without the coarse branch` and runs the fine stage alone. That warning is not gated by `verbose`.
