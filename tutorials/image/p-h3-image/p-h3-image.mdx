**P-H3-Image** is Pruna AI's open-weights image model built on [MiniMax H3](/tutorials/video/minimax/minimax-h3). It handles two tasks in one checkpoint: text-to-image generation and image editing. A full image takes 8 sampling steps with no classifier-free guidance, at 8 megapixels by default.

The model leans toward photographic and film looks: documentary and editorial photography, portraits with real skin texture, TV-frame anime, screen-printed posters, and flat graphic design with short quoted text. A prompt upsampler based on Qwen3.5-9B rewrites a one-line request into the detailed prompt the model renders best, and returns that rewritten prompt so you can read it before it reaches the sampler.

In ComfyUI, P-H3-Image runs as two workflow templates, one for text to image and one for image editing. It reuses the MiniMax H3 diffusion model and adds Pruna's text encoder, prompt upsampler, VAE and LoRA, about 35 GB of model files in total. The int8 files fit in about 21 GB of VRAM.

**Model Highlights**
- **8 steps, no CFG**: One distilled sampling schedule and a single positive conditioning, with no negative prompt
- **8 megapixels**: Square, 4:3, 3:2, 16:9 and their portrait versions, up to 3872 x 2176
- **Prompt upsampler built in**: Your one-line request is expanded into a full prompt, and the expanded prompt is shown in the workflow
- **Editing with references**: The first image is the one being edited, and further images become `<Picture 2>`, `<Picture 3>` and so on in the prompt
- **Image only**: P-H3-Image does not generate video or audio

## Requirements

- ComfyUI 0.44.0 or later. Both templates use the PH3ImageConditioning node added in 0.44.0
- About 35 GB of model files. The diffusion model is the same one the MiniMax H3 workflows use, so you may already have it
- A GPU with about 21 GB of VRAM for the int8 files

P-H3-Image is released under the MiniMax H3 Community License, which excludes some regions unless you hold a separate license from MiniMax. For commercial use, request a license through [Comfy](https://comfy.org/minimax/license).

Write the request after `Request:` in the prompt box, and keep the `Aspect ratio:` line in sync with the Resolution Selector. The selector is set to 8 megapixels with a multiple of 32, which gives these canvases:

| Selector ratio | Size at 8 MP, multiple 32 |
| :--- | :--- |
| 1:1 (Square) | 2912 x 2912 |
| 4:3 (Standard) | 3360 x 2496 |
| 3:2 (Photo) | 3552 x 2368 |
| 16:9 (Widescreen) | 3872 x 2176 |
| 3:4 (Portrait Standard) | 2496 x 3360 |
| 2:3 (Portrait Photo) | 2368 x 3552 |
| 9:16 (Portrait Widescreen) | 2176 x 3872 |

- **Sampling**: 8 steps are the model's own schedule. More steps do not add detail, and there is no CFG or negative prompt to tune
- **Seed**: set to `randomize` for new images and back to `fixed` to reproduce the shipped example
- **Upsampled prompt**: the Preview Any node shows the rewritten prompt. It is worth reading before you change the request

Load the image you want to change into the `Load Image` node and describe the result after `Request:`. The output follows the shape of that image, so the width and height inputs on the conditioning node stay at 0.

- **Source size**: the edit is rendered at the size of the first image, scaled up to at least 4 megapixels
- **More references**: connect additional images to add `<Picture 2>`, `<Picture 3>` and further references to the prompt
- **What to keep**: name what must not change. Without that, the model tends to redraw the whole scene

## Prompting tips

1. **Say what the image is**: Open with one sentence that names the real object, for example "a photograph by an experienced street photographer" or "a two-color risograph print". This sets the look more reliably than style words
2. **Describe one scene**: Give a viewpoint, one main subject caught in a moment, a few supporting elements, and light with a source and a direction
3. **Quote every string of text**: Text without its exact words turns into pseudo-text. Put each string in quotes, keep it short, say where it sits, and end with "no other text"
4. **Leave out hype words**: Words like stunning, epic, cinematic or 8k push the model toward a glossy, oversaturated look

## Limitations

- **Lower resolutions show more artifacts**: Faces, hands and small details break more often at 2 and 4 megapixels than at 8
- **Hands and background people can break**: Small people in the background can come out distorted. Rendering at 8 megapixels helps
- **Text is not fully reliable**: Short quoted strings render well, but dense text such as body copy or long code turns into pseudo-text
- **Prompt sensitive**: Very long prompts make images worse, and very short prompts give weak results without the upsampler
