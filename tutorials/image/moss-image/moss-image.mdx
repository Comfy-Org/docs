## About MOSS-Image

MOSS-Image is OpenMOSS's open-weights text-to-image model: a 5B single-stream DiT that turns a full scene caption into one finished image. It is strongest where text and placement matter, because it renders English and Chinese typography, accepts prompts of up to about 4K tokens, and can read a JSON layout that says where each object and each line of text belongs. Weights ship under Apache 2.0, so you download once and run on your own GPU with no API key and no per-image credits.

The family has two checkpoints. The instruction-tuned **SFT** checkpoint is the one the templates load: it groups text and lays out scenes more cleanly. The **Base** checkpoint has no post-training or CFG distillation, which makes it the starting point for community LoRAs. Both run in the same graph, so switching checkpoints is a single loader change.

In ComfyUI the model runs from single-file checkpoints in int8 and bf16, with a Qwen3.5 9B text encoder loaded as type `moss_image` and the FLUX.2 small VAE. The text to image templates also ship a prompt enhancer that rewrites a short request into a full caption before sampling, using the same text encoder the model already needs.

**Model highlights:**

- 5B single-stream DiT with bilingual English and Chinese text rendering
- Native layout guidance: draw boxes, give each box a caption, and text boxes render their own text
- Prompt enhancer built into the text to image templates, so a one-line idea is enough
- Two checkpoints: SFT for cleaner layouts, Base for fine-tuning and LoRA work
- Long prompts of roughly 4K tokens, and canvas sizes in multiples of 16

### MOSS-Image: Layout-Guided Text to Image {#image_moss_image_t2i_bboxes}

Generate an image from a prompt plus a layout you draw. Open `Create Bounding Boxes` and drag a box for each element; each box carries its own caption, and boxes marked as text render that text inside them. `MOSS-Image Layout Prompt` turns the boxes into the layout prompt the model reads, so the caption in the box and your scene prompt are both used.

Draw the background box first and the foreground elements last: boxes are emitted in the order you draw them. Each box is labelled `text` if you mark it as text, otherwise `object`. To label a box that holds a person as a character, list its number from the `Create Bounding Boxes` preview in `character_boxes` on `MOSS-Image Layout Prompt`, for example `1, 3`. Numbers that point at a text box have no effect. Both layout templates ship this field filled in (`2` in SFT, `1` in Base), so check it against your own boxes before queueing.

With at least one box connected, `MOSS-Image Layout Prompt` outputs a JSON prompt: a scene caption plus one item per box. The layout templates ship `enable_prompt_enhancer` off, so that JSON reaches the model unchanged. Turning it on lets the prompt enhancer rewrite the text, which can drop the boxes.

#### Tips on editing

- **Phrase the change the way the LoRA was trained.** `Change only the X to Y. Keep the character, face, hair, pose, background and composition unchanged.` works best. A vague instruction like "improve it" gives the model too much freedom.
- **Keep `edit_format` on `Moss-Image-Edit`.** Both encode nodes must carry the value the LoRA was trained with. A different value still returns an image, but identity, framing and fine detail drift away from the source.
- **Keep CFG at 4.0.** The negative branch matters for this LoRA. Lower values can add accessories such as a necklace that were not in the source photo.
- **Connect up to four references.** The encode nodes grow extra slots when you connect them, so a garment, a face and a prop can each go in separately. State in the prompt what each one is for.

#### Tips on control

- **`Render MoGe Geometry` uses the mask by default.** Only the silhouette is controlled. Switch it to `depth` when the face profile, shoulders and background falloff should follow the reference too: the pose gets tighter and the prompt has less room.
- **`end_percent` sets how long the map is held.** At 0.6 the last steps render surface and lighting freely. At 1.0 geometry stays pinned to the final step.
- **The LoRA is what makes the map work.** The control adapter is loaded just before the control node, and without it the node has no effect.
- **Paint a map by hand when the estimate is wrong.** `Painter` is already in the graph: connect its output to `depth_map`, white near and black far. `color_map` is unconnected by default, takes one flat colour per region, and must match the output size.

## Prompting tips

- **Describe the finished image, not the request.** The model was trained on captions, so write what the picture looks like rather than an instruction like "make me a poster". The prompt enhancer follows the same rule, which is why a short prompt still works.
- **Base reads tag sequences.** With the prompt enhancer off, MOSS-Image-Base accepts comma-separated tags as well as captions, in the documented order: quality, score, meta, year, character, series, artist, then general tags, for example `best quality, highres, hatsune miku, vocaloid, @foo bar, 1girl, blue hair`.
- **Turn the prompt enhancer off to control the wording.** Set `enable_prompt_enhancer` to `false` on the subgraph node and your prompt goes to the model unchanged. With the prompt enhancer on, `prompt_enhancer_seed` changes how the prompt is rewritten. Both settings show the result in `Preview Any`, so you can compare.
- **Control line breaks yourself.** Automatic breaks may not land where you want them. Put real newlines or `\n` in the text you want rendered when the position of a break matters.
- **Use the layout workflow when placement matters.** Boxes give the model an explicit position for each element and each block of text, which is more reliable than describing positions in prose.
- **Keep the canvas in the recommended range.** `ResolutionSelector` picks the aspect ratio and the megapixel count (1 MP by default). 1 MP to 2 MP is the recommended output range and the model extrapolates from about 0.25 MP to 4 MP; width and height must be multiples of 16.
- **Start from the template settings, then go slower for the official look.** The templates run 25 steps at CFG 2.5 with the `er_sde` sampler. The official Base settings are 50 steps at CFG 3 with the `euler` sampler, so try those if a result is undercooked.
- **Raise CFG for short prompts on Base.** The official CFG range for MOSS-Image-Base is 3.0 to 6.0, above the 2.5 the templates ship. Turn the prompt enhancer off for a short prompt to reach the model, keep 3.0 for a long one, and raise it as needed.
- **Keep the negative prompt short.** The templates ship `nsfw, worst quality, bad anatomy, watermark, jpeg artifact`.
- **Skip layer guidance runs at layer 22.** The subgraph node carries an `SLG` toggle, and 22 is the official layer. Turning it off can look more realistic but may collapse detail; other layers are only reachable inside the subgraph.
- **Base is for fine-tuning.** When you train a LoRA on MOSS-Image, freeze the text encoder.

## Going above 2 MP

The recommended output range is 1 MP to 2 MP, and the model extrapolates to about 4 MP. Anything larger is outside that range, so build large images from successive passes instead of one big canvas.

The templates feed a fixed `Empty Flux 2 Latent` to the sampler, so this needs an edit inside the subgraph:

1. Render the first pass at 1 MP or 2 MP.
2. Decode the result, resize it in pixel space with `Upscale Image`, then encode it again with `VAE Encode`. Upscaling the latent resamples it directly and loses detail the second pass cannot recover.
3. Feed the encoded latent to the sampler in place of `Empty Flux 2 Latent` and set `denoise` to about 0.6 for a 1.5x step. Lower keeps the first pass intact, higher reworks the composition.

Repeat the resize and re-render instead of jumping to the final size. A single jump from 2 MP to 8K tends to repeat detail rather than add it, and an 8K canvas needs `VAE Decode (Tiled)`.

## Reference images and the prompt enhancer

The subgraph node has an optional `ref_image (for llm)` input. It reaches the prompt enhancer, not the diffusion model: MOSS-Image has no image input, so it cannot copy a reference. With the prompt enhancer on, the image shapes the caption it writes; with the prompt enhancer off, the image is ignored.

The prompt enhancer runs on the Qwen3.5 text encoder the model already loads, through `Generate Text`, with a system prompt written from the official MOSS-Image prompt enhancer skill. Its output length is `max_length`, 4096 tokens in the templates. In the `MOSS-Image: Text to Image` and `MOSS-Image Base: Text to Image` templates, `prompt_enhancer_seed` reproduces a caption, and `Preview Any` shows the text that actually reaches the sampler.
