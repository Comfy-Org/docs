Patina generates the surface data a 3D asset needs. One run returns a base texture plus the basecolor, normal, roughness, metalness and height maps that a PBR material expects, and the whole set comes from the same latent, so the maps line up pixel for pixel instead of needing a separate bake.

In ComfyUI the provider runs through three partner nodes. **Patina Material** builds a material from a text prompt, from a photo, or from a photo plus a mask. **Patina Material Extract** pulls a tiling material out of a photo that already contains the surface you want. **Patina PBR Material Maps** converts one image into the map set without regenerating anything.

All three are cloud API nodes. They need a Comfy account with credits, download no model files, and bill per run, with every map you switch on adding to the price. See [Partner node pricing](/tutorials/partner-nodes/pricing) for current rates.

## Available workflows

### Material Extract: photo to tiling material {#api_patina_material_extract}

Point the node at a photo that already contains the material and the prompt says which surface to pull out and what structure to keep. The texture comes back seamless, so it repeats across a large surface without a visible border.

### Material: text to material {#api_patina_material_t2m}

Describe the surface and get a complete material back, with no source image at all. The prompt carries the whole result, so name the pattern and the finish rather than the object it belongs to.

### Material: image to material {#api_patina_material_i2m}

Connect a surface photo and Patina redraws it as a tiling material, keeping the pattern from the image. `strength` decides how far it moves away from the photo: low keeps the original texture, high rewrites more of it.

### PBR Maps: image to map set {#api_patina_pbr_maps}

Derive the maps from an image that is already the material. Nothing is regenerated here: the maps describe exactly what the picture contains, so seams, perspective and lighting in the source stay in the result.

This node does not tile. Use it when you already have a seamless basecolor and want the rest of the set, and use Material or Material Extract when the result has to repeat. Inputs up to 2048 px are accepted; larger images are scaled down unless you turn off `auto_downscale`.

## Node controls

| Control | Values | Applies to | Effect |
| --- | --- | --- | --- |
| `prompt` | text | all three nodes | Names the surface or material. On Extract, says which part of the photo to pull out |
| map toggles | `basecolor`, `normal`, `roughness`, `metalness`, `height` | all three nodes | Which maps are returned. Basecolor and normal are on by default, the rest are off, and each enabled map adds to the run price |
| `image_size` | `1:1 (1024x1024)`, `1:1 (512x512)`, `4:3 (1024x768)`, `3:4 (768x1024)`, `16:9 (1024x576)`, `9:16 (576x1024)`, `custom` | Material, Material Extract | Output size. `custom` takes a width and height from 512 to 2048 in steps of 16 |
| `upscale_factor` | `0`, `2`, `4` | Material, Material Extract | Seamless upscaling of the maps. The base texture is not upscaled, and `4` reaches 8K map output from a 2K run |
| `strength` | 0.01 to 1.0, default 0.6 | Material, Material Extract | How far the result may move away from the source photo. Ignored on text to material |
| `tiling_mode` | `both`, `horizontal`, `vertical` | Material, Material Extract | Tiling direction |
| `num_inference_steps` | 1 to 8, default 8 | Material, Material Extract | Denoising steps. There is nothing to gain above 8 |
| `tile_size` | 32 to 256, default 128 | Material, Material Extract | Tile size in latent space: 64 is about 512 px, 128 about 1024 px |
| `tile_stride` | 16 to 128, default 64 | Material, Material Extract | Tile stride in latent space |
| `prompt_expansion` | off by default | Material, Material Extract | LLM rewrite of the prompt. Keep it off unless the prompt is thin, because expansion reframes the prompt as a photo and tends to wash out the metalness map |
| `seed` | integer | all three nodes | Rerun control. Results are non-deterministic |
| `auto_downscale` | on by default | PBR Maps | Scales an input whose longest side is over 2048 px back to 2048 px. Turn it off to get an error on oversized images instead |

Outputs follow a fixed slot order. Material and Material Extract return `texture`, `basecolor`, `normal`, `roughness`, `metalness`, `height` and `expanded_prompt`. PBR Maps returns the five maps without a separate base texture.

## Tips

- **Name the surface, not the scene.** On a photo of a chair, "chair webbing fabric" extracts the woven straps and ignores the frame, the floor and the paddle in shot.
- **Add structure when the pattern drifts.** On Extract, a clause like "keep the weave and the strap edges" stops the pattern from wandering between runs.
- **Pick the material that repeats inside a few hundred pixels.** Webbing, brick, pavers, planks and plaster tile well. A rock cliff, an aerial terrain or a single object come back as a repaint that will not tile.
- **Turn maps off before you run.** Three maps are usually enough for a game or a product material, and the price follows the number of maps.
- **Chain Extract into PBR Maps for a full set from one photo.** Extract makes the basecolor tile, then PBR Maps derives the remaining maps from it.
- **Generate the map, then check the metalness on metals.** Prompt expansion is the usual reason a metal surface comes back flat.

## Get started

1. Update ComfyUI to the latest version
2. Go to Template Library, search for `Patina`
3. Pick the workflow that matches your input: Extract for a photo of a surface, Text to Material for a prompt only, Image to Material for a photo to redraw, PBR Maps for an existing basecolor
4. Switch off the maps you do not need, then run the workflow
