## 概要

**APIキーとシークレット**は、Comfy Cloud がお客様に代わって使用するプロバイダーの API キーを保存する Comfy Cloud の設定パネルです。シークレットの値は保存時に暗号化され、その値が再び表示されることはありません。

このパネルでは2種類の認証情報を扱います。

- **モデルプロバイダーの認証情報**: Hugging Face または Civitai のトークンで、インポート時にプライベートモデルやゲート付きモデルをダウンロードするために使用します。インポートの流れ全体については[モデルのインポート](/ja/cloud/import-models)を参照してください。
- **BYOKプロバイダーキー**: Runway または Google Gemini のキーで、パートナーノードの呼び出しを自分のプロバイダーアカウントで実行できるようにします。詳細は [BYOKプロバイダーキー](#byok-provider-keys) を参照してください。

## シークレットパネルを開く

1. [Comfy Cloud](https://cloud.comfy.org) にログインします。
2. `Ctrl + ,`（macOS では `Cmd + ,`）で設定ダイアログを開くか、Comfy Cloud メニューの **設定** をクリックします。
3. 設定サイドバーで **シークレット** を選択します。

このパネルは、シークレットが有効になっているログイン済みのアカウントに表示されます。

![Comfy Cloud 設定ダイアログのシークレットセクション](/images/cloud/import_model/setting_secerts-1.png)

リストには、保存されているすべてのシークレットが、その名前、プロバイダー、作成日、および最後に使用された日付（その情報が利用可能な場合）とともに表示されます。

## シークレットを追加

<Steps>
  <Step title="新しいシークレットの作成を開始">
    **シークレットを追加** をクリックします。
  </Step>
  <Step title="プロバイダーを選択">
    **プロバイダー** ドロップダウンからプロバイダーを選択します。リストは Comfy Cloud から読み込まれるため、後から追加されたプロバイダーも自動的にここに表示されます。プロバイダーを選択すると、そのプロバイダー独自のガイダンスが表示されます。たとえば、Runway の APIキーの場所や、Google AI Studio で Google Gemini のキーを生成する方法などです。
  </Step>
  <Step title="認証情報の種類を選択">
    複数の種類の認証情報を受け付けるプロバイダーでは、**認証情報の種類** セレクターが表示されます。ほとんどのプロバイダーはテキスト形式の単一の APIキーを使用します。一部のプロバイダーは代わりに JSON 認証情報を使用します。JSON を貼り付けるか、ファイルをアップロードしてください。JSON オブジェクトは最大 1 MB です。
  </Step>
  <Step title="シークレットに名前を付ける">
    任意の名前を 255 文字以内で入力します。名前は一意である必要があり、各プロバイダーは 1 つのシークレットを保持できます。
  </Step>
  <Step title="値を入力">
    キーまたは認証情報を貼り付けます。値は保存時に暗号化され、再度表示することはできないため、ご自身でコピーを保管しておいてください。
  </Step>
  <Step title="保存">
    **保存** をクリックします。Comfy Cloud はその認証情報をすぐに使用できます。
  </Step>
</Steps>

![名前、プロバイダー、シークレット値の各フィールドを備えたシークレットを追加ダイアログ](/images/cloud/import_model/setting_secerts-2.png)

## シークレットの管理

- **編集**: シークレットの編集アイコンをクリックすると、名前の変更や値の置き換えができます。値を空欄のままにすると現在の値が保持され、シークレットの作成後にプロバイダーと認証情報の種類を変更することはできません。認証情報を別のプロバイダーに移すには、シークレットを削除して新しいシークレットを追加します。
- **削除**: 削除アイコンをクリックして確認します。シークレットの削除は永続的で、元に戻すことはできません。

## BYOKプロバイダーキー {#byok-provider-keys}

Bring your own key（BYOK）では、パートナーノードがComfyのクレジットではなく、ご自身のプロバイダーアカウントで実行されます。

- Comfy Cloudのパートナーノードでは、現在 **Runway** と **Google Gemini** でBYOKをサポートしています。その他のプロバイダーは、エンタープライズのお客様からのリクエストに応じて追加できます。
- BYOKはワークスペース単位で有効になり、ご自身のキーで実行されるパートナーノードの呼び出しは、Comfyのクレジットを消費するのではなく、そのプロバイダーから直接請求されます。
- ワークスペースでBYOKを有効にするには、[エンタープライズリクエストを送信](https://www.comfy.org/contact)してください。

ワークスペースでBYOKを有効にしたら、シークレットパネルでプロバイダーのAPIキーを追加します。その後、そのワークスペースにおけるそのプロバイダーのパートナーノード呼び出しは、ご自身のキーで実行されます。

## プライベートモデルの認証情報

シークレットに保存された Hugging Face または Civitai のトークンは、モデルをインポートする際に自動的に使用されます。これが、プライベートリポジトリやゲート付きリポジトリをダウンロードする方法です。トークンには、インポート元のリポジトリへの読み取りアクセスが必要で、インポートできるのは `.safetensors` ファイルのみです。手順の流れ、サポートされているモデルフォルダ、インポートの制限については、[モデルのインポート](/ja/cloud/import-models)を参照してください。

<Note>
  シークレットパネルは、サードパーティプロバイダーの認証情報を保存します。これは、Comfy Cloud API への呼び出しを認証する Comfy APIキーとは別のものです。[APIキーの取得](/ja/development/api-development/getting-an-api-key)を参照してください。
</Note>

## FAQ

<AccordionGroup>
  <Accordion title="自分のキーを使っても Comfy クレジットは消費されますか？">
    いいえ。ご自身の BYOK キーで実行されるパートナーノードの呼び出しは、そのプロバイダーから直接請求されるため、Comfy クレジットを消費しません。
  </Accordion>

  <Accordion title="BYOK ではどのプロバイダーを利用できますか？">
    Comfy Cloudのパートナーノードでは、現在 Runway と Google Gemini です。その他のプロバイダーは、エンタープライズのお客様向けに[エンタープライズ申請フォーム](https://www.comfy.org/contact)からリクエストに応じて追加できます。
  </Accordion>

  <Accordion title="ワークスペースで BYOK を有効にするにはどうすればよいですか？">
    BYOK はワークスペース単位で有効になります。[エンタープライズ申請を送信](https://www.comfy.org/contact)していただければ設定しますので、その後シークレットパネルでプロバイダーキーを追加してください。
  </Accordion>

  <Accordion title="保存した後にシークレット値を読み取ることはできますか？">
    いいえ。シークレットは暗号化されており、保存された値がインターフェースに返されることはないため、キーのコピーはご自身で保管してください。値は **編集** でいつでも置き換えられますし、シークレットを削除して新しく追加することもできます。
  </Accordion>

  <Accordion title="同じプロバイダーに 2 つ目のキーを追加できないのはなぜですか？">
    各プロバイダーが保持できるシークレットは 1 つです。そのプロバイダーの既存のシークレットを編集して新しいキーを追加するか、別のエントリーとして登録したい場合は先に既存のシークレットを削除してください。
  </Accordion>

  <Accordion title="認証情報の保存に失敗するのはなぜですか？">
    よくある原因は、名前の不足、255 文字を超える名前、すでに使用されている名前、またはシークレットがすでに存在するプロバイダーです。JSON 認証情報の場合、コンテンツが JSON オブジェクトとしてパースでき、1 MB 以内である必要があります。
  </Accordion>

  <Accordion title="トークンは保存されたのにプライベートモデルのインポートがまだ失敗します。どうすればよいですか？">
    インポート元のリポジトリへの読み取りアクセス権がトークンにあるか確認してください。プライベートまたはゲート付きリポジトリへのアクセス権がないトークンでは、そのモデルをダウンロードできません。
  </Accordion>
</AccordionGroup>
