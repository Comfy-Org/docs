ComfyUI の更新については、さまざまなインストール方法に沿って複数のセクションで説明してきましたが、この包括的なガイドではすべての更新手順を統合し、ユーザーが ComfyUI の更新方法を明確に理解できるよう支援します。

## ComfyUI の更新方法

<Tabs>
<Tab title="ポータブル">
ComfyUI ポータブル版では、簡単な更新のために便利なバッチスクリプトを提供しています。

 ### 更新スクリプトの場所
ポータブルインストールディレクトリ内の `update` フォルダーに、以下の更新スクリプトがあります：

 ```
 ComfyUI_windows_portable
 └─ 📂update
    ├── update.py
    ├── update_comfyui.bat                           // 最新開発バージョンに更新
    ├── update_comfyui_stable.bat                    // 最新安定バージョンに更新
    └── update_comfyui_and_python_dependencies.bat   // ⚠️ 危険：依存関係を再インストール - 競合を引き起こす可能性あり
```
<Warning>更新中は安定したインターネット接続を確保してください。</Warning>

<Warning>
**⚠️ 危険：`update_comfyui_and_python_dependencies.bat` は非常に注意して使用してください！**

このスクリプトは通常の更新よりも包括的で、以下を実行します：
- ✅ ComfyUI コード自体を更新
- ✅ PyTorch を更新（NVIDIA GPU CUDA 12.9 用）
- ✅ すべての Python 依存関係を再インストール

**リスク：**
- 既存の設定と依存関係の競合を引き起こす可能性
- 特定のパッケージバージョンに依存するカスタムノードを破損する可能性
- 手動で設定したパッケージを上書きする可能性

**⚠️ このスクリプトを使用するのは以下の場合のみ：**
- 依存関係の問題を修正する必要がある場合
- メジャーバージョンの更新を実行する場合
- 日常の更新には、代わりに `update_comfyui.bat` を使用してください

**このスクリプトを実行する前に：**
1. **ComfyUI インストール全体をバックアップ**
2. インストールしたカスタムパッケージのバージョンを文書化
3. 必要に応じてカスタムノードを再インストールする準備をする
</Warning>
</Tab>
<Tab title="デスクトップ">
Comfy デスクトップ版は、Comfy Engine をパッケージマネージャーとして使用し、ComfyUI を管理します。ComfyUI エンジンを更新するには、[管理パネル](/ja/installation/desktop/usage/manage#update-tab) のアップデートタブを開き、**安定版**（デフォルト）または **GitHub 最新版** の更新チャンネルを選択できます。

デスクトップアプリ自体の更新は自動で行われ、ComfyUI エンジンの更新とは別です。
</Tab>
<Tab title="手動インストール">
手動インストールされた ComfyUI は、更新を完了するために Git コマンドが必要です。

### 更新前の要件
システムに [Git](https://git-scm.com/downloads) がインストールされており、ComfyUI が Git clone 経由でインストールされていることを確認してください。

### 更新手順
<Steps>
<Step title="仮想環境をアクティブ化">
まず、ComfyUI の Python 仮想環境をアクティブ化します（使用している場合）：
```bash
# conda 環境の場合
conda activate comfyui

# venv 環境の場合
# Windows
venv\Scripts\activate
# macOS/Linux  
source venv/bin/activate
```
</Step>
<Step title="最新コードをプル">
ComfyUI インストールディレクトリに移動し、最新コードをプルします：
```bash
cd <ComfyUI-installation-path>
git pull
```
</Step>
<Step title="依存関係を更新">
ComfyUI の依存パッケージをインストールまたは更新します：
```bash
pip install -r requirements.txt
```
<Warning>
システムレベルの Python 環境を汚染しないよう、ComfyUI の仮想環境にいることを確認してください
</Warning>
</Step>
<Step title="ComfyUI を再起動">
更新後、ComfyUI を再起動します：
```bash
python main.py
```
</Step>
</Steps>

### バージョン切り替え（オプション）
特定のバージョンに切り替えるには、以下のコマンドを使用します：
```bash
# コミット履歴を表示
git log --oneline

# 特定のコミットに切り替え
git checkout <commit-hash>

# 最新バージョンに戻る
git checkout master
```
<Tip>最新の機能とセキュリティ修正のために定期的な更新を推奨しますが、システムの安定性のために安定バージョンを推奨します</Tip>
</Tab>
</Tabs>

## ComfyUI を更新する際に更新が必要なものは？

ComfyUI の更新は主に 2 つのコンポーネントで構成されます：
1. ComfyUI のコアコードを更新
2. ComfyUI のコア依存関係を更新（必要な Python 依存関係と ComfyUI 機能依存パッケージを含む）

**コアコード**：新しいノード、新しいモデルサポート、新機能など
**コア依存関係**：主に ComfyUI のフロントエンド機能、ワークフローテンプレート、ノードヘルプドキュメントなどを含む

```
comfyui-frontend-package   # ComfyUI フロントエンド機能
comfyui-workflow-templates # ComfyUI ワークフローテンプレート  
comfyui-embedded-docs      # ComfyUI ノードヘルプドキュメント
comfy-kitchen              # ComfyUI コアユーティリティ
comfy-aimdo                # ComfyUI コアユーティリティ
```

これらのコア依存関係は、別のリポジトリで管理されています：
- [ComfyUI_frontend](https://github.com/Comfy-Org/ComfyUI_frontend/) - フロントエンドインターフェースとインタラクティブ機能
- [workflow_templates](https://github.com/Comfy-Org/workflow_templates) - 事前構築されたワークフローテンプレート
- [comfyui-embedded-docs](https://github.com/Comfy-Org/embedded-docs) - ノードヘルプドキュメント
- [comfy-kitchen](https://github.com/Comfy-Org/comfy-kitchen) - 複数の計算バックエンドを持つ Diffusion 推論用の高速カーネルライブラリ
- [comfy-aimdo](https://github.com/Comfy-Org/comfy-aimdo) - AI モデル必要オフローディングアロケータ

開発バージョン（nightly）と安定バージョン（release）の違いを理解することが重要です：
- **開発バージョン（nightly）**：最新のコミットコード。最新機能にアクセスできますが、潜在的な問題を含む可能性があります
- **安定バージョン（release）**：安定リリースに基づいて構築。通常は開発バージョンより遅れますが、より高い安定性を提供します。機能のテストと安定化後に安定バージョンをサポートします

多くのユーザーは、更新中にリリースバージョンまたはデスクトップバージョンを使用していますが、必要な機能が開発バージョンでのみ利用可能であることに気づきます。そのような場合は、ローカルの `ComfyUI/requirements.txt` が [nightly バージョン依存関係](https://github.com/Comfy-Org/ComfyUI/blob/master/requirements.txt) と一致しているか確認し、すべての依存関係が最新機能をサポートしているかを判断してください。

## よくある更新の問題

### 不足しているまたは古いフロントエンド、ワークフローテンプレート、更新後のノード

<Tabs><Tab title="依存関係が適切に更新されていない">
    ユーザーは多くの場合、`git pull` コマンドのみを使用して ComfyUI コードをアップデートしますが、**コアとなる依存関係の更新を怠り**、以下のような問題が発生します。

  - フロントエンド機能の不足または異常
  - 新しく追加されたワークフローテンプレートが見つからない
  - ノードのヘルプドキュメントが古い、または不足している
  - 新機能に対応するフロントエンドサポートがない

  `git pull` コマンドを使用した後、対応する ComfyUI 環境で `pip install -r requirements.txt` を使用して依存関係を更新してください。
  </Tab><Tab title="依存関係の更新失敗">
    依存関係の更新が失敗する場合、通常はネットワークまたはコンピューターの権限の問題が原因です。更新中にコア依存関係の失敗が発生すると、システムは古いバージョンにフォールバックします。起動時には通常、次のようなログが表示されます：
    ```
    Falling back to the default frontend.
    ComfyUI frontend version: xxx
    ```

    次のトラブルシューティング手順に従ってください：
    1. 適切な環境で `pip list` を使用して、現在インストールされている依存関係パッケージを表示します。バージョンの不一致が見つかった場合は、ComfyUI環境で `pip install -r requirements.txt` を使用して依存関係の更新を再度試みてください。
    2. 更新後も問題が解決しない場合は、ネットワーク接続を確認してください。中国本土のユーザーは、GitHubリポジトリに確実にアクセスするためにプロキシを構成する必要がある場合があります。
    3. 問題が続く場合は、コンピューターの権限を確認してください。管理者権限が必要な場合は、管理者権限でコマンドラインを実行してください。
  </Tab>
</Tabs>

### コア依存関係更新のトラブルシューティング

コア依存関係の更新が失敗した場合は、次のトラブルシューティング手順に従ってください：

<Steps>
  <Step title="ネットワーク接続を確認">
    中国本土にいる場合は、PyPIにアクセスできるようにするか、国内ミラーを構成してください：
    ```bash
    # 清華大学ミラーを使用
    pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
    ```
  </Step>
  <Step title="コアパッケージを個別にインストール">
    バッチインストールが失敗する場合は、パッケージを個別にインストールしてみてください。**まず `ComfyUI/requirements.txt` でバージョン要件を確認してください**：
    
    **次に指定されたバージョンに従ってインストールします（requirements.txtのバージョン番号を使用）：**
    ```bash
    pip install comfyui-frontend-package==<version> 
    pip install comfyui-workflow-templates==<version>
    pip install comfyui-embedded-docs==<version>
    pip install comfy-kitchen==<version>
    pip install comfy-aimdo==<version>
    ```
    <Warning>
    `ComfyUI/requirements.txt` で指定された正確なバージョン番号を使用することを推奨します。互換性の問題が発生する可能性があるため、個別に最新バージョンにアップグレードしないでください。
    </Warning>
  </Step>
</Steps>

### 更新後に新機能が見つからないのはなぜですか？

これは最も一般的な問題の一つです：
- **デスクトップ版**を使用している場合、デスクトップ版は安定リリースに基づいて構築されているため、機能が遅れる可能性があります。
- **開発版（ナイトリー）**を使用していることを確認し、**安定版（リリース）**ではないことを確認してください。

さらに、更新プロセス中に対応する依存関係が正常に更新されていることを確認してください。更新後も問題が解決しない場合は、[依存関係更新のトラブルシューティング](#dependency-update-troubleshooting)セクションを参照して問題を診断してください。

### 開発版（ナイトリー）と安定版（リリース）の切り替え方法

バージョンの違い：

<Tabs>
  <Tab title="開発版（ナイトリー）">
    - **特徴**：最新のコミットコードを含む
    - **利点**：最新の機能と改善をいち早く体験できる
    - **リスク**：未発見のバグや不安定な要素が含まれている可能性がある
    - **適している対象**：開発者、テスター、最新機能を試したいユーザー
  </Tab>
  <Tab title="安定版（リリース）">
    - **特徴**：テストされ検証された安定したコード
    - **利点**：安定性が高く、本番環境に適している
    - **欠点**：機能更新に遅延があり、開発版より数週間から数ヶ月遅れる場合がある
    - **適している対象**：安定性を必要とするユーザー、本番環境ユーザー
  </Tab>
</Tabs>

<Tabs>
  <Tab title="ポータブル">
    `update_comfyui_stable.bat` の代わりに `update_comfyui.bat` を使用します：
    ```
    # 開発版（最新機能）
    ダブルクリック：update_comfyui.bat
    
    # 安定版
    ダブルクリック：update_comfyui_stable.bat
    ```
  </Tab>
  <Tab title="手動インストール">
    ```bash
    # 開発版に切り替え
    git checkout master
    git pull
    
    # 最新の安定版に切り替え
    git fetch --tags
    git checkout $(git describe --tags `git rev-list --tags --max-count=1`)
    ```
  </Tab>
  <Tab title="デスクトップ版">
    デスクトップ版は通常、安定リリースに基づいて構築されており、現在バージョンの切り替えはサポートされていません。最新機能が必要な場合は、以下をお勧めします：
    1. デスクトップ版の更新を待つ
    2. または、ポータブル版/手動インストールを使用して最新機能を体験する
  </Tab>
</Tabs>

### 更新後にエラーが発生した場合の対処法

1. **依存関係を確認**：`pip install -r requirements.txt` を実行して、すべての依存関係が更新されていることを確認します
2. **カスタムノードを確認**：一部のカスタムノードが新しいバージョンと互換性がない場合があります
3. **バージョンをロールバック**：問題が深刻な場合は、以前の安定版にロールバックできます

問題が発生した場合は、トラブルシューティングページを参照して解決策を見つけてください。
