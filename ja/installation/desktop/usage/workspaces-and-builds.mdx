Comfy Desktop は、チームが Comfy Developer Platform で共有している ComfyUI セットアップをインストールできます。たとえば、選択したモデルとカスタムノードを含む承認済みのビルドなどです。Developer Platform では、このセットアップはワークスペースが番号付きのバージョンで公開する Developer Platform Build であり、Comfy Desktop はそのうち 1 つのバージョンをチームビルドとしてコンピューターにインストールします。ワークスペースを選択し、そのビルドをインストールし、チームが新しいバージョンを公開したときに更新し、独自のビルドを Developer Platform にアップロードします。

Developer Platform で Build を作成し、そのバージョンを公開する方法については、[Adding Custom Builds to Comfy Cloud](/ja/development/deploy/cloud-custom-builds) を参照してください。

## ビルドの表示対象となるワークスペースを選択する

各ワークスペースにはそれぞれ独自のDeveloper Platform Buildsがあり、Comfy Desktopは一度に1つのワークスペースを表示します。チームのビルドを表示するには、まずログインしてください。[Comfy Cloudにログインして開く](/ja/installation/desktop/overview#ログインしてcomfy-cloudを開く) を参照してください。

**サイドバー**の下部で選択されているワークスペースによって、表示される内容が決まります:

- **ホーム**、**サイドバー**、**ビルド**ページ、およびビルドページには、そのワークスペース内のビルドのみが一覧表示されます。
- **新規ビルド**では、**チームのビルド**の下にそのワークスペースのDeveloper Platform Buildsが表示されます。**個人**ワークスペースには独自のビルドがあります。

ワークスペースを切り替えるには、[ワークスペースメニューを使用する](/ja/installation/desktop/usage/overview#ワークスペースメニューを使用する) を参照してください。Comfy Desktopは選択したワークスペースを記憶し、次回はそのワークスペースで開きます。

<Tip>
  Comfy Desktopを開いている間にチームがビルドを公開した場合は、**ビルド**ページの**ワークスペースを更新**をクリックしてください。ワークスペースとそのDeveloper Platform Buildsが再読み込みされます。
</Tip>

## チームのビルドをインストールする

Developer Platform のビルドは、お使いのコンピューターの OS と GPU 向けのビルドを含むバージョンが公開されると、Comfy Desktop に表示されます。これをインストールすると、このコンピューターにチームのビルドが追加されます。**新規ビルド**ダイアログのうち、**名前**や**場所**など、すべてのビルドに共通する項目については、[新しいビルドをインストールする](/ja/installation/desktop/usage/instance-management#新しいビルドをインストール)を参照してください。

<Steps>
  <Step title="新規ビルドダイアログを開く">
    **ビルド**ページで、**新規ビルド**をクリックします。

    ログインしている場合、ダイアログはワークスペースのビルドを表示した状態で開き、最初のビルドが選択されています。ワークスペースにインストールできるビルドがない場合は、代わりに**公式リリース**を表示した状態で開きます。
  </Step>
  <Step title="ビルドとハードウェアを確認する">
    サマリーには、インストールされる内容が表示されます。

    - **リリース**：ビルドの名前と、その説明、**リリース v{version}**、**{creator} による**。
    - **ハードウェア**：このコンピューターの OS と GPU に対応するビルドターゲット（NVIDIA と CUDA 12.8 など）と、そのリリースバージョン。

    **名前**ボックスにはビルドの名前が提案されます。
  </Step>
  <Step title="別のビルドを選択する（任意）">
    **変更**をクリックすると、**セットアップの変更**が開きます。

    - **ソース**：**チームのビルド**を選択します。ログインしていない場合はブラウザが開いてログインできるようになり、ダイアログには**ブラウザで続ける**と表示されます。
    - **リリース**：ビルドを選択します。リストには、このコンピューターにインストールできるビルドのみが表示されます。**オンラインでビルドを表示**をクリックすると、ブラウザで Developer Platform 上のワークスペースのビルドが開きます。**ビルドを更新**をクリックすると、リストが再読み込みされます。
    - **ハードウェア**：ビルドターゲットを選択します。このコンピューターに推奨されるターゲットがあらかじめ選択されています。

    Comfy Desktop がワークスペースに切り替えている間、ダイアログには**ワークスペースの認可を待機しています… プロンプトが表示されたら、ブラウザで認可を完了してください。**と表示されます。

    **変更を保存**をクリックすると、サマリーに戻ります。
  </Step>
  <Step title="ビルドをインストールする">
    **インストール**をクリックします。インストールの進捗を確認する方法は、[新しいビルドをインストールする](/ja/installation/desktop/usage/instance-management#新しいビルドをインストール)を参照してください。
  </Step>
</Steps>

インストールが完了すると、**ビルド**ページのビルドのタイルに、インストールしたバージョンである**ビルド v{version}**が表示されます。ビルドがリストにない場合は、[トラブルシューティング](#トラブルシューティング)を参照してください。

## チームビルドを更新する

チームビルドは、その Developer Platform ビルドのバージョン間でのみ移行できます。チームが新しいバージョンを公開したら、ビルドを更新してそのバージョンを入手します。ビルドページの **概要** タブには、**ビルドバージョン** セクションが表示されます。

1. **サイドバー** でチームビルドをクリックして、ビルドページを開きます。更新が利用可能な場合、**概要** タブにドットが表示され、ビルドのタイルに **更新が利用可能** と表示されます。
2. **概要** で **ビルドバージョン** セクションを確認します。**インストール済み**、**最新公開**、**最終確認** があり、**更新が利用可能** または **最新の状態** が表示されます。再度確認するには、**アップデートを確認** をクリックします。
3. **v{version} に更新** をクリックします。[クイックアクションメニュー](/ja/installation/desktop/usage/instance-management#ビルドリストからのクイックアクション) から **更新** を選択することもできます。
4. **ビルドの更新** ダイアログで、移行元と移行先のバージョンを確認してから、**今すぐ更新** をクリックします。

更新では、ビルドの環境を新しいバージョンに置き換え、ワークフローとすでにステージングされたモデルを保持します。実行中は、進行状況に **v{version} に更新中** と表示されます。完了すると、**インストール済み** に新しいバージョンが表示されます。

## ビルドをDeveloper Platformにアップロードする

**Upload build** を実行すると、このコンピュータ上のビルドからDeveloper Platformのビルドが開始され、ワークスペースから公開したり、チームがインストールしたりできるようになります。ログインしている必要があり、ビルドがこのコンピュータにインストールされている必要があります。Comfy Cloudおよびリモートビルドはアップロードできません。

1. **サイドバー**でビルドを右クリックするか、**Builds** ページのタイルまたは **Home** のカードを右クリックします。
2. **Upload build** を選択します。ヒントには **Upload this build to Comfy Developer Platform.** と表示されます。

実行中は、項目に **Creating…** と表示されます。その後、Comfy Desktopは次の処理を行います。

1. ビルドの手動スナップショットを保存します。これはビルドの **Snapshots** タブに表示されます。[スナップショットの保存と復元](/ja/installation/desktop/usage/instance-management#スナップショットの保存と復元)を参照してください。
2. スナップショットを下書きとして、ビルドが属するワークスペース内のDeveloper Platformに送信します。**Personal** ワークスペース内のビルドは、**Personal** ワークスペースに送信されます。
3. ブラウザで下書きを開きます。ビルドページには **Draft** と **Desktop snapshot received** が表示されます。

下書きは、そのバージョンが公開され、Developer Platform上でビルドが完了するまで、**Your team's builds** には表示されません。公開するには、[ビルドの公開](/ja/development/deploy/cloud-custom-builds#ビルドを公開する)を参照してください。

ビルド上で別のタスクが実行されている場合、**Upload build** はグレー表示になります。ポインタを合わせると、**Wait for the current task on this build to finish.** と表示されます。
