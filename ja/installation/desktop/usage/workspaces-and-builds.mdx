Comfy Desktop は、お使いの Comfy アカウントに接続できます。サインインすると、Chooser にワークスペース機能が追加されます。個人ワークスペースと所属するチームワークスペースの切り替え、選択済みのワークスペースに属するインスタンスの表示、そのワークスペースに公開された ComfyUI Build のインストールができるようになります。また、ローカルインスタンスを、ワークスペースの他のメンバーがインストールできる Build に変換することもできます。

サインインは任意です。ローカルインスタンス、スナップショット、設定はアカウントなしで動作します。

## サインイン

アカウントチップは Chooser の右上にあります。

- **サインアウト状態**: チップには **ログイン** ボタンが表示されます。クリックするとブラウザでのサインインフローが開くので、その後アプリに戻ります。
- **サインイン済み**: チップにはアバターとメールが表示されます。クリックすると **サインアウト** を含むメニューが開きます。

サインアウトはセッションを終了するだけです。インスタンスはそのまま残ります。インストールが進行中の場合、Comfy Desktop は続行する前に、サインアウトするとそのインストールがキャンセルされることを警告します。

## ワークスペースの切り替え

インスタンスグリッドの上にはワークスペースバーがあります。

- **ワークスペーススイッチャー**: **個人**スペースと、所属しているすべてのチームワークスペース。クリックすると切り替えられます。
- **ワークスペースを更新**: サインインすると表示されます。ワークスペースリストと、選択済みワークスペースの Builds カタログを再読み込みします。
- **INSTANCES**: 選択済みワークスペースに属するインスタンスの数。

選択済みのワークスペースが Chooser のスコープを決めます。グリッドにはそのワークスペースに属するインスタンスだけが表示され、New Instance フローではそのワークスペースの Builds が提示されます。Comfy Desktop は選択したワークスペースを記憶し、次回アプリを開いたときにそのワークスペースを復元します。

## Build のインストール

Build とは、ワークスペースに公開されたパッケージ化された ComfyUI 環境です。新規インスタンスウィザードには、その Build のリリースバージョン、クリエイター、ハードウェアターゲット、必要なディスク容量の見積もりが表示されます。Build をインストールすると、通常の ComfyUI インストールではなく、その環境をそのままローカルインスタンスとして利用できます。

1. Chooser の **+** カードをクリックして、新規インスタンスウィザードを開きます。
2. 方法の行で **Managed Builds** を選択します。まだサインインしていない場合、Comfy Desktop は先にログインを求めます。
3. **Release** で、インストールする Build を選択します。インストール可能で、お使いのマシンと互換性のある Build のみが一覧表示されます。**View builds online** を使ってブラウザで Builds ページを開くか、更新ボタンで一覧を再読み込みできます。
4. **Hardware** で、お使いのマシン向けのリリースターゲット（たとえば Windows with NVIDIA (CUDA 12.8)）を選択します。ハードウェアに推奨されるターゲットが事前に選択されています。
5. ウィザードに沿って進み、インスタンスをインストールします。

サインインしている場合、ウィザードは **Managed Builds** で開き、選択したワークスペースに互換性のある Build がない場合は **Public Builds** にフォールバックします。**Public Builds** は、検出されたハードウェア向けのスタンダードな ComfyUI インストールです。

## Build の更新

Build のインストールは、その作者が公開した環境にとどまります。ComfyUI のリリースチャンネルには追従しないため、前に進むのは Build のバージョンです。

インスタンスの[管理パネル](/ja/installation/desktop/usage/manage)を開き、**更新**タブに切り替えます。**Build Version** カードにはこのインスタンスが実行しているバージョンが表示され、ワークスペースがより新しいバージョンを公開すると **Update available** バッジが付き、Comfy Desktop が公開済みバージョンを読み取ったうえで最新を使っている場合は **Up to date** になります。見出しの下には次の行が並びます。

- **Installed**: ディスク上の Build バージョン（例: `v7`）
- **Latest Published**: 公開されている最新バージョン
- **Last Checked**: Comfy Desktop が公開済みバージョンを最後に読み取った時刻

カードの下には次のボタンがあります。

- **Check for updates**: この Build の公開済みバージョンを Comfy Developer Platform から読み直します。
- **Update to v...**: より新しいバージョンがあるときだけ表示され、移動先のバージョン名を伴います（例: **Update to v8**）。確認ダイアログには両方のバージョンが並び、更新が管理対象の環境を置き換えること、ワークフローとステージ済みのモデルは保持されることが示されます。

Comfy Desktop は同じフォルダ内で、新しいバージョンをその場にインストールします。ダウンロードするのはお使いのマシン向けにビルドされたアーティファクトです。ハードウェア向けのビルドがない新しいバージョンも一覧には表示され、選ぶとそのバージョンにこのマシン向けのビルドがない旨のメッセージで停止し、インスタンスは変更されません。更新は実行中にキャンセルでき、新しい環境が整うまでインスタンスは元の環境のままです。新しいバージョンが必要とするモデルはバックグラウンドでステージングされ、終わらなかったダウンロードは次回の起動で再開します。

バージョン一覧はワークスペースのカタログから取得します。アプリがそのカタログをまだ読み取っていない間は、カードにはインストール済みのバージョンと **Check for updates** だけが表示され、最新バージョンは出ません。

### Build の管理パネルのタブ

Build のインストールでは、管理パネルの 6 つのタブのうち 4 つが、**更新**、**スタートアップ引数**、**ターミナル**、**情報**の順で表示されます。**スナップショット**と**ストレージ**は意図的にありません。

- Build は独自のモデルセットと環境を同梱するため、共有モデルフォルダや、インスタンスごとの入力・出力パスを設定する必要がありません。
- Comfy Desktop は Build のインストールにスナップショットタブを表示しないため、参照も復元もできるスナップショット一覧はありません。更新タブが提示するのはより新しい公開バージョンだけなので、Build を以前のバージョンに戻す方法はありません。

**スタートアップ引数**には、スタンドアロンインストールと同じコントロールが並びます。起動引数、ComfyUI-Manager のポリシー、起動モード、ブラウザキャッシュ、ポートの動作、環境変数です。Build は固定のモデル許可リスト付きで公開されることがあり、その場合 ComfyUI-Manager なしで起動するため、Manager の項目は効果を持ちません。

## インスタンスから Build を作成する

ローカルのインスタンスを Build として公開すると、そのワークスペースの他のメンバーがインストールできるようになります。

1. Comfy アカウントにログインします。
2. Chooser で、インスタンスの **⋮ メニュー**を開き、**Create Build** を選択します。
3. Comfy Desktop が、そのインスタンスから Comfy Developer Platform にドラフトの Build を作成します。ドラフトは、そのインスタンスが属するワークスペースに属します。

**Create Build** は、インストール済みでディスク上にインストールパスがあるローカルのインスタンスに対して提供されます。クラウドまたはリモートのインスタンスでは提供されません。Build はドラフトとして開始されるため、リリースする前にその内容を確認できます。

Desktop のスナップショットやワークフロー JSON ファイルから Build を作成する方法など、Build ワークフローの全体については、[Comfy API Build を作成するその他の方法](/ja/development/serverless/build-sources)を参照してください。
