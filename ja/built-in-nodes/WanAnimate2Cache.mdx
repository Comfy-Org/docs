ポーズビデオのブロック単位のアクティベーションを一度キャッシュすることで、サンプリングステップごとに再計算する必要がなくなり、生成時間がおよそ半分になります。その代わりに追加のメモリを使用します。bf16で480x832解像度・81フレームの場合、約12.5GBのシステムRAMを消費し、メモリ使用量は解像度とビデオの長さに応じて増加します。

## 入力

| パラメータ | 説明 | データ型 | 必須 | 範囲 |
|-----------|-------------|-----------|----------|-------|
| `model` | キャッシュを接続するWan Animate2モデル。 | MODEL | はい | |
| `device` | キャッシュを保持する場所。cpu（RAM）が安全な選択肢です。一般的なサイズでは、キャッシュはモデルと一緒にVRAMに収まりません。gpu（VRAM）は、収まる場合には高速になる可能性があります。（デフォルト: "cpu"） | STRING | はい | "cpu"<br />"gpu" |
| `dtype` | 保存精度。defaultは、アクティベーションをモデルの計算dtypeで保存します。int8はキャッシュを半分に、int4は4分の1にします。convrotは精度を維持するために使用されます。（デフォルト: "default"） | STRING | はい | "default"<br />"int8"<br />"int4" |

注記: コンテキストウィンドウを使用する場合、各ウィンドウは個別にキャッシュされるため、メモリ使用量はウィンドウ数に応じて増加します。static_standardスケジュールを使用してください。uniformスケジュールはステップごとにウィンドウを移動させるため、キャッシュが再利用されません。

## 出力
