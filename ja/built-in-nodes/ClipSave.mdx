`CLIPSave` ノードは、CLIPテキストエンコーダモデルをSafeTensors形式でディスクに保存します。高度なモデルマージワークフロー向けに設計されており、モデルの内部構造に基づいてCLIPモデルを構成部分（CLIP-L、CLIP-G、T5XXLなど）に自動的に分割し、各コンポーネントを個別のファイルとして保存します。

## 入力

| パラメータ | 説明 | データ型 | 必須 | 範囲 |
| --- | --- | --- | --- | --- |
| `clip` | 保存するCLIPモデル。 | CLIP | 必須 | - |
| `ファイル名プレフィックス` | 保存されるファイルのプレフィックスパスとファイル名。ノードはコンポーネントのサフィックス（例：`_clip_l`、`_clip_g`）とカウンタを追加して、一意のファイル名を作成します（デフォルト：`clip/ComfyUI`）。 | STRING | 必須 | - |
| `prompt` | ワークフローのプロンプト情報。出力ファイルにメタデータとして保存されます。このパラメータはUIでは表示されません。 | PROMPT | 任意 | - |
| `extra_pnginfo` | 追加のメタデータ。出力ファイルにキーと値のペアとして保存されます。このパラメータはUIでは表示されません。 | EXTRA_PNGINFO | 任意 | - |

## 出力

このノードには出力コネクションがありません。処理したファイルを `ComfyUI/output/` ディレクトリに直接保存します。保存されるファイルにはメタデータ（形式は `"pt"` に設定され、ワークフローのプロンプトと追加のPNG情報が含まれます）が含まれます。ただし、ComfyUI が `--disable-metadata` 引数で起動されている場合を除きます。

### 保存ファイルの詳細

このノードはCLIPモデルのステート辞書を解析し、検出された各コンポーネントを個別のSafeTensorsファイルとして保存します。コンポーネントは、パラメータキーのプレフィックスによって識別されます。次のプレフィックスがチェックされます：

- `clip_l.`（CLIP-L テキストエンコーダ）
- `clip_g.`（CLIP-G テキストエンコーダ）
- `clip_h.`（CLIP-H テキストエンコーダ）
- `t5xxl.`（T5-XXL テキストエンコーダ）
- `pile_t5xl.`（Pile-T5-XL テキストエンコーダ）
- `mt5xl.`（mT5-XL テキストエンコーダ）
- `umt5xxl.`（UMT5-XXL テキストエンコーダ）
- `t5base.`（T5-Base テキストエンコーダ）
- `gemma2_2b.`（Gemma 2 2B テキストエンコーダ）
- `llama.`（LLaMA テキストエンコーダ）
- `hydit_clip.`（Hydit CLIP テキストエンコーダ）
- 空のプレフィックス（その他のCLIPコンポーネント）

検出された各コンポーネントについて、ノードは `{filename_prefix}_{counter:05}_.safetensors` という名前のファイルを作成します。このとき、ファイル名プレフィックスにコンポーネントプレフィックスが追加されます（例：`clip/ComfyUI_clip_l_00001_.safetensors`）。保存時には、パラメータキーから `transformer.` プレフィックスが除去されます。
