CLIPTextEncodeSD3は、異なるCLIPモデルを使用して複数のテキストプロンプトをエンコードすることで、Stable Diffusion 3モデル用のテキスト入力を処理します。このノードは、3つの個別のテキスト入力（`clip_g`、`clip_l`、`t5xxl`）を処理し、空のテキストパディングを管理するオプションを提供します。このノードは、異なるテキスト入力間のトークン配置を適切に保証し、SD3生成パイプラインに適したコンディショニングデータを返します。

## 入力

| パラメータ | 説明 | データ型 | 必須 | 範囲 |
| --- | --- | --- | --- | --- |
| `クリップ` | テキストエンコードに使用されるCLIPモデル | CLIP | はい | - |
| `クリップ_l` | ローカルCLIPモデル用のテキスト入力。複数行テキストと動的プロンプトをサポートします。 | STRING | はい | - |
| `クリップ_g` | グローバルCLIPモデル用のテキスト入力。複数行テキストと動的プロンプトをサポートします。 | STRING | はい | - |
| `t5xxl` | T5-XXLモデル用のテキスト入力。複数行テキストと動的プロンプトをサポートします。 | STRING | はい | - |
| `空のパディング` | 空のテキスト入力の処理方法を制御します。"none"に設定すると、`clip_g`、`clip_l`、または`t5xxl`の空のテキスト入力はパディングではなく空のトークンリストになります。"empty_prompt"に設定すると、空の入力は空のプロンプトとしてトークン化されます（標準のパディング動作）。これは高度なパラメータです（デフォルト："none"）。 | COMBO | はい | `"none"`<br />`"empty_prompt"` |

**パラメータ制約：**

- `empty_padding`が"none"に設定されている場合、`clip_g`、`clip_l`、または`t5xxl`の空のテキスト入力は、パディングではなく空のトークンリストになります
- このノードは、`clip_l`と`clip_g`入力の長さが異なる場合、短い方に空のトークンをパディングすることで、トークン長を自動的にバランスさせます
- すべてのテキスト入力は動的プロンプトと複数行テキスト入力をサポートしています

## 出力

| 出力名 | 説明 | データ型 |
| --- | --- | --- |
| `CONDITIONING` | SD3生成パイプラインで使用できる状態にエンコードされたテキストコンディショニングデータ | CONDITIONING |
