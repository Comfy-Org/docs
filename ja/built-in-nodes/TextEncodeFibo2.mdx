Fibo 2.0 のプロンプトをコンディショニングと対応する空の latent にエンコードします。プロンプトはプレーンテキストまたは構造化された JSON キャプションのいずれかです。画像が接続されている場合は編集指示、または `edit_instruction` キーを持つ結果の JSON キャプションになり、VAE が接続されているときは画像が両方の出力の参照 latent として機能します。`latent` 出力をサンプリングします。そのサイズは、画像がクロップされるサイズです。

## 入力

| パラメータ | 説明 | データ型 | 必須 | 範囲 |
| --- | --- | --- | --- | --- |
| `clip` | プロンプトをトークン化してエンコードするために使用する Fibo 2.0 テキストエンコーダーです。 | CLIP | はい | - |
| `prompt` | 生成の元になるキャプション、または画像が接続されている場合の編集指示です。画像は `<image_1>`、`<image_2>` などとして参照してください。期待する結果の JSON キャプションも使用でき、変更内容はその `edit_instruction` キーに記述します。 | STRING | はい | - |
| `negative_prompt` | 避けたい方向へ誘導するキャプションで、ネガティブコンディショニングとしてエンコードされます。空でない値は、キャプションのように整形されず、そのまま Fibo 2.0 のチャットテンプレートに入れて送られます。空の場合は、Fibo 2.0 が編集ワークフローでの classifier-free guidance 用に学習された null キャプションになります（デフォルト: 空）。 | STRING | はい | - |
| `vae` | 画像を参照 latent にエンコードするために使用する VAE です。これがない場合、画像はテキストエンコーディングを条件付けるだけです。 | VAE | いいえ | - |
| `images` | 編集する画像で、最大 16 枚です。1 枚の画像は結果のサイズにスケーリングされ、中央でクロップされます。これは編集が画像とピクセル単位で一致するためです。複数の画像は、それぞれが自身の学習済みサイズにスケーリングされます。 | IMAGE | いいえ | 0 〜 16 枚の画像 |
| `width` | 結果の幅で、16 の倍数に切り捨てられます。0 の場合は、最初の画像のアスペクト比に対して Fibo 2.0 が学習されたサイズ（約 1 メガピクセル）、画像がない場合は 1024 を使用します（デフォルト: 0）。 | INT | はい | 0 〜 16384 （ステップ 16） |
| `height` | 結果の高さで、16 の倍数に切り捨てられます。0 の場合は、最初の画像のアスペクト比に対して Fibo 2.0 が学習されたサイズ（約 1 メガピクセル）、画像がない場合は 1024 を使用します（デフォルト: 0）。 | INT | はい | 0 〜 16384 （ステップ 16） |
| `batch_size` | バッチ内に作成する latent の数です（デフォルト: 1）。 | INT | はい | 1 〜 4096 |

参照 latent は両方の出力に付加されるため、画像はポジティブ分岐だけでなくコンディショニングと一緒に渡されます。VAE が接続されていない場合、画像はテキストエンコーダーによってのみ参照され、参照 latent は追加されません。

## 出力

| 出力名 | 説明 | データ型 |
| --- | --- | --- |
| `positive` | プロンプトのコンディショニングです。VAE と画像が接続されている場合は参照 latent が含まれます。 | CONDITIONING |
| `negative` | `negative_prompt` のコンディショニングです。テキストのみで、同じ参照 latent が含まれます。 | CONDITIONING |
| `latent` | 要求されたサイズの空の latent で、サンプリング可能な状態です。 | LATENT |
