**P-H3-Image** は、[MiniMax H3](/ja/tutorials/video/minimax/minimax-h3) をベースにした Pruna AI のオープンウェイト画像モデルです。1つの checkpoint で2つのタスクを処理します。テキストから画像への生成と、画像編集です。画像1枚の生成には classifier-free guidance なしで8サンプリングステップ、デフォルトで8メガピクセルを使用します。

このモデルは写真・フィルム調のルックに寄っています。ドキュメンタリーやエディトリアル写真、リアルな肌の質感を持つポートレート、TV フレーム風のアニメ、スクリーン印刷風のポスター、短い引用テキストを含むフラットなグラフィックデザインなどです。Qwen3.5-9B ベースのプロンプトアップサンプラーが、一行のリクエストをモデルが最もよく描画できる詳細なプロンプトに書き換え、その書き換え後のプロンプトを返すので、サンプラーに渡る前に内容を確認できます。

ComfyUI では、P-H3-Image はテキストから画像へと画像編集の2つのワークフローテンプレートとして動作します。MiniMax H3 の diffusion モデルを再利用し、Pruna のテキストエンコーダー、プロンプトアップサンプラー、VAE、LoRA を追加します。モデルファイルの合計は約 35 GB です。int8 ファイルは約 21 GB の VRAM にフィットします。

**モデルの特長**
- **8ステップ、CFG なし**: 蒸留された単一のサンプリングスケジュールと単一のポジティブ条件付けを使用し、ネガティブプロンプトはありません
- **8メガピクセル**: スクエア、4:3、3:2、16:9 とその縦長バージョンに対応し、最大 3872 x 2176
- **プロンプトアップサンプラー内蔵**: 一行のリクエストが完全なプロンプトに展開され、展開されたプロンプトがワークフロー内に表示されます
- **参照画像による編集**: 最初の画像が編集対象で、以降の画像はプロンプト内で `<Picture 2>`、`<Picture 3>` などになります
- **画像のみ**: P-H3-Image はビデオやオーディオを生成しません

## 要件

- ComfyUI 0.44.0 以降。どちらのテンプレートも、0.44.0 で追加された PH3ImageConditioning ノードを使用します
- 約 35 GB のモデルファイル。diffusion モデルは MiniMax H3 ワークフローで使われているものと同じなので、すでに持っているかもしれません
- int8 ファイル用に約 21 GB の VRAM を備えた GPU

P-H3-Image は MiniMax H3 Community License の下でリリースされており、MiniMax から別途ライセンスを取得しない限り、一部の地域は対象外です。商用利用の場合は、[Comfy](https://comfy.org/minimax/license) からライセンスを申請してください。

## P-H3-Image テキストから画像へのワークフロー

1行のリクエストから8メガピクセルの画像を生成します。テンプレートはまずプロンプトアップサンプラーを実行し、その後8ステップのスケジュールを実行します。

プロンプトボックスの `Request:` の後にリクエストを書き、`Aspect ratio:` の行を解像度セレクターと同期させてください。セレクターは8メガピクセル、32の倍数に設定されており、次のキャンバスサイズになります:

| セレクターの比率 | 8 MP・32の倍数でのサイズ |
| :--- | :--- |
| 1:1（スクエア） | 2912 x 2912 |
| 4:3（スタンダード） | 3360 x 2496 |
| 3:2（フォト） | 3552 x 2368 |
| 16:9（ワイドスクリーン） | 3872 x 2176 |
| 3:4（ポートレート スタンダード） | 2496 x 3360 |
| 2:3（ポートレート フォト） | 2368 x 3552 |
| 9:16（ポートレート ワイドスクリーン） | 2176 x 3872 |

- **サンプリング**: 8ステップがモデル自体のスケジュールです。ステップを増やしてもディテールは追加されず、調整できる CFG やネガティブプロンプトもありません
- **シード**: 新しい画像を生成するには `randomize` に設定し、収録されている作例を再現するには `fixed` に戻してください
- **アップサンプルされたプロンプト**: Preview Any ノードに書き換えられたプロンプトが表示されます。リクエストを変更する前に読んでおく価値があります

変更したい画像を `Load Image` に読み込み、`Request:` の後に望む結果を記述します。出力はその画像の形状に従うため、条件付けノードの幅と高さの入力は 0 のままにします。

- **ソースサイズ**: 編集結果は最初の画像のサイズでレンダリングされ、最低 4 メガピクセルまで拡大されます
- **参照画像を増やす**: 追加の画像を接続すると、`<Picture 2>`、`<Picture 3>` 以降の参照をプロンプトに加えられます
- **保持するもの**: 変更してはいけない要素を明示してください。これがないと、モデルはシーン全体を描き直す傾向があります

## プロンプトのヒント

1. **画像が何であるかを述べる**: 実際の対象を名指しする一文から始めます。たとえば "a photograph by an experienced street photographer" や "a two-color risograph print" です。これはスタイルを表す言葉よりも確実にルックを設定できます
2. **1 つのシーンを描写する**: 視点、ある瞬間を捉えた主要な被写体を 1 つ、いくつかの補助的な要素、そしてソースと方向が明確なライトを指定します
3. **すべての文字列を引用する**: 正確な言葉を伴わないテキストは疑似テキストになってしまいます。各文字列を引用符で囲み、短く保ち、どこに配置するかを述べ、最後に "no other text" と付け加えます
4. **誇張表現は省く**: stunning、epic、cinematic、8k といった言葉は、モデルを光沢のある彩度過剰なルックへと導きます

## 制限事項

- **低い解像度ではアーティファクトが増える**：顔、手、細かい詳細は、8メガピクセルより2メガピクセルや4メガピクセルの方が崩れやすい
- **手や背景の人物が崩れることがある**：背景にいる小さな人物が歪んで出力されることがある。8メガピクセルでレンダリングすると改善する
- **テキストは完全には信頼できない**：短い引用文字列はうまくレンダリングされるが、本文コピーや長いコードのような密度の高いテキストは疑似テキストになってしまう
- **プロンプトに敏感**：非常に長いプロンプトは画像を悪化させ、非常に短いプロンプトはアップサンプラーなしでは弱い結果になる
