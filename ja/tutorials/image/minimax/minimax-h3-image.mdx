**MiniMax-H3-Image** は MiniMax のオープンウェイト画像モデルで、1つの checkpoint がテキストから画像への生成と画像編集の両方をカバーします。diffusion transformer は BF16 で 33.1B パラメータを持ち、CFG を使わない 6 ステップのサンプラーに蒸留されています。出力は約 16 MP のネイティブ解像度なので、4096 x 4096 の画像はアップスケールの連鎖ではなく 1 回のパスで生成できます。

- [Comfy-Org/MiniMax-H3 (Hugging Face)](https://huggingface.co/Comfy-Org/MiniMax-H3): このモデルが使用する Qwen3-VL-32B text encoder
- [MiniMaxAI/MiniMax-H3-Image-PE (Hugging Face)](https://huggingface.co/MiniMaxAI/MiniMax-H3-Image-PE): 公式の prompt expander

## 主な機能

- **テキストから画像生成と編集を1つのcheckpointで**: 編集用のモデルやアダプターを別途読み込む必要はありません
- **6ステップのサンプリング**: ガイダンスは1に固定されているため、CFGパスもネガティブプロンプトもありません
- **ネイティブで約16 MP**: アップスケール処理なしで4096 x 4096、最大6272 x 2688まで
- **複数の参照**: 最大16枚の入力画像を、プロンプト内で `<Picture 1>` 以降として指定
- **オプションのプロンプトエキスパンダー**: 短いリクエストを、モデルが最もよく読み取る詳細なキャプションに変換します
- **オープンウェイト**: ComfyUIで完全なローカル制御が可能

## テンプレート

このモデルには 2 つのテンプレートワークフローが付属しています。どちらも ComfyUI **0.45.0+** とテンプレートパック **0.11.104+** が必要です。

### MiniMax-H3-Image テキストから画像生成 {#image_minimax_h3_image_t2i}

テキストプロンプトから画像を生成します。テンプレートは正方形のキャンバスで 4 MP で開きます。これは意図的にモデルのネイティブ解像度より低く設定されており、VRAM の少ないマシンでメモリ不足が発生しないようにしています。GPU に余裕がある場合は、解像度セレクターでサイズを上げてください。

## サンプリングとキャンバスサイズ

どちらのテンプレートも蒸留スケジュールを搭載しています:

| 設定 | 値 |
| --- | --- |
| サンプラー | euler |
| スケジューラー | simple |
| ステップ数 | 6 |
| ガイダンス（CFG） | 1 |
| デノイズ | 1 |

ガイダンスが1の場合、classifier-free guidance のパスは実行されないため、テンプレートにはネガティブプロンプトがありません。避けたい事項を含め、希望する内容はすべてポジティブプロンプトに記述してください。

ネイティブ出力は約16 MPです。各辺は32 pxの倍数で生成され、任意の幅と高さを指定できます。次のサイズは一般的な比率に対応しています:

| アスペクト比 | サイズ（幅 x 高さ） |
| --- | --- |
| 1:1 | 4096 x 4096 |
| 4:3 | 4736 x 3552 |
| 3:4 | 3552 x 4736 |
| 3:2 | 5024 x 3360 |
| 2:3 | 3360 x 5024 |
| 16:9 | 5472 x 3072 |
| 9:16 | 3072 x 5472 |
| 21:9 | 6272 x 2688 |

より小さいキャンバスも使用でき、所要時間も短くなります。テキストから画像へのテンプレートでは、解像度セレクターがアスペクト比と目標メガピクセル数を個別に設定するため、4 MPは上限ではなく出発点です。

### テキストから画像生成の出力が過剰処理される場合の対処

テキストのみの出力では、毛穴やほくろが強調され、肌や布地がかさついた質感になる過剰処理が起こることがあります。`MiniMax H3 Image Conditioning` の `images` 入力に任意の画像を接続すると改善します。キャンバスを大きくしても、この症状は 16 MP でも残ります。

条件付けノードは Text to Image サブグラフの内側にあります。サブグラフ内に `Load Image` ノードを追加し、`images` に接続してください。画像の内容は問わないため、空白の画像でも効果があります。

条件付けノードの `vae` 入力を外すと、コストは視覚トークン分だけになります。画像はテキストエンコーダーにのみ渡り、`VAEDecode` 側の VAE 接続はそのまま残ります。画像は小さくて構いません。ノードが短辺 1024 px に揃えます。

## 画像編集での参照画像

画像編集テンプレートは、ソース画像を `<Picture 1>` としてモデルに送信します。追加の画像は `<Picture 2>`、`<Picture 3>` のように順番にラベル付けされ、最大16枚の参照画像まで指定でき、プロンプトはそれぞれのラベルで参照します。最初の画像が編集対象で、残りは被写体の同一性、小道具、素材、構図を補うので、`<Picture 1>` の車両を `<Picture 2>` の車両に置き換えるといった短い指示で十分です。

参照画像を追加するには、ワークフローに別の `Load Image` ノードを配置し、プロンプト生成ステップと条件付けノードの両方に接続します。条件付けノードの VAE 入力は接続したままにしてください。テンプレートは最初から接続されており、VAE があると参照画像は画像 latent としても条件に加わるため、編集結果がソースに追従しやすくなります。参照画像の短辺は 1024 px 以上にし、同一性を保つ場合は 2048 px にしてください。ノード側で拡大縮小されるため、1024 px 未満の画像は拡大され（増えたピクセルは補間です）、2048 px を超えるディテールは破棄されます。

拡大縮小ノードを有効にしない場合、編集結果はソース画像と同じサイズで返ります。有効にすると指定した目標サイズで生成され、既定で有効なテンプレートパックでは 4 MP、テンプレートパック 0.11.104 では 1 MP のままバイパスされているため、選択して `Ctrl-B` で有効にしてから目標値を設定してください。メモリが足りない場合はサンプリング前に目標値を下げます。

## プロンプトエキスパンダー

どちらのテンプレートも、サンプラーの手前にテキスト生成ステップを備えています。テキストから画像へのテンプレートでは、プロンプトを詳細な英語のキャプションに書き換え、キャンバスのアスペクト比を選択します。画像編集テンプレートでは、短い指示を、完成した画像を参照情報に基づいて説明する記述に変換します。

MiniMax-H3-Image の公式エキスパンダーは Qwen3.8-27B FP4 モデルで、[MiniMaxAI/MiniMax-H3-Image-PE](https://huggingface.co/MiniMaxAI/MiniMax-H3-Image-PE) として公開されています。テンプレートでは代わりに、より軽量な Qwen3.5 9B W4A8 ビルドを使用しているため、エキスパンダーは 21 GB の diffusion モデルと同じ GPU 上に収まります。

テキストから画像へのテンプレートはエキスパンダーがオフの状態で提供されるため、入力したプロンプトはそのままモデルに渡ります。キャプションの書き換えとアスペクト比の自動選択を行いたい場合はオンに切り替えてください。画像編集テンプレートはオンの状態で提供されます。
