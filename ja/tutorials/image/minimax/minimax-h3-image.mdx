**MiniMax-H3-Image** は MiniMax のオープンウェイト画像モデルで、1つの checkpoint がテキストから画像への生成と画像編集の両方をカバーします。diffusion transformer は BF16 で 33.1B パラメータを持ち、CFG を使わない 6 ステップのサンプラーに蒸留されています。出力は約 16 MP のネイティブ解像度なので、4096 x 4096 の画像はアップスケールの連鎖ではなく 1 回のパスで生成できます。

- [MiniMaxAI/MiniMax-H3-Image-PE (Hugging Face)](https://huggingface.co/MiniMaxAI/MiniMax-H3-Image-PE): 公式の prompt expander

## 主な機能

- **テキストから画像生成と編集を1つのcheckpointで**: 編集用のモデルやアダプターを別途読み込む必要はありません
- **6ステップのサンプリング**: ガイダンスは1に固定されているため、CFGパスもネガティブプロンプトもありません
- **ネイティブで約16 MP**: アップスケール処理なしで4096 x 4096、最大6272 x 2688まで
- **複数の参照**: 最大16枚の入力画像を、プロンプト内で `<Picture 1>` 以降として指定
- **オプションのプロンプトエキスパンダー**: 短いリクエストを、モデルが最もよく読み取る詳細なキャプションに変換します
- **オープンウェイト**: ComfyUIで完全なローカル制御が可能

## サンプリングとキャンバスサイズ

どちらのテンプレートも蒸留スケジュールを搭載しています:

| 設定 | 値 |
| --- | --- |
| サンプラー | euler |
| スケジューラー | simple |
| ステップ数 | 6 |
| ガイダンス（CFG） | 1 |
| デノイズ | 1 |

ガイダンスが1の場合、classifier-free guidance のパスは実行されないため、テンプレートにはネガティブプロンプトがありません。避けたい事項を含め、希望する内容はすべてポジティブプロンプトに記述してください。

ネイティブ出力は約16 MPです。各辺は32 pxの倍数で生成され、任意の幅と高さを指定できます。次のサイズは一般的な比率に対応しています:

| アスペクト比 | サイズ（幅 x 高さ） |
| --- | --- |
| 1:1 | 4096 x 4096 |
| 4:3 | 4736 x 3552 |
| 3:4 | 3552 x 4736 |
| 3:2 | 5024 x 3360 |
| 2:3 | 3360 x 5024 |
| 16:9 | 5472 x 3072 |
| 9:16 | 3072 x 5472 |
| 21:9 | 6272 x 2688 |

より小さいキャンバスも使用でき、所要時間も短くなります。テキストから画像へのテンプレートでは、解像度セレクターがアスペクト比と目標メガピクセル数を個別に設定するため、4 MP 以上、セレクターの上限である 16 MP までの任意のサイズは 1 か所の設定で指定できます。

## 画像編集での参照画像

画像編集テンプレートは、ソース画像を `<Picture 1>` としてモデルに送信します。追加の画像は `<Picture 2>`、`<Picture 3>` のように順番にラベル付けされ、最大16枚の参照画像まで指定でき、プロンプトはそれぞれのラベルで参照します。最初の画像が編集対象で、残りは被写体の同一性、小道具、素材、構図を補うので、`<Picture 1>` の車両を `<Picture 2>` の車両に置き換えるといった短い指示で十分です。

参照画像を追加するには、ワークフローに別の `Load Image` ノードを配置し、プロンプト生成ステップと条件付けノードの両方に接続します。条件付けノードの VAE 入力は接続したままにしてください。テンプレートは最初から接続されており、VAE があると参照画像は画像 latent としても条件に加わるため、編集結果がソースに追従しやすくなります。参照画像の短辺は 1024 px 以上にし、同一性を保つ場合は 2048 px にしてください。ノード側で拡大縮小されるため、1024 px 未満の画像は拡大され（増えたピクセルは補間です）、2048 px を超えるディテールは破棄されます。

拡大縮小ノードを有効にしない場合、編集結果はソース画像と同じサイズで返ります。有効にすると指定した目標サイズで生成され、現在のテンプレートパックでは 16 MP、テンプレートパック 0.11.104 では 1 MP のままバイパスされているため、選択して `Ctrl-B` で有効にしてから目標値を設定してください。メモリが足りない場合はサンプリング前に目標値を下げます。

モデルが編集する画像を読み込むときの短辺は最大 2048 px で、これは 1:1 で約 4 MP、16:9 で約 7 MP にあたります。それを超えるターゲットでは、増えるのは生成されたディテールで、ソース画像のディテールではありません。ディテールを重視するときはターゲットをそのサイズに合わせ、結果は後から拡大してください。

### 編集プロンプトの書き方

プロンプトエキスパンダーをオンにしておけば短い指示で十分です。モデルが最も読みやすい構成に書き換えます。オフにして自分で書くときは、同じ構成を使ってください。

1. **要素を先に書き、そこに番号を振る**: `The woman in a red coat in <Picture 1> is <Subject 1>` のように、特定できる見た目の特徴を添えます。定義には必ず対応する `<Picture N>` を書きます。
2. **完成後の画像を説明し、各被写体の結果を書く**: `<Subject 1> is fully preserved`、または `<Subject 1> is partially preserved; her face and coat remain, while her pose changes to a lean toward <Subject 2>`。
3. **変わった部分と新しく加わる部分だけを書く**: 削除したオブジェクトの跡に何が残るか、編集で加える文字はここに書きます。

参照画像に由来しない内容には被写体番号を付けません。削除した要素は `<Picture N>` で完成後の説明に一度だけ触れ、その跡に残る領域を書きます。

`<Subject N>` はテキストエンコーダーが読む語句であり、サンプラーが強制する結び付けではありません。編集を成立させるのは説明文そのものです。何が変わり何が残るかを書き、参照画像が自動で引き継ぐと期待しないでください。公式の編集例に構成全体が載っています: [revised_prompt.edit.txt](https://github.com/MiniMax-AI/MiniMax-H3-Image/blob/main/examples/revised_prompt.edit.txt)。

### 画像の拡大と修復

編集ワークフローは 2 パス目の拡大も自分で行えます。別のアップスケーラーは不要です。`scale total pixels` を持つ `Resize Image/Mask` ノードで目標サイズを設定し（テンプレートでは 16 MP）、`Boolean (Enable PE?)` ノードのトグルをオフにします。使用中のパックでこのノードがバイパスされている場合は、選択して `Ctrl-B` で有効にしてください。

```text
Re-render and sharpen as if the photo were taken with a 50 mm lens. Remove noise and compression artifacts. Improve skin, hair, eye and fabric detail while keeping pose, identity, and colors.
```

レンズの記述は元画像の撮影条件に合わせます。エキスパンダーがオフなら指示はそのままモデルに渡り、オンの場合は新しい画像の説明を書いて指定していない内容まで加えます。

フレーム全体が再生成されるため、これは新しいディテールを伴う拡大であり、忠実な複製ではありません。目標サイズがモデルの読み取りサイズ（1:1 で約 4 MP）に近いほどポーズ、同一性、色が保たれます。短辺 2048 px を超える部分は生成されたディテールだからです。プロンプトに書かなかった部分は変わり得て、目標サイズが大きいと肌の質感がテカった古い見た目になることがあります。

### 画像の一部を変更せずに残す

サンプラーはマスクが `0` の位置に元の latent を戻し、それ以外を再生成します。フレームの一部を保つ方法はこれだけです。

1. MaskEditor で再生成したい領域を白く塗り（`Load Image` ノードを右クリックして **Open in MaskEditor**）、その **MASK** 出力を `Set Latent Noise Mask` に接続します。アルファチャンネルのない画像は全黒のマスクとして読み込まれ、フレーム全体が保持されます。
2. 条件付けノードの画像入力にすでに入っている画像を `VAE Encode` します。条件付けノードの `LATENT` 出力は `width` と `height` で作られる空のキャンバスにすぎず、`latent_image` に置いた latent が出力サイズを決めます。
3. `positive` は接続したまま、マスクを適用した latent をサンプラーの `latent_image` に接続します。

マスクは latent グリッドにリサンプルされ、1 セルは 16 px です。被写体より約 16 px 広く取ってエッジをぼかすと、接地影も再生成範囲に残ります。

プロンプトは完成後の画像全体を説明したままで、マスクはコピーするピクセルを決めるだけです。保持したピクセルは VAE を往復して戻るため、元のピクセルではなく再エンコードされた結果です。モデルが元画像を読むサイズ（1:1 で約 4 MP）で実行すると、保持側と再生成側のディテールが揃います。

## プロンプトエキスパンダー

どちらのテンプレートも、サンプラーの手前にテキスト生成ステップを備えています。テキストから画像へのテンプレートでは、プロンプトを詳細な英語のキャプションに書き換えます。画像編集テンプレートでは、短い指示を、完成した画像を参照情報に基づいて説明する記述に変換します。

MiniMax-H3-Image の公式エキスパンダーは Qwen3.8-27B FP4 モデルで、[MiniMaxAI/MiniMax-H3-Image-PE](https://huggingface.co/MiniMaxAI/MiniMax-H3-Image-PE) として公開されています。テンプレートでは代わりに、より軽量な Qwen3.5 9B W4A8 ビルドを使用しているため、エキスパンダーは 21 GB の diffusion モデルと同じ GPU 上に収まります。

どちらのテンプレートもエキスパンダーがオンの状態で提供されるため、プロンプトはサンプリング前に書き換えられます。オフにすると入力したプロンプトがそのままモデルに渡ります。
