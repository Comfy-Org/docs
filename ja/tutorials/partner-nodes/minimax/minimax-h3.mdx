[MiniMax H3](https://www.minimax.io/blog/minimax-h3) は、MiniMax の汎用オムニモーダル生成モデルであり、ComfyUI では MiniMax H3 APIノードを通じて利用できます。APIワークフローは MiniMax のサーバー上で生成を実行するため、モデルのダウンロードやローカル GPU は必須ではなく、生成済みビデオの1秒ごとに Comfy API アカウントへ請求されます。

MiniMax H3 は、**ネイティブステレオオーディオ**付きのビデオを生成します。音声、サウンドエフェクト、音楽は、後から重ねるのではなく、単一のフォワードパスでまとめてモデリングされます。出力は、1クリップあたり5～15秒、最大2K解像度です。

**MiniMax H3 Max** は、fal が MiniMax H3 をベースに高速生成向けにポストトレーニングしたバリアントで、ComfyUI 0.34.2 で同じ API ノードに追加されました。リアルタイムよりも速く生成でき、最大 50,000 文字のプロンプトに対応し、480P と 768P の解像度に加え、ComfyUI がすでにサポートしているノードで構成される任意の 2 段階グラフを備えています：MiniMax H3 Context IR ノードによるプロンプト拡張、その後 MiniMax H3 Regenerate to 2K ノードによる 2K への再生成。

**MiniMax H3 Max Turbo** は、ComfyUI 0.34.4 でテキストから動画生成ノードと先頭・末尾フレームノードに追加された、より高速で低価格な H3 Max オプションです。480P または 768P でレンダリングし、先頭・末尾フレームノードでは解像度とアスペクト比のオプションが廃止され、出力の比率は入力フレームに従います。

<Note>
これらのAPIワークフローは、お使いの Comfy アカウントを通じて MiniMax のサーバー上で実行されます。商用目的で H3 を自社のハードウェアでローカルに実行するには、[MiniMax 商用ライセンス](https://comfy.org/minimax/license)が必要です。これは、唯一の公式リセラーである Comfy から入手できます。
</Note>

## MiniMax H3 が得意なこと

- **ネイティブステレオオーディオ**: ボイス、サウンドエフェクト、音楽は、後から重ね合わせるのではなく、ビデオとともに単一のフォワードパスでモデリングされます
- **高解像度出力**: 1クリップあたり5〜15秒で、最大2K解像度に対応
- **テキストから動画へ**: テキストプロンプトから、オーディオ付きのビデオを生成します
- **ファーストフレーム/ラストフレームビデオ**: 最初のフレームと、オプションの最後のフレーム画像の間のモーションを生成します
- **参照条件付き生成**: 最大9枚の参照画像、3本の参照ビデオ、3つの参照オーディオクリップを条件として、ビデオを生成します
- **MiniMax H3 Max**: 480P/768P 出力、長文プロンプト、任意の 2K アップスケール段階を備えた高速バリアント。H3 Max では Reference ノードは最大 12 個の参照ファイルに対応します
- **MiniMax H3 Max Turbo**: テキストから動画生成ノードと先頭・末尾フレームノードで利用できる最速の H3 Max オプション。秒あたりのレートは Max の約半分です

## MiniMax H3 API ワークフロー

テンプレートライブラリには、H3 ベースモデル向けに 3 つ、H3 Max 向けに 4 つ、H3 Max Turbo 向けに 2 つの API サンプルワークフローが含まれています：

- **テキストから動画生成**：テキストプロンプトから動画を生成します。
- **先頭・末尾フレームから動画生成**：先頭フレームと末尾フレームの画像から、その間の動画を生成します。
- **リファレンスから動画生成**：参照画像、動画、オーディオを条件として動画を生成します。
- **H3 Max T2V / I2V / FLF2V / R2V**：より高速な MiniMax H3 Max モデルで同じモードを実行します。各ワークフローには、任意のプロンプト拡張と 2K アップスケール段階が組み込まれています。
- **H3 Max Turbo T2V / I2V**：最速の MiniMax H3 Max Turbo モデルでテキストから動画生成と先頭・末尾フレーム動画を実行します。こちらにも任意のプロンプト拡張と 2K アップスケール段階が組み込まれています。

### MiniMax H3 Max

4 つの `api_minimax_h3_max_*` テンプレートは、同じ API ノードを通じて MiniMax H3 Max モデルで実行されます。Text to Video ノードと First-Last-Frame ノードには ComfyUI 0.34.2 で H3 Max オプションが追加され、Reference to Video ノードには 0.34.3 で追加されました。すべて実行するには、ComfyUI を少なくとも 0.34.3 にアップデートしてください。

H3 Max はリアルタイムよりも速く生成でき、ベースモデルより低いレートで課金されます：480P で 15.09 クレジット/秒、768P で 24.14 クレジット/秒（[Minimax 料金表](/ja/tutorials/partner-nodes/pricing) を参照）。各 Max テンプレートには、Switch ノードの背後に 2 つの任意段階があり、どちらもデフォルトでオフです：

1. **プロンプト拡張**：生成前に MiniMax H3 Context IR ノードでプロンプトを書き換えます。`Prompt Enhance` ブール値をオンにすると有効になります
2. **2K へのアップスケール**：最初のパスのビデオに対して MiniMax H3 Regenerate to 2K ノードを実行します。`Upscale to 2K` ブール値をオンにすると有効になります

Max テンプレートを配線する際は、以下の点に注意してください：

- **アップスケールする場合は 768P で生成**：Regenerate to 2K ノードは 768P のソースビデオのみを受け付けます
- **ノード間で再生時間を一致させる**：生成とプロンプト拡張は同じ再生時間を使用する必要があります。一致しないと各段階がずれます。Regenerate to 2K ノードには再生時間の入力がなく、送信された 768P ビデオを元の再生時間で再レンダリングします
- **追加入力は複製する**：3 つのノードは追加コンテキストを自動的に共有しません。参照ビデオ、オーディオ、別の画像を追加した場合は、同じ配線を Context IR ノードと Regenerate ノードの両方に接続してください

#### プロンプト作成のヒント

1. **プロンプト**：シーン全体と、それに付随するオーディオ（セリフ、SFX、音楽）を1つのブロックで記述します。
2. **再生時間**：再生時間の入力は5〜15秒に対応しています。ワークフローには、高速な5秒のプレビューが含まれています。
3. **解像度と比率**：API は2Kでレンダリングします。`16:9`、`9:16`、`1:1` などのアスペクト比プリセットを選択してください。
4. **ウォーターマーク**：AIGC ウォーターマークはデフォルトでオフになっています。必要な場合は、ノードの詳細設定で有効にしてください。

#### プロンプトのヒント

1. **フレーム**: `first_frame` 入力は必須で、`last_frame` は任意です。モデルはそれらの間のモーションを生成します
2. **アスペクト比**: 出力は入力画像に従うため、両方のフレームを同じアスペクト比にしてください
3. **画像の制約**: 各フレームの幅と高さは 256 から 5760 ピクセルの間で、アスペクト比は 2:5 から 5:2 の間である必要があります
4. **プロンプト**: フレーム間の遷移と、希望するオーディオ（会話、SFX、音楽）を説明してください

#### プロンプト作成のヒント

1. **タグによる参照**：プロンプト内の順序で各入力を参照します。たとえば、`Image 1`、`Video 1`、`Audio 1` のように指定します。`@Image1`、`@Video1`、`@Audio1` の省略記法も使用でき、同じタグとして解決されます。
2. **制限**：参照画像は最大9枚、参照ビデオは最大3本、参照オーディオクリップは最大3つまで指定できます。各ビデオまたはオーディオクリップは2〜15秒である必要があります。また、参照ビデオと参照オーディオは、それぞれ合計15秒までに制限されます。
3. **オーディオには視覚的なアンカーが必要**：参照オーディオは、少なくとも1つの参照画像または参照ビデオがないと使用できません。
4. **ビデオの要件**：参照ビデオは23.976〜60 FPSである必要があります。
5. **プロンプト**：各参照にジョブ（アイデンティティ、スタイル、モーション、ボイス）を割り当て、ターゲットショットを説明します。明示的な割り当ての方がはるかに良い結果になる傾向があります。

#### プロンプト記述ガイド

MiniMaxは、参照駆動型生成（R2V）向けの公式の[フル参照モードのプロンプトガイド](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_ref_en.md)を公開しています。このガイドでは、リライト出力の構造（サブジェクト定義、参照ラベル、保持分析など）と、各参照にターゲットショット内での役割を割り当てる方法について説明しています。

## H3 Maxノードでビデオを編集する

H3 Maxには、プロンプトだけでなくビデオや静止画を起点として、その素材を編集する6つのパートナーノードも用意されています。Recast、Extend Video、Reframe Video、Insert Video、Lip Sync、Camera Controlです。これらのノードにテンプレートは付属していません。**Partner Nodes > video > MiniMax** のノードライブラリから追加してください。見つからない場合はComfyUIを最新バージョンにアップデートしてください。

| ノード | 機能 | 開始素材 |
| :--- | :----------- | :------------- |
| **MiniMax H3 Max Recast** | ビデオ内の人物を参照写真の人物に置き換え、ソースの動き、カメラ、カット、サウンドを維持します | 5〜30秒のビデオ、1〜4枚の写真 |
| **MiniMax H3 Max Extend Video** | プロンプトで記述した新しい映像でビデオを続けます | 1.625〜60秒のビデオ、1〜15秒の新しい映像 |
| **MiniMax H3 Max Reframe Video** | ビデオを新しいアスペクト比に収め、その周囲の領域を生成します。タイミングとサウンドは維持されます | 0.5〜300秒のビデオ |
| **MiniMax H3 Max Insert Video** | 2つのタイムスタンプの間の区間を、新しく生成したシーンに置き換えます | 最大60秒のビデオと、開始時刻および再開時刻 |
| **MiniMax H3 Max Lip Sync** | 静止画をアニメーションさせ、口の動きをオーディオトラックに追従させます | 画像1枚、5〜899秒のオーディオ |
| **MiniMax H3 Max Camera Control** | 静止画の被写体の周囲をカメラが周回します | 画像1枚と、終了角度および距離 |

料金はノード、モデル、解像度、再生時間、参照入力によって決まります。価格バッジには、実行前に秒あたりの料金、おおよその範囲、または計算された合計が表示されます。たとえば Extend Video は H3 Max と H3 Max Turbo の両方に対応し、選択した再生時間、解像度、モデルから合計を計算します。解像度ごとの料金は[Minimaxの料金表](/ja/tutorials/partner-nodes/pricing)に記載されています。

Recast、Extend Video、Insert Videoのプロンプトでは、接続した参照を `@Image1`、`@Audio1`、`@Video1` として参照します。番号は接続順です。ノードはリクエストを送信する前に各タグを対応する参照に解決します。対応する種類の参照数を超えるタグがあると実行がエラーで停止し、ノードが受け付けない種類のタグ（例: Recast のオーディオ）はそのまま送信されます。

### Recast

ソースビデオの人物を1〜4枚の参照写真の人物に置き換えます。カメラ、カット、オリジナルのサウンドは維持されます。ソースビデオは5〜30秒で、各ショットは15秒以下、アスペクト比は0.4〜2.5である必要があります。写真は最低256x256ピクセル必要です。デフォルトでは左から右へ主要な人物を置き換えます。プロンプトで1人ずつ割り当てることもでき、例えば `the man becomes @Image2` のように指定します。デフォルトでは768P、または1080Pでレンダリングされ、**Enhance realism** を有効にすると肌のテクスチャがより自然になり、新しい人物がシーンに馴染みます。

### Extend Video

ビデオの末尾に1〜15秒の新しい映像を追加します。プロンプトにはソース映像ではなく、次に何が起きるかを記述します。MaxおよびTurboモデルに対応し、ソースビデオは1.625〜60秒、最大50 MB、アスペクト比は0.4〜2.5です。最大3つのオプションの参照オーディオで新しい映像を誘導できます。各2秒以上、合計14.5秒です。**Output** では、選択した解像度で再レンダリングされたビデオ全体（`extended`）か、新しい映像のみ（`continuation`。冒頭にソースの末尾が1.6秒繰り返されます）を返します。解像度は480P〜2Kです。2Kの場合、`extended` はソースと新規映像を合わせて45秒までに制限されます。

### Reframe Video

ビデオを新しいアスペクト比（16:9、9:16、1:1、4:3、3:4、21:9、9:21のいずれか）に収め直し、収め直したフレームの周囲の領域を生成します。ソースのタイミングとサウンドは維持されます。ソースビデオは0.5〜300秒で、オプションのプロンプトで生成される周囲の内容を誘導できます。480P、768P、または1080Pでレンダリングします。

### Insert Video

ビデオの `start_time` から `resume_time` までの区間を、新しく生成した5〜13秒のシーンに置き換えます。ソースビデオは最大60秒で、`resume_time` は末尾から少なくとも1.375秒前である必要があります。新しいシーンはプロンプトで、参照で、またはその両方で記述します。最大9枚の参照画像と3本の参照ビデオ（各2〜15秒、合計15秒）を使用できます。**Color match** はデフォルトで有効で、新しいシーンをソースに馴染ませます。480Pまたは768Pでレンダリングします。

### Lip Sync

静止画をアニメーションさせ、口の動きがオーディオトラックに追従するようにします。ビデオの長さはオーディオと同じになります。オーディオは5〜899秒です。画像は最低256x256ピクセル、アスペクト比は0.4〜2.5である必要があります。480P、768P、1080P、または2Kでレンダリングします。**Transcription** はデフォルトでオフです。オンにすると先にオーディオを文字起こしし、そのテキストを使って同期を誘導します。

### Camera Control

静止画から、カメラが被写体の周囲の新しい角度と距離へ移動するビデオを生成します。終了時のカメラは `azimuth`（水平方向の周回、正の値で右へ移動）、`elevation`（正の値で見下ろし、負の値で見上げる）、`distance`（1で距離を維持、1未満で近づき、1より大きいと引く）で設定します。**Create Camera Info** または **Compose Camera Angle Prompt** ノードからのカメラ情報入力を使うと、代わりに3Dビュー上で角度を設定できます。プロンプトを空にするとシーンが固定され、カメラだけが動きます。再生時間は1〜15秒で、480P、768P、1080Pに対応します。azimuthは正確な結果ではなく目標値です。90度を指定しても、実際には30〜90度の間に収まることがよくあります。
