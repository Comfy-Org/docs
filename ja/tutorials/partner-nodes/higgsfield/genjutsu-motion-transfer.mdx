**Higgsfield Genjutsu Motion Transfer** は、新しいビデオを生成するのではなく、既存のビデオを再構築します。ソースクリップは動き、カメラワーク、タイミング、オーディオをそのまま維持し、キャスト、ロケーション、衣装、スタイルは 1〜8 枚の参照画像から再構築されます。変更したい部分を説明すると、それ以外のショットは撮影時のまま維持されます。

Higgsfield は Genjutsu を Motion Transfer と Object Swap の 2 つのモードで提供しています。ComfyUI は Motion Transfer を `partner/video/Higgsfield` カテゴリの `HiggsfieldMotionTransferNode` を通じて公開しています。これはクラウド API ノードです。クレジット付きの Comfy アカウントが必要で、モデルをダウンロードせず、出力 1 秒単位で課金されます。これは結果の長さがソースクリップに従うためです。

このノードは、演技がすでに存在し、見た目だけを変更したい場合に便利です。スマートフォンで撮影したクリップを別のキャラクターで再演させたり、撮影をこれまで利用できなかったロケーションへ移したり、別の市場向けに映像のスタイルを変えたり、1 つのテイクから複数のバリエーションを個別に撮影することなく作成したりできます。

## ノードのコントロール

| コントロール | 値 | 効果 |
| --- | --- | --- |
| `model` | `genjutsu-v1.0` | Genjutsu モデル。これを選択すると、以下の入力が表示されます |
| `video` | 4～30 秒 | 動き、カメラワーク、タイミング、オーディオが保持されるソースクリップ。短いクリップは拒否され、長いクリップは最初の 30 秒にトリミングされます |
| `reference_images` | 1～8 枚の画像 | 使用するキャラクター、場所、またはスタイル。1 つのスロットにつき 1 枚の画像を接続します（`image_1`、`image_2` など）。バッチ入力は画像 1 枚につき 1 回としてカウントされ、すべてのスロットの合計は 8 を超えることはできません |
| `prompt` | テキスト、任意 | 結果を説明します。たとえば、どの参照がどの人物を置き換えるか、または新しい設定などです |
| `resolution` | `480p`、`720p`、`1080p` | 出力の解像度。デフォルトは `720p` |
| `seed` | 整数 | ノードを再実行するかどうかのみを制御します。同じシードでも実行ごとに結果が異なる場合があります |

出力の長さは準備されたソースクリップに従うため、12 秒のクリップは 12 秒のビデオを返します。

## プロンプトのヒント

- **各リファレンスが何を置き換えるのかを明記する。** プロンプトは任意ですが、どの画像がどの人物やオブジェクトに対応するのかを指定できる唯一の場所です。短い指示として記述します。たとえば、ダンサーを1枚目のリファレンス画像のキャラクターに置き換え、2枚目を新しい場面設定に使う、といった書き方です。
- **リファレンスは絞る。** 要素ごとに1枚の画像で通常は十分です。キャラクター、ロケーション、衣装の変更、スタイルなどが該当します。画像を増やすほどモデルが混ぜ合わせる要素が増え、結果の予測が難しくなります。
- **望む構図に合わせる。** 出力はソースクリップの動きとカメラを引き継ぐため、仕上がりに合った構図のソースビデオを選んでください。クローズアップの演技はクローズアップのままになります。
- **変更点を説明し、シーン全体は説明しない。** プロンプトに書かれていない部分はすべてリファレンスから再構築されるため、動きやテンポ、オーディオを繰り返し述べる必要はありません。
- **実行ごとのばらつきを想定する。** シードは結果を固定しません。同じ設定でも異なるテイクが生成されることがあります。

## はじめる

1. ComfyUI をバージョン 0.40.0 以降にアップデートします
2. **Template Library** に移動し、`Higgsfield Genjutsu` を検索します
3. ソースクリップを `LoadVideo` ノードに、参照画像を `LoadImage` ノードに読み込みます
4. プロンプトを入力し、`resolution` を選択して、ワークフローを実行します
