プロンプトは H3 のマルチモーダル学習が最も活きる場所です。ショット、カメラワーク、セリフ、効果音をすべて 1 つのプロンプトブロックにまとめられます。このページでは、ComfyUI における MiniMax H3 のプロンプト作成リソースを紹介します: MiniMax の公式ガイド、すべてのワークフローに共通するヒント、セリフと話者のルール、スタイル効果のためのプロンプト埋め込み。

## 公式ガイド

MiniMax は 2 つの公式プロンプト作成ガイドを公開しています。

- [ベース生成モード](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)（T2VA、I2VA、FL2VA、L2VA）: プロンプトを時間軸に沿ったショット構成にまとめ、カメラワークとオーディオ(セリフ、SFX、音楽)を組み合わせます。各モードの例も掲載されています
- [フルリファレンスモード](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_ref_en.md)（R2V）: リライト出力の構造(被写体の定義、参照ラベル、保持分析)と、ターゲットショットにおける各参照の役割の割り当て方法

MiniMax はインストール可能な [H3 skills](https://github.com/MiniMax-AI/MiniMax-H3/tree/main/skills) も公開しています。その中には、これらのガイドをエージェント向けにパッケージ化したプロンプト作成スキルが含まれます。

各ワークフローのページでは、これらのガイドを各テンプレートに適用した例を紹介しています: [テキストから動画・画像から動画](/ja/tutorials/video/minimax/minimax-h3-native)、[参照から動画](/ja/tutorials/video/minimax/minimax-h3-native#minimax-h3-リファレンスからビデオ-r2v)、[マルチフレーム参照](/ja/tutorials/video/minimax/minimax-h3-multiframe#プロンプト作成ガイド)、[Fun ControlNet Union](/ja/tutorials/video/minimax/minimax-h3-fun-controlnet#プロンプトのヒント)。

## 一般的なヒント

最終的なプロンプトは固定された構造に従います。I2VA のプロンプトは 1 行目に固定の画像位置合わせ文が入り、その後に空行を 1 行挟みます。例: `For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.` FL2VA と L2VA はこの行にそれぞれの固定文を使い、各参照画像をターゲット動画内の位置に合わせます。T2VA のプロンプトには指示行がなく、フィールドから直接始まります。本文には次の順序で 3 つのフィールドが入ります:

```text
integrated_multimodal_description: [Shot 1] ...
overall_soundscape: ...
non_diegetic_music: ...
```

プロンプト自体は英語で書きます。セリフと歌詞は `<d>` タグの中に、画面に表示されるテキストは元の言語のまま、どちらも原文どおりに保持します。

1. **シーン全体を説明する**: まずシーン全体(場所、登場人物、何が起きているか)を述べ、次に時間軸に沿ったショットに分割します。全体のスタイルと冒頭の構図は、画像位置合わせ指示の後に、`integrated_multimodal_description` 内の `[Shot 1]` の先頭に書きます
2. **ショット・カメラ・オーディオ**: ショット、カメラワーク、それに付随するオーディオ(セリフ、SFX、音楽)を 1 つのプロンプトブロックで記述します
3. **解像度**: H3 のネイティブキャンバスは短辺 768px で、16:9 では 1344x768 になります。解像度は 32 の倍数に丸められます。詳細は[出力解像度の設定](/ja/tutorials/video/minimax/minimax-h3#出力解像度の設定)を参照してください
4. **長さ**: ノードの `length` 入力は 24fps のフレーム数(デフォルト 124、約 5 秒)で、モデルの 17 フレームブロックグリッド(17k+5)に切り上げてスナップします
5. **画面内テキストは引用符で**: 画面に実際に表示されるテキスト(看板、バナー、字幕、ネオンサインなど)はすべて英語の二重引用符で囲み、1 つずつ個別に列挙します。元のテキストと句読点は翻訳せずそのまま写します。例: `A red neon sign reading "营业中" glows above the doorway.` セリフは `<d>` タグを使ってください。引用符は印刷テキスト用、`<d>` はキャラクターの発話用です
6. **R2V でのオーディオ再利用マーカー**: フルリファレンス(R2V)プロンプトでは、保持分析で各オーディオ参照の関係を宣言します。`fully_copy` はソース音声を 1:1 で最終音声トラックとして使用し、`partially_copy` はタイムラインの一部または選択したレイヤーのみをコピーするか、コピー後に他の音を追加・削除・置換し、`reference` は信号をコピーせずに声質、リズム、音楽スタイル、セリフの内容、または音の質感のみを参照し、`weak_reference` はカテゴリや雰囲気の大まかな類似のみを保持します。マーカーは、そのオーディオがターゲット動画で実際に果たす役割と一致している必要があります。公式フルリファレンスガイドのリレーションシップマーカーの表を参照してください
7. **オーディオレーンを明示する**: 各プロンプトには 2 つのオーディオフィールドがあり、ルールが異なります。`overall_soundscape` は動画全体の環境音、動作音、非言語の人の声を 1〜4 文で要約し(セリフ、歌唱、ダイジェティック音楽は `integrated_multimodal_description` に属し、ここには書きません)、クリップを完全な無音にする場合にのみ `N/A` を使います。`non_diegetic_music` は観客にだけ聞こえるスコアを 1〜3 文で記述し、そのような音楽がない場合は `N/A` を使います。静かなショットが意図しない話し声で返ってきたら、両方のフィールドを明示的に書き出して再生成してください。公式ベースガイドの `overall_soundscape` と `non_diegetic_music` のセクションを参照してください
8. **禁止は肯定形で書く**: H3 のテンプレートは条件入力が 1 つだけの `BasicGuider` ノードでサンプリングするため、ネガティブ分岐がなくネガティブプロンプトは効きません(ガイダーは `cfg` 1 で動作し、ComfyUI は無条件パスをスキップします。`CFGGuider` がネガティブ条件を使うのは `cfg` が 1 を超える場合だけです)。不要な要素を名指しする指示は、その記述自体がモデルの読む説明に加わり、それを差し引く別のパスがないため、`no subtitles and no on-screen text` のような書き方はテキストを画面内容として登録してしまいます。代わりに画面にあるべきものを書き、たとえば `the sign above the door is blank` とします。フルリファレンスプロンプトでは、同じ内容を保持分析で限定します(`fully_preserved`、`partially_preserved`、`attribute_transfer`、`weak_reference` が各参照の寄与を表します)

ワークフロー固有のプロンプト方法(参照タグ、タイムラインアンカー、コントロールビデオの長さ)は、各ワークフローのページで説明します。

## セリフと話者

どのワークフローでもセリフには固定のルールがあり、それらは公式ベースガイドの話者・セリフ・歌唱のセクションに基づきます。

- **安定した話者 ID**: プロンプト内のすべての声に `(S1)` や `(S2)` のような ID を付けます。画面外の声や歌唱も同じで、その声が話すすべてのショットで同じ ID を繰り返します。ID は被写体ではなく話者に振る番号です。発話しないキャラクターに ID は付かず、プロンプト内の最初の声は、そのキャラクターの番号が何であっても `(S1)` になります。同時に発声する話者は `(S1,S2)` のような複合 ID を使います
- **`<d>` の外側と内側**: 特徴づけの語句、話者 ID、動作、話し方はタグの外に書き、タグの中には言語タグとセリフの原文だけを原文どおりに入れます。各セリフはそれが話されるショットの中に、そのショットの動作と同じ段落で書きます
- **ボイスオーバー**: キャラクターが発話していないのに観客に聞こえるセリフには、正確なフレーズ `says in an off-screen voiceover` が必要で、さらに `<d>` ブロックの直後に、画面内のキャラクターの唇が閉じたままであることを明記します。カットをまたいで続くセリフは、両方の接続点に `<scenetrans>` を書き、音声がトランジションを越えて続くことも明記します
- **複数の話者とオーディオ参照**: フルリファレンス(R2V)プロンプトで 2 人以上の話者にそれぞれオーディオ参照を組み合わせる場合、プロンプトの記述と参照の接続順がどちらも正しくても、H3 がオーディオ参照を別の話者に渡すことがあります。各ショットではそのショットに必要な参照だけを使い、セリフは絶対タイムコードではなく可視の出来事に結び付けます。例えば `When the phone is at his ear, the man in the coat speaks` のように書きます。タイムコードはカット用です。それでもセリフが別の話者に割り当てられるときは、音声ツールでそのセリフを生成し、その話者のオーディオ参照として渡したうえで、そのクリップの実際の使われ方に合う関係マーカーを選びます。クリップが動画の完全な最終音声トラックになる場合は `fully_copy`、タイムラインの一部だけをカバーする場合は `partially_copy` です

## プロンプト埋め込み

[Comfy-Org/ComfyUI#15697](https://github.com/Comfy-Org/ComfyUI/pull/15697) により、MiniMax H3 でプロンプト埋め込みがサポートされました。H3 のプロンプトで ComfyUI 標準の `embedding:` 構文を使用できます。

埋め込みファイルを `ComfyUI/models/embeddings/` に置き、プロンプト内で名前で参照します(例: `embedding:my_embedding`)。埋め込みは他の ComfyUI モデルと同様に読み込まれ、テキスト条件に混合されます。

[Comfy-Org/MiniMax-H3](https://huggingface.co/Comfy-Org/MiniMax-H3/tree/main/embeddings) リポジトリの `embeddings` フォルダには、10 個のスタイル埋め込みがホストされています。これらのファイルは非公式です。コミュニティメンバーの [silveroxides](https://huggingface.co/silveroxides) が [Hugging Face PR #50](https://huggingface.co/Comfy-Org/MiniMax-H3/discussions/50) 経由で投稿したもので、Comfy-Org や MiniMax が作成したものではありません。オリジナルのファイルは [silveroxides/MiniMax-H3_tests](https://huggingface.co/silveroxides/MiniMax-H3_tests/tree/main/embeddings) リポジトリにあります。ファイル名が意図する効果を表し、トリガーワードは拡張子を除いたファイル名です:

| 埋め込み | 効果(ファイル名より) |
|---|---|
| `minimaxh3_art_is_explosion` | 爆発するようなアート構図 |
| `minimaxh3_blooming_flowers` | 花が咲く |
| `minimaxh3_bullet_time` | バレットタイム効果 |
| `minimaxh3_dark_magic` | ダークマジックの雰囲気 |
| `minimaxh3_fire_breath` | 火を吐く効果 |
| `minimaxh3_four_seasons` | 四季の移り変わり |
| `minimaxh3_kiss_camera` | キスシーンのカメラワーク |
| `minimaxh3_spiral_ascent` | 螺旋上昇 |
| `minimaxh3_storm_magic` | ストームマジック |
| `minimaxh3_truman_show` | トルーマン・ショー風 |
