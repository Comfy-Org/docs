**Wan2.1 InfiniteTalk** は、[MeiGen-AI](https://github.com/MeiGen-AI/InfiniteTalk) が開発した、Wan2.1 をベースに構築されたオープンソースのオーディオ駆動型ビデオ生成モデルです。1枚の参照画像とオーディオ入力から、全身トーキングビデオを生成できます。キャラクターの口の動きと体の動きは、指定したオーディオに合わせて自動的に同期されます。

**主な機能**:
- **オーディオ駆動のリップシンク**: 入力オーディオに合った自然な口の動きを生成
- **全身の動き**: 同一性、背景、カメラワークを保ちながら、同期した体の動きを追加
- **デュアルモード**: 単一キャラクターと複数キャラクターの両方のシナリオに対応
- **ComfyUI ネイティブ**: 組み込みの `WanInfiniteTalkToVideo` ノードがあり、カスタムノードは不要

## ワークフローの手順

1. **入力画像を読み込む**: キャラクターの参照画像を `Load Image` ノードにドラッグします。複数キャラクターのシナリオでは、マスクエディターを使って各キャラクターのマスクを描画します。
2. **オーディオトラックを読み込む**: オーディオファイルを `Load Audio` ノードに接続します（キャラクターごとに1つ）。
3. **拡散モデルを読み込む**: `Load Diffusion Model` ノードが `Wan2_1-I2V-14B-480p_fp8_e4m3fn_scaled_KJ.safetensors` を使用していることを確認します。
4. **モデルパッチを読み込む**: `ModelPatchLoader` ノードを介して、適切な InfiniteTalk パッチ（`single` または `multi` バリアント）を読み込みます。
5. **InfiniteTalk を設定する**: `WanInfiniteTalkToVideo` ノードのパラメータを調整します。例えば、`length`（フレーム単位のビデオ長）、`motion_frame_count`（モーションコンテキストとして使用する過去のフレーム）、`audio_scale` などです。
6. **生成**: ワークフローを実行します。モデルは、入力オーディオに同期した全身トーキングビデオを生成します。

### ビデオ長の延長

各 **Video Extend** グループは、ビデオを約 3.24 秒（25 fps で 81 フレーム）延長します。オーディオがそれより長い場合は、次の操作を行います。

1. 「Video Extend」グループをボックス選択します
2. `Ctrl-C`（コピー）を押し、続けて `Ctrl-Shift-V`（接続を保ったまま貼り付け）を押します
3. 前の `InfiniteTalk (Base Generation)` ノードの `IMAGE` 出力を、新しい `WanInfiniteTalkToVideo` ノードの `previous_frames` 入力に接続します
4. `Batch Images` ノードの `IMAGE` 出力を、新しい `Batch Images` ノードの画像入力に接続します

## よくある質問

<AccordionGroup>
  <Accordion title="ComfyUI が「Not enough GPU memory」と表示するのはなぜですか？">
    このメッセージは ComfyUI の汎用的なメモリ不足のテキストです。このテンプレートには batch size の設定がないため、下げられるバッチ数はありません。読み込むモデルファイルは合計約 30 GB です。`Wan2_1-I2V-14B-480p_fp8_e4m3fn_scaled_KJ` 拡散モデル（16.6 GB）、`umt5_xxl_fp8` テキストエンコーダー（6.7 GB）、InfiniteTalk パッチ（5.1 GB）。既定の 832 x 480、81 フレームではサンプリング用バッファの余裕がほとんど残らないため、そこで停止します。
  </Accordion>
  <Accordion title="最初に何を下げればよいですか？">
    メモリへの影響が大きい2つの値を下げてから再実行します。**Width** と **Height** は InfiniteTalk グループの上にある `PrimitiveInt` ノードで、既定値は 832 x 480 です。どちらも 16 で割り切れる必要があるため、640 x 368 が有効な小さい組み合わせです。`WanInfiniteTalkToVideo` の **length** は既定 81 フレーム、ステップは 4 なので、有効な値は 4n+1（例: 49）です。それでも足りない場合は、`motion_frame_count`（既定 9、最大 33）を下げてモーションコンテキストのフレームを減らし、テスト中は余分な **Video Extend** グループを削除してください。
  </Accordion>
  <Accordion title="single パッチにするとメモリは減りますか？">
    パッチ自体では減りません。2つのパッチファイルのサイズはほぼ同じです（`single` 5.13 GB、`multi` 5.12 GB）。減るのは話者を1人だけにした場合で、2つ目のオーディオエンコーダー出力と2つのマスク入力が不要になります。パッチはモードと一致させる必要があるため、ノードのモードを `single_speaker` にするときだけ `ModelPatchLoader` を `single` に切り替えてください。
  </Accordion>
  <Accordion title="このワークフローは Mac で動きますか？">
    動きますが、Apple Silicon では CPU と GPU が1つのユニファイドメモリを共有するため、独立した VRAM を満杯にしたり解放したりする概念がありません。ComfyUI はマシンの総メモリをデバイスが使えるメモリとして扱い、他のアプリも同じプールから消費します。32 GB の Mac は約 30 GB のモデルファイルとサンプリング用バッファを同時に保持する必要があるため、既定設定ではメモリ不足になります。[システム要件](/ja/installation/system_requirements) で MPS バックエンドを説明しています。
  </Accordion>
  <Accordion title="macOS では VRAM 関連の起動オプションは効果がありますか？">
    ありません。Apple Silicon では ComfyUI が VRAM モードを共有メモリに固定するため（`comfy/model_management.py`）、`--lowvram`、`--novram`、`--highvram` は上書きされます。重みをユニファイドプールの外に移す場所がないためです。Nvidia と ROCm の GPU では dynamic VRAM が既定で有効になり、有効な間は `--lowvram` が効果を発揮しないため、これらの環境でもほとんど役に立ちません。[起動オプション](/ja/development/comfyui-server/startup-flags) を参照してください。Mac で有効なのは、メモリを多く使う他のアプリを終了する、上記のとおり解像度とフレーム数を下げる、`--cache-none` を付けて ComfyUI を起動しノード出力を実行間にキャッシュしない、の3つです。
  </Accordion>
  <Accordion title="それでもメモリ不足になる場合は？">
    macOS では PyTorch がデバイスの推奨ワーキングセットサイズの 1.7 倍を超える MPS 割り当てを拒否し、実行がこの上限に当たることがよくあります。`PYTORCH_MPS_HIGH_WATERMARK_RATIO=0.0` はこの上限を外しますが、Mac がスワップに入ったり他のアプリが固まったりする可能性があるため、最後の手段としてのみ使用してください。
  </Accordion>
  <Accordion title="Apple Silicon で fp8 モデルを使うとメモリは節約できますか？">
    NVIDIA GPU のようには節約できません。MPS には PyTorch の fp8 演算カーネルがないため、重みは bf16 に変換して実行されます。bf16 のコピーがメモリに収まる場合は読み込み時にモデルが展開され、fp8 ファイルは bf16 とほぼ同じメモリを使います。収まらない場合は重みは fp8 のまま保持され演算時に変換されるため、メモリと引き換えに速度を失います。Mac で効くのは解像度とフレーム数です。
  </Accordion>
</AccordionGroup>
