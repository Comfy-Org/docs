セルフホスティングとは、ComfyUI を自分で実行し、それを API として呼び出すことを意味します。ハードウェア、モデル、カスタムノードはすべて自分で管理することになりますが、その代わりに完全な制御を得られます。任意の GPU、任意のモデル、任意のノードパックを使用でき、データが自分のインフラストラクチャの外に出ることはありません。

ComfyUI はデフォルトで HTTP サーバーとして動作するため、正常に動作しているインストールはすでに API エンドポイントです。以下の選択肢は、そのインストールがどこにあるかという点だけが異なります。

## 自分のハードウェア

最もシンプルなデプロイは、目の前にあるマシンです。ComfyUI をインストールすれば、そのまま `http://127.0.0.1:8188` でサービスが提供されます:

- Linux、macOS、Windows 向けの[手動インストール](/ja/installation/manual_install)。サーバーではこれがスタンダードな選択です
- ローカル開発には [Comfy Desktop](/ja/installation/desktop/overview) または [Windows ポータブル版](/ja/installation/comfyui_portable_windows)

ヘッドレス（ブラウザなし）で実行する場合や、デフォルト以外のアドレスで待ち受ける場合は、[サーバー起動フラグ](/ja/development/comfyui-server/startup-flags)を参照してください。例:

```bash
python main.py --listen 0.0.0.0 --port 8188
```

<Warning>
  ComfyUI サーバーにはデフォルトで認証がありません。信頼できるネットワーク上でのみ非ループバックアドレスにバインドするか、認証付きのリバースプロキシを前段に配置してください。
</Warning>

## GPUクラウドプロバイダー

GPUをお持ちでない場合は、レンタルしてComfyUIを実行できます。コミュニティでよく利用されているプロバイダーには次のようなものがあります:

- **[Runpod](https://www.runpod.io)**: コミュニティのComfyUIテンプレートがあらかじめ設定されたGPUポッドを提供。
- **[Vast.ai](https://vast.ai)**: GPUマーケットプレイス。ここでもコミュニティのComfyUIテンプレートが利用できます。

これらのプロバイダーでは、通常はコミュニティのテンプレートまたはイメージから始めて、そこにモデルとカスタムノードを追加します。結果として、公開URLまたはSSHトンネルを前面に備えた、通常のセルフホスト型ComfyUIになります。

<Note>
  これらのテンプレートはコミュニティによって維持されているものであり、ComfyUIチームによって公開またはサポートされているものではありません。認証情報やプライベートモデルを配置する前に、テンプレートが何をインストールするのかを確認してください。
</Note>

このワークフローのマネージド版が必要で、ビルド、リリース、オートスケーリングを任せたい場合は、[Developer PlatformでのComfy APIデプロイ](/ja/development/serverless/overview)をご利用ください。

## コミュニティ Docker イメージ

<DockerNotice />

コンテナ化された ComfyUI は、他のセルフホストインストールとまったく同じように動作します。サーバーポートを公開し、通常どおり呼び出すだけです。

## 次のステップ: これに対してワークフローを実行する

セルフホスト型のデプロイメントは、2つの方法で呼び出すことができます:

<CardGroup cols={2}>
  <Card title="Comfy SDKs + API Proxy" icon="code" href="/ja/development/comfyui-server/api-proxy">
    公式SDKを使って自身のインスタンスを呼び出します。v2ベータの間は、ComfyUIと並行して動作する小さなサービスであるAPI Proxyが必要です。
  </Card>
  <Card title="ComfyUI Server API" icon="server" href="/ja/development/comfyui-server/comms_overview">
    追加のサービスなしで、生のRESTおよびWebSocket APIを直接呼び出します。ローカルの全機能を利用できますが、リリース間の互換性は保証されません。
  </Card>
</CardGroup>
