Comfy Cloud API 経由で送信されたワークフローは、他のクラウドのワークフローと同じクレジットおよび同時実行数の上限を使用します。

## クレジットと使用量

APIリクエストは、Comfy Cloud Web UI と同じ月額クレジットの割り当てから消費されます。API専用のクレジットプールはありません。各プランに含まれるクレジット、トップアップのオプション、ワークフローごとの実行時間上限は、UIジョブと同様にAPIジョブにも適用されます。

月額クレジットの量とトップアップのオプションについては、[料金ページ](https://www.comfy.org/cloud/pricing?utm_source=docs&utm_campaign=cloud-api)を参照してください。トップアップはアカウントのダッシュボードから購入できます。

## 同時実行の上限 {#concurrency-limits}

前のジョブの完了を待たずに複数のワークフローを送信できます。ジョブはサブスクリプションのプラン上限まで並列で実行されます:

| プラン | 同時実行ワークフロー数 |
| :------- | :------------------- |
| スタンダード | 1                    |
| クリエイター | 3                    |
| プロ | 5                    |

チームプランでは、プロよりもメンバーあたりの同時実行ワークフロー数が多くなります。アカウントの同時実行数については [platform.comfy.org](https://platform.comfy.org) を確認してください。追加のジョブはキューに入り、スロットが空き次第実行されます。

キューが満杯の場合、SDK は一定の範囲内でリトライした後、`QueueFull` を発生させます。

チームプランとエンタープライズプランでは、同時実行数はメンバーごとに設定されます。ワークスペース内の全員がそれぞれ独自の同時実行上限を持つため、あるメンバーの実行中ジョブが別のメンバーをブロックすることはありません。

<Info>
  複数のジョブを同時に実行できるのは API 経由のみです。Comfy Cloud UI では 1 人につき 1 つのワークフローが実行され、エディタでキューに入れたワークフローは順番に実行されます。サブスクリプションの詳細は[料金ページ](https://www.comfy.org/cloud/pricing?utm_source=docs&utm_campaign=cloud-api)をご覧ください。
</Info>

## ランタイムとキューの上限

すべてのクラウドワークフローには最大ランタイムがあります。制限時間を超えて実行されたジョブは自動的にキャンセルされます：

| プラン       | 最大ランタイム |
| :----------- | :------------- |
| スタンダード | 30分           |
| クリエイター | 30分           |
| プロ         | 1時間          |

ワークフローは一度に最大100件までキューに追加できます。チームの同時実行の上限を引き上げるには、[サポートに連絡](https://support.comfy.org/)してください。

## デプロイメントの課金

カスタムビルドの[デプロイメント](/ja/development/serverless/overview)は、ワーカーの GPU 時間とモデルのストレージを Comfy クレジットから課金します。

### デプロイしていないビルドの保存に料金はかかりますか？

いいえ。ビルドとそのバージョンは無料で保存されます。ストレージの課金はデプロイした時点で始まります:

- バージョンをデプロイすると、Comfy Cloud はそのモデルをデプロイメントのワーカーが共有するネットワークストレージにコピーします。Comfy Cloud は、そのリージョンにそのビルドのデプロイメントが存在する限り、デプロイメントが停止している間も含めて、ストレージを GB 単位・月単位で課金します。ジョブが[ワークスペースライブラリ](/ja/development/deploy/cloud-custom-builds#自分の-lora-やモデルを追加する)から使用するモデルはそこにコピーされません。ワーカーがジョブのためにそれらをダウンロードします。
  - [デプロイメントに追加](/ja/development/serverless/overview#実行中のデプロイにモデルを追加する)したモデルも同様にそこへコピーされ、そのストレージとしてカウントされます。
- 各ワーカーのローカルディスクには、GPU 料金以外の追加料金はかかりません。
- デプロイメントを削除すると、そのコンピュートは解放されます。ネットワークストレージの課金は、それを使用する最後のデプロイメントを削除した時点で終了します。

ストレージと GPU の料金については、Developer Platform の[**Limits**](https://platform.comfy.org/settings/limits)を開き、**Deployment pricing** を確認してください。デプロイダイアログの **Estimated cost** パネルにも、デプロイメントの GPU 時間とモデルストレージが表示されます。

### 常時ウォーム状態のワーカーはどのように課金されますか？

[常時ウォーム状態のワーカー](/ja/development/serverless/overview#ワーカーをスケールする)（comfy-cli の `--min`）は、ジョブを処理しているかどうかに関わらず、実行されている間ずっと GPU 時間が課金されます。

その数を超えるワーカーは、**Max workers**（`--max`）まで、ジョブが到着したときに起動します。これらのワーカーは、起動した瞬間からジョブの処理を通じて、そして最後のジョブの後、解放されるまでのアイドル時間について GPU 時間が課金されます。デフォルトでは、ワーカーは最後のジョブの後 3 分間起動したままになります。Developer Platform でデプロイメントを作成する際、**Keep worker up after a job** でこの時間を 30 秒から 20 分の範囲で設定できます。常時ウォーム状態のワーカーが `0` の場合、そのアイドル時間が終了してすべてのワーカーが解放されると、GPU の課金は停止します。次のジョブは GPU の起動を待つことになります。

ワークスペースのクレジットが不足すると、そのデプロイメントは停止します。

GPU の料金については、Developer Platform の[**Limits**](https://platform.comfy.org/settings/limits)を開き、**Deployment pricing** を確認してください。料金はワーカーごと、実行時間 1 時間あたりです。

## 既存の v1 統合

非推奨の [v1 Cloud API](/ja/development/cloud/overview) も Comfy Cloud 上で動作します。既存の統合や、[Comfy API v2](/ja/api-reference/v2/overview) ではまだ利用できない Cloud の機能にはこちらを使用してください。実行可能なサンプルは、非推奨の [Cloud API Reference](/ja/development/cloud/api-reference) にあります。
