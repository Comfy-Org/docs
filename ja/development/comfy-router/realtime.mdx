Comfy Routerは、falが提供するxAIのGrok Voiceとのリアルタイム音声対音声セッションを中継します。Comfy APIキーを使ってRouterへのWebSocketを1本開きます。Routerはアカウントとクレジットを確認し、上流でセッションを開いてから、イベントを双方向に中継します。セッションの秒数に応じてComfyクレジットから支払います。

## エンドポイント

```text
wss://api.comfy.org/v2/realtime/fal/xai/grok-voice/realtime
```

リクエストは WebSocket アップグレードです（`GET` に `Connection: Upgrade` と `Upgrade: websocket` を指定）。それ以外のリクエストは `426` で拒否されます。

## 認証

アップグレードリクエストのヘッダーで、`X-API-Key: comfyui-...` または `Authorization: Bearer comfyui-...` のいずれかの形式で Comfy APIキーを送信してください。Router はクエリ文字列や WebSocket サブプロトコルからキーを読み取りません。

<Warning>
ブラウザは WebSocket にヘッダーを設定できず、Comfy APIキーがブラウザに渡っては決してなりません。サーバーからセッションを開き、オーディオを自身でブラウザへ中継してください。
</Warning>

## 接続

アップグレードが成功したら、xAI が Grok Voice 向けにドキュメント化しているリアルタイムイベントを送受信します。この例ではセッションを設定し、1 回のテキストターンを送信して、受信した各イベントタイプを出力します。

<CodeGroup>

```python Python
# pip install websockets msgpack
import asyncio
import os

import msgpack
import websockets

URL = "wss://api.comfy.org/v2/realtime/fal/xai/grok-voice/realtime"


async def send(ws, event):
    await ws.send(msgpack.packb(event))


async def main():
    async with websockets.connect(
        URL,
        additional_headers={"X-API-Key": os.environ["COMFY_API_KEY"]},
    ) as ws:
        await send(ws, {
            "type": "session.update",
            "session": {
                "voice": "eve",
                "instructions": "You are a helpful assistant.",
                "turn_detection": {"type": "server_vad"},
            },
        })
        await send(ws, {
            "type": "conversation.item.create",
            "item": {
                "type": "message",
                "role": "user",
                "content": [{"type": "input_text", "text": "Hello!"}],
            },
        })
        await send(ws, {"type": "response.create"})

        async for message in ws:
            if isinstance(message, str):
                continue  # fal 独自の x-fal-message フレーム
            event = msgpack.unpackb(message)
            print(event["type"])
            if event["type"] == "response.done":
                break


asyncio.run(main())
```

```javascript Node.js
// npm install ws @msgpack/msgpack
import WebSocket from "ws";
import { encode, decode } from "@msgpack/msgpack";

const ws = new WebSocket(
  "wss://api.comfy.org/v2/realtime/fal/xai/grok-voice/realtime",
  { headers: { "X-API-Key": process.env.COMFY_API_KEY } },
);

ws.on("unexpected-response", (req, res) => {
  // アップグレードは拒否されました。JSON ボディに理由が示されます。
  let body = "";
  res.on("data", (chunk) => (body += chunk));
  res.on("end", () => console.error(res.statusCode, body));
});

const send = (event) => ws.send(encode(event));

ws.on("open", () => {
  send({
    type: "session.update",
    session: {
      voice: "eve",
      instructions: "You are a helpful assistant.",
      turn_detection: { type: "server_vad" },
    },
  });
  send({
    type: "conversation.item.create",
    item: {
      type: "message",
      role: "user",
      content: [{ type: "input_text", text: "Hello!" }],
    },
  });
  send({ type: "response.create" });
});

ws.on("message", (data, isBinary) => {
  if (!isBinary) return; // fal 独自の x-fal-message フレーム
  const event = decode(data);
  console.log(event.type);
  if (event.type === "response.done") ws.close();
});

ws.on("close", (code) => console.log("closed", code));
```

</CodeGroup>

終わったらすぐにソケットを閉じてください。課金は最後のレスポンスまでではなく、セッションが閉じるまで続きます。

## イベント

Router は独自のイベントプロトコルを定義していません。サーバーイベントは fal が送信するそのままの形で届き、Router が受け付けるクライアントイベントは変更されずに転送されます。イベント一覧、セッションフィールド、ボイス、オーディオ形式については、次を参照してください:

- [xAI Speech to Speech](https://docs.x.ai/developers/model-capabilities/audio/speech-to-speech) および xAI の [realtime イベントスキーマ](https://docs.x.ai/voice-realtime.ws.json)
- fal の [Grok Voice realtime モデルページ](https://fal.ai/models/xai/grok-voice/realtime) とその [API ページ](https://fal.ai/models/xai/grok-voice/realtime/api)

各クライアントイベントは、例のように 1 つの msgpack バイナリメッセージとして送信してください。これは fal の realtime クライアントが使用するフレーミングであり、モデルのイベントも同じ方法で、`session.created` で始まる msgpack バイナリメッセージとして返されます。fal はさらに、タイプ `x-fal-message` の独自の JSON テキストメッセージ（タイミング情報）も送信します。これらはスキップできます。Router のチェックでは、クライアントイベントを 1 つの JSON テキストメッセージとして受け取ることもできますが、クライアントで JSON をテストしていない限り msgpack を使用してください。

Router は転送する前に各クライアントイベントをチェックします:

- **イベントタイプ:** `session.update`、`input_audio_buffer.append`、`input_audio_buffer.commit`、`input_audio_buffer.clear`、`conversation.item.create`、`conversation.item.delete`、`conversation.item.truncate`、`response.create`、`response.cancel`、および fal の `x-fal-session.configure`。
- **モデル:** `session.update` 内の `model` は `grok-voice-latest`、`grok-voice-3.0`、または `grok-voice-2.0` でなければなりません。
- **ツール:** クライアントが実行する関数ツールは許可されます。サーバー側ツール（Web 検索、X 検索、ファイル検索、MCP）は拒否されます。
- **メディア:** 画像およびビデオ入力は拒否されます。セッションは音声とテキストのみです。
- **サイズ:** 1 つのクライアントメッセージは最大 1 MiB です。

拒否されたイベントは転送されず、Router はクローズコード `1008` でセッションを閉じます。

## 料金

セッションの料金は**1秒あたり$0.0011869**です（1分あたり約$0.0712、または1秒あたり0.2504クレジット、1分あたり約15.0クレジット、211クレジット = 1米ドルの場合）。セッションが開いている間は15秒単位で課金され、最後の端数分は秒単位で切り上げて課金されます。課金はアップグレード時点からソケットが閉じるまで継続し、オーディオが流れているかどうかは関係ありません。

## 制限

| 制限 | 値 |
| --- | --- |
| アカウントあたりのセッション数 | 同時に開けるセッションは 1 つです。2 つ目を開くと、`router.realtime.session_already_live` を伴う `429` が返されます。 |
| セッションの長さ | 最大 30 分で、接続時点であなたのクレジット残高が賄える時間を超えることはありません。 |
| セッション中のクレジット | Router は 15 秒ごとにあなたの残高を再確認し、残高が次の 1 秒分を賄えなくなるとセッションを終了します。 |
| 接続レート | 各アップグレード試行は、あなたの[呼び出し元ごとのリクエストレート](/ja/development/comfy-router/limitations#リクエストは呼び出し元ごとにレート制限される)にカウントされ、他の Router 呼び出しと共有されます。 |

セッションが時間制限に達した場合、またはクレジットが不足した場合、接続はクローズフレームなしで閉じられることがあります（多くの場合、クローズコード `1006` として現れます）。クレジットを追加した後にのみ再接続するか、より長い時間が必要な場合は新しいセッションを開始してください。

## エラー

### アップグレード前

Router が接続を拒否した場合、プロトコルを切り替えずに HTTP ステータスと JSON ボディで応答します:

```json
{
  "detail": "Insufficient credits to open a realtime session.",
  "error_type": "insufficient_credits",
  "code": "router.realtime.insufficient_credits"
}
```

分岐には `code` を使用してください。`detail` は人間向けです。

| ステータス | `code` | 原因 | 対処 |
| --- | --- | --- | --- |
| `426` | `router.realtime.upgrade_required` | リクエストが WebSocket のアップグレードではありませんでした。 | WebSocket クライアントで接続してください。 |
| `401` | `router.realtime.unauthorized` | APIキーが不足しているか、無効です。 | 有効なキーを `X-API-Key` または `Authorization: Bearer` で送信してください。 |
| `402` | `router.realtime.insufficient_credits` | 残高がセッションの最低1秒分にも満たない状態です。 | クレジットを追加してから再接続してください。 |
| `402` | `router.realtime.spend_denied` | セッションの課金対象となるウォレットに資金がありません。ボディ内の `denied_reason` と `billed_workspace` がどのウォレットかを示します。 | そのワークスペースにクレジットを追加してから再接続してください。 |
| `403` | `router.realtime.provider_disabled` | ワークスペースのパートナープロバイダーポリシーがこのプロバイダーを許可していません。 | ワークスペースの管理者に許可を依頼してください。 |
| `404` | `router.realtime.model_not_allowed` | URL 内のモデルはリアルタイムでは利用不可です。 | URL を確認してください。 |
| `429` | `router.realtime.rate_limited` | リクエストレートを超過しました。 | `Retry-After` の時間だけ待ってから再試行してください。 |
| `429` | `router.realtime.session_already_live` | アカウントで既に別のセッションが開かれています。 | 先にそのセッションを閉じてください。 |
| `429` | `router.realtime.concurrency_limit` | パートナーモデルの同時呼び出し数が多すぎます。 | 同時実行数を減らしてから再試行してください。 |
| `502` | `router.realtime.upstream_refused`, `router.realtime.token_mint_failed` | 上流プロバイダーがセッションを開きませんでした。 | バックオフを伴って再試行してください。 |
| `503` | その他の `router.realtime.*` コード | リアルタイムセッションが一時的に利用できません。 | バックオフを伴って再試行してください。 |

### アップグレード後

| クローズコード | 意味 | 対処 |
| --- | --- | --- |
| `1008` | クライアントイベントが拒否されました（[イベント](#イベント) を参照）。 | イベントを修正してください。セッションは終了します。 |
| `1012` | Router が再起動中です。 | 再接続してください。新しいセッションが開始され、新しいアップグレード時点から課金されます。 |
| `1006`（クローズフレームなし） | セッションが時間制限に達した、またはクレジットが不足した際にクライアントが報告する値としてよく見られます。ネットワーク切断も同じように見えます。 | クレジットを追加するか、新しいセッションを開始してください。 |

その他のクローズコードは fal または xAI からのものです。[イベント](#イベント) でリンクされている各社のドキュメントを参照してください。
