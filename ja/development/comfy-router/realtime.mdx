Comfy Routerは、falが提供するxAIのGrok Voiceとのリアルタイムなspeech-to-speechセッションを中継します。Comfy APIキーを使ってRouterへのWebSocketを1本開きます。Routerはアカウントとクレジットを確認し、上流でセッションを開いてから、イベントを双方向に中継します。セッションの秒数に応じて、Comfyのクレジットから支払います。

## エンドポイント

```text
wss://api.comfy.org/v2/realtime/fal/xai/grok-voice/realtime
```

リクエストは WebSocket のアップグレードです（`Connection: Upgrade` と `Upgrade: websocket` を伴う `GET`）。それ以外は `426` で拒否されます。

## 認証

アップグレードリクエストのヘッダーで Comfy APIキーを送信します。`X-API-Key: comfyui-...` または `Authorization: Bearer comfyui-...` のいずれかを使用します。Router はクエリ文字列や WebSocket サブプロトコルからキーを読み取りません。

<Warning>
ブラウザは WebSocket でヘッダーを設定できず、Comfy APIキーがブラウザに到達してはなりません。サーバーからセッションを開き、オーディオを自分でブラウザに中継してください。
</Warning>

## 接続

アップグレードが成功したら、xAI が Grok Voice 向けにドキュメント化しているリアルタイムイベントを送受信します。この例では、セッションを設定し、1回のテキストターンを送信して、受信した各イベントタイプを出力します。

<CodeGroup>

```python Python
# pip install websockets msgpack
import asyncio
import os

import msgpack
import websockets

URL = "wss://api.comfy.org/v2/realtime/fal/xai/grok-voice/realtime"


async def send(ws, event):
    await ws.send(msgpack.packb(event))


async def main():
    async with websockets.connect(
        URL,
        additional_headers={"X-API-Key": os.environ["COMFY_API_KEY"]},
    ) as ws:
        await send(ws, {
            "type": "session.update",
            "session": {
                "voice": "eve",
                "instructions": "You are a helpful assistant.",
                "turn_detection": {"type": "server_vad"},
            },
        })
        await send(ws, {
            "type": "conversation.item.create",
            "item": {
                "type": "message",
                "role": "user",
                "content": [{"type": "input_text", "text": "Hello!"}],
            },
        })
        await send(ws, {"type": "response.create"})

        async for message in ws:
            if isinstance(message, str):
                continue  # fal 独自の x-fal-message フレーム
            event = msgpack.unpackb(message)
            print(event["type"])
            if event["type"] == "response.done":
                break


asyncio.run(main())
```

```javascript Node.js
// npm install ws @msgpack/msgpack
import WebSocket from "ws";
import { encode, decode } from "@msgpack/msgpack";

const ws = new WebSocket(
  "wss://api.comfy.org/v2/realtime/fal/xai/grok-voice/realtime",
  { headers: { "X-API-Key": process.env.COMFY_API_KEY } },
);

ws.on("unexpected-response", (req, res) => {
  // アップグレードが拒否されました。JSON ボディに理由が示されます。
  let body = "";
  res.on("data", (chunk) => (body += chunk));
  res.on("end", () => console.error(res.statusCode, body));
});

const send = (event) => ws.send(encode(event));

ws.on("open", () => {
  send({
    type: "session.update",
    session: {
      voice: "eve",
      instructions: "You are a helpful assistant.",
      turn_detection: { type: "server_vad" },
    },
  });
  send({
    type: "conversation.item.create",
    item: {
      type: "message",
      role: "user",
      content: [{ type: "input_text", text: "Hello!" }],
    },
  });
  send({ type: "response.create" });
});

ws.on("message", (data, isBinary) => {
  if (!isBinary) return; // fal 独自の x-fal-message フレーム
  const event = decode(data);
  console.log(event.type);
  if (event.type === "response.done") ws.close();
});

ws.on("close", (code) => console.log("closed", code));
```

</CodeGroup>

終わったらすぐにソケットを閉じてください。課金は最後の応答までではなく、セッションが閉じるまで発生します。

## イベント

Router は独自のイベントプロトコルを定義していません。サーバーイベントは fal が送信したそのままの形で届き、Router が受け付けるクライアントイベントは変更されずに転送されます。イベント一覧、セッションフィールド、音声、オーディオ形式については、以下を参照してください。

- [xAI Speech to Speech](https://docs.x.ai/developers/model-capabilities/audio/speech-to-speech) と xAI の [realtime event schema](https://docs.x.ai/voice-realtime.ws.json)
- fal の [Grok Voice realtime モデルページ](https://fal.ai/models/xai/grok-voice/realtime) とその [API ページ](https://fal.ai/models/xai/grok-voice/realtime/api)

例のように、各クライアントイベントを 1 つの msgpack バイナリメッセージとして送信してください。これは fal の realtime クライアントが使用するフレーミングであり、モデルのイベントも同じ方法で、`session.created` で始まる msgpack バイナリメッセージとして返されます。fal はさらに、タイプ `x-fal-message` の独自の JSON テキストメッセージ（タイミング情報）も送信しますが、これらはスキップしてかまいません。Router のチェックはクライアントイベントを 1 つの JSON テキストメッセージとしても受け付けますが、クライアントで JSON をテスト済みでない限り msgpack を使用してください。

Router は転送する前に各クライアントイベントをチェックします。

- **イベントタイプ:** `session.update`、`input_audio_buffer.append`、`input_audio_buffer.commit`、`input_audio_buffer.clear`、`conversation.item.create`、`conversation.item.delete`、`conversation.item.truncate`、`response.create`、`response.cancel`、および fal の `x-fal-session.configure`。
- **モデル:** `session.update` 内の `model` は `grok-voice-latest`、`grok-voice-3.0`、または `grok-voice-2.0` である必要があります。
- **ツール:** クライアントが実行する関数ツールは許可されます。サーバー側ツール（Web検索、X検索、ファイル検索、MCP）は拒否されます。
- **メディア:** 画像およびビデオ入力は拒否されます。セッションは音声とテキストのみです。
- **サイズ:** 1 つのクライアントメッセージは最大 1 MiB です。

拒否されたイベントは転送されず、Router はクローズコード `1008` でセッションをクローズします。

## 料金

セッションの料金は**1秒あたり$0.0011869**です（1分あたり約$0.0712、または1秒あたり0.2504クレジット、1分あたり約15.0クレジット。211クレジット = $1 USDとして）。セッションが開いている間は15秒単位で課金され、最後の端数分は1秒単位で切り上げて課金されます。課金はアップグレードからソケットが閉じるまで、オーディオが流れているかどうかに関係なく行われます。

## 制限

| 制限 | 値 |
| --- | --- |
| アカウントあたりのセッション数 | 同時に開けるセッションは 1 つです。2 つ目を開こうとすると `429` と `router.realtime.session_already_live` が返されます。 |
| セッションの長さ | 最大 30 分で、接続時点のあなたのクレジット残高で賄える時間を超えることはありません。 |
| セッション中のクレジット | Router は 15 秒ごとに残高を再確認し、次の 1 秒を賄えなくなった時点でセッションを終了します。 |
| 接続レート | 各アップグレードの試行は[呼び出し元ごとのリクエストレート](/ja/development/comfy-router/limitations#リクエストは呼び出し元ごとにレート制限される)にカウントされ、他の Router 呼び出しと共有されます。 |

セッションが時間制限に達した場合、またはクレジットが不足した場合、接続は close フレームなしで閉じられることがあります（多くの場合、クローズコード `1006` として現れます）。再接続はチャージした後に行うか、より長い時間が必要な場合は新しいセッションを開始してください。

## エラー

### アップグレード前

Routerが接続を拒否した場合、プロトコルを切り替える代わりにHTTPステータスとJSONボディで応答します：

```json
{
  "detail": "Insufficient credits to open a realtime session.",
  "error_type": "insufficient_credits",
  "code": "router.realtime.insufficient_credits"
}
```

`code` で分岐します。`detail` は人向けの情報です。

| ステータス | `code` | 原因 | 対処方法 |
| --- | --- | --- | --- |
| `426` | `router.realtime.upgrade_required` | リクエストがWebSocketアップグレードではありませんでした。 | WebSocketクライアントで接続してください。 |
| `401` | `router.realtime.unauthorized` | APIキーが不足しているか無効です。 | `X-API-Key` または `Authorization: Bearer` で有効なキーを送信してください。 |
| `402` | `router.realtime.insufficient_credits` | 残高が少なくとも1秒分のセッションをカバーできません。 | クレジットを追加してから再接続してください。 |
| `402` | `router.realtime.spend_denied` | セッションの請求先となるウォレットに、そのための資金がありません。ボディ内の `denied_reason` と `billed_workspace` がどのウォレットかを示します。 | そのワークスペースにクレジットを追加してから再接続してください。 |
| `403` | `router.realtime.provider_disabled` | ワークスペースのパートナープロバイダーポリシーでは、このプロバイダーは許可されていません。 | ワークスペース管理者に許可を依頼してください。 |
| `404` | `router.realtime.model_not_allowed` | URL内のモデルはリアルタイムでは利用できません。 | URLを確認してください。 |
| `429` | `router.realtime.rate_limited` | リクエストレートを超えました。 | `Retry-After` を待ってから再試行してください。 |
| `429` | `router.realtime.session_already_live` | アカウントでは別のセッションがすでに開いています。 | 先にそれを閉じてください。 |
| `429` | `router.realtime.concurrency_limit` | パートナーモデルの同時呼び出しが多すぎます。 | 同時実行を減らして再試行してください。 |
| `502` | `router.realtime.upstream_refused`, `router.realtime.token_mint_failed` | 上流プロバイダーがセッションを開きませんでした。 | バックオフしながら再試行してください。 |
| `503` | その他の `router.realtime.*` コード | リアルタイムセッションは一時的に利用できません。 | バックオフしながら再試行してください。 |

### アップグレード後

| クローズコード | 意味 | 対処方法 |
| --- | --- | --- |
| `1008` | クライアントイベントが拒否されました（[イベント](#イベント) を参照）。 | イベントを修正してください。セッションは終了です。 |
| `1012` | Routerが再起動しています。 | 再接続してください。新しいセッションが開始され、新しいアップグレードから課金されます。 |
| `1006`（クローズフレームなし） | セッションが時間制限に達したか、クレジットが不足したときにクライアントが報告する内容であることがよくあります。ネットワーク切断も同じように見えます。 | クレジットを追加するか、新しいセッションを開始してください。 |

その他のクローズは fal または xAI からのものです。詳細は [イベント](#イベント) でリンクされているドキュメントを参照してください。
