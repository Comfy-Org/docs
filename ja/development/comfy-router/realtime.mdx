Router のほとんどのモデルは、1つのリクエストを受け取って完了した結果を返します。Realtime モデルは代わりにライブセッションを保持します。モデルの実行中に入力を送信し、生成されるそばから出力を受け取ります。Router はこれらを2つのサーフェスで提供します。

| モデル | 機能 | サーフェス |
| --- | --- | --- |
| `google/genie-4` | Genie 4 インタラクティブワールドモデル。キー操作とテキストで誘導 | WebSocket セッション、`GET /v2/realtime/google/google/genie-4` |
| `xai/grok-voice/realtime` | Grok Voice 音声対音声会話 | WebSocket セッション、`GET /v2/realtime/fal/xai/grok-voice/realtime` |
| `fal-ai/abot-world-0` | インタラクティブワールドモデル。WebRTC 経由のビデオ | WebRTC シグナリング、`POST /v2/realtime/wma/fal` |
| `fal-ai/lingbot-world-2` | インタラクティブワールドモデル。WebRTC 経由のビデオ | WebRTC シグナリング、`POST /v2/realtime/wma/fal` |

4つすべてが**セッション時間の秒単位**で課金され、他の Router 呼び出しと同じワークスペースのクレジット残高から差し引かれます。料金については [Router の料金](/ja/development/comfy-router/pricing) を参照してください。セッションには資金のあるワークスペースが必要です。クレジットがない場合、セッションの開始は `402` で拒否されます。

<Note>
  WebSocket のパスは `/v2/realtime/{provider}/{model}` です。ここで `{provider}` はそのモデルを提供するプロバイダー、`{model}` は完全なモデル id です。そのため Genie 4 のパスでは `google` が2回現れます。
</Note>

## 認証

Realtime ルートは、他の Router 呼び出しと同じ認証情報を受け付けます。

- **サーバーから** は、WebSocket のアップグレードリクエストまたはシグナリングリクエストで、APIキーを `X-API-Key: comfyui-...` または `Authorization: Bearer comfyui-...` として送信します。APIキーはサーバー上に保管し、ブラウザへ配布しないでください。
- **ブラウザから** は、WebSocket がリクエストヘッダーを設定できません。Comfy アカウントでサインインしているブラウザは、代わりに Firebase ID トークンを `comfy-realtime.v1` とともにサブプロトコルオファーで渡します:

  ```js
  const ws = new WebSocket(url, ["comfy-realtime.v1", "comfy-bearer." + idToken]);
  ```

  トークンは有効期限が切れていない Firebase ID トークンである必要があります。APIキーがこの方法で受け付けられることは決してなく、認証情報が URL クエリ文字列で受け付けられることもありません。`comfy-realtime.v1` を伴わずに `comfy-bearer.` を含むオファーは、セッションが開く前に `400` で拒否されます。`comfy-realtime.v1` をオファーすると、サーバーは `101` レスポンスでそれを選択します。

  サブプロトコルオファーは WebSocket セッションにのみ適用されます。WebRTC シグナリングは通常の HTTP であるため、ブラウザはそこでは `Authorization: Bearer <Firebase ID token>` をヘッダーとして送信します。

## WebSocket セッション

`wss://api.comfy.org/v2/realtime/{provider}/{model}` への WebSocket アップグレードでセッションを開きます。Router はアップグレードを認証し、残高を確認し、セッションの存続中、クライアントとモデルの間でフレームを中継します。

### セッションのルール

- **ワークスペースごとに有効な WebSocket セッションは 1 つです。** セッションが有効な状態で 2 回目のアップグレードを行うと、`429` と `code: router.realtime.session_already_live` で拒否されます。別のセッションを開く前に、最初のセッションを閉じてください。
- **メータリングは最初のフレームから開始されます。** 課金は整数秒単位で、最低 1 秒を下限として行われます。`google/genie-4` の場合、課金はモデルが最初のフレームを送信した時点で開始されます。それより前に、最初の 20 秒以内にセッションが終了した場合は請求されません。20 秒経過してもフレームが届かない場合は、アップグレードが成功した時点から課金がカウントされます。その他のモデルは `101` の時点から課金されます。
- **セッションの実行中も残高が再確認されます。** Router はセッションを計測し、15 秒ごとに残高を再確認します。残高がまだいくらかの時間をカバーできる場合、セッションの上限はそれに合わせて短縮されます（Genie 4 のセッションは、その上限に達すると `1000` で終了します）。残高がもう 1 秒分すらカバーできなくなった場合、またはアカウントがブロックされている場合、Router は close フレームを送らずに接続を切断します（ほとんどのクライアントは close コード `1006` を報告します）。クレジットが不足している場合は、再接続する前にチャージしてください。セッションの最大長も、あらかじめ残高でカバーできる範囲に短縮されます。

### Genie 4

`google/genie-4` は、テキストプロンプトからインタラクティブな世界を生成し、その後キー押下でその世界を移動します。**テキストフレームのみ**を受け付け、各フレームは `event_type` を持つ JSON オブジェクトです。バイナリフレーム、または 64 KiB を超えるメッセージはセッションを終了させます。

| `event_type` | フィールド | 備考 |
| --- | --- | --- |
| `world_setup` | `world_prompt: { "text": "..." }` | 最初のイベントでなければなりません。プロンプトは必須で、空でなく、最大 8 KiB です。テキストのみです。`reference_image` や画像またはビデオのフィールドは拒否されます。同じ `world_setup` を繰り返しても無視されます。異なるプロンプトで送信するとセッションが終了します。 |
| `user_action` | `action`, `input` | `action` は `key_down`、`key_up`、`key_click` のいずれかです。`input` は以下の 10 個のキーのいずれかです。 |
| `input` | `content: [{ "type": "text", "text": "..." }]` | テキストで世界を操作します。テキストパートのみで、それぞれ最大 8 KiB です。 |
| `interaction.complete` | なし | セッションを正常に終了します。他のフィールドを付けずに送信してください。 |

`user_action` で指定できる 10 個のキー:

| 目的 | キー |
| --- | --- |
| 移動 | `key_w`, `key_s`, `key_a`, `key_d` |
| カメラ | `arrow_up`, `arrow_down`, `arrow_left`, `arrow_right` |
| アクション | `space`, `key_e` |

他のイベントタイプ、フィールド、キー、`world_setup` より前の `user_action` または `input`、あるいは継続的なイベントの大量送信（約 120 のバーストを超え、その後 1 秒あたり約 60）は、クローズコード `1008`（ポリシー違反）でセッションを終了させます。拒否されたメッセージの内容はモデルに届きません。

モデル自身のイベントは同じソケットで返されます。セッションは次の場合に終了します:

- モデルの `interaction.completed` イベントの後、クローズコード `1000`。
- モデルの `error` イベントの後、プロバイダーのクローズコードまたは `1011`。
- **120 秒**のセッション上限（残高がそれより少ない場合はより早く）で、クローズコード `1000`。

モデルのイベント内のエラーテキストは、あなたに届く前に一般的なメッセージに置き換えられることがあります。

```python Python
# Python 3.10+
# インストール: python -m pip install "websockets>=13"
# 実行: COMFY_API_KEY=comfyui-... python genie.py
import asyncio
import json
import os

from websockets.asyncio.client import connect
from websockets.exceptions import InvalidStatus

URL = "wss://api.comfy.org/v2/realtime/google/google/genie-4"


async def receive(ws):
    async for message in ws:
        if isinstance(message, bytes):
            print(f"<- {len(message)} bytes")
            continue
        event = json.loads(message)
        print("<-", event.get("event_type"))


async def main():
    try:
        ws = await connect(
            URL,
            additional_headers={"X-API-Key": os.environ["COMFY_API_KEY"]},
            max_size=None,
        )
    except InvalidStatus as err:
        # 拒否されたアップグレード: ボディは detail、error_type、code を含む JSON です。
        print(err.response.status_code, err.response.body.decode(errors="replace"))
        return

    async with ws:
        reader = asyncio.create_task(receive(ws))

        async def send(event):
            await ws.send(json.dumps(event))

        await send({
            "event_type": "world_setup",
            "world_prompt": {"text": "A quiet harbor town at sunset, seen from the docks"},
        })
        await send({"event_type": "user_action", "action": "key_down", "input": "key_w"})
        await asyncio.sleep(2)
        await send({"event_type": "user_action", "action": "key_up", "input": "key_w"})
        await send({"event_type": "user_action", "action": "key_click", "input": "arrow_left"})
        await send({"event_type": "input", "content": [{"type": "text", "text": "Make it start to rain"}]})
        await asyncio.sleep(5)
        await send({"event_type": "interaction.complete"})

        await reader
        print("closed:", ws.close_code)


asyncio.run(main())
```

### Grok Voice

`xai/grok-voice/realtime` は音声対音声の会話です。セッションは fal のリアルタイムワイヤフォーマットに従います。各イベントを [MessagePack](https://msgpack.org) でエンコードしたバイナリフレームとして送信し、応答は MessagePack バイナリフレームまたは JSON テキストフレームとして受信します。内部のイベントは xAI のリアルタイム音声イベントです。

次のクライアントイベントを送信できます: `session.update`、`x-fal-session.configure`、`input_audio_buffer.append`、`input_audio_buffer.commit`、`input_audio_buffer.clear`、`conversation.item.create`、`conversation.item.delete`、`conversation.item.truncate`、`response.create`、`response.cancel`。各イベントに含められるのは、ドキュメントに記載されたフィールドのみです。

- ツールは、クライアントで実行される `function` ツールに限られます。MCP サーバー、ウェブ検索、X 検索などのサーバー側ツールは拒否されます。
- 画像やビデオのコンテンツは、イベント内のどこにあっても拒否されます。
- `session.model` を設定する場合、`grok-voice-latest`、`grok-voice-3.0`、`grok-voice-2.0` のいずれかである必要があります。

これらのルールに違反するメッセージは転送されず、クローズコード `1008` でセッションを終了させます。セッションの上限は **30 分** で、残高でカバーできる時間まで事前に短縮されます。上限に達すると、クローズフレームなしで接続が閉じられます。

Grok Voice セッションの料金は **1 秒あたり $0.0011869** です（1 分あたり約 $0.0712。211 クレジット = $1 の場合、1 秒あたり約 0.25 クレジット、1 分あたり 15 クレジットに相当）。課金は、オーディオが流れているかどうかに関係なく、ソケットが開いている全時間に対して発生します。

```js Node
// Node 20 以降
// インストール: npm install ws @msgpack/msgpack
// 実行: COMFY_API_KEY=comfyui-... node grok-voice.mjs
import { decode, encode } from "@msgpack/msgpack";
import WebSocket from "ws";

const ws = new WebSocket("wss://api.comfy.org/v2/realtime/fal/xai/grok-voice/realtime", {
  headers: { "X-API-Key": process.env.COMFY_API_KEY },
});
const send = (event) => ws.send(Buffer.from(encode(event)));

ws.on("unexpected-response", (_req, res) => {
  let body = "";
  res.on("data", (chunk) => (body += chunk));
  res.on("end", () => console.error("refused:", res.statusCode, body));
});

ws.on("open", () => {
  send({
    type: "session.update",
    session: {
      voice: "Ara",
      instructions: "Answer in one short sentence.",
      turn_detection: { type: null },
    },
  });
  send({
    type: "conversation.item.create",
    item: { type: "message", role: "user", content: [{ type: "input_text", text: "Say hello." }] },
  });
  send({ type: "response.create" });
});

ws.on("message", (data, isBinary) => {
  const event = isBinary ? decode(data) : JSON.parse(data.toString());
  console.log("<-", event.type);
  if (event.type === "response.done" || event.type === "error") ws.close(1000);
});

ws.on("close", (code) => console.log("closed", code));
```

テキストの代わりに音声を送信するには、`input_audio_buffer.append`（base64 の `audio`）でオーディオをストリーミングし、その後 `input_audio_buffer.commit` と `response.create` を送信します。

## WebRTC ワールドモデル

`fal-ai/abot-world-0` と `fal-ai/lingbot-world-2` は WebRTC 経由でビデオをストリーミングします。メディアは**ブラウザと fal の間を直接**、ピアツーピアで流れます。Router は接続を確立するための HTTP シグナリングだけを処理し、fal の認証情報を付与するため、クライアントが認証情報を保持することはありません。

すべてのシグナリング呼び出しは、Comfy の認証情報と JSON ボディを伴う `https://api.comfy.org/v2/realtime/wma/fal` への `POST` で、実際の宛先は `x-fal-target-url` ヘッダーで指定します。これは fal の JavaScript クライアントが使用するプロキシの契約なので、そのクライアントのプロキシ設定をこのルートに向けることができます。受け付けられる宛先は次のものだけです。それ以外は `400` と `code: router.realtime.wma_target_rejected` で拒否されます:

| `x-fal-target-url` | ボディ | 目的 |
| --- | --- | --- |
| `https://wma.fal.run/ice` | `{"app_id": "<model>"}` | ICE サーバーを取得します。セッションを開かず、課金もされません。 |
| `https://wma.fal.run/session` | `"app_id": "<model>"` を含む | セッションを開きます。応答にはその `session_id` が含まれます。 |
| `https://wma.fal.run/session/heartbeat` | `{"session_id": "<id>"}` | セッションを維持します。 |
| `https://wma.fal.run/session/close` | `{"session_id": "<id>"}` | セッションを終了します。同じボディで `DELETE /v2/realtime/wma/fal` を呼んでも同じ結果になります。 |

ボディはキーの重複がない、最大 64 KiB の JSON オブジェクトである必要があります。`app_id` と `session_id` はこの通りに正確に綴ってください。大文字と小文字が異なる場合は `400` で拒否されます。

```bash
# ワールドモデルの ICE サーバーを取得します（セッションなし、課金なし）。
curl -X POST https://api.comfy.org/v2/realtime/wma/fal \
  -H "X-API-Key: $COMFY_API_KEY" \
  -H "Content-Type: application/json" \
  -H "x-fal-target-url: https://wma.fal.run/ice" \
  -d '{"app_id": "fal-ai/lingbot-world-2"}'
```

```js
// Comfy アカウントでサインインしたブラウザからハートビートとクローズを送信します。
const signal = (target, body) =>
  fetch("https://api.comfy.org/v2/realtime/wma/fal", {
    method: "POST",
    headers: {
      Authorization: `Bearer ${idToken}`,
      "Content-Type": "application/json",
      "x-fal-target-url": target,
    },
    body: JSON.stringify(body),
  });

const beat = setInterval(
  () => signal("https://wma.fal.run/session/heartbeat", { session_id: sessionId }),
  5000,
);

// ユーザーが停止したら、ピア接続を切断してからセッションをクローズします。
clearInterval(beat);
peerConnection.close();
const res = await signal("https://wma.fal.run/session/close", { session_id: sessionId });
console.log(await res.json()); // { session_id, closed: true, settled: true | false }
```

### セッションのライフサイクルと課金

- **最大長。** 各セッションは最大 **480 秒** 実行されます。
- **ハートビート。** fal のクライアントと同様に 5 秒ごとに 1 回送信します。Router はセッションごとに 1 秒あたり最大 1 回転送します。それより速いハートビートは `429` と `Retry-After: 1` で拒否されます。ハートビートとクローズは、お使いのアカウントが開いてまだクローズしていない `session_id` に対してのみ受け付けられます。それ以外の場合は `404` と `code: router.realtime.wma_session_not_found` が返ります。
- **課金。** セッションは、開始した時点から最後のハートビートの 5 秒後まで、最大 480 秒まで 1 秒単位で課金されます。セッションをクローズすると請求はすぐに確定します。ハートビートが 15 秒を超えて停止したセッションは自動的に確定されます。クローズ応答の `settled: false` は、請求がまだ確定処理中であり、まもなく反映されることを意味します。
- **開始時の残高チェック。** Router はピアツーピアセッションを開始後に停止できないため、セッションを開くには、このセッションの 480 秒全体に加えて、ワークスペースですでに開いているすべての WebRTC セッションの全長をカバーする残高が必要です。不足している場合、`/session` は `402` と `code: router.realtime.insufficient_credits` で拒否されます。これはチェックであり、予約ではありません。セッションの実行中も、他の支出が同じ残高から引き落とされる可能性があります。
- **同時セッション。** ワークスペースは同時に **2** つの WebRTC ワールドモデルセッションを保持できます。クローズされたセッションは、開いてから約 480 秒後（さらに短い確定待ち時間）までスロットを保持するため、クローズしてすぐに開き直すと `429` と `code: router.realtime.concurrency_limit` で拒否されることがあります。応答に示された `Retry-After` の時間だけ待ってください。

fal 自体がシグナリング呼び出しにエラーで応答した場合、Router は fal のステータスとボディをそのまま透過させます。

## エラー

拒否されたアップグレードやシグナリング呼び出しは、HTTP ステータスと、`detail`、`error_type`、および理由を示す `code` を含む JSON ボディで応答します。判定は `detail` ではなく `code` または `error_type` で分岐してください。WebSocket セッションが開いた後は、問題はクローズコードで報告されます。

| ステータス | `code` | 意味 |
| --- | --- | --- |
| `400` | `router.realtime.subprotocol_required` | `comfy-bearer.` オファーに `comfy-realtime.v1` が付いていませんでした。 |
| `401` | | 有効な認証情報がありません。 |
| `402` | `router.realtime.insufficient_credits` | ワークスペースの残高がセッションを開くには不足しています。 |
| `403` | `router.realtime.model_unavailable` | モデルはお使いのアカウントでは利用できません。 |
| `403` | `router.realtime.account_blocked` | アカウントがブロックされています。 |
| `404` | `router.realtime.model_not_allowed` | モデルはこのルートでは提供されていません。パスとモデル ID を確認してください。 |
| `426` | `router.realtime.upgrade_required` | WebSocket ルートに通常の HTTP リクエストが届きました。プロキシが `Upgrade` と `Connection` ヘッダーを削除していないか確認してください。 |
| `429` | `router.realtime.rate_limited` | リクエストが多すぎるか、プロバイダーが容量上限に達しています。`Retry-After` を待ってください。 |
| `429` | `router.realtime.session_already_live` | ワークスペースには既にライブ WebSocket セッションがあります。 |
| `429` | `router.realtime.concurrency_limit` | 同時セッションが多すぎます。後で再試行してください。 |
| `503` | `router.realtime.shutting_down` | リクエストを処理しているサーバーが再起動中です。再試行してください。 |

アップグレード、および `/ice` と `/session` のシグナリング呼び出しは、他の Router 呼び出しと同じ呼び出し元ごとの[リクエスト許可](/ja/development/comfy-router/limitations#リクエストは呼び出し元ごとにレート制限される)を消費します。

| クローズコード | 意味 |
| --- | --- |
| `1000` | 正常終了: モデルが完了したか、Genie 4 セッションが上限に達しました。 |
| `1006` | クローズフレームが届きませんでした。Router 側の原因には、Grok Voice セッションが時間上限に達した、クレジットが不足した、アカウントがブロックされた、などがあります。ネットワーク切断やプロキシのタイムアウトも同じように見えます。Router から送信されるものではなく、接続が切断されたときにクライアントが報告します。 |
| `1008` | クライアントメッセージがモデルのルールに違反しました（上記の各モデルを参照）。 |
| `1011` | モデルがエラーを報告しました。 |
| `1012` | サーバーが再起動中です。新しいセッションを開いてください。 |
