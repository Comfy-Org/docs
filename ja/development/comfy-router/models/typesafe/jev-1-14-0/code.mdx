同じボディを `POST https://api.comfy.org/v2/models/typesafe/jev-1.14.0/requests` に送信します。Router は実行が受け付けられるとすぐに `201` と `request_id` を返し、結果は準備ができ次第、このプロセスからでも別のプロセスからでも収集できます。[キューの配信](/ja/development/comfy-router/queue)では、ステータス、キャンセル、収集の流れを説明します。

```python Python
import asyncio
from comfy_sdk import AsyncComfy

# 環境から COMFY_API_KEY を読み取ります。
# 各 submit() 呼び出しは独自の Idempotency-Key を生成し、自動リトライで再利用します。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "typesafe/jev-1.14.0",
            {
                "questions": {
                    "department": {
                        "criteria": {
                            "billing": "Payments, invoicing, refunds",
                            "technical": "Bugs, outages, integrations",
                        },
                        "instructions": "Which team should handle this?",
                        "type": "choice",
                    },
                    "is_urgent": {
                        "instructions": "Does this convey urgency?",
                        "type": "noul",
                    },
                },
                "state": "Help! My payouts have been failing for 3 days.",
            },
        )
        print("request_id:", handle.request_id)  # モデル ID と合わせて、別のプロセスが必要とするすべて

        # リクエストが完了するまでポーリングし、サーバーが指定する Retry-After の間待機します。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # プロバイダー自身のペイロードで、models.run() が返すのと同じ値です。
        # 失敗またはキャンセル済みのリクエストは、ここで型付きの Router エラーを発生させます。
        result = await handle.get()

    print(result)

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// 環境から COMFY_API_KEY を読み取ります。
// 各 submit() 呼び出しは独自の Idempotency-Key を生成し、自動リトライで再利用します。
const handle = await comfy.models.submit("typesafe/jev-1.14.0", {
  questions: {
    department: {
      criteria: {
        billing: "Payments, invoicing, refunds",
        technical: "Bugs, outages, integrations",
      },
      instructions: "Which team should handle this?",
      type: "choice",
    },
    is_urgent: {
      instructions: "Does this convey urgency?",
      type: "noul",
    },
  },
  state: "Help! My payouts have been failing for 3 days.",
});
console.log("requestId:", handle.requestId); // モデル ID と合わせて、別のプロセスが必要とするすべて

// リクエストが完了するまでポーリングし、サーバーが指定する Retry-After の間待機します。
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// models.run() が返すのと同じ結果です。失敗またはキャンセル済みのリクエストはここで拒否されます。
const result = await handle.get();

console.log(result.data);
```

## スキーマ

### 入力

<ParamField body="assets" type="object">
  リクエスト内の画像。参照文字列をキーとします。各参照は `state`、`instructions`、`criteria` のいずれかに必ず含まれている必要があります。各画像は 1 辺 280～1568 ピクセルの静止 PNG または JPEG で、デコード後 16 MiB 以下です。TypeSafe は合計 32 MiB を超える呼び出しを拒否します。
</ParamField>

<ParamField body="model" type="string">
  ピン留めされた Jev バージョン。任意です。Router はパス内のモデル ID からこれを補完します。`jev-latest` と `jev-preview` のエイリアスは受け付けられません。
</ParamField>

<ParamField body="questions" type="object" required>
  回答するご質問。任意の ID をキーとして指定します。各回答は同じ ID の下に返されます。
</ParamField>

<ParamField body="state" type="object" required>
  評価するコンテンツ。文字列、または最大 64 階層までの構造化データ（オブジェクトまたは配列）です。その中の任意の箇所にあるアセット参照は、対応する画像に置き換えられます。
</ParamField>

Router が `GET /v2/models/typesafe/jev-1.14.0/openapi.json` で提供するスキーマから生成済みです。これはリクエストがプロバイダーに到達する前に Router が呼び出しを検証する際に使用するドキュメントと同じものです。

### 出力

<ResponseField name="answers" type="object" required>
  ご質問ごとに 1 つの回答。送信したご質問の ID をキーとします。
</ResponseField>

<ResponseField name="model" type="string" required>
  回答した Jev のバージョン（例: `jev-1.14.0`）。
</ResponseField>

<ResponseField name="usage" type="object">
  リクエストのトークン使用量。
</ResponseField>

<ResponseField name="usage.input_tokens" type="integer">
  入力トークン。リクエスト内のすべての画像を含みます。
</ResponseField>

<ResponseField name="usage.output_tokens" type="integer">
  出力トークン。
</ResponseField>
