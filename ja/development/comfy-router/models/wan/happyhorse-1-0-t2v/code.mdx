</ParamField>

<ParamField body="input.audio_url" type="string">
  オーディオファイルのダウンロードURL。対応形式: mp3、wav。reference_video_urls とは併用できません。
</ParamField>

<ParamField body="input.img_url" type="string">
  先頭フレーム画像の URL または Base64 エンコードされたデータ。wan2.5-i2v-preview モデルと
wan2.6-i2v モデルでは必須です。happyhorse-1.x の i2v 系のスペルは、先頭フレームをここで受け取ることは
ありません。先頭フレームは type が first_frame のメディア要素として渡します（後述の media を参照）。
また、wan2.6-i2v では成功する img_url のボディも、happyhorse-1.0-i2v と happyhorse-1.1-i2v では
プロバイダーに拒否されます。さらに wan2.7/wan3.0 系のスペルも参照アセットを media で渡します。
画像形式: JPEG、JPG、PNG、BMP、WEBP。
解像度: 360〜2000 ピクセル。ファイルサイズ: 最大 10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。動画生成用の参照素材（画像、オーディオ、ビデオ）を指定します。
各要素は type と url フィールドを持ちます。このフィールドはこのコンポーネントが提供するすべての
モデルで共通ですが、どの type 値を受け付けるか、また画像やビデオの入力を img_url や
reference_video_urls ではなくここで渡すかどうかは、モデルによって異なります。モデルごとの
対応する type 値は次のとおりです:
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frame と
  last_frame: JPEG/JPG/PNG/BMP/WEBP、1辺 240〜8000 ピクセル、アスペクト比 1:8〜8:1、
  最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。
  driving_audio（WAV/MP3、2〜30 秒、最大 15MB）と first_clip（MP4/MOV、2〜10 秒、
  1辺 240〜4096 ピクセル、最大 100MB）: 公開 HTTP/HTTPS URL のみで、インラインの
  data: URL は受け付けられません。
- wan2.7-r2v: first_frame（任意、最大 1 個）、reference_image、reference_video。少なくとも
  1 つの reference_image または reference_video が必要で、reference_image と
  reference_video の合計は最大 5 個です。first_frame と reference_image: JPEG/JPG/PNG/BMP/WEBP
  （アルファチャンネルなし）、1辺 240〜8000 ピクセル、アスペクト比 1:8〜8:1、最大
  20MB、公開 URL または data:\{MIME_type};base64,... URL。reference_video: 公開
  HTTP/HTTPS URL のみで、インラインの data: URL は受け付けられません。
- wan2.7-videoedit: video（ちょうど 1 個、編集対象のクリップ: MP4/MOV、2〜10 秒、
  1辺 240〜4096 ピクセル、最大 100MB、公開 HTTP/HTTPS URL のみで、インラインの data: URL
  は受け付けられません）に加えて、任意で 0〜4 個の reference_image（JPEG/JPG/PNG/BMP/WEBP、
  1辺 240〜8000 ピクセル、アスペクト比 1:8〜8:1、最大 20MB、公開 URL
  または data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime: first_frame（最大 1 個）、last_frame（最大 1 個）、
  reference_image（最大 10 個）、reference_video（最大 5 クリップ、合計再生時間 \<= 15 秒）、
  reference_audio（最大 5 クリップ、合計再生時間 \<= 15 秒）、file（最大 1 個、link とは
  併用不可）、link（最大 1 個、file とは併用不可）。reference_*/file/link の各 type
  と first_frame/last_frame の各 type は同一リクエスト内で同時に使用できません。
  配列の順序がプロンプト内でのアセットの参照順（Image 1、Video 1、
  Audio 1、...）を定義します。first_frame、last_frame、reference_image: JPEG/JPG/PNG/BMP/WEBP、
  1辺 240〜8000 ピクセル、アスペクト比 最大 8:1、最大 20MB、公開 URL または
  data:\{MIME_type};base64,... URL。reference_video、reference_audio、file、link: 公開
  HTTP/HTTPS URL のみで、インラインの data: URL は受け付けられません。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v: first_frame のみ、ちょうど 1 個。これらのスペルは
  先頭フレームを img_url ではなくここで受け取ります。少なくとも 300x300 ピクセル、アスペクト比
  1:2.5〜2.5:1、JPEG/JPG/PNG/WEBP、最大 20MB、公開 URL または
  data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v: reference_image のみ、1〜9 個。これがこのモデル
  唯一の参照入力です。最短辺が少なくとも 400 ピクセル、JPEG/JPG/PNG/WEBP、
  最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。この操作では reference_video は
  入力 type ではありません。
- happyhorse-1.0-video-edit: video（ちょうど 1 個、編集対象のクリップ: MP4/MOV、3〜60
  秒、長辺が最大 4096 ピクセル、短辺が少なくとも 360 ピクセル、アスペクト比
  1:2.5〜2.5:1、最大 100MB、公開 HTTP/HTTPS URL のみで、インラインの data:
  URL は受け付けられません）に加えて、任意で 0〜5 個の reference_image（JPEG/JPG/PNG/BMP/WEBP、
  少なくとも 300x300 ピクセル、アスペクト比 1:2.5〜2.5:1、最大 20MB、公開 URL
  または data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview:
  テキストから動画への操作です。これらのパートナーのリファレンスにはメディア入力の記載がないため、この
  フィールドは未設定のままにしてください。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v: このコンポーネントはこれらのスペルに対して
  メディアの語彙を列挙していません。wan2.5-i2v-preview と wan2.6-i2v は先頭
  フレームを img_url で受け取り、wan2.6-r2v は参照クリップを reference_video_urls で受け取ります。
上記のモデルごとの個数はこのスキーマの制約ではなくパートナーの制約です。受け付け可能な type と
その上限はモデルごとに異なるため、media には minItems/maxItems が宣言されていません。
スキーマが受け付けることはプロバイダーが受け付けることを意味しません。逆方向についても、上記の
アセットごとの「最大 20MB」という数値は、画像入力（唯一インラインで送信できる入力）に対する
上限であり、パートナーが最終的に受け取るアセットに対する上限です。アセットが公開 URL の場合、
そのバイト列が Comfy を経由することはないため、これらの数値は記載どおりに適用されます。
インラインの data:\{MIME_type};base64,... URL は Comfy を経由するため、転送時の上限にも
直面します。Comfy Router の POST ボディは合計 100 MiB に制限され、超えると 413 が返されます。
また base64 はペイロードを約 4/3 に膨らませるため、およそ 75 MB を超える単一のインライン
アセットは、ここに挙げたパートナーのルールに到達する前に拒否されます。そのサイズでは、単一のアセットがパートナー自身の20MB の上限ならインラインで余裕をもって収まります。そのため、1 つのアセットではパートナーのルールが制約となります。複数のアセットにまたがる場合は転送の上限が制約となります。100 MiB の Router の上限は各要素ではなくリクエスト全体を制限するためです。これらの上限に近いものはパブリック URL として送信してください。
</ParamField>

<ParamField body="input.media[].url" type="string" required>
  メディアファイルの URL: パブリックな HTTP/HTTPS URL、または、各モデルについて上記の `media` の説明に記載されている IMAGE 入力に限り、インラインの `data:{MIME_type};base64,...` URL。対象となる IMAGE 入力は、wan2.7-i2v の first_frame と last_frame、wan2.7-r2v の first_frame と reference_image、wan2.7-videoedit の reference_image、wan3.0-video と wan3.0-video-prime の first_frame、last_frame、reference_image、happyhorse-1.0-i2v と happyhorse-1.1-i2v の first_frame、happyhorse-1.0-r2v と happyhorse-1.1-r2v の reference_image、および happyhorse-1.0-video-edit の reference_image です。これらのモデルのいずれでも、ビデオ、オーディオ、ファイル、リンクの入力はインラインの data: URL を受け付けません。パートナー自身のアップロードサービスからの oss://dashscope-instant の一時 URL、または（wan2.7-videoedit では）Asset Center の asset_id は、それをアップロードした Alibaba Cloud アカウントに対してのみ解決されます。Comfy は自身のキーでモデル呼び出しを行い、アップロード経路を公開しないため、呼び出し元自身の oss:// URL や asset_id はサポートされる入力ではありません。このフィールドは URL スキームを検証しないため、そのような値はここで拒否されず、そのままパートナーに転送されます。モデルごとのサイズとピクセルの制限、およびインラインのペイロードを全体として制限する 100 MiB の Router リクエスト本文の上限については、`media` の説明を参照してください。

<ParamField body="input.negative_prompt" type="string">
  ネガティブプロンプト（reverse prompt words）は、ビデオ画面に表示したくないコンテンツを記述するために使用します。500 文字を超えると、wan モデルは拒否せずに切り捨てます。これはプロンプトと同じ入力予算にカウントされます。
</ParamField>

<ParamField body="input.prompt" type="string">
  テキストプロンプトの語句。中国語と英語をサポートします。文書化された長さを超えると、wan2.x モデルはプロンプトを拒否せずに切り捨てます: wan2.5 と wan2.6 は 1,500 文字、wan2.7 は 5,000 文字です。wan3.0-video と wan3.0-video-prime は最大 20,000 文字を受け付けます。プロバイダーは、prompt と negative_prompt を合わせた長さが UTF-8 テキストで約 60,850 バイト（約 20,000 文字の中国語）を超えるリクエストを拒否し、InvalidParameter `Range of input length should be [1, 61440]` を返します。複数の参照ビデオを使用する wan2.6-r2v では、参照ビデオの順序で被写体を指すために 'character1'、'character2' などを使用します。例: 「Character1 が道端で歌い、Character2 がそのそばで踊る」。wan3.0-video の参照モードでは、media 配列内の対応する順序でメディアアセットを指すために 'Image 1'、'Video 1'、'Audio 1' などを使用します。
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  wan2.6-r2v モデル専用の参照ビデオ URL。1-3 本のビデオ URL の配列です。
入力制限:
- 形式: mp4, mov
- 数量: 1-3 本のビデオ
- 単一ビデオの長さ: 2-30 秒
- 単一ファイルサイズ: 最大 30MB
- audio_url と併用できません
参照再生時間: 単一ビデオは最大 5s、2 本の場合はそれぞれ最大 2.5s、3 本の場合は比例して短くなります。
課金: 使用した実際の参照再生時間に基づきます。
</ParamField>

- wan3.0-video: ビデオ入力なしの場合は [2, 30] の整数。ビデオ入力ありの場合は、入力ビデオの再生時間と出力ビデオの再生時間の合計が 30 秒を超えてはいけません。-1 はスマート再生時間モードを有効にし、モデルが適切な再生時間を選択します
このプロキシは [-1, 30] の範囲外の再生時間に対して 400 を返します。

  範囲: `-1` から `30`
</ParamField>

<ParamField body="parameters.prompt_extend" type="boolean" default="true">
  プロンプトのインテリジェントな書き換えを有効にするかどうか。デフォルトは true です。
</ParamField>

<ParamField body="parameters.ratio" type="string">

wan3.0-video の場合、adaptive（デフォルト）は適切な入力メディアの比率と意図に基づくアスペクト比。

  指定可能な値: `adaptive`、`16:9`、`9:16`、`1:1`、`4:3`、`3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  解像度レベル。サポートされる値はモデルによって異なります:
- wan2.5-i2v-preview: 480P、720P、1080P
- wan2.6 モデル (t2v、i2v、r2v): 720P、1080P のみ (480P は非サポート)
- wan2.7 モデル (i2v、t2v、r2v、videoedit): 720P、1080P (デフォルト 1080P)
- wan3.0-video、wan3.0-video-prime: 480P、720P、1080P (上流のデフォルトは 1080P)
- happyhorse-1.0-* (t2v、i2v、r2v、video-edit): 720P、1080P
- happyhorse-1.1-* (t2v、i2v、r2v): 480P、720P、1080P
このプロキシは、resolution も size も指定しないビデオ生成リクエストを拒否します。
これは解像度ティアが課金レートを選択するためです。チェック前に resolution を
大文字化し、大文字化した値を転送します。この列挙に含まれない値には 400 を返し、
上記で 480P 非対応と記載された wan2.6、wan2.7、happyhorse-1.0 モデルに対して
480P (resolution として送信された場合も、480P の size として送信された場合も) には 400 を返します。

  指定可能な値: `480P`、`720P`、`1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">

  範囲: `0` から `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  インテリジェントなマルチレンズ制御。prompt_extend が有効な場合にのみ機能します。
wan2.6 および wan2.7-r2v モデル用です。
- single: シングルショットビデオ (デフォルト)
- multi: マルチショットビデオ

  指定可能な値: `multi`、`single`
</ParamField>

<ParamField body="parameters.size" type="string">
  幅*高さ形式のビデオ解像度。サポートされる解像度はモデルによって異なります:
wan2.5 T2V の場合: 480P (480*832、832*480、624*624)、720P、1080P の各サイズ
wan2.6 T2V/R2V の場合 (480P なし):
  720P: 1280*720、720*1280、960*960、1088*832、832*1088
  1080P: 1920*1080、1080*1920、1440*1440、1632*1248、1248*1632
size と resolution の両方を送信した場合、課金ティアは size で選択され、
resolution はそのモデルに対してこのプロキシが受け付ける値である必要があります。480P の size は、
解像度の説明で 480P 非対応と記載されているすべてのモデルで 400 を返します。
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
