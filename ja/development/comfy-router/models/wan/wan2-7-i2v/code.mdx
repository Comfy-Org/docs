Wan 2.7 I2V の API リファレンスです。Wan 2.7 の画像から動画へは、メディアリストで指定した最初のフレームをアニメーション化します。このメディアリストでは、最後のフレーム、駆動用のオーディオトラック、オープニングクリップも受け付けます。

**入力：** 画像, ビデオ, オーディオ, テキスト · **出力：** ビデオ + オーディオ

## クイックスタート

[あなたの Comfy ワークスペース](https://platform.comfy.org/profile/api-keys?onboarding=router)でキーを作成し、`COMFY_API_KEY` としてエクスポートします。Python と TypeScript のスニペットは Comfy SDK（`pip install comfy-sdk` および `npm install @comfyorg/sdk`）を使用しています。cURL のスニペットは、同じ呼び出しを生の HTTP で実行するものです。

**モデル ID:** `wan/wan2.7-i2v`

**エンドポイント:** `POST https://api.comfy.org/v2/models/wan/wan2.7-i2v`

同じボディを `POST https://api.comfy.org/v2/models/wan/wan2.7-i2v/requests` に送信します。Router は実行が受け付けられるとすぐに `201` と `request_id` を返し、結果は準備ができ次第、このプロセスからでも別のプロセスからでも収集できます。[キュー配信](/ja/development/comfy-router/queue) では、ステータス、キャンセル、収集について順を追って説明します。

```python Python
import asyncio
from comfy_sdk import AsyncComfy

# 環境変数から COMFY_API_KEY を読み取ります。
# 各 submit() 呼び出しは独自の Idempotency-Key を生成し、自動リトライで再利用します。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/wan2.7-i2v",
            {
                "input": {
                    "prompt": "the robot lowers its raised arm and steps toward the camera, the flat orange backdrop holds steady",
                    "media": [
                        {
                            "type": "first_frame",
                            "url": "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # モデル ID と合わせて、別のプロセスが必要とするすべての情報

        # リクエストが完了するまでポーリングし、サーバーが指定する Retry-After の時間だけ待機します。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # プロバイダー自身のペイロードで、models.run() が返す値と同じです。
        # 失敗またはキャンセルされたリクエストは、ここで型付きの Router エラーを送出します。
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())
```

### 入力

<ParamField body="input" type="object" required>
  プロンプトなどの基本情報を入力します。
</ParamField>

<ParamField body="input.audio_url" type="string">
  オーディオファイルのダウンロードURL。対応形式: mp3 と wav。reference_video_urls とは併用できません。
</ParamField>

<ParamField body="input.img_url" type="string">
  先頭フレームの画像URL、または Base64 エンコードされたデータ。wan2.5-i2v-preview と
wan2.6-i2v モデルでは必須です。happyhorse-1.x の i2v 表記はここで先頭フレームを受け取りません。
type が first_frame の media 要素として受け取ります（後述の media を参照）。また、
wan2.6-i2v では成功する img_url ボディも、happyhorse-1.0-i2v と happyhorse-1.1-i2v では
プロバイダーに拒否されます。wan2.7/wan3.0 の表記も参照アセットを media で受け取ります。
画像形式: JPEG、JPG、PNG、BMP、WEBP。
解像度: 360～2000 ピクセル。ファイルサイズ: 最大 10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。ビデオ生成用の参照素材（画像、オーディオ、ビデオ）を指定します。
各要素は type フィールドと url フィールドを持ちます。このフィールドはこのコンポーネントから
提供されるすべてのモデルで共有されますが、あるモデルがどの type 値を受け付けるか、
また img_url や reference_video_urls ではなくここで画像やビデオの入力を受け取るかどうかは
モデルごとに異なります。モデルごとの対応する type 値:
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frame と
  last_frame: JPEG/JPG/PNG/BMP/WEBP、各辺 240～8000 ピクセル、アスペクト比 1:8 から
  8:1 の間、最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。
  driving_audio（WAV/MP3、2～30 秒、最大 15MB）と first_clip（MP4/MOV、2～10
  秒、各辺 240～4096 ピクセル、最大 100MB）: 公開 HTTP/HTTPS URL。インラインの
  data: URL は受け付けられません。
- wan2.7-r2v: first_frame（任意、最大 1）、reference_image、reference_video。少なくとも
  1 つの reference_image または reference_video が必須で、reference_image と
  reference_video の合計は最大 5 です。first_frame と reference_image: JPEG/JPG/PNG/BMP/WEBP
  （アルファチャンネルなし）、各辺 240～8000 ピクセル、アスペクト比 1:8 から 8:1 の間、最大
  20MB、公開 URL または data:\{MIME_type};base64,... URL。reference_video: 公開
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-videoedit: video（ちょうど 1 つ、編集対象のクリップ: MP4/MOV、2～10 秒、
  各辺 240～4096 ピクセル、最大 100MB、公開 HTTP/HTTPS URL。インラインの data: URL
  は受け付けられません）に加えて、任意で 0～4 つの reference_image（JPEG/JPG/PNG/BMP/WEBP、
  各辺 240～8000 ピクセル、アスペクト比 1:8 から 8:1 の間、最大 20MB、公開 URL
  または data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime: first_frame（最大 1）、last_frame（最大 1）、
  reference_image（最大 10）、reference_video（最大 5 クリップ、合計再生時間 \<= 15 秒）、
  reference_audio（最大 5 クリップ、合計再生時間 \<= 15 秒）、file（最大 1、link とは
  併用不可）、link（最大 1、file とは併用不可）。reference_*/file/link の type
  と first_frame/last_frame の type は、同じリクエスト内では同時に使用できません。
  配列の順序がプロンプト内のアセットの参照順を定義します（Image 1、Video 1、
  Audio 1...）。first_frame、last_frame、reference_image: JPEG/JPG/PNG/BMP/WEBP、
  各辺 240～8000 ピクセル、アスペクト比は最大 8:1、最大 20MB、公開 URL または
  data:\{MIME_type};base64,... URL。reference_video、reference_audio、file、link: 公開
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v: first_frame のみ、ちょうど 1 つ。これらの表記は
  先頭フレームを img_url ではなくここで受け取ります。最低 300x300 ピクセル、アスペクト比
  1:2.5 から 2.5:1 の間、JPEG/JPG/PNG/WEBP、最大 20MB、公開 URL または
  data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v: reference_image のみ、1～9 個。これは
  このモデル唯一の参照入力です。最短辺が最低 400 ピクセル、JPEG/JPG/PNG/WEBP、
  最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。reference_video は
  この操作の入力 type ではありません。
- happyhorse-1.0-video-edit: video（ちょうど 1 つ、編集対象のクリップ: MP4/MOV、3～60
  秒、長辺が最大 4096 ピクセル、短辺が最低 360 ピクセル、アスペクト比
  1:2.5 から 2.5:1 の間、最大 100MB、公開 HTTP/HTTPS URL。インラインの data:
  URL は受け付けられません）に加えて、任意で 0～5 つの reference_image（JPEG/JPG/PNG/WEBP、
  最低 300x300 ピクセル、アスペクト比 1:2.5 から 2.5:1 の間、最大 20MB、公開 URL
  または data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview:
  テキストから動画への操作。これらのパートナーのリファレンスにはメディア入力の記載がないため、このフィールドは未設定のままにしてください。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v: このコンポーネントはこれらの表記に対して
  media の語彙を列挙していません。wan2.5-i2v-preview と wan2.6-i2v は先頭フレームを
  img_url で受け取り、wan2.6-r2v は参照クリップを reference_video_urls で受け取ります。
上記のモデルごとの数値は、このスキーマの制約ではなくパートナーの制約です。media には
minItems/maxItems が宣言されていません。許容される type とその上限がモデルごとに異なるためです。
スキーマが受け入れることは、プロバイダーが受け入れることを意味しません。逆に、上記の
アセットごとの「最大 20MB」という数値（画像入力に対する上限であり、インラインで送信できる
唯一の入力でもあります）は、パートナーが最終的に受け取るアセットに対する上限であり、
アセットが公開 URL の場合は記載どおりに適用されます。そのバイト列が Comfy を経由することは
ないためです。インラインの data:\{MIME_type};base64,... URL は Comfy を経由するため、
転送時の上限にも直面します。Comfy Router の POST ボディは合計 100 MiB に制限され、
それを超えると 413 が返されます。また base64 はペイロードを約 4/3 に膨張させるため、
およそ 75 MB を超える単一のインラインアセットは、ここに示したどのパートナーのルールにも
到達する前に拒否されます。そのサイズでは、単一のアセットはパートナー自身の
</ParamField>20MB の上限ならインラインで無理なく収まるため、単一のアセットではパートナーのルールが制約となります。複数のアセットにまたがる場合はトランスポートの上限が制約となります。100 MiB の Router 上限は各要素ではなくリクエスト全体を制限するためです。これらの上限に近いものは、パブリック URL として送信してください。
</ParamField>

<ParamField body="input.media[].type" type="string" required>
  メディアアセットの種別

  指定可能な値: `first_frame`, `last_frame`, `driving_audio`, `first_clip`, `reference_image`, `reference_video`, `reference_audio`, `video`, `file`, `link`
</ParamField>

<ParamField body="input.media[].url" type="string" required>
  メディアファイルの URL。パブリックな HTTP/HTTPS URL、または、各モデルについて上記の `media` の説明に記載されているまさに IMAGE 入力（wan2.7-i2v の first_frame と last_frame、wan2.7-r2v の first_frame と reference_image、wan2.7-videoedit の reference_image、wan3.0-video と wan3.0-video-prime の first_frame、last_frame、reference_image、happyhorse-1.0-i2v と happyhorse-1.1-i2v の first_frame、happyhorse-1.0-r2v と happyhorse-1.1-r2v の reference_image、happyhorse-1.0-video-edit の reference_image）に限り、インラインの `data:{MIME_type};base64,...` URL を指定できます。これらのモデルのいずれにおいても、video、audio、file、link の入力はインラインの data: URL を受け付けません。パートナー自身のアップロードサービスによる oss://dashscope-instant の一時 URL、または（wan2.7-videoedit では）Asset Center の asset_id は、それをアップロードした Alibaba Cloud アカウントに対してのみ解決されます。Comfy は自身のキーでモデルを呼び出し、アップロード経路を公開していないため、呼び出し元自身の oss:// URL や asset_id はサポートされる入力ではありません。このフィールドは URL スキームを検証しないため、そのような値はここで拒否されることなく、そのままパートナーへ転送されます。モデルごとのサイズとピクセルの制限、およびインラインのペイロードを全体として制限する 100 MiB の Router リクエストボディ上限については、`media` の説明を参照してください。
</ParamField>

<ParamField body="input.prompt" type="string">
  テキストプロンプト。中国語と英語に対応しており、長さは 800 文字以内です
（wan3.0-video では最大 20,000 文字。制限を超えたコンテンツは切り捨てられます）。
複数の参照ビデオを使う wan2.6-r2v では、'character1'、'character2' などを用いて、
参照ビデオの順序で被写体を参照します。例: "Character1 sings on the roadside, Character2 dances beside it"
wan3.0-video の参照モードでは、'Image 1'、'Video 1'、'Audio 1' などを用いて、
media 配列内の対応する順序でメディアアセットを参照します。
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  wan2.6-r2v モデル専用の参照ビデオ URL。1〜3 個のビデオ URL の配列です。
入力の制限:
- 形式: mp4, mov
- 数量: 1〜3 本のビデオ
- 単一ビデオの長さ: 2〜30 秒
- 単一ファイルサイズ: 最大 30MB
- audio_url と併用できません
参照の再生時間: 単一ビデオは最大 5 秒、2 本の場合はそれぞれ最大 2.5 秒、3 本の場合はそれに比例して短くなります。
課金: 実際に使用した参照の再生時間に基づきます。
</ParamField>

<ParamField body="input.template" type="string">
  ビデオエフェクトテンプレート名。任意です。現在サポートされているのは squish、flying、carousel です。使用した場合、prompt パラメータは無視されます。
</ParamField>

</ParamField>

- wan2.5 モデル: 5 秒または 10 秒
- wan2.6-t2v、wan2.6-i2v: 5、10、15 秒
- wan2.6-r2v: 5 秒または 10 秒のみ（15 秒はサポートなし）
- wan2.7-i2v、wan2.7-t2v: [2, 15] の整数
- wan2.7-r2v、wan2.7-videoedit: [2, 10] の整数
- wan3.0-video: ビデオ入力なしの場合は [2, 30] の整数。ビデオ入力がある場合、入力ビデオの再生時間と出力ビデオの再生時間の合計は 30 秒を超えてはなりません。-1 はスマート再生時間モードを有効にし、モデルが適切な再生時間を選択します

  範囲: `-1` 〜 `30`
</ParamField>

<ParamField body="parameters.prompt_extend" type="boolean" default="true">
  プロンプトのインテリジェントな書き換えを有効にするかどうか。デフォルトは true です
</ParamField>

<ParamField body="parameters.ratio" type="string">
  生成されるビデオのアスペクト比。wan2.7 および wan3.0 モデル専用です。
wan2.7 モデルでは、指定しない場合、解像度ティアに基づいてデフォルトが決まります。
wan3.0-video では、adaptive（デフォルト）が入力メディアの比率と意図に基づいて
適切なアスペクト比を自動的に推奨します。

  指定可能な値: `adaptive`, `16:9`, `9:16`, `1:1`, `4:3`, `3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  解像度レベル。サポートされる値はモデルによって異なります:
- wan2.5-i2v-preview: 480P、720P、1080P
- wan2.6-i2v: 720P、1080P のみ（480P はサポートなし）
- wan2.7 モデル（i2v、t2v、r2v、videoedit）: 720P、1080P（デフォルト 1080P）
- wan3.0-video、wan3.0-video-prime: 480P、720P、1080P（上流のデフォルト 1080P）このプロキシは、解像度もサイズも指定されていないビデオ生成リクエストを拒否します。これは、解像度ティアによって課金レートが選択されるためです。

  指定可能な値: `480P`、`720P`、`1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  乱数シード。モデルが生成するコンテンツのランダム性を制御するために使用します。

  範囲: `0` から `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  インテリジェントなマルチレンズ制御。prompt_extend が有効な場合にのみ機能します。
wan2.6 および wan2.7-r2v モデル向け。
- single: シングルショットビデオ（デフォルト）
- multi: マルチショットビデオ

  指定可能な値: `multi`、`single`
</ParamField>

<ParamField body="parameters.size" type="string">
  幅*高さ形式のビデオ解像度。サポートされる解像度はモデルによって異なります:
wan2.5 T2V の場合: 480P (480*832、832*480、624*624)、720P、1080P サイズ
wan2.6 T2V/R2V の場合（480P なし）:
  720P: 1280*720、720*1280、960*960、1088*832、832*1088
  1080P: 1920*1080、1080*1920、1440*1440、1632*1248、1248*1632
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  ウォーターマークロゴを追加するかどうか。ウォーターマークは右下隅に配置されます。
</ParamField>
