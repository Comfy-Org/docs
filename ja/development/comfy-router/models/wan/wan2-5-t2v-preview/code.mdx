Wan 2.5 T2V プレビューの API リファレンスです。Wan 2.5 のテキストから動画への生成は、プロンプトのみから短いビデオを作成します。参照画像や参照ビデオは不要です。

**入力：** オーディオ, テキスト · **出力：** ビデオ + オーディオ

**エンドポイント:** `POST https://api.comfy.org/v2/models/wan/wan2.5-t2v-preview`

import asyncio
from comfy_sdk import AsyncComfy

# 環境変数から COMFY_API_KEY を読み取ります。
# 各 submit() 呼び出しは独自の Idempotency-Key を発行し、自動リトライのために再利用します。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/wan2.5-t2v-preview",
            {
                "input": {
                    "prompt": "a single red maple leaf falling onto still water, slow motion, shallow depth of field",
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # モデル ID と合わせれば、別のプロセスに必要なものはすべて揃います

        # リクエストが完了するまでポーリングし、サーバーが指定する Retry-After の秒数だけ待機します。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # プロバイダー自身のペイロードで、models.run() が返すのと同じ値です。
        # 失敗またはキャンセル済みのリクエストは、ここで型付きの Router エラーを発生させます。
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())

// 各 submit() 呼び出しは独自の Idempotency-Key を発行し、自動リトライのために再利用します。
type Result = { output: { video_url: string } };
const handle = await comfy.models.submit<Result>("wan/wan2.5-t2v-preview", {
  input: {
    prompt: "a single red maple leaf falling onto still water, slow motion, shallow depth of field",
  },
  parameters: {
    resolution: "720P",
    duration: 5,
  },
});
console.log("requestId:", handle.requestId); // モデル ID と合わせれば、別のプロセスに必要なものはすべて揃います

// リクエストが完了するまでポーリングし、サーバーが指定する Retry-After の秒数だけ待機します。
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// models.run() が返すのと同じ結果です。失敗またはキャンセル済みのリクエストは、ここで reject されます。
const result = await handle.get();
if (result.kind !== "json") throw new Error("expected a JSON result");

console.log("video:", result.data.output.video_url);

### 入力

<ParamField body="input" type="object" required>
  プロンプト語句などの基本情報を入力します。
</ParamField>

<ParamField body="input.audio_url" type="string">
  オーディオファイルのダウンロードURL。対応形式: mp3 と wav。reference_video_urls とは併用できません。
</ParamField>

<ParamField body="input.img_url" type="string">
  先頭フレーム画像のURL、または Base64 エンコードされたデータ。wan2.5-i2v-preview および
wan2.6-i2v モデルでは必須です。happyhorse-1.x の i2v 系スペルは、ここで先頭フレームを受け取りません。
代わりに type が first_frame のメディア要素として受け取ります（後述の media を参照）。また、
wan2.6-i2v では成功する img_url ボディも、happyhorse-1.0-i2v および happyhorse-1.1-i2v では
プロバイダーに拒否されます。さらに wan2.7/wan3.0 系スペルも参照アセットを media で受け取ります。
画像形式: JPEG、JPG、PNG、BMP、WEBP。解像度: 360～2000 ピクセル。ファイルサイズ: 最大 10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。ビデオ生成のための参照素材（画像、オーディオ、ビデオ）を指定します。
各要素は type と url フィールドを持ちます。このフィールドはこのコンポーネントから提供される
すべてのモデルで共有されますが、あるモデルがどの type 値を受け付けるか、またそもそも
img_url や reference_video_urls ではなくここで画像やビデオの入力を受け取るかどうかは、
モデルによって異なります。モデルごとの対応 type 値:
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frame と
  last_frame: JPEG/JPG/PNG/BMP/WEBP、1 辺 240～8000 ピクセル、アスペクト比 1:8 ～ 8:1、
  最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。
  driving_audio（WAV/MP3、2～30 秒、最大 15MB）および first_clip（MP4/MOV、2～10 秒、
  1 辺 240～4096 ピクセル、最大 100MB）: 公開 HTTP/HTTPS URL。インラインの
  data: URL は受け付けられません。
- wan2.7-r2v: first_frame（任意、最大 1）、reference_image、reference_video。少なくとも
  1 つの reference_image または reference_video が必要で、reference_image と
  reference_video の合計は最大 5 です。first_frame と reference_image:
  JPEG/JPG/PNG/BMP/WEBP（アルファチャンネルなし）、1 辺 240～8000 ピクセル、アスペクト比
  1:8 ～ 8:1、最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。
  reference_video: 公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-videoedit: video（厳密に 1 つ、編集対象のクリップ: MP4/MOV、2～10 秒、
  1 辺 240～4096 ピクセル、最大 100MB、公開 HTTP/HTTPS URL。インラインの data: URL
  は受け付けられません）と、任意で 0～4 個の reference_image（JPEG/JPG/PNG/BMP/WEBP、
  1 辺 240～8000 ピクセル、アスペクト比 1:8 ～ 8:1、最大 20MB、公開 URL
  または data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime: first_frame（最大 1）、last_frame（最大 1）、
  reference_image（最大 10）、reference_video（最大 5 クリップ、合計再生時間 \<= 15 秒）、
  reference_audio（最大 5 クリップ、合計再生時間 \<= 15 秒）、file（最大 1、link とは
  併用不可）、link（最大 1、file とは併用不可）。reference_*/file/link タイプ
  と first_frame/last_frame タイプは、同じリクエスト内では相互に排他的です。配列の順序が
  プロンプト内のアセットの参照順（Image 1、Video 1、Audio 1…）を定義します。
  first_frame、last_frame、reference_image: JPEG/JPG/PNG/BMP/WEBP、
  1 辺 240～8000 ピクセル、アスペクト比は最大 8:1、最大 20MB、公開 URL または
  data:\{MIME_type};base64,... URL。reference_video、reference_audio、file、link: 公開
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v: first_frame のみ、厳密に 1 つ。これらのスペルは
  先頭フレームを img_url ではなくここで受け取ります。少なくとも 300x300 ピクセル、アスペクト比
  1:2.5 ～ 2.5:1、JPEG/JPG/PNG/WEBP、最大 20MB、公開 URL または
  data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v: reference_image のみ、1～9 個。これが
  このモデル唯一の参照入力です。最短辺は少なくとも 400 ピクセル、JPEG/JPG/PNG/WEBP、
  最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。reference_video は
  この操作の入力タイプではありません。
- happyhorse-1.0-video-edit: video（厳密に 1 つ、編集対象のクリップ: MP4/MOV、3～60
  秒、長辺は最大 4096 ピクセル、短辺は少なくとも 360 ピクセル、アスペクト比
  1:2.5 ～ 2.5:1、最大 100MB、公開 HTTP/HTTPS URL。インラインの data:
  URL は受け付けられません）と、任意で 0～5 個の reference_image（JPEG/JPG/PNG/WEBP、
  少なくとも 300x300 ピクセル、アスペクト比 1:2.5 ～ 2.5:1、最大 20MB、公開 URL
  または data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview:
  テキストから動画への操作。これらのスペルのパートナーリファレンスにはメディア入力の
  記載がないため、このフィールドは未設定のままにします。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v: このコンポーネントはこれらのスペルに対して
  メディアの語彙を列挙していません。wan2.5-i2v-preview と wan2.6-i2v は先頭フレームを
  img_url で受け取り、wan2.6-r2v は参照クリップを reference_video_urls で受け取ります。
上記のモデルごとの個数はパートナーの制約であり、このスキーマの制約ではありません。media には
minItems/maxItems が宣言されていません。許容されるタイプとその上限はモデルごとに異なるためです。
スキーマが受け付けることは、プロバイダーが受け付けることを意味しません。逆に、上記のアセットごとの
「最大 20MB」という数値は、画像入力（インラインで送信できる唯一の入力）に対する上限であり、
パートナーが最終的に受け取るアセットに対するパートナーの上限です。アセットが公開 URL の場合は
記載どおりに適用されます。そのバイト列が Comfy を経由することがないためです。インラインの
data:\{MIME_type};base64,... URL は Comfy を経由するため、転送上の上限にも直面します。Comfy Router
の POST ボディは合計 100 MiB が上限で、それを超えると 413 が返されます。また base64 はペイロードを
約 4/3 に膨らませるため、およそ 75 MB を超える単一のインラインアセットは、ここに挙げたパートナーの
ルールに到達する前に拒否されます。そのサイズでは、パートナー自身の20MB の上限内ならインラインで問題なく収まるため、1 つのアセットについてはパートナーのルールが制約となります。一方、複数のアセットにまたがる場合は転送の上限が制約となります。これは、100 MiB の Router の上限が各要素ではなくリクエスト全体を制限するためです。これらの上限に近いものは、公開 URL として送信してください。
</ParamField>

<ParamField body="input.media[].url" type="string" required>
  メディアファイルの URL: 公開 HTTP/HTTPS URL、または、上記の `media` の説明が各モデルについて列挙しているまさにその画像入力 (wan2.7-i2v の first_frame と last_frame、wan2.7-r2v の first_frame と reference_image、wan2.7-videoedit の reference_image、wan3.0-video と wan3.0-video-prime の first_frame、last_frame と reference_image、happyhorse-1.0-i2v と happyhorse-1.1-i2v の first_frame、happyhorse-1.0-r2v と happyhorse-1.1-r2v の reference_image、および happyhorse-1.0-video-edit の reference_image) に限り、インラインの `data:{MIME_type};base64,...` URL を使用できます。これらのモデルのいずれにおいても、ビデオ、オーディオ、ファイル、リンクの入力はインラインの data: URL を受け付けません。パートナー自身のアップロードサービスによる oss://dashscope-instant の一時 URL、または (wan2.7-videoedit では) Asset Center の asset_id は、それをアップロードした Alibaba Cloud アカウントに対してのみ解決されます。Comfy は自身のキーでモデルを呼び出し、アップロード経路を公開していないため、呼び出し元自身の oss:// URL や asset_id はサポートされる入力ではありません。このフィールドは URL スキームを検証しないため、そのような値はここで拒否されることなく、そのままパートナーに転送されます。モデルごとのサイズとピクセルの制限、およびインラインペイロードを全体として制限する 100 MiB の Router リクエストボディ上限については、`media` の説明を参照してください。

<ParamField body="input.prompt" type="string">
  テキストプロンプトの語句。中国語と英語をサポートし、長さは 800 文字以内です
(wan3.0-video では最大 20,000 文字。制限を超えた内容は切り捨てられます)。
複数の参照ビデオを使う wan2.6-r2v では、'character1'、'character2' などを使用して、参照ビデオの順序に対応する被写体を参照します。例: "Character1 sings on the roadside, Character2 dances beside it"
wan3.0-video の参照モードでは、'Image 1'、'Video 1'、'Audio 1' などを使用して、media 配列内の対応する順序のメディアアセットを参照します。
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  wan2.6-r2v モデル専用の参照ビデオ URL。1〜3 本のビデオ URL の配列です。
入力の制限:
- フォーマット: mp4、mov
- 数量: ビデオ 1〜3 本
- 単一ビデオの長さ: 2〜30 秒
- 単一ファイルサイズ: 最大 30MB
- audio_url と併用できません
参照の再生時間: 単一ビデオは最大 5 秒、2 本の場合は各最大 2.5 秒、3 本の場合は比例して短くなります。
課金: 実際に使用した参照の再生時間に基づきます。
</ParamField>

<ParamField body="input.template" type="string">

<ParamField body="parameters.duration" type="integer" default="5">
  生成されるビデオの再生時間 (秒):
- wan2.5 モデル: 5 秒または 10 秒
- wan2.6-t2v、wan2.6-i2v: 5、10、または 15 秒
- wan2.6-r2v: 5 秒または 10 秒のみ (15 秒はサポートされません)
- wan2.7-i2v、wan2.7-t2v: [2, 15] の整数
- wan2.7-r2v、wan2.7-videoedit: [2, 10] の整数
- wan3.0-video: ビデオ入力なしの場合は [2, 30] の整数。ビデオ入力ありの場合は、入力ビデオの再生時間 + 出力ビデオの再生時間の合計が 30 秒を超えてはなりません。-1 はモデルが適切な再生時間を選ぶスマート再生時間モードを有効にします

  範囲: `-1` から `30`
</ParamField>

<ParamField body="parameters.ratio" type="string">
  生成されるビデオのアスペクト比。wan2.7 および wan3.0 モデル専用です。
wan2.7 モデルでは、指定しない場合、解像度ティアに基づいてデフォルトが決まります。
wan3.0-video では、adaptive (デフォルト) が入力メディアの比率と意図に基づいて適切なアスペクト比を自動的に推奨します。

  指定可能な値: `adaptive`、`16:9`、`9:16`、`1:1`、`4:3`、`3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  解像度レベル。サポートされる値はモデルによって異なります:
- wan2.5-i2v-preview: 480P、720P、1080P
- wan2.6-i2v: 720P、1080P のみ (480P はサポートされません)
- wan2.7 モデル (i2v、t2v、r2v、videoedit): 720P、1080P (デフォルト 1080P)
- wan3.0-video、wan3.0-video-prime: 480P、720P、1080P (上流のデフォルトは 1080P)
このプロキシは、resolution も size も指定していないビデオ生成リクエストを拒否します。解像度ティアが課金レートを決定するためです。

  指定可能な値: `480P`, `720P`, `1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  乱数シード。モデルが生成するコンテンツのランダム性を制御するために使用します

  範囲: `0` から `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  インテリジェントなマルチレンズ制御。prompt_extend が有効な場合にのみ動作します。
wan2.6 および wan2.7-r2v モデル用。
- single: 単一ショットのビデオ（デフォルト）
- multi: マルチショットのビデオ

  指定可能な値: `multi`, `single`
</ParamField>

<ParamField body="parameters.size" type="string">
  width*height 形式のビデオ解像度。対応する解像度はモデルによって異なります:
wan2.5 T2V の場合: 480P (480*832, 832*480, 624*624)、720P、1080P のサイズ
wan2.6 T2V/R2V の場合（480P なし）:
  720P: 1280*720, 720*1280, 960*960, 1088*832, 832*1088
  1080P: 1920*1080, 1080*1920, 1440*1440, 1632*1248, 1248*1632
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  ウォーターマークロゴを追加するかどうか。ウォーターマークは右下隅に表示されます
</ParamField>
