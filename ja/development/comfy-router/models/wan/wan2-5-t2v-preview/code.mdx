Wan 2.5 T2V プレビューの API リファレンスです。Wan 2.5 のテキストから動画への生成は、プロンプトのみから短いビデオを作成します。参照画像や参照ビデオは不要です。

**入力：** オーディオ, テキスト · **出力：** ビデオ + オーディオ

## クイックスタート

**モデル ID:** `wan/wan2.5-t2v-preview`

**エンドポイント:** `POST https://api.comfy.org/v2/models/wan/wan2.5-t2v-preview`

import asyncio
from comfy_sdk import AsyncComfy

# 環境変数から COMFY_API_KEY を読み取ります。
# 各 submit() 呼び出しは独自の Idempotency-Key を発行し、自動リトライのために再利用します。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/wan2.5-t2v-preview",
            {
                "input": {
                    "prompt": "a single red maple leaf falling onto still water, slow motion, shallow depth of field",
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # モデル ID と合わせれば、別のプロセスに必要なものはすべて揃います

        # リクエストが完了するまでポーリングし、サーバーが指定する Retry-After の秒数だけ待機します。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # プロバイダー自身のペイロードで、models.run() が返すのと同じ値です。
        # 失敗またはキャンセル済みのリクエストは、ここで型付きの Router エラーを発生させます。
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())

// 各 submit() 呼び出しは独自の Idempotency-Key を発行し、自動リトライのために再利用します。
type Result = { output: { video_url: string } };
const handle = await comfy.models.submit<Result>("wan/wan2.5-t2v-preview", {

  },
  parameters: {
    resolution: "720P",
    duration: 5,
  },
});
console.log("requestId:", handle.requestId); // モデル ID と合わせれば、別のプロセスに必要なものはすべて揃います

// リクエストが完了するまでポーリングし、サーバーが指定する Retry-After の秒数だけ待機します。
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// models.run() が返すのと同じ結果です。失敗またはキャンセル済みのリクエストは、ここで reject されます。
const result = await handle.get();

console.log("video:", result.data.output.video_url);

<ParamField body="input.img_url" type="string">
  先頭フレームの画像URLまたはBase64エンコードされたデータ。wan2.5-i2v-preview および
wan2.6-i2v モデルでは必須です。happyhorse-1.x の i2v 系のスペルでは、先頭フレームをここでは受け取りません。
先頭フレームは type が first_frame の media 要素として受け取ります（後述の media を参照）。
また、wan2.6-i2v では成功する img_url のボディも、happyhorse-1.0-i2v と
happyhorse-1.1-i2v ではプロバイダーに拒否されます。さらに wan2.7/wan3.0 系のスペルも
参照アセットを media で受け取ります。画像形式: JPEG、JPG、PNG、BMP、WEBP。
解像度: 360〜2000ピクセル。ファイルサイズ: 最大10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。動画生成のための参照素材（画像、オーディオ、ビデオ）を指定します。
各要素は type と url フィールドを持ちます。このフィールドはこのコンポーネントから提供される
すべてのモデルで共通であり、どの type 値を受け付けるか、またそもそも画像やビデオの入力を
img_url や reference_video_urls ではなくここで受け取るかどうかは、モデルごとに異なります。
モデルごとの対応 type 値:
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frame と
  last_frame: JPEG/JPG/PNG/BMP/WEBP、1辺240〜8000ピクセル、アスペクト比1:8〜8:1、
  最大20MB、公開URLまたは data:\{MIME_type};base64,... URL。
  driving_audio（WAV/MP3、2〜30秒、最大15MB）と first_clip（MP4/MOV、2〜10秒、
  1辺240〜4096ピクセル、最大100MB）: 公開HTTP/HTTPS URL。インラインの
  data: URL は受け付けられません。
- wan2.7-r2v: first_frame（任意、最大1）、reference_image、reference_video。
  reference_image または reference_video が少なくとも1つ必要で、reference_image と
  reference_video の合計は最大5つです。first_frame と reference_image: JPEG/JPG/PNG/BMP/WEBP
  （アルファチャンネルなし）、1辺240〜8000ピクセル、アスペクト比1:8〜8:1、最大
  20MB、公開URLまたは data:\{MIME_type};base64,... URL。reference_video: 公開
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-videoedit: video（ちょうど1つ。編集対象のクリップ: MP4/MOV、2〜10秒、
  1辺240〜4096ピクセル、最大100MB、公開HTTP/HTTPS URL。インラインの data: URL
  は受け付けられません）に加えて、任意で0〜4つの reference_image（JPEG/JPG/PNG/BMP/WEBP、
  1辺240〜8000ピクセル、アスペクト比1:8〜8:1、最大20MB、公開URL
  または data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime: first_frame（最大1）、last_frame（最大1）、
  reference_image（最大10）、reference_video（最大5クリップ、合計再生時間 \<= 15s）、
  reference_audio（最大5クリップ、合計再生時間 \<= 15s）、file（最大1、link と併用不可）、
  link（最大1、file と併用不可）。reference_*/file/link タイプと first_frame/last_frame
  タイプは同一リクエスト内で同時に使用できません。配列の順序が、プロンプト内での
  アセットの参照順（Image 1、Video 1、Audio 1、...）を定義します。first_frame、last_frame、
  reference_image: JPEG/JPG/PNG/BMP/WEBP、1辺240〜8000ピクセル、アスペクト比最大8:1、
  最大20MB、公開URLまたは data:\{MIME_type};base64,... URL。reference_video、
  reference_audio、file、link: 公開HTTP/HTTPS URL。インラインの data: URL は
  受け付けられません。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v: first_frame のみ、ちょうど1つ。これらのスペルは
  先頭フレームを img_url ではなくここで受け取ります。少なくとも300x300ピクセル、アスペクト比
  1:2.5〜2.5:1、JPEG/JPG/PNG/WEBP、最大20MB、公開URLまたは
  data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v: reference_image のみ、1〜9つ。これが
  このモデル唯一の参照入力です。最短辺が少なくとも400ピクセル、JPEG/JPG/PNG/WEBP、
  最大20MB、公開URLまたは data:\{MIME_type};base64,... URL。reference_video は
  この操作の入力タイプではありません。
- happyhorse-1.0-video-edit: video（ちょうど1つ。編集対象のクリップ: MP4/MOV、3〜60
  秒、長辺が最大4096ピクセル、短辺が少なくとも360ピクセル、アスペクト比
  1:2.5〜2.5:1、最大100MB、公開HTTP/HTTPS URL。インラインの data:
  URL は受け付けられません）に加えて、任意で0〜5つの reference_image（JPEG/JPG/PNG/WEBP、
  少なくとも300x300ピクセル、アスペクト比1:2.5〜2.5:1、最大20MB、公開URL
  または data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview:
  テキストから動画への操作です。これらのパートナー参照ドキュメントにはメディア入力が
  記載されていないため、このフィールドは未設定のままにします。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v: このコンポーネントはこれらのスペル向けの
  メディア語彙を列挙していません。wan2.5-i2v-preview と wan2.6-i2v は先頭フレームを
  img_url で受け取り、wan2.6-r2v は参照クリップを reference_video_urls で受け取ります。
上記のモデルごとの個数はこのスキーマの制約ではなくパートナーの制約です。media には
minItems/maxItems が宣言されていません。これは受け付け可能なタイプとその上限が
モデルごとに異なるためです。スキーマが受け付けることは、プロバイダーが受け付けることを
意味しません。逆方向についても同様で、上記のアセットごとの「最大20MB」という数値は、
画像入力に対する上限であり、インラインで送信できる唯一の入力に対する上限です。
これはパートナーが最終的に受け取るアセットに対する上限であり、アセットが公開URLの
場合は記載どおりに適用されます。そのバイト列は Comfy を経由しないためです。インラインの
data:\{MIME_type};base64,... URL は Comfy を経由するため、転送上の上限にも直面します。
Comfy Router の POST ボディは合計100 MiBに制限され、それを超えると 413 が返されます。
また base64 はペイロードを約4/3に膨らませるため、およそ75 MBを超える単一の
インラインアセットは、ここに示すパートナーのルールに到達する前に拒否されます。
そのサイズでは、パートナー自身の

<ParamField body="input.media[].url" type="string" required>
  メディアファイルの URL。パブリックな HTTP/HTTPS URL、または、上記の `media` の説明で各モデルについて列挙されている IMAGE 入力（wan2.7-i2v の first_frame と last_frame、wan2.7-r2v の first_frame と reference_image、wan2.7-videoedit の reference_image、wan3.0-video と wan3.0-video-prime の first_frame、last_frame、reference_image、happyhorse-1.0-i2v と happyhorse-1.1-i2v の first_frame、happyhorse-1.0-r2v と happyhorse-1.1-r2v の reference_image、happyhorse-1.0-video-edit の reference_image）に限り、インラインの `data:{MIME_type};base64,...` URL を指定できます。これらのモデルのビデオ、オーディオ、ファイル、リンクのいずれの入力も、インラインの data: URL を受け付けません。パートナー自身のアップロードサービスが発行する oss://dashscope-instant の一時 URL、または（wan2.7-videoedit では）Asset Center の asset_id は、それをアップロードした Alibaba Cloud アカウントに対してのみ解決されます。Comfy は自身のキーでモデルを呼び出し、アップロード経路を公開していないため、呼び出し元自身の oss:// URL や asset_id はサポートされる入力ではありません。このフィールドは URL スキームを検証しないため、そのような値はここで拒否されず、そのままパートナーに転送されます。モデルごとのサイズとピクセルの制限、およびインラインのペイロードを合計で制限する 100 MiB の Router リクエストボディの上限については、`media` の説明を参照してください。

<ParamField body="input.negative_prompt" type="string">
  ネガティブプロンプトは、ビデオ画面に表示したくないコンテンツを記述するために使用します。500 文字を超えると、wan モデルは拒否せずに切り詰めます。prompt と同じ入力予算にカウントされます。

<ParamField body="input.prompt" type="string">
  テキストプロンプト。中国語と英語をサポートします。独自に定められた長さを超えると、wan2.x モデルはプロンプトを拒否せずに切り詰めます。wan2.5 と wan2.6 は 1,500 文字、wan2.7 は 5,000 文字です。wan3.0-video と wan3.0-video-prime は最大 20,000 文字を受け付けます。プロバイダーは、prompt と negative_prompt を合わせて約 60,850 バイトの UTF-8 テキスト（約 20,000 文字の中国語）を超えるリクエストを拒否し、InvalidParameter `Range of input length should be [1, 61440]` を返します。wan2.6-r2v で複数の参照ビデオを使う場合は、参照ビデオの順序に従って 'character1'、'character2' などで被写体を参照してください。例: "Character1 sings on the roadside, Character2 dances beside it"
wan3.0-video の参照モードでは、media 配列内の対応する順序でメディアアセットを参照するために 'Image 1'、'Video 1'、'Audio 1' などを使用します。
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  wan2.6-r2v モデル専用の参照ビデオ URL。1〜3 本のビデオ URL の配列です。
入力の制限:
- 形式: mp4、mov
- 数量: 1〜3 本のビデオ
- 単一ビデオの長さ: 2〜30 秒
- 単一ファイルサイズ: 最大 30MB
- audio_url と併用できません
参照再生時間: ビデオ 1 本の場合は最大 5 秒、2 本の場合は各最大 2.5 秒、3 本の場合はそれぞれ比例して短くなります。
課金: 実際に使用された参照再生時間に基づきます。
</ParamField>

<ParamField body="parameters.duration" type="integer" default="5">
  生成されるビデオの再生時間（秒）:
- wan2.5 モデル: 5 または 10 秒
- wan2.6-t2v、wan2.6-i2v: 5、10、または 15 秒
- wan2.6-r2v: 5 または 10 秒のみ（15 秒は非サポート）
- wan2.7-i2v、wan2.7-t2v: [2, 15] の整数
- wan2.7-r2v、wan2.7-videoedit: [2, 10] の整数
- wan3.0-video: ビデオ入力なしの場合は [2, 30] の整数。ビデオ入力ありの場合は、入力ビデオの再生時間と出力ビデオの再生時間の合計が 30 秒を超えてはなりません。-1 はスマート再生時間モードを有効にし、モデルが適切な再生時間を選択します
このプロキシは [-1, 30] の範囲外の duration に対して 400 を返します。

  範囲: `-1` から `30`
</ParamField>

<ParamField body="parameters.prompt_extend" type="boolean" default="true">
  プロンプトのインテリジェントな書き換えを有効にするかどうか。デフォルトは true です
</ParamField>

<ParamField body="parameters.ratio" type="string">
  生成されるビデオのアスペクト比。wan2.7 と wan3.0 モデルのみ。wan2.7 モデルでは、指定しない場合、解像度ティアに基づいてデフォルトが決まります。wan3.0-video では、adaptive（デフォルト）が適切な入力メディアの比率と意図に基づくアスペクト比。

  指定可能な値: `adaptive`、`16:9`、`9:16`、`1:1`、`4:3`、`3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  解像度レベル。サポートされる値はモデルによって異なります:
- wan2.5-i2v-preview: 480P、720P、1080P
- wan2.6 モデル（t2v、i2v、r2v）: 720P、1080P のみ（480P 非対応）
- wan2.7 モデル（i2v、t2v、r2v、videoedit）: 720P、1080P（デフォルト 1080P）
- wan3.0-video、wan3.0-video-prime: 480P、720P、1080P（上流のデフォルトは 1080P）
- happyhorse-1.0-*（t2v、i2v、r2v、video-edit）: 720P、1080P
- happyhorse-1.1-*（t2v、i2v、r2v）: 480P、720P、1080P
このプロキシは、resolution も size も指定されていないビデオ生成リクエストを拒否します。これは解像度ティアが課金レートを選択するためです。チェック前に resolution を大文字化し、その大文字化した値を転送します。この enum に含まれない値には 400 を返し、上記で 480P 非対応として示した wan2.6、wan2.7、happyhorse-1.0 モデルでは、480P（resolution として送信された場合も、480P の size として送信された場合も）に対して 400 を返します。

  指定可能な値: `480P`、`720P`、`1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  乱数シード。モデルが生成するコンテンツのランダム性を制御するために使用します

  範囲: `0` から `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  インテリジェントなマルチレンズ制御。prompt_extend が有効な場合にのみ機能します。
wan2.6 および wan2.7-r2v モデル向け。
- single: 単一ショットのビデオ（デフォルト）
- multi: マルチショットのビデオ

  指定可能な値: `multi`、`single`
</ParamField>

<ParamField body="parameters.size" type="string">
  幅*高さ形式のビデオ解像度。サポートされる解像度はモデルによって異なります:
wan2.5 T2V の場合: 480P（480*832、832*480、624*624）、720P、1080P のサイズ
wan2.6 T2V/R2V の場合（480P なし）:
  720P: 1280*720、720*1280、960*960、1088*832、832*1088
  1080P: 1920*1080、1080*1920、1440*1440、1632*1248、1248*1632
size と resolution の両方が送信された場合、size が課金ティアを選択し、resolution はそのモデルに対してこのプロキシが受け入れる値である必要があります。480P の size は、解像度の説明で 480P 非対応として示されているすべてのモデルで 400 を返します。
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  ウォーターマークロゴを追加するかどうか。ウォーターマークは右下隅に配置されます
</ParamField>
