Wan 2.6 R2V の API リファレンス。Wan 2.6 の参照から動画は、1～3 本の参照ビデオの被写体を新しいシーンへ持ち込みます。プロンプト内では character1、character2 などのように指定します。

**入力：** 画像, ビデオ, テキスト · **出力：** ビデオ + オーディオ

## クイックスタート

[お使いの Comfy ワークスペース](https://platform.comfy.org/profile/api-keys?onboarding=router)でキーを作成し、`COMFY_API_KEY` としてエクスポートします。Python と TypeScript のスニペットは Comfy SDK（`pip install comfy-sdk` および `npm install @comfyorg/sdk`）を使用しています。cURL のスニペットは同じ呼び出しを raw HTTP で行うものです。

**モデル ID:** `wan/wan2.6-r2v`

**エンドポイント:** `POST https://api.comfy.org/v2/models/wan/wan2.6-r2v`

同じボディを `POST https://api.comfy.org/v2/models/wan/wan2.6-r2v/requests` に送信します。Router は実行が受け付けられるとすぐに `201` と `request_id` を返し、結果は準備ができ次第、このプロセスまたは別のプロセスから収集されます。[キュー配信](/ja/development/comfy-router/queue)では、ステータス、キャンセル、収集について説明します。

```python Python
import asyncio
from comfy_sdk import AsyncComfy

# COMFY_API_KEY を環境変数から読み取ります。
# 各 submit() 呼び出しは独自の Idempotency-Key を発行し、自動リトライで再利用します。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/wan2.6-r2v",
            {
                "input": {
                    "prompt": "character1 walks in from the left, turns to the camera and waves, plain orange backdrop",
                    "reference_video_urls": ["https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/street_dancer.mp4"],
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # モデル ID と合わせて、別のプロセスに必要な情報はこれだけです

        # リクエストが完了するまでポーリングし、サーバーが指定する Retry-After だけ待機します。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # プロバイダー自身のペイロードで、models.run() が返す値と同じです。
        # 失敗またはキャンセルされたリクエストは、ここで型付き Router エラーを発生させます。
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// COMFY_API_KEY を環境変数から読み取ります。
// 各 submit() 呼び出しは独自の Idempotency-Key を発行し、自動リトライで再利用します。
type Result = { output: { video_url: string } };
const handle = await comfy.models.submit<Result>("wan/wan2.6-r2v", {
  input: {
    prompt: "character1 walks in from the left, turns to the camera and waves, plain orange backdrop",
    reference_video_urls: ["https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/street_dancer.mp4"],
  },
  parameters: {
    resolution: "720P",
    duration: 5,
  },
});
console.log("requestId:", handle.requestId); // モデル ID と合わせて、別のプロセスに必要な情報はこれだけです

// リクエストが完了するまでポーリングし、サーバーが指定する Retry-After だけ待機します。
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// models.run() が返すのと同じ結果です。失敗またはキャンセルされたリクエストはここで reject されます。
const result = await handle.get();
if (result.kind !== "json") throw new Error("expected a JSON result");

console.log("video:", result.data.output.video_url);
```

## スキーマ

### 入力

<ParamField body="input" type="object" required>
  プロンプトなどの基本情報を入力します。
</ParamField>

<ParamField body="input.audio_url" type="string">
  オーディオファイルのダウンロードURL。対応形式: mp3、wav。reference_video_urls とは併用できません。
</ParamField>

<ParamField body="input.img_url" type="string">
  先頭フレームの画像URL、または Base64 エンコードされたデータ。wan2.5-i2v-preview と wan2.6-i2v モデルでは必須です。happyhorse-1.x の i2v 系の綴りでは、先頭フレームをここで受け取るのではなく、type が first_frame のメディア要素として受け取ります（後述の media を参照）。wan2.6-i2v では成功する img_url ボディも、happyhorse-1.0-i2v と happyhorse-1.1-i2v ではプロバイダーに拒否されます。また、wan2.7/wan3.0 系の綴りも参照アセットを media で受け取ります。画像形式: JPEG、JPG、PNG、BMP、WEBP。解像度: 360〜2000 ピクセル。ファイルサイズ: 最大 10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。ビデオ生成用の参照素材（画像、オーディオ、ビデオ）を指定します。各要素は type と url フィールドを持ちます。このフィールドは、このコンポーネントが提供するすべてのモデルで共有されていますが、あるモデルがどの type 値を受け付けるか（また、画像やビデオの入力を img_url や reference_video_urls ではなくそもそもここで受け取るかどうか）は、モデルによって異なります。モデルごとの対応 type 値:
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frame と last_frame: JPEG/JPG/PNG/BMP/WEBP、1辺 240〜8000 ピクセル、アスペクト比 1:8〜8:1、最大 20MB、公開URL または data:\{MIME_type};base64,... URL。driving_audio（WAV/MP3、2〜30 秒、最大 15MB）と first_clip（MP4/MOV、2〜10 秒、1辺 240〜4096 ピクセル、最大 100MB）: 公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-r2v: first_frame（任意、最大 1）、reference_image、reference_video。reference_image または reference_video が少なくとも 1 つ必要で、reference_image と reference_video を合計して最大 5 つです。first_frame と reference_image: JPEG/JPG/PNG/BMP/WEBP（アルファチャンネルなし）、1辺 240〜8000 ピクセル、アスペクト比 1:8〜8:1、最大 20MB、公開URL または data:\{MIME_type};base64,... URL。reference_video: 公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-videoedit: video（ちょうど 1 つ。編集対象のクリップ: MP4/MOV、2〜10 秒、1辺 240〜4096 ピクセル、最大 100MB、公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません）に加えて、任意で 0〜4 個の reference_image（JPEG/JPG/PNG/BMP/WEBP、1辺 240〜8000 ピクセル、アスペクト比 1:8〜8:1、最大 20MB、公開URL または data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime: first_frame（最大 1）、last_frame（最大 1）、reference_image（最大 10）、reference_video（最大 5 クリップ、合計再生時間 \<= 15s）、reference_audio（最大 5 クリップ、合計再生時間 \<= 15s）、file（最大 1、link とは併用不可）、link（最大 1、file とは併用不可）。reference_*/file/link の type と first_frame/last_frame の type は、同じリクエスト内では同時に使用できません。配列の順序が、プロンプト内でのアセットの参照順（Image 1、Video 1、Audio 1、…）を定義します。first_frame、last_frame、reference_image: JPEG/JPG/PNG/BMP/WEBP、1辺 240〜8000 ピクセル、アスペクト比は最大 8:1、最大 20MB、公開URL または data:\{MIME_type};base64,... URL。reference_video、reference_audio、file、link: 公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v: first_frame のみ、ちょうど 1 つ。これらの綴りでは、先頭フレームを img_url ではなくここで受け取ります。少なくとも 300x300 ピクセル、アスペクト比 1:2.5〜2.5:1、JPEG/JPG/PNG/WEBP、最大 20MB、公開URL または data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v: reference_image のみ、1〜9 個。これがこのモデル唯一の参照入力です。最短辺が少なくとも 400 ピクセル、JPEG/JPG/PNG/WEBP、最大 20MB、公開URL または data:\{MIME_type};base64,... URL。reference_video はこの操作の入力タイプではありません。
- happyhorse-1.0-video-edit: video（ちょうど 1 つ。編集対象のクリップ: MP4/MOV、3〜60 秒、長辺が最大 4096 ピクセル、短辺が少なくとも 360 ピクセル、アスペクト比 1:2.5〜2.5:1、最大 100MB、公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません）に加えて、任意で 0〜5 個の reference_image（JPEG/JPG/PNG/WEBP、少なくとも 300x300 ピクセル、アスペクト比 1:2.5〜2.5:1、最大 20MB、公開URL または data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview: テキストから動画への操作です。これらのパートナーのリファレンスにはメディア入力の記載がないため、このフィールドは未設定のままにしてください。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v: このコンポーネントは、これらの綴りに対してメディアの語彙を列挙していません。wan2.5-i2v-preview と wan2.6-i2v は先頭フレームを img_url で受け取り、wan2.6-r2v は参照クリップを reference_video_urls で受け取ります。

上記のモデルごとの個数は、このスキーマの制約ではなくパートナーの制約です。許容される type とその上限がモデルごとに異なるため、media には minItems/maxItems が宣言されていません。スキーマが受け付けることは、プロバイダーが受け付けることを意味しません。逆に言えば、上記のアセットごとの「最大 20MB」という数値（画像入力に課された上限であり、インラインで送信できる唯一の入力です）は、パートナーが最終的に受け取るアセットに対する上限であり、アセットが公開URL の場合は書かれているとおりに適用されます。そのバイト列が Comfy を経由しないためです。インラインの data:\{MIME_type};base64,... URL は Comfy を経由するため、転送上限にも直面します。Comfy Router の POST ボディは合計 100 MiB に制限され、超えると 413 が返されます。また base64 はペイロードを約 4/3 に膨らませるため、およそ 75 MB を超える単一のインラインアセットは、ここに挙げたパートナーのルールに到達する前に拒否されます。そのサイズでは、単一のアセットがパートナー自身の20MB の上限はインラインでも余裕をもって収まるため、アセット 1 つの場合はパートナーのルールが制約となります。複数のアセットにまたがる場合は転送の上限が制約となります。100 MiB の Router の上限は個々の要素ではなくリクエスト全体を制限するためです。これらの上限に近いものはパブリック URL として送信してください。
</ParamField>

<ParamField body="input.media[].type" type="string" required>
  メディアアセットの種類

  指定可能な値: `first_frame`, `last_frame`, `driving_audio`, `first_clip`, `reference_image`, `reference_video`, `reference_audio`, `video`, `file`, `link`
</ParamField>

<ParamField body="input.media[].url" type="string" required>
  メディアファイルの URL。パブリックな HTTP/HTTPS URL、または、上記の `media` の説明で各モデルごとに列挙されているまさにその画像入力（wan2.7-i2v の first_frame と last_frame、wan2.7-r2v の first_frame と reference_image、wan2.7-videoedit の reference_image、wan3.0-video と wan3.0-video-prime の first_frame、last_frame、reference_image、happyhorse-1.0-i2v と happyhorse-1.1-i2v の first_frame、happyhorse-1.0-r2v と happyhorse-1.1-r2v の reference_image、happyhorse-1.0-video-edit の reference_image）の場合は、インラインの `data:{MIME_type};base64,...` URL。これらのモデルのいずれにおいても、ビデオ、オーディオ、ファイル、リンクの入力はインラインの data: URL を受け付けません。パートナー自身のアップロードサービスによる oss://dashscope-instant の一時 URL、または（wan2.7-videoedit では）Asset Center の asset_id は、それをアップロードした Alibaba Cloud アカウントに対してのみ解決されます。Comfy は自身のキーでモデル呼び出しを行い、アップロード経路を公開していないため、呼び出し元自身の oss:// URL や asset_id はサポートされる入力ではありません。このフィールドは URL スキームを検証しないため、そのような値はここで拒否されるのではなく、そのままパートナーに転送されます。モデルごとのサイズとピクセルの制限、およびインラインのペイロードを全体として制限する Router の 100 MiB リクエストボディ上限については、`media` の説明を参照してください。
</ParamField>

<ParamField body="input.negative_prompt" type="string">
  逆プロンプトの語句は、ビデオ画面に表示したくないコンテンツを記述するために使用します
</ParamField>

<ParamField body="input.prompt" type="string">
  テキストプロンプトの語句。中国語と英語に対応し、長さは 800 文字を超えないこと（wan3.0-video では最大 20,000 文字。制限を超えたコンテンツは切り捨てられます）。
複数の参照ビデオを使う wan2.6-r2v では、参照ビデオの順序に従って被写体を指すために「character1」「character2」などを使用します。例:「Character1 sings on the roadside, Character2 dances beside it」
wan3.0-video の参照モードでは、media 配列内の対応する順序でメディアアセットを指すために「Image 1」「Video 1」「Audio 1」などを使用します。
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  wan2.6-r2v モデル専用の参照ビデオ URL。1～3 本のビデオ URL の配列。
入力の制限:
- 形式: mp4、mov
- 本数: 1～3 本
- 単一ビデオの長さ: 2～30 秒
- 単一ファイルサイズ: 最大 30MB
- audio_url と併用不可
参照時間: 単一ビデオは最大 5 秒、2 本の場合は各最大 2.5 秒、3 本の場合は比例して短くなります。
課金: 実際に使用した参照時間に基づきます。
</ParamField>

<ParamField body="input.template" type="string">
  ビデオエフェクトテンプレート名。任意。現在サポートされているのは squish、flying、carousel です。使用した場合、prompt パラメータは無視されます。
</ParamField>

<ParamField body="model" type="string">
  呼び出すモデルの ID。このコンポーネントでは制約されません。Comfy Router は `POST /v2/models/wan/{model}` の `{model}` パスセグメントからこれを設定するため、Router の呼び出し元は省略します。`POST /proxy/wan/api/v1/services/aigc/video-generation/video-synthesis` への直接の v1 呼び出しでは必ず指定する必要があり、受け付けられる綴りの enum はそのオペレーション自身のコンポーネント `WanVideoGenerationRequest` にあります。
</ParamField>

<ParamField body="parameters" type="object">
  ビデオ処理パラメータ
</ParamField>

<ParamField body="parameters.audio" type="boolean" default="true">
  ビデオにオーディオを追加するかどうか。wan3.0-video と wan3.0-video-prime のみでサポートされます。他の wan モデルでは、プロバイダーはそのような切り替えを記載していません。
</ParamField>

<ParamField body="parameters.audio_setting" type="string" default="&quot;auto&quot;">
  wan2.7-videoedit モデルのビデオオーディオ設定。
- auto（デフォルト）: モデルがプロンプトの内容に基づいてインテリジェントに判断します
- origin: 入力ビデオのオリジナルオーディオを強制的に保持します

  指定可能な値: `auto`, `origin`
</ParamField>

<ParamField body="parameters.duration" type="integer" default="5">
  生成されるビデオの再生時間（秒）:
- wan2.5 モデル: 5 秒または 10 秒
- wan2.6-t2v、wan2.6-i2v: 5、10、15 秒
- wan2.6-r2v: 5 秒または 10 秒のみ（15 秒は非サポート）
- wan2.7-i2v、wan2.7-t2v: [2, 15] の整数
- wan2.7-r2v、wan2.7-videoedit: [2, 10] の整数
- wan3.0-video: ビデオ入力なしの場合は [2, 30] の整数。ビデオ入力ありの場合は入力ビデオの再生時間 + 出力ビデオの再生時間の合計が 30 秒を超えてはなりません。-1 はモデルが適切な再生時間を選ぶスマート再生時間モードを有効にします
このプロキシは [-1, 30] の範囲外の再生時間に対して 400 を返します。

  範囲: `-1` ～ `30`
</ParamField>

<ParamField body="parameters.prompt_extend" type="boolean" default="true">
  プロンプトのインテリジェントな書き換えを有効にするかどうか。デフォルトは true
</ParamField>

<ParamField body="parameters.ratio" type="string">
  生成されるビデオのアスペクト比。wan2.7 および wan3.0 モデル専用です。
wan2.7 モデルでは、指定しない場合は解像度ティアに基づいてデフォルトが決まります。
wan3.0-video では、adaptive（デフォルト）が入力メディアの比率と意図に基づいて適切なアスペクト比を自動的に推奨します。

  指定可能な値: `adaptive`, `16:9`, `9:16`, `1:1`, `4:3`, `3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  解像度レベル。サポートされる値はモデルによって異なります:
- wan2.5-i2v-preview: 480P、720P、1080P
- wan2.6 モデル（t2v、i2v、r2v）: 720P、1080P のみ（480P 非サポート）
- wan2.7 モデル（i2v、t2v、r2v、videoedit）: 720P、1080P（デフォルト 1080P）
</ParamField>- wan3.0-video、wan3.0-video-prime: 480P、720P、1080P（アップストリームのデフォルトは 1080P）
- happyhorse-1.0-*（t2v、i2v、r2v、video-edit）: 720P、1080P
- happyhorse-1.1-*（t2v、i2v、r2v）: 480P、720P、1080P
このプロキシは、解像度もサイズも指定されていないビデオ生成リクエストを拒否します。解像度の階層が課金レートを決定するためです。チェックの前に解像度を大文字に変換し、大文字化した値を転送します。この列挙型に含まれない値には 400 を返し、上記で 480P がないと記載されている wan2.6、wan2.7、happyhorse-1.0 モデルでは、480P（解像度として送信された場合も、480P のサイズとして送信された場合も）に対して 400 を返します。

  指定可能な値: `480P`, `720P`, `1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">

  範囲: `0` から `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  インテリジェントなマルチレンズ制御。prompt_extend が有効な場合にのみ動作します。wan2.6 および wan2.7-r2v モデル用です。
- single: シングルショットビデオ（デフォルト）
- multi: マルチショットビデオ

  指定可能な値: `multi`, `single`
</ParamField>

<ParamField body="parameters.size" type="string">
  ビデオの解像度を 幅*高さ の形式で指定します。サポートされる解像度はモデルによって異なります:
wan2.5 T2V の場合: 480P（480*832、832*480、624*624）、720P、1080P の各サイズ
wan2.6 T2V/R2V の場合（480P なし）:
  720P: 1280*720, 720*1280, 960*960, 1088*832, 832*1088
  1080P: 1920*1080, 1080*1920, 1440*1440, 1632*1248, 1248*1632
サイズと解像度の両方を送信した場合、課金される階層を選択するのはサイズであり、解像度は依然としてそのモデルに対してこのプロキシが受け付ける値である必要があります。480P のサイズは、解像度の説明で 480P がないと記載されているすべてのモデルで 400 を返します。
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">

## 使用例

### 入力

```json
{
  "input": {
    "prompt": "character1 walks in from the left, turns to the camera and waves, plain orange backdrop",
    "reference_video_urls": [
      "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/street_dancer.mp4"
    ]
  },
  "parameters": {
    "resolution": "720P",
    "duration": 5
  }
}
```

```json
{
  "output": {
    "task_id": "0385dc79-5ff8-4d82-bcb6-7c1a9f2e4d60",
```
