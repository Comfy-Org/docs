Wan 2.6 R2V の API リファレンス。Wan 2.6 の参照から動画は、1～3 本の参照ビデオの被写体を新しいシーンへ持ち込みます。プロンプト内では character1、character2 などのように指定します。

**入力：** 画像, ビデオ, テキスト · **出力：** ビデオ + オーディオ

## クイックスタート

[お使いの Comfy ワークスペース](https://platform.comfy.org/profile/api-keys?onboarding=router)でキーを作成し、`COMFY_API_KEY` としてエクスポートします。Python と TypeScript のスニペットは Comfy SDK（`pip install comfy-sdk` および `npm install @comfyorg/sdk`）を使用しています。cURL のスニペットは同じ呼び出しを raw HTTP で行うものです。

**モデル ID:** `wan/wan2.6-r2v`

**エンドポイント:** `POST https://api.comfy.org/v2/models/wan/wan2.6-r2v`

同じボディを `POST https://api.comfy.org/v2/models/wan/wan2.6-r2v/requests` に送信します。Router は実行が受け付けられるとすぐに `201` と `request_id` を返し、結果は準備ができ次第、このプロセスまたは別のプロセスから収集されます。[キュー配信](/ja/development/comfy-router/queue)では、ステータス、キャンセル、収集について説明します。

```python Python
import asyncio
from comfy_sdk import AsyncComfy

# COMFY_API_KEY を環境変数から読み取ります。
# 各 submit() 呼び出しは独自の Idempotency-Key を発行し、自動リトライで再利用します。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/wan2.6-r2v",
            {
                "input": {
                    "prompt": "character1 walks in from the left, turns to the camera and waves, plain orange backdrop",
                    "reference_video_urls": ["https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/street_dancer.mp4"],
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # モデル ID と合わせて、別のプロセスに必要な情報はこれだけです

        # リクエストが完了するまでポーリングし、サーバーが指定する Retry-After だけ待機します。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # プロバイダー自身のペイロードで、models.run() が返す値と同じです。
        # 失敗またはキャンセルされたリクエストは、ここで型付き Router エラーを発生させます。
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())
```

import { comfy } from "@comfyorg/sdk";

// COMFY_API_KEY を環境変数から読み取ります。
// 各 submit() 呼び出しは独自の Idempotency-Key を発行し、自動リトライで再利用します。
type Result = { output: { video_url: string } };
const handle = await comfy.models.submit<Result>("wan/wan2.6-r2v", {
  input: {
    prompt: "character1 walks in from the left, turns to the camera and waves, plain orange backdrop",
    reference_video_urls: ["https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/street_dancer.mp4"],
  },
  parameters: {
    resolution: "720P",
    duration: 5,
  },
});
console.log("requestId:", handle.requestId); // モデル ID と合わせて、別のプロセスに必要な情報はこれだけです

// リクエストが完了するまでポーリングし、サーバーが指定する Retry-After だけ待機します。
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// models.run() が返すのと同じ結果です。失敗またはキャンセルされたリクエストはここで reject されます。
const result = await handle.get();
if (result.kind !== "json") throw new Error("expected a JSON result");

## スキーマ

### 入力

<ParamField body="input" type="object" required>
  プロンプトなどの基本情報を入力します。
</ParamField>

<ParamField body="input.audio_url" type="string">
  オーディオファイルのダウンロードURL。対応形式はmp3とwavです。reference_video_urlsとは併用できません。
</ParamField>

<ParamField body="input.img_url" type="string">
  先頭フレームの画像URL、またはBase64エンコードされたデータ。wan2.5-i2v-previewモデルと
wan2.6-i2vモデルでは必須です。happyhorse-1.xのi2v系の表記はここで先頭フレームを受け取りません。
先頭フレームはtypeがfirst_frameのメディア要素として受け取ります（下記のmediaを参照）。
また、wan2.6-i2vで成功するimg_urlのボディは、happyhorse-1.0-i2vとhappyhorse-1.1-i2vでは
プロバイダーに拒否されます。さらにwan2.7/wan3.0系の表記も参照アセットをmediaで受け取ります。
画像形式：JPEG、JPG、PNG、BMP、WEBP。
解像度：360-2000ピクセル。ファイルサイズ：最大10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。動画生成に使用する参照素材（画像、オーディオ、ビデオ）を指定します。
各要素はtypeフィールドとurlフィールドを持ちます。このフィールドはこのコンポーネントから提供される
すべてのモデルで共通ですが、どのtype値が受け入れられるか、また画像やビデオの入力を
img_urlやreference_video_urlsではなくここで渡すかどうかはモデルによって異なります。
モデルごとの対応type値は次のとおりです。
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frameと
  last_frame：JPEG/JPG/PNG/BMP/WEBP、1辺240-8000ピクセル、アスペクト比率1:8から
  8:1の間、最大20MB、パブリックURLまたはdata:\{MIME_type};base64,... URL。
  driving_audio（WAV/MP3、2-30秒、最大15MB）とfirst_clip（MP4/MOV、2-10
  秒、1辺240-4096ピクセル、最大100MB）：パブリックなHTTP/HTTPS URL。インラインの
  data: URLは受け付けられません。
- wan2.7-r2v: first_frame（任意、最大1）、reference_image、reference_video。少なくとも
  reference_imageまたはreference_videoが1つ必要で、reference_imageと
  reference_videoの合計は最大5つです。first_frameとreference_image：JPEG/JPG/PNG/BMP/WEBP
  （アルファチャンネルなし）、1辺240-8000ピクセル、アスペクト比率1:8から8:1の間、最大
  20MB、パブリックURLまたはdata:\{MIME_type};base64,... URL。reference_video：パブリックな
  HTTP/HTTPS URL。インラインのdata: URLは受け付けられません。
- wan2.7-videoedit: video（ちょうど1つ。編集対象のクリップ：MP4/MOV、2-10秒、
  1辺240-4096ピクセル、最大100MB、パブリックなHTTP/HTTPS URL。インラインのdata: URL
  は受け付けられません）に加えて、任意で0から4つのreference_image（JPEG/JPG/PNG/BMP/WEBP、
  1辺240-8000ピクセル、アスペクト比率1:8から8:1の間、最大20MB、パブリックURL
  またはdata:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime: first_frame（最大1）、last_frame（最大1）、
  reference_image（最大10）、reference_video（最大5クリップ、合計再生時間\<=15秒）、
  reference_audio（最大5クリップ、合計再生時間\<=15秒）、file（最大1、linkとは併用不可）、
  link（最大1、fileとは併用不可）。reference_*/file/linkタイプと
  first_frame/last_frameタイプは同じリクエスト内で同時に使用できません。
  配列の順序がプロンプト内でのアセットの参照順序を定義します（Image 1、Video 1、
  Audio 1、...）。first_frame、last_frame、reference_image：JPEG/JPG/PNG/BMP/WEBP、
  1辺240-8000ピクセル、アスペクト比率最大8:1、最大20MB、パブリックURLまたは
  data:\{MIME_type};base64,... URL。reference_video、reference_audio、file、link：パブリックな
  HTTP/HTTPS URL。インラインのdata: URLは受け付けられません。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v: first_frameのみ、ちょうど1つ。これらの表記は
  先頭フレームをここで受け取り、img_urlでは受け取りません。最小300x300ピクセル、アスペクト比率
  1:2.5から2.5:1の間、JPEG/JPG/PNG/WEBP、最大20MB、パブリックURLまたは
  data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v: reference_imageのみ、1から9つ。これは
  このモデル唯一の参照入力です。短辺が最小400ピクセル、JPEG/JPG/PNG/WEBP、
  最大20MB、パブリックURLまたはdata:\{MIME_type};base64,... URL。この操作ではreference_videoは
  入力タイプではありません。
- happyhorse-1.0-video-edit: video（ちょうど1つ。編集対象のクリップ：MP4/MOV、3-60
  秒、長辺が最大4096ピクセル、短辺が最小360ピクセル、アスペクト
  比率1:2.5から2.5:1の間、最大100MB、パブリックなHTTP/HTTPS URL。インラインのdata:
  URLは受け付けられません）に加えて、任意で0から5つのreference_image（JPEG/JPG/PNG/WEBP、
  最小300x300ピクセル、アスペクト比率1:2.5から2.5:1の間、最大20MB、パブリックURL
  またはdata:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview:
  テキストから動画への操作。これらの対応するリファレンスにはメディア入力の記載がないため、
  このフィールドは未設定のままにしてください。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v: このコンポーネントはこれらの表記に対して
  メディアの語彙を定義していません。wan2.5-i2v-previewとwan2.6-i2vは先頭
  フレームをimg_urlで受け取り、wan2.6-r2vは参照クリップをreference_video_urlsで受け取ります。
上記のモデルごとの個数はパートナーの制約であり、このスキーマの制約ではありません。mediaには
minItems/maxItemsが宣言されていません。許容されるtypeとその上限はモデルごとに異なるためです。
スキーマが受け付けることはプロバイダーが受け付けることを意味しません。また逆に、上記の
アセットごとの「最大20MB」という値（画像入力の上限であり、インラインで送信できる唯一の入力）
は、パートナーが最終的に受け取るアセットに対するパートナーの上限であり、アセットがパブリック
URLである場合はそのまま適用されます。そのバイト列はComfyを経由しないためです。インラインの
data:\{MIME_type};base64,... URLはComfyを経由するため、転送上の上限にも直面します。Comfy Router
のPOSTボディは合計100 MiBに制限され、超えると413が返されます。またbase64はペイロードを
約4/3に膨らませるため、およそ75 MBを超える単一のインラインアセットは、ここに記載された
パートナーのルールに到達する前に拒否されます。そのサイズでは、単一のアセットはパートナー自身の20MB の上限はインラインで問題なく収まるため、1 つのアセットについてはパートナーのルールが制約となります。複数のアセットにまたがる場合は転送の上限が制約となります。これは、100 MiB の Router の上限が各要素ではなくリクエスト全体を制限するためです。これらの上限に近いものは、パブリック URL として送信してください。
</ParamField>

<ParamField body="input.media[].type" type="string" required>
  メディアアセットの種類

  指定可能な値: `first_frame`、`last_frame`、`driving_audio`、`first_clip`、`reference_image`、`reference_video`、`reference_audio`、`video`、`file`、`link`
</ParamField>

<ParamField body="input.media[].url" type="string" required>
  メディアファイルの URL: パブリックな HTTP/HTTPS URL、または、上記の `media` の説明でモデルごとに列挙されている画像入力に限り、インラインの `data:{MIME_type};base64,...` URL です。対象となる画像入力は、wan2.7-i2v の first_frame と last_frame、wan2.7-r2v の first_frame と reference_image、wan2.7-videoedit の reference_image、wan3.0-video と wan3.0-video-prime の first_frame、last_frame、reference_image、happyhorse-1.0-i2v と happyhorse-1.1-i2v の first_frame、happyhorse-1.0-r2v と happyhorse-1.1-r2v の reference_image、happyhorse-1.0-video-edit の reference_image です。これらのモデルのいずれにおいても、ビデオ、オーディオ、ファイル、リンクの入力はインラインの data: URL を受け付けません。パートナー自身のアップロードサービスが発行する oss://dashscope-instant の一時 URL、または（wan2.7-videoedit では）Asset Center の asset_id は、それをアップロードした Alibaba Cloud アカウントに対してのみ解決されます。Comfy は自身のキーでモデルを呼び出し、アップロード用のルートを公開していないため、呼び出し元自身の oss:// URL や asset_id はサポートされる入力ではありません。このフィールドは URL スキームを検証しないため、そのような値はここで拒否されることなく、そのままパートナーに転送されます。モデルごとのサイズとピクセルの上限、およびインラインペイロードを全体として制限する 100 MiB の Router リクエストボディの上限については、`media` の説明を参照してください。
</ParamField>

<ParamField body="input.negative_prompt" type="string">
  ネガティブプロンプトの語句は、動画内に表示したくないコンテンツを記述するために使用します。500 文字を超えると、wan モデルはそれを拒否せずに切り捨てます。これは prompt と同じ入力予算に算入されます。
</ParamField>

<ParamField body="input.prompt" type="string">
  テキストプロンプトの語句。中国語と英語をサポートします。文書化されたそれぞれの長さを超えると、wan2.x モデルはプロンプトを拒否せずに切り捨てます。wan2.5 と wan2.6 では 1,500 文字、wan2.7 では 5,000 文字です。wan3.0-video と wan3.0-video-prime は最大 20,000 文字を受け付けます。prompt と negative_prompt を合わせて約 60,850 バイトの UTF-8 テキスト（約 20,000 文字の中国語）を超えるリクエストは、プロバイダーが拒否し、InvalidParameter `Range of input length should be [1, 61440]` を返します。
wan2.6-r2v で複数の参照ビデオを使用する場合は、参照ビデオの順序に従って被写体を 'character1'、'character2' などで参照します。例: "Character1 sings on the roadside, Character2 dances beside it"
wan3.0-video の参照モードでは、media 配列内の対応する順序でメディアアセットを参照するために 'Image 1'、'Video 1'、'Audio 1' などを使用します。
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  wan2.6-r2v モデル専用の参照ビデオ URL。1〜3 本のビデオ URL の配列。
入力の制限:
- 形式: mp4, mov
- 本数: ビデオ 1〜3 本
- 1 本あたりのビデオの長さ: 2〜30 秒
- 1 ファイルあたりのファイルサイズ: 最大 30MB
- audio_url と併用できません
参照の再生時間: ビデオ 1 本で最大 5 秒、2 本で各最大 2.5 秒、3 本では比例して短くなります。
課金: 実際に使用した参照の再生時間に基づきます。
</ParamField>

<ParamField body="input.template" type="string">
  ビデオエフェクトのテンプレート名。任意。現在サポートされているのは squish、flying、carousel です。使用すると、prompt パラメータは無視されます。
</ParamField>

<ParamField body="model" type="string">
  呼び出すモデルの ID。このコンポーネントでは制約されません。Comfy Router は `POST /v2/models/wan/{model}` の `{model}` パスセグメントからこれを設定するため、Router の呼び出し元は省略します。`POST /proxy/wan/api/v1/services/aigc/video-generation/video-synthesis` への直接の v1 呼び出しでは必ず指定する必要があり、受け付けられる表記の列挙はそのオペレーション自身のコンポーネント `WanVideoGenerationRequest` にあります。
</ParamField>

<ParamField body="parameters" type="object">
  ビデオ処理パラメータ
</ParamField>

<ParamField body="parameters.audio" type="boolean" default="true">
  ビデオにオーディオを追加するかどうか。wan3.0-video と wan3.0-video-prime でのみサポートされます。他の wan モデルについては、プロバイダーはそのような切り替えを文書化していません。
</ParamField>

<ParamField body="parameters.audio_setting" type="string" default="&quot;auto&quot;">
  wan2.7-videoedit モデルのビデオオーディオ設定。
- auto（デフォルト）: モデルがプロンプトのコンテンツに基づいてインテリジェントに判断します
- origin: 入力ビデオのオリジナルオーディオを強制的に保持します

  指定可能な値: `auto`、`origin`
</ParamField>

<ParamField body="parameters.duration" type="integer" default="5">
  生成されるビデオの再生時間（秒）:
- wan2.5 モデル: 5 秒または 10 秒
- wan2.6-t2v、wan2.6-i2v: 5 秒、10 秒、または 15 秒
- wan2.6-r2v: 5 秒または 10 秒のみ（15 秒は非サポート）
- wan2.7-i2v、wan2.7-t2v: [2, 15] の整数
- wan2.7-r2v、wan2.7-videoedit: [2, 10] の整数
- wan3.0-video: ビデオ入力なしの場合は [2, 30] の整数。ビデオ入力ありの場合は、入力ビデオの再生時間 + 出力ビデオの再生時間の合計が 30 秒を超えてはなりません。-1 を指定すると、モデルが適切な再生時間を選択するスマート再生時間モードになります。
このプロキシは、[-1, 30] の範囲外の再生時間に対して 400 を返します。

  範囲: `-1` から `30`
</ParamField>

<ParamField body="parameters.prompt_extend" type="boolean" default="true">
  プロンプトのインテリジェントな書き換えを有効にするかどうか。デフォルトは true です。
</ParamField>

<ParamField body="parameters.ratio" type="string">
  生成されるビデオのアスペクト比。wan2.7 と wan3.0 モデル専用です。
wan2.7 モデルでは、指定しない場合、解像度の階層に基づいてデフォルトが決まります。
wan3.0-video では、adaptive（デフォルト）が適切な入力メディアの比率と意図に基づくアスペクト比。

  指定可能な値: `adaptive`, `16:9`, `9:16`, `1:1`, `4:3`, `3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  解像度レベル。サポートされる値はモデルによって異なります:
- wan2.5-i2v-preview: 480P, 720P, 1080P
- wan2.6 モデル (t2v, i2v, r2v): 720P, 1080P のみ (480P はサポートなし)
- wan2.7 モデル (i2v, t2v, r2v, videoedit): 720P, 1080P (デフォルト 1080P)
- wan3.0-video, wan3.0-video-prime: 480P, 720P, 1080P (上流のデフォルト 1080P)
- happyhorse-1.0-* (t2v, i2v, r2v, video-edit): 720P, 1080P
- happyhorse-1.1-* (t2v, i2v, r2v): 480P, 720P, 1080P
このプロキシは、resolution も size も指定されていないビデオ生成リクエストを拒否します。解像度の階層が課金レートを決定するためです。チェックの前に resolution を大文字化し、大文字化した値を転送します。この enum に含まれない値には 400 を返し、上記で 480P 非対応として挙げた wan2.6、wan2.7、happyhorse-1.0 のモデルでは 480P (resolution として送信された場合も、480P の size として送信された場合も) に対して 400 を返します。

  指定可能な値: `480P`, `720P`, `1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  乱数シード。モデルが生成するコンテンツのランダム性を制御するために使用します。

  範囲: `0` から `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  インテリジェントなマルチレンズ制御。prompt_extend が有効な場合にのみ機能します。
wan2.6 および wan2.7-r2v モデル用です。
- single: 単一ショットのビデオ (デフォルト)
- multi: マルチショットのビデオ

  指定可能な値: `multi`, `single`
</ParamField>

<ParamField body="parameters.size" type="string">
  幅*高さ形式で指定するビデオ解像度。サポートされる解像度はモデルによって異なります:
wan2.5 T2V の場合: 480P (480*832, 832*480, 624*624), 720P, 1080P の各サイズ
wan2.6 T2V/R2V の場合 (480P なし):
  720P: 1280*720, 720*1280, 960*960, 1088*832, 832*1088
  1080P: 1920*1080, 1080*1920, 1440*1440, 1632*1248, 1248*1632
size と resolution の両方が送信された場合、課金階層を選択するのは size であり、resolution はそのモデルに対してこのプロキシが受け付ける値である必要があります。480P の size は、解像度の説明で 480P 非対応として挙げられているすべてのモデルで 400 を返します。
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  ウォーターマークロゴを追加するかどうか。ウォーターマークは右下隅に配置されます。
</ParamField>

  "input": {

    "duration": 5
  }
