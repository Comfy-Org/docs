Wan 3.0 Video の API リファレンスです。Wan 3.0 Video は、プロンプトのみから、または最初と最後のフレーム、参照画像、ビデオ、オーディオを含むメディアリストから生成します。これらはプロンプト内で Image 1、Video 1、Audio 1 として参照します。

**入力：** テキスト, 画像, ビデオ, オーディオ · **出力：** ビデオ + オーディオ

## サービングプロバイダー

このモデルは、リクエストで別のプロバイダーを指定しない限り、Comfy Router が直接サービングします。以下のプロバイダーも、同じエンドポイントで同じモデル ID を使用してこのモデルをサービングしており、`model_provider` クエリパラメータで選択します。

- **Comfy** (デフォルト): `POST https://api.comfy.org/v2/models/wan/wan3.0-video`
- **Higgsfield**、`higgsfield/higgsfield-wan-3` として: `POST https://api.comfy.org/v2/models/wan/wan3.0-video?model_provider=higgsfield`

`strict_mode` のデフォルトは false であるため、Router はこのページに記載されているネイティブのリクエストボディをプロバイダー独自のスキーマに変換し、レスポンスを元の形式に戻します。API リファレンスの [`model_provider`、`strict_mode`、`fallback_provider`](/ja/development/comfy-router/reference#post-v2modelsprovidermodel) を参照し、この方法でルーティングされるすべてのモデルについては[サービングプロバイダー](/ja/development/comfy-router/providers)を参照してください。

</ParamField>

<ParamField body="input.img_url" type="string">
  先頭フレーム画像のURL、または Base64 エンコードされたデータ。wan2.5-i2v-preview および
wan2.6-i2v モデルでは必須です。happyhorse-1.x の i2v 表記は、先頭フレームをここでは
受け取りません。type が first_frame の media 要素として受け取ります（後述の media を参照）。
また、wan2.6-i2v では成功する img_url のボディも、happyhorse-1.0-i2v および
happyhorse-1.1-i2v ではプロバイダーに拒否されます。さらに wan2.7/wan3.0 の表記も
参照アセットを media で受け取ります。画像形式: JPEG、JPG、PNG、BMP、WEBP。
解像度: 360～2000 ピクセル。ファイルサイズ: 最大 10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。ビデオ生成用の参照素材（画像、オーディオ、ビデオ）を指定します。
各要素には type と url フィールドが含まれます。このフィールドは、このコンポーネントから提供される
すべてのモデルで共有されており、どのモデルがどの type 値を受け入れるか、またその画像や
ビデオ入力を img_url や reference_video_urls ではなくそもそもここで渡すかどうかは、
モデルによって異なります。モデルごとの対応 type 値:
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frame と
  last_frame: JPEG/JPG/PNG/BMP/WEBP、各辺 240～8000 ピクセル、アスペクト比 1:8
  から 8:1 の間、最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。
  driving_audio（WAV/MP3、2～30 秒、最大 15MB）と first_clip（MP4/MOV、2～10
  秒、各辺 240～4096 ピクセル、最大 100MB）: 公開 HTTP/HTTPS URL。インラインの
  data: URL は受け付けられません。
- wan2.7-r2v: first_frame（任意、最大 1）、reference_image、reference_video。少なくとも
  1 つの reference_image または reference_video が必要で、reference_image と
  reference_video の合計は最大 5 つです。first_frame と reference_image: JPEG/JPG/PNG/BMP/WEBP
  （アルファチャンネルなし）、各辺 240～8000 ピクセル、アスペクト比 1:8 から 8:1 の間、最大
  20MB、公開 URL または data:\{MIME_type};base64,... URL。reference_video: 公開
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-videoedit: video（正確に 1 つ、編集対象のクリップ: MP4/MOV、2～10 秒、
  各辺 240～4096 ピクセル、最大 100MB、公開 HTTP/HTTPS URL。インラインの data: URL
  は受け付けられません）に加えて、任意で 0～4 個の reference_image（JPEG/JPG/PNG/BMP/WEBP、
  各辺 240～8000 ピクセル、アスペクト比 1:8 から 8:1 の間、最大 20MB、公開 URL
  または data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime: first_frame（最大 1）、last_frame（最大 1）、
  reference_image（最大 10）、reference_video（最大 5 クリップ、合計再生時間 \<= 15s）、
  reference_audio（最大 5 クリップ、合計再生時間 \<= 15s）、file（最大 1、link とは
  併用不可）、link（最大 1、file とは併用不可）。reference_*/file/link タイプ
  と first_frame/last_frame タイプは、同一リクエスト内で相互に排他的です。
  配列の順序がプロンプト内のアセットの参照順序を定義します（Image 1、Video 1、
  Audio 1、...）。first_frame、last_frame、reference_image: JPEG/JPG/PNG/BMP/WEBP、
  各辺 240～8000 ピクセル、アスペクト比は最大 8:1、最大 20MB、公開 URL または
  data:\{MIME_type};base64,... URL。reference_video、reference_audio、file、link: 公開
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v: first_frame のみ、正確に 1 つ。これらの表記は
  先頭フレームをここで受け取り、img_url では受け取りません。少なくとも 300x300 ピクセル、アスペクト比
  1:2.5 から 2.5:1 の間、JPEG/JPG/PNG/WEBP、最大 20MB、公開 URL または
  data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v: reference_image のみ、1～9 個。これが
  このモデルの唯一の参照入力です。最短辺が少なくとも 400 ピクセル、JPEG/JPG/PNG/WEBP、
  最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。reference_video は
  この操作の入力タイプではありません。
- happyhorse-1.0-video-edit: video（正確に 1 つ、編集対象のクリップ: MP4/MOV、3～60
  秒、長辺が最大 4096 ピクセル、短辺が少なくとも 360 ピクセル、アスペクト
  比 1:2.5 から 2.5:1 の間、最大 100MB、公開 HTTP/HTTPS URL。インラインの data:
  URL は受け付けられません）に加えて、任意で 0～5 個の reference_image（JPEG/JPG/PNG/WEBP、
  少なくとも 300x300 ピクセル、アスペクト比 1:2.5 から 2.5:1 の間、最大 20MB、公開 URL
  または data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview:
  テキストから動画への操作。これらのパートナー参照にはメディア入力の記載がないため、この
  フィールドは未設定のままにしてください。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v: このコンポーネントは、これらの表記に対する
  メディアの語彙を列挙していません。wan2.5-i2v-preview と wan2.6-i2v は先頭
  フレームを img_url で受け取り、wan2.6-r2v は参照クリップを reference_video_urls で受け取ります。
上記のモデルごとの個数はパートナーの制約であり、このスキーマの制約ではありません。media には
minItems/maxItems が宣言されていません。許容されるタイプとその上限がモデルごとに
異なるためです。スキーマが受け入れても、プロバイダーが受け入れるとは限りません。また逆に、
上記のアセットごとの「最大 20MB」という数値（画像入力に対する上限であり、インラインで
送信できる唯一の入力です）は、パートナーが最終的に受け取るアセットに対する上限であり、
アセットが公開 URL である場合には記載どおりに適用されます。そのバイト列は Comfy を
経由しないためです。インラインの data:\{MIME_type};base64,...
URL は Comfy を経由するため、転送の上限にも直面します。Comfy Router
の POST ボディは合計 100 MiB に制限され、それを超えると 413 が返されます。また base64 は
ペイロードを約 4/3 に膨らませるため、おおよそ 75 MB を超える単一のインラインアセットは、
ここにあるパートナーのルールに到達する前に拒否されます。そのサイズでは、単一のアセットが
パートナー自身の20MB の上限であればインラインで問題なく収まるため、1 つのアセットについてはパートナーのルールが制約となります。
複数のアセットにまたがる場合は転送の上限が制約となります。100 MiB の Router 上限は個々の要素ではなく
リクエスト全体を制限するためです。これらの上限に近いものは公開 URL として送信してください。
</ParamField>

<ParamField body="input.media[].url" type="string" required>
  メディアファイルの URL: 公開 HTTP/HTTPS URL、または上記の `media` の説明でモデルごとに挙げられている画像入力（wan2.7-i2v の first_frame と last_frame、wan2.7-r2v の first_frame と reference_image、wan2.7-videoedit の reference_image、wan3.0-video と wan3.0-video-prime の first_frame、last_frame、reference_image、happyhorse-1.0-i2v と happyhorse-1.1-i2v の first_frame、happyhorse-1.0-r2v と happyhorse-1.1-r2v の reference_image、happyhorse-1.0-video-edit の reference_image）に限り、インラインの `data:{MIME_type};base64,...` URL です。これらのモデルのいずれにおいても、ビデオ、オーディオ、ファイル、リンクの入力がインラインの data: URL を受け付けることはありません。パートナー自身のアップロードサービスによる oss://dashscope-instant の一時 URL、または（wan2.7-videoedit では）Asset Center の asset_id は、それをアップロードした Alibaba Cloud アカウントに対してのみ解決されます。Comfy は自身のキーでモデル呼び出しを行い、アップロード経路を公開していないため、呼び出し元自身の oss:// URL や asset_id はサポートされる入力ではありません。このフィールドは URL スキームを検証しないため、そのような値はここで拒否されず、そのままパートナーへ転送されます。モデルごとのサイズとピクセルの上限、およびインラインペイロードを全体として制限する 100 MiB の Router リクエストボディ上限については、`media` の説明を参照してください。

<ParamField body="input.prompt" type="string">
  テキストプロンプト。中国語と英語に対応し、長さは 800 文字以内です
（wan3.0-video では最大 20,000 文字。制限を超えたコンテンツは切り捨てられます）。
複数の参照ビデオを使用する wan2.6-r2v では、'character1'、'character2' などを使って、参照ビデオの順に
被写体を参照します。例:「Character1 が道端で歌い、Character2 がその横で踊る」
wan3.0-video の参照モードでは、'Image 1'、'Video 1'、'Audio 1' などを使って、media 配列内の
対応する順序のメディアアセットを参照します。
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  wan2.6-r2v モデル専用の参照ビデオ URL。1～3 本のビデオ URL の配列。
入力の制限:
- 形式: mp4、mov
- 数量: 1～3 本のビデオ
- 単一ビデオの長さ: 2～30 秒
- 単一ファイルサイズ: 最大 30MB
- audio_url と併用できません
参照の再生時間: 単一ビデオは最大 5 秒、2 本のビデオはそれぞれ最大 2.5 秒、3 本のビデオは比例してさらに短くなります。
課金: 実際に使用した参照の再生時間に基づきます。
</ParamField>

<ParamField body="input.template" type="string">
  ビデオエフェクトのテンプレート名。任意。現在サポートされているのは、squish、flying、carousel です。使用した場合、prompt パラメータは無視されます。
</ParamField>

<ParamField body="model" type="string">
  呼び出すモデルの ID。このコンポーネントでは制約されません: Comfy Router が `POST /v2/models/wan/{model}` の `{model}` パスセグメントから設定するため、Router の呼び出し元は省略します。`POST /proxy/wan/api/v1/services/aigc/video-generation/video-synthesis` への直接の v1 呼び出しでは必ず指定する必要があり、受け付けられる表記の列挙はそのオペレーション自身のコンポーネント `WanVideoGenerationRequest` にあります。
</ParamField>

<ParamField body="parameters.audio" type="boolean" default="true">

</ParamField>

<ParamField body="parameters.audio_setting" type="string" default="&quot;auto&quot;">

- auto（デフォルト）: モデルがプロンプトの内容に基づいてインテリジェントに判断します
- origin: 入力ビデオのオリジナルオーディオを強制的に保持します

  指定可能な値: `auto`, `origin`
</ParamField>

<ParamField body="parameters.duration" type="integer" default="5">
  生成されるビデオの再生時間（秒）:
- wan2.5 モデル: 5 秒または 10 秒
- wan2.6-t2v、wan2.6-i2v: 5 秒、10 秒、または 15 秒
- wan2.6-r2v: 5 秒または 10 秒のみ（15 秒は非サポート）
- wan2.7-i2v、wan2.7-t2v: [2, 15] の整数
- wan2.7-r2v、wan2.7-videoedit: [2, 10] の整数
- wan3.0-video: ビデオ入力なしの場合は [2, 30] の整数。ビデオ入力ありの場合は、入力ビデオの

  範囲: `-1` ～ `30`
</ParamField>

<ParamField body="parameters.ratio" type="string">

wan3.0-video では、adaptive（デフォルト）が入力メディアの比率と意図に基づいて
適切なアスペクト比を自動的に推奨します。

  指定可能な値: `adaptive`, `16:9`, `9:16`, `1:1`, `4:3`, `3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  解像度レベル。サポートされる値はモデルによって異なります:
- wan2.5-i2v-preview: 480P、720P、1080P
- wan2.6-i2v: 720P、1080P のみ（480P は非サポート）
- wan2.7 モデル（i2v、t2v、r2v、videoedit）: 720P、1080P（デフォルト 1080P）
- wan3.0-video、wan3.0-video-prime: 480P、720P、1080P（上流のデフォルト 1080P）
このプロキシは、解像度とサイズのどちらも指定しないビデオ生成リクエストを拒否します。解像度のティアによって課金レートが決まるためです。

  指定可能な値: `480P`、`720P`、`1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">

</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">

wan2.6 および wan2.7-r2v モデル用。
- single: シングルショットビデオ（デフォルト）
- multi: マルチショットビデオ

  指定可能な値: `multi`、`single`
</ParamField>

<ParamField body="parameters.size" type="string">

wan2.5 T2V の場合: 480P（480*832、832*480、624*624）、720P、1080P サイズ
wan2.6 T2V/R2V の場合（480P なし）:
  720P: 1280*720、720*1280、960*960、1088*832、832*1088
  1080P: 1920*1080、1080*1920、1440*1440、1632*1248、1248*1632
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
