Wan 3.0 Video の API リファレンスです。Wan 3.0 Video は、プロンプトのみから、または最初と最後のフレーム、参照画像、ビデオ、オーディオを含むメディアリストから生成します。これらはプロンプト内で Image 1、Video 1、Audio 1 として参照します。

**入力：** テキスト, 画像, ビデオ, オーディオ · **出力：** ビデオ + オーディオ

## サービングプロバイダー

このモデルは、リクエストで別のプロバイダーを指定しない限り、Comfy Router が直接サービングします。以下のプロバイダーも、同じエンドポイントで同じモデル ID を使用してこのモデルをサービングしており、`model_provider` クエリパラメータで選択します。

- **Comfy** (デフォルト): `POST https://api.comfy.org/v2/models/wan/wan3.0-video`
- **Higgsfield**、`higgsfield/higgsfield-wan-3` として: `POST https://api.comfy.org/v2/models/wan/wan3.0-video?model_provider=higgsfield`

`strict_mode` のデフォルトは false であるため、Router はこのページに記載されているネイティブのリクエストボディをプロバイダー独自のスキーマに変換し、レスポンスを元の形式に戻します。API リファレンスの [`model_provider`、`strict_mode`、`fallback_provider`](/ja/development/comfy-router/reference#post-v2modelsprovidermodel) を参照し、この方法でルーティングされるすべてのモデルについては[サービングプロバイダー](/ja/development/comfy-router/providers)を参照してください。

  オーディオファイルのダウンロードURL。対応形式: mp3 および wav。reference_video_urls とは併用できません。
</ParamField>

<ParamField body="input.img_url" type="string">
  先頭フレームの画像URL、または Base64 エンコードされたデータ。wan2.5-i2v-preview および wan2.6-i2v モデルでは必須です。happyhorse-1.x の i2v 表記では、先頭フレームをここでは受け取りません。先頭フレームは type が first_frame の media 要素として受け取ります（後述の media を参照）。また、wan2.6-i2v では成功する img_url のボディも、happyhorse-1.0-i2v と happyhorse-1.1-i2v ではプロバイダーによって拒否されます。さらに wan2.7/wan3.0 の表記も、参照アセットは同様に media で受け取ります。画像形式: JPEG、JPG、PNG、BMP、WEBP。解像度: 360～2000 ピクセル。ファイルサイズ: 最大 10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。動画生成のための参照素材（画像、オーディオ、ビデオ）を指定します。各要素は type と url フィールドを持ちます。このフィールドは、このコンポーネントから提供されるすべてのモデルで共通ですが、あるモデルがどの type の値を受け付けるか、またそのモデルが画像やビデオの入力を img_url や reference_video_urls ではなくここで受け取るかどうかは、モデルごとに異なります。モデルごとの対応する type の値:
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frame と last_frame: JPEG/JPG/PNG/BMP/WEBP、1辺 240～8000 ピクセル、アスペクト比 1:8～8:1、最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。driving_audio（WAV/MP3、2～30 秒、最大 15MB）と first_clip（MP4/MOV、2～10 秒、1辺 240～4096 ピクセル、最大 100MB）: 公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-r2v: first_frame（任意、最大 1）、reference_image、reference_video。reference_image または reference_video のうち少なくとも 1 つが必須で、reference_image と reference_video の合計は最大 5 です。first_frame と reference_image: JPEG/JPG/PNG/BMP/WEBP（アルファチャンネルなし）、1辺 240～8000 ピクセル、アスペクト比 1:8～8:1、最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。reference_video: 公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-videoedit: video（必ず 1 つ、編集対象のクリップ: MP4/MOV、2～10 秒、1辺 240～4096 ピクセル、最大 100MB、公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません）に加えて、任意で 0～4 つの reference_image（JPEG/JPG/PNG/BMP/WEBP、1辺 240～8000 ピクセル、アスペクト比 1:8～8:1、最大 20MB、公開 URL または data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime: first_frame（最大 1）、last_frame（最大 1）、reference_image（最大 10）、reference_video（最大 5 クリップ、合計再生時間 \<= 15 秒）、reference_audio（最大 5 クリップ、合計再生時間 \<= 15 秒）、file（最大 1、link とは併用不可）、link（最大 1、file とは併用不可）。reference_*/file/link のタイプと first_frame/last_frame のタイプは、同じリクエスト内では同時に使用できません。配列の順序が、プロンプト内でのアセットの参照順（Image 1、Video 1、Audio 1、...）を定義します。first_frame、last_frame、reference_image: JPEG/JPG/PNG/BMP/WEBP、1辺 240～8000 ピクセル、アスペクト比は最大 8:1、最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。reference_video、reference_audio、file、link: 公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v: first_frame のみ、必ず 1 つ。これらの表記では先頭フレームをここで受け取り、img_url では受け取りません。少なくとも 300x300 ピクセル、アスペクト比 1:2.5～2.5:1、JPEG/JPG/PNG/WEBP、最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v: reference_image のみ、1～9 個。これがこのモデル唯一の参照入力です。最短辺が少なくとも 400 ピクセル、JPEG/JPG/PNG/WEBP、最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。reference_video はこの操作の入力タイプではありません。
- happyhorse-1.0-video-edit: video（必ず 1 つ、編集対象のクリップ: MP4/MOV、3～60 秒、長辺が最大 4096 ピクセル、短辺が少なくとも 360 ピクセル、アスペクト比 1:2.5～2.5:1、最大 100MB、公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません）に加えて、任意で 0～5 つの reference_image（JPEG/JPG/PNG/WEBP、少なくとも 300x300 ピクセル、アスペクト比 1:2.5～2.5:1、最大 20MB、公開 URL または data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview: テキストから動画への操作。パートナーのリファレンスにはメディア入力の記載がないため、このフィールドは未設定のままにしてください。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v: このコンポーネントは、これらの表記に対する media の語彙を列挙していません。wan2.5-i2v-preview と wan2.6-i2v は先頭フレームを img_url で受け取り、wan2.6-r2v は参照クリップを reference_video_urls で受け取ります。

上記のモデルごとの個数はパートナーの制約であり、このスキーマの制約ではありません。media には minItems/maxItems が宣言されていません。許可されるタイプとその上限がモデルごとに異なるためです。スキーマが受け入れても、プロバイダーが受け入れるとは限りません。逆に、上記のアセットごとの「最大 20MB」という数値は、画像入力に対する上限であり、インラインで送信できる唯一の入力でもあります。これらはパートナーが最終的に受け取るアセットに対するパートナーの上限であり、アセットが公開 URL である場合はそのバイト列が Comfy を経由しないため、記載どおりに適用されます。インラインの data:\{MIME_type};base64,... URL は Comfy を経由するため、転送上の上限にも直面します。Comfy Router の POST ボディは合計 100 MiB に制限され、それを超えると 413 が返されます。また base64 はペイロードを約 4/3 に膨らませるため、約 75 MB を超える単一のインラインアセットは、ここに記載したパートナーのルールに到達する前に拒否されます。そのサイズでは、単一のアセットはパートナー自身の20MB の上限はインラインで問題なく収まるため、1つのアセットについてはパートナーのルールが制約となります。複数のアセットにまたがる場合は転送の上限が制約となります。100 MiB の Router 上限は各要素ではなくリクエスト全体を制限するためです。これらの上限に近いものはすべてパブリック URL として送信してください。
</ParamField>

このプロキシは、`resolution` と `size` のどちらも指定していないビデオ生成リクエストを拒否します。解像度ティアが課金レートを選択するためです。チェックの前に `resolution` を大文字化し、その大文字化した値を転送します。この enum に含まれない値には 400 を返し、上記で 480P がないモデルとして挙げられている wan2.6、wan2.7、happyhorse-1.0 では 480P (`resolution` として送信された場合も、480P の `size` として送信された場合も) に対して 400 を返します。

<ParamField body="parameters.size" type="string">

wan2.6 T2V/R2V の場合 (480P なし):

  1080P: 1920*1080、1080*1920、1440*1440、1632*1248、1248*1632

    "duration": 5
  }
