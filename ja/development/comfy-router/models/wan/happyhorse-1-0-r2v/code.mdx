HappyHorse 1.0 R2V の API リファレンスです。HappyHorse 1.0 の参照から動画は、1 つ以上の参照画像の被写体を新しいシーンを通じて一貫させます。プロンプトでは character1、character2 などとして指定します。

**入力：** 画像, テキスト · **出力：** ビデオ

**モデル ID:** `wan/happyhorse-1.0-r2v`

**エンドポイント:** `POST https://api.comfy.org/v2/models/wan/happyhorse-1.0-r2v`

import asyncio
from comfy_sdk import AsyncComfy

# 環境から COMFY_API_KEY を読み取ります。
# 各 submit() 呼び出しは独自の Idempotency-Key を生成し、自動リトライのために再利用します。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/happyhorse-1.0-r2v",
            {
                "input": {
                    "prompt": "character1 walks in from the left, turns to the camera and waves, plain orange backdrop",
                    "media": [
                        {
                            "type": "reference_image",
                            "url": "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # モデル ID と合わせて、別のプロセスが必要とするものはこれだけです

        # リクエストが完了するまでポーリングし、サーバーが指定する Retry-After の時間だけ待機します。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # プロバイダー自身のペイロード。models.run() が返すのと同じ値です。
        # 失敗またはキャンセルされたリクエストは、ここで型付きの Router エラーを発生させます。

  プロンプトなどの基本情報を入力します。
</ParamField>

<ParamField body="input.audio_url" type="string">
  オーディオファイルのダウンロードURL。対応形式: mp3 と wav。reference_video_urls とは併用できません。
</ParamField>

<ParamField body="input.img_url" type="string">
  先頭フレームの画像URL、または Base64 エンコードされたデータ。wan2.5-i2v-preview および
wan2.6-i2v モデルでは必須です。happyhorse-1.x の i2v 表記では、先頭フレームをここでは受け取りません。
代わりに type が first_frame のメディア要素として受け取ります（下記 media を参照）。
wan2.6-i2v で成功する img_url ボディは、happyhorse-1.0-i2v と happyhorse-1.1-i2v ではプロバイダーに
拒否されます。また wan2.7/wan3.0 の表記も参照アセットを media で受け取ります。画像形式: JPEG、JPG、PNG、BMP、WEBP。
解像度: 360-2000 ピクセル。ファイルサイズ: 最大 10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。ビデオ生成用の参照素材（画像、オーディオ、ビデオ）を指定します。
各要素は type フィールドと url フィールドを含みます。このフィールドは、このコンポーネントから
提供されるすべてのモデルで共通ですが、あるモデルがどの type 値を受け入れるか、また img_url や
reference_video_urls ではなくここに画像またはビデオ入力を渡すかどうかは、モデルによって異なります。
モデルごとの対応 type 値:
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frame と
  last_frame: JPEG/JPG/PNG/BMP/WEBP、1辺あたり 240-8000 ピクセル、アスペクト比 1:8～8:1、
  最大 20MB、公開URL または data:\{MIME_type};base64,... URL。
  driving_audio（WAV/MP3、2～30 秒、最大 15MB）と first_clip（MP4/MOV、2～10 秒、
  1辺あたり 240-4096 ピクセル、最大 100MB）: 公開 HTTP/HTTPS URL。インラインの
  data: URL は受け付けられません。
- wan2.7-r2v: first_frame（任意、最大1）、reference_image、reference_video。少なくとも
  1つの reference_image または reference_video が必要で、reference_image と
  reference_video を合わせて最大5つです。first_frame と reference_image: JPEG/JPG/PNG/BMP/WEBP
  （アルファチャンネルなし）、1辺あたり 240-8000 ピクセル、アスペクト比 1:8～8:1、最大
  20MB、公開URL または data:\{MIME_type};base64,... URL。reference_video: 公開
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-videoedit: video（ちょうど1つ、編集対象のクリップ: MP4/MOV、2～10 秒、
  1辺あたり 240-4096 ピクセル、最大 100MB、公開 HTTP/HTTPS URL。インラインの data: URL
  は受け付けられません）に加えて、任意で 0～4 個の reference_image（JPEG/JPG/PNG/BMP/WEBP、
  1辺あたり 240-8000 ピクセル、アスペクト比 1:8～8:1、最大 20MB、公開URL
  または data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime: first_frame（最大1）、last_frame（最大1）、
  reference_image（最大10）、reference_video（最大5クリップ、合計再生時間 \<= 15s）、
  reference_audio（最大5クリップ、合計再生時間 \<= 15s）、file（最大1、link と併用不可）、
  link（最大1、file と併用不可）。reference_*/file/link タイプと first_frame/last_frame
  タイプは、同じリクエスト内で相互に排他的です。配列の順序が、プロンプト内のアセットの
  参照順序（Image 1、Video 1、Audio 1、...）を定義します。first_frame、last_frame、
  reference_image: JPEG/JPG/PNG/BMP/WEBP、1辺あたり 240-8000 ピクセル、アスペクト比
  最大 8:1、最大 20MB、公開URL または data:\{MIME_type};base64,... URL。reference_video、
  reference_audio、file、link: 公開 HTTP/HTTPS URL。インラインの data: URL は
  受け付けられません。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v: first_frame のみ、ちょうど1つ。これらの表記は
  先頭フレームをここで受け取り、img_url では受け取りません。少なくとも 300x300 ピクセル、
  アスペクト比 1:2.5～2.5:1、JPEG/JPG/PNG/WEBP、最大 20MB、公開URL または
  data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v: reference_image のみ、1～9 個。これが
  このモデル唯一の参照入力です。最短辺が少なくとも 400 ピクセル、JPEG/JPG/PNG/WEBP、
  最大 20MB、公開URL または data:\{MIME_type};base64,... URL。reference_video は
  この操作の入力タイプではありません。
- happyhorse-1.0-video-edit: video（ちょうど1つ、編集対象のクリップ: MP4/MOV、3～60
  秒、長辺が最大 4096 ピクセル、短辺が少なくとも 360 ピクセル、アスペクト比
  1:2.5～2.5:1、最大 100MB、公開 HTTP/HTTPS URL。インラインの data:
  URL は受け付けられません）に加えて、任意で 0～5 個の reference_image（JPEG/JPG/PNG/WEBP、
  少なくとも 300x300 ピクセル、アスペクト比 1:2.5～2.5:1、最大 20MB、公開URL
  または data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview:
  テキストから動画への操作。対応するパートナーのリファレンスにはメディア入力の記載がないため、
  このフィールドは未設定のままにしてください。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v: このコンポーネントは、これらの表記に対して
  media の語彙を列挙していません。wan2.5-i2v-preview と wan2.6-i2v は先頭フレームを
  img_url で受け取り、wan2.6-r2v は参照クリップを reference_video_urls で受け取ります。
上記のモデルごとの個数はパートナー側の制約であり、このスキーマのものではありません。media には
minItems/maxItems が宣言されていません。許容されるタイプとその上限がモデルごとに異なるためです。
スキーマが受け入れることはプロバイダーが受け入れることを意味しません。逆に、上記のアセット
ごとの「最大 20MB」という数値は、画像入力の上限であり（これらはインラインで送信できる唯一の
入力です）、最終的に受け取るアセットに対するパートナー側の上限であり、アセットが公開URL の場合は
そのまま適用されます。そのバイト列は Comfy を経由しないためです。インラインの
data:\{MIME_type};base64,... URL は Comfy を経由するため、転送上限にも直面します。Comfy Router
の POST ボディは合計 100 MiB に制限され、超えると 413 が返されます。また base64 はペイロードを
約 4/3 に膨らませるため、およそ 75 MB を超える単一のインラインアセットは、ここに記載された
パートナーのルールに到達する前に拒否されます。そのサイズでは、単一のアセットはパートナー自身の20MB の上限はインラインに余裕で収まるため、1つのアセットについてはパートナーのルールが制約となります。トランスポートの上限は複数のアセットにまたがる場合に制約となります。100 MiB の Router 上限は各要素ではなくリクエスト全体を制限するためです。これらの上限に近いものはすべてパブリック URL として送信してください。

<ParamField body="input.media[].url" type="string" required>
  メディアファイルの URL。パブリックな HTTP/HTTPS URL、または、上記の `media` の説明が各モデルについて挙げているまさに画像の入力（wan2.7-i2v の first_frame と last_frame、wan2.7-r2v の first_frame と reference_image、wan2.7-videoedit の reference_image、wan3.0-video と wan3.0-video-prime の first_frame、last_frame、reference_image、happyhorse-1.0-i2v と happyhorse-1.1-i2v の first_frame、happyhorse-1.0-r2v と happyhorse-1.1-r2v の reference_image、そして happyhorse-1.0-video-edit の reference_image）に限り、インラインの `data:{MIME_type};base64,...` URL。
  これらのモデルのいずれでも、ビデオ、オーディオ、ファイル、リンクの入力はインラインの data: URL を受け付けません。パートナー自身のアップロードサービスによる oss://dashscope-instant の一時 URL、または（wan2.7-videoedit では）Asset Center の asset_id は、それをアップロードした Alibaba Cloud アカウントに対してのみ解決されます。Comfy は自身のキーでモデル呼び出しを行い、アップロード経路を公開しないため、呼び出し元自身の oss:// URL や asset_id はサポートされる入力ではありません。このフィールドは URL スキームを検証しないため、そのような値はここで拒否されず、そのままパートナーへ転送されます。モデルごとのサイズとピクセルの制限、およびインラインのペイロードを全体として制限する 100 MiB の Router リクエストボディ上限については、`media` の説明を参照してください。

<ParamField body="input.prompt" type="string">
  テキストプロンプト。中国語と英語に対応し、長さは800文字以内（wan3.0-video では最大20,000文字。制限を超えたコンテンツは切り捨てられます）。
  wan2.6-r2v で複数の参照ビデオを使用する場合は、参照ビデオの順序に従って被写体を 'character1'、'character2' などで参照します。例: "Character1 sings on the roadside, Character2 dances beside it"
  wan3.0-video の参照モードでは、media 配列内の対応する順序でメディアアセットを参照するために 'Image 1'、'Video 1'、'Audio 1' などを使用します。

<ParamField body="input.reference_video_urls" type="string[]">
  wan2.6-r2v モデル専用の参照ビデオ URL。1～3本のビデオ URL の配列。
入力の制限:
- フォーマット: mp4、mov
- 本数: 1～3本のビデオ
- 単一ビデオの長さ: 2～30秒
- 単一ファイルサイズ: 最大30MB

参照の再生時間: 単一ビデオは最大5秒、2本の場合は各最大2.5秒、3本の場合はそれに比例して短くなります。
課金: 実際に使用した参照の再生時間に基づきます。

- wan2.7-r2v、wan2.7-videoedit: [2, 10] の整数
- wan3.0-video: ビデオ入力なしの場合は [2, 30] の整数。ビデオ入力ありの場合は、入力ビデオの再生時間と出力ビデオの再生時間の合計が30秒を超えてはなりません。-1 はモデルが適切な再生時間を選ぶスマート再生時間モードを有効にします
このプロキシは [-1, 30] の範囲外の再生時間に対して400を返します。

  範囲: `-1` ～ `30`
</ParamField>

<ParamField body="parameters.prompt_extend" type="boolean" default="true">

<ParamField body="parameters.ratio" type="string">

wan3.0-video では、adaptive（デフォルト）が入力メディアの比率と意図に基づいて適切なアスペクト比を自動的に推奨します。

  指定可能な値: `adaptive`、`16:9`、`9:16`、`1:1`、`4:3`、`3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  解像度レベル。サポートされる値はモデルによって異なります:
- wan2.5-i2v-preview: 480P、720P、1080P
- wan2.6 モデル（t2v、i2v、r2v）: 720P、1080P のみ（480P はサポートされません）
- wan2.7 モデル（i2v、t2v、r2v、videoedit）: 720P、1080P（デフォルト 1080P）
- wan3.0-video、wan3.0-video-prime: 480P、720P、1080P（上流のデフォルトは 1080P）
- happyhorse-1.0-*（t2v、i2v、r2v、video-edit）: 720P、1080P
- happyhorse-1.1-*（t2v、i2v、r2v）: 480P、720P、1080P
このプロキシは、解像度も size も指定されていないビデオ生成リクエストを拒否します。解像度のティアが課金レートを選択するためです。このプロキシは、解像度をチェックする前に大文字に変換し、その大文字に変換した値をそのまま転送します。この enum に含まれない値には 400 を返し、上記で 480P を持たないものとして記載されている wan2.6、wan2.7、happyhorse-1.0 のモデルでは、480P（解像度として送信された場合も、480P の size として送信された場合も）に対して 400 を返します。

  指定可能な値: `480P`, `720P`, `1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">

</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">

wan2.6 および wan2.7-r2v モデル用です。
- single: シングルショットビデオ（デフォルト）
- multi: マルチショットビデオ

  指定可能な値: `multi`, `single`
</ParamField>

<ParamField body="parameters.size" type="string">
  width*height 形式のビデオ解像度。対応する解像度はモデルによって異なります:
wan2.5 T2V の場合: 480P（480*832、832*480、624*624）、720P、1080P のサイズ
wan2.6 T2V/R2V の場合（480P なし）:
  720P: 1280*720, 720*1280, 960*960, 1088*832, 832*1088
  1080P: 1920*1080, 1080*1920, 1440*1440, 1632*1248, 1248*1632
size と resolution の両方を送信した場合、課金ティアを選択するのは size であり、
resolution はモデルに対してこのプロキシが受け付ける値である必要があります。480P の size は、
resolution の説明で 480P を持たないと記載されているすべてのモデルで 400 を返します。
</ParamField>
