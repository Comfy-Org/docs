HappyHorse 1.0 R2V の API リファレンスです。HappyHorse 1.0 の参照から動画は、1 つ以上の参照画像の被写体を新しいシーンを通じて一貫させます。プロンプトでは character1、character2 などとして指定します。

**入力：** 画像, テキスト · **出力：** ビデオ

**モデル ID:** `wan/happyhorse-1.0-r2v`

**エンドポイント:** `POST https://api.comfy.org/v2/models/wan/happyhorse-1.0-r2v`

import asyncio
from comfy_sdk import AsyncComfy

# 環境から COMFY_API_KEY を読み取ります。
# 各 submit() 呼び出しは独自の Idempotency-Key を生成し、自動リトライのために再利用します。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/happyhorse-1.0-r2v",
            {
                "input": {
                    "prompt": "character1 walks in from the left, turns to the camera and waves, plain orange backdrop",
                    "media": [
                        {

                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # モデル ID と合わせて、別のプロセスが必要とするものはこれだけです

        # リクエストが完了するまでポーリングし、サーバーが指定する Retry-After の時間だけ待機します。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # プロバイダー自身のペイロード。models.run() が返すのと同じ値です。
        # 失敗またはキャンセルされたリクエストは、ここで型付きの Router エラーを発生させます。

<ParamField body="input.audio_url" type="string">
  オーディオファイルのダウンロードURL。対応形式: mp3、wav。reference_video_urls とは併用できません。
</ParamField>

<ParamField body="input.img_url" type="string">
  先頭フレームの画像URL、またはBase64エンコードされたデータ。wan2.5-i2v-preview と
wan2.6-i2v モデルでは必須です。happyhorse-1.x の i2v 系の表記では先頭フレームをここで受け取りません
-- 先頭フレームは type が first_frame のメディア要素として受け取ります（下記の media を参照）。そして
wan2.6-i2v で成功する img_url ボディは、happyhorse-1.0-i2v と happyhorse-1.1-i2v では
プロバイダーに拒否されます -- また wan2.7/wan3.0 系の表記も参照アセットを
media で受け取ります。画像形式: JPEG、JPG、PNG、BMP、WEBP。
解像度: 360〜2000ピクセル。ファイルサイズ: 最大10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。動画生成のための参照素材（画像、オーディオ、ビデオ）を指定します。
各要素は type と url フィールドを持ちます。このフィールドはこのコンポーネントから提供される
すべてのモデルで共通であり、あるモデルがどの type 値を受け付けるか -- そして画像やビデオの入力を
img_url や reference_video_urls ではなくここで持つかどうか -- はモデルごとに異なります。
モデル別の対応 type 値:
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frame と
  last_frame: JPEG/JPG/PNG/BMP/WEBP、1辺240〜8000ピクセル、アスペクト比 1:8
  〜8:1、最大20MB、公開URL または data:\{MIME_type};base64,... URL。
  driving_audio（WAV/MP3、2〜30秒、最大15MB）と first_clip（MP4/MOV、2〜10
  秒、1辺240〜4096ピクセル、最大100MB）: 公開 HTTP/HTTPS URL。インラインの
  data: URL は受け付けられません。
- wan2.7-r2v: first_frame（任意、最大1）、reference_image、reference_video。少なくとも
  1つの reference_image または reference_video が必要で、reference 画像と
  reference ビデオの合計は最大5つです。first_frame と reference_image: JPEG/JPG/PNG/BMP/WEBP
  （アルファチャンネルなし）、1辺240〜8000ピクセル、アスペクト比 1:8〜8:1、最大
  20MB、公開URL または data:\{MIME_type};base64,... URL。reference_video: 公開
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-videoedit: video（ちょうど1つ、編集対象のクリップ: MP4/MOV、2〜10秒、
  1辺240〜4096ピクセル、最大100MB、公開 HTTP/HTTPS URL。インラインの data: URL
  は受け付けられません）に加えて、任意で0〜4つの reference_image（JPEG/JPG/PNG/BMP/WEBP、
  1辺240〜8000ピクセル、アスペクト比 1:8〜8:1、最大20MB、公開URL
  または data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime: first_frame（最大1）、last_frame（最大1）、
  reference_image（最大10）、reference_video（最大5クリップ、合計再生時間 \<= 15秒）、
  reference_audio（最大5クリップ、合計再生時間 \<= 15秒）、file（最大1、link とは併用
  不可）、link（最大1、file とは併用不可）。reference_*/file/link の type と
  first_frame/last_frame の type は、同一リクエスト内で同時に使用できません。
  配列の順序がプロンプト内でのアセットの参照順序を定義します（Image 1、Video 1、
  Audio 1、...）。first_frame、last_frame、reference_image: JPEG/JPG/PNG/BMP/WEBP、
  1辺240〜8000ピクセル、アスペクト比 最大8:1、最大20MB、公開URL または
  data:\{MIME_type};base64,... URL。reference_video、reference_audio、file、link: 公開
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v: first_frame のみ、ちょうど1つ。これらの表記では
  先頭フレームをここで受け取り、img_url では受け取りません。最小300x300ピクセル、アスペクト比
  1:2.5〜2.5:1、JPEG/JPG/PNG/WEBP、最大20MB、公開URL または
  data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v: reference_image のみ、1〜9つ。これは
  このモデル唯一の参照入力です。最短辺 最小400ピクセル、JPEG/JPG/PNG/WEBP、
  最大20MB、公開URL または data:\{MIME_type};base64,... URL。reference_video は
  この操作の入力 type ではありません。
- happyhorse-1.0-video-edit: video（ちょうど1つ、編集対象のクリップ: MP4/MOV、3〜60
  秒、長辺 最大4096ピクセル、短辺 最小360ピクセル、アスペクト比
  1:2.5〜2.5:1、最大100MB、公開 HTTP/HTTPS URL。インラインの data:
  URL は受け付けられません）に加えて、任意で0〜5つの reference_image（JPEG/JPG/PNG/WEBP、
  最小300x300ピクセル、アスペクト比 1:2.5〜2.5:1、最大20MB、公開URL
  または data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview:
  テキストから動画への操作。これらの対応リファレンスにはメディア入力の記載がないため、このフィールドは
  未設定のままにしてください。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v: このコンポーネントはこれらの表記に対して
  media の語彙を列挙していません。wan2.5-i2v-preview と wan2.6-i2v は先頭フレームを
  img_url で受け取り、wan2.6-r2v は参照クリップを reference_video_urls で受け取ります。
上記のモデル別の個数はパートナーの制約であり、このスキーマの制約ではありません。media には
minItems/maxItems が宣言されていません。受け付け可能な type とその上限はモデルごとに
異なるためです。スキーマが受け付けることはプロバイダーが受け付けることを意味しません -- そして
逆方向として、上記のアセット単位の「最大20MB」という数値 -- 画像入力（インラインで送信できる
唯一の入力）の上限 -- は、最終的にパートナーが持つアセットに対するパートナーの上限であり、
アセットが公開URLの場合はそのまま適用されます。これらのバイト列は Comfy を経由しないためです。
インラインの data:\{MIME_type};base64,... URL は Comfy を経由するため、転送時の上限にも
直面します。Comfy Router の POST ボディは合計100 MiB に制限され、超えると 413 が返り、
base64 はペイロードを約4/3に膨らませるため、およそ75 MB を超える単一のインラインアセットは
ここに記されたパートナーのルールに到達する前に拒否されます。そのサイズでは、パートナー自身の20MB の上限はインラインに余裕で収まるため、1つのアセットではパートナーのルールが制約となります。複数のアセットにまたがる場合はトランスポートの上限が制約となります。100 MiB の Router の上限は個々の要素ではなくリクエスト全体を制限するためです。これらの上限に近いものはパブリック URL として送信してください。
</ParamField>

<ParamField body="input.media[].url" type="string" required>

<ParamField body="input.negative_prompt" type="string">
  逆プロンプトは、ビデオ画面に映したくないコンテンツを記述するために使用します。500 文字を超えると、wan モデルはそれを拒否せずに切り捨てます。prompt と同じ入力予算にカウントされます。

<ParamField body="input.prompt" type="string">
  テキストプロンプトです。中国語と英語をサポートします。ドキュメントに記載された長さを超えると、wan2.x モデルはプロンプトを拒否せずに切り捨てます: wan2.5 と wan2.6 では 1,500 文字、wan2.7 では 5,000 文字です。wan3.0-video と wan3.0-video-prime は最大 20,000 文字を受け付けます。prompt と negative_prompt を合わせて約 60,850 バイトの UTF-8 テキスト（約 20,000 文字の中国語）を超えるリクエストは、プロバイダーが拒否し、InvalidParameter `Range of input length should be [1, 61440]` を返します。
  複数の参照ビデオを指定する wan2.6-r2v では、参照ビデオの順序に対応させて 'character1'、'character2' などで被写体を参照します。例: "Character1 sings on the roadside, Character2 dances beside it"
  wan3.0-video の参照モードでは、media 配列内の対応する順序で 'Image 1'、'Video 1'、'Audio 1' などを使ってメディアアセットを参照します。
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  wan2.6-r2v モデル専用の参照ビデオ URL。1-3 本のビデオ URL の配列です。
入力の制限:
- 形式: mp4、mov
- 数量: 1-3 本
- 単一ビデオの長さ: 2-30 秒
- 単一ファイルのファイルサイズ: 最大 30MB
- audio_url と併用できません
参照の再生時間: 単一ビデオは最大 5 秒、2 本の場合はそれぞれ最大 2.5 秒、3 本の場合は比例して短くなります。
課金: 実際に使用した参照の再生時間に基づきます。
</ParamField>

  指定可能な値: `auto`、`origin`
</ParamField>

<ParamField body="parameters.duration" type="integer" default="5">
  生成されるビデオの再生時間（秒）:
- wan2.5 モデル: 5 秒または 10 秒
- wan2.6-t2v、wan2.6-i2v: 5 秒、10 秒、または 15 秒
- wan2.6-r2v: 5 秒または 10 秒のみ（15 秒は非サポート）
- wan2.7-i2v、wan2.7-t2v: [2, 15] の整数
- wan2.7-r2v、wan2.7-videoedit: [2, 10] の整数
- wan3.0-video: ビデオ入力なしの場合は [2, 30] の整数。ビデオ入力ありの場合は、入力ビデオの再生時間と出力ビデオの再生時間の合計が 30 秒を超えてはなりません。-1 を指定すると、モデルが適切な再生時間を選択するスマート再生時間モードが有効になります
このプロキシは [-1, 30] の範囲外の duration に対して 400 を返します。

  範囲: `-1` から `30`
</ParamField>

<ParamField body="parameters.prompt_extend" type="boolean" default="true">

</ParamField>

<ParamField body="parameters.ratio" type="string">
  生成されるビデオのアスペクト比。wan2.7 および wan3.0 モデル専用です。
wan2.7 モデルでは、指定しない場合は解像度のティアに基づいてデフォルトが決まります。
wan3.0-video では、adaptive（デフォルト）が適切なものを自動的に推奨しますアスペクト比は入力メディアの比率と意図に基づいて決まります。

  指定可能な値: `adaptive`、`16:9`、`9:16`、`1:1`、`4:3`、`3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  解像度レベル。サポートされる値はモデルによって異なります:
- wan2.5-i2v-preview: 480P、720P、1080P
- wan2.6 モデル（t2v、i2v、r2v）: 720P、1080P のみ（480P 非対応）
- wan2.7 モデル（i2v、t2v、r2v、videoedit）: 720P、1080P（デフォルト 1080P）
- wan3.0-video、wan3.0-video-prime: 480P、720P、1080P（上流のデフォルト 1080P）
- happyhorse-1.0-*（t2v、i2v、r2v、video-edit）: 720P、1080P
- happyhorse-1.1-*（t2v、i2v、r2v）: 480P、720P、1080P
このプロキシは、resolution と size のどちらも指定されていないビデオ生成リクエストを拒否します。解像度の階層が課金レートを決めるためです。チェックの前に resolution を大文字化して、その大文字化した値を転送します。この列挙にない値には 400 を返し、上記の 480P 非対応として挙げた wan2.6、wan2.7、happyhorse-1.0 モデルでは 480P に対して（resolution として送られた場合も、480P の size として送られた場合も）400 を返します。

  指定可能な値: `480P`、`720P`、`1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  乱数シード。モデルが生成するコンテンツのランダム性を制御するために使用します。

  範囲: `0` から `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  インテリジェントなマルチレンズ制御。prompt_extend が有効な場合にのみ機能します。
wan2.6 および wan2.7-r2v モデル用。
- single: シングルショットビデオ（デフォルト）
- multi: マルチショットビデオ

  指定可能な値: `multi`、`single`
</ParamField>

<ParamField body="parameters.size" type="string">
  幅*高さ形式のビデオ解像度。サポートされる解像度はモデルによって異なります:
wan2.5 T2V の場合: 480P（480*832、832*480、624*624）、720P、1080P の各サイズ
wan2.6 T2V/R2V の場合（480P なし）:
  720P: 1280*720、720*1280、960*960、1088*832、832*1088
  1080P: 1920*1080、1080*1920、1440*1440、1632*1248、1248*1632
size と resolution の両方を送信した場合、課金階層を選ぶのは size であり、resolution はそのモデルに対してこのプロキシが受け付ける値である必要があります。480P の size は、解像度の説明で 480P 非対応として挙げたすべてのモデルで 400 を返します。
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">

</ParamField>
