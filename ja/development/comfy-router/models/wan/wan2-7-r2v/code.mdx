Wan 2.7 R2V の API リファレンスです。Wan 2.7 の参照から動画は、参照画像や参照ビデオに含まれる被写体を新しいシーンへ持ち込み、プロンプト内で character1、character2 などとして指定します。

**入力：** 画像, ビデオ, テキスト · **出力：** ビデオ

**モデル ID:** `wan/wan2.7-r2v`

**エンドポイント:** `POST https://api.comfy.org/v2/models/wan/wan2.7-r2v`

import asyncio
from comfy_sdk import AsyncComfy

# 環境変数から COMFY_API_KEY を読み取ります。
# 各 submit() 呼び出しは独自の Idempotency-Key を発行し、自動リトライ時に再利用します。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/wan2.7-r2v",
            {
                "input": {
                    "prompt": "character1 walks in from the left, turns to the camera and waves, plain orange backdrop",
                    "media": [
                        {
                            "type": "reference_image",
                            "url": "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # モデル ID と合わせて、別のプロセスが必要とする情報はこれだけです

        # リクエストが完了するまでポーリングし、サーバーが指定する Retry-After の秒数だけ待機します。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # プロバイダー自身のペイロードで、models.run() が返す値と同じものです。
        # 失敗またはキャンセルされたリクエストは、ここで型付きの Router エラーを発生させます。
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())

### 入力

<ParamField body="input" type="object" required>
  プロンプトなどの基本情報を入力します。
</ParamField>

<ParamField body="input.audio_url" type="string">
  オーディオファイルのダウンロードURL。対応形式: mp3 と wav。reference_video_urls と併用できません。
</ParamField>

<ParamField body="input.img_url" type="string">
  先頭フレーム画像のURL、または Base64 エンコードされたデータ。wan2.5-i2v-preview および
wan2.6-i2v モデルでは必須です。happyhorse-1.x の i2v 表記はここでは先頭フレームを受け取りません。
先頭フレームは type が first_frame の media 要素として受け取ります（下記の media を参照）。
また、wan2.6-i2v では成功する img_url ボディが、happyhorse-1.0-i2v および happyhorse-1.1-i2v
ではプロバイダーに拒否されます。wan2.7/wan3.0 の表記も参照アセットを media で受け取ります。
画像形式: JPEG、JPG、PNG、BMP、WEBP。
解像度: 360～2000 ピクセル。ファイルサイズ: 最大 10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。ビデオ生成のための参照素材（画像、オーディオ、ビデオ）を
指定します。各要素は type フィールドと url フィールドを含みます。このフィールドはこの
コンポーネントから提供されるすべてのモデルで共有されていますが、どのモデルがどの type
値を受け付けるか、また画像やビデオの入力を img_url や reference_video_urls ではなく
ここで受け取るかどうかは、モデルによって異なります。モデルごとの対応 type 値:
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frame と
  last_frame: JPEG/JPG/PNG/BMP/WEBP、1 辺 240～8000 ピクセル、アスペクト比 1:8～
  8:1、最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。
  driving_audio（WAV/MP3、2～30 秒、最大 15MB）と first_clip（MP4/MOV、2～10
  秒、1 辺 240～4096 ピクセル、最大 100MB）: 公開 HTTP/HTTPS URL。インラインの
  data: URL は受け付けられません。
- wan2.7-r2v: first_frame（任意、最大 1）、reference_image、reference_video。
  reference_image または reference_video が少なくとも 1 つ必要で、reference_image
  と reference_video の合計は最大 5 です。first_frame と reference_image:
  JPEG/JPG/PNG/BMP/WEBP（アルファチャンネルなし）、1 辺 240～8000 ピクセル、アスペクト比 1:8～8:1、最大
  20MB、公開 URL または data:\{MIME_type};base64,... URL。reference_video: 公開
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-videoedit: video（ちょうど 1 つ、編集対象のクリップ: MP4/MOV、2～10 秒、
  1 辺 240～4096 ピクセル、最大 100MB、公開 HTTP/HTTPS URL。インラインの data: URL
  は受け付けられません）に加えて、任意で 0～4 個の reference_image（JPEG/JPG/PNG/BMP/WEBP、
  1 辺 240～8000 ピクセル、アスペクト比 1:8～8:1、最大 20MB、公開 URL
  または data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime: first_frame（最大 1）、last_frame（最大 1）、
  reference_image（最大 10）、reference_video（最大 5 クリップ、合計再生時間 \<= 15 秒）、
  reference_audio（最大 5 クリップ、合計再生時間 \<= 15 秒）、file（最大 1、link と
  併用不可）、link（最大 1、file と併用不可）。reference_*/file/link タイプ
  と first_frame/last_frame タイプは、同じリクエスト内で同時に使用できません。
  配列の順序が、プロンプト内のアセットの参照順（Image 1、Video 1、
  Audio 1、…）を定義します。first_frame、last_frame、reference_image: JPEG/JPG/PNG/BMP/WEBP、
  1 辺 240～8000 ピクセル、アスペクト比最大 8:1、最大 20MB、公開 URL または
  data:\{MIME_type};base64,... URL。reference_video、reference_audio、file、link:
  公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v: first_frame のみ、ちょうど 1 つ。これらの表記
  は先頭フレームを「ここで」受け取り、img_url では受け取りません。少なくとも 300x300 ピクセル、アスペクト比
  1:2.5～2.5:1、JPEG/JPG/PNG/WEBP、最大 20MB、公開 URL または
  data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v: reference_image のみ、1～9 個。これが
  このモデル唯一の参照入力です。短辺が少なくとも 400 ピクセル、JPEG/JPG/PNG/WEBP、
  最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。reference_video は
  この操作の入力タイプではありません。
- happyhorse-1.0-video-edit: video（ちょうど 1 つ、編集対象のクリップ: MP4/MOV、3～60
  秒、長辺が最大 4096 ピクセル、短辺が少なくとも 360 ピクセル、アスペクト
  比 1:2.5～2.5:1、最大 100MB、公開 HTTP/HTTPS URL。インラインの data:
  URL は受け付けられません）に加えて、任意で 0～5 個の reference_image（JPEG/JPG/PNG/WEBP、
  少なくとも 300x300 ピクセル、アスペクト比 1:2.5～2.5:1、最大 20MB、公開 URL
  または data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview:
  テキストから動画への操作。これらのパートナーのリファレンスには media 入力の記載がないため、このフィールドは
  未設定のままにしてください。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v: このコンポーネントはこれらの表記に対して
  media の語彙を列挙していません。wan2.5-i2v-preview と wan2.6-i2v は先頭
  フレームを img_url で受け取り、wan2.6-r2v は参照クリップを reference_video_urls で受け取ります。
上記のモデルごとの個数はパートナーの制約であり、このスキーマの制約ではありません。media には
minItems/maxItems が宣言されていません。受け付け可能な type とその上限が
モデルごとに異なるためです。スキーマが受け付けることは、プロバイダーが受け付けることを意味しません。また、
逆に、上記のアセットごとの「最大 20MB」という数値は（画像
入力に対する上限であり、インラインで送信できる唯一の入力です）、パートナーが最終的に受け取る
アセットに対する上限であり、アセットが公開 URL である場合はそのまま適用されます。
そのバイト列は Comfy を経由しないためです。インラインの data:\{MIME_type};base64,...
URL は Comfy を経由するため、転送上の上限にも直面します。Comfy Router
の POST ボディは合計 100 MiB に制限され、それを超えると 413 で応答されます。また base64 は
ペイロードを約 4/3 に膨らませるため、単一のインラインアセットがおよそ 75 MB を超えると、
ここに挙げたパートナーのルールに到達する前に拒否されます。そのサイズでは、単一のアセットがパートナー自身の20MB の上限はインラインに余裕をもって収まるため、アセット 1 つの場合に制約となるのはパートナーのルールです。トランスポートの上限は複数のアセットにまたがる場合に制約となります。100 MiB の Router の上限は各要素ではなくリクエスト全体を制限するためです。これらの上限に近いものは公開 URL として送信してください。
</ParamField>

<ParamField body="input.media[].url" type="string" required>
  メディアファイルの URL。公開 HTTP/HTTPS URL、または、上記の `media` の説明がモデルごとに列挙しているまさにその IMAGE 入力（wan2.7-i2v の first_frame と last_frame、wan2.7-r2v の first_frame と reference_image、wan2.7-videoedit の reference_image、wan3.0-video と wan3.0-video-prime の first_frame、last_frame、reference_image、happyhorse-1.0-i2v と happyhorse-1.1-i2v の first_frame、happyhorse-1.0-r2v と happyhorse-1.1-r2v の reference_image、happyhorse-1.0-video-edit の reference_image）に限り、インラインの `data:{MIME_type};base64,...` URL を使用できます。これらのモデルのいずれにおいても、ビデオ、オーディオ、ファイル、リンクの入力はインラインの data: URL を受け付けません。パートナー自身のアップロードサービスによる oss://dashscope-instant の一時 URL、または（wan2.7-videoedit では）Asset Center の asset_id は、アップロードした Alibaba Cloud アカウントに対してのみ解決されます。Comfy は自身のキーでモデルを呼び出し、アップロード経路を公開していないため、呼び出し元自身の oss:// URL や asset_id はサポートされる入力ではありません。このフィールドは URL スキームを検証しないため、そのような値はここで拒否されるのではなく、そのままパートナーに転送されます。モデルごとのサイズとピクセルの制限、およびインラインのペイロードを全体として制限する 100 MiB の Router リクエストボディ上限については、`media` の説明を参照してください。
</ParamField>

<ParamField body="input.negative_prompt" type="string">

<ParamField body="input.prompt" type="string">
  テキストプロンプトの語句。中国語と英語をサポートし、長さは 800 文字を超えないこと
（wan3.0-video では最大 20,000 文字。制限を超えたコンテンツは切り詰められます）。
複数の参照ビデオを使用する wan2.6-r2v では、'character1'、'character2' などを使用して、
参照ビデオの順序に従って被写体を参照します。例: "Character1 sings on the roadside, Character2 dances beside it"
wan3.0-video の参照モードでは、'Image 1'、'Video 1'、'Audio 1' などを使用して、
media 配列内の対応する順序でメディアアセットを参照します。
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  wan2.6-r2v モデル専用の参照ビデオ URL。1～3 本のビデオ URL の配列。
入力の制限:
- 形式: mp4、mov
- 数量: 1～3 本のビデオ
- 単一ビデオの長さ: 2～30 秒
- 単一ファイルサイズ: 最大 30MB
- audio_url と併用できません
参照再生時間: 単一ビデオは最大 5 秒、2 本のビデオはそれぞれ最大 2.5 秒、3 本のビデオはそれに比例して短くなります。
課金: 実際に使用した参照再生時間に基づきます。
</ParamField>

<ParamField body="input.template" type="string">

</ParamField>

</ParamField>

<ParamField body="parameters.duration" type="integer" default="5">
  生成されるビデオの再生時間（秒）:
- wan2.5 モデル: 5 または 10 秒
- wan2.6-t2v、wan2.6-i2v: 5、10、または 15 秒
- wan2.6-r2v: 5 または 10 秒のみ（15 秒はサポートされません）
- wan2.7-i2v、wan2.7-t2v: [2, 15] の整数
- wan2.7-r2v、wan2.7-videoedit: [2, 10] の整数
- wan3.0-video: ビデオ入力なしの場合は [2, 30] の整数。ビデオ入力ありの場合は、入力
  ビデオの再生時間の合計 + 出力ビデオの再生時間が 30 秒を超えてはなりません。-1 は
  モデルが適切な再生時間を選択するスマート再生時間モードを有効にします
このプロキシは [-1, 30] の範囲外の duration に対して 400 を返します。

  範囲: `-1` ～ `30`
</ParamField>

<ParamField body="parameters.prompt_extend" type="boolean" default="true">
  プロンプトのインテリジェントな書き換えを有効にするかどうか。デフォルトは true です
</ParamField>

<ParamField body="parameters.ratio" type="string">
  生成されるビデオのアスペクト比。wan2.7 および wan3.0 モデル専用です。
wan2.7 モデルでは、指定しない場合、解像度の階層に基づいてデフォルトが決まります。
wan3.0-video では、adaptive（デフォルト）が入力メディアの比率と意図に基づいて
適切なアスペクト比を自動的に推奨します。

  指定可能な値: `adaptive`, `16:9`, `9:16`, `1:1`, `4:3`, `3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  解像度レベル。サポートされる値はモデルによって異なります:
- wan2.5-i2v-preview: 480P、720P、1080P
- wan2.6 モデル（t2v、i2v、r2v）: 720P、1080P のみ（480P はサポートされません）
- wan2.7 モデル（i2v、t2v、r2v、videoedit）: 720P、1080P（デフォルト 1080P）
- wan3.0-video, wan3.0-video-prime: 480P、720P、1080P（upstream default 1080P）
- happyhorse-1.0-*（t2v、i2v、r2v、video-edit）: 720P、1080P
- happyhorse-1.1-*（t2v、i2v、r2v）: 480P、720P、1080P
このプロキシは、resolution も size も指定されていないビデオ生成リクエストを拒否します。解像度のティアが課金レートを決定するためです。resolution はチェックの前に大文字へ変換し、大文字に変換した値をそのまま転送します。この enum に含まれない値には 400 を返し、上記で 480P がないと記載されている wan2.6、wan2.7、happyhorse-1.0 のモデルに対しては、480P（resolution として送信された場合も、480P の size として送信された場合も）に 400 を返します。

  取り得る値: `480P`、`720P`、`1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  乱数シード。モデルが生成するコンテンツのランダム性を制御するために使用します

  範囲: `0` から `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  インテリジェントなマルチレンズ制御。prompt_extend が有効な場合にのみ機能します。
wan2.6 および wan2.7-r2v モデル用。
- single: 単一ショットのビデオ（デフォルト）
- multi: マルチショットのビデオ

  取り得る値: `multi`、`single`
</ParamField>

<ParamField body="parameters.size" type="string">
  幅*高さ形式のビデオ解像度。サポートされる解像度はモデルによって異なります:
wan2.5 T2V の場合: 480P（480*832、832*480、624*624）、720P、1080P のサイズ
wan2.6 T2V/R2V の場合（480P なし）:
  720P: 1280*720、720*1280、960*960、1088*832、832*1088
  1080P: 1920*1080、1080*1920、1440*1440、1632*1248、1248*1632
size と resolution の両方を送信した場合、課金されるティアを選択するのは size であり、resolution はそのモデルに対してこのプロキシが受け付ける値である必要があります。480P の size は、resolution の説明で 480P がないと記載されているすべてのモデルで 400 を返します。
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  透かしロゴを追加するかどうか。透かしは右下隅に配置されます
</ParamField>
