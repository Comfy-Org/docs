HappyHorse 1.1 I2V の API リファレンスです。HappyHorse 1.1 の画像から動画への変換は、静止した最初のフレームをアニメーション化し、同期したセリフ、エフェクト、音楽を同じパスでレンダリングします。

**入力：** 画像, テキスト · **出力：** ビデオ

## クイックスタート

[あなたの Comfy ワークスペース](https://platform.comfy.org/profile/api-keys?onboarding=router)でキーを作成し、`COMFY_API_KEY` としてエクスポートします。Python と TypeScript のスニペットは Comfy SDK（`pip install comfy-sdk`、`npm install @comfyorg/sdk`）を使用しています。cURL のスニペットは、同じ呼び出しを生の HTTP で行うものです。

**モデル ID:** `wan/happyhorse-1.1-i2v`

**エンドポイント:** `POST https://api.comfy.org/v2/models/wan/happyhorse-1.1-i2v`

```python Python
import asyncio
from comfy_sdk import AsyncComfy

# 環境変数から COMFY_API_KEY を読み取ります。
# 各 submit() 呼び出しは独自の Idempotency-Key を発行し、自動リトライ時に再利用します。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/happyhorse-1.1-i2v",
            {
                "input": {
                    "prompt": "the robot lowers its raised arm and steps toward the camera, the flat orange backdrop holds steady",
                    "media": [
                        {
                            "type": "first_frame",
                            "url": "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # モデル ID とあわせて、別のプロセスが必要とする情報はこれだけです

        # リクエストが完了するまでポーリングし、サーバーが指定する Retry-After の時間だけ待機します。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # プロバイダー自身のペイロードで、models.run() が返すのと同じ値です。
        # 失敗またはキャンセル済みのリクエストは、ここで型付きの Router エラーを発生させます。
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())
```

## スキーマ

### 入力

<ParamField body="input" type="object" required>
  プロンプトなどの基本情報を入力します。
</ParamField>

<ParamField body="input.audio_url" type="string">
  オーディオファイルのダウンロード URL。対応形式は mp3 と wav です。reference_video_urls とは併用できません。
</ParamField>

<ParamField body="input.img_url" type="string">
  先頭フレームの画像 URL、または Base64 エンコードされたデータ。wan2.5-i2v-preview と
wan2.6-i2v モデルでは必須です。happyhorse-1.x の i2v 系の表記は、先頭フレームをここでは
受け取りません。type が first_frame の media 要素として受け取ります（後述の media を参照）。
また、wan2.6-i2v では成功する img_url のボディも、happyhorse-1.0-i2v と
happyhorse-1.1-i2v ではプロバイダーに拒否されます。wan2.7/wan3.0 の表記も同様に、
参照アセットを media で受け取ります。画像形式: JPEG、JPG、PNG、BMP、WEBP。
解像度: 360～2000 ピクセル。ファイルサイズ: 最大 10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。ビデオ生成用の参照素材（画像、オーディオ、ビデオ）を指定します。
各要素には type フィールドと url フィールドが含まれます。このフィールドは、このコンポーネントが
提供するすべてのモデルで共通です。あるモデルがどの type 値を受け入れるか、また画像や
ビデオの入力を img_url や reference_video_urls ではなくそもそもここで渡すかどうかは、
モデルごとに異なります。モデルごとの対応 type 値は次のとおりです:
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frame と
  last_frame: JPEG/JPG/PNG/BMP/WEBP、1 辺あたり 240～8000 ピクセル、アスペクト比 1:8
  ～8:1、最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。
  driving_audio（WAV/MP3、2～30 秒、最大 15MB）と first_clip（MP4/MOV、2～10
  秒、1 辺あたり 240～4096 ピクセル、最大 100MB）: 公開 HTTP/HTTPS URL。インラインの
  data: URL は受け付けられません。
- wan2.7-r2v: first_frame（任意、最大 1）、reference_image、reference_video。少なくとも
  1 つの reference_image または reference_video が必須で、参照画像と参照ビデオの合計は
  最大 5 です。first_frame と reference_image: JPEG/JPG/PNG/BMP/WEBP（アルファチャンネル
  なし）、1 辺あたり 240～8000 ピクセル、アスペクト比 1:8～8:1、最大 20MB、公開 URL
  または data:\{MIME_type};base64,... URL。reference_video: 公開 HTTP/HTTPS URL。
  インラインの data: URL は受け付けられません。
- wan2.7-videoedit: video（ちょうど 1 つ。編集対象のクリップ: MP4/MOV、2～10 秒、
  1 辺あたり 240～4096 ピクセル、最大 100MB、公開 HTTP/HTTPS URL。インラインの data:
  URL は受け付けられません）に加えて、任意で 0～4 個の reference_image（JPEG/JPG/PNG/BMP/WEBP、
  1 辺あたり 240～8000 ピクセル、アスペクト比 1:8～8:1、最大 20MB、公開 URL
  または data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime: first_frame（最大 1）、last_frame（最大 1）、
  reference_image（最大 10）、reference_video（最大 5 クリップ、合計再生時間 \<= 15s）、
  reference_audio（最大 5 クリップ、合計再生時間 \<= 15s）、file（最大 1、link とは
  併用不可）、link（最大 1、file とは併用不可）。reference_*/file/link タイプ
  と first_frame/last_frame タイプは、同じリクエスト内では相互排他的です。
  配列の順序が、プロンプト内でのアセットの参照順（Image 1、Video 1、Audio 1、...）を
  定義します。first_frame、last_frame、reference_image: JPEG/JPG/PNG/BMP/WEBP、
  1 辺あたり 240～8000 ピクセル、アスペクト比は最大 8:1、最大 20MB、公開 URL または
  data:\{MIME_type};base64,... URL。reference_video、reference_audio、file、link:
  公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v: first_frame のみ、ちょうど 1 つ。これらの
  表記では先頭フレームをここで受け取り、img_url では受け取りません。最低 300x300
  ピクセル、アスペクト比 1:2.5～2.5:1、JPEG/JPG/PNG/WEBP、最大 20MB、公開 URL または
  data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v: reference_image のみ、1～9 個。これはこの
  モデル唯一の参照入力です。最短辺が最低 400 ピクセル、JPEG/JPG/PNG/WEBP、
  最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。reference_video は
  この操作の入力タイプではありません。
- happyhorse-1.0-video-edit: video（ちょうど 1 つ。編集対象のクリップ: MP4/MOV、3～60
  秒、長辺が最大 4096 ピクセル、短辺が最低 360 ピクセル、アスペクト比 1:2.5～2.5:1、
  最大 100MB、公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません）に
  加えて、任意で 0～5 個の reference_image（JPEG/JPG/PNG/WEBP、最低 300x300 ピクセル、
  アスペクト比 1:2.5～2.5:1、最大 20MB、公開 URL または data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview:
  テキストから動画への操作です。これらのパートナーリファレンスには media 入力の記載が
  ないため、このフィールドは未設定のままにしてください。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v: このコンポーネントはこれらの表記に対する
  media の語彙を列挙していません。wan2.5-i2v-preview と wan2.6-i2v は先頭フレームを
  img_url で受け取り、wan2.6-r2v は参照クリップを reference_video_urls で受け取ります。
上記のモデルごとの個数は、このスキーマの制約ではなくパートナーの制約です。media に
minItems/maxItems は宣言されていません。受け入れ可能なタイプとその上限はモデルごとに
異なるためです。スキーマが受け入れても、プロバイダーが受け入れるとは限りません。逆に、
上記のアセットごとの「最大 20MB」という数値は、画像入力に対する上限であり、インラインで
送信できる唯一の入力でもあります。これらは最終的に受け取るアセットに対するパートナーの
上限であり、アセットが公開 URL の場合は、そのバイトが Comfy を経由しないため、記載どおりに
適用されます。インラインの data:\{MIME_type};base64,... URL は Comfy を経由するため、
転送時の上限にも直面します。Comfy Router の POST ボディは合計 100 MiB に制限され、それを
超えると 413 で応答されます。また base64 はペイロードを約 4/3 に膨らませるため、およそ
75 MB を超える単一のインラインアセットは、ここに挙げたパートナーのルールのいずれかに
到達する前に拒否されます。そのサイズでは、パートナー自身の単一アセットが20MB の上限はインラインで問題なく収まるため、アセット 1 件ではパートナーのルールが制約となります。一方、転送の上限は複数のアセットにまたがる場合に効いてきます。100 MiB の Router 上限は個々の要素ではなくリクエスト全体を制限するためです。これらの上限に近いものは、パブリック URL として送信してください。
</ParamField>

<ParamField body="input.media[].type" type="string" required>
  メディアアセットの種類

  指定可能な値: `first_frame`、`last_frame`、`driving_audio`、`first_clip`、`reference_image`、`reference_video`、`reference_audio`、`video`、`file`、`link`

<ParamField body="input.media[].url" type="string" required>
  メディアファイルの URL。パブリックな HTTP/HTTPS URL、または、上記の `media` の説明がモデルごとに列挙しているまさに IMAGE 入力（wan2.7-i2v では first_frame と last_frame、wan2.7-r2v では first_frame と reference_image、wan2.7-videoedit では reference_image、wan3.0-video と wan3.0-video-prime では first_frame、last_frame、reference_image、happyhorse-1.0-i2v と happyhorse-1.1-i2v では first_frame、happyhorse-1.0-r2v と happyhorse-1.1-r2v では reference_image、happyhorse-1.0-video-edit では reference_image）に対しては、インラインの `data:{MIME_type};base64,...` URL を指定できます。これらのモデルのいずれでも、video、audio、file、link の入力はインラインの data: URL を受け付けません。パートナー自身のアップロードサービスによる oss://dashscope-instant の一時 URL、または（wan2.7-videoedit では）Asset Center の asset_id は、それをアップロードした Alibaba Cloud アカウントに対してのみ解決されます。Comfy は自身のキーでモデルを呼び出し、アップロード経路を公開していないため、呼び出し元自身の oss:// URL や asset_id はサポートされる入力ではありません。このフィールドは URL スキームを検証しないため、そのような値はここで拒否されず、そのままパートナーに転送されます。モデルごとのサイズとピクセルの制限、およびインラインのペイロードを全体として制限する 100 MiB の Router リクエストボディ上限については、`media` の説明を参照してください。
</ParamField>

<ParamField body="input.negative_prompt" type="string">

<ParamField body="input.prompt" type="string">
  テキストプロンプト。中国語と英語をサポートし、長さは 800 文字以内です
（wan3.0-video では最大 20,000 文字。制限を超えたコンテンツは切り捨てられます）。
複数の参照ビデオを指定する wan2.6-r2v では、参照ビデオの順序に合わせて
被写体を 'character1'、'character2' などで参照します。例: 「Character1 が道端で歌い、Character2 がそのそばで踊る」
wan3.0-video の参照モードでは、media 配列内の対応する順序で
メディアアセットを 'Image 1'、'Video 1'、'Audio 1' などで参照します。
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  wan2.6-r2v モデル専用の参照ビデオ URL。1～3 本のビデオ URL の配列。
入力の制限:
- フォーマット: mp4、mov
- 本数: 1～3 本のビデオ
- 1 本あたりのビデオの長さ: 2～30 秒
- 1 ファイルあたりのサイズ: 最大 30MB
- audio_url と併用できません
参照の再生時間: ビデオ 1 本の場合は最大 5 秒、2 本の場合は各最大 2.5 秒、3 本の場合はそれに比例して短くなります。
課金: 実際に使用した参照の再生時間に基づきます。
</ParamField>

<ParamField body="input.template" type="string">
  ビデオエフェクトテンプレート名。任意。現在サポートされている値: squish、flying、carousel。使用した場合、prompt パラメータは無視されます。
</ParamField>

<ParamField body="model" type="string">

</ParamField>

- wan2.7 モデル（i2v、t2v、r2v、videoedit）: 720P、1080P（デフォルト 1080P）
- wan3.0-video、wan3.0-video-prime: 480P、720P、1080P（上流のデフォルト 1080P）このプロキシは、解像度もサイズも指定していないビデオ生成リクエストを拒否します。解像度のティアによって課金レートが決まるためです。
