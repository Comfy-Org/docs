Wan 2.7 T2V の API リファレンス。Wan 2.7 のテキストから動画へは、プロンプトのみから 720P または 1080P、2～15 秒の短いビデオを生成します。

**入力：** テキスト · **出力：** ビデオ + オーディオ

## クイックスタート

[Comfy ワークスペース](https://platform.comfy.org/profile/api-keys?onboarding=router)でキーを作成し、`COMFY_API_KEY` としてエクスポートします。Python と TypeScript のスニペットは Comfy SDK（`pip install comfy-sdk` および `npm install @comfyorg/sdk`）を使用しており、cURL スニペットは同じ呼び出しを生の HTTP で行うものです。

**モデル ID:** `wan/wan2.7-t2v`

**エンドポイント:** `POST https://api.comfy.org/v2/models/wan/wan2.7-t2v`

同じボディを `POST https://api.comfy.org/v2/models/wan/wan2.7-t2v/requests` に送信します。Router は実行が受け付けられるとすぐに `201` と `request_id` を返し、結果は準備ができ次第、このプロセスからでも別のプロセスからでも収集できます。[キュー配信](/ja/development/comfy-router/queue)では、ステータス、キャンセル、収集について説明します。

```python Python
import asyncio
from comfy_sdk import AsyncComfy

# 環境変数から COMFY_API_KEY を読み取ります。
# submit() の呼び出しごとに独自の Idempotency-Key が発行され、自動リトライで再利用されます。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/wan2.7-t2v",
            {
                "input": {
                    "prompt": "a single red maple leaf falling onto still water, slow motion, shallow depth of field",
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # モデル ID と合わせれば、別のプロセスに必要な情報はこれだけです

        # リクエストが完了するまでポーリングし、サーバーが指定した Retry-After の秒数だけ待機します。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # プロバイダー自身のペイロードで、models.run() が返す値と同じです。
        # 失敗またはキャンセル済みのリクエストは、ここで型付きの Router エラーを発生させます。
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// 環境変数から COMFY_API_KEY を読み取ります。
// submit() の呼び出しごとに独自の Idempotency-Key が発行され、自動リトライで再利用されます。
type Result = { output: { video_url: string } };
const handle = await comfy.models.submit<Result>("wan/wan2.7-t2v", {
  input: {
    prompt: "a single red maple leaf falling onto still water, slow motion, shallow depth of field",
  },
  parameters: {
    resolution: "720P",
    duration: 5,
  },
});
console.log("requestId:", handle.requestId); // モデル ID と合わせれば、別のプロセスに必要な情報はこれだけです

// リクエストが完了するまでポーリングし、サーバーが指定した Retry-After の秒数だけ待機します。
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// models.run() が返すのと同じ結果です。失敗またはキャンセル済みのリクエストは、ここで reject されます。
const result = await handle.get();
if (result.kind !== "json") throw new Error("expected a JSON result");

console.log("video:", result.data.output.video_url);
```

## スキーマ

### 入力

<ParamField body="input" type="object" required>
  プロンプトの語句などの基本情報を入力します。
</ParamField>

<ParamField body="input.audio_url" type="string">
  オーディオファイルのダウンロードURL。対応形式：mp3 と wav。reference_video_urls とは併用できません。
</ParamField>

<ParamField body="input.img_url" type="string">
  先頭フレーム画像の URL、または Base64 エンコードされたデータ。wan2.5-i2v-preview と
wan2.6-i2v モデルでは必須です。happyhorse-1.x の i2v 系スペルはここで先頭フレームを
受け取りません。先頭フレームは type が first_frame のメディア要素として受け取ります
（後述の media を参照）。また、wan2.6-i2v では成功する img_url ボディも、
happyhorse-1.0-i2v と happyhorse-1.1-i2v ではプロバイダーに拒否されます。wan2.7/wan3.0
系のスペルも参照アセットを media で受け取ります。画像形式：JPEG、JPG、PNG、BMP、WEBP。
解像度：360～2000 ピクセル。ファイルサイズ：最大 10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。動画生成用の参照素材（画像、オーディオ、ビデオ）を指定します。各要素は type フィールドと url フィールドを持ちます。このフィールドはこのコンポーネントから提供されるすべてのモデルで共通ですが、どの type 値を受け付けるか、また画像やビデオの入力を img_url や reference_video_urls ではなくここで渡すかどうかは、モデルごとに異なります。モデルごとの対応 type 値：
- wan2.7-i2v：first_frame、last_frame、driving_audio、first_clip。first_frame と
  last_frame：JPEG/JPG/PNG/BMP/WEBP、1辺 240～8000 ピクセル、アスペクト比 1:8～
  8:1、最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。
  driving_audio（WAV/MP3、2～30 秒、最大 15MB）と first_clip（MP4/MOV、2～10
  秒、1辺 240～4096 ピクセル、最大 100MB）：公開 HTTP/HTTPS URL。インラインの
  data: URL は受け付けられません。
- wan2.7-r2v：first_frame（省略可能、最大 1）、reference_image、reference_video。
  reference_image または reference_video を少なくとも 1 つ指定する必要があり、参照
  画像と参照ビデオを合計しても最大 5 つです。first_frame と reference_image：JPEG/JPG/PNG/BMP/WEBP
  （アルファチャンネルなし）、1辺 240～8000 ピクセル、アスペクト比 1:8～8:1、最大
  20MB、公開 URL または data:\{MIME_type};base64,... URL。reference_video：公開
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-videoedit：video（ちょうど 1 つ、編集対象のクリップ：MP4/MOV、2～10 秒、
  1辺 240～4096 ピクセル、最大 100MB、公開 HTTP/HTTPS URL。インラインの data: URL
  は受け付けられません）と、省略可能な 0～4 個の reference_image（JPEG/JPG/PNG/BMP/WEBP、
  1辺 240～8000 ピクセル、アスペクト比 1:8～8:1、最大 20MB、公開 URL
  または data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime：first_frame（最大 1）、last_frame（最大 1）、
  reference_image（最大 10）、reference_video（最大 5 クリップ、合計再生時間 \<= 15 秒）、
  reference_audio（最大 5 クリップ、合計再生時間 \<= 15 秒）、file（最大 1、link と
  併用不可）、link（最大 1、file と併用不可）。reference_*/file/link の各 type
  と first_frame/last_frame の各 type は、同一リクエスト内で同時に使用できません。
  配列の順序が、プロンプト内でのアセットの参照順序を定義します（Image 1、Video 1、
  Audio 1、...）。first_frame、last_frame、reference_image：JPEG/JPG/PNG/BMP/WEBP、
  1辺 240～8000 ピクセル、アスペクト比 最大 8:1、最大 20MB、公開 URL または
  data:\{MIME_type};base64,... URL。reference_video、reference_audio、file、link：
  公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v：first_frame のみ、ちょうど 1 つ。これらの
  スペルは先頭フレームを HERE（ここ）で受け取り、img_url では受け取りません。最低
  300x300 ピクセル、アスペクト比 1:2.5～2.5:1、JPEG/JPG/PNG/WEBP、最大 20MB、公開
  URL または data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v：reference_image のみ、1～9 個。これがこの
  モデル唯一の参照入力です。最短辺 最低 400 ピクセル、JPEG/JPG/PNG/WEBP、最大
  20MB、公開 URL または data:\{MIME_type};base64,... URL。reference_video は
  この操作の入力 type ではありません。
- happyhorse-1.0-video-edit：video（ちょうど 1 つ、編集対象のクリップ：MP4/MOV、3～
  60 秒、長辺 最大 4096 ピクセル、短辺 最低 360 ピクセル、アスペクト比 1:2.5～
  2.5:1、最大 100MB、公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられ
  ません）と、省略可能な 0～5 個の reference_image（JPEG/JPG/PNG/WEBP、最低
  300x300 ピクセル、アスペクト比 1:2.5～2.5:1、最大 20MB、公開 URL または
  data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview：
  テキストから動画への操作。これらのパートナーリファレンスには media 入力が記載されていないため、
  このフィールドは未設定のままにしてください。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v：このコンポーネントはこれらのスペルに
  ついて media の語彙を何も定義していません。wan2.5-i2v-preview と wan2.6-i2v は先頭
  フレームを img_url で受け取り、wan2.6-r2v は参照クリップを reference_video_urls で
  受け取ります。
上記のモデルごとの個数はこのスキーマの制約ではなく、パートナーの制約です。media には
minItems/maxItems が宣言されていません。許容される type とその上限がモデルごとに異なる
ためです。スキーマが受け入れたからといってプロバイダーが受け入れるとは限りません。
逆の向きについても、上記のアセットごとの「最大 20MB」という数値（画像入力の上限であり、
インラインで送信できる唯一の入力です）は、最終的にパートナーが受け取るアセットに対する
パートナーの上限であり、アセットが公開 URL の場合はそのまま適用されます。そのバイト列が
Comfy を経由することはないためです。インラインの data:\{MIME_type};base64,...
URL は Comfy を経由するため、転送時の上限にも直面します。Comfy Router の POST ボディは
合計 100 MiB に制限されており、それを超えると 413 が返されます。また base64 はペイロードを
約 4/3 に膨張させるため、約 75 MB を超える単一のインラインアセットは、ここに示した
パートナーのルールに到達する前に拒否されます。そのサイズでは、パートナー自身の20MBの上限はインラインで問題なく収まるため、1つのアセットについてはパートナーのルールが制約となります。トランスポートの上限は複数のアセットにまたがる場合に制約となります。これは、100 MiB という Router の上限が各要素ではなくリクエスト全体を制限するためです。これらの上限に近いものはすべてパブリック URL として送信してください。
</ParamField>

<ParamField body="input.media[].type" type="string" required>
  メディアアセットのタイプ

  指定可能な値: `first_frame`、`last_frame`、`driving_audio`、`first_clip`、`reference_image`、`reference_video`、`reference_audio`、`video`、`file`、`link`
</ParamField>

<ParamField body="input.media[].url" type="string" required>
  メディアファイルの URL。パブリックな HTTP/HTTPS URL、または（上記の `media` の説明が各モデルについて列挙している IMAGE 入力、すなわち wan2.7-i2v の first_frame と last_frame、wan2.7-r2v の first_frame と reference_image、wan2.7-videoedit の reference_image、wan3.0-video と wan3.0-video-prime の first_frame、last_frame、reference_image、happyhorse-1.0-i2v と happyhorse-1.1-i2v の first_frame、happyhorse-1.0-r2v と happyhorse-1.1-r2v の reference_image、happyhorse-1.0-video-edit の reference_image に対してのみ）インラインの `data:{MIME_type};base64,...` URL。これらのモデルのいずれにおいても、video、audio、file、link の入力はインラインの data: URL を受け付けません。パートナー自身のアップロードサービスによる oss://dashscope-instant の一時 URL、または（wan2.7-videoedit では）Asset Center の asset_id は、それをアップロードした Alibaba Cloud アカウントに対してのみ解決されます。Comfy は自身のキーでモデルを呼び出し、アップロード経路を公開していないため、呼び出し元自身の oss:// URL や asset_id はサポートされる入力ではありません。このフィールドは URL スキームを検証しないため、そのような値はここで拒否されることなく、そのままパートナーに転送されます。モデルごとのサイズとピクセルの制限、およびインラインペイロードを全体として制限する 100 MiB の Router リクエストボディ上限については、`media` の説明を参照してください。
</ParamField>

<ParamField body="input.negative_prompt" type="string">
  ネガティブプロンプトは、ビデオ画面に表示したくないコンテンツを記述するために使用します
</ParamField>

<ParamField body="input.prompt" type="string">
  テキストプロンプト。中国語と英語をサポートし、長さは 800 文字以内です
（wan3.0-video では最大 20,000 文字。制限を超えたコンテンツは切り捨てられます）。
複数の参照ビデオを指定する wan2.6-r2v では、参照ビデオの順序に従って被写体を指すために「character1」「character2」などを使用します。例: "Character1 sings on the roadside, Character2 dances beside it"
wan3.0-video の参照モードでは、media 配列内の対応する順序でメディアアセットを指すために「Image 1」「Video 1」「Audio 1」などを使用します。
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  wan2.6-r2v モデル専用の参照ビデオ URL。1～3 本のビデオ URL の配列。
入力の制限:
- フォーマット: mp4、mov
- 数量: 1～3 本のビデオ
- 単一ビデオの長さ: 2～30 秒
- 単一ファイルサイズ: 最大 30MB
- audio_url と併用できません
参照再生時間: 単一ビデオは最大 5 秒、2 本の場合はそれぞれ最大 2.5 秒、3 本の場合はそれに比例して短くなります。
課金: 実際に使用された参照再生時間に基づきます。
</ParamField>

<ParamField body="input.template" type="string">
  ビデオエフェクトのテンプレート名。任意。現在サポートされているのは squish、flying、carousel です。使用すると、prompt パラメータは無視されます。
</ParamField>

<ParamField body="model" type="string">
  呼び出すモデルの ID。このコンポーネントでは制約されません。Comfy Router が `POST /v2/models/wan/{model}` の `{model}` パスセグメントから設定するため、Router の呼び出し元はこれを省略します。`POST /proxy/wan/api/v1/services/aigc/video-generation/video-synthesis` への直接の v1 呼び出しでは必ず指定する必要があり、受け付けられる表記の enum はその操作自身のコンポーネント `WanVideoGenerationRequest` にあります。
</ParamField>

<ParamField body="parameters" type="object">
  ビデオ処理パラメータ
</ParamField>

<ParamField body="parameters.audio" type="boolean" default="true">
  ビデオにオーディオを追加するかどうか。wan3.0-video と wan3.0-video-prime のみでサポートされます。プロバイダーは他の wan モデルについてそのような切り替えを文書化していません。
</ParamField>

<ParamField body="parameters.audio_setting" type="string" default="&quot;auto&quot;">
  wan2.7-videoedit モデルのビデオオーディオ設定。
- auto（デフォルト）: モデルがプロンプトのコンテンツに基づいてインテリジェントに判断します
- origin: 入力ビデオのオリジナルオーディオを強制的に保持します

  指定可能な値: `auto`、`origin`
</ParamField>

<ParamField body="parameters.duration" type="integer" default="5">
  生成されるビデオの長さ（秒）:
- wan2.5 モデル: 5 または 10 秒
- wan2.6-t2v、wan2.6-i2v: 5、10、または 15 秒
- wan2.6-r2v: 5 または 10 秒のみ（15 秒は非サポート）
- wan2.7-i2v、wan2.7-t2v: [2, 15] の整数
- wan2.7-r2v、wan2.7-videoedit: [2, 10] の整数
- wan3.0-video: ビデオ入力なしの場合は [2, 30] の整数。ビデオ入力を指定する場合は、
  入力ビデオの長さと出力ビデオの長さの合計が 30 秒を超えてはなりません。-1 を指定すると
  スマート再生時間モードが有効になり、モデルが適切な長さを選択します

  範囲: `-1` ～ `30`
</ParamField>

<ParamField body="parameters.prompt_extend" type="boolean" default="true">
  プロンプトのインテリジェントな書き換えを有効にするかどうか。デフォルトは true です
</ParamField>

<ParamField body="parameters.ratio" type="string">
  生成されるビデオのアスペクト比。wan2.7 および wan3.0 モデル専用です。
wan2.7 モデルでは、指定しない場合は解像度ティアに基づいてデフォルトが決まります。
wan3.0-video では、adaptive（デフォルト）が入力メディアの比率と意図に基づいて
適切なアスペクト比を自動的に推奨します。

  指定可能な値: `adaptive`、`16:9`、`9:16`、`1:1`、`4:3`、`3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  解像度レベル。サポートされる値はモデルによって異なります:
- wan2.5-i2v-preview: 480P、720P、1080P
- wan2.6-i2v: 720P、1080P のみ（480P は非サポート）
- wan2.7 モデル（i2v、t2v、r2v、videoedit）: 720P、1080P（デフォルト 1080P）
- wan3.0-video、wan3.0-video-prime: 480P、720P、1080P（上流のデフォルトは 1080P）このプロキシは、解像度とサイズのどちらも指定していないビデオ生成リクエストを拒否します。解像度のティアが課金レートを決定するためです。

  指定可能な値: `480P`、`720P`、`1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  乱数シード。モデルが生成するコンテンツのランダム性を制御するために使用します

  範囲: `0` から `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  インテリジェントなマルチレンズ制御。prompt_extend が有効な場合にのみ機能します。
wan2.6 および wan2.7-r2v モデル用。
- single: シングルショットビデオ（デフォルト）
- multi: マルチショットビデオ

  指定可能な値: `multi`、`single`
</ParamField>

<ParamField body="parameters.size" type="string">
  幅*高さ形式のビデオ解像度。対応解像度はモデルによって異なります:
wan2.5 T2V の場合: 480P (480*832、832*480、624*624)、720P、1080P の各サイズ
wan2.6 T2V/R2V の場合（480P なし）:
  720P: 1280*720、720*1280、960*960、1088*832、832*1088
  1080P: 1920*1080、1080*1920、1440*1440、1632*1248、1248*1632
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  ウォーターマークロゴを追加するかどうか。ウォーターマークは右下隅に配置されます
</ParamField>

Router が `GET /v2/models/wan/wan2.7-t2v/openapi.json` で提供するスキーマから生成されています。これは、リクエストがプロバイダーに到達する前に呼び出しの検証に使用されるものと同じドキュメントです。
