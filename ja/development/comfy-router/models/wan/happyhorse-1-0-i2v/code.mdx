import asyncio
from comfy_sdk import AsyncComfy

# 環境変数から COMFY_API_KEY を読み取ります。
# 各 submit() 呼び出しは独自の Idempotency-Key を発行し、自動リトライで再利用します。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/happyhorse-1.0-i2v",
            {
                "input": {
                    "prompt": "the robot lowers its raised arm and steps toward the camera, the flat orange backdrop holds steady",
                    "media": [
                        {
                            "type": "first_frame",
                            "url": "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # モデル ID と合わせて、別のプロセスに必要なものはこれだけです

        # リクエストが完了するまでポーリングし、サーバーが指定する Retry-After だけ待機します。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # プロバイダー自身のペイロードで、models.run() が返す値と同じです。
        # 失敗またはキャンセルされたリクエストは、ここで型付きの Router エラーを発生させます。
        result = await handle.get()

    print("video:", result["output"]["video_url"])

  プロンプト文などの基本情報を入力します。
</ParamField>

<ParamField body="input.audio_url" type="string">
  音声ファイルのダウンロードURL。対応形式: mp3、wav。reference_video_urls と併用できません。
</ParamField>

<ParamField body="input.img_url" type="string">
  最初のフレーム画像のURL、またはBase64エンコードされたデータ。wan2.5-i2v-preview および
wan2.6-i2v モデルでは必須です。happyhorse-1.x の i2v 表記では、最初のフレームをここでは
受け取りません。最初のフレームは type が first_frame のメディア要素として受け取ります
（下記の media を参照）。wan2.6-i2v で成功する img_url ボディは、happyhorse-1.0-i2v および
happyhorse-1.1-i2v ではプロバイダーに拒否されます。また wan2.7/wan3.0 の表記でも参照
アセットは media で受け取ります。画像形式: JPEG、JPG、PNG、BMP、WEBP。
解像度: 360〜2000 ピクセル。ファイルサイズ: 最大 10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。動画生成のための参照素材（画像、オーディオ、ビデオ）を指定します。
各要素は type と url フィールドを持ちます。このフィールドはこのコンポーネントから提供される
すべてのモデルで共通であり、あるモデルがどの type 値を受け付けるのか、また画像やビデオの入力を
img_url や reference_video_urls ではなくここで行うのかどうかは、モデルによって異なります。
モデルごとの対応 type 値:
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frame と
  last_frame: JPEG/JPG/PNG/BMP/WEBP、1辺あたり 240〜8000 ピクセル、アスペクト比 1:8〜8:1、
  最大 20MB、パブリック URL または data:\{MIME_type};base64,... URL。
  driving_audio（WAV/MP3、2〜30 秒、最大 15MB）と first_clip（MP4/MOV、2〜10 秒、
  1辺あたり 240〜4096 ピクセル、最大 100MB）: パブリックな HTTP/HTTPS URL。
  インラインの data: URL は受け付けられません。
- wan2.7-r2v: first_frame（任意、最大 1）、reference_image、reference_video。少なくとも
  1 つの reference_image または reference_video が必要で、reference_image と
  reference_video の合計は最大 5 です。first_frame と reference_image: JPEG/JPG/PNG/BMP/WEBP
  （アルファチャンネルなし）、1辺あたり 240〜8000 ピクセル、アスペクト比 1:8〜8:1、最大
  20MB、パブリック URL または data:\{MIME_type};base64,... URL。reference_video: パブリックな
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-videoedit: video（ちょうど 1 つ、編集対象のクリップ: MP4/MOV、2〜10 秒、
  1辺あたり 240〜4096 ピクセル、最大 100MB、パブリックな HTTP/HTTPS URL。インラインの data: URL
  は受け付けられません）に加えて、任意で 0〜4 個の reference_image（JPEG/JPG/PNG/BMP/WEBP、
  1辺あたり 240〜8000 ピクセル、アスペクト比 1:8〜8:1、最大 20MB、パブリック URL
  または data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime: first_frame（最大 1）、last_frame（最大 1）、
  reference_image（最大 10）、reference_video（最大 5 クリップ、合計再生時間 \<= 15 秒）、
  reference_audio（最大 5 クリップ、合計再生時間 \<= 15 秒）、file（最大 1、link と併用不可）、
  link（最大 1、file と併用不可）。reference_*/file/link タイプと first_frame/last_frame タイプは
  同じリクエスト内では排他的です。配列の順序がプロンプト内でのアセットの参照順序を定義します
  （Image 1、Video 1、Audio 1、...）。first_frame、last_frame、reference_image: JPEG/JPG/PNG/BMP/WEBP、
  1辺あたり 240〜8000 ピクセル、アスペクト比最大 8:1、最大 20MB、パブリック URL または
  data:\{MIME_type};base64,... URL。reference_video、reference_audio、file、link: パブリックな
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v: first_frame のみ、ちょうど 1 つ。これらの表記では
  最初のフレームをここで受け取り、img_url では受け取りません。少なくとも 300x300 ピクセル、
  アスペクト比 1:2.5〜2.5:1、JPEG/JPG/PNG/WEBP、最大 20MB、パブリック URL または
  data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v: reference_image のみ、1〜9 個。これがこのモデルの
  唯一の参照入力です。最短辺が少なくとも 400 ピクセル、JPEG/JPG/PNG/WEBP、最大 20MB、
  パブリック URL または data:\{MIME_type};base64,... URL。reference_video はこの操作の
  入力タイプではありません。
- happyhorse-1.0-video-edit: video（ちょうど 1 つ、編集対象のクリップ: MP4/MOV、3〜60 秒、
  長辺が最大 4096 ピクセル、短辺が少なくとも 360 ピクセル、アスペクト比 1:2.5〜2.5:1、
  最大 100MB、パブリックな HTTP/HTTPS URL。インラインの data: URL は受け付けられません）に
  加えて、任意で 0〜5 個の reference_image（JPEG/JPG/PNG/WEBP、少なくとも 300x300 ピクセル、
  アスペクト比 1:2.5〜2.5:1、最大 20MB、パブリック URL または data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview:
  テキストから動画への操作。これらの表記に対応するパートナーのリファレンスにはメディア入力が
  記載されていないため、このフィールドは未設定のままにしてください。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v: このコンポーネントはこれらの表記に対して
  media の語彙を列挙していません。wan2.5-i2v-preview と wan2.6-i2v は最初のフレームを
  img_url で受け取り、wan2.6-r2v は参照クリップを reference_video_urls で受け取ります。
上記のモデルごとの個数はこのスキーマの制約ではなく、パートナーの制約です。media には
minItems/maxItems が宣言されていません。許容される type とその上限はモデルごとに異なるためです。
スキーマが受け付けることはプロバイダーが受け付けることを意味しません。逆方向についても、
上記のアセットごとの「最大 20MB」という数値は、インラインで送信できる唯一の入力である画像入力の
上限であり、パートナーが最終的に受け取るアセットに対する上限です。アセットがパブリック URL の
場合はそのまま適用されます。そのバイト列は Comfy を経由しないためです。インラインの
data:\{MIME_type};base64,... URL は Comfy を経由するため、転送上の上限にも直面します。
Comfy Router の POST ボディは合計 100 MiB に制限され、超えると 413 が返されます。また base64 は
ペイロードを約 4/3 に膨らませるため、およそ 75 MB を超える単一のインラインアセットは、ここに
挙げたパートナーのルールに到達する前に拒否されます。そのサイズでは、パートナー自身の20MB の上限はインラインでも余裕を持って収まるため、アセット 1 つの場合はパートナーのルールが制約となります。複数のアセットにまたがる場合はトランスポートの上限が制約となります。100 MiB の Router の上限は個々の要素ではなくリクエスト全体を制限するためです。これらの上限に近いものはパブリック URL として送信してください。
</ParamField>

<ParamField body="input.media[].url" type="string" required>
  メディアファイルの URL: パブリックな HTTP/HTTPS URL、または（上記の `media` の説明で各モデルについて列挙されている IMAGE 入力、すなわち wan2.7-i2v の first_frame と last_frame、wan2.7-r2v の first_frame と reference_image、wan2.7-videoedit の reference_image、wan3.0-video と wan3.0-video-prime の first_frame、last_frame、reference_image、happyhorse-1.0-i2v と happyhorse-1.1-i2v の first_frame、happyhorse-1.0-r2v と happyhorse-1.1-r2v の reference_image、happyhorse-1.0-video-edit の reference_image に限ります）インラインの `data:{MIME_type};base64,...` URL。これらのモデルのいずれにおいても、ビデオ、オーディオ、ファイル、リンクの入力はインラインの data: URL を受け付けません。パートナー自身のアップロードサービスによる oss://dashscope-instant の一時 URL、または（wan2.7-videoedit では）Asset Center の asset_id は、それをアップロードした Alibaba Cloud アカウントに対してのみ解決されます。Comfy は自身のキーでモデルを呼び出し、アップロード経路を公開しないため、呼び出し元自身の oss:// URL や asset_id はサポートされる入力ではありません。このフィールドは URL スキームを検証しないため、そのような値はここで拒否されず、そのままパートナーへ転送されます。モデルごとのサイズとピクセルの上限、およびインラインペイロードを全体として制限する 100 MiB の Router リクエストボディ上限については、`media` の説明を参照してください。
</ParamField>

<ParamField body="input.negative_prompt" type="string">
  逆プロンプトの言葉は、ビデオ画面に表示したくないコンテンツを記述するために使用します。500 文字を超えると、wan モデルは拒否せずに切り捨てます。これは prompt と同じ入力予算にカウントされます。

<ParamField body="input.prompt" type="string">
  テキストプロンプトの言葉。中国語と英語をサポートします。文書化された長さを超えると、wan2.x モデルはプロンプトを拒否せずに切り捨てます。wan2.5 と wan2.6 では 1,500 文字、wan2.7 では 5,000 文字です。wan3.0-video と wan3.0-video-prime は最大 20,000 文字を受け付けます。プロバイダーは、prompt と negative_prompt を合わせて約 60,850 バイトの UTF-8 テキスト（約 20,000 の中国語文字）を超えるリクエストを拒否し、InvalidParameter `Range of input length should be [1, 61440]` を返します。
複数の参照ビデオを使う wan2.6-r2v では、参照ビデオの順序に従って被写体を指すために 'character1'、'character2' などを使用します。例: "Character1 sings on the roadside, Character2 dances beside it"
wan3.0-video の参照モードでは、media 配列内の対応する順序でメディアアセットを指すために 'Image 1'、'Video 1'、'Audio 1' などを使用します。
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  wan2.6-r2v モデル専用の参照ビデオ URL。1〜3 本のビデオ URL の配列。
入力の制限:
- 形式: mp4、mov
- 数量: 1〜3 本のビデオ
- 単一ビデオの長さ: 2〜30 秒
- 単一ファイルサイズ: 最大 30MB
- audio_url と併用できません
参照の再生時間: 単一ビデオは最大 5 秒、2 本の場合はそれぞれ最大 2.5 秒、3 本の場合は比例して短くなります。
課金: 使用した実際の参照再生時間に基づきます。
</ParamField>

<ParamField body="parameters.duration" type="integer" default="5">

- wan2.6-r2v: 5 秒または 10 秒のみ（15 秒はサポートされません）
- wan2.7-i2v、wan2.7-t2v: [2, 15] の整数
- wan2.7-r2v、wan2.7-videoedit: [2, 10] の整数
- wan3.0-video: ビデオ入力なしの場合は [2, 30] の整数。ビデオ入力がある場合、
  入力ビデオの再生時間と出力ビデオの再生時間の合計は 30 秒を超えてはなりません。-1 を指定すると
  スマート再生時間モードが有効になり、モデルが適切な再生時間を選択します

<ParamField body="parameters.resolution" type="string">

- wan2.5-i2v-preview: 480P、720P、1080P
- wan2.6 モデル (t2v、i2v、r2v): 720P、1080P のみ (480P 非サポート)
- wan2.7 モデル (i2v、t2v、r2v、videoedit): 720P、1080P (デフォルト 1080P)
- wan3.0-video、wan3.0-video-prime: 480P、720P、1080P (上流のデフォルト 1080P)
- happyhorse-1.0-* (t2v、i2v、r2v、video-edit): 720P、1080P
- happyhorse-1.1-* (t2v、i2v、r2v): 480P、720P、1080P
このプロキシは、resolution も size も指定されていないビデオ生成リクエストを拒否します。resolution のティアが課金レートを決めるためです。チェックの前に resolution を大文字化して転送し、この列挙にない値には 400 を返します。また、上記で 480P 非対応と記載されている wan2.6、wan2.7、happyhorse-1.0 の各モデルでは、480P (resolution として送信された場合も、480P の size として送信された場合も) に対して 400 を返します。

  指定可能な値: `480P`、`720P`、`1080P`
</ParamField>

- multi: マルチショットのビデオ

<ParamField body="parameters.size" type="string">

wan2.5 T2V の場合: 480P (480*832、832*480、624*624)、720P、1080P の各サイズ
wan2.6 T2V/R2V の場合 (480P なし):
  720P: 1280*720、720*1280、960*960、1088*832、832*1088
  1080P: 1920*1080、1080*1920、1440*1440、1632*1248、1248*1632
size と resolution の両方を送信した場合、課金ティアを選択するのは size で、
resolution はそのモデルに対してこのプロキシが受け付ける値である必要があります。480P の size は、

</ParamField>
