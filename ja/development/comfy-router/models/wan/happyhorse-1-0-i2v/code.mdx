from comfy_sdk import AsyncComfy

# 環境変数から COMFY_API_KEY を読み取ります。
# 各 submit() 呼び出しは独自の Idempotency-Key を発行し、自動リトライで再利用します。
async def main():

        handle = await client.models.submit(

                    "media": [

                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # モデル ID と合わせて、別のプロセスに必要なものはこれだけです

        # リクエストが完了するまでポーリングし、サーバーが指定する Retry-After だけ待機します。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # プロバイダー自身のペイロードで、models.run() が返す値と同じです。
        # 失敗またはキャンセルされたリクエストは、ここで型付きの Router エラーを発生させます。

### 入力

<ParamField body="input" type="object" required>
  プロンプトワードなどの基本情報を入力します。
</ParamField>

<ParamField body="input.audio_url" type="string">
  オーディオファイルのダウンロードURL。対応形式: mp3 および wav。reference_video_urls とは併用できません。
</ParamField>

<ParamField body="input.img_url" type="string">
  先頭フレームの画像URL、または Base64 エンコードされたデータ。wan2.5-i2v-preview および
wan2.6-i2v モデルでは必須です。happyhorse-1.x の i2v 系の指定では、先頭フレームをここで受け取りません。
type が first_frame の media 要素として受け取ります（後述の media を参照）。また、wan2.6-i2v で成功する
img_url ボディは、happyhorse-1.0-i2v および happyhorse-1.1-i2v ではプロバイダーに拒否されます。
さらに wan2.7/wan3.0 系の指定も、参照アセットを media で受け取ります。画像形式: JPEG、JPG、PNG、BMP、WEBP。
解像度: 360〜2000 ピクセル。ファイルサイズ: 最大 10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。動画生成用の参照素材（画像、オーディオ、ビデオ）を指定します。
各要素は type と url フィールドを含みます。このフィールドは、このコンポーネントから提供される
すべてのモデルで共通です。あるモデルがどの type 値を受け付けるか、また画像またはビデオの入力を
img_url や reference_video_urls ではなくここで渡すかどうかは、モデルによって異なります。
モデルごとの対応 type 値:
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frame と
  last_frame: JPEG/JPG/PNG/BMP/WEBP、1辺あたり 240〜8000 ピクセル、アスペクト比 1:8〜8:1、
  最大 20MB、公開URLまたは data:\{MIME_type};base64,... URL。
  driving_audio（WAV/MP3、2〜30 秒、最大 15MB）および first_clip（MP4/MOV、2〜10 秒、
  1辺あたり 240〜4096 ピクセル、最大 100MB）: 公開 HTTP/HTTPS URL。インラインの
  data: URL は受け付けられません。
- wan2.7-r2v: first_frame（任意、最大 1）、reference_image、reference_video。少なくとも
  1 つの reference_image または reference_video が必要で、参照画像と参照ビデオの合計は
  最大 5 です。first_frame と reference_image: JPEG/JPG/PNG/BMP/WEBP（アルファチャンネルなし）、
  1辺あたり 240〜8000 ピクセル、アスペクト比 1:8〜8:1、最大 20MB、公開URLまたは
  data:\{MIME_type};base64,... URL。reference_video: 公開 HTTP/HTTPS URL。インラインの
  data: URL は受け付けられません。
- wan2.7-videoedit: video（ちょうど 1 つ、編集対象のクリップ: MP4/MOV、2〜10 秒、
  1辺あたり 240〜4096 ピクセル、最大 100MB、公開 HTTP/HTTPS URL。インラインの data: URL
  は受け付けられません）に加えて、任意で 0〜4 個の reference_image（JPEG/JPG/PNG/BMP/WEBP、
  1辺あたり 240〜8000 ピクセル、アスペクト比 1:8〜8:1、最大 20MB、公開URLまたは
  data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime: first_frame（最大 1）、last_frame（最大 1）、
  reference_image（最大 10）、reference_video（最大 5 クリップ、合計再生時間 \<= 15s）、
  reference_audio（最大 5 クリップ、合計再生時間 \<= 15s）、file（最大 1、link とは
  併用できません）、link（最大 1、file とは併用できません）。reference_*/file/link の type と
  first_frame/last_frame の type は、同じリクエスト内では同時に使用できません。配列の順序が、
  プロンプト内のアセットの参照順（Image 1、Video 1、Audio 1、...）を定義します。first_frame、
  last_frame および reference_image: JPEG/JPG/PNG/BMP/WEBP、1辺あたり 240〜8000 ピクセル、
  アスペクト比は最大 8:1、最大 20MB、公開URLまたは data:\{MIME_type};base64,... URL。
  reference_video、reference_audio、file および link: 公開 HTTP/HTTPS URL。インラインの
  data: URL は受け付けられません。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v: first_frame のみ、ちょうど 1 つ。これらの指定は
  先頭フレームを img_url ではなくここで受け取ります。少なくとも 300x300 ピクセル、アスペクト比
  1:2.5〜2.5:1、JPEG/JPG/PNG/WEBP、最大 20MB、公開URLまたは
  data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v: reference_image のみ、1〜9 個。これがこのモデルの
  唯一の参照入力です。最短辺は少なくとも 400 ピクセル、JPEG/JPG/PNG/WEBP、最大 20MB、
  公開URLまたは data:\{MIME_type};base64,... URL。reference_video はこの操作の入力タイプ
  ではありません。
- happyhorse-1.0-video-edit: video（ちょうど 1 つ、編集対象のクリップ: MP4/MOV、3〜60 秒、
  長辺は最大 4096 ピクセル、短辺は少なくとも 360 ピクセル、アスペクト比 1:2.5〜2.5:1、
  最大 100MB、公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません）に加えて、
  任意で 0〜5 個の reference_image（JPEG/JPG/PNG/WEBP、少なくとも 300x300 ピクセル、
  アスペクト比 1:2.5〜2.5:1、最大 20MB、公開URLまたは data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview:
  テキストから動画への操作。これらの対応するパートナーのリファレンスには media 入力の記載が
  ないため、このフィールドは未設定のままにしてください。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v: このコンポーネントは、これらの指定向けの
  media ボキャブラリを列挙していません。wan2.5-i2v-preview と wan2.6-i2v は先頭フレームを
  img_url で受け取り、wan2.6-r2v は参照クリップを reference_video_urls で受け取ります。
上記のモデルごとの個数はパートナーの制約であり、このスキーマのものではありません。media には
minItems/maxItems が宣言されていません。許容される type とその上限はモデルごとに異なるためです。
スキーマが受け入れることはプロバイダーが受け入れることを意味しません。逆に、上記のアセット単位の
「最大 20MB」という数値（画像入力の上限であり、インラインで送信できる唯一の入力）は、パートナーが
最終的に受け取るアセットに対する上限であり、アセットが公開URLである場合にはそのまま適用されます。
そのバイト列が Comfy を経由しないためです。インラインの data:\{MIME_type};base64,...
URL は Comfy を経由するため、転送時の上限にも直面します。Comfy Router の POST ボディは合計
100 MiB に制限され、それを超えると 413 で応答されます。また base64 はペイロードを約 4/3 に
膨らませるため、およそ 75 MB を超える単一のインラインアセットは、ここに記述されたパートナーの
ルールに到達する前に拒否されます。そのサイズでは、パートナー自身の20MB の上限であればインラインで余裕をもって収まります。そのため、1 つのアセットについてはパートナーのルールが制約となります。複数のアセットにまたがる場合はトランスポートの上限が制約となります。100 MiB の Router 上限は各要素ではなくリクエスト全体を制限するためです。これらの上限に近いものはパブリック URL として送信してください。
</ParamField>

<ParamField body="input.media[].url" type="string" required>
  メディアファイルの URL: パブリックな HTTP/HTTPS URL、または、上記の `media` の説明が各モデルについて列挙しているまさにその画像入力（wan2.7-i2v の first_frame と last_frame、wan2.7-r2v の first_frame と reference_image、wan2.7-videoedit の reference_image、wan3.0-video と wan3.0-video-prime の first_frame、last_frame、reference_image、happyhorse-1.0-i2v と happyhorse-1.1-i2v の first_frame、happyhorse-1.0-r2v と happyhorse-1.1-r2v の reference_image、そして happyhorse-1.0-video-edit の reference_image）に限り、インラインの `data:{MIME_type};base64,...` URL。これらのモデルのいずれにおいても、ビデオ、オーディオ、ファイル、リンクの入力がインラインの data: URL を受け付けることはありません。パートナー自身のアップロードサービスによる oss://dashscope-instant の一時 URL、または（wan2.7-videoedit では）Asset Center の asset_id は、それをアップロードした Alibaba Cloud アカウントに対してのみ解決されます。Comfy は自身のキーでモデルを呼び出し、アップロード経路を公開していないため、呼び出し元自身の oss:// URL や asset_id はサポートされる入力ではありません。このフィールドは URL スキームを検証しないため、そのような値はここで拒否されることなくパートナーへそのまま転送されます。モデルごとのサイズとピクセルの制限、およびインラインのペイロードを全体として制限する 100 MiB の Router リクエストボディ上限については、`media` の説明を参照してください。
</ParamField>

<ParamField body="input.prompt" type="string">
  テキストプロンプト。中国語と英語をサポートし、長さは 800 文字以内です
（wan3.0-video では最大 20,000 文字。制限を超えたコンテンツは切り捨てられます）。
複数の参照ビデオを使用する wan2.6-r2v では、参照ビデオの順序に従って被写体を
'character1'、'character2' などで参照します。例: "Character1 sings on the roadside, Character2 dances beside it"
wan3.0-video の参照モードでは、media 配列内の対応する順序でメディアアセットを
'Image 1'、'Video 1'、'Audio 1' などで参照します。
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  wan2.6-r2v モデル専用の参照ビデオ URL。1～3 本のビデオ URL の配列です。
入力の制限:
- 形式: mp4、mov
- 本数: 1～3 本
- 単一ビデオの長さ: 2～30 秒
- 単一ファイルサイズ: 最大 30MB
- audio_url と併用できません
参照再生時間: 単一ビデオで最大 5 秒、2 本の場合はそれぞれ最大 2.5 秒、3 本の場合は比例して短くなります。
課金: 実際に使用された参照再生時間に基づきます。
</ParamField>

<ParamField body="parameters.duration" type="integer" default="5">
  生成されるビデオの再生時間（秒）:

- wan2.6-t2v、wan2.6-i2v: 5、10、または 15 秒
- wan2.6-r2v: 5 秒または 10 秒のみ（15 秒はサポートされません）
- wan2.7-i2v、wan2.7-t2v: [2, 15] の整数
- wan2.7-r2v、wan2.7-videoedit: [2, 10] の整数
- wan3.0-video: ビデオ入力なしの場合は [2, 30] の整数。ビデオ入力がある場合は、
  入力ビデオの再生時間と出力ビデオの再生時間の合計が 30 秒を超えてはなりません。-1 は
  スマート再生時間モードを有効にし、モデルが適切な再生時間を選択します
このプロキシは [-1, 30] の範囲外の再生時間に対して 400 を返します。

  範囲: `-1`～`30`
</ParamField>

<ParamField body="parameters.prompt_extend" type="boolean" default="true">

<ParamField body="parameters.ratio" type="string">

wan3.0-video では、adaptive（デフォルト）が入力メディアの比率と意図に基づいて
適切なアスペクト比を自動的に推奨します。

  指定可能な値: `adaptive`, `16:9`, `9:16`, `1:1`, `4:3`, `3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  解像度レベル。サポートされる値はモデルによって異なります:
- wan2.5-i2v-preview: 480P、720P、1080P
- wan2.6 モデル（t2v、i2v、r2v）: 720P、1080P のみ（480P はサポートされません）
- wan2.7 モデル（i2v、t2v、r2v、videoedit）: 720P、1080P（デフォルトは 1080P）- wan3.0-video, wan3.0-video-prime: 480P, 720P, 1080P（上流のデフォルトは 1080P）
- happyhorse-1.0-* (t2v, i2v, r2v, video-edit): 720P, 1080P
- happyhorse-1.1-* (t2v, i2v, r2v): 480P, 720P, 1080P
このプロキシは、解像度もサイズも指定していないビデオ生成リクエストを拒否します。これは、課金レートを選択するのが解像度のティアだからです。チェックの前に解像度を大文字化し、その大文字化した値を転送します。この enum に含まれない値には 400 を返し、上記で 480P がないと記載されている wan2.6、wan2.7、happyhorse-1.0 のモデルでは、480P に対して（解像度として送信された場合でも 480P のサイズとして送信された場合でも）400 を返します。

  可能な値: `480P`, `720P`, `1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">

  範囲: `0` から `2147483647` まで
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">

- single: 単一ショットのビデオ（デフォルト）
- multi: マルチショットのビデオ

  可能な値: `multi`, `single`
</ParamField>

<ParamField body="parameters.size" type="string">
  width*height 形式のビデオ解像度。対応する解像度はモデルによって異なります:
wan2.5 T2V の場合: 480P (480*832, 832*480, 624*624), 720P, 1080P の各サイズ
wan2.6 T2V/R2V の場合（480P なし）:
  720P: 1280*720, 720*1280, 960*960, 1088*832, 832*1088
  1080P: 1920*1080, 1080*1920, 1440*1440, 1632*1248, 1248*1632
サイズと解像度の両方を送信した場合、課金対象のティアを選択するのはサイズであり、解像度はそのモデルに対してこのプロキシが受け入れる値である必要があります。480P のサイズは、解像度の説明で 480P がないものとして挙げられているすべてのモデルで 400 を返します。
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
