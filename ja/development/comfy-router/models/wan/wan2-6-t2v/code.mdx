Wan 2.6 T2V の API リファレンス。Wan 2.6 のテキストから動画への変換は、プロンプトのみから短いビデオを生成します。解像度は 720P または 1080P、長さは最大 15 秒です。

**入力：** オーディオ, テキスト · **出力：** ビデオ + オーディオ

**モデル ID:** `wan/wan2.6-t2v`

**エンドポイント:** `POST https://api.comfy.org/v2/models/wan/wan2.6-t2v`

import asyncio

# 環境変数から COMFY_API_KEY を読み取ります。
# submit() 呼び出しごとに独自の Idempotency-Key を発行し、自動リトライのために再利用します。
async def main():

                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )

        # リクエストが完了するまでポーリングし、サーバーが指定する Retry-After の秒数だけ待機します。
        async for update in handle.iter_events():

        # プロバイダー自身のペイロード。models.run() が返すのと同じ値です。
        # 失敗またはキャンセルされたリクエストは、ここで型付きの Router エラーを発生させます。

### 入力

<ParamField body="input" type="object" required>
  プロンプトなどの基本情報を入力します。
</ParamField>

<ParamField body="input.audio_url" type="string">
  オーディオファイルのダウンロードURL。対応形式: mp3 および wav。reference_video_urls とは併用できません。
</ParamField>

<ParamField body="input.img_url" type="string">
  先頭フレーム画像のURLまたはBase64エンコードされたデータ。wan2.5-i2v-preview と
wan2.6-i2v モデルでは必須です。happyhorse-1.x の i2v 表記では、先頭フレームをここでは
受け取りません。先頭フレームは type が first_frame のメディア要素として渡します（下記の
media を参照）。また、wan2.6-i2v で成功する img_url のボディは、happyhorse-1.0-i2v と
happyhorse-1.1-i2v ではプロバイダーによって拒否されます。さらに wan2.7/wan3.0 の表記では
参照アセットも media で渡します。画像形式: JPEG、JPG、PNG、BMP、WEBP。
解像度: 360-2000 ピクセル。ファイルサイズ: 最大 10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。動画生成用の参照素材（画像、オーディオ、ビデオ）を指定します。
各要素は type と url フィールドを持ちます。このフィールドはこのコンポーネントで提供される
すべてのモデルで共通ですが、あるモデルがどの type 値を受け付けるか、また画像やビデオの
入力をここで受け取るのか img_url や reference_video_urls で受け取るのかは、モデルごとに
異なります。モデルごとの対応 type 値:
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frame と
  last_frame: JPEG/JPG/PNG/BMP/WEBP、1辺 240-8000 ピクセル、アスペクト比 1:8 から
  8:1、最大 20MB、公開URLまたは data:\{MIME_type};base64,... URL。
  driving_audio（WAV/MP3、2-30 秒、最大 15MB）と first_clip（MP4/MOV、2-10 秒、
  1辺 240-4096 ピクセル、最大 100MB）: 公開 HTTP/HTTPS URL。インラインの
  data: URL は受け付けられません。
- wan2.7-r2v: first_frame（任意、最大 1）、reference_image、reference_video。
  reference_image または reference_video が少なくとも 1 つ必要で、reference_image と
  reference_video の合計は最大 5 です。first_frame と reference_image: JPEG/JPG/PNG/BMP/WEBP
  （アルファチャンネルなし）、1辺 240-8000 ピクセル、アスペクト比 1:8 から 8:1、最大
  20MB、公開URLまたは data:\{MIME_type};base64,... URL。reference_video: 公開
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-videoedit: video（ちょうど 1 つ、編集対象のクリップ: MP4/MOV、2-10 秒、
  1辺 240-4096 ピクセル、最大 100MB、公開 HTTP/HTTPS URL。インラインの data: URL
  は受け付けられません）に加えて、任意で 0 から 4 つの reference_image（JPEG/JPG/PNG/BMP/WEBP、
  1辺 240-8000 ピクセル、アスペクト比 1:8 から 8:1、最大 20MB、公開URL
  または data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime: first_frame（最大 1）、last_frame（最大 1）、
  reference_image（最大 10）、reference_video（最大 5 クリップ、合計再生時間 \<= 15s）、
  reference_audio（最大 5 クリップ、合計再生時間 \<= 15s）、file（最大 1、link とは
  併用不可）、link（最大 1、file とは併用不可）。reference_*/file/link タイプと
  first_frame/last_frame タイプは同一リクエスト内で排他的です。配列の順序が
  プロンプト内でのアセットの参照順（Image 1、Video 1、Audio 1、…）を定義します。
  first_frame、last_frame、reference_image: JPEG/JPG/PNG/BMP/WEBP、
  1辺 240-8000 ピクセル、アスペクト比 最大 8:1、最大 20MB、公開URLまたは
  data:\{MIME_type};base64,... URL。reference_video、reference_audio、file、link: 公開
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v: first_frame のみ、ちょうど 1 つ。これらの表記
  では先頭フレームをここで受け取り、img_url では受け取りません。少なくとも 300x300 ピクセル、
  アスペクト比 1:2.5 から 2.5:1、JPEG/JPG/PNG/WEBP、最大 20MB、公開URLまたは
  data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v: reference_image のみ、1 から 9 個。これが
  このモデル唯一の参照入力です。短辺が少なくとも 400 ピクセル、JPEG/JPG/PNG/WEBP、
  最大 20MB、公開URLまたは data:\{MIME_type};base64,... URL。この操作で reference_video は
  入力タイプではありません。
- happyhorse-1.0-video-edit: video（ちょうど 1 つ、編集対象のクリップ: MP4/MOV、3-60
  秒、長辺が最大 4096 ピクセル、短辺が少なくとも 360 ピクセル、アスペクト比 1:2.5 から 2.5:1、
  最大 100MB、公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません）に加えて、
  任意で 0 から 5 つの reference_image（JPEG/JPG/PNG/WEBP、少なくとも 300x300 ピクセル、
  アスペクト比 1:2.5 から 2.5:1、最大 20MB、公開URLまたは data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview:
  テキストから動画への操作。これらのパートナーのリファレンスにはメディア入力の記載がないため、
  このフィールドは未設定のままにしてください。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v: このコンポーネントは、これらの表記に対して
  メディアの語彙を列挙していません。wan2.5-i2v-preview と wan2.6-i2v は先頭フレームを
  img_url で受け取り、wan2.6-r2v は参照クリップを reference_video_urls で受け取ります。
上記のモデルごとの個数はこのスキーマの制約ではなくパートナーの制約です。media には
minItems/maxItems が宣言されていません。許容される type とその上限がモデルごとに異なるためです。
スキーマが受け付けることはプロバイダーが受け付けることを意味しません。また逆方向についても、
上記のアセットごとの「最大 20MB」という数値（画像入力の上限であり、インラインで送信できる
唯一の入力です）は、最終的に受け取るアセットに対するパートナーの上限であり、アセットが
公開URLの場合はそのまま適用されます。そのバイト列が Comfy を経由することはないためです。
インラインの data:\{MIME_type};base64,... URL は Comfy を経由するため、転送上の上限にも
直面します。Comfy Router の POST ボディは合計で 100 MiB に制限され、超えると 413 が返され、
また base64 はペイロードを約 4/3 に膨らませるため、約 75 MB を超える単一のインラインアセットは、
ここに挙げたパートナーのルールに到達する前に拒否されます。そのサイズでは、単一のアセットは
パートナー自身の20MBの上限ならインラインで問題なく収まるため、単一のアセットではパートナーのルールが制約となります。複数のアセットにまたがる場合はトランスポートの上限が制約となります。100 MiB の Router の上限は各要素ではなくリクエスト全体を制限するためです。これらの上限に近いものはすべてパブリック URL として送信してください。
</ParamField>

<ParamField body="input.media[].url" type="string" required>
  メディアファイルの URL: パブリックな HTTP/HTTPS URL、または、上記の `media` の説明で各モデル向けに列挙されている IMAGE 入力に限り、インラインの `data:{MIME_type};base64,...` URL を使用できます。対象は wan2.7-i2v の first_frame と last_frame、wan2.7-r2v の first_frame と reference_image、wan2.7-videoedit の reference_image、wan3.0-video と wan3.0-video-prime の first_frame、last_frame、reference_image、happyhorse-1.0-i2v と happyhorse-1.1-i2v の first_frame、happyhorse-1.0-r2v と happyhorse-1.1-r2v の reference_image、そして happyhorse-1.0-video-edit の reference_image です。これらのモデルの video、audio、file、link のいずれの入力もインラインの data: URL を受け付けません。パートナー自身のアップロードサービスが発行する oss://dashscope-instant の一時 URL、または（wan2.7-videoedit では）Asset Center の asset_id は、それをアップロードした Alibaba Cloud アカウントに対してのみ解決されます。Comfy は自身のキーでモデルを呼び出し、アップロード経路を公開していないため、呼び出し元自身の oss:// URL や asset_id はサポートされる入力ではありません。このフィールドは URL スキームを検証しないため、そのような値はここで拒否されるのではなく、そのままパートナーへ転送されます。モデルごとのサイズとピクセルの制限、およびインラインのペイロードを合計で制限する 100 MiB の Router リクエストボディ上限については、`media` の説明を参照してください。
</ParamField>

<ParamField body="input.negative_prompt" type="string">
  逆プロンプトは、ビデオ画面に表示したくないコンテンツを記述するために使用します。500 文字を超えると、wan モデルは拒否するのではなく切り詰めます。これは prompt と同じ入力バジェットにカウントされます。
</ParamField>

<ParamField body="input.prompt" type="string">
  テキストプロンプト。中国語と英語をサポートします。自身に定められた長さを超えると、wan2.x モデルは拒否するのではなくプロンプトを切り詰めます。wan2.5 と wan2.6 では 1,500 文字、wan2.7 では 5,000 文字です。wan3.0-video と wan3.0-video-prime は最大 20,000 文字を受け付けます。プロバイダーは、prompt と negative_prompt を合わせて約 60,850 バイトの UTF-8 テキスト（約 20,000 文字の中国語）を超えるリクエストを拒否し、InvalidParameter `Range of input length should be [1, 61440]` を返します。複数の参照ビデオを使う wan2.6-r2v では、参照ビデオの順序に対応させて「character1」「character2」などで被写体を指定します。例: "Character1 sings on the roadside, Character2 dances beside it"。wan3.0-video の参照モードでは、media 配列内の対応する順序に従って「Image 1」「Video 1」「Audio 1」などでメディアアセットを指定します。
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  wan2.6-r2v モデル専用の参照ビデオ URL。1〜3 本のビデオ URL の配列です。
入力の制限:
- 形式: mp4、mov
- 数量: 1〜3 本のビデオ
- 1 本あたりの長さ: 2〜30 秒
- 1 ファイルあたりのサイズ: 最大 30MB
- audio_url と併用できません
参照再生時間: 1 本の場合は最大 5 秒、2 本の場合は各最大 2.5 秒、3 本の場合はそれに比例して短くなります。
課金: 実際に使用された参照再生時間に基づきます。
</ParamField>

</ParamField>

<ParamField body="parameters.duration" type="integer" default="5">
  生成されるビデオの再生時間（秒）:
- wan2.5 モデル: 5 秒または 10 秒
- wan2.6-t2v、wan2.6-i2v: 5 秒、10 秒、または 15 秒
- wan2.6-r2v: 5 秒または 10 秒のみ（15 秒は非サポート）
- wan2.7-i2v、wan2.7-t2v: [2, 15] の整数

  範囲: `-1` から `30`
</ParamField>

<ParamField body="parameters.prompt_extend" type="boolean" default="true">
  プロンプトのインテリジェントな書き換えを有効にするかどうか。デフォルトは true です
</ParamField>

<ParamField body="parameters.ratio" type="string">
  生成されるビデオのアスペクト比。wan2.7 および wan3.0 モデル専用です。
wan2.7 モデルでは、指定しない場合、解像度ティアに基づいてデフォルトが決まります。
wan3.0-video では、adaptive（デフォルト）が適切な入力メディアの比率と意図に基づくアスペクト比。

  取り得る値: `adaptive`、`16:9`、`9:16`、`1:1`、`4:3`、`3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  解像度レベル。サポートされる値はモデルによって異なります:
- wan2.5-i2v-preview: 480P、720P、1080P
- wan2.6 モデル (t2v、i2v、r2v): 720P、1080P のみ (480P 非サポート)
- wan2.7 モデル (i2v、t2v、r2v、videoedit): 720P、1080P (デフォルト 1080P)
- wan3.0-video、wan3.0-video-prime: 480P、720P、1080P (上流のデフォルトは 1080P)
- happyhorse-1.0-* (t2v、i2v、r2v、video-edit): 720P、1080P
- happyhorse-1.1-* (t2v、i2v、r2v): 480P、720P、1080P
このプロキシは、resolution と size のどちらも指定されていないビデオ生成リクエストを拒否します。解像度ティアが課金レートを決定するためです。resolution はチェック前に大文字へ変換され、大文字化された値が転送されます。この enum に含まれない値には 400 を返し、480P を持たないと上記で説明されている wan2.6、wan2.7、happyhorse-1.0 の各モデルでは、480P (resolution として送信された場合も、480P の size として送信された場合も) に対して 400 を返します。

  取り得る値: `480P`、`720P`、`1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  乱数シード。モデルが生成するコンテンツのランダム性を制御するために使用します。

  範囲: `0` から `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  インテリジェントなマルチレンズ制御。prompt_extend が有効な場合にのみ機能します。
wan2.6 および wan2.7-r2v モデル向け。
- single: 単一ショットのビデオ (デフォルト)
- multi: マルチショットのビデオ

  取り得る値: `multi`、`single`
</ParamField>

<ParamField body="parameters.size" type="string">
  幅*高さ形式のビデオ解像度。サポートされる解像度はモデルによって異なります:
wan2.5 T2V の場合: 480P (480*832、832*480、624*624)、720P、1080P の各サイズ
wan2.6 T2V/R2V の場合 (480P なし):
  720P: 1280*720、720*1280、960*960、1088*832、832*1088
  1080P: 1920*1080、1080*1920、1440*1440、1632*1248、1248*1632
size と resolution の両方が送信された場合、課金ティアを選択するのは size であり、resolution はそのモデルに対してこのプロキシが受け入れる値である必要があります。480P の size は、解像度の説明で 480P を持たないと記載されているすべてのモデルで 400 を返します。
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  ウォーターマークロゴを追加するかどうか。ウォーターマークは右下隅に配置されます。
</ParamField>
