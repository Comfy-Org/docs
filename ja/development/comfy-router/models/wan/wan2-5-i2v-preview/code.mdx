Wan 2.5 I2V Preview の API リファレンスです。Wan 2.5 の画像から動画への変換では、静止した最初のフレームを短いビデオに変換し、その動きとカメラの動きはプロンプトで記述します。

**入力：** 画像, オーディオ, テキスト · **出力：** ビデオ + オーディオ

## クイックスタート

**モデル ID:** `wan/wan2.5-i2v-preview`

**エンドポイント:** `POST https://api.comfy.org/v2/models/wan/wan2.5-i2v-preview`

import asyncio
from comfy_sdk import AsyncComfy

# 環境変数から COMFY_API_KEY を読み取ります。
# submit() を呼び出すたびに独自の Idempotency-Key が発行され、自動リトライ時に再利用されます。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/wan2.5-i2v-preview",
            {
                "input": {
                    "prompt": "the robot lowers its raised arm and steps toward the camera, the flat orange backdrop holds steady",
                    "img_url": "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # モデル ID とこれだけで、別のプロセスに必要な情報は揃います

        # リクエストが完了するまでポーリングし、サーバーが指示する Retry-After の時間だけ待機します。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # プロバイダー自身のペイロードで、models.run() が返す値と同じです。
        # 失敗またはキャンセルされたリクエストは、ここで型付きの Router エラーを送出します。
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())

### 入力

<ParamField body="input" type="object" required>
  プロンプト語句などの基本情報を入力します。
</ParamField>

<ParamField body="input.audio_url" type="string">
  オーディオファイルのダウンロードURL。対応形式: mp3 と wav。reference_video_urls とは併用できません。
</ParamField>

<ParamField body="input.img_url" type="string">
  先頭フレーム画像のURL、またはBase64エンコードされたデータ。wan2.5-i2v-preview と
wan2.6-i2v モデルでは必須です。happyhorse-1.x の i2v 表記では、先頭フレームをここで受け取りません。
先頭フレームは type が first_frame のメディア要素として受け取ります（後述の media を参照）。
また、wan2.6-i2v で成功する img_url ボディは、happyhorse-1.0-i2v と
happyhorse-1.1-i2v ではプロバイダーに拒否されます。さらに wan2.7/wan3.0 の表記では、
参照アセットを media でも受け取ります。画像形式: JPEG、JPG、PNG、BMP、WEBP。
解像度: 360-2000 ピクセル。ファイルサイズ: 最大 10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。動画生成のための参照素材（画像、オーディオ、ビデオ）を指定します。
各要素は type と url フィールドを持ちます。このフィールドは本コンポーネントが提供するすべての
モデルで共有されますが、あるモデルがどの type 値を受け付けるか、また画像やビデオの入力を
img_url や reference_video_urls ではなくここで受け取るかどうかはモデルによって異なります。
モデルごとの対応 type 値:
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frame と
  last_frame: JPEG/JPG/PNG/BMP/WEBP、1辺 240-8000 ピクセル、アスペクト比 1:8
  から 8:1 の間、最大 20MB、公開URL または data:\{MIME_type};base64,... URL。
  driving_audio（WAV/MP3、2-30 秒、最大 15MB）と first_clip（MP4/MOV、2-10
  秒、1辺 240-4096 ピクセル、最大 100MB）: 公開 HTTP/HTTPS URL。インラインの
  data: URL は受け付けられません。
- wan2.7-r2v: first_frame（任意、最大1）、reference_image、reference_video。少なくとも
  reference_image または reference_video が1つ必要で、参照画像と
  参照ビデオは合計で最大5つです。first_frame と reference_image: JPEG/JPG/PNG/BMP/WEBP
  （アルファチャンネルなし）、1辺 240-8000 ピクセル、アスペクト比 1:8 から 8:1 の間、最大
  20MB、公開URL または data:\{MIME_type};base64,... URL。reference_video: 公開
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-videoedit: video（正確に1つ、編集対象のクリップ: MP4/MOV、2-10 秒、
  1辺 240-4096 ピクセル、最大 100MB、公開 HTTP/HTTPS URL。インラインの data: URL
  は受け付けられません）に加えて、任意で 0〜4 個の reference_image（JPEG/JPG/PNG/BMP/WEBP、
  1辺 240-8000 ピクセル、アスペクト比 1:8 から 8:1 の間、最大 20MB、公開URL
  または data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime: first_frame（最大1）、last_frame（最大1）、
  reference_image（最大10）、reference_video（最大5クリップ、合計再生時間 \<= 15s）、
  reference_audio（最大5クリップ、合計再生時間 \<= 15s）、file（最大1、link とは
  併用不可）、link（最大1、file とは併用不可）。reference_*/file/link の type
  と first_frame/last_frame の type は同一リクエスト内で同時に使用できません。
  配列の順序がプロンプト内のアセットの参照順序（Image 1、Video 1、
  Audio 1、...）を定義します。first_frame、last_frame、reference_image: JPEG/JPG/PNG/BMP/WEBP、
  1辺 240-8000 ピクセル、アスペクト比 最大 8:1、最大 20MB、公開URL または
  data:\{MIME_type};base64,... URL。reference_video、reference_audio、file、link:
  公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v: first_frame のみ、正確に1つ。これらの表記
  では先頭フレームを img_url ではなくここで受け取ります。最小 300x300 ピクセル、アスペクト比
  1:2.5 から 2.5:1 の間、JPEG/JPG/PNG/WEBP、最大 20MB、公開URL または
  data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v: reference_image のみ、1〜9 個。これは
  モデル唯一の参照入力です。短辺は最小 400 ピクセル、JPEG/JPG/PNG/WEBP、
  最大 20MB、公開URL または data:\{MIME_type};base64,... URL。reference_video は
  この操作の入力タイプではありません。
- happyhorse-1.0-video-edit: video（正確に1つ、編集対象のクリップ: MP4/MOV、3-60
  秒、長辺 最大 4096 ピクセル、短辺 最小 360 ピクセル、アスペクト
  比 1:2.5 から 2.5:1 の間、最大 100MB、公開 HTTP/HTTPS URL。インラインの data:
  URL は受け付けられません）に加えて、任意で 0〜5 個の reference_image（JPEG/JPG/PNG/WEBP、
  最小 300x300 ピクセル、アスペクト比 1:2.5 から 2.5:1 の間、最大 20MB、公開URL
  または data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview:
  テキストから動画への操作です。これらのパートナーの参照ドキュメントにはメディア入力が
  記載されていないため、このフィールドは未設定のままにしてください。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v: このコンポーネントはこれらの表記に対する
  メディアの語彙を列挙していません。wan2.5-i2v-preview と wan2.6-i2v は先頭
  フレームを img_url で受け取り、wan2.6-r2v は参照クリップを reference_video_urls で
  受け取ります。
上記のモデルごとの件数はパートナーの制約であり、このスキーマの制約ではありません。media には
minItems/maxItems が宣言されていません。許容される type とその上限が
モデルごとに異なるためです。スキーマが受け付けることはプロバイダーが受け付けることを意味しません。
また逆に、上記のアセットごとの「最大 20MB」という値、つまり画像
入力（インラインで送信できる唯一の入力）に対する上限は、パートナーが最終的に
受け取るアセットに対するパートナーの上限であり、アセットが公開URLである場合には
そのまま適用されます。そのバイト列は Comfy を経由しないためです。インラインの data:\{MIME_type};base64,...
URL は Comfy を経由するため、転送時の上限にも直面します。Comfy Router の
POST ボディは合計 100 MiB に制限され、超えると 413 が返されます。さらに base64 は
ペイロードを約 4/3 に膨張させるため、およそ 75 MB を超える単一のインラインアセットは、ここに挙げた
パートナーのルールに到達する前に拒否されます。そのサイズでは、パートナー自身の20MB の上限はインラインに余裕で収まるため、1つのアセットについてはパートナーのルールが制約となります。複数のアセットにまたがる場合は転送の上限が制約となります。100 MiB の Router の上限は個々の要素ではなくリクエスト全体を制限するためです。これらの上限に近いものはすべてパブリック URL として送信してください。
</ParamField>

<ParamField body="input.media[].url" type="string" required>
  メディアファイルの URL。パブリックな HTTP/HTTPS URL、または、上記の `media` の説明でモデルごとに列挙されている IMAGE 入力（wan2.7-i2v の first_frame と last_frame、wan2.7-r2v の first_frame と reference_image、wan2.7-videoedit の reference_image、wan3.0-video と wan3.0-video-prime の first_frame、last_frame、reference_image、happyhorse-1.0-i2v と happyhorse-1.1-i2v の first_frame、happyhorse-1.0-r2v と happyhorse-1.1-r2v の reference_image、happyhorse-1.0-video-edit の reference_image）に限り、インラインの `data:{MIME_type};base64,...` URL を指定できます。これらのモデルのビデオ、オーディオ、ファイル、リンクのいずれの入力も、インラインの data: URL を受け付けません。パートナー自身のアップロードサービスが発行する oss://dashscope-instant の一時 URL、または（wan2.7-videoedit では）Asset Center の asset_id は、それをアップロードした Alibaba Cloud アカウントに対してのみ解決されます。Comfy は自身のキーでモデルを呼び出し、アップロード経路を公開していないため、呼び出し元自身の oss:// URL や asset_id はサポートされる入力ではありません。このフィールドは URL スキームを検証しないため、そのような値はここで拒否されることなく、そのままパートナーへ転送されます。モデルごとのサイズとピクセルの上限、およびインラインのペイロードを合計で制限する 100 MiB の Router リクエストボディ上限については、`media` の説明を参照してください。
</ParamField>

<ParamField body="input.negative_prompt" type="string">
  逆プロンプトの語句は、ビデオ画面に表示したくないコンテンツを記述するために使用します。500 文字を超えると、wan モデルは拒否せずに切り捨てます。これは prompt と同じ入力予算にカウントされます。
</ParamField>

<ParamField body="input.prompt" type="string">
  テキストプロンプトの語句。中国語と英語をサポートします。文書化された長さを超えると、wan2.x モデルは拒否せずにプロンプトを切り捨てます。wan2.5 と wan2.6 は 1,500 文字、wan2.7 は 5,000 文字です。wan3.0-video と wan3.0-video-prime は最大 20,000 文字まで受け付けます。prompt と negative_prompt を合わせて約 60,850 バイトの UTF-8 テキスト（約 20,000 文字の中国語）を超えるリクエストは、プロバイダーが拒否し、InvalidParameter `Range of input length should be [1, 61440]` を返します。
複数の参照ビデオを使う wan2.6-r2v では、参照ビデオの順序に従って被写体を 'character1'、'character2' などで参照します。例:「Character1 が道端で歌い、Character2 がその横で踊る」
wan3.0-video の参照モードでは、media 配列内の対応する順序でメディアアセットを 'Image 1'、'Video 1'、'Audio 1' などで参照します。
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  wan2.6-r2v モデル専用の参照ビデオ URL。1〜3 本のビデオ URL の配列。
入力の制限:
- 形式: mp4、mov
- 本数: 1〜3 本
- 1 本あたりの長さ: 2〜30 秒
- 1 ファイルあたりのサイズ: 最大 30MB
- audio_url と併用できません
参照の再生時間: ビデオ 1 本なら最大 5 秒、2 本ならそれぞれ最大 2.5 秒、3 本なら比例して短くなります。
課金: 実際に使用した参照の再生時間に基づきます。
</ParamField>

<ParamField body="input.template" type="string">
  ビデオエフェクトのテンプレート名。任意。現在サポートされているのは squish、flying、carousel です。使用すると prompt パラメータは無視されます。
</ParamField>

</ParamField>

- wan2.5 モデル: 5 秒または 10 秒
- wan2.6-t2v、wan2.6-i2v: 5、10、15 秒
- wan2.6-r2v: 5 秒または 10 秒のみ（15 秒は非サポート）
- wan2.7-i2v、wan2.7-t2v: [2, 15] の整数
- wan2.7-r2v、wan2.7-videoedit: [2, 10] の整数
- wan3.0-video: ビデオ入力なしなら [2, 30] の整数。ビデオ入力ありの場合、
  入力ビデオの再生時間と出力ビデオの再生時間の合計が 30 秒を超えてはなりません。-1 を指定すると
  スマート再生時間モードが有効になり、モデルが適切な再生時間を選択します
このプロキシは [-1, 30] の範囲外の再生時間に対して 400 を返します。

  範囲: `-1` から `30`
</ParamField>

<ParamField body="parameters.prompt_extend" type="boolean" default="true">
  プロンプトのインテリジェントな書き換えを有効にするかどうか。デフォルトは true です
</ParamField>

<ParamField body="parameters.ratio" type="string">
  生成されるビデオのアスペクト比。wan2.7 と wan3.0 モデル専用です。
wan2.7 モデルでは、指定しない場合は解像度の階層に基づいてデフォルトが決まります。
wan3.0-video では、adaptive（デフォルト）が適切な入力メディアの比率と意図に基づくアスペクト比。

  指定可能な値: `adaptive`, `16:9`, `9:16`, `1:1`, `4:3`, `3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  解像度レベル。サポートされる値はモデルによって異なります:
- wan2.5-i2v-preview: 480P, 720P, 1080P
- wan2.6 モデル (t2v, i2v, r2v): 720P, 1080P のみ (480P はサポートされません)
- wan2.7 モデル (i2v, t2v, r2v, videoedit): 720P, 1080P (デフォルト 1080P)
- wan3.0-video, wan3.0-video-prime: 480P, 720P, 1080P (上流のデフォルト 1080P)
- happyhorse-1.0-* (t2v, i2v, r2v, video-edit): 720P, 1080P
- happyhorse-1.1-* (t2v, i2v, r2v): 480P, 720P, 1080P
このプロキシは、resolution も size も指定されていないビデオ生成リクエストを拒否します。解像度ティアが課金レートを選択するためです。このプロキシは検証の前に resolution を大文字化し、大文字化した値を転送します。この列挙に含まれない値には 400 を返し、上記で 480P がないとされている wan2.6、wan2.7、happyhorse-1.0 モデルでは、480P に対して 400 を返します (resolution として送信された場合も、480P の size として送信された場合も同様です)。

  指定可能な値: `480P`, `720P`, `1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  乱数シード。モデルが生成するコンテンツのランダム性を制御するために使用します

  範囲: `0` から `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  インテリジェントなマルチレンズ制御。prompt_extend が有効な場合にのみ機能します。
wan2.6 および wan2.7-r2v モデル向けです。
- single: シングルショットビデオ (デフォルト)
- multi: マルチショットビデオ

  指定可能な値: `multi`, `single`
</ParamField>

<ParamField body="parameters.size" type="string">
  width*height 形式のビデオ解像度。サポートされる解像度はモデルによって異なります:
wan2.5 T2V の場合: 480P (480*832, 832*480, 624*624)、720P、1080P のサイズ
wan2.6 T2V/R2V の場合 (480P なし):
  720P: 1280*720, 720*1280, 960*960, 1088*832, 832*1088
  1080P: 1920*1080, 1080*1920, 1440*1440, 1632*1248, 1248*1632
size と resolution の両方が送信された場合、課金ティアを選択するのは size であり、
resolution はそのモデルに対してこのプロキシが受け付ける値である必要があります。480P の size は、
resolution の説明で 480P がないと記載されているすべてのモデルで 400 を返します。
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  ウォーターマークロゴを追加するかどうか。ウォーターマークは右下隅に配置されます
</ParamField>
