Wan 2.6 I2V の API リファレンスです。Wan 2.6 の画像から動画へは、静止した最初のフレームをアニメーション化します。720P または 1080P、最大 15 秒に対応しています。

**入力：** 画像, オーディオ, テキスト · **出力：** ビデオ + オーディオ

## クイックスタート

**モデル ID:** `wan/wan2.6-i2v`

**エンドポイント:** `POST https://api.comfy.org/v2/models/wan/wan2.6-i2v`

# 環境変数から COMFY_API_KEY を読み取ります。
# 各 submit() 呼び出しは独自の Idempotency-Key を発行し、自動リトライで再利用します。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/wan2.6-i2v",
            {
                "input": {
                    "prompt": "the robot lowers its raised arm and steps toward the camera, the flat orange backdrop holds steady",
                    "img_url": "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # モデル ID と合わせて、別のプロセスが必要とするすべて

        # リクエストが完了するまでポーリングし、サーバーが指定する Retry-After の間待機します。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # プロバイダー自身のペイロードで、models.run() が返す値と同じです。
        # 失敗またはキャンセルされたリクエストはここで型付きの Router エラーを発生させます。
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())

### 入力

<ParamField body="input" type="object" required>
  プロンプトなどの基本情報を入力します。
</ParamField>

<ParamField body="input.audio_url" type="string">
  オーディオファイルのダウンロードURL。対応形式: mp3 および wav。reference_video_urls とは併用できません。
</ParamField>

<ParamField body="input.img_url" type="string">
  先頭フレームの画像URLまたは Base64 エンコードデータ。wan2.5-i2v-preview および
wan2.6-i2v モデルでは必須です。happyhorse-1.x の i2v 系スペルは、先頭フレームを
ここでは受け取りません。代わりに type が first_frame の media 要素として受け取ります
（後述の media を参照）。また、wan2.6-i2v で成功する img_url のボディは、
happyhorse-1.0-i2v と happyhorse-1.1-i2v ではプロバイダーに拒否されます。さらに
wan2.7/wan3.0 系のスペルも参照アセットを media で受け取ります。画像形式: JPEG、JPG、PNG、BMP、WEBP。
解像度: 360-2000 ピクセル。ファイルサイズ: 最大 10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。ビデオ生成用の参照素材（画像、オーディオ、ビデオ）を
指定します。各要素は type フィールドと url フィールドを持ちます。このフィールドは
このコンポーネントから提供されるすべてのモデルで共有されており、どのモデルがどの
type 値を受け入れるか、また画像やビデオの入力を img_url や reference_video_urls
ではなくここで持つかどうかは、モデルごとに異なります。モデルごとの対応 type 値:
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frame と
  last_frame: JPEG/JPG/PNG/BMP/WEBP、1 辺あたり 240-8000 ピクセル、アスペクト比は
  1:8 から 8:1 の間、最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。
  driving_audio（WAV/MP3、2-30 秒、最大 15MB）と first_clip（MP4/MOV、2-10
  秒、1 辺あたり 240-4096 ピクセル、最大 100MB）: 公開 HTTP/HTTPS URL。インラインの
  data: URL は受け付けられません。
- wan2.7-r2v: first_frame（任意、最大 1）、reference_image、reference_video。少なくとも
  1 つの reference_image または reference_video が必要で、reference 画像と
  reference ビデオの合計は最大 5 です。first_frame と reference_image: JPEG/JPG/PNG/BMP/WEBP
  （アルファチャンネルなし）、1 辺あたり 240-8000 ピクセル、アスペクト比は 1:8 から 8:1 の間、最大
  20MB、公開 URL または data:\{MIME_type};base64,... URL。reference_video: 公開
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-videoedit: video（正確に 1 つ、編集対象のクリップ: MP4/MOV、2-10 秒、
  1 辺あたり 240-4096 ピクセル、最大 100MB、公開 HTTP/HTTPS URL。インラインの data: URL
  は受け付けられません）に加えて、任意で 0 から 4 つの reference_image（JPEG/JPG/PNG/BMP/WEBP、
  1 辺あたり 240-8000 ピクセル、アスペクト比は 1:8 から 8:1 の間、最大 20MB、公開 URL
  または data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime: first_frame（最大 1）、last_frame（最大 1）、
  reference_image（最大 10）、reference_video（最大 5 クリップ、合計再生時間 \<= 15s）、
  reference_audio（最大 5 クリップ、合計再生時間 \<= 15s）、file（最大 1、link とは
  併用不可）、link（最大 1、file とは併用不可）。reference_*/file/link の type
  と first_frame/last_frame の type は、同じリクエスト内で相互に排他的です。
  配列の順序が、プロンプト内のアセットの参照順序を定義します（Image 1、Video 1、
  Audio 1、...）。first_frame、last_frame、reference_image: JPEG/JPG/PNG/BMP/WEBP、
  1 辺あたり 240-8000 ピクセル、アスペクト比は最大 8:1、最大 20MB、公開 URL または
  data:\{MIME_type};base64,... URL。reference_video、reference_audio、file、link: 公開
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v: first_frame のみ、正確に 1 つ。これらのスペルは
  先頭フレームを img_url ではなくここで受け取ります。少なくとも 300x300 ピクセル、アスペクト比
  は 1:2.5 から 2.5:1 の間、JPEG/JPG/PNG/WEBP、最大 20MB、公開 URL または
  data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v: reference_image のみ、1 から 9 つ。これが
  このモデル唯一の参照入力です。最短辺は少なくとも 400 ピクセル、JPEG/JPG/PNG/WEBP、
  最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。reference_video は
  この操作の入力タイプではありません。
- happyhorse-1.0-video-edit: video（正確に 1 つ、編集対象のクリップ: MP4/MOV、3-60
  秒、長辺は最大 4096 ピクセル、短辺は少なくとも 360 ピクセル、アスペクト
  比は 1:2.5 から 2.5:1 の間、最大 100MB、公開 HTTP/HTTPS URL。インラインの data:
  URL は受け付けられません）に加えて、任意で 0 から 5 つの reference_image（JPEG/JPG/PNG/WEBP、少なくとも
  300x300 ピクセル、アスペクト比は 1:2.5 から 2.5:1 の間、最大 20MB、公開 URL
  または data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview:
  テキストから動画への操作。これらのパートナーの参照資料にはメディア入力が記載されていないため、この
  フィールドは未設定のままにしてください。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v: このコンポーネントはこれらのスペル向けの
  メディア語彙を列挙していません。wan2.5-i2v-preview と wan2.6-i2v は先頭
  フレームを img_url で受け取り、wan2.6-r2v は参照クリップを reference_video_urls で受け取ります。
上記のモデルごとの数値はパートナーの制約であり、このスキーマの制約ではありません。受け入れ可能な
type とその上限はモデルごとに異なるため、media には
minItems/maxItems が宣言されていません。スキーマが受け入れることは、プロバイダーが受け入れることを
意味しません。逆に、上記のアセットごとの「最大 20MB」という数値は、画像
入力（インラインで送信できる唯一の入力）の上限であり、パートナーが最終的に受け取る
アセットに対するパートナーの上限です。そして、アセットが公開 URL である場合は記載どおりに適用されます。
そのバイトは Comfy を経由しないためです。インラインの data:\{MIME_type};base64,...
URL は Comfy を経由するため、転送時の上限にも直面します。Comfy Router
の POST ボディは合計 100 MiB に制限され、それを超えると 413 が返されます。また base64 は
ペイロードを約 4/3 に膨らませるため、おおよそ 75 MB を超える単一のインラインアセットは、ここに
記載したパートナーのルールに到達する前に拒否されます。そのサイズでは、単一のアセットがパートナー自身の20MB の上限であればインラインで問題なく収まるため、アセットが 1 つの場合はパートナーのルールが制約条件となります。トランスポートの上限は複数のアセットにまたがる場合に制約となり、100 MiB の Router 上限は要素ごとではなくリクエスト全体を制限するからです。これらの上限に近いものはパブリック URL として送信してください。
</ParamField>

<ParamField body="input.media[].url" type="string" required>
  メディアファイルの URL: パブリックな HTTP/HTTPS URL、または、上記の `media` の説明で各モデルごとに列挙されているまさにその IMAGE 入力（wan2.7-i2v の first_frame と last_frame、wan2.7-r2v の first_frame と reference_image、wan2.7-videoedit の reference_image、wan3.0-video と wan3.0-video-prime の first_frame、last_frame、reference_image、happyhorse-1.0-i2v と happyhorse-1.1-i2v の first_frame、happyhorse-1.0-r2v と happyhorse-1.1-r2v の reference_image、そして happyhorse-1.0-video-edit の reference_image）に限り、インラインの `data:{MIME_type};base64,...` URL。これらのモデルのいずれにおいても、video、audio、file、link の入力はインラインの data: URL を受け付けません。パートナー自身のアップロードサービスによる oss://dashscope-instant の一時 URL、または（wan2.7-videoedit では）Asset Center の asset_id は、それをアップロードした Alibaba Cloud アカウントに対してのみ解決されます。Comfy は自身のキーでモデルを呼び出し、アップロード経路を公開していないため、呼び出し元自身の oss:// URL や asset_id はサポートされた入力ではありません。このフィールドは URL スキームを検証しないため、そのような値はここで拒否されることなく、そのままパートナーへ転送されます。モデルごとのサイズとピクセルの上限、およびインラインのペイロードを全体として制限する 100 MiB の Router リクエストボディ上限については、`media` の説明を参照してください。

<ParamField body="input.prompt" type="string">
  テキストプロンプト。中国語と英語をサポートし、長さは 800 文字以内（wan3.0-video では最大 20,000 文字。上限を超えたコンテンツは切り捨てられます）。
複数の参照ビデオを使う wan2.6-r2v では、'character1'、'character2' などを参照ビデオの順序で被写体を指すために使用します。例: "Character1 sings on the roadside, Character2 dances beside it"
wan3.0-video の参照モードでは、'Image 1'、'Video 1'、'Audio 1' などを使用し、media 配列内の対応する順序でメディアアセットを参照します。
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  wan2.6-r2v モデル専用の参照ビデオ URL。1～3 本のビデオ URL の配列です。
入力の制限:
- 形式: mp4、mov
- 本数: 1～3 本
- 1 本あたりのビデオの長さ: 2～30 秒
- 1 ファイルあたりのファイルサイズ: 最大 30MB
- audio_url と併用できません
参照再生時間: ビデオ 1 本なら最大 5 秒、2 本ならそれぞれ最大 2.5 秒、3 本ならそれに応じて短くなります。
課金: 実際に使用した参照再生時間に基づきます。
</ParamField>

<ParamField body="input.template" type="string">
  ビデオエフェクトのテンプレート名。任意。現在サポートされているのは squish、flying、carousel です。使用した場合、prompt パラメータは無視されます。

<ParamField body="parameters.duration" type="integer" default="5">
  生成されるビデオの再生時間（秒）:
- wan2.5 モデル: 5 秒または 10 秒
- wan2.6-t2v、wan2.6-i2v: 5、10、または 15 秒
- wan2.6-r2v: 5 秒または 10 秒のみ（15 秒は非サポート）
- wan2.7-i2v、wan2.7-t2v: [2, 15] の整数
- wan2.7-r2v、wan2.7-videoedit: [2, 10] の整数
- wan3.0-video: ビデオ入力がない場合は [2, 30] の整数。ビデオ入力がある場合は、入力ビデオの再生時間と出力ビデオの再生時間の合計が 30 秒を超えてはなりません。-1 を指定すると、モデルが適切な再生時間を選択するスマート再生時間モードが有効になります

  範囲: `-1` ～ `30`
</ParamField>

<ParamField body="parameters.prompt_extend" type="boolean" default="true">
  プロンプトのインテリジェントな書き換えを有効にするかどうか。デフォルトは true です
</ParamField>

<ParamField body="parameters.ratio" type="string">
  生成されるビデオのアスペクト比。wan2.7 および wan3.0 モデル専用です。
wan2.7 モデルでは、指定しない場合は解像度の階層に基づいてデフォルトが決まります。
wan3.0-video では、adaptive（デフォルト）が入力メディアの比率と意図に基づいて適切なアスペクト比を自動的に推奨します。

  指定可能な値: `adaptive`、`16:9`、`9:16`、`1:1`、`4:3`、`3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  解像度レベル。サポートされる値はモデルによって異なります:
- wan2.5-i2v-preview: 480P、720P、1080P
- wan2.6-i2v: 720P、1080P のみ（480P は非サポート）
- wan2.7 モデル（i2v、t2v、r2v、videoedit）: 720P、1080P（デフォルト 1080P）
- wan3.0-video、wan3.0-video-prime: 480P、720P、1080P（アップストリームのデフォルト 1080P）

</ParamField>このプロキシは、解像度もサイズも指定されていないビデオ生成リクエストを拒否します。解像度ティアが課金レートを決定するためです。

  指定可能な値: `480P`, `720P`, `1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  乱数シード。モデルが生成するコンテンツのランダム性を制御するために使用します。

  範囲: `0` ～ `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  インテリジェントなマルチレンズ制御。prompt_extend が有効な場合にのみ動作します。
wan2.6 および wan2.7-r2v モデル用。
- single: シングルショットビデオ（デフォルト）
- multi: マルチショットビデオ

  指定可能な値: `multi`, `single`
</ParamField>

<ParamField body="parameters.size" type="string">
  幅*高さ 形式のビデオ解像度。対応する解像度はモデルによって異なります。
wan2.5 T2V の場合: 480P（480*832、832*480、624*624）、720P、1080P の各サイズ
wan2.6 T2V/R2V の場合（480P なし）:
  720P: 1280*720, 720*1280, 960*960, 1088*832, 832*1088
  1080P: 1920*1080, 1080*1920, 1440*1440, 1632*1248, 1248*1632
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  ウォーターマークロゴを追加するかどうか。ウォーターマークは右下隅に配置されます。
</ParamField>
