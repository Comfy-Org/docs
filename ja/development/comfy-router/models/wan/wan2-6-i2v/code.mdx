Wan 2.6 I2V の API リファレンスです。Wan 2.6 の画像から動画へは、静止した最初のフレームをアニメーション化します。720P または 1080P、最大 15 秒に対応しています。

**入力：** 画像, オーディオ, テキスト · **出力：** ビデオ + オーディオ

## クイックスタート

**モデル ID:** `wan/wan2.6-i2v`

**エンドポイント:** `POST https://api.comfy.org/v2/models/wan/wan2.6-i2v`

# 環境変数から COMFY_API_KEY を読み取ります。
# 各 submit() 呼び出しは独自の Idempotency-Key を発行し、自動リトライで再利用します。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(

                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # モデル ID と合わせて、別のプロセスが必要とするすべて

        # リクエストが完了するまでポーリングし、サーバーが指定する Retry-After の間待機します。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # プロバイダー自身のペイロードで、models.run() が返す値と同じです。
        # 失敗またはキャンセルされたリクエストはここで型付きの Router エラーを発生させます。

    print("video:", result["output"]["video_url"])

<ParamField body="input.audio_url" type="string">
  オーディオファイルのダウンロードURL。対応形式: mp3 および wav。reference_video_urls とは併用できません。
</ParamField>

<ParamField body="input.img_url" type="string">
  最初フレームの画像URLまたはBase64エンコードデータ。wan2.5-i2v-preview および
wan2.6-i2v モデルでは必須です。happyhorse-1.x の i2v 表記では、最初フレームをここで渡しません。
type が first_frame の media 要素として渡します（後述の media を参照）。
また、wan2.6-i2v では成功する img_url のボディも、happyhorse-1.0-i2v および
happyhorse-1.1-i2v ではプロバイダーに拒否されます。wan2.7/wan3.0 の表記でも、
参照アセットは同様に media で渡します。画像形式: JPEG、JPG、PNG、BMP、WEBP。
解像度: 360～2000ピクセル。ファイルサイズ: 最大10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。ビデオ生成用の参照素材（画像、オーディオ、ビデオ）を
指定します。各要素は type フィールドと url フィールドを持ちます。このフィールドは
このコンポーネントから提供されるすべてのモデルで共通ですが、どの type 値をその
モデルが受け付けるか、また画像やビデオの入力を img_url や reference_video_urls
ではなくここで渡すかどうかは、モデルによって異なります。モデルごとの対応 type 値は
次のとおりです:
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frame と
  last_frame: JPEG/JPG/PNG/BMP/WEBP、1辺あたり240～8000ピクセル、アスペクト比1:8
  ～8:1、最大20MB、パブリックURLまたは data:\{MIME_type};base64,... URL。
  driving_audio（WAV/MP3、2～30秒、最大15MB）と first_clip（MP4/MOV、2～10
  秒、1辺あたり240～4096ピクセル、最大100MB）: パブリックな HTTP/HTTPS URL。
  インラインの data: URL は受け付けられません。
- wan2.7-r2v: first_frame（任意、最大1）、reference_image、reference_video。
  reference_image または reference_video のうち少なくとも1つが必須で、reference
  画像と reference ビデオの合計は最大5です。first_frame と reference_image: JPEG/JPG/PNG/BMP/WEBP
  （アルファチャンネルなし）、1辺あたり240～8000ピクセル、アスペクト比1:8～8:1、最大
  20MB、パブリックURLまたは data:\{MIME_type};base64,... URL。reference_video: パブリックな
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-videoedit: video（ちょうど1つ、編集対象のクリップ: MP4/MOV、2～10秒、
  1辺あたり240～4096ピクセル、最大100MB、パブリックな HTTP/HTTPS URL。インラインの data: URL
  は受け付けられません）と、任意で0～4つの reference_image（JPEG/JPG/PNG/BMP/WEBP、
  1辺あたり240～8000ピクセル、アスペクト比1:8～8:1、最大20MB、パブリックURL
  または data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime: first_frame（最大1）、last_frame（最大1）、
  reference_image（最大10）、reference_video（最大5クリップ、合計再生時間 \<= 15秒）、
  reference_audio（最大5クリップ、合計再生時間 \<= 15秒）、file（最大1、link とは併用
  不可）、link（最大1、file とは併用不可）。reference_*/file/link の各 type
  と first_frame/last_frame の各 type は、同じリクエスト内では相互排他です。
  配列の順序が、プロンプト内でのアセットの参照順序を定義します（Image 1、Video 1、
  Audio 1、...）。first_frame、last_frame、reference_image: JPEG/JPG/PNG/BMP/WEBP、
  1辺あたり240～8000ピクセル、アスペクト比最大8:1、最大20MB、パブリックURLまたは
  data:\{MIME_type};base64,... URL。reference_video、reference_audio、file、link: パブリックな
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v: first_frame のみ、ちょうど1つ。これらの表記
  では最初フレームをここで渡し、img_url では渡しません。少なくとも300x300ピクセル、アスペクト比
  1:2.5～2.5:1、JPEG/JPG/PNG/WEBP、最大20MB、パブリックURLまたは
  data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v: reference_image のみ、1～9個。これが
  このモデル唯一の参照入力です。最短辺が少なくとも400ピクセル、JPEG/JPG/PNG/WEBP、
  最大20MB、パブリックURLまたは data:\{MIME_type};base64,... URL。reference_video は
  この操作の入力 type ではありません。
- happyhorse-1.0-video-edit: video（ちょうど1つ、編集対象のクリップ: MP4/MOV、3～60
  秒、長辺が最大4096ピクセル、短辺が少なくとも360ピクセル、アスペクト
  比1:2.5～2.5:1、最大100MB、パブリックな HTTP/HTTPS URL。インラインの data:
  URL は受け付けられません）と、任意で0～5つの reference_image（JPEG/JPG/PNG/WEBP、
  少なくとも300x300ピクセル、アスペクト比1:2.5～2.5:1、最大20MB、パブリックURL
  または data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview:
  テキストから動画への操作です。これらのパートナー参照ドキュメントには media 入力の記載がないため、このフィールドは
  未設定のままにしてください。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v: これらの表記について、このコンポーネントは
  media の語彙を列挙していません。wan2.5-i2v-preview と wan2.6-i2v は最初
  フレームを img_url で渡し、wan2.6-r2v は参照クリップを reference_video_urls で渡します。
上記のモデルごとの個数は、このスキーマの制約ではなくパートナーの制約です。media には
minItems/maxItems が宣言されていません。許容される type とその上限がモデルごとに
異なるためです。スキーマが受け付けることは、プロバイダーが受け付けることを意味しません。逆に、
上記のアセットごとの「最大20MB」という数値（画像入力の上限であり、インラインで送信できる
唯一の入力です）は、パートナーが最終的に受け取るアセットに対するパートナーの上限であり、
アセットがパブリックURLの場合は記載どおりに適用されます。そのバイト列が Comfy を
経由しないためです。インラインの data:\{MIME_type};base64,...
URL は Comfy を経由するため、転送上の上限にも直面します。Comfy Router
の POST ボディは合計100MiBに制限され、それを超えると 413 が返されます。また base64 は
ペイロードを約4/3に膨らませるため、およそ75MBを超える単一のインラインアセットは、ここに
記されたパートナーのルールに到達する前に拒否されます。そのサイズでは、パートナー自身の20MB の上限ならインラインで問題なく収まるため、アセット 1 つの場合はパートナーのルールが制約となります。複数のアセットにまたがる場合は転送の上限が制約となります。これは 100 MiB の Router 上限が各要素ではなくリクエスト全体を制限するためです。これらの上限に近いものは、パブリック URL として送信してください。

<ParamField body="parameters.duration" type="integer" default="5">
  生成されるビデオの再生時間（秒）:
- wan2.5 モデル: 5 または 10 秒
- wan2.6-t2v、wan2.6-i2v: 5、10、または 15 秒
- wan2.6-r2v: 5 または 10 秒のみ（15 秒は非サポート）

  入力ビデオの再生時間 + 出力ビデオの再生時間の合計が 30 秒を超えてはなりません。-1 を指定すると、
  モデルが適切な再生時間を選ぶスマート再生時間モードが有効になります
このプロキシは [-1, 30] の範囲外の再生時間に対して 400 を返します。

  範囲: `-1` から `30`
</ParamField>

<ParamField body="parameters.prompt_extend" type="boolean" default="true">
  プロンプトのインテリジェントな書き換えを有効にするかどうか。デフォルトは true です
</ParamField>

<ParamField body="parameters.ratio" type="string">
  生成されるビデオのアスペクト比。wan2.7 および wan3.0 モデル専用です。
wan2.7 モデルでは、指定しない場合は解像度の階層に基づいてデフォルトが決まります。
wan3.0-video では、adaptive（デフォルト）が入力メディアの比率と意図に基づいて
適切なアスペクト比を自動的に推奨します。

  指定可能な値: `adaptive`、`16:9`、`9:16`、`1:1`、`4:3`、`3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  解像度レベル。サポートされる値はモデルによって異なります:
- wan2.5-i2v-preview: 480P、720P、1080P
- wan2.6 モデル（t2v、i2v、r2v）: 720P、1080P のみ（480P は非サポート）
- wan2.7 モデル（i2v、t2v、r2v、videoedit）: 720P、1080P（デフォルト 1080P）
- wan3.0-video、wan3.0-video-prime: 480P、720P、1080P（アップストリームのデフォルトは 1080P）
- happyhorse-1.0-*（t2v、i2v、r2v、video-edit）: 720P、1080P
- happyhorse-1.1-*（t2v、i2v、r2v）: 480P、720P、1080P
このプロキシは、解像度も size も指定していないビデオ生成リクエストを拒否します。解像度の階層が課金レートを決めるためです。このプロキシは、確認する前に解像度を大文字に変換し、大文字に変換した値を転送します。この enum に含まれない値には 400 を返し、上記で 480P を持たないと記載されている wan2.6、wan2.7、happyhorse-1.0 の各モデルに対する 480P（解像度として送信された場合も、480P の size として送信された場合も）には 400 を返します。

  指定可能な値: `480P`, `720P`, `1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  乱数シード。モデルが生成するコンテンツのランダム性を制御するために使用します。

  範囲: `0` ～ `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  インテリジェントなマルチレンズ制御。prompt_extend が有効な場合にのみ機能します。
wan2.6 および wan2.7-r2v モデルで使用します。
- single: 単一ショットビデオ（デフォルト）
- multi: マルチショットビデオ

  指定可能な値: `multi`, `single`
</ParamField>

<ParamField body="parameters.size" type="string">
  width*height 形式のビデオ解像度。対応する解像度はモデルによって異なります:
wan2.5 T2V の場合: 480P（480*832、832*480、624*624）、720P、1080P の各サイズ
wan2.6 T2V/R2V の場合（480P なし）:
  720P: 1280*720、720*1280、960*960、1088*832、832*1088
  1080P: 1920*1080、1080*1920、1440*1440、1632*1248、1248*1632
size と解像度の両方を送信した場合、課金対象の階層を選択するのは size であり、解像度はそのモデルに対してこのプロキシが受け付ける値である必要があります。480P の size は、解像度の説明で 480P を持たないと記載されているすべてのモデルで 400 を返します。
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  透かしロゴを追加するかどうか。透かしは右下隅に配置されます。
</ParamField>
