**入力：** ビデオ, 画像, テキスト · **出力：** ビデオ

import asyncio
from comfy_sdk import AsyncComfy

# 環境変数から COMFY_API_KEY を読み取ります。
# submit() を呼び出すたびに独自の Idempotency-Key が生成され、自動再試行で再利用されます。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/wan2.7-videoedit",
            {
                "input": {
                    "prompt": "restyle the clip as a hand-drawn ink sketch, keep the dancer's movement unchanged",
                    "media": [
                        {
                            "type": "video",
                            "url": "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/street_dancer.mp4",
                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                    "audio_setting": "origin",
                },
            },
        )
        print("request_id:", handle.request_id)  # モデル ID とあわせて、別のプロセスが必要とする情報のすべて

        # リクエストが完了するまでポーリングし、サーバーが指定する Retry-After の間待機します。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # プロバイダー自身のペイロードで、models.run() が返すのと同じ値です。
        # 失敗またはキャンセル済みのリクエストは、ここで型付きの Router エラーを発生させます。

    print("video:", result["output"]["video_url"])

</ParamField>

<ParamField body="input.img_url" type="string">
  最初のフレーム画像の URL、または Base64 エンコードされたデータ。wan2.5-i2v-preview と
wan2.6-i2v モデルでは必須です。happyhorse-1.x の i2v 系の名称は、最初のフレームを
ここでは受け取りません。type が first_frame の media 要素として受け取ります（後述の
media を参照）。また、wan2.6-i2v では成功する img_url のボディも、happyhorse-1.0-i2v と
happyhorse-1.1-i2v ではプロバイダーに拒否されます。wan2.7/wan3.0 系の名称も参照アセットを
media で受け取ります。画像形式: JPEG、JPG、PNG、BMP、WEBP。
解像度: 360-2000 ピクセル。ファイルサイズ: 最大 10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。ビデオ生成用の参照素材（画像、オーディオ、ビデオ）を指定します。各要素は type と url のフィールドを持ちます。このフィールドは本コンポーネントから提供されるすべてのモデルで共通であり、どのモデルがどの type 値を受け付けるか、またそもそも画像やビデオの入力を img_url や reference_video_urls ではなくここで持つかどうかは、モデルによって異なります。モデルごとの対応 type 値:
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frame と last_frame: JPEG/JPG/PNG/BMP/WEBP、各辺 240-8000 ピクセル、アスペクト比 1:8 から 8:1、最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。driving_audio（WAV/MP3、2-30 秒、最大 15MB）と first_clip（MP4/MOV、2-10 秒、各辺 240-4096 ピクセル、最大 100MB）: 公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-r2v: first_frame（任意、最大 1）、reference_image、reference_video。reference_image または reference_video が少なくとも 1 つ必要で、reference_image と reference_video は合計で最大 5 です。first_frame と reference_image: JPEG/JPG/PNG/BMP/WEBP（アルファチャンネルなし）、各辺 240-8000 ピクセル、アスペクト比 1:8 から 8:1、最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。reference_video: 公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-videoedit: video（正確に 1 つ、編集対象のクリップ: MP4/MOV、2-10 秒、各辺 240-4096 ピクセル、最大 100MB、公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません）に加えて、任意で 0 から 4 つの reference_image（JPEG/JPG/PNG/BMP/WEBP、各辺 240-8000 ピクセル、アスペクト比 1:8 から 8:1、最大 20MB、公開 URL または data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime: first_frame（最大 1）、last_frame（最大 1）、reference_image（最大 10）、reference_video（最大 5 クリップ、合計再生時間 \<= 15s）、reference_audio（最大 5 クリップ、合計再生時間 \<= 15s）、file（最大 1、link とは併用不可）、link（最大 1、file とは併用不可）。reference_*/file/link タイプと first_frame/last_frame タイプは、同一リクエスト内では相互に排他的です。配列の順序が、プロンプト内のアセットの参照順序を定義します（Image 1、Video 1、Audio 1、...）。first_frame、last_frame、reference_image: JPEG/JPG/PNG/BMP/WEBP、各辺 240-8000 ピクセル、アスペクト比は最大 8:1、最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。reference_video、reference_audio、file、link: 公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v: first_frame のみ、正確に 1 つ。これらの名称は最初のフレームを img_url ではなくここで受け取ります。少なくとも 300x300 ピクセル、アスペクト比 1:2.5 から 2.5:1、JPEG/JPG/PNG/WEBP、最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v: reference_image のみ、1 から 9 つ。これはこのモデル唯一の参照入力です。最短辺が少なくとも 400 ピクセル、JPEG/JPG/PNG/WEBP、最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。reference_video はこの操作の入力タイプではありません。
- happyhorse-1.0-video-edit: video（正確に 1 つ、編集対象のクリップ: MP4/MOV、3-60 秒、長辺が最大 4096 ピクセル、短辺が少なくとも 360 ピクセル、アスペクト比 1:2.5 から 2.5:1、最大 100MB、公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません）に加えて、任意で 0 から 5 つの reference_image（JPEG/JPG/PNG/WEBP、少なくとも 300x300 ピクセル、アスペクト比 1:2.5 から 2.5:1、最大 20MB、公開 URL または data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview: テキストから動画への操作です。これらのパートナーリファレンスには media 入力の記載がないため、このフィールドは未設定のままにしてください。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v: 本コンポーネントは、これらの名称に対する media の語彙を列挙していません。wan2.5-i2v-preview と wan2.6-i2v は最初のフレームを img_url で受け取り、wan2.6-r2v は参照クリップを reference_video_urls で受け取ります。
上記のモデルごとの件数は本スキーマの制約ではなくパートナーの制約です。media には minItems/maxItems が宣言されていません。許容されるタイプとその上限がモデルごとに異なるためです。スキーマが受理しても、プロバイダーが受理するとは限りません。逆に、上記のアセットごとの「最大 20MB」という数値（画像入力の上限であり、インラインで送信できる唯一の入力です）は、最終的にパートナーが受け取るアセットに対するパートナーの上限であり、アセットが公開 URL の場合はそのまま適用されます。そのバイト列は Comfy を経由しないためです。インラインの data:\{MIME_type};base64,... URL は Comfy を経由するため、転送上の上限にも直面します。Comfy Router の POST ボディは合計 100 MiB に制限され、それを超えると 413 が返されます。また base64 はペイロードを約 4/3 に膨らませるため、およそ 75 MB を超える単一のインラインアセットは、ここに示したパートナーのルールに到達する前に拒否されます。そのサイズでは、パートナー自身の20MBの上限はインラインで問題なく収まるため、単一のアセットではパートナーのルールが制約となります。
トランスポートの上限は複数のアセットにまたがる場合に制約となります。100 MiBのRouter上限は
各要素ではなくリクエスト全体を制限するためです。これらの上限に近いものは、すべてパブリック
URLとして送信してください。

  プロンプトのインテリジェントな書き換えを有効にするかどうか。デフォルトはtrueです
</ParamField>

<ParamField body="parameters.ratio" type="string">
  生成されるビデオのアスペクト比。wan2.7およびwan3.0モデル専用です。
wan2.7モデルでは、指定しない場合、解像度ティアに基づいてデフォルトが決まります。
wan3.0-videoでは、adaptive（デフォルト）が入力メディアの比率と意図に基づいて
適切なアスペクト比を自動的に推奨します。

  指定可能な値: `adaptive`, `16:9`, `9:16`, `1:1`, `4:3`, `3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  解像度レベル。サポートされる値はモデルによって異なります:
- wan2.5-i2v-preview: 480P, 720P, 1080P
- wan2.6モデル（t2v、i2v、r2v）: 720P, 1080Pのみ（480Pはサポートされません）
- wan2.7モデル（i2v、t2v、r2v、videoedit）: 720P, 1080P（デフォルトは1080P）
- wan3.0-video, wan3.0-video-prime: 480P, 720P, 1080P（上流のデフォルトは 1080P）
- happyhorse-1.0-*（t2v, i2v, r2v, video-edit）: 720P, 1080P
- happyhorse-1.1-*（t2v, i2v, r2v）: 480P, 720P, 1080P
このプロキシは、resolution と size のどちらも指定されていないビデオ生成リクエストを拒否します。解像度のティアが課金レートを決定するためです。チェックの前に resolution を大文字化し、大文字化した値を転送します。この enum に含まれない値には 400 を返し、上記で 480P を持たないものとして記載されている wan2.6、wan2.7、happyhorse-1.0 のモデルに対しては、480P（resolution として送信された場合でも、480P の size として送信された場合でも）に 400 を返します。

  指定可能な値: `480P`, `720P`, `1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  乱数シード。モデルが生成するコンテンツのランダム性を制御するために使用します

  範囲: `0` ～ `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  インテリジェントなマルチレンズ制御。prompt_extend が有効な場合にのみ機能します。wan2.6 および wan2.7-r2v モデル用です。
- single: 単一ショットのビデオ（デフォルト）
- multi: マルチショットのビデオ

  指定可能な値: `multi`, `single`
</ParamField>

<ParamField body="parameters.size" type="string">
  width*height 形式のビデオ解像度。対応する解像度はモデルによって異なります:
wan2.5 T2V の場合: 480P（480*832, 832*480, 624*624）、720P、1080P の各サイズ
wan2.6 T2V/R2V の場合（480P なし）:
  720P: 1280*720, 720*1280, 960*960, 1088*832, 832*1088
  1080P: 1920*1080, 1080*1920, 1440*1440, 1632*1248, 1248*1632
size と resolution の両方を送信した場合、課金ティアを選択するのは size であり、resolution はそのモデルに対してこのプロキシが受け付ける値である必要があります。480P の size は、resolution の説明で 480P なしと記載されているすべてのモデルで 400 を返します。
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  ウォーターマークロゴを追加するかどうか。ウォーターマークは右下隅に配置されます
</ParamField>
