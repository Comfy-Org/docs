**入力：** ビデオ, 画像, テキスト · **出力：** ビデオ

from comfy_sdk import AsyncComfy

# 環境変数から COMFY_API_KEY を読み取ります。
# submit() を呼び出すたびに独自の Idempotency-Key が生成され、自動再試行で再利用されます。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/wan2.7-videoedit",
            {
                "input": {
                    "prompt": "restyle the clip as a hand-drawn ink sketch, keep the dancer's movement unchanged",
                    "media": [
                        {

                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                    "audio_setting": "origin",
                },
            },
        )
        print("request_id:", handle.request_id)  # モデル ID とあわせて、別のプロセスが必要とする情報のすべて

        # リクエストが完了するまでポーリングし、サーバーが指定する Retry-After の間待機します。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # プロバイダー自身のペイロードで、models.run() が返すのと同じ値です。
        # 失敗またはキャンセル済みのリクエストは、ここで型付きの Router エラーを発生させます。

    print("video:", result["output"]["video_url"])

### 入力

<ParamField body="input" type="object" required>
  プロンプトなど、基本的な情報を入力します。
</ParamField>

<ParamField body="input.audio_url" type="string">
  オーディオファイルのダウンロードURL。対応形式: mp3 と wav。reference_video_urls とは併用できません。
</ParamField>

<ParamField body="input.img_url" type="string">
  先頭フレーム画像のURL、または Base64 エンコードされたデータ。wan2.5-i2v-preview と
wan2.6-i2v モデルでは必須です。happyhorse-1.x の i2v 系スペルでは先頭フレームをここでは
受け取りません。first_frame タイプの media 要素として受け取ります（後述の media を参照）。
また、wan2.6-i2v では成功する img_url ボディも、happyhorse-1.0-i2v と
happyhorse-1.1-i2v ではプロバイダーに拒否されます。さらに wan2.7/wan3.0 系のスペルも
参照アセットは media で受け取ります。画像形式: JPEG、JPG、PNG、BMP、WEBP。
解像度: 360～2000ピクセル。ファイルサイズ: 最大10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。ビデオ生成用の参照素材（画像、オーディオ、ビデオ）を
指定します。各要素は type フィールドと url フィールドを含みます。このフィールドはこの
コンポーネントから提供されるすべてのモデルで共通であり、どの type 値を特定のモデルが
受け付けるか、またそのモデルが画像やビデオの入力を img_url や reference_video_urls
ではなくここで渡すかどうかは、モデルごとに異なります。モデルごとの対応 type 値:
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frame と
  last_frame: JPEG/JPG/PNG/BMP/WEBP、1辺あたり240～8000ピクセル、アスペクト比 1:8
  ～8:1、最大20MB、パブリックURL または data:\{MIME_type};base64,... URL。
  driving_audio（WAV/MP3、2～30秒、最大15MB）と first_clip（MP4/MOV、2～10
  秒、1辺あたり240～4096ピクセル、最大100MB）: パブリックな HTTP/HTTPS URL。
  インラインの data: URL は受け付けられません。
- wan2.7-r2v: first_frame（任意、最大1）、reference_image、reference_video。少なくとも
  1つの reference_image または reference_video が必要で、参照画像と
  参照ビデオの合計は最大5つです。first_frame と reference_image: JPEG/JPG/PNG/BMP/WEBP
  （アルファチャンネルなし）、1辺あたり240～8000ピクセル、アスペクト比 1:8～8:1、最大
  20MB、パブリックURL または data:\{MIME_type};base64,... URL。reference_video: パブリックな
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-videoedit: video（ちょうど1つ、編集対象のクリップ: MP4/MOV、2～10秒、
  1辺あたり240～4096ピクセル、最大100MB、パブリックな HTTP/HTTPS URL。インラインの data: URL
  は受け付けられません）に加えて、任意で0～4つの reference_image（JPEG/JPG/PNG/BMP/WEBP、
  1辺あたり240～8000ピクセル、アスペクト比 1:8～8:1、最大20MB、パブリックURL
  または data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime: first_frame（最大1）、last_frame（最大1）、
  reference_image（最大10）、reference_video（最大5クリップ、再生時間の合計 \<= 15s）、
  reference_audio（最大5クリップ、再生時間の合計 \<= 15s）、file（最大1、link とは
  併用不可）、link（最大1、file とは併用不可）。reference_*/file/link タイプ
  と first_frame/last_frame タイプは、同じリクエスト内では相互に排他的です。
  配列の順序がプロンプト内のアセットの参照順（Image 1、Video 1、
  Audio 1、...）を定義します。first_frame、last_frame、reference_image: JPEG/JPG/PNG/BMP/WEBP、
  1辺あたり240～8000ピクセル、アスペクト比は最大8:1、最大20MB、パブリックURL
  または data:\{MIME_type};base64,... URL。reference_video、reference_audio、file、link:
  パブリックな HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v: first_frame のみ、ちょうど1つ。これらのスペル
  では先頭フレームをここで受け取り、img_url では受け取りません。少なくとも 300x300 ピクセル、アスペクト比
  1:2.5～2.5:1、JPEG/JPG/PNG/WEBP、最大20MB、パブリックURL または
  data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v: reference_image のみ、1～9つ。これはこの
  モデル唯一の参照入力です。最短辺が少なくとも400ピクセル、JPEG/JPG/PNG/WEBP、
  最大20MB、パブリックURL または data:\{MIME_type};base64,... URL。reference_video は
  この操作の入力タイプではありません。
- happyhorse-1.0-video-edit: video（ちょうど1つ、編集対象のクリップ: MP4/MOV、3～60
  秒、長辺が最大4096ピクセル、短辺が少なくとも360ピクセル、アスペクト比
  1:2.5～2.5:1、最大100MB、パブリックな HTTP/HTTPS URL。インラインの data:
  URL は受け付けられません）に加えて、任意で0～5つの reference_image（JPEG/JPG/PNG/BMP/WEBP、
  少なくとも 300x300 ピクセル、アスペクト比 1:2.5～2.5:1、最大20MB、パブリックURL
  または data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview:
  テキストから動画への操作。これらのパートナーのリファレンスには media 入力の記載がないため、このフィールドは
  未設定のままにしてください。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v: このコンポーネントはこれらのスペルに対する media
  の語彙を列挙していません。wan2.5-i2v-preview と wan2.6-i2v は先頭
  フレームを img_url で受け取り、wan2.6-r2v は参照クリップを reference_video_urls で受け取ります。
上記のモデルごとの数値はこのスキーマの制約ではなく、パートナーの制約です。media には
minItems/maxItems が宣言されていません。受け付けられるタイプとその上限が
モデルごとに異なるためです。スキーマが受け付けても、プロバイダーが受け付けるとは限りません。逆に、
上記のアセットごとの「最大20MB」という数値（画像入力の上限であり、インラインで
送信できる唯一の入力です）は、最終的に受け取るアセットに対するパートナーの上限であり、
アセットがパブリックURLの場合には記載どおりに適用されます。そのバイト列は
Comfy を経由しないためです。インラインの data:\{MIME_type};base64,...
URL は Comfy を経由するため、転送上の上限にも達します。Comfy Router
の POST ボディは合計 100 MiB に制限され、それを超えると 413 が返されます。また base64 は
ペイロードを約 4/3 に膨らませるため、およそ 75 MB を超える単一のインラインアセットは、ここに示した
パートナーのルールに到達する前に拒否されます。そのサイズでは、パートナー自身の単一の
アセットは20MB の上限はインラインで余裕をもって収まるため、1 つのアセットについてはパートナーのルールが制約となります。
100 MiB の Router 上限は各要素ではなくリクエスト全体を制限するため、トランスポートの上限は複数のアセットにまたがる場合に制約となります。
これらの上限に近いものは、パブリック URL として送信してください。

<ParamField body="input.prompt" type="string">
  テキストプロンプトの語句。中国語と英語をサポートし、長さは 800 文字以内です
(wan3.0-video では最大 20,000 文字。制限を超えたコンテンツは切り捨てられます)。
複数の参照ビデオを使用する wan2.6-r2v では、'character1'、'character2' などを使用して、
参照ビデオの順序で被写体を参照します。例: "Character1 sings on the roadside, Character2 dances beside it"
wan3.0-video の参照モードでは、'Image 1'、'Video 1'、'Audio 1' などを使用して、
media 配列内の対応する順序でメディアアセットを参照します。
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  wan2.6-r2v モデル専用の参照ビデオ URL。1～3 個のビデオ URL の配列です。
入力の制限:
- フォーマット: mp4、mov
- 数量: 1～3 本のビデオ
- 単一ビデオの長さ: 2～30 秒
- 単一ファイルサイズ: 最大 30MB
- audio_url と併用できません
参照の再生時間: 単一ビデオは最大 5 秒、2 本のビデオはそれぞれ最大 2.5 秒、3 本のビデオはそれに比例して短くなります。
課金: 実際に使用した参照の再生時間に基づきます。
</ParamField>

- wan2.6-t2v、wan2.6-i2v: 5、10、または 15 秒
- wan2.6-r2v: 5 秒または 10 秒のみ (15 秒はサポートされません)
- wan2.7-i2v、wan2.7-t2v: [2, 15] の整数
- wan2.7-r2v、wan2.7-videoedit: [2, 10] の整数
- wan3.0-video: ビデオ入力なしの場合は [2, 30] の整数。ビデオ入力ありの場合は、
  入力ビデオの再生時間 + 出力ビデオの再生時間の合計が 30 秒を超えてはなりません。-1 を指定すると、
  モデルが適切な再生時間を選択するスマート再生時間モードが有効になります

  範囲: `-1` から `30`
</ParamField>

<ParamField body="parameters.prompt_extend" type="boolean" default="true">
  プロンプトのインテリジェントな書き換えを有効にするかどうか。デフォルトは true です
</ParamField>

<ParamField body="parameters.ratio" type="string">
  生成されるビデオのアスペクト比。wan2.7 および wan3.0 モデル専用です。
wan2.7 モデルでは、指定しない場合は解像度の階層に基づいてデフォルトが決まります。
wan3.0-video では、adaptive (デフォルト) が入力メディアの比率と意図に基づいて
適切なアスペクト比を自動的に推奨します。

  指定可能な値: `adaptive`、`16:9`、`9:16`、`1:1`、`4:3`、`3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  解像度レベル。サポートされる値はモデルによって異なります:
- wan2.5-i2v-preview: 480P、720P、1080P
- wan2.6-i2v: 720P、1080P のみ (480P はサポートされません)
- wan2.7 モデル (i2v、t2v、r2v、videoedit): 720P、1080P (デフォルト 1080P)
- wan3.0-video、wan3.0-video-prime: 480P、720P、1080P (上流のデフォルト 1080P)このプロキシは、解像度とサイズのどちらも指定されていないビデオ生成リクエストを拒否します。解像度ティアによって課金レートが決まるためです。

  指定可能な値: `480P`, `720P`, `1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  乱数シード。モデルが生成するコンテンツのランダム性を制御するために使用します

  範囲: `0` から `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  インテリジェントなマルチレンズ制御。prompt_extend が有効な場合にのみ機能します。
wan2.6 および wan2.7-r2v モデル用。
- single: シングルショットビデオ（デフォルト）
- multi: マルチショットビデオ

  指定可能な値: `multi`, `single`
</ParamField>

<ParamField body="parameters.size" type="string">
  幅*高さ 形式のビデオ解像度。サポートされる解像度はモデルによって異なります:
wan2.5 T2V の場合: 480P (480*832, 832*480, 624*624)、720P、1080P サイズ
wan2.6 T2V/R2V の場合（480P なし）:
  720P: 1280*720, 720*1280, 960*960, 1088*832, 832*1088
  1080P: 1920*1080, 1080*1920, 1440*1440, 1632*1248, 1248*1632
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  ウォーターマークロゴを追加するかどうか。ウォーターマークは右下隅に配置されます
</ParamField>
