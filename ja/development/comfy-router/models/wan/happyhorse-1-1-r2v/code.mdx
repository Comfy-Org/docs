import asyncio
from comfy_sdk import AsyncComfy

# 環境変数から COMFY_API_KEY を読み取ります。
# submit() 呼び出しごとに独自の Idempotency-Key を生成し、自動リトライで再利用します。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/happyhorse-1.1-r2v",
            {
                "input": {
                    "prompt": "character1 walks in from the left, turns to the camera and waves, plain orange backdrop",
                    "media": [
                        {

                            "url": "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # モデル ID と合わせて、別のプロセスに必要な情報はこれだけです

        # リクエストが完了するまでポーリングし、サーバーが指定する Retry-After の時間だけ待機します。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # プロバイダー自身のペイロードで、models.run() が返すのと同じ値です。
        # 失敗またはキャンセル済みのリクエストは、ここで型付きの Router エラーを発生させます。

  オーディオファイルのダウンロードURL。対応形式: mp3 と wav。reference_video_urls とは併用できません。
</ParamField>

<ParamField body="input.img_url" type="string">
  最初フレームの画像URL、または Base64 エンコードされたデータ。wan2.5-i2v-preview モデルと
wan2.6-i2v モデルでは必須です。happyhorse-1.x の i2v 系スペルは、最初フレームをここでは
受け取りません。first_frame タイプのメディア要素として受け取ります（後述の media を参照）。
また、wan2.6-i2v で成功する img_url ボディは、happyhorse-1.0-i2v と happyhorse-1.1-i2v では
プロバイダーに拒否されます。さらに wan2.7/wan3.0 系スペルも参照アセットを media で受け取ります。
画像形式: JPEG、JPG、PNG、BMP、WEBP。
解像度: 360-2000ピクセル。ファイルサイズ: 最大10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。ビデオ生成のための参照素材（画像、オーディオ、ビデオ）を指定します。
各要素は type と url フィールドを含みます。このフィールドはこのコンポーネントから提供される
すべてのモデルで共通であり、あるモデルがどの type 値を受け入れるか（また、画像またはビデオの
入力を img_url や reference_video_urls ではなくここで受け取るかどうか）はモデルによって異なります。
モデルごとの対応 type 値:
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frame と
  last_frame: JPEG/JPG/PNG/BMP/WEBP、1辺あたり240-8000ピクセル、アスペクト比 1:8 から 8:1 の間、
  最大20MB、パブリックURL または data:\{MIME_type\};base64,... URL。
  driving_audio（WAV/MP3、2-30秒、最大15MB）と first_clip（MP4/MOV、2-10秒、
  1辺あたり240-4096ピクセル、最大100MB）: パブリックな HTTP/HTTPS URL。インラインの
  data: URL は受け付けられません。
- wan2.7-r2v: first_frame（任意、最大1）、reference_image、reference_video。少なくとも
  1つの reference_image または reference_video が必要で、reference_image と
  reference_video を合わせて最大5つです。first_frame と reference_image: JPEG/JPG/PNG/BMP/WEBP
  （アルファチャンネルなし）、1辺あたり240-8000ピクセル、アスペクト比 1:8 から 8:1 の間、最大
  20MB、パブリックURL または data:\{MIME_type\};base64,... URL。reference_video: パブリックな
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-videoedit: video（ちょうど1つ、編集対象のクリップ: MP4/MOV、2-10秒、
  1辺あたり240-4096ピクセル、最大100MB、パブリックな HTTP/HTTPS URL。インラインの data: URL
  は受け付けられません）に加えて、任意で0から4つの reference_image（JPEG/JPG/PNG/BMP/WEBP、
  1辺あたり240-8000ピクセル、アスペクト比 1:8 から 8:1 の間、最大20MB、パブリックURL
  または data:\{MIME_type\};base64,... URL）。
- wan3.0-video, wan3.0-video-prime: first_frame（最大1）、last_frame（最大1）、
  reference_image（最大10）、reference_video（最大5クリップ、合計再生時間 \<= 15秒）、
  reference_audio（最大5クリップ、合計再生時間 \<= 15秒）、file（最大1、link とは併用
  できません）、link（最大1、file とは併用できません）。reference_*/file/link タイプ
  と first_frame/last_frame タイプは、同一リクエスト内で相互排他的です。
  配列の順序がプロンプト内のアセットの参照順序を定義します（Image 1、Video 1、
  Audio 1、...）。first_frame、last_frame と reference_image: JPEG/JPG/PNG/BMP/WEBP、
  1辺あたり240-8000ピクセル、アスペクト比 最大 8:1、最大20MB、パブリックURL または
  data:\{MIME_type\};base64,... URL。reference_video、reference_audio、file と link:
  パブリックな HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- happyhorse-1.0-i2v, happyhorse-1.1-i2v: first_frame のみ、ちょうど1つ。これらのスペルは
  最初フレームをここで受け取り、img_url では受け取りません。少なくとも 300x300 ピクセル、
  アスペクト比 1:2.5 から 2.5:1 の間、JPEG/JPG/PNG/WEBP、最大20MB、パブリックURL または
  data:\{MIME_type\};base64,... URL。
- happyhorse-1.0-r2v, happyhorse-1.1-r2v: reference_image のみ、1から9つ。これは
  このモデル唯一の参照入力です。最短辺が少なくとも400ピクセル、JPEG/JPG/PNG/WEBP、
  最大20MB、パブリックURL または data:\{MIME_type\};base64,... URL。reference_video は
  この操作の入力タイプではありません。
- happyhorse-1.0-video-edit: video（ちょうど1つ、編集対象のクリップ: MP4/MOV、3-60秒、
  長辺が最大4096ピクセル、短辺が少なくとも360ピクセル、アスペクト比 1:2.5 から 2.5:1 の間、
  最大100MB、パブリックな HTTP/HTTPS URL。インラインの data: URL は受け付けられません）
  に加えて、任意で0から5つの reference_image（JPEG/JPG/PNG/WEBP、少なくとも 300x300
  ピクセル、アスペクト比 1:2.5 から 2.5:1 の間、最大20MB、パブリックURL または
  data:\{MIME_type\};base64,... URL）。
- happyhorse-1.0-t2v, happyhorse-1.1-t2v, wan2.7-t2v, wan2.6-t2v, wan2.5-t2v-preview:
  テキストから動画への操作。これらのパートナー参照にはメディア入力の記載がないため、
  このフィールドは未設定のままにしてください。
- wan2.5-i2v-preview, wan2.6-i2v, wan2.6-r2v: このコンポーネントはこれらのスペルに対する
  メディア語彙を列挙していません。wan2.5-i2v-preview と wan2.6-i2v は最初フレームを
  img_url で受け取り、wan2.6-r2v は参照クリップを reference_video_urls で受け取ります。
上記のモデルごとの数値はパートナーの制約であり、このスキーマの制約ではありません。media には
minItems/maxItems が宣言されていません。許容される type とその上限はモデルごとに異なるためです。
スキーマが受け入れることはプロバイダーが受け入れることを意味しません。また逆に、上記の
アセットごとの「最大20MB」という数値（画像入力の上限であり、これらはインラインで送信できる
唯一の入力です）は、パートナーが最終的に受け取るアセットに対する上限であり、アセットが
パブリックURLの場合はそのまま適用されます。そのバイトは Comfy を経由しないためです。
インラインの data:\{MIME_type\};base64,... URL は Comfy を経由するため、転送上の上限にも
直面します。Comfy Router の POST ボディは合計 100 MiB に制限され、それを超えると 413 が
返されます。また base64 はペイロードを約 4/3 に膨らませるため、およそ 75 MB を超える
単一のインラインアセットは、ここに記載されたパートナーのルールに到達する前に拒否されます。
そのサイズでは、パートナー自身の20MB の上限はインラインで余裕をもって収まるため、1 つのアセットについてはパートナーのルールが制約となります。複数のアセットにまたがる場合は転送の上限が制約となります。100 MiB の Router 上限は各要素ではなくリクエスト全体を制限するためです。これらの上限に近いものは、パブリック URL として送信してください。

<ParamField body="input.prompt" type="string">
  テキストプロンプト。中国語と英語をサポートし、長さは 800 文字を超えないようにしてください

複数の参照ビデオを使用する wan2.6-r2v では、'character1'、'character2' などを使用して、参照ビデオの順に被写体を参照します。

<ParamField body="input.reference_video_urls" type="string[]">
  wan2.6-r2v モデル専用の参照ビデオ URL。1〜3 本のビデオ URL の配列です。

- 数量: ビデオ 1〜3 本

参照再生時間: 単一ビデオは最大 5 秒、2 本のビデオはそれぞれ最大 2.5 秒、3 本のビデオは比例して短くなります。

- wan2.6-r2v: 5 秒または 10 秒のみ（15 秒はサポートされません）
- wan2.7-i2v、wan2.7-t2v: 範囲 [2, 15] の整数
- wan2.7-r2v、wan2.7-videoedit: 範囲 [2, 10] の整数
- wan3.0-video: ビデオ入力なしの場合は範囲 [2, 30] の整数。ビデオ入力ありの場合、総入力ビデオ再生時間 + 出力ビデオ再生時間が 30 秒を超えてはなりません。-1 はスマート再生時間モードを有効にし、モデルが適切な再生時間を選択します

  範囲: `-1` から `30`
</ParamField>

<ParamField body="parameters.prompt_extend" type="boolean" default="true">

</ParamField>

<ParamField body="parameters.ratio" type="string">

wan3.0-video では、adaptive（デフォルト）が入力メディアの比率と意図に基づいて適切な
比率を自動的に推奨します。

  可能な値: `adaptive`, `16:9`, `9:16`, `1:1`, `4:3`, `3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  解像度レベル。サポートされる値はモデルによって異なります:
- wan2.5-i2v-preview: 480P、720P、1080P
- wan2.6-i2v: 720P、1080P のみ（480P はサポートされません）
- wan2.7 モデル（i2v、t2v、r2v、videoedit）: 720P、1080P（デフォルト 1080P）
- wan3.0-video、wan3.0-video-prime: 480P、720P、1080P（上流のデフォルトは 1080P）このプロキシは、解像度も size も指定されていないビデオ生成リクエストを拒否します。解像度のティアによって課金レートが選択されるためです。

  指定可能な値: `480P`、`720P`、`1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">

  範囲: `0` から `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">

wan2.6 および wan2.7-r2v モデル用。
- single: シングルショットビデオ（デフォルト）
- multi: マルチショットビデオ

  指定可能な値: `multi`、`single`
</ParamField>

<ParamField body="parameters.size" type="string">

wan2.5 T2V の場合: 480P（480*832、832*480、624*624）、720P、1080P の各サイズ
wan2.6 T2V/R2V の場合（480P なし）:
  720P: 1280*720、720*1280、960*960、1088*832、832*1088
  1080P: 1920*1080、1080*1920、1440*1440、1632*1248、1248*1632
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
