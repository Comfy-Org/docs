**入力：** 画像, テキスト · **出力：** ビデオ

import asyncio
from comfy_sdk import AsyncComfy

# 環境変数から COMFY_API_KEY を読み取ります。
# submit() 呼び出しごとに独自の Idempotency-Key を生成し、自動リトライで再利用します。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(

            {

                    "media": [

                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # モデル ID と合わせて、別のプロセスに必要な情報はこれだけです

        # リクエストが完了するまでポーリングし、サーバーが指定する Retry-After の時間だけ待機します。
        async for update in handle.iter_events():

        # プロバイダー自身のペイロードで、models.run() が返すのと同じ値です。
        # 失敗またはキャンセル済みのリクエストは、ここで型付きの Router エラーを発生させます。

  プロンプトワードなどの基本情報を入力します。
</ParamField>

<ParamField body="input.audio_url" type="string">
  オーディオファイルのダウンロード URL。対応形式: mp3 および wav。reference_video_urls とは併用できません。
</ParamField>

<ParamField body="input.img_url" type="string">
  先頭フレーム画像の URL、または Base64 エンコードされたデータ。wan2.5-i2v-preview および
wan2.6-i2v モデルでは必須です。happyhorse-1.x の i2v 系の呼称は、先頭フレームをここでは
受け取りません。type が first_frame の media 要素として受け取ります（後述の media を参照）。
また、wan2.6-i2v では成功する img_url ボディも、happyhorse-1.0-i2v と
happyhorse-1.1-i2v ではプロバイダーに拒否されます。wan2.7/wan3.0 系の呼称も、
参照アセットを media で受け取ります。画像形式: JPEG、JPG、PNG、BMP、WEBP。
解像度: 360-2000 ピクセル。ファイルサイズ: 最大 10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。動画生成のための参照素材（画像、オーディオ、ビデオ）を
指定します。各要素は type と url フィールドを含みます。このフィールドはこの
コンポーネントから提供されるすべてのモデルで共通であり、どのモデルがどの type 値を
受け入れるか、また画像やビデオの入力を img_url や reference_video_urls ではなく
ここで渡すかどうかは、モデルによって異なります。モデルごとの対応 type 値:
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frame と
  last_frame: JPEG/JPG/PNG/BMP/WEBP、1辺あたり 240-8000 ピクセル、アスペクト比 1:8
  から 8:1 の間、最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。
  driving_audio（WAV/MP3、2-30 秒、最大 15MB）と first_clip（MP4/MOV、2-10
  秒、1辺あたり 240-4096 ピクセル、最大 100MB）: 公開 HTTP/HTTPS URL。インラインの
  data: URL は受け付けられません。
- wan2.7-r2v: first_frame（任意、最大 1）、reference_image、reference_video。少なくとも
  reference_image または reference_video が 1 つ必要で、参照画像と
  参照ビデオの合計は最大 5 です。first_frame と reference_image: JPEG/JPG/PNG/BMP/WEBP
  （アルファチャンネルなし）、1辺あたり 240-8000 ピクセル、アスペクト比 1:8 から 8:1 の間、最大
  20MB、公開 URL または data:\{MIME_type};base64,... URL。reference_video: 公開
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-videoedit: video（ちょうど 1 つ。編集対象のクリップ: MP4/MOV、2-10 秒、
  1辺あたり 240-4096 ピクセル、最大 100MB、公開 HTTP/HTTPS URL。インラインの data: URL
  は受け付けられません）に加えて、任意で 0 から 4 つの reference_image（JPEG/JPG/PNG/BMP/WEBP、
  1辺あたり 240-8000 ピクセル、アスペクト比 1:8 から 8:1 の間、最大 20MB、公開 URL
  または data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime: first_frame（最大 1）、last_frame（最大 1）、
  reference_image（最大 10）、reference_video（最大 5 クリップ、合計再生時間 \<= 15s）、
  reference_audio（最大 5 クリップ、合計再生時間 \<= 15s）、file（最大 1、link とは
  併用不可）、link（最大 1、file とは併用不可）。reference_*/file/link の type
  と first_frame/last_frame の type は、同じリクエスト内では同時に使用できません。
  配列の順序が、プロンプト内でのアセットの参照順序を定義します（画像 1、ビデオ 1、
  オーディオ 1、...）。first_frame、last_frame、reference_image: JPEG/JPG/PNG/BMP/WEBP、
  1辺あたり 240-8000 ピクセル、アスペクト比は最大 8:1、最大 20MB、公開 URL または
  data:\{MIME_type};base64,... URL。reference_video、reference_audio、file、link:
  公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v: first_frame のみ、ちょうど 1 つ。これらの呼称
  は先頭フレームをここで受け取り、img_url では受け取りません。少なくとも 300x300
  ピクセル、アスペクト比 1:2.5 から 2.5:1 の間、JPEG/JPG/PNG/WEBP、最大 20MB、公開 URL
  または data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v: reference_image のみ、1 から 9 個。これが
  このモデル唯一の参照入力です。最短辺が少なくとも 400 ピクセル、JPEG/JPG/PNG/WEBP、
  最大 20MB、公開 URL または data:\{MIME_type};base64,... URL。reference_video は
  この操作の入力タイプではありません。
- happyhorse-1.0-video-edit: video（ちょうど 1 つ。編集対象のクリップ: MP4/MOV、3-60
  秒、長辺が最大 4096 ピクセル、短辺が少なくとも 360 ピクセル、アスペクト
  比 1:2.5 から 2.5:1 の間、最大 100MB、公開 HTTP/HTTPS URL。インラインの data:
  URL は受け付けられません）に加えて、任意で 0 から 5 つの reference_image（JPEG/JPG/PNG/BMP/WEBP、
  少なくとも 300x300 ピクセル、アスペクト比 1:2.5 から 2.5:1 の間、最大 20MB、公開 URL
  または data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview:
  テキストから動画への操作。これらのパートナーのリファレンスには media 入力の記載が
  ないため、このフィールドは未設定のままにしてください。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v: このコンポーネントはこれらの呼称に
  ついて media の語彙を列挙していません。wan2.5-i2v-preview と wan2.6-i2v は先頭
  フレームを img_url で受け取り、wan2.6-r2v は参照クリップを reference_video_urls で
  受け取ります。
上記のモデルごとの個数は、このスキーマの制約ではなくパートナーの制約です。media
には minItems/maxItems が宣言されていません。許容される type とその上限は
モデルごとに異なるためです。スキーマで受け入れられることは、プロバイダーが受け入れ
ることを意味しません。また逆に、上記のアセットごとの「最大 20MB」という数値
（画像入力の上限であり、インラインで送信できる唯一の入力です）は、最終的に
受け取るアセットに対するパートナーの上限であり、アセットが公開 URL の場合は
そのまま適用されます。そのバイト列が Comfy を経由することはないためです。
インラインの data:\{MIME_type};base64,... URL は Comfy を経由するため、
転送時の上限にも当てはまります。Comfy Router の POST ボディは合計で 100 MiB に
制限され、それを超えると 413 が返されます。また base64 はペイロードを約 4/3 に
膨らませるため、およそ 75 MB を超える単一のインラインアセットは、ここにある
パートナーのルールのいずれかに到達する前に拒否されます。そのサイズでは、
パートナー自身の20MB の上限であればインラインで問題なく収まるため、アセットが 1 つの場合はパートナーのルールが制約となります。複数のアセットにまたがる場合は、転送時の上限が制約となります。100 MiB の Router 上限は各要素ではなくリクエスト全体を制限するためです。これらの上限に近いものは public URL として送信してください。

<ParamField body="input.media[].url" type="string" required>

<ParamField body="input.prompt" type="string">
  テキストプロンプトの語句。中国語と英語をサポートし、長さは 800 文字以内です

複数の参照ビデオを使用する wan2.6-r2v では、参照ビデオの順序に合わせて 'character1'、'character2' などで被写体を参照してください。例：「Character1 が道端で歌い、Character2 がその横で踊る」

<ParamField body="input.reference_video_urls" type="string[]">
  wan2.6-r2v モデル専用の参照ビデオ URL。1～3 本のビデオ URL の配列です。

- 本数: 1～3 本のビデオ
- 単一ビデオの長さ: 2～30 秒
- 単一ファイルサイズ: 最大 30MB

参照の再生時間: 単一ビデオは最大 5 秒、2 本のビデオはそれぞれ最大 2.5 秒、3 本のビデオはそれに比例して短くなります。

</ParamField>

このプロキシは、解像度もサイズも指定されていないビデオ生成リクエストを拒否します。解像度の階層が課金レートを決定するためです。解像度はチェックの前に大文字に変換し、変換後の値を転送します。この enum に含まれない値には 400 を返し、上記で 480P 非対応として挙げられている wan2.6、wan2.7、happyhorse-1.0 モデルでは、480P（解像度として送信された場合も、480P のサイズとして送信された場合も）に対して 400 を返します。
