// 環境変数から COMFY_API_KEY を読み取ります。
// 各 submit() 呼び出しは独自の Idempotency-Key を発行し、自動リトライのために再利用します。

const handle = await comfy.models.submit<Result>("wan/wan3.0-video-prime", {

  },
  parameters: {

    duration: 5,
  },
});
console.log("requestId:", handle.requestId); // モデル ID と合わせれば、別のプロセスに必要なものはそれだけです

// リクエストが完了するまでポーリングし、サーバーが示す Retry-After の秒数だけ待機します。
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// models.run() が返すのと同じ結果です。失敗またはキャンセル済みのリクエストは、ここで reject されます。

if (result.kind !== "json") throw new Error("expected a JSON result");

<ParamField body="input.img_url" type="string">

最初のフレームは type が first_frame のメディア要素として受け取ります（後述の media を参照）。

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。動画生成のための参照素材（画像、オーディオ、ビデオ）を指定します。
各要素は type フィールドと url フィールドを持ちます。このフィールドはこのコンポーネントから提供される
すべてのモデルで共通であり、あるモデルがどの type 値を受け付けるか、また画像やビデオの入力を
img_url や reference_video_urls ではなくここで受け取るかどうかは、モデルによって異なります。
モデルごとの対応 type 値は次のとおりです：
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frame と
  last_frame：JPEG/JPG/PNG/BMP/WEBP、1辺240〜8000ピクセル、アスペクト比1:8〜8:1、
  最大20MB、パブリックURLまたは data:\{MIME_type};base64,... URL。

  1辺240〜4096ピクセル、最大100MB）：パブリックな HTTP/HTTPS URL。インラインの
  data: URL は受け付けられません。
- wan2.7-r2v: first_frame（任意、最大1）、reference_image、reference_video。少なくとも
  1つの reference_image または reference_video が必要で、reference_image と
  reference_video の合計は最大5つです。first_frame と reference_image：JPEG/JPG/PNG/BMP/WEBP
  （アルファチャンネルなし）、1辺240〜8000ピクセル、アスペクト比1:8〜8:1、最大
  20MB、パブリックURLまたは data:\{MIME_type};base64,... URL。reference_video：パブリックな
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-videoedit: video（ちょうど1つ。編集対象のクリップ：MP4/MOV、2〜10秒、
  1辺240〜4096ピクセル、最大100MB、パブリックな HTTP/HTTPS URL。インラインの data: URL
  は受け付けられません）に加えて、任意で0〜4つの reference_image（JPEG/JPG/PNG/BMP/WEBP、
  1辺240〜8000ピクセル、アスペクト比1:8〜8:1、最大20MB、パブリックURL
  または data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime: first_frame（最大1）、last_frame（最大1）、
  reference_image（最大10）、reference_video（最大5クリップ、合計再生時間 \<= 15秒）、
  reference_audio（最大5クリップ、合計再生時間 \<= 15秒）、file（最大1、link とは
  併用不可）、link（最大1、file とは併用不可）。reference_*/file/link の各 type
  と first_frame/last_frame の各 type は、同じリクエスト内では排他的です。
  配列の順序が、プロンプト内でのアセットの参照順（Image 1、Video 1、
  Audio 1、...）を定義します。first_frame、last_frame、reference_image：JPEG/JPG/PNG/BMP/WEBP、
  1辺240〜8000ピクセル、アスペクト比最大8:1、最大20MB、パブリックURLまたは
  data:\{MIME_type};base64,... URL。reference_video、reference_audio、file、link：
  パブリックな HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v: first_frame のみ、ちょうど1つ。これらの表記は
  最初のフレームをここで受け取り、img_url では受け取りません。少なくとも300x300ピクセル、
  アスペクト比1:2.5〜2.5:1、JPEG/JPG/PNG/WEBP、最大20MB、パブリックURLまたは
  data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v: reference_image のみ、1〜9つ。これが
  このモデル唯一の参照入力です。最短辺が少なくとも400ピクセル、JPEG/JPG/PNG/WEBP、
  最大20MB、パブリックURLまたは data:\{MIME_type};base64,... URL。reference_video は
  この操作の入力タイプではありません。
- happyhorse-1.0-video-edit: video（ちょうど1つ。編集対象のクリップ：MP4/MOV、3〜60
  秒、長辺が最大4096ピクセル、短辺が少なくとも360ピクセル、アスペクト
  比1:2.5〜2.5:1、最大100MB、パブリックな HTTP/HTTPS URL。インラインの data:
  URL は受け付けられません）に加えて、任意で0〜5つの reference_image（JPEG/JPG/PNG/WEBP、
  少なくとも300x300ピクセル、アスペクト比1:2.5〜2.5:1、最大20MB、パブリックURL
  または data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview:
  テキストから動画への操作です。対応するパートナーのリファレンスにはメディア入力が
  記載されていないため、このフィールドは未設定のままにしてください。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v: このコンポーネントは、これらの表記に対する
  メディアの語彙を列挙していません。wan2.5-i2v-preview と wan2.6-i2v は最初のフレームを
  img_url で受け取り、wan2.6-r2v は参照クリップを reference_video_urls で受け取ります。
上記のモデルごとの個数はパートナーの制約であり、このスキーマの制約ではありません。media には
minItems/maxItems が宣言されていません。許容される type とその上限はモデルごとに異なるためです。
スキーマが受け付けることは、プロバイダーが受け付けることを意味しません。逆方向についても、

パブリックURLの場合はそのまま適用されます。そのバイト列は Comfy を経由しないためです。

達します。Comfy Router の POST ボディは合計で100 MiB に制限され、それを超えると 413 が返り、
base64 はペイロードを約4/3に膨らませるため、およそ75 MB を超える単一のインラインアセットは、
ここに挙げたパートナーのルールのいずれかに到達する前に拒否されます。そのサイズでは、パートナー自身の
</ParamField>

<ParamField body="parameters.resolution" type="string">
  解像度レベル。サポートされる値はモデルによって異なります:
- wan2.5-i2v-preview: 480P, 720P, 1080P
- wan2.6 モデル（t2v、i2v、r2v）: 720P、1080P のみ（480P は非サポート）
- wan2.7 モデル（i2v、t2v、r2v、videoedit）: 720P、1080P（デフォルト 1080P）
- wan3.0-video、wan3.0-video-prime: 480P、720P、1080P（上流のデフォルトは 1080P）
- happyhorse-1.0-*（t2v、i2v、r2v、video-edit）: 720P、1080P
- happyhorse-1.1-*（t2v、i2v、r2v）: 480P、720P、1080P
このプロキシは resolution も size も指定されていないビデオ生成リクエストを拒否します。
解像度ティアが課金レートを決定するためです。チェックの前に resolution を大文字化し、
大文字化した値を転送します。400 を返しますこのenum外の値に対して返され、また 480P に対しては 400 を返します（`resolution` として送信された場合も、480P の `size` として送信された場合も同様です）。対象は、上記で 480P を持たないと記載されている wan2.6、wan2.7、happyhorse-1.0 モデルです。

  指定可能な値: `480P`、`720P`、`1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  乱数シード。モデルが生成するコンテンツのランダム性を制御するために使用します

  範囲: `0` から `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  インテリジェントなマルチレンズ制御。prompt_extend が有効な場合にのみ動作します。
wan2.6 および wan2.7-r2v モデル向け。
- single: シングルショットビデオ（デフォルト）
- multi: マルチショットビデオ

  指定可能な値: `multi`、`single`
</ParamField>

<ParamField body="parameters.size" type="string">
  幅*高さ形式のビデオ解像度。対応する解像度はモデルによって異なります:
wan2.5 T2V の場合: 480P（480*832、832*480、624*624）、720P、1080P のサイズ
wan2.6 T2V/R2V の場合（480P なし）:
  720P: 1280*720、720*1280、960*960、1088*832、832*1088
  1080P: 1920*1080、1080*1920、1440*1440、1632*1248、1248*1632
size と resolution の両方を送信した場合、課金ティアを選択するのは size であり、
resolution はこのプロキシがそのモデルに対して受け付ける値である必要があります。480P のサイズは、
解像度の説明で 480P を持たないと記載されているすべてのモデルで 400 を返します。
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  ウォーターマークロゴを追加するかどうか。ウォーターマークは右下隅に配置されます
</ParamField>
