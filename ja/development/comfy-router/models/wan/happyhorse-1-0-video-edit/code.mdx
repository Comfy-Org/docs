HappyHorse 1.0 Video Edit の API リファレンス。HappyHorse 1.0 video edit は、テキスト指示に基づいて既存のクリップを書き換えます。任意で参照画像をガイドとして使用することもできます。

**入力：** ビデオ, 画像, テキスト · **出力：** ビデオ

## クイックスタート

[Comfy ワークスペース](https://platform.comfy.org/profile/api-keys?onboarding=router)でキーを作成し、`COMFY_API_KEY` としてエクスポートします。Python と TypeScript のスニペットは Comfy SDK（`pip install comfy-sdk` および `npm install @comfyorg/sdk`）を使用しています。cURL スニペットは、生の HTTP で同じ呼び出しを行うものです。

**モデル ID:** `wan/happyhorse-1.0-video-edit`

**エンドポイント:** `POST https://api.comfy.org/v2/models/wan/happyhorse-1.0-video-edit`

同じボディを `POST https://api.comfy.org/v2/models/wan/happyhorse-1.0-video-edit/requests` に送信します。Router は実行が受け付けられるとすぐに `201` と `request_id` を返し、結果は準備ができ次第、このプロセスからでも別のプロセスからでも収集されます。[キュー配信](/ja/development/comfy-router/queue)では、ステータス、キャンセル、収集について順を追って説明しています。

```python Python
import asyncio
from comfy_sdk import AsyncComfy

# 環境変数から COMFY_API_KEY を読み取ります。
# 各 submit() 呼び出しは独自の Idempotency-Key を発行し、自動リトライのために再利用します。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/happyhorse-1.0-video-edit",
            {
                "input": {
                    "prompt": "restyle the clip as a hand-drawn ink sketch, keep the dancer's movement unchanged",
                    "media": [
                        {
                            "type": "video",
                            "url": "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/street_dancer.mp4",
                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                },
            },
        )
        print("request_id:", handle.request_id)  # モデル ID と合わせて、別のプロセスに必要なものはこれだけです

        # リクエストが完了するまでポーリングし、サーバーが指定する Retry-After の秒数だけ待機します。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # プロバイダー自身のペイロードで、models.run() が返す値と同じです。
        # 失敗またはキャンセルされたリクエストはここで型付きの Router エラーを発生させます。
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())
```

## スキーマ

### 入力

<ParamField body="input" type="object" required>
  プロンプトなどの基本情報を入力します。
</ParamField>

<ParamField body="input.audio_url" type="string">
  音声ファイルのダウンロードURL。対応形式: mp3、wav。reference_video_urls とは併用できません。
</ParamField>

<ParamField body="input.img_url" type="string">
  最初のフレーム画像のURL、またはBase64エンコードされたデータ。wan2.5-i2v-preview および
wan2.6-i2v モデルでは必須です。happyhorse-1.x の i2v 系の表記では、最初のフレームをここで受け取りません。
最初のフレームは type が first_frame のメディア要素として受け取ります（後述の media を参照）。また、
wan2.6-i2v では成功する img_url のボディも、happyhorse-1.0-i2v と happyhorse-1.1-i2v ではプロバイダーに
拒否されます。wan2.7/wan3.0 系の表記も参照アセットを media で受け取ります。画像形式: JPEG、JPG、PNG、BMP、WEBP。
解像度: 360〜2000ピクセル。ファイルサイズ: 最大10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。動画生成用の参照素材（画像、音声、ビデオ）を指定します。
各要素は type フィールドと url フィールドを持ちます。このフィールドはこのコンポーネントが提供する
すべてのモデルで共有されますが、どのモデルがどの type 値を受け付けるか、また画像やビデオの入力を
img_url や reference_video_urls ではなくここで受け取るかどうかはモデルによって異なります。
モデルごとの対応する type 値は次のとおりです:
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frame と
  last_frame: JPEG/JPG/PNG/BMP/WEBP、1辺240〜8000ピクセル、アスペクト比1:8〜8:1、
  最大20MB、公開URLまたは data:\{MIME_type};base64,... URL。
  driving_audio（WAV/MP3、2〜30秒、最大15MB）と first_clip（MP4/MOV、2〜10
  秒、1辺240〜4096ピクセル、最大100MB）: 公開HTTP/HTTPS URL。インラインの
  data: URL は受け付けられません。
- wan2.7-r2v: first_frame（任意、最大1）、reference_image、reference_video。少なくとも
  1つの reference_image または reference_video が必要で、reference 画像と
  reference ビデオの合計は最大5つです。first_frame と reference_image: JPEG/JPG/PNG/BMP/WEBP
  （アルファチャンネルなし）、1辺240〜8000ピクセル、アスペクト比1:8〜8:1、最大
  20MB、公開URLまたは data:\{MIME_type};base64,... URL。reference_video: 公開
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-videoedit: video（ちょうど1つ、編集対象のクリップ: MP4/MOV、2〜10秒、
  1辺240〜4096ピクセル、最大100MB、公開HTTP/HTTPS URL。インラインの data: URL
  は受け付けられません）に加えて、任意で0〜4個の reference_image（JPEG/JPG/PNG/BMP/WEBP、
  1辺240〜8000ピクセル、アスペクト比1:8〜8:1、最大20MB、公開URL
  または data:\{MIME_type};base64,... URL）。
- wan3.0-video, wan3.0-video-prime: first_frame（最大1）、last_frame（最大1）、
  reference_image（最大10）、reference_video（最大5クリップ、合計再生時間 \<= 15s）、
  reference_audio（最大5クリップ、合計再生時間 \<= 15s）、file（最大1、link とは併用不可）、
  link（最大1、file とは併用不可）。reference_*/file/link の各 type と
  first_frame/last_frame の各 type は同じリクエスト内では同時に使用できません。
  配列の順序が、プロンプト内のアセットの参照順（Image 1、Video 1、
  Audio 1、...）を定義します。first_frame、last_frame、reference_image: JPEG/JPG/PNG/BMP/WEBP、
  1辺240〜8000ピクセル、アスペクト比最大8:1、最大20MB、公開URLまたは
  data:\{MIME_type};base64,... URL。reference_video、reference_audio、file、link:
  公開HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- happyhorse-1.0-i2v, happyhorse-1.1-i2v: first_frame のみ、ちょうど1つ。これらの表記では
  最初のフレームを img_url ではなくここで受け取ります。少なくとも300x300ピクセル、アスペクト比
  1:2.5〜2.5:1、JPEG/JPG/PNG/WEBP、最大20MB、公開URLまたは
  data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v, happyhorse-1.1-r2v: reference_image のみ、1〜9個。これが
  このモデル唯一の参照入力です。短辺が少なくとも400ピクセル、JPEG/JPG/PNG/WEBP、
  最大20MB、公開URLまたは data:\{MIME_type};base64,... URL。reference_video は
  この操作の入力タイプではありません。
- happyhorse-1.0-video-edit: video（ちょうど1つ、編集対象のクリップ: MP4/MOV、3〜60
  秒、長辺が最大4096ピクセル、短辺が少なくとも360ピクセル、アスペクト
  比1:2.5〜2.5:1、最大100MB、公開HTTP/HTTPS URL。インラインの data:
  URL は受け付けられません）に加えて、任意で0〜5個の reference_image（JPEG/JPG/PNG/WEBP、
  少なくとも300x300ピクセル、アスペクト比1:2.5〜2.5:1、最大20MB、公開URL
  または data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v, happyhorse-1.1-t2v, wan2.7-t2v, wan2.6-t2v, wan2.5-t2v-preview:
  テキストから動画への操作です。対応するパートナーのリファレンスにはメディア入力の記載がないため、
  このフィールドは未設定のままにしてください。
- wan2.5-i2v-preview, wan2.6-i2v, wan2.6-r2v: このコンポーネントはこれらの表記に対する
  メディアの語彙を列挙していません。wan2.5-i2v-preview と wan2.6-i2v は最初の
  フレームを img_url で受け取り、wan2.6-r2v は参照クリップを reference_video_urls で受け取ります。
上記のモデルごとの個数はパートナーの制約であり、このスキーマの制約ではありません。media には
minItems/maxItems が宣言されていません。許容される type とその上限は
モデルごとに異なるためです。スキーマが受け付けることはプロバイダーが受け付けることを意味しません。
また逆に、上記のアセットごとの「最大20MB」という数値、つまり画像
入力（インラインで送信できる唯一の入力）の上限は、最終的にパートナーが受け取る
アセットに対するパートナーの上限であり、アセットが公開URLの場合はそのまま適用されます。
そのバイト列がComfyを経由することはないためです。インラインの data:\{MIME_type};base64,...
URL はComfyを経由し、転送の上限にも当たります: Comfy Router の
POST ボディは合計100 MiB に制限され、超えると 413 が返されます。また base64 は
ペイロードを約4/3に膨らませるため、およそ75MBを超える単一のインラインアセットは、
ここに示すパートナーのルールに到達する前に拒否されます。そのサイズでは、パートナー自身の20MB の上限はインラインでも余裕を持って収まるため、単一のアセットではパートナーのルールの方が制約となります。転送の上限は複数のアセットにまたがる場合に効いてきます。100 MiB の Router 上限は各要素ではなくリクエスト全体を制限するためです。これらの上限に近いものは、すべてパブリック URL として送信してください。
</ParamField>

<ParamField body="input.media[].type" type="string" required>
  メディアアセットの種類

  指定可能な値: `first_frame`、`last_frame`、`driving_audio`、`first_clip`、`reference_image`、`reference_video`、`reference_audio`、`video`、`file`、`link`
</ParamField>

<ParamField body="input.media[].url" type="string" required>
  メディアファイルの URL。パブリックな HTTP/HTTPS URL、または、上記の `media` の説明がモデルごとに列挙している IMAGE 入力（wan2.7-i2v の first_frame と last_frame、wan2.7-r2v の first_frame と reference_image、wan2.7-videoedit の reference_image、wan3.0-video と wan3.0-video-prime の first_frame、last_frame、reference_image、happyhorse-1.0-i2v と happyhorse-1.1-i2v の first_frame、happyhorse-1.0-r2v と happyhorse-1.1-r2v の reference_image、happyhorse-1.0-video-edit の reference_image）に限り、インラインの `data:{MIME_type};base64,...` URL も使用できます。これらのモデルの video、audio、file、link のいずれの入力も、インラインの data: URL を受け付けません。パートナー自身のアップロードサービスが発行する oss://dashscope-instant の一時 URL、または（wan2.7-videoedit では）Asset Center の asset_id は、アップロードした Alibaba Cloud アカウントに対してのみ解決されます。Comfy は自身のキーでモデルを呼び出すためアップロード経路を公開しておらず、呼び出し元自身の oss:// URL や asset_id はサポート対象の入力ではありません。このフィールドは URL スキームを検証しないため、そのような値はここで拒否されず、そのままパートナーへ転送されます。モデルごとのサイズとピクセルの制限、およびインラインのペイロードを合計で制限する 100 MiB の Router リクエストボディ上限については、`media` の説明を参照してください。
</ParamField>

<ParamField body="input.negative_prompt" type="string">
  逆プロンプトの語句は、ビデオ画面に映したくないコンテンツを記述するために使用します。500 文字を超えると、wan モデルは拒否せずに切り詰めます。prompt と同じ入力予算に計上されます。
</ParamField>

<ParamField body="input.prompt" type="string">
  テキストプロンプトです。中国語と英語をサポートします。文書化された長さを超えると、wan2.x モデルはプロンプトを拒否せずに切り詰めます。wan2.5 と wan2.6 は 1,500 文字、wan2.7 は 5,000 文字です。wan3.0-video と wan3.0-video-prime は最大 20,000 文字まで受け付けます。プロンプトと negative_prompt を合わせて約 60,850 バイトの UTF-8 テキスト（約 20,000 の中国語文字）を超えるリクエストはプロバイダーが拒否し、InvalidParameter `Range of input length should be [1, 61440]` を返します。
参照ビデオを複数使う wan2.6-r2v では、参照ビデオの順序に従って被写体を 'character1'、'character2' などで参照します。例: "Character1 sings on the roadside, Character2 dances beside it"
wan3.0-video の reference モードでは、media 配列内の対応する順序でメディアアセットを 'Image 1'、'Video 1'、'Audio 1' などで参照します。
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  wan2.6-r2v モデル専用の参照ビデオ URL。1〜3 本のビデオ URL の配列です。
入力の制限:
- 形式: mp4、mov
- 本数: 1〜3 本
- 1 本あたりの長さ: 2〜30 秒
- 1 ファイルあたりのサイズ: 最大 30MB
- audio_url と併用できません
参照の再生時間: 1 本の場合は最大 5 秒、2 本の場合はそれぞれ最大 2.5 秒、3 本の場合は比例して短くなります。
課金: 実際に使用した参照の再生時間に基づきます。
</ParamField>

<ParamField body="input.template" type="string">
  ビデオエフェクトのテンプレート名。任意です。現在サポートしているのは squish、flying、carousel です。使用した場合、prompt パラメータは無視されます。
</ParamField>

</ParamField>

<ParamField body="parameters.audio" type="boolean" default="true">

</ParamField>

<ParamField body="parameters.audio_setting" type="string" default="&quot;auto&quot;">

<ParamField body="parameters.duration" type="integer" default="5">

- wan2.7 モデル（i2v、t2v、r2v、videoedit）: 720P、1080P（デフォルト 1080P）
- wan3.0-video、wan3.0-video-prime: 480P、720P、1080P（上流のデフォルトは 1080P）

- happyhorse-1.1-*（t2v、i2v、r2v）: 480P、720P、1080P
このプロキシは、resolution も size も指定されていないビデオ生成リクエストを拒否します。解像度ティアが課金レートを決めるためです。チェックの前に resolution を大文字化し、大文字化した値をそのまま転送します。この enum に含まれない値には 400 を返し、上記で 480P 非対応と記載した wan2.6、wan2.7、happyhorse-1.0 モデルでは、480P（resolution として送信された場合も、480P の size として送信された場合も）に対して 400 を返します。

  1080P: 1920*1080、1080*1920、1440*1440、1632*1248、1248*1632
