HappyHorse 1.0 Video Edit の API リファレンス。HappyHorse 1.0 video edit は、テキスト指示に基づいて既存のクリップを書き換えます。任意で参照画像をガイドとして使用することもできます。

**入力：** ビデオ, 画像, テキスト · **出力：** ビデオ

## クイックスタート

[Comfy ワークスペース](https://platform.comfy.org/profile/api-keys?onboarding=router)でキーを作成し、`COMFY_API_KEY` としてエクスポートします。Python と TypeScript のスニペットは Comfy SDK（`pip install comfy-sdk` および `npm install @comfyorg/sdk`）を使用しています。cURL スニペットは、生の HTTP で同じ呼び出しを行うものです。

**モデル ID:** `wan/happyhorse-1.0-video-edit`

**エンドポイント:** `POST https://api.comfy.org/v2/models/wan/happyhorse-1.0-video-edit`

同じボディを `POST https://api.comfy.org/v2/models/wan/happyhorse-1.0-video-edit/requests` に送信します。Router は実行が受け付けられるとすぐに `201` と `request_id` を返し、結果は準備ができ次第、このプロセスからでも別のプロセスからでも収集されます。[キュー配信](/ja/development/comfy-router/queue)では、ステータス、キャンセル、収集について順を追って説明しています。

```python Python
import asyncio
from comfy_sdk import AsyncComfy

# 環境変数から COMFY_API_KEY を読み取ります。
# 各 submit() 呼び出しは独自の Idempotency-Key を発行し、自動リトライのために再利用します。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/happyhorse-1.0-video-edit",
            {
                "input": {
                    "prompt": "restyle the clip as a hand-drawn ink sketch, keep the dancer's movement unchanged",
                    "media": [
                        {
                            "type": "video",
                            "url": "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/street_dancer.mp4",
                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                },
            },
        )
        print("request_id:", handle.request_id)  # モデル ID と合わせて、別のプロセスに必要なものはこれだけです

        # リクエストが完了するまでポーリングし、サーバーが指定する Retry-After の秒数だけ待機します。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # プロバイダー自身のペイロードで、models.run() が返す値と同じです。
        # 失敗またはキャンセルされたリクエストはここで型付きの Router エラーを発生させます。
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())
```

## スキーマ

### 入力

<ParamField body="input" type="object" required>
  プロンプトなど、基本的な情報を入力します。
</ParamField>

<ParamField body="input.audio_url" type="string">
  オーディオファイルのダウンロードURL。対応形式: mp3 と wav。reference_video_urls とは併用できません。
</ParamField>

<ParamField body="input.img_url" type="string">
  先頭フレームの画像URL、または Base64 エンコードされたデータ。wan2.5-i2v-preview および
wan2.6-i2v モデルでは必須です。happyhorse-1.x の i2v 系の表記では、ここに先頭フレームを
指定しません。先頭フレームは type が first_frame の media 要素として指定します（後述の
media を参照）。また、wan2.6-i2v では成功する img_url のボディも、happyhorse-1.0-i2v と
happyhorse-1.1-i2v ではプロバイダーに拒否されます。さらに wan2.7/wan3.0 の表記でも
参照アセットは media で指定します。画像形式: JPEG、JPG、PNG、BMP、WEBP。
解像度: 360〜2000ピクセル。ファイルサイズ: 最大10MB。
</ParamField>

<ParamField body="input.media" type="object[]">
  メディアアセットのリスト。ビデオ生成用の参照素材（画像、オーディオ、ビデオ）を指定します。
各要素には type と url フィールドが含まれます。このフィールドはこのコンポーネントが提供する
すべてのモデルで共有されていますが、あるモデルがどの type 値を受け付けるか、また画像や
ビデオの入力を img_url や reference_video_urls ではなくここで渡すかどうかは、モデルごとに
異なります。モデルごとの対応 type 値:
- wan2.7-i2v: first_frame、last_frame、driving_audio、first_clip。first_frame と
  last_frame: JPEG/JPG/PNG/BMP/WEBP、1辺あたり240〜8000ピクセル、アスペクト比は1:8〜8:1、
  最大20MB、公開URLまたは data:\{MIME_type};base64,... URL。
  driving_audio（WAV/MP3、2〜30秒、最大15MB）と first_clip（MP4/MOV、2〜10秒、
  1辺あたり240〜4096ピクセル、最大100MB）: 公開 HTTP/HTTPS URL。インラインの
  data: URL は受け付けられません。
- wan2.7-r2v: first_frame（任意、最大1）、reference_image、reference_video。
  reference_image または reference_video が少なくとも1つ必要で、reference_image と
  reference_video の合計は最大5つです。first_frame と reference_image: JPEG/JPG/PNG/BMP/WEBP
  （アルファチャンネルなし）、1辺あたり240〜8000ピクセル、アスペクト比は1:8〜8:1、最大
  20MB、公開URLまたは data:\{MIME_type};base64,... URL。reference_video: 公開
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- wan2.7-videoedit: video（ちょうど1つ、編集対象のクリップ: MP4/MOV、2〜10秒、
  1辺あたり240〜4096ピクセル、最大100MB、公開 HTTP/HTTPS URL。インラインの data: URL
  は受け付けられません）と、任意で0〜4つの reference_image（JPEG/JPG/PNG/BMP/WEBP、
  1辺あたり240〜8000ピクセル、アスペクト比は1:8〜8:1、最大20MB、公開URL
  または data:\{MIME_type};base64,... URL）。
- wan3.0-video、wan3.0-video-prime: first_frame（最大1）、last_frame（最大1）、
  reference_image（最大10）、reference_video（最大5クリップ、合計再生時間 \<= 15秒）、
  reference_audio（最大5クリップ、合計再生時間 \<= 15秒）、file（最大1、link とは併用不可）、
  link（最大1、file とは併用不可）。reference_*/file/link の type と
  first_frame/last_frame の type は、同じリクエスト内では同時に使用できません。
  配列の順序が、プロンプト内のアセットの参照順序を定義します（Image 1、Video 1、
  Audio 1、...）。first_frame、last_frame、reference_image: JPEG/JPG/PNG/BMP/WEBP、
  1辺あたり240〜8000ピクセル、アスペクト比は最大8:1、最大20MB、公開URLまたは
  data:\{MIME_type};base64,... URL。reference_video、reference_audio、file、link: 公開
  HTTP/HTTPS URL。インラインの data: URL は受け付けられません。
- happyhorse-1.0-i2v、happyhorse-1.1-i2v: first_frame のみ、ちょうど1つ。これらの表記
  では先頭フレームをここで指定し、img_url では指定しません。少なくとも300x300ピクセル、
  アスペクト比は1:2.5〜2.5:1、JPEG/JPG/PNG/WEBP、最大20MB、公開URLまたは
  data:\{MIME_type};base64,... URL。
- happyhorse-1.0-r2v、happyhorse-1.1-r2v: reference_image のみ、1〜9つ。これが
  このモデル唯一の参照入力です。最短辺が少なくとも400ピクセル、JPEG/JPG/PNG/WEBP、
  最大20MB、公開URLまたは data:\{MIME_type};base64,... URL。reference_video は
  この操作の入力タイプではありません。
- happyhorse-1.0-video-edit: video（ちょうど1つ、編集対象のクリップ: MP4/MOV、3〜60秒、
  長辺が最大4096ピクセル、短辺が少なくとも360ピクセル、アスペクト比は1:2.5〜2.5:1、
  最大100MB、公開 HTTP/HTTPS URL。インラインの data: URL は受け付けられません）と、
  任意で0〜5つの reference_image（JPEG/JPG/PNG/BMP/WEBP、少なくとも300x300ピクセル、
  アスペクト比は1:2.5〜2.5:1、最大20MB、公開URLまたは data:\{MIME_type};base64,... URL）。
- happyhorse-1.0-t2v、happyhorse-1.1-t2v、wan2.7-t2v、wan2.6-t2v、wan2.5-t2v-preview:
  テキストから動画への操作です。これらの対になるパートナーのリファレンスには media 入力の
  記載がないため、このフィールドは未設定のままにしてください。
- wan2.5-i2v-preview、wan2.6-i2v、wan2.6-r2v: このコンポーネントはこれらの表記に対する
  media の語彙を列挙していません。wan2.5-i2v-preview と wan2.6-i2v は先頭フレームを
  img_url で指定し、wan2.6-r2v は参照クリップを reference_video_urls で指定します。
上記のモデルごとの個数は、このスキーマではなくパートナー側の制約です。許容される type と
その上限がモデルごとに異なるため、media には minItems/maxItems が宣言されていません。
スキーマが受け付けたからといって、プロバイダーが受け付けるとは限りません。逆に、上記の
アセットごとの「最大20MB」という数値（画像入力の上限であり、インラインで送信できる唯一の
入力です）は、最終的に得られるアセットに対するパートナー側の上限であり、アセットが公開URL
の場合は記載どおりに適用されます。そのバイト列が Comfy を経由することはないためです。
インラインの data:\{MIME_type};base64,... URL は Comfy を経由するため、転送時の上限にも
直面します。Comfy Router の POST ボディは合計 100 MiB に制限され、それを超えると 413 が
返されます。また base64 はペイロードを約4/3に膨らませるため、約75 MB を超える単一の
インラインアセットは、ここに挙げたパートナーのルールに到達する前に拒否されます。その
サイズでは、単一のアセットがパートナー自身の20MB の上限はインラインでも余裕を持って収まるため、アセットが 1 つの場合はパートナーのルールが制約となります。複数のアセットにまたがる場合は転送側の上限が制約となります。100 MiB の Router 上限は各要素ではなくリクエスト全体を制限するためです。これらの上限に近いものは公開 URL として送信してください。
</ParamField>

<ParamField body="input.media[].type" type="string" required>
  メディアアセットのタイプ

  指定可能な値: `first_frame`, `last_frame`, `driving_audio`, `first_clip`, `reference_image`, `reference_video`, `reference_audio`, `video`, `file`, `link`
</ParamField>

<ParamField body="input.media[].url" type="string" required>
  メディアファイルの URL。公開 HTTP/HTTPS URL、または（上記の `media` の説明で各モデルに対して列挙されている画像入力、すなわち wan2.7-i2v の first_frame と last_frame、wan2.7-r2v の first_frame と reference_image、wan2.7-videoedit の reference_image、wan3.0-video と wan3.0-video-prime の first_frame、last_frame、reference_image、happyhorse-1.0-i2v と happyhorse-1.1-i2v の first_frame、happyhorse-1.0-r2v と happyhorse-1.1-r2v の reference_image、happyhorse-1.0-video-edit の reference_image に限り）インラインの `data:{MIME_type};base64,...` URL を指定できます。これらのモデルのビデオ、オーディオ、ファイル、リンクのいずれの入力も、インラインの data: URL を受け付けません。パートナー自身のアップロードサービスによる oss://dashscope-instant の一時 URL、または（wan2.7-videoedit では）Asset Center の asset_id は、それをアップロードした Alibaba Cloud アカウントに対してのみ解決されます。Comfy は自身のキーでモデルを呼び出し、アップロード経路を公開していないため、呼び出し元自身の oss:// URL や asset_id はサポートされる入力ではありません。このフィールドは URL スキームを検証しないため、そのような値はここで拒否されず、そのままパートナーへ転送されます。モデルごとのサイズとピクセルの制限、およびインラインペイロード全体を制限する 100 MiB の Router リクエストボディ上限については、`media` の説明を参照してください。
</ParamField>

<ParamField body="input.negative_prompt" type="string">
  逆プロンプトの語句は、ビデオ画面に映したくないコンテンツを記述するために使用します
</ParamField>

<ParamField body="input.prompt" type="string">
  テキストプロンプト。中国語と英語をサポートし、長さは 800 文字以内です
（wan3.0-video では最大 20,000 文字。制限を超えた内容は切り捨てられます）。
複数の参照ビデオを使う wan2.6-r2v では、'character1'、'character2' などを使って、
参照ビデオの順序で被写体を指定します。例：「Character1 sings on the roadside, Character2 dances beside it」
wan3.0-video の reference モードでは、'Image 1'、'Video 1'、'Audio 1' などを使って、
media 配列内の対応する順序でメディアアセットを指定します。
</ParamField>

<ParamField body="input.reference_video_urls" type="string[]">
  wan2.6-r2v モデル専用の参照ビデオ URL。1〜3 本のビデオ URL の配列。
入力の制限:
- フォーマット: mp4、mov
- 本数: 1〜3 本
- 1 本のビデオの長さ: 2〜30 秒
- 単一ファイルサイズ: 最大 30MB
- audio_url と併用できません
参照の再生時間: ビデオ 1 本なら最大 5 秒、2 本ならそれぞれ最大 2.5 秒、3 本ならそれに応じて短くなります。
課金: 実際に使用した参照の再生時間に基づきます。
</ParamField>

<ParamField body="input.template" type="string">
  ビデオエフェクトのテンプレート名。任意です。現在サポートされているのは squish、flying、carousel です。使用すると、prompt パラメータは無視されます。
</ParamField>

<ParamField body="model" type="string">
  呼び出すモデルの ID。このコンポーネントでは制約されません。Comfy Router が `POST /v2/models/wan/{model}` の `{model}` パスセグメントから設定するため、Router の呼び出し元は省略します。`POST /proxy/wan/api/v1/services/aigc/video-generation/video-synthesis` への v1 の直接呼び出しでは必ず指定する必要があり、受け付けられる表記の列挙はそのオペレーション自身のコンポーネント `WanVideoGenerationRequest` にあります。
</ParamField>

<ParamField body="parameters" type="object">
  ビデオ処理パラメータ
</ParamField>

<ParamField body="parameters.audio" type="boolean" default="true">
  ビデオにオーディオを追加するかどうか。wan3.0-video と wan3.0-video-prime のみでサポートされます。他の wan モデルについては、プロバイダーはそのような切り替えをドキュメント化していません。
</ParamField>

<ParamField body="parameters.audio_setting" type="string" default="&quot;auto&quot;">
  wan2.7-videoedit モデルのビデオオーディオ設定。
- auto（デフォルト）: モデルがプロンプトの内容に基づいてインテリジェントに判断します
- origin: 入力ビデオのオリジナルオーディオを強制的に保持します

  指定可能な値: `auto`, `origin`
</ParamField>

<ParamField body="parameters.duration" type="integer" default="5">
  生成されるビデオの長さ（秒）:
- wan2.5 モデル: 5 秒または 10 秒
- wan2.6-t2v、wan2.6-i2v: 5 秒、10 秒、または 15 秒
- wan2.6-r2v: 5 秒または 10 秒のみ（15 秒はサポートされません）
- wan2.7-i2v、wan2.7-t2v: [2, 15] の整数
- wan2.7-r2v、wan2.7-videoedit: [2, 10] の整数
- wan3.0-video: ビデオ入力なしの場合は [2, 30] の整数。ビデオ入力ありの場合、入力ビデオの合計再生時間 + 出力ビデオの再生時間が 30 秒を超えてはなりません。-1 を指定するとスマート再生時間モードが有効になり、モデルが適切な再生時間を選択します

  範囲: `-1` 〜 `30`
</ParamField>

<ParamField body="parameters.prompt_extend" type="boolean" default="true">
  プロンプトのインテリジェントな書き換えを有効にするかどうか。デフォルトは true です
</ParamField>

<ParamField body="parameters.ratio" type="string">
  生成されるビデオのアスペクト比。wan2.7 と wan3.0 のモデル専用です。
wan2.7 モデルでは、指定しない場合は解像度の階層に基づいてデフォルトが決まります。
wan3.0-video では、adaptive（デフォルト）が入力メディアの比率と意図に基づいて適切な
アスペクト比を自動的に推奨します。

  指定可能な値: `adaptive`, `16:9`, `9:16`, `1:1`, `4:3`, `3:4`
</ParamField>

<ParamField body="parameters.resolution" type="string">
  解像度レベル。サポートされる値はモデルによって異なります:
- wan2.5-i2v-preview: 480P、720P、1080P
- wan2.6-i2v: 720P、1080P のみ（480P はサポートされません）
- wan2.7 モデル（i2v、t2v、r2v、videoedit）: 720P、1080P（デフォルト 1080P）
- wan3.0-video、wan3.0-video-prime: 480P、720P、1080P（上流のデフォルト 1080P）
このプロキシは、解像度もサイズも指定されていないビデオ生成リクエストを拒否します。解像度のティアによって課金レートが決まるためです。

  指定可能な値: `480P`、`720P`、`1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  乱数シード。モデルが生成するコンテンツのランダム性を制御するために使用します

  範囲: `0` から `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  インテリジェントなマルチレンズ制御。prompt_extend が有効な場合にのみ機能します。
wan2.6 および wan2.7-r2v モデルが対象です。
- single: 単一ショットビデオ（デフォルト）
- multi: マルチショットビデオ

  指定可能な値: `multi`、`single`
</ParamField>

<ParamField body="parameters.size" type="string">
  幅*高さ 形式のビデオ解像度。対応する解像度はモデルによって異なります:
wan2.5 T2V の場合: 480P (480*832, 832*480, 624*624)、720P、1080P サイズ
wan2.6 T2V/R2V の場合 (480P なし):
  720P: 1280*720, 720*1280, 960*960, 1088*832, 832*1088
  1080P: 1920*1080, 1080*1920, 1440*1440, 1632*1248, 1248*1632
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  ウォーターマークロゴを追加するかどうか。ウォーターマークは右下隅に配置されます
</ParamField>
