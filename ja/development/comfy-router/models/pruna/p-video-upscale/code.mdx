同じボディを `POST https://api.comfy.org/v2/models/pruna/p-video-upscale/requests` に送信します。Router は実行が受け付けられるとすぐに `201` と `request_id` を返し、結果は準備ができ次第、このプロセスからでも別のプロセスからでも回収できます。[キュー配信](/ja/development/comfy-router/queue)では、ステータス、キャンセル、回収の流れを説明します。

<CodeGroup>
```python Python
import asyncio
from comfy_sdk import AsyncComfy

# 環境変数から COMFY_API_KEY を読み取ります。
# submit() の呼び出しごとに独自の Idempotency-Key を発行し、自動リトライ時に再利用します。
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "pruna/p-video-upscale",
            {
                "input": {
                    "target": "1080p",
                    "video": "https://example.com/source.mp4",
                },
            },
        )
        print("request_id:", handle.request_id)  # モデル ID と合わせて、別のプロセスが必要とするすべての情報

        # リクエストが完了するまでポーリングし、サーバーが指定する Retry-After の秒数だけ待機します。
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # プロバイダー自身のペイロードで、models.run() が返すのと同じ値です。
        # 失敗またはキャンセル済みのリクエストは、ここで型付きの Router エラーを送出します。
        result = await handle.get()

    print(result)

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// 環境変数から COMFY_API_KEY を読み取ります。
// submit() の呼び出しごとに独自の Idempotency-Key を発行し、自動リトライ時に再利用します。
const handle = await comfy.models.submit("pruna/p-video-upscale", {
  input: {
    target: "1080p",
    video: "https://example.com/source.mp4",
  },
});
console.log("requestId:", handle.requestId); // モデル ID と合わせて、別のプロセスが必要とするすべての情報

// リクエストが完了するまでポーリングし、サーバーが指定する Retry-After の秒数だけ待機します。
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// models.run() が返すのと同じ結果です。失敗またはキャンセル済みのリクエストは、ここで reject されます。
const result = await handle.get();

console.log(result.data);
```

## スキーマ

### 入力

<ParamField body="input" type="object" required>
  P-Video-Upscale のパラメータ。ジョブは返却されたビデオの秒数に応じて課金され、返却されたファイルから計測して 1 秒単位で切り上げられます。料金レートは `target` と、出力フレームレートが 30 fps を超えるかどうかで決まります。`fps` を省略した場合、出力は `video` のフレームレートを維持するため、そのレートで料金ティアが決まります。`turbo` ジョブはフレームレートに関係なく、その `target` の turbo レートで課金されます。安全フィルタは常に有効で、リクエスト内の `enable_safety_filter` の値は無視されます。
</ParamField>

<ParamField body="input.fps" type="integer">
  出力フレームレート (16-60)。ソースのレートより高いレートは補間されます。省略した場合、出力はソースのレートを維持します。

  範囲: `16` から `60`
</ParamField>

<ParamField body="input.target" type="string" default="&quot;1080p&quot;">
  出力解像度プリセット: 720p、1080p、2k、4k。プリセットはピクセル面積を設定します。16:9 でないビデオはアスペクト比を維持します。すでにターゲットより大きいビデオは縮小されません。

  指定可能な値: `720p`, `1080p`, `2k`, `4k`
</ParamField>

<ParamField body="input.turbo" type="boolean" default="false">
  品質がやや低い代わりに高速なジョブ。フレームレートに関係なく、turbo レート (スタンダードレートの約 3 分の 1) で課金されます。
</ParamField>

<ParamField body="input.video" type="string" required>
  入力ビデオの URI。最大 512 MiB。`fps` を省略した場合は公開読み取り可能な http(s) URL である必要があります。ジョブを送信する前にそのフレームレートが読み取られるためです。
</ParamField>

Router が `GET /v2/models/pruna/p-video-upscale/openapi.json` で提供するスキーマから生成されており、リクエストがプロバイダーに到達する前に呼び出しを検証する際にも同じドキュメントが使われます。

<ResponseField name="moderation.categories" type="string[]">

<ResponseField name="moderation.reason" type="string">

<ResponseField name="status" type="string">
