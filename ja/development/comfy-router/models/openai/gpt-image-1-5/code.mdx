モデルの公開されている例は GENERATION 呼び出しで、このフィールドを省略している。`image` を追加することが 2 つのモードの違いのすべてである。エンドポイントもモデル ID も同じだが、編集のプロンプトはシーンではなく、望む「変更」を記述する点が異なる。そのため、構造上新しいのはこのフィールドだけであるにもかかわらず、以下の編集ボディは生成の例とは異なって見える。
これは記載されたまま正確にコピーできる: `{"prompt": "give the rocketship rainbow coloring", "image": ["data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="], "size": "1024x1024"}`。ペイロードは省略形ではなく完全な 1x1 PNG であり、このボディは Router 自身のリクエスト検証テストで受理されるケースとしてピン留めされている。自分の画像のバイト列に差し替えること。
画像 1 枚またはその配列を受け付ける。gpt-image-1 以降は最大 16 枚を受け取り、Router はディスパッチ前にこのスキーマからそれを強制する。
</ParamField>

<ParamField body="mask" type="string">
  1 枚の画像。呼び出し元に代わって Router が取得する https URL、またはバイト列をインラインで含む `data:image/<format>;base64,<payload>` URI のいずれか。受け付ける画像形式は png、webp、jpeg で、そのセットはプロバイダーに任されるのではなく解決時に強制される。svg、gif、avif、tiff は、送信した画像を名指ししてここで拒否される。原因から 2 ホップ離れたパートナーのエラーになることはない。
URL 形式を推奨する。base64 ペイロードは約 4/3 に膨張し、リクエストボディ全体は 100 MiB が上限なので、インライン形式は約 75 MB のソース画像で上限に達する。URL ならこれを完全に回避できる。この説明の最後に記載する画像ごとおよびリクエストごとのメディア上限はボディ上限よりも厳しいため、実際のサイズの画像ではまずそちらに達する。
URL は自分の認証情報なしで解決できなければならない。Router はサーバー側で取得し、リクエストに呼び出し元の認証情報を付けない。そのため、署名がクエリ文字列に含まれる presigned URL がサポートされる形式である。`/api/assets/{id}/content` のような認証済みエンドポイントは、画像ではなく 401 を Router に返す。その URL を自分でリクエストし、リダイレクト先の署名付き URL を渡すこと。
取得はオープンなインターネットではなく、名前を挙げたホストの集合に限定される。同じリストは、送信した URL だけでなくすべてのリダイレクトホップにも再適用される。したがって、他のホストの URL、またはリスト外へリダイレクトする URL は、プロバイダーに接続する前に拒否される。現在そのリストは Comfy 自身のアセット配信のみである。Comfy のアセットバケット配下の署名付き `storage.googleapis.com` URL で、これは `/api/assets/{id}/content` がリダイレクトする形式である。パートナーの CDN や通常の https ホストはリストに含まれない。
2 つの拡張が展開中で、どちらも現在はデフォルトで無効である。これらは 1 つの切り替えの背後で提供され、一緒に有効化される。したがって以下はすべて、まだこれに依存して構築するものではなく、今後提供されるものとして扱うこと。どちらかに依存する前に確認すること。
1 つ目は、`POST /customers/storage` がアップロード先として署名するバケットである。展開があなたの環境に到達するまで、そのエンドポイントからのアップロード URL はここで拒否される。バケットは Comfy 自身のものでホストも同じであってもである。したがって「Comfy にアップロードしてから URL を渡す」はまだ動作せず、動作する形式は `/api/assets/{id}/content` がリダイレクトする署名付き URL である。
2 つ目は全員に一度にではなく、アカウントごとに有効化される。これらのホストの背後にあるバケットは我々のものではなくあなたのものであるためである。上記の切り替えがオンになっても、サードパーティの受信メディアが有効化されていないアカウントは拒否され、ホストがサポートされていないとではなく、その旨の文言で伝えられる。あなたのアカウントで有効化するよう Comfy の担当者に依頼すること。さらにこれは以下のサードパーティのオブジェクトストレージホストを許可する。バケットはあなたのものであり、Router はその所有権を主張しない。Cloudflare R2 (`<account>.r2.cloudflarestorage.com`、`<id>.r2.dev`)、Amazon S3 (`s3.amazonaws.com` および `s3.<region>.amazonaws.com`、パス形式または `<bucket>.` を先頭に付ける形式のいずれか)、Azure Blob Storage (`<account>.blob.core.windows.net`)、Alibaba Cloud OSS (`<bucket>.oss-<region>.aliyuncs.com`、`oss-accelerate` エンドポイントを含む)。これらは特にオブジェクトストレージのエンドポイントである。同じプロバイダードメイン上の汎用エンドポイント、たとえば Alibaba Function Compute のトリガーはリストに含まれず拒否される。
以下の例は形状のみを示す。実際の値は署名クエリパラメータも含むが、公開された例は仕様に永遠に残るため、また実際の署名は漏洩した認証情報でありかつ機能しなくなるリンクでもあるため、ここでは意図的に省略している。
