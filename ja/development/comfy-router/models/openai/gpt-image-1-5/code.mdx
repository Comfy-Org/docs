<ParamField body="mask" type="string">
  1 つの画像。呼び出し元に代わって Router が取得する https URL、またはバイト列をインラインで含む `data:image/<format>;base64,<payload>` URI のいずれかの形式です。受け付けられる画像形式は png、webp、jpeg で、このセットはプロバイダーに任されるのではなく解決時に強制されます。svg、gif、avif、tiff はここで拒否され、送信した画像が名指しされます。原因から 2 ホップ離れたパートナーエラーにはなりません。
URL 形式を推奨します。base64 ペイロードは約 4/3 に膨らみ、リクエストボディ全体は 20 MiB に制限されるため、インライン形式ではソース画像が 15 MB 付近で上限に達します。URL ならこれを完全に回避できます。
URL は認証情報なしで解決できなければなりません。Router はサーバー側でそれを取得し、リクエストに呼び出し元の認証情報を付けません。そのため、署名がクエリ文字列に含まれる形式の署名付き URL がサポートされる形式です。`/api/assets/{id}/content` のような認証済みエンドポイントは、画像ではなく 401 を Router に返します。その URL はご自身でリクエストし、リダイレクト先の署名付き URL を渡してください。
取得はオープンなインターネットではなく、名前を挙げたホストのセットに限定され、同じリストが送信した URL だけでなくすべてのリダイレクト先にも再適用されます。そのため、他のホスト上の URL、あるいはリスト外へリダイレクトする URL は、プロバイダーに接触する前に拒否されます。現時点でこのリストは Comfy 自身のアセット配信のみです。Comfy のアセットバケット配下の署名付き `storage.googleapis.com` URL で、`/api/assets/{id}/content` がリダイレクトする形式です。パートナー CDN や通常の https ホストはリストに含まれません。
2 つの拡張が展開中で、どちらも現時点ではデフォルトで無効です。それらは 1 つの切り替えの背後で提供され、同時に有効になります。以下はまだ構築の前提とせず、今後のものとして扱ってください。どちらかに依存する前に確認してください。
1 つ目は、`POST /customers/storage` がアップロード先として署名するバケットです。展開がお使いの環境に届くまで、そのエンドポイントからのアップロード URL はここで拒否されます。バケットは Comfy 自身のものでホストも同じであるにもかかわらずです。したがって「Comfy にアップロードしてから URL を渡す」はまだ機能せず、機能するのは `/api/assets/{id}/content` がリダイレクトする署名付き URL の形式です。
2 つ目は、以下のサードパーティのオブジェクトストレージホストを追加で許可します。バケットはお客様のものであり、Router はその所有権を主張しません: Cloudflare R2 (`<account>.r2.cloudflarestorage.com`、`<id>.r2.dev`)、Amazon S3 (`s3.amazonaws.com` および `s3.<region>.amazonaws.com`、パス形式または `<bucket>.` プレフィックス形式のいずれか)、Azure Blob Storage (`<account>.blob.core.windows.net`)、Alibaba Cloud OSS (`<bucket>.oss-<region>.aliyuncs.com`、`oss-accelerate` エンドポイントを含む)。これらは具体的にはオブジェクトストレージのエンドポイントです。Alibaba Function Compute のトリガーなど、同じプロバイダードメイン上の汎用エンドポイントはリストに含まれず、拒否されます。
以下の例は形状のみを示しています。実際の値には署名のクエリパラメータも含まれますが、公開された例は仕様に永遠に残り、実際の署名は漏えいした認証情報であると同時に機能しなくなるリンクでもあるため、ここでは意図的に省略しています。
各画像は 25 MiB、1 つのリクエストの画像は合計 64 MiB に制限されます。
