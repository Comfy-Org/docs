モデルが公開している例は生成呼び出しであり、このフィールドを省略しています。`image` を追加することが2つのモードの違いのすべてです（同じエンドポイント、同じモデル ID）。ただし編集プロンプトはシーンではなく希望する変更を記述するため、構造的に新しいのはこのフィールドだけであるにもかかわらず、以下の編集ボディは生成の例とは異なって見えます。
これは表示されているとおりにそのままコピーできます: `{"prompt": "give the rocketship rainbow coloring", "image": ["data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="], "size": "1024x1024"}`。ペイロードは省略形ではなく完全な 1x1 PNG であり、このボディは Router 自身のリクエスト検証テストで受理されるケースとしてピン留めされています。ご自身の画像のバイト列に差し替えてください。
1つの画像またはその配列を受け付けます。gpt-image-1 以降は最大16枚を受け取り、Router はディスパッチ前にこのスキーマに基づいてそれを強制します。
</ParamField>

<ParamField body="mask" type="string">
  1つの画像を、Router が呼び出し元に代わって取得する https URL、またはバイト列をインラインで含む `data:image/<format>;base64,<payload>` URI のいずれかの形式で指定します。受け付ける画像形式は png、webp、jpeg で、このセットはプロバイダーに委ねられるのではなく解決時に強制されます。svg、gif、avif、tiff はここで拒否され、送信した画像が名指しされます。原因から2ホップ離れたパートナーのエラーになることはありません。
URL 形式を推奨します。base64 ペイロードは約 4/3 に膨張し、リクエストボディ全体は 100 MiB に制限されるため、インライン形式ではソース画像が約 75 MB で上限に達します。URL ならこれを完全に回避できます。この説明の最後に記載されている画像ごとおよびリクエストごとのメディア上限は、ボディの上限よりも厳しいため、実際のサイズの画像ではまずこちらに達します。
URL はあなたの認証情報なしで解決できなければなりません。Router はサーバー側でそれを取得し、リクエストに呼び出し元の認証情報を一切付けません。そのため、署名がクエリ文字列に含まれる形式の署名付き URL がサポートされる形式です。`/api/assets/{id}/content` のような認証済みエンドポイントは、画像ではなく 401 を Router に返します。その URL を自分でリクエストし、リダイレクト先の署名付き URL を渡してください。
取得は開かれたインターネットではなく、名前を挙げたホストの集合に限定され、同じリストが送信する URL だけでなくすべてのリダイレクト先にも再適用されます。そのため、他のホストの URL や、リスト外へリダイレクトする URL は、プロバイダーに接続する前に拒否されます。現在、そのリストは Comfy 自身のアセット配信のみです。すなわち Comfy のアセットバケット配下の署名付き `storage.googleapis.com` URL であり、これは `/api/assets/{id}/content` がリダイレクトする形式です。パートナーの CDN や通常の https ホストはリストに含まれません。
2つの緩和がロールアウト中で、どちらも本日時点ではデフォルトで無効です。これらは1つの切り替えの背後で提供され、まとめて有効化されます。したがって、以下はすべて今後に予定されているものとして扱い、まだ依存して構築する対象とはしないでください。どちらかに依存する前に確認してください。
1つ目は `POST /customers/storage` がアップロード先として署名するバケットです。ロールアウトがあなたの環境に到達するまで、そのエンドポイントからのアップロード URL はここで拒否されます。たとえバケットが Comfy 自身のものでホストが同じであってもです。そのため「Comfy にアップロードしてから URL を渡す」はまだ機能せず、機能する形式は `/api/assets/{id}/content` がリダイレクトする署名付き URL です。
2つ目は全員に対して一度にではなくアカウントごとに有効化されます。これらのホストの背後にあるバケットが私たちのものではなくあなたのものだからです。上記の切り替えがオンになっても、サードパーティの受信メディアが有効化されていないアカウントは拒否され、ホストがサポートされていないと告げられるのではなく、その旨の文言で告げられます。あなたのアカウントで有効化するよう Comfy の担当者に依頼してください。これはさらに以下のサードパーティのオブジェクトストレージホストを許可します。そこではバケットはあなたのものであり、Router はそれに対する所有権を主張しません: Cloudflare R2 (`<account>.r2.cloudflarestorage.com`、`<id>.r2.dev`)、Amazon S3 (`s3.amazonaws.com` および `s3.<region>.amazonaws.com`、パス形式または `<bucket>.` 接頭辞形式のいずれか)、Azure Blob Storage (`<account>.blob.core.windows.net`)、Alibaba Cloud OSS (`<bucket>.oss-<region>.aliyuncs.com`、`oss-accelerate` エンドポイントを含む)。これらは特にオブジェクトストレージのエンドポイントです。同じプロバイダードメイン上の汎用エンドポイント、たとえば Alibaba Function Compute のトリガーは、リストに含まれず拒否されます。
以下の例は形状のみを示しています。実際の値は署名クエリパラメータも含みますが、公開された例は仕様に永遠に残り、実際の署名は漏洩した認証情報であると同時に機能しなくなるリンクでもあるため、ここでは意図的に省略しています。
各画像は 25 MiB、1つのリクエストの画像は合計 64 MiB に制限されます。
