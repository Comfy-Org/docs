<ParamField body="image" type="string | string[]">
  編集するソース画像。このフィールドの有無が編集操作を選択します。テキストから画像への生成では完全に省略してください。
モデルが公開している例はこのフィールドを省略した GENERATION 呼び出しです。`image` を追加することが 2 つのモードの違いのすべてです（同じエンドポイント、同じモデル id）。ただし編集プロンプトはシーンではなく希望する変更を記述するため、構造的に新しいのはこのフィールドだけであるにもかかわらず、以下の編集用ボディは生成の例とは異なって見えます。
そのままコピーできます: `{"prompt": "give the rocketship rainbow coloring", "image": ["data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="], "size": "1024x1024"}`。ペイロードは省略形ではなく完全な 1x1 PNG であり、このボディは Router 自身のリクエスト検証テストで受け入れられるケースとしてピン留めされています。ご自身の画像のバイト列に差し替えてください。
1 つの画像またはその配列を受け付けます。gpt-image-1 以降は最大 16 個まで受け付け、Router はディスパッチ前にこのスキーマに基づいてそれを強制します。
</ParamField>

<ParamField body="mask" type="string">
  1 つの画像を、Router が呼び出し元に代わって取得する https URL、またはバイト列をインラインで含む `data:image/<format>;base64,<payload>` URI のいずれかで指定します。受け付けられる画像形式は png、webp、jpeg で、この集合はプロバイダーに任されるのではなく解決時に強制されます。svg、gif、avif、tiff はここで拒否され、送信した画像が示されます。原因から 2 ホップ離れたパートナーエラーになることはありません。
URL 形式を推奨します。base64 ペイロードは約 4/3 に膨らみ、リクエストボディ全体は 100 MiB に制限されるため、インライン形式ではソース画像が約 75 MB で上限に達します。URL ならこれを完全に回避できます。この説明の最後に示す画像ごとおよびリクエストごとのメディア上限はボディの上限よりも厳しいため、実用的なサイズの画像ではまずそちらに達します。
URL は認証情報なしで解決できる必要があります。Router はサーバー側で取得し、リクエストに呼び出し元の認証情報を付けません。そのため署名がクエリ文字列にある事前署名済み URL がサポートされる形式です。`/api/assets/{id}/content` のような認証が必要なエンドポイントは、画像ではなく 401 を Router に返します。その URL はご自身でリクエストし、リダイレクト先の署名付き URL を渡してください。
取得は開かれたインターネットではなく、名前を挙げたホスト群に限定されます。同じリストは送信した URL だけでなく、すべてのリダイレクト先にも再適用されます。したがって、それ以外のホストの URL や、リスト外へリダイレクトする URL は、プロバイダーに接続する前に拒否されます。現在このリストは Comfy 自身のアセット配信のみです。Comfy のアセットバケット配下の署名付き `storage.googleapis.com` URL で、`/api/assets/{id}/content` がリダイレクトする形式です。パートナー CDN や通常の https ホストはリストに含まれません。
2 つの拡張が展開中で、どちらも現在はデフォルトで無効です。これらは 1 つの切り替えの背後で提供され、一緒に有効化されます。したがって以下はすべて今後に予定されているものとして扱い、まだそれに依存した実装はしないでください。どちらかに依存する前に確認してください。
1 つ目は `POST /customers/storage` がアップロード先として署名するバケットです。展開がお使いの環境に到達するまで、このエンドポイントから得たアップロード URL はここで拒否されます。バケットは Comfy 自身のものでホストも同じであるにもかかわらずです。そのため「Comfy にアップロードしてから URL を渡す」方法はまだ機能せず、機能するのは `/api/assets/{id}/content` がリダイレクトする署名付き URL です。
2 つ目は全員に一度にではなくアカウント単位で有効化されます。これらのホストの背後にあるバケットは当社のものではなくお客様のものであるためです。上の切り替えがオンになっていても、サードパーティの受信メディアが有効になっていないアカウントは拒否され、ホストがサポート対象外であるとは告げられず、その文言で通知されます。お使いのアカウントで有効化するよう Comfy の担当者に依頼してください。これにより、バケットがお客様のもので Router が所有権を主張しない以下のサードパーティ オブジェクトストレージ ホストも追加で許可されます: Cloudflare R2（`<account>.r2.cloudflarestorage.com`、`pub-<hash>.r2.dev`）、Amazon S3（`s3.amazonaws.com` および `s3.<region>.amazonaws.com`、パス形式または `<bucket>.` を先頭に付ける形式のいずれか）、Azure Blob Storage（`<account>.blob.core.windows.net`）、Alibaba Cloud OSS（`<bucket>.oss-<region>.aliyuncs.com`、`oss-accelerate` エンドポイントを含む）。これらは具体的にはオブジェクトストレージのエンドポイントです。同じプロバイダーのドメイン上の汎用エンドポイント、たとえば Alibaba Function Compute のトリガーはリストに含まれず拒否されます。
照合されるのはプロバイダーではなくホスト名の形式です。したがって上でプロバイダーを挙げたからといって、そのプロバイダーが発行しうるすべての URL が受け入れられるわけではありません。呼び出し元がそれぞれに到達するのは自然なことなので、紛らわしい 3 つのケースを明示しておきます。R2 のカスタムドメイン（`cdn.example.com`）は受け入れられません。Cloudflare は `pub-<hash>.r2.dev` をレート制限のあるデバッグ用ホスト名として文書化し、本番トラフィックはカスタムドメインに向けるよう案内していますが、カスタムドメインのホスト名には R2 であることを示す情報がないため、Router は他のホストと区別できず拒否します。`<account>.r2.cloudflarestorage.com` エンドポイントに署名するか、`pub-<hash>.r2.dev` 形式を使用してください。S3 の IPv6 dualstack エンドポイント（`s3.dualstack.<region>.amazonaws.com`）も受け入れられません。通常のリージョナルエンドポイントを使用してください。Azure Blob の代替 DNS ゾーン（`<account>.z<N>.blob.storage.azure.net`）も同様です。`<account>.blob.core.windows.net` を使用してください。返される拒否メッセージにはこれと同じ形式が記載されているため、それらを読むためにここに来る必要はありません。
上記の `<account>` と `pub-<hash>` は、通常その形で受け取るプレースホルダーを示したものであり、階層の深さを制限するものではありません。マッチングはオブジェクトストレージのドメインサフィックスに対して行われるため、同じ名前空間の下にあるより深い名前（`a.b.pub-<hash>.r2.dev`）も受け入れられます。ただし、それによって広がるのは名前空間自体ではありません。サフィックスは依然として列挙されたもののいずれかでなければなりません。
以下の例は形状のみを示しています。実際の値には署名用のクエリパラメータも含まれますが、ここでは意図的に省略しています。公開された例は仕様の中に永久に残るため、また実際の署名は漏洩した認証情報であると同時に、いずれ機能しなくなるリンクでもあるためです。
各画像は 25 MiB、1 回のリクエストの画像は合計 64 MiB に制限されます。
