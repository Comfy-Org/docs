### 入力

<ParamField body="background" type="string">
  背景の透明度

  指定可能な値: `transparent`、`opaque`

<ParamField body="image" type="string | string[]">
  編集対象のソース画像。このフィールドが存在することが編集操作を選択します。テキストから画像への生成では完全に省略してください。
モデルの公開例は、このフィールドを省略した GENERATION 呼び出しです。`image` を追加することが 2 つのモードの違いのすべてです（同じエンドポイント、同じモデル id）。ただし、編集プロンプトはシーンではなく望む変更を記述するため、構造上新しいのがこのフィールドだけであっても、後述の編集ボディは生成の例とは異なって見えます。
これは記載どおりにそのままコピーできます: `{"prompt": "give the rocketship rainbow coloring", "image": ["data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="], "size": "1024x1024"}` -- ペイロードは省略形ではなく完全な 1x1 PNG であり、このボディは Router 自身のリクエスト検証テストで受け入れ済みケースとしてピン留めされています。ご自身の画像のバイト列に差し替えてください。
1 つの画像またはその配列を受け付けます。gpt-image-1 以降は最大 16 個で、Router はディスパッチ前にこのスキーマに基づいてそれを強制します。
</ParamField>

<ParamField body="mask" type="string">
  1 つの画像。呼び出し元に代わって Router が取得する https URL、またはバイト列をインラインで含む `data:image/<format>;base64,<payload>` URI のいずれかの形式です。受け付けられる画像タイプは png、webp、jpeg で、このセットはプロバイダーに任されるのではなく解決時に強制されます。svg、gif、avif、tiff はここで拒否され、原因から 2 ホップ離れたパートナーエラーになるのではなく、送信した画像が名指しされます。
URL 形式を推奨します。base64 ペイロードは約 4/3 に膨らみ、リクエストボディ全体は 20 MiB に制限されるため、インライン形式ではソース画像が約 15 MB で上限に達します。URL はそれを完全に回避します。
URL はあなたの資格情報なしで解決できなければなりません。Router はそれをサーバー側で取得し、リクエストに呼び出し元の資格情報を一切付けません。そのため、署名がクエリ文字列にある presigned URL がサポートされる形式です。`/api/assets/{id}/content` のような認証済みエンドポイントは、画像ではなく Router に 401 を返します。その URL を自分でリクエストし、リダイレクト先の署名付き URL を渡してください。
取得はオープンなインターネットではなく、名前付きのホスト集合に限定されます。同じリストは、送信する URL だけでなくすべてのリダイレクトホップにも再適用されます。そのため、他のホスト上の URL や、リスト外へリダイレクトする URL は、プロバイダーに接触する前に拒否されます。現在、そのリストは Comfy 自身のアセット配信のみです。Comfy のアセットバケット配下の署名付き `storage.googleapis.com` URL で、これが `/api/assets/{id}/content` のリダイレクト先となる形式です。パートナー CDN や通常の https ホストはリストに含まれません。
2 つの拡張が展開中で、どちらも本日時点ではデフォルトで無効です。それらは 1 つの切り替えの背後で提供され、一緒に有効になります。そのため、以下はすべてまだこれに対して構築するものではなく、今後のものとして扱ってください。どちらかに依存する前に確認してください。
1 つ目は、`POST /customers/storage` がアップロード先として署名するバケットです。ロールアウトがあなたの環境に到達するまで、そのエンドポイントからのアップロード URL は、バケットが Comfy 自身のものでホストも同じであっても、ここで拒否されます。したがって「Comfy にアップロードしてから URL を渡す」はまだ機能せず、機能する形式は `/api/assets/{id}/content` のリダイレクト先である署名付き URL です。
2 つ目は、これらのサードパーティのオブジェクトストレージホストを追加で許可します。ここではバケットはあなたのものであり、Router はそれに対して所有権を主張しません: Cloudflare R2（`<account>.r2.cloudflarestorage.com`、`<id>.r2.dev`）、Amazon S3（`s3.amazonaws.com` および `s3.<region>.amazonaws.com`、path-style 形式または `<bucket>.` を先頭に付ける形式のいずれか）、Azure Blob Storage（`<account>.blob.core.windows.net`）、Alibaba Cloud OSS（`<bucket>.oss-<region>.aliyuncs.com`、`oss-accelerate` エンドポイントを含む）。これらは特にオブジェクトストレージのエンドポイントです。同じプロバイダードメイン上の汎用エンドポイント、たとえば Alibaba Function Compute のトリガーは、リストに含まれず拒否されます。
以下の例は形状のみを示しています。実際の値は署名クエリパラメータも含みます。これはここでは意図的に省略されています。公開された例は仕様の中に永遠に残り、実際の署名は漏洩した資格情報であると同時に機能しなくなるリンクでもあるためです。
各画像は 25 MiB、1 つのリクエストの画像は合計 64 MiB に制限されます。
