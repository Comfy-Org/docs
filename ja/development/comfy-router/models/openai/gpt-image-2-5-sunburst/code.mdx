### 入力

<ParamField body="background" type="string">
  背景の透明度

  指定可能な値: `transparent`、`opaque`
</ParamField>

<ParamField body="image" type="string | string[]">
  編集対象のソース画像。このフィールドが存在することが編集操作を選択します。テキストから画像への生成では完全に省略してください。
1 枚の画像、またはその配列を受け付けます。gpt-image-1 以降は最大 16 枚を扱い、Router はディスパッチ前にこのスキーマに基づいてそれを強制します。
</ParamField>

<ParamField body="mask" type="string">
  1 枚の画像を、呼び出し元に代わって Router が取得する https URL、またはバイト列をインラインで運ぶ `data:image/<format>;base64,<payload>` URI のいずれかで指定します。受け付ける画像タイプは png、webp、jpeg で、このセットはプロバイダー任せにせず解決時に強制されます。svg、gif、avif、tiff はここで拒否され、送信した画像を名指しします。原因から 2 ホップ離れたパートナーエラーにはなりません。
URL 形式を推奨します。base64 ペイロードはおよそ 4/3 に膨らみ、リクエストボディ全体は 10 MiB に制限されるため、インライン形式ではソース画像が約 7.5 MB で上限に達します。URL ならこれを完全に回避できます。
URL は認証情報なしで解決できなければなりません。Router はサーバー側で取得し、リクエストに呼び出し元の認証情報を付けません。そのため、署名がクエリ文字列にある Comfy 署名済みアセット URL がサポートされる形式です。`/api/assets/{id}/content` のような認証済みエンドポイントは、画像ではなく Router に 401 を返します。その URL は自分でリクエストし、リダイレクト先の署名済み URL を渡してください。取得はオープンなインターネットではなく Comfy 自身のアセットバケットに限定され、送信した URL だけでなくすべてのリダイレクトホップでも同様です。そのため、サードパーティの URL やリダイレクトする URL は拒否されます。
以下の例は形状のみを示しています。実際の値は署名用クエリパラメータも含みますが、公開された例は仕様に永遠に残り、実際の署名は漏洩した認証情報であり、かつ機能しなくなるリンクでもあるため、ここでは意図的に省略しています。
各画像は 25 MiB、1 リクエストの画像は合計 64 MiB に制限されます。
