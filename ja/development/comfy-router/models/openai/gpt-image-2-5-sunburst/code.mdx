<ParamField body="image" type="string | string[]">
  編集するソース画像。このフィールドの有無が編集操作を選択します。テキストから画像への生成では完全に省略してください。
モデルが公開している例は、このフィールドを省略した生成呼び出しです。`image` を追加することが 2 つのモードの違いのすべてであり、エンドポイントもモデル ID も同じです。ただし、編集用のプロンプトはシーンではなく、実現したい変更を記述するため、構造的に新しいのがこのフィールドだけであっても、以下の編集用ボディは生成の例とは異なる読み方になります。
これは印刷されたままの形でコピーできます: `{"prompt": "give the rocketship rainbow coloring", "image": ["data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="], "size": "1024x1024"}`。このペイロードは省略形ではなく完全な 1x1 PNG であり、このボディは Router 自身のリクエスト検証テストで受け入れられるケースとしてピン留めされています。お使いの画像のバイト列に置き換えてください。
1 枚の画像、またはその配列を受け付けます。gpt-image-1 以降は最大 16 枚で、Router はディスパッチ前にこのスキーマからそれを強制します。
</ParamField>

<ParamField body="mask" type="string">
  1 枚の画像を、Router が呼び出し元に代わって取得する https URL、またはバイト列をインラインで含む `data:image/<format>;base64,<payload>` URI のいずれかで指定します。受け付ける画像形式は png、webp、jpeg で、このセットはプロバイダーに任されるのではなく解決時に強制されます。svg、gif、avif、tiff はここで拒否され、送信した画像を名指しします。原因から 2 ホップ離れたパートナーエラーになることはありません。
URL 形式を推奨します。base64 ペイロードはおよそ 4/3 に膨張し、リクエストボディ全体は 100 MiB が上限であるため、インライン形式ではソース画像が約 75 MB で上限に達します。URL ならこれを完全に回避できます。この説明の末尾に記載されている画像ごとおよびリクエストごとのメディア上限はボディの上限よりも厳しいため、実際のサイズの画像ではまずそちらに当たることになります。
URL は認証情報なしで解決できなければなりません。Router はそれをサーバー側で取得し、リクエストに呼び出し元の認証情報を付けません。したがって、署名がクエリ文字列に含まれる形式の署名付き URL がサポートされる形式です。`/api/assets/{id}/content` のような認証が必要なエンドポイントは、画像ではなく 401 を Router に返します。その URL はご自身でリクエストし、リダイレクト先の署名付き URL を渡してください。
取得はオープンなインターネットではなく、名前を挙げたホストの集合に限定されます。同じリストは、送信する URL だけでなくすべてのリダイレクトホップにも再適用されます。そのため、それ以外のホストの URL、またはリスト外へリダイレクトする URL は、プロバイダーに接続する前に拒否されます。現時点でそのリストは Comfy 自身のアセット配信のみです。Comfy のアセットバケット配下の署名付き `storage.googleapis.com` URL で、これは `/api/assets/{id}/content` がリダイレクトする形式です。パートナーの CDN や通常の https ホストはこのリストに含まれません。
2 つの拡張が展開中で、どちらも現時点ではデフォルトで無効です。それらは 1 つの切り替えの背後で提供され、まとめて有効になります。そのため、以下はすべて近日提供されるものとして扱い、まだ依存して構築する対象とは考えないでください。どちらかに依存する前に問い合わせてください。
1 つ目は、`POST /customers/storage` がアップロード先として署名するバケットです。展開がお使いの環境に届くまで、そのエンドポイントから得たアップロード URL はここで拒否されます。バケットは Comfy 自身のものでホストも同じであるにもかかわらずです。したがって「Comfy にアップロードしてから URL を渡す」はまだ機能せず、機能する形式は `/api/assets/{id}/content` がリダイレクトする署名付き URL です。
2 つ目は、全員に対して一度にではなくアカウントごとに有効化されます。これらのホストの背後にあるバケットは弊社のものではなくお客様のものであるためです。上記の切り替えがオンになっていても、サードパーティの受信メディアが有効化されていないアカウントは拒否され、ホストがサポートされていないと告げられるのではなくその旨の文言で通知されます。お使いのアカウントで有効にするよう Comfy の担当者に依頼してください。これにより、以下のサードパーティのオブジェクトストレージホストも許可されます。そこではバケットはお客様のものであり、Router はその所有権を主張しません: Cloudflare R2 (`<account>.r2.cloudflarestorage.com`、`pub-<hash>.r2.dev`)、Amazon S3 (`s3.amazonaws.com` および `s3.<region>.amazonaws.com`、パス形式または `<bucket>.` を前に付ける形式のいずれか)、Azure Blob Storage (`<account>.blob.core.windows.net`)、Alibaba Cloud OSS (`<bucket>.oss-<region>.aliyuncs.com`、`oss-accelerate` エンドポイントを含む)。これらは具体的にはオブジェクトストレージのエンドポイントです。同じプロバイダードメイン上の汎用エンドポイント、たとえば Alibaba Function Compute のトリガーは、リストに含まれず拒否されます。
照合されるのはプロバイダーではなくホスト名の形式です。そのため、上にプロバイダー名を挙げたからといって、そのプロバイダーが発行しうるすべての URL が受け入れられるわけではありません。呼び出し元がそれぞれに妥当にたどり着きうる 3 つの惜しい例は、はっきり述べておく価値があります。R2 のカスタムドメイン (`cdn.example.com`) は受け入れられません。Cloudflare は `pub-<hash>.r2.dev` をレート制限のあるデバッグ用ホスト名として文書化し、本番トラフィックは代わりにカスタムドメインに向けるよう案内しています。しかしカスタムドメインのホスト名には R2 であることを示すものが何も含まれないため、Router は他のホストと区別できず拒否します。`<account>.r2.cloudflarestorage.com` エンドポイントに署名するか、`pub-<hash>.r2.dev` 形式を使用してください。S3 の IPv6 dualstack エンドポイント (`s3.dualstack.<region>.amazonaws.com`) も受け入れられません。通常のリージョナルエンドポイントを使用してください。Azure Blob の代替 DNS ゾーン (`<account>.z<N>.blob.storage.azure.net`) も同様です。`<account>.blob.core.windows.net` を使用してください。返される拒否メッセージにはこれらの同じ形式が記載されているので、それらを読むためにここに来る必要はありません。
上記の `<account>` と `pub-<hash>` のプレースホルダーは、通常その形式で受け取ることになる形を示したものであり、階層の深さを制限するものではありません。マッチングはオブジェクトストレージのドメインサフィックスに対して行われるため、同じ名前空間の下にあるより深い名前（`a.b.pub-<hash>.r2.dev`）も受け付けられます。ただし、それによって名前空間そのものが広がるわけではありません。サフィックスは依然として一覧に記載されたいずれかでなければなりません。
以下の例は形状のみを示しています。実際の値には署名用のクエリパラメータも付きますが、ここでは意図的に省略しています。公開された例は仕様の中に永久に残り、実際の署名は漏洩した認証情報であると同時に、やがて機能しなくなるリンクでもあるためです。
各画像は 25 MiB、1 回のリクエストの画像は合計 64 MiB に制限されます。

  生成が完了した時刻の Unix タイムスタンプ（秒）。これは OpenAI が画像生成レスポンスで必須（REQUIRED）と宣言している唯一のメンバーであるため、OpenAI が生成元である場合は常に存在します。alt ベースの id のいずれかで fal、wavespeed、runware が提供するレスポンスでは、他の 4 つの解決済みパラメータのメンバーと同様に完全に省略されます。現在のエポック値は 2^31 に十分近く、フォーマットされていない `integer` は多くの SDK ジェネレータで 32 ビットフィールドを生成してしまうため、`int64` として宣言されています。

  フォーマット: `int64`
</ResponseField>

<ResponseField name="output_format" type="string">
  `data[].b64_json` 内のバイト列のエンコーディングです。`png`、`webp`、`jpeg` のいずれかになります。これは OpenAI が実際にエンコードした形式であり、リクエストで `output_format` が送信された場合はその値、送信されなかった場合は `png` になります。そのためデコーダは、リクエストから形式を再導出するのではなく、これに基づいて判断できます。
</ResponseField>

<ResponseField name="quality" type="string">
  生成が実際に実行された品質ティアです。OpenAI は `low`、`medium`、`high`、`xhigh`、`max` のいずれかを報告します。これはリクエストのエコーではなく解決済みのティアであり、リクエスト自体の `quality` のデフォルトは `auto` です。
</ResponseField>

<ResponseField name="size" type="string">
  生成が実際に実行されたピクセル寸法を `<width>x<height>` の形式で示します。これは解決済みのサイズです。リクエストの `size` はデフォルトが `auto` で、明示的に `auto` を許容するため、実際に使用された寸法が報告される唯一の場所になります。
</ResponseField>
