<ParamField body="image" type="string | string[]">
  編集するソース画像。このフィールドの有無が編集操作を選択します。テキストから画像への生成では完全に省略してください。
モデルが公開している例はこのフィールドを省略した生成呼び出しです。2つのモードの違いは `image` を追加することだけです。エンドポイントもモデル ID も同じですが、編集プロンプトはシーンではなく希望する変更を記述するため、構造的に新しいのがこのフィールドだけであっても、以下の編集用ボディは生成の例とは異なる内容になります。
記載どおりにそのままコピーできます: `{"prompt": "give the rocketship rainbow coloring", "image": ["data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="], "size": "1024x1024"}`。ペイロードは省略形ではなく完全な 1x1 PNG で、このボディは Router 自身のリクエスト検証テストで受け入れられるケースとしてピン留めされています。ご自身の画像のバイト列に置き換えてください。
1枚の画像、またはその配列を受け付けます。gpt-image-1 以降では最大16枚までで、Router はディスパッチ前にこのスキーマに基づいて強制します。
</ParamField>

<ParamField body="mask" type="string">
  1枚の画像で、Router が呼び出し元に代わって取得する https URL、またはバイト列をインラインで含む `data:image/<format>;base64,<payload>` URI のいずれかの形式です。受け入れられる画像形式は png、webp、jpeg で、このセットはプロバイダーに任されるのではなく解決時に強制されます。svg、gif、avif、tiff はここで拒否され、原因から2ホップ離れたパートナーエラーになる代わりに、送信した画像を名指しして通知されます。
URL 形式を推奨します。base64 ペイロードは約 4/3 に膨張し、リクエストボディ全体は 100 MiB に制限されるため、インライン形式ではソース画像が約 75 MB で上限に達します。URL ならこれを完全に回避できます。この説明の最後に記載する画像あたりおよびリクエストあたりのメディア上限はボディ上限よりも厳しいため、実際のサイズの画像ではまずこちらに達します。
URL は認証情報なしで解決できる必要があります。Router はサーバー側で取得し、リクエストに呼び出し元の認証情報を付けません。そのため、署名がクエリ文字列に含まれる presigned URL がサポートされる形式です。`/api/assets/{id}/content` のような認証済みエンドポイントは画像ではなく 401 を Router に返します。その URL はご自身でリクエストし、リダイレクト先の署名付き URL を渡してください。
フェッチはオープンなインターネットではなく、名前を挙げたホスト群に限定され、同じリストが送信した URL だけでなくすべてのリダイレクトホップにも再適用されます。したがって、それ以外のホストの URL や、リスト外にリダイレクトする URL は、プロバイダーに接触する前に拒否されます。現在このリストは Comfy 自身のアセット配信のみです。つまり Comfy のアセットバケット配下の署名付き `storage.googleapis.com` URL で、これは `/api/assets/{id}/content` がリダイレクトする形式です。パートナー CDN や通常の https ホストはリストに含まれません。
2つの拡張がロールアウト中で、どちらも現在はデフォルトで無効です。これらは1つの切り替えの背後で提供され、同時に有効になります。したがって以下はすべて近日提供予定のものとして扱い、まだ依存して実装する対象とはしないでください。いずれかに依存する前に確認してください。
1つ目は `POST /customers/storage` がアップロード先として署名するバケットです。ロールアウトがお使いの環境に到達するまで、そのエンドポイントからのアップロード URL はここで拒否されます。バケットが Comfy 自身のものでホストも同じであってもです。そのため「Comfy にアップロードしてから URL を渡す」はまだ機能せず、機能する形式は `/api/assets/{id}/content` がリダイレクトする署名付き URL です。
2つ目は全員一斉ではなくアカウント単位で有効化されます。これらのホストの背後にあるバケットが弊社のものではなくお客様のものであるためです。上記の切り替えがオンになっていても、サードパーティの受信メディアが有効化されていないアカウントは拒否され、ホストがサポート外であるとは告げられず、その旨の文言で通知されます。お使いのアカウントで有効化するよう Comfy の担当者にご依頼ください。また、バケットがお客様のもので Router が所有権を主張しない以下のサードパーティのオブジェクトストレージホストを追加で許可します: Cloudflare R2（`<account>.r2.cloudflarestorage.com`、`<id>.r2.dev`）、Amazon S3（`s3.amazonaws.com` および `s3.<region>.amazonaws.com`、path-style 形式または `<bucket>.` を前置する形式のいずれか）、Azure Blob Storage（`<account>.blob.core.windows.net`）、Alibaba Cloud OSS（`<bucket>.oss-<region>.aliyuncs.com`、`oss-accelerate` エンドポイントを含む）。これらは特にオブジェクトストレージのエンドポイントです。同じプロバイダードメイン上の汎用エンドポイント、たとえば Alibaba Function Compute のトリガーはリストに含まれず拒否されます。
以下の例は形状のみを示しています。実際の値には署名のクエリパラメータも含まれますが、公開された例は仕様に永遠に残り、実際の署名は漏洩した認証情報であると同時に機能しなくなるリンクでもあるため、ここでは意図的に省略しています。
各画像は 25 MiB、1リクエストの画像は合計 64 MiB に制限されます。
