モデルが公開している例は生成の呼び出しで、このフィールドを省略しています。`image` を追加することが 2 つのモードの違いのすべてです（同じエンドポイント、同じモデル ID）。ただし編集用のプロンプトはシーンではなく望む変更を記述するため、構造的に新しいのはこのフィールドだけでも、下記の編集用ボディは生成の例とは異なって見えます。

<ParamField body="mask" type="string">
  1 枚の画像を、呼び出し元に代わって Router が取得する https URL、またはバイト列をインラインで含む `data:image/<format>;base64,<payload>` URI のいずれかで指定します。受け付ける画像形式は png、webp、jpeg で、この組み合わせはプロバイダーに委ねるのではなく解決時に強制されます。svg、gif、avif、tiff はここで拒否され、送信した画像が名指しされます。原因から 2 ホップ離れたパートナーエラーにはなりません。
URL 形式を推奨します。base64 ペイロードは約 4/3 に膨らみ、リクエストボディ全体は 100 MiB に制限されるため、インライン形式ではソース画像が概ね 75 MB で上限に達します。URL ならこれを完全に回避できます。この説明の末尾に記載する画像あたりおよびリクエストあたりのメディア上限はボディの上限より厳しいため、実用サイズの画像ではまずそちらに当たります。
URL は認証情報なしで解決できる必要があります。Router はサーバー側で取得し、呼び出し元の認証情報をリクエストに含めません。そのため、署名がクエリ文字列に含まれる形式の署名付き URL がサポートされる形式です。`/api/assets/{id}/content` のような認証付きエンドポイントは、画像ではなく 401 を Router に返します。その URL をご自身でリクエストし、リダイレクト先の署名付き URL を渡してください。
取得は開かれたインターネットではなく、名前を挙げたホスト群に限定されます。同じリストは、送信した URL だけでなくすべてのリダイレクトホップにも再適用されます。そのため、他のホストの URL や、リスト外へリダイレクトする URL は、プロバイダーに接続する前に拒否されます。現時点でそのリストは Comfy 自身のアセット配信のみです。すなわち Comfy のアセットバケット配下の署名付き `storage.googleapis.com` URL で、これは `/api/assets/{id}/content` がリダイレクトする先の形式です。パートナーの CDN や通常の https ホストはリストに含まれません。
2 つの拡張が展開中で、どちらも現時点では既定で無効です。これらは 1 つの切り替えの背後で提供され、同時に有効化されます。そのため以下はすべて、まだ依存して実装する対象ではなく、今後提供予定のものとして扱ってください。どちらかに依存する前に確認してください。
1 つ目は `POST /customers/storage` がアップロード先として署名するバケットです。展開がお使いの環境に届くまで、このエンドポイントが発行するアップロード URL はここで拒否されます。バケットは Comfy 自身のものでホストも同じであっても変わりません。そのため「Comfy にアップロードしてから URL を渡す」はまだ動作せず、動作するのは `/api/assets/{id}/content` がリダイレクトする署名付き URL の形式です。
2 つ目は全員一斉ではなくアカウント単位で有効化されます。これらのホストの背後にあるバケットは当社のものではなくお客様のものだからです。上記の切り替えがオンになっていても、サードパーティのインバウンドメディアが有効化されていないアカウントは拒否され、ホストが未サポートであるとは告げずに、その旨がそのまま伝えられます。お使いのアカウントでの有効化を Comfy の担当者に依頼してください。これにより次のサードパーティのオブジェクトストレージホストも許可されます。ここではバケットはお客様のものであり、Router はその所有権を主張しません。Cloudflare R2（`<account>.r2.cloudflarestorage.com`、`pub-<hash>.r2.dev`）、Amazon S3（`s3.amazonaws.com` と `s3.<region>.amazonaws.com`、パス形式または `<bucket>.` 接頭辞形式のいずれか）、Azure Blob Storage（`<account>.blob.core.windows.net`）、Alibaba Cloud OSS（`<bucket>.oss-<region>.aliyuncs.com`、`oss-accelerate` エンドポイントを含む）。これらはあくまでオブジェクトストレージのエンドポイントです。同じプロバイダーのドメイン上の汎用エンドポイント、たとえば Alibaba Function Compute のトリガーはリストに含まれず、拒否されます。
照合されるのはプロバイダーではなくホスト名の形式です。したがって上記でプロバイダー名を挙げたからといって、そのプロバイダーが発行しうるすべての URL が受け入れられるわけではありません。呼び出し元が妥当にたどり着きうる 3 つの紛らわしい形式を明記しておきます。R2 のカスタムドメイン（`cdn.example.com`）は受け入れられません。Cloudflare は `pub-<hash>.r2.dev` をレート制限付きのデバッグ用ホスト名と位置づけ、本番トラフィックはカスタムドメインに向けるよう案内していますが、カスタムドメインのホスト名には R2 であることを示す情報が何も含まれないため、Router は他のホストと区別できず拒否します。`<account>.r2.cloudflarestorage.com` エンドポイントに署名するか、`pub-<hash>.r2.dev` 形式を使用してください。S3 の IPv6 dualstack エンドポイント（`s3.dualstack.<region>.amazonaws.com`）も受け入れられません。通常のリージョナルエンドポイントを使用してください。Azure Blob の代替 DNS ゾーン（`<account>.z<N>.blob.storage.azure.net`）も同様です。`<account>.blob.core.windows.net` を使用してください。返される拒否メッセージにはこれらの形式が示されるため、ここに戻って読む必要はありません。
上記の `<account>` と `pub-<hash>` は、通常たどり着く形式を示すプレースホルダーであり、深さの制限ではありません。マッチングはオブジェクトストレージのドメインサフィックスに対して行われるため、同じ名前空間の下にあるより深い名前（`a.b.pub-<hash>.r2.dev`）も受け入れられます。ただし、これによって広げられるわけではないのは名前空間そのものです。サフィックスは依然として列挙されたもののいずれかでなければなりません。

各画像は 25 MiB、1 リクエストの画像は合計 64 MiB までです。唯一の例外は ideogram/ideogram-4-5 Precise Edit（`image` を送信する呼び出し）で `context_window` が利用可能な場合です。その場合、各画像は最大 50 MB（50,000,000 バイト）かつ 67,108,864 ピクセル、1 リクエストの画像は合計 128 MiB までです。
