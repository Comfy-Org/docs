<ParamField body="mask" type="string">
  1 つの画像を、呼び出し元に代わって Router が取得する https URL、またはバイト列をインラインで含む `data:image/<format>;base64,<payload>` URI のいずれかで指定します。受け付けられる画像タイプは png、webp、jpeg で、このセットはプロバイダーに任されず解決時に強制されます。svg、gif、avif、tiff はここで拒否され、送信した画像が名指しされます。原因から 2 ホップ離れたパートナーエラーになることはありません。
URL 形式を推奨します。base64 ペイロードはおおよそ 4/3 に膨張し、リクエストボディ全体は 20 MiB に制限されるため、インライン形式ではソース画像が約 15 MB で上限に達します。URL ならそれを完全に回避できます。
URL は認証情報なしで解決できなければなりません。Router はサーバー側でそれを取得し、リクエストに呼び出し元の認証情報を一切付けません。そのため、署名がクエリ文字列に含まれる形式、すなわち署名付き URL がサポートされる形式です。`/api/assets/{id}/content` のような認証が必要なエンドポイントは、画像ではなく Router に 401 を返します。その URL をご自身でリクエストし、リダイレクト先の署名付き URL を渡してください。
取得はオープンなインターネットではなく、名前を挙げた一連のホストに限定され、同じリストが送信した URL だけでなくすべてのリダイレクトホップにも再適用されます。したがって、それ以外のホストの URL や、リスト外へリダイレクトする URL は、プロバイダーに接触する前に拒否されます。現在このリストは Comfy 自身のアセット配信のみです。Comfy のアセットバケット配下の署名付き `storage.googleapis.com` URL であり、これは `/api/assets/{id}/content` がリダイレクトする形式です。パートナー CDN や通常の https ホストはリストにありません。
2 つの緩和策が展開中で、どちらも本日時点ではデフォルトでオフです。これらは 1 つの切り替えの背後で提供され、一緒に有効になります。そのため以下はすべて、まだ依存して構築する対象ではなく、今後提供されるものとして扱ってください。どちらかに依存する前に確認してください。
1 つ目は、`POST /customers/storage` がアップロード先として署名するバケットです。展開がお使いの環境に届くまで、そのエンドポイントから得たアップロード URL はここで拒否されます。バケットは Comfy 自身のものでホストも同じであるにもかかわらずです。したがって「Comfy にアップロードしてから URL を渡す」はまだ機能せず、機能するのは `/api/assets/{id}/content` がリダイレクトする署名付き URL の形式です。
2 つ目は、全員に一斉ではなくアカウントごとに有効化されます。これらのホストの背後にあるバケットは当社のものではなくお客様のものであるためです。上記の切り替えがオンになっていても、サードパーティの受信メディアが有効化されていないアカウントは拒否され、ホストがサポートされていないとは告げられず、その旨の文言で通知されます。お使いのアカウントで有効化するよう Comfy の担当者に依頼してください。さらに、次のサードパーティのオブジェクトストレージホストを許可します。バケットはお客様のものであり、Router はその所有権を主張しません: Cloudflare R2 (`<account>.r2.cloudflarestorage.com`、`<id>.r2.dev`)、Amazon S3 (`s3.amazonaws.com` および `s3.<region>.amazonaws.com`、パス形式または `<bucket>.` 接頭辞形式のいずれか)、Azure Blob Storage (`<account>.blob.core.windows.net`)、Alibaba Cloud OSS (`<bucket>.oss-<region>.aliyuncs.com`、`oss-accelerate` エンドポイントを含む)。これらは特にオブジェクトストレージのエンドポイントです。同じプロバイダードメイン上の汎用エンドポイント、たとえば Alibaba Function Compute のトリガーはリストになく、拒否されます。
以下の例は形状のみを示しています。実際の値は署名のクエリパラメータも伴いますが、ここでは意図的に省略しています。公開された例は仕様の中に永遠に残り、実際の署名は漏洩した認証情報であると同時に機能しなくなるリンクでもあるためです。
