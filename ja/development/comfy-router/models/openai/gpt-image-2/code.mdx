1 枚の画像またはその配列を受け付けます。gpt-image-1 以降は最大 16 枚を受け付け、Router はディスパッチ前にこのスキーマからそれを強制します。

<ParamField body="mask" type="string">
  1 枚の画像を、Router が呼び出し元に代わって取得する https URL、またはバイト列をインラインで保持する `data:image/<format>;base64,<payload>` URI のいずれかで指定します。受け付ける画像タイプは png、webp、jpeg で、このセットはプロバイダーに委ねるのではなく解決時に強制されます。svg、gif、avif、tiff はここで拒否され、送信した画像が名指しされます。原因から 2 ホップも離れたパートナーエラーにはなりません。
URL 形式を推奨します。Base64 ペイロードはおよそ 4/3 に膨張し、リクエストボディ全体は 10 MiB に制限されているため、インライン形式ではソース画像が約 7.5 MB で上限に達します。URL ならこれを完全に回避できます。
URL は認証情報なしで解決できる必要があります。Router はこれをサーバーサイドで取得し、リクエストに呼び出し元の認証情報を一切付けません。そのため、署名がクエリ文字列に含まれる Comfy 署名済みアセット URL がサポートされる形式です。`/api/assets/{id}/content` のような認証済みエンドポイントは、画像ではなく 401 を Router に返します。その URL を自分でリクエストし、リダイレクト先の署名済み URL を渡してください。取得はオープンインターネットではなく Comfy 自身のアセットバケットに限定され、送信した URL だけでなくすべてのリダイレクトホップにも適用されるため、サードパーティの URL やリダイレクトする URL は拒否されます。
以下の例は形状のみを示しています。実際の値には署名クエリパラメータも含まれますが、ここでは意図的に省略しています。公開された例は仕様の中に永久に残り、実際の署名は漏洩した認証情報であると同時に、機能しなくなるリンクでもあるからです。
各画像は 25 MiB、1 リクエストの画像は合計 64 MiB に制限されています。
