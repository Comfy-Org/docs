<ParamField body="mask" type="string">
  1 つの画像を、Router が呼び出し元の代理で取得する https URL、またはバイト列をインラインで含む `data:image/<format>;base64,<payload>` URI のいずれかとして指定します。受け入れられる画像形式は png、webp、jpeg で、このセットはプロバイダーに任されるのではなく解決時に強制されます。svg、gif、avif、tiff はここで拒否され、送信した画像が特定されるため、原因から 2 ホップ離れたパートナーエラーにはなりません。
URL 形式を推奨します。base64 ペイロードはおよそ 4/3 に膨らみ、リクエストボディ全体は 20 MiB に制限されるため、インライン形式は約 15 MB のソース画像で上限に達します。URL はそれを完全に回避します。
URL は資格情報なしで解決できる必要があります。Router はそれをサーバー側で取得し、リクエストに呼び出し元の資格情報を付けません。そのため、署名がクエリ文字列に含まれる署名付き URL がサポートされる形式です。`/api/assets/{id}/content` のような認証済みエンドポイントは、画像ではなく 401 を Router に返します。その URL を自分でリクエストし、リダイレクト先の署名付き URL を渡してください。
取得は開かれたインターネットではなく、指定されたホストのセットに限定され、同じリストが送信した URL だけでなくすべてのリダイレクトホップにも再適用されます。そのため、他のホストの URL やリスト外へリダイレクトする URL は、プロバイダーに接触する前に拒否されます。現在そのリストは Comfy 自身のアセット配信のみです。Comfy のアセットバケット配下の署名付き `storage.googleapis.com` URL で、これは `/api/assets/{id}/content` がリダイレクトする形式です。パートナー CDN や通常の https ホストはリストに含まれません。
2 つの拡張が展開中で、どちらも現在デフォルトでは無効です。これらは 1 つの切り替えの背後で提供され、一緒に有効化されます。したがって以下はすべて、まだ依存して構築する対象ではなく、今後提供されるものとして扱ってください。どちらかに依存する前に確認してください。
1 つ目は、`POST /customers/storage` がアップロード先として署名するバケットです。展開がお使いの環境に到達するまで、そのエンドポイントからのアップロード URL はここで拒否されます。バケットは Comfy 自身のものでホストも同じであってもです。そのため「Comfy にアップロードしてから URL を渡す」はまだ機能せず、機能するのは `/api/assets/{id}/content` がリダイレクトする署名付き URL の形式です。
2 つ目はさらに、以下のサードパーティのオブジェクトストレージホストを許可します。ここではバケットはあなたのものであり、Router はその所有権を主張しません: Cloudflare R2 (`<account>.r2.cloudflarestorage.com`、`<id>.r2.dev`)、Amazon S3 (`s3.amazonaws.com` および `s3.<region>.amazonaws.com`、パス形式または `<bucket>.` プレフィックス形式のいずれか)、Azure Blob Storage (`<account>.blob.core.windows.net`)、Alibaba Cloud OSS (`<bucket>.oss-<region>.aliyuncs.com`、`oss-accelerate` エンドポイントを含む)。これらは特にオブジェクトストレージのエンドポイントです。同じプロバイダードメイン上の汎用エンドポイント、たとえば Alibaba Function Compute のトリガーはリストに含まれず、拒否されます。
以下の例は形状のみを示しています。実際の値には署名クエリパラメータも含まれますが、公開された例は仕様に永久に残り、実際の署名は漏洩した資格情報であると同時に機能しなくなるリンクでもあるため、ここでは意図的に省略しています。
各画像は 25 MiB、1 つのリクエストの画像は合計 64 MiB に制限されます。
