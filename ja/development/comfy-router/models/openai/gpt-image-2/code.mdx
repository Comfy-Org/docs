URL 形式を推奨します。base64 ペイロードは約 4/3 に膨張し、リクエストボディ全体は 100 MiB に制限されるため、インライン形式ではソース画像が約 75 MB で上限に達します。URL ならこれを完全に回避できます。この説明の最後に記載されている画像ごとおよびリクエストごとのメディア上限はボディの上限よりも厳しいため、実際のサイズの画像ではまずそちらに達します。
URL は認証情報なしで解決できる必要があります。Router はサーバー側で取得し、呼び出し元の認証情報をリクエストに付けません。そのため、署名がクエリ文字列に含まれる形式の署名付き URL がサポートされる形式です。`/api/assets/{id}/content` のような認証が必要なエンドポイントは画像ではなく 401 を Router に返します。その URL はご自身でリクエストし、リダイレクト先の署名付き URL を渡してください。
取得はオープンなインターネットではなく、名前を挙げたホスト群に限定され、同じリストは送信した URL だけでなく各リダイレクトホップにも再適用されます。そのため、他のホストの URL や、リスト外へリダイレクトする URL は、いずれかのプロバイダーに接触する前に拒否されます。現在のリストは Comfy 自身のアセット配信のみです。Comfy のアセットバケット配下の署名付き `storage.googleapis.com` URL で、これが `/api/assets/{id}/content` がリダイレクトする形式です。パートナーの CDN や通常の https ホストはリストに含まれません。
2つの拡張が展開中で、どちらも現在はデフォルトで無効です。これらは1つの切り替えの背後で提供され、同時に有効化されます。そのため以下はすべて、まだそれに基づいて構築するものではなく、今後提供されるものとして扱ってください。どちらかに依存する前に確認してください。
1つ目は `POST /customers/storage` がアップロード先として署名するバケットです。展開がお使いの環境に到達するまでは、そのエンドポイントからのアップロード URL はここで拒否されます。バケットは Comfy 自身のものでホストも同じであってもです。したがって「Comfy にアップロードして、その URL を渡す」はまだ機能せず、機能するのは `/api/assets/{id}/content` がリダイレクトする署名付き URL の形式です。
