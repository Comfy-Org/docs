<ParamField body="background" type="string">

<ParamField body="image" type="string | string[]">
  編集対象のソース画像。このフィールドの有無が編集操作を選択します。テキストから画像への生成では完全に省略してください。
モデルの公開されている例は GENERATION 呼び出しで、このフィールドを省略しています。`image` を追加することが 2 つのモードの違いのすべてです（同じエンドポイント、同じモデル id）。ただし編集プロンプトはシーンではなく、望む変更を記述するため、以下に示す編集用のボディは、構造的に新しいのがこのフィールドだけであっても、生成の例とは異なって読めます。
これは印刷されたままの形でコピーできます: `{"prompt": "give the rocketship rainbow coloring", "image": ["data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="], "size": "1024x1024"}`。ペイロードは省略形ではなく完全な 1x1 PNG であり、このボディは Router 自身のリクエスト検証テストで受け入れられるケースとしてピン留めされています。ご自身の画像のバイト列に差し替えてください。
1 枚の画像またはその配列を受け付けます。gpt-image-1 以降は最大 16 枚を受け付け、Router はディスパッチ前にこのスキーマからそれを強制します。
</ParamField>

<ParamField body="mask" type="string">
  1 枚の画像を、呼び出し元に代わって Router が取得する https URL、またはバイト列をインラインで含む `data:image/<format>;base64,<payload>` URI のいずれかで指定します。受け入れられる画像形式は png、webp、jpeg で、このセットはプロバイダーに任されるのではなく解決時に強制されます。svg、gif、avif、tiff はここで拒否され、送信した画像が名指しされます。原因から 2 ホップ離れたパートナーのエラーになることはありません。
URL 形式を推奨します。base64 ペイロードは約 4/3 に膨らみ、リクエストボディ全体は 100 MiB に制限されるため、インライン形式ではソース画像が約 75 MB で上限に達します。URL ならこれを完全に回避できます。この説明の最後に記載されている画像ごとおよびリクエストごとのメディア上限は、ボディの上限よりも厳しいため、実際のサイズの画像ではまずこちらに達します。
URL は認証情報なしで解決できる必要があります。Router はサーバー側でそれを取得し、リクエストに呼び出し元の認証情報を一切付けません。そのため、署名がクエリ文字列にあるような署名付き URL がサポートされる形式です。`/api/assets/{id}/content` のような認証が必要なエンドポイントは、画像ではなく 401 を Router に返します。その URL を自分でリクエストし、リダイレクト先の署名付き URL を渡してください。
取得はオープンなインターネットではなく、指定されたホスト群に限定され、同じリストが送信した URL だけでなくすべてのリダイレクトホップにも再適用されます。したがって、他のホストの URL や、リスト外へリダイレクトされる URL は、プロバイダーに接触する前に拒否されます。現在、このリストは Comfy 自身のアセット配信のみです。Comfy のアセットバケット配下の署名付き `storage.googleapis.com` URL で、これは `/api/assets/{id}/content` がリダイレクトする形式です。パートナーの CDN や通常の https ホストはリストに含まれません。
2 つの拡張がロールアウト中で、どちらも現在は既定で無効です。これらは 1 つの切り替えの背後で提供され、まとめて有効になります。そのため、以下はすべて今後に提供予定のものとして扱い、まだ依存して構築する対象とはしないでください。どちらかに依存する前に確認してください。
1 つ目は、`POST /customers/storage` がアップロード先として署名するバケットです。ロールアウトがお使いの環境に到達するまで、そのエンドポイントからのアップロード URL はここで拒否されます。バケットは Comfy 自身のものでホストも同じであってもです。そのため「Comfy にアップロードしてから URL を渡す」はまだ機能せず、機能する形式は `/api/assets/{id}/content` がリダイレクトする署名付き URL です。
2 つ目は全員に一度にではなくアカウント単位で有効になります。これらのホストの背後にあるバケットが弊社ではなくお客様のものだからです。上記の切り替えがオンになっても、サードパーティの受信メディアが有効化されていないアカウントは拒否され、ホストがサポートされていないと伝えられるのではなく、その旨がそのまま伝えられます。お使いのアカウントで有効化するよう Comfy の担当者に依頼してください。さらにこれは以下のサードパーティのオブジェクトストレージホストを許可します。ここではバケットはお客様のものであり、Router はその所有権を主張しません。Cloudflare R2（`<account>.r2.cloudflarestorage.com`、`<id>.r2.dev`）、Amazon S3（`s3.amazonaws.com` および `s3.<region>.amazonaws.com`、パス形式または `<bucket>.` を前置する形式のいずれか）、Azure Blob Storage（`<account>.blob.core.windows.net`）、Alibaba Cloud OSS（`<bucket>.oss-<region>.aliyuncs.com`、`oss-accelerate` エンドポイントを含む）。これらは特にオブジェクトストレージのエンドポイントです。同じプロバイダードメイン上の汎用エンドポイント、たとえば Alibaba Function Compute のトリガーはリストに含まれず、拒否されます。
以下の例は形状のみを示しています。実際の値には署名クエリパラメータも含まれますが、公開された例は仕様の中に永久に残り、実際の署名は漏洩した認証情報であると同時に機能しなくなるリンクでもあるため、ここでは意図的に省略しています。
各画像は 25 MiB、1 つのリクエストの画像は合計 64 MiB に制限されます。
