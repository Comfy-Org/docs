## スキーマ

### 入力

<ParamField body="background" type="string">
  背景の透明性。`auto` はモデルに選択させます。

  取り得る値: `transparent`、`opaque`、`auto`
</ParamField>

<ParamField body="image" type="string | string[]">
  編集するソース画像。このフィールドの有無が編集操作を選択します。テキストから画像への生成ではこれを完全に省略します。
モデルの公開されている例はこのフィールドを省略した生成呼び出しです。`image` を追加することが2つのモードの違いのすべてです（同じエンドポイント、同じモデル id）。ただし編集プロンプトはシーンではなく希望する変更を記述するため、構造的に新しいのはこのフィールドだけであっても、以下の編集ボディは生成の例とは異なって見えます。
これは記述どおりにそのままコピーできます: `{"prompt": "give the rocketship rainbow coloring", "image": ["data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="], "size": "1024x1024"}`。ペイロードは完全な 1x1 PNG であり、省略形ではありません。このボディは Router 自身のリクエスト検証テストで受け入れられるケースとしてピン留めされています。ご自身の画像のバイト列に差し替えてください。
1つの画像またはその配列を受け付けます。gpt-image-1 以降は最大 16 個で、Router はディスパッチ前にこのスキーマからそれを強制します。
</ParamField>

<ParamField body="mask" type="string">
  1つの画像。呼び出し元に代わって Router が取得する https URL、またはバイト列をインラインで含む `data:image/<format>;base64,<payload>` URI のいずれかの形式です。受け入れられる画像タイプは png、webp、jpeg で、このセットはプロバイダーに任されるのではなく解決時に強制されます。svg、gif、avif、tiff はここで拒否され、送信した画像が名指しされます。原因から2ホップ離れたパートナーエラーにはなりません。
URL 形式を推奨します。base64 ペイロードは約 4/3 に膨張し、リクエストボディ全体は 100 MiB に上限が設定されているため、インライン形式はソース画像約 75 MB が上限になります。URL ならこれを完全に回避できます。この説明の最後に記載されている画像ごとおよびリクエストごとのメディア上限はボディ上限よりも厳しいため、実用的なサイズの画像ではまずこちらに到達します。
URL はあなたの認証情報なしで解決できなければなりません。Router はサーバー側で取得し、リクエストに呼び出し元の認証情報を付けません。そのため、署名がクエリ文字列にある形式の署名付き URL がサポートされる形式です。`/api/assets/{id}/content` のような認証済みエンドポイントは Router に画像ではなく 401 を返します。その URL をご自身でリクエストし、リダイレクト先の署名付き URL を渡してください。
取得は開かれたインターネットではなく、指定されたホストのセットに限定されます。同じリストは、送信した URL だけでなくすべてのリダイレクトホップにも再適用されます。そのため、他のホストの URL やリスト外へリダイレクトする URL は、プロバイダーに接触する前に拒否されます。現在、このリストは Comfy 自身のアセット配信のみです。Comfy のアセットバケット配下の署名付き `storage.googleapis.com` URL で、これは `/api/assets/{id}/content` がリダイレクトする形式です。パートナー CDN や通常の https ホストはリストに含まれません。
2つの拡張が展開中で、どちらも現在はデフォルトで無効です。これらは1つの切り替えの背後で提供され、一緒に有効になります。そのため以下はすべてまだ構築対象ではなく今後提供されるものとして扱ってください。どちらかに依存する前に確認してください。
1つ目は `POST /customers/storage` がアップロード先として署名するバケットです。ロールアウトがあなたの環境に到達するまで、そのエンドポイントからのアップロード URL はここで拒否されます。バケットは Comfy 自身のものでホストも同じであってもです。そのため「Comfy にアップロードしてから URL を渡す」はまだ機能しません。機能するのは `/api/assets/{id}/content` がリダイレクトする署名付き URL です。
2つ目は全員に一度にではなくアカウントごとに有効化されます。これらのホストの背後のバケットは当社のものではなくあなたのものだからです。上記の切り替えがオンになっていても、サードパーティの受信メディアが有効化されていないアカウントは拒否され、ホストが未サポートだとは告げられず、その文言で伝えられます。Comfy の担当者にあなたのアカウントで有効化するよう依頼してください。これはさらに、バケットがあなたのもので Router が所有権を主張しない以下のサードパーティのオブジェクトストレージホストを許可します: Cloudflare R2（`<account>.r2.cloudflarestorage.com`、`<id>.r2.dev`）、Amazon S3（`s3.amazonaws.com` および `s3.<region>.amazonaws.com`、path-style または `<bucket>.` プレフィックス形式のいずれか）、Azure Blob Storage（`<account>.blob.core.windows.net`）、Alibaba Cloud OSS（`oss-accelerate` エンドポイントを含む `<bucket>.oss-<region>.aliyuncs.com`）。これらは特にオブジェクトストレージのエンドポイントです。同じプロバイダードメイン上の汎用エンドポイント、たとえば Alibaba Function Compute トリガーはリストになく拒否されます。
以下の例は形状のみを示しています。実際の値は署名クエリパラメータも含みますが、公開された例は仕様に永遠に残り、実際の署名は漏洩した認証情報であると同時に機能しなくなるリンクでもあるため、ここでは意図的に省略しています。
各画像は 25 MiB、1リクエストの画像は合計 64 MiB に制限されます。
