同じボディを `POST https://api.comfy.org/v2/models/openai/gpt-image-1/requests` に送信します。Router は実行が受け付けられ次第 `201` と `request_id` を返し、結果は準備が整った時点で、このプロセスからでも別のプロセスからでも取得できます。ステータス、キャンセル、結果の取得については [Queued delivery](/ja/development/comfy-router/queue) で詳しく説明しています。

<CodeGroup>
```python Python
from comfy_sdk import Comfy

# 環境から COMFY_API_KEY を読み取ります。
# submit() を呼び出すたびに独自の Idempotency-Key が発行され、自動リトライのために再利用されます。
with Comfy() as client:
    handle = client.models.submit(
        "openai/gpt-image-1",
        {
            "prompt": "a rocketship on a launchpad",
            "quality": "low",
            "size": "1024x1024",
        },
    )
    print("request_id:", handle.request_id)  # モデル ID と合わせれば、別のプロセスに必要なものはこれだけです

    # リクエストが完了するまでポーリングし、サーバーが指定する Retry-After の秒数だけ待機します。
    for update in handle.iter_events():
        print(update.status, update.queue_position)

    # プロバイダー自身のペイロードで、models.run() が返す値と同じものです。
    # 失敗またはキャンセルされたリクエストは、ここで型付きの Router エラーを送出します。
    result = handle.get()

print(result)
```

<ParamField body="image" type="string | string[]">
  編集対象のソース画像。このフィールドの有無が編集操作を選択します。テキストから画像への生成では完全に省略してください。
モデルが公開している例は生成呼び出しであり、このフィールドを省略しています。`image` を追加することが 2 つのモードの違いのすべてです（同じエンドポイント、同じモデル ID）。ただし編集用の prompt はシーンではなく、望む変更を記述するため、構造的に新しいのはこのフィールドだけであるにもかかわらず、以下の編集用ボディは生成の例とは異なって見えます。
これは印刷されたとおりにそのままコピーできます: `{"prompt": "give the rocketship rainbow coloring", "image": ["data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="], "size": "1024x1024"}`。このペイロードは省略形ではなく完全な 1x1 PNG であり、このボディは Router 自身のリクエスト検証テストで受け入れられるケースとしてピン留めされています。ご自身の画像のバイト列に差し替えてください。
1 枚の画像またはその配列を受け付けます。gpt-image-1 以降は最大 16 枚で、Router はディスパッチ前にこのスキーマに基づいてそれを強制します。
</ParamField>

<ParamField body="mask" type="string">
  1 枚の画像を、Router が呼び出し元に代わって取得する https URL、またはバイト列をインラインで含む `data:image/<format>;base64,<payload>` URI のいずれかで指定します。受け付ける画像形式は png、webp、jpeg で、このセットはプロバイダーに委ねるのではなく解決時に強制されます。svg、gif、avif、tiff はここで拒否され、送信した画像を名指しします。原因から 2 ホップ離れたパートナーエラーになることはありません。
URL 形式を推奨します。base64 ペイロードは約 4/3 に膨らみ、リクエストボディ全体は 20 MiB に制限されるため、インライン形式ではソース画像が約 15 MB で上限に達します。URL ならこれを完全に回避できます。
URL は認証情報なしで解決できなければなりません。Router はサーバー側で取得し、呼び出し元の認証情報をリクエストに付与しません。そのためサポートされる形式は、署名がクエリ文字列に入っている presigned URL です。`/api/assets/{id}/content` のような認証が必要なエンドポイントは、画像ではなく 401 を Router に返します。その URL をご自身でリクエストし、リダイレクト先の署名済み URL を渡してください。
取得は開かれたインターネットではなく、名前を挙げたホストの集合に限定されます。同じリストは、送信した URL だけでなくすべてのリダイレクトホップにも再度適用されます。したがって、それ以外のホストの URL や、リスト外へリダイレクトする URL は、プロバイダーに接触する前に拒否されます。現在このリストは Comfy 自身のアセット配信のみです。つまり Comfy のアセットバケット配下の署名済み `storage.googleapis.com` URL であり、これは `/api/assets/{id}/content` がリダイレクトする形式です。パートナー CDN や通常の https ホストはリストに含まれません。
2 つの拡張が展開中で、どちらも現在はデフォルトで無効です。これらは 1 つの切り替えの背後で提供され、まとめて有効になります。そのため以下はすべて今後の予定として扱い、まだ依存して実装する対象とはしないでください。どちらかに依存する場合は事前に確認してください。
1 つ目は、`POST /customers/storage` がアップロード先として署名するバケットです。ロールアウトがお使いの環境に到達するまで、このエンドポイントからのアップロード URL はここで拒否されます。バケットが Comfy 自身のものでホストも同じであっても変わりません。つまり「Comfy にアップロードしてから URL を渡す」はまだ機能せず、機能するのは `/api/assets/{id}/content` がリダイレクトする署名済み URL です。
2 つ目は、以下のサードパーティのオブジェクトストレージホストを追加で許可します。ここではバケットはお客様のものであり、Router はその所有権を主張しません。Cloudflare R2（`<account>.r2.cloudflarestorage.com`、`<id>.r2.dev`）、Amazon S3（`s3.amazonaws.com` および `s3.<region>.amazonaws.com`、パス形式または `<bucket>.` を前に付ける形式のいずれか）、Azure Blob Storage（`<account>.blob.core.windows.net`）、Alibaba Cloud OSS（`<bucket>.oss-<region>.aliyuncs.com`、`oss-accelerate` エンドポイントを含む）。これらは特にオブジェクトストレージのエンドポイントです。同じプロバイダードメイン上の汎用エンドポイント、たとえば Alibaba Function Compute のトリガーはリストに含まれず、拒否されます。
以下の例は形状のみを示しています。実際の値は署名用クエリパラメータも含みますが、公開された例は仕様の中に永遠に残るため、ここでは意図的に省略しています。実際の署名は認証情報の漏洩であると同時に、いずれ機能しなくなるリンクでもあります。
各画像は 25 MiB、1 つのリクエストの画像は合計 64 MiB が上限です。
