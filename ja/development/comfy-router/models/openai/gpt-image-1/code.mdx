### 入力

<ParamField body="background" type="string">
  背景の透明性。`auto` はモデルに選択させます。

  指定可能な値: `transparent`、`opaque`、`auto`
</ParamField>

<ParamField body="image" type="string | string[]">
  編集するソース画像。このフィールドの有無が編集操作を選択します。テキストから画像への生成では完全に省略してください。
モデルが公開している例はこのフィールドを省略した生成呼び出しです。`image` を追加することが 2 つのモードの違いのすべてです。同じエンドポイント、同じモデル id ですが、編集用のプロンプトはシーンではなく望む変更を記述するため、構造的に新しいのはこのフィールドだけであるにもかかわらず、以下の編集用ボディは生成の例とは異なって見えます。
これは記載どおりにそのままコピーできます: `{"prompt": "give the rocketship rainbow coloring", "image": ["data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="], "size": "1024x1024"}`。ペイロードは省略形ではなく完全な 1x1 PNG であり、このボディは Router 自身のリクエスト検証テストで受け入れられるケースとしてピン留めされています。ご自身の画像のバイト列に差し替えてください。
1 枚の画像またはその配列を受け付けます。gpt-image-1 以降は最大 16 枚で、Router はディスパッチ前にこのスキーマに基づいてそれを強制します。
</ParamField>

<ParamField body="mask" type="string">
  1 枚の画像を、Router が呼び出し元に代わって取得する https URL、またはバイト列をインラインで含む `data:image/<format>;base64,<payload>` URI のいずれかの形式で指定します。受け付ける画像タイプは png、webp、jpeg で、このセットはプロバイダーに委ねるのではなく解決時に強制されます。svg、gif、avif、tiff はここで拒否され、送信した画像を名指しします。原因から 2 ホップ離れたパートナーのエラーになることはありません。
URL 形式を推奨します。base64 ペイロードはおよそ 4/3 に膨張し、リクエストボディ全体は 100 MiB に制限されるため、インライン形式ではソース画像が約 75 MB で上限に達します。URL ならこれを完全に回避できます。この説明の最後に示す画像ごとおよびリクエストごとのメディア上限はボディの上限よりも厳しいため、実際のサイズの画像ではまずこちらに突き当たります。
URL は認証情報なしで解決できなければなりません。Router はサーバー側でこれを取得し、リクエストに呼び出し元の認証情報を付けません。したがって、署名がクエリ文字列にあるような署名付き URL（presigned URL）がサポートされる形式です。`/api/assets/{id}/content` のような認証が必要なエンドポイントは、画像ではなく Router に 401 を返します。その URL はご自身でリクエストし、リダイレクト先の署名付き URL を渡してください。
取得は開かれたインターネットではなく、名前を挙げたホストの集合に限定され、同じリストが送信した URL だけでなくすべてのリダイレクトホップにも再適用されます。したがって、他のホストの URL や、リスト外へリダイレクトする URL は、どのプロバイダーにも接続する前に拒否されます。現在、そのリストは Comfy 自身のアセット配信のみです。Comfy のアセットバケット配下の署名付き `storage.googleapis.com` URL で、これは `/api/assets/{id}/content` がリダイレクトする形式です。パートナーの CDN や通常の https ホストはリストにありません。
2 つの拡張が展開中で、どちらも本日時点ではデフォルトで無効です。これらは 1 つの切り替えの背後で提供され、同時に有効になります。したがって、以下はすべて今後に予定されているものとして扱い、まだ依存して実装する対象とはしないでください。どちらかに依存する前に確認してください。
1 つ目は、`POST /customers/storage` がアップロード先として署名するバケットです。展開がお使いの環境に到達するまで、そのエンドポイントからのアップロード URL は、バケットが Comfy 自身のものでホストも同じであっても、ここで拒否されます。つまり「Comfy にアップロードしてから URL を渡す」という方法はまだ機能せず、機能するのは `/api/assets/{id}/content` がリダイレクトする署名付き URL の形式です。
2 つ目は、全員に一度にではなくアカウントごとに有効化されます。これらのホストの背後にあるバケットは当社ではなくお客様のものだからです。上記の切り替えがオンになっていても、サードパーティの受信メディアが有効化されていないアカウントは拒否され、ホストがサポート対象外だと言われるのではなく、その旨の文言で伝えられます。お使いのアカウントで有効化するよう Comfy の担当者に依頼してください。さらに、次のサードパーティのオブジェクトストレージホストを許可します。ここではバケットはお客様のものであり、Router はその所有権を主張しません: Cloudflare R2（`<account>.r2.cloudflarestorage.com`、`pub-<hash>.r2.dev`）、Amazon S3（`s3.amazonaws.com` および `s3.<region>.amazonaws.com`、パス形式または `<bucket>.` を前置する形式のいずれか）、Azure Blob Storage（`<account>.blob.core.windows.net`）、Alibaba Cloud OSS（`<bucket>.oss-<region>.aliyuncs.com`、`oss-accelerate` エンドポイントを含む）。これらは特にオブジェクトストレージのエンドポイントです。同じプロバイダーのドメイン上の汎用エンドポイント、たとえば Alibaba Function Compute のトリガーはリストになく、拒否されます。
一致するのはプロバイダーではなくホスト名の形式です。したがって、上に挙げたプロバイダー名は、そのプロバイダーが発行しうるすべての URL が受け入れられることを意味しません。また、呼び出し元がそれぞれの形式で到達するのは妥当なことなので、3 つの近いはずれは明記しておく価値があります。R2 のカスタムドメイン（`cdn.example.com`）は受け入れられません。Cloudflare は `pub-<hash>.r2.dev` をレート制限付きのデバッグ用ホスト名として文書化し、本番トラフィックは代わりにカスタムドメインに向けるよう案内していますが、カスタムドメインのホスト名にはそれが R2 であると識別する情報が何もないため、Router は他のホストと区別できず拒否します。`<account>.r2.cloudflarestorage.com` エンドポイントに署名するか、`pub-<hash>.r2.dev` 形式を使用してください。S3 の IPv6 dualstack エンドポイント（`s3.dualstack.<region>.amazonaws.com`）も受け入れられません。通常のリージョナルエンドポイントを使用してください。Azure Blob の代替 DNS ゾーン（`<account>.z<N>.blob.storage.azure.net`）も同様です。`<account>.blob.core.windows.net` を使用してください。返される拒否メッセージにはこれら同じ形式が記載されているので、それらを読むためにここへ来る必要はありません。
上記の `<account>` と `pub-<hash>` は、通常そのままの形で到達するプレースホルダーであり、階層の深さを制限するものではありません。マッチングはオブジェクトストレージのドメインサフィックスに対して行われるため、同じ名前空間配下のより深い名前（`a.b.pub-<hash>.r2.dev`）も受け入れられます。ただし、それによって名前空間そのものが広がるわけではなく、サフィックスは依然として列挙されているもののいずれかである必要があります。
以下の例は形状のみを示しています。実際の値には署名用のクエリパラメータも含まれますが、ここでは意図的に省略しています。公開された例は仕様の中に永久に残り、実際の署名は漏えいした認証情報であると同時に、やがて機能しなくなるリンクでもあるためです。
各画像は 25 MiB に、1 回のリクエストの画像は合計 64 MiB に制限されます。
