```python Python
from comfy_sdk import Comfy

# 環境から COMFY_API_KEY を読み取ります。
# submit() を呼び出すたびに独自の Idempotency-Key が発行され、自動リトライのために再利用されます。
with Comfy() as client:
    handle = client.models.submit(
        "openai/gpt-image-1",
        {
            "prompt": "a rocketship on a launchpad",
            "quality": "low",
            "size": "1024x1024",
        },
    )
    print("request_id:", handle.request_id)  # モデル ID と合わせれば、別のプロセスに必要なものはこれだけです

    # リクエストが完了するまでポーリングし、サーバーが指定する Retry-After の秒数だけ待機します。
    for update in handle.iter_events():
        print(update.status, update.queue_position)

    # プロバイダー自身のペイロードで、models.run() が返す値と同じものです。
    # 失敗またはキャンセルされたリクエストは、ここで型付きの Router エラーを送出します。
    result = handle.get()

print(result)
```

<ParamField body="image" type="string | string[]">
  編集するソース画像。このフィールドの有無が編集操作を選択します。テキストから画像への生成では完全に省略してください。
モデルが公開している例は生成呼び出しであり、このフィールドを省略しています。`image` を追加することが2つのモードの違いのすべてです（同じエンドポイント、同じモデル ID）。ただし編集プロンプトはシーンではなく、希望する変更を記述するため、構造的に新しいのはこのフィールドだけであるにもかかわらず、以下の編集ボディは生成の例とは異なって見えます。
これは記載どおりにそのままコピーできます: `{"prompt": "give the rocketship rainbow coloring", "image": ["data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="], "size": "1024x1024"}`。ペイロードは省略形ではなく完全な 1x1 PNG であり、このボディは Router 自身のリクエスト検証テストで受け入れられるケースとしてピン留めされています。ご自身の画像のバイト列に差し替えてください。
1枚の画像またはその配列を受け付けます。gpt-image-1 以降は最大 16 枚で、Router はディスパッチ前にこのスキーマに基づいてそれを強制します。
</ParamField>

<ParamField body="mask" type="string">
  1枚の画像。呼び出し元の代理で Router が取得する https URL、またはバイト列をインラインで含む `data:image/<format>;base64,<payload>` URI のいずれかの形式です。受け入れられる画像タイプは png、webp、jpeg で、このセットはプロバイダーに任されるのではなく解決時に強制されます。svg、gif、avif、tiff はここで拒否され、原因から2ホップ離れたパートナーエラーになる代わりに、送信した画像が名前を挙げて示されます。
URL 形式を推奨します。base64 ペイロードは約 4/3 に膨張し、リクエストボディ全体は 20 MiB に制限されるため、インライン形式ではソース画像が約 15 MB で上限に達します。URL ならこれを完全に回避できます。
URL は認証情報なしで解決できる必要があります。Router はサーバー側で取得し、リクエストに呼び出し元の認証情報を付与しません。そのため、署名がクエリ文字列に含まれる形式の署名付き URL がサポートされる形式です。`/api/assets/{id}/content` のような認証が必要なエンドポイントは Router に画像ではなく 401 を返します。その URL はご自身でリクエストし、リダイレクト先の署名付き URL を渡してください。
取得はオープンなインターネットではなく、名前を挙げたホスト群に限定されます。同じリストは、送信した URL だけでなくすべてのリダイレクトホップにも再適用されます。そのため、他のホスト上の URL、またはリスト外へリダイレクトする URL は、プロバイダーに接続される前に拒否されます。現時点でこのリストは Comfy 自身のアセット配信のみです。すなわち Comfy のアセットバケット配下の署名付き `storage.googleapis.com` URL で、これは `/api/assets/{id}/content` がリダイレクトする形式です。パートナー CDN や通常の https ホストはリストに含まれません。
2つの拡張が展開中で、どちらも現時点ではデフォルトで無効です。これらは1つの切り替えで提供され、同時に有効化されます。そのため以下はすべて、まだこれに依存して構築するものではなく、今後提供予定のものとして扱ってください。どちらかに依存する前に確認してください。
1つ目は `POST /customers/storage` がアップロード先として署名するバケットです。展開がお使いの環境に到達するまで、そのエンドポイントから得たアップロード URL はここで拒否されます。バケットは Comfy 自身のものでホストも同じであっても変わりません。したがって「Comfy にアップロードしてから URL を渡す」はまだ機能せず、機能するのは `/api/assets/{id}/content` がリダイレクトする署名付き URL の形式です。
2つ目は、以下のサードパーティのオブジェクトストレージホストを追加で許可します。バケットはお客様のものであり、Router はその所有権を主張しません: Cloudflare R2（`<account>.r2.cloudflarestorage.com`、`<id>.r2.dev`）、Amazon S3（`s3.amazonaws.com` および `s3.<region>.amazonaws.com`、パス形式または `<bucket>.` 接頭辞形式のいずれか）、Azure Blob Storage（`<account>.blob.core.windows.net`）、Alibaba Cloud OSS（`<bucket>.oss-<region>.aliyuncs.com`、`oss-accelerate` エンドポイントを含む）。これらは特にオブジェクトストレージのエンドポイントです。同じプロバイダードメイン上の汎用エンドポイント、たとえば Alibaba Function Compute のトリガーはリストに含まれず、拒否されます。
以下の例は形状のみを示しています。実際の値には署名のクエリパラメータも含まれますが、公開された例は仕様に永遠に残り、実際の署名は漏えいした認証情報であると同時に機能しなくなるリンクでもあるため、ここでは意図的に省略しています。
各画像は 25 MiB、1つのリクエストの画像は合計 64 MiB に制限されます。
