## 提供プロバイダー

このモデルは、リクエストで別のプロバイダーを指定しない限り、Comfy Router が直接提供します。以下のプロバイダーも、同じエンドポイント、同じモデル ID でこのモデルを提供しており、`model_provider` クエリパラメータで選択します。

- **Comfy**（デフォルト）: `POST https://api.comfy.org/v2/models/openai/gpt-image-2.5-flare`
- **fal**、`fal/fal-gpt-image-2.5-flare` として: `POST https://api.comfy.org/v2/models/openai/gpt-image-2.5-flare?model_provider=fal`
- **Runware**、`runware/runware-gpt-image-2.5-flare` として: `POST https://api.comfy.org/v2/models/openai/gpt-image-2.5-flare?model_provider=runware`

`strict_mode` のデフォルトは false であるため、Router はこのページに記載されているネイティブなリクエストボディをプロバイダー独自のスキーマに変換し、レスポンスを元の形式に変換し直します。API リファレンスの [`model_provider`、`strict_mode`、`fallback_provider`](/ja/development/comfy-router/reference#post-v2modelsprovidermodel) を参照し、この方法でルーティングされるすべてのモデルについては[提供プロバイダー](/ja/development/comfy-router/providers)を参照してください。

<ParamField body="image" type="string | string[]">
  編集するソース画像。このフィールドの有無が編集操作を選択します。テキストから画像への生成では完全に省略してください。
モデルが公開している例は生成の呼び出しで、このフィールドを省略しています。`image` を追加することが 2 つのモードの違いのすべてです。エンドポイントもモデル ID も同じですが、編集用のプロンプトはシーンではなく加えたい変更を記述するため、構造上新しく追加されるフィールドがこれだけであるにもかかわらず、以下に示す編集用のボディは生成の例とは読み方が異なります。
これは記載どおりにそのままコピーできます: `{"prompt": "give the rocketship rainbow coloring", "image": ["data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="], "size": "1024x1024"}`。ペイロードは省略表記ではなく完全な 1x1 PNG であり、このボディは Router 自身のリクエスト検証テストで受理されるケースとしてピン留めされています。ご自身の画像のバイト列に差し替えてください。
1 枚の画像またはその配列を受け付けます。gpt-image-1 以降は最大 16 枚で、Router はディスパッチ前にこのスキーマに基づいてそれを強制します。
</ParamField>

<ParamField body="mask" type="string">
  画像 1 枚。呼び出し元に代わって Router が取得する https URL、またはバイト列をインラインで含む `data:image/<format>;base64,<payload>` URI のいずれかの形式です。受け入れられる画像形式は png、webp、jpeg で、この組み合わせはプロバイダーに任されるのではなく解決時に強制されます。svg、gif、avif、tiff はここで拒否され、送信した画像が名指しされます。原因から 2 ホップ離れた場所でパートナーのエラーになることはありません。
URL 形式を推奨します。base64 ペイロードはおよそ 4/3 に膨らみ、リクエストボディ全体は 100 MiB が上限であるため、インライン形式ではソース画像が約 75 MB で上限に達します。URL ならこれを完全に回避できます。この説明の最後に記載する画像ごとおよびリクエストごとのメディア上限はボディの上限よりも厳しいため、実際のサイズの画像では、先に到達するのはこちらです。
URL はあなたの認証情報なしで解決できる必要があります。Router はサーバー側で取得し、リクエストに呼び出し元の認証情報を付与しません。したがって、署名がクエリ文字列に含まれる形式の署名付き URL がサポートされる形式です。`/api/assets/{id}/content` のような認証が必要なエンドポイントは、画像ではなく 401 を Router に返します。その URL はご自身でリクエストし、リダイレクト先の署名付き URL を渡してください。
取得先はオープンなインターネットではなく、名前を挙げたホストの集合に限定されており、同じリストが、送信する URL だけでなくすべてのリダイレクト先にも適用されます。そのため、それ以外のホストの URL や、リスト外へリダイレクトする URL は、どのプロバイダーにも接続する前に拒否されます。現在このリストは Comfy 自身のアセット配信のみです。Comfy のアセットバケット配下の署名付き `storage.googleapis.com` URL で、これは `/api/assets/{id}/content` がリダイレクトする形式です。パートナーの CDN や通常の https ホストはリストに含まれません。
2 つの拡張が展開中で、どちらも現在は既定で無効です。それらは 1 つの切り替えの背後で提供され、まとめて有効になります。したがって、以下はまだ構築対象とするものではなく、今後提供されるものとして扱ってください。どちらかに依存する前に確認してください。
1 つ目は、`POST /customers/storage` がアップロード先として署名するバケットです。展開があなたの環境に到達するまで、そのエンドポイントからのアップロード URL はここで拒否されます。バケットは Comfy 自身のものでホストも同じであるにもかかわらずです。そのため「Comfy にアップロードしてから URL を渡す」はまだ機能せず、機能する形式は `/api/assets/{id}/content` がリダイレクトする署名付き URL です。
2 つ目は全員に一斉ではなくアカウントごとに有効になります。これらのホストの背後にあるバケットは当社のものではなくあなたのものだからです。上記の切り替えがオンになっていても、サードパーティのインバウンドメディアが有効化されていないアカウントは拒否され、ホストが未サポートであるとは告げられず、その旨の文言で通知されます。ご自身のアカウントで有効化するよう Comfy の担当者にご依頼ください。さらに、バケットがあなたのもので Router が所有権を主張しない、以下のサードパーティのオブジェクトストレージホストを許可します: Cloudflare R2 (`<account>.r2.cloudflarestorage.com`、`<id>.r2.dev`)、Amazon S3 (`s3.amazonaws.com` および `s3.<region>.amazonaws.com`、パス形式または `<bucket>.` を先頭に付ける形式のいずれか)、Azure Blob Storage (`<account>.blob.core.windows.net`)、Alibaba Cloud OSS (`<bucket>.oss-<region>.aliyuncs.com`、`oss-accelerate` エンドポイントを含む)。これらは特にオブジェクトストレージのエンドポイントです。同じプロバイダードメイン上の汎用エンドポイント、たとえば Alibaba Function Compute のトリガーはリストに含まれず、拒否されます。
以下の例は形状のみを示しています。実際の値は署名のクエリパラメータも伴いますが、ここでは意図的に省略しています。公開された例は仕様の中に永遠に残り、実際の署名は漏えいした認証情報であると同時に、いずれ機能しなくなるリンクでもあるためです。
各画像は 25 MiB、1 つのリクエストの画像は合計 64 MiB が上限です。
