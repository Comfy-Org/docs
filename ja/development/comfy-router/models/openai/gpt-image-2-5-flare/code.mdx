### 入力

<ParamField body="background" type="string">

<ParamField body="image" type="string | string[]">
  編集するソース画像。このフィールドが存在すると編集操作が選択されます。テキストから画像への生成では完全に省略してください。
モデルが公開している例は、このフィールドを省略した生成呼び出しです。`image` を追加することが 2 つのモードの違いのすべてです。同じエンドポイント、同じモデル id です。ただし編集プロンプトはシーンではなく、望む変更を記述するため、以下に示す編集ボディは、構造上新しいのがこのフィールドだけであるにもかかわらず、生成の例とは異なる読み方になります。
掲載どおりにそのままコピーできます: `{"prompt": "give the rocketship rainbow coloring", "image": ["data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="], "size": "1024x1024"}`。ペイロードは省略形ではなく完全な 1x1 PNG であり、このボディは Router 自身のリクエスト検証テストで受け入れられるケースとしてピン留めされています。ご自身の画像のバイト列に差し替えてください。
1 枚の画像またはその配列を受け付けます。gpt-image-1 以降は最大 16 枚で、Router はディスパッチ前にこのスキーマに基づいてそれを強制します。
</ParamField>

<ParamField body="mask" type="string">
  1 枚の画像で、呼び出し元に代わって Router が取得する https URL、またはバイト列をインラインで含む `data:image/<format>;base64,<payload>` URI のいずれかです。受け付けられる画像タイプは png、webp、jpeg で、このセットはプロバイダーに任されるのではなく解決時に強制されます。svg、gif、avif、tiff はここで拒否され、送信した画像を名指しします。原因から 2 ホップ離れたパートナーエラーになることはありません。
URL 形式を推奨します。base64 ペイロードは約 4/3 に膨張し、リクエストボディ全体は 20 MiB に制限されるため、インライン形式ではソース画像がおよそ 15 MB で上限に達します。URL ならこれを完全に回避できます。
URL は認証情報なしで解決できなければなりません。Router はサーバー側で取得し、リクエストに呼び出し元の認証情報を付けません。そのため、署名がクエリ文字列にある署名付き URL がサポートされる形式です。`/api/assets/{id}/content` のような認証が必要なエンドポイントは、画像ではなく Router に 401 を返します。その URL をご自身でリクエストし、リダイレクト先の署名付き URL を渡してください。
取得はオープンなインターネットではなく、名前付きのホスト群に限定されます。また同じリストは、送信する URL だけでなく、すべてのリダイレクトホップにも再適用されます。したがって、それ以外のホストの URL、またはリスト外へリダイレクトする URL は、プロバイダーに連絡する前に拒否されます。現在このリストは Comfy 自身のアセット配信のみです。Comfy のアセットバケット配下の署名付き `storage.googleapis.com` URL で、これが `/api/assets/{id}/content` がリダイレクトする形式です。パートナー CDN や通常の https ホストはリストにありません。
2 つの拡張が展開中で、どちらも本日時点ではデフォルトで無効です。これらは 1 つの切り替えの背後で提供され、同時に有効になります。そのため、以下はすべてまだ構築対象ではなく、今後提供されるものとして扱ってください。どちらかに依存する前に確認してください。
1 つ目は `POST /customers/storage` がアップロード先として署名するバケットです。展開がお使いの環境に届くまで、そのエンドポイントからのアップロード URL はここで拒否されます。バケットは Comfy 自身のものでホストも同じであるにもかかわらずです。したがって「Comfy にアップロードして URL を渡す」はまだ機能せず、機能する形式は署名付き URL `/api/assets/{id}/content` がリダイレクトする先です。
2 つ目はさらに、次のサードパーティのオブジェクトストレージホストを許可します。バケットはお客様のものであり、Router はその所有権を主張しません。Cloudflare R2 (`<account>.r2.cloudflarestorage.com`、`<id>.r2.dev`)、Amazon S3（`s3.amazonaws.com` および `s3.<region>.amazonaws.com`、パス形式または `<bucket>.` プレフィックス形式のいずれか）、Azure Blob Storage (`<account>.blob.core.windows.net`)、Alibaba Cloud OSS (`<bucket>.oss-<region>.aliyuncs.com`、`oss-accelerate` エンドポイントを含む)。これらは特にオブジェクトストレージのエンドポイントです。同じプロバイダードメイン上の汎用エンドポイント、たとえば Alibaba Function Compute のトリガーは、リストになく拒否されます。
以下の例は形状のみを示しています。実際の値は署名クエリパラメータも含みますが、ここでは意図的に省略しています。公開された例は仕様に永遠に残り、実際の署名は漏洩した認証情報であると同時に機能しなくなるリンクだからです。
各画像は 25 MiB、1 リクエストの画像は合計 64 MiB に制限されます。
