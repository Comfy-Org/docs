<ParamField body="image" type="string | string[]">
  編集するソース画像。このフィールドの有無が編集操作を選択します。テキストから画像への生成では完全に省略してください。
モデルの公開されている例は GENERATION 呼び出しで、このフィールドを省略しています。`image` を追加することが2つのモードの違いのすべてです（エンドポイントもモデル ID も同じ）。ただし編集プロンプトはシーンではなく望む変更を記述するため、以下に示す編集ボディは、構造的に新しいのはこのフィールドだけであるにもかかわらず、生成の例とは異なる見え方になります。
これは記載されたままコピーできます: `{"prompt": "give the rocketship rainbow coloring", "image": ["data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="], "size": "1024x1024"}`。このペイロードは省略形ではなく完全な 1x1 PNG であり、このボディは Router 自身のリクエスト検証テストで受理されるケースとしてピン留めされています。ご自身の画像のバイト列に差し替えてください。
1枚の画像またはその配列を受け付けます。gpt-image-1 以降は最大 16 枚で、Router はディスパッチ前にこのスキーマに基づいてそれを強制します。
</ParamField>

<ParamField body="mask" type="string">
  1枚の画像で、呼び出し元に代わって Router が取得する https URL、またはバイト列をインラインで含む `data:image/<format>;base64,<payload>` URI のいずれかの形式です。受け付けられる画像タイプは png、webp、jpeg で、このセットはプロバイダーに任されるのではなく解決時に強制されます。svg、gif、avif、tiff はここで拒否され、送信した画像を名指しします。原因から2ホップ離れたパートナーのエラーになってしまうことはありません。
URL 形式を推奨します。base64 ペイロードは約 4/3 に膨らみ、リクエストボディ全体は 100 MiB が上限なので、インライン形式ではソース画像が約 75 MB で頭打ちになります。URL ならこれを完全に回避できます。この説明の最後に示す画像単位およびリクエスト単位のメディア上限はボディの上限より厳しいため、実用的なサイズの画像ではまずそちらに当たることになります。
URL は認証情報なしで解決できなければなりません。Router はサーバー側で取得し、リクエストに呼び出し元の認証情報を付けません。そのため、署名がクエリ文字列に入っている形式の署名付き URL がサポートされる形式です。`/api/assets/{id}/content` のような認証が必要なエンドポイントは、画像ではなく Router に 401 を返します。その URL はご自身でリクエストし、リダイレクト先の署名付き URL を渡してください。
取得は開かれたインターネットではなく、名前を挙げた一連のホストに限定されます。同じリストは、送信する URL だけでなくすべてのリダイレクト先にも再適用されます。そのため、他のホストの URL や、リスト外へリダイレクトする URL は、プロバイダーに接触する前に拒否されます。現在このリストには Comfy 自身のアセット配信のみが含まれます。Comfy のアセットバケット配下の署名付き `storage.googleapis.com` URL で、`/api/assets/{id}/content` がリダイレクトする形式です。パートナーの CDN や通常の https ホストはリストにありません。
2つの拡張が展開中で、どちらも現時点ではデフォルトで無効です。1つの切り替えの背後で提供され、同時に有効化されます。そのため以下はすべて今後の予定として扱い、まだそれに依存して開発しないでください。どちらかに依存する前に確認してください。
1つ目は `POST /customers/storage` がアップロード先として署名するバケットです。展開があなたの環境に届くまで、そのエンドポイントから得たアップロード URL はここで拒否されます。バケットが Comfy 自身のものでホストも同じであっても同様です。つまり「Comfy にアップロードしてから URL を渡す」はまだ機能せず、機能するのは `/api/assets/{id}/content` がリダイレクトする署名付き URL の形式です。
2つ目は全員に一度にではなくアカウント単位で有効化されます。これらのホストの背後にあるバケットは当社のものではなくお客様のものだからです。上記の切り替えがオンになっても、サードパーティのインバウンドメディアが有効化されていないアカウントは拒否され、ホストがサポートされていないと伝えるのではなく、その旨をその言葉で伝えられます。Comfy の担当者に依頼して、あなたのアカウントで有効化してもらってください。さらに、以下のサードパーティのオブジェクトストレージホストも許可します。バケットはお客様のものであり、Router はその所有権を主張しません。Cloudflare R2 (`<account>.r2.cloudflarestorage.com`、`<id>.r2.dev`)、Amazon S3 (`s3.amazonaws.com` および `s3.<region>.amazonaws.com`、パス形式または `<bucket>.` プレフィックス付き形式のいずれか)、Azure Blob Storage (`<account>.blob.core.windows.net`)、Alibaba Cloud OSS (`<bucket>.oss-<region>.aliyuncs.com`、`oss-accelerate` エンドポイントを含む) です。これらは特にオブジェクトストレージのエンドポイントです。同じプロバイダードメイン上の汎用エンドポイント、たとえば Alibaba Function Compute のトリガーはリストになく拒否されます。
以下の例は形状のみを示しています。実際の値は署名クエリパラメータも持ちますが、ここでは意図的に省略しています。公開された例は仕様に永遠に残り、実際の署名は漏洩した認証情報であると同時に機能しなくなるリンクでもあるからです。
各画像は 25 MiB、1リクエストの画像は合計 64 MiB が上限です。
