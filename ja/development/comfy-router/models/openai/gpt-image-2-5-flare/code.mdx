## 提供プロバイダー

このモデルは、リクエストで別のプロバイダーを指定しない限り、Comfy Router が直接提供します。以下のプロバイダーも、同じエンドポイント、同じモデル ID でこのモデルを提供しており、`model_provider` クエリパラメータで選択します。

- **Comfy**（デフォルト）: `POST https://api.comfy.org/v2/models/openai/gpt-image-2.5-flare`
- **fal**、`fal/fal-gpt-image-2.5-flare` として: `POST https://api.comfy.org/v2/models/openai/gpt-image-2.5-flare?model_provider=fal`
- **Runware**、`runware/runware-gpt-image-2.5-flare` として: `POST https://api.comfy.org/v2/models/openai/gpt-image-2.5-flare?model_provider=runware`
- **WaveSpeed**、`wavespeed/wavespeed-gpt-image-2.5-flare` として: `POST https://api.comfy.org/v2/models/openai/gpt-image-2.5-flare?model_provider=wavespeed`

`strict_mode` のデフォルトは false であるため、Router はこのページに記載されているネイティブなリクエストボディをプロバイダー独自のスキーマに変換し、レスポンスを元の形式に変換し直します。API リファレンスの [`model_provider`、`strict_mode`、`fallback_provider`](/ja/development/comfy-router/reference#post-v2modelsprovidermodel) を参照し、この方法でルーティングされるすべてのモデルについては[提供プロバイダー](/ja/development/comfy-router/providers)を参照してください。

### 入力

<ParamField body="background" type="string">
  背景の透過性。`auto` を指定するとモデルが選択します。

  指定可能な値: `transparent`、`opaque`、`auto`

<ParamField body="image" type="string | string[]">
  編集対象のソース画像。このフィールドの有無が編集操作を選択します。テキストから画像への生成では完全に省略してください。
モデルの公開している例は、このフィールドを省略した生成呼び出しです。`image` を追加することが2つのモードの違いのすべてです（エンドポイントもモデル id も同じ）。ただし編集用のプロンプトはシーンではなく、変更したい内容を記述するため、構造的に新しいフィールドがこれだけであるにもかかわらず、以下に示す編集用のボディは生成の例とは異なって見えます。
記載どおりにそのままコピーできます: `{"prompt": "give the rocketship rainbow coloring", "image": ["data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="], "size": "1024x1024"}`。ペイロードは省略形ではなく完全な 1x1 PNG であり、このボディは Router 自身のリクエスト検証テストで受理されるケースとしてピン留めされています。ご自身の画像のバイト列に差し替えてください。
1枚の画像、またはその配列を受け付けます。gpt-image-1 以降は最大 16 枚を受け付け、Router はディスパッチ前にこのスキーマに基づいてそれを強制します。
</ParamField>

<ParamField body="mask" type="string">
  1枚の画像を、呼び出し元に代わって Router が取得する https URL、またはバイト列をインラインで含む `data:image/<format>;base64,<payload>` URI のいずれかで指定します。受け付ける画像形式は png、webp、jpeg で、このセットはプロバイダーに委ねられるのではなく解決時に強制されます。svg、gif、avif、tiff はここで拒否されます。その際、原因から2ホップ離れたパートナーエラーになるのではなく、送信した画像が示されます。
URL 形式を推奨します。base64 ペイロードは約 4/3 に膨らみ、リクエストボディ全体は 100 MiB が上限であるため、インライン形式ではソース画像が約 75 MB で上限に達します。URL ならこれを完全に回避できます。この説明の最後に記載する画像あたりおよびリクエストあたりのメディア上限はボディの上限より厳しいため、実際のサイズの画像ではまずそちらに達することになります。
URL は認証情報なしで解決できる必要があります。Router はサーバー側で取得し、リクエストに呼び出し元の認証情報を付けません。そのため、署名がクエリ文字列に含まれる形式の署名付き URL がサポートされる形式です。`/api/assets/{id}/content` のような認証付きエンドポイントは、画像ではなく 401 を Router に返します。その URL はご自身でリクエストし、リダイレクト先の署名付き URL を渡してください。
取得先はオープンなインターネットではなく、名前を挙げたホストのセットに限定されます。同じリストは、送信した URL だけでなくすべてのリダイレクトホップにも再適用されます。そのため、それ以外のホストの URL や、リストから外れる先へリダイレクトする URL は、どのプロバイダーにも接触する前に拒否されます。現在このリストには Comfy 自身のアセット配信のみが含まれます。Comfy のアセットバケット配下の署名付き `storage.googleapis.com` URL で、これが `/api/assets/{id}/content` のリダイレクト先の形式です。パートナー CDN や通常の https ホストはリストに含まれません。
2つの拡張が展開中で、どちらも現在は既定でオフです。これらは1つの切り替えの背後で提供され、まとめて有効になります。そのため、以下はすべて今後提供予定のものとして扱い、まだ依存して実装する対象にはしないでください。どちらかに依存する前に問い合わせてください。
1つ目は、`POST /customers/storage` がアップロード先として署名するバケットです。この展開がお使いの環境に届くまで、そのエンドポイントから得られるアップロード URL はここで拒否されます。バケットは Comfy 自身のものでホストも同じであっても変わりません。つまり「Comfy にアップロードしてから URL を渡す」はまだ機能せず、機能するのは `/api/assets/{id}/content` のリダイレクト先である署名付き URL の形式です。
2つ目は、全員に一斉ではなくアカウント単位で有効化されます。これらのホストの背後にあるバケットが当社ではなくお客様のものであるためです。上記の切り替えがオンになっていても、サードパーティの受信メディアが有効化されていないアカウントは拒否され、ホストが未サポートであるとは言われず、その旨をそのまま伝えられます。お使いのアカウントで有効化するよう Comfy の担当者に依頼してください。さらに、以下のサードパーティのオブジェクトストレージホストが追加で許可されます。これらのバケットはお客様のものであり、Router はその所有権を主張しません: Cloudflare R2（`<account>.r2.cloudflarestorage.com`、`<id>.r2.dev`）、Amazon S3（`s3.amazonaws.com` および `s3.<region>.amazonaws.com`、パス形式または `<bucket>.` プレフィックス形式のいずれか）、Azure Blob Storage（`<account>.blob.core.windows.net`）、Alibaba Cloud OSS（`<bucket>.oss-<region>.aliyuncs.com`、`oss-accelerate` エンドポイントを含む）。これらは特にオブジェクトストレージのエンドポイントです。同じプロバイダードメイン上の汎用エンドポイント、たとえば Alibaba Function Compute のトリガーはリストに含まれず、拒否されます。
以下の例は形状のみを示しています。実際の値には署名のクエリパラメータも含まれますが、公開された例は仕様に永遠に残るものであり、実際の署名は漏えいした認証情報であると同時に機能しなくなるリンクでもあるため、ここでは意図的に省略しています。
各画像は 25 MiB、1回のリクエストの画像は合計 64 MiB が上限です。
