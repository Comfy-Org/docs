<ResponseField name="content.upstream_expires_at" type="string (date-time)">
  上流URLが機能しなくなるRFC 3339時刻です。URL自体が持つ最も早い署名時刻と有効期間を足したもので、`updated_at` が存在する場合はタスクの `updated_at` に24時間（BytePlusがドキュメント化しているURLの寿命）を加えた時刻より遅くなることはなく、存在しない場合もタスクの `updated_at` に24時間を加えた時刻です。`upstream_video_url` または `upstream_last_frame_url` が存在する場合にのみ含まれ、どちらのソースも時刻を提供しない場合は省略されます。再ホストされた `video_url` / `last_frame_url` の有効期間とは無関係です。

  形式: `date-time`
</ResponseField>

<ResponseField name="content.upstream_last_frame_url" type="string">
  最終フレームのBytePlus自身のダウンロードURLです。再ホストされた `last_frame_url` の隣にバイト単位でそのまま返され、`upstream_video_url` と同じ条件に従います。すなわち、オプトインしたワークスペースのみ、Seedance 2.xのみ、BytePlusがクリアすると欠落し、`upstream_expires_at` まではベアラ資格情報です。
</ResponseField>

<ResponseField name="content.upstream_video_url" type="string">
  出力ビデオのBytePlus自身のダウンロードURLで、再ホストされた `video_url` の隣にバイト単位でそのまま返されます。Comfyがサーバー側でオプトインしたワークスペースがポーリングするSeedance 2.xのタスクでのみ存在します（リクエストパラメータはありません）。それ以外の場合は存在せず、ワークスペースに解決されない資格情報（特定のワークスペースにスコープされていないレガシーAPIキーなど）も同様です。また、BytePlusが生成の24時間後にURLをクリアすると存在しなくなります。これは署名済みのオブジェクトストレージURLであり、したがってベアラ資格情報です。保持している人は誰でも有効期限までビデオをダウンロードできるため、シークレットとして扱ってください。`upstream_expires_at` で期限切れになり、Seedance 2.5ではBytePlusがダウンロード回数を100回に制限しており、そのうち1回はRouter自身の再ホストが消費します。
</ResponseField>

<ResponseField name="content.video_url" type="string">
  出力ビデオのダウンロードURLです。RouterはビデオをComfyのストレージに再ホストしてこのフィールドを書き換えるため、通常は最大24時間有効なComfy署名付きURLになります。発行時に24時間で署名され、23時間のメモから再生されるため、後でのポーリングでは残り1時間しかないURLが返ることがあります。再ホストを実行できなかった場合、このフィールドはBytePlus自身のURLを保持し、BytePlusはタスクの24時間後にそれをクリアし、一部のモデルではダウンロード回数を100回に制限します。いずれの場合もリンクは期限切れになるため、URLを保存するのではなくビデオをダウンロードしてください。
</ResponseField>

<ResponseField name="created_at" type="integer">
  タスクが作成された時刻です。値は秒単位のUNIXタイムスタンプです。
</ResponseField>

<ResponseField name="duration" type="number">
  生成されたビデオの再生時間（秒）です。BytePlusがこの点で一貫していないため、整数ではなく数値として宣言されています。ビデオタスクが整数秒を返す例が確認されており、同系列のBytePlusの各サーフェスは小数の再生時間を報告するため、クライアントは整数値を前提にしてはいけません。BytePlus自身のフィールドで、成功したビデオタスクで返され、そのまま転送されます。
</ResponseField>

<ResponseField name="error" type="object">
  エラー情報です。タスクが成功した場合はnullが返されます。タスクが失敗した場合はエラー情報が返されます。
</ResponseField>

<ResponseField name="error.code" type="string">
  上流のModelArkエラーコードです。SensitiveContentDetected、InputTextSensitiveContentDetected、InputImageSensitiveContentDetected、InputVideoSensitiveContentDetected、InputAudioSensitiveContentDetected、OutputTextSensitiveContentDetected、OutputImageSensitiveContentDetected、OutputVideoSensitiveContentDetected、OutputAudioSensitiveContentDetected はコンテンツポリシーによる拒否を識別します。ファミリーにはドット区切りの理由が付くことがあり、例えば InputImageSensitiveContentDetected.PrivacyInformation、OutputVideoSensitiveContentDetected.PolicyViolation、OutputImageSensitiveContentDetected.DeepFake などです。これは列挙型ではなくオープンな文字列です。他のコードは検証やプロバイダーの失敗を表します。RouterはHTTP 400のエラーエンベロープとHTTP 200の失敗タスク応答でポリシーファミリーを認識しますが、トランスポートの失敗を上書きすることはありません。
</ResponseField>

<ResponseField name="error.message" type="string">
  エラーメッセージ
</ResponseField>

<ResponseField name="id" type="string">The ID of the video generation task
</ResponseField>

<ResponseField name="model" type="string">
  タスクで使用されたモデルの名前とバージョン
</ResponseField>

<ResponseField name="output_format" type="string">
  生成されたビデオのコンテナ形式（mp4 または mov）。`content` の兄弟としてトップレベルで返されます。Seedance のビデオタスククエリはここでこれを返します。BytePlus 独自のフィールドであり、そのまま転送されます。
</ResponseField>

<ResponseField name="resolution" type="string">
  生成されたビデオの解像度（例: `1080p`）。BytePlus 独自のフィールドであり、成功したビデオタスクで返され、そのまま転送されます。
</ResponseField>

<ResponseField name="seed" type="integer">
  タスクで実際に使用された生成シード。BytePlus 独自のフィールドであり、成功したビデオタスクで返され、そのまま転送されます。

  形式: `int64`
</ResponseField>

<ResponseField name="status" type="string">
  タスクの状態

  取り得る値: `queued`, `running`, `cancelled`, `succeeded`, `failed`, `expired`
</ResponseField>

<ResponseField name="updated_at" type="integer">
  タスクが最後に更新された時間。値は UNIX タイムスタンプ（秒）です。
</ResponseField>

<ResponseField name="usage" type="object">
  リクエストのトークン使用量
</ResponseField>

<ResponseField name="usage.completion_tokens" type="integer">
  モデルによって生成されたトークン数
</ResponseField>

<ResponseField name="usage.total_tokens" type="integer">
  ビデオ生成モデルでは、入力トークン数は計算されず、0 がデフォルトです。したがって、total_tokens = completion_tokens となります。
</ResponseField>
