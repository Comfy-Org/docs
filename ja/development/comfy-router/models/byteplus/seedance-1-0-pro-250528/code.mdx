### 出力

<ResponseField name="content" type="object">
  ビデオ生成タスクの完了後の出力です。出力ビデオのダウンロード URL に加え、BytePlus が返す場合はその最終フレームのダウンロード URL を含みます。`video_url` と `last_frame_url` はどちらも Comfy のストレージへ再ホストされ、ここにある他のフィールドはすべて BytePlus 自身のものです。null を許容します。BytePlus はタスクの 24 時間後に URL をクリアするため、その後でポーリングした成功済みドキュメントでは `content` が存在しないか null になることがあります。
</ResponseField>

<ResponseField name="content.last_frame_url" type="string">
  生成されたビデオの最終フレームのダウンロード URL で、リクエストで `return_last_frame` を指定した場合に返されます。この URL から画像形式を推測しないでください。BytePlus はリクエスト側では最終フレームを PNG として記載していますが、Router は提供されたバイト列をそのまま再ホストし、上流の Content-Type またはコンテンツスニッフィングに基づいて型を判定します。`image/jpeg` はそのどちらも失敗した場合の最後のフォールバックにすぎません。Router は最終フレームを Comfy のストレージへ再ホストしてこのフィールドを書き換えるため、通常は最大 24 時間有効な Comfy が署名した URL になります。発行時に 24 時間で署名され、23 時間のメモから再利用されるため、後からのポーリングでは残り 1 時間程度の URL が返ることがあります。再ホストを実行できなかった場合は、代わりに BytePlus 自身の URL がこのフィールドに残りますが、BytePlus はタスクの 24 時間後にそれをクリアします。いずれの場合もリンクは失効するため、URL を保存するのではなくフレームをダウンロードしてください。
</ResponseField>

</ResponseField>

<ResponseField name="content.upstream_expires_at" type="string (date-time)">
  上流の URL が機能しなくなる RFC 3339 形式の時刻です。URL 自体が持つ最も早い署名時刻に有効期間を加えたものですが、`updated_at` が存在する場合はタスクの `updated_at` に 24 時間（BytePlus が文書化している URL の寿命）を加えた時刻より後になることはなく、存在しない場合はタスクの `updated_at` に 24 時間を加えた時刻になります。`upstream_video_url` または `upstream_last_frame_url` が存在する場合にのみ含まれ、どちらのソースも時刻を提供しない場合は省略されます。再ホストされた `video_url` / `last_frame_url` の寿命とは関係ありません。

  形式: `date-time`
</ResponseField>

<ResponseField name="content.upstream_last_frame_url" type="string">
  最終フレームについての BytePlus 自身のダウンロード URL で、再ホストされた `last_frame_url` の隣にそのままのバイト列で返されます。条件は `upstream_video_url` と同じです。すなわち、オプトインしたワークスペースのみ、Seedance 2.x のみであり、BytePlus がクリアした後は存在せず、`upstream_expires_at` まではベアラー資格情報として扱われます。
</ResponseField>

<ResponseField name="content.upstream_video_url" type="string">
  出力ビデオについての BytePlus 自身のダウンロード URL で、再ホストされた `video_url` の隣にそのままのバイト列で返されます。Comfy がサーバー側でオプトインしたワークスペースによるポーリングの Seedance 2.x タスクにのみ含まれます（リクエストパラメーターはありません）。それ以外の場合は含まれず、ワークスペースに解決されない資格情報（特定のワークスペースに紐付かないレガシーな API キーなど）も同様です。また、生成の 24 時間後に BytePlus が URL をクリアすると存在しなくなります。これは署名付きのオブジェクトストレージ URL、つまりベアラー資格情報であるため、これを保持する誰もが失効までビデオをダウンロードできます。秘密情報と同様に扱ってください。`upstream_expires_at` で失効し、Seedance 2.5 では BytePlus がダウンロード回数を 100 回に制限しており、そのうち 1 回は Router 自身の再ホストが消費します。
</ResponseField>

<ResponseField name="content.video_url" type="string">
  出力ビデオのダウンロード URL です。Router はビデオを Comfy のストレージへ再ホストしてこのフィールドを書き換えるため、通常は最大 24 時間有効な Comfy が署名した URL になります。発行時に 24 時間で署名され、23 時間のメモから再利用されるため、後からのポーリングでは残り 1 時間程度の URL が返ることがあります。再ホストを実行できなかった場合は、代わりに BytePlus 自身の URL がこのフィールドに残りますが、BytePlus はタスクの 24 時間後にそれをクリアし、一部のモデルではダウンロード回数を 100 回に制限します。いずれの場合もリンクは失効するため、URL を保存するのではなくビデオをダウンロードしてください。
</ResponseField>

<ResponseField name="created_at" type="integer">
  タスクが作成された日時です。値は秒単位の UNIX タイムスタンプです。
</ResponseField>

<ResponseField name="duration" type="number">
  生成されたビデオの再生時間（秒）です。BytePlus がこの点で一貫していないため、整数ではなく数値として宣言されています。ビデオタスクが整数秒を返す例も確認されており、BytePlus の他のサーフェスでは小数の再生時間が報告されることもあるため、クライアントは整数値だと仮定してはいけません。BytePlus 自身のフィールドで、成功したビデオタスクで返され、そのまま転送されます。
</ResponseField>

<ResponseField name="error" type="object">
  エラー情報です。タスクが成功した場合は null が返されます。タスクが失敗した場合はエラー情報が返されます。
</ResponseField>

<ResponseField name="error.code" type="string">
  上流の ModelArk エラーコードです。SensitiveContentDetected、InputTextSensitiveContentDetected、InputImageSensitiveContentDetected、InputVideoSensitiveContentDetected、InputAudioSensitiveContentDetected、OutputTextSensitiveContentDetected、OutputImageSensitiveContentDetected、OutputVideoSensitiveContentDetected、OutputAudioSensitiveContentDetected はコンテンツポリシーによる拒否を示します。ファミリーにはドット区切りの理由が付くことがあり、例えば InputImageSensitiveContentDetected.PrivacyInformation、OutputVideoSensitiveContentDetected.PolicyViolation、OutputImageSensitiveContentDetected.DeepFake などがあります。これは enum ではなくオープンな文字列であり、他のコードは検証やプロバイダーの失敗を表します。Router は HTTP 400 のエラーエンベロープと HTTP 200 の失敗タスク応答の両方でポリシーファミリーを認識しますが、トランスポートの失敗を上書きすることはありません。
</ResponseField>

<ResponseField name="error.message" type="string">
  エラーメッセージ
</ResponseField>

<ResponseField name="id" type="string">
  動画生成タスクの ID
</ResponseField>

<ResponseField name="model" type="string">
  タスクで使用されたモデルの名前とバージョン
</ResponseField>

<ResponseField name="output_format" type="string">
  生成されたビデオのコンテナ形式（mp4 または mov）。`content` の兄弟としてトップレベルで返されます。Seedance のビデオタスククエリはここでこの値を返します。BytePlus 独自のフィールドで、変更されずにそのまま転送されます。
</ResponseField>

<ResponseField name="resolution" type="string">
  生成されたビデオの解像度（例: `1080p`）。BytePlus 独自のフィールドで、成功したビデオタスクで返され、変更されずにそのまま転送されます。
</ResponseField>

<ResponseField name="seed" type="integer">
  タスクで実際に使用された生成シード。BytePlus 独自のフィールドで、成功したビデオタスクで返され、変更されずにそのまま転送されます。

  形式: `int64`
</ResponseField>

<ResponseField name="status" type="string">
  タスクの状態

  取りうる値: `queued`, `running`, `cancelled`, `succeeded`, `failed`, `expired`
</ResponseField>

<ResponseField name="updated_at" type="integer">
  タスクが最後に更新された時間。この値は秒単位の UNIX タイムスタンプです。
</ResponseField>

<ResponseField name="usage" type="object">
  リクエストのトークン使用量
</ResponseField>

<ResponseField name="usage.completion_tokens" type="integer">
  モデルによって生成されたトークン数
</ResponseField>

<ResponseField name="usage.total_tokens" type="integer">
  ビデオ生成モデルでは入力トークン数は計算されず、0 が既定値です。そのため、total_tokens = completion_tokens となります。
</ResponseField>
