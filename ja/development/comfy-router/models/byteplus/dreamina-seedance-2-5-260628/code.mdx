  生成されたビデオの最終フレームのダウンロードURLで、リクエストで `return_last_frame` を設定した場合に返されます。この URL から画像形式を推測しないでください。BytePlus はリクエスト側で最終フレームを PNG として文書化していますが、Router は提供されたバイト列をそのまま再ホストし、上流の Content-Type またはコンテンツスニッフィングから型を判定します。`image/jpeg` は両方が失敗した場合の最後のフォールバックにすぎません。Router は最終フレームを Comfy のストレージに再ホストしてこのフィールドを書き換えるため、通常は最大24時間有効な Comfy 署名付き URL になります。発行時に24時間で署名され、23時間のメモから再生されるため、後でポーリングすると残り1時間しかない URL が返ることがあります。再ホストを実行できなかった場合、このフィールドは BytePlus 自身の URL のままとなり、BytePlus がタスクの24時間後にそれをクリアします。いずれにせよリンクは失効するため、URL を保存するのではなくフレームをダウンロードしてください。
</ResponseField>

<ResponseField name="content.output_format" type="string">
  生成されたビデオのコンテナ形式（mp4 または mov）で、BytePlus が `content` の中にネストして返す場合のものです。Seedance モデルはこれを `content` のトップレベルの兄弟として返すことの方が多く、トップレベルの `output_format` フィールドを参照してください。Router は存在する方のフィールドを読み取ります。
</ResponseField>

<ResponseField name="content.upstream_expires_at" type="string (date-time)">
  上流の URL が機能しなくなる RFC 3339 の時刻です。URL 自体が持つ最も早い署名時刻に有効期間を加えた値で、`updated_at` が存在する場合はタスクの `updated_at` に24時間（BytePlus が文書化している URL の寿命）を加えた値を超えることはなく、存在しない場合はタスクの `updated_at` に24時間を加えた値です。`upstream_video_url` または `upstream_last_frame_url` が存在する場合にのみ存在し、どちらのソースからも時刻が得られない場合は省略されます。再ホストされた `video_url` / `last_frame_url` の寿命とは関係ありません。

  形式: `date-time`
</ResponseField>

<ResponseField name="content.upstream_last_frame_url" type="string">
  最終フレームの BytePlus 自身のダウンロードURLで、再ホストされた `last_frame_url` の隣に、`upstream_video_url` と同じ条件でバイト単位のまま返されます。オプトインしたワークスペースのみ、Seedance 2.x のみで、BytePlus がクリアすると存在せず、`upstream_expires_at` まではベアラ認証情報として扱われます。
</ResponseField>

<ResponseField name="content.upstream_video_url" type="string">
  出力ビデオの BytePlus 自身のダウンロードURLで、再ホストされた `video_url` の隣にバイト単位のまま返されます。サーバー側で Comfy がオプトインしたワークスペースがポーリングする Seedance 2.x タスクにのみ存在します（リクエストパラメータはありません）。それ以外のすべての場合、たとえばワークスペースに解決されない認証情報（特定のワークスペースにスコープされていないレガシー APIキーなど）には存在せず、BytePlus が生成の24時間後に URL をクリアすると存在しなくなります。これは署名済みのオブジェクトストレージ URL であり、したがってベアラ認証情報です。保持している人は誰でも有効期限までビデオをダウンロードできるため、シークレットと同様に扱ってください。`upstream_expires_at` に失効し、Seedance 2.5 では BytePlus がダウンロード回数を100回に制限しており、そのうち1回は Router 自身の再ホストが消費します。
</ResponseField>

<ResponseField name="content.video_url" type="string">
  出力ビデオのダウンロードURLです。Router はビデオを Comfy のストレージに再ホストしてこのフィールドを書き換えるため、通常は最大24時間有効な Comfy 署名付き URL になります。発行時に24時間で署名され、23時間のメモから再生されるため、後でポーリングすると残り1時間しかない URL が返ることがあります。再ホストを実行できなかった場合、このフィールドは BytePlus 自身の URL のままとなり、BytePlus がタスクの24時間後にそれをクリアし、一部のモデルではダウンロード回数が100回に制限されます。いずれにせよリンクは失効するため、URL を保存するのではなくビデオをダウンロードしてください。
</ResponseField>

<ResponseField name="created_at" type="integer">
  タスクが作成された時刻です。値は秒単位の UNIX タイムスタンプです。
</ResponseField>

<ResponseField name="duration" type="number">
  生成されたビデオの再生時間（秒）です。整数ではなく数値として宣言されているのは、BytePlus の扱いが一貫していないためです。ビデオタスクが整数の秒を返す一方で、同じ BytePlus の他のサーフェスでは小数の再生時間が報告されることが観測されているため、クライアントは整数値を前提にしてはいけません。BytePlus 自身のフィールドで、成功したビデオタスクで返され、変更されずにそのまま転送されます。
</ResponseField>

<ResponseField name="error" type="object">
  エラー情報です。タスクが成功した場合は null が返されます。タスクが失敗した場合はエラー情報が返されます。
</ResponseField>

<ResponseField name="error.code" type="string">
  上流の ModelArk エラーコードです。SensitiveContentDetected、InputTextSensitiveContentDetected、InputImageSensitiveContentDetected、InputVideoSensitiveContentDetected、InputAudioSensitiveContentDetected、OutputTextSensitiveContentDetected、OutputImageSensitiveContentDetected、OutputVideoSensitiveContentDetected、OutputAudioSensitiveContentDetected はコンテンツポリシーによる拒否を示します。ファミリーにはドット区切りの理由が付くことがあり、たとえば InputImageSensitiveContentDetected.PrivacyInformation、OutputVideoSensitiveContentDetected.PolicyViolation、OutputImageSensitiveContentDetected.DeepFake などです。これは enum ではなくオープンな文字列です。その他のコードは検証やプロバイダーの障害を表します。Router は HTTP 400 のエラーエンベロープおよび HTTP 200 の失敗タスク応答でポリシーファミリーを認識し、トランスポート障害を上書きすることはありません。
</ResponseField>

<ResponseField name="error.message" type="string">
  エラーメッセージ
</ResponseField>

<ResponseField name="id" type="string">
  動画生成タスクの ID
</ResponseField>

<ResponseField name="model" type="string">
  タスクで使用されたモデルの名前とバージョン
</ResponseField>

<ResponseField name="output_format" type="string">
  生成されたビデオのコンテナ形式 (mp4 または mov)。`content` の兄弟として最上位レベルで返されます。Seedance のビデオタスククエリはここでこれを返します。BytePlus 独自のフィールドで、変更されずにそのまま転送されます。
</ResponseField>

<ResponseField name="resolution" type="string">
  生成されたビデオの解像度 (例: `1080p`)。BytePlus 独自のフィールドで、成功したビデオタスクで返され、変更されずにそのまま転送されます。
</ResponseField>

<ResponseField name="seed" type="integer">
  タスクで実際に使用された生成シード。BytePlus 独自のフィールドで、成功したビデオタスクで返され、変更されずにそのまま転送されます。

  形式: `int64`
</ResponseField>

<ResponseField name="status" type="string">
  タスクの状態

  取り得る値: `queued`、`running`、`cancelled`、`succeeded`、`failed`、`expired`
</ResponseField>

<ResponseField name="updated_at" type="integer">
  タスクが最後に更新された時間。値は秒単位の UNIX タイムスタンプです。
</ResponseField>

<ResponseField name="usage" type="object">
  リクエストのトークン使用量
</ResponseField>

<ResponseField name="usage.completion_tokens" type="integer">
  モデルによって生成されたトークンの数
</ResponseField>

<ResponseField name="usage.total_tokens" type="integer">
  ビデオ生成モデルでは、入力トークンの数は計算されず、0 がデフォルトになります。したがって、total_tokens = completion_tokens となります。
</ResponseField>
