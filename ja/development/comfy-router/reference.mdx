モデル ID でアドレス指定される Comfy Router の正規ルート。

ベース URL: `https://api.comfy.org`

以下のすべてのエンドポイントは認証が必要です。`X-API-Key: <api-key>` または `Authorization: Bearer <jwt>` を送信してください。

Comfy API キーは Bearer トークンとして送信することもできます。両方の認証ヘッダーが指定された場合、`X-API-Key` が優先されます。キーと JWT の違いについては[認証ヘッダー](/ja/development/comfy-router/headers#リクエストヘッダー)を、アクセス要件については[クイックスタート](/ja/development/comfy-router/quickstart)を参照してください。

### `POST /v2/models/{provider}/{model}`

**正規のモデル ID を指定してパートナーモデルを同期的に実行します。**

モデルを実行し、完了した結果を同じレスポンスで受け取ります。

**パラメータ**

<ParamField path="provider" type="RouterProviderSegment" required>
  正規の `{provider}/{model}` モデル ID のプロバイダー部分。

  型: [`RouterProviderSegment`](#routerprovidersegment) -- 英数字スラッグ（例: `anthropic`）、最大 64 文字
</ParamField>

<ParamField path="model" type="RouterModelSegment" required>
  正規の `{provider}/{model}` モデル ID のモデル部分。

  型: [`RouterModelSegment`](#routermodelsegment) -- 英数字スラッグ（例: `claude-opus-4-6`）、最大 128 文字
</ParamField>

<ParamField header="Idempotency-Key" type="string">
  1 つの論理的な呼び出しを安全に再試行できるようにする、呼び出し側が生成するキー。

  1〜255 文字
</ParamField>

<ParamField query="model_provider" type="string">
  このモデルを提供する代替プロバイダーを、現在のデフォルトの代わりに選択します。代替プロバイダーは `fal`、`wavespeed`、`runware`、`higgsfield` で、`GET /v2/models/{provider}/{model}` は、あるモデルがそれらのどれをサポートしているかを報告します。拒否は固定の順序でチェックされ、先のものは、後のものが該当するかどうかに関係なく応答します。認識されない値（登録済みのプロバイダーですらないもの）は `400` で拒否されます。次に、ボディがマルチパート操作（編集）を選択しているリクエストで代替プロバイダーを指定すると、`detail` が "this request's `image` selects the edit operation" で始まる `409` で拒否されます。ただし、そのプロバイダーのこのモデル用トランスレーターがその操作を提供できない場合に限ります。トランスレーターがメディアを扱えるレッグは通常どおり処理されます。次に、bring-your-own-key 認証情報が解決されたリクエストでは、どの代替プロバイダーも `detail` が `this request resolved a BYOK credential` で始まる `409` で拒否されます（そのレスポンスを参照）。そのプロバイダーがこのモデルを提供しているかどうかは関係ありません。次に、指定されたプロバイダー自身のゲートがあり、そのプロバイダーがあなたに対して有効化されていない場合は `error_type: not_enabled` を伴う `403` で、ゲートを評価できない場合は `error_type: service_unavailable` を伴う `503` で拒否します。そして、これら 4 つすべてを通過した後にのみ、このモデル用のレッグを持たない実在のプロバイダーが `error_type: invalid_input` を伴う `400` で拒否されます。これは認識されない値と同じ応答です。`fallback_provider` は、bring-your-own-key のリクエスト、ボディがマルチパート操作を選択しているリクエスト、および `strict_mode=true` の下では、拒否されるのではなく無効です。
</ParamField>

<ParamField query="strict_mode" type="boolean">
  `model_provider` と併用した場合にのみ意味を持ちます。

  デフォルト: False
</ParamField>

<ParamField query="fallback_provider" type="string">
  最初の試行が Router に起因する理由、または試行したプロバイダーに起因する理由で失敗した場合に、Router がこの呼び出しをそのモデルの他の登録済みプロバイダーに対して再試行するかどうかを制御します。省略した場合、または `false` 以外の値はフォールバックを有効のままにします。`false` は無効にします。フォールバックが成功したレスポンスには `X-Comfy-Router-Fallback-Provider` が付与されます。bring-your-own-key 認証情報が解決されたリクエストでは、このパラメータの値に関係なくフォールバックは利用できません。試行は単に行われず、最初の失敗がそのまま返ります。これは拒否ではなく無効であり、ここから `409` が発生することはありません。同じ理由で、ボディがマルチパート操作を選択しているリクエストおよび `strict_mode=true` の下でも同様です。いずれも呼び出しを 1 つのプロバイダーに結び付けるもので、別のプロバイダーに対して忠実に再実行することはできないため、フォールバックは拒否されるのではなく単にスキップされます。その `409` で拒否されるのは明示的な `model_provider` だけであり、この無条件のスキップとは異なり、そのマルチパート `409` はトランスレーターがその操作を提供できないレッグにのみ適用されます。
</ParamField>

<ParamField query="reject_unknown_fields" type="boolean">
  このモデルの入力スキーマが宣言していないトップレベルのリクエストボディフィールドを、受け入れるのではなく拒否することを選択します。ネストされたフィールドはチェックされず、宣言されていないフィールドを許可するスキーマを持つモデル、または作成済みスキーマを持たないモデルでは何も拒否されません。また、`strict_mode=true` で送信されたキュー中の送信でも拒否されません。

  デフォルト: False
</ParamField>

**リクエストボディ**

`application/json` -- [`RouterModelInput`](#routermodelinput)（必須）パートナーモデルのネイティブ JSON 入力。`model_provider` がない場合、このボディはモデル自身のネイティブスキーマであり、モデル自身のプロバイダーが呼び出しを処理するときは呼び出し元の `strict_mode` は何も変えません。Comfy Router 自体がそのような呼び出しを別のプロバイダーへルーティングする場合、Router はそのプロバイダー向けにボディを変換しますが、そこで `strict_mode` がどのように適用されるかはこの契約の対象外です。`model_provider` が代替プロバイダーを選択し、`strict_mode=false`（デフォルト）の場合、ボディは送信前にそのプロバイダーの実際のスキーマへ変換されます。正確に表現できないネイティブフィールドは破棄され、レスポンスの `X-Comfy-Router-Dropped-Params` ヘッダーで開示されます。決して無言では行われません。`model_provider` が代替プロバイダーを選択し、`strict_mode=true` の場合は変換が実行されません。ボディはすでにその代替プロバイダー自身の実際のスキーマ（このモデルのネイティブなものではない）である必要があり（`strict_mode` を参照）、そのまま転送されます。ボディ自身のフィールドは、複数の操作をサポートするモデルで Router が実行する操作も選択します。編集可能な画像モデルの場合、入力画像を含めるとテキストから画像へから画像から画像へ（編集）操作に切り替わり、これは独自のレートで課金される場合があります。Seedance ビデオモデルの場合、`content[].role` が操作を選択します（最初のフレーム画像は画像から動画へ、参照画像またはクリップは参照から動画を選択します）。モデル自身のプロバイダーが呼び出しを処理する場合、Seedance の課金は役割ではなく `content` 内のメディア種別に従います。ビデオ入力があるリクエストは動画から動画へとして課金され、そうでなければ画像があるものは画像から動画へ、それ以外はテキストから動画へ課金されます。ただし `draft_task` アイテムからの最終レンダーは、それがレンダリングする Draft の操作として課金されます。一部のモデルはテキストから動画へと画像から動画へで同じレートを課金します。`model_provider` が代替プロバイダーを選択する場合、または Comfy Router が別のプロバイダーで呼び出しを処理する場合、conditioning を伴う各操作はそのプロバイダー独自のレートで課金される場合があります。

## エラーバケット

Router の機械可読なエラーカテゴリで、`X-Comfy-Error-Type` ヘッダーでも送信されます。

### リクエストレベルバケット

Router が受け付けたものの、完了できなかったリクエストに対して発生します。

| `error_type` | 意味 |
| --- | --- |
| `invalid_input` | リクエストがモデルに到達する前に拒否されました。ボディの形式が不正、ページネーションカーソルが不正または期限切れ、モデル自身のスキーマが受け付けない入力、またはこのリクエストに使用できない `Idempotency-Key`（別のリクエストで既に使用済み。方法、パスとクエリ、またはボディが異なる。もしくは、レスポンスを再生できない呼び出しによって既に消費済み）です。 |
| `content_policy_violation` | プロバイダーがコンテンツポリシーを理由にリクエストを拒否しました。 |
| `provider_error` | パートナープロバイダーが自身の障害を報告したか、Router が結果として解釈できないレスポンスを返しました。 |
| `provider_timeout` | パートナープロバイダーが期限までに応答しませんでした。 |
| `insufficient_credits` | 呼び出し元のワークスペースに、モデルを実行するための十分なクレジットがありません。 |
| `budget_exceeded` | ハード支出上限に達しました。 |
| `model_not_found` | `{provider}/{model}` という ID が、Router で実行できるモデルを指していません。不明なプロバイダー、未登録の ID、カタログが提供終了日を過ぎて廃止したモデル、またはプロバイダーが現在 Comfy 向けに提供していないカタログ登録済みの ID です。 |
| `byok_credential_rejected` | この呼び出しで指定されたキーがプロバイダーに拒否されました。 |

### トランスポートレベルバケット

モデルへの呼び出しの前またはその周辺で、Router 自身によって発生します。

| `error_type` | 意味 |
| --- | --- |
| `budget_check_unavailable` | ハード支出上限を確認できませんでした。 |
| `unauthorized` | リクエストに利用可能な認証情報が含まれていませんでした。 |
| `forbidden` | 認証情報は有効ですが、このモデルまたはこの操作に対する権限がありません。 |
| `concurrency_limit_exceeded` | ワークスペースはすでに許可された数の呼び出しを実行中です。いずれかが完了したら再試行してください。 |
| `client_disconnected` | 呼び出し側が、Router が結果を返す前に接続を閉じました。 |
| `internal_error` | Router 自体が失敗しました。 |
| `deadline_exceeded` | 回答が到着する前に、Comfy が自身の設定済みの上限で接続の維持を停止しました。 |
| `not_enabled` | この呼び出し側に対して Comfy Router がまだ有効になっていません。 |
| `service_unavailable` | Comfy Router が依存するサービスが一時的に利用できず、呼び出し側に問題はありません。 |
| `rate_limited` | 呼び出し側がウィンドウ単位で測定される割り当てを消費し、そのウィンドウが経過するのを待つ必要があります。または、モデルプロバイダーが生成を開始する前に呼び出しをスロットルしました。 |
| `cancelled` | キューに入っていたリクエストが、結果を生成する前に、キャンセルルートまたはオペレーターによって取り消されました。これは終端状態であり、それ自体は課金に関する表明ではありません。 |
| `queue_timeout` | キュー中のリクエストが、一度も受け入れられることなくキュータイムアウトを超えて待機し続けました。 |
| `request_not_found` | `request_id` が、このモデルにおける呼び出し元のどのリクエストも指していません。 |
| `queue_backlog_full` | 呼び出し元が既に実行待ちのキュー中リクエストを抱えすぎているため、この送信は拒否されました。 |
| `result_expired` | リクエストは存在し、完了していましたが、その結果はもう保存されていないため、collect に返すものがありません。 |

<ResponseField name="X-Comfy-Estimated-Duration-P90-Seconds" type="integer">

<ResponseField name="X-Comfy-Estimated-Duration-Seconds" type="integer">

  この呼び出しに対するサーバー生成の識別子で、Router のすべてのレスポンス（成功、4xx、5xx のいずれも）に含まれます。エラーレスポンスこそ、ユーザーがサポート依頼で引用する ID を必要とするまさにその場面だからです。
</ResponseField>

</ResponseField>

<ResponseField name="X-Comfy-Router-Provider" type="string">

</ResponseField>

<ResponseField name="X-Committed-Spend-Remaining" type="integer">

## 事前のコスト見積もり

`POST /v2/models/{provider}/{model}/estimate` は、実行せずにボディの料金を見積もります。また、キューに投入される送信（`POST /v2/models/{provider}/{model}/requests`）は、その `201` で `estimate` と同じ [`RouterCostEstimate`](#routercostestimate) を返します。どちらも Comfy の標準リスト価格で価格設定されます。ただし、ベンダーが報告するコストで請求されるモデルは例外で、そのコストはベンダーの公開価格表から `estimated` として算出されます。どちらも契約料金や顧客固有の料金を反映しません。交渉価格のあるワークスペースにはリスト価格が提示され、契約料金が請求されます。その場合、`source: exact` はリスト価格に対して正確という意味であり、そのワークスペースの請求額に対して正確という意味ではありません。どちらが返す数値も見積もりであり、最終請求額ではありません。ワークスペースの使用量および請求記録にある確定請求額が最終です。自分のプロバイダーキーでの実行は Comfy から請求されません（以下を参照）。デプロイで見積もりが無効になっている場合、ルートは `403` と `error_type: not_enabled` を返し、送信レスポンスは `estimate` を省略します。どちらも、Router がディスパッチする形でボディの料金を見積もります（`model_provider` レッグ用に変換され、実行されるオペレーションにリターゲットされます）が、送信時の `estimate` は実行前の価格ではありません。これは実行が受け入れられ、キューに入った後にのみ返され、その実行はディスパッチ前にキャンセルされない限り請求されます。カタログには依然として価格が掲載されていません。

金額より先に `source` を読んでください。数値の欠落は無料を意味しません。

| `source` | 含まれるもの | 読み方 |
| --- | --- | --- |
| `exact` | `amount`、`amount_cents`、`credits` | `pricing_as_of` の料率でこのボディに対して請求される額と等しい見積もりです。ワークスペースの使用量および請求記録にある確定した請求額が最終的な金額です。 |
| `estimated` | `min_amount`、`max_amount` とその `_cents` 形式、`amount` は含まれない | プロバイダーが報告する数量に請求額が依存し、その数量の上下限がボディで決まる見積もりです。請求額は上下限の範囲内になると見込まれ、ワークスペースの使用量および請求記録にある確定した請求額が最終的な金額です。 |
| `free` | `amount` は "0"、`amount_cents` と `credits` は `0` | 料率表がこのリクエストをゼロで価格付けするため、見積もりは `0` です。ワークスペースの使用量および請求記録にある確定した請求額が最終的な金額です。`0` と表示されるのは `free` の見積もりだけです。 |
| `unknown` | `reason`、数値なし | 実行前に価格を提示できませんでした。その他の `source` 値は `unknown` として扱ってください。 |

`unknown` の見積もりの `reason` は次のいずれかです:

- `not_quotable`: Router はこの呼び出しを実行前に価格付けできません。プロバイダーが報告する数量で請求され、その数量の上下限がボディで決まらないか、送信されたままのボディを価格付けできないためです。認識できない `reason` は `not_quotable` として扱ってください。
- `unpriced_model`: 料率表がこのリクエストを価格付けしていません。
- `byok`(キュー中の送信のみ): 実行は自分のプロバイダーキーを使用するため、Comfy は何も請求しません。
- `pricing_unavailable`(キュー中の送信のみ): リクエストの受け付け時に料率表を読み取れませんでした。送信はそのまま受け付けられ、実行は通常どおり請求されます。

Router がまだ実行前に価格付けできないモデルは、[事前見積もりのないモデル](/ja/development/comfy-router/limitations#事前見積もりのないモデル)に一覧されています。そこに載っていないモデルでも、特定のボディでは `unknown` を返すことがあるため、すべての見積もりで `source` を読んでください。

見積もりがフェイルクローズするのは次の場合です:

- 数値に料率表が必要で、カードが読み込まれていないか古い場合、`/estimate` は推測ではなく `503` を返します。キュー中の送信は見積もりを理由に拒否されることはなく、代わりに `source: unknown` と `reason: pricing_unavailable` を含みます。実行前にまったく価格付けできない呼び出し(`not_quotable`)、または自分のプロバイダーキーでのキュー中の送信(`byok`)は、カードを読まずに応答されるため、その `200` はカードが新しいかどうかについては何も示しません。
- `/estimate` はデフォルトの実行と同様に、モデル自身の入力スキーマに対してボディを検証します。そのため、モデルのスキーマに適合しないボディは、実行が返すのと同じ `422` を、同じ `detail[]` 形状で受け取ります。何も価格付けもディスパッチもされません。
- キュー中の送信の冪等なリプレイ(`Idempotent-Replayed: true`)は `estimate` を含みません。元の見積もりが保存されていないためです。

見積もりの限界。`200` の数値は、実行が受け付けられること、または正確にその金額が請求されることを約束するものではありません:

- `/estimate` は `strict_mode` や `reject_unknown_fields` を受け取らないため、モデルのネイティブな契約のみを検証します。`strict_mode=true` の実行が代替プロバイダー自身のスキーマで受け付けるボディが、ここでは `422` になることがあります。また、`reject_unknown_fields=true` の実行なら拒否する未宣言のトップレベルフィールドが、ここでは価格付けされます。Anthropic Messages モデルは例外です。そのスキーマは未宣言のフィールドを許容するため、`reject_unknown_fields=true` の実行でも何も拒否せず、見積もりは未宣言のトップレベルフィールド `tools`、`tool_choice`、`temperature`、`top_p`、`top_k`、`stop_sequences`、`metadata`、`thinking` および空の `mcp_servers` のみを価格付けします。その他の未宣言のトップレベルフィールドがあると、`reason: not_quotable` とともに `unknown` を返します。
- `pricing_as_of` は料率表を取得した時刻です。ベンダーの公開価格表から取得した `estimated` の見積もりは、その価格表を読んだ日付を持ちます。請求数量をベンダーの公開スケジュールから予測し、その後レートカードで価格設定する `exact` または `estimated` の見積もりは、そのスケジュールの読み取り日がカードより古い場合、スケジュールの読み取り日を持ちます。カードもスケジュールも読まれていない場合は、見積もりを返した時刻です。これは価格の固定ではありません。実行は、レーティング時点で有効な料率で請求されます。
- `/estimate` は `model_provider` が示すレグ、またはネイティブのプロバイダーを価格付けします。`fallback_provider` や `strict_mode` パラメータは受け取りません。フォールバックのリトライが別のプロバイダーで行われる同期実行は、そのプロバイダーの料率で請求され、見積もりはそのレグを価格付けしていません。実行のレスポンスの `X-Comfy-Router-Fallback-Provider` が、それが発生したことを示します。キュー中の送信にはフォールバックがないため、その `estimate` は実行されるレグを価格付けします。
- `/estimate` は常にプラットフォームの請求額を算出します。自分のプロバイダーキーでの実行は Comfy から請求されませんが、`/estimate` はそれを検出せずに数値を返します。`reason: byok` を返すのはキュー中の送信だけです。
- ドルは丸めていないセントから最大8桁の小数で表示され、課金対象の1セント未満の `amount` が `0` と表示されることはありません。`credits` は `round(amount × 211, 2)` であり、これは `X-Comfy-Credits-Used` が課金に適用するのと同じ変換です。そのため、ごく小さい非ゼロの価格では `credits` が `0` にラウンドされることがあります。これが重要となる場合は、`credits` ではなく `amount` または `amount_cents` で予算を立ててください。このヘッダーは引き続き、1回の実行に対する事後的な数値です。残高は Comfy プラットフォーム上にあります。

## 結果アセット

モデルは、アセット URL、インラインバイト、またはその両方を返すことができます。以下のプロバイダーは、選択済みのアセットを Comfy ストレージにコピーし、その URL を置き換えます。この動作はモデルによって異なります。これを選択するリクエストヘッダーはありません。

| モデル | Comfy ストレージにコピーされるもの | Comfy ホスト URL の最大有効期間 |
| --- | --- | --- |
| `bfl/*` | 完了したアセット、および結果に含まれている場合はドラフトキャッシュのアセット | 24 時間 |
| `byteplus/*` ビデオモデル (`seedance`、`dreamina-seedance`) | 完了したビデオ、および結果に含まれている場合はラストフレーム画像 | 24 時間 |
| `fal/h3-max`、`fal/h3-max-turbo` | 完了したビデオ | 24 時間 |
| `minimax/*` | 完了したビデオ | 12 時間 |
| `xai/*` | 生成されたすべての画像、および完了したビデオ | 24 時間 |

これらの有効期間は、URL を開いたときではなく、URL が署名されたときに開始されます。キャッシュされた URL や再利用された URL は残り時間が短い場合があります。再利用しても有効期間は更新されません。`Idempotency-Key` レコードは、保持する URL より長く残ることがあるため、そうした URL の有効期限が切れる 1 時間前から、同じキーでの再試行は記録済みのレスポンスではなく `409 invalid_input` で応答されます。応答が返された時点ですでにそれだけ期限に近かった場合は、5 分間は再再生できます。アセットは速やかにダウンロードしてください。コピーされるのは各行に記載されたアセットのみです。`byteplus/seedream-*` と `byteplus/seededit-*` の画像は BytePlus ビデオの行には含まれず、`fal/fal-*` のモデルは fal の行には含まれません。

コピーを実行するのは、モデルのネイティブプロバイダーのみです。代替プロバイダーによって処理された実行、すなわち `model_provider` が代替プロバイダーを指定している場合、`model_provider` を指定しておらず Comfy Router が別のプロバイダーで処理した実行（同期実行ルートの `X-Comfy-Router-Provider` で報告されます）、またはネイティブ実行のフォールバック再試行が代替プロバイダーに到達した場合（`X-Comfy-Router-Fallback-Provider` で開示されます）は、そのプロバイダー自身の URL を返します。これらの URL はプロバイダーの有効期限に従い、コピーされません。`model_provider` の値 `default`、`comfy`、`comfyui` は代替プロバイダーを指定しないため、それらの実行はネイティブであり、上記と同様にコピーされます。フォールバック再試行がネイティブプロバイダーに戻った `model_provider` の実行も同様です。

**Veo (`veo/*`) には別のストレージパスがあります。** `response.videos[]` では、存在する方のメンバーを読み取ってください。`bytesBase64Encoded` はクリップをインラインで含み、`gcsUri` は、プロバイダーから Comfy ストレージへの直接書き込みが環境で構成されている場合に、Comfy が署名した HTTPS リンクを含みます。そのリンクはレスポンスから 24 時間有効です。後者の場合はアセットをコピーするのではなく直接書き込むため、Veo は再ホスティングの表には含まれていません。

その他のモデルは、プロバイダーのアセット参照またはインラインバイトを返します。プロバイダーの URL はプロバイダーの有効期限に従います。これは上記の有効期間よりはるかに短い場合があり、Router の契約では規定されていません。

**オリジナルの BytePlus URL（Seedance 2.x、オプトイン）。** Comfy がサーバー側でオプトインしたワークスペースでは、Seedance 2.x の結果に、コピーされた URL の隣に BytePlus 自身の URL が `content.upstream_video_url` と `content.upstream_last_frame_url` として含まれ、さらに `content.upstream_expires_at` も含まれます。リクエストパラメーターはなく、デフォルトでオプトインされるワークスペースはありません。これらの URL は生成から 24 時間後に期限切れとなり、BytePlus がクリアすると存在しなくなります。Seedance 2.5 では BytePlus がそれぞれ 100 ダウンロードに制限しており、Router 自身のコピーがそのうち 1 回を使用します。各 URL はそのオブジェクトのベアラークレデンシャルです。保持している誰でも、期限が切れるまでアセットをダウンロードできます。

**ゼロデータ保持のワークスペース。** Comfy がゼロデータ保持を設定したワークスペースでは、BytePlus の結果は Comfy ストレージにコピーされません。上記の `byteplus/*` ビデオの行は適用されず、`content.video_url` と `content.last_frame_url` は BytePlus 自身のプロバイダー URL となり、BytePlus が送信したそのままの形で返されます。これらは 24 時間有効で、Seedance 2.5 では BytePlus がそれぞれ 100 回のダウンロードに制限しているため、アセットは速やかにダウンロードしてください。このような結果は `Idempotency-Key` レコードから再生されません。

コピーはアセットごとのベストエフォートです。1 つのコピーが失敗した場合、そのエントリはプロバイダーの参照を保持します。レスポンスには Comfy とプロバイダーの両方の URL が含まれる可能性があり、アセットごとの明示的なコピーステータスフィールドはありません。生成は引き続き成功し、課金されます。1 つの正常に再ホストされたアセットから、すべての URL の有効期間を推測しないでください。

結果が Comfy ホストかどうかは、完了した呼び出しが後でその `Idempotency-Key` レコードから再生できるかどうかも決定します。上記の `Idempotency-Key` パラメーターは、再生できない場合に再試行が何で応答されるかを説明しています。

## モデルごとの入力および出力スキーマ

各モデルのフィールドは `GET /v2/models/{provider}/{model}/openapi.json` から読み取ります。この呼び出しには APIキーが必要です。スキーマが作成されているすべてのモデルについて、同じドキュメントが APIキーなしでこのサイトの `/router-schemas/{provider}/{model}.json` にも公開されています。このコピーは最後のドキュメント更新時に取得されたスナップショットであるため、両者が異なる場合はエンドポイントの内容が正式です。オペレーションの `requestBody` は入力の検証を記述しており、その `200` レスポンスは、スキーマが作成されている場合に出力の形状とメディアタイプを記述しています。`x-comfy-input-schema-authored` が false の場合、Router はモデル固有の事前検証なしで任意の JSON オブジェクトを受け入れます。プロバイダーの要件は引き続き適用されます。出力スキーマは結果を記述するものであり、Router は返されたプロバイダーのペイロードをそれらに対して検証しません。スキーマが作成されていない出力では、`application/json` ではなく `*/*` が使用される場合があります。デコードする前にレスポンスのコンテンツタイプを確認してください。

## スキーマ

### RouterBilledWorkspace

拒否された呼び出しが課金対象としていたウォレットで、`RouterErrorResponse.billed_workspace` に含まれます。「どのウォレットが空なのか?」に答えるものであり、呼び出し元の UI で現在選択済みのワークスペースとは限りません。また、チームメンバーの個人認証情報では、資金のあるチームが開かれていても、ここにはそのメンバーの個人ウォレットが示されます。`denied_reason` と同時にのみ存在します。

**フィールド**

<ResponseField name="id" type="string">
  クラウドのワークスペース id。レガシーレールでは存在しません。
</ResponseField>

<ResponseField name="type" type="string" required>
  `personal` または `team`。オープンな文字列であり、それ以外の値は個人として扱ってください。
</ResponseField>

<ResponseField name="rail" type="string">
  呼び出しがクラウドワークスペースではなく、呼び出し元のワークスペース導入前の Metronome 顧客に課金される場合は `legacy` です。その顧客にはワークスペース id がありません。クラウドワークスペースの場合は存在しません。

### RouterCostEstimate

この呼び出しにかかるコストの事前見積もりです。米ドル建てで、ディスパッチ前に Comfy のスタンダード定価で価格設定されるか、ベンダーが報告するコストで課金されるモデルの場合はベンダーの公開価格表に基づいて価格設定されます。このベンダー報告の場合、`source: exact` は、オプトインした少数のモデルに対して、かつ公開価格表がその金額を完全に決定できる場合（価格を左右するすべてのフィールドが明示されているか、金額を変えないデフォルトのままである場合）に限り返されます。それ以外のベンダー報告の見積もりはすべて `estimated` です。価格表で完全に決定できるものも含まれます。いずれの場合も、実行は完了後にベンダーが報告する金額で課金され、見積もり金額がそのまま請求されることはありません。契約料金や顧客固有の料金は反映されません。交渉価格のあるワークスペースは定価で見積もられ、契約料金で請求されます。その場合の `source: exact` は定価での正確さを意味し、そのワークスペースの請求額を意味しません。最終請求額ではありません。実際に支払うのは、ワークスペースの使用量と請求記録にある確定請求額です。実行後に報告される `X-Comfy-Credits-Used` は、事後に丸められた数値であり、領収書ではありません。`source` はその数値をどの程度信頼できるかを示します。`exact` は `amount` を持ちます。`free` は `amount` "0" を持ちます（レートカードがこのリクエストをゼロと価格設定）。`estimated` は `min_amount` と `max_amount` を持ち、`amount` は持ちません。`unknown` はどちらも持たず、`reason` を持ちます。`amount` がないことを無料と解釈してはいけません。価格ロックではありません。`pricing_as_of` を参照してください。

### RouterErrorResponse

認証、アクセス、モデル検索、クォータ、およびプロバイダーのトランスポート障害に対するエラーボディ。

**フィールド**

<ResponseField name="detail" type="string" required>
  障害の人間が読める説明で、エンドユーザーに表示しても安全です。機械解析用ではありません。代わりに `error_type` で分岐してください。退役したモデルに対する `model_not_found` の場合、`detail` は、後継モデルが記録されていて呼び出し元に表示可能であれば `<id> was retired on <YYYY-MM-DD>; use <successor>` と表示され、そうでなければ通常の候補リストの代わりに `<id> was retired on <YYYY-MM-DD>` とのみ表示されます。ここで名前が挙がる後継モデルは、常に呼び出しを再ポイントできる有効なカタログ ID です。終了日がまだ未来の日付であるモデルは退役していません。`GET /v2/models` に引き続きリストされ、その日付まで実行可能なままです。`detail` の他の部分と同様、この退役に関する文言は表示用であり、互換性の保証はありません。機械解析しないというルールには、2 つの文書化された例外があります。`POST /v2/models/{provider}/{model}` では、`409` が `invalid_input` バケットを共有する 3 つの無関係な条件に対して返され、それらを区別するのは `detail` だけです。`detail` が "this request's `image` selects the edit operation" で始まる場合はマルチパートの `model_provider` 拒否であり、`detail` が `this request resolved a BYOK credential` で始まる場合は BYOK の `model_provider` 拒否です。どちらも新しい `Idempotency-Key` では解消されません。そのルート上の他の `invalid_input` `409` はキー競合です。どちらのプレフィックスも安定した契約条件であり、マッチングに使用できます。他のどこでも、`detail` に基づく分岐に互換性の保証はありません。
</ResponseField>

<ResponseField name="error_type" type="RouterErrorType" required>
  Router の障害に対する粗い機械可読バケットで、`X-Comfy-Error-Type` レスポンスヘッダーにミラーリングされるため、呼び出し元はボディを解析せずに分岐できます。このセットは 23 個の値で閉じられています。7 つのリクエストレベルのバケット `invalid_input`、`content_policy_violation`、`provider_error`、`provider_timeout`、`insufficient_credits`、`budget_exceeded`、`model_not_found`、およびトランスポートレベルの `unauthorized`、`forbidden`、`concurrency_limit_exceeded`、`client_disconnected`、`internal_error`、`deadline_exceeded`、`not_enabled`、`service_unavailable`、`budget_check_unavailable`、`rate_limited`、`cancelled`、`queue_timeout`、`request_not_found`、`queue_backlog_full`、`result_expired`、さらにリクエストレベルの `byok_credential_rejected` です。「閉じられている」とは今日文書化されているセットを指し、永遠に続く境界ではありません。セットは拡大することが予想されるため、これは意図的に `enum` ではなくプレーンな文字列になっています。したがって、クライアントは認識できない値を `internal_error` として扱う必要があり、上記のリストを網羅的に分岐して次の追加で壊れるべきではありません。

  型: [`RouterErrorType`](#routererrortype)
</ResponseField>

<ResponseField name="upstream_detail" type="string">
  `invalid_input` 拒否に対する、範囲が限定されサニタイズされた理由。同期ルートでは、モデルプロバイダーが提示した理由であり、`error_type` が `invalid_input` で、`X-Comfy-Upstream-Status` がプロバイダーの `4xx` または `2xx` の場合にのみ存在します。つまり、プロバイダーがリクエストを不正な形式として拒否し、その理由を述べた場合です。通常、そのステータスは `4xx` です。成功エンベロープ内で拒否された生成を報告するプロバイダーの場合は `2xx` になります（BytePlus の失敗したタスクのポーリングは HTTP `200` で、理由がボディに含まれます）。そこでは、プロバイダーの `5xx`、トランスポート障害、コンテンツポリシー拒否、および Router が自身に関して発生させた拒否を含む、他のすべての障害では存在しません。また、`X-Comfy-Upstream-Detail` ヘッダーをミラーリングします。`invalid_input` で終了した実行のキュー中の収集（`GET /v2/models/{provider}/{model}/requests/{request_id}`）は、最初の収集時にこのフィールドに同じ理由を保持し、その後リクエストから削除します。後続の収集は通常、それなしで同じ `error_type` と `detail` を返すため、最初の収集から読み取ってください。その読み取りはどちらのヘッダーも送信しません。キュー中の収集は、Router がプロバイダーに送信する前にリクエストを拒否し、理由を 1 文で述べられる場合、Router 自身の理由にもこのフィールドを使用します。同期ルートではそれを `detail` で返します。個々のフィールドを名指しする拒否には、このフィールドは含まれません。
</ResponseField>

<ResponseField name="refusal_subject" type="string">
  コンテンツポリシー拒否がどの入力または出力に関するものかを示す、Router レベルの閉じた語彙: `input`、`output`、`input_text`、`input_image`、`input_video`、`input_audio`、`output_text`、`output_image`、`output_video`、`output_audio`。プロバイダーがモダリティを名指ししなかった場合、裸の `input` / `output` 値がどちら側かを示します。`error_type` が `content_policy_violation` で、プロバイダーが拒否された対象を機械可読コードで名指しした場合にのみ存在し、それ以外では存在しません。プロバイダーのテキストではありません。現在、BytePlus、Runway、BFL、Gemini、Veo、Vertex、xAI および Wan の拒否、ならびに MiniMax Router の Nano Banana レッグの Gemini 拒否に対して名指しされます。拒否がどちら側に関するものかを示さないプロバイダーでは、存在しません。`X-Comfy-Refusal-Subject` ヘッダーをミラーリングします。
