ベース URL: `https://api.comfy.org`

以下のすべてのエンドポイントは認証が必要です。`X-API-Key: <api-key>` または `Authorization: Bearer <jwt>` を送信してください。

### `POST /v2/models/{provider}/{model}`

**正規のモデル ID でパートナーモデルを同期的に実行します。**

モデルを実行し、完了した結果を同じレスポンスで受け取ります。

**パラメータ**

<ParamField path="provider" type="RouterProviderSegment" required>
  正規の `{provider}/{model}` モデル ID のプロバイダー部分。

  型: [`RouterProviderSegment`](#routerprovidersegment)、英数字のスラッグ（例: `anthropic`）、最大 64 文字
</ParamField>

<ParamField path="model" type="RouterModelSegment" required>
  正規の `{provider}/{model}` モデル ID のモデル部分。

  型: [`RouterModelSegment`](#routermodelsegment)、英数字のスラッグ（例: `claude-opus-4-6`）、最大 128 文字
</ParamField>

<ParamField header="Idempotency-Key" type="string">
  1 つの論理的な呼び出しの再試行を安全にする、呼び出し側が生成するキー。

  1〜255 文字
</ParamField>

<ParamField query="model_provider" type="string">
  このモデルを現在のデフォルトの代わりに配信する代替プロバイダーを選択します。代替プロバイダーは `fal`、`wavespeed`、`runware`、`higgsfield` で、`GET /v2/models/{provider}/{model}` は、あるモデルがそれらのどれをサポートしているかを報告します。拒否は固定の順序で判定され、先の判定は、後の判定に該当するかどうかに関係なく応答します。認識されない値（登録されたプロバイダーでさえないもの）は `400` で拒否されます。次に、ボディがマルチパート操作（編集）を選択しているリクエストでの代替プロバイダーは、`detail` が "this request's `image` selects the edit operation" で始まる `409` で拒否されますが、それはそのプロバイダーのこのモデル用のトランスレーターがその操作を提供できない場合に限られます。トランスレーターがメディアを扱えるレッグは通常どおり処理されます。次に、bring-your-own-key 認証情報が解決されたリクエストでは、代替プロバイダーはどれでも `detail` が `this request resolved a BYOK credential` で始まる `409` で拒否されます（そのレスポンスを参照）。そのプロバイダーがこのモデルを提供するかどうかは関係ありません。次に、指定されたプロバイダー自身のゲートがあり、そのプロバイダーがあなたに対して有効になっていない場合は `error_type: not_enabled` を伴う `403` で、ゲートを評価できない場合は `error_type: service_unavailable` を伴う `503` で拒否します。そしてこれら 4 つすべてを通過した後にのみ、このモデル用のレッグを持たない実在のプロバイダーが `error_type: invalid_input` を伴う `400` で拒否されます。これは認識されない値と同じ応答です。`fallback_provider` は、bring-your-own-key リクエスト、ボディがマルチパート操作を選択しているリクエスト、および `strict_mode=true` の下では、拒否されるのではなく何の効果も持ちません。
</ParamField>

<ParamField query="strict_mode" type="boolean">
  `model_provider` と併用した場合にのみ意味を持ちます。

  デフォルト: False
</ParamField>

<ParamField query="fallback_provider" type="string">
  最初の試行が Router または試行したプロバイダーに起因する理由で失敗したときに、Router がこの呼び出しをモデルの他の登録済みプロバイダーに対して再試行するかどうかを制御します。省略した場合、または `false` 以外の値はフォールバックを有効のままにします。`false` は無効にします。フォールバックが成功したレスポンスには `X-Comfy-Router-Fallback-Provider` が付与されます。bring-your-own-key 認証情報が解決されたリクエストでは、このパラメータの値に関係なくフォールバックは利用できません。試行は単に行われず、最初の失敗がそのまま返ります。これは拒否ではなく不作用であり、ここから `409` が発生することはありません。同じ理由で、ボディがマルチパート操作を選択しているリクエストおよび `strict_mode=true` の下でも同様です。それぞれが呼び出しを 1 つのプロバイダーに結び付けるため、別のプロバイダーに対して忠実に再現することはできず、フォールバックは拒否されるのではなく単にスキップされます。その `409` で拒否されるのは明示的な `model_provider` だけであり、この無条件のスキップとは異なり、そのマルチパートの `409` はトランスレーターがその操作を提供できないレッグにのみ適用されます。
</ParamField>

<ParamField query="reject_unknown_fields" type="boolean">
  このモデルの入力スキーマが宣言していないトップレベルのリクエストボディフィールドを、受け入れるのではなく拒否するようにオプトインします。ネストされたフィールドはチェックされず、宣言されていないフィールドを許可するスキーマを持つモデルや、作成済みスキーマを持たないモデルの場合は何も拒否されません。また、`strict_mode=true` で送信されたキュー中の送信でも拒否されません。

  デフォルト: False
</ParamField>

**リクエストボディ**

`application/json` -- [`RouterModelInput`](#routermodelinput)（必須）

パートナーモデルのネイティブ JSON 入力です。`model_provider` がない場合、リクエストはモデルのデフォルトプロバイダーでネイティブディスパッチを実行し、このボディはモデル自身のネイティブスキーマであって、変更されずに転送されます（そこでは `strict_mode` は意味を持たず、何も変わりません）。`model_provider` が代替プロバイダーを選択し、`strict_mode=false`（デフォルト）の場合、ボディは送信前にそのプロバイダーの実際のスキーマに変換されます。正確に表現できないネイティブフィールドは削除され、レスポンスの `X-Comfy-Router-Dropped-Params` ヘッダーで開示されます。暗黙に削除されることはありません。`model_provider` が代替プロバイダーを選択し、`strict_mode=true` の場合、変換は実行されません。ボディはすでにその代替プロバイダー自身の実際のスキーマである必要があり（このモデルのネイティブスキーマではありません。`strict_mode` を参照）、変更されずに転送されます。ボディ自体のフィールドも、複数の操作をサポートするモデルで Router が実行する操作を選択します。編集可能な画像モデルの場合、入力画像を含めると、テキストから画像への操作から画像から画像へ（編集）の操作に切り替わり、それは独自のレートで課金される場合があります。Seedance ビデオモデルの場合、`content[].role` が操作を選択します（最初のフレームの画像は画像から動画へ、参照画像またはクリップは参照から動画を選択します）。ネイティブディスパッチでは、Seedance の課金は役割ではなく `content` 内のメディア種別に従います。ビデオ入力が少しでもあるリクエストは動画から動画へとして課金され、そうでなければ画像があるものは画像から動画へとして、それもなければテキストから動画へとして課金されます。ただし、`draft_task` 項目からの最終レンダーは、それがレンダリングする Draft の操作として課金されます。テキストから動画へと画像から動画へで同じレートを請求するモデルもあります。`model_provider` が代替プロバイダーを選択している場合、条件付きの各操作はそのプロバイダー独自のレートで課金される場合があります。

### `POST /v2/models/{provider}/{model}/estimate`

**モデル呼び出しを実行する前に、実行せずに価格を見積もります。**

このボディをこのモデルで実行した場合のコストを、米ドルで事前に見積もって返します。価格は、実行時の請求に使われるのと同じレートカードから算出されます。これは見積もりであり、最終的な請求額ではありません。実際に支払うのは、ワークスペースの使用状況および請求記録に確定した請求額です。ボディはまずモデルの入力スキーマに対して検証されます。これはデフォルトの実行（`strict_mode` なし、`reject_unknown_fields` なし）が検証するのと同じ方法です。そのため、モデルのスキーマに適合しないボディは、実行時と同じ `422` になります。プロバイダーには何も送信されず、課金も発生しません。この回答は価格の固定ではありません。`pricing_as_of` の時点で有効なレートで算出され、実行は評価時点で有効なレートで請求されます。機能のロールアウト中は、このルートは `403` を返し、`error_type: not_enabled` となります。

<ParamField path="provider" type="RouterProviderSegment" required>
  正規の `{provider}/{model}` モデル ID の小文字のプロバイダーセグメント。実行対象のモデルを持つパートナーです。

  型: [`RouterProviderSegment`](#routerprovidersegment)：英数字スラッグ（例: `anthropic`）、最大 64 文字
</ParamField>

<ParamField path="model" type="RouterModelSegment" required>
  正規の `{provider}/{model}` モデル ID の小文字のモデルセグメント。そのプロバイダー内で実行するモデルです。

  型: [`RouterModelSegment`](#routermodelsegment)：英数字スラッグ（例: `claude-opus-4-6`）、最大 128 文字

  型: [`RouterProviderSegment`](#routerprovidersegment)：英数字のスラッグ（例: `anthropic`）、最大 64 文字
</ParamField>

<ParamField path="model" type="RouterModelSegment" required>
  正規の `{provider}/{model}` モデル ID の小文字のモデルセグメント。そのプロバイダー内で実行するモデルです。

  型: [`RouterModelSegment`](#routermodelsegment)：英数字のスラッグ（例: `claude-opus-4-6`）、最大 128 文字

## 事前のコスト見積もり

`POST /v2/models/{provider}/{model}/estimate` は、リクエストボディを実行せずにその価格を見積もります。また、キュー中の送信 (`POST /v2/models/{provider}/{model}/requests`) は、その `201` で `estimate` と同じ [`RouterCostEstimate`](#routercostestimate) を返します。どちらも、Comfy がその実行の請求に用いるレートカードから価格が決まります。どちらが返す数値も見積もりであり、最終的な請求額ではありません。ワークスペースの利用状況および請求記録にある確定額が最終です。自分のプロバイダーキーでの実行は Comfy から課金されません（後述）。見積もりの展開中は、このルートは `error_type: not_enabled` を伴う `403` を返し、送信レスポンスは `estimate` を省略します。カタログには依然として価格が含まれていません。

金額を確認する前に `source` を読んでください。数値が不足していても、決して無料という意味ではありません。

| `source` | 含まれるもの | 読み方 |
| --- | --- | --- |
| `exact` | `amount`、`amount_cents`、`credits` | `pricing_as_of` のレートに基づく、このボディに対する請求額に等しい見積もりです。ワークスペースの利用状況および請求記録にある確定額が最終です。 |
| `estimated` | `min_amount`、`max_amount` とそれぞれの `_cents` 形式（`amount` はなし） | 請求額がプロバイダーから報告される数量に依存し、ボディがその数量の境界を定める見積もりです。請求額はその境界の間になると見込まれ、ワークスペースの利用状況および請求記録にある確定額が最終です。 |
| `unknown` | `reason`（数値はなし） | 実行前に価格を示すことができませんでした。その他の `source` の値はすべて `unknown` として扱ってください。 |

`unknown` の見積もりの `reason` は次のいずれかです。

- `not_quotable`: Router はこの呼び出しが実行される前に価格を算出できません。プロバイダーが後から報告する数量で課金され、ボディがその範囲を定めていないか、送信されたままの内容では価格を算出できないためです。認識できない `reason` はすべて `not_quotable` として扱ってください。
- `unpriced_model`: レートカードがこのリクエストの価格を定めていません。
- `byok`（キュー中の送信のみ）: 実行が自分のプロバイダーキーを使用するため、Comfy はその実行に対して何も課金しません。
- `pricing_unavailable`（キュー中の送信のみ）: リクエストを受け付けた時点でレートカードを読み取れませんでした。送信はそれでも受け入れられ、実行は通常どおり課金されます。

Router が実行前にまだ価格を算出できないモデルは、[事前見積もりのないモデル](/ja/development/comfy-router/limitations#事前見積もりのないモデル) に一覧されています。そこに一覧されていないモデルでも、特定のボディに対しては `unknown` を返すことがあるため、すべての見積もりで `source` を読んでください。

見積もりがフェイルクローズするのは、次の場合です。

- 数値を出すためにレートカードが必要で、カードが読み込まれていないか古い場合、`/estimate` は推測ではなく `503` を返します。キュー中の送信が見積もりを理由に拒否されることはありません。代わりに `reason: pricing_unavailable` を伴う `source: unknown` を返します。実行前にまったく価格を算出できない呼び出し（`not_quotable`）、または自分のプロバイダーキーでのキュー中の送信（`byok`）は、カードを読まずに応答されるため、その `200` はカードが新しいかどうかについて何も示しません。
- `/estimate` は、デフォルトの実行と同様に、モデル自身の入力スキーマに対してボディを検証します。そのため、モデルのスキーマに適合しないボディには、実行が返すのと同じ `422` が、同じ `detail[]` の形状で返ります。価格の算出もディスパッチも行われません。
- キュー中の送信の冪等な再生（`Idempotent-Replayed: true`）は `estimate` を省略します。元の見積もりは保存されないためです。

見積もりの限界。`200` の数値は、その実行が受け入れられることや、まさにその額が課金されることを約束するものではありません。

- `/estimate` は `strict_mode` や `reject_unknown_fields` を受け取らないため、モデルのネイティブな契約のみを検証します。`strict_mode=true` の実行が代替プロバイダー自身のスキーマで受け入れるボディも、ここでは `422` になることがあります。また、`reject_unknown_fields=true` の実行なら拒否するであろう、宣言されていないトップレベルフィールドも、ここでは価格が算出されます。
- `pricing_as_of` は、レートカードを取得した時刻です（カードを読まなかった場合は、見積もりに応答した時刻）。これは価格の固定ではありません。実行は、評価された時点で有効なレートで課金されます。
- `/estimate` が見積もるのは、`model_provider` が指定するレグ、またはネイティブのプロバイダーです。`fallback_provider` や `strict_mode` パラメータは受け取りません。フォールバックの再試行が別のプロバイダーに到達した同期実行は、そのプロバイダーのレートで課金され、見積もりはそのレートを示していません。実行のレスポンスにある `X-Comfy-Router-Fallback-Provider` が、それが発生したことを示します。キュー中の送信にはフォールバックがないため、その `estimate` は実行されるレグを見積もります。
- `/estimate` とキュー中の送信の `estimate` は、`model_provider` のレグにおける同じボディ、または兄弟オペレーションで実行されるボディに対して、わずかに異なるドキュメントの価格を算出することがあります。送信の `estimate` は、その実行が送るドキュメントに基づいて価格が算出されます。
- `/estimate` は常にプラットフォームの請求額を見積もります。自分のプロバイダーキーでの実行は Comfy から課金されませんが、`/estimate` はそれを検出せず、依然として数値を返します。`reason: byok` を返すのはキュー中の送信だけです。
- ドルは丸めていないセントから、最大 8 桁の小数で表示され、課金対象となる 1 セント未満の `amount` が `0` と表示されることはありません。`credits` は `round(amount × 211, 2)` で、`X-Comfy-Credits-Used` が請求額に適用するのと同じ換算です。そのため、非常に小さな非ゼロの価格では `credits` が `0` にラウンドされることがあります。それが問題になる場合は `credits` ではなく `amount` または `amount_cents` で予算を立ててください。このヘッダーは実行後の数値のままであり、残高は Comfy プラットフォーム上にあります。

## 結果アセット

モデルは、アセット URL、インラインバイト、またはその両方を返すことができます。以下のプロバイダーは、選択済みのアセットを Comfy ストレージにコピーし、その URL を置き換えます。この動作はモデルによって異なります。これを選択するリクエストヘッダーはありません。

| モデル | Comfy ストレージにコピーされるもの | Comfy ホスト URL の最大有効期間 |
| --- | --- | --- |
| `bfl/*` | 完了したアセット、および結果に含まれている場合はドラフトキャッシュのアセット | 24 時間 |
| `byteplus/*` ビデオモデル (`seedance`、`dreamina-seedance`) | 完了したビデオ、および結果に含まれている場合はラストフレーム画像 | 24 時間 |
| `minimax/*` | 完了したビデオ | 12 時間 |
| `xai/*` | 生成されたすべての画像、および完了したビデオ | 24 時間 |

これらの有効期間は、URL を開いたときではなく、URL が署名されたときに開始されます。キャッシュされた URL や再利用された URL は残り時間が短い場合があります。再利用しても有効期間は更新されません。アセットは速やかにダウンロードしてください。コピーされるのは各行に記載されたアセットのみです。`byteplus/seedream-*` と `byteplus/seededit-*` の画像は BytePlus ビデオの行には含まれません。

コピーを実行するのは、モデルのネイティブプロバイダーのみです。代替プロバイダーによって処理された実行、つまり `model_provider` が代替プロバイダーを指定している場合、またはネイティブ実行のフォールバック再試行が代替プロバイダーに到達した場合（`X-Comfy-Router-Fallback-Provider` で開示されます）は、そのプロバイダー自身の URL を返します。これらの URL はプロバイダーの有効期限に従い、コピーされません。`model_provider` の値 `default`、`comfy`、`comfyui` は代替プロバイダーを指定しないため、それらの実行はネイティブであり、上記と同様にコピーされます。フォールバック再試行がネイティブプロバイダーに戻った `model_provider` の実行も同様です。

**Veo (`veo/*`) には別のストレージパスがあります。** `response.videos[]` では、存在する方のメンバーを読み取ってください。`bytesBase64Encoded` はクリップをインラインで含み、`gcsUri` は、プロバイダーから Comfy ストレージへの直接書き込みが環境で構成されている場合に、Comfy が署名した HTTPS リンクを含みます。そのリンクはレスポンスから 24 時間有効です。後者の場合はアセットをコピーするのではなく直接書き込むため、Veo は再ホスティングの表には含まれていません。

その他のモデルは、プロバイダーのアセット参照またはインラインバイトを返します。プロバイダーの URL はプロバイダーの有効期限に従います。これは上記の有効期間よりはるかに短い場合があり、Router の契約では規定されていません。

コピーはアセットごとのベストエフォートです。1 つのコピーが失敗した場合、そのエントリはプロバイダーの参照を保持します。レスポンスには Comfy とプロバイダーの両方の URL が含まれる可能性があり、アセットごとの明示的なコピーステータスフィールドはありません。生成は引き続き成功し、課金されます。1 つの正常に再ホストされたアセットから、すべての URL の有効期間を推測しないでください。

結果が Comfy ホストかどうかは、完了した呼び出しが後でその `Idempotency-Key` レコードから再生できるかどうかも決定します。上記の `Idempotency-Key` パラメーターは、再生できない場合に再試行が何で応答されるかを説明しています。

## モデルごとの入力および出力スキーマ

各モデルのフィールドは `GET /v2/models/{provider}/{model}/openapi.json` から読み取ります。この呼び出しには APIキーが必要です。スキーマが作成されているすべてのモデルについて、同じドキュメントが APIキーなしでこのサイトの `/router-schemas/{provider}/{model}.json` にも公開されています。このコピーは最後のドキュメント更新時に取得されたスナップショットであるため、両者が異なる場合はエンドポイントの内容が正式です。オペレーションの `requestBody` は入力の検証を記述しており、その `200` レスポンスは、スキーマが作成されている場合に出力の形状とメディアタイプを記述しています。`x-comfy-input-schema-authored` が false の場合、Router はモデル固有の事前検証なしで任意の JSON オブジェクトを受け入れます。プロバイダーの要件は引き続き適用されます。出力スキーマは結果を記述するものであり、Router は返されたプロバイダーのペイロードをそれらに対して検証しません。スキーマが作成されていない出力では、`application/json` ではなく `*/*` が使用される場合があります。デコードする前にレスポンスのコンテンツタイプを確認してください。

## スキーマ

### RouterChargesOnPolicyRejection

このモデルでコンテンツポリシーによる拒否が課金されるかどうか。不明な値は課金される可能性があるものとして扱ってください。

型: `string`

### RouterCostEstimate

この呼び出しにかかる費用を、ディスパッチ前に、実行の課金に用いられるのと同じレートカードから米ドルで見積もった事前見積もりです。最終的な請求額ではありません。実際に支払うのは、ワークスペースの使用量および請求記録にある確定した請求額です。実行後に報告される `X-Comfy-Credits-Used` は事後に丸められた数値であり、領収書ではありません。`source` はその数値をどこまで信頼できるかを示します。`exact` は `amount` を持ち、`estimated` は `min_amount` と `max_amount` を持ち `amount` は持ちません。`unknown` はどちらも持たず `reason` を持ちます。`amount` が存在しないことを無料と読み取らないでください。価格の固定ではありません。`pricing_as_of` を参照してください。

**フィールド**

<ResponseField name="source" type="string" required>
  `exact` | `estimated` | `unknown`。それ以外の値は `unknown` として読み取ります。`exact` と `estimated` はいずれも見積もりを表すもので、どちらも最終的な請求額ではありません。`unknown` は数値を持ちません。
</ResponseField>

<ResponseField name="currency" type="string" required>
  常に `USD` です。
</ResponseField>

<ResponseField name="amount" type="string">
  小数文字列としてのドル額。例: "0.04"。最大 8 桁の小数で、指数表記はありません。課金対象となる 1 セント未満の価格が "0" として表示されることはありません。`source` が `exact` の場合のみ存在します。最終的な請求額ではありません。最終的なのは、ワークスペースの使用量および請求記録にある確定した請求額です。
</ResponseField>

<ResponseField name="min_amount" type="string">
  小数文字列としてのドル額の下限。`source` が `estimated` の場合のみ存在します。
</ResponseField>

<ResponseField name="max_amount" type="string">
  小数文字列としてのドル額の上限。`source` が `estimated` の場合のみ存在します。
</ResponseField>

<ResponseField name="amount_cents" type="number">
  計算用の、端数処理を行っていない米セント単位の同じ数値。`amount` とともに存在します。

  double
</ResponseField>

<ResponseField name="min_amount_cents" type="number">
  端数処理を行っていない米セント単位の `min_amount`。`min_amount` とともに存在します。

  double
</ResponseField>

<ResponseField name="max_amount_cents" type="number">
  米セント単位の `max_amount`。`max_amount` とともに存在します。

  double
</ResponseField>

<ResponseField name="credits" type="number">
  プラットフォームの換算（$1 = 211 credits）を用いた Comfy クレジット単位の `amount`。小数第 2 位に丸められます。`exact` な見積もりで `X-Comfy-Credits-Used` が保持すると想定される値です。このヘッダーは事後に丸められた数値であり、領収書ではありません。ワークスペースの使用量および請求記録にある確定した請求額が最終的な金額です。

  double
</ResponseField>

<ResponseField name="provider" type="string" required>
  この見積もりが対象とするプロバイダーのレッグ。キュー中の送信では、実行されるレッグになります。
</ResponseField>

<ResponseField name="model" type="RouterModelId" required>
  正規の Comfy Router モデル ID で、`{provider}/{model}` の形式です。`POST /v2/models/{provider}/{model}` でモデルを指定する値とまったく同じもので、呼び出し元は何からも再導出することなくそのパスに埋め込めます。その `pattern` は `RouterProviderSegment` と `RouterModelSegment` を単一の `/` で連結したもので、`maxLength` はそれらの合計にその区切り文字を加えたものです。

  型: [`RouterModelId`](#routermodelid)。モデル ID（例: `anthropic/claude-opus-4-6`）、最大 193 文字
</ResponseField>

<ResponseField name="pricing_as_of" type="string" required>
  この見積もりの価格算出に使用したレートカードを取得した日時。実行は、評価された時点で有効な料率で課金され、この瞬間の料率で課金されるわけではありません。レートカードが読まれなかった場合（`reason: pricing_unavailable`、`byok`、またはどのカードからも価格を算出できない `not_quotable` の呼び出し）は、見積もりが返された日時を示します。

  date-time
</ResponseField>

<ResponseField name="reason" type="string">
  `source` が `unknown` の場合のみ存在します。`not_quotable`（Router は実行前にこの呼び出しの価格を算出できません。価格がプロバイダーから返される内容に依存するか、リクエストボディが課金対象の数量を定めていないためです）、`unpriced_model`（レートカードにこのリクエストの価格がない）、`byok`（キュー中の送信のみ: 実行は自身のプロバイダーキーを使用するため、Comfy は何も請求しません）、または `pricing_unavailable`（キュー中の送信のみ: リクエストの受け入れ時にレートカードを読めませんでした。これは一時的なもので、実行は通常どおり課金されます）。それ以外の値は `not_quotable` として読み取ります。
</ResponseField>

### RouterErrorResponse

認証、アクセス、モデル検索、クォータ、プロバイダーの転送に関する失敗のエラーボディです。

**フィールド**

<ResponseField name="detail" type="string" required>
  失敗を人間が読める形で説明したもので、エンドユーザーに提示しても安全です。機械的にパースされることはありません。代わりに `error_type` で分岐してください。退役したモデルに対する `model_not_found` の場合、後継モデルが記録されていて呼び出し元から参照できるときは `detail` に `<id> was retired on <YYYY-MM-DD>; use <successor>` が入り、そうでないときは通常の候補リストではなく `<id> was retired on <YYYY-MM-DD>` だけが入ります。ここで示される後継モデルは常に、呼び出しの向き先を変更できる有効なカタログ ID です。提供終了日がまだ未来であるモデルは退役していません。その日付までは `GET /v2/models` に一覧表示され、実行可能なままです。`detail` の他の部分と同様に、この退役に関する文言は表示用であり、互換性の保証はありません。機械的にパースされないというルールには、文書化された 2 つの例外があります。`POST /v2/models/{provider}/{model}` では、`409` が `invalid_input` バケットを共有する 3 つの無関係な条件に対して返され、それらを区別するのは `detail` だけです。`detail` が「this request's `image` selects the edit operation」で始まる場合は multipart の `model_provider` 拒否であり、`detail` が `this request resolved a BYOK credential` で始まる場合は BYOK の `model_provider` 拒否です。どちらも新しい `Idempotency-Key` では解消しません。そのルートにおける他の `invalid_input` の `409` はキーの競合です。どちらのプレフィックスも安定した契約用語であり、マッチングしてもかまいません。これ以外の箇所では、`detail` で分岐することに互換性の保証はありません。
</ResponseField>

<ResponseField name="error_type" type="RouterErrorType" required>
  Router の失敗を表す粗い機械可読なバケットで、`X-Comfy-Error-Type` レスポンスヘッダーにも反映されるため、呼び出し元はボディをパースせずに分岐できます。この集合は 19 個の値で閉じています。6 つのリクエストレベルのバケット `invalid_input`、`content_policy_violation`、`provider_error`、`provider_timeout`、`insufficient_credits`、`model_not_found` に加えて、トランスポートレベルの `unauthorized`、`forbidden`、`concurrency_limit_exceeded`、`client_disconnected`、`internal_error`、`deadline_exceeded`、`not_enabled`、`service_unavailable`、`rate_limited`、`cancelled`、`queue_timeout`、`request_not_found`、`queue_backlog_full` です。「閉じている」とは今日文書化されている集合を指すのであり、永久に保たれる上限ではありません。集合は増えることが想定されているため、これは意図的に `enum` ではなくプレーンな文字列になっています。したがってクライアントは、上記のリストを網羅的に switch して次の追加のたびに壊れるのではなく、認識できない値を `internal_error` として扱わなければなりません。

  型: [`RouterErrorType`](#routererrortype)
</ResponseField>

<ResponseField name="upstream_detail" type="string">
  モデルプロバイダーがリクエストを拒否した理由を、範囲を限定してサニタイズしたものです。`error_type` が `invalid_input` で、`X-Comfy-Upstream-Status` がプロバイダーの `4xx` または `2xx` の場合にのみ存在します。つまり、プロバイダーがリクエストを不正な形式として拒否し、その理由を述べた場合です。通常このステータスは `4xx` です。成功のエンベロープ内で拒否された生成を報告するプロバイダーでは `2xx` になります（BytePlus の失敗タスクのポーリングは HTTP `200` で、理由はボディに含まれます）。それ以外のすべての失敗では存在しません。プロバイダーの `5xx`、トランスポートの失敗、コンテンツポリシーによる拒否、および Router が自身について発生させた拒否が含まれます。`X-Comfy-Upstream-Detail` ヘッダーに反映されます。
</ResponseField>

<ResponseField name="refusal_subject" type="string">
  コンテンツポリシーによる拒否がどの入力または出力に関するものかを、Router レベルの閉じた語彙として示します。`input`、`output`、`input_text`、`input_image`、`input_video`、`input_audio`、`output_text`、`output_image`、`output_video`、`output_audio` です。プロバイダーがモダリティを特定しなかった場合、単なる `input` / `output` の値がどちら側かを示します。`error_type` が `content_policy_violation` で、プロバイダーが拒否された対象を機械可読なコードで示した場合にのみ存在し、それ以外では存在しません。プロバイダーのテキストが入ることはありません。現在は BytePlus、Runway、BFL、Gemini、Veo、Vertex、xAI、Wan の拒否に対して、また MiniMax Router の Nano Banana レッグにおける Gemini の拒否に対しても付与されます。拒否がどちら側に関するものかを示さないプロバイダーでは存在しません。`X-Comfy-Refusal-Subject` ヘッダーに反映されます。
</ResponseField>
