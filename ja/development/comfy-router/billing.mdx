課金が発生するのは、プロバイダーが Comfy に課金したときです。同じルールが同期呼び出しと[キュー中](/ja/development/comfy-router/queue#冪等性と課金)の呼び出しにも適用され、結果を再送する同一キーの[再試行](/ja/development/comfy-router/errors#再試行の結果)に二重の課金は発生しません。

## モデル課金に関する事実

`GET /v2/models` とモデル詳細レスポンスには `billing.charges_on_policy_rejection` が含まれます。これはポリシー拒否についてのものであり、すべての失敗や価格見積もりを示すものではありません。

| 値 | 意味 |
| --- | --- |
| `yes` | ポリシー拒否に対して課金されます。 |
| `no` | ポリシー拒否に対して課金されません。 |
| `unknown` | まだ挙動が確認されていません。課金される可能性があるものとして扱ってください。 |

これらの文字列は明示的に比較してください。`"no"` は Python と JavaScript では真（truthy）と評価されます。認識できない値はすべて `unknown` として扱ってください。クレジット不足で拒否されたリクエストは `insufficient_credits` を報告します。

## 請求の照合

プロバイダーのペイロードには独自のコストや使用量の数値が含まれることがありますが、それらは Comfy の請求額ではありません。`X-Comfy-Credits-Used` は許可リストに載っているプロバイダーでは返されることがありますが、すべてのプロバイダーで返されるわけではなく、再送もされません。照合には[ワークスペースの使用量と請求書](https://platform.comfy.org)を使用してください。請求を調査する際は、リクエスト ID を保管してください。
