Comfy API では、定義した環境と、その環境を実行するエンドポイントを分けて管理します。**Build** は ComfyUI 環境を定義します。**リリース**は、Build を対応ターゲット向けにパッケージ化したものです。**デプロイ**は、リリースをマネージドエンドポイントとして実行します。

## 実行方法を選ぶ

| 選択肢 | 適した用途 | 管理するもの |
| --- | --- | --- |
| [Comfy Cloud](/ja/development/deploy/cloud) | ブラウザーでマネージド版 ComfyUI を使う、またはエンドポイントを設定せずにワークフローを実行する。 | ワークフローと API 呼び出し。Build やデプロイの作成は不要です。 |
| [Comfy API](/ja/development/serverless/quickstart) | 特定の ComfyUI 環境、モデル、カスタムノード、依存関係を使うマネージドエンドポイントが必要。 | Build、そのリリース、1 つ以上のデプロイ。 |
| [セルフホスト](/ja/development/deploy/self-hosting) | マシン、ソフトウェア、モデル、カスタムノードを自分で選んで管理する。 | 自分の ComfyUI インストールとインフラストラクチャ。 |

ワークフローに Comfy Cloud で利用できないカスタムノードや依存関係が必要な場合は、Comfy API またはセルフホストの ComfyUI を使います。Comfy API はパッケージ化された環境からマネージドエンドポイントを作成します。変更を試すための対話型 Sandbox ではありません。

## Comfy API の各要素の関係

```text
ワークスペース → ローカルプロジェクト → Build → リリース → デプロイ → ワークフローリクエスト
```

1. **ワークスペース**: チームがアクセス権、Build、デプロイ、使用上限を管理するアカウントの範囲です。
2. **ローカルプロジェクトフォルダー**: `comfy-build.yaml` と関連するワークフローやアセットをマシン上に保存するフォルダーです。このファイルは Build を記述し、リモートの既知の状態を記録します。モデルファイルは含みません。オンラインリソースではなく、ローカルのフォルダーです。
3. **Build**: ComfyUI のバージョン、モデル、カスタムノード、設定など、ComfyUI 環境を定義します。Developer Platform にプッシュすると利用できるようになります。
4. **リリース**: `linux/nvidia` など、対応ターゲット向けにビルドされた Build のバージョンです。Build を変更したときや別のターゲットが必要なときは、新しいリリースを作成します。
5. **デプロイ**: リリースから作成された稼働中のエンドポイントです。GPU、リージョン、ワーカー数の範囲など、独自のコンピューティング設定があります。たとえば異なる GPU タイプを使うために、同じ Build から複数のデプロイを実行できます。

[Comfy SDK](/ja/development/api-development/sdks) または CLI を使い、デプロイのエンドポイントに API 形式のワークフローリクエストを送ります。デプロイは、リリースにパッケージ化された環境を使ってリクエストを実行します。

## 更新するとどうなるか

- **環境を変更する**: Build の定義を更新してプッシュし、新しいリリースを作成します。準備ができたら、デプロイがそのリリースを使うように更新します。
- **容量を変更する**: デプロイをスケールまたは停止します。Build やリリースではなく、コンピューティング設定が変わります。
- **別のワークフローを実行する**: 別の API 形式ワークフローをエンドポイントに送ります。必要なモデルとノードが Build に含まれていれば、新しいリリースは不要です。

**インスタンス**は、Comfy Desktop が管理する環境など、ComfyUI の実行環境を指します。Comfy API でユーザーが作成して運用するのはデプロイです。基盤となるランタイムインスタンスを管理する必要はありません。
