모든 Router 모델은 `{provider}/{model}` 형식의 ID로 지정됩니다. 카탈로그에서 해당 ID를 찾은 다음 `POST /v2/models/{provider}/{model}`을 호출하세요.

## 카탈로그 찾아보기

생성에 사용한 것과 동일한 API 키로 모델을 나열합니다:

```bash
curl -H "X-API-Key: $COMFY_API_KEY" \
  "https://api.comfy.org/v2/models?limit=50"
```

축약된 카탈로그 응답:

```json
{
  "data": [
    {
      "id": "bfl/flux-2-pro",
      "provider": "bfl",
      "model": "flux-2-pro",
      "billing": { "charges_on_policy_rejection": "no" }
    }
  ],
  "has_more": true,
  "next_cursor": "example-cursor",
  "limit": 50
}
```

호출 경로에는 `id`를 사용합니다. `billing` 객체에는 가격이 아니라 결제 관련 사실이 담겨 있습니다. 이 값에 의존하기 전에 [정책 거부 결제](/ko/development/comfy-router/billing#모델-청구-정보)를 읽어 보세요.

### 페이지네이션

- `has_more`가 `true`이면 반환된 `next_cursor`를 `cursor`로 전달합니다. 이전 페이지가 요청한 것보다 짧았더라도 `has_more`가 `false`이면 중지합니다.
- 커서는 불투명한 값으로 취급합니다. 값을 URL 인코딩하세요. 예를 들어 cURL에서는 `--get --data-urlencode "cursor=$NEXT_CURSOR"`를 사용합니다. 오프셋을 계산하거나 커서를 수정하지 마세요.
- `limit`의 기본값은 20이며 최대 100으로 제한됩니다. 상한을 초과하는 값은 잘리며, 0과 음수 값은 기본값을 선택합니다. 응답에는 실제로 사용된 limit이 보고됩니다.
- 잘못된 커서는 `400` / `invalid_input`을 반환합니다. 목록을 조용히 다시 시작하지 않습니다.
- 커서는 카탈로그 업데이트 전반에 걸쳐 유효하게 유지될 수 있지만, 순회는 스냅샷이 아닙니다. 현재 위치 이전에 추가된 모델은 해당 순회에 나타나지 않을 수 있습니다.

`503` / `service_unavailable`은 일시적입니다. 백오프를 두고 재시도하세요. 이를 빈 카탈로그로 취급하지 마세요. SDK 실행 메서드는 선택한 모델을 직접 호출합니다.

## 모델 하나 조회하기

모델 ID를 알고 있다면 카탈로그 항목을 직접 가져오세요:

```bash
curl -H "X-API-Key: $COMFY_API_KEY" \
  https://api.comfy.org/v2/models/bfl/flux-2-pro
```

모델 상세 엔드포인트를 사용하면 전체 카탈로그를 순회하지 않아도 됩니다. 전체 항목 필드는 [API 참조](/ko/development/comfy-router/reference)를 참고하세요.
