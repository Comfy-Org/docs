Comfy Router의 정식 라우트로, 모델 ID로 주소가 지정됩니다.

기본 URL: `https://api.comfy.org`

아래의 모든 엔드포인트에는 인증이 필요합니다. `X-API-Key: <api-key>` 또는 `Authorization: Bearer <jwt>`를 전송하십시오.

Comfy API 키는 Bearer 토큰으로도 전송할 수 있습니다. 두 자격 증명 헤더를 모두 제공하면 `X-API-Key`가 우선합니다. 키와 JWT의 구분은 [인증 헤더](/ko/development/comfy-router/headers#요청-헤더)를, 액세스 요구 사항은 [퀵스타트](/ko/development/comfy-router/quickstart)를 참고하십시오.

## 엔드포인트

### `GET /v2/models`

**Comfy Router가 실행할 수 있는 모델 목록을 조회합니다.**

사용 가능한 모델 ID와 과금 정보를 나열합니다. `has_more`가 참인 동안 `next_cursor`를 사용하세요.

**파라미터**

<ParamField query="cursor" type="RouterPageCursor">
  불투명한 페이지네이션 커서입니다.

  타입: [`RouterPageCursor`](#routerpagecursor) -- `next_cursor`로 반환되는 불투명 커서, 1–512자
</ParamField>

<ParamField query="limit" type="integer">
  한 페이지에 반환할 모델 수입니다.

  최대 100, 기본값: 20
</ParamField>

<ParamField header="If-None-Match" type="string">
  호출자가 이전 `200` 응답에서 보유한 `ETag`입니다.
</ParamField>

**응답**

<ResponseField name="200" type="RouterModelListResponse">
  OK - 모델 카탈로그의 한 페이지입니다.

  본문: [`RouterModelListResponse`](#routermodellistresponse) -- 헤더: `X-Comfy-Request-Id`, `ETag`, `Cache-Control`
</ResponseField>

<ResponseField name="304" type="no body">
  Not Modified - 호출자가 `If-None-Match`로 보낸 `ETag` 이후 페이지가 변경되지 않았습니다.

  헤더: `X-Comfy-Request-Id`, `ETag`, `Cache-Control`
</ResponseField>

<ResponseField name="400" type="RouterErrorResponse">
  잘못된 요청입니다. 오류 유형과 요청 본문을 확인하세요.

  본문: [`RouterErrorResponse`](#routererrorresponse) -- 헤더: `X-Comfy-Error-Type`, `X-Comfy-Request-Id`
</ResponseField>

<ResponseField name="401" type="RouterErrorResponse">
  자격 증명이 누락되었거나 유효하지 않습니다.

  본문: [`RouterErrorResponse`](#routererrorresponse) -- 헤더: `X-Comfy-Error-Type`, `X-Comfy-Request-Id`
</ResponseField>

<ResponseField name="403" type="RouterErrorResponse">
  이 호출자 또는 모델에 대해 요청이 허용되지 않습니다.

  본문: [`RouterErrorResponse`](#routererrorresponse) -- 헤더: `X-Comfy-Error-Type`, `X-Comfy-Request-Id`
</ResponseField>

<ResponseField name="503" type="RouterErrorResponse">
  Router를 일시적으로 사용할 수 없습니다. 백오프를 적용하여 재시도하세요.

  본문: [`RouterErrorResponse`](#routererrorresponse) -- 헤더: `X-Comfy-Error-Type`, `X-Comfy-Request-Id`
</ResponseField>

### `GET /v2/models/{provider}/{model}`

**표준 모델 ID로 파트너 모델 하나의 카탈로그 항목을 조회합니다.**

전체 카탈로그를 나열하지 않고 모델 하나의 세부 정보를 조회합니다.

**파라미터**

<ParamField path="provider" type="RouterProviderSegment" required>
  표준 `{provider}/{model}` 모델 ID의 공급자 부분입니다.

  유형: [`RouterProviderSegment`](#routerprovidersegment). 영숫자 슬러그(예: `anthropic`), 최대 64자
</ParamField>

<ParamField path="model" type="RouterModelSegment" required>
  표준 `{provider}/{model}` 모델 ID의 모델 부분입니다.

  유형: [`RouterModelSegment`](#routermodelsegment). 영숫자 슬러그(예: `claude-opus-4-6`), 최대 128자
</ParamField>

<ParamField header="If-None-Match" type="string">
  호출자가 이전 `200` 응답에서 보유한 `ETag`입니다.
</ParamField>

**응답**

<ResponseField name="200" type="RouterModelDetail">
  OK: 모델의 카탈로그 항목입니다.

  본문: [`RouterModelDetail`](#routermodeldetail). 헤더: `X-Comfy-Request-Id`, `ETag`, `Cache-Control`
</ResponseField>

<ResponseField name="304" type="no body">
  수정되지 않음: 호출자가 `If-None-Match`에 보낸 `ETag` 이후 항목이 변경되지 않았습니다.

  헤더: `X-Comfy-Request-Id`, `ETag`, `Cache-Control`
</ResponseField>

<ResponseField name="401" type="RouterErrorResponse">
  자격 증명이 누락되었거나 유효하지 않습니다.

  본문: [`RouterErrorResponse`](#routererrorresponse). 헤더: `X-Comfy-Error-Type`, `X-Comfy-Request-Id`
</ResponseField>

<ResponseField name="403" type="RouterErrorResponse">
  이 호출자 또는 모델에 대해서는 요청이 허용되지 않습니다.

  본문: [`RouterErrorResponse`](#routererrorresponse). 헤더: `X-Comfy-Error-Type`, `X-Comfy-Request-Id`
</ResponseField>

<ResponseField name="404" type="RouterErrorResponse">
  모델 ID를 찾을 수 없습니다.

  본문: [`RouterErrorResponse`](#routererrorresponse). 헤더: `X-Comfy-Error-Type`, `X-Comfy-Request-Id`
</ResponseField>

<ResponseField name="503" type="RouterErrorResponse">
  Router를 일시적으로 사용할 수 없습니다. 백오프를 적용해 다시 시도하세요.

  본문: [`RouterErrorResponse`](#routererrorresponse). 헤더: `X-Comfy-Error-Type`, `X-Comfy-Request-Id`
</ResponseField>

### `POST /v2/models/{provider}/{model}`

**표준 모델 ID로 파트너 모델을 동기적으로 실행합니다.**

모델을 실행하고 완료된 결과를 같은 응답에서 받습니다.

**파라미터**

<ParamField path="provider" type="RouterProviderSegment" required>
  표준 `{provider}/{model}` 모델 ID에서 공급자 부분입니다.

  유형: [`RouterProviderSegment`](#routerprovidersegment) -- 영숫자 슬러그, 예: `anthropic`, 최대 64자
</ParamField>

<ParamField path="model" type="RouterModelSegment" required>
  표준 `{provider}/{model}` 모델 ID에서 모델 부분입니다.

  유형: [`RouterModelSegment`](#routermodelsegment) -- 영숫자 슬러그, 예: `claude-opus-4-6`, 최대 128자
</ParamField>

<ParamField header="Idempotency-Key" type="string">
  하나의 논리적 호출을 안전하게 재시도할 수 있게 해 주는, 호출자가 생성한 키입니다.

  1–255자
</ParamField>

<ParamField query="model_provider" type="string">
  이 모델을 현재 기본값 대신 다른 공급자가 서비스하도록 선택합니다. `fal`, `wavespeed`, `runware`, `higgsfield`가 대체 공급자이며, `GET /v2/models/{provider}/{model}`은 주어진 모델이 이들 중 무엇을 지원하는지 알려줍니다. 거부는 고정된 순서로 검사되며, 앞선 검사는 뒤따르는 검사에 해당하든 아니든 응답합니다. 등록된 공급자가 전혀 아닌, 인식되지 않는 값은 `400`으로 거부됩니다. 다음으로, 본문이 멀티파트 작업(편집)을 선택하는 요청에서 대체 공급자를 지정하면 `detail`이 "this request's `image` selects the edit operation"으로 시작하는 `409`로 거부되지만, 이는 해당 공급자의 이 모델에 대한 번역기가 그 작업을 처리할 수 없을 때만입니다. 미디어를 실제로 처리하는 번역기를 가진 레그는 정상적으로 진행됩니다. 다음으로, bring-your-own-key 자격 증명을 확인한 요청에서는 해당 공급자가 이 모델을 서비스하는지와 무관하게, 대체 공급자를 지정하면 `detail`이 `this request resolved a BYOK credential`로 시작하는 `409`로 거부됩니다(해당 응답 참조). 다음으로, 지정된 공급자 자체의 게이트가 검사되는데, 해당 공급자가 내게 활성화되어 있지 않으면 `error_type: not_enabled`와 함께 `403`으로, 게이트를 평가할 수 없으면 `error_type: service_unavailable`과 함께 `503`으로 거부합니다. 그리고 이 네 가지를 모두 통과한 뒤에야 이 모델에 대한 레그가 없는 실제 공급자가 `error_type: invalid_input`과 함께 `400`으로 거부되며, 이는 인식되지 않는 값과 같은 응답입니다. `fallback_provider`는 bring-your-own-key 요청에서, 본문이 멀티파트 작업을 선택하는 요청에서, 그리고 `strict_mode=true`에서 거부되지 않고 효력이 없습니다.
</ParamField>

<ParamField query="strict_mode" type="boolean">
  `model_provider`와 함께 사용할 때만 의미가 있습니다.

  기본값: 거짓
</ParamField>

<ParamField query="fallback_provider" type="string">
  첫 시도가 Router 또는 시도한 공급자에 기인하는 이유로 실패했을 때, Router가 이 호출을 모델의 다른 등록 공급자로 재시도할지 여부를 제어합니다. 생략하거나 `false` 이외의 값을 주면 폴백이 켜진 채로 유지되고, `false`는 폴백을 끕니다. 폴백이 성공한 응답에는 `X-Comfy-Router-Fallback-Provider`가 포함됩니다. bring-your-own-key 자격 증명을 확인한 요청에서는 이 파라미터가 무엇을 말하든 폴백을 사용할 수 없습니다. 시도 자체가 이루어지지 않고 첫 실패가 그대로 전달되며, 이는 거부가 아니라 효력이 없는 것입니다. 여기서 `409`가 발생하지는 않습니다. 같은 이유로, 본문이 멀티파트 작업을 선택하는 요청과 `strict_mode=true`에서도 마찬가지입니다. 각각은 호출을 하나의 공급자에 묶어 다른 공급자에 대해 충실히 재생할 수 없으므로, 폴백은 거부되지 않고 그냥 건너뜁니다. 그 `409`로 거부되는 것은 명시적인 `model_provider`뿐이며, 이 무조건적인 건너뜀과 달리 멀티파트 `409`는 번역기가 해당 작업을 처리할 수 없는 레그에만 적용됩니다.
</ParamField>

<ParamField query="reject_unknown_fields" type="boolean">
  이 모델의 입력 스키마가 선언하지 않은 최상위 요청 본문 필드를 수용하는 대신 거부하도록 선택합니다. 중첩 필드는 검사하지 않으며, 스키마가 선언되지 않은 필드를 허용하거나 작성된 스키마가 없는 모델에서는, 또는 `strict_mode=true`로 보낸 대기 중 제출에서는 아무것도 거부되지 않습니다.

  기본값: 거짓
</ParamField>

**요청 본문**

`application/json` -- [`RouterModelInput`](#routermodelinput) (필수)

파트너 모델의 기본 JSON 입력입니다. `model_provider`가 없으면 요청은 모델의 기본 공급자에서 네이티브 디스패치로 실행되며, 이 본문은 모델 자체의 네이티브 스키마이고 그대로 전달됩니다(이 경우 `strict_mode`는 의미가 없으며 아무것도 바꾸지 않습니다). `model_provider`가 대체 공급자를 선택하고 `strict_mode=false`(기본값)이면, 본문은 전송되기 전에 해당 공급자의 실제 스키마로 변환됩니다. 정확히 표현할 수 없는 네이티브 필드는 버려지고 응답의 `X-Comfy-Router-Dropped-Params` 헤더를 통해 공개되며, 결코 조용히 처리되지 않습니다. `model_provider`가 대체 공급자를 선택하고 `strict_mode=true`이면 변환이 실행되지 않습니다. 본문은 이 모델의 네이티브 스키마가 아니라 이미 해당 대체 공급자 자체의 실제 스키마여야 하며(`strict_mode` 참조), 그대로 전달됩니다. 본문의 필드 자체가 하나 이상의 작업을 지원하는 모델에서 Router가 어떤 작업을 실행할지도 선택합니다. 편집 가능한 이미지 모델의 경우 입력 이미지를 포함하면 텍스트 기반 이미지 생성에서 이미지 기반 이미지 생성(편집) 작업으로 전환되며, 이 작업은 자체 요율로 과금될 수 있습니다. Seedance 비디오 모델의 경우 `content[].role`이 작업을 선택합니다(첫 프레임 이미지는 이미지 기반 비디오 생성을, 레퍼런스 이미지나 클립은 레퍼런스 기반 비디오 생성을 선택합니다). 네이티브 디스패치에서 Seedance 과금은 역할이 아니라 `content`의 미디어 종류를 따릅니다. 비디오 입력이 하나라도 있는 요청은 비디오 기반 비디오 생성으로 과금되고, 그렇지 않고 이미지가 하나라도 있으면 이미지 기반 비디오 생성으로, 그 외에는 텍스트 기반 비디오 생성으로 과금되며, 단 `draft_task` 항목에서 나온 최종 렌더는 그것이 렌더링하는 Draft의 작업으로 과금됩니다. 일부 모델은 텍스트 기반 비디오 생성과 이미지 기반 비디오 생성에 같은 요율을 부과합니다. `model_provider`가 대체 공급자를 선택하는 경우, 조건이 적용된 각 작업은 해당 공급자 자체의 요율로 과금될 수 있습니다.

**응답**

<ResponseField name="200" type="RouterModelOutput">
  OK: `model_provider`가 없거나, `model_provider`가 있으면서 `strict_mode=false`인 경우(기본값이며, 가능하면 이 모델의 네이티브 계약으로 다시 변환하고 변환 실패 시 대체 공급자 자체의 원시 응답으로 폴백합니다. 이는 기록되며 결코 조용히 처리되지 않습니다) 형태는 이 모델 자체의 네이티브 출력입니다. `strict_mode=true`이면 대체 공급자의 응답이 변경 없이 반환됩니다. 파트너가 생성을 바이트로 직접 응답하는 모델의 경우, 본문은 `application/json`이 아니라 파트너 자체의 `Content-Type` 아래에 있는 해당 바이트입니다. 응답 `Content-Type`을 기준으로 분기하고 JSON 문서라고 가정하지 마세요.

  본문: [`RouterModelOutput`](#routermodeloutput) 또는 원시 바이트(`*/*`). 헤더: `X-Comfy-Request-Id`, `X-Content-Type-Options`, `X-Comfy-Router-Fallback-Provider`, `X-Comfy-Router-Provider`, `X-Comfy-Router-Dropped-Params`, `X-Comfy-Credits-Used`, `Idempotent-Replayed`, `X-Committed-Spend-Limit`, `X-Committed-Spend-Current`, `X-Committed-Spend-Remaining`
</ResponseField>

<ResponseField name="400" type="RouterErrorResponse">
  잘못된 요청입니다. 오류 유형과 요청 본문을 확인하세요.

  본문: [`RouterErrorResponse`](#routererrorresponse). 헤더: `X-Comfy-Error-Type`, `X-Comfy-Request-Id`, `X-Comfy-Upstream-Status`, `X-Comfy-Upstream-Detail`, `X-Comfy-Refusal-Subject`, `Idempotent-Replayed`
</ResponseField>

<ResponseField name="401" type="RouterErrorResponse">
  자격 증명이 누락되었거나 유효하지 않습니다.

  본문: [`RouterErrorResponse`](#routererrorresponse). 헤더: `X-Comfy-Error-Type`, `X-Comfy-Request-Id`

Seedance의 첫 프레임 이미지는 이미지 기반 비디오 생성을 선택하고, 레퍼런스 이미지나 클립은 레퍼런스 기반 비디오 생성을 선택합니다). 네이티브 디스패치에서 Seedance 요청은 역할이 아니라 `content`의 미디어 종류에 따라 과금됩니다. 비디오 입력이 있으면 비디오 기반 비디오 생성으로, 그렇지 않고 이미지가 있으면 이미지 기반 비디오 생성으로, 그 외에는 텍스트 기반 비디오 생성으로 과금됩니다. 단, `draft_task` 항목의 최종 렌더는 그것이 렌더링하는 Draft의 작업으로 과금되며, 일부 모델은 텍스트 기반 비디오 생성과 이미지 기반 비디오 생성에 같은 요율을 부과합니다. `model_provider`로 대체 공급자를 선택하면 조건화된 각 작업은 해당 공급자의 자체 요율로 과금될 수 있습니다. 동일한 공급자 선택 규약이 디스패치 시 적용됩니다. `model_provider`가 없거나, `model_provider`와 함께 `strict_mode=false`(기본값)인 경우 본문은 모델의 네이티브 문서이며 실행이 접수되기 전에 모델 자체의 입력 스키마에 대해 검증됩니다. 따라서 모델이 거부할 본문은 몇 분 후에 실패하는 대기 중 요청이 아니라 여기에서 `422`가 됩니다. 비엄격 대체 공급자 본문은 디스패치 시 해당 공급자의 실제 스키마로 추가 변환됩니다. `strict_mode=true`인 경우 본문은 이미 대체 공급자 자체의 스키마여야 하며 변경 없이 전달됩니다. 네이티브 스키마 검증은 동기 경로에서와 정확히 마찬가지로 건너뜁니다(`model_provider`와 `strict_mode` 참조).

**제출된 요청 하나의 실행 대기열 상태를 조회합니다.**

폴링 엔드포인트입니다. 요청의 현재 상태만 응답하며 결과는 절대 담지 않으므로, 클라이언트는 매 폴링마다 출력을 전송받지 않고도 오래 걸리는 생성을 지켜볼 수 있습니다. 결과는 이 응답이 `COMPLETED`일 때 아래의 조회 엔드포인트에서 한 번만 수집합니다.

**파라미터**

<ParamField path="provider" type="RouterProviderSegment" required>
  정규 `{provider}/{model}` 모델 ID의 소문자 공급자 세그먼트로, 모델을 실행하는 파트너입니다.

  유형: [`RouterProviderSegment`](#routerprovidersegment) -- 영숫자 슬러그, 예: `anthropic`, 최대 64자

<ParamField path="model" type="RouterModelSegment" required>

## 오류 버킷

기계가 읽을 수 있는 Router 오류 카테고리이며, `X-Comfy-Error-Type` 헤더로도 전송됩니다.

### 요청 수준 버킷

Router가 요청을 접수한 뒤 완료하지 못한 경우 발생합니다.

| `error_type` | 의미 |
| --- | --- |
| `invalid_input` | 요청이 모델에 도달하기 전에 거부되었습니다. 형식이 잘못된 본문, 형식이 잘못되었거나 만료된 페이지네이션 커서, 모델 자체 스키마가 허용하지 않는 입력, 또는 이 요청에 사용할 수 없는 `Idempotency-Key`(다른 요청에 이미 사용되었거나(방법, 경로와 쿼리, 또는 본문이 다름) 응답을 재생할 수 없는 호출에 이미 소비된 경우)입니다. |
| `content_policy_violation` | 공급자가 콘텐츠 정책을 이유로 요청을 거부했습니다. |
| `provider_error` | 파트너 공급자가 자체적인 실패를 보고했거나, Router가 결과로 해석할 수 없는 응답을 반환했습니다. |
| `provider_timeout` | 파트너 공급자가 자체 마감 시간 내에 응답하지 않았습니다. |
| `insufficient_credits` | 호출한 워크스페이스에 모델을 실행할 크레딧이 충분하지 않습니다. |
| `model_not_found` | `{provider}/{model}` ID가 Router가 실행할 수 있는 모델을 가리키지 않습니다. 알 수 없는 공급자, 등록되지 않은 ID, 카탈로그에서 서비스 종료 날짜가 지나 퇴출된 ID, 또는 공급자가 현재 Comfy용으로 제공하지 않는 카탈로그 ID입니다. |

### 전송 수준 버킷

모델 호출 이전이나 그 무렵에 Router 자체에서 발생합니다.

| `error_type` | 의미 |
| --- | --- |
| `unauthorized` | 요청에 사용할 수 있는 자격 증명이 없었습니다. |
| `forbidden` | 자격 증명은 유효하지만 이 모델이나 이 작업에 대한 권한이 없습니다. |
| `concurrency_limit_exceeded` | 워크스페이스에 이미 허용된 만큼의 호출이 진행 중입니다. 그중 하나가 끝나면 다시 시도하세요. |
| `client_disconnected` | Router가 결과를 반환하기 전에 호출자가 연결을 닫았습니다. |
| `internal_error` | Router 자체가 실패했습니다. |
| `deadline_exceeded` | 응답이 도착하기 전에 Comfy가 자체적으로 설정된 한도에서 연결 유지를 중단했습니다. |
| `not_enabled` | 이 호출자에 대해서는 Comfy Router가 아직 활성화되지 않았습니다. |
| `service_unavailable` | Comfy Router가 의존하는 서비스가 일시적으로 사용할 수 없으며, 호출자는 아무 잘못도 하지 않았습니다. |
| `rate_limited` | 호출자가 창을 기준으로 측정되는 허용량을 모두 소진했으며, 해당 창이 넘어갈 때까지 기다려야 합니다. |
| `cancelled` | 대기 중이던 요청이 결과를 생성하기 전에 취소 경로를 통해서든 운영자에 의해서든 철회되었습니다. 이는 터미널 상태이며, 그 자체로 요금 청구에 대한 진술은 아닙니다. |
| `queue_timeout` | 대기 중인 요청이 실행 대기열 타임아웃을 넘겨 대기했지만 결국 승인되지 않았습니다. |
| `request_not_found` | `request_id`가 이 모델에서 호출자의 요청 중 어느 것도 가리키지 않습니다. |
| `queue_backlog_full` | 호출자에게 이미 실행을 기다리는 대기 중 요청이 너무 많아 이 제출이 거부되었습니다. |

## 실행 전 비용 추정

`POST /v2/models/{provider}/{model}/estimate`는 본문을 실행하지 않고 가격을 산정하며, 대기 중 제출(`POST /v2/models/{provider}/{model}/requests`)은 `201` 응답에서 `estimate`와 동일한 [`RouterCostEstimate`](#routercostestimate)를 반환합니다. 둘 다 Comfy가 해당 실행에 청구하는 요율 카드를 기준으로 가격이 산정됩니다. 어느 쪽이 반환하든 모든 수치는 추정치이며 최종 청구액이 아닙니다. 워크스페이스의 사용량 및 청구 기록에 있는 확정 청구액이 최종입니다. 자체 공급자 키로 실행한 경우에는 Comfy가 청구하지 않습니다(아래 참조). 추정 기능이 점진적으로 배포되는 동안에는 이 경로가 `error_type: not_enabled`와 함께 `403`을 응답하고, 제출 응답에서는 `estimate`가 생략됩니다. 카탈로그에는 여전히 가격이 없습니다.

어떤 금액보다도 `source`를 먼저 확인하세요. 수치가 누락되었다고 해서 무료라는 뜻은 결코 아닙니다.

| `source` | 포함하는 항목 | 해석 방법 |
| --- | --- | --- |
| `exact` | `amount`, `amount_cents`, `credits` | `pricing_as_of`의 요율로 이 본문에 대해 청구되는 금액과 같은 추정치입니다. 워크스페이스의 사용량 및 청구 기록에 있는 확정 청구액이 최종입니다. |
| `estimated` | `min_amount`, `max_amount` 및 각각의 `_cents` 형태, `amount` 없음 | 요금이 공급자가 나중에 보고하는 수량에 따라 달라지고 본문이 그 범위를 정하는 추정치입니다. 청구액은 두 경계 사이가 될 것으로 예상되며, 워크스페이스의 사용량 및 청구 기록에 있는 확정 청구액이 최종입니다. |
| `unknown` | `reason`, 수치 없음 | 실행 전에는 가격을 제시할 수 없습니다. 다른 모든 `source` 값은 `unknown`으로 취급하세요. |

`unknown` 추정의 `reason`은 다음 중 하나입니다.

- `not_quotable`: Router가 실행 전에 이 호출의 가격을 산정할 수 없습니다. 본문이 범위를 정하지 않은, 공급자가 나중에 보고하는 수량을 기준으로 청구되거나, 본문을 전송된 그대로 가격 산정할 수 없기 때문입니다. 인식되지 않는 `reason`은 모두 `not_quotable`로 취급하세요.
- `unpriced_model`: 요율 카드에 이 요청의 가격이 없습니다.
- `byok`(대기 중 제출 전용): 자체 공급자 키로 실행하므로 Comfy는 이에 대해 아무것도 청구하지 않습니다.
- `pricing_unavailable`(대기 중 제출 전용): 요청이 접수될 때 요율 카드를 읽을 수 없었습니다. 제출은 그대로 수락되며 실행은 평소와 같이 청구됩니다.

Router가 실행 전에 아직 가격을 산정할 수 없는 모델은 [실행 전 추정이 없는 모델](/ko/development/comfy-router/limitations#사전-견적이-없는-모델)에 나열되어 있습니다. 목록에 없는 모델도 특정 본문에 대해서는 `unknown`을 응답할 수 있으므로, 모든 추정에서 `source`를 확인하세요.

추정이 실패 시 안전하게 닫히는 지점:

- 수치를 내려면 요율 카드가 필요한데 카드가 로드되지 않았거나 오래된 경우, `/estimate`는 추측 대신 `503`을 응답합니다. 대기 중 제출은 추정 때문에 거부되는 일이 없으며, 대신 `reason: pricing_unavailable`과 함께 `source: unknown`을 포함합니다. 실행 전에 전혀 가격을 산정할 수 없는 호출(`not_quotable`)이나 자체 공급자 키를 사용하는 대기 중 제출(`byok`)은 카드를 읽지 않고 응답하므로, 그 `200`은 카드가 최신인지에 대해 아무것도 말해주지 않습니다.
- `/estimate`는 기본 실행과 마찬가지로 모델 자체의 입력 스키마에 대해 본문을 검증하므로, 모델 스키마를 통과하지 못하는 본문은 실행이 응답했을 것과 동일한 `detail[]` 형태의 동일한 `422`를 받습니다. 가격 산정도 디스패치도 이루어지지 않습니다.
- 대기 중 제출의 멱등 재실행(`Idempotent-Replayed: true`)은 원본 견적이 저장되지 않으므로 `estimate`를 생략합니다.

추정의 한계. `200` 수치가 실행이 수락된다거나 정확히 그 금액이 청구된다는 약속은 아닙니다.

- `/estimate`는 `strict_mode`나 `reject_unknown_fields`를 받지 않으므로 모델의 네이티브 계약만 검사합니다. `strict_mode=true` 실행이 대체 공급자 자체 스키마에서 수락하는 본문이 여기서는 `422`를 받을 수 있고, `reject_unknown_fields=true` 실행이라면 거부했을 선언되지 않은 최상위 필드도 여기서는 가격이 산정됩니다.
- `pricing_as_of`는 요율 카드를 가져온 시점입니다(카드를 읽지 않은 경우에는 추정이 응답된 시점). 이는 가격 고정이 아닙니다. 실행은 요율이 적용되는 시점에 유효한 요율로 청구됩니다.
- `/estimate`는 `model_provider`가 지정한 레그, 또는 네이티브 공급자의 가격을 제시합니다. `fallback_provider`나 `strict_mode` 매개변수는 받지 않습니다. 폴백 재시도가 다른 공급자로 넘어간 동기 실행은 그 공급자의 요율로 청구되며, 추정은 이를 제시하지 않았습니다. 실행 응답의 `X-Comfy-Router-Fallback-Provider`가 그런 일이 있었음을 알려줍니다. 대기 중 제출에는 폴백이 없으므로 그 `estimate`는 실제로 실행되는 레그의 가격을 제시합니다.
- `/estimate`와 대기 중 제출의 `estimate`는 `model_provider` 레그에서 동일한 본문에 대해, 또는 형제 작업에서 실행되는 본문에 대해 약간 다른 문서의 가격을 산정할 수 있습니다. 제출의 `estimate`는 실행이 전송하는 문서를 기준으로 가격이 산정됩니다.
- `/estimate`는 항상 플랫폼 요금을 제시합니다. 자체 공급자 키로 실행한 경우 Comfy는 청구하지 않지만, `/estimate`는 이를 감지하지 못하고 여전히 수치를 반환합니다. `reason: byok`를 응답하는 것은 대기 중 제출뿐입니다.
- 달러는 반올림되지 않은 센트에서 최대 소수점 8자리로 표시되며, 청구 가능한 1센트 미만의 `amount`가 `0`으로 표시되는 일은 없습니다. `credits`는 `round(amount × 211, 2)`로, `X-Comfy-Credits-Used`가 요금에 적용하는 것과 동일한 변환입니다. 따라서 0이 아닌 아주 작은 가격에서 `credits`가 `0`으로 반올림될 수 있습니다. 이것이 중요한 경우에는 `credits`가 아니라 `amount` 또는 `amount_cents`를 기준으로 예산을 세우세요. 해당 헤더는 실행에 대한 사후 수치로 남으며, 잔액은 Comfy 플랫폼에 있습니다.

## 결과 에셋

모델은 에셋 URL, 인라인 바이트, 또는 둘 다를 반환할 수 있습니다. 아래 공급자는 선택된 에셋을 Comfy 스토리지로 복사하고 해당 URL을 대체합니다. 이 동작은 모델에 따라 다르며, 이를 선택하는 요청 헤더는 없습니다.

| 모델 | Comfy 스토리지로 복사되는 항목 | Comfy 호스팅 URL 최대 수명 |
| --- | --- | --- |
| `bfl/*` | 완료된 에셋, 그리고 결과에 포함된 경우 드래프트 캐시 에셋 | 24시간 |
| `byteplus/*` 비디오 모델 (`seedance`, `dreamina-seedance`) | 완료된 비디오, 그리고 결과에 포함된 경우 마지막 프레임 이미지 | 24시간 |
| `minimax/*` | 완료된 비디오 | 12시간 |
| `xai/*` | 생성된 모든 이미지, 그리고 완료된 비디오 | 24시간 |

이 수명은 URL에 서명될 때 시작되며, URL을 열 때 시작되는 것이 아닙니다. 캐시되었거나 재생된 URL은 남은 시간이 더 적을 수 있으며, 재생해도 수명이 갱신되지 않습니다. 에셋을 즉시 다운로드하세요. 각 행에 명시된 에셋만 복사됩니다. `byteplus/seedream-*` 및 `byteplus/seededit-*` 이미지는 BytePlus 비디오 행에 포함되지 않습니다.

복사는 해당 모델의 네이티브 공급자만 수행합니다. 대체 공급자가 처리한 실행, 즉 `model_provider`가 대체 공급자를 지정한 경우나 폴백 재시도가 대체 공급자에 도달한 네이티브 실행(`X-Comfy-Router-Fallback-Provider`로 공개됨)은 해당 공급자 자체의 URL을 반환하며, 이 URL은 공급자의 만료 정책을 따르고 복사되지 않습니다. `model_provider` 값 `default`, `comfy`, `comfyui`는 대체 공급자를 지정하지 않으므로 해당 실행은 네이티브이며 위와 같이 복사됩니다. 폴백 재시도가 다시 네이티브 공급자에 도달한 `model_provider` 실행도 마찬가지입니다.

**Veo(`veo/*`)는 별도의 스토리지 경로를 사용합니다.** `response.videos[]`에서 존재하는 멤버를 읽으세요. `bytesBase64Encoded`는 클립을 인라인으로 담고 있으며, `gcsUri`는 환경이 공급자의 Comfy 스토리지 직접 쓰기에 맞게 구성된 경우 Comfy가 서명한 HTTPS 링크를 담고 있습니다. 해당 링크는 응답 시점부터 24시간 동안 유효합니다. 후자의 경우 에셋을 복사하는 대신 직접 쓰기 때문에 Veo는 재호스팅 표에 포함되지 않습니다.

다른 모델은 공급자 에셋 참조 또는 인라인 바이트를 반환합니다. 공급자 URL은 공급자의 만료 정책을 따르며, 이는 위 수명보다 훨씬 짧을 수 있고 Router 계약에 명시되어 있지 않습니다.

복사는 에셋별 최선 노력 방식으로 수행됩니다. 복사 하나가 실패하면 해당 항목은 공급자 참조를 유지합니다. 응답에는 Comfy URL과 공급자 URL이 모두 포함될 수 있으며, 에셋별 복사 상태 필드는 명시적으로 없습니다. 생성은 여전히 성공하며 과금됩니다. 성공적으로 재호스팅된 에셋 하나로 모든 URL의 수명을 추론하지 마세요.

결과가 Comfy 호스팅인지 여부는 완료된 호출을 나중에 해당 `Idempotency-Key` 레코드에서 재생할 수 있는지도 결정합니다. 위의 `Idempotency-Key` 매개변수는 재생할 수 없을 때 재시도에 무엇이 응답되는지 설명합니다.

## 모델별 입력 및 출력 스키마

각 모델의 필드는 `GET /v2/models/{provider}/{model}/openapi.json`에서 확인할 수 있습니다. 이 호출에는 API 키가 필요합니다. 스키마가 작성된 모든 모델에 대해 동일한 문서가 이 사이트에도 인증 없이 `/router-schemas/{provider}/{model}.json`에서 게시됩니다. 이 복사본은 마지막 문서 업데이트 시점에 캡처한 스냅샷이므로, 두 문서가 다를 경우 엔드포인트가 우선합니다. 오퍼레이션의 `requestBody`는 입력 검증을 설명하고, `200` 응답은 스키마가 작성된 경우 출력 형태와 미디어 타입을 설명합니다. `x-comfy-input-schema-authored`가 false이면 Router는 모델별 사전 검증 없이 모든 JSON 객체를 허용합니다. 공급자 요구 사항은 여전히 적용됩니다. 출력 스키마는 결과를 설명하며, Router는 반환된 공급자 페이로드를 스키마와 대조하여 검증하지 않습니다. 스키마가 작성되지 않은 출력은 `application/json` 대신 `*/*`를 사용할 수 있으므로, 디코딩하기 전에 응답 콘텐츠 타입을 확인하세요.

## 스키마

### RouterChargesOnPolicyRejection
이 모델에 대해 콘텐츠 정책 거부가 청구되는지 여부입니다. 알 수 없는 값은 청구될 수 있는 것으로 간주하세요.

유형: `string`

### RouterCostEstimate

이 호출에 드는 비용을 디스패치 이전에, 실행 시 과금되는 것과 동일한 요율표를 기준으로 산정한 사전 견적이며 미국 달러로 표시됩니다. 최종 청구 금액은 아닙니다. 실제로 지불하는 금액은 워크스페이스의 사용량 및 청구 기록에 있는 정산 금액입니다. 실행 이후에 보고되는 `X-Comfy-Credits-Used`는 반올림된 사후 수치이며 영수증이 아닙니다. `source`는 이 숫자를 얼마나 신뢰할 수 있는지 나타냅니다: `exact`는 `amount`를 포함하고, `estimated`는 `min_amount`와 `max_amount`를 포함하며 `amount`는 없고, `unknown`은 둘 다 없이 `reason`을 포함합니다. 누락된 `amount`를 무료로 해석하지 마세요. 가격 고정이 아닙니다. `pricing_as_of`를 참고하세요.

</ResponseField>
