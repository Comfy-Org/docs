Comfy Router의 정식 라우트로, 모델 ID로 주소가 지정됩니다.

기본 URL: `https://api.comfy.org`

아래의 모든 엔드포인트에는 인증이 필요합니다. `X-API-Key: <api-key>` 또는 `Authorization: Bearer <jwt>`를 전송하십시오.

Comfy API 키는 Bearer 토큰으로도 전송할 수 있습니다. 두 자격 증명 헤더를 모두 제공하면 `X-API-Key`가 우선합니다. 키와 JWT의 구분은 [인증 헤더](/ko/development/comfy-router/headers#요청-헤더)를, 액세스 요구 사항은 [퀵스타트](/ko/development/comfy-router/quickstart)를 참고하십시오.

## 엔드포인트

### `GET /v2/models`

**Comfy Router에서 실행할 수 있는 모델을 나열합니다.**

사용 가능한 모델 ID와 과금 정보를 나열합니다. `has_more`가 참인 동안 `next_cursor`를 사용하세요.

**파라미터**

<ParamField query="cursor" type="RouterPageCursor">
  불투명 페이지네이션 커서입니다.

  Type: [`RouterPageCursor`](#routerpagecursor): `next_cursor`로 반환되는 불투명 커서, 1–512자
</ParamField>

<ParamField query="limit" type="integer">
  한 페이지에 반환할 모델 수입니다.

  최대 100, 기본값: 20
</ParamField>

<ParamField header="If-None-Match" type="string">
  호출자가 이전 `200` 응답에서 보유한 `ETag`입니다.
</ParamField>

**응답**

<ResponseField name="200" type="RouterModelListResponse">
  OK: 모델 카탈로그의 한 페이지입니다.

  본문: [`RouterModelListResponse`](#routermodellistresponse) -- 헤더: `X-Comfy-Request-Id`, `ETag`, `Cache-Control`
</ResponseField>

<ResponseField name="304" type="no body">
  Not Modified: 호출자가 `If-None-Match`에 담아 보낸 `ETag` 이후로 페이지가 변경되지 않았습니다.

  헤더: `X-Comfy-Request-Id`, `ETag`, `Cache-Control`
</ResponseField>

<ResponseField name="400" type="RouterErrorResponse">
  잘못된 요청입니다. 오류 유형과 요청 본문을 확인하세요.

  본문: [`RouterErrorResponse`](#routererrorresponse) -- 헤더: `X-Comfy-Error-Type`, `X-Comfy-Request-Id`
</ResponseField>

<ResponseField name="401" type="RouterErrorResponse">
  자격 증명이 누락되었거나 유효하지 않습니다.

  본문: [`RouterErrorResponse`](#routererrorresponse) -- 헤더: `X-Comfy-Error-Type`, `X-Comfy-Request-Id`
</ResponseField>

<ResponseField name="403" type="RouterErrorResponse">

  본문: [`RouterErrorResponse`](#routererrorresponse) -- 헤더: `X-Comfy-Error-Type`, `X-Comfy-Request-Id`
</ResponseField>

<ResponseField name="429" type="RouterErrorResponse">

  본문: [`RouterErrorResponse`](#routererrorresponse) -- 헤더: `X-Comfy-Error-Type`, `X-Comfy-Request-Id`, `Retry-After`
</ResponseField>

<ResponseField name="503" type="RouterErrorResponse">
  Router를 일시적으로 사용할 수 없습니다. 백오프를 두고 재시도하세요.

  본문: [`RouterErrorResponse`](#routererrorresponse) -- 헤더: `X-Comfy-Error-Type`, `X-Comfy-Request-Id`
</ResponseField>

### `POST /v2/models/{provider}/{model}`

**정규 모델 ID로 파트너 모델을 동기적으로 실행합니다.**

모델을 실행하고 완료된 결과를 같은 응답에서 받습니다.

**파라미터**

<ParamField path="provider" type="RouterProviderSegment" required>
  정규 `{provider}/{model}` 모델 ID의 공급자 부분입니다.

  타입: [`RouterProviderSegment`](#routerprovidersegment) -- 영숫자 슬러그, 예: `anthropic`, 최대 64자
</ParamField>

<ParamField path="model" type="RouterModelSegment" required>
  정규 `{provider}/{model}` 모델 ID의 모델 부분입니다.

  타입: [`RouterModelSegment`](#routermodelsegment) -- 영숫자 슬러그, 예: `claude-opus-4-6`, 최대 128자
</ParamField>

<ParamField header="Idempotency-Key" type="string">
  하나의 논리적 호출을 재시도해도 안전하게 만드는 호출자 생성 키입니다.

  1–255자
</ParamField>

<ParamField query="model_provider" type="string">
  이 모델을 서비스할 대체 공급자를 현재 기본값 대신 선택합니다. `fal`, `wavespeed`, `runware`, `higgsfield`가 대체 공급자이며, `GET /v2/models/{provider}/{model}`은 특정 모델이 이들 중 어느 것을 지원하는지 보고합니다. 이 파라미터의 거부는 고정된 순서로 검사되며, 앞선 거부는 뒤의 거부 해당 여부와 무관하게 응답합니다. 등록된 공급자가 전혀 아닌, 인식되지 않는 값은 `400`으로 거부됩니다. 그다음, 본문이 멀티파트 작업(편집)을 선택하는 요청에서 대체 공급자는 `detail`이 "this request's `image` selects the edit operation"으로 시작하는 `409`로 거부되지만, 해당 공급자의 이 모델에 대한 변환기가 그 작업을 처리할 수 없을 때만 그렇습니다. 미디어를 실제로 전달하는 변환기를 가진 레그는 정상적으로 진행됩니다. 그다음, 자체 키(BYOK) 자격 증명을 확인한 요청에서는 해당 공급자가 이 모델을 서비스하는지와 무관하게 모든 대체 공급자가 `detail`이 `this request resolved a BYOK credential`로 시작하는 `409`로 거부됩니다(해당 응답 참조). 그다음, 명명된 공급자 자체의 게이트가 검사되며, 이 게이트는 해당 공급자가 귀하에게 활성화되지 않은 경우 `error_type: not_enabled`와 함께 `403`으로, 게이트를 평가할 수 없는 경우 `error_type: service_unavailable`과 함께 `503`으로 거부합니다. 그리고 이 네 가지를 모두 통과한 뒤에야 이 모델에 대한 레그가 없는 실제 공급자가 `error_type: invalid_input`과 함께 `400`으로 거부되며, 이는 인식되지 않는 값과 동일한 응답입니다. `fallback_provider`는 자체 키 요청에서, 본문이 멀티파트 작업을 선택하는 요청에서, 그리고 `strict_mode=true`인 경우 거부되지 않고 아무 효과도 없습니다.
</ParamField>

<ParamField query="strict_mode" type="boolean">
  `model_provider`와 함께 사용할 때만 의미가 있습니다.

  기본값: False
</ParamField>

<ParamField query="fallback_provider" type="string">
  첫 시도가 Router 또는 시도한 공급자에게 귀속되는 이유로 실패했을 때 Router가 이 호출을 모델의 다른 등록된 공급자에 대해 재시도할지 여부를 제어합니다. 생략하거나 `false` 이외의 값을 주면 폴백이 켜진 상태로 유지되며, `false`는 이를 끕니다. 폴백이 성공한 응답에는 `X-Comfy-Router-Fallback-Provider`가 포함됩니다. 자체 키 자격 증명을 확인한 요청에서는 이 파라미터의 값과 무관하게 폴백을 사용할 수 없습니다. 시도 자체가 이루어지지 않고 첫 실패가 그대로 전달되며, 이는 거부가 아니라 아무 효과도 없는 것입니다. 여기서 `409`가 발생하지는 않습니다. 같은 이유로 본문이 멀티파트 작업을 선택하는 요청과 `strict_mode=true`에서도 마찬가지입니다. 각각은 호출을 하나의 공급자에 묶어 다른 공급자에 대해 충실히 재현할 수 없게 하므로, 폴백은 거부되지 않고 단순히 건너뜁니다. 그 `409`로 거부되는 것은 명시적인 `model_provider`뿐이며, 이 무조건적 건너뛰기와 달리 멀티파트 `409`는 변환기가 그 작업을 처리할 수 없는 레그에만 적용됩니다.
</ParamField>

<ParamField query="reject_unknown_fields" type="boolean">
  이 모델의 입력 스키마가 선언하지 않은 최상위 요청 본문 필드를 수용하는 대신 거부하도록 선택합니다. 중첩 필드는 검사하지 않으며, 선언되지 않은 필드를 허용하는 스키마를 가진 모델이나 작성된 스키마가 없는 모델, 또는 `strict_mode=true`로 보낸 대기 중 제출에서는 아무것도 거부되지 않습니다.

  기본값: False
</ParamField>

**요청 본문**

`application/json` -- [`RouterModelInput`](#routermodelinput) (필수)

파트너 모델의 네이티브 JSON 입력입니다. `model_provider`가 없으면 이 본문은 모델 자체의 네이티브 스키마이며, 모델 자체의 공급자가 호출을 처리할 때 호출자의 `strict_mode`는 아무것도 바꾸지 않습니다. Comfy Router 자체가 그러한 호출을 다른 공급자로 라우팅하면 Router는 해당 공급자를 위해 본문을 변환하며, 그곳에서 `strict_mode`가 어떻게 적용되는지는 이 계약의 일부가 아닙니다. `model_provider`가 대체 공급자를 선택하고 `strict_mode=false`(기본값)인 경우, 본문은 전송되기 전에 해당 공급자의 실제 스키마로 변환됩니다. 정확히 표현할 수 없는 네이티브 필드는 삭제되고 응답의 `X-Comfy-Router-Dropped-Params` 헤더를 통해 고지되며, 조용히 처리되는 일은 없습니다. `model_provider`가 대체 공급자를 선택하고 `strict_mode=true`이면 변환이 실행되지 않습니다. 본문은 이 모델의 네이티브 스키마가 아니라 이미 해당 대체 공급자 자체의 실제 스키마여야 하며(`strict_mode` 참조), 변경 없이 전달됩니다. 본문 자체의 필드는 Router가 두 가지 이상의 작업을 지원하는 모델에서 어떤 작업을 실행할지도 선택합니다. 편집 가능한 이미지 모델의 경우 입력 이미지를 포함하면 텍스트 기반 이미지 생성에서 이미지 기반 이미지 생성(편집) 작업으로 전환되며, 이 작업은 자체 요율로 과금될 수 있습니다. Seedance 비디오 모델의 경우 `content[].role`이 작업을 선택합니다(첫 프레임 이미지는 이미지 기반 비디오 생성을 선택하고, 레퍼런스 이미지 또는 클립은 레퍼런스 기반 비디오 생성을 선택합니다). 모델 자체의 공급자가 호출을 처리할 때 Seedance 청구는 역할이 아니라 `content`의 미디어 종류를 따릅니다. 비디오 입력이 하나라도 있는 요청은 비디오 기반 비디오 생성으로 청구되고, 그렇지 않고 이미지가 하나라도 있으면 이미지 기반 비디오 생성으로, 그 외에는 텍스트 기반 비디오 생성으로 청구됩니다. 단, `draft_task` 항목의 최종 렌더는 렌더링하는 Draft의 작업으로 청구됩니다. 일부 모델은 텍스트 기반 비디오 생성과 이미지 기반 비디오 생성에 동일한 요율을 청구합니다. `model_provider`가 대체 공급자를 선택하는 경우, 또는 Comfy Router가 다른 공급자에서 호출을 처리하는 경우, 조건이 지정된 각 작업은 해당 공급자 자체의 요율로 과금될 수 있습니다.

`application/json`: [`RouterModelInput`](#routermodelinput) (필수)

Seedance 첫 프레임 이미지는 이미지 기반 비디오 생성을 선택하고, 레퍼런스 이미지 또는 클립은 레퍼런스 기반 비디오 생성을 선택합니다). 모델 자체 공급자가 호출을 서비스할 때 Seedance 요청은 역할이 아니라 `content`의 미디어 종류에 따라 청구됩니다. 비디오 입력이 있으면 비디오 기반 비디오 생성으로 청구되고, 그렇지 않고 이미지가 있으면 이미지 기반 비디오 생성으로, 그 외에는 텍스트 기반 비디오 생성으로 청구됩니다. 단, `draft_task` 항목의 최종 렌더는 렌더링하는 Draft의 작업으로 청구되며, 일부 모델은 텍스트 기반 비디오 생성과 이미지 기반 비디오 생성에 동일한 요율을 부과합니다. `model_provider`로 대체 공급자를 선택하거나 Comfy Router가 다른 공급자에서 호출을 서비스하는 경우, 각 조건이 적용된 작업은 해당 공급자의 자체 요율로 과금될 수 있습니다. 동일한 공급자 선택 계약이 디스패치 시점에도 적용됩니다. `model_provider`가 없거나, `model_provider`와 `strict_mode=false`(기본값)를 함께 사용하는 경우 본문은 모델의 네이티브 문서이며 실행이 수락되기 전에 모델 자체 입력 스키마에 대해 검증됩니다. 따라서 모델이 거부할 본문은 몇 분 후 실패하는 대기열 요청이 아니라 여기서 `422`가 됩니다. 비엄격 모드의 대체 공급자 본문은 디스패치 시 해당 공급자의 실제 스키마로 추가 변환됩니다. `strict_mode=true`이면 본문은 이미 대체 공급자 자체 스키마여야 하며 변경 없이 전달됩니다. 네이티브 스키마 검증은 동기 라우트에서와 정확히 마찬가지로 건너뜁니다(`model_provider` 및 `strict_mode` 참조).

### `PUT /v2/models/{provider}/{model}/requests/{request_id}/cancel`

**제출된 요청 하나에 대한 취소를 요청합니다.**

아직 완료되지 않은 요청을 중지하도록 Comfy에 요청합니다. 이는 요청일 뿐 보장이 아니며, `202`는 바로 그 점을 나타냅니다. `CANCELLATION_REQUESTED`는 요청이 접수되었다는 뜻이지 실행이 중지되었다는 뜻이 아닙니다. 이미 파트너에게 전달되어 진행 중인 실행은 그대로 완료될 수 있으며, 완료된 파트너 생성은 누군가 결과를 수집했는지 여부와 관계없이 과금됩니다. 따라서 실제로 무슨 일이 일어났는지 알아야 하는 호출자는 이후에 상태 엔드포인트를 조회해야 하며, 이때 효력이 발생한 취소는 다른 모든 최종 결과와 마찬가지로 `error_type`을 담은 `COMPLETED`로 나타납니다.

**파라미터**

## 오류 버킷

기계가 읽을 수 있는 Router 오류 카테고리이며, `X-Comfy-Error-Type` 헤더로도 전송됩니다.

### 요청 수준 버킷

Router가 요청을 접수한 뒤 완료하지 못한 경우 발생합니다.

| `error_type` | 의미 |
| --- | --- |
| `invalid_input` | 요청이 모델에 도달하기 전에 거부되었습니다. 원인은 형식이 잘못된 본문, 형식이 잘못되었거나 만료된 페이지네이션 커서, 모델 자체 스키마가 허용하지 않는 입력, 또는 이 요청에 사용할 수 없는 `Idempotency-Key`(다른 요청에 이미 사용되어 방법, 경로와 쿼리 또는 본문이 다르거나, 응답을 재생할 수 없는 호출에서 이미 소비된 경우)입니다. |
| `content_policy_violation` | 공급자가 콘텐츠 정책을 이유로 요청을 거부했습니다. |
| `provider_error` | 파트너 공급자가 자체적인 실패를 보고했거나, Router가 결과로 해석할 수 없는 응답을 반환했습니다. |
| `provider_timeout` | 파트너 공급자가 자체 마감 시간 내에 응답하지 않았습니다. |
| `insufficient_credits` | 호출한 워크스페이스에 모델을 실행할 크레딧이 충분하지 않습니다. |
| `model_not_found` | `{provider}/{model}` ID가 Router가 실행할 수 있는 모델을 가리키지 않습니다. 알 수 없는 공급자, 등록되지 않은 ID, 카탈로그에서 서비스 종료 날짜가 지나 퇴출된 ID, 또는 공급자가 현재 Comfy용으로 제공하지 않는 카탈로그 ID입니다. |
| `byok_credential_rejected` | 이 호출에 제공된 키를 공급자가 거부했습니다. |

### 전송 수준 버킷

모델 호출 이전이나 그 무렵에 Router 자체에서 발생합니다.

| `error_type` | 의미 |
| --- | --- |
| `unauthorized` | 요청에 사용할 수 있는 자격 증명이 없었습니다. |
| `forbidden` | 자격 증명은 유효하지만 이 모델이나 이 작업에 대한 권한이 없습니다. |
| `concurrency_limit_exceeded` | 워크스페이스에 이미 허용된 만큼의 호출이 진행 중입니다. 그중 하나가 끝나면 다시 시도하세요. |
| `client_disconnected` | Router가 결과를 반환하기 전에 호출자가 연결을 닫았습니다. |
| `internal_error` | Router 자체가 실패했습니다. |
| `deadline_exceeded` | 응답이 도착하기 전에 Comfy가 자체 구성된 한도에 도달하여 연결 유지를 중단했습니다. |
| `not_enabled` | 이 호출자에 대해서는 Comfy Router가 아직 활성화되지 않았습니다. |
| `service_unavailable` | Comfy Router가 의존하는 서비스가 일시적으로 사용할 수 없으며, 호출자는 아무 잘못도 하지 않았습니다. |
| `rate_limited` | 호출자가 창을 기준으로 측정되는 허용량을 모두 소진하여 해당 창이 넘어갈 때까지 기다려야 하거나, 모델 공급자가 생성을 시작하기 전에 호출을 제한한 경우입니다. |
| `cancelled` | 대기 중이던 요청이 결과를 생성하기 전에 취소 경로를 통해서든 운영자에 의해서든 철회되었습니다. 이는 터미널 상태이며, 그 자체로 요금 청구에 대한 판단은 아닙니다. |
| `queue_timeout` | 대기 중인 요청이 실행 대기열 타임아웃을 넘겨 대기했지만 결국 승인되지 않았습니다. |
| `request_not_found` | `request_id`가 이 모델에서 호출자의 요청 중 어느 것도 가리키지 않습니다. |
| `queue_backlog_full` | 호출자에게 이미 실행을 기다리는 대기 중 요청이 너무 많아 이 제출이 거부되었습니다. |
| `result_expired` | 요청은 존재했고 완료되었지만, 그 결과가 더 이상 저장되지 않아 수집 시 반환할 것이 없습니다. |

<ResponseField name="Retry-After" type="integer">

  전송되는 응답: `503`
</ResponseField>

<ResponseField name="Retry-After" type="integer">
  대기 중인 이 요청을 다시 폴링하기 전에 대기할 시간(초)입니다.

  전송되는 응답: `200`, `202`
</ResponseField>

<ResponseField name="Retry-After" type="integer">
  `error_type: rate_limited`를 담은 `429` 이후에 다른 요청을 보내기 전에 대기할 시간(초)입니다. 즉, 호출자의 분당 요청 허용량이 요청을 하나 더 받아들일 수 있을 만큼 다시 채워질 때까지의 시간입니다.

  전송되는 응답: `429`
</ResponseField>

<ResponseField name="Retry-After" type="integer">
  동일한 `Idempotency-Key`로 같은 요청을 재시도하기 전에 대기할 시간(초)입니다.

  전송되는 응답: `409`, `502`, `504`
</ResponseField>

<ResponseField name="X-Comfy-Credits-Used" type="string">
  이 실행에 소요된 비용을 Comfy 크레딧으로 나타낸 것으로, 청구 자체가 산정되는 것과 동일한 요율표를 기준으로 계산됩니다. 따라서 호출자는 자체 가격표를 갖출 필요가 없으며, 청구되는 호출이 두 번 이상 발생한 실행에서는 마지막 호출의 값이 아니라 그 합계입니다.
</ResponseField>

<ResponseField name="X-Comfy-Error-Type" type="RouterErrorType">
  실패를 나타내는 대략적인 기계 판독 가능 분류로, Router가 모든 오류 응답에 설정합니다.

  유형: [`RouterErrorType`](#routererrortype)
</ResponseField>

<ResponseField name="X-Comfy-Estimate-Source" type="string">
  `status`가 `IN_PROGRESS`인 동안의 상태 조회에서만 `X-Comfy-Estimated-Duration-Seconds`와 함께 전송됩니다. 해당 생성 소요 시간 추정치의 출처(비용 추정치의 `source`가 아님)를 나타내며, `historical`(최근 실행에서 측정됨) 또는 `default`(미디어 종류별 대체값으로, 최근 실행 기록이 너무 적을 때 사용됨)입니다.
</ResponseField>

<ResponseField name="X-Comfy-Estimated-Duration-P90-Seconds" type="integer">
  `status`가 `IN_PROGRESS`인 동안의 상태 조회에서만 `X-Comfy-Estimated-Duration-Seconds`와 함께 전송됩니다. 해당 생성 소요 시간 추정치의 90번째 백분위수를 정수 초로 나타낸 값입니다.
</ResponseField>

<ResponseField name="X-Comfy-Estimated-Duration-Seconds" type="integer">
  `status`가 `IN_PROGRESS`인 동안의 상태 조회에서만 전송됩니다. 공급자가 생성을 수락한 뒤 생성 전체 실행에 걸리는 시간에 대한 Router의 추정치를 정수 초로 나타낸 것으로, 남은 시간이 아니며 `IN_QUEUE`에서 보낸 시간은 절대 포함하지 않습니다.
</ResponseField>

<ResponseField name="X-Comfy-Refusal-Subject" type="string">
  콘텐츠 정책 거부가 어떤 입력 또는 출력에 관한 것인지를 Router 수준의 폐쇄된 어휘로 나타냅니다: `input`, `output`, `input_text`, `input_image`, `input_video`, `input_audio`, `output_text`, `output_image`, `output_video`, `output_audio`.
</ResponseField>

<ResponseField name="X-Comfy-Request-Id" type="string">
  이 호출에 대해 서버가 생성한 식별자로, 성공, 4xx, 5xx 응답 모두를 포함한 모든 Router 응답에 존재합니다. 오류 응답이야말로 사용자가 지원 요청에서 인용할 id가 필요한 바로 그 순간이기 때문입니다.
</ResponseField>

<ResponseField name="X-Comfy-Router-Dropped-Params" type="string">
  문자열 배열을 담은 JSON 인코딩된 단일 문자열입니다. 쉼표로 분할하지 말고 JSON 파서로 디코딩하세요. 전송되는 값은 쉼표로 구분된 OpenAPI 배열이 아니라 하나의 문자열이며, 각 항목은 자체적으로 쉼표를 포함하는 문장이기 때문입니다. 변환이 이 호출의 요청 본문을 생성했지만 해당 요청을 처리한 공급자에서 하나 이상의 네이티브 필드를 정확히 표현할 수 없었을 때마다 존재하며, 누락된 각 필드와 그 이유를 명시합니다. 호출자가 `model_provider`(`strict_mode=false`, 기본값)로 해당 변환을 요청했든 자동 `fallback_provider` 재시도가 이를 실행했든 마찬가지입니다.
</ResponseField>

<ResponseField name="X-Comfy-Router-Fallback-Provider" type="string">
  `fallback_provider`가 실제로 이 호출을 두 번째 공급자에 대해 재시도했고 그 재시도가 성공한 경우에만 공급자 이름과 함께 존재합니다. 최종적으로 호출을 처리한 공급자이며, 시도되었다가 함께 실패한 공급자는 절대 아닙니다.
</ResponseField>

<ResponseField name="X-Comfy-Router-Provider" type="string">
  이 호출을 처리한 Router 구간의 공급자로, 모든 성공적인 실행 응답에 존재합니다. `model_provider`를 지정하지 않은 호출을 처리하기 위해 Comfy Router가 선택한 공급자(모델 자체의 공급자 또는 Comfy가 라우팅한 다른 공급자), `model_provider`가 지정한 대체 공급자, 또는 `fallback_provider` 재시도가 도달한 공급자(이 경우에만 `X-Comfy-Router-Fallback-Provider`도 이를 명시함)입니다. 이는 Router가 디스패치한 구간이며 출력을 생성한 벤더와 반드시 같지는 않습니다. 네이티브 구간 내부의 프록시 수준 연쇄(예를 들어 `vertexai` Gemini 이미지 체인)가 어떤 헤더에도 이름이 없는 다른 벤더로 호출을 넘길 수 있기 때문입니다.
</ResponseField>

<ResponseField name="X-Comfy-Upstream-Detail" type="string">
  모델 공급자가 요청을 거부한 이유를 길이를 제한하고 정제하여 나타낸 것입니다.
</ResponseField>

<ResponseField name="X-Comfy-Upstream-Status" type="integer">
  이 호출에 대한 모델 공급자 자체의 HTTP 상태입니다.
</ResponseField>

<ResponseField name="X-Committed-Spend-Current" type="integer">
  호출자가 현재 아직 진행 중인 호출에 약정한 USD 센트입니다.
</ResponseField>

<ResponseField name="X-Committed-Spend-Limit" type="integer">
  호출자가 아직 진행 중인 호출에 약정할 수 있는 파트너 지출의 상한(USD 센트)입니다. 이 금액은 호출이 승인되는 순간부터 보류되고 해당 호출이 완료되면 해제됩니다.
</ResponseField>

<ResponseField name="X-Committed-Spend-Remaining" type="integer">

<ResponseField name="X-Content-Type-Options" type="string">
  Router 모델의 모든 성공적인 실행에서 항상 `nosniff`입니다.
</ResponseField>

<ResponseField name="X-Model-Concurrency-Current" type="integer">
  이 호출을 거부한 게이트에서 집계한, 호출자가 고비용으로 분류된 모델에 대해 수행한 동시 호출 수입니다.

<ResponseField name="X-Model-Concurrency-Limit" type="integer">

## 실행 전 비용 예상

`POST /v2/models/{provider}/{model}/estimate`는 본문을 실행하지 않고 가격을 산정하며, 대기 중인 제출(`POST /v2/models/{provider}/{model}/requests`)은 `201` 응답에서 `estimate`와 동일한 [`RouterCostEstimate`](#routercostestimate)를 반환합니다. 두 경로 모두 Comfy의 표준 정가로 가격이 산정되지만, 공급자가 보고하는 비용으로 청구되는 모델은 예외로, 해당 모델은 공급자의 공개 가격표를 기준으로 `estimated` 처리됩니다. 어느 쪽도 계약 요율이나 고객별 요율을 반영하지 않습니다. 협상된 가격이 적용되는 워크스페이스에는 정가가 제시되지만 실제로는 계약 요율로 청구되며, 이때 `source: exact`는 해당 워크스페이스의 청구 금액이 아니라 정가 기준으로 정확하다는 의미입니다. 두 경로가 반환하는 모든 금액은 최종 청구액이 아닌 추정치입니다. 최종 금액은 워크스페이스의 사용량 및 청구 기록에 확정된 청구액입니다. 자체 공급자 키로 실행한 경우에는 Comfy가 청구하지 않습니다(아래 참조). 배포에서 추정 기능이 꺼져 있으면 해당 라우트는 `error_type: not_enabled`와 함께 `403`으로 응답하고, 제출 응답에서는 `estimate`가 생략됩니다. 두 경로 모두 Router가 디스패치하는 방식대로 본문의 가격을 산정하지만(`model_provider` 구간에 맞게 변환되고, 실제로 실행되는 작업으로 재지정됨), 제출 응답의 `estimate`는 사전 가격이 아닙니다. 이 값은 실행이 승인되어 대기 중 상태가 된 이후에야 도착하며, 해당 실행은 디스패치 이전에 취소되지 않는 한 청구됩니다. 카탈로그에는 여전히 가격 정보가 없습니다.

어떤 금액보다 먼저 `source`를 확인하십시오. 금액이 누락되었다고 해서 무료를 의미하지는 않습니다.

| `source` | 포함 내용 | 해석 방법 |
| --- | --- | --- |
| `exact` | `amount`, `amount_cents`, `credits` | `pricing_as_of`의 요율로 이 본문에 대해 청구될 금액과 같은 예상치입니다. 최종 청구액은 워크스페이스의 사용량 및 청구 기록에 정산된 금액입니다. |
| `estimated` | `min_amount`, `max_amount` 및 각각의 `_cents` 형태, `amount` 없음 | 청구액이 공급자가 다시 보고하는 수량에 따라 달라지며 본문이 그 범위를 한정하는 경우의 예상치입니다. 청구액은 그 범위 내일 것으로 예상되며, 최종 청구액은 워크스페이스의 사용량 및 청구 기록에 정산된 금액입니다. |
| `free` | `amount` "0", `amount_cents` 및 `credits` `0` | 요율표가 이 요청을 0으로 산정하므로 예상치는 `0`입니다. 최종 청구액은 워크스페이스의 사용량 및 청구 기록에 정산된 금액입니다. 오직 `free` 견적만 `0`으로 표시됩니다. |
| `unknown` | `reason`, 금액 없음 | 실행 전에는 가격을 제시할 수 없습니다. 다른 모든 `source` 값은 `unknown`으로 취급하십시오. |

`unknown` 예상치의 `reason`은 다음 중 하나입니다:

- `not_quotable`: 실행 전에는 Router가 이 호출의 가격을 산정할 수 없습니다. 공급자가 다시 보고하는 수량으로 청구되는데 본문이 그 범위를 한정하지 않거나, 본문을 보낸 그대로 가격을 산정할 수 없기 때문입니다. 인식되지 않는 모든 `reason`은 `not_quotable`로 취급하십시오.
- `unpriced_model`: 요율표가 이 요청의 가격을 산정하지 않습니다.
- `byok`(대기 중 제출에만 해당): 실행이 자체 공급자 키를 사용하므로 Comfy는 이에 대해 아무것도 청구하지 않습니다.
- `pricing_unavailable`(대기 중 제출에만 해당): 요청이 접수될 때 요율표를 읽을 수 없었습니다. 제출은 여전히 수락되며 실행은 평소와 같이 청구됩니다.

Router가 아직 실행 전에 가격을 산정할 수 없는 모델은 [실행 전 예상치가 없는 모델](/ko/development/comfy-router/limitations#사전-견적이-없는-모델)에 나열되어 있습니다. 여기에 나열되지 않은 모델도 특정 본문에 대해서는 `unknown`을 응답할 수 있으므로, 모든 예상치에서 `source`를 확인하십시오.

예상치가 실패 시 안전하게 동작하는 지점:

- 금액 산정에 요율표가 필요한데 요율표가 로드되지 않았거나 오래된 경우, `/estimate`는 추측 대신 `503`을 응답합니다. 대기 중 제출은 예상치 때문에 거부되는 일이 없으며, 대신 `source: unknown`과 `reason: pricing_unavailable`을 담습니다. 실행 전에 전혀 가격을 산정할 수 없는 호출(`not_quotable`)이나 자체 공급자 키를 사용하는 대기 중 제출(`byok`)은 요율표를 읽지 않고 응답하므로, 그 `200` 응답은 요율표가 최신인지에 대해 아무것도 말해주지 않습니다.
- `/estimate`는 기본 실행과 마찬가지로 모델 자체의 입력 스키마에 대해 본문을 검증하므로, 모델 스키마를 통과하지 못하는 본문은 실행이 응답했을 것과 동일한 `detail[]` 형태를 가진 동일한 `422`를 받습니다. 아무것도 가격이 산정되거나 디스패치되지 않습니다.
- 대기 중 제출의 멱등 재생(`Idempotent-Replayed: true`)은 `estimate`를 생략합니다. 원본 견적이 저장되지 않기 때문입니다.

예상치의 한계. `200` 응답의 금액은 실행이 수락된다거나 정확히 그 금액이 청구된다는 약속이 아닙니다:

- `/estimate`는 `strict_mode`나 `reject_unknown_fields`를 받지 않으므로 모델의 기본 계약만 검사합니다. `strict_mode=true` 실행이 대체 공급자 자체 스키마에서 수락하는 본문이 여기서는 `422`를 받을 수 있고, `reject_unknown_fields=true` 실행이 거부할 선언되지 않은 최상위 필드도 여기서는 가격이 산정됩니다. Anthropic Messages 모델은 예외입니다. 해당 스키마는 선언되지 않은 필드를 허용하므로 `reject_unknown_fields=true` 실행도 아무것도 거부하지 않으며, 예상치는 선언되지 않은 최상위 필드 `tools`, `tool_choice`, `temperature`, `top_p`, `top_k`, `stop_sequences`, `metadata`, `thinking` 및 빈 `mcp_servers`에 대해서만 가격을 산정합니다. 그 밖의 선언되지 않은 최상위 필드가 있으면 `reason: not_quotable`과 함께 `unknown`을 응답합니다.
- `pricing_as_of`는 요율표를 가져온 시점입니다. 공급자의 공개 가격표에서 가져온 `estimated` 견적은 그 가격표를 읽은 날짜를 담습니다. 청구 수량을 공급자의 공개 일정표에서 예측한 뒤 요율표로 가격을 매기는 `exact` 또는 `estimated` 견적은, 해당 일정표를 읽은 날짜가 요율표보다 이르면 그 날짜를 담습니다. 요율표와 일정표 모두 읽지 않은 경우에는 예상치를 응답한 시점입니다. 이는 가격 고정이 아닙니다. 실행은 요율이 적용되는 시점에 유효한 요율로 청구됩니다.
- `/estimate`는 `model_provider`가 지정한 레그 또는 기본 공급자의 견적을 제시합니다. `fallback_provider`나 `strict_mode` 매개변수는 받지 않습니다. 폴백 재시도가 다른 공급자에 도달한 동기 실행은 예상치가 제시하지 않았던 그 공급자의 요율로 청구되며, 실행 응답의 `X-Comfy-Router-Fallback-Provider`가 그런 일이 있었음을 알려줍니다. 대기 중 제출에는 폴백이 없으므로 그 `estimate`는 실제 실행되는 레그의 견적을 제시합니다.
- `/estimate`는 항상 플랫폼 청구액의 견적을 제시합니다. 자체 공급자 키로 실행하면 Comfy는 청구하지 않지만, `/estimate`는 이를 감지하지 못하고 여전히 금액을 반환합니다. `reason: byok`를 응답하는 것은 대기 중 제출뿐입니다.
- 달러는 반올림되지 않은 센트 값을 기준으로 소수점 이하 최대 8자리까지 표시되며, 청구 가능한 1센트 미만의 `amount`는 절대 `0`으로 표시되지 않습니다. `credits`는 `round(amount × 211, 2)`이며, 이는 `X-Comfy-Credits-Used`가 청구 금액에 적용하는 것과 동일한 변환입니다. 따라서 매우 작은 0이 아닌 가격에서는 `credits`가 `0`으로 반올림될 수 있습니다. 이 점이 중요할 때는 `credits`가 아니라 `amount` 또는 `amount_cents`를 기준으로 예산을 책정하세요. 해당 헤더는 한 번의 실행에 대한 사후 수치로 남습니다. 잔액은 Comfy 플랫폼에 있습니다.

## 결과 에셋

모델은 에셋 URL, 인라인 바이트 또는 둘 다를 반환할 수 있습니다. 아래 공급자는 선택된 에셋을 Comfy 스토리지로 복사하고 해당 URL을 대체합니다. 이 동작은 모델에 따라 다르며, 이를 선택하는 요청 헤더는 없습니다.

| 모델 | Comfy 스토리지로 복사되는 항목 | Comfy 호스팅 URL 최대 수명 |
| --- | --- | --- |
| `bfl/*` | 완료된 에셋, 그리고 결과에 포함된 경우 드래프트 캐시 에셋 | 24시간 |
| `byteplus/*` 비디오 모델 (`seedance`, `dreamina-seedance`) | 완료된 비디오, 그리고 결과에 포함된 경우 마지막 프레임 이미지 | 24시간 |
| `fal/h3-max`, `fal/h3-max-turbo` | 완료된 비디오 | 24시간 |
| `minimax/*` | 완료된 비디오 | 12시간 |
| `xai/*` | 생성된 모든 이미지, 그리고 완료된 비디오 | 24시간 |

이 수명은 URL을 열 때가 아니라 URL에 서명될 때 시작됩니다. 캐시되었거나 재생된 URL은 남은 시간이 더 적을 수 있으며, 재생해도 수명이 갱신되지 않습니다. `Idempotency-Key` 기록은 보유한 URL보다 오래 유지될 수 있습니다. 따라서 해당 URL이 만료되기 1시간 전부터 같은 키로 재시도하면 기록된 응답 대신 `409 invalid_input`이 응답됩니다. 응답이 제공될 때 이미 그만큼 만료에 가까웠던 경우에는 5분 동안 재생할 수 있습니다. 에셋을 즉시 다운로드하세요. 각 행에 명시된 에셋만 복사됩니다. `byteplus/seedream-*` 및 `byteplus/seededit-*` 이미지는 BytePlus 비디오 행에 포함되지 않으며, `fal/fal-*` 모델은 fal 행에 포함되지 않습니다.

복사는 해당 모델의 네이티브 공급자만 수행합니다. 대체 공급자가 처리한 실행은 해당 공급자 자체의 URL을 반환하며, 이 URL은 공급자의 만료를 따르고 복사되지 않습니다. 여기에는 `model_provider`가 대체 공급자를 지정한 실행, `model_provider`를 지정하지 않았지만 Comfy Router가 다른 공급자에서 처리한 실행(동기 실행 라우트에서 `X-Comfy-Router-Provider`로 보고됨), 폴백 재시도가 대체 공급자에 도달한 네이티브 실행(`X-Comfy-Router-Fallback-Provider`로 공개됨)이 포함됩니다. `model_provider` 값 `default`, `comfy`, `comfyui`는 대체 공급자를 지정하지 않으므로 해당 실행은 네이티브이며 위와 같이 복사됩니다. 폴백 재시도가 다시 네이티브 공급자에 도달한 `model_provider` 실행도 마찬가지입니다.

**Veo(`veo/*`)는 별도의 스토리지 경로를 사용합니다.** `response.videos[]`에서 존재하는 멤버를 읽으세요. `bytesBase64Encoded`는 클립을 인라인으로 담고 있으며, `gcsUri`는 공급자가 Comfy 스토리지에 직접 쓰도록 환경이 구성된 경우 Comfy가 서명한 HTTPS 링크를 담고 있습니다. 해당 링크는 응답 시점부터 24시간 동안 유효합니다. 후자의 경우 에셋을 복사하는 대신 직접 쓰기 때문에 Veo는 재호스팅 표에 포함되지 않습니다.

다른 모델은 공급자 에셋 참조 또는 인라인 바이트를 반환합니다. 공급자 URL은 공급자의 만료 정책을 따르며, 이는 위 수명보다 훨씬 짧을 수 있고 Router 계약에 명시되어 있지 않습니다.

**원본 BytePlus URL(Seedance 2.x, 옵트인).** Comfy가 서버 측에서 옵트인한 워크스페이스의 경우, Seedance 2.x 결과는 복사된 URL 옆에 BytePlus 자체 URL을 `content.upstream_video_url` 및 `content.upstream_last_frame_url`에 담고, `content.upstream_expires_at`도 함께 담습니다. 요청 매개변수는 없으며 기본적으로 옵트인되는 워크스페이스도 없습니다. 이 URL은 생성 후 24시간이 지나면 만료되며, BytePlus가 지우면 더 이상 존재하지 않습니다. Seedance 2.5에서는 BytePlus가 각 URL의 다운로드를 100회로 제한하며, Router 자체 복사도 그중 1회를 사용합니다. 각 URL은 해당 객체에 대한 베어러 자격 증명이므로, 이를 보유한 사람은 만료될 때까지 에셋을 다운로드할 수 있습니다.

**제로 데이터 보존 워크스페이스.** Comfy가 제로 데이터 보존으로 구성한 워크스페이스에서는 BytePlus 결과가 Comfy 스토리지에 복사되지 않습니다. 위의 `byteplus/*` 비디오 행은 적용되지 않으며, `content.video_url`과 `content.last_frame_url`은 BytePlus가 전송한 그대로 반환되는 BytePlus 자체 공급자 URL입니다. 이 URL은 24시간 동안 유효하고, Seedance 2.5에서는 BytePlus가 각 URL당 다운로드를 100회로 제한하므로 에셋을 신속히 다운로드하세요. 이러한 결과는 `Idempotency-Key` 기록에서 재생되지 않습니다.

복사는 에셋별 최선 노력 방식으로 수행됩니다. 복사 하나가 실패하면 해당 항목은 공급자 참조를 유지합니다. 응답에는 Comfy URL과 공급자 URL이 모두 포함될 수 있으며, 에셋별 복사 상태를 나타내는 명시적 필드는 없습니다. 생성은 여전히 성공하며 과금됩니다. 성공적으로 재호스팅된 에셋 하나로 모든 URL의 수명을 추론하지 마세요.

결과가 Comfy 호스팅인지 여부는 완료된 호출을 나중에 해당 `Idempotency-Key` 기록에서 재생할 수 있는지도 결정합니다. 위의 `Idempotency-Key` 매개변수는 재생할 수 없을 때 재시도에 무엇이 응답되는지 설명합니다.

## 모델별 입력 및 출력 스키마

각 모델의 필드는 `GET /v2/models/{provider}/{model}/openapi.json`에서 확인할 수 있습니다. 이 호출에는 API 키가 필요합니다. 스키마가 작성된 모든 모델에 대해 동일한 문서가 이 사이트에도 인증 없이 `/router-schemas/{provider}/{model}.json`에서 게시됩니다. 이 복사본은 마지막 문서 업데이트 시점에 캡처한 스냅샷이므로, 두 문서가 다를 경우 엔드포인트가 우선합니다. 오퍼레이션의 `requestBody`는 입력 검증을 설명하고, `200` 응답은 스키마가 작성된 경우 출력 형태와 미디어 타입을 설명합니다. `x-comfy-input-schema-authored`가 false이면 Router는 모델별 사전 검증 없이 모든 JSON 객체를 허용합니다. 공급자 요구 사항은 여전히 적용됩니다. 출력 스키마는 결과를 설명하며, Router는 반환된 공급자 페이로드를 스키마와 대조하여 검증하지 않습니다. 스키마가 작성되지 않은 출력은 `application/json` 대신 `*/*`를 사용할 수 있으므로, 디코딩하기 전에 응답 콘텐츠 타입을 확인하세요.

### RouterCostEstimate

이 호출에 드는 비용을 미국 달러로 미리 산출한 사전 견적입니다. 발송 전에 Comfy의 표준 정가로 가격이 책정되며, 공급자가 보고한 비용으로 청구되는 모델의 경우에는 공급자가 공개한 가격표를 기준으로 책정됩니다. 공급자가 보고한 비용으로 청구되는 경우, `source: exact`는 옵트인한 소수의 모델에 대해서만, 그리고 공개된 가격표가 그 수치를 완전히 결정할 때만 반환됩니다(가격을 좌우하는 모든 필드가 명시되었거나, 값을 바꿀 수 없는 기본값으로 남아 있는 경우). 그 밖의 공급자 보고 견적은 모두 `estimated`이며, 가격표만으로 충분히 결정될 수 있는 일부도 여기에 포함됩니다. 어느 쪽이든 실행이 완료된 후에는 공급자가 보고한 금액으로 청구되며, 견적에 적힌 수치가 그대로 청구되지는 않습니다. 계약 요율이나 고객별 요율은 반영하지 않습니다. 협상된 가격이 있는 워크스페이스는 정가로 견적이 나오고 계약 요율로 청구되며, 이때 `source: exact`는 정가 기준으로 정확하다는 뜻이지 해당 워크스페이스의 청구 금액이 정확하다는 뜻이 아닙니다. 최종 청구 금액이 아닙니다. 실제로 지불하는 금액은 워크스페이스의 사용량 및 청구 기록에 정산된 금액입니다. 실행 이후에 보고되는 `X-Comfy-Credits-Used`는 반올림된 사후 수치이며 영수증이 아닙니다. `source`는 이 수치를 얼마나 신뢰할 수 있는지 나타냅니다. `exact`는 `amount`를 포함하고, `free`는 `amount` "0"을 포함하며(요율 카드가 이 요청의 가격을 0으로 책정), `estimated`는 `min_amount`와 `max_amount`를 포함하고 `amount`는 없으며, `unknown`은 둘 다 없고 `reason`을 포함합니다. `amount`가 없다고 해서 무료로 해석해서는 안 됩니다. 가격 고정이 아닙니다. `pricing_as_of`를 참고하세요.

**필드**

<ResponseField name="source" type="string" required>
  `exact` | `estimated` | `free` | `unknown`; 다른 값은 `unknown`으로 읽습니다. `exact`와 `estimated`는 모두 추정치를 표시하며, 어느 것도 최종 청구 금액이 아닙니다. `free`는 요율 카드가 이 요청의 가격을 0으로 책정한다는 뜻이므로 `amount`가 "0"입니다. `unknown`은 어떤 수치도 포함하지 않습니다.
</ResponseField>

<ResponseField name="currency" type="string" required>
  항상 `USD`입니다.
</ResponseField>

<ResponseField name="amount" type="string">
  예상 비용을 소수점 문자열로 나타낸 달러 금액입니다(예: "0.04"). 소수점 이하 최대 8자리까지이며 지수 표기는 없습니다. 청구 가능한 1센트 미만 가격은 "0"으로 표시되지 않으며, `free` 견적만 "0"으로 표시됩니다. `source`가 `exact` 또는 `free`일 때만 존재합니다. 최종 청구 금액이 아니며, 최종 금액은 워크스페이스의 사용량 및 청구 기록에 정산된 금액입니다.
</ResponseField>

<ResponseField name="min_amount" type="string">

</ResponseField>

<ResponseField name="max_amount" type="string">

<ResponseField name="max_amount_cents" type="number">

### RouterErrorResponse

인증, 접근, 모델 조회, 할당량 및 공급자 전송 실패에 대한 오류 본문입니다.

**필드**

<ResponseField name="detail" type="string" required>
  실패에 대한 사람이 읽을 수 있는 설명으로, 최종 사용자에게 노출해도 안전합니다. 기계적으로 파싱되지 않습니다. 대신 `error_type`으로 분기하세요. 은퇴한 모델에 대한 `model_not_found`의 경우, 후속 모델이 기록되어 있고 호출자에게 표시된다면 `detail`은 `<id> was retired on <YYYY-MM-DD>; use <successor>`로 표시되고, 그렇지 않다면 일반적인 제안 목록 대신 `<id> was retired on <YYYY-MM-DD>`로만 표시됩니다. 여기에 명시된 후속 모델은 항상 호출을 다시 지정할 수 있는 라이브 카탈로그 ID입니다. 서비스 종료 날짜가 아직 미래인 모델은 은퇴한 것이 아닙니다. 해당 날짜까지 `GET /v2/models`에 계속 나열되며 실행 가능한 상태로 유지됩니다. `detail`의 나머지 부분과 마찬가지로 이 은퇴 관련 문구는 표시용이며 호환성 보장을 제공하지 않습니다. 기계적으로 파싱되지 않는다는 규칙에는 문서화된 두 가지 예외가 있습니다. `POST /v2/models/{provider}/{model}`에서 `409`는 `invalid_input` 버킷을 공유하는 세 가지 서로 무관한 상황에 대해 응답되며, 오직 `detail`만이 이들을 구분합니다. "this request's `image` selects the edit operation"으로 시작하는 `detail`은 multipart `model_provider` 거부이고, `this request resolved a BYOK credential`로 시작하는 `detail`은 BYOK `model_provider` 거부입니다. 둘 다 새로운 `Idempotency-Key`로도 해소되지 않습니다. 해당 라우트에서 다른 모든 `invalid_input` `409`는 키 충돌입니다. 두 접두사는 안정적인 계약 용어이며 매칭 대상으로 사용할 수 있습니다. 그 밖의 어디에서도 `detail`을 기준으로 분기하는 것은 호환성 보장을 제공하지 않습니다.
</ResponseField>

<ResponseField name="error_type" type="RouterErrorType" required>
  Router 실패에 대한 포괄적이고 기계 판독 가능한 버킷으로, 호출자가 본문을 파싱하지 않고 분기할 수 있도록 `X-Comfy-Error-Type` 응답 헤더에도 반영됩니다. 이 집합은 스물한 개 값으로 닫혀 있습니다. 여섯 개의 요청 수준 버킷 `invalid_input`, `content_policy_violation`, `provider_error`, `provider_timeout`, `insufficient_credits`, `model_not_found`와, 전송 수준의 `unauthorized`, `forbidden`, `concurrency_limit_exceeded`, `client_disconnected`, `internal_error`, `deadline_exceeded`, `not_enabled`, `service_unavailable`, `rate_limited`, `cancelled`, `queue_timeout`, `request_not_found`, `queue_backlog_full`, `result_expired`, 그리고 요청 수준의 `byok_credential_rejected`입니다. '닫혀 있다'는 것은 오늘 문서화된 기준의 집합을 뜻하며 영원히 유지되는 한계가 아닙니다. 이 집합은 늘어날 것으로 예상되며, 이것이 이 필드가 의도적으로 `enum`이 아닌 일반 문자열인 이유입니다. 따라서 클라이언트는 위 목록에 대해 빠짐없이 switch하지 말고, 인식할 수 없는 값을 `internal_error`로 처리해야 다음 추가 항목에서 깨지지 않습니다.

  유형: [`RouterErrorType`](#routererrortype)
</ResponseField>

<ResponseField name="upstream_detail" type="string">
  `invalid_input` 거부에 대한, 범위가 제한되고 정제된 사유입니다. 동기 라우트에서는 모델 공급자가 제시한 사유이며, `error_type`이 `invalid_input`이고 `X-Comfy-Upstream-Status`가 공급자의 `4xx` 또는 `2xx`일 때만 존재합니다. 즉 공급자가 요청을 잘못된 형식으로 거부하고 그 이유를 밝힌 경우입니다. 보통 그 상태는 `4xx`이며, 성공 응답 봉투 안에서 거부된 생성을 보고하는 공급자의 경우 `2xx`입니다(BytePlus의 실패한 작업 폴링은 HTTP `200`이고 사유는 본문에 있습니다). 그 외의 모든 실패, 즉 공급자 `5xx`, 전송 실패, 콘텐츠 정책 거부, Router가 자기 자신에 대해 발생시킨 모든 거부에서는 존재하지 않으며, `X-Comfy-Upstream-Detail` 헤더에 반영됩니다. `invalid_input`으로 종료된 실행의 대기 중 collect(`GET /v2/models/{provider}/{model}/requests/{request_id}`)는 첫 번째 collect에서 이 필드에 같은 사유를 담고, 그런 다음 요청에서 이를 삭제합니다. 나중의 collect는 보통 동일한 `error_type`과 `detail`을 이 필드 없이 응답하므로, 첫 번째 collect에서 읽어야 합니다. 그 읽기는 어느 헤더도 전송하지 않습니다. 대기 중 collect는 Router가 요청을 공급자에게 보내기 전에 거부했고 그 이유를 한 문장으로 설명할 수 있는 경우 Router 자체의 사유에도 이 필드를 사용하며, 동기 라우트는 이를 `detail`에 담아 응답합니다. 개별 필드를 지목하는 거부는 이 필드를 갖지 않습니다.
</ResponseField>

<ResponseField name="refusal_subject" type="string">
  콘텐츠 정책 거부가 어떤 입력 또는 출력에 관한 것이었는지로서, Router 수준의 닫힌 어휘입니다: `input`, `output`, `input_text`, `input_image`, `input_video`, `input_audio`, `output_text`, `output_image`, `output_video`, `output_audio`. 공급자가 모달리티를 지목하지 않은 경우 단순한 `input` / `output` 값이 어느 쪽인지를 나타냅니다. `error_type`이 `content_policy_violation`이고 공급자가 거부된 대상을 기계 판독 가능한 코드로 지목한 경우에만 존재하며, 그 외에는 없습니다. 공급자 텍스트는 절대 아닙니다. 현재 BytePlus, Runway, BFL, Gemini, Veo, Vertex, xAI 및 Wan의 거부와 MiniMax Router의 Nano Banana 레그의 Gemini 거부에 대해 명명되며, 거부가 어느 쪽에 관한 것인지 밝히지 않는 공급자는 이 필드를 비워 둡니다. `X-Comfy-Refusal-Subject` 헤더에 반영됩니다.
</ResponseField>

<ResponseField name="denied_reason" type="string">
  파트너 노드 지출 거부에 대한 빌링의 정책 분기입니다. 청구되는 지갑이 비어 있으면 `no_funds`, 자금 조회에서 그렇게 밝히지 않은 채 호출이 거부되면 `unspecified`입니다. `error_type`이 `insufficient_credits`이고 배포가 지갑 정보를 보고할 때만 존재하며, 그 외에는 없습니다. 표시 텍스트가 아닌 기계 판독 가능한 코드입니다: `detail`을 표시하고, 이 필드로 분기하세요.
</ResponseField>

<ResponseField name="billed_workspace" type="RouterBilledWorkspace">

  유형: [`RouterBilledWorkspace`](#routerbilledworkspace)
</ResponseField>
<ResponseField name="credential_kind" type="string">

</ResponseField>

<ResponseField name="estimate" type="RouterCostEstimate">
  이 요청에 대한 사전 비용 추정치로, 호출자에 대해 비용 추정이 활성화된 경우 새로 접수될 때 포함됩니다. 이 요청이 고정된 공급자 구간을 제시합니다(실행 대기열에는 폴백 루프가 없으므로 `fallback_provider`는 실행되는 구간을 절대 바꾸지 않습니다). 수치를 제시할 수 없을 때도 `source: unknown`과 함께 여전히 존재하며, 제출은 추정치 때문에 실패하지 않습니다. 멱등 재생(`Idempotent-Replayed: true`)에서는 생략됩니다. 원본 견적이 저장되지 않기 때문입니다. 이것은 추정치이며 최종 청구액도, 가격 고정도 아닙니다. 실행은 요율이 산정되는 시점에 적용되는 요율로 청구되며, 워크스페이스의 사용량 및 청구 기록에 정산된 금액이 최종입니다.

  Type: [`RouterCostEstimate`](#routercostestimate)
</ResponseField>

### RouterValidationErrorContext

유형: `object`

### RouterValidationErrorDetail

필드 수준 검증 실패 하나를 나타냅니다.

**필드**

<ResponseField name="loc" type="array of any" required>
  문제가 된 필드의 경로이며, 가장 바깥 세그먼트가 먼저 옵니다. 예를 들어 `["body", "image_url"]` 또는 정수가 배열을 인덱싱하는 `["body", "images", 0]`과 같습니다.
</ResponseField>

<ResponseField name="msg" type="string" required>
  이 단일 실패에 대한 사람이 읽을 수 있는 설명입니다.
</ResponseField>

<ResponseField name="type" type="string" required>
  이 실패의 구체적이고 기계가 읽을 수 있는 사유로, 공급자로부터 변경 없이 그대로 전달됩니다. 이는 타입이 지정된 SDK 예외 계층이 분기하는 값이며, 응답 헤더의 `error_type`은 그저 이를 포괄적으로 묶은 버킷일 뿐입니다.
</ResponseField>

<ResponseField name="ctx" type="RouterValidationErrorContext">
  하나의 `RouterValidationErrorDetail`에 대해 위반된 경계값으로, 공급자로부터 그대로 전달됩니다. 예를 들어 `greater_than`과 함께 오는 `{"limit_value": 8}`, `image_too_small`과 함께 오는 `{"min_width": 512}`, 또는 `file_too_large`와 함께 오는 `{"max_size_bytes": 10485760}`과 같습니다. 키 집합은 공급자와 오류 유형에 따라 다르므로, 이 객체는 의도적으로 열린 객체입니다. 이를 고정된 필드 목록으로 좁히거나 `msg` 문자열에 접어 넣는 것은, 이식된 통합이 컴파일은 되지만 경계값을 읽던 분기를 조용히 잃게 되는 바로 그 방식입니다. 오류 유형에 경계값이 없으면 생략됩니다.

  유형: [`RouterValidationErrorContext`](#routervalidationerrorcontext)
</ResponseField>

<ResponseField name="input" type="RouterValidationErrorInput">
  문제가 된 입력 값으로, 호출자가 `loc`에서 다시 도출하지 않고도 무엇이 거부되었는지 볼 수 있도록 그대로 되돌려 전달됩니다. 문자열, 숫자, 논리값, 배열, 객체 또는 null 등 모든 JSON 유형이 될 수 있으므로, 이 스키마는 객체로 좁히지 않고 의도적으로 타입을 지정하지 않은 채로 둡니다. 공급자가 입력을 되돌려 전달하지 않으면 생략됩니다.

  유형: [`RouterValidationErrorInput`](#routervalidationerrorinput)
</ResponseField>
