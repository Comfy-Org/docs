<Note>
**Comfy Router는 아직 일반에 공개되지 않았습니다.** 아래에서 언급하는 라우트(`POST /v1/models/{provider}/{model}` 및 카탈로그·스키마 관련 라우트)는 아직 요청을 처리하지 않습니다. 현재 인증된 호출은 `404`를 반환합니다. 이 페이지는 해당 라우트들이 제공할 계약을 설명하며, 통합이 알려진 형태를 기준으로 작성될 수 있도록 해당 롤아웃 이전에 게시되었습니다. 아래의 모든 내용은 해당 계약에 대한 설명이지, 지금 당장 실행할 수 있는 동작에 대한 설명이 아닙니다.
</Note>

Router는 파트너 모델을 하나의 동기식 HTTP 호출로 실행합니다. 애플리케이션이 완료된 결과를 기다릴 수 있고 모델 자체의 입력 및 출력 필드를 처리할 수 있는 경우에 사용하십시오.

## Router가 지원하는 기능

| 요구 사항 | Router 지원 | 대안 또는 다음 단계 |
| --- | --- | --- |
| 하나의 요청으로 생성 | `POST /v2/models/{provider}/{model}`가 완료된 결과를 반환합니다. | [빠른 시작](/ko/development/comfy-router/quickstart)부터 시작하세요. |
| 작업을 제출하고 나중에 수집 | 일반적인 작업/상태 API나 완료 webhook이 없습니다. | worker에서 Router를 실행하거나, 제출 후 폴링 연산을 제공하는 파트너 프록시를 사용하세요. |
| 진행 상황 표시 또는 출력 스트리밍 | 호출 중에는 실시간 진행 상황, 스트리밍, 미리보기 프레임이 없습니다. | 불확정 상태를 표시하거나, 지원되는 프록시 연산을 사용하세요. |
| 연결이 끊긴 이후 복구 | Router가 수락된 생성에 대한 핸들을 보관한 경우 동일 키 수집을 사용할 수 있습니다. | 키를 보존하고 [재시도 가이드](/ko/development/comfy-router/api#retry-outcomes)를 따르세요. |
| Comfy 청구 내역 대사 | 응답에 범용 Comfy 비용 또는 크레딧 잔액 필드가 없습니다. | [워크스페이스 청구](https://platform.comfy.org)를 사용하세요. |
| 결과를 영구적으로 저장 | 에셋 URL은 재호스팅 및 재생된 URL을 포함해 만료될 수 있습니다. | 에셋을 다운로드하세요. [결과 에셋](/ko/development/comfy-router/reference#결과-에셋)을 참고하세요. |

## 대기 중 제출 없음

Router는 모델이 실행되는 동안 연결을 유지합니다. 비동기 공급자의 경우 작업을 제출하고 내부적으로 폴링합니다. Router 작업 ID, 상태 엔드포인트, 콜백 또는 웹훅은 노출하지 않습니다.

요청을 그만큼 오래 열어 둘 수 없다면, 워커에서 Router를 호출하고 애플리케이션에서 작업을 추적하세요. 공급자의 제출 및 폴링 제어가 필요할 때는 [파트너 프록시](#router는-모든-파트너-작업을-다루지-않습니다)를 사용하세요.

## 호출이 서버 마감 시간에 중단됨

Router의 기본 마감 시간은 **10분**이며, 배포 시 설정할 수 있습니다. Router가 자체 오류와 요청 ID를 먼저 반환할 수 있도록, 클라이언트 타임아웃을 그보다 길게 설정하세요.

`504` / `deadline_exceeded`는 Router가 대기를 중단했음을 의미하고, `504` / `provider_timeout`은 공급자가 타임아웃되었음을 의미합니다. 타임아웃이나 연결 끊김은 해당 생성이 청구되지 않았음을 증명하지 않으며, 이미 수락된 공급자 작업을 취소하지도 않습니다. 재시도하기 전에 [타임아웃과 수금](/ko/development/comfy-router/api#timeouts-and-collection)을 읽어보세요.

## 복구는 공급자에 따라 달라집니다

Router는 수락된 submit-and-poll 생성에 대해 공급자 핸들을 보유할 수 있습니다. 동일한 `Idempotency-Key`를 재사용하면 나중에 이를 수집할 수 있으며, 완료된 재생 가능 응답도 키 기록에서 가져올 수 있습니다.

연결 해제된 모든 호출이 복구 가능한 것은 아닙니다. 전송하기 전에 요청과 키를 보존한 다음, [재시도 결과 표](/ko/development/comfy-router/api#retry-outcomes)를 사용하십시오. 새 키는 새 호출을 생성하며 추가 요금이 발생할 수 있습니다.

## 요청은 호출자별로 속도 제한됨

| 응답 | 원인 | 조치 |
| --- | --- | --- |
| `429` / `concurrency_limit_exceeded` | 동시 호출이 너무 많거나, 약정 지출(committed-spend) 상한 아래의 여유가 부족함. | 동시 작업을 줄이세요. 지출 헤더를 보면 지출 상한과 호출 수 제한을 구분할 수 있습니다. |
| `429` / `rate_limited` | 요청 허용량이 소진됨. | 재시도하기 전에 `Retry-After`를 기다리세요. |

요청 속도 제한은 호출(invocation)과 카탈로그/스키마 읽기에 적용되며, 생성 이전에 거부된 요청도 포함합니다. 이 제한은 소스 IP가 아니라 인증된 호출자를 따릅니다. 호출자의 공급자 키를 사용한 호출은 예외이며, 공급자 측 제한은 여전히 적용됩니다.

카탈로그와 스키마 읽기는 캐시하세요. 스키마는 `ETag`와 `If-None-Match`로 재검증하세요. 재시도 및 약정 지출 필드에 대해서는 [Headers](/ko/development/comfy-router/headers)를 참고하세요.

## 호출이 실행되는 동안에는 진행률이 없음

Router는 최종 응답을 반환하며, 스트리밍되는 토큰, 서버 전송 이벤트, 백분율 업데이트, 중간 미리보기 프레임은 없습니다. 공급자의 내부 폴링 상태는 요청 중에 전달되지 않습니다.

불확정 진행 표시기를 표시하세요. 진행률이나 스트리밍이 필요하다면, 해당 기능을 노출하는 파트너 프록시 작업을 사용하세요.

<span id="no-cost-or-credit-figures-on-a-response" />

## Comfy 요금 및 사용량

응답에는 공급자 사용량 또는 비용 필드가 포함될 수 있습니다. 이는 보편적인 Comfy 요금을 나타내지 않습니다. `X-Comfy-Credits-Used`는 선택 사항이며 재전송되지 않습니다. 잔액, 사용량, 청구서는 Comfy 플랫폼에서 확인하세요.

카탈로그는 가격 대신 `billing.charges_on_policy_rejection`을 포함한 청구 관련 사실 정보를 제공합니다. `yes`, `no`, `unknown`은 명시적으로 처리하세요. 자세한 내용은 [billing](/ko/development/comfy-router/api#model-billing-facts)을 참조하세요.

## Router는 모든 파트너 작업을 다루지 않습니다

Router는 모델을 실행합니다. 파일 업로드, 계정 읽기, 에셋 관리, 스트리밍, 공급자 작업 제어에는 `/proxy/…` 아래의 파트너 프록시 라우트가 필요할 수 있습니다. [Comfy API 명세](/ko/openapi-v2.yaml)를 확인하세요. 지원 여부는 공급자마다 다릅니다.

## 모델 출력 및 저장된 에셋

입력과 출력 필드는 모델에 따라 다릅니다. 공급자 SDK나 프록시에서 옮겨오면 라우트와 결과를 읽는 방식이 모두 달라질 수 있습니다.

일부 에셋은 Comfy 스토리지에 다시 호스팅되고, 다른 에셋은 공급자 URL이거나 인라인 바이트입니다. 수명과 재생 동작은 [결과 에셋](/ko/development/comfy-router/reference#결과-에셋)을 참조하세요.
