동일한 본문을 `POST https://api.comfy.org/v2/models/ideogram/ideogram-4-5/requests`로 보냅니다. Router는 실행이 접수되는 즉시 `request_id`와 함께 `201`로 응답하며, 결과는 준비되면 이 프로세스 또는 다른 프로세스에서 수집합니다. [대기 중 전달](/ko/development/comfy-router/queue)에서 상태, 취소, 수집 과정을 안내합니다.

```python Python
import asyncio
from comfy_sdk import AsyncComfy

# 환경 변수에서 COMFY_API_KEY를 읽습니다.
# 각 submit() 호출은 자체 Idempotency-Key를 생성하고 자동 재시도에 재사용합니다.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "ideogram/ideogram-4-5",
            {
                "prompt": "A poster for a jazz festival, bold typography, warm colours",
                "quality": "low",
            },
        )
        print("request_id:", handle.request_id)  # 모델 ID와 함께라면 다른 프로세스에 필요한 전부입니다

        # 요청이 완료될 때까지 폴링하며, 서버가 지정한 Retry-After만큼 대기합니다.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # 공급자 자체의 페이로드로, models.run()이 반환하는 것과 동일한 값입니다.
        # 실패했거나 취소된 요청은 여기서 타입이 지정된 Router 오류를 발생시킵니다.
        result = await handle.get()

    print(result)

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// 환경 변수에서 COMFY_API_KEY를 읽습니다.
// 각 submit() 호출은 자체 Idempotency-Key를 생성하고 자동 재시도에 재사용합니다.
const handle = await comfy.models.submit("ideogram/ideogram-4-5", {
  prompt: "A poster for a jazz festival, bold typography, warm colours",
  quality: "low",
});
console.log("requestId:", handle.requestId); // 모델 ID와 함께라면 다른 프로세스에 필요한 전부입니다

// 요청이 완료될 때까지 폴링하며, 서버가 지정한 Retry-After만큼 대기합니다.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// models.run()이 반환하는 것과 동일한 결과입니다. 실패했거나 취소된 요청은 여기서 거부됩니다.
const result = await handle.get();

console.log(result.data);
```

### 입력

<ParamField body="context_window" type="string">
  Precise Edit 전용이며 `image`가 필요합니다. 소스 이미지에서 편집이 수행되는 영역으로, 매우 큰 이미지의 한 부분만 편집하고 나머지는 그대로 둔 채 전체 크기로 반환할 수 있게 합니다. `none`(기본값)은 전체 이미지를 편집합니다. `auto`는 `mask` 주변에 영역을 맞추며 `mask`가 필요합니다. 그 외에는 `y_min,x_min,y_max,x_max`를 네 개의 음수가 아닌 정수 픽셀 경계로 전송하며, `y_max`는 `y_min`보다 크고 `x_max`는 `x_min`보다 커야 하며, 각 변이 최소 256픽셀이고, 가로 세로 비율이 1:6에서 6:1 사이이며, 면적이 최대 4,194,304픽셀이어야 합니다. `image`가 없는 요청에서 `none` 이외의 값은 거부됩니다. `context_window`는 컨텍스트 창 게이트가 활성화된 경우에만 허용됩니다. 활성화되지 않은 경우 `none` 이외의 모든 값은 422와 함께 거부됩니다.
</ParamField>

</ParamField>

<ParamField body="image" type="string">
  이미지 하나를, Router가 호출자를 대신해 가져오는 https URL 또는 바이트를 인라인으로 담은 `data:image/<format>;base64,<payload>` URI 중 하나로 지정합니다. 허용되는 이미지 유형은 png, webp, jpeg이며, 이 집합은 공급자에게 맡기지 않고 확인 시점에 강제됩니다. svg, gif, avif, tiff는 원인에서 두 단계 떨어진 파트너 오류가 되는 대신, 보낸 이미지를 지목하며 여기서 거부됩니다.
URL 형식을 선호하세요. base64 페이로드는 대략 4/3로 부풀려지고 전체 요청 본문은 100 MiB로 제한되므로, 인라인 형식은 약 75 MB 소스 이미지 근처에서 상한에 도달합니다. URL은 이 제한을 완전히 우회합니다. 이 설명 끝에 명시된 이미지당 및 요청당 미디어 상한은 본문 상한보다 더 엄격하므로, 실제 크기가 있는 이미지라면 먼저 부딪히는 것은 이 상한입니다.
URL은 귀하의 자격 증명 없이 해석되어야 합니다. Router는 서버 측에서 이를 가져오며 요청에 호출자 자격 증명을 보내지 않으므로, 서명이 쿼리 문자열에 있는 미리 서명된 URL이 지원되는 형식입니다. `/api/assets/{id}/content` 같은 인증된 엔드포인트는 이미지 대신 Router에 401을 반환합니다. 해당 URL을 직접 요청하고, 리디렉션되는 서명된 URL을 전달하세요.
가져오기는 공개 인터넷이 아니라 이름이 지정된 호스트 집합으로 제한되며, 동일한 목록이 보내는 URL뿐 아니라 모든 리디렉션 홉에도 다시 적용됩니다. 따라서 다른 호스트의 URL이나 목록 밖으로 리디렉션되는 URL은 공급자에 연결되기 전에 거부됩니다. 현재 이 목록은 Comfy 자체 에셋 전달만 포함합니다. Comfy 에셋 버킷 아래의 서명된 `storage.googleapis.com` URL이며, 이는 `/api/assets/{id}/content`가 리디렉션하는 형식입니다. 파트너 CDN이나 일반 https 호스트는 목록에 없습니다.
두 가지 확장이 롤아웃 중이며 현재 둘 다 기본적으로 꺼져 있습니다. 두 확장은 하나의 전환 뒤에 함께 제공되고 함께 활성화되므로, 아래의 모든 내용은 아직 기반으로 구축할 대상이 아니라 향후 제공될 내용으로 취급하세요. 둘 중 하나에 의존하기 전에 문의하세요.
첫 번째는 `POST /customers/storage`가 귀하의 업로드에 서명하여 넣는 버킷입니다. 롤아웃이 귀하의 환경에 도달하기 전까지 해당 엔드포인트의 업로드 URL은 버킷이 Comfy 소유이고 호스트가 동일하더라도 여기서 거부됩니다. 따라서 "Comfy에 업로드한 다음 URL을 전달"하는 방식은 아직 작동하지 않으며, 작동하는 형식은 `/api/assets/{id}/content`가 리디렉션하는 서명된 URL입니다.
두 번째는 모든 사람에게 한 번에 적용되는 것이 아니라 계정별로 활성화됩니다. 이러한 호스트 뒤의 버킷은 우리 것이 아니라 귀하의 것이기 때문입니다. 위 전환이 켜져 있더라도 타사 인바운드 미디어가 활성화되지 않은 계정은 거부되며, 호스트가 지원되지 않는다는 말이 아니라 그렇게 거부되었다고 안내받습니다. Comfy 담당자에게 계정에 대해 활성화해 달라고 요청하세요. 또한 이 확장은 버킷이 귀하의 것이고 Router가 소유권을 주장하지 않는 다음 타사 객체 스토리지 호스트를 허용합니다. Cloudflare R2(`<account>.r2.cloudflarestorage.com`, `pub-<hash>.r2.dev`), Amazon S3(`s3.amazonaws.com` 및 `s3.<region>.amazonaws.com`, 경로 스타일 또는 `<bucket>.` 접두사 형식 모두), Azure Blob Storage(`<account>.blob.core.windows.net`), Alibaba Cloud OSS(`<bucket>.oss-<region>.aliyuncs.com`, `oss-accelerate` 엔드포인트 포함)입니다. 이들은 특히 객체 스토리지 엔드포인트입니다. Alibaba Function Compute 트리거처럼 동일한 공급자 도메인의 범용 엔드포인트는 목록에 없으며 거부됩니다.
일치시키는 것은 공급자가 아니라 호스트 이름 형태입니다. 따라서 위에서 공급자를 명시했다고 해서 해당 공급자가 발급할 수 있는 모든 URL이 허용되는 것은 아니며, 호출자가 합리적으로 각각을 가지고 올 수 있는 세 가지 유사 사례를 분명히 밝힐 가치가 있습니다. R2 사용자 지정 도메인(`cdn.example.com`)은 허용되지 않습니다. Cloudflare는 `pub-<hash>.r2.dev`를 속도 제한된 디버그 호스트 이름으로 문서화하고 프로덕션 트래픽은 대신 사용자 지정 도메인으로 보냅니다. 그러나 사용자 지정 도메인은 호스트 이름에 R2임을 식별하는 내용이 없으므로 Router는 다른 호스트와 구분할 수 없어 거부합니다. `<account>.r2.cloudflarestorage.com` 엔드포인트에 미리 서명하거나 `pub-<hash>.r2.dev` 형식을 사용하세요. S3의 IPv6 dualstack 엔드포인트(`s3.dualstack.<region>.amazonaws.com`)도 허용되지 않습니다. 일반 리전 엔드포인트를 사용하세요. Azure Blob의 대체 DNS 영역(`<account>.z<N>.blob.storage.azure.net`)도 마찬가지입니다. `<account>.blob.core.windows.net`을 사용하세요. 돌려받는 거부 메시지에 이러한 동일한 형식이 명시되므로 읽기 위해 여기로 올 필요는 없습니다.
위의 `<account>` 및 `pub-<hash>` 자리표시자는 일반적으로 사용하게 될 형식을 보여 줍니다. 깊이 제한이 아닙니다. 일치는 객체 스토리지 도메인 접미사에서 이루어지므로 동일한 네임스페이스 아래의 더 깊은 이름(`a.b.pub-<hash>.r2.dev`)도 허용됩니다. 그것으로 확장되지 않는 것은 네임스페이스 자체입니다. 접미사는 여전히 나열된 것 중 하나여야 합니다.
아래 예시는 형태만 보여 줍니다. 실제 값에는 서명 쿼리 파라미터도 함께 포함되며, 게시된 예시는 사양에 영원히 남고 실제 서명은 유출된 자격 증명이자 작동을 멈추는 링크이므로 여기서는 의도적으로 생략했습니다.
각 이미지는 25 MiB로 제한되며, 한 요청의 이미지는 전체 64 MiB로 제한됩니다. 유일한 예외는 `context_window`를 사용할 수 있는 ideogram/ideogram-4-5 Precise Edit(`image`를 전송하는 호출)입니다. 이 경우 각 이미지는 최대 50 MB(50,000,000바이트) 및 67,108,864픽셀, 한 요청의 이미지는 전체 최대 128 MiB까지 허용됩니다.
</ParamField>

<ParamField body="mask" type="string">
  이미지 하나로, Router가 호출자를 대신해 가져오는 https URL이거나 바이트를 인라인으로 담은 `data:image/<format>;base64,<payload>` URI입니다. 허용되는 이미지 유형은 png, webp, jpeg이며, 이 집합은 공급자에게 맡기지 않고 resolve 시점에 강제됩니다. svg, gif, avif 또는 tiff는 원인에서 두 단계 떨어진 파트너 오류가 되는 대신, 전송한 이미지를 지목하며 여기에서 거부됩니다.
URL 형식을 선호하세요. base64 페이로드는 대략 4/3로 팽창하고 전체 요청 본문은 100 MiB로 제한되므로, 인라인 형식은 약 75 MB 소스 이미지에서 한계에 도달합니다. URL은 이를 완전히 우회합니다. 이 설명 끝에 명시된 이미지당 및 요청당 미디어 상한은 본문 상한보다 엄격하므로, 실제 크기의 이미지라면 먼저 마주치는 것은 이 상한입니다.
URL은 귀하의 자격 증명 없이 해석되어야 합니다. Router는 서버 측에서 이를 가져오며 요청에 호출자 자격 증명을 포함하지 않으므로, 서명이 쿼리 문자열에 있는 사전 서명된 URL이 지원되는 형식입니다. `/api/assets/{id}/content`와 같은 인증된 엔드포인트는 이미지 대신 Router에 401을 응답합니다. 해당 URL을 직접 요청하고 리다이렉트되는 서명된 URL을 전달하세요.
가져오기는 개방된 인터넷이 아니라 지정된 호스트 집합으로 제한되며, 동일한 목록이 전송한 URL뿐 아니라 모든 리다이렉트 홉에도 다시 적용됩니다. 따라서 다른 호스트의 URL이나 목록 밖으로 리다이렉트되는 URL은 어떤 공급자와도 접촉하기 전에 거부됩니다. 현재 이 목록은 Comfy 자체 에셋 전달뿐입니다. 즉 Comfy 에셋 버킷 아래의 서명된 `storage.googleapis.com` URL이며, `/api/assets/{id}/content`가 리다이렉트하는 형식입니다. 파트너 CDN이나 일반 https 호스트는 목록에 없습니다.
두 가지 확장이 롤아웃 중이며 오늘날 둘 다 기본적으로 꺼져 있습니다. 이들은 하나의 전환 뒤에 출시되어 함께 활성화되므로, 아래의 모든 내용은 아직 이를 기반으로 구축할 대상이 아니라 곧 제공될 예정으로 취급하세요. 둘 중 하나에 의존하기 전에 문의하세요.
첫 번째는 `POST /customers/storage`가 업로드를 서명해 넣는 버킷입니다. 롤아웃이 귀하의 환경에 도달할 때까지 해당 엔드포인트의 업로드 URL은, 버킷이 Comfy 소유이고 호스트도 동일함에도 불구하고 여기에서 거부됩니다. 따라서 "Comfy에 업로드한 다음 URL을 전달"하는 방식은 아직 작동하지 않으며, 작동하는 형식은 `/api/assets/{id}/content`가 리다이렉트하는 서명된 URL입니다.
두 번째는 모든 사람에게 한꺼번에 적용되는 것이 아니라 계정별로 활성화됩니다. 이 호스트들 뒤의 버킷이 우리 것이 아니라 귀하의 것이기 때문입니다. 위의 전환이 켜져 있더라도, 서드파티 인바운드 미디어가 활성화되지 않은 계정은 거부되며, 호스트가 지원되지 않는다는 안내 대신 그렇게 명시된 안내를 받습니다. Comfy 담당자에게 계정에 대해 활성화를 요청하세요. 또한 다음 서드파티 오브젝트 스토리지 호스트를 허용하며, 여기서는 버킷이 귀하의 것이고 Router는 이에 대해 어떠한 소유권도 주장하지 않습니다: Cloudflare R2(`<account>.r2.cloudflarestorage.com`, `pub-<hash>.r2.dev`), Amazon S3(`s3.amazonaws.com` 및 `s3.<region>.amazonaws.com`, 경로 스타일 또는 `<bucket>.` 접두 형식 모두), Azure Blob Storage(`<account>.blob.core.windows.net`), Alibaba Cloud OSS(`<bucket>.oss-<region>.aliyuncs.com`, `oss-accelerate` 엔드포인트 포함). 이들은 특히 오브젝트 스토리지 엔드포인트입니다. 동일한 공급자 도메인의 범용 엔드포인트(예: Alibaba Function Compute 트리거)는 목록에 없으며 거부됩니다.
일치되는 것은 공급자가 아니라 호스트 이름 형식입니다. 따라서 위에서 공급자를 언급했다고 해서 해당 공급자가 발급할 수 있는 모든 URL이 허용되는 것은 아니며, 호출자가 합리적으로 각각을 사용할 수 있으므로 세 가지 유사 사례를 분명히 밝힐 필요가 있습니다. R2 사용자 정의 도메인(`cdn.example.com`)은 허용되지 않습니다. Cloudflare는 `pub-<hash>.r2.dev`를 속도 제한이 있는 디버그 호스트 이름으로 문서화하고 프로덕션 트래픽은 대신 사용자 정의 도메인으로 보내지만, 사용자 정의 도메인은 호스트 이름에 R2임을 식별할 아무것도 담고 있지 않으므로 Router는 이를 다른 호스트와 구별할 수 없어 거부합니다. `<account>.r2.cloudflarestorage.com` 엔드포인트를 사전 서명하거나 `pub-<hash>.r2.dev` 형식을 사용하세요. S3의 IPv6 dualstack 엔드포인트(`s3.dualstack.<region>.amazonaws.com`)도 허용되지 않습니다. 일반 리전 엔드포인트를 사용하세요. Azure Blob의 대체 DNS 영역(`<account>.z<N>.blob.storage.azure.net`)도 마찬가지입니다. `<account>.blob.core.windows.net`을 사용하세요. 반환되는 거부 메시지에 이와 동일한 형식이 명시되므로 여기까지 와서 읽을 필요가 없습니다.
위의 `<account>` 및 `pub-<hash>` 자리 표시자는 일반적으로 사용하게 될 형식을 보여줄 뿐이며, 깊이 제한이 아닙니다. 일치는 오브젝트 스토리지 도메인 접미사를 기준으로 하므로, 동일한 네임스페이스 아래의 더 깊은 이름(`a.b.pub-<hash>.r2.dev`)도 허용됩니다. 그것으로 넓어지지 않는 것은 네임스페이스 자체입니다. 접미사는 여전히 나열된 것 중 하나여야 합니다.
아래 예시는 형태만 보여줍니다. 실제 값은 서명 쿼리 파라미터도 함께 가지지만, 게시된 예시는 스펙에 영원히 남고 실제 서명은 유출된 자격 증명이자 작동을 멈추는 링크이므로 여기서는 의도적으로 생략했습니다.각 이미지는 25 MiB로 제한되며, 하나의 요청에서 이미지 전체 합계는 64 MiB로 제한됩니다. 한 가지 예외는 `context_window`를 사용할 수 있는 ideogram/ideogram-4-5 Precise Edit(`image`를 전송하는 호출)이며, 여기서는 각 이미지가 최대 50 MB(50,000,000바이트) 및 67,108,864픽셀, 하나의 요청에서 이미지 전체 합계가 최대 128 MiB까지 허용됩니다.
