### 입력

<ParamField body="background" type="string">
  배경 투명도입니다. `auto`를 사용하면 모델이 선택합니다.

  가능한 값: `transparent`, `opaque`, `auto`
</ParamField>

<ParamField body="image" type="string | string[]">
  편집할 소스 이미지입니다. 이 필드가 있으면 편집 작업이 선택됩니다. 텍스트 기반 이미지 생성에는 이 필드를 완전히 생략하십시오.
모델의 공개 예시는 이 필드를 생략하는 GENERATION 호출입니다. `image`를 추가하는 것이 두 모드 사이의 차이 전부입니다: 엔드포인트도 같고 모델 id도 같습니다. 다만 편집 프롬프트는 장면이 아니라 원하는 변경을 설명하므로, 구조적으로 새로 추가되는 필드는 이것 하나뿐인데도 아래의 편집 본문은 생성 예시와 다르게 읽힙니다.
표시된 그대로 복사할 수 있습니다: `{"prompt": "give the rocketship rainbow coloring", "image": ["data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="], "size": "1024x1024"}`. 페이로드는 축약형이 아니라 완전한 1x1 PNG이며, 이 본문은 Router 자체의 요청 검증 테스트에서 허용되는 사례로 고정되어 있습니다. 자신의 이미지 바이트로 교체하십시오.
이미지 하나 또는 이미지 배열을 받습니다. gpt-image-1 및 이후 모델은 최대 16개까지 받으며, Router는 디스패치하기 전에 이 스키마를 기준으로 이를 강제합니다.
</ParamField>

<ParamField body="mask" type="string">
  이미지 하나를 지정하며, Router가 호출자를 대신해 가져오는 https URL 또는 바이트를 인라인으로 담은 `data:image/<format>;base64,<payload>` URI 중 하나입니다. 허용되는 이미지 유형은 png, webp, jpeg이며, 이 집합은 공급자에게 맡기지 않고 확인 시점에 강제됩니다. svg, gif, avif, tiff는 원인에서 두 단계 떨어진 파트너 오류가 되는 대신, 보낸 이미지를 지목하며 여기에서 거부됩니다.
URL 형식을 선호하십시오. base64 페이로드는 대략 4/3로 증가하고 전체 요청 본문은 100 MiB로 제한되므로, 인라인 형식은 소스 이미지 약 75 MB에서 한계에 도달합니다. URL은 이 문제를 완전히 피해 갑니다. 이 설명 끝에 명시된 이미지당 및 요청당 미디어 상한은 본문 상한보다 더 엄격하므로, 실제 크기가 있는 이미지라면 이 상한을 먼저 만나게 됩니다.
URL은 자격 증명 없이 접근할 수 있어야 합니다. Router는 이를 서버 측에서 가져오며 요청에 호출자 자격 증명을 보내지 않습니다. 따라서 서명이 쿼리 문자열에 포함된 형태인 presigned URL이 지원되는 형식입니다. `/api/assets/{id}/content` 같은 인증된 엔드포인트는 이미지 대신 Router에 401을 응답합니다. 해당 URL을 직접 요청하고 리다이렉트되는 서명된 URL을 전달하십시오.
가져오기는 오픈 인터넷이 아니라 이름이 지정된 호스트 집합으로 제한되며, 동일한 목록이 보내는 URL뿐 아니라 모든 리다이렉트 홉에도 다시 적용됩니다. 따라서 다른 호스트의 URL이나 목록 밖으로 리다이렉트하는 URL은 어떤 공급자와도 접촉하기 전에 거부됩니다. 현재 이 목록은 Comfy 자체 에셋 전달만 포함합니다: Comfy 에셋 버킷 아래의 서명된 `storage.googleapis.com` URL이며, `/api/assets/{id}/content`가 리다이렉트하는 형식입니다. 파트너 CDN이나 일반 https 호스트는 목록에 없습니다.
두 가지 확장이 롤아웃 중이며 현재 둘 다 기본적으로 꺼져 있습니다. 이들은 하나의 전환 뒤에서 제공되며 함께 활성화되므로, 아래의 모든 내용은 아직 구축 대상으로 삼을 것이 아니라 향후 제공될 예정인 것으로 취급하십시오. 둘 중 하나에 의존하기 전에 문의하십시오.
첫 번째는 `POST /customers/storage`가 업로드를 서명해 넣는 버킷입니다. 롤아웃이 사용자 환경에 도달할 때까지 해당 엔드포인트의 업로드 URL은 여기에서 거부됩니다. 버킷은 Comfy 자체의 것이고 호스트도 동일한데도 그렇습니다. 따라서 "Comfy에 업로드한 다음 URL을 전달"하는 방식은 아직 작동하지 않으며, 작동하는 형식은 `/api/assets/{id}/content`가 리다이렉트하는 서명된 URL입니다.
두 번째는 모든 사용자에게 한꺼번에 적용되는 것이 아니라 계정별로 활성화됩니다. 이 호스트 뒤의 버킷이 우리 것이 아니라 사용자의 것이기 때문입니다. 위의 전환이 켜져 있더라도 제3자 인바운드 미디어가 활성화되지 않은 계정은 거부되며, 호스트가 지원되지 않는다는 안내 대신 그 표현 그대로 안내받습니다. 사용자의 계정에 대해 활성화하려면 Comfy 담당자에게 문의하십시오. 또한 버킷이 사용자 소유이고 Router가 이에 대해 소유권을 주장하지 않는 다음 제3자 오브젝트 스토리지 호스트를 추가로 허용합니다: Cloudflare R2 (`<account>.r2.cloudflarestorage.com`, `pub-<hash>.r2.dev`), Amazon S3 (`s3.amazonaws.com` 및 `s3.<region>.amazonaws.com`, 경로 스타일 또는 `<bucket>.` 접두사 형식 모두), Azure Blob Storage (`<account>.blob.core.windows.net`) 및 Alibaba Cloud OSS (`<bucket>.oss-<region>.aliyuncs.com`, `oss-accelerate` 엔드포인트 포함). 이들은 특히 오브젝트 스토리지 엔드포인트입니다: 같은 공급자 도메인의 범용 엔드포인트, 예를 들어 Alibaba Function Compute 트리거는 목록에 없으며 거부됩니다.
일치되는 것은 공급자가 아니라 호스트 이름 형식입니다. 따라서 위에서 공급자를 언급했다고 해서 해당 공급자가 발급할 수 있는 모든 URL이 허용되는 것은 아니며, 호출자가 합리적으로 각각에 도달할 수 있는 세 가지 유사 사례를 분명히 언급할 가치가 있습니다. R2 사용자 지정 도메인(`cdn.example.com`)은 허용되지 않습니다: Cloudflare는 `pub-<hash>.r2.dev`를 속도 제한이 있는 디버그 호스트 이름으로 문서화하고 프로덕션 트래픽은 대신 사용자 지정 도메인으로 보냅니다. 그러나 사용자 지정 도메인은 호스트 이름에 R2임을 식별하는 정보가 없으므로 Router는 이를 다른 호스트와 구분할 수 없어 거부합니다. `<account>.r2.cloudflarestorage.com` 엔드포인트에 presign하거나 `pub-<hash>.r2.dev` 형식을 사용하십시오. S3의 IPv6 dualstack 엔드포인트(`s3.dualstack.<region>.amazonaws.com`)도 허용되지 않습니다. 일반 리전 엔드포인트를 사용하십시오. Azure Blob의 대체 DNS 영역(`<account>.z<N>.blob.storage.azure.net`)도 허용되지 않습니다. `<account>.blob.core.windows.net`을 사용하십시오. 돌려받는 거부 메시지에는 이와 동일한 형식이 명시되므로 이를 읽기 위해 여기로 올 필요는 없습니다.
`<account>` 및 `pub-<hash>` 자리 표시자는 일반적으로 도착하게 될 형태를 보여 줍니다. 이는 깊이 제한이 아닙니다. 일치는 객체 스토리지 도메인 접미사에서 이루어지므로, 같은 네임스페이스 아래의 더 깊은 이름(`a.b.pub-<hash>.r2.dev`)도 허용됩니다. 그로 인해 확장되지 않는 것은 네임스페이스 자체입니다. 접미사는 여전히 나열된 것 중 하나여야 합니다.
아래 예시는 형태만 보여 줍니다. 실제 값에는 서명 쿼리 파라미터도 포함되어 있는데, 여기서는 의도적으로 생략했습니다. 게시된 예시는 명세에 영구히 남고, 실제 서명은 유출된 자격 증명이자 작동이 중단되는 링크이기 때문입니다.
각 이미지는 25 MiB로 제한되며, 한 요청의 이미지들은 총 64 MiB로 제한됩니다. 유일한 예외는 `image`를 보내는 호출이면서 `context_window`를 사용할 수 있는 ideogram/ideogram-4-5 Precise Edit입니다. 여기서는 각 이미지가 최대 50 MB(50,000,000바이트) 및 67,108,864픽셀까지 가능하고, 한 요청의 이미지들은 총 128 MiB까지 가능합니다.
</ParamField>

<ParamField body="size" type="string">

<ParamField body="stream" type="boolean">

Router가 `text/event-stream`을 중계하는 대신 공급자 응답을 캡처하기 때문입니다(`image`를 포함한 요청에서는 편집이 이 필드 없이 다시 인코딩되므로 대신 이 필드를 삭제합니다). 어떤 Comfy 인터페이스도 gpt-image 부분 이미지 스트리밍을 제공하지 않습니다. v1 `POST /proxy/openai/images/generations` 인그레스는 `stream: true`를 400으로 거부하고 요청을 업스트림으로 전혀 전달하지 않습니다. 따라서 이 필드를 생략하고 완료된 응답을 하나의 JSON 본문으로 읽으세요. 스트림이 열리지 않으므로 `stream: true`와 1보다 큰 `n`을 함께 사용하는 것에 대한 OpenAI의 제한은 여기에 적용되지 않습니다. `n`은 보낸 그대로 전달됩니다.
</ParamField>

OpenAI가 이미지 생성 응답에서 REQUIRED로 선언한 유일한 멤버이므로, OpenAI가 생성 주체일 때는 항상 존재합니다. alt 기반 id 중 fal-, pika-, wavespeed-, runware-가 처리한 응답에서는 다른 네 개의 확정된 파라미터 멤버와 마찬가지로 이 필드가 완전히 생략됩니다. 현재의 epoch 값이 2^31에 충분히 가까워서, `integer`로 서식 없이 선언하면 많은 SDK 생성기에서 32비트 필드가 만들어지기 때문에 `int64`로 선언되었습니다.
