모델의 공개 예시는 이 필드를 생략한 GENERATION 호출입니다. `image`를 추가하는 것이 두 모드 사이의 차이 전부입니다(같은 엔드포인트, 같은 모델 id). 다만 편집 프롬프트는 장면이 아니라 원하는 변경을 설명하므로, 구조적으로 새로운 것은 이 필드뿐인데도 아래의 편집 본문은 생성 예시와 다르게 읽힙니다.
그대로 복사해 사용할 수 있습니다: `{"prompt": "give the rocketship rainbow coloring", "image": ["data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="], "size": "1024x1024"}`. 이 페이로드는 축약이 아니라 완전한 1x1 PNG이며, 이 본문은 Router 자체의 요청 검증 테스트에서 허용되는 사례로 고정되어 있습니다. 자신의 이미지 바이트로 바꿔 넣으세요.

<ParamField body="mask" type="string">
  이미지 하나로, Router가 호출자를 대신해 가져오는 https URL 또는 바이트를 인라인으로 담은 `data:image/<format>;base64,<payload>` URI 중 하나입니다. 허용되는 이미지 유형은 png, webp, jpeg이며, 이 집합은 공급자에게 맡기지 않고 resolve 시점에 강제됩니다. svg, gif, avif 또는 tiff는 원인에서 두 단계 떨어진 파트너 오류가 되는 대신, 보낸 이미지를 지목하며 여기에서 거부됩니다.
URL 형식을 권장합니다. base64 페이로드는 약 4/3로 부풀고 전체 요청 본문은 100 MiB로 제한되므로, 인라인 형식은 약 75 MB 소스 이미지에서 한계에 도달합니다. URL은 이를 완전히 피해갑니다. 이 설명 끝에 명시된 이미지당 및 요청당 미디어 상한은 본문 상한보다 더 엄격하므로, 어느 정도 실제 크기의 이미지라면 먼저 마주치는 것은 이 상한입니다.
URL은 자격 증명 없이 해석되어야 합니다. Router는 이를 서버 측에서 가져오며 요청에 호출자 자격 증명을 보내지 않으므로, 서명이 쿼리 문자열에 있는 presigned URL이 지원되는 형식입니다. `/api/assets/{id}/content` 같은 인증된 엔드포인트는 이미지 대신 Router에 401을 응답합니다. 해당 URL을 직접 요청하고 그것이 리디렉션하는 서명된 URL을 전달하세요.
가져오기는 개방된 인터넷이 아니라 지정된 호스트 집합으로 제한되며, 동일한 목록이 보내는 URL뿐 아니라 모든 리디렉션 홉에도 다시 적용됩니다. 따라서 다른 호스트의 URL이나 목록 밖으로 리디렉션하는 URL은 어떤 공급자에도 접촉하기 전에 거부됩니다. 현재 그 목록은 Comfy 자체의 에셋 전송뿐입니다. Comfy 에셋 버킷 아래의 서명된 `storage.googleapis.com` URL이며, 이것이 `/api/assets/{id}/content`가 리디렉션하는 형식입니다. 파트너 CDN이나 일반 https 호스트는 목록에 없습니다.
두 가지 확장이 롤아웃 중이며 오늘 기준 둘 다 기본적으로 꺼져 있습니다. 하나의 전환 뒤에서 출시되어 함께 활성화되므로, 아래 내용은 아직 대비해 개발할 대상이 아니라 예정된 사항으로 취급하세요. 둘 중 하나에 의존하기 전에 문의하세요.
첫 번째는 `POST /customers/storage`가 업로드에 서명하는 버킷입니다. 롤아웃이 귀하의 환경에 도달할 때까지 해당 엔드포인트의 업로드 URL은 여기에서 거부됩니다. 버킷이 Comfy 자체 것이고 호스트도 동일한데도 그렇습니다. 따라서 "Comfy에 업로드한 다음 URL을 전달"은 아직 작동하지 않으며, 작동하는 형식은 서명된 URL `/api/assets/{id}/content`가 리디렉션하는 URL입니다.
두 번째는 모든 사람에게 한꺼번에가 아니라 계정별로 활성화됩니다. 이 호스트들 뒤의 버킷이 우리 것이 아니라 귀하의 것이기 때문입니다. 위 전환이 켜져 있더라도 서드파티 인바운드 미디어가 활성화되지 않은 계정은 거부되며, 호스트가 지원되지 않는다는 대신 그런 문구로 안내됩니다. Comfy 담당자에게 계정에 대해 활성화를 요청하세요. 또한 버킷이 귀하의 것이고 Router가 이에 대한 소유권을 주장하지 않는 다음 서드파티 오브젝트 스토리지 호스트를 추가로 허용합니다: Cloudflare R2(`<account>.r2.cloudflarestorage.com`, `<id>.r2.dev`), Amazon S3(`s3.amazonaws.com` 및 `s3.<region>.amazonaws.com`, path-style 또는 `<bucket>.` 접두사 형식 모두), Azure Blob Storage(`<account>.blob.core.windows.net`), Alibaba Cloud OSS(`<bucket>.oss-<region>.aliyuncs.com`, `oss-accelerate` 엔드포인트 포함). 이들은 특히 오브젝트 스토리지 엔드포인트입니다. 같은 공급자 도메인의 범용 엔드포인트, 예를 들어 Alibaba Function Compute 트리거는 목록에 없으며 거부됩니다.
아래 예시는 형태만 보여줍니다. 실제 값은 서명 쿼리 파라미터도 함께 가지지만, 공개된 예시는 명세에 영원히 남고 실제 서명은 유출된 자격 증명이자 작동을 멈추는 링크이므로 여기서는 의도적으로 생략했습니다.

  생성된 이미지의 배경이 `opaque`인지 `transparent`인지, OpenAI가 이번 생성에 대해 확정한 값입니다. 요청 매개변수의 기본값은 `auto`이므로, 이 값을 고정하지 않은 호출자는 여기에서 실제로 어떤 값이 생성되었는지 알 수 있습니다.
</ResponseField>

<ResponseField name="created" type="integer">
  생성이 완료된 시각의 Unix 타임스탬프(초)입니다. OpenAI가 이미지 생성 응답에서 REQUIRED로 선언하는 유일한 멤버이므로, OpenAI가 생성자인 경우에는 항상 존재합니다. fal이 제공하는 `openai/gpt-image-2` 응답에서는 다른 네 개의 확정된 매개변수 멤버들과 마찬가지로 이 필드가 완전히 생략됩니다. `int64`로 선언된 이유는 현재의 epoch 값이 2^31에 충분히 가까워서, 포맷되지 않은 `integer`는 많은 SDK 생성기에서 32비트 필드를 만들기 때문입니다.

  형식: `int64`
</ResponseField>

<ResponseField name="output_format" type="string">
  `data[].b64_json`에 담긴 바이트의 인코딩으로, `png`, `webp` 또는 `jpeg`입니다. OpenAI가 실제로 인코딩한 형식이며, 요청에 `output_format`이 전송된 경우에는 그 값이고 전송되지 않은 경우에는 `png`입니다. 따라서 디코더는 요청에서 형식을 다시 도출하는 대신 이 값을 기준으로 삼을 수 있습니다.
</ResponseField>

<ResponseField name="quality" type="string">
  생성이 실제로 실행된 품질 등급으로, OpenAI는 `low`, `medium`, `high`, `xhigh` 또는 `max` 중 하나를 보고합니다. 이는 요청을 그대로 반환한 값이 아니라 확정된(RESOLVED) 등급이며, 요청 자체의 `quality` 기본값은 `auto`입니다.
</ResponseField>

<ResponseField name="size" type="string">
  생성이 실제로 실행된 픽셀 크기로, `<width>x<height>` 형식입니다. 이는 확정된(RESOLVED) 크기입니다. 요청의 `size` 기본값은 `auto`이고 `auto`를 명시적으로 허용하므로, 실제로 사용된 크기가 보고되는 유일한 위치입니다.
</ResponseField>
