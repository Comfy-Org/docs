동일한 본문을 `POST https://api.comfy.org/v2/models/openai/gpt-image-2.5-flare/requests` 로 보냅니다. Router는 실행이 접수되는 즉시 `201` 과 `request_id` 를 응답하며, 결과는 준비가 되면 이 프로세스나 다른 프로세스에서 수집합니다. 상태, 취소, 수집 방법은 [큐 전송](/ko/development/comfy-router/queue) 를 참고하세요.

```python Python
from comfy_sdk import Comfy

# 환경에서 COMFY_API_KEY를 읽습니다.
# 각 submit() 호출은 자체 Idempotency-Key를 생성하고 자동 재시도에 재사용합니다.
with Comfy() as client:
    handle = client.models.submit(
        "openai/gpt-image-2.5-flare",
        {
            "prompt": "a rocketship on a launchpad",
            "quality": "low",
            "size": "1024x1024",
        },
    )
    print("request_id:", handle.request_id)  # 모델 ID와 함께라면 다른 프로세스에 필요한 전부입니다

    # 요청이 완료될 때까지 폴링하며, 서버가 지정한 Retry-After만큼 대기합니다.
    for update in handle.iter_events():
        print(update.status, update.queue_position)

    # 공급자의 자체 페이로드이며, models.run()이 반환하는 것과 동일한 값입니다.
    # 실패하거나 취소된 요청은 여기에서 타입이 지정된 Router 오류를 발생시킵니다.
    result = handle.get()

print(result)
```

  size: "1024x1024",
});

for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// models.run()이 반환하는 것과 동일한 결과입니다. 실패하거나 취소된 요청은 여기에서 거부됩니다.

    print(update.state.rawValue, update.queuePosition.map(String.init) ?? "unknown")

// A request that failed or was cancelled throws the typed Router error here.
let result = try await handle.result()

### 입력

<ParamField body="background" type="string">
  배경 투명도

  가능한 값: `transparent`, `opaque`
</ParamField>

<ParamField body="image" type="string | string[]">
  편집할 소스 이미지입니다. 이 필드의 존재 여부가 편집 작업을 선택합니다. 텍스트 기반 이미지 생성의 경우 이 필드를 완전히 생략하세요.
모델의 공개 예시는 이 필드를 생략한 생성 호출입니다. `image`를 추가하는 것이 두 모드 사이의 차이 전부입니다. 엔드포인트도, 모델 id도 동일합니다. 다만 편집 프롬프트는 장면이 아니라 원하는 **변경**을 설명하므로, 구조적으로 새로운 필드는 이것 하나뿐인데도 아래의 편집 본문은 생성 예시와 다르게 읽힙니다.
그대로 복사해 쓸 수 있습니다: `{"prompt": "give the rocketship rainbow coloring", "image": ["data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="], "size": "1024x1024"}` -- 페이로드는 축약이 아니라 완전한 1x1 PNG이며, 이 본문은 Router 자체의 요청 검증 테스트에서 허용되는 사례로 고정되어 있습니다. 여러분 이미지의 바이트로 바꿔 넣으세요.
이미지 하나 또는 그 배열을 받습니다. gpt-image-1 이후 버전은 최대 16개까지 받으며, Router는 디스패치 전에 이 스키마를 기준으로 이를 강제합니다.
</ParamField>

<ParamField body="mask" type="string">
  이미지 하나로, Router가 호출자를 대신해 가져오는 https URL이거나 바이트를 인라인으로 담은 `data:image/<format>;base64,<payload>` URI입니다. 허용되는 이미지 유형은 png, webp, jpeg이며, 이 집합은 공급자에게 맡기지 않고 확인 시점에 **강제**됩니다. svg, gif, avif 또는 tiff는 원인에서 두 단계 떨어진 파트너 오류가 되는 대신, 보낸 이미지를 지목하며 여기서 거부됩니다.
URL 형식을 권장합니다. base64 페이로드는 대략 4/3로 부풀고 요청 본문 전체가 20 MiB로 제한되므로, 인라인 형식은 약 15 MB 소스 이미지에서 한계에 도달합니다. URL은 이를 완전히 피해 갑니다.
**URL은 여러분의 자격 증명 없이 해석되어야 합니다.** Router는 이를 서버 측에서 가져오며 요청에 호출자 자격 증명을 함께 보내지 않습니다. 따라서 서명이 쿼리 문자열에 있는 presigned URL이 지원되는 형식입니다. `/api/assets/{id}/content` 같은 인증된 엔드포인트는 Router에 이미지 대신 401을 응답합니다. 그 URL을 직접 요청하고, 리다이렉트되는 서명된 URL을 전달하세요.
**가져오기는 개방된 인터넷이 아니라 지정된 호스트 집합으로 제한**되며, 같은 목록이 보내는 URL은 물론 모든 리다이렉트 단계에도 다시 적용됩니다. 따라서 다른 호스트의 URL이나 목록 밖으로 리다이렉트되는 URL은 어떤 공급자와도 접촉하기 전에 거부됩니다. 현재 이 목록에는 Comfy 자체의 에셋 전송만 포함됩니다. 즉 Comfy 에셋 버킷 아래의 서명된 `storage.googleapis.com` URL이며, 이는 `/api/assets/{id}/content`가 리다이렉트하는 형식입니다. 파트너 CDN이나 일반 https 호스트는 목록에 **없습니다**.
**두 가지 확장이 순차 배포 중이며 현재 둘 다 기본적으로 꺼져 있습니다.** 두 기능은 하나의 전환 뒤에 함께 배포되어 함께 활성화되므로, 아래 내용은 아직 이를 기반으로 개발할 대상이 아니라 예정된 사항으로 취급하세요. 둘 중 하나에 의존하기 전에 문의하세요.
**첫 번째**는 `POST /customers/storage`가 업로드를 서명해 넣는 버킷입니다. 배포가 여러분의 환경에 도달하기 전까지는 그 엔드포인트의 업로드 URL이 여기서 거부됩니다. 버킷이 Comfy 자체의 것이고 호스트도 동일한데도 그렇습니다. 따라서 "Comfy에 업로드한 뒤 URL을 전달"하는 방식은 아직 **작동하지 않으며**, 작동하는 형식은 `/api/assets/{id}/content`가 리다이렉트하는 서명된 URL입니다.
**두 번째**는 다음의 서드파티 객체 스토리지 호스트를 추가로 허용합니다. 이 경우 버킷은 여러분의 것이며 Router는 이에 대한 소유권을 주장하지 않습니다: Cloudflare R2 (`<account>.r2.cloudflarestorage.com`, `<id>.r2.dev`), Amazon S3 (`s3.amazonaws.com` 및 `s3.<region>.amazonaws.com`, 경로 스타일 또는 `<bucket>.` 접두 형식 모두), Azure Blob Storage (`<account>.blob.core.windows.net`), Alibaba Cloud OSS (`<bucket>.oss-<region>.aliyuncs.com`, `oss-accelerate` 엔드포인트 포함). 이들은 구체적으로 객체 스토리지 엔드포인트입니다. 같은 공급자 도메인의 범용 엔드포인트, 예컨대 Alibaba Function Compute 트리거는 목록에 없으며 거부됩니다.
아래 예시는 형태만 보여줍니다. 실제 값에는 서명 쿼리 파라미터도 포함되는데, 공개된 예시는 명세에 영원히 남고 실제 서명은 유출된 자격 증명이자 작동을 멈추는 링크이므로 여기서는 의도적으로 생략했습니다.
각 이미지는 25 MiB, 한 요청의 이미지들은 총 64 MiB로 제한됩니다.

</ResponseField>

<ResponseField name="output_format" type="string">
  `data[].b64_json`에 있는 바이트의 인코딩이며, `png`, `webp` 또는 `jpeg` 중 하나입니다. OpenAI가 실제로 인코딩한 형식으로, 요청이 전송된 경우에는 요청의 `output_format`이고 전송되지 않은 경우에는 `png`입니다. 따라서 디코더는 요청에서 형식을 다시 도출하는 대신 이 값을 기준으로 삼을 수 있습니다.
</ResponseField>

<ResponseField name="quality" type="string">
  생성이 실제로 실행된 품질 등급이며, OpenAI는 `low`, `medium`, `high`, `xhigh`, `max` 중 하나를 보고합니다. 이는 요청을 그대로 반영한 것이 아니라 확정된 등급입니다. 요청의 `quality` 자체는 기본값이 `auto`입니다.
</ResponseField>

<ResponseField name="size" type="string">
  생성이 실제로 실행된 픽셀 크기이며, `<width>x<height>` 형식입니다. 이는 확정된 크기입니다. 요청의 `size`는 기본값이 `auto`이고 `auto`를 명시적으로 허용하므로, 실제 사용된 크기가 보고되는 곳은 여기뿐입니다.
</ResponseField>
