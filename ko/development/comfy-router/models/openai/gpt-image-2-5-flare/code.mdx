## Serving providers

이 모델은 요청에서 다른 공급자를 지정하지 않는 한 Comfy Router가 직접 제공합니다. 아래 공급자들도 동일한 엔드포인트와 동일한 모델 ID로 이 모델을 제공하며, `model_provider` 쿼리 매개변수로 선택합니다.

- **Comfy** (기본값): `POST https://api.comfy.org/v2/models/openai/gpt-image-2.5-flare`
- **fal**, `fal/fal-gpt-image-2.5-flare`로: `POST https://api.comfy.org/v2/models/openai/gpt-image-2.5-flare?model_provider=fal`
- **Runware**, `runware/runware-gpt-image-2.5-flare`로: `POST https://api.comfy.org/v2/models/openai/gpt-image-2.5-flare?model_provider=runware`
- **WaveSpeed**, `wavespeed/wavespeed-gpt-image-2.5-flare`로: `POST https://api.comfy.org/v2/models/openai/gpt-image-2.5-flare?model_provider=wavespeed`

`strict_mode`의 기본값은 거짓이므로, Router는 이 페이지에 문서화된 네이티브 요청 본문을 해당 공급자의 자체 스키마로 변환하고 응답을 다시 변환합니다. API 레퍼런스의 [`model_provider`, `strict_mode` 및 `fallback_provider`](/ko/development/comfy-router/reference#post-v2modelsprovidermodel)와 이러한 방식으로 라우팅되는 모든 모델에 대해서는 [Serving providers](/ko/development/comfy-router/providers)를 참조하세요.

<ParamField body="image" type="string | string[]">
  편집할 소스 이미지입니다. 이 필드의 존재 여부가 편집 작업을 선택합니다. 텍스트 기반 이미지 생성 시에는 이 필드를 완전히 생략하세요.
모델의 공개된 예시는 이 필드를 생략하는 생성 호출입니다. `image`를 추가하는 것이 두 모드 사이의 차이 전부입니다. 동일한 엔드포인트, 동일한 모델 id이며, 다만 편집 프롬프트는 장면이 아니라 원하는 변경 사항을 설명하므로, 구조적으로 새로운 필드는 이것 하나뿐인데도 아래의 편집 본문은 생성 예시와 다르게 읽힙니다.
이는 인쇄된 그대로 복사할 수 있습니다: `{"prompt": "give the rocketship rainbow coloring", "image": ["data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="], "size": "1024x1024"}`. 페이로드는 축약이 아니라 완전한 1x1 PNG이며, 이 본문은 Router 자체의 요청 검증 테스트에서 허용 사례로 고정되어 있습니다. 자신의 이미지 바이트로 교체하세요.
이미지 하나 또는 이미지 배열을 허용합니다. gpt-image-1 및 이후 버전은 최대 16개를 받으며, Router는 디스패치 전에 이 스키마에 따라 이를 강제합니다.
</ParamField>

<ParamField body="mask" type="string">
  이미지 하나로, Router가 호출자를 대신해 가져오는 https URL 또는 바이트를 인라인으로 담은 `data:image/<format>;base64,<payload>` URI 중 하나입니다. 허용되는 이미지 유형은 png, webp, jpeg이며, 이 집합은 공급자에게 맡기지 않고 resolve 시점에 강제됩니다. svg, gif, avif 또는 tiff는 원인에서 두 홉 떨어진 파트너 오류가 되는 대신, 보낸 이미지를 지목하며 여기에서 거부됩니다.
URL 형식을 선호하세요. base64 페이로드는 대략 4/3로 부풀고 전체 요청 본문은 100 MiB로 제한되므로, 인라인 형식은 약 75 MB 소스 이미지에서 한계에 도달합니다. URL은 이를 완전히 우회합니다. 이 설명 끝에 명시된 이미지당 및 요청당 미디어 상한은 본문 상한보다 더 엄격하므로, 실제 크기가 있는 이미지라면 먼저 마주치는 것은 이 상한입니다.
URL은 자격 증명 없이 해석되어야 합니다. Router는 이를 서버 측에서 가져오며 요청에 호출자 자격 증명을 보내지 않으므로, 서명이 쿼리 문자열에 있는 presigned URL이 지원되는 형식입니다. `/api/assets/{id}/content` 같은 인증된 엔드포인트는 이미지 대신 Router에 401을 응답합니다. 해당 URL을 직접 요청하고 그것이 리디렉션하는 서명된 URL을 전달하세요.
가져오기는 열린 인터넷이 아니라 이름이 지정된 호스트 집합으로 제한되며, 동일한 목록이 보내는 URL뿐 아니라 모든 리디렉션 홉에도 다시 적용됩니다. 따라서 다른 호스트의 URL이나 목록 밖으로 리디렉션하는 URL은 어떤 공급자와도 접촉하기 전에 거부됩니다. 현재 이 목록은 Comfy 자체 에셋 전달뿐입니다. Comfy 에셋 버킷 아래의 서명된 `storage.googleapis.com` URL이며, 이것이 `/api/assets/{id}/content`가 리디렉션하는 형식입니다. 파트너 CDN이나 일반 https 호스트는 목록에 없습니다.
두 가지 확장이 롤아웃 중이며 오늘 기준 둘 다 기본적으로 꺼져 있습니다. 이들은 하나의 전환 뒤에 출시되어 함께 활성화되므로, 아래의 모든 내용을 아직 대비해 개발할 대상이 아니라 예정된 사항으로 취급하세요. 둘 중 하나에 의존하기 전에 문의하세요.
첫 번째는 `POST /customers/storage`가 업로드를 서명해 넣는 버킷입니다. 롤아웃이 여러분의 환경에 도달할 때까지 그 엔드포인트의 업로드 URL은 여기에서 거부됩니다. 버킷이 Comfy 자체의 것이고 호스트도 동일한데도 그렇습니다. 따라서 "Comfy에 업로드한 다음 URL을 전달"하는 방식은 아직 작동하지 않으며, 작동하는 형식은 `/api/assets/{id}/content`가 리디렉션하는 서명된 URL입니다.
두 번째는 모든 사람에게 한꺼번에가 아니라 계정별로 활성화됩니다. 이 호스트들 뒤의 버킷이 우리 것이 아니라 여러분의 것이기 때문입니다. 위 전환이 켜진 뒤에도 서드파티 인바운드 미디어가 활성화되지 않은 계정은 거부되며, 호스트가 지원되지 않는다는 말 대신 그대로 그렇게 통보받습니다. Comfy 담당자에게 계정에 대해 활성화를 요청하세요. 이는 추가로 다음 서드파티 오브젝트 스토리지 호스트를 허용합니다. 여기서 버킷은 여러분의 것이며 Router는 이에 대한 소유권을 주장하지 않습니다: Cloudflare R2 (`<account>.r2.cloudflarestorage.com`, `<id>.r2.dev`), Amazon S3 (`s3.amazonaws.com` 및 `s3.<region>.amazonaws.com`, path-style 또는 `<bucket>.` 접두사 형식 모두), Azure Blob Storage (`<account>.blob.core.windows.net`), Alibaba Cloud OSS (`<bucket>.oss-<region>.aliyuncs.com`, `oss-accelerate` 엔드포인트 포함). 이들은 구체적으로 오브젝트 스토리지 엔드포인트입니다. 같은 공급자 도메인의 범용 엔드포인트, 예를 들어 Alibaba Function Compute 트리거는 목록에 없으며 거부됩니다.
아래 예시는 형태만 보여줍니다. 실제 값은 서명 쿼리 파라미터도 함께 담는데, 공개된 예시는 스펙에 영원히 남고 실제 서명은 유출된 자격 증명이자 작동을 멈추는 링크이므로 여기서는 의도적으로 생략했습니다.
각 이미지는 25 MiB로, 한 요청의 이미지는 총 64 MiB로 제한됩니다.
</ParamField>

<ResponseField name="background" type="string">
  생성된 이미지의 배경이 `opaque`인지 `transparent`인지를 나타내며, OpenAI가 이번 생성에서 해석한 값입니다. 요청 파라미터의 기본값은 `auto`이므로, 이를 고정하지 않은 호출자는 여기에서 실제로 생성된 값이 무엇인지 알 수 있습니다.
</ResponseField>

<ResponseField name="created" type="integer">
  생성이 완료된 시점의 Unix 타임스탬프(초)입니다. OpenAI가 이미지 생성 응답에서 필수(REQUIRED)로 선언하는 유일한 멤버이므로, OpenAI가 생성자인 경우에는 항상 존재합니다. fal이나 wavespeed가 제공하는 `openai/gpt-image-2` 응답에서는 나머지 네 개의 해석된 파라미터 멤버와 마찬가지로 이 필드가 완전히 생략됩니다. `int64`로 선언된 이유는 현재의 epoch 값이 2^31에 충분히 가까워서, 포맷을 지정하지 않은 `integer`는 많은 SDK 생성기에서 32비트 필드를 만들어 내기 때문입니다.

  형식: `int64`
</ResponseField>

<ResponseField name="output_format" type="string">
  `data[].b64_json`에 담긴 바이트의 인코딩: `png`, `webp` 또는 `jpeg`. OpenAI가 실제로 인코딩한 형식이며, 요청에 `output_format`이 전송된 경우에는 그 값이, 전송되지 않은 경우에는 `png`가 됩니다. 따라서 디코더는 요청에서 형식을 다시 도출할 필요 없이 이 값을 기준으로 삼을 수 있습니다.
</ResponseField>

<ResponseField name="quality" type="string">
  생성이 실제로 실행된 품질 등급: OpenAI는 `low`, `medium`, `high`, `xhigh` 또는 `max` 중 하나를 보고합니다. 이는 요청을 그대로 반영한 것이 아니라 해석된(RESOLVED) 등급이며, 요청 자체의 `quality` 기본값은 `auto`입니다.
</ResponseField>

<ResponseField name="size" type="string">
  생성이 실제로 실행된 픽셀 크기로, `<width>x<height>` 형식입니다. 이는 해석된(RESOLVED) 크기입니다. 요청의 `size` 기본값은 `auto`이며 `auto`를 명시적으로 허용하므로, 실제로 사용된 크기가 보고되는 유일한 위치입니다.
</ResponseField>
