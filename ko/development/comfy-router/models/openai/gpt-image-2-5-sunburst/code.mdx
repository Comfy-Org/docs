URL 형식을 권장합니다. base64 페이로드는 약 4/3로 팽창하고 전체 요청 본문은 100 MiB로 제한되므로, 인라인 형식은 약 75 MB 소스 이미지에서 한계에 도달합니다. URL은 이 문제를 완전히 피해 갑니다. 이 설명 끝에 명시된 이미지당 및 요청당 미디어 상한은 본문 상한보다 더 엄격하므로, 실질적인 크기의 이미지라면 이 상한에 먼저 부딪힙니다.

<ResponseField name="background" type="string">
  생성된 이미지의 배경이 `opaque`인지 `transparent`인지 여부로, OpenAI가 이번 생성에 대해 해석한 값입니다. 요청 파라미터의 기본값은 `auto`이므로, 이를 고정하지 않은 호출자는 여기에서 어떤 값이 생성되었는지 알 수 있습니다.
</ResponseField>

<ResponseField name="created" type="integer">
  생성이 완료된 시각의 Unix 타임스탬프(초)입니다. OpenAI가 이미지 생성 응답에서 REQUIRED로 선언한 유일한 멤버이므로, OpenAI가 생성 주체일 때는 항상 존재합니다. fal이 제공하는 `openai/gpt-image-2` 응답에서는 다른 네 개의 해석된 파라미터 멤버와 마찬가지로 이 필드가 완전히 생략됩니다. 현재의 epoch 값이 2^31에 충분히 가까워, 서식을 지정하지 않은 `integer`는 많은 SDK 생성기에서 32비트 필드를 만들어내기 때문에 `int64`로 선언되었습니다.

  형식: `int64`
</ResponseField>

<ResponseField name="output_format" type="string">
  `data[].b64_json`에 담긴 바이트의 인코딩으로, `png`, `webp` 또는 `jpeg`입니다. 이는 OpenAI가 실제로 인코딩한 형식이며, 요청에 `output_format`이 전송된 경우에는 그 값이, 전송되지 않은 경우에는 `png`가 됩니다. 따라서 디코더는 요청에서 형식을 다시 도출하는 대신 이 값을 기준으로 삼을 수 있습니다.
</ResponseField>

<ResponseField name="quality" type="string">
  생성이 실제로 실행된 품질 등급으로, OpenAI는 `low`, `medium`, `high`, `xhigh` 또는 `max` 중 하나를 보고합니다. 이는 요청을 그대로 반영한 것이 아니라 해석된(RESOLVED) 등급이며, 요청 자체의 `quality` 기본값은 `auto`입니다.
</ResponseField>

<ResponseField name="size" type="string">
  생성이 실제로 실행된 픽셀 크기로, `<width>x<height>` 형식입니다. 이는 해석된(RESOLVED) 크기입니다. 요청의 `size`는 기본값이 `auto`이고 `auto`를 명시적으로 허용하므로, 실제 사용된 크기가 보고되는 곳은 여기뿐입니다.
</ResponseField>
