Wan 3.0 Video API 레퍼런스. Wan 3.0 Video는 프롬프트만으로 생성하거나, 첫 프레임과 마지막 프레임, 레퍼런스 이미지, 비디오, 오디오로 구성된 미디어 목록으로 생성할 수 있으며, 프롬프트에서는 각각 Image 1, Video 1, Audio 1로 지칭됩니다.

**입력:** 텍스트, 이미지, 비디오, 오디오 · **출력:** 비디오 + 오디오

## 빠른 시작

[내 Comfy 워크스페이스](https://platform.comfy.org/profile/api-keys?onboarding=router)에서 키를 생성하고 `COMFY_API_KEY`로 내보내세요. Python 및 TypeScript 스니펫은 Comfy SDK(`pip install comfy-sdk` 및 `npm install @comfyorg/sdk`)를 사용하며, cURL 스니펫은 원시 HTTP를 통한 동일한 호출입니다.

**모델 ID:** `wan/wan3.0-video`

**엔드포인트:** `POST https://api.comfy.org/v2/models/wan/wan3.0-video`

```python Python
import asyncio
from comfy_sdk import AsyncComfy

# 환경에서 COMFY_API_KEY를 읽습니다.
# 각 submit() 호출은 자체 Idempotency-Key를 생성하고 자동 재시도에 재사용합니다.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "wan/wan3.0-video",
            {
                "input": {
                    "prompt": "the robot lowers its raised arm and steps toward the camera, the flat orange backdrop holds steady",
                    "media": [
                        {
                            "type": "first_frame",
                            "url": "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # 모델 ID와 함께면 다른 프로세스에 필요한 전부입니다

        # 요청이 완료될 때까지 폴링하며, 서버가 지정한 Retry-After만큼 대기합니다.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # 공급자 자체의 페이로드로, models.run()이 반환하는 것과 동일한 값입니다.
        # 실패했거나 취소된 요청은 여기에서 타입이 지정된 Router 오류를 발생시킵니다.
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())
```

## 제공 공급자

이 모델은 요청에서 다른 공급자를 지정하지 않는 한 Comfy Router가 직접 제공합니다. 아래 공급자들도 같은 엔드포인트, 같은 모델 ID로 이 모델을 제공하며, `model_provider` 쿼리 매개변수로 선택합니다.

- **Comfy** (기본값): `POST https://api.comfy.org/v2/models/wan/wan3.0-video`
- **Higgsfield**, `higgsfield/higgsfield-wan-3`(으)로: `POST https://api.comfy.org/v2/models/wan/wan3.0-video?model_provider=higgsfield`

`strict_mode`의 기본값은 거짓(false)이므로, Router는 이 페이지에 문서화된 네이티브 요청 본문을 해당 공급자 자체의 스키마로 변환하고 응답을 다시 변환합니다. API 레퍼런스의 [`model_provider`, `strict_mode` 및 `fallback_provider`](/ko/development/comfy-router/reference#post-v2modelsprovidermodel)와, 이 방식으로 라우팅되는 모든 모델을 다루는 [제공 공급자](/ko/development/comfy-router/providers)를 참고하세요.

### 입력

<ParamField body="input" type="object" required>
  프롬프트 단어 등 기본 정보를 입력하세요.
</ParamField>

<ParamField body="input.audio_url" type="string">
  오디오 파일 다운로드 URL입니다. 지원 형식: mp3, wav. reference_video_urls와 함께 사용할 수 없습니다.
</ParamField>

<ParamField body="input.img_url" type="string">
  첫 프레임 이미지 URL 또는 Base64로 인코딩된 데이터입니다. wan2.5-i2v-preview 및
wan2.6-i2v 모델에서 필수입니다. happyhorse-1.x i2v 표기법은 첫 프레임을 여기서
받지 않습니다. 즉, first_frame 유형의 미디어 요소로 받으며(아래 media 참조),
wan2.6-i2v에서 성공하는 img_url 본문은 공급자가 happyhorse-1.0-i2v 및
happyhorse-1.1-i2v에서 거부합니다. 또한 wan2.7/wan3.0 표기법도 참조 에셋을
media에서 받습니다. 이미지 형식: JPEG, JPG, PNG, BMP, WEBP.
해상도: 360-2000 픽셀. 파일 크기: 최대 10MB.
</ParamField>

<ParamField body="input.media" type="object[]">
  미디어 에셋 목록입니다. 비디오 생성용 참조 자료(이미지, 오디오, 비디오)를
지정합니다. 각 요소는 type과 url 필드를 포함합니다. 이 필드는 이 컴포넌트에서
제공되는 모든 모델이 공유하며, 특정 모델이 어떤 type 값을 허용하는지, 그리고
이미지나 비디오 입력을 img_url이나 reference_video_urls가 아니라 여기에서 받는지
여부는 모델마다 다릅니다. 모델별 지원 type 값은 다음과 같습니다:
- wan2.7-i2v: first_frame, last_frame, driving_audio, first_clip. first_frame과
  last_frame: JPEG/JPG/PNG/BMP/WEBP, 변당 240-8000 픽셀, 가로세로 비율 1:8
  ~ 8:1, 최대 20MB, 공개 URL 또는 data:\{MIME_type};base64,... URL.
  driving_audio(WAV/MP3, 2-30초, 최대 15MB)와 first_clip(MP4/MOV, 2-10초,
  변당 240-4096 픽셀, 최대 100MB): 공개 HTTP/HTTPS URL이며, 인라인
  data: URL은 허용되지 않습니다.
- wan2.7-r2v: first_frame(선택 사항, 최대 1개), reference_image, reference_video.
  최소 하나의 reference_image 또는 reference_video가 필요하며, reference 이미지와
  reference 비디오를 합쳐 최대 5개입니다. first_frame과 reference_image:
  JPEG/JPG/PNG/BMP/WEBP(알파 채널 없음), 변당 240-8000 픽셀, 가로세로 비율 1:8 ~ 8:1,
  최대 20MB, 공개 URL 또는 data:\{MIME_type};base64,... URL. reference_video: 공개
  HTTP/HTTPS URL이며, 인라인 data: URL은 허용되지 않습니다.
- wan2.7-videoedit: video(정확히 1개, 편집 대상 클립: MP4/MOV, 2-10초,
  변당 240-4096 픽셀, 최대 100MB, 공개 HTTP/HTTPS URL이며, 인라인 data: URL은
  허용되지 않음)와 선택적 0~4개의 reference_image(JPEG/JPG/PNG/BMP/WEBP,
  변당 240-8000 픽셀, 가로세로 비율 1:8 ~ 8:1, 최대 20MB, 공개 URL
  또는 data:\{MIME_type};base64,... URL).
- wan3.0-video, wan3.0-video-prime: first_frame(최대 1개), last_frame(최대 1개),
  reference_image(최대 10개), reference_video(최대 5개 클립, 총 재생 시간 \<= 15초),
  reference_audio(최대 5개 클립, 총 재생 시간 \<= 15초), file(최대 1개, link와 함께
  사용할 수 없음), link(최대 1개, file과 함께 사용할 수 없음). reference_*/file/link
  유형과 first_frame/last_frame 유형은 동일한 요청 내에서 상호 배타적입니다.
  배열 순서는 프롬프트에서 에셋의 참조 순서를 정의합니다(Image 1, Video 1,
  Audio 1, ...). first_frame, last_frame 및 reference_image:
  JPEG/JPG/PNG/BMP/WEBP, 변당 240-8000 픽셀, 가로세로 비율 최대 8:1, 최대 20MB,
  공개 URL 또는 data:\{MIME_type};base64,... URL. reference_video, reference_audio,
  file 및 link: 공개 HTTP/HTTPS URL이며, 인라인 data: URL은 허용되지 않습니다.
- happyhorse-1.0-i2v, happyhorse-1.1-i2v: first_frame만 해당하며 정확히 1개입니다.
  이 표기법들은 첫 프레임을 img_url이 아니라 여기에서 받습니다. 최소 300x300 픽셀,
  가로세로 비율 1:2.5 ~ 2.5:1, JPEG/JPG/PNG/WEBP, 최대 20MB, 공개 URL 또는
  data:\{MIME_type};base64,... URL.
- happyhorse-1.0-r2v, happyhorse-1.1-r2v: reference_image만 해당하며 1~9개입니다.
  이것이 이 모델의 유일한 참조 입력입니다. 최단 변 최소 400 픽셀,
  JPEG/JPG/PNG/WEBP, 최대 20MB, 공개 URL 또는 data:\{MIME_type};base64,... URL.
  reference_video는 이 연산의 입력 유형이 아닙니다.
- happyhorse-1.0-video-edit: video(정확히 1개, 편집 대상 클립: MP4/MOV, 3-60초,
  긴 변 최대 4096 픽셀, 짧은 변 최소 360 픽셀, 가로세로 비율 1:2.5 ~ 2.5:1,
  최대 100MB, 공개 HTTP/HTTPS URL이며, 인라인 data: URL은 허용되지 않음)와
  선택적 0~5개의 reference_image(JPEG/JPG/PNG/BMP/WEBP, 최소 300x300 픽셀,
  가로세로 비율 1:2.5 ~ 2.5:1, 최대 20MB, 공개 URL 또는
  data:\{MIME_type};base64,... URL).
- happyhorse-1.0-t2v, happyhorse-1.1-t2v, wan2.7-t2v, wan2.6-t2v, wan2.5-t2v-preview:
  텍스트 기반 비디오 생성 연산입니다. 이들의 파트너 참조 문서에는 미디어 입력이
  문서화되어 있지 않으므로 이 필드를 설정하지 마세요.
- wan2.5-i2v-preview, wan2.6-i2v, wan2.6-r2v: 이 컴포넌트는 이 표기법들에 대한
  미디어 어휘를 열거하지 않습니다. wan2.5-i2v-preview와 wan2.6-i2v는 첫 프레임을
  img_url에서 받고, wan2.6-r2v는 참조 클립을 reference_video_urls에서 받습니다.
위의 모델별 개수는 이 스키마의 제약이 아니라 파트너의 제약입니다. 허용되는 유형과
그 상한이 모델마다 다르기 때문에 media에는 minItems/maxItems가 선언되어 있지
않습니다. 스키마가 허용한다고 해서 공급자가 허용하는 것은 아닙니다. 반대로, 위의
에셋별 "최대 20MB" 수치는(이미지 입력에 대한 상한이며, 인라인으로 전송될 수 있는
유일한 입력입니다) 파트너가 최종적으로 받는 에셋에 대한 파트너의 상한이며, 해당
에셋이 공개 URL일 때는 그대로 적용됩니다. 그 바이트는 Comfy를 거치지 않기
때문입니다. 인라인 data:\{MIME_type};base64,... URL은 Comfy를 거치며 전송 상한도
적용됩니다. Comfy Router의 POST 본문은 총 100 MiB로 제한되며 이를 초과하면 413으로
응답되고, base64는 페이로드를 약 4/3로 부풀리므로 대략 75 MB를 초과하는 단일 인라인
에셋은 여기의 파트너 규칙에 도달하기 전에 거부됩니다. 그 크기에서는 단일 에셋이
파트너 자체의20MB 상한은 인라인으로 충분히 들어가므로, 에셋 하나에 대해서는 파트너 규칙이 적용됩니다. 여러 에셋에 걸치면 전송 상한이 적용되는데, 100 MiB Router 상한이 각 요소가 아니라 요청 전체를 제한하기 때문입니다. 이 상한에 가까운 값은 공개 URL로 전송하세요.
</ParamField>

</ParamField>

<ParamField body="input.media[].url" type="string" required>
  미디어 파일의 URL: 공개 HTTP/HTTPS URL 또는, 위의 `media` 설명이 각 모델에 대해 나열한 바로 그 IMAGE 입력(wan2.7-i2v의 first_frame과 last_frame, wan2.7-r2v의 first_frame과 reference_image, wan2.7-videoedit의 reference_image, wan3.0-video와 wan3.0-video-prime의 first_frame, last_frame, reference_image, happyhorse-1.0-i2v와 happyhorse-1.1-i2v의 first_frame, happyhorse-1.0-r2v와 happyhorse-1.1-r2v의 reference_image, happyhorse-1.0-video-edit의 reference_image)에 한해 인라인 `data:{MIME_type};base64,...` URL입니다. 이 모델들 중 어느 것도 video, audio, file 또는 link 입력에 인라인 data: URL을 받지 않습니다. 파트너 자체 업로드 서비스의 oss://dashscope-instant 임시 URL 또는 (wan2.7-videoedit의 경우) Asset Center asset_id는 이를 업로드한 Alibaba Cloud 계정에 대해서만 해석됩니다.
