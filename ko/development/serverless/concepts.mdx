Comfy API에서는 정의한 환경과 그 환경을 실행하는 엔드포인트를 분리합니다. **Build**는 ComfyUI 환경을 정의합니다. **릴리스**는 Build를 지원 대상에 맞게 패키징합니다. **배포**는 릴리스를 관리형 엔드포인트로 실행합니다.

## 실행 방식 선택

| 선택 | 사용 사례 | 관리 항목 |
| --- | --- | --- |
| [Comfy Cloud](/ko/development/deploy/cloud) | 브라우저에서 관리형 ComfyUI를 사용하거나 엔드포인트를 설정하지 않고 워크플로를 실행합니다. | 워크플로와 API 호출입니다. Build나 배포를 만들 필요가 없습니다. |
| [Comfy API](/ko/development/serverless/quickstart) | 지정한 ComfyUI 환경, 모델, 커스텀 노드, 종속성을 갖춘 관리형 엔드포인트가 필요합니다. | Build, 해당 릴리스, 하나 이상의 배포입니다. |
| [자체 호스팅](/ko/development/deploy/self-hosting) | 머신, 소프트웨어, 모델, 커스텀 노드를 직접 선택하고 관리합니다. | 자체 ComfyUI 설치와 인프라입니다. |

워크플로에 Comfy Cloud에서 제공되지 않는 커스텀 노드나 종속성이 필요하다면 Comfy API 또는 자체 호스팅 ComfyUI를 사용하세요. Comfy API는 패키징된 환경에서 관리형 엔드포인트를 만듭니다. 변경 사항을 시험하는 대화형 Sandbox가 아닙니다.

## Comfy API 구성 요소의 관계

```text
워크스페이스 → 로컬 프로젝트 → Build → 릴리스 → 배포 → 워크플로 요청
```

1. **워크스페이스**: 팀에서 액세스 권한, Build, 배포, 사용량 한도를 관리하는 계정 범위입니다.
2. **로컬 프로젝트 폴더**: 컴퓨터에서 `comfy-build.yaml`과 관련 워크플로 또는 에셋 파일을 보관하는 폴더입니다. 이 파일은 Build를 설명하고 마지막으로 확인한 원격 상태를 추적합니다. 모델 파일은 포함하지 않습니다. 온라인 리소스가 아니라 로컬 폴더입니다.
3. **Build**: ComfyUI 버전, 모델, 커스텀 노드, 설정을 포함한 ComfyUI 환경 정의입니다. Developer Platform에 푸시하면 사용할 수 있습니다.
4. **릴리스**: `linux/nvidia`와 같은 지원 대상용으로 빌드된 Build 버전입니다. Build를 변경하거나 다른 대상이 필요하면 새 릴리스를 만드세요.
5. **배포**: 릴리스로 만든 실행 중인 엔드포인트입니다. GPU, 리전, 워커 수 범위와 같은 컴퓨팅 설정이 있습니다. 예를 들어 GPU 유형을 다르게 사용하도록 같은 Build에서 여러 배포를 실행할 수 있습니다.

[Comfy SDK](/ko/development/api-development/sdks) 또는 CLI를 사용해 배포 엔드포인트로 API 형식 워크플로 요청을 보냅니다. 배포는 릴리스에 패키징된 환경에서 요청을 실행합니다.

## 항목을 업데이트하면 어떻게 되나요?

- **환경 변경**: Build 정의를 업데이트하고 푸시한 다음 새 릴리스를 만듭니다. 준비가 되면 배포가 새 릴리스를 사용하도록 업데이트합니다.
- **용량 변경**: 배포를 확장하거나 중지합니다. Build나 릴리스가 아니라 컴퓨팅 설정이 바뀝니다.
- **다른 워크플로 실행**: 다른 API 형식 워크플로를 엔드포인트로 보냅니다. 필요한 모델과 노드가 Build에 이미 있으면 새 릴리스가 필요하지 않습니다.

**인스턴스**는 Comfy Desktop에서 관리하는 환경과 같은 ComfyUI 실행 환경을 뜻합니다. Comfy API에서 사용자가 만들고 운영하는 객체는 배포입니다. 내부 런타임 인스턴스는 직접 관리할 필요가 없습니다.
