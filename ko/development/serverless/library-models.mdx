Comfy API는 배포의 Release에 포함되어 있지 않더라도 워크스페이스 라이브러리의 모델을 실행합니다. LoRA 또는 다른 `.safetensors` 모델을 라이브러리에 업로드하고, 새 Build, Release, 재배포 없이 배포에서 실행하세요.

워크스페이스 라이브러리를 사용하면 배포에서 직접 학습한 LoRA를 사용해 보거나, 워크플로에서 파일 이름 하나만 변경하여 API 요청마다 다른 LoRA를 선택할 수 있습니다.

## 시작하기 전에

모델을 워크스페이스 라이브러리에 업로드하기 전에 다음 요구 사항을 충족해야 합니다:

- **플랜**: 워크스페이스에 활성 Pro, Creator, Team, Enterprise 플랜이 필요합니다.
- **모델 파일**: 파일은 2 GB 이하의 `.safetensors` 파일이어야 합니다. SDXL 또는 FLUX와 같은 더 큰 베이스 모델은 여전히 Build에 포함됩니다.
- **활성 배포**: 배포는 라이브러리와 동일한 워크스페이스에 있어야 합니다.

<Warning>
  워크스페이스 라이브러리 모델을 사용할 수 있게 되기 전에 생성된 일부 배포에서는 해당 모델을 로드할 수 없습니다. 워크스페이스 라이브러리 모델을 사용하려면 새 배포를 생성하세요. 이전 배포에서는 작업이 다음 메시지와 함께 실패할 수 있습니다: `Library model "<file name>" is unavailable on this deployment. Retry the job. If it still fails, contact support with the job ID.`
</Warning>

## 워크스페이스 라이브러리에 모델 업로드

세 가지 도구 중 하나로 모델을 업로드할 수 있습니다:

- **클라우드 편집기**: 파일을 업로드하거나 Civitai 또는 Hugging Face 링크에서 가져옵니다.
- **comfy-cli**: 터미널이나 스크립트에서 업로드합니다.
- **Developer Platform**: Build의 모델 단계에서 업로드합니다.

사용하는 도구의 탭을 선택하세요.

<Tabs>
  <Tab title="클라우드 편집기">
    1. **Run** 왼쪽의 배포 메뉴에서 **Run on** 아래에 **Comfy Cloud**가 선택되어 있는지 확인합니다.
    2. **왼쪽 사이드바**에서 **모델 라이브러리**를 클릭한 다음 **가져오기**를 클릭합니다.
    3. **파일 선택**을 클릭하거나 `.safetensors` 파일을 대화상자로 끌어다 놓습니다.
    4. **이 모델의 유형은 무엇인가요?** 에서 LoRA의 경우 **LoRA**를 그대로 두고, 파일에 맞는 유형을 선택합니다.
    5. **업로드**를 클릭합니다. 업로드가 끝나면 **완료**를 클릭합니다.

    ![my_style_lora_9e2417.safetensors(97.37 MB)가 선택되어 있고, 이 모델의 유형은 무엇인가요?가 LoRA로 설정되어 있으며, 뒤로 및 업로드 버튼이 있는 모델 가져오기 대화상자](/images/development/serverless/library-models-editor-import.png)

    대신 Civitai 또는 Hugging Face 링크에서 모델을 가져오려면:

    1. **가져오기** 대화상자에서 **여기에 링크를 붙여넣으세요**에 모델 링크를 붙여넣습니다.
    2. **계속**을 클릭합니다.
    3. **이 모델의 유형은 무엇인가요?** 에서 모델 유형을 선택합니다.
    4. **가져오기**를 클릭합니다.

    배포에서 실행되는 것은 `.safetensors` 파일뿐입니다. `.ckpt` 같은 다른 형식의 링크 가져오기는 라이브러리에는 가져와지지만 배포에서는 실행되지 않습니다.
  </Tab>
  <Tab title="comfy-cli">
    파일을 업로드하고 `--type`으로 모델 유형을 설정합니다:

    ```bash
    comfy assets library upload my_style.safetensors --type loras
    ```

    파일이 라이브러리에 있는지 확인합니다:

    ```bash
    comfy assets library ls --tags models,loras
    ```
  </Tab>
  <Tab title="Developer Platform">
    1. Developer Platform에서 Build의 모델 단계를 열고 **모델 업로드**를 클릭합니다.
    2. **워크스페이스 라이브러리**를 선택합니다.
    3. `.safetensors` 파일을 드롭 영역으로 끌어다 놓거나, 영역을 클릭해 찾아봅니다.
    4. **모델 유형**에서 LoRA의 경우 **LoRA**를 그대로 두고, 파일에 맞는 유형을 선택합니다.
    5. **업로드**를 클릭합니다.

    ![Build의 어떤 모델이 빌드에 포함되나요? 단계에 있는 모델 업로드 대화상자로, 공개, 비공개, 워크스페이스 라이브러리 탭, 선택된 워크스페이스 라이브러리, 드롭 영역, LoRA로 설정된 모델 유형, 파일이 워크스페이스 라이브러리에 있다는 문구, 취소 및 업로드 버튼이 표시됩니다](/images/development/serverless/library-models-platform-upload.png)
  </Tab>
</Tabs>

모델이 라이브러리에 있으면 워크스페이스의 모든 멤버가 사용할 수 있습니다. 라이브러리는 LoRA뿐 아니라 모든 모델 유형을 받습니다. 로더 노드가 읽는 폴더에 맞는 유형을 선택하세요. 예를 들어 LoRA는 `loras`, VAE는 `vae`입니다.

## 배포에서 모델 실행

모델이 라이브러리에 있으면 클라우드 에디터에서 또는 API를 통해 배포에서 실행할 수 있습니다. 작업을 보내는 방식에 해당하는 탭을 선택하세요.

<Tabs>
  <Tab title="클라우드 에디터">
    1. **Run** 왼쪽의 배포 메뉴를 클릭합니다. **Run on**에서 배포를 선택합니다. 에디터가 다시 로드되며, 열려 있던 탭은 그대로 유지됩니다.
    2. `Load LoRA (Model and CLIP)` 노드를 추가하거나, 해당 노드가 포함된 워크플로를 엽니다.
    3. 노드의 `lora_name` 목록에서 파일을 선택합니다. 목록에는 릴리스의 모델과 함께 라이브러리 모델이 표시됩니다.
    4. **Run**을 클릭합니다.

    첫 실행에서는 워커가 파일을 다운로드하는 동안 실행 대기열에서 해당 작업의 행에 `Downloading my_style.safetensors`가 표시됩니다. 작업이 여러 모델을 다운로드하면 행에 `Downloading <file name> (<n> of <total>)`이 표시됩니다.

    ![체크포인트 로드 노드와 LoRA 로드 (모델 및 CLIP) 노드가 있는 워크플로, lora_name에 업로드한 LoRA가 선택됨, 큐 패널의 맨 위 행에 Downloading my_style_lora_9e2417.safetensors 0 B of 97.37 MB 표시](/images/development/serverless/library-models-editor-downloading.png)
  </Tab>
  <Tab title="API">
    [API 형식 워크플로](/ko/development/api-development/workflow-api-format)에서 `LoraLoader` 노드의 `lora_name` 입력을 `.safetensors`를 포함한 라이브러리 파일 이름으로 설정합니다:

    ```json
    "10": {
      "class_type": "LoraLoader",
      "inputs": {
        "lora_name": "my_style.safetensors",
        "strength_model": 1.0,
        "strength_clip": 1.0,
        "model": ["4", 0],
        "clip": ["4", 1]
      }
    }
    ```

    `comfy deploy run`, [Comfy SDK](/ko/development/api-development/sdks) 또는 [Comfy API v2](/ko/api-reference/v2/overview)로 워크플로를 전송합니다:

    ```bash
    comfy deploy run --deployment <deployment-id> --workflow workflow_api.json
    ```

    다른 LoRA를 사용하려면 다음 요청에서 `lora_name`을 라이브러리의 다른 파일 이름으로 변경하면 됩니다. 새 빌드, 릴리스 또는 재배포는 필요하지 않습니다.
  </Tab>
</Tabs>

<Tip>
  라이브러리 모델을 사용하는 워커의 첫 작업은 시간이 더 오래 걸립니다. 워커가 먼저 모델을 다운로드하기 때문입니다. 같은 워커의 이후 작업은 캐시된 사본을 사용합니다. 새 워커는 모델을 다시 다운로드하며, 다른 모델을 위한 공간을 확보하기 위해 캐시에서 모델을 제거한 워커도 마찬가지입니다. 다운로드를 건너뛰려면 모델을 빌드에 추가하세요.
</Tip>

## 제한 및 이름 규칙 준수

[시작하기 전](#시작하기-전에)에 설명된 파일 크기 및 형식 제한 외에도 다음 제한이 적용됩니다.

| 제한 | 값 |
| --- | --- |
| 워크스페이스 저장소 | 워크스페이스당 모델 1 TB (링크 가져오기 포함) |
| 워크플로당 라이브러리 모델 이름 | 100 |

101번째 라이브러리 모델을 지정하는 로더는 해당 파일이 라이브러리에 없는 것처럼 실패합니다.

작업이 올바른 파일을 찾도록 다음 규칙을 따르세요.

- **로더가 읽는 폴더를 사용하세요.** 로더는 자신의 모델 유형에 해당하는 라이브러리 파일만 찾습니다. `Load LoRA` 노드는 `checkpoints`가 아닌 `loras`로 업로드된 파일을 찾습니다.
- **순수 파일 이름을 사용하세요.** 로더 입력에는 `my_style.safetensors`처럼 앞에 폴더가 붙지 않은 파일 이름만 설정하세요.
- **Release 모델의 이름을 재사용하지 마세요.** Release에 해당 이름의 파일이 이미 있으면 워커는 라이브러리 파일이 아닌 Release의 파일을 사용합니다.
- **폴더 간에 이름을 고유하게 유지하세요.** 하나의 로더가 읽는 두 폴더에 라이브러리에 같은 파일 이름이 있으면 API를 통해 전송된 작업은 두 파일 모두 로드하지 않습니다.
- **최신 파일이 우선한다는 점을 염두에 두세요.** 한 폴더에 라이브러리에 같은 이름의 파일이 두 개 있으면 작업은 마지막에 추가된 파일을 사용합니다.
- **베이스 모델을 일치시키세요.** LoRA는 워크플로가 로드하는 베이스 모델과 일치해야 합니다.
- **배포에 있는 로더를 사용하세요.** 로더 노드는 배포에서 사용할 수 있어야 합니다. 라이브러리 모델은 Comfy Cloud에 있는 로더 노드를 통해서만 로드됩니다. 사용하는 로더가 Comfy Cloud에 없는 커스텀 노드에서 제공되는 경우 해당 모델을 Build에 추가하세요.

## 라이브러리 모델 변경 또는 삭제

**Run on**에서 배포가 선택된 경우, **Model Library**에는 해당 Release의 모델만 표시됩니다. 라이브러리 모델을 변경하거나 삭제하려면 먼저 Comfy Cloud로 다시 전환하세요:

1. **Run** 왼쪽의 배포 메뉴를 클릭합니다. **Run on**에서 **Comfy Cloud**를 선택합니다.
2. **Left sidebar**에서 **Model Library**를 클릭합니다.

모델 유형을 변경하려면:

- 모델 카드 위에 마우스를 올리고 **Model Info**를 클릭한 다음 새 **Model Type**을 선택합니다.

<Warning>
  모델을 삭제하면 모든 멤버의 워크스페이스 라이브러리에서 해당 모델이 제거됩니다. 여전히 해당 파일을 지정하는 작업이나 API 요청은 로더 입력에서 `Value not in list` 오류와 함께 실패합니다.
</Warning>

모델을 삭제하려면:

1. 모델 카드 위에 마우스를 올리고 **More**를 클릭한 다음 **Delete**를 클릭합니다.
2. **Delete this model?**에서 **Delete**를 클릭합니다.
