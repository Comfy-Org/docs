자가 호스팅은 ComfyUI를 직접 실행하고 이를 API로 호출하는 것을 의미합니다. 하드웨어, 모델, 커스텀 노드를 직접 관리하고, 그 대가로 완전한 제어권을 얻습니다: 어떤 GPU, 어떤 모델, 어떤 노드 팩이든 사용할 수 있고, 데이터는 인프라를 벗어나지 않습니다.

ComfyUI는 기본적으로 HTTP 서버로 실행되므로, 정상적인 설치라면 이미 API 엔드포인트입니다. 아래 옵션은 해당 설치가 어디에 있는지에 따라서만 다릅니다.

## 자체 하드웨어

가장 간단한 배포는 지금 사용 중인 컴퓨터를 이용하는 것입니다. ComfyUI를 설치하기만 하면 바로 `http://127.0.0.1:8188`에서 실행됩니다:

- [수동 설치](/ko/installation/manual_install): Linux, macOS, Windows용이며, 서버에서 표준적으로 선택되는 방법입니다
- [Comfy Desktop](/ko/installation/desktop/overview) 또는 [휴대용 Windows 빌드](/ko/installation/comfyui_portable_windows): 로컬 개발용입니다

헤드리스(브라우저 없이)로 실행하거나 기본 주소가 아닌 주소에서 수신 대기하려면 [서버 시작 플래그](/ko/development/comfyui-server/startup-flags)를 참조하세요. 예를 들어:

```bash
python main.py --listen 0.0.0.0 --port 8188
```

<Warning>
  ComfyUI 서버는 기본적으로 인증 기능이 없습니다. 신뢰할 수 있는 네트워크에서만 루프백이 아닌 주소로 바인딩하거나, 인증이 포함된 리버스 프록시를 서버 앞에 배치하세요.
</Warning>

## GPU 클라우드 제공업체

GPU가 없는 경우 GPU를 임대하여 ComfyUI를 실행할 수 있습니다. 커뮤니티에서 일반적으로 사용하는 제공업체는 다음과 같습니다:

- **[Runpod](https://www.runpod.io)**: 사전 구성된 커뮤니티 ComfyUI 템플릿을 제공하는 GPU 파드(pod).
- **[Vast.ai](https://vast.ai)**: GPU 마켓플레이스. 여기서도 커뮤니티 ComfyUI 템플릿을 사용할 수 있습니다.

이러한 제공업체에서는 일반적으로 커뮤니티 템플릿이나 이미지에서 시작한 다음 모델과 커스텀 노드를 추가합니다. 결과는 공개 URL 또는 SSH 터널이 앞에 있는 노멀(normal)한 셀프 호스팅 ComfyUI입니다.

<Note>
  이 템플릿은 커뮤니티에서 유지관리되며 ComfyUI 팀이 게시하거나 지원하지 않습니다. 템플릿에 자격 증명이나 개인 모델을 넣기 이전에 템플릿이 설치하는 내용을 검토하세요.
</Note>

빌드, 릴리스, 자동 확장이 대신 처리되는 이 워크플로의 관리형 버전을 원한다면, [Serverless API](/ko/development/serverless/overview)가 바로 그것을 제공합니다.

## 커뮤니티 Docker 이미지

<DockerNotice />

컨테이너화된 ComfyUI는 다른 자체 호스팅 설치와 동일하게 동작합니다. 서버 포트를 노출하고 평소처럼 호출하면 됩니다.
