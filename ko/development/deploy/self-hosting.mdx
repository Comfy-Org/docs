셀프 호스팅은 ComfyUI를 직접 실행하고 이를 API로 호출하는 것을 의미합니다. 하드웨어, 모델, 커스텀 노드를 직접 관리하는 대신 완전한 제어권을 얻게 됩니다. 원하는 GPU, 원하는 모델, 원하는 노드 팩을 사용할 수 있고 데이터는 여러분의 인프라를 벗어나지 않습니다.

ComfyUI는 기본적으로 HTTP 서버로 실행되므로, 정상적으로 동작하는 설치 환경은 이미 API 엔드포인트입니다. 아래 옵션들은 그 설치가 어디에 위치하는지에만 차이가 있습니다.

## 자체 하드웨어

가장 간단한 배포 방식은 바로 앞에 있는 컴퓨터를 사용하는 것입니다. ComfyUI를 설치하면 기본적으로 `http://127.0.0.1:8188`에서 서비스를 제공합니다:

- Linux, macOS, Windows용 [수동 설치](/ko/installation/manual_install)이며, 서버에서의 표준 선택입니다
- 로컬 개발용으로는 [Comfy Desktop](/ko/installation/desktop/overview) 또는 [포터블 Windows 빌드](/ko/installation/comfyui_portable_windows)를 사용하세요

헤드리스(브라우저 없이)로 실행하거나 기본값이 아닌 주소에서 수신 대기하려면 [서버 시작 플래그](/ko/development/comfyui-server/startup-flags)를 참고하세요. 예를 들어:

```bash
python main.py --listen 0.0.0.0 --port 8188
```

<Warning>
  ComfyUI 서버는 기본적으로 인증 기능이 없습니다. 신뢰할 수 있는 네트워크에서만 loopback이 아닌 주소에 바인딩하거나, 인증을 갖춘 리버스 프록시를 앞에 배치하세요.
</Warning>

## GPU 클라우드 제공업체

GPU가 없다면 GPU를 대여해 ComfyUI를 실행할 수 있습니다. 커뮤니티에서 흔히 사용하는 제공업체는 다음과 같습니다.

- **[Runpod](https://www.runpod.io)**: 미리 구성된 커뮤니티 ComfyUI 템플릿이 포함된 GPU pod를 제공합니다.
- **[Vast.ai](https://vast.ai)**: GPU 마켓플레이스로, 여기에서도 커뮤니티 ComfyUI 템플릿을 사용할 수 있습니다.

이러한 제공업체에서는 보통 커뮤니티 템플릿이나 이미지에서 시작한 뒤 모델과 커스텀 노드를 추가합니다. 그 결과 앞단에 공개 URL이나 SSH 터널이 있는 일반적인 셀프 호스팅 ComfyUI가 만들어집니다.

<Note>
  이 템플릿들은 커뮤니티에서 유지 관리하며, ComfyUI 팀이 게시하거나 지원하지 않습니다. 자격 증명이나 비공개 모델을 올리기 전에 템플릿이 무엇을 설치하는지 확인하세요.
</Note>

빌드, 릴리스, 오토스케일링을 대신 처리해 주는 관리형 버전의 워크플로를 원한다면 [개발자 플랫폼의 Comfy API 배포](/ko/development/serverless/overview)를 사용하세요.

## 커뮤니티 Docker 이미지

<DockerNotice />

컨테이너화된 ComfyUI는 다른 자체 호스팅 설치와 동일하게 동작합니다: 서버 포트를 노출하고 평소처럼 호출하면 됩니다.
