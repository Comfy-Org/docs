<Warning>
  **베타:** Comfy API v2는 `0.1.x` 버전이며 API 표면이 아직 변경될 수 있습니다. v2 내의 변경 사항은 추가적으로 이루어지며, 호환성을 깨뜨리는 변경은 v3로 출시됩니다.
</Warning>

외부 애플리케이션에서 ComfyUI 워크플로를 실행하기 위한 공식 버전 관리 HTTP API입니다: 입력 업로드, 워크플로 제출, 실행 관찰, 결과 검색.

대부분의 사용자는 이 API를 Python과 TypeScript로 래핑하는 [Comfy SDK](/ko/development/api-development/sdks)부터 시작하는 것이 좋습니다. 다른 언어로 작업하는 경우에는 이러한 엔드포인트를 직접 호출하세요. 전체 엔드포인트 문서는 OpenAPI 사양에서 생성된 이 섹션의 API Reference 페이지에서 확인할 수 있습니다.

## v2가 실행되는 위치

동일한 API가 세 가지 진입점을 통해 제공되므로, 하나의 통합 코드는 기본 URL만 변경하면 그 사이를 이동할 수 있습니다.

**Comfy Cloud.** `https://cloud.comfy.org`에서 제공되는 관리형 멀티 테넌트 서비스입니다. [API 키](/ko/development/api-development/getting-an-api-key)를 생성하면 모든 워크플로를 제출할 수 있습니다. 크레딧, 모델 탐색, 실행 대기열 관리와 같은 클라우드 전용 기능은 v2가 아닌 [v1 Cloud API](/ko/development/cloud/overview)에 있습니다.

**Serverless API(Developer Platform).** [Developer Platform](https://platform.comfy.org)을 통해 배포하는 워크플로는 `https://{deployment}.run.comfy.app`에 자체 전용 엔드포인트를 가지며, 동일한 API 키를 사용하여 동일한 v2 API를 제공합니다. 서버리스 배포는 하나의 고정된 워크플로를 실행하므로 독립적으로 확장되며 `GET /workflow`는 실행된 그래프를 반환합니다. 빌드 및 배포에 대한 자세한 내용은 [Serverless API 가이드](/ko/development/serverless/overview)를 참조하세요.

**오픈소스 ComfyUI(프록시 경유).** 베타 기간 동안 자체 호스팅 ComfyUI는 [comfy-api-proxy](https://github.com/Comfy-Org/comfy-api-proxy)를 통해 v2를 사용합니다. 이 프록시는 ComfyUI와 함께 실행되는 작은 오픈소스 서비스입니다:

```bash
pip install comfy-api-proxy
comfy-api-proxy
```

기본적으로 `127.0.0.1:8188`의 ComfyUI를 프록시하고 `127.0.0.1:8189`에서 v2 API를 제공하며, 루프백에만 바인딩됩니다. 인증은 기본적으로 비활성화되어 있으며, 선택적으로 정적 베어러 토큰을 사용할 수 있습니다. 이 프록시는 임시 방편입니다. v2가 안정화되면 ComfyUI 코어에 통합되며 프록시는 더 이상 필요하지 않습니다. 구성 세부 정보는 SDK 가이드의 [자체 ComfyUI](/ko/development/api-development/sdks#자체-comfyui)를 참조하세요.

## 설계 원칙

- **폴링 우선.** 모든 기능은 일반 GET 폴링을 통해 접근할 수 있습니다. SSE 스트림은 실시간 개선 사항일 뿐, 결코 진실의 원천이 아닙니다.
- **모든 것은 재개 가능.** 제출은 멱등적이며, 작업 상태와 출력은 `expires_at`까지 ID로 조회할 수 있습니다.
- **콘텐츠 주소 지정 에셋.** 에셋은 서버가 계산한 blake3 해시를 키로 하는 blob을 UUID로 식별하는 레코드이므로, 동일한 입력이 두 번 업로드되지 않습니다.
- **링크를 따라가고, URL을 직접 만들지 마세요.** 응답에는 후속 URL이 포함되어 있습니다.

이러한 설계 원칙의 근거는 [설계 노트](/ko/development/api-development/sdks-design)를 참조하세요.

## 기본 URL

| 유형 | URL | 인증 |
|---------|-----|----------------|
| Comfy Cloud | `https://cloud.comfy.org` | `Authorization: Bearer <api-key>` |
| 서버리스 배포 | `https://{deployment}.run.comfy.app` | `Authorization: Bearer <api-key>` |
| 자체 호스팅, [comfy-api-proxy](https://github.com/Comfy-Org/comfy-api-proxy)를 통한 | `http://127.0.0.1:8189` | 기본적으로 없음, 선택적 정적 Bearer 토큰 |

## 엔드포인트 카테고리

| 카테고리 | 설명 |
|----------|-------------|
| 에셋 | 콘텐츠 주소 지정 블롭에 대한 UUID 식별 레코드입니다. 입력을 업로드하고 출력을 다운로드합니다. |
| 작업 | 워크플로의 단일 실행입니다. 지속적이며, 폴링할 수 있고, 취소할 수 있습니다. |

## Comfy Router

Comfy API v2는 사용자가 제출하고 폴링하는 지속형 작업으로 워크플로를 실행합니다. 직접 모델 호출(하나의 파트너 모델, 하나의 요청, 모델의 네이티브 입력 및 출력)의 경우 [Comfy Router](/ko/api-reference/comfy-router/quickstart)를 참조하세요. 먼저 [Router 제한 사항](/ko/api-reference/comfy-router/limitations)을 확인하세요. Router는 아직 일반 공개되지 않았습니다.
