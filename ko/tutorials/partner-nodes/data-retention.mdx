모든 파트너 노드 요청은 플랫폼에 저장되는 데이터를 생성합니다. 입력(이미지, 비디오, 3D 에셋, 오디오)과 모델이 생성한 출력이 여기에 해당합니다. 이 페이지에서는 각 데이터 유형이 보존되는 기간을 설명합니다. 각 공급자가 이 데이터를 기본적으로 어디에서 처리하는지는 [모델 공급자](/ko/tutorials/partner-nodes/model-providers)에서 확인할 수 있습니다.

## 저장되는 항목

파트너 노드를 실행하면 두 종류의 파일이 저장됩니다.

- **입력 파일**: 노드에 제공하는 참조 이미지, 오디오 및 기타 미디어. 입력은 계정의 스토리지 공간에 업로드됩니다.
- **출력 파일**: 노드가 생성하는 이미지, 비디오, 오디오 및 기타 미디어. 출력은 Comfy 관리 스토리지에 기록되며 다운로드 URL로 제공됩니다.

입력 및 출력 파일은 모두 Comfy 관리 클라우드 스토리지 버킷에 저장됩니다.

## 파일 보존 기간

모든 파트너 노드 미디어 파일은 생성된 후 **24시간**이 지나면 자동으로 삭제됩니다. 삭제는 입력 및 출력 파일 모두에 적용됩니다.

| 파일 유형 | 삭제 시점 |
| --- | --- |
| 입력 파일 | 24시간 |
| 출력 파일 | 24시간 |

<Note>
  24시간 삭제 기간은 플랫폼 기본값이며 모든 파트너 노드 호출에 적용됩니다. 파일을 더 오래 보관해야 하는 경우 만료되기 이전에 자체 스토리지로 다운로드하세요.
</Note>

## 삭제 후 발생하는 상황

파일이 삭제되면 해당 다운로드 URL은 오류를 반환합니다. 삭제된 파일은 복구할 수 없으며, 다시 필요할 경우 동일한 미디어를 다시 업로드하거나 재생성해야 합니다.

입력 파일을 삭제하면 계정 스토리지에서 해당 파일 기록도 제거되므로 이후 호출에서 해당 입력을 재사용할 수 없습니다.

## 공급자 작업 기록

일부 파트너 노드는 미디어 파일 대신 작업 ID를 공급자에게 전송하며, 공급자는 그 ID 뒤에 있는 기록을 기준으로 작업합니다. Tripo의 후속 작업 노드가 이 방식입니다. `Tripo: Texture model`, `Tripo: Rig model`, `Tripo: Retarget rigged model`, `Tripo: Convert model`, `Tripo: Edit Multiview`, `Tripo: Segment Model`, `Tripo: Retopology`, `Tripo: Complete Mesh Parts` 는 모두 `model_task_id` 또는 `multiview_task_id` 같은 입력을 받습니다.

생성된 모델 파일은 영향을 받지 않습니다. 작업이 완료되는 즉시 다운로드되어 출력 디렉터리에 저장됩니다.

공급자 작업 기록은 위의 24시간 기간이 아니라 공급자 자체의 보존 정책을 따릅니다. Tripo는 작업 완료 후 7일 동안 작업 기록을 보존합니다(2026년 12월 1일부터 적용). 그보다 오래된 작업 ID는 더 이상 확인할 수 없으므로, 만료된 `model_task_id`로 저장된 워크플로우를 다시 실행하면 후속 작업 노드에서 실패합니다.

복구하려면 이미 다운로드한 모델 파일을 `Tripo: Import Model` 로 다시 가져오세요. 새로운 `model_task_id`가 반환되며 텍스처, 리깅, 변환 노드에서 사용할 수 있으므로 기본 모델에 대해 다시 비용을 지불할 필요가 없습니다.

## 파일을 더 오래 보관하기

워크플로에서 입력 파일을 24시간 이상 계속 사용할 수 있어야 하는 경우, 각 작업 이전에 파일을 다시 업로드하세요. 장기 실행 파이프라인의 경우 해당 파일이 필요한 호출 직전에 다시 업로드하세요.

보관하려는 출력이 있다면 24시간 이내에 자체 스토리지로 다운로드하세요.
