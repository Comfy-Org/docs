동시성 제한은 귀하의 계정이 동시에 처리할 수 있는 요청의 수를 제어합니다. 제한을 초과하는 요청은 `429` 오류 코드와 함께 거부됩니다. 귀하의 동시성 제한은 누적 유료 결제 금액에 따라 결정되며, 호출하는 모든 엔드포인트에 걸쳐 플랫폼 차원에서 적용됩니다.

<Note>
동시성 제한은 모든 사용자를 위해 플랫폼을 빠르고 안정적으로 유지하도록 시간이 지남에 따라 조정됩니다. 이 페이지의 특정 값은 현재 구성을 반영하며 변경될 수 있습니다.
</Note>

## 작동 방식

요청을 제출하면 플랫폼은 해당 요청을 귀하의 동시성 제한과 비교하여 추적합니다. 제한을 초과하면 처리 중인 요청이 완료될 때까지 추가 요청은 `429` 오류와 함께 거부됩니다.

## 파트너 노드 동시성 vs. 클라우드 작업 동시성

이 페이지에서는 파트너 노드 호출의 동시성 제한에 대해 구체적으로 설명합니다. 이 제한은 **클라우드 작업 동시성**과 별개로 독립적으로 적용되는 제한입니다. 클라우드 작업 동시성은 한 번에 실행할 수 있는 Comfy Cloud 워크플로 실행 수를 제어하며, 누적 유료 결제 금액이 아닌 클라우드 플랜 또는 구독 등급에 따라 설정됩니다.

두 제한은 독립적으로 적용되므로, 실제 처리량은 둘 중 먼저 도달하는 제한에 의해 결정됩니다. 높은 클라우드 플랜이 그 자체로 파트너 노드 동시성 제한을 높여 주지는 않습니다. 파트너 노드 동시성 제한은 아래의 누적 유료 결제 금액 등급에 따라 별도로 관리됩니다.

## 동시성 등급

귀하의 동시성 제한은 **누적 유료 결제 금액**(Comfy Cloud와 파트너 노드 전체에서의 크레딧 구매 및 구독 결제 합계)을 기준으로 결정됩니다. 이 합계는 계정이 존재하는 기간 동안 누적되며, 초기화되거나 특정 기간만 소급하여 계산되지 않습니다.

아래의 [확정 지출 상한](#확정-지출-상한)과 혼동하지 마세요. “확정 지출”은 현재 실행 중인 호출에 묶여 있는 금액이며, 귀하의 등급이 함께 설정하는 별도의 상한입니다. 그 밖에 두 수치 사이의 관계는 없습니다.

| 누적 유료 결제 금액      | 동시성 제한 |
| :--------------------- | -----------------: |
| $0(구매 내역 없음)       | 1                  |
| $0 초과 ~ $100 이하      | 5                  |
| $100 이상               | 10                 |
| $500 이상               | 20                 |
| $1,000 이상             | 40                 |

이 표를 읽는 방법:

- **먼저 일치하는 항목이 우선합니다.** 행은 가장 구체적인 항목부터 포괄적인 항목 순으로 평가됩니다. 팀이 설정한 맞춤 제한이 결제 등급보다 우선하고, 결제 등급이 결제 이력이 없는 계정의 최저 한도보다 우선합니다. 누적 결제 금액이 $1,200이면 40이 적용되며, 더 낮은 등급은 고려되지 않습니다.
- **평생 기준이며, 롤링 방식이 아닙니다.** 몇 달 전의 결제도 여전히 등급에 반영됩니다. 결제 금액은 시간이 지나도 만료되거나 초기화되지 않습니다.
- **클라우드와 파트너 노드 결제가 모두 포함됩니다.** 클라우드 구독 비용을 결제했는지 파트너 노드 크레딧을 구매했는지는 중요하지 않습니다. 둘 다 동일한 누적 유료 결제 총액에 포함됩니다.
- **성공적인 결제 한 번이면 최저 한도를 벗어납니다.** 성공적인 결제를 한 번도 하지 않은 계정은 동시 호출 1회로 제한됩니다. 한 번만 성공적으로 결제해도 기본 등급(5)이 적용되며, $100 / $500 / $1,000 기준을 넘으면 한도가 더 높아집니다.
- **맞춤 제한이 표보다 우선합니다.** 팀이 계정에 특정 제한을 설정한 경우(예: 엔터프라이즈 계약 또는 정책 제한)에는 결제 기준의 모든 행보다 우선하며, 0(파트너 노드 액세스 비활성화)까지 내려갈 수 있습니다.

셀프 서비스 제한은 $1,000 등급에서 최대 **동시 40개 요청**까지 확장됩니다.

## 모델 기반 제한

비용이 높은 모델은 허용되는 동시성이 낮습니다. 요청당 **$5 이상**의 비용이 드는 모델을 호출하면 해당 모델의 동시성 제한은 계정 등급 제한의 **4분의 1**입니다(내림 처리, 최소 1). 비용이 낮은 모델에 대한 요청은 계정의 전체 제한을 계속 사용하며, 두 제한은 독립적으로 추적됩니다.

## 확정 지출 상한

<Note>
확정 지출 상한은 현재 순차적으로 적용되는 중이며, 허용 금액도 동시성 제한과 마찬가지로 시간이 지남에 따라 조정되므로 이 페이지에는 구체적인 상한 값을 표시하지 않습니다. 지금 귀하의 계정에서 이 거부가 발생하는지 여부와 관계없이 `429`와 아래 헤더를 처리하도록 구현하세요.
</Note>

동시에 실행되는 호출 수와 별개로, 귀하의 등급은 **진행 중인 호출에 확정된 미국 달러 총액**에도 상한을 둡니다. 호출은 실행되는 동안 그 비용을 계속 점유하므로, 동시성 슬롯이 남아 있더라도 플랫폼이 이 상한을 이유로 파트너 노드 호출을 거부할 수 있습니다. 소수의 고가 호출이 다수의 저가 호출보다 더 큰 금액을 확정할 수 있기 때문입니다.

“확정 지출”은 현재 실행 중인 호출에 묶여 있는 금액입니다. 등급을 결정하는 별도의 합계인 [누적 유료 결제 금액](#동시성-등급)과는 다릅니다. 귀하의 등급이 두 상한을 모두 결정하지만, 그 밖에 두 수치 사이의 관계는 없습니다.

두 상한은 동일한 `429`를 공유합니다. 어느 쪽에 걸렸는지는 응답의 `detail`이 알려주며, 확정 지출로 인한 거부에서는 진행 중인 호출에 확정된 금액이 상한에 도달했다고 안내합니다. `X-Committed-Spend-*` 헤더는 그 거부에만 포함되므로, 메시지 텍스트가 아니라 헤더를 기준으로 분기하세요.

| 헤더 | 의미 |
| :--- | :--- |
| `X-Committed-Spend-Limit` | 확정 지출 상한(미국 달러 센트 단위 정수) |
| `X-Committed-Spend-Current` | 진행 중인 호출에 확정된 센트 금액으로, 거부된 호출은 포함하지 않습니다 |
| `X-Committed-Spend-Remaining` | 상한 아래 남은 여유분(센트 단위, 최소값 0) |

`X-Committed-Spend-Remaining`은 **거부 시에도 양수일 수 있습니다.** 모순이 아닙니다. 거부된 호출의 비용이 남은 여유분보다 컸을 뿐이며, 더 저렴한 호출이었다면 허용되었을 것입니다.

재시도 방식은 동시성 제한과 동일합니다. 귀하 자신의 진행 중인 호출이 완료되면 상한에 여유가 생깁니다. 오류 버킷과 응답에 포함되는 다른 헤더를 비롯한 `429`의 전체 계약은 [Comfy Router API 레퍼런스](/ko/development/comfy-router/reference)를 참고하세요.

## 동시 실행 슬롯 작동 방식

파트너 노드 호출은 요청이 수락된 순간부터 공급자가 결과를 반환할 때까지 하나의 동시 실행 슬롯을 사용합니다. 비디오 또는 3D 생성은 결과가 반환되기까지 몇 분이 걸릴 수 있습니다. 호출이 완료되면 슬롯이 즉시 해제됩니다.

실행 중인 호출만 한도에 포함됩니다. 완료된 호출은 즉시 슬롯을 해제하므로, 실행 과정에서 많은 파트너 노드 호출을 수행하는 워크플로도 성공적으로 완료될 수 있습니다. 단, 같은 순간에 실행 중인 호출 수가 허용된 한도를 초과할 수는 없습니다.

## 한도에 도달하면 어떻게 되나요

모든 동시 실행 슬롯이 사용 중일 때 파트너 노드를 또 호출하면 해당 호출은 즉시 거부되며 HTTP `429` 상태와 함께 기존 요청이 완료될 때까지 기다리라는 메시지가 응답 본문에 포함됩니다.

- **같은 `429`가 확정 지출을 의미할 수도 있습니다.** 진행 중인 호출이 등급에서 허용하는 금액을 이미 모두 확정한 경우에는 동시성 슬롯이 남아 있어도 같은 상태 코드로 거부됩니다. [확정 지출 상한](#확정-지출-상한)을 참고하세요.
- **차단된 계정은 대신 403을 반환합니다.** 계정에서 파트너 노드 액세스가 비활성화된 경우(사용자 지정 한도가 0인 경우) 호출은 `429`가 아닌 HTTP `403`으로 거부됩니다.
- **동시성은 보유 크레딧 잔액과 별개입니다.** 동시성 슬롯은 동시에 실행할 수 있는 호출 수만 제어합니다. 보유 크레딧 잔액이 0이 되면 동시성 슬롯이 얼마나 비어 있는지와 관계없이 크레딧이 부족하여 호출이 실패합니다. 계속 실행하려면 잔액을 양수로 유지하세요.
- 제한된 호출이 자동으로 재시도되는지 여부는 API를 호출하는 방식에 따라 다릅니다. 사용 중인 특정 노드 또는 클라이언트의 동작을 확인하세요.

## 동시성 응답 헤더

파트너 노드 응답에는 요청이 처리된 시점의 동시성 사용량을 반영하는 헤더가 포함됩니다. 이러한 헤더는 성공적인 응답과 제한된 응답 모두에 설정되며, API 키 사용자와 기타 호출자 모두에게 동일하게 적용됩니다.

| 헤더 | 의미 |
| :--- | :--- |
| `X-Concurrency-Limit` | 사용자의 유효 동시성 한도 |
| `X-Concurrency-Current` | 현재 진행 중인 호출 수(이 호출 포함) |
| `X-Concurrency-Remaining` | 아직 사용 가능한 슬롯 |

무제한 맞춤 제한이 있는 계정에는 이 헤더가 반환되지 않습니다. 또한 최선의 노력으로 제공되는 값이므로, 상태 확인과 디버깅에는 유용하지만 정밀한 스케줄링 신호로 사용해서는 안 됩니다.

40개 이상의 동시성 제한을 원하시는 경우, 당사 지원팀에 문의해주세요.
