[MiniMax H3](https://www.minimax.io/blog/minimax-h3)는 MiniMax의 오픈 가중치 omni-modal 모델입니다. 텍스트, 이미지, 비디오, 오디오를 단일 컨텍스트에서 이해하고 **네이티브 스테레오 오디오** 비디오(음성, SFX, 음악 일체)를 한 번에 생성합니다. 오픈 가중치는 약 100만 픽셀(단변 768px), 24fps, 최대 약 15초가 목표입니다. 2K는 호스팅 서비스 출력이며 ComfyUI에서는 별도 업스케일이 필요합니다.

문서는 6개 페이지로 나뉩니다:

- **개요**(이 페이지): 기능, 체크포인트, 워크플로 인덱스, 해상도, 클립 길이, 스텝, 샘플러, 가속
- **[네이티브 워크플로](/ko/tutorials/video/minimax/minimax-h3-native)**: T2V, I2V, R2V 및 네이티브 노드 기법
- **[멀티프레임 레퍼런스](/ko/tutorials/video/minimax/minimax-h3-multiframe)**: 타임라인에 레퍼런스 프레임 고정
- **[Fun ControlNet Union](/ko/tutorials/video/minimax/minimax-h3-fun-controlnet)**: 컨트롤 비디오 또는 마스크 인페인팅
- **[프롬프트 가이드](/ko/tutorials/video/minimax/minimax-h3-prompt-guide)**: 공식 가이드, 팁, 임베딩
- **[FastH3](/ko/tutorials/video/minimax/minimax-h3-fastvideo)**: FastVideo 스파스 어텐션 체크포인트

<UpdateReminder/>
<Note>
H3의 오픈 가중치는 로컬에서 실행할 수 있습니다. 로컬에서 생성한 출력물을 상업적으로 사용하려면 Comfy(유일한 공식 유통사)를 통해 [MiniMax 상업용 라이선스](https://comfy.org/minimax/license)가 필요합니다. Comfy Cloud에서 생성한 결과물에는 이미 상업적 사용 권한이 포함되어 있습니다. 티어와 가격은 [상업적 라이선스](#상업적-라이선스)를 참조하세요.
</Note>

## 주요 기능

- **네이티브 스테레오 오디오**: 대화, SFX, 음악을 하나의 MP4에
- **멀티모달 컨텍스트**: 텍스트, 이미지, 비디오, 오디오 참조 조합
- **참조 기반 생성**: 참조에서 정체성, 스타일, 모션, 카메라, 목소리 고정
- **지시 따르기**: 참조와 샷 관계를 자연어로 설명
- **정확한 텍스트 렌더링**: 철자와 브랜드 요소를 선명하게
- **오픈 가중치**: ComfyUI에서 로컬 전체 제어

## 시작하기

1. ComfyUI 업데이트: 기본 T2V/I2V/R2V 템플릿 **0.30.0+**, 멀티프레임 레퍼런스 **0.34.0+**, Fun ControlNet Union·스파스 어텐션·Model Attention Backend **0.35.0+**, FastH3 **0.36.0+**
2. **템플릿 라이브러리** > **비디오** > MiniMax H3 워크플로 선택
3. 팝업에서 모델 다운로드(수십 GB, 시간·디스크 확보)

가중치: [Comfy-Org/MiniMax-H3](https://huggingface.co/Comfy-Org/MiniMax-H3).

<Note>
풀·pruned가 모두 있으면 **pruned** 사용. pruned는 adaln을 공유 곡선 테이블(`adaln_t_table`)에 두며 ComfyUI가 파일에서 읽습니다. 템플릿은 `minimax_h3_*_pruned_int8_convrot.safetensors` 로드.**풀** 빌드에서 증류한 LoRA의 adaln 텐서는 pruned에 없음(형상 불일치로 스킵). Turbo LoRA는 adaln 없어 양쪽 빌드 가능.
</Note>

## 체크포인트 정밀도 선택

VRAM에 맞는 최소 빌드 선택. `UNETLoader` 파일만 변경; 양자화는 checkpoint에서 읽음. LoRA는 빌드 계열 일치(풀 LoRA는 pruned에서 adaln 손실).

| 빌드(fl2va / ref2va) | 크기 | 비고 |
| --- | --- | --- |
| [`pruned_w6a8`](https://huggingface.co/Comfy-Org/MiniMax-H3/blob/main/diffusion_models/minimax_h3_fl2va_pruned_w6a8.safetensors) | 16 GB | 최소; INT8 경로; ComfyUI 0.38.0+ |
| [`pruned_int8_convrot`](https://huggingface.co/Comfy-Org/MiniMax-H3/blob/main/diffusion_models/minimax_h3_fl2va_pruned_int8_convrot.safetensors) | 21 GB | 템플릿 기본 |
| [`pruned_fp8_scaled`](https://huggingface.co/Comfy-Org/MiniMax-H3/blob/main/diffusion_models/minimax_h3_fl2va_pruned_fp8_scaled.safetensors) | 21 GB | INT8과 동일 크기 |
| [`pruned_bf16`](https://huggingface.co/Comfy-Org/MiniMax-H3/blob/main/diffusion_models/minimax_h3_fl2va_pruned_bf16.safetensors) | 40 GB | 비양자화 pruned |
| [`bf16`](https://huggingface.co/Comfy-Org/MiniMax-H3/blob/main/diffusion_models/minimax_h3_fl2va_bf16.safetensors) | 66 GB | 풀 비양자화 |

링크는 T2V/I2V `fl2va`; `ref2va`는 같은 폴더·크기.**Comfy Kitchen attention은 `int8_convrot` checkpoint 실행 불가**; 해당 백엔드는 `bf16` 선택.

VRAM 부족 시 한 단계 축소. CPU offload는 정밀도보다 느림. RTX 30 시리즈 INT8 행렬 약 2× FP16, FP8 경로 없어 동일 크기에서 INT8이 FP8보다 빠른 경우 많음.

비디오·오디오 VAE 필요: [비디오 fp16/int8_convrot](https://huggingface.co/Comfy-Org/MiniMax-H3/tree/main/vae), [오디오 fp32](https://huggingface.co/Comfy-Org/MiniMax-H3/blob/main/vae/minimax_h3_audio_vae_fp32.safetensors). 템플릿 int8 비디오 + fp32 오디오; int8 비디오는 ComfyUI 0.36.0+ 디코드 약 2×. `VAELoader`에서 교체.

## 출력 해상도 설정

**Resolution Selector**가 H3 노드 `width`/`height` 설정:

- **Aspect ratio**: `16:9 (Widescreen)`, `9:16 (Portrait Widescreen)`, `1:1 (Square)` 등
- **Megapixels**: 총 픽셀(클수록 느림)
- **Multiple**: 그리드 정렬; H3는 **32** 유지

템플릿의 **Megapixels** 기본값은 **0.4**입니다. 16:9에서 **864×480**, 1:1에서 **640×640**(I2V 기본)입니다. 0.4 MP는 빨라서 초안용으로 충분하니, 최종 렌더 전에 **Megapixels**를 올리세요.

16:9 네이티브: **0.98**(약 1344×768) 또는 **1344 × 768**. **1.0** MP(1376×768)는 768×1344 상한 초과. 학습 약 1 MP; 과대 캔버스는 디테일 증가 없음. 2K는 네이티브 생성 후 별도 업스케일.

### 고해상도 업스케일

24채널 비디오 latent **latent 업스케일러**로 VAE 왕복 고스팅 방지.[Minimax_h3_latent_Upscaler](https://huggingface.co/LBH-123-AI/Minimax_h3_latent_Upscaler)(비공식)는 [가중치](https://huggingface.co/LBH-123-AI/Minimax_h3_latent_Upscaler/blob/main/minimax_h3_latent_upscaler_3d_conv_v1/minimax_h3_latent_upscaler_3d_conv_v1_bf16.safetensors)와 [커스텀 노드](https://github.com/LBH-123-AI/Comfyui_Minimax_h3_latent_Upscaler) 필요. 저해상도 후 **Minimax H3 Latent Upscaler (3D)**(`scale` 1.0–4.0, 기본 2.0), 목표 해상도 재샘플.

Latent 업스케일은 시간 절약, 피크 VRAM은 아님. 다듬기는 부분 디노이즈: `denoise` **0.1–0.5** 구도 유지; 큰 변경 시만 상향. 다듬기 샘플러는 다단 히스토리 재구성 스텝 충분(「샘플러와 스케줄러」 참고).

비디오 latent(24)+오디오 latent(32) 분리. 업스케일러는 비디오 공간만; 다듬기에서 둘 디노이즈. 낮은 `denoise`로 1패스 오디오 유지. 완전 일치 시 다듬기 전 `VAEDecodeAudio`로 1패스 오디오를 최종 `CreateVideo`에(`SaveAudioAdvanced`로 무손실).

## 클립 길이

H3는 짧은 클립 학습; 노드는 넓은 범위 허용, 과장도 차단 안 함.

템플릿 `duration`(초)을 24fps **17k+5** 프레임으로 변환.

| 설정 | 범위 |
| --- | --- |
| `length` 입력 | 5–3600 프레임(약 0.2 s–150 s) |
| 학습 범위 | 약 124–362 프레임(약 5–15 s) |
| 프레임 그리드 | 24fps `17k+5`(124 프레임 = 5 s) |
| 템플릿 기본 | 5 s → 124 프레임 |

만 해상도 긴 클립은 VRAM 먼저 소진. Megapixels 낮춤.

### 클립 연결

학습 범위 초과는 I2V 이어가기로 각 클립 마지막 프레임부터. 오차 누적(얼굴 텍스처 먼저 열화); turbo/증류는 일찍 「번」.

`video_minimax_h3_i2v_continuation`(빈 프롬프트): 마지막 프레임 로드 후 다음 구간 설명. 연속 샷은 짧게, 번 전 컷. 긴 연결은 1패스 이후 [H3-Anti-Burn-LoRA](https://huggingface.co/Imagineer13/H3-Anti-Burn-LoRA/blob/main/h3_antiburn_universal_v1.safetensors) `strength_model` 약 0.5.

## 스텝 수

기본(Lightning LoRA **끔**): **20** 스텝. turbo 켬: T2V/I2V(이어가기 포함) **8**, R2V·멀티프레임·Fun ControlNet **4**. T2V/I2V 서브그래프 `turbo_mode`, `turbo_steps`, `turbo_model_strength`. 4스텝 fl2va: [`minimax_h3_fl2v_turbo_4step_v1.0_768p_comfyui_bf16.safetensors`](https://huggingface.co/Comfy-Org/MiniMax-H3/blob/main/loras/minimax_h3_fl2v_turbo_4step_v1.0_768p_comfyui_bf16.safetensors), `turbo_steps` **4**.

참조 샷은 스텝 더 필요: 참조 토큰 매 스텝; 4스텝 turbo는 참조 거의 미적용(포즈/얼굴 드리프트). 밀착 참조는 turbo 끄거나 **25** 근처.

증류 schedule은 20스텝 기준보다 디테일 평활. turbo 파일은 모드별; 스타일 LoRA 전 고정 시드 테스트. `turbo_steps`↑ + `turbo_model_strength`↓(&lt;1)로 기본 품질·시간 trade-off. 예: 4스텝 파일 6–8스텝, 강도 ~0.8.

Turbo는 schedule만 단축, 스텝당 시간 동일(로드 시 병합). 4스텝 LoRA 20스텝 ≈ 기본 20스텝 시간.

내용별:

- 단순 샷: **12–16** 스텝 종종 충분
- 고주파 디테일(체인메일, 필리그리, 작은 물체 다수): ~**50**까지; 미만 시 움직임 중 삼각 격자 아티팩트(turbo worse)
- 모션/프롬프트 이득 대부분 **16** 전; **50** 이후 차이 작음
- 네이티브 해상도 soft는 대개 해상도 문제

오디오는 공동 디노이즈에서 영상보다 늦게 수렴. 음성·음색 **12+**; **8**에서 오디오 약함.

## 샘플러와 스케줄러

템플릿 **`res_multistep`** + **`simple`**. T2V/I2V/FastH3 서브그래프; R2V·멀티프레임·Fun ControlNet 캔버스 `KSamplerSelect`, `BasicScheduler`.

`res_multistep` 2차 다단(첫 스텝 Euler). 2 샘플러 분할 시 다단 히스토리 손실. 단일 실행 또는 2번째에 충분 스텝.

기본 shift **12**, `audio_shift` **3**(모델 정의). FastH3 **ModelSamplingMiniMaxH3** `shift_video` **10**, `shift_audio` **3**. 증류 빌드 video shift 오류(8스텝 **3** vs **10**) 격자 아티팩트.[DMAD 4-step LoRA](https://huggingface.co/ZhengmingYu/DMAD/blob/main/minimax_h3/dmad_minimax_h3_4step_full_critic_comfyui.safetensors) shift **12**, `audio_shift` **2**, **`lcm`** + **`simple`**.

## Sage Attention으로 생성 가속

[Sage Attention](https://github.com/woct0rdho/SageAttention) 약 **2×** 가속, 화질 영향 보통 작음(선택 설치):

1. [releases](https://github.com/woct0rdho/SageAttention/releases)에서 PyTorch/CUDA wheel `pip install`
2. [KJNodes](https://github.com/kijai/ComfyUI-KJNodes) `Patch Sage Attention KJ`
3. `UNETLoader`–`BasicGuider` 사이, `sage_attention` `auto`
4. 또는 `--use-sage-attention`

일부 H3 레이어는 float16/bfloat16 외 → PyTorch attention 폴백(콘솔 경고 정상).

### INT8 어텐션 화질 저하

클립 말 morph·화면 글자 깨짐은 INT8 attention 양자화 흔함.

- 템플릿 **`int8_convrot`**. **Comfy Kitchen 미지원**([issue #15529](https://github.com/Comfy-Org/ComfyUI/issues/15529)). 기본 attention 또는 **`pruned_bf16`** 후 백엔드 변경.
- **bf16**에서 **Comfy Kitchen attention**(양자화 전 채널 회전) 유사 속도로 아티팩트 제거.

`BasicGuider` 모델 경로 **Model Attention Backend**(`comfy kitchen attention`) 또는 `--use-ck-attention`(0.32.0+). `comfy-kitchen` INT8 커널 필요.

## 스파스 어텐션으로 생성 가속

**Model Sparse Attention**(0.35.0+, 실험) 긴 클립 attention 비용 절감. 베이스 H3 **`sol-attn`**(`sla`/`vsa`는 대응 가중치). CUDA + `comfy-kitchen` `sol_attn`, 없으면 dense.

- 기본 `start_percent` **0.2**, `end_percent` **1.0**. ~**0.4** 시작·**0.9** 종료로 처음/끝 프레임 보호.
- H3 **`sink_conditioning`** **`exact_kv_and_rows`** 유지.
- **`tau`**: 클수록 sparse/빠름(`1.0` ~16% 정확 블록, `1.3` 기본, `2.0` ~2.7%).
- `min_tokens`(기본 **12288**) 미만 이득 작음.

FastH3 **`vsa`**, `keep_percent` **10**; [FastH3 페이지](/ko/tutorials/video/minimax/minimax-h3-fastvideo).

### 스파스 어텐션이 실제로 동작하는지 확인

베이스 H3 템플릿에는 이 노드가 없습니다. `UNETLoader`와 `BasicGuider` 사이에 **Model Sparse Attention**을 추가한 뒤 **`verbose`**(고급, 기본 꺼짐)를 켜면 attention 형태마다 한 줄씩 로그가 남습니다.

dense로 남는 호출은 `dense (<n> tokens): <reason>` 또는 `dense (<b>, <n>, <h>, <d>): <reason>`을 출력하며, 처음 걸린 조건만 보고합니다.

| 로그 이유 | 조치 |
| --- | --- |
| `no compiled sol_attn kernel for this GPU` | 설치된 `comfy-kitchen`에 이 GPU용 kernel이 없습니다. 업데이트하거나 해당 머신에서는 이 노드를 쓰지 않습니다. |
| `<n> tokens < min_tokens <value>` | 해상도나 클립 길이를 올리거나 `min_tokens`를 낮춥니다(기본 **12288**). |
| `sigma <x> outside the start/end window` | `start_percent`와 `end_percent`를 넓힙니다. |
| `block <i> in dense_blocks` | 해당 블록 번호를 `dense_blocks`에서 뺍니다. |
| `no H3 layout for this call` | `vsa`에서만 발생합니다. `sol-attn`으로 바꿉니다. |

성공한 호출은 `sparse (<b>, <n>, <h>, <d>), sinks <k>/<q>` 또는 `sparse producer path: <n> tokens, <mode>`를 출력합니다.

`verbose`를 켜도 로그가 없는 경우가 세 가지 있습니다. H3 경로의 활성값이 bfloat16이 아니거나, `head_dim`이 **128**이 아니거나, rope 주파수가 없으면 조용히 dense로 돌아갑니다.

`vsa`는 FastH3 체크포인트에 묶여 있습니다. 해당 가중치에만 있는 `to_gate_compress` 레이어가 주는 거친 브랜치를 읽기 때문에, 다른 H3 체크포인트에서는 노드가 `VSA: the model has no to_gate_compress layers; running the fine stage without the coarse branch`를 출력하고 세밀 단계만 실행합니다. 이 경고는 `verbose`와 무관합니다.
