**Wan2.1 InfiniteTalk**은 [MeiGen-AI](https://github.com/MeiGen-AI/InfiniteTalk)가 개발한, Wan2.1을 기반으로 하는 오픈 소스 오디오 기반 비디오 생성 모델입니다. 단일 참조 이미지와 오디오 입력만으로 전신 토킹 비디오를 생성할 수 있습니다. 캐릭터의 입 움직임과 신체 동작은 제공된 오디오에 맞춰 자동으로 동기화됩니다.

**주요 기능**:
- **오디오 기반 립 싱크**: 입력 오디오에 맞는 자연스러운 입 움직임 생성
- **전신 모션**: 정체성, 배경, 카메라 움직임을 유지하면서 동기화된 신체 모션 추가
- **듀얼 모드**: 단일 캐릭터와 다중 캐릭터 시나리오 모두 지원
- **ComfyUI 네이티브**: `WanInfiniteTalkToVideo` 노드가 내장되어 있어 커스텀 노드가 필요하지 않습니다

## 워크플로 단계

1. **입력 이미지 로드**: 캐릭터 참조 이미지를 `Load Image` 노드로 드래그합니다. 다중 캐릭터 시나리오에서는 마스크 편집기를 사용해 각 캐릭터의 마스크를 그립니다.
2. **오디오 트랙 로드**: 오디오 파일을 `Load Audio` 노드에 연결합니다(캐릭터당 하나).
3. **확산 모델 로드**: `Load Diffusion Model` 노드가 `Wan2_1-I2V-14B-480p_fp8_e4m3fn_scaled_KJ.safetensors`를 사용하고 있는지 확인합니다.
4. **모델 패치 로드**: `ModelPatchLoader` 노드를 통해 적절한 InfiniteTalk 패치(`single` 또는 `multi` 변형)를 로드합니다.
5. **InfiniteTalk 구성**: `length`(프레임 단위의 비디오 길이), `motion_frame_count`(모션 컨텍스트로 사용되는 이전 프레임), `audio_scale` 등 `WanInfiniteTalkToVideo` 노드 파라미터를 조정합니다.
6. **생성**: 워크플로를 실행합니다. 모델이 입력 오디오와 동기화된 전신 토킹 비디오를 생성합니다.

### 비디오 길이 연장

각 **Video Extend** 그룹은 비디오를 약 3.24초(25 fps 기준 81프레임) 연장합니다. 오디오가 더 길면 다음을 수행할 수 있습니다:

1. "Video Extend" 그룹을 상자 선택합니다
2. `Ctrl-C`(복사)를 누른 다음 `Ctrl-Shift-V`(연결과 함께 붙여넣기)를 누릅니다
3. 이전 `InfiniteTalk (Base Generation)` 노드의 `IMAGE` 출력을 새 `WanInfiniteTalkToVideo` 노드의 `previous_frames` 입력에 연결합니다
4. `Batch Images` 노드의 `IMAGE` 출력을 새 `Batch Images` 노드의 이미지 입력에 연결합니다

## 자주 묻는 질문

<AccordionGroup>
  <Accordion title="ComfyUI에 &quot;Not enough GPU memory&quot;가 표시되는 이유는 무엇인가요?">
    이 문구는 ComfyUI의 일반적인 메모리 부족 메시지입니다. 이 템플릿에는 batch size 설정이 없으므로 줄일 배치 크기가 없습니다. 로드하는 모델 파일은 합계 약 30 GB입니다. `Wan2_1-I2V-14B-480p_fp8_e4m3fn_scaled_KJ` 확산 모델(16.6 GB), `umt5_xxl_fp8` 텍스트 인코더(6.7 GB), InfiniteTalk 패치(5.1 GB)입니다. 기본값인 832 x 480, 81프레임에서는 샘플링 버퍼를 위한 여유가 거의 남지 않으므로 실행이 중단됩니다.
  </Accordion>
  <Accordion title="무엇을 먼저 낮춰야 하나요?">
    메모리에 가장 큰 영향을 주는 두 값을 낮춘 뒤 다시 실행하세요. **Width**와 **Height**는 InfiniteTalk 그룹 위의 `PrimitiveInt` 노드이며 기본값은 832 x 480입니다. 둘 다 16으로 나누어져야 하므로 640 x 368이 유효한 더 작은 조합입니다. `WanInfiniteTalkToVideo`의 **length**는 기본 81프레임이고 단계는 4이므로 유효값은 4n+1(예: 49)입니다. 그래도 부족하면 `motion_frame_count`(기본 9, 최대 33)를 낮춰 모션 컨텍스트 프레임을 줄이고, 테스트하는 동안에는 여분의 **Video Extend** 그룹을 제거하세요.
  </Accordion>
  <Accordion title="single 패치를 쓰면 메모리가 줄어드나요?">
    패치 자체로는 줄지 않습니다. 두 패치 파일 크기가 거의 같습니다(`single` 5.13 GB, `multi` 5.12 GB). 줄어드는 것은 화자를 한 명만 실행할 때이며, 두 번째 오디오 인코더 출력과 두 개의 마스크 입력이 필요 없어집니다. 패치는 모드와 일치해야 하므로 노드 모드를 `single_speaker`로 바꿀 때만 `ModelPatchLoader`를 `single`로 전환하세요.
  </Accordion>
  <Accordion title="이 워크플로를 Mac에서 실행할 수 있나요?">
    가능하지만 Apple Silicon에서는 CPU와 GPU가 하나의 통합 메모리 풀을 함께 사용하므로 채우거나 비울 별도의 VRAM이 없습니다. ComfyUI는 시스템의 전체 RAM을 장치가 사용할 수 있는 메모리로 간주하며, 다른 응용 프로그램도 같은 풀에서 사용합니다. 32 GB Mac은 약 30 GB의 모델 파일과 샘플링 버퍼를 함께 담아야 하므로 기본 설정에서는 메모리가 부족합니다. [시스템 요구 사항](/ko/installation/system_requirements)에서 MPS 백엔드를 설명합니다.
  </Accordion>
  <Accordion title="macOS에서 VRAM 관련 실행 옵션이 도움이 되나요?">
    아닙니다. Apple Silicon에서 ComfyUI는 VRAM 모드를 공유 메모리로 고정하며(`comfy/model_management.py`), 이는 `--lowvram`, `--novram`, `--highvram`를 덮어씁니다. 가중치를 통합 풀 밖으로 옮길 곳이 없기 때문입니다. Nvidia 및 ROCm GPU에서는 dynamic VRAM이 기본으로 켜져 있고 켜져 있는 동안 `--lowvram`은 효과가 없으므로, 이런 환경에서도 거의 도움이 되지 않습니다. [시작 옵션](/ko/development/comfyui-server/startup-flags)을 참조하세요. Mac에서 효과가 있는 방법은 메모리를 많이 쓰는 다른 앱을 종료하고, 위와 같이 해상도와 프레임 수를 낮추고, `--cache-none`으로 ComfyUI를 시작해 노드 출력이 실행 사이에 캐시되지 않게 하는 것입니다.
  </Accordion>
  <Accordion title="그래도 메모리가 부족하면 어떻게 하나요?">
    macOS에서 PyTorch는 장치의 권장 작업 집합 크기의 1.7배를 넘는 MPS 할당을 거부하며, 실행이 이 상한에 부딪히는 경우가 많습니다. `PYTORCH_MPS_HIGH_WATERMARK_RATIO=0.0`은 이 상한을 해제하지만 Mac이 스왑으로 넘어가거나 다른 앱이 멈출 수 있으므로 최후의 수단으로만 사용하세요.
  </Accordion>
  <Accordion title="Apple Silicon에서 fp8 모델을 쓰면 메모리가 절약되나요?">
    NVIDIA GPU처럼 절약되지는 않습니다. MPS에는 PyTorch의 fp8 연산 커널이 없어 가중치가 bf16으로 변환되어 실행됩니다. bf16 복사본이 메모리에 들어가면 로드 시 모델이 확장되어 fp8 파일은 bf16과 거의 같은 메모리를 사용합니다. 들어가지 않으면 가중치는 fp8로 유지되고 연산 시 변환되므로 메모리를 얻는 대신 속도를 잃습니다. Mac에서 효과가 있는 것은 해상도와 프레임 수입니다.
  </Accordion>
</AccordionGroup>
