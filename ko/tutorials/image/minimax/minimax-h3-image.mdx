**MiniMax-H3-Image**는 MiniMax의 오픈 웨이트 이미지 모델로, 체크포인트 하나로 텍스트 기반 이미지 생성과 이미지 편집을 모두 처리합니다. diffusion transformer는 BF16 기준 33.1B 파라미터이며, CFG 없이 6-step 샘플러로 증류되었습니다. 출력은 약 16 MP의 네이티브 해상도이므로 4096 x 4096 이미지를 업스케일 체인 없이 한 번에 생성할 수 있습니다.

**관련 링크**

- [MiniMaxAI/MiniMax-H3-Image (Hugging Face)](https://huggingface.co/MiniMaxAI/MiniMax-H3-Image): 공식 모델 카드와 가중치
- [MiniMax-H3-Image (ModelScope)](https://modelscope.cn/models/minimax/MiniMax-H3-Image): 중국 본토용 공식 미러
- [MiniMax-AI/MiniMax-H3-Image (GitHub)](https://github.com/MiniMax-AI/MiniMax-H3-Image): 공식 예제와 skill
- [Comfy-Org/MiniMax-H3-Image (Hugging Face)](https://huggingface.co/Comfy-Org/MiniMax-H3-Image): diffusion 모델 및 이미지 VAE
- [Comfy-Org/MiniMax-H3 (Hugging Face)](https://huggingface.co/Comfy-Org/MiniMax-H3): 이 모델에서 사용하는 Qwen3-VL-32B 텍스트 인코더
- [MiniMaxAI/MiniMax-H3-Image-PE (Hugging Face)](https://huggingface.co/MiniMaxAI/MiniMax-H3-Image-PE): 공식 프롬프트 확장기

## 주요 기능

- **하나의 checkpoint로 텍스트 기반 이미지 생성과 편집**: 별도의 편집 모델이나 어댑터를 로드할 필요가 없습니다
- **6단계 샘플링**: 가이드가 1로 고정되어 CFG 패스와 네거티브 프롬프트가 없습니다
- **기본 약 16 MP**: 업스케일 패스 없이 4096 x 4096에서 최대 6272 x 2688
- **다중 레퍼런스**: 최대 16개의 입력 이미지를 사용하며, 프롬프트에서 `<Picture 1>`부터 지정합니다
- **선택적 프롬프트 확장기**: 짧은 요청을 모델이 가장 잘 읽는 상세 캡션으로 변환합니다
- **오픈 가중치**: ComfyUI에서 완전한 로컬 제어

## 샘플링 및 캔버스 크기

두 템플릿 모두 증류된 스케줄을 제공합니다:

| 설정 | 값 |
| --- | --- |
| 샘플러 | euler |
| 스케줄러 | simple |
| 스텝 | 6 |
| 가이드(CFG) | 1 |
| Denoise | 1 |

가이드가 1이면 classifier-free guidance 패스가 없으므로 템플릿에는 네거티브 프롬프트가 포함되지 않습니다. 피하고 싶은 요소를 포함해 원하는 모든 내용을 포지티브 프롬프트에 작성하세요.

기본 출력은 약 16 MP입니다. 모든 변은 32 px의 배수로 생성되며, 너비와 높이는 임의의 값을 사용할 수 있습니다. 다음 크기는 일반적인 비율을 커버합니다:

| 화면 비율 | 크기(너비 x 높이) |
| --- | --- |
| 1:1 | 4096 x 4096 |
| 4:3 | 4736 x 3552 |
| 3:4 | 3552 x 4736 |
| 3:2 | 5024 x 3360 |
| 2:3 | 3360 x 5024 |
| 16:9 | 5472 x 3072 |
| 9:16 | 3072 x 5472 |
| 21:9 | 6272 x 2688 |

더 작은 캔버스도 사용할 수 있으며 시간이 덜 걸립니다. 텍스트 기반 이미지 생성 템플릿에서 해상도 선택기는 화면 비율과 목표 메가픽셀 수를 별도로 설정하므로, 4 MP 이상, 선택기 상한인 16 MP까지의 원하는 크기는 설정 한 곳만 바꾸면 됩니다.

## 이미지 편집에서의 참조 이미지

이미지 편집 템플릿은 소스 이미지를 `<Picture 1>`로 모델에 보냅니다. 추가 이미지는 `<Picture 2>`, `<Picture 3>`처럼 순서대로 라벨이 붙고 최대 16개의 참조 이미지까지 지정할 수 있으며, 프롬프트는 각 라벨로 이들을 참조합니다. 첫 번째 이미지가 편집 대상이고 나머지는 동일성, 소품, 재질, 구도를 보태므로 `<Picture 1>`의 차량을 `<Picture 2>`의 차량으로 바꾸는 정도의 짧은 지시로 충분합니다.

참조를 추가하려면 워크플로에 `Load Image` 노드를 하나 더 배치하고 프롬프트 생성 단계와 조건화 노드 모두에 연결합니다. 조건화 노드의 VAE 입력은 연결한 상태로 두세요. 템플릿은 이미 연결되어 있으며, VAE가 있으면 참조 이미지가 이미지 latent로도 조건에 포함되어 편집 결과가 소스를 더 잘 따라갑니다. 참조 이미지의 짧은 변은 1024 px 이상으로 하고, 동일성을 유지해야 할 때는 2048 px를 쓰세요. 노드가 알아서 조정하므로 1024 px 미만은 확대되고(늘어난 픽셀은 보간일 뿐입니다), 2048 px를 넘는 디테일은 버려집니다.

크기 조정 노드를 켜지 않으면 편집 결과는 소스 이미지와 같은 크기로 나옵니다. 켜면 지정한 목표 크기로 생성되며, 현재 템플릿 팩에서는 16 MP이고 템플릿 팩 0.11.104에서는 1 MP 상태로 바이패스되어 있으므로 선택한 뒤 `Ctrl-B`로 활성화하고 목표값을 설정하세요. 메모리가 부족하면 샘플링 전에 목표값을 낮춥니다.

모델이 편집할 이미지를 읽을 때 짧은 변은 최대 2048 px이며, 이는 1:1에서 약 4 MP, 16:9에서 약 7 MP에 해당합니다. 그보다 큰 대상 크기에서는 소스의 디테일이 아니라 생성된 디테일이 늘어납니다. 디테일이 중요할 때는 대상 크기를 그 크기에 맞추고 결과는 나중에 업스케일하세요.

### 편집 프롬프트 작성

확장기를 켜 두면 짧은 지시로 충분합니다. 모델이 가장 잘 읽는 구조로 문장을 다시 씁니다. 확장기를 끄고 직접 쓸 때는 같은 구조를 따르세요.

1. **요소를 먼저 쓰고 번호를 붙입니다.** `The woman in a red coat in <Picture 1> is <Subject 1>`처럼 쓰고, 그 대상을 특정할 수 있는 눈에 보이는 단서를 덧붙입니다. 모든 정의에는 해당 `<Picture N>`을 밝힙니다.
2. **완성될 이미지를 설명하고 각 대상의 결과를 적습니다.** `<Subject 1> is fully preserved`, 또는 `<Subject 1> is partially preserved; her face and coat remain, while her pose changes to a lean toward <Subject 2>`.
3. **바뀐 부분과 새로 생기는 부분만 씁니다.** 삭제한 객체가 남긴 표면과 편집으로 추가할 글자가 여기에 들어갑니다.

참조 이미지에 원본이 없는 내용은 대상 번호를 받지 않습니다. 삭제한 요소는 완성 이미지 설명에서 `<Picture N>`으로 한 번만 언급하고, 그 자리에 남는 영역을 씁니다.

`<Subject N>`은 텍스트 인코더가 읽는 문구일 뿐 샘플러가 강제하는 연결이 아니므로, 편집을 붙잡아 두는 것은 설명 자체입니다. 참조 이미지가 알아서 이어 준다고 가정하지 말고 무엇이 바뀌고 무엇이 남는지 쓰세요. 공식 편집 예시에 전체 구조가 있습니다: [revised_prompt.edit.txt](https://github.com/MiniMax-AI/MiniMax-H3-Image/blob/main/examples/revised_prompt.edit.txt).

### 이미지 확대 및 복원

편집 워크플로우가 두 번째 확대 패스까지 직접 처리하며, 별도 업스케일러 모델이 필요 없습니다. `scale total pixels`가 있는 `Resize Image/Mask` 노드에서 목표 크기를 설정하고(템플릿에서는 16 MP), `Boolean (Enable PE?)` 노드의 토글을 끄세요. 사용 중인 팩에서 이 노드가 바이패스되어 있으면 선택한 뒤 `Ctrl-B`로 활성화합니다.

```text
Re-render and sharpen as if the photo were taken with a 50 mm lens. Remove noise and compression artifacts. Improve skin, hair, eye and fabric detail while keeping pose, identity, and colors.
```

렌즈 설명은 원본 촬영 조건에 맞추세요. 확장기가 꺼져 있으면 지시가 그대로 모델에 전달되고, 켜져 있으면 새 이미지 설명을 쓰면서 요청하지 않은 내용까지 더합니다.

프레임 전체가 다시 생성되므로 새 디테일이 더해진 확대이지 충실한 복제가 아닙니다. 목표 크기가 모델이 원본을 읽는 크기(1:1에서 약 4 MP)에 가까울수록 포즈, 정체성, 색이 유지되며, 짧은 변 2048 px를 넘는 부분은 생성된 디테일입니다. 프롬프트에 쓰지 않은 부분은 바뀔 수 있고, 목표 크기가 크면 피부 질감이 번들거리고 늙어 보일 수 있습니다.

## 프롬프트 확장기 {#prompt-expander}

두 템플릿 모두 샘플러 앞에 텍스트 생성 단계를 두고 있습니다. 텍스트 기반 이미지 생성 템플릿에서는 프롬프트를 상세한 영어 캡션으로 다시 씁니다. 이미지 편집 템플릿에서는 짧은 지시를 완성된 이미지에 대한 레퍼런스 인식 설명으로 바꿉니다.

MiniMax-H3-Image의 공식 확장기는 Qwen3.8-27B FP4 모델이며, [MiniMaxAI/MiniMax-H3-Image-PE](https://huggingface.co/MiniMaxAI/MiniMax-H3-Image-PE)로 공개되어 있습니다. 템플릿은 대신 더 가벼운 Qwen3.5 9B W4A8 빌드를 사용하므로, 확장기가 21 GB diffusion 모델과 함께 하나의 GPU에 들어갑니다.

두 템플릿 모두 확장기가 켜진 상태로 제공되므로 프롬프트는 샘플링 전에 다시 씁니다. 확장기를 끄면 입력한 프롬프트가 그대로 모델에 전달됩니다.
