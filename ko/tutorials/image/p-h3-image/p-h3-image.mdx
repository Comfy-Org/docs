**P-H3-Image**는 Pruna AI의 오픈 웨이트 이미지 모델로, [MiniMax H3](/ko/tutorials/video/minimax/minimax-h3)를 기반으로 만들어졌습니다. 하나의 checkpoint에서 텍스트 기반 이미지 생성과 이미지 편집이라는 두 가지 작업을 처리합니다. 전체 이미지는 classifier-free guidance 없이 8 샘플링 스텝으로 생성되며, 기본값은 8 메가픽셀입니다.

이 모델은 사진 및 필름 느낌에 치우쳐 있습니다. 다큐멘터리와 에디토리얼 사진, 실제 피부 질감이 살아 있는 인물 사진, TV 프레임 스타일 애니메이션, 스크린 인쇄 포스터, 그리고 짧은 인용 텍스트가 들어간 플랫 그래픽 디자인이 여기에 해당합니다. Qwen3.5-9B 기반의 프롬프트 업샘플러가 한 줄 요청을 모델이 가장 잘 렌더링하는 상세 프롬프트로 다시 작성하고, 그 재작성된 프롬프트를 반환하므로 샘플러에 도달하기 전에 직접 확인할 수 있습니다.

ComfyUI에서 P-H3-Image는 두 개의 워크플로 템플릿으로 실행됩니다. 하나는 텍스트 기반 이미지 생성용, 다른 하나는 이미지 편집용입니다. MiniMax H3 diffusion 모델을 재사용하고 Pruna의 텍스트 인코더, 프롬프트 업샘플러, VAE, LoRA를 추가하며, 모델 파일은 총 약 35 GB입니다. int8 파일은 약 21 GB의 VRAM에 들어갑니다.

**모델 하이라이트**
- **8 스텝, CFG 없음**: 하나의 증류된 샘플링 스케줄과 단일 포지티브 조건화를 사용하며, 네거티브 프롬프트가 없습니다
- **8 메가픽셀**: 정사각형, 4:3, 3:2, 16:9 및 그 세로 버전을 지원하며, 최대 3872 x 2176입니다
- **프롬프트 업샘플러 내장**: 한 줄 요청이 전체 프롬프트로 확장되고, 확장된 프롬프트가 워크플로에 표시됩니다
- **참조 이미지를 사용한 편집**: 첫 번째 이미지가 편집 대상이며, 이후 이미지는 프롬프트에서 `<Picture 2>`, `<Picture 3>` 등이 됩니다
- **이미지 전용**: P-H3-Image는 비디오나 오디오를 생성하지 않습니다

## 요구 사항

- ComfyUI 0.44.0 이상. 두 템플릿 모두 0.44.0에서 추가된 PH3ImageConditioning 노드를 사용합니다
- 약 35 GB의 모델 파일. diffusion 모델은 MiniMax H3 워크플로에서 사용하는 것과 동일하므로 이미 가지고 있을 수 있습니다
- int8 파일을 위한 약 21 GB VRAM의 GPU

P-H3-Image는 MiniMax H3 커뮤니티 라이선스로 배포되며, 이 라이선스는 MiniMax로부터 별도의 라이선스를 받지 않는 한 일부 지역에는 적용되지 않습니다. 상업적 사용을 위해서는 [Comfy](https://comfy.org/minimax/license)를 통해 라이선스를 요청하세요.

프롬프트 상자에서 `Request:` 뒤에 요청을 작성하고, `Aspect ratio:` 줄을 해상도 선택기와 일치하게 유지하세요. 선택기는 32의 배수로 8메가픽셀에 설정되어 있으며, 다음과 같은 캔버스가 만들어집니다:

| 선택기 비율 | 8 MP, 32의 배수에서의 크기 |
| :--- | :--- |
| 1:1 (정사각형) | 2912 x 2912 |
| 4:3 (표준) | 3360 x 2496 |
| 3:2 (사진) | 3552 x 2368 |
| 16:9 (와이드스크린) | 3872 x 2176 |
| 3:4 (세로 표준) | 2496 x 3360 |
| 2:3 (세로 사진) | 2368 x 3552 |
| 9:16 (세로 와이드스크린) | 2176 x 3872 |

- **샘플링**: 8단계는 모델 자체의 스케줄입니다. 단계를 늘려도 디테일이 더해지지 않으며, 조정할 CFG나 네거티브 프롬프트가 없습니다
- **시드**: 새 이미지에는 `randomize`로 설정하고, 배포된 예제를 재현하려면 `fixed`로 되돌리세요
- **업샘플된 프롬프트**: Preview Any 노드가 재작성된 프롬프트를 보여줍니다. 요청을 변경하기 전에 읽어볼 만합니다

변경하려는 이미지를 `Load Image`에 불러오고, `Request:` 뒤에 원하는 결과를 설명하세요. 출력은 해당 이미지의 형태를 따르므로, 조건화 노드의 너비와 높이 입력은 0으로 유지합니다.

- **소스 크기**: 편집 결과는 첫 번째 이미지의 크기로 렌더링되며, 최소 4메가픽셀까지 확대됩니다
- **참조 추가**: 이미지를 추가로 연결하면 프롬프트에 `<Picture 2>`, `<Picture 3>` 및 그 이후의 참조가 추가됩니다
- **유지할 것**: 변경되면 안 되는 요소를 명시하세요. 그렇지 않으면 모델이 장면 전체를 다시 그리는 경향이 있습니다

## 프롬프트 작성 팁

1. **이미지가 무엇인지 말하세요**: "숙련된 거리 사진작가가 찍은 사진"이나 "두 가지 색상의 리소그래프 인쇄"처럼 실제 대상을 명명하는 문장으로 시작하세요. 이렇게 하면 스타일 단어보다 더 안정적으로 결과물의 느낌이 정해집니다
2. **하나의 장면을 설명하세요**: 시점, 한 순간을 포착한 하나의 주요 피사체, 몇 가지 보조 요소, 그리고 소스와 방향이 있는 라이트를 제시하세요
3. **모든 텍스트 문자열을 인용하세요**: 정확한 단어를 지정하지 않은 텍스트는 의사 텍스트로 변합니다. 각 문자열을 따옴표로 묶고, 짧게 유지하고, 어디에 위치하는지 말하고, "no other text"로 끝내세요
4. **과장된 단어는 빼세요**: stunning, epic, cinematic, 8k 같은 단어는 모델을 광택이 나고 과도하게 채도가 높은 모습으로 몰아갑니다

## 제한 사항

- **해상도가 낮을수록 아티팩트가 더 많이 나타남**: 얼굴, 손, 작은 세부 정보는 8메가픽셀보다 2메가픽셀, 4메가픽셀에서 더 자주 깨집니다
- **손과 배경 인물이 깨질 수 있음**: 배경에 있는 작은 인물은 왜곡되어 나올 수 있습니다. 8메가픽셀로 렌더링하면 도움이 됩니다
- **텍스트는 완전히 신뢰할 수 없음**: 짧은 인용 문자열은 잘 렌더링되지만, 본문 텍스트나 긴 코드처럼 밀도가 높은 텍스트는 유사 텍스트로 변합니다
- **프롬프트에 민감함**: 프롬프트가 너무 길면 이미지 품질이 떨어지고, 너무 짧으면 업샘플러 없이는 약한 결과가 나옵니다
