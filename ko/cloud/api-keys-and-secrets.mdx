## 개요

**API 키 및 시크릿**은 Comfy Cloud가 사용자를 대신해 사용하는 공급자 API 키를 저장하는 Comfy Cloud 설정 패널입니다. 시크릿 값은 저장할 때 암호화되며, 값 자체는 다시 표시되지 않습니다.

이 패널에는 두 종류의 자격 증명이 있습니다:

- **모델 공급자 자격 증명**: Hugging Face 또는 Civitai 토큰으로, 가져오기 중에 비공개 및 게이트 모델을 다운로드하는 데 사용됩니다. 전체 가져오기 흐름은 [모델 가져오기](/ko/cloud/import-models)를 참고하세요.
- **BYOK 공급자 키**: Runway 또는 Google Gemini 키로, 파트너 노드 호출이 사용자 자신의 공급자 계정에서 실행되도록 합니다. [BYOK 공급자 키](#byok-provider-keys)를 참고하세요.

## 시크릿 패널 열기

1. [Comfy Cloud](https://cloud.comfy.org)에 로그인합니다.
2. `Ctrl + ,`(macOS에서는 `Cmd + ,`)로 설정 대화상자를 열거나, Comfy Cloud 메뉴에서 **설정**을 클릭합니다.
3. 설정 사이드바에서 **시크릿**을 선택합니다.

이 패널은 시크릿이 활성화된 로그인 계정에 표시됩니다.

![Comfy Cloud 설정 대화상자의 시크릿 섹션](/images/cloud/import_model/setting_secerts-1.png)

목록에는 저장된 모든 시크릿이 이름, 공급자, 생성 날짜, 마지막 사용 날짜와 함께 표시됩니다. 마지막 사용 날짜는 해당 정보를 확인할 수 있는 경우에만 표시됩니다.

## 시크릿 추가

<Steps>
  <Step title="새 시크릿 시작">
    **시크릿 추가**를 클릭합니다.
  </Step>
  <Step title="공급자 선택">
    **공급자** 드롭다운에서 공급자를 선택합니다. 목록은 Comfy Cloud에서 로드되므로, 나중에 추가된 공급자도 자동으로 여기에 표시됩니다. 공급자를 선택하면 해당 공급자의 가이드가 표시됩니다. 예를 들어 Runway API 키를 어디에서 찾을 수 있는지, Google AI Studio에서 Google Gemini 키를 생성하는 방법 등입니다.
  </Step>
  <Step title="자격 증명 유형 선택">
    두 가지 이상의 자격 증명을 받는 공급자는 **자격 증명 유형** 선택기를 표시합니다. 대부분의 공급자는 단일 API 키를 텍스트로 받습니다. 일부는 대신 JSON 자격 증명을 받습니다. 이 경우 JSON을 붙여넣거나 파일을 업로드하세요. JSON 객체는 최대 1 MB입니다.
  </Step>
  <Step title="시크릿 이름 지정">
    원하는 이름을 최대 255자까지 입력합니다. 이름은 고유해야 하며, 각 공급자는 시크릿 하나만 보관할 수 있습니다.
  </Step>
  <Step title="값 입력">
    키 또는 자격 증명을 붙여넣습니다. 값은 저장할 때 암호화되며 다시 볼 수 없으므로 직접 복사본을 보관하세요.
  </Step>
  <Step title="저장">
    **저장**을 클릭합니다. Comfy Cloud는 해당 자격 증명을 즉시 사용할 수 있습니다.
  </Step>
</Steps>

![이름, 공급자, 시크릿 값 필드가 있는 시크릿 추가 대화 상자](/images/cloud/import_model/setting_secerts-2.png)

## 시크릿 관리

- **편집**: 시크릿의 편집 아이콘을 클릭하여 이름을 바꾸거나 값을 교체합니다. 값을 비워 두면 현재 값이 유지되며, 시크릿을 만든 이후에는 공급자와 자격 증명 유형을 변경할 수 없습니다. 자격 증명을 다른 공급자로 옮기려면 시크릿을 삭제하고 새 시크릿을 추가하십시오.
- **삭제**: 삭제 아이콘을 클릭하고 확인합니다. 시크릿 삭제는 영구적이며 되돌릴 수 없습니다.

## BYOK 공급자 키 {#byok-provider-keys}

BYOK(Bring your own key)를 사용하면 Comfy 크레딧 대신 자신의 공급자 계정에서 파트너 노드를 실행할 수 있습니다.

- Comfy Cloud의 파트너 노드에서는 현재 **Runway**와 **Google Gemini**에 대한 BYOK를 지원합니다. 다른 공급자는 엔터프라이즈 고객의 요청에 따라 추가할 수 있습니다.
- BYOK는 워크스페이스 단위로 켜지며, 자신의 키로 실행되는 파트너 노드 호출은 Comfy 크레딧을 사용하는 대신 해당 공급자가 직접 청구합니다.
- 워크스페이스에 BYOK를 사용하려면 [엔터프라이즈 요청을 제출](https://www.comfy.org/contact)하세요.

워크스페이스에 BYOK가 활성화되면 시크릿 패널에서 공급자의 API 키를 추가하세요. 그러면 해당 워크스페이스에서 그 공급자의 파트너 노드 호출이 자신의 키로 실행됩니다.

## 비공개 모델용 자격 증명

시크릿에 저장된 Hugging Face 또는 Civitai token은 모델을 가져올 때 자동으로 사용되며, 이것이 비공개 및 gated 저장소를 다운로드하는 방식입니다. token은 가져오려는 저장소에 대한 읽기 권한이 필요하며, `.safetensors` 파일만 가져올 수 있습니다. 단계별 흐름, 지원되는 모델 폴더, 가져오기 제한은 [모델 가져오기](/ko/cloud/import-models)에서 확인할 수 있습니다.

<Note>
  시크릿 패널은 타사 제공업체의 자격 증명을 저장합니다. 이는 Comfy Cloud API 호출을 인증하는 Comfy API 키와는 별개입니다. 자세한 내용은 [API 키 발급받기](/ko/development/api-development/getting-an-api-key)를 참조하세요.
</Note>

## FAQ

<AccordionGroup>
  <Accordion title="자체 키를 사용해도 Comfy 크레딧이 차감되나요?">
    아니요. 자체 BYOK 키로 실행되는 파트너 노드 호출은 해당 공급자가 직접 청구하므로 Comfy 크레딧이 차감되지 않습니다.
  </Accordion>

  <Accordion title="BYOK와 함께 사용할 수 있는 공급자는 어디인가요?">
    Comfy Cloud의 파트너 노드에서는 현재 Runway와 Google Gemini입니다. 다른 공급자는 [엔터프라이즈 요청 양식](https://www.comfy.org/contact)을 통해 엔터프라이즈 고객의 요청에 따라 추가할 수 있습니다.
  </Accordion>

  <Accordion title="워크스페이스에서 BYOK를 어떻게 켜나요?">
    BYOK는 워크스페이스별로 활성화됩니다. [엔터프라이즈 요청을 제출](https://www.comfy.org/contact)하면 저희가 설정해 드리고, 그다음 시크릿 패널에서 공급자 키를 추가하시면 됩니다.
  </Accordion>

  <Accordion title="저장한 후에도 시크릿 값을 볼 수 있나요?">
    아니요. 시크릿은 암호화되며 저장된 값은 인터페이스로 반환되지 않으므로 키 사본을 직접 보관하세요. **편집**으로 언제든지 값을 교체하거나, 시크릿을 삭제하고 새로 추가할 수 있습니다.
  </Accordion>

  <Accordion title="같은 공급자에 두 번째 키를 추가할 수 없는 이유는 무엇인가요?">
    공급자마다 시크릿 하나를 보관합니다. 해당 공급자의 기존 시크릿을 편집하여 새 키를 추가하거나, 별도의 항목을 원한다면 기존 시크릿을 먼저 삭제하세요.
  </Accordion>

  <Accordion title="자격 증명 저장이 실패하는 이유는 무엇인가요?">
    흔한 원인은 이름 누락됨, 이름이 255자를 초과함, 이미 사용 중인 이름, 또는 이미 시크릿이 있는 공급자입니다. JSON 자격 증명의 경우 콘텐츠가 JSON 객체로 파싱되어야 하며 1 MB 이하여야 합니다.
  </Accordion>

  <Accordion title="토큰은 저장되었지만 비공개 모델 가져오기가 계속 실패합니다. 어떻게 해야 하나요?">
    가져오려는 저장소에 대한 읽기 액세스 권한이 토큰에 있는지 확인하세요. 비공개 또는 게이트 저장소에 대한 액세스 권한이 없는 토큰으로는 해당 모델을 다운로드할 수 없습니다.
  </Accordion>
</AccordionGroup>
