Select Model Device 노드를 사용하면 확산 모델이 실행될 장치(CPU 또는 특정 GPU)를 수동으로 선택할 수 있습니다. 이 노드는 모델을 다른 장치로 이동할 수 있으며, 다른 다중 GPU 노드와의 충돌을 자동으로 처리합니다. `"default"`를 선택하면 모델 로더가 선택한 원래 장치가 복원됩니다.

## 입력

| 매개변수 | 설명 | 데이터 타입 | 필수 | 범위 |
| --- | --- | --- | --- | --- |
| `model` | 특정 장치에 배치할 확산 모델입니다. | MODEL | 예 |  |
| `device` | 모델의 대상 장치입니다. 옵션은 현재 머신에서 사용 가능한 장치를 기준으로 동적으로 생성됩니다. (기본값: `"default"`) | COMBO | 예 | `"default"`<br />`"cpu"`<br />`"gpu:0"`<br />`"gpu:1"`<br />... (감지된 GPU마다 `"gpu:N"` 항목 하나) |

**매개변수 세부 정보:**
- `"default"`: 이전 Select Model Device 호출 이후에도 모델 로더가 할당한 로드 및 오프로드 장치를 복원합니다.
- `"cpu"`: 로드 및 오프로드 장치를 모두 CPU로 고정합니다.
- `"gpu:N"`: 로드 장치를 N번째 사용 가능한 GPU에 고정합니다(예: 첫 번째 GPU의 경우 `"gpu:0"`). 오프로드 장치는 로더의 원래 선택으로 복원됩니다.

**중요 참고 사항:**
- 요청한 장치가 현재 머신에 없으면(예: 2-GPU 머신에서 만든 워크플로를 1-GPU 머신에서 여는 경우) 노드는 실패하는 대신 모델을 변경 없이 그대로 전달하고 메시지를 기록합니다. 알 수 없는 `gpu:N` 값은 입력 유효성 검사 중 허용되므로 이식 가능한 워크플로가 조기에 오류를 내지 않습니다.
- 모델이 이미 요청한 장치에 있으면 노드는 빠른 경로를 사용하며 모델을 다시 로드하지 않습니다.
- 요청한 장치가 입력 모델이 이미 있는 장치와 다르면 로더의 재로드 팩터리를 사용하여 새 모델을 생성하므로 새 patcher가 새 장치에서 독립적인 가중치를 소유합니다.
- 모델 로더가 다중 GPU를 지원하지 않으면(재로드 팩터리 없음) 노드는 모델을 변경 없이 그대로 전달하고 경고를 기록합니다.
- MultiGPU CFG Split 복제본이 이미 선택한 장치를 점유하고 있으면 해당 복제본이 제거되어 두 모델이 같은 장치에 바인딩되지 않습니다.
- 기본값이 아닌 장치(CPU 또는 GPU)를 선택하면 노드는 모델의 compute dtype도 해당 장치에서 지원하는 값으로 조정합니다.
- 이미 모델을 사용한 노드(예: KSampler) 뒤에 이 노드를 배치하는 것은 권장되지 않습니다. 장치가 원래 장치와 일치하면 이전 노드에서 변경한 모든 상태가 관찰되기 때문입니다.

## 출력

| 출력 이름 | 설명 | 데이터 타입 |
| --- | --- | --- |
| `model` | 선택한 장치에 배치된 확산 모델입니다. 장치가 유효하지 않거나 사용할 수 없으면 모델은 변경 없이 그대로 전달됩니다. | MODEL |
