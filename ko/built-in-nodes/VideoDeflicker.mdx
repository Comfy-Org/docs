처리된 비디오에서 시간적 플리커를 제거하여 각 프레임이 이웃 프레임의 움직임을 따르면서도 자체 디테일을 유지하도록 합니다. 업스케일링하거나 프레임별로 처리한 후 깜박임이 발생하는 영상에 적합합니다: 광학 흐름 모델과 플리커가 있는 프레임을 연결하고, 선택적으로 안정적인 원본 복사본을 가이드로 연결하세요.

## 입력

| 매개변수 | 설명 | 데이터 타입 | 필수 | 범위 |
| --- | --- | --- | --- | --- |
| `optical_flow` | Load Optical Flow Model 노드의 광학 흐름 모델입니다(torchvision RAFT-large). | OPTICAL_FLOW | 예 | - |
| `images` | 안정화할 플리커가 있는 프레임입니다. 예를 들어 업스케일링되었거나 프레임별로 처리된 비디오입니다. | IMAGE | 예 | - |
| `guide` | 움직임을 따라갈 안정적인 원본 프레임이며, 모든 해상도에서 사용할 수 있습니다. 기본값은 `images`이며, 이 경우 플리커가 덜 제거됩니다. 또한 모션 보정 후 가이드 프레임 간 차이가 스무딩 가중치에 반영되므로, 추정된 모션으로 설명되지 않는 변화가 있는 가이드는 모션 추정이 맞더라도 스무딩이 약해집니다. | IMAGE | 아니요 | - |
| `strength` | 각 프레임이 이웃 프레임을 따르는 강도입니다(기본값: 1.0). 값이 높을수록 플리커를 더 많이 제거하고 미세 디테일을 더 많이 부드럽게 만듭니다. 0은 프레임을 변경하지 않고 반환합니다. | FLOAT | 예 | 0.0 ~ 100.0 (단계: 0.1) |
| `direction` | 처리 패스의 방향입니다. `bidirectional`은 정방향 패스와 역방향 패스를 평균하여 움직임 뒤에 처지는 현상을 방지합니다. `forward`는 단일 패스를 실행합니다. (기본값: `bidirectional`) | COMBO | 예 | `"bidirectional"`<br />`"forward"` |
| `threshold` | 프레임과 움직임 보상된 이웃 프레임 사이의 변화가 이 값보다 크면 실제 변화로 간주되어 덜 평활화됩니다(기본값: 0.1). 0은 모든 변화를 동일하게 평활화합니다. | FLOAT | 예 | 0.0 ~ 1.0 (단계: 0.01) |

**참고:**

- 광학 흐름은 `guide`를 축소한 사본에서 계산되므로 `images`와 크기가 같을 필요가 없습니다. `guide`의 픽셀은 출력에 섞이지 않습니다.
- `images`와 `guide` 중 더 짧은 쪽을 넘는 프레임은 처리되지 않습니다. `guide`가 더 짧으면 남은 프레임은 그대로 반환됩니다.

## 출력

| 출력 이름 | 설명 | 데이터 타입 |
| --- | --- | --- |
| `IMAGE` | 플리커가 제거된 프레임이며, `images`와 동일한 크기와 프레임 수를 가집니다. | IMAGE |
