Tripo: Smart UV는 모델의 UV를 다시 언랩하고 텍스처, 리그, 애니메이션을 새 레이아웃에 다시 매핑합니다. 모델의 원래 UV 레이아웃을 사용할 수 없을 때 사용합니다. 예를 들어 리토폴로지 후이거나 텍스처 이음새를 다시 만들어야 할 때입니다. 입력 모델은 80,000개 삼각형을 초과해서는 안 됩니다(쿼드는 두 개로 계산). 따라서 더 큰 모델은 먼저 Tripo: Retopology 또는 `face_limit`로 줄이십시오.

> **참고:** Tripo는 작업 기록을 서버에 7일 동안 보관합니다(2026년 12월 1일부터 적용). 그보다 오래된 작업 ID는 더 이상 확인할 수 없으므로, 해당 기간이 지난 후 저장된 워크플로를 다시 실행하면 이 노드에서 실패합니다. 이전 Tripo 노드를 다시 실행하여 새 작업 ID를 만들거나, 다운로드한 모델을 **Tripo: Import Model**로 다시 가져오십시오.

## 입력

| 매개변수 | 설명 | 데이터 타입 | 필수 | 범위 |
|-----------|-------------|-----------|----------|-------|
| `model_task_id` | 다시 언랩할 모델의 작업 ID입니다. Tripo 생성 노드의 모델 작업 ID 또는 리그, 리타깃, 세그먼트 작업 ID를 받습니다. | MODEL_TASK_ID | 예 | Tripo 작업 ID |
| `bake` | 기존 텍스처를 새 UV 레이아웃에 베이크합니다. 끄면 베이크를 건너뛰고 색상 텍스처가 없는 모델을 반환합니다(기본값: True). | BOOLEAN | 예 | `True`<br />`False` |

## 출력

| 출력 이름 | 설명 | 데이터 타입 |
|-------------|-------------|-----------|
| `model task_id` | 완료된 UV 작업의 작업 ID입니다. 예를 들어 Tripo: Texture와 같은 다른 Tripo 노드에 전달할 수 있습니다. | MODEL_TASK_ID |
| `GLB` | 다시 언랩된 모델의 GLB 형식입니다. 원본 모델이 FBX이면 비어 있습니다. | GLB FILE |
| `FBX` | 다시 언랩된 모델의 FBX 형식입니다. 원본 모델이 FBX인 경우(예: 쿼드 메시)에만 채워집니다. | FBX FILE |
| `UV atlas` | 모델의 렌더링된 UV 레이아웃을 이미지로 나타낸 것입니다. | IMAGE |
