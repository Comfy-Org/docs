다양한 섹션에서 다양한 설치 방법을 통해 ComfyUI 업데이트에 대해 다뤘지만, 이 포괄적인 가이드는 모든 업데이트 절차를 한데 모아 사용자가 ComfyUI를 명확히 업데이트하는 방법을 이해하도록 돕습니다.

## ComfyUI를 어떻게 업데이트하나요?

<Tabs>
<Tab title="휴대용">
ComfyUI 휴대용 버전은 간편한 일괄 스크립트를 제공해 쉽게 업데이트할 수 있습니다.

 ### 업데이트 스크립트 위치
휴대용 설치 디렉토리의 `update` 폴더에는 다음과 같은 업데이트 스크립트가 있습니다:

 ```
 ComfyUI_windows_portable
 └─ 📂update
    ├── update.py
    ├── update_comfyui.bat                           // Update to latest development version
    ├── update_comfyui_stable.bat                    // Update to latest stable version
    └── update_comfyui_and_python_dependencies.bat   // ⚠️ DANGER: Reinstalls dependencies - may cause conflicts
```

<Warning>업데이트 중에는 안정적인 인터넷 연결을 유지하세요.</Warning>

<Warning>
**⚠️ 위험: `update_comfyui_and_python_dependencies.bat` 스크립트는 매우 신중히 사용하세요!**

이 스크립트는 일반 업데이트보다 더 철저하며 다음을 수행합니다:
- ✅ ComfyUI 코드 자체 업데이트
- ✅ **표준 Nvidia 포터블**용 PyTorch 업데이트(현재 **CUDA 13.0 / cu130**, Python 3.13)
- ✅ 모든 파이썬 의존성 재설치

**레거시 Nvidia 포터블(CUDA 12.6 / cu126):** Nvidia **10시리즈 및 이전 GPU**용으로 따로 제공되는 포터블 패키지를 설치했다면, 해당 빌드는 **CUDA 12.6**과 Python 3.12를 사용합니다. cu130을 그 패키지의 올바른 대상으로 보지 마세요. 해당 포터블에 맞는 cu126 wheel 인덱스로 PyTorch를 다시 설치·업데이트하거나, [Portable 설치 가이드](/ko/installation/comfyui_portable_windows)에서 cu126 패키지를 다시 받으세요.

**위험:**
- 기존 설정과의 의존성 충돌을 일으킬 수 있음
- 특정 패키지 버전에 의존하는 커스텀 노드를 깨뜨릴 수 있음
- 수동으로 구성한 패키지를 덮어쓸 수 있음
- cu126(또는 기타 비-cu130) 포터블에서 무작정 cu130 wheel을 넣으면 GPU 시작이 깨질 수 있음

**⚠️ 이 스크립트는 다음 경우에만 사용하세요:**
- 의존성 문제를 해결해야 할 때
- 주요 버전 업데이트를 수행할 때
- 매일 업데이트를 원한다면 `update_comfyui.bat`를 사용하세요

**이 스크립트를 실행하기 전에:**
1. ComfyUI 전체 설치본 백업하기
2. 설치한 맞춤형 패키지 버전 기록하기
3. 사용 중인 포터블 패키지 확인하기(cu130 표준 vs cu126 레거시) — [Windows용 ComfyUI Portable](/ko/installation/comfyui_portable_windows) 참고
4. 필요하다면 커스텀 노드를 다시 설치할 준비 갖추기
</Warning>
</Tab>
<Tab title="데스크탑">
ComfyUI를 업데이트하려면 [관리 패널](/ko/installation/desktop/usage/instance-management#comfyui-업데이트)의 업데이트 탭을 여세요. **안정판**(기본값) 또는 **GitHub 최신판** 업데이트 채널을 선택할 수 있습니다.

데스크탑 앱 자체의 업데이트는 자동으로 이루어지며, ComfyUI 인스턴스 업데이트와는 별개입니다.
</Tab>
<Tab title="수동 설치">
수동으로 설치한 ComfyUI는 Git 명령어를 사용해 업데이트를 완료해야 합니다.

### 업데이트 전 요구사항
시스템에 [Git](https://git-scm.com/downloads)이 설치되어 있고, ComfyUI가 Git 복제를 통해 설치되었는지 확인하세요.

### 업데이트 단계
<Steps>
<Step title="가상 환경 활성화">
먼저 ComfyUI의 파이썬 가상 환경을 활성화하세요(사용 중인 경우):
```bash
# conda 환경용
conda activate comfyui

# venv 환경용
# Windows
venv\Scripts\activate
# macOS/Linux  
source venv/bin/activate
```
</Step>
<Step title="최신 코드 가져오기">
ComfyUI 설치 디렉토리로 이동한 후 최신 코드를 가져오세요:
```bash
cd <ComfyUI-installation-path>
git pull
```
</Step>
<Step title="의존성 업데이트">
ComfyUI의 의존성 패키지를 설치하거나 업데이트하세요:
```bash
pip install -r requirements.txt
```
<Warning>
ComfyUI의 가상 환경에 있는 상태에서 작업해야 시스템 레벨 파이썬 환경을 오염시키지 않습니다
</Warning>
</Step>
<Step title="ComfyUI 재시작">
업데이트 후 ComfyUI를 다시 시작하세요:
```bash
python main.py
```
</Step>
</Steps>

### 버전 전환 (선택 사항)
특정 버전으로 전환하려면 다음 명령어를 사용하세요:
```bash
# 커밋 내역 보기
git log --oneline

# 특정 커밋으로 전환
git checkout <commit-hash>

# 최신 버전으로 돌아가기
git checkout master
```
<Tip>최신 기능과 보안 수정을 위해 정기적으로 업데이트하는 것이 좋으며, 안정적인 버전은 시스템 안정성을 위해 권장됩니다</Tip>
</Tab>
</Tabs>

## ComfyUI를 업데이트할 때 무엇을 업데이트해야 하나요?

ComfyUI 업데이트는 주로 두 가지 요소로 이루어집니다:
1. ComfyUI 핵심 코드 업데이트
2. ComfyUI 핵심 의존성 업데이트, 여기에는 필요한 Python 의존성과 ComfyUI 기능 의존성 패키지가 포함됩니다

**핵심 코드**: 새로운 노드, 새로운 모델 지원, 새로운 기능 등
**핵심 의존성**: 주로 ComfyUI의 프론트엔드 기능, 워크플로 템플릿, 노드 도움말 문서 등이 포함됩니다

```
comfyui-frontend-package   # ComfyUI 프론트엔드 기능
comfyui-workflow-templates # ComfyUI 워크플로 템플릿  
comfyui-embedded-docs      # ComfyUI 노드 도움말 문서
comfy-kitchen              # ComfyUI 핵심 유틸리티
comfy-aimdo                # ComfyUI 핵심 유틸리티
```

이러한 핵심 의존성은 별도의 저장소에서 관리됩니다:
- [ComfyUI_frontend](https://github.com/Comfy-Org/ComfyUI_frontend/) - 프론트엔드 인터페이스 및 대화형 기능
- [workflow_templates](https://github.com/Comfy-Org/workflow_templates) - 미리 만들어진 워크플로 템플릿
- [comfyui-embedded-docs](https://github.com/Comfy-Org/embedded-docs) - 노드 도움말 문서
- [comfy-kitchen](https://github.com/Comfy-Org/comfy-kitchen) - 여러 컴퓨팅 백엔드를 사용하는 Diffusion 추론용 고속 커널 라이브러리
- [comfy-aimdo](https://github.com/Comfy-Org/comfy-aimdo) - AI 모델 수요 오프로딩 할당기

개발(nightly) 버전과 안정(release) 버전의 차이를 이해하는 것이 중요합니다:
- **개발 버전(nightly)**: 최신 커밋 코드로, 최신 기능을 사용할 수 있지만 잠재적인 문제가 포함될 수 있습니다
- **안정 버전(release)**: 안정적인 릴리스를 기반으로 구축되며, 보통 개발 버전보다 늦지만 더 높은 안정성을 제공합니다. 기능이 테스트되고 안정화된 후에 안정 버전을 지원합니다

많은 사용자가 업데이트 과정에서 릴리스 버전이나 데스크탑의 기본 **안정** 채널에 머물러 있다가, 필요한 기능이 개발/최신 테스트 버전(nightly) 빌드에서만 제공된다는 것을 발견하곤 합니다. **데스크탑**에서는 [관리 → 업데이트](/ko/installation/desktop/usage/instance-management#comfyui-업데이트)에서 **GitHub 최신 버전**으로 전환하세요. 휴대용 또는 수동 설치의 경우, 로컬 `ComfyUI/requirements.txt`가 [nightly 버전 의존성](https://github.com/Comfy-Org/ComfyUI/blob/master/requirements.txt)과 일치하는지 확인하여 모든 의존성이 최신 기능을 지원하는지 판단하세요.

## 일반적인 업데이트 문제

### 업데이트 이후 프론트엔드, 워크플로 템플릿, 노드가 누락되거나 오래된 경우


<Tabs>
  <Tab title="의존성이 제대로 업데이트되지 않은 경우">
    사용자는 종종 `git pull` 명령만 사용하여 ComfyUI 코드를 업데이트하고 **핵심 의존성 업데이트는 소홀히 하여**, 다음과 같은 문제가 발생합니다:

  - 프런트엔드 기능이 누락되거나 비정상적으로 동작
  - 새로 추가된 워크플로 템플릿을 찾을 수 없음
  - 노드 도움말 문서가 오래되었거나 누락됨
  - 새로운 기능에 해당하는 프런트엔드 지원이 없음

  `git pull` 명령을 사용한 후에는 해당 ComfyUI 환경에서 `pip install -r requirements.txt`를 사용하여 의존성을 업데이트하세요.
  </Tab>
  <Tab title="의존성 업데이트 실패">
    의존성 업데이트가 실패하는 경우, 일반적으로 네트워크 또는 컴퓨터 권한 문제가 원인입니다. 업데이트 중 핵심 의존성 오류가 발생하면 시스템은 이전 버전으로 폴백합니다. 일반적으로 시작 시 다음과 같은 로그가 표시됩니다:
    ```
    Falling back to the default frontend.
    ComfyUI frontend version: xxx
    ```

    다음 문제 해결 단계를 따르세요:
    1. 해당 환경에서 `pip list`를 사용하여 현재 설치된 의존성 패키지를 확인합니다. 버전 불일치가 발견되면 ComfyUI 환경에서 `pip install -r requirements.txt`를 사용하여 의존성 업데이트를 다시 시도합니다.
    2. 업데이트 후에도 문제가 지속되면 네트워크 연결을 확인하세요. 중국 본토 사용자는 GitHub 저장소에 안정적으로 접근하기 위해 프록시를 구성해야 할 수 있습니다.
    3. 문제가 계속되면 컴퓨터 권한을 확인하세요. 관리자 권한이 필요한 경우 관리자 권한으로 명령줄을 실행하세요.
  </Tab>
</Tabs>

### 핵심 종속성 업데이트 문제 해결

핵심 종속성 업데이트가 실패하면 다음 문제 해결 단계를 따르세요.

<Steps>
  <Step title="네트워크 연결 확인">
    중국 본토에 있는 경우 PyPI에 액세스할 수 있는지 확인하거나 국내 미러를 구성하세요.
    ```bash
    # 칭화대학교 미러 사용
    pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
    ```
  </Step>
  <Step title="핵심 패키지 개별 설치">
    배치 설치가 실패하면 패키지를 개별적으로 설치해 보세요. **먼저 `ComfyUI/requirements.txt`의 버전 요구 사항을 확인하세요**.
    
    **그런 다음 지정된 버전에 따라 설치하세요(requirements.txt의 버전 번호 사용):**
    ```bash
    pip install comfyui-frontend-package==<version> 
    pip install comfyui-workflow-templates==<version>
    pip install comfyui-embedded-docs==<version>
    pip install comfy-kitchen==<version>
    pip install comfy-aimdo==<version>
    ```
    <Warning>
    `ComfyUI/requirements.txt`에 지정된 정확한 버전 번호를 사용하는 것이 권장됩니다. 호환성 문제가 발생할 수 있으므로 최신 버전으로 독립적으로 업그레이드하지 마세요.
    </Warning>
  </Step>
</Steps>

### 업데이트 이후 새 기능을 찾을 수 없는 이유는 무엇인가요?

이것은 가장 흔한 문제 중 하나입니다:
- **Desktop**에서 **Stable** 업데이트 채널을 사용 중이라면 기능이 최신 GitHub 커밋보다 뒤처질 수 있습니다. 더 새로운 기능이 필요할 때 [관리 → 업데이트](/ko/installation/desktop/usage/instance-management#comfyui-업데이트) 탭에서 채널을 **Latest on GitHub**로 전환하세요(Latest는 덜 안정적일 수 있습니다).
- Portable 또는 수동 설치의 경우, 최신 커밋이 필요할 때 **안정 버전(release)**이 아니라 **개발 버전(nightly)**을 사용 중인지 확인하세요.

또한 업데이트 과정에서 해당 의존성이 성공적으로 업데이트되었는지 확인하세요. 업데이트 후에도 문제가 지속되면 [의존성 업데이트 문제 해결](#일반적인-업데이트-문제) 섹션을 참고하여 문제를 진단하세요.

### 개발(Nightly) 버전과 안정(Release) 버전 간에 전환하는 방법은 무엇인가요?

버전 간 차이점:

<Tabs>
  <Tab title="개발 버전(Nightly)">
    - **특징**: 최신 커밋 코드를 포함합니다
    - **장점**: 최신 기능과 개선 사항을 가장 먼저 경험할 수 있습니다
    - **위험**: 발견되지 않은 버그나 불안정 요소가 포함될 수 있습니다
    - **적합한 사용자**: 개발자, 테스터, 최신 기능을 경험하고자 하는 사용자
  </Tab>
  <Tab title="안정 버전(Release)">
    - **특징**: 테스트와 검증을 거친 안정적인 코드입니다
    - **장점**: 안정성이 높아 프로덕션 환경에 적합합니다
    - **단점**: 기능 업데이트가 지연되어 개발 버전보다 몇 주 또는 몇 달 뒤처질 수 있습니다
    - **적합한 사용자**: 안정성을 요구하는 사용자, 프로덕션 환경 사용자
  </Tab>
</Tabs>

  <Tab title="포터블">

### 업데이트 이후 오류가 발생하면 어떻게 해야 하나요?

1. **의존성 확인**: `pip install -r requirements.txt`를 실행하여 모든 의존성이 업데이트되었는지 확인하세요
2. **커스텀 노드 확인**: 일부 커스텀 노드는 새 버전과 호환되지 않을 수 있습니다
3. **버전 롤백**: 문제가 심각한 경우 이전 안정 버전으로 롤백할 수 있습니다

문제가 발생하면 문제 해결 페이지에서 해결 방법을 참고하세요.

### 새로운 기능에 대한 업데이트 소식을 어떻게 받아볼 수 있나요?

- **GitHub Releases**: 안정적인 버전 업데이트는 [ComfyUI Releases](https://github.com/Comfy-Org/ComfyUI/releases)에서 확인하세요
- **GitHub Commits**: 개발 진행 상황을 파악하려면 [최신 커밋](https://github.com/Comfy-Org/ComfyUI/commits/master)을 확인하세요
- **커뮤니티 논의**: 최신 소식은 [블로그](https://blog.comfy.org)와 [Twitter](https://x.com/comfyui)를 팔로우하세요
