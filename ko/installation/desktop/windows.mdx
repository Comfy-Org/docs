**Comfy Desktop**은 하나의 실행기에서 여러 ComfyUI 인스턴스를 실행할 수 있게 해주는 다중 설치 매니저입니다. 이 가이드에서는 Windows에서 Comfy Desktop을 설치하고 제거하는 방법을 다룹니다.

## 시스템 요구 사항

- **OS:** Windows 10 이상
- **아키텍처:** x64 또는 ARM64
- **GPU:** 좋은 성능을 위해서는 전용 GPU(NVIDIA / AMD)를 권장하지만, 필수는 아닙니다.
- **디스크 공간:** 설치당 최소 4.85 GB 권장

## 설치

다운로드한 `.exe` 설치 프로그램(NSIS 설치 프로그램)을 실행하고 안내에 따라 진행하세요. 설치 후 Start Menu 또는 바탕화면 바로가기에서 Comfy Desktop을 실행하세요.

![Windows setup](/images/desktop/installation/windows_1_install.png)
앱을 처음 열면 첫 실행 설정에서 Comfy를 어떻게 실행할지 묻습니다. Comfy Cloud에서 실행하거나 이 컴퓨터에 로컬로 설치할 수 있습니다. 어떤 선택을 수집하는지는 [첫 실행](/ko/installation/desktop/overview#첫-실행) 을 참조하세요.

## 제거

### Comfy Desktop 제거

1. **설정 → 앱 → 설치된 앱**으로 이동합니다.
2. **Comfy Desktop**을 찾아 **제거**를 클릭합니다.

![Windows에서 Comfy Desktop 제거](/images/desktop/installation/windows_2_uninstall.png)

### 앱 제거 시 제거되지 않는 항목

Comfy Desktop을 제거하면 런처 앱 자체만 제거됩니다. 다음 데이터는 **제거되지 않으며**, 완전히 정리하려면 수동으로 삭제해야 합니다.

| 데이터 | 기본 위치 | 설명 |
|------|-----------------|-------------|
| 설치 | `%LOCALAPPDATA%\Comfy-Desktop\ComfyUI-Installs` | 생성한 각 ComfyUI 설치(앱 내에서도 삭제 가능). 사용자 지정 설치 경로도 제거되지 않습니다. 이전 설치본은 `%USERPROFILE%\ComfyUI-Installs`에 남아 있을 수 있습니다. |
| 공유 모델 및 출력 | `%LOCALAPPDATA%\Comfy-Desktop\ComfyUI-Shared` | 공유 모델 라이브러리, 입력/출력 디렉토리. 이전 설치본은 여전히 `%USERPROFILE%\ComfyUI-Shared`를 사용할 수 있습니다. |
| 앱 설정 및 레지스트리 | `%APPDATA%\Comfy Desktop` | 설정 및 설치 기록 |
| 로그 | `%APPDATA%\Comfy Desktop\logs` | 데스크톱 앱 로그(`app.log`) |

<Warning>위에 나열된 디렉토리에는 **개인 ComfyUI 데이터**(모델, 출력, 설정, 설치)가 포함되어 있습니다. 이는 Comfy Desktop 애플리케이션 파일이 **아닙니다**. 삭제하면 데이터가 영구적으로 제거됩니다.</Warning>

모든 항목을 완전히 제거하려면:

1. **앱 데이터 폴더 삭제**: `%APPDATA%\Comfy Desktop`
2. **개별 설치 삭제**: 앱 내에서 삭제하거나 `%LOCALAPPDATA%\Comfy-Desktop\ComfyUI-Installs`를 수동으로 삭제합니다(설치가 생성된 경로가 `%USERPROFILE%\ComfyUI-Installs`인 경우 해당 경로를 삭제). 직접 설정한 사용자 지정 설치 디렉토리도 삭제하세요.
3. **공유 모델 라이브러리 삭제**: 더 이상 필요하지 않은 경우에만 `%LOCALAPPDATA%\Comfy-Desktop\ComfyUI-Shared`(또는 `%USERPROFILE%\ComfyUI-Shared`)를 삭제합니다.

## ComfyUI가 Windows 오류 코드로 충돌할 때

ComfyUI 프로세스가 네이티브 오류로 종료되면 Windows는 원인을 알 수 없는 큰 종료 코드를 돌려줍니다. Comfy Desktop은 실패가 나타나는 위치에서 그 10진수와 16진수 조합을 해석합니다.

- **시작 중**: 실행이 실패하며 `Process exited with code 3221225477 / 0xC0000005 (memory access violation ...)` 와 ComfyUI 출력의 마지막 몇 줄이 표시됩니다.
- **ComfyUI가 시작된 뒤**: 인스턴스 창은 닫히지 않고 **ComfyUI exited unexpectedly** 와 `exit code 3221225477 / 0xC0000005`, 오류 출력의 마지막 부분, 그리고 **Restart ComfyUI** 와 **Back** 작업이 표시됩니다. 이 충돌은 해당 인스턴스에만 영향을 줍니다.

두 값은 같습니다. 10진수 3221225477이 0xC0000005(STATUS_ACCESS_VIOLATION)이며, Windows에서의 세그멘테이션 오류입니다. Comfy Desktop은 이를 메모리 액세스 위반으로 보고하며, 보통 ComfyUI의 결함이 아니라 네이티브 라이브러리의 손상 또는 누락이라고 안내합니다. 다만 코드만으로는 어느 라이브러리가 원인인지 알 수 없습니다. 다른 구성 요소가 손상시킨 메모리 때문에 모듈이 종료될 수도 있으므로, 로그와 아래의 모듈 이름으로 좁혀야 합니다.

Windows가 보고하는 다른 네이티브 오류도 같은 10진수와 16진수 조합으로 표시되며 이름은 나오지 않습니다. `0xC000001D` 는 잘못된 명령으로, 보통 CPU에 해당 빌드가 요구하는 명령 집합이 없다는 뜻입니다. `0xC0000409` 는 fail-fast 종료이며, 대부분 스택 버퍼 오버런, `0xC0000374` 는 힙 손상입니다.

### 전체 로그 확인

실패 메시지에는 ComfyUI 출력의 마지막 몇 줄만 표시됩니다. 실행의 전체 출력은 설치 폴더의 로그 파일에 기록됩니다.

```
<install folder>\logs\comfyui.log
```

인스턴스의 **관리 패널** 에는 같은 설치의 셸을 여는 [터미널 탭](/ko/installation/desktop/usage/manage#터미널-탭) 이 있으므로 그곳에서 읽어도 됩니다. 마지막 몇 줄이 Python 가져오기 단계라면 패키지를 불러오는 중에 종료된 것입니다. 워크플로우까지 진행했는지는 로그의 앞부분에서 확인할 수 있습니다.

### 문제 모듈 찾기

충돌한 라이브러리는 ComfyUI 로그에 남지 않습니다. Windows 이벤트 뷰어에 기록됩니다.

1. `Win+R` 을 누르고 `eventvwr.msc` 를 입력한 뒤 Enter를 누릅니다.
2. **Windows 로그 → 응용 프로그램** 을 엽니다.
3. 충돌 시각에 기록된 **응용 프로그램 오류** 이벤트를 선택합니다. **오류가 발생한 응용 프로그램 이름**(또는 **응용 프로그램 경로**)이 해당 인스턴스의 `python.exe` 를 가리키며, 같은 이벤트의 **오류가 발생한 모듈 이름** 을 확인합니다.

| 모듈 | 원인 | 해결 |
|---|---|---|
| `nvcuda.dll`, `nvml.dll` | GPU 드라이버가 이 설치의 CUDA 빌드보다 오래됨 | NVIDIA 드라이버를 업데이트합니다. CUDA 13 빌드는 580 이상, 이전 CUDA 빌드는 더 낮은 버전도 허용합니다 |
| `torch*.dll`, `cudnn*.dll`, `cublas*.dll` | 인스턴스 환경의 PyTorch 또는 CUDA 패키지가 손상되었거나 일부만 교체됨 | 인스턴스를 다시 설치하거나 [업데이트 탭](/ko/installation/desktop/usage/manage#업데이트-탭) 에서 PyTorch를 전환합니다 |
| `msvcp140.dll`, `vcruntime140.dll`, `vcruntime140_1.dll` | Microsoft Visual C++ 런타임이 없음 | Microsoft Visual C++ 2015-2022 Redistributable(x64)을 설치한 뒤 다시 실행합니다 |

`0xC0000005` 충돌일 때 Comfy Desktop은 `C:\Windows\System32` 에서 이 세 런타임 파일을 확인하고, 빠진 파일이 있으면 메시지에 그 사실을 덧붙입니다. 이 안내가 나오면 런타임을 설치하는 것이 해결책이며, 아래 모듈 표는 해당되지 않습니다. Windows가 전혀 찾지 못하는 라이브러리는 오류 모듈로 나타나지 않고 `0xC0000135`(STATUS_DLL_NOT_FOUND)로 실패합니다.

### 함께 확인할 원인

- **메모리에 들어가지 않는 모델.** 큰 텍스트 인코더나 확산 모델을 불러온 직후 충돌이 반복되면 메모리가 한계일 가능성이 큽니다. 로그와 시스템 RAM, GPU 메모리 사용량을 확인한 뒤 더 작은 모델이나 더 가벼운 정밀도를 시도하세요.
- **의존성 동기화가 중단된 경우.** 설치나 업데이트는 ComfyUI의 `requirements.txt` 로 환경을 동기화하며, PyTorch 패키지는 PyTorch 구성에서 따로 처리합니다. 큰 다운로드는 오래 걸릴 수 있고, 연결이 끊기거나 응답하지 않는 미러 때문에 중단되면 버전이 어긋난 패키지가 남아 다음 실행에서 충돌할 수 있습니다. 환경을 직접 고치지 말고 인스턴스를 다시 설치하세요. **Uninstall** 은 설치 폴더와 그 안의 모든 파일을 삭제하므로, 그곳에 둔 파일은 먼저 옮기세요. 공유 디렉터리의 모델은 영향을 받지 않습니다.
