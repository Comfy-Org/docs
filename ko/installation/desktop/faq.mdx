## 일반 질문

<Accordion title="Comfy Desktop과 레거시 데스크톱의 차이점은 무엇인가요?">
Comfy Desktop은 **멀티 설치 관리자** 역할을 하는 완전히 새로 작성된 버전입니다. 단일 설치 애플리케이션이었던 레거시 데스크톱과 달리, Comfy Desktop을 사용하면 여러 ComfyUI 버전을 나란히 설치, 관리 및 실행할 수 있습니다. 또한 스냅샷 및 모델 다운로드 관리 기능도 추가되었습니다.

레거시 데스크톱 사용자라면 [마이그레이션 가이드](/ko/installation/desktop/usage/migrate)를 확인하여 기존 설정을 이전하세요.
</Accordion>
<Accordion title="Comfy Desktop은 오픈 소스인가요?">
네. 소스는 [GitHub](https://github.com/Comfy-Org/Comfy-Desktop)에서 확인할 수 있습니다. Comfy Desktop은 이중 라이선스로 제공됩니다: [AGPL-3.0-or-later](https://github.com/Comfy-Org/Comfy-Desktop/blob/main/LICENSE) 또는 Comfy Org의 상용 라이선스 (`licensing@comfy.org`) 중에서 선택할 수 있습니다.
</Accordion>
<Accordion title="Comfy Desktop이 Portable/Manual 설치를 대체하나요?">
Comfy Desktop은 여러 설치 옵션 중 하나입니다. 필요에 따라 **Portable (Windows)** 설치, **Manual Install** 또는 **Comfy Cloud**를 계속 사용할 수 있습니다. Desktop은 사용 편의성과 원클릭 업데이트, 스냅샷 관리 같은 기능으로 인해 대부분의 사용자에게 권장됩니다.
</Accordion>
<Accordion title="업데이트 확인을 끌 수 있나요?">
아니요. Comfy Desktop은 시작 직후와 이후 10분마다 새 버전을 확인하며, 이 확인은 끌 수 없습니다. 유일한 업데이트 설정은 **Desktop Settings → Updates**의 **Automatically install Desktop updates**이며, 기본값은 켜짐입니다.

- **켜짐**: 새 버전이 백그라운드에서 다운로드되어 별도 확인 없이 설치됩니다. 다운로드 중에는 제목 표시줄에 **Downloading update…**가, 적용할 준비가 되면 **Desktop Update Ready**가 표시됩니다.
- **꺼짐**: Comfy Desktop은 계속 확인하고 알려주지만, 자동으로 다운로드하지는 않습니다. 대신 제목 표시줄에 **Desktop Update** 알약이 표시되며, 이를 클릭하면 업데이트가 다운로드되고 다시 시작하라는 안내가 나옵니다.

인스턴스 내부의 ComfyUI 버전은 별도로 업데이트합니다. 인스턴스의 **Update** 탭에서 **Stable** 또는 **Latest on GitHub** 채널을 선택해 업데이트하세요.

Linux에서는 앱 내 업데이터가 `.deb` 설치에는 적용되지 않습니다. [범용 다운로드 링크](https://dl.todesktop.com/241130tqe9q3y)에서 새 패키지를 내려받아 `sudo apt install ./*.deb`로 설치하세요.
</Accordion>

## 설치 및 설정

<Accordion title="시스템 요구 사항은 무엇인가요?">
전체 내용은 [시스템 요구 사항](/ko/installation/system_requirements)을 참조하세요.

- **Windows:** Windows 10 이상, x64 또는 ARM64. 전용 GPU (NVIDIA / AMD)가 권장되지만 필수는 아닙니다.
- **macOS:** macOS 13 이상 (Ventura), Apple Silicon (M1 이상)
- **Linux:** 공식 `.deb` 및 AppImage 패키지는 [Comfy Desktop 저장소](https://github.com/Comfy-Org/Comfy-Desktop)를 통해 배포됩니다. 전용 GPU가 권장됩니다.
- **디스크:** 독립형 설치당 최소 4.85 GB
- **RAM:** 최소 8 GB, 16 GB 권장
</Accordion>
<Accordion title="관리자 권한 없이 Comfy Desktop을 설치할 수 있나요?">
**Windows**에서는 독립형 설치에 관리자 권한이 필요하지 않습니다. **macOS**에서는 초기 시스템 전체 설치에 관리자 권한이 필요합니다. **Linux**에서는 `.deb` 패키지 설치에 `sudo`가 필요합니다. AppImage는 관리자 권한 없이 사용자 공간에서 실행됩니다.
</Accordion>
<Accordion title="Comfy Desktop은 어떻게 다운로드하나요?">
공식 [ComfyUI 다운로드 페이지](https://comfy.org/download)에서 최신 Windows 또는 macOS 빌드를 다운로드하세요. Linux에서는 [Comfy Desktop 저장소](https://github.com/Comfy-Org/Comfy-Desktop)의 [범용 다운로드 링크](https://dl.todesktop.com/241130tqe9q3y)에서 `.deb` 또는 AppImage를 받을 수 있습니다. 소스에서 실행하려면 [Linux 설치 가이드](/ko/installation/desktop/linux)를 참조하세요.
</Accordion>
<Accordion title="레거시 데스크톱과 Comfy Desktop을 모두 설치할 수 있나요?">
네, 공존할 수 있습니다. 하지만 설치된 프로그램을 새로운 Comfy Desktop으로 이전하고 최종적으로 레거시 데스크톱을 제거하는 것이 좋습니다. [마이그레이션 가이드](/ko/installation/desktop/usage/migrate)를 참조하세요.
</Accordion>

## 사용법

<Accordion title="새 ComfyUI 설치를 추가하려면 어떻게 하나요?">
대시보드에서 **+** 카드를 선택하거나(또는 ☰ 메뉴의 **New Instance**) 독립형 인스턴스를 만듭니다. 기존 설치를 추적하려면 제목 표시줄의 ☰ 메뉴를 열고 **Add Existing Instance**를 선택하세요. **Comfy Cloud** 카드를 사용하여 Cloud에 연결하세요.

- **Standalone:** 번들 Python이 포함된 새 설치
- **Add Existing Instance:** git 복제 또는 포터블 설치 추적
- **Cloud:** Comfy Cloud에 연결
</Accordion>
<Accordion title="여러 ComfyUI 버전을 동시에 실행할 수 있나요?">
네! Comfy Desktop은 이를 위해 설계되었습니다. 각 설치는 자체 Python과 의존성을 가진 격리된 환경에서 실행되며, 각자 자신의 창을 가집니다.

로컬 인스턴스가 실행 중이거나 시작 중일 때 다른 인스턴스를 시작하면 Comfy Desktop이 먼저 확인합니다. **Run All**은 실행 중인 인스턴스와 함께 새 인스턴스를 시작하고, **Close & Launch**는 먼저 기존 인스턴스를 중지합니다. [Desktop Settings](/ko/installation/desktop/usage/settings#환경설정)에서 **Warn before running multiple instances**를 끄면 이 확인이 표시되지 않습니다.
</Accordion>
<Accordion title="모델, 커스텀 노드, 설정은 어디에 저장되나요?">
모델은 기본적으로 인스턴스 간에 공유됩니다. [데스크톱 설정 → 스토리지](/ko/installation/desktop/usage/settings#저장소)에서 공유 폴더를 구성하세요.

- **Standalone:** 설치 자체는 설치 폴더에 있습니다. 커스텀 노드와 Python 환경은 설치별로 있습니다. 모델은 일반적으로 공유 모델 디렉토리에서 가져옵니다.
- **Git clone / portable (tracked):** 데이터는 기존 폴더(`models/`, `custom_nodes/`, `user/`)에 유지됩니다. 공유 모델, 입력 및 출력을 선택할 수 있습니다.
</Accordion>
<Accordion title="스냅샷은 어떻게 작동하나요?">
Comfy Desktop은 부팅과 재시작할 때마다, 업데이트 전후에, 그리고 복원 후에 스냅샷을 자동으로 생성합니다. 스냅샷에는 인스턴스의 ComfyUI 버전, 커스텀 노드와 버전, 환경의 모든 pip 패키지가 기록됩니다. 모델 파일, 입력, 출력은 포함되지 않습니다.

인스턴스의 **Snapshots** 탭에서 스냅샷을 찾아보고 복원, 내보내기, 공유할 수 있습니다. [스냅샷](/ko/installation/desktop/usage/snapshots)을 참조하세요.
</Accordion>
### Comfy Desktop 중지/종료 방법

실행 중인 ComfyUI 인스턴스를 중지하려면(앱을 열린 상태로 유지하면서 Python 백엔드 중지):

1. 인스턴스 카드에서 **⋮ (kebab) 메뉴**를 클릭합니다.
2. **중지**를 선택합니다.
3. 대화상자에서 확인합니다.

이렇게 하면 ComfyUI Python 프로세스가 중지되지만 데스크톱 앱 창은 열린 상태로 유지되므로 언제든지 다시 시작할 수 있습니다. 앱을 종료하려면 왼쪽 상단의 **☰ 메뉴**를 열고 **Quit Desktop**을 선택합니다(또는 운영 체제의 해당 종료 명령). 인스턴스 창을 닫으면 그 창의 ComfyUI가 중지되고, 마지막 창을 닫으면 Comfy Desktop이 종료되므로 창을 닫아도 Dashboard로 돌아가지 않습니다. 앱에 머물면서 인스턴스를 계속 실행하려면 제목 표시줄 알약 버튼에서 **인스턴스 선택기**를 열고 **Open Dashboard**를 선택하세요. 자세한 내용은 [창 닫기와 종료](/ko/installation/desktop/usage/overview#windows-closing-and-quitting)를 참고하세요.

## 문제 해결

<Accordion title="설치 후 앱이 시작되지 않습니다">
1. **Windows:** 관리자 권한으로 한 번 실행해 보세요.
2. **macOS:** 보안 경고가 표시되면 **시스템 설정 → 개인정보 보호 및 보안**으로 이동하여 **그래도 열기**를 클릭하세요.
3. **Linux:** FUSE 2가 설치되어 있는지 확인하세요 (`sudo apt install libfuse2`)
4. 최신 버전은 [다운로드 페이지](https://comfy.org/download)에서 확인하세요.
</Accordion>
<Accordion title="업데이트 후 Comfy Desktop이 저절로 종료됩니다 (Windows)">
Windows에서 업데이트 다운로드가 완료되지 않으면 Comfy Desktop 1.0.46 이하 버전이 실행되지 않을 수 있습니다. 앱이 업데이트 화면을 잠깐 표시한 뒤 오류 없이 종료됩니다. 이 현상은 실행할 때마다 반복되며, 앱이 수정 버전을 다운로드하기 전에 종료됩니다. 버전 1.0.47 이상에서는 이 문제가 수정되었습니다.

복구하려면 최신 버전을 수동으로 설치하세요.

1. [최신 Windows 설치 프로그램](https://dl.todesktop.com/241130tqe9q3y/windows)을 다운로드하거나 [다운로드 페이지](https://comfy.org/download)에서 받으세요.
2. 설치 프로그램을 실행하세요. 이전 버전을 먼저 제거할 필요는 없습니다.
3. Comfy Desktop을 실행하세요.

설치 항목, 모델, 설정은 그대로 유지됩니다.
</Accordion>
<Accordion title="GPU가 감지되지 않습니다">
- NVIDIA 드라이버가 최신인지 확인하세요.
- Linux에서는 CUDA 툴킷이 설치되어 있는지 확인하세요.
- 설치 유형이 GPU를 지원하는지 확인하세요 (Standalone 및 Git Clone은 지원; 클라우드 연결은 원격 GPU 사용).
</Accordion>
<Accordion title="설치가 업데이트에 실패합니다">
- 인터넷 연결을 확인하세요.
- 다시 시도하기 전에 인스턴스의 **Snapshots** 탭에서 수동 스냅샷을 생성하세요.
- 문제가 계속되면 이전 스냅샷으로 복원하고 다시 시도하세요.
</Accordion>
<Accordion title="Low Disk Space 또는 Not Enough Space for Template Models가 표시됩니다">
**새 인스턴스** 과정에서 Comfy Desktop은 설치 드라이브의 여유 공간을 확인합니다. **Low Disk Space**는 경고입니다 — **Continue Anyway**로 진행하거나 다른 경로를 선택하세요. **Not Enough Space for Template Models**는 해당 템플릿을 차단합니다. 더 가벼운 워크플로를 고르거나 공간을 확보하세요. 디스크가 매우 작으면 템플릿 단계가 건너뛰어질 수 있습니다. [새 인스턴스 생성하기](/ko/installation/desktop/usage/instance-management#새-인스턴스-생성하기)를 참조하세요.
</Accordion>
<Accordion title="Comfy Desktop 시작 로그는 어떻게 확인하나요?">
Desktop 앱은 순환되는 `app.log` 파일에 기록합니다. 가장 빠른 방법은 **데스크탑 설정 → 로그 → 진단 → 로그 폴더 열기**입니다 (왼쪽 상단 ☰ 메뉴).

기본 로그 폴더:

- **Windows:** `%APPDATA%\Comfy Desktop\logs`
- **macOS:** `~/Library/Logs/Comfy Desktop`
- **Linux:** `~/.config/Comfy Desktop/logs`

`app.log`를 찾으세요. 이전 세션은 타임스탬프가 붙은 `app.log_*.log` 파일로 순환됩니다.

ComfyUI 프로세스 출력(Desktop 앱 자체가 아님)을 확인하려면 인스턴스의 **관리** 패널에서 **터미널** 탭을 사용하세요. [관리](/ko/installation/desktop/usage/manage)를 참조하세요.
</Accordion>
<Accordion title="ComfyUI에서 Ollama를 사용할 수 있나요?">
ComfyUI는 확산 모델 백엔드로 [Ollama](https://ollama.ai)를 네이티브로 통합하지 않습니다. 다만 ComfyUI Manager 레지스트리의 **커스텀 노드**를 통해 Ollama가 제공하는 LLM으로 프롬프트 생성과 텍스트 처리를 할 수 있습니다.

LLM 서비스 연결은 [커스텀 노드 설치](/ko/installation/install_custom_node)를 참조하세요.
</Accordion>
<Accordion title="Comfy Desktop을 어떻게 제거하나요?">
Comfy Desktop과 설치는 디스크에서 분리되어 있습니다. 앱과 설치를 제거하려면:

1. 앱 내에서 **설치 항목을 제거**하세요. 인스턴스 카드의 ⋮ 메뉴에서 **Uninstall**을 선택하면 해당 인스턴스와 디스크의 파일이 삭제됩니다. Manage 패널의 **More** 메뉴에서 **Forget**을 선택하면 목록에서만 사라지고 파일은 디스크에 남습니다(Legacy Desktop에서 마이그레이션한 설치는 그 자리에서 인계되므로 **Forget**이 표시되지 않습니다). 설치 폴더를 수동으로 삭제해도 됩니다.
2. 시스템의 표준 방법을 사용해 **앱을 제거**하세요 (Windows의 프로그램 추가/제거, macOS의 휴지통으로 드래그, Linux의 패키지 관리자).

앱 설정, 로그, 공유 모델, 출력은 그대로 남습니다. 남은 폴더와 완전한 정리는 [Windows](/ko/installation/desktop/windows#앱-제거-시-제거되지-않는-항목), [macOS](/ko/installation/desktop/macos#앱을-제거해도-삭제되지-않는-항목), [Linux](/ko/installation/desktop/linux#남은-데이터-삭제)를 참고하세요.
</Accordion>
<Accordion title="Comfy Desktop을 헤드리스 또는 서버 모드로 실행할 수 있나요?">
아니요. Comfy Desktop은 로컬 GUI 애플리케이션으로 설계되었으며, 헤드리스 모드, 서버 전용 모드 또는 원격 조작 모드를 지원하지 않습니다. ComfyUI 인스턴스를 시작하고 관리하려면 그래픽 데스크톱 환경이 필요합니다.

헤드리스 또는 서버 배포가 필요하다면 **수동 ComfyUI 설치** 또는 **Windows Portable 빌드**를 대신 사용하세요.
</Accordion>
