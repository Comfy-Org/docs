Comfy Desktop은 Comfy 계정에 연결할 수 있습니다. 로그인하면 Chooser에 워크스페이스 기능이 추가됩니다. 개인 워크스페이스와 소속된 팀 워크스페이스 사이를 전환하고, 선택된 워크스페이스에 속한 인스턴스를 확인하고, 해당 워크스페이스에 게시된 ComfyUI Build를 설치할 수 있습니다. 또한 로컬 인스턴스를 워크스페이스의 다른 멤버가 설치할 수 있는 Build로 전환할 수도 있습니다.

로그인은 선택 사항입니다. 로컬 인스턴스, 스냅샷, 설정은 계정 없이도 작동합니다.

## 로그인

계정 칩은 Chooser 오른쪽 상단에 있습니다.

- **로그아웃 상태**: 칩에 **로그인** 버튼이 표시됩니다. 클릭하면 브라우저 로그인 흐름이 열립니다. 그런 다음 앱으로 돌아오세요.
- **로그인 완료**: 칩에 아바타와 이메일이 표시됩니다. 클릭하면 **로그아웃**이 있는 메뉴가 열립니다.

로그아웃은 세션만 종료합니다. 인스턴스는 그대로 유지됩니다. 설치가 진행 중인 경우, Comfy Desktop은 계속 진행하기 이전에 로그아웃하면 설치가 취소된다고 경고합니다.

## 워크스페이스 전환

인스턴스 그리드 위에는 워크스페이스 바가 있습니다:

- **워크스페이스 전환기**: **개인** 공간과 소속된 모든 팀 워크스페이스입니다. 클릭하면 전환됩니다.
- **워크스페이스 새로 고침**: 로그인하면 표시됩니다. 선택된 워크스페이스의 워크스페이스 목록과 Builds 카탈로그를 다시 로드합니다.
- **INSTANCES**: 선택된 워크스페이스에 속한 인스턴스 수입니다.

선택된 워크스페이스는 Chooser의 범위를 결정합니다. 그리드에는 해당 워크스페이스에 속한 인스턴스만 표시되며, 새 인스턴스 생성 흐름에서는 해당 워크스페이스의 Builds를 제공합니다. Comfy Desktop은 선택한 워크스페이스를 기억하고, 다음에 앱을 열 때 해당 워크스페이스를 복원합니다.

## Build 설치

Build는 워크스페이스에 게시된 패키징된 ComfyUI 환경입니다. 새 인스턴스 마법사에는 해당 Build의 릴리스 버전, 제작자, 하드웨어 대상, 필요한 디스크 공간 예상치가 표시됩니다. Build를 설치하면 일반적인 ComfyUI 설치 대신 해당 환경을 그대로 로컬 인스턴스로 사용할 수 있습니다.

1. Chooser에서 **+** 카드를 클릭하여 새 인스턴스 마법사를 엽니다.
2. 방법 행에서 **Managed Builds**를 선택합니다. 아직 로그인하지 않았다면 Comfy Desktop에서 먼저 로그인하도록 요청합니다.
3. **Release**에서 설치할 Build를 선택합니다. 설치 준비가 완료되었고 사용 중인 컴퓨터와 호환되는 Build만 나열됩니다. **View builds online**으로 브라우저에서 Builds 페이지를 열거나, 새로 고침 버튼으로 목록을 다시 불러올 수 있습니다.
4. **Hardware**에서 사용 중인 컴퓨터의 릴리스 대상을 선택합니다. 예를 들어 Windows with NVIDIA (CUDA 12.8)입니다. 하드웨어에 권장되는 대상이 미리 선택되어 있습니다.
5. 마법사의 안내에 따라 인스턴스를 설치합니다.

로그인한 상태라면 마법사는 **Managed Builds**로 열리고, 선택한 워크스페이스에 호환되는 Build가 없으면 **Public Builds**로 대체됩니다. **Public Builds**는 감지된 하드웨어에 대한 표준 ComfyUI 설치입니다.

## Build 업데이트

Build 설치본은 작성자가 게시한 환경에 머뭅니다. ComfyUI 릴리스 채널을 따라가지 않으며, 앞으로 나아가는 것은 Build 버전입니다.

인스턴스의 [관리 패널](/ko/installation/desktop/usage/manage)을 열고 **업데이트** 탭으로 전환하세요. **Build Version** 카드에 이 인스턴스가 실행 중인 버전이 표시되고, 워크스페이스가 더 새로운 버전을 게시하면 **Update available** 배지가 붙으며, Comfy Desktop이 게시된 버전을 읽은 뒤 최신 버전을 쓰고 있으면 **Up to date**가 표시됩니다. 헤드라인 아래에는 다음 행이 나옵니다.

- **Installed**: 디스크에 있는 Build 버전(예: `v7`)
- **Latest Published**: 게시된 최신 버전
- **Last Checked**: Comfy Desktop이 게시된 버전을 마지막으로 읽은 시각

카드 아래 버튼:

- **Check for updates**: 이 Build의 게시된 버전을 Comfy Developer Platform에서 다시 읽습니다.
- **Update to v...**: 더 새로운 버전이 있을 때만 나타나며 이동할 버전을 이름에 담습니다(예: **Update to v8**). 확인 대화상자에는 두 버전이 모두 나오고, 업데이트가 관리 환경을 교체하며 워크플로우와 이미 스테이징된 모델은 유지된다는 설명이 함께 표시됩니다.

Comfy Desktop은 같은 폴더에서 새 버전을 그 자리에 설치합니다. 사용 중인 머신에 맞춰 빌드된 아티팩트를 내려받습니다. 하드웨어용 빌드가 없는 새 버전도 목록에 표시되며, 선택하면 해당 버전에 이 머신용 빌드가 없다는 메시지와 함께 중단되고 인스턴스는 그대로 유지됩니다. 업데이트는 실행 중에 취소할 수 있고, 새 환경이 준비될 때까지 인스턴스는 기존 환경을 유지합니다. 새 버전에 필요한 모델은 백그라운드에서 스테이징되며, 끝나지 않은 다운로드는 다음 실행에서 이어집니다.

버전 목록은 워크스페이스 카탈로그에서 가져옵니다. 앱이 아직 그 카탈로그를 읽지 않았다면 카드에는 설치된 버전과 **Check for updates**만 표시되고 최신 버전은 나오지 않습니다.

### Build의 관리 패널 탭

Build 설치본은 관리 패널의 여섯 탭 중 네 개를 **업데이트**, **시작 인자**, **터미널**, **정보** 순서로 표시합니다. **스냅샷**과 **저장소**는 의도적으로 없습니다.

- Build는 자체 모델 세트와 자체 환경을 함께 제공하므로 공유 모델 폴더도, 인스턴스별 입력·출력 경로도 설정할 것이 없습니다.
- Comfy Desktop은 Build 설치본에 스냅샷 탭을 표시하지 않으므로 살펴보거나 복원할 스냅샷 목록이 없습니다. 업데이트 탭은 더 새로운 게시 버전만 제시하므로 Build를 이전 버전으로 되돌릴 방법은 없습니다.

**시작 인자**에는 독립 실행형 설치와 같은 컨트롤이 있습니다. 실행 인수, ComfyUI-Manager 정책, 실행 모드, 브라우저 캐시, 포트 동작, 환경 변수입니다. Build는 고정된 모델 허용 목록과 함께 게시될 수 있으며, 그런 Build는 ComfyUI-Manager 없이 실행되므로 Manager 항목은 효과가 없습니다.

## 인스턴스에서 Build 생성

로컬 인스턴스를 Build로 게시하면 해당 워크스페이스의 다른 멤버가 설치할 수 있습니다.

1. Comfy 계정에 로그인합니다.
2. Chooser에서 인스턴스의 **⋮ 메뉴**를 열고 **Create Build**를 선택합니다.
3. Comfy Desktop은 해당 인스턴스로부터 Comfy Developer Platform에 초안 Build를 생성합니다. 초안은 인스턴스가 속한 워크스페이스에 속합니다.

**Create Build**는 설치되어 있고 디스크에 설치 경로가 있는 로컬 인스턴스에 대해 제공됩니다. 클라우드 또는 원격 인스턴스에는 제공되지 않습니다. Build는 초안으로 시작하므로 릴리스하기 전에 내용을 검토할 수 있습니다.

Desktop 스냅샷 또는 워크플로 JSON 파일에서 Build를 생성하는 방법을 포함한 전체 Build 워크플로는 [Comfy API Build를 생성하는 다른 방법](/ko/development/serverless/build-sources)을 참조하세요.
