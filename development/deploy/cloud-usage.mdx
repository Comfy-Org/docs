Workflows submitted through the Comfy Cloud API use the same credits and concurrency limits as other Cloud workflows.

## Credits and usage

API requests draw from the same monthly credit allocation as the Comfy Cloud web UI. There is no separate API credit pool. Each tier's included credits, top-up options, and per-workflow runtime caps apply to API jobs in the same way as UI jobs.

See the [pricing page](https://www.comfy.org/cloud/pricing?utm_source=docs&utm_campaign=cloud-api) for monthly credit amounts and top-up options. You can purchase top-ups from your account dashboard.

## Concurrency limits

You can submit multiple workflows without waiting for previous jobs to complete. Jobs run in parallel up to your subscription tier's limit:

| Plan     | Concurrent workflows |
| :------- | :------------------- |
| Standard | 1                    |
| Creator  | 3                    |
| Pro      | 5                    |

Team plans run more concurrent workflows per member than Pro. Check [platform.comfy.org](https://platform.comfy.org) for the concurrency on your account. Additional jobs queue and run as slots become available.

If the queue is full, the SDKs retry within a bounded budget before raising `QueueFull`.

On Team and Enterprise plans, concurrency is per member: everyone in the workspace has their own concurrency limit, so one member's running jobs never block another's.

<Info>
  Running more than one job at a time is only supported through the API. The Comfy Cloud UI runs one workflow at a time per person, and workflows queued in the editor run in order. See the [pricing plans](https://www.comfy.org/cloud/pricing?utm_source=docs&utm_campaign=cloud-api) for subscription details.
</Info>

## Runtime and queue limits

Every Cloud workflow has a maximum runtime. A job that runs past the limit is cancelled automatically:

| Plan     | Maximum runtime |
| :------- | :-------------- |
| Standard | 30 minutes      |
| Creator  | 30 minutes      |
| Pro      | 1 hour          |

You can have up to 100 workflows queued at once. To raise a Team concurrency limit, [contact support](https://support.comfy.org/).

## Deployment billing

A [deployment](/development/serverless/overview) of a custom Build bills GPU time for its workers and storage for its models, from Comfy Credits.

### Am I charged for storing Builds that are not deployed?

No. Builds and their versions are stored at no charge. Storage billing starts when you deploy:

- When you deploy a version, Comfy Cloud copies its models onto network storage that the deployment's workers share. Comfy Cloud bills the storage per GB per month for as long as a deployment of the Build exists in that region, including while the deployment is stopped. Models a job uses from your [workspace library](/development/deploy/cloud-custom-builds#add-your-own-lora-or-model) aren't copied there. The worker downloads them for the job. Models you [add to a deployment](/development/serverless/overview#add-a-model-to-a-running-deployment) are copied there, and count toward that storage.
- Local disk on each worker adds no charge beyond the GPU rate.
- Deleting a deployment releases its compute. Billing for the network storage ends when you delete the last deployment that uses it.

For storage and GPU rates, open [**Limits**](https://platform.comfy.org/settings/limits) on the Developer Platform and check **Deployment pricing**. The deploy dialog's **Estimated cost** panel also shows the GPU time and model storage for a deployment.

### How are always-warm workers billed?

[Always-warm workers](/development/serverless/overview#scale-the-workers) (`--min` in comfy-cli) bill GPU time for as long as they run, whether or not they process jobs.

Workers above that number, up to **Max workers** (`--max`), start when jobs arrive. They bill GPU time from the moment they start, through their jobs, and for the idle time after their last job before they're released. By default, a worker stays up for 3 minutes after its last job. You can set that time, from 30 seconds to 20 minutes, in **Keep worker up after a job** when you create the deployment on the Developer Platform. With `0` always-warm workers, GPU billing stops once that idle time ends and every worker is released. The next job waits while a GPU starts.

If your workspace runs out of credits, its deployments stop.

For GPU rates, open [**Limits**](https://platform.comfy.org/settings/limits) on the Developer Platform and check **Deployment pricing**. Rates are per worker, for each hour it runs.
