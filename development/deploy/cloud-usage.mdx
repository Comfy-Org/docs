Workflows submitted through the Comfy Cloud API use the same credits and concurrency limits as other Cloud workflows.

## Credits and usage

API requests draw from the same monthly credit allocation as the Comfy Cloud web UI. There is no separate API credit pool. Each tier's included credits, top-up options, and per-workflow runtime caps apply to API jobs in the same way as UI jobs.

See the [pricing page](https://www.comfy.org/cloud/pricing?utm_source=docs&utm_campaign=cloud-api) for monthly credit amounts and top-up options. You can purchase top-ups from your account dashboard.

## Concurrent jobs

You can submit multiple workflows without waiting for previous jobs to complete. Jobs run in parallel up to your subscription tier's limit. Check [platform.comfy.org](https://platform.comfy.org) for your current concurrency limit. Additional jobs queue and run as slots become available.

If the queue is full, the SDKs retry within a bounded budget before raising `QueueFull`.

On Team and Enterprise plans, concurrency is per member: everyone in the workspace has their own concurrency limit, so one member's running jobs never block another's.

<Info>
  Running more than one job at a time is only supported through the API. The Comfy Cloud UI runs one workflow at a time per person, and workflows queued in the editor run in order. See the [pricing plans](https://www.comfy.org/cloud/pricing?utm_source=docs&utm_campaign=cloud-api) for subscription details.
</Info>

## Existing v1 integrations

The deprecated [v1 Cloud API](/development/cloud/overview) also runs against Comfy Cloud. Use it for existing integrations or Cloud capabilities not yet available in [Comfy API v2](/api-reference/v2/overview). Runnable examples are in the deprecated [Cloud API Reference](/development/cloud/api-reference).
