Comfy API separates the environment you define from the endpoint that runs it. A **Build** describes the ComfyUI environment. A **release** packages that Build for a supported target. A **deployment** runs a release as a managed endpoint.

## Choose a path

| Choose | When to use it | What you manage |
| --- | --- | --- |
| [Comfy Cloud](/development/deploy/cloud) | You want a managed ComfyUI in the browser or want to run workflows without setting up an endpoint. | Your workflows and API calls. There is no Build or deployment to create. |
| [Comfy API](/development/serverless/quickstart) | You need a managed endpoint with a specific ComfyUI environment, models, custom nodes, and dependencies. | A Build, its releases, and one or more deployments. |
| [Self-hosting](/development/deploy/self-hosting) | You want to choose and manage the machine, software, models, and custom nodes. | Your own ComfyUI installation and infrastructure. |

If a workflow needs custom nodes or dependencies that are not available in Comfy Cloud, use Comfy API or self-host ComfyUI. Comfy API creates a managed endpoint from a packaged environment. It is not an interactive sandbox for trying changes.

## How the Comfy API pieces fit together

```text
Workspace → local project → Build → release → deployment → workflow requests
```

1. **Workspace**: The account context where your team manages access, Builds, deployments, and usage limits.
2. **Local project folder**: The folder on your machine where you keep `comfy-build.yaml` and related workflow or asset files. The file describes the Build and tracks its last known remote state. It does not contain model files. This is a local folder, not an online resource.
3. **Build**: The definition of a ComfyUI environment, including its ComfyUI version, models, custom nodes, and settings. Push it to make it available on the Developer Platform.
4. **Release**: A built version of a Build for a supported target, such as `linux/nvidia`. Create a new release when you change the Build or need another target.
5. **Deployment**: A running endpoint created from a release. It has compute settings such as GPU, region, and worker bounds. You can run multiple deployments from the same Build, for example to use different GPU types.

Send API-format workflow requests to the deployment endpoint using the [Comfy SDKs](/development/api-development/sdks) or the CLI. The deployment runs those requests using the environment packaged in its release.

## What changes when you update something?

- **Change the environment**: Update the Build definition, push it, and create a new release. Update the deployment to use that release when you are ready.
- **Change capacity**: Scale or stop a deployment. This changes its compute settings, not the Build or release.
- **Run a different workflow**: Send another API-format workflow to the endpoint. You do not need a new release if the workflow's required models and nodes are already in the Build.

An **instance** is a ComfyUI environment, such as one managed by Comfy Desktop. For Comfy API, the user-facing object you create and operate is the deployment. You do not need to manage its underlying runtime instances.
