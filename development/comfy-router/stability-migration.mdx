Stability API integrations can move to Comfy in one of two ways. Both run the same Stability models and bill the same Comfy credits. They differ in how much of your code changes.

## Choose your path

| | Compatibility service | Native Comfy Router |
| --- | --- | --- |
| Base URL | `https://stability.comfy.org` | `https://api.comfy.org` |
| Paths | Stability's own (`/v1/generation/...`, `/v2beta/...`) | `POST /v2/models/stability/<slug>` |
| Request body | Stability's multipart form or JSON, unchanged | JSON, with images as Comfy-signed asset URLs |
| Response | Stability's shapes: raw image bytes, Stability JSON with base64, or a GLB body for 3D | JSON with a Comfy-signed URL: `image` for image models, `model` (a GLB) for 3D models |
| Errors | Stability's error envelope | [Router errors](/development/comfy-router/errors) |
| Code changes | Base URL and API key only | Request and response handling |
| Best for | Existing Stability integrations and the ComfyUI Stability nodes | New integrations |

**Use the compatibility service** if you have working Stability API code and want it running on Comfy with no other changes.

**Use native Comfy Router** for new integrations. It is the same API as every other model on Router, with the Comfy SDKs, [queued delivery](/development/comfy-router/queue), idempotent retries and one error format.

Both paths need a Comfy API key. Create one in [your Comfy workspace](https://platform.comfy.org/profile/api-keys?onboarding=router) and export it:

```bash
export COMFY_API_KEY="comfyui-..."
```

Keep API keys on your server or in your local environment, not in browser JavaScript.

## Compatibility service

The compatibility service at `https://stability.comfy.org` accepts Stability's own paths and request bodies, runs each call on Comfy Router, and answers in Stability's response and error shapes. To migrate, change two things:

1. The base URL, from `https://api.stability.ai` to `https://stability.comfy.org`.
2. The key in the `Authorization: Bearer` header, from your Stability key to your Comfy API key.

Everything else stays the same: paths, form fields, the `Accept` header, and how you read the response.

### Before and after

<CodeGroup>
```bash cURL (before)
curl -f -sS https://api.stability.ai/v2beta/stable-image/generate/core \
  -H "Authorization: Bearer $STABILITY_API_KEY" \
  -H "Accept: image/*" \
  -F prompt="a lighthouse on a cliff at sunset, oil painting" \
  -F output_format=png \
  -o lighthouse.png
```

```bash cURL (after)
curl -f -sS https://stability.comfy.org/v2beta/stable-image/generate/core \
```

</CodeGroup>

Image inputs are sent the way Stability expects them, as multipart file parts. The compatibility service uploads each one to Comfy storage before the call runs.

### Authentication

Send your Comfy API key as `Authorization: Bearer <key>`, the same header Stability uses. A request with no Bearer token, or with a key Comfy rejects, answers `401` with `name` set to `unauthorized`.

`GET /v1/engines/list`, `GET /v1/user/account` and `GET /v1/user/balance` answer so that Stability SDKs that call them at startup keep working. They return fixed Stability-shaped JSON: the balance is always `0` and is not your Comfy credit balance. Generation is not gated on it. When your credits run out, a generation answers `402`. Check your balance and usage in [your Comfy workspace](https://platform.comfy.org).

### Response shapes

Responses follow Stability's rules for each API version:

- **`/v2beta/...`** returns the raw image bytes when `Accept` is `image/*` or is not set, and `{"image": "<base64>", "finish_reason": "...", "seed": N}` when `Accept` is `application/json`.
- **`/v1/generation/...`** returns `{"artifacts": [{"base64": "...", "seed": N, "finishReason": "..."}]}` by default, with one artifact per image, and raw bytes when `Accept` is `image/png`.
- **`/v2beta/3d/...`** returns the 3D model as a binary glTF (`.glb`) body.

An `Accept` value the path cannot answer is refused with `406`.

### Asynchronous endpoints

Two paths run asynchronously, as they do on Stability: `/v2beta/stable-image/edit/replace-background-and-relight` and `/v2beta/stable-image/upscale/creative`. The submit call answers `200` with a generation `id`. Poll `GET /v2beta/results/{id}` with the same key until it returns the result:

| Status | Meaning |
| --- | --- |
| `202` | Still running. Poll again later. |
| `200` | Done. The body is the image, in the shape your `Accept` header asked for. |
| `404` | The id is unknown or has expired. |
| Any other error | The generation failed. The body is a Stability error. |

```bash
# 1. Submit. The response is {"id": "...", "status": "in-progress"}.
curl -f -sS https://stability.comfy.org/v2beta/stable-image/upscale/creative \
  -H "Authorization: Bearer $COMFY_API_KEY" \
  -F image=@source.png \
  -F prompt="a detailed photo of a cat" \
  -F output_format=png

# 2. Poll until the status is 200, then save the image.
GENERATION_ID="<id from step 1>"
curl -sS https://stability.comfy.org/v2beta/results/$GENERATION_ID \
  -H "Authorization: Bearer $COMFY_API_KEY" \
  -H "Accept: image/*" \
  -o upscaled.png -w "%{http_code}\n"
```

### Errors

Errors use Stability's envelope. A `/v1/...` path answers `{"id": "...", "name": "...", "message": "..."}`. A `/v2beta/...` path answers `{"id": "...", "name": "...", "errors": ["..."]}`. The message carries Router's error detail. A validation failure lists one entry per invalid field, as `field: message`.

Router errors map onto Stability statuses and names like this:

| Router error type | Stability status | `name` |
| --- | --- | --- |
| `invalid_input` | `400` | `bad_request` |
| Request validation failure | `422` | `invalid_request` |
| `unauthorized` | `401` | `unauthorized` |
| `insufficient_credits` | `402` | `payment_required` |
| `forbidden`, or `not_enabled` answered as `403` | `403` | `forbidden` |
| `content_policy_violation` | `403` | `content_moderation` |
| `model_not_found` | `404` | `not_found` |
| `rate_limited`, `concurrency_limit_exceeded` | `429` | `rate_limit_exceeded` |
| `service_unavailable`, `provider_timeout`, `deadline_exceeded`, `queue_timeout`, or `not_enabled` answered with another status | `503` | `service_unavailable` |
| Request body too large | `413` | `payload_too_large` |
| Anything else, including `provider_error` | `500` | `internal_error` |

A `429` or `503` carries Router's `Retry-After` header when Router sent one. Wait that long before you retry.

## Native Comfy Router

Native Router calls send a JSON body to `POST https://api.comfy.org/v2/models/stability/<slug>` with your key in `X-API-Key`. The body uses Stability's field names. Image inputs are Comfy-signed asset URLs rather than file uploads, and the response is JSON with a Comfy-signed URL valid for up to 24 hours. Image models return it in `image`. The two 3D models (`stability/stable-fast-3d` and `stability/stable-point-aware-3d`) return the GLB URL in `model` instead. Download the result before the URL expires.

Each [model page](#endpoint-mapping) carries the full request schema, Python and TypeScript SDK snippets, and the queued variant for that model.

### Synchronous example

`stability/generate-core`:

```bash
curl https://api.comfy.org/v2/models/stability/generate-core \
  -H "X-API-Key: $COMFY_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{"aspect_ratio": "16:9", "prompt": "a lighthouse on a cliff at sunset, oil painting", "seed": 12345}'
```

```json Response
{
  "finish_reason": "SUCCESS",
  "image": "https://example.invalid/stability/image.png",
  "seed": 12345
}
```

### Asynchronous example

`stability/upscale-creative` runs asynchronously at Stability. On the synchronous route, Router submits the job and polls it for you, then answers with the finished result in the same shape as above. It is billed once, when the job succeeds. For a long run, or to collect the result from another process, queue it instead:

```bash
BASE="https://api.comfy.org/v2/models/stability/upscale-creative"

# 1. Submit. Router answers 201 with a request_id.
curl "$BASE/requests" \
  -H "X-API-Key: $COMFY_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{"creativity": 0.3, "image": "https://storage.googleapis.com/example-bucket/source.png", "prompt": "a detailed photo of a cat", "seed": 12345}'

# 2. Poll until status is COMPLETED, waiting the Retry-After seconds each response names.
REQUEST_ID="<request_id from the 201 body>"
curl -i "$BASE/requests/$REQUEST_ID/status" -H "X-API-Key: $COMFY_API_KEY"

# 3. Collect. 200 with the result, 202 while it is still running.
curl "$BASE/requests/$REQUEST_ID" -H "X-API-Key: $COMFY_API_KEY"
```

The collected result has the same shape as the synchronous response. The `image` value in these examples is a placeholder; a real call must pass a Comfy-signed asset URL.
