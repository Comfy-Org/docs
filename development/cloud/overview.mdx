# Comfy Cloud API

The Comfy Cloud API provides programmatic access to run workflows on Comfy Cloud infrastructure. The API is compatible with local ComfyUI's API, making it easy to migrate existing integrations.

The Python and TypeScript examples on this page use the official [Comfy SDKs](/development/api-development/sdks), which wrap the API's [v2 endpoints](/api-reference/v2/overview). The curl examples show the underlying HTTP calls, which you can make from any language. See the [Cloud API Reference](/development/cloud/api-reference) for the full HTTP surface.

<Note>
  **Subscription required:** API access is available on the **Standard**, **Creator** and **Pro** tiers. The Free tier does not include API access. See [pricing plans](https://www.comfy.org/cloud/pricing?utm_source=docs&utm_campaign=cloud-api) for details.
</Note>

## Credits and Usage

API requests draw from the same monthly credit allocation as the Comfy Cloud web UI. There is no separate API credit pool. Each tier's included credits, top-up options, and per-workflow runtime caps apply to API jobs in exactly the same way as UI jobs. See the [pricing page](https://www.comfy.org/cloud/pricing?utm_source=docs&utm_campaign=cloud-api) for the monthly credit amounts on the Standard, Creator and Pro tiers. If you run out of credits mid-month, top-ups can be purchased from your account dashboard.

## Base URL

```
https://cloud.comfy.org
```

This is the SDK's default target, so you do not need to configure it for Comfy Cloud. To point the same code at a serverless deployment or your own ComfyUI, set `COMFY_BASE_URL`. See [Choosing a base URL](/development/api-development/sdks#choosing-a-base-url).

## Authentication

All API requests require an API key. Over raw HTTP you pass it in the `X-API-Key` header. With the SDKs you hand it to the client once and the client authenticates every request for you.

### Getting an API Key

See [Getting an API Key](/development/api-development/getting-an-api-key) for instructions on creating and managing your Cloud API key.

### Using the API Key

<CodeGroup>
```bash curl
curl -X GET "https://cloud.comfy.org/api/user" \
  -H "X-API-Key: $COMFY_CLOUD_API_KEY"
```

```python Python
import os
from comfy_sdk import Comfy

client = Comfy(api_key=os.environ["COMFY_CLOUD_API_KEY"])
```

```typescript TypeScript
import { Comfy } from "@comfyorg/sdk";

const client = new Comfy({ apiKey: process.env.COMFY_CLOUD_API_KEY! });
```
</CodeGroup>

An invalid or missing key raises `Unauthorized`. A key that is valid but not entitled raises `Forbidden`.

## Core Concepts

### Workflows

ComfyUI workflows are JSON objects describing a graph of nodes. The API accepts workflows in the [API format](/development/api-development/workflow-api-format) (node IDs as keys with class_type, inputs, etc.) as produced by the ComfyUI frontend's "Export Workflow (API)" option.

### Jobs

When you submit a workflow, a **job** is created. Jobs are executed asynchronously:
1. Submit a workflow with `client.submit(wf)`, or `POST /api/prompt` over HTTP
2. Receive a job ID
3. Monitor progress by polling or by following the live event stream
4. Retrieve outputs when complete

### Assets

Input files are uploaded as **assets** and referenced by workflow inputs. Asset handles are lazy and content addressed: the file is hashed locally and only uploaded if the server does not already have those bytes, so re-running with the same input costs nothing.

### Parallel Execution (Concurrent Jobs)

API users can submit multiple workflows concurrently without waiting for previous jobs to complete. `submit()` returns as soon as the job is accepted, so you can keep several in flight. The dispatcher will run them in parallel up to your subscription tier's limit.

| Subscription Tier | Concurrent Jobs |
|-------------------|-----------------|
| Standard          | 1               |
| Creator           | 3               |
| Pro               | 5               |

Jobs submitted beyond your concurrency limit will queue normally and execute automatically as slots free up. If the queue itself is full, the SDKs retry for you within a bounded budget before raising `QueueFull`.

<Info>
  Parallel execution is currently available via the API only. See [pricing plans](https://www.comfy.org/cloud/pricing?utm_source=docs&utm_campaign=cloud-api) for subscription details.
</Info>

#### Example: Submitting Multiple Jobs in Parallel

<CodeGroup>
```python Python
import os
from comfy_sdk import Comfy

client = Comfy(api_key=os.environ["COMFY_CLOUD_API_KEY"])

# Create variations by changing the seed
jobs = []
for seed in [42, 123, 456]:
    wf = client.workflows.from_file("workflow_api.json")
    wf.set_input("3", "seed", seed)
    jobs.append(client.submit(wf))

for job in jobs:
    print(f"Job submitted: {job.id}")

# The jobs run in parallel. Wait for all of them.
for job in jobs:
    job.wait()
```

```typescript TypeScript
import { Comfy } from "@comfyorg/sdk";

const client = new Comfy({ apiKey: process.env.COMFY_CLOUD_API_KEY! });

// Create variations by changing the seed
const jobs = await Promise.all(
  [42, 123, 456].map(async (seed) => {
    const wf = await client.workflows.fromFile("workflow_api.json");
    wf.setInput("3", "seed", seed);
    return client.submit(wf);
  })
);

for (const job of jobs) {
  console.log(`Job submitted: ${job.id}`);
}

// The jobs run in parallel. Wait for all of them.
await Promise.all(jobs.map((job) => job.wait()));
```
</CodeGroup>

`"3"` is the node ID of the sampler in `workflow_api.json`. Use `AsyncComfy` in Python if you want the waits to be concurrent rather than sequential.

### Outputs

Generated content (images, videos, audio) is stored in cloud storage. The SDKs download outputs for you. Over raw HTTP, output files are fetched from the `/api/view` endpoint, which returns a 302 redirect to a temporary signed URL.

## Quick Start

Here's a complete example showing how to submit a workflow, monitor its progress, and retrieve outputs.

### Step 1: Submit a Workflow

<CodeGroup>
```bash curl
curl -X POST "https://cloud.comfy.org/api/prompt" \
  -H "X-API-Key: $COMFY_CLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt": '"$(cat workflow_api.json)"'}'
```

```python Python
import os
from comfy_sdk import Comfy

client = Comfy(api_key=os.environ["COMFY_CLOUD_API_KEY"])

# Load your workflow (exported from ComfyUI in API format)
wf = client.workflows.from_file("workflow_api.json")

# Optional: attach an input file to the node that consumes it
asset = client.assets.from_file("photo.png")
wf.set_input("10", "image", asset)

# Submit the workflow
job = client.submit(wf)
print(f"Job submitted: {job.id}")
```

```typescript TypeScript
import { Comfy } from "@comfyorg/sdk";

const client = new Comfy({ apiKey: process.env.COMFY_CLOUD_API_KEY! });

// Load your workflow (exported from ComfyUI in API format)
const wf = await client.workflows.fromFile("workflow_api.json");

// Optional: attach an input file to the node that consumes it
const asset = client.assets.fromFile("photo.png");
wf.setInput("10", "image", asset);

// Submit the workflow
const job = await client.submit(wf);
console.log(`Job submitted: ${job.id}`);
```
</CodeGroup>

`"10"` is a node ID from `workflow_api.json`, the node your input image feeds into. Submission is idempotent, so a retried submit does not run the workflow twice.

<Note>
  To submit and wait in one call, use `client.run(wf)` instead of `submit()`. Use `submit()` when you want to do other work while the job executes.
</Note>

### Step 2: Monitor Job Progress

You can wait for the job by polling, or follow the live event stream for real-time updates.

#### Option A: Polling (Simple)

`wait()` polls until the job reaches a terminal state. Polling is authoritative: it is the source of truth for job state, and it survives a dropped connection.

<CodeGroup>
```bash curl
# Poll for job completion
curl -X GET "$BASE_URL/api/job/{prompt_id}/status" \
  -H "X-API-Key: $COMFY_CLOUD_API_KEY"

# Response examples:
# {"status": "queued_waiting"}       - Job is queued
# {"status": "executing"}            - Job is currently running
# {"status": "success"}              - Job finished successfully
# {"status": "error"}                - Job encountered an error
# {"status": "non_retryable_error"}  - Job failed, retrying will not help
# {"status": "lost"}                 - Job disappeared before finishing
# {"status": "cancelled"}            - Job was cancelled
```

```python Python
from comfy_sdk import JobFailed

job.wait()  # polls until the job reaches a terminal state

try:
    job.result()  # the finished job, or JobFailed with the node-level detail
    print("Job completed!")
except JobFailed as e:
    print(f"Job failed: {e.error}")

# A job from another process, rehydrated by id
job = client.jobs.get("<job-id>")
```

```typescript TypeScript
await job.wait(); // polls until the job reaches a terminal state

if (job.status !== "succeeded") {
  throw new Error(`Job ${job.status}`);
}
console.log("Job completed!");

// A job from another process, rehydrated by id
const existing = await client.jobs.get("<job-id>");
```
</CodeGroup>

**Job status values (HTTP):** `success`, `error`, `non_retryable_error`, `lost`, and `cancelled` are the five terminal states. Everything else means the job is still in flight, including `submitted`, `queued_waiting`, `preparing`, `executing`, and transitional states such as `cancel_requested`. Poll until you see a terminal value rather than matching on the in-flight names. The SDKs handle this for you and surface a failure as `JobFailed`.

#### Option B: Live Progress Events

`job.events()` gives you a live stream of the job's state: node and step progress, preview frames, and each output the moment it is committed. It reconnects on its own if the connection drops.

<CodeGroup>
```python Python
from comfy_sdk import Progress, Preview, OutputReady, StatusChange

for event in job.events():
    match event:
        case Progress() as p:
            print(f"{p.value:.0%} {p.message}")
        case Preview() as pv:
            image = pv.to_pil()
        case OutputReady() as o:
            o.output.to_file(f"partial/{o.output.name}")
        case StatusChange(status="succeeded"):
            break
```

```typescript TypeScript
// The label is required: a bare `break` inside a switch leaves the switch,
// not the loop.
eventLoop: for await (const event of job.events()) {
  switch (event.kind) {
    case "progress":
      console.log(event.value);
      break;
    case "outputReady":
      await event.output.toFile(event.output.name);
      break;
    case "statusChange":
      if (event.status === "succeeded") break eventLoop;
  }
}
```
</CodeGroup>

`Preview.to_pil()` requires the optional Pillow extra: `pip install "comfy-sdk[pil]"`.

The stream is a live feed, not a replayable log. It exists so you can render progress, not so you can rely on it for results. `run()` and `wait()` fall back to polling automatically. See [Design Notes](/development/api-development/sdks-design#poll-first-stream-for-progress) for why.

<Note>
  The raw WebSocket protocol, including message types and binary preview frames, is documented in the [WebSocket Reference](/development/cloud/api-reference#websocket-for-real-time-progress).
</Note>

### Step 3: Download Outputs

Once the job completes, write the generated files to disk. `get_outputs()` filters by node ID, and `job.outputs` gives you everything the job produced.

<CodeGroup>
```bash curl
# Step 1: read the 302 target. Do not use -L here: following the redirect
# would resend your API key to the storage host.
SIGNED_URL=$(curl -s -o /dev/null -w '%{redirect_url}' \
  "$BASE_URL/api/view?filename=output.png&subfolder=&type=output" \
  -H "X-API-Key: $COMFY_CLOUD_API_KEY")

# Step 2: the signed URL carries its own authorization, so send no headers.
curl -s "$SIGNED_URL" -o output.png
```

```python Python
# Outputs of a single node
for output in job.get_outputs("9"):
    output.to_file(output.name)

# Every output the job produced
for output in job.outputs:
    output.to_file(f"./my_outputs/{output.name}")

# Or keep the bytes in memory, or hand a URL to something else
data = job.outputs[0].to_bytes()
link = job.outputs[0].get_download_url()  # url and expires_at
```

```typescript TypeScript
// Outputs of a single node
for (const output of job.getOutputs("9")) {
  await output.toFile(output.name);
}

// Every output the job produced
for (const output of job.outputs) {
  await output.toFile(`./my_outputs/${output.name}`);
}

// Or keep the bytes in memory, or hand a URL to something else
const data = await job.outputs[0].toBytes();
const { url, expiresAt } = await job.outputs[0].getDownloadUrl();
```
</CodeGroup>

The node ID (`"9"` in this example) corresponds to the SaveImage or other output node in your workflow. You can find these IDs by opening your workflow JSON file and looking for nodes with `class_type` like `SaveImage`, `VHS_VideoCombine`, etc.

Every output also carries the ID of the job that produced it (`output.job_id`, TypeScript `output.jobId`), so a file you found later still leads back to its job and, through `job.get_workflow()`, to the graph behind it.

<Info>
  Calling `/api/view` directly returns a 302 redirect to a temporary signed URL. Do not follow that redirect with your API key attached: the signed URL points at storage, carries its own authorization, and needs no header from you. Read the `Location` header and fetch it as a separate unauthenticated request, as the curl sample above does. The SDKs handle this for you.
</Info>

### Complete Example

Here's a full end-to-end example combining all three steps:

<CodeGroup>
```python Python
import os
from comfy_sdk import Comfy, JobFailed

client = Comfy(api_key=os.environ["COMFY_CLOUD_API_KEY"])

def main():
    # 1. Load and modify the workflow
    wf = client.workflows.from_file("workflow_api.json")
    wf.set_input("3", "seed", 42)
    wf.set_input("6", "text", "a beautiful sunset")

    # 2. Attach an input file (uploaded only if the server lacks those bytes)
    asset = client.assets.from_file("photo.png")
    wf.set_input("10", "image", asset)

    # 3. Submit and wait for completion
    try:
        job = client.run(wf)
    except JobFailed as e:
        raise SystemExit(f"Job failed: {e.error}")

    print(f"Job {job.id} finished")

    # 4. Download the outputs
    for output in job.outputs:
        output.to_file(output.name)
        print(f"Downloaded: {output.name}")

if __name__ == "__main__":
    main()
```

```typescript TypeScript
import { Comfy, JobFailed } from "@comfyorg/sdk";

const client = new Comfy({ apiKey: process.env.COMFY_CLOUD_API_KEY! });

async function main() {
  // 1. Load and modify the workflow
  const wf = await client.workflows.fromFile("workflow_api.json");
  wf.setInput("3", "seed", 42);
  wf.setInput("6", "text", "a beautiful sunset");

  // 2. Attach an input file (uploaded only if the server lacks those bytes)
  const asset = client.assets.fromFile("photo.png");
  wf.setInput("10", "image", asset);

  // 3. Submit and wait for completion
  let job;
  try {
    job = await client.run(wf);
  } catch (e) {
    if (e instanceof JobFailed) throw new Error(`Job failed: ${e.message}`);
    throw e;
  }

  console.log(`Job ${job.id} finished`);

  // 4. Download the outputs
  for (const output of job.outputs) {
    await output.toFile(output.name);
    console.log(`Downloaded: ${output.name}`);
  }
}

main();
```
</CodeGroup>
