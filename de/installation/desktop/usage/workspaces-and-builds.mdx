Comfy Desktop kann eine ComfyUI-Einrichtung installieren, die Ihr Team auf der Comfy Developer Platform teilt, zum Beispiel einen freigegebenen Build mit ausgewählten Modellen und Custom Nodes. Auf der Developer Platform ist diese Einrichtung ein Developer Platform Build, den Ihr Workspace in nummerierten Versionen veröffentlicht, und Comfy Desktop installiert eine Version davon auf Ihrem Computer als Team-Build. Sie wählen den Workspace, installieren dessen Build, aktualisieren ihn, wenn Ihr Team eine neuere Version veröffentlicht, und laden Ihre eigenen Builds auf die Developer Platform hoch.

Informationen zum Erstellen eines Builds auf der Developer Platform und zum Veröffentlichen seiner Versionen finden Sie unter [Benutzerdefinierte Builds zu Comfy Cloud hinzufügen](/development/deploy/cloud-custom-builds).

## Workspace für die angezeigten Builds wählen

Jeder Workspace hat eigene Developer Platform Builds, und Comfy Desktop zeigt immer nur einen Workspace gleichzeitig an. Um die Builds Ihres Teams zu sehen, melden Sie sich zuerst an. Folgen Sie [Anmelden und Comfy Cloud öffnen](/de/installation/desktop/overview#anmelden-und-comfy-cloud-öffnen).

Der unten in der **Seitenleiste** ausgewählte Workspace entscheidet darüber, was Sie sehen:

- **Home**, die **Seitenleiste**, die Seite **Builds** und Build-Seiten listen nur die Builds in diesem Workspace auf.
- **New build** bietet die Developer Platform Builds dieses Workspace unter **Your team's builds** an. Ihr **Persönlich**-Workspace hat eigene.

Wie Sie Workspaces wechseln, lesen Sie unter [Workspace-Menü verwenden](/de/installation/desktop/usage/overview#workspace-menü-verwenden). Comfy Desktop merkt sich den von Ihnen ausgewählten Workspace und öffnet beim nächsten Mal diesen.

<Tip>
  Wenn Ihr Team einen Build veröffentlicht, während Comfy Desktop geöffnet ist, klicken Sie auf der Seite **Builds** auf **Refresh workspaces**. Dadurch werden Ihre Workspaces und deren Developer Platform Builds neu geladen.
</Tip>

## Ein Build von Ihrem Team installieren

Ein Developer Platform Build erscheint in Comfy Desktop, sobald eine veröffentlichte Version mit einem Build für das Betriebssystem und die GPU Ihres Computers vorliegt. Durch die Installation wird ein Team-Build auf diesem Computer hinzugefügt. Informationen zu den Teilen des Dialogs **New build**, die alle Builds gemeinsam haben, wie **Name** und **Location**, finden Sie unter [Neuen Build installieren](/de/installation/desktop/usage/instance-management#install-a-new-build).

<Steps>
  <Step title="Dialog New build öffnen">
    Klicken Sie auf der Seite **Builds** auf **New build**.

    Wenn Sie angemeldet sind, zeigt der Dialog die Builds Ihres Workspace an, wobei der erste Build ausgewählt ist. Wenn der Workspace keinen Build zum Installieren enthält, zeigt er stattdessen **Official release** an.
  </Step>
  <Step title="Build und Hardware prüfen">
    Die Zusammenfassung zeigt, was installiert wird:

    - **Release**: der Name des Builds mit seiner Beschreibung, **Release v{version}** und **By {creator}**.
    - **Hardware**: das Build-Ziel für Betriebssystem und GPU dieses Computers, z. B. NVIDIA mit CUDA 12.8, mit seiner Release-Version.

    Das Feld **Name** schlägt den Namen des Builds vor.
  </Step>
  <Step title="Anderen Build auswählen (optional)">
    Klicken Sie auf **Change**, um **Change setup** zu öffnen.

    - **Source**: Wählen Sie **Your team's builds** aus. Wenn Sie nicht angemeldet sind, öffnet sich Ihr Browser, damit Sie sich anmelden können, und der Dialog zeigt **Continue in your browser**.
    - **Release**: Wählen Sie einen Build aus. Die Liste zeigt nur Builds, die auf diesem Computer installiert werden können. Klicken Sie auf **View builds online**, um die Builds Ihres Workspace auf der Developer Platform in Ihrem Browser zu öffnen, oder klicken Sie auf **Refresh builds**, um die Liste neu zu laden.
    - **Hardware**: Wählen Sie ein Build-Ziel aus. Das für diesen Computer empfohlene Ziel ist bereits für Sie ausgewählt.

    Während Comfy Desktop zum Workspace wechselt, zeigt der Dialog **Waiting for workspace authorization… Complete authorization in your browser if prompted.**

    Klicken Sie auf **Save changes**, um zur Zusammenfassung zurückzukehren.
  </Step>
  <Step title="Build installieren">
    Klicken Sie auf **Install**. Um die Installation zu verfolgen, lesen Sie [Neuen Build installieren](/de/installation/desktop/usage/instance-management#install-a-new-build).
  </Step>
</Steps>

Wenn die Installation abgeschlossen ist, zeigt die Kachel des Builds auf der Seite **Builds** **Build v{version}** an, die von Ihnen installierte Version. Wenn der Build nicht in der Liste steht, lesen Sie [Fehlerbehebung](#fehlerbehebung).

## Team-Build aktualisieren

Ein Team-Build lässt sich nur auf andere Versionen seines Developer Platform Build aktualisieren. Wenn Ihr Team eine neuere Version veröffentlicht, aktualisieren Sie den Build, um sie zu erhalten. Seine Build-Seite zeigt im Tab **Übersicht** einen Abschnitt **Build-Version**.

1. Klicken Sie in der **Seitenleiste** auf den Team-Build, um seine Build-Seite zu öffnen. Wenn ein Update verfügbar ist, zeigt der Tab **Übersicht** einen Punkt an, und die Kachel des Builds zeigt **Update verfügbar**.
2. Prüfen Sie auf **Übersicht** den Abschnitt **Build-Version**: **Installiert**, **Neueste veröffentlichte Version** und **Zuletzt geprüft**, mit **Update verfügbar** oder **Auf dem neuesten Stand**. Um erneut zu prüfen, klicken Sie auf **Nach Updates suchen**.
3. Klicken Sie auf **Auf v{version} aktualisieren**. Sie können auch **Aktualisieren** im [Schnellaktionsmenü](/de/installation/desktop/usage/instance-management#quick-actions-from-the-build-list) auswählen.
4. Prüfen Sie im Dialog **Build aktualisieren** die Versionen, zwischen denen aktualisiert wird, und klicken Sie dann auf **Jetzt aktualisieren**.

Das Update ersetzt die Umgebung des Builds durch die neue Version und behält Ihre Workflows sowie die bereits bereitgestellten Modelle bei. Während der Aktualisierung zeigt der Fortschritt **Wird auf v{version} aktualisiert** an. Nach Abschluss zeigt **Installiert** die neue Version an.

## Ein Build in die Developer Platform hochladen

**Upload build** startet einen Developer Platform Build aus einem Build auf diesem Computer, damit Ihr Workspace ihn veröffentlichen und Ihr Team ihn installieren kann. Sie müssen angemeldet sein, und der Build muss auf diesem Computer installiert sein. Comfy Cloud und Remote-Builds können nicht hochgeladen werden.

1. Klicken Sie mit der rechten Maustaste auf den Build in der **Seitenleiste** oder mit der rechten Maustaste auf seine Kachel auf der Seite **Builds** bzw. auf seine Karte auf **Home**.
2. Wählen Sie **Upload build** aus. Der Hinweis dazu lautet **Upload this build to Comfy Developer Platform.**

Während der Vorgang läuft, zeigt das Element **Creating…** an. Comfy Desktop führt dann Folgendes aus:

1. Speichert einen manuellen Snapshot des Builds. Er erscheint auf der Registerkarte **Snapshots** des Builds. Siehe [Snapshots speichern und wiederherstellen](/de/installation/desktop/usage/instance-management#save-and-restore-snapshots).
2. Sendet den Snapshot als Entwurf an die Developer Platform, und zwar in dem Workspace, zu dem der Build gehört. Ein Build in Ihrem **Personal**-Workspace wird in Ihrem **Personal**-Workspace abgelegt.
3. Öffnet den Entwurf in Ihrem Browser, wo die Build-Seite **Draft** und **Desktop snapshot received** anzeigt.

Der Entwurf erscheint erst unter **Your team's builds**, wenn eine Version davon veröffentlicht ist und auf der Developer Platform fertig gebaut wurde. Informationen zum Veröffentlichen finden Sie unter [Publish the Build](/development/deploy/cloud-custom-builds#publish-the-build).

Wenn auf dem Build eine andere Aufgabe läuft, ist **Upload build** ausgegraut. Halten Sie den Zeiger darüber, um **Wait for the current task on this build to finish.** zu lesen.

## Fehlerbehebung

<AccordionGroup>
  <Accordion title="Release meldet „No compatible Builds are available to install.“">
    Comfy Desktop führt ein Developer Platform Build nur dann auf, wenn dessen neueste veröffentlichte Version fertig gebaut wurde und ein Build für das Betriebssystem und die GPU dieses Computers vorliegt. Prüfen Sie, ob der in der **Seitenleiste** ausgewählte Workspace derjenige ist, in den Ihr Team veröffentlicht. Klicken Sie auf **View builds online**, um den Build auf der Developer Platform zu prüfen, und klicken Sie anschließend auf **Refresh builds**.
  </Accordion>
  <Accordion title="Der Dialog zeigt „Couldn't load builds. Retry“">
    Comfy Desktop konnte die Builds Ihres Workspace nicht laden. Klicken Sie auf **Couldn't load builds. Retry**, um sie erneut zu laden.
  </Accordion>
  <Accordion title="Der Hinweis „Could not upload build“">
    Der Hinweis **Could not upload build** nennt den Grund, zum Beispiel **Could not create a draft in Comfy Developer Platform.** Wählen Sie erneut **Upload build**.
  </Accordion>
</AccordionGroup>
