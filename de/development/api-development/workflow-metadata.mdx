## Überblick

Beim Speichern einer Ausgabedatei kann ComfyUI den Workflow, der die Datei erzeugt hat, in der Datei selbst ablegen.

Sie können sich das so vorstellen, dass ein generiertes Bild zusammen mit seinem Rezept gespeichert wird. Das Bild ist das Ergebnis, und der eingebettete Workflow beschreibt die Schritte, mit denen es erstellt wurde.

Eingebettete Workflow-Metadaten ermöglichen es Ihnen:

- Eine generierte Datei in ComfyUI erneut zu öffnen und ihren Workflow wiederherzustellen.
- Eine generierte Datei zusammen mit dem Workflow weiterzugeben, der zu ihrer Erstellung verwendet wurde.
- Generierungseinstellungen in einem automatisierten Workflow einzusehen.
- Tools zu erstellen, die ComfyUI-Workflow-Metadaten aus Ausgabedateien lesen.

Die Metadaten werden im Dateiformat selbst gespeichert. Sie verändern den sichtbaren Bild- oder Videoinhalt nicht.

## Eingebettete Felder

ComfyUI speichert üblicherweise zwei JSON-Felder:

| Feld | Beschreibung |
| --- | --- |
| `workflow` | Der vollständige Workflow-Graph, einschließlich Nodes, Verbindungen und Layoutinformationen. |
| `prompt` | Der API-Prompt, mit dem der Workflow ausgeführt wird. Er enthält die Nodes und Eingänge, die für die Ausführung erforderlich sind. |

Ein vereinfachtes Beispiel sieht so aus:

```json
{
  "workflow": {
    "nodes": [],
    "links": []
  },
  "prompt": {
    "3": {
      "class_type": "KSampler",
      "inputs": {}
    }
  }
}
```

Der tatsächliche Inhalt hängt vom Workflow und der ComfyUI-Version ab. Custom Nodes können über `extra_pnginfo` zusätzliche Felder hinzufügen.

Die beiden Felder erfüllen unterschiedliche Zwecke. `workflow` dient dazu, den Workflow im Frontend wiederherzustellen. `prompt` ist die ausführungsorientierte Darstellung, die beim Übermitteln eines Workflows an einen ComfyUI-Server verwendet wird. Eine Datei kann eines der Felder ohne das andere enthalten.

## Unterstützte Formate

Integrierte Save-Nodes betten Metadaten in die folgenden Ausgabeformate ein:

| Ausgabe | Speicherort der Metadaten |
| --- | --- |
| PNG | PNG-`tEXt`-Chunks |
| Animiertes PNG | PNG-Textmetadaten |
| Animiertes WebP | EXIF-Tags |
| MP4 | Container-Metadaten-Tags |
| WebM | Container-Metadaten-Tags |
| `.latent` | Safetensors-Metadaten |
| `.safetensors` | Safetensors-Metadaten, wenn sie von einem Node geschrieben wurde, der Workflow-Metadaten enthält |

Der genaue Metadaten-Support hängt vom Save-Node und vom Schreibpfad der Datei ab. Eine Datei, die von einer anderen Anwendung neu kodiert wurde, enthält möglicherweise keine Metadaten mehr.

Animierte WebP-Dateien speichern die Werte in EXIF-Tags. Die Tags enthalten Zeichenketten wie `workflow:{JSON}` und `prompt:{JSON}`. Dies unterscheidet sich von MP4 und WebM, die die Werte als Container-Metadaten-Tags speichern.

## Wie ComfyUI Metadaten schreibt

Eingebaute Ausgabe-Nodes erhalten den API-Prompt und zusätzliche Workflow-Informationen, wenn ComfyUI einen Workflow ausführt. Sofern das Speichern von Metadaten nicht deaktiviert ist, serialisiert der speichernde Node diese Werte als JSON und schreibt sie in die Ausgabedatei.

Bei PNG-Ausgaben werden die Werte als Texteinträge geschrieben. Die Standardfeldnamen sind `prompt` und `workflow`.

Die Metadaten sind keine separate Sidecar-Datei. Sie werden während des Speichervorgangs in die Ausgabedatei geschrieben. Das bedeutet, dass beim Kopieren der Datei auch der eingebettete Workflow kopiert wird, aber jeder Vorgang, der die Datei neu schreibt, die Metadaten entfernen oder ersetzen kann.

Um Metadaten beim Starten von ComfyUI zu deaktivieren, verwenden Sie:

```bash
python main.py --disable-metadata
```

In ComfyUI Desktop öffnen Sie **Settings** > **Server-Config** und aktivieren Sie **Disable saving prompt metadata in files.**

Dateien, die bei aktivierter Option erstellt werden, können nicht dazu verwendet werden, einen Workflow aus eingebetteten Metadaten wiederherzustellen.

## Wie ComfyUI Metadaten liest

Um einen Workflow in der ComfyUI-Oberfläche wiederherzustellen, ziehen Sie eine generierte Datei auf den Canvas. Sie können eine Datei auch über **File** > **Open** öffnen.

Wenn die Datei sowohl `workflow` als auch `prompt` enthält, verwendet ComfyUI den eingebetteten `workflow`, um den Canvas neu aufzubauen. Wenn die Datei keinen Workflow enthält, behandelt ComfyUI unterstützte Mediendateien als reguläre Eingabemedien.

Wenn Sie eine Integration erstellen, prüfen Sie, ob das Feld vorhanden ist, bevor Sie es parsen. Metadaten können fehlen, weil die Datei mit `--disable-metadata` erstellt wurde, weil der Node zum Speichern keine Workflow-Informationen erhalten hat oder weil eine andere Anwendung die Datei neu kodiert hat.

Eine browserbasierte Möglichkeit, eingebettete Workflows zu prüfen oder zu bearbeiten, finden Sie im [ComfyUI Embedded Workflow Editor](https://comfyui-embedded-workflow-editor.vercel.app/).

## Einschränkungen

- Eingebettete Metadaten sind keine digitale Signatur. Sie belegen nicht, wer eine Datei erstellt oder verändert hat.
- Der Workflow enthält weder die Modelldateien noch die Eingabe-Assets oder die Custom-Node-Pakete, von denen er abhängt.
- Wird ein Modell, ein Eingabe-Asset oder ein Custom Node verschoben oder umbenannt, kann ein wiederhergestellter Workflow möglicherweise nicht ausgeführt werden.
- Bild- und Videobearbeitungsprogramme können Metadaten entfernen, wenn sie eine Datei neu kodieren.
- Dateien, die mit `--disable-metadata` erstellt wurden, enthalten nicht die standardmäßigen ComfyUI-Workflow-Metadaten.
- Behandeln Sie eingebettete Metadaten als optionale und nicht vertrauenswürdige Eingabe. Validieren Sie vor der Verwendung, ob ein Wert gültiges JSON ist, und gehen Sie nicht davon aus, dass ein Workflow jedes Modell oder jeden Custom Node enthält, der zum Ausführen erforderlich ist.
