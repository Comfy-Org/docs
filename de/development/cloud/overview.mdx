<Warning>
  **Veraltet:** Die Cloud API v1 gilt zugunsten von [Comfy API v2](/api-reference/v2/overview) als veraltet. Sie bleibt für bestehende Integrationen und für Cloud-Funktionen verfügbar, die v2 noch nicht bereitstellt, aber Endpunkte und Verhalten können sich ohne Ankündigung ändern.
</Warning>

Die Cloud API v1 bietet programmatischen Zugriff auf [Comfy Cloud](/de/development/deploy/cloud), Comcys Managed Service zum Ausführen von Workflows auf Cloud-Infrastruktur.

Comfy Cloud ist eine zustandsbehaftete Anwendung. Ihr Konto trägt Zustand, der über Aufträge hinweg bestehen bleibt: Credits und Abonnementstufe, hochgeladene Assets und generierte Ausgaben, die Auftragswarteschlange sowie die Menge der installierten Modelle und Nodes. Die API v1 ist die Oberfläche für diese gesamte Anwendung und enthält daher Funktionen, die in der portablen [Comfy API v2](/api-reference/v2/overview) nicht unterstützt werden, etwa Warteschlangenverwaltung, das Durchsuchen von Modellen, Node-Definitionen und Konto-Endpunkte. Verwenden Sie v2 (oder die SDKs, die sie umhüllen), um Workflows abzusenden und Ergebnisse abzurufen, und zwar so, dass dies auch mit Comfy API-Implementierungen und selbst gehostetem ComfyUI funktioniert. Verwenden Sie v1 für die Cloud-spezifischen Funktionen darum herum.

Um Workflows auszuführen, beginnen Sie mit [Auf Comfy Cloud deployen](/de/development/deploy/cloud) und den [Comfy SDKs](/de/development/api-development/sdks). Credits und Nebenläufigkeitslimits werden in [Nutzung und Limits](/de/development/deploy/cloud-usage) behandelt; ausführbare v1-Beispiele finden Sie in der [Cloud API-Referenz](/de/development/cloud/api-reference). Diese Seite behandelt die v1-spezifische Oberfläche: Authentifizierung und die Endpunkte, die v2 nicht bereitstellt.

<Note>
  **Abonnement erforderlich:** Der API-Zugriff erfordert ein kostenpflichtiges Comfy Cloud-Abonnement; der kostenlose Tarif enthält ihn nicht. Siehe die [Preispläne](https://www.comfy.org/cloud/pricing?utm_source=docs&utm_campaign=cloud-api).
</Note>

## Basis-URL

```
https://cloud.comfy.org
```


## Authentifizierung

Alle v1-Anfragen erfordern einen API-Schlüssel, der im Header `X-API-Key` übergeben wird:

```bash
curl -X GET "https://cloud.comfy.org/api/user" \
  -H "X-API-Key: $COMFY_CLOUD_API_KEY"
```

Anweisungen zum Erstellen und Verwalten von Schlüsseln finden Sie unter [API-Schlüssel erhalten](/de/development/api-development/getting-an-api-key). Ein ungültiger oder fehlender Schlüssel gibt `401` zurück. Ein Schlüssel zu einem inaktiven Abonnement gibt `429` zurück.

Derselbe Schlüssel wird für [Partner-Nodes](/de/tutorials/partner-nodes/overview) verwendet. Über HTTP übergeben Sie ihn erneut in `extra_data.api_key_comfy_org`; Beispiele finden Sie unter [Partner-Nodes verwenden](/de/development/cloud/api-reference#partner-nodes-verwenden).

## Was die SDKs noch nicht abdecken

Die SDKs decken das Ausführen eines Workflows, das Abrufen der Ergebnisse und das Abbrechen einer Aufgabe ab. Der übrige Funktionsumfang von Comfy Cloud ist nur über HTTP erreichbar. Rufen Sie diese Endpunkte daher direkt auf, auch wenn Sie für die Ausführung ein SDK verwenden.

| Fähigkeit | Endpunkt | Referenz |
|---|---|---|
| Status der Warteschlange, laufende und ausstehende Aufträge | `GET /api/queue` | [Warteschlangenverwaltung](/de/development/cloud/api-reference#websocket-nachrichtentypen) |
| Aktuelle Ausführung unterbrechen | `POST /api/interrupt` | [Warteschlangenverwaltung](/de/development/cloud/api-reference#websocket-nachrichtentypen) |
| Node-Definitionen und Eingabe-Spezifikationen | `GET /api/object_info` | [Objektinformationen](/de/development/cloud/api-reference#objektinformationen) |
| Verfügbare Modelle durchsuchen | Modell-Endpunkte | [OpenAPI-Spezifikation](/de/development/cloud/openapi) |
| Konto- und Benutzerinformationen | `GET /api/user` | [OpenAPI-Spezifikation](/de/development/cloud/openapi) |
| Maskierungs-Uploads, die auf ein vorhandenes Bild verweisen | `POST /api/upload/mask` | [Eingaben hochladen](/de/development/cloud/api-reference#workflows-ausführen) |

Das Abbrechen einer Aufgabe wird von beidem abgedeckt: Die SDKs brechen eine Aufgabe ab, für die Sie ein Handle besitzen, und `POST /api/queue` bricht anhand der ID ab.

## Fehlerbehandlung

REST-Endpunkte geben standardmäßige HTTP-Statuscodes zurück:

| Status | Beschreibung |
|--------|-------------|
| `400` | Ungültige Anfrage (fehlerhafter Workflow, fehlende Felder) |
| `401` | Nicht autorisiert (ungültiger oder fehlender API-Schlüssel) |
| `402` | Unzureichende Credits |
| `429` | Abonnement inaktiv |
| `500` | Interner Serverfehler |

Die SDKs lösen diese stattdessen als typisierte Exceptions aus, darunter `Unauthorized`, `InvalidWorkflow`, `InsufficientCredits`, `QueueFull` und `JobFailed`, die alle von `ComfyError` erben.

Ausführungsfehler sind von HTTP-Fehlern zu unterscheiden. Die während der Ausführung übermittelten `exception_type`-Werte finden Sie unter [Fehlerbehandlung](/de/development/cloud/api-reference#fehlerbehandlung).
