```python Python
import asyncio
from comfy_sdk import AsyncComfy

# Liest COMFY_API_KEY aus der Umgebung.
# Jeder submit()-Aufruf erzeugt seinen eigenen Idempotency-Key und verwendet ihn bei automatischen Wiederholungsversuchen erneut.
async def main():
    async with AsyncComfy() as client:
        handle = await client.models.submit(
            "bria/image",
            {
                "prompt": "A red vintage bicycle leaning against a brick wall in soft morning light",
            },
        )
        print("request_id:", handle.request_id)  # zusammen mit der Modell-ID alles, was ein anderer Prozess braucht

        # Abfragen, bis die Anfrage abgeschlossen ist, und dabei das vom Server angegebene Retry-After abwarten.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Die eigene Payload des Anbieters, derselbe Wert, den models.run() zurückgibt.
        # Eine fehlgeschlagene oder abgebrochene Anfrage löst hier den typisierten Router-Fehler aus.
        result = await handle.get()

    print(result)

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Liest COMFY_API_KEY aus der Umgebung.
// Jeder submit()-Aufruf erzeugt seinen eigenen Idempotency-Key und verwendet ihn bei automatischen Wiederholungsversuchen erneut.
const handle = await comfy.models.submit("bria/image", {
  prompt: "A red vintage bicycle leaning against a brick wall in soft morning light",
});
console.log("requestId:", handle.requestId); // zusammen mit der Modell-ID alles, was ein anderer Prozess braucht

// Abfragen, bis die Anfrage abgeschlossen ist, und dabei das vom Server angegebene Retry-After abwarten.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// Dasselbe Ergebnis, das models.run() zurückgibt. Eine fehlgeschlagene oder abgebrochene Anfrage führt hier zu einem Reject.
const result = await handle.get();

console.log(result.data);
```

```bash cURL
# 1. Absenden. Router antwortet mit 201 und request_id, status_url, response_url und cancel_url.
curl https://api.comfy.org/v2/models/bria/image/requests \
  -H "X-API-Key: $COMFY_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d "{\"prompt\": \"A red vintage bicycle leaning against a brick wall in soft morning light\"}"

# 2. Abfragen, bis der Status COMPLETED ist, und dabei jeweils die in der Antwort angegebenen Retry-After-Sekunden abwarten.
REQUEST_ID="<request_id from the 201 body>"
curl -i https://api.comfy.org/v2/models/bria/image/requests/$REQUEST_ID/status \
  -H "X-API-Key: $COMFY_API_KEY"

# 3. Abholen. 200 mit der nativen Ausgabe des Modells, 202 mit dem Status-Body, solange der Lauf noch läuft.
curl https://api.comfy.org/v2/models/bria/image/requests/$REQUEST_ID \
  -H "X-API-Key: $COMFY_API_KEY"
```

### Eingaben

<ParamField body="aspect_ratio" type="string" default="&quot;1:1&quot;">
  Seitenverhältnis des Ausgabebilds, eines von „1:1“, „2:3“, „3:2“, „3:4“, „4:3“, „4:5“, „5:4“, „9:16“, „16:9“, „16:10“, „10:16“, „2:1“, „1:2“, „21:9“, „9:21“, „3:1“, „1:3“, „4:1“, „1:4“, „5:1“ oder „1:5“. Bria lehnt die Seitenverhältnisse ab „16:10“ aufwärts in Verbindung mit „4MP“ ab, außerdem eine Verfeinerung, die sowohl prompt als auch structured_prompt sendet, sowie Bilder, die keinen Prompt enthalten.
</ParamField>

<ParamField body="images" type="string[]">
  Ein Referenzbild, das das neue Bild inspiriert. Öffentlich verfügbare URL oder Base64-kodiert. Akzeptierte Formate: JPEG, JPG, PNG, WEBP. Muss genau ein Element enthalten.
</ParamField>

<ParamField body="ip_signal" type="boolean" default="false">
  Wenn wahr, wird eine Warnung für potenzielle IP-Inhalte im Prompt zurückgegeben.
</ParamField>

<ParamField body="model_version" type="string">
  Die Version des zu verwendenden Modells. Nur „FIBO“ wird akzeptiert; lassen Sie den Parameter weg, um dasselbe Modell auszuführen.
</ParamField>

<ParamField body="output_type" type="string" default="&quot;png&quot;">
  Format des Ausgabebilds, „png“ oder „jpeg“.
</ParamField>

<ParamField body="prompt" type="string">
  Textbasierte Anweisung. Verwenden Sie ihn allein, um ein neues Bild zu generieren, oder zusammen mit images oder structured_prompt, um das Ergebnis zu steuern oder zu verfeinern.
</ParamField>

<ParamField body="prompt_content_moderation" type="boolean" default="true">
  Wenn wahr, wird bei einem Fehler der Prompt-Moderation 422 zurückgegeben.
</ParamField>

<ParamField body="resolution" type="string" default="&quot;1MP&quot;">
  Auflösung des Ausgabebilds, „1MP“ oder „4MP“. „4MP“ verbessert die Bilddetails, erhöht aber die Latenz um etwa 30 Sekunden.
</ParamField>

<ParamField body="seed" type="integer">
  Seed für eine deterministische Generierung. Wenn er weggelassen wird, wird ein zufälliger Seed verwendet.
</ParamField>

<ParamField body="structured_prompt" type="string">
  Ein String, der den strukturierten Prompt im JSON-Format enthält, aus dem Ergebnis einer früheren Generierung. Verwenden Sie ihn mit demselben Seed, um dieses Bild neu zu erzeugen, oder ändern Sie einen Teil davon, um das Bild zu verfeinern.
</ParamField>

<ParamField body="sync" type="boolean">
  Muss falsch sein oder weggelassen werden. Der synchrone Modus von Bria (wahr) wird abgelehnt statt weitergeleitet, sowohl auf Comfy Router als auch auf der eigenen `/proxy/`-Route dieser Operation: Comfy Router legt den Rückgabemodus vor dem Dispatch fest und pollt das Ergebnis innerhalb des Aufrufs, und die `/proxy/`-Route gibt die request_id und status_url zum Pollen zurück.
</ParamField>

<ParamField body="visual_input_content_moderation" type="boolean" default="true">
  Wenn wahr, wird bei einem Fehler der Bilder-Moderation 422 zurückgegeben.
</ParamField>

<ParamField body="visual_output_content_moderation" type="boolean" default="true">
  Wenn wahr, wird bei einem Fehler der Moderation der visuellen Ausgabe 422 zurückgegeben.
</ParamField>
