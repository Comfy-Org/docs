<ResponseField name="content" type="object">

Sowohl `video_url` als auch `last_frame_url` werden auf den Comfy-Speicher umgehostet (RE-HOSTED); alle anderen Felder hier stammen von BytePlus selbst. Nullable: BytePlus löscht die URLs 24 Stunden nach der Aufgabe, und ein erfolgreiches Dokument, das danach abgefragt wird, kann `content` fehlend oder als null enthalten.
</ResponseField>

<ResponseField name="content.last_frame_url" type="string">
  Download-URL für das letzte Frame des generierten Videos. Sie wird zurückgegeben, wenn die Anfrage `return_last_frame` gesetzt hat. Leiten Sie das Bildformat nicht aus dieser URL ab: BytePlus dokumentiert das letzte Frame auf der Anfrageseite als PNG, Router hostet die Bytes, die es erhält, neu und bestimmt ihren Typ anhand des Upstream-Content-Type oder eines Content-Sniffs, und `image/jpeg` ist nur der letzte Ausweg, wenn beides fehlschlägt. Router hostet das letzte Frame auf den Comfy-Speicher um und schreibt dieses Feld neu. Es ist daher normalerweise eine von Comfy signierte URL, die bis zu 24 Stunden gültig ist: beim Erzeugen für 24 Stunden signiert und aus einem 23-Stunden-Memo erneut ausgegeben, sodass eine spätere Abfrage eine URL zurückgeben kann, die nur noch eine Stunde gültig ist. Konnte das Umhosten nicht durchgeführt werden, behält das Feld stattdessen BytePlus' eigene URL, die BytePlus 24 Stunden nach der Aufgabe löscht. So oder so läuft der Link ab, laden Sie das Frame daher herunter, anstatt die URL zu speichern.
</ResponseField>

<ResponseField name="content.output_format" type="string">
  Containerformat des generierten Videos (mp4 oder mov), wenn BytePlus es in `content` verschachtelt. Seedance-Modelle geben es häufiger als Geschwisterfeld auf oberster Ebene von `content` zurück (siehe das Feld `output_format` auf oberster Ebene), und Router liest, welches der beiden vorhanden ist.
</ResponseField>

  BytePlus' eigene Download-URL für das Ausgabevideo, bytegenau neben der umgehosteten `video_url` zurückgegeben. NUR für Seedance-2.x-Aufgaben vorhanden, die von einem Workspace abgefragt werden, für den Comfy serverseitig ein Opt-in hat (es gibt keinen Request-Parameter); für alle anderen fehlt sie, auch für ein Credential, das keinem Workspace zugeordnet ist (etwa ein älterer API-Schlüssel ohne Workspace-Bindung), und sie fehlt, sobald BytePlus seine URLs 24 Stunden nach der Generierung löscht. Sie ist eine vorsignierte Object-Storage-URL und damit ein Bearer-Credential: Wer sie besitzt, kann das Video bis zum Ablauf herunterladen, behandeln Sie sie daher wie ein Geheimnis. Sie läuft bei `upstream_expires_at` ab, und bei Seedance 2.5 begrenzt BytePlus sie auf 100 Downloads, von denen einer vom Umhosten durch Router selbst verbraucht wird.
</ResponseField>

<ResponseField name="content.video_url" type="string">
  Download-URL für das Ausgabevideo. Router hostet das Video auf den Comfy-Speicher um und schreibt dieses Feld neu. Es ist daher normalerweise eine von Comfy signierte URL, die bis zu 24 Stunden gültig ist: beim Erzeugen für 24 Stunden signiert und aus einem 23-Stunden-Memo erneut ausgegeben, sodass eine spätere Abfrage eine URL zurückgeben kann, die nur noch eine Stunde gültig ist. Konnte das Umhosten nicht durchgeführt werden, behält das Feld stattdessen BytePlus' eigene URL, die BytePlus 24 Stunden nach der Aufgabe löscht und bei einigen Modellen auf 100 Downloads begrenzt. So oder so läuft der Link ab, laden Sie das Video daher herunter, anstatt die URL zu speichern.
</ResponseField>

<ResponseField name="created_at" type="integer">
  Der Zeitpunkt, zu dem die Aufgabe erstellt wurde. Der Wert ist ein UNIX-Zeitstempel in Sekunden.
</ResponseField>

<ResponseField name="duration" type="number">
  Die Dauer des generierten Videos in Sekunden. Als Zahl und nicht als Integer deklariert, weil BytePlus darin nicht konsistent ist: Bei Videoaufgaben wurden ganze Sekunden beobachtet, während benachbarte BytePlus-Oberflächen gebrochene Dauern melden. Ein Client darf daher keinen ganzzahligen Wert annehmen. Ein eigenes Feld von BytePlus, das bei erfolgreichen Videoaufgaben zurückgegeben und unverändert weitergeleitet wird.
</ResponseField>

<ResponseField name="error" type="object">
  Die Fehlerinformationen. Ist die Aufgabe erfolgreich, wird null zurückgegeben. Schlägt die Aufgabe fehl, werden die Fehlerinformationen zurückgegeben.
</ResponseField>

<ResponseField name="error.code" type="string">
  Fehlercode von Upstream ModelArk. SensitiveContentDetected, InputTextSensitiveContentDetected, InputImageSensitiveContentDetected, InputVideoSensitiveContentDetected, InputAudioSensitiveContentDetected, OutputTextSensitiveContentDetected, OutputImageSensitiveContentDetected, OutputVideoSensitiveContentDetected und OutputAudioSensitiveContentDetected kennzeichnen Ablehnungen durch die Inhaltsrichtlinie. Eine Familie kann einen durch Punkte getrennten Grund haben, etwa InputImageSensitiveContentDetected.PrivacyInformation, OutputVideoSensitiveContentDetected.PolicyViolation oder OutputImageSensitiveContentDetected.DeepFake. Dies ist ein offener String, kein Enum: Andere Codes beschreiben Validierungs- und Anbieterfehler. Router erkennt Richtlinien-Familien in HTTP-400-Fehlerhüllen und HTTP-200-Antworten fehlgeschlagener Aufgaben, ohne Transportfehler zu überschreiben.
</ResponseField>

<ResponseField name="error.message" type="string">
  Die Fehlermeldung
</ResponseField>

<ResponseField name="id" type="string">
  Die ID der Videoerzeugungsaufgabe
</ResponseField>

<ResponseField name="model" type="string">
  Der Name und die Version des von der Aufgabe verwendeten Modells
</ResponseField>

<ResponseField name="output_format" type="string">
  Containerformat des generierten Videos (mp4 oder mov), das auf der OBERSTEN EBENE als Geschwister von `content` zurückgegeben wird. Genau dort gibt die Seedance-Abfrage für Videoaufgaben es zurück. BytePlus' eigenes Feld, unverändert weitergegeben.
</ResponseField>

<ResponseField name="resolution" type="string">
  Die Auflösung des generierten Videos, zum Beispiel `1080p`. BytePlus' eigenes Feld, das bei erfolgreichen Videoaufgaben zurückgegeben und unverändert weitergegeben wird.
</ResponseField>

<ResponseField name="seed" type="integer">
  Der tatsächlich für die Aufgabe verwendete Seed. BytePlus' eigenes Feld, das bei erfolgreichen Videoaufgaben zurückgegeben und unverändert weitergegeben wird.

  Format: `int64`
</ResponseField>

<ResponseField name="status" type="string">
  Der Status der Aufgabe

  Mögliche Werte: `queued`, `running`, `cancelled`, `succeeded`, `failed`, `expired`
</ResponseField>

<ResponseField name="updated_at" type="integer">
  Der Zeitpunkt, zu dem die Aufgabe zuletzt aktualisiert wurde. Der Wert ist ein UNIX-Zeitstempel in Sekunden.
</ResponseField>

<ResponseField name="usage" type="object">

<ResponseField name="usage.completion_tokens" type="integer">

<ResponseField name="usage.total_tokens" type="integer">
