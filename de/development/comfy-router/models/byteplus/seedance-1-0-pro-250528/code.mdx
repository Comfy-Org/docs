  Die eigene Download-URL von BytePlus für das Ausgabevideo, Byte für Byte neben der erneut gehosteten `video_url` zurückgegeben. Nur bei Seedance-2.x-Aufgaben vorhanden, die von einem Workspace abgefragt werden, für den Comfy serverseitig ein Opt-in hinterlegt hat (es gibt keinen Anfrageparameter); für alle anderen fehlt sie, auch für ein Credential, das keinem Workspace zugeordnet werden kann (etwa ein älterer API-Schlüssel ohne Workspace-Bezug), und sie fehlt, sobald BytePlus seine URLs 24 Stunden nach der Generierung löscht. Es handelt sich um eine vorab signierte Object-Storage-URL und damit um ein Bearer-Credential: Wer sie besitzt, kann das Video bis zu ihrem Ablauf herunterladen, behandeln Sie sie daher wie ein Geheimnis. Sie läuft zu `upstream_expires_at` ab, und bei Seedance 2.5 begrenzt BytePlus sie auf 100 Downloads, von denen der eigene Re-Host von Router einen verbraucht.
</ResponseField>

<ResponseField name="content.video_url" type="string">
  Download-URL für das Ausgabevideo. Router hostet das Video erneut auf dem Comfy-Speicher und schreibt dieses Feld um, daher ist es normalerweise eine von Comfy signierte URL, die bis zu 24 Stunden gültig ist: beim Erzeugen für 24 Stunden signiert und aus einem 23-Stunden-Memo erneut ausgeliefert, sodass eine spätere Abfrage eine URL zurückgeben kann, die nur noch eine Stunde gültig ist. Konnte das erneute Hosten nicht durchgeführt werden, behält das Feld stattdessen die URL von BytePlus, die BytePlus 24 Stunden nach der Aufgabe löscht und bei manchen Modellen auf 100 Downloads begrenzt. So oder so läuft der Link ab, laden Sie das Video daher herunter, anstatt die URL zu speichern.
</ResponseField>

<ResponseField name="created_at" type="integer">
  Der Zeitpunkt, zu dem die Aufgabe erstellt wurde. Der Wert ist ein UNIX-Zeitstempel in Sekunden.
</ResponseField>

<ResponseField name="duration" type="number">
  Die Dauer des generierten Videos in Sekunden. Sie ist als Zahl und nicht als Integer deklariert, weil BytePlus hier nicht konsistent ist: Videoaufgaben haben bereits ganze Sekunden zurückgegeben, während andere BytePlus-Oberflächen gebrochene Dauern melden. Ein Client darf daher keinen ganzzahligen Wert annehmen. Dies ist ein Feld von BytePlus, das bei erfolgreichen Videoaufgaben zurückgegeben und unverändert weitergeleitet wird.
</ResponseField>

<ResponseField name="error" type="object">
  Die Fehlerinformationen. Wenn die Aufgabe erfolgreich ist, wird null zurückgegeben. Wenn die Aufgabe fehlschlägt, werden die Fehlerinformationen zurückgegeben.
</ResponseField>

<ResponseField name="error.code" type="string">
  Upstream-Fehlercode von ModelArk. SensitiveContentDetected, InputTextSensitiveContentDetected, InputImageSensitiveContentDetected, InputVideoSensitiveContentDetected, InputAudioSensitiveContentDetected, OutputTextSensitiveContentDetected, OutputImageSensitiveContentDetected, OutputVideoSensitiveContentDetected und OutputAudioSensitiveContentDetected kennzeichnen Ablehnungen durch die Inhaltsrichtlinie. Eine Familie kann einen durch Punkte getrennten Grund haben, etwa InputImageSensitiveContentDetected.PrivacyInformation, OutputVideoSensitiveContentDetected.PolicyViolation oder OutputImageSensitiveContentDetected.DeepFake. Dies ist ein offener String, kein Enum: Andere Codes beschreiben Validierungs- und Anbieterfehler. Router erkennt Richtlinien-Familien in HTTP-400-Fehlerhüllen und in HTTP-200-Antworten auf fehlgeschlagene Aufgaben, ohne Transportfehler zu überschreiben.
</ResponseField>

<ResponseField name="error.message" type="string">
  Die Fehlermeldung
</ResponseField>

<ResponseField name="id" type="string">
  Die ID der Aufgabe zur Videogenerierung
</ResponseField>

<ResponseField name="model" type="string">
  Der Name und die Version des Modells, das die Aufgabe verwendet
</ResponseField>

<ResponseField name="output_format" type="string">
  Containerformat des generierten Videos (mp4 oder mov), das auf der OBERSTEN EBENE als Geschwisterelement von `content` zurückgegeben wird. Hier gibt die Abfrage der Seedance-Videoaufgabe es zurück. Das eigene Feld von BytePlus, unverändert weitergegeben.
</ResponseField>

<ResponseField name="resolution" type="string">
  Die Auflösung des generierten Videos, zum Beispiel `1080p`. Das eigene Feld von BytePlus, das bei erfolgreichen Videoaufgaben zurückgegeben und unverändert weitergegeben wird.
</ResponseField>

<ResponseField name="seed" type="integer">
  Der tatsächlich für die Aufgabe verwendete Generierungs-Seed. Das eigene Feld von BytePlus, das bei erfolgreichen Videoaufgaben zurückgegeben und unverändert weitergegeben wird.

  Format: `int64`
</ResponseField>

<ResponseField name="status" type="string">
  Der Status der Aufgabe

  Mögliche Werte: `queued`, `running`, `cancelled`, `succeeded`, `failed`, `expired`
</ResponseField>

<ResponseField name="updated_at" type="integer">
  Der Zeitpunkt, an dem die Aufgabe zuletzt aktualisiert wurde. Der Wert ist ein UNIX-Zeitstempel in Sekunden.
</ResponseField>

<ResponseField name="usage" type="object">

</ResponseField>

<ResponseField name="usage.completion_tokens" type="integer">

<ResponseField name="usage.total_tokens" type="integer">
