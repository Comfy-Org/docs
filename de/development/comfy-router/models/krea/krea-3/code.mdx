```python Python
import asyncio

# Liest COMFY_API_KEY aus der Umgebung.
# Jeder submit()-Aufruf erzeugt seinen eigenen Idempotenzschlüssel und verwendet ihn bei automatischen Wiederholungsversuchen erneut.
async def main():

            "krea/krea-3",

                "resolution": "1k",

        # Die Payload des Anbieters selbst, derselbe Wert, den models.run() zurückgibt.

        result = await handle.get()

asyncio.run(main())
```

```typescript TypeScript
import { comfy } from "@comfyorg/sdk";

// Liest COMFY_API_KEY aus der Umgebung.
// Jeder submit()-Aufruf erzeugt seinen eigenen Idempotenzschlüssel und verwendet ihn bei automatischen Wiederholungsversuchen erneut.
const handle = await comfy.models.submit("krea/krea-3", {
  prompt: "A ceramic coffee mug on a clean studio background",
  resolution: "1k",
});
console.log("requestId:", handle.requestId); // zusammen mit der Modell-ID alles, was ein anderer Prozess benötigt

// Wiederholt abfragen, bis die Anfrage abgeschlossen ist, und dabei die vom Server genannte Retry-After-Zeit abwarten.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// Dasselbe Ergebnis, das models.run() zurückgibt. Eine fehlgeschlagene oder abgebrochene Anfrage führt hier zu einem abgelehnten Promise.
const result = await handle.get();

console.log(result.data);
```

<ParamField body="image_urls" type="string[]">
  Bild-URLs für die Eingabe, bis zu 8. Mehr als 8 Einträge werden vor jedem Abruf abgelehnt (400 auf /proxy/krea; die Schema-Prüfung von Comfy Router antwortet zuerst mit 422). Die image_url, die beim Hochladen des Bildes an POST /proxy/krea/assets (Multipart-Formularfeld `file`) zurückgegeben wird, wird immer akzeptiert. Ob andere öffentliche https-URLs akzeptiert werden, hängt von der Umgebung ab: Wo sie nicht akzeptiert werden, wird jeder Link, der keine https-URL auf dem Host app-uploads.krea.ai ist, mit 400 und der Meldung „image_urls must be image_url values returned by POST /proxy/krea/assets“ abgelehnt, laden Sie das Bild stattdessen hoch; wo sie akzeptiert werden, wird jede öffentliche https-Bild-URL akzeptiert, und eine URL, die fehlerhaft ist oder kein https ist, wird mit 400 abgelehnt (eine URL, deren Port numerisch, aber außerhalb des zulässigen Bereichs liegt, wird von dieser Prüfung nicht erfasst und kann stattdessen mit 502 fehlschlagen). In diesem Fall wird eine Anfrage, bei der ein image_urls-Eintrag kein Link auf app-uploads.krea.ai ist (eine öffentliche https-URL oder eine base64-data:-URI, wo diese akzeptiert werden), ebenfalls vor jedem Abruf mit 400 abgelehnt, es sei denn, der gesamte Anfrage-Body wird als application/json statt als Multipart gesendet, ist gültiges UTF-8, umfasst höchstens 25100288 Bytes und enthält nur die Felder, die dieses Schema deklariert. Für eine wohlgeformte https-URL in diesem Fall wird eine Referenz, die der Aufrufer beheben kann, mit 400 und Nennung ihres Hosts abgelehnt: Ihr Host lässt sich nicht auflösen oder ist nicht öffentlich erreichbar, wenn er vor dem Abruf geprüft wird, sie leitet häufiger als erlaubt weiter, auf eine URL, die kein https ist, oder auf einen Host, der nicht öffentlich erreichbar ist, sie gibt einen 4xx außer 408 oder 429 zurück, sie ist kein Bild, sie ist ein Bild in einem Format, das nicht gelesen werden kann, ihr Bildgrößen-Header liegt nicht innerhalb der ersten 2 MiB, oder eine Antwort ohne deklarierte Länge oder mit Chunked-Encoding endet vor ihrem Bildgrößen-Header. Jeder andere Fehler beim Abruf schlägt mit einem 502-Fehler auf POST /proxy/krea fehl (Comfy Router antwortet darauf mit 500 internal_error): ein vorübergehender DNS-, TLS- oder Verbindungsfehler, ein Timeout, ein Ursprungs-408, -429, -5xx oder anderer Nicht-200-Status, oder ein Host, der diese Prüfung bestanden hat, sich aber nicht auflösen lässt oder nicht öffentlich erreichbar ist, wenn der Abruf die Verbindung herstellt. Einige davon beheben sich bei erneutem Versuch (ein Resolver-Fehler, Timeout, abgebrochene Verbindung, ein Ursprung, der 5xx, 408 oder 429 antwortet, oder ein Host, dessen DNS-Antwort zwischen Host-Prüfung und Verbindung auf eine nicht öffentliche Adresse wechselt, was bei erneutem Versuch gelingen oder den 400 für einen nicht öffentlichen Host ergeben kann); andere schlagen jedes Mal auf dieselbe Weise fehl, zum Beispiel ein TLS-Zertifikat, dem der Abruf nicht vertraut (selbstsigniert, abgelaufen oder für den falschen Hostnamen), oder ein Ursprung, der ein 2xx außer 200 oder ein 3xx antwortet, dem der Abruf nicht folgt (etwa 204, 206, 300, 304 oder 305, oder ein 301, 302, 303, 307 oder 308 ohne Location), laden Sie das Bild also stattdessen hoch, wenn ein erneuter Versuch auf dieselbe Weise fehlschlägt. Eine über Comfy Router in die Warteschlange gestellte Anfrage wiederholt einen solchen Fehler nicht, wenn einer ihrer image_urls-Einträge kein Link auf app-uploads.krea.ai ist, reichen Sie sie also selbst erneut ein, wenn die Ursache sich beheben kann. Wo andere URLs nicht akzeptiert werden, schlägt ein Link auf app-uploads.krea.ai, der kein Live-Upload ist, mit einem 5xx-Fehler fehl; wo sie akzeptiert werden, wird er mit 400 abgelehnt wie jede andere nicht erreichbare Referenz. Solange ein Server noch nicht gelernt hat, was zutrifft, schlägt jede https-URL mit einem Host, der kein Link auf app-uploads.krea.ai ist, öffentlich oder nicht, mit einem 503-Fehler fehl, der gefahrlos erneut versucht werden kann (eine in die Warteschlange gestellte Anfrage wird dabei automatisch erneut versucht). Der 400 einer in die Warteschlange gestellten Anfrage enthält nur das generische invalid_input-Detail, zeigt also weder den Host noch den obigen Wortlaut, und die Warteschlange versucht es nicht erneut. Ein 400 aus der Warteschlange kann von jedem Feld stammen, nicht nur von image_urls (zum Beispiel eine nicht unterstützte Auflösung oder thinking_mode), prüfen Sie also zuerst die anderen Felder. Wenn diese gültig sind, laden Sie jedes Bild an POST /proxy/krea/assets hoch und reichen Sie die Anfrage mit diesen image_url-Werten und einem neuen Idempotency-Key (oder keinem) erneut ein: Die Wiederverwendung des Schlüssels mit einem geänderten Body wird mit 409 invalid_input abgelehnt, was nichts über die Bilder aussagt, und die Wiederverwendung mit demselben Body wird mit 201, der ursprünglichen request_id und Idempotent-Replayed: true beantwortet, startet also keinen neuen Lauf, und ihre Ergebnis-URL gibt denselben 400 zurück (ihre Status-URL antwortet mit 200 und error_type invalid_input). Wo andere öffentliche https-URLs akzeptiert werden und auch diese erneute Einreichung mit 400 fehlschlägt, ist das Bild selbst das Problem (zum Beispiel ist es kein unterstütztes Bild, oder sein Bildgrößen-Header liegt nicht innerhalb der ersten 2 MiB). Wo sie nicht akzeptiert werden, schlägt dasselbe hochgeladene Bild mit einem 5xx fehl (500 internal_error auf Comfy Router) statt mit diesem 400, und das Bild ist weiterhin das Problem, erneutes Hochladen hilft also nicht. Von jedem Bild werden nur die ersten 2 MiB gelesen, um seine Größe zu ermitteln, ein Bild, dessen Größeninformationen nicht innerhalb dieses Fensters gelesen werden können (etwa ein JPEG mit über 2 MiB eingebetteten Metadaten, oder ein palettenbasiertes PNG, dessen Transparenzdaten, oder ohne diese der Beginn seines ersten Bilddaten-Chunks, jenseits von 2 MiB liegen, etwa nach über 2 MiB Text- oder Farbprofil-Chunks), wird daher mit 400 und der Meldung abgelehnt, sein Bildgrößen-Header liege nicht innerhalb der ersten 2 MiB, ob hochgeladen oder nicht; speichern Sie es ohne die großen Metadaten erneut, oder speichern Sie ein palettenbasiertes PNG als nicht palettenbasiertes PNG.
