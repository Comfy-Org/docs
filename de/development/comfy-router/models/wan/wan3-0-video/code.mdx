API-Referenz für Wan 3.0 Video. Wan 3.0 Video generiert allein aus einem Prompt oder aus einer Medienliste mit erstem und letztem Frame, Referenzbildern, Videos und Audio, die im Prompt als Image 1, Video 1 und Audio 1 adressiert werden.

**Eingabe:** Text, Bild, Video, Audio · **Ausgabe:** Video + Audio

## Schnellstart

Erstellen Sie einen Schlüssel in [Ihrem Comfy Workspace](https://platform.comfy.org/profile/api-keys?onboarding=router) und exportieren Sie ihn als `COMFY_API_KEY`. Die Python- und TypeScript-Snippets verwenden die Comfy SDKs (`pip install comfy-sdk` und `npm install @comfyorg/sdk`); das cURL-Snippet ist derselbe Aufruf über direktes HTTP.

**Modell-ID:** `wan/wan3.0-video`

**Endpunkt:** `POST https://api.comfy.org/v2/models/wan/wan3.0-video`

        handle = await client.models.submit(
            "wan/wan3.0-video",

                "input": {
                    "prompt": "the robot lowers its raised arm and steps toward the camera, the flat orange backdrop holds steady",

                        },
                    ],
                },
                "parameters": {
                    "resolution": "720P",
                    "duration": 5,
                },
            },
        )
        print("request_id:", handle.request_id)  # zusammen mit der Modell-ID alles, was ein anderer Prozess benötigt

        # Pollen, bis die Anfrage abgeschlossen ist, und dabei das vom Server genannte Retry-After abwarten.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # Die eigene Payload des Anbieters, derselbe Wert, den models.run() zurückgibt.
        # Eine fehlgeschlagene oder abgebrochene Anfrage wirft hier den typisierten Router-Fehler.
        result = await handle.get()

    print("video:", result["output"]["video_url"])

asyncio.run(main())

// Jeder submit()-Aufruf erzeugt einen eigenen Idempotency-Key und verwendet ihn für automatische Wiederholungsversuche erneut.
type Result = { output: { video_url: string } };
const handle = await comfy.models.submit<Result>("wan/wan3.0-video", {
  input: {
    prompt: "the robot lowers its raised arm and steps toward the camera, the flat orange backdrop holds steady",
    media: [
      {
        type: "first_frame",
        url: "https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/input/pink_robot_front.png",
      },
    ],
  },
  parameters: {
    resolution: "720P",
    duration: 5,
  },
});
console.log("requestId:", handle.requestId); // zusammen mit der Modell-ID alles, was ein anderer Prozess benötigt

// Pollen, bis die Anfrage abgeschlossen ist, und dabei das vom Server genannte Retry-After abwarten.
for await (const update of handle.events()) {
  console.log(update.status, update.queuePosition);
}

// Dasselbe Ergebnis, das models.run() zurückgibt. Eine fehlgeschlagene oder abgebrochene Anfrage wird hier zurückgewiesen.
const result = await handle.get();
if (result.kind !== "json") throw new Error("expected a JSON result");

console.log("video:", result.data.output.video_url);

## Anbieter für die Bereitstellung {#serving-providers}

Dieses Modell wird direkt von Comfy Router bereitgestellt, sofern die Anfrage keinen anderen Anbieter nennt. Die unten aufgeführten Anbieter stellen es ebenfalls bereit, am selben Endpoint und mit derselben Modell-ID, ausgewählt über den Query-Parameter `model_provider`.

- **Comfy** (Standard): `POST https://api.comfy.org/v2/models/wan/wan3.0-video`
- **Higgsfield**, als `higgsfield/higgsfield-wan-3`: `POST https://api.comfy.org/v2/models/wan/wan3.0-video?model_provider=higgsfield`

`strict_mode` ist standardmäßig false, daher übersetzt Router den auf dieser Seite dokumentierten nativen Request-Body in das Schema des Anbieters und übersetzt die Antwort zurück. Siehe [`model_provider`, `strict_mode` und `fallback_provider`](/de/development/comfy-router/reference#post-v2modelsprovidermodel) in der API-Referenz und [Anbieter für die Bereitstellung](/de/development/comfy-router/providers) für jedes auf diese Weise geroutete Modell.

media sind keine minItems/maxItems deklariert, weil die zulässigen Typen und ihre Obergrenzen

das Asset akzeptiert. In die andere Richtung gilt: Die oben genannten Angaben „höchstens 20MB“
pro Asset, also die Obergrenze für die Bildeingänge, die einzigen Eingänge, die inline gesendet

begrenzt und wird bei Überschreitung mit 413 beantwortet, und base64 vergrößert eine Nutzlast
um etwa 4/3. Daher wird ein einzelnes Inline-Asset über etwa 75 MB abgelehnt, bevor eine der
Partnerregeln hier erreicht wird. Bei dieser Größe ein einzelnes Asset mit der eigenen …20 MB Obergrenze passen für Inline-Daten bequem, daher greift bei einem einzelnen Asset die Partner-Regel; das Transportlimit greift über mehrere hinweg, da die 100-MiB-Obergrenze des Routers die GESAMTE Anfrage begrenzt und nicht jedes Element einzeln. - happyhorse-1.0-* (t2v, i2v, r2v, video-edit): 720P, 1080P
- happyhorse-1.1-* (t2v, i2v, r2v): 480P, 720P, 1080P
Dieser Proxy lehnt Videogenerierungsanfragen ab, die weder resolution
noch size angeben, da die Auflösungsstufe den Abrechnungssatz bestimmt. Er wandelt
resolution vor der Prüfung in Großbuchstaben um und gibt den in Großbuchstaben umgewandelten Wert weiter, gibt 400 zurückbei einem Wert außerhalb dieses Enum und gibt 400 für 480P zurück (ob als resolution oder als 480P-Größe gesendet) bei den oben aufgeführten Modellen wan2.6, wan2.7 und happyhorse-1.0, die kein 480P haben.

  Mögliche Werte: `480P`, `720P`, `1080P`
</ParamField>

<ParamField body="parameters.seed" type="integer">
  Zufallszahl-Seed, der die Zufälligkeit der vom Modell generierten Inhalte steuert

  Bereich: `0` bis `2147483647`
</ParamField>

<ParamField body="parameters.shot_type" type="string" default="&quot;single&quot;">
  Intelligente Mehrfachobjektiv-Steuerung. Nur aktiv, wenn prompt_extend aktiviert ist.
Für die Modelle wan2.6 und wan2.7-r2v.
- single: Video mit einer einzigen Aufnahme (Standard)
- multi: Video mit mehreren Aufnahmen

  Mögliche Werte: `multi`, `single`
</ParamField>

<ParamField body="parameters.size" type="string">
  Videoauflösung im Format Breite*Höhe. Die unterstützten Auflösungen variieren je nach Modell:
Für wan2.5 T2V: Größen 480P (480*832, 832*480, 624*624), 720P, 1080P
Für wan2.6 T2V/R2V (kein 480P):
  720P: 1280*720, 720*1280, 960*960, 1088*832, 832*1088
  1080P: 1920*1080, 1080*1920, 1440*1440, 1632*1248, 1248*1632
Wenn sowohl size als auch resolution gesendet werden, wählt size die abgerechnete Stufe,
und resolution muss weiterhin ein Wert sein, den dieser Proxy für das Modell akzeptiert. Eine 480P-Größe
gibt 400 bei jedem Modell zurück, das die Beschreibung von resolution als Modell ohne 480P aufführt.
</ParamField>

<ParamField body="parameters.watermark" type="boolean" default="false">
  Ob ein Wasserzeichen-Logo hinzugefügt wird; das Wasserzeichen befindet sich in der unteren rechten Ecke
</ParamField>
