## Anbieter, die das Modell bereitstellen

Dieses Modell wird direkt von Comfy Router bereitgestellt, sofern die Anfrage keinen anderen Anbieter nennt. Die folgenden Anbieter stellen es ebenfalls bereit, über denselben Endpoint und mit derselben Modell-ID, ausgewählt über den Query-Parameter `model_provider`.

- **Comfy** (Standard): `POST https://api.comfy.org/v2/models/kling/kling-v3`
- **Higgsfield**, als `higgsfield/higgsfield-kling-3-std`: `POST https://api.comfy.org/v2/models/kling/kling-v3?model_provider=higgsfield`
- **Tencent**: `POST https://api.comfy.org/v2/models/kling/kling-v3?model_provider=tencent`
  - Limits: 720P, ohne Ton; 3–15 Sekunden (Standard 5); Seitenverhältnis 16:9, 9:16 oder 1:1
  - Abgelehnt mit `invalid_input`: `image`, `image_tail`, `sound: "on"`, `mode` anders als `std` (z. B. `"pro"`), `multi_shot`, `multi_prompt`, `shot_type`
  - Fallback: Wenn Tencent fehlschlägt, wird die Anfrage einmal auf Kling (dem Standardanbieter) wiederholt. Senden Sie `fallback_provider=false`, um dies zu deaktivieren. Bei abgelehnten Eingaben und BYOK-Anfragen greift kein Fallback.

`strict_mode` ist standardmäßig falsch, daher übersetzt Router den nativen Request-Body, der auf dieser Seite dokumentiert ist, in das eigene Schema des Anbieters und übersetzt die Antwort wieder zurück. Siehe [`model_provider`, `strict_mode` und `fallback_provider`](/de/development/comfy-router/reference#post-v2modelsprovidermodel) in der API-Referenz und [Anbieter, die das Modell bereitstellen](/de/development/comfy-router/providers) für jedes Modell, das auf diese Weise geroutet wird.
