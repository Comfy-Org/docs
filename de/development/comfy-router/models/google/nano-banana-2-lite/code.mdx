### Eingaben

```json

  "contents": [
    {
      "role": "user",
      "parts": [

          "text": "a single red maple leaf on a plain white background, studio lighting"

    }
  ],

    "responseModalities": [

```

### Ausgaben

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [
          {
            "inlineData": {
              "mimeType": "image/png",
              "data": "PGJhc2U2ND4="
            }
          }
        ]
      },
      "finishReason": "STOP"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 12,
    "candidatesTokenCount": 1290
  }
}
```

Standardmäßig enthalten generierte Bildteile Base64-Bytes in `inlineData.data` und einen Medientyp in `inlineData.mimeType`. Dekodieren Sie die Bytes und speichern Sie sie in einer Datei. Mit `uploadImagesToStorage: true` verwenden hochgeladene Bilder stattdessen `fileData.fileUri` für eine signierte URL und `fileData.mimeType` für den Medientyp. Laden Sie diese Bilder herunter, bevor die URLs ablaufen, also 24 Stunden nach ihrer Erstellung. Wenn ein Upload fehlschlägt, bleibt dieses Bild inline, prüfen Sie daher jeden Teil auf `inlineData` oder `fileData`; Textteile können ebenfalls auftreten, und es ist nicht garantiert, dass das Bild der erste Teil ist. Der Pfad `candidates[0].content.parts[0].inlineData.data` in den obigen Quickstart-Beispielen liest den einzelnen Inline-Teil der Beispielantwort auf dieser Seite; bei einer echten Antwort durchsuchen Sie `parts` stattdessen nach dem gewünschten Schlüssel, anstatt Position 0 zu indexieren.
