API-Referenz für Google Gemini. Google Gemini ist Googles Familie multimodaler Textmodelle: von schnellen Entwürfen bis zu tiefem Reasoning über die Flash- und Pro-Stufen.

## Schnellstart

Erstellen Sie einen Schlüssel in [Ihrem Comfy Workspace](https://platform.comfy.org/profile/api-keys?onboarding=router) und exportieren Sie ihn als `COMFY_API_KEY`. Die Python- und TypeScript-Snippets verwenden die Comfy SDKs (`pip install comfy-sdk` und `npm install @comfyorg/sdk`); das cURL-Snippet ist derselbe Aufruf über rohes HTTP.

Wählen Sie das Modell, das Sie aufrufen möchten. Alles Folgende, von den Snippets bis zu Schema und Beispielen, richtet sich nach dieser Wahl.

# Each submit() call mints its own Idempotency-Key and reuses it for automatic retries.
async def main():

                },
            },
        )
        print("request_id:", handle.request_id)  # with the model ID, all another process needs

        # Poll until the request completes, waiting the Retry-After the server names.
        async for update in handle.iter_events():
            print(update.status, update.queue_position)

        # The provider's own payload, the same value models.run() returns.
        # A request that failed or was cancelled raises the typed Router error here.
        result = await handle.get()

asyncio.run(main())

<ParamField body="generationConfig.temperature" type="number" default="1">
  Die Temperature wird beim Sampling während der Antwortgenerierung verwendet, also dann, wenn topP und topK angewendet werden. Sie steuert den Grad der Zufälligkeit bei der Token-Auswahl. Niedrigere Temperaturen eignen sich für Prompts, die eine weniger offene oder kreative Antwort verlangen, höhere Temperaturen können zu vielfältigeren oder kreativeren Ergebnissen führen. Eine Temperature von 0 bedeutet, dass immer die Token mit der höchsten Wahrscheinlichkeit ausgewählt werden. In diesem Fall sind die Antworten auf einen bestimmten Prompt weitgehend deterministisch, eine geringe Variation ist aber weiterhin möglich. <ParamField body="generationConfig.topP" type="number" default="0.95">
  Wenn angegeben, wird Nucleus-Sampling verwendet.
Top-P ändert, wie das Modell Token für die Ausgabe auswählt. Token werden vom wahrscheinlichsten (siehe top-K) bis zum unwahrscheinlichsten ausgewählt, bis die Summe ihrer Wahrscheinlichkeiten dem Top-P-Wert entspricht. Haben etwa die Token A, B und C eine Wahrscheinlichkeit von 0.3, 0.2 und 0.1 und der Top-P-Wert ist 0.5, wählt das Modell anhand der Temperature entweder A oder B als nächstes Token und schließt C als Kandidat aus.
Geben Sie einen niedrigeren Wert für weniger zufällige Antworten und einen höheren Wert für zufälligere Antworten an.

  Bereich: `0` bis `1`

  Format: `float`
</ParamField>
