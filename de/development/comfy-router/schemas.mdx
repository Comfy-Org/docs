Jedes Router-Modell akzeptiert einen eigenen nativen Request-Body und gibt ein eigenes natives Ergebnis zurück. Lesen Sie das Schema des Modells, um beides zu erfahren.

## Eingabe- und Ausgabeschemas lesen

Jedes Modell stellt ein eigenständiges OpenAPI-Dokument bereit:

```bash
curl --dump-header schema-headers.txt \
  -H "X-API-Key: $COMFY_API_KEY" \
  https://api.comfy.org/v2/models/bfl/flux-2-pro/openapi.json
```

Innerhalb der Modell-Operation beschreibt `requestBody` die Eingabe, und die `200`-Antwort beschreibt die Ausgabe, sofern ein Ausgabeschema erstellt wurde. Eingabevalidierung und Ausgabedokumentation sind verschieden: Router validiert gegen sein Eingabeschema, validiert aber das zurückgegebene Anbieter-Ergebnis nicht gegen sein Ausgabeschema.

Prüfen Sie den Medientyp der Ausgabe sowie deren Felder. Eine nicht erstellte Ausgabe kann `*/*` verwenden, und einige Modelle liefern Binärdaten statt JSON.

### Ein Schema cachen

Speichern Sie das Schema und dessen `ETag`. Übergeben Sie bei einem späteren Abruf des Schemas diesen ETag in `If-None-Match`. Eine `304`-Antwort hat keinen Body; behalten Sie das gecachte Dokument. Eine `200`-Antwort liefert ein Ersatzdokument und einen ETag.

```bash
curl -H "X-API-Key: $COMFY_API_KEY" \
  -H 'If-None-Match: "previous-etag-value"' \
  https://api.comfy.org/v2/models/bfl/flux-2-pro/openapi.json
```

Die Schema-Route verwendet `Cache-Control: private, must-revalidate`. Halten Sie authentifizierte Antworten aus gemeinsam genutzten Caches heraus. Dieses ETag/304-Verhalten gilt nur für den Schema-Endpunkt.

## Validierung und Fallback-Schemas

Ein erstelltes Eingabeschema weist ungültige Felder vor dem Anbieter-Aufruf mit `422` und einem `detail[]`-Array zurück. Lesen Sie die Feldpfade in `loc`; siehe [Validierungsfehler](/de/development/comfy-router/errors#validierungsfehler).

Einige Schemas akzeptieren jedes JSON-Objekt und setzen `x-comfy-input-schema-authored: false`. Router leitet diese Anfragen ohne modellspezifische Validierung weiter, sodass der Anbieter sie trotzdem ablehnen kann.

## Ergebnis lesen

Router gibt die terminale Ergebnisform jedes Modells zurück. Es gibt keinen gemeinsamen Umschlag für Bilder, Videos oder Text: Die BFL-Bildausgabe verwendet `result.sample`, während andere Modelle URL-Listen oder Inline-Bytes zurückgeben können.

Einige Asset-URLs werden von Comfy neu gehostet; andere bleiben Anbieter-URLs oder Inline-Bytes. Prüfen Sie [Ergebnis-Assets](/de/development/comfy-router/reference#result-assets) und laden Sie ablaufende Assets zeitnah herunter. Replays verlängern URLs nicht.
