Sie werden abgerechnet, wenn der Anbieter Comfy abrechnet. Dieselbe Regel gilt für synchrone und [in der Warteschlange befindliche](/de/development/comfy-router/queue#idempotency-and-billing) Aufrufe, und ein [erneuter Versuch](/de/development/comfy-router/errors#retry-outcomes) mit demselben Schlüssel, der ein Ergebnis erneut ausliefert, ist keine zweite Abbuchung.

## Fakten zur Modellabrechnung

`GET /v2/models` und die Detailantwort eines Modells enthalten `billing.charges_on_policy_rejection`. Dieses Feld beschreibt eine Richtlinienablehnung, nicht jeden Fehler und auch keine Preisschätzung.

| Wert | Bedeutung |
| --- | --- |
| `yes` | Eine Richtlinienablehnung wird abgerechnet. |
| `no` | Eine Richtlinienablehnung wird nicht abgerechnet. |
| `unknown` | Das Verhalten wurde noch nicht festgestellt. Behandeln Sie es als möglicherweise abgerechnet. |

Vergleichen Sie diese Zeichenketten explizit: `"no"` ist in Python und JavaScript truthy. Behandeln Sie jeden nicht erkannten Wert als `unknown`. Eine Anfrage, die wegen fehlender Credits abgelehnt wird, meldet `insufficient_credits`.

## Abbuchungen abgleichen

Payloads von Anbietern können eigene Kosten- oder Nutzungszahlen enthalten; diese sind nicht die Abbuchung von Comfy. `X-Comfy-Credits-Used` ist nur für einige Modelle und nur bei erfolgreichen Antworten verfügbar. Wenn Router ein Ergebnis für denselben `Idempotency-Key` erneut ausliefert, wiederholt es den ursprünglichen Header mit `Idempotent-Replayed: true`. Der Aufruf wird trotzdem nur einmal abgerechnet, zählen Sie einen erneut ausgelieferten Header also nicht noch einmal mit. Ein fehlender Header bedeutet nicht, dass der Aufruf kostenlos war. Nutzen Sie [Workspace-Nutzung und Rechnungen](https://platform.comfy.org/settings/billing) für den Abgleich und bewahren Sie die Request-ID auf, wenn Sie eine Abbuchung untersuchen.
