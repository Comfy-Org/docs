<div className="router-quickstart-marker" />

Comfy Router bietet Ihnen eine einzige API für gehostete Bild- und Videomodelle unter `https://api.comfy.org`. Erstellen Sie einen API-Schlüssel in [Ihrem Comfy Workspace](https://platform.comfy.org/profile/api-keys?onboarding=router) und rufen Sie dann jedes Modell mit den offiziellen [Python- und TypeScript-SDKs](/de/development/api-development/sdks) oder über einfaches HTTP auf. Die Abrechnung erfolgt nach Nutzung: Standardmäßig wird für jede Anfrage Credits vom Guthaben Ihres Workspace abgebucht, ohne Abonnement. Preise und weitere Abrechnungsoptionen finden Sie unter [Router-Preise](/de/development/comfy-router/pricing).

<Note>
  **Ausgaben mit LiteLLM verfolgen?** Router meldet die USD-Kosten eines synchronen Laufs in dem Header, den LiteLLM liest, sodass Sie keine Preistabelle pflegen müssen. Siehe [Comfy Router mit LiteLLM verwenden](/de/development/comfy-router/litellm).
</Note>

<Steps titleSize="h2">
  <Step title="Credits zu Ihrem Workspace hinzufügen (optional)">
    Überspringen Sie diesen Schritt, wenn Ihr Workspace bereits über Guthaben verfügt oder einen Enterprise-Plan nutzt.

    Router berechnet Credits pro Anfrage, und ein Workspace ohne Credit-Guthaben erhält `402` mit `error_type: insufficient_credits`. Laden Sie Ihr Konto unter [Workspace-Abrechnung](https://platform.comfy.org/settings/billing) auf. Wie Kosten gemeldet werden, erfahren Sie unter [Router-Abrechnung](/de/development/comfy-router/billing).
  </Step>

  <Step title="API-Schlüssel erstellen">
    Erstellen Sie einen Schlüssel in [Ihrem Comfy Workspace](https://platform.comfy.org/profile/api-keys?onboarding=router). Legen Sie in einem Bash-kompatiblen Terminal fest:

    ```bash
    export COMFY_API_KEY="comfyui-..."
    ```

    Behalten Sie API-Schlüssel auf Ihrem Server oder in Ihrer lokalen Umgebung. Diese Beispiele sind für ein Terminal oder einen Server gedacht, nicht für JavaScript im Browser.

    Ein Workspace ohne Guthaben gibt `402` `insufficient_credits` selbst bei einem ungültigen Request-Body zurück, weil die Credit-Prüfung vor der Validierung des Bodys läuft. Fügen Sie zuerst Credits hinzu (Schritt 1), bevor Sie die Anfrage debuggen.
  </Step>

  <Step title="Anfrage in die Warteschlange stellen">
    Wählen Sie Ihre Sprache und führen Sie das Beispiel aus. Die Generierung kann einige Minuten dauern.

    <CodeGroup>

    ```python Python
    # Python 3.10+
    # Installation: python -m pip install "comfy-sdk>=0.3.0"
    # Als quickstart.py speichern und dann ausführen: python quickstart.py

    import asyncio

    from comfy_sdk import AsyncComfy

    # AsyncComfy liest COMFY_API_KEY aus der Umgebung.
    async def main():
        async with AsyncComfy() as client:
            handle = await client.models.submit(
                "byteplus/dreamina-seedance-2-5-260628",
                {
                    "content": [
                        {
                            "text": "A red fox trotting through a snowy pine forest",
                            "type": "text",
                        },
                    ],
                    "duration": 5,
                    "ratio": "16:9",
                    "resolution": "720p",
                },
            )
            print("request_id:", handle.request_id)

            # Abfragen, bis die Anfrage abgeschlossen ist, und dabei den vom Server genannten Retry-After-Wert abwarten.
            async for update in handle.iter_events():
                print(update.status, update.queue_position)

            result = await handle.get()

        print("result:", result)

    asyncio.run(main())
    ```

    ```bash cURL
    # 1. Anfrage absenden. Speichern Sie die request_id aus der 201-Antwort.
    curl https://api.comfy.org/v2/models/byteplus/dreamina-seedance-2-5-260628/requests \
      -H "X-API-Key: $COMFY_API_KEY" \
      -H "Idempotency-Key: $(uuidgen)" \
      -H "Content-Type: application/json" \
      -d '{"content": [{"text": "A red fox trotting through a snowy pine forest", "type": "text"}], "duration": 5, "ratio": "16:9", "resolution": "720p"}'

    # 2. Abfragen, bis der Status COMPLETED ist, und dabei jedes Mal den Retry-After-Wert abwarten.
    REQUEST_ID="paste-request-id-from-201-response"
    curl -i "https://api.comfy.org/v2/models/byteplus/dreamina-seedance-2-5-260628/requests/$REQUEST_ID/status" \
      -H "X-API-Key: $COMFY_API_KEY"

    # 3. Das Modell-Ergebnis abrufen.
    curl "https://api.comfy.org/v2/models/byteplus/dreamina-seedance-2-5-260628/requests/$REQUEST_ID" \
      -H "X-API-Key: $COMFY_API_KEY"
    ```

    ```typescript TypeScript
    // Node.js 22+
    // Installation: npm install "@comfyorg/sdk@>=0.4.0" --save-dev tsx
    // Als quickstart.mts speichern und dann ausführen: npx tsx quickstart.mts

    import { comfy } from "@comfyorg/sdk";

    // Comfy liest COMFY_API_KEY aus der Umgebung.
    const handle = await comfy.models.submit(
      "byteplus/dreamina-seedance-2-5-260628",
      {
        content: [
          {
            text: "A red fox trotting through a snowy pine forest",
            type: "text",
          },
        ],
        duration: 5,
        ratio: "16:9",
        resolution: "720p",
      },
    );
    console.log("requestId:", handle.requestId);

    // Abfragen, bis die Anfrage abgeschlossen ist, und dabei den vom Server genannten Retry-After-Wert abwarten.
    for await (const update of handle.events()) {
      console.log(update.status, update.queuePosition);
    }

    const result = await handle.get();

    console.log("result:", result.data);
    ```

    </CodeGroup>

    Jeder Submit-Aufruf des SDK erstellt einen Idempotenzschlüssel und verwendet ihn für automatische Wiederholungsversuche erneut.
    Das cURL-Beispiel erstellt einen mit `uuidgen`. Falls dieses nicht verfügbar ist, verwenden Sie einen anderen UUID-Generator.
    Details zu Status, Abbruch und Abholung der Ergebnisse finden Sie unter [Zustellung über die Warteschlange](/de/development/comfy-router/queue).
  </Step>
</Steps>

## Bild-zu-Video und Referenz-zu-Video

Dieselbe Seedance-Anfrage nimmt Bild-, Video- und Audio-Eingaben an. Fügen Sie Elemente zu `content` hinzu und setzen Sie für jedes die `role`. Die Rollen, die Sie senden, bestimmen den Ablauf, den Router ausführt. Die Abrechnung richtet sich nach den Medientypen in `content`, nicht nach den Rollen: Eine Anfrage mit einer Videoeingabe wird als Video-zu-Video abgerechnet, andernfalls wird eine Anfrage mit einem Bild als Bild-zu-Video abgerechnet, und eine reine Textanfrage wird als Text-zu-Video abgerechnet. Manche Modelle berechnen für Text-zu-Video und Bild-zu-Video denselben Tarif.

| Operation | `content`-Elemente |
|---|---|
| Text-zu-Video | ein `text`-Element |
| Bild-zu-Video | ein `text`-Element plus ein `image_url`-Element mit `role: first_frame` |
| Erstes-und-letztes-Bild | zusätzlich ein zweites `image_url`-Element mit `role: last_frame` |
| Referenz-zu-Video | ein `text`-Element plus `image_url`-Elemente mit `role: reference_image` und, bei Seedance 2.0 und 2.5, `video_url`-Elemente mit `role: reference_video` sowie `audio_url`-Elemente mit `role: reference_audio` |

Eine Bild-`url` kann eine öffentliche URL oder eine Zeichenkette `data:image/<format>;base64,<content>` sein. Reichen Sie ein, fragen Sie ab und holen Sie ab, genau wie im Schnellstart oben. Nur der Body ändert sich.

```bash Image-to-video
curl https://api.comfy.org/v2/models/byteplus/dreamina-seedance-2-5-260628/requests \
  -H "X-API-Key: $COMFY_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "content": [
      {"type": "text", "text": "The fox turns and runs into the trees"},
      {"type": "image_url", "image_url": {"url": "https://example.com/fox.png"}, "role": "first_frame"}
    ],
    "duration": 5,
    "resolution": "720p"
  }'
```

```bash Reference-to-video
curl https://api.comfy.org/v2/models/byteplus/dreamina-seedance-2-5-260628/requests \
  -H "X-API-Key: $COMFY_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "content": [
      {"type": "text", "text": "The character from the reference walks through a neon-lit market"},
      {"type": "image_url", "image_url": {"url": "https://example.com/character.png"}, "role": "reference_image"},
      {"type": "image_url", "image_url": {"url": "https://example.com/outfit.png"}, "role": "reference_image"}
    ],
    "omni_reference_task_type": "reference",
    "duration": 5,
    "ratio": "16:9",
    "resolution": "720p"
  }'
```

Bei Seedance 2.5 übernehmen Anfragen mit erstem Bild und mit erstem und letztem Bild das Ausgabeseitenverhältnis vom ersten Bild. Lassen Sie `ratio` weg oder senden Sie `adaptive`, denn ein konkretes Verhältnis wird mit `400` abgelehnt. Das Anfrageschema gilt für die gesamte Seedance-Familie und kann Rollen auflisten, die ein Modell ignoriert. Prüfen Sie daher das Feld `x-comfy-router-input-modalities` im [Eingabeschema](/de/development/comfy-router/models) jedes Modells, um zu sehen, welche Eingabearten dieses Modell akzeptiert. `reference_video` und `reference_audio` benötigen zum Beispiel ein Modell, das dort `video` oder `audio` auflistet.

### Referenzvideo bearbeiten oder verlängern

Bei Seedance 2.5 legt `omni_reference_task_type` fest, was das Modell mit den Referenzmedien tun soll: `reference` erzeugt ein neues Video, das von ihnen geführt wird, `edit` ändert einen `reference_video`-Clip, und `extend` verlängert einen. Ohne das Feld wählt das Modell die Aufgabe aus dem Prompt, und eine Bearbeitung behält Länge und Seitenverhältnis des Clips und ignoriert `duration` und `ratio`. Auf dem nativen BytePlus-Zweig wird ein expliziter Wert, der nicht zur Anfrage passt, vor dem Start der Generierung abgelehnt, daher wird er nicht abgerechnet. Ein alternativer Anbieter-Zweig, der beim Fallback genutzt oder mit `model_provider` gewählt wird, hat kein Aufgabenfeld: Er verwirft den Wert und lässt den Anbieter die Aufgabe ableiten, als wäre das Feld weggelassen worden. Das Verwerfen wird in `X-Comfy-Router-Dropped-Params` bekannt gegeben, in der Antwort einer synchronen Ausführungsroute und im `201` des Absendens in die Warteschlange. Die Warteschlangenroute hat keinen Fallback und erreicht einen alternativen Zweig daher nur über `model_provider`.

```bash Edit a reference video
curl https://api.comfy.org/v2/models/byteplus/dreamina-seedance-2-5-260628/requests \
  -H "X-API-Key: $COMFY_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "content": [
      {"type": "text", "text": "Make the fox bright red"},
      {"type": "video_url", "video_url": {"url": "https://example.com/fox.mp4"}, "role": "reference_video"}
    ],
    "omni_reference_task_type": "edit",
    "duration": -1,
    "resolution": "720p"
  }'
```

Eine Bearbeitung behält die Länge des Quellclips bei, senden Sie daher `"duration": -1` und lassen Sie `ratio` weg. Eine `extend`-Anfrage liefert nur das neu erzeugte Segment, mit der `duration`, die Sie senden.
