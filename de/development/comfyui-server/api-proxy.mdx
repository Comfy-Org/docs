Die [Comfy SDKs](/de/development/api-development/sdks) sprechen [Comfy API v2](/de/api-reference/v2/overview). Ein selbst gehostetes ComfyUI stellt v2 über [comfy-api-proxy](https://github.com/Comfy-Org/comfy-api-proxy) bereit, einen kleinen Open-Source-Dienst, der neben Ihrer Instanz läuft.

## Installieren und ausführen

```bash
pip install comfy-api-proxy
comfy-api-proxy
```

Standardmäßig leitet der Proxy Anfragen an das ComfyUI auf `127.0.0.1:8188` weiter und stellt die v2-API auf `127.0.0.1:8189` bereit. Mit `--comfyui` und `--port` ändern Sie beides.

Starten Sie ihn mit `--comfyui-base-dir /path/to/ComfyUI`, wenn Sie auch Modelldateien in Ihre Installation hochladen möchten.

## SDK auf den Proxy ausrichten

Legen Sie die Basis-URL fest und erstellen Sie den Client wie gewohnt:

```bash
export COMFY_BASE_URL="http://127.0.0.1:8189"
```

<CodeGroup>
```python Python
from comfy_sdk import Comfy

client = Comfy()
```

```typescript TypeScript
import { Comfy } from "@comfyorg/sdk";

const client = new Comfy();
```
</CodeGroup>

Alles im [SDK-Leitfaden](/de/development/api-development/sdks) funktioniert gegen den Proxy genauso wie gegen Comfy Cloud.

## Authentifizierung

Eine Authentifizierung ist standardmäßig nicht erforderlich. Wenn der Proxy mit einem statischen Bearer-Token konfiguriert ist, übergeben Sie dieses Token als API-Schlüssel des SDK: `Comfy(api_key="...")`.

<Warning>
  Der Proxy bindet standardmäßig nur an das Loopback-Interface. Wenn Sie ihn über Loopback hinaus verfügbar machen, zum Beispiel vor einem ComfyUI auf einer gemieteten GPU, konfigurieren Sie ein Bearer-Token oder schalten Sie einen authentifizierenden Reverse-Proxy davor.
</Warning>
