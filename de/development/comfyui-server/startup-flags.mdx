ComfyUI akzeptiert Befehlszeilenargumente, wenn es mit `python main.py` gestartet wird. Diese Seite dokumentiert alle Flags, die in [`comfy/cli_args.py`](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy/cli_args.py) definiert sind.

<Note>
  Benutzer von **Windows Portable** können Flags zu den `.bat`-Startdateien hinzufügen (zum Beispiel `run_nvidia_gpu.bat`). Siehe die [Windows Portable-Anleitung](/de/installation/comfyui_portable_windows) für Details.
</Note>

Führen Sie `python main.py --help` in Ihrem ComfyUI-Verzeichnis aus, um den integrierten Hilfetext anzuzeigen. Kombinieren Sie mehrere Flags nach Bedarf:

```bash
python main.py --listen 0.0.0.0 --port 8288 --disable-auto-launch --lowvram
```


## Netzwerk & Server

| Flag | Standard | Beschreibung |
|------|---------|-------------|
| `--listen` `[IP]` | `127.0.0.1` | IP-Adresse, auf der der Server lauscht. Eine kommagetrennte Liste wird unterstützt (z. B. `127.2.2.2,127.3.3.3`). Wenn kein Wert angegeben wird, wird standardmäßig `0.0.0.0,::` verwendet (alle IPv4- und IPv6-Schnittstellen). |
| `--port` | `8188` | Port, auf dem der Server lauscht. |
| `--tls-keyfile` `PATH` | Keine | Pfad zur Schlüsseldatei für TLS (SSL). Aktiviert HTTPS. Erfordert `--tls-certfile`. |
| `--tls-certfile` `PATH` | Keine | Pfad zur Zertifikatsdatei für TLS (SSL). Aktiviert HTTPS. Erfordert `--tls-keyfile`. |
| `--enable-cors-header` `[ORIGIN]` | disabled | Aktiviert CORS. Optionaler Origin oder `*` für alle Origins, wenn kein Wert angegeben wird. |
| `--max-upload-size` | `100` | Maximale Größe beim Hochladen in MB. |
| `--enable-compress-response-body` | disabled | Aktiviert die Komprimierung des HTTP-Antwortkörpers. |

<CodeGroup>
```bash
# Auf allen Schnittstellen lauschen (LAN-Zugriff)
python main.py --listen

# Auf einer bestimmten IP-Adresse lauschen
python main.py --listen 0.0.0.0

# Benutzerdefinierter Port mit HTTPS
python main.py --port 8443 --tls-keyfile key.pem --tls-certfile cert.pem
```
</CodeGroup>

## Start & Browser

| Flag | Standard | Beschreibung |
|------|---------|-------------|
| `--auto-launch` | `disabled` | ComfyUI beim Start automatisch im Standardbrowser öffnen. |
| `--disable-auto-launch` | `disabled` | Automatisches Starten des Browsers deaktivieren. |
| `--windows-standalone-build` | `disabled` | Komfortmodus für den portablen Windows-Build. Aktiviert den automatischen Start beim Hochfahren (entspricht `--auto-launch`) und schaltet das Assets-System ein. |

<Note>
  `--windows-standalone-build` setzt `auto_launch` auf `true` und aktiviert das Assets-System. `--disable-auto-launch` überschreibt den Browserstart und `--disable-assets` überschreibt das Assets-System. Um als Server ohne geöffneten Browser zu laufen, verwenden Sie `--disable-auto-launch`.
</Note>

```bash
# Server ohne Browserstart ausführen
python main.py --disable-auto-launch
```

## Präzision & Inferenz

<Note>
  Die Flags in den Gruppen **Global**, **UNET**, **VAE** und **Text Encoder** unten schließen sich innerhalb jeder Gruppe gegenseitig aus. Es kann immer nur ein Flag pro Gruppe verwendet werden.
</Note>

### Globales Gleitkomma

| Flag | Beschreibung |
|------|-------------|
| `--force-fp32` | Erzwingt fp32 global. Melden Sie, wenn dies die GPU-Leistung verbessert. |
| `--force-fp16` | Erzwingt fp16 global. Setzt außerdem `--fp16-unet`. |

### UNET-Präzision

| Flag | Beschreibung |
|------|-------------|
| `--fp32-unet` | Führt das Diffusionsmodell in fp32 aus. |
| `--fp64-unet` | Führt das Diffusionsmodell in fp64 aus. |
| `--bf16-unet` | Führt das Diffusionsmodell in bf16 aus. |
| `--fp16-unet` | Führt das Diffusionsmodell in fp16 aus. |
| `--fp8_e4m3fn-unet` | Speichert UNet-Gewichte in fp8 (e4m3fn). |
| `--fp8_e5m2-unet` | Speichert UNet-Gewichte in fp8 (e5m2). |
| `--fp8_e8m0fnu-unet` | Speichert UNet-Gewichte in fp8 (e8m0fnu). |

Jedes FP8-Flag-Suffix benennt ein 8-Bit-Gleitkomma-Layout aus der branchenüblichen FP8-Spezifikation (ONNX / OCP):
- **e4m3fn**: 4 Exponentenbits, 3 Mantissenbits. Gutes Gleichgewicht aus Präzision und Reichweite für Modellgewichte auf NVIDIA-Ada-Lovelace- und neueren GPUs.
- **e5m2**: 5 Exponentenbits, 2 Mantissenbits. Größere dynamische Reichweite, aber geringere Präzision als e4m3fn. Nützlich, wenn die Gewichtsbeträge stark variieren.
- **e8m0fnu**: 8 Exponentenbits, 0 Mantissenbits. Maximale dynamische Reichweite ohne Bruchteilpräzision. Wird typischerweise als Block-Skalierungsfaktor verwendet (nur Zweierpotenzen).

### VAE-Präzision

| Flag | Beschreibung |
|------|-------------|
| `--fp16-vae` | Führt den VAE in fp16 aus. Kann schwarze Bilder verursachen. |
| `--fp32-vae` | Führt den VAE in voller Präzision fp32 aus. |
| `--bf16-vae` | Führt den VAE in bf16 aus. |
| `--cpu-vae` | Führt den VAE auf der CPU aus (schließt sich nicht mit den VAE-Präzisions-Flags aus). |

### Text-Encoder-Präzision

| Flag | Beschreibung |
|------|-------------|
| `--fp8_e4m3fn-text-enc` | Speichert Text-Encoder-Gewichte in fp8 (e4m3fn). |
| `--fp8_e5m2-text-enc` | Speichert Text-Encoder-Gewichte in fp8 (e5m2). |
| `--fp16-text-enc` | Speichert Text-Encoder-Gewichte in fp16. |
| `--fp32-text-enc` | Speichert Text-Encoder-Gewichte in fp32. |
| `--bf16-text-enc` | Speichert Text-Encoder-Gewichte in bf16. |

Die Erklärung der einzelnen FP8-Format-Suffixe finden Sie im Abschnitt [UNET-Präzision](#unet-präzision).

### Weitere Inferenz-Optionen

| Flag | Standard | Beschreibung |
|------|---------|-------------|
| `--fp16-intermediates` | disabled | Experimentell: verwendet fp16 für Zwischentensoren zwischen Nodes statt fp32. |
| `--force-channels-last` | disabled | Erzwingt das Speicherformat channels-last während der Inferenz. |
| `--supports-fp8-compute` | disabled | Verhält sich, als ob das Gerät fp8-Berechnungen unterstützt. |
| `--enable-triton-backend` | disabled | Aktiviert das Triton-Backend in comfy-kitchen. Beim Start standardmäßig deaktiviert. |
| `--disable-triton-backend` | disabled | Deaktiviert das Triton-Backend von comfy-kitchen erzwungenermaßen und überschreibt dabei `--enable-triton-backend`. |

## Vorschau

| Flag | Standard | Beschreibung |
|------|----------|--------------|
| `--preview-method` | `none` | Vorschaumethode für Sampler-Nodes. Optionen: `none`, `auto`, `latent2rgb`, `taesd`. |
| `--preview-size` | `512` | Maximale Größe der Bildvorschau in Pixeln. |

## Cache

<Note>
  Die Flags für den Cache-Modus schließen sich gegenseitig aus. Es sollte nur eines von `--cache-ram`, `--cache-classic`, `--high-ram`, `--cache-lru` oder `--cache-none` verwendet werden.
</Note>

| Flag | Standard | Beschreibung |
|------|---------|-------------|
| `--cache-ram` `[GB] [GB]` | aktiviert (Standardmodus) | Caching auf Basis von RAM-Druck. Erster Wert: Schwellenwert für den aktiven Cache in GB. Optionaler zweiter Wert: Schwellenwert für Inaktiv-Cache/Anheften in GB. Ohne Werte: aktiv = 10% des System-RAM (Min. 2 GB, Max. 10 GB); inaktiv = 100% des System-RAM (Max. 128 GB). Akzeptiert höchstens zwei Werte. |
| `--cache-classic` | — | Verwendet den alten aggressiven Caching-Stil. |
| `--high-ram` | deaktiviert | Kann die Leistung auf Systemen mit reichlich RAM leicht verbessern oder auf Systemen, bei denen die Nutzung der Auslagerungsdatei dem erneuten Laden von Modellen vorgezogen wird. Aktiviert außerdem klassisches Caching. |
| `--cache-lru` `N` | `0` (deaktiviert) | LRU-Caching mit maximal N zwischengespeicherten Node-Ergebnissen. Keine feste Obergrenze; begrenzt durch verfügbaren RAM/VRAM. Kann mehr RAM/VRAM verbrauchen. |
| `--cache-none` | — | Reduzierte RAM/VRAM-Nutzung; führt bei jedem Lauf jeden Node erneut aus. |
| `--force-output-rerun` | deaktiviert | Führt Output-Nodes bei jedem Lauf erneut aus, auch bei einem Cache-Treffer, sodass sie ihre Dateien erneut schreiben. Ihre Eingänge werden aus dem Cache wiederverwendet, solange die zwischengespeicherten Ergebnisse noch vorhanden sind, sodass Modelle und Latents nicht neu berechnet werden. API-Nodes sind ausgenommen, da ein erneuter Lauf einen kostenpflichtigen externen Aufruf wiederholt, und Output-Nodes, die von einem zwischengespeicherten expandierenden Node erzeugt wurden, werden nicht erneut ausgeführt. Für Multi-Tenant-Server, die Ausgabedateien nach jeder Aufgabe löschen. |

<Note>
  ComfyUI verwendet zwischengespeicherte Node-Ergebnisse zwischen Läufen derselben Sitzung wieder, was wiederholte Läufe schneller macht. Verwenden Sie `--cache-none`, wenn jeder Lauf stattdessen mit einem leeren Cache starten soll, zum Beispiel beim Debuggen eines Workflows oder um eine zwischengespeicherte Wiederverwendung zwischen Läufen auszuschließen. Jeder Node wird erneut ausgeführt, daher dauern Generierungen länger. Es handelt sich um ein Start-Flag, daher müssen Sie ComfyUI neu starten, damit es wirksam wird.
</Note>

| `--use-split-cross-attention` | Split-Cross-Attention-Optimierung verwenden. |
| `--use-quad-cross-attention` | Subquadratische Cross-Attention-Optimierung verwenden. |
| `--use-pytorch-cross-attention` | PyTorch 2.0 Cross-Attention verwenden. |
| `--use-sage-attention` | Sage-Attention verwenden. |
| `--use-flash-attention` | FlashAttention verwenden. |
| `--use-ck-attention` | Comfy-Kitchen-Attention verwenden. Erfordert Hardware-Support für die INT8-Kernel. |
| `--disable-xformers` | xformers deaktivieren. |

## VRAM & Speicher

Asynchrones Weight-Offloading ist auf Nvidia- und AMD-GPUs standardmäßig aktiviert, und dynamischer VRAM wird automatisch aktiviert, sofern er unterstützt wird. Die folgenden Flags überschreiben diese Standardeinstellungen.

<Note>
  Die VRAM-Modus-Flags (`--gpu-only`, `--highvram`, `--lowvram`, `--novram`, `--cpu`) schließen sich gegenseitig aus.
</Note>

| Flag | Standard | Beschreibung |
|------|---------|-------------|
| `--gpu-only` | – | Alles auf der GPU speichern und ausführen (Text-Encoder, CLIP usw.). |
| `--highvram` | – | Modelle im GPU-Speicher behalten, statt sie nach der Nutzung auf die CPU zu entladen. |
| `--lowvram` | – | Keine Wirkung, wenn dynamischer VRAM aktiviert ist. Andernfalls werden Text-Encoder auf der CPU ausgeführt. |
| `--novram` | – | Minimale VRAM-Nutzung, wenn `--lowvram` nicht ausreicht. |
| `--cpu` | – | CPU für alles verwenden (langsam). |
| `--reserve-vram` `GB` | Vom Betriebssystem abhängig | VRAM in GB, der für das Betriebssystem und andere Software reserviert wird. |
| `--vram-headroom` `GB` | `0` | Zusätzlicher VRAM in GB, den dynamischer VRAM über dem standardmäßigen Headroom hinaus freihalten soll. ComfyUI versucht, diesen VRAM-Betrag vollständig frei und ungenutzt zu halten, wobei sogar der von anderen Anwendungen genutzte VRAM mitgezählt wird. |
| `--disable-nvml-pressure` | deaktiviert | CUDA statt NVML verwenden, um den Speicherdruck des dynamischen VRAM zu melden. |
| `--async-offload` `[NUM_STREAMS]` | Auf Nvidia und AMD aktiviert | Asynchrones Weight-Offloading. Optionale Anzahl an Streams (Standard: 2). |
| `--disable-async-offload` | – | Asynchrones Weight-Offloading deaktivieren. |
| `--disable-dynamic-vram` | – | Dynamischen VRAM deaktivieren; schätzungsbasierte Modellladung verwenden. |
| `--enable-dynamic-vram` | Automatisch auf Nvidia, ROCm 7.14+ | Dynamischen VRAM auf Systemen aktivieren, auf denen er standardmäßig nicht aktiviert ist. |
| `--fast-disk` | falsch | Datenträgerbasiertes dynamisches Laden und Offload statt nicht angeheftetem RAM erzwingen. Nützlich bei schnellen NVMe-Laufwerken. Wenn weder dieses Flag noch `--disable-fast-disk` gesetzt ist, werden datenträgerbasiertes Laden und Offload automatisch aktiviert, sofern sich jede Modelldatei auf einem als schnell erkannten Speicher befindet. |
| `--disable-fast-disk` | deaktiviert | Datenträgerbasiertes dynamisches Laden und Offload deaktivieren, sodass stattdessen nicht angehefteter RAM verwendet wird. Überschreibt `--fast-disk` und die automatische Erkennung. |
| `--disable-cuda-graphs` | deaktiviert | CUDA-Graphen deaktivieren. |
| `--disable-comfy-compiler` | deaktiviert | Den Comfy-Modellcompiler einschließlich seiner CUDA-Graph-Unterfunktion deaktivieren. |
| `--assert-graph-breaks` | deaktiviert | Bei Graph Breaks des Comfy-Modellcompilers abbrechen. |
| `--force-non-blocking` | deaktiviert | Nicht blockierende Tensor-Operationen erzwingen. Kann auf Nicht-Nvidia-Systemen helfen; kann einige Workflows beeinträchtigen. |
| `--disable-smart-memory` | deaktiviert | Aggressiv in den RAM auslagern, statt Modelle im VRAM zu behalten. |
| `--disable-pinned-memory` | deaktiviert | Die Nutzung von angeheftetem Speicher deaktivieren. |
| `--mmap-torch-files` | deaktiviert | mmap beim Laden von ckpt/pt-Dateien verwenden. |
| `--disable-mmap` | deaktiviert | mmap beim Laden von safetensors nicht verwenden. |

## Leistung & Debugging

| Flag | Standard | Beschreibung |
|------|----------|--------------|
| `--fast` `[OPT...]` | disabled | Aktivieren Sie experimentelle Optimierungen, die Qualität oder Stabilität beeinträchtigen können. `--fast` allein aktiviert alle. Einzelne Optionen: `fp16_accumulation`, `fp8_matrix_mult`, `cublas_ops`, `autotune`. |
| `--deterministic` | disabled | Verwenden Sie nach Möglichkeit langsamere deterministische PyTorch-Algorithmen. Dies garantiert nicht in allen Fällen identische Bilder. |
| `--default-hashing-function` | `sha256` | Hashfunktion für den Vergleich doppelter Dateinamen/Inhalte. Auswahl: `md5`, `sha1`, `sha256`, `sha512`. |
| `--debug-hang` | disabled | Aktivieren Sie Stacktrace-Dumps bei Ctrl-C, um Hänger zu debuggen. |

```bash
# Alle schnellen Optimierungen aktivieren (experimentell)
python main.py --fast

# Nur bestimmte Optimierungen aktivieren
python main.py --fast fp16_accumulation cublas_ops
```

## Custom Nodes und API-Nodes

| Flag | Standard | Beschreibung |
|------|---------|-------------|
| `--disable-all-custom-nodes` | disabled | Das Laden aller Custom Nodes deaktivieren. |
| `--whitelist-custom-nodes` `FOLDER...` | — | Custom-Node-Ordner, die auch dann geladen werden, wenn `--disable-all-custom-nodes` gesetzt ist. |
| `--disabled-nodes-config` `PATH` | — | Pfad zu einer YAML-Datei mit einer Liste von Node-IDs, die deaktiviert werden sollen. Die Datei muss eine Liste `disabled_nodes` mit Node-ID-Strings enthalten. |
| `--disable-partner-nodes` | disabled | Das Laden von Partner-Nodes (den kostenpflichtigen API-Nodes) deaktivieren. Das Frontend behält seinen Internetzugriff. |
| `--offline` | disabled | Verhindert die Kommunikation des Frontends mit dem Internet durch eine restriktive Content-Security-Policy. Deaktiviert außerdem Partner-Nodes. |
| `--disable-api-nodes` | disabled | Veralteter Alias für `--offline`. Verwenden Sie `--offline` oder `--disable-partner-nodes`, um nur Partner-Nodes zu deaktivieren. |
| `--disable-metadata` | disabled | Das Speichern von Prompt-Metadaten in Ausgabedateien deaktivieren. |

<Note>
  `--offline` ändert außerdem, was der Browser laden darf. Das Flag fügt eine Content-Security-Policy hinzu, die die Seite auf Ressourcen beschränkt, die ComfyUI selbst ausliefert. Dadurch werden Bilder, Schriftarten, Medien, Frames und Netzwerkanfragen von anderen Ursprüngen blockiert, und Partner-Nodes (API-Nodes) werden gar nicht erst registriert. Wenn eine Vorschau oder ein Thumbnail, das normalerweise geladen wird, nach einem Neustart fehlt, prüfen Sie die Startargumente auf dieses Flag, bevor Sie den Node untersuchen. `--disable-partner-nodes` verhindert nur das Laden von Partner-Nodes und lässt den übrigen Internetzugriff des Frontends unangetastet.
</Note>

```bash
# Fehlerbehebung bei Problemen mit Custom Nodes
python main.py --disable-all-custom-nodes

# Nur bestimmte Custom Nodes zulassen
python main.py --disable-all-custom-nodes --whitelist-custom-nodes ComfyUI-Manager
```

| Flag | Standardwert | Beschreibung |
|------|--------------|--------------|

| `--list-feature-flags` | — | Gibt die bekannten, über die CLI setzbaren Feature-Flags als JSON aus und beendet das Programm. |

```bash
# Verfügbare Feature-Flags auflisten
python main.py --list-feature-flags

# Feature-Flags setzen
python main.py --feature-flag show_signin_button=true
```

| `--disable-product-tips` | deaktiviert | Blendet die Konsolenhinweise zu kommerziellen Produkten und Deployments von Comfy-Org aus. Entspricht dem Setzen von `COMFYUI_DISABLE_PRODUCT_TIPS=1`. Die Hinweise werden auch bei `CI`, `--dont-print-server` oder `--windows-standalone-build` übersprungen. |
| `--multi-user` | deaktiviert | Speicherung pro Benutzer aktivieren. |
| `--quick-test-for-ci` | deaktiviert | Schneller Starttest für CI. Beendet sich direkt nach der Initialisierung. |
