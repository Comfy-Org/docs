Workflows, die über die Comfy Cloud API übermittelt werden, nutzen dieselben Credits und Parallelitätslimits wie andere Cloud-Workflows.

## Credits und Nutzung

API-Anfragen greifen auf dieselbe monatliche Credit-Zuweisung zurück wie die Comfy Cloud Web-UI. Es gibt keinen separaten API-Credit-Pool. Die in jedem Tarif enthaltenen Credits, Aufladeoptionen und Laufzeitbeschränkungen pro Workflow gelten für API-Aufträge genauso wie für UI-Aufträge.

Die monatlichen Credit-Mengen und Aufladeoptionen finden Sie auf der [Preisseite](https://www.comfy.org/cloud/pricing?utm_source=docs&utm_campaign=cloud-api). Aufladungen können Sie über Ihr Konto-Dashboard erwerben.

## Parallelitätslimits

Sie können mehrere Workflows absenden, ohne auf den Abschluss vorheriger Aufträge zu warten. Aufträge laufen parallel, bis zum Limit Ihres Abonnement-Tarifs:

| Plan     | Gleichzeitige Workflows |
| :------- | :---------------------- |
| Standard | 1                       |
| Creator  | 3                       |
| Pro      | 5                       |

Team-Tarife führen mehr gleichzeitige Workflows pro Mitglied aus als Pro. Informationen zur Parallelität Ihres Kontos finden Sie auf [platform.comfy.org](https://platform.comfy.org). Weitere Aufträge werden in die Warteschlange gestellt und ausgeführt, sobald Slots frei werden.

Ist die Warteschlange voll, versuchen die SDKs innerhalb eines begrenzten Budgets erneut, bevor sie `QueueFull` auslösen.

Bei Team- und Enterprise-Tarifen gilt die Parallelität pro Mitglied: Jedes Mitglied im Workspace hat sein eigenes Parallelitätslimit, sodass laufende Aufträge eines Mitglieds nie die eines anderen blockieren.

<Info>
  Mehr als einen Auftrag gleichzeitig auszuführen, wird nur über die API unterstützt. Die Comfy Cloud UI führt pro Person jeweils einen Workflow aus, und im Editor in die Warteschlange gestellte Workflows werden in ihrer Reihenfolge ausgeführt. Details zu den Abonnements finden Sie unter [Preispläne](https://www.comfy.org/cloud/pricing?utm_source=docs&utm_campaign=cloud-api).
</Info>

## Limits für Laufzeit und Warteschlange

Jeder Cloud-Workflow hat eine maximale Laufzeit. Eine Aufgabe, die das Limit überschreitet, wird automatisch abgebrochen:

| Tarif    | Maximale Laufzeit |
| :------- | :---------------- |
| Standard | 30 Minuten        |
| Creator  | 30 Minuten        |
| Pro      | 1 Stunde          |

Sie können bis zu 100 Workflows gleichzeitig in die Warteschlange einreihen. Um ein Parallelitätslimit für Teams zu erhöhen, [kontaktieren Sie den Support](https://support.comfy.org/).

## Abrechnung für Deployments {#deployment-billing}

Ein [Deployment](/de/development/serverless/overview) eines benutzerdefinierten Builds wird über Comfy Credits mit GPU-Zeit für seine Worker und Speicher für seine Modelle abgerechnet.

### Fallen Kosten für die Speicherung nicht deployter Builds an?

Nein. Builds und ihre Versionen werden kostenlos gespeichert. Die Speicherabrechnung beginnt mit dem Deployment:

- Wenn Sie eine Version deployen, kopiert Comfy Cloud ihre Modelle auf Netzwerkspeicher, den die Worker des Deployments gemeinsam nutzen. Comfy Cloud berechnet den Speicher pro GB und Monat, solange ein Deployment des Builds in dieser Region existiert, auch während das Deployment gestoppt ist. Modelle, die eine Aufgabe aus Ihrer [Workspace-Bibliothek](/de/development/deploy/cloud-custom-builds#add-your-own-lora-or-model) verwendet, werden nicht dorthin kopiert. Der Worker lädt sie für die Aufgabe herunter.
  - Modelle, die Sie [zu einem Deployment hinzufügen](/de/development/serverless/overview#add-a-model-to-a-running-deployment), werden ebenfalls dorthin kopiert und werden auf diesen Speicher angerechnet.
- Der lokale Datenträger auf jedem Worker verursacht über den GPU-Preis hinaus keine zusätzlichen Kosten.
- Wenn Sie ein Deployment löschen, wird dessen Compute freigegeben. Die Abrechnung des Netzwerkspeichers endet, wenn Sie das letzte Deployment löschen, das ihn verwendet.

Die Preise für Speicher und GPU finden Sie unter [**Limits**](https://platform.comfy.org/settings/limits) auf der Developer Platform. Prüfen Sie dort **Deployment pricing**. Das Panel **Estimated cost** im Deploy-Dialog zeigt außerdem die GPU-Zeit und den Modellspeicher eines Deployments.

### Wie werden Always-warm-Worker abgerechnet?

[Always-warm-Worker](/de/development/serverless/overview#worker-skalieren) (`--min` in comfy-cli) werden mit GPU-Zeit abgerechnet, solange sie laufen, unabhängig davon, ob sie Aufträge verarbeiten.

Worker über dieser Anzahl, bis zu **Max workers** (`--max`), starten, wenn Aufträge eintreffen. Sie werden ab dem Moment ihres Starts mit GPU-Zeit abgerechnet, während ihrer Aufträge und für die Leerlaufzeit nach ihrem letzten Auftrag, bevor sie freigegeben werden. Standardmäßig bleibt ein Worker 3 Minuten nach seiner letzten Aufgabe aktiv. Sie können diese Zeit, von 30 Sekunden bis 20 Minuten, in **Keep worker up after a job** festlegen, wenn Sie das Deployment auf der Developer Platform erstellen. Mit `0` Always-warm-Workern endet die GPU-Abrechnung, sobald diese Leerlaufzeit abläuft und jeder Worker freigegeben ist. Die nächste Aufgabe wartet, während eine GPU startet.

Wenn Ihr Workspace keine Credits mehr hat, werden seine Deployments gestoppt.

Die GPU-Preise finden Sie unter [**Limits**](https://platform.comfy.org/settings/limits) auf der Developer Platform. Prüfen Sie dort **Deployment pricing**. Die Preise gelten pro Worker und pro Stunde Laufzeit.
