## Basisstandards

### 1. Nutzen für die Community
Custom Nodes müssen der ComfyUI-Community wertvolle Funktionalität bieten.

Vermeiden Sie:
- Übermäßige Eigenwerbung
- Identitätsanmaßung oder irreführendes Verhalten
- Bösartiges Verhalten
- Eigenwerbung ist nur im dafür vorgesehenen Abschnitt Ihres Einstellungsmenüs zulässig
- Obere und seitliche Menüs sollten ausschließlich nützliche Funktionalität enthalten

### 2. Node-Kompatibilität
Beeinträchtigen Sie nicht die Operationen anderer Custom Nodes (Installation, Updates, Entfernen).
- Bei Abhängigkeiten von anderen Custom Nodes:
  - Zeigen Sie klare Warnungen an, wenn die abhängige Funktionalität verwendet wird
  - Stellen Sie Beispiel-Workflows bereit, die die erforderlichen Nodes demonstrieren

### 3. Rechtliche Konformität
Alle geltenden Gesetze und Vorschriften müssen eingehalten werden.

### 5. Qualitätsanforderungen
Nodes müssen voll funktionsfähig, gut dokumentiert und aktiv gepflegt sein.

### 6. Richtlinien für Forks
Geforkte Nodes müssen:
  - eindeutig andere Namen als das Original haben
  - deutliche Unterschiede in Funktionalität oder Code aufweisen

Nachfolgend finden Sie die Standards, die für die Veröffentlichung von Custom Nodes im Registry erfüllt sein müssen.

## Sicherheitsstandards

Custom Nodes sollten sicher sein. Wir werden zunächst mit Custom Nodes arbeiten, die gegen diese Standards verstoßen, damit sie überarbeitet werden. Wenn es wichtige Funktionalität gibt, die vom Kern bereitgestellt werden sollte, fordern Sie diese bitte im [rfcs repo](https://github.com/comfy-org/rfcs) an.

### eval/exec-Aufrufe

#### Richtlinie
Die Verwendung der Funktionen `eval` und `exec` ist in Custom Nodes aus Sicherheitsgründen verboten.

#### Begründung
Diese Funktionen können die Ausführung beliebigen Codes ermöglichen und dadurch potenzielle Schwachstellen für Remote Code Execution (RCE) schaffen, wenn Benutzereingaben verarbeitet werden. Workflows mit Nodes, die Benutzereingaben an `eval` oder `exec` weitergeben, könnten für verschiedene Cyberangriffe ausgenutzt werden, darunter:
- Keylogging
- Ransomware
- Sonstige Ausführung bösartigen Codes

### subprocess für pip install

#### Richtlinie
Die Installation von Paketen zur Laufzeit über subprocess-Aufrufe ist nicht zulässig.

#### Begründung
- Erster Punkt
Der ComfyUI Manager wird mit ComfyUI ausgeliefert und ermöglicht dem Benutzer die Installation von Abhängigkeiten
- Eine zentralisierte Verwaltung von Abhängigkeiten verbessert Sicherheit und Benutzererfahrung
- Hilft, potenzielle Supply-Chain-Angriffe zu verhindern
- Beseitigt die Notwendigkeit mehrfacher Neuladevorgänge von ComfyUI

### Code-Obfuskierung

#### Richtlinie
Code-Obfuskierung ist in Custom Nodes verboten.

#### Begründung
Obfuskierter Code:
- Ist nicht überprüfbar und wahrscheinlich bösartig
