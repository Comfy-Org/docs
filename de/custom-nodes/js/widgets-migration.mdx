Widget-Werte liegen jetzt in einem Pinia-basierten Store statt direkt auf der Widget-Instanz. Widget-Namen müssen pro Node eindeutig sein, und das Umbenennen eines Widgets gelingt nur, wenn der neue Name frei ist. `node.widgets` kann außerdem `undefined` sein, bis es erstmals zugewiesen wird.

## Galeriewerte nach der PrimeVue-Ersetzung

Das Vue-Widget `galleria` akzeptiert ein Array aus Bild-URL-Zeichenketten, passend zum `GALLERIA`-Eingabeschema. Bei mehreren Bildern werden Miniaturansichten sowie Schaltflächen für Vorherige und Nächste angezeigt. Die Navigation endet beim ersten und beim letzten Bild.

PrimeVue-Bildobjekte mit `itemImageSrc` oder `thumbnailImageSrc` werden nicht mehr unterstützt. Konvertieren Sie sie in URL-Zeichenketten. Das Widget liest keine PrimeVue-Optionen wie `showThumbnails`, `showItemNavigators`, `circular`, `autoPlay`, `transitionInterval`, `showIndicators`, `numVisible` oder `responsiveOptions` mehr aus. Erweiterungen, die diese Steuerelemente benötigen, müssen ein eigenes Galerie-Widget bereitstellen.

## Widget-Namen müssen eindeutig und stabil sein

Zwei Widgets am selben Node dürfen nicht denselben Namen tragen. Wenn Sie ein zweites Widget mit einem Namen hinzufügen, der bereits verwendet wird, benennt das Frontend das neue Widget mit einem nummerierten Suffix um, etwa `strength#1`, sobald sich der Node in einem Graphen befindet. Eine Suche über den ursprünglichen Namen findet dann nur das erste Widget:

```js
node.addWidget('number', 'strength', 0, () => {})
const second = node.addWidget('number', 'strength', 1, () => {})
second.name // 'strength#1', sobald sich der Node in einem Graphen befindet
```

Geben Sie jedem Widget einen eindeutigen Namen.

Wenn Sie einem registrierten Widget einen neuen `widget.name` zuweisen, wird sein gespeicherter Wert auf den neuen Namen übertragen. Wenn ein anderes Widget am Node diesen Namen bereits verwendet, wird die Zuweisung ignoriert und `widget.name` behält seinen alten Wert. Prüfen Sie `widget.name` daher anschließend. Eingabe-Slots, die das Widget über den Namen referenzieren, werden nicht aktualisiert. Entfernen Sie ein Widget nicht und fügen Sie kein neues hinzu, um es umzubenennen: `removeWidget()` löscht den gespeicherten Wert und leert Eingabe-Slots, die direkt an das Widget gebunden sind. Eingabe-Slots, die es nur über den Namen referenzieren, behalten diesen Namen bei.

## `node.widgets` kann undefined sein

`node.widgets` gibt `undefined` zurück, bis es mindestens einmal zugewiesen wurde.
Initialisieren Sie das Array, bevor Sie Widgets hinzufügen:

```ts
export function nodeCreated(node: LGraphNode) {
  node.widgets ??= []
  node.widgets.push(myWidget)
}
```

Sichern Sie Lesezugriffe auf dieselbe Weise ab:

```ts
const widgetCount = node.widgets?.length ?? 0
```

**Das Setzen von `node.widgets = undefined` löscht den Wert.** Ein späterer Lesezugriff gibt erneut `undefined` zurück, nicht `[]`.

**Änderungen, die vor dem Anhängen des Nodes an einen Graphen vorgenommen werden, werden automatisch übernommen.** Für den üblichen Fall, Widgets in einem Konstruktor oder in `onNodeCreated` zu erstellen, müssen Sie selbst nichts aufrufen.

`node.widgets` erscheint in `Object.keys(node)` und in Objekt-Spreads wie `{...node}`.

## `node.addCustomWidget()` statt direktem Anhängen an `node.widgets` bevorzugen

Widgets, die mit `node.addWidget()`, `node.addCustomWidget()` oder
`node.addDOMWidget()` hinzugefügt werden, werden automatisch im Store registriert. Ein einfaches Objekt,
das direkt an `node.widgets` angehängt wird, wird ebenfalls in eine Widget-Instanz umgewandelt
und registriert, sobald sich der Node in einem Graphen befindet. Die Umwandlung erfolgt normalerweise
an Ort und Stelle, aber ein eingefrorenes Objekt oder eines mit nicht konfigurierbaren Eigenschaften wird
durch ein separates Widget ersetzt. Behalten Sie daher das Widget, das `addCustomWidget()` zurückgibt, oder
lesen Sie es aus `node.widgets` wieder aus. `addCustomWidget()` ist weiterhin der empfohlene
Aufruf: Er gibt das Widget zurück und stellt den gespeicherten Wert des Widgets wieder her, wenn ein
Workflow geladen wird.

```js
node.addCustomWidget({
  name: 'my_widget',
  type: 'custom',
  value: '',
  options: {},
  draw(ctx, node, width, y, height) {},
  mouse(event, pos, node) {}
})
```

Wenn Sie `widget.value` lesen oder schreiben, bevor der Node an einen Graphen angehängt wird,
wird der Wert lokal gehalten und beim Anhängen mit dem Store synchronisiert. Es gehen keine Werte
verloren, aber eine vom Store gesteuerte UI (etwa das rechte Panel) sieht den Wert bis dahin nicht.

## Widgets mit `node.removeWidget()` entfernen

Verwenden Sie `node.removeWidget(widget)`, um ein Widget zu entfernen. Wenn Sie `node.widgets` direkt per Splicing bearbeiten, wird die Slot-Bereinigung übersprungen, und der Wert des entfernten Widgets bleibt im Store, bis der Node selbst aus dem Graphen entfernt wird.

## Agent-Änderungen rufen `setValue` ohne Zeigerereignis auf

Wenn der In-App-Agent ein Widget ändert, das eine `BaseWidget`-Instanz ist, ruft das Frontend `widget.setValue(value, { node, canvas })` auf, also dieselbe Methode, die auch eine Benutzerbearbeitung durchläuft. Zuvor hat es `widget.value` direkt zugewiesen und dann `callback` und `onWidgetChanged` selbst aufgerufen. Das gilt auch für einfache Objekte, die mit `addCustomWidget()` hinzugefügt oder an `node.widgets` angehängt werden, da das Frontend sie in `BaseWidget`-Instanzen umwandelt. DynamicGroup-Controller für die Zeilenanzahl und hochgestufte Subgraph-Host-Widgets erhalten weiterhin die direkte Zuweisung.

Wenn Sie `setValue` überschreiben, akzeptieren Sie Optionen in der Form `{ node, e?, canvas? }`: `e` ist bei diesen Aufrufen nie gesetzt, und `canvas` kann ebenfalls fehlen. Lesen Sie `options.e` oder `options.canvas` nicht, ohne sie vorher zu prüfen. Ein Wrapper, der das ursprüngliche `setValue` nur mit dem Wert aufruft, funktioniert weiterhin: Die Optionen haben standardmäßig den Wert `{ node: widget.node }`.

`callback` und `onWidgetChanged` erhalten jetzt den Wert, den das Widget akzeptiert hat, nicht den Wert, den der Agent gesendet hat. Ein Zahlen-Widget begrenzt den Wert auf `min`/`max` und wandelt eine numerische Zeichenkette in eine Zahl um. In `callback` ist `e` `undefined`, und `pos` ebenfalls, wenn kein Canvas vorhanden ist.

`setValue` kehrt ohne Änderung zurück, wenn der Wert, nachdem ein Zahlen-Widget ihn begrenzt und umgewandelt hat, bereits identisch (`===`) mit dem aktuellen Wert ist. Daher ändert `'5'` bei einem Zahlen-Widget mit dem Wert `5` nichts. Es kehrt auch zurück, wenn ein Zahlen-Widget einen Wert erhält, für den `Number(value)` `NaN` ist. Weder `callback` noch `onWidgetChanged` wird ausgelöst, und die Graph-Version ändert sich nicht. Eine numerische Zeichenkette wie `'7'` wird umgewandelt und angewendet.

## `useWidgetValueStore()` nicht aus Erweiterungscode aufrufen

Rufen Sie `useWidgetValueStore()` nicht aus Erweiterungen auf. Verwenden Sie stattdessen `node.widgets`, `node.addWidget()` / `addCustomWidget()` / `removeWidget()` und `widget.value`. Die interne Schlüsselbildung des Stores und seine Abhängigkeit von Pinia sind keine unterstützte Schnittstelle für Erweiterungen.
