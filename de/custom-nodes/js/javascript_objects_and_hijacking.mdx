## LiteGraph

Die ComfyUI-Oberfläche baut auf [LiteGraph](https://github.com/jagenjo/litegraph.js) auf. Ein Großteil der ComfyUI-Funktionalität wird von LiteGraph bereitgestellt. Wenn Sie komplexere Nodes entwickeln, ist es daher wahrscheinlich hilfreich, dieses Repository zu klonen und die Dokumentation zu durchsuchen, die Sie unter `doc/index.html` finden.

## ComfyApp

Das `app`-Objekt (stets erreichbar über `import { app } from "../../scripts/app.js";`) repräsentiert die im Browser laufende Comfy-Anwendung und enthält eine Reihe nützlicher Eigenschaften und Funktionen, von denen einige unten aufgeführt sind.

<Note>
**Veraltet:** Das Hijacking/Monkey-Patching von Funktionen auf `app` oder Prototypen ist veraltet und kann sich in naher Zukunft jederzeit ändern. Verwenden Sie stattdessen die offiziellen [Erweiterungs-Hooks](/de/custom-nodes/js/javascript_hooks) und die [Context Menu API](/de/custom-nodes/js/context-menu-migration).
</Note>

<Warning>Das Hijacking von Funktionen auf `app` wird nicht empfohlen, da Comfy ständig weiterentwickelt wird und sich das Kernverhalten ändern kann.</Warning>

### Eigenschaften

Wichtige Eigenschaften von `app` sind (die Liste ist nicht vollständig):

| Eigenschaft     | Inhalt                                                                                                                                                          |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `canvas`        | Ein LGraphCanvas-Objekt, das die aktuelle Benutzeroberfläche darstellt. Es enthält einige potenziell interessante Eigenschaften wie `node_over` und `selected_nodes`. |
| `canvasEl`      | Das DOM-`<canvas>`-Element                                                                                                                                      |
| `graph`         | Eine Referenz auf das LGraph-Objekt, das den aktuellen Graphen beschreibt                                                                                       |
| `runningNodeId` | Während der Ausführung: der Node, der gerade ausgeführt wird                                                                                                    |
| `ui`            | Bietet Zugriff auf einige UI-Elemente wie die Warteschlange, das Menü und Dialoge                                                                               |

`canvas` (für grafische Elemente) und `graph` (für logische Verbindungen) sind wahrscheinlich diejenigen, auf die Sie am ehesten zugreifen möchten.

### Funktionen

Auch hier gibt es viele davon. Einige wichtige sind:

| Funktion          | Hinweise                                                                  |
| ----------------- | ------------------------------------------------------------------------- |
| graphToPrompt     | Wandelt den Graphen in einen Prompt um, der an den Python-Server gesendet werden kann |
| loadGraphData     | Lädt einen Graphen                                                        |
| queuePrompt       | Sendet einen Prompt an die Warteschlange                                  |
| registerExtension | Diese Funktion haben Sie bereits gesehen: Sie wird verwendet, um eine Erweiterung hinzuzufügen |

## LGraph

Das `LGraph`-Objekt ist Teil des LiteGraph-Frameworks und repräsentiert den aktuellen logischen Zustand des Graphen (Nodes und Verbindungen).
Wenn Sie den Graphen manipulieren möchten, beschreibt die LiteGraph-Dokumentation (unter `doc/index.html`, wenn Sie `https://github.com/jagenjo/litegraph.js` klonen) die Funktionen, die Sie benötigen.

Mit `graph` können Sie Details zu Nodes und Verbindungen abrufen, zum Beispiel:

```Javascript
const ComfyNode_object_for_my_node = app.graph.getNodeById(my_node_id) 
ComfyNode_object_for_my_node.inputs.forEach(input => {
    const link_id = input.link;
    if (link_id) {
        const LLink_object = app.graph.links[link_id]
        const id_of_upstream_node = LLink_object.origin_id
        // usw.
    }
});
```


## LLink

Das `LLink`-Objekt, auf das Sie über `graph.links` zugreifen, repräsentiert eine einzelne Verbindung im Graph: vom Ausgangs-Slot `link.origin_slot` des Nodes `link.origin_id` zum Slot `link.target_slot` des Nodes `link.target_id`. Außerdem enthält es in `link.type` einen String für den Datentyp sowie `link.id`.

`LLink`-Objekte werden in der Methode `connect` eines `LGraphNode` erzeugt (von dem `ComfyNode` eine Unterklasse ist).

<Tip>Vermeiden Sie es, eigene LLink-Objekte zu erstellen. Verwenden Sie stattdessen die LiteGraph-Funktionen.</Tip>

## ComfyNode

`ComfyNode` ist eine Unterklasse von `LGraphNode`. Die LiteGraph-Dokumentation ist daher für allgemeinere Operationen hilfreich. Comfy hat das Kernverhalten von LiteGraph jedoch erheblich erweitert und nutzt außerdem nicht alle LiteGraph-Funktionen.

<Tip>Die folgende Beschreibung gilt für einen normalen Node. Gruppen-Nodes, Primitiv-Nodes, Notizen und Redirect-Nodes haben andere Eigenschaften.</Tip>

Ein `ComfyNode`-Objekt repräsentiert einen Node im aktuellen Workflow. Es besitzt eine Reihe wichtiger Eigenschaften, die Sie nutzen können, sowie sehr viele Funktionen, die Sie verwenden oder abfangen können, um das Verhalten zu ändern.

<Note>
**Veraltet:** Das Abfangen von Prototypmethoden auf `ComfyNode` oder `LGraphNode` ist veraltet und kann sich in naher Zukunft jederzeit ändern. Verwenden Sie nach Möglichkeit die offiziellen [Erweiterungs-Hooks](/de/custom-nodes/js/javascript_hooks), etwa `getNodeMenuItems` für Kontextmenüs. Beispiele finden Sie im [Migrationsleitfaden für Kontextmenüs](/de/custom-nodes/js/context-menu-migration).
</Note> 

Um einen vollständigeren Eindruck vom Node-Objekt zu erhalten, kann es hilfreich sein, den folgenden Code in Ihre Erweiterung einzufügen und einen Breakpoint auf dem `console.log`-Befehl zu setzen. Wenn Sie anschließend einen neuen Node erstellen, können Sie mit Ihrem bevorzugten Debugger den Node untersuchen.

```Javascript
async nodeCreated(node) {
    console.log("nodeCreated")
}
```

### Eigenschaften

| Eigenschaft       | Inhalt                                                                                                                              |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `bgcolor`         | Die Hintergrundfarbe des Nodes oder undefined für den Standardwert                                                                  |
| `comfyClass`      | Die Python-Klasse, die den Node repräsentiert                                                                                       |
| `flags`           | Ein Dictionary, das Flags zum Zustand des Nodes enthalten kann. Insbesondere ist `flags.collapsed` bei eingeklappten Nodes true.     |
| `graph`           | Eine Referenz auf das LGraph-Objekt                                                                                                 |
| `id`              | Eine eindeutige ID                                                                                                                  |
| `input_type`      | Eine Liste der Eingabetypen (z. B. "STRING", "MODEL", "CLIP" usw.). Entspricht im Allgemeinen den Python-INPUT_TYPES                  |
| `inputs`          | Eine Liste der Eingänge (siehe unten)                                                                                               |
| `mode`            | Normalerweise 0; wird auf 2 gesetzt, wenn der Node stummgeschaltet ist, und auf 4, wenn der Node umgangen wird. Die Werte 1 und 3 werden von Comfy nicht verwendet. |
| `order`           | Die Position des Nodes in der Ausführungsreihenfolge. Wird von `LGraph.computeExecutionOrder()` festgelegt, wenn der Prompt übermittelt wird |
| `pos`             | Die [x,y]-Position des Nodes auf dem Canvas                                                                                         |
| `properties`      | Ein Dictionary mit `"Node name for S&R"`, das von LiteGraph verwendet wird                                                          |
| `properties_info` | Der Typ und der Standardwert der Einträge in `properties`                                                                           |
| `size`            | Die Breite und Höhe des Nodes auf dem Canvas                                                                                        |
| `title`           | Anzeigetitel                                                                                                                         |
| `type`            | Der eindeutige Name (aus Python) der Node-Klasse                                                                                    |
| `widgets`         | Eine Liste der Widgets (siehe unten)                                                                                                |
| `widgets_values`  | Eine Liste der aktuellen Werte der Widgets                                                                                          |

### Funktionen

Es gibt eine sehr große Anzahl an Funktionen (85, als ich das letzte Mal gezählt habe). Eine Auswahl ist unten aufgeführt.
Die meisten dieser Funktionen sind unverändert aus dem LiteGraph-Kerncode übernommen.

#### Eingaben, Ausgaben, Widgets

| Funktion               | Hinweise                                                                                           |
| ---------------------- | -------------------------------------------------------------------------------------------------- |
| Inputs / Outputs       | Die meisten haben Ausgabemethoden mit den entsprechenden Namen: s/In/Out/                          |
| `addInput`             | Erstellt eine neue Eingabe, definiert über Name und Typ                                            |
| `addInputs`            | Array-Version von `addInput`                                                                       |
| `findInputSlot`        | Ermittelt den Slot-Index aus dem Namen der Eingabe                                                 |
| `findInputSlotByType`  | Findet eine Eingabe, die dem Typ entspricht. Optionen, um freie Slots zu bevorzugen oder nur diese zu verwenden |
| `removeInput`          | Über den Slot-Index                                                                                |
| `getInputNode`         | Ruft den mit dieser Eingabe verbundenen Node ab. Das Ausgabe-Äquivalent ist `getOutputNodes` und gibt eine Liste zurück |
| `getInputLink`         | Ruft die mit dieser Eingabe verbundene LLink ab. Kein Ausgabe-Äquivalent                           |
| Widgets                |                                                                                                    |
| `addWidget`            | Fügt ein Standard-Comfy-Widget hinzu                                                                |
| `addCustomWidget`      | Fügt ein benutzerdefiniertes Widget hinzu (definiert im `getComfyWidgets`-Hook)                    |
| `addDOMWidget`         | Fügt ein Widget hinzu, das durch ein DOM-Element definiert ist                                     |
| `convertWidgetToInput` | Wandelt ein Widget in eine Eingabe um, wenn `isConvertableWidget` (in `widgetInputs.js`) dies erlaubt |

#### Verbindungen

| Funktion              | Hinweise                                                                                          |
| --------------------- | ------------------------------------------------------------------------------------------------- |
| `connect`             | Verbindet den Ausgang dieses Nodes mit der Eingabe eines anderen Nodes                            |
| `connectByType`       | Verbindet den Ausgang über die Angabe des Typs mit einem anderen Node - verbindet mit dem ersten verfügbaren passenden Slot |
| `connectByTypeOutput` | Verbindet eine Eingabe über den Typ mit dem Ausgang eines anderen Nodes                            |
| `disconnectInput`     | Entfernt jede Verbindung in die Eingabe (angegeben über Name oder Index)                          |
| `disconnectOutput`    | Trennt einen Ausgang von der Eingabe eines angegebenen Nodes                                      |
| `onConnectionsChange` | Wird für jeden Node aufgerufen. `side==1`, wenn es sich um eine Eingabe an diesem Node handelt    |
| `onConnectInput`      | Wird _vor_ dem Herstellen einer Verbindung aufgerufen. Wenn dies `false` zurückgibt, wird die Verbindung abgelehnt |

#### Anzeige  

| Funktion           | Hinweise                                                                                               |
| ------------------ | ------------------------------------------------------------------------------------------------------ |
| `setDirtyCanvas`   | Legt fest, dass der Vordergrund (Nodes) und/oder der Hintergrund (Verbindungen und Bilder) neu gezeichnet werden müssen |

| `onDrawForeground` | Wird mit einem `CanvasRenderingContext2D`-Objekt aufgerufen, um den Node zu zeichnen.                  |

## Eingaben und Widgets

Eingaben und Widgets sind die beiden Möglichkeiten, wie Daten in einen Node eingespeist werden können. Im Allgemeinen kann ein Widget in eine Eingabe umgewandelt werden, aber nicht alle Eingaben können in ein Widget umgewandelt werden (da viele Datentypen nicht über ein UI-Element eingegeben werden können).

`node.inputs` ist eine Liste der aktuellen Eingaben (farbige Punkte auf der linken Seite des Nodes), die ihren `.name`, `.type` und `.link` angibt (eine Referenz auf die verbundene `LLink` in `app.graph.links`).

Wenn eine Eingabe ein Widget ist, das umgewandelt wurde, enthält sie außerdem eine Referenz auf das nun inaktive Widget in `.widget`.

`node.widgets` ist eine Liste aller Widgets, unabhängig davon, ob sie in eine Eingabe umgewandelt wurden. Ein Widget hat:

| Eigenschaft/Funktion | Hinweise                                                                     |
| -------------------- | ---------------------------------------------------------------------------- |
| `callback`           | Eine Funktion, die aufgerufen wird, wenn der Wert des Widgets geändert wird   |
| `last_y`             | Die vertikale Position des Widgets im Node                                   |
| `name`               | Der (innerhalb eines Nodes eindeutige) Name des Widgets                      |
| `options`            | Wie im Python-Code angegeben (z. B. default, min und max)                    |
| `type`               | Der Name des Widget-Typs (siehe unten) in Kleinbuchstaben                    |
| `value`              | Der aktuelle Wert des Widgets. Dies ist eine Eigenschaft mit `get`- und `set`-Methoden |

### Widget-Typen

`app.widgets` ist ein Dictionary der aktuell registrierten Widget-Typen, dessen Schlüssel die GROSSBUCHSTABEN-Version des Namens des Typs ist.
Zu den in Comfy integrierten Widget-Typen gehören die selbsterklärenden `BOOLEAN`, `INT` und `FLOAT`
sowie `STRING` (in zwei Varianten, einzeilig und mehrzeilig),
`COMBO` für die Auswahl aus einer Liste per Dropdown und `IMAGEUPLOAD`, das in Load Image-Nodes verwendet wird.

Benutzerdefinierte Widget-Typen können hinzugefügt werden, indem Sie eine `getCustomWidgets`-Methode in Ihrer Erweiterung bereitstellen.

## Prompt

Wenn Sie in Comfy auf die Schaltfläche `Queue Prompt` klicken, wird die Methode `app.graphToPrompt()` aufgerufen, um den aktuellen Graphen in einen Prompt umzuwandeln, der an den Server gesendet werden kann.

`app.graphToPrompt` gibt ein Objekt zurück (im Folgenden als `prompt` bezeichnet) mit zwei Eigenschaften: `output` und `workflow`.

### output

`prompt.output` ordnet der `node_id` jedes Nodes im Graphen ein Objekt mit zwei Eigenschaften zu.

- `prompt.output[node_id].class_type`, der eindeutige Name der Custom-Node-Klasse, wie im Python-Code definiert
- `prompt.output[node_id].inputs`, enthält den Wert jedes Eingangs (oder Widgets) als Zuordnung vom Namen des Eingangs zu:
    - dem ausgewählten Wert, wenn es ein Widget ist, oder
    - einem Array mit (`upstream_node_id`, `upstream_node_output_slot`), wenn eine Verbindung mit dem Eingang verbunden ist, oder
    - undefined, wenn es ein Widget ist, das in einen Eingang umgewandelt wurde und nicht verbunden ist
    - andere nicht verbundene Eingänge sind nicht in `.inputs` enthalten

<Tip>Beachten Sie, dass die `upstream_node_id` in dem Array, das einen verbundenen Eingang beschreibt, als String und nicht als Integer dargestellt wird.</Tip>

### workflow

`prompt.workflow` enthält die folgenden Eigenschaften:

- `config` - ein Dictionary mit zusätzlichen Konfigurationsoptionen (standardmäßig leer)
- `extra` - ein Dictionary mit zusätzlichen Informationen über den Workflow. Standardmäßig enthält es:
    - `extra.ds` - beschreibt die aktuelle Ansicht des Graphen (`scale` und `offset`)
- `groups` - alle Gruppen im Workflow
- `last_link_id` - die id der zuletzt hinzugefügten Verbindung
- `last_node_id` - die id des zuletzt hinzugefügten Nodes
- `links` - eine Liste aller Verbindungen im Graphen. Jeder Eintrag ist ein Array aus fünf Integern und einem String:
    - (`link_id`, `upstream_node_id`, `upstream_node_output_slot`, `downstream_node_id`, `downstream_node_input_slot`, `data type`)
- `nodes` - eine Liste aller Nodes im Graphen. Jeder Eintrag ist eine Zuordnung einer Teilmenge der Eigenschaften des Nodes, wie [oben](#comfynode) beschrieben
    - Die folgenden Eigenschaften sind enthalten: `flags`, `id`, `inputs`, `mode`, `order`, `pos`, `properties`, `size`, `type`, `widgets_values`
    - Zusätzlich gibt es, sofern ein Node Ausgänge besitzt, eine Eigenschaft `outputs`, die eine Liste der Ausgänge des Nodes ist, wobei jeder Ausgang Folgendes enthält:
        - `name` - der Name des Ausgangs
        - `type` - der Datentyp des Ausgangs
        - `links` - eine Liste der `link_id` aller Verbindungen von diesem Ausgang (kann, wenn es keine Verbindungen gibt, eine leere Liste oder null sein)
        - `shape` - die Form, mit der der Ausgang gezeichnet wird (Standard 3 für einen Punkt)
        - `slot_index` - die Slot-Nummer des Ausgangs
- `version` - die LiteGraph-Versionsnummer (zum Zeitpunkt des Schreibens `0.4`)

<Tip>Bei Nodes ohne Ausgänge fehlt `nodes.output`, es ist dann keine leere Liste.</Tip>
