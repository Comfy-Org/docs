## LiteGraph

Die ComfyUI-Oberfläche baut auf [LiteGraph](https://github.com/jagenjo/litegraph.js) auf. Ein Großteil der ComfyUI-Funktionalität wird von LiteGraph bereitgestellt. Wenn Sie komplexere Nodes entwickeln, ist es daher wahrscheinlich hilfreich, dieses Repository zu klonen und die Dokumentation zu durchsuchen, die Sie unter `doc/index.html` finden.

## ComfyApp

Das `app`-Objekt (immer erreichbar über `import { app } from "../../scripts/app.js";`) repräsentiert die Comfy-Anwendung, die im Browser läuft, und enthält eine Reihe nützlicher Eigenschaften und Funktionen, von denen einige unten aufgeführt sind.

<Note>
**Veraltet:** Das Hijacking/Monkey-Patching von Funktionen auf `app` oder Prototypen ist veraltet und kann sich in naher Zukunft jederzeit ändern. Verwenden Sie stattdessen die offiziellen [Erweiterungs-Hooks](/custom-nodes/js/javascript_hooks) und die [Context Menu API](/de/custom-nodes/js/context-menu-migration).
</Note>

<Warning>
  Das Hijacking von Funktionen auf `app` wird nicht empfohlen, da Comfy ständig weiterentwickelt wird und sich das Kernverhalten ändern kann.
</Warning>

### Eigenschaften

Wichtige Eigenschaften von `app` sind (die Liste ist nicht vollständig):

| Eigenschaft     | Inhalt                                                                                                                                                          |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `canvas`        | Ein LGraphCanvas-Objekt, das die aktuelle Benutzeroberfläche darstellt. Es enthält einige potenziell interessante Eigenschaften wie `node_over` und `selected_nodes`. |
| `canvasEl`      | Das DOM-`<canvas>`-Element                                                                                                                                      |
| `graph`         | Eine Referenz auf das LGraph-Objekt, das den aktuellen Graphen beschreibt                                                                                       |
| `runningNodeId` | Während der Ausführung der Node, der gerade ausgeführt wird                                                                                                     |
| `ui`            | Bietet Zugriff auf einige UI-Elemente wie die Warteschlange, das Menü und Dialoge                                                                               |

`canvas` (für grafische Elemente) und `graph` (für logische Verbindungen) sind wahrscheinlich diejenigen, auf die Sie am ehesten zugreifen möchten.

### Funktionen

Auch hier gibt es viele davon. Einige wichtige sind:

| Funktion          | Hinweise                                                                  |
| ----------------- | ------------------------------------------------------------------------- |
| graphToPrompt     | Wandelt den Graphen in einen Prompt um, der an den Python-Server gesendet werden kann |
| loadGraphData     | Lädt einen Graphen                                                        |
| queuePrompt       | Absenden eines Prompts an die Warteschlange                               |
| registerExtension | Diese haben Sie schon gesehen: wird verwendet, um eine Erweiterung hinzuzufügen |

## LGraph

Das Objekt `LGraph` gehört zum LiteGraph-Framework und repräsentiert den aktuellen logischen Zustand des Diagramms (Nodes und Verbindungen). 
Wenn Sie das Diagramm bearbeiten möchten, beschreibt die LiteGraph-Dokumentation (unter `doc/index.html`, wenn Sie `https://github.com/jagenjo/litegraph.js` klonen) 
die Funktionen, die Sie dafür benötigen.

Mit `graph` erhalten Sie Details zu Nodes und Verbindungen, zum Beispiel:

```Javascript
const ComfyNode_object_for_my_node = app.graph._nodes_by_id(my_node_id) 
ComfyNode_object_for_my_node.inputs.forEach(input => {
    const link_id = input.link;
    if (link_id) {
        const LLink_object = app.graph.links[link_id]
        const id_of_upstream_node = LLink_object.origin_id
        // etc
    }
});
```

## LLink

Das Objekt `LLink`, auf das Sie über `graph.links` zugreifen, repräsentiert eine einzelne Verbindung im Graphen, vom Ausgangs-Slot `link.origin_slot` des Nodes `link.origin_id` zum Slot `link.target_slot` des Nodes `link.target_id`. Es enthält außerdem eine Zeichenkette für den Datentyp in `link.type` sowie `link.id`.

`LLink`-Objekte werden in der Methode `connect` eines `LGraphNode` erstellt (von dem `ComfyNode` eine Unterklasse ist).

<Tip>Vermeiden Sie es, eigene `LLink`-Objekte zu erstellen. Verwenden Sie stattdessen die LiteGraph-Funktionen.</Tip>

## ComfyNode

`ComfyNode` ist eine Unterklasse von `LGraphNode`; die LiteGraph-Dokumentation ist daher für allgemeinere
Operationen hilfreich. Comfy hat jedoch das Kernverhalten von LiteGraph erheblich erweitert und nutzt auch nicht
die gesamte Funktionalität von LiteGraph.

<Tip>Die folgende Beschreibung gilt für einen normalen Node.
Group Nodes, Primitive Nodes, Notizen und Redirect-Nodes haben andere Eigenschaften.</Tip>

Ein `ComfyNode`-Objekt repräsentiert einen Node im aktuellen Workflow. Es besitzt eine Reihe wichtiger Eigenschaften,
die Sie nutzen können, sowie eine sehr große Anzahl von Funktionen, die Sie verwenden oder hijacken können, um
das Verhalten zu ändern.

<Note>
**Veraltet:** Das Hijacken von Prototypmethoden auf `ComfyNode` oder `LGraphNode` ist veraltet und kann sich jederzeit in naher Zukunft ändern. Verwenden Sie die offiziellen [Erweiterungs-Hooks](/custom-nodes/js/javascript_hooks), wo verfügbar, wie z. B. `getNodeMenuItems` für Kontextmenüs. Beispiele finden Sie im [Leitfaden zur Kontextmenü-Migration](/de/custom-nodes/js/context-menu-migration).
</Note>

Um ein vollständigeres Bild des Node-Objekts zu erhalten, kann es hilfreich sein, den folgenden
Code in Ihre Erweiterung einzufügen und einen Breakpoint auf dem Befehl `console.log` zu setzen. Wenn Sie dann einen neuen Node erstellen,
können Sie mit Ihrem bevorzugten Debugger den Node untersuchen.

```Javascript
async nodeCreated(node) {
    console.log("nodeCreated")
}
```

| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `bgcolor`         | Die Hintergrundfarbe des Nodes oder undefined für den Standard                                                                         |
| `comfyClass`      | Die Python-Klasse, die den Node repräsentiert                                                                                          |
| `flags`           | Ein Wörterbuch, das Flags zum Status des Nodes enthalten kann. Insbesondere ist `flags.collapsed` bei eingeklappten Nodes true.        |
| `graph`           | Eine Referenz auf das LGraph-Objekt                                                                                                    |
| `id`              | Eine eindeutige ID                                                                                                                     |
| `input_type`      | Eine Liste der Eingabetypen (z. B. "STRING", "MODEL", "CLIP" usw.). Entspricht im Allgemeinen den Python-INPUT_TYPES                  |
| `inputs`          | Eine Liste von Eingängen (unten erläutert)                                                                                             |

| `order`           | Die Position des Nodes in der Ausführungsreihenfolge. Wird von `LGraph.computeExecutionOrder()` festgelegt, wenn der Prompt übermittelt wird |
| `pos`             | Die [x,y]-Position des Nodes auf dem Canvas                                                                                             |
| `properties`      | Ein Wörterbuch, das `"Node name for S&R"` enthält, verwendet von LiteGraph                                                             |
| `properties_info` | Der Typ und Standardwert der Einträge in `properties`                                                                                   |
| `size`            | Die Breite und Höhe des Nodes auf dem Canvas                                                                                           |
| `title`           | Anzeigetitel                                                                                                                           |
| `type`            | Der eindeutige Name (aus Python) der Node-Klasse                                                                                       |
| `widgets`         | Eine Liste von Widgets (unten erläutert)                                                                                               |
| `widgets_values`  | Eine Liste der aktuellen Werte der Widgets                                                                                             |### Funktionen

### Funktionen

#### Eingänge, Ausgänge, Widgets

| Funktion               | Anmerkungen                                                                                              |

| `addCustomWidget`      | Ein benutzerdefiniertes Widget hinzufügen (definiert im Hook `getComfyWidgets`)                          |
| `addDOMWidget`         | Ein Widget hinzufügen, das durch ein DOM-Element definiert ist                                           |

| Funktion              | Anmerkungen                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------------- |
| `connect`             | Den Ausgang dieses Nodes mit dem Eingang eines anderen Nodes verbinden                            |

| Funktion           | Anmerkungen                                                                                                  |

## Eingänge und Widgets

Eingänge und Widgets sind die beiden Arten, wie Daten in einen Node gelangen können. Im Allgemeinen kann ein Widget in eine Eingabe umgewandelt werden, aber nicht alle Eingaben lassen sich in ein Widget umwandeln (da sich viele Datentypen nicht über ein UI-Element eingeben lassen).

`node.inputs` ist eine Liste der aktuellen Eingänge (die farbigen Punkte auf der linken Seite des Nodes) und enthält deren `.name`, `.type` und `.link` (eine Referenz auf die verbundene `LLink` in `app.graph.links`).

Wenn ein Eingang aus einem umgewandelten Widget besteht, enthält er außerdem eine Referenz auf das nun inaktive Widget in `.widget`.

`node.widgets` ist eine Liste aller Widgets, unabhängig davon, ob sie in eine Eingabe umgewandelt wurden. Ein Widget besitzt:

| Eigenschaft/Funktion | Hinweise                                                                  |
| -------------------- | ------------------------------------------------------------------------- |
| `callback`           | Eine Funktion, die aufgerufen wird, wenn der Widget-Wert geändert wird    |
| `last_y`             | Die vertikale Position des Widgets im Node                                |
| `name`               | Der Widget-Name (innerhalb eines Nodes eindeutig)                         |
| `options`            | Wie im Python-Code angegeben (z. B. default, min und max)                 |
| `type`               | Der Name des Widget-Typs (siehe unten) in Kleinschreibung                 |
| `value`              | Der aktuelle Widget-Wert. Eine Eigenschaft mit `get`- und `set`-Methoden  |

### Widget-Typen

`app.widgets` ist ein Dictionary der aktuell registrierten Widget-Typen, dessen Schlüssel der Name des jeweiligen Typs in GROSSBUCHSTABEN ist. Zu den in Comfy eingebauten Widget-Typen gehören die selbsterklärenden `BOOLEAN`, `INT` und `FLOAT` sowie `STRING` (in zwei Varianten: einzeilig und mehrzeilig), `COMBO` für die Auswahl aus einer Liste per Dropdown und `IMAGEUPLOAD`, das in Load Image-Nodes verwendet wird.

Benutzerdefinierte Widget-Typen können hinzugefügt werden, indem Sie eine `getCustomWidgets`-Methode in Ihrer Erweiterung bereitstellen.

## Prompt

Wenn Sie in Comfy auf die Schaltfläche `Queue Prompt` klicken, wird die Methode `app.graphToPrompt()` aufgerufen, um den aktuellen Graphen in einen Prompt umzuwandeln, der an den Server gesendet werden kann.

`app.graphToPrompt` gibt ein Objekt zurück (im Folgenden `prompt` genannt) mit zwei Eigenschaften: `output` und `workflow`.

### output

`prompt.output` ordnet jedem `node_id` eines Nodes im Graphen ein Objekt mit zwei Eigenschaften zu.

- `prompt.output[node_id].class_type`: der eindeutige Name der Custom-Node-Klasse, wie im Python-Code definiert
- `prompt.output[node_id].inputs`: enthält den Wert jeder Eingabe (oder jedes Widgets) als Zuordnung vom Namen der Eingabe zu:
    - dem ausgewählten Wert, wenn es sich um ein Widget handelt, oder
    - einem Array mit (`upstream_node_id`, `upstream_node_output_slot`), wenn eine Verbindung mit der Eingabe verbunden ist, oder
    - undefined, wenn es sich um ein Widget handelt, das in eine Eingabe umgewandelt wurde und nicht verbunden ist
    - andere nicht verbundene Eingaben sind nicht in `.inputs` enthalten

<Tip>Beachten Sie, dass die `upstream_node_id` im Array, das eine verbundene Eingabe beschreibt, als String und nicht als Integer dargestellt wird.</Tip>

### workflow

`prompt.workflow` enthält die folgenden Eigenschaften:

- `config`: ein Dictionary zusätzlicher Konfigurationsoptionen (standardmäßig leer)
- `extra`: ein Dictionary mit zusätzlichen Informationen über den Workflow. Standardmäßig enthält es:
    - `extra.ds`: beschreibt die aktuelle Ansicht des Graphen (`scale` und `offset`)
- `groups`: alle Gruppen im Workflow
- `last_link_id`: die ID der zuletzt hinzugefügten Verbindung
- `last_node_id`: die ID des zuletzt hinzugefügten Nodes
- `links`: eine Liste aller Verbindungen im Graphen. Jeder Eintrag ist ein Array aus fünf Integern und einem String:
    - (`link_id`, `upstream_node_id`, `upstream_node_output_slot`, `downstream_node_id`, `downstream_node_input_slot`, `data type`)
- `nodes`: eine Liste aller Nodes im Graphen. Jeder Eintrag ist eine Zuordnung einer Teilmenge der Eigenschaften des Nodes, wie [oben](#comfynode) beschrieben
    - Die folgenden Eigenschaften sind enthalten: `flags`, `id`, `inputs`, `mode`, `order`, `pos`, `properties`, `size`, `type`, `widgets_values`
    - Darüber hinaus gibt es, sofern ein Node Ausgänge besitzt, eine Eigenschaft `outputs`, die eine Liste der Ausgänge des Nodes ist, wobei jeder Ausgang Folgendes enthält:
        - `name`: der Name des Ausgangs
        - `type`: der Datentyp des Ausgangs
        - `links`: eine Liste der `link_id` aller Verbindungen von diesem Ausgang (kann, wenn keine Verbindungen bestehen, eine leere Liste oder null sein)
        - `shape`: die Form, mit der der Ausgang gezeichnet wird (Standard 3 für einen Punkt)
        - `slot_index`: die Slot-Nummer des Ausgangs
- `version`: die LiteGraph-Versionsnummer (zum Zeitpunkt dieses Textes `0.4`)

<Tip>`nodes.output` fehlt bei Nodes ohne Ausgänge; es ist keine leere Liste.</Tip>
