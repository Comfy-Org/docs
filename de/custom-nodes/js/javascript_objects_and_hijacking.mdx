## LiteGraph

Die ComfyUI-Oberfläche baut auf [LiteGraph](https://github.com/jagenjo/litegraph.js) auf. Ein Großteil der ComfyUI-Funktionalität wird von LiteGraph bereitgestellt. Wenn Sie komplexere Nodes entwickeln, ist es daher wahrscheinlich hilfreich, dieses Repository zu klonen und die Dokumentation zu durchsuchen, die Sie unter `doc/index.html` finden.

## ComfyApp

Das `app`-Objekt (immer erreichbar über `import { app } from "../../scripts/app.js";`) repräsentiert die Comfy-Anwendung, die im Browser läuft, und enthält eine Reihe nützlicher Eigenschaften und Funktionen, von denen einige unten aufgeführt sind.

<Note>
**Veraltet:** Hijacking/Monkey-Patching von Funktionen auf `app` oder Prototypen ist veraltet und kann sich in naher Zukunft jederzeit ändern. Verwenden Sie stattdessen die offiziellen [Erweiterungs-Hooks](/custom-nodes/js/javascript_hooks) und die [Context Menu API](/de/custom-nodes/js/context-menu-migration).
</Note>

<Warning>
  Das Hijacking von Funktionen auf `app` wird nicht empfohlen, da Comfy ständig weiterentwickelt wird und sich das Kernverhalten ändern kann.
</Warning>

### Eigenschaften

Wichtige Eigenschaften von `app` sind (die Liste ist nicht vollständig):

| Eigenschaft     | Inhalt                                                                                                                                                          |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `canvas`        | Ein LGraphCanvas-Objekt, das die aktuelle Benutzeroberfläche darstellt. Es enthält einige potenziell interessante Eigenschaften wie `node_over` und `selected_nodes`. |
| `canvasEl`      | Das DOM-`<canvas>`-Element                                                                                                                                      |
| `graph`         | Eine Referenz auf das LGraph-Objekt, das den aktuellen Graphen beschreibt                                                                                       |
| `runningNodeId` | Während der Ausführung der Node, der gerade ausgeführt wird                                                                                                     |
| `ui`            | Bietet Zugriff auf einige UI-Elemente wie die Warteschlange, das Menü und Dialoge                                                                               |

`canvas` (für grafische Elemente) und `graph` (für logische Verbindungen) sind wahrscheinlich diejenigen, auf die Sie am ehesten zugreifen möchten.

### Funktionen

Auch hier gibt es viele davon. Einige wichtige sind:

| Funktion          | Hinweise                                                                  |
| ----------------- | ------------------------------------------------------------------------- |
| graphToPrompt     | Wandelt den Graphen in einen Prompt um, der an den Python-Server gesendet werden kann |
| loadGraphData     | Lädt einen Graphen                                                        |
| queuePrompt       | Absenden eines Prompts an die Warteschlange                               |
| registerExtension | Diese haben Sie schon gesehen: wird verwendet, um eine Erweiterung hinzuzufügen |

## LGraph

The `LGraph` object is part of the LiteGraph framework, and represents the current logical state of the graph (nodes and links). 
If you want to manipulate the graph, the LiteGraph documentation (at `doc/index.html` if you clone `https://github.com/jagenjo/litegraph.js`) 
describes the functions you will need.

You can use `graph` to obtain details of nodes and links, for example:

```Javascript
const ComfyNode_object_for_my_node = app.graph._nodes_by_id(my_node_id) 
ComfyNode_object_for_my_node.inputs.forEach(input => {
    const link_id = input.link;
    if (link_id) {
        const LLink_object = app.graph.links[link_id]
        const id_of_upstream_node = LLink_object.origin_id
        // etc
    }
});
```

## LLink

Das `LLink`-Objekt, auf das Sie über `graph.links` zugreifen, repräsentiert eine einzelne Verbindung im Graphen: vom Ausgabeslot `link.origin_slot` des Nodes `link.origin_id` zum Slot `link.target_slot` des Nodes `link.target_id`. Außerdem enthält es einen String für den Datentyp in `link.type` sowie `link.id`.

`LLink`s werden in der Methode `connect` eines `LGraphNode` erstellt (`ComfyNode` ist eine Unterklasse davon).

<Tip>
  Vermeiden Sie es, eigene LLink-Objekte zu erstellen. Verwenden Sie stattdessen die Funktionen von LiteGraph.
</Tip>

## ComfyNode

`ComfyNode` ist eine Unterklasse von `LGraphNode`, daher ist die LiteGraph-Dokumentation für allgemeinere Operationen hilfreich. Comfy hat das Kernverhalten von LiteGraph jedoch deutlich erweitert und nutzt außerdem nicht alle LiteGraph-Funktionen.

<Tip>
  Die folgende Beschreibung gilt für einen normalen Node. Group Nodes, primitive Nodes, Notizen und Redirect Nodes haben andere Eigenschaften.
</Tip>

Ein `ComfyNode`-Objekt repräsentiert einen Node im aktuellen Workflow. Es besitzt eine Reihe wichtiger Eigenschaften, die Sie nutzen können, sowie eine sehr große Anzahl von Funktionen, die Sie verwenden oder kapern (hijacken) können, um das Verhalten zu ändern.

<Note>
**Veraltet:** Das Hijacken von Prototyp-Methoden auf `ComfyNode` oder `LGraphNode` ist veraltet und kann sich jederzeit in naher Zukunft ändern. Verwenden Sie wo verfügbar die offiziellen [Erweiterungs-Hooks](/custom-nodes/js/javascript_hooks), etwa `getNodeMenuItems` für Kontextmenüs. Beispiele finden Sie im [Context Menu Migration Guide](/de/custom-nodes/js/context-menu-migration).
</Note> 

Um einen vollständigeren Eindruck vom Node-Objekt zu bekommen, kann es hilfreich sein, den folgenden Code in Ihre Erweiterung einzufügen und einen Breakpoint auf den `console.log`-Befehl zu setzen. Wenn Sie dann einen neuen Node erstellen, können Sie mit Ihrem bevorzugten Debugger den Node inspizieren.

```Javascript
async nodeCreated(node) {
    console.log("nodeCreated")
}
```

### Eigenschaften

| Eigenschaft       | Inhalt                                                                                                                              |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `bgcolor`         | Die Hintergrundfarbe des Nodes oder undefined für den Standardwert                                                                  |
| `comfyClass`      | Die Python-Klasse, die den Node repräsentiert                                                                                       |
| `flags`           | Ein Dictionary, das Flags zum Zustand des Nodes enthalten kann. Insbesondere ist `flags.collapsed` bei eingeklappten Nodes wahr.     |
| `graph`           | Eine Referenz auf das LGraph-Objekt                                                                                                 |
| `id`              | Eine eindeutige ID                                                                                                                  |
| `input_type`      | Eine Liste der Eingabetypen (z. B. „STRING“, „MODEL“, „CLIP“ usw.). Entspricht im Allgemeinen den Python-INPUT_TYPES                 |
| `inputs`          | Eine Liste der Eingänge (weiter unten beschrieben)                                                                                  |
| `mode`            | Normalerweise 0, auf 2 gesetzt, wenn der Node stummgeschaltet (muted) ist, und auf 4, wenn der Node umgangen (bypassed) wird. Die Werte 1 und 3 werden von Comfy nicht verwendet |
| `order`           | Die Position des Nodes in der Ausführungsreihenfolge. Wird von `LGraph.computeExecutionOrder()` gesetzt, wenn der Prompt übermittelt wird |
| `pos`             | Die [x,y]-Position des Nodes auf dem Canvas                                                                                          |
| `properties`      | Ein Dictionary mit „Node name for S&R“, das von LiteGraph verwendet wird                                                            |
| `properties_info` | Der Typ und der Standardwert der Einträge in `properties`                                                                            |
| `size`            | Die Breite und Höhe des Nodes auf dem Canvas                                                                                         |
| `title`           | Angezeigter Titel                                                                                                                    |
| `type`            | Der eindeutige Name (aus Python) der Node-Klasse                                                                                     |
| `widgets`         | Eine Liste der Widgets (weiter unten beschrieben)                                                                                    |
| `widgets_values`  | Eine Liste der aktuellen Werte der Widgets                                                                                           |

### Funktionen

Es gibt eine sehr große Anzahl an Funktionen (85, als ich das letzte Mal gezählt habe). Eine Auswahl ist unten aufgeführt.
Die meisten dieser Funktionen sind unverändert aus dem LiteGraph-Kerncode übernommen.

#### Eingänge, Ausgänge, Widgets

| Funktion               | Hinweise                                                                                              |
| ---------------------- | ----------------------------------------------------------------------------------------------------- |
| Eingänge / Ausgänge    | Die meisten besitzen Ausgabemethoden mit den entsprechenden Namen: s/In/Out/                           |
| `addInput`             | Erstellt einen neuen Eingang, der durch Name und Typ definiert ist                                    |
| `addInputs`            | Array-Version von `addInput`                                                                           |
| `findInputSlot`        | Ermittelt den Slot-Index anhand des Eingangsnamens                                                     |
| `findInputSlotByType`  | Findet einen Eingang, der dem Typ entspricht. Optionen, um freie Slots zu bevorzugen oder ausschließlich zu verwenden |
| `removeInput`          | Anhand des Slot-Index                                                                                  |
| `getInputNode`         | Ruft den mit diesem Eingang verbundenen Node ab. Das Ausgabe-Äquivalent ist `getOutputNodes` und gibt eine Liste zurück |
| `getInputLink`         | Ruft das mit diesem Eingang verbundene LLink ab. Kein Ausgabe-Äquivalent                               |
| Widgets                |                                                                                                        |
| `addWidget`            | Fügt ein Standard-Widget von Comfy hinzu                                                               |
| `addCustomWidget`      | Fügt ein benutzerdefiniertes Widget hinzu (definiert im `getComfyWidgets`-Hook)                        |
| `addDOMWidget`         | Fügt ein Widget hinzu, das durch ein DOM-Element definiert ist                                         |
| `convertWidgetToInput` | Wandelt ein Widget in einen Eingang um, sofern `isConvertableWidget` dies erlaubt (in `widgetInputs.js`) |

#### Verbindungen

| Funktion              | Hinweise                                                                                             |
| --------------------- | ---------------------------------------------------------------------------------------------------- |
| `connect`             | Verbindet den Ausgang dieses Nodes mit dem Eingang eines anderen Nodes                                |
| `connectByType`       | Verbindet den Ausgang durch Angabe des Typs mit einem anderen Node: stellt eine Verbindung zum ersten verfügbaren passenden Slot her |
| `connectByTypeOutput` | Verbindet den Eingang anhand des Typs mit dem Ausgang eines anderen Nodes                             |
| `disconnectInput`     | Entfernt jede Verbindung zu dem Eingang (angegeben durch Name oder Index)                             |
| `disconnectOutput`    | Trennt einen Ausgang vom Eingang eines angegebenen Nodes                                              |
| `onConnectionChange`  | Wird bei jedem Node aufgerufen. `side==1`, wenn es sich um einen Eingang an diesem Node handelt       |
| `onConnectInput`      | Wird _vor_ dem Herstellen einer Verbindung aufgerufen. Wenn dies `false` zurückgibt, wird die Verbindung abgelehnt |

#### Anzeige

| Funktion           | Hinweise                                                                                                  |
| ------------------ | ---------------------------------------------------------------------------------------------------------- |
| `setDirtyCanvas`   | Gibt an, dass der Vordergrund (Nodes) und/oder der Hintergrund (Verbindungen und Bilder) neu gezeichnet werden müssen |
| `onDrawBackground` | Wird mit einem `CanvasRenderingContext2D`-Objekt aufgerufen, um den Hintergrund zu zeichnen. Wird von Comfy zum Rendern von Bildern verwendet |
| `onDrawForeground` | Wird mit einem `CanvasRenderingContext2D`-Objekt aufgerufen, um den Node zu zeichnen.                      |
| `getTitle`         | Der anzuzeigende Titel.                                                                                    |
| `collapse`         | Schaltet den reduzierten Zustand des Nodes um.                                                             |

<Warning>
  `collapse` ist schlecht benannt; es _schaltet_ den reduzierten Zustand um. Es nimmt einen booleschen Parameter an, mit dem `node.collapsable === false` überschrieben werden kann.
</Warning>

#### Sonstiges

| Funktion     | Hinweise                                                              |
| ------------ | --------------------------------------------------------------------- |
| `changeMode` | Damit legen Sie fest, ob der Node umgangen (`mode == 4`) oder nicht umgangen (`mode == 0`) wird |

## Eingaben und Widgets

Eingaben und Widgets stellen die beiden Möglichkeiten dar, wie Daten in einen Node eingespeist werden können. Im Allgemeinen kann ein Widget in eine Eingabe umgewandelt werden, aber nicht alle Eingaben können in ein Widget umgewandelt werden (da sich viele Datentypen nicht über ein UI-Element eingeben lassen).

`node.inputs` ist eine Liste der aktuellen Eingaben (farbige Punkte auf der linken Seite des Nodes), die deren `.name`, `.type` und `.link` angibt (eine Referenz auf die verbundene `LLink` in `app.graph.links`).

Wenn eine Eingabe ein Widget ist, das umgewandelt wurde, enthält sie außerdem eine Referenz auf das nun inaktive Widget in `.widget`.

`node.widgets` ist eine Liste aller Widgets, unabhängig davon, ob sie in eine Eingabe umgewandelt wurden. Ein Widget hat:

| Eigenschaft/Funktion | Hinweise                                                                     |
| ----------------- | ------------------------------------------------------------------------- |
| `callback`        | Eine Funktion, die aufgerufen wird, wenn der Widget-Wert geändert wird                        |
| `last_y`          | Die vertikale Position des Widgets im Node                           |
| `name`            | Der Widget-Name (innerhalb eines Nodes eindeutig)                                    |
| `options`         | Wie im Python-Code angegeben (z. B. Standard, Min. und Max.)           |
| `type`            | Der Name des Widget-Typs (siehe unten) in Kleinbuchstaben                      |
| `value`           | Der aktuelle Widget-Wert. Dies ist eine Eigenschaft mit den Methoden `get` und `set` |

### Widget-Typen

`app.widgets` ist ein Dictionary der aktuell registrierten Widget-Typen, wobei die Schlüssel die Namen der Typen in Großbuchstaben sind. 
Zu den in ComfyUI integrierten Widget-Typen gehören die selbsterklärenden `BOOLEAN`, `INT` und `FLOAT` 
sowie `STRING` (in zwei Varianten: einzeilig und mehrzeilig), 
`COMBO` für die Dropdown-Auswahl aus einer Liste und `IMAGEUPLOAD`, das in Nodes vom Typ Load Image verwendet wird.

Benutzerdefinierte Widget-Typen können hinzugefügt werden, indem Sie eine Methode `getCustomWidgets` in Ihrer Erweiterung bereitstellen.

## Prompt

Wenn Sie in Comfy auf die Schaltfläche `Queue Prompt` klicken, wird die Methode `app.graphToPrompt()` aufgerufen, um den aktuellen Graphen in einen Prompt umzuwandeln, der an den Server gesendet werden kann.

`app.graphToPrompt` gibt ein Objekt zurück (im Folgenden `prompt` genannt) mit zwei Eigenschaften, `output` und `workflow`.

### output

`prompt.output` bildet die `node_id` jedes Nodes im Graphen auf ein Objekt mit zwei Eigenschaften ab.

- `prompt.output[node_id].class_type`, der eindeutige Name der Custom-Node-Klasse, wie er im Python-Code definiert ist
- `prompt.output[node_id].inputs`, enthält den Wert jeder Eingabe (oder jedes Widgets) als Zuordnung vom Namen der Eingabe zu:
    - dem ausgewählten Wert, wenn es sich um ein Widget handelt, oder
    - einem Array mit (`upstream_node_id`, `upstream_node_output_slot`), wenn eine Verbindung an der Eingabe anliegt, oder
    - undefined, wenn es sich um ein Widget handelt, das in eine Eingabe umgewandelt wurde und nicht verbunden ist
    - weitere nicht verbundene Eingaben sind nicht in `.inputs` enthalten

<Tip>
  Beachten Sie, dass die `upstream_node_id` im Array, das eine verbundene Eingabe beschreibt, als String und nicht als Integer dargestellt wird.
</Tip>

### workflow

`prompt.workflow` enthält die folgenden Eigenschaften:

- `config` - ein Dictionary zusätzlicher Konfigurationsoptionen (standardmäßig leer)
- `extra` - ein Dictionary mit zusätzlichen Informationen zum Workflow. Standardmäßig enthält es:
    - `extra.ds` - beschreibt die aktuelle Ansicht des Graphen (`scale` und `offset`)
- `groups` - alle Gruppen im Workflow
- `last_link_id` - die ID der zuletzt hinzugefügten Verbindung
- `last_node_id` - die ID des zuletzt hinzugefügten Nodes
- `links` - eine Liste aller Verbindungen im Graphen. Jeder Eintrag ist ein Array aus fünf Integern und einem String:
    - (`link_id`, `upstream_node_id`, `upstream_node_output_slot`, `downstream_node_id`, `downstream_node_input_slot`, `data type`)
- `nodes` - eine Liste aller Nodes im Graphen. Jeder Eintrag ist eine Zuordnung einer Teilmenge der Eigenschaften des Nodes, wie [oben](#comfynode) beschrieben
    - Die folgenden Eigenschaften sind enthalten: `flags`, `id`, `inputs`, `mode`, `order`, `pos`, `properties`, `size`, `type`, `widgets_values`
    - Darüber hinaus gibt es, sofern ein Node Ausgänge besitzt, eine Eigenschaft `outputs`. Sie ist eine Liste der Ausgänge des Nodes, von denen jeder Folgendes enthält:
        - `name` - der Name des Ausgangs
        - `type` - der Datentyp des Ausgangs
        - `links` - eine Liste der `link_id` aller Verbindungen von diesem Ausgang (falls es keine Verbindungen gibt, kann sie leer oder null sein),
        - `shape` - die Form, mit der der Ausgang gezeichnet wird (Standard 3 für einen Punkt)
        - `slot_index` - die Slot-Nummer des Ausgangs
- `version` - die LiteGraph-Versionsnummer (zum Zeitpunkt der Erstellung `0.4`)

<Tip>
  `nodes.output` fehlt bei Nodes ohne Ausgänge, es ist keine leere Liste.
</Tip>
