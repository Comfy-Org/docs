## LiteGraph

Die ComfyUI-Oberfläche baut auf [LiteGraph](https://github.com/jagenjo/litegraph.js) auf. Ein Großteil der ComfyUI-Funktionalität wird von LiteGraph bereitgestellt. Wenn Sie komplexere Nodes entwickeln, ist es daher wahrscheinlich hilfreich, dieses Repository zu klonen und die Dokumentation zu durchsuchen, die Sie unter `doc/index.html` finden.

## ComfyApp

Das `app`-Objekt (immer erreichbar über `import { app } from "../../scripts/app.js";`) repräsentiert die Comfy-Anwendung, die im Browser läuft, und enthält eine Reihe nützlicher Eigenschaften und Funktionen, von denen einige unten aufgeführt sind.

<Note>
**Veraltet:** Das Hijacking/Monkey-Patching von Funktionen auf `app` oder Prototypen ist veraltet und kann sich in naher Zukunft jederzeit ändern. Verwenden Sie stattdessen die offiziellen [Erweiterungs-Hooks](/de/custom-nodes/js/javascript_hooks) und die [Context Menu API](/de/custom-nodes/js/context-menu-migration).
</Note>

<Warning>Das Hijacking von Funktionen auf `app` wird nicht empfohlen, da Comfy ständig weiterentwickelt wird und sich das Kernverhalten ändern kann.</Warning>

### Eigenschaften

Wichtige Eigenschaften von `app` sind (die Liste ist nicht vollständig):

| Eigenschaft     | Inhalt                                                                                                                                                          |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `canvas`        | Ein LGraphCanvas-Objekt, das die aktuelle Benutzeroberfläche darstellt. Es enthält einige potenziell interessante Eigenschaften wie `node_over` und `selected_nodes`. |
| `canvasEl`      | Das DOM-`<canvas>`-Element                                                                                                                                      |
| `graph`         | Eine Referenz auf das LGraph-Objekt, das den aktuellen Graphen beschreibt                                                                                       |
| `runningNodeId` | Während der Ausführung der Node, der gerade ausgeführt wird                                                                                                     |
| `ui`            | Bietet Zugriff auf einige UI-Elemente wie die Warteschlange, das Menü und Dialoge                                                                               |

`canvas` (für grafische Elemente) und `graph` (für logische Verbindungen) sind wahrscheinlich diejenigen, auf die Sie am ehesten zugreifen möchten.

### Funktionen

Auch hier gibt es viele davon. Einige wichtige sind:

| Funktion          | Hinweise                                                                  |
| ----------------- | ------------------------------------------------------------------------- |
| graphToPrompt     | Konvertiert den Graphen in einen Prompt, der an den Python-Server gesendet werden kann |
| loadGraphData     | Lädt einen Graphen                                                        |
| queuePrompt       | Sendet einen Prompt an die Warteschlange ab                               |
| registerExtension | Diese haben Sie schon gesehen: wird verwendet, um eine Erweiterung hinzuzufügen |

## LGraph

Das `LGraph`-Objekt ist Teil des LiteGraph-Frameworks und repräsentiert den aktuellen logischen Zustand des Graphen (Nodes und Verbindungen).
Wenn Sie den Graphen manipulieren möchten, beschreibt die LiteGraph-Dokumentation (unter `doc/index.html`, wenn Sie `https://github.com/jagenjo/litegraph.js` klonen)
die Funktionen, die Sie benötigen.

Mit `graph` können Sie Details zu Nodes und Verbindungen abrufen, zum Beispiel:

```Javascript
const ComfyNode_object_for_my_node = app.graph._nodes_by_id(my_node_id) 
ComfyNode_object_for_my_node.inputs.forEach(input => {
    const link_id = input.link;
    if (link_id) {
        const LLink_object = app.graph.links[link_id]
        const id_of_upstream_node = LLink_object.origin_id
        // usw.
    }
});
```


## LLink

Das Objekt `LLink`, auf das Sie über `graph.links` zugreifen, repräsentiert eine einzelne Verbindung im Diagramm, vom Ausgabeslot `link.origin_slot` des Nodes `link.origin_id` zum Slot `link.target_slot` des Nodes `link.target_id`. Außerdem enthält es eine Zeichenkette für den Datentyp in `link.type` sowie `link.id`.

`LLink`s werden in der Methode `connect` eines `LGraphNode` erstellt (von dem `ComfyNode` eine Unterklasse ist).

<Tip>Vermeiden Sie es, eigene LLink-Objekte zu erstellen. Verwenden Sie stattdessen die LiteGraph-Funktionen.</Tip>

## ComfyNode

`ComfyNode` ist eine Unterklasse von `LGraphNode`, daher ist die LiteGraph-Dokumentation für allgemeinere Operationen hilfreich. Comfy hat jedoch das Kernverhalten von LiteGraph deutlich erweitert und nutzt auch nicht alle Funktionen von LiteGraph.

<Tip>Die folgende Beschreibung gilt für einen normalen Node.
Group Nodes, Primitiv-Nodes, Note-Nodes und Redirect-Nodes haben andere Eigenschaften.</Tip>

Ein `ComfyNode`-Objekt repräsentiert einen Node im aktuellen Workflow. Es besitzt eine Reihe wichtiger Eigenschaften, die Sie nutzen können, sowie eine sehr große Anzahl von Funktionen, die Sie verwenden oder kapern können, um das Verhalten zu ändern.

<Note>
**Veraltet:** Das Hijacking von Prototyp-Methoden auf `ComfyNode` oder `LGraphNode` ist veraltet und kann sich jederzeit in naher Zukunft ändern. Verwenden Sie nach Möglichkeit die offiziellen [Erweiterungs-Hooks](/de/custom-nodes/js/javascript_hooks), etwa `getNodeMenuItems` für Kontextmenüs. Beispiele finden Sie im [Context Menu Migration Guide](/de/custom-nodes/js/context-menu-migration).
</Note>

Um einen vollständigeren Eindruck vom Node-Objekt zu bekommen, kann es hilfreich sein, den folgenden Code in Ihre Erweiterung einzufügen und einen Breakpoint auf den `console.log`-Befehl zu setzen. Wenn Sie dann einen neuen Node erstellen, können Sie mit Ihrem bevorzugten Debugger den Node inspizieren.

```Javascript
async nodeCreated(node) {
    console.log("nodeCreated")
}
```

### Eigenschaften

| Eigenschaft       | Inhalt                                                                                                                              |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `bgcolor`         | Die Hintergrundfarbe des Nodes oder undefined für die Standardeinstellung                                                            |
| `comfyClass`      | Die Python-Klasse, die den Node repräsentiert                                                                                       |
| `flags`           | Ein Dictionary, das Flags zum Status des Nodes enthalten kann. Insbesondere ist `flags.collapsed` bei eingeklappten Nodes `true`.    |
| `graph`           | Eine Referenz auf das LGraph-Objekt                                                                                                 |
| `id`              | Eine eindeutige ID                                                                                                                  |
| `input_type`      | Eine Liste der Eingabetypen (z. B. "STRING", "MODEL", "CLIP" usw.). Entspricht im Allgemeinen den Python-INPUT_TYPES                 |
| `inputs`          | Eine Liste der Eingänge (siehe unten)                                                                                               |
| `mode`            | Normalerweise 0, auf 2 gesetzt, wenn der Node stummgeschaltet (muted) ist, und auf 4, wenn er umgangen (bypassed) wird. Die Werte 1 und 3 werden von Comfy nicht verwendet |
| `order`           | Die Position des Nodes in der Ausführungsreihenfolge. Wird von `LGraph.computeExecutionOrder()` gesetzt, wenn der Prompt übermittelt wird |
| `pos`             | Die [x,y]-Position des Nodes auf dem Canvas                                                                                         |
| `properties`      | Ein Dictionary mit `"Node name for S&R"`, das von LiteGraph verwendet wird                                                          |
| `properties_info` | Typ und Standardwert der Einträge in `properties`                                                                                   |
| `size`            | Breite und Höhe des Nodes auf dem Canvas                                                                                            |
| `title`           | Angezeigter Titel                                                                                                                   |
| `type`            | Der eindeutige Name (aus Python) der Node-Klasse                                                                                    |
| `widgets`         | Eine Liste der Widgets (siehe unten)                                                                                                |
| `widgets_values`  | Eine Liste der aktuellen Werte der Widgets                                                                                          |### Funktionen

Es gibt eine sehr große Anzahl an Funktionen (85, als ich das letzte Mal gezählt habe). Eine Auswahl ist unten aufgeführt.
Die meisten dieser Funktionen sind unverändert aus dem LiteGraph-Kerncode übernommen.

#### Eingänge, Ausgänge, Widgets

| Funktion | Hinweise |
| --------------------- | -------------------------------------------------------------------------------------------------- |
| Eingänge / Ausgänge | Die meisten haben Ausgabemethoden mit den entsprechenden Namen: s/In/Out/ |
| `addInput` | Erstellt einen neuen Eingang, definiert durch Name und Typ |
| `addInputs` | Array-Version von `addInput` |
| `findInputSlot` | Sucht den Slot-Index anhand des Eingangsnamens |
| `findInputSlotByType` | Sucht einen Eingang, der dem Typ entspricht. Optionen, um freie Slots zu bevorzugen oder ausschließlich zu verwenden |
| `removeInput` | Nach Slot-Index |
| `getInputNode` | Ruft den Node ab, der mit diesem Eingang verbunden ist. Das Ausgangsäquivalent ist `getOutputNodes`, das eine Liste zurückgibt |
| `getInputLink` | Ruft das LLink-Objekt ab, das mit diesem Eingang verbunden ist. Kein Ausgangsäquivalent |
| Widgets | |
| `addWidget` | Fügt ein Standard-Comfy-Widget hinzu |
| `addCustomWidget` | Fügt ein benutzerdefiniertes Widget hinzu (definiert im `getComfyWidgets`-Hook) |
| `addDOMWidget` | Fügt ein Widget hinzu, das durch ein DOM-Element definiert ist |
| `convertWidgetToInput` | Wandelt ein Widget in einen Eingang um, wenn `isConvertableWidget` dies erlaubt (in `widgetInputs.js`) |

#### Verbindungen

| Funktion | Hinweise |
| --------------------- | ------------------------------------------------------------------------------------------------- |
| `connect` | Verbindet den Ausgang dieses Nodes mit dem Eingang eines anderen Nodes |
| `connectByType` | Verbindet den Ausgang durch Angabe des Typs mit einem anderen Node. Stellt eine Verbindung zum ersten verfügbaren passenden Slot her |
| `connectByTypeOutput` | Verbindet den Eingang nach Typ mit dem Ausgang eines anderen Nodes |
| `disconnectInput` | Entfernt jede Verbindung zum Eingang (angegeben durch Name oder Index) |
| `disconnectOutput` | Trennt einen Ausgang vom Eingang eines angegebenen Nodes |
| `onConnectionChange` | Wird bei jedem Node aufgerufen. `side==1`, wenn es sich um einen Eingang an diesem Node handelt |
| `onConnectInput` | Wird _vor_ dem Herstellen einer Verbindung aufgerufen. Wenn dies `false` zurückgibt, wird die Verbindung abgelehnt |

#### Anzeige

| Funktion | Hinweise |
| ------------------ | ------------------------------------------------------------------------------------------------------ |
| `setDirtyCanvas` | Gibt an, dass der Vordergrund (Nodes) und/oder der Hintergrund (Verbindungen und Bilder) neu gezeichnet werden müssen |
| `onDrawBackground` | Wird mit einem `CanvasRenderingContext2D`-Objekt aufgerufen, um den Hintergrund zu zeichnen. Wird von Comfy verwendet, um Bilder zu rendern |
| `onDrawForeground` | Wird mit einem `CanvasRenderingContext2D`-Objekt aufgerufen, um den Node zu zeichnen. |
| `getTitle` | Der anzuzeigende Titel. |
| `collapse` | Schaltet den reduzierten Zustand des Nodes um. |

Es akzeptiert einen booleschen Parameter, mit dem sich
`node.collapsable === false` überschreiben lässt.</Warning>

#### Sonstiges

| Funktion | Hinweise |
| ------------ | ------------------------------------------------------------------ |
| `changeMode` | Wird verwendet, um den Node als umgangen (`mode == 4`) oder nicht umgangen (`mode == 0`) festzulegen |

## Eingänge und Widgets

Eingänge und Widgets stellen die beiden Möglichkeiten dar, wie Daten in einen Node eingespeist werden können. Im Allgemeinen kann ein Widget in eine Eingabe umgewandelt werden, aber nicht alle Eingänge können in ein Widget umgewandelt werden (da viele Datentypen nicht über ein UI-Element eingegeben werden können).

`node.inputs` ist eine Liste der aktuellen Eingänge (farbige Punkte auf der linken Seite des Nodes), die deren `.name`, `.type` und `.link` angibt (eine Referenz auf die verbundene `LLink` in `app.graph.links`).

Wenn es sich bei einem Eingang um ein umgewandeltes Widget handelt, enthält er außerdem eine Referenz auf das nun inaktive Widget in `.widget`.

`node.widgets` ist eine Liste aller Widgets, unabhängig davon, ob sie in eine Eingabe umgewandelt wurden. Ein Widget hat:

| Eigenschaft/Funktion | Anmerkungen                                                                 |
| -------------------- | --------------------------------------------------------------------------- |
| `callback`           | Eine Funktion, die aufgerufen wird, wenn der Widget-Wert geändert wird      |
| `last_y`             | Die vertikale Position des Widgets im Node                                  |
| `name`               | Der Widget-Name (eindeutig innerhalb eines Nodes)                           |
| `options`            | Wie im Python-Code angegeben (z. B. Standard, Min. und Max.)                |
| `type`               | Der Name des Widget-Typs (siehe unten) in Kleinbuchstaben                   |
| `value`              | Der aktuelle Widget-Wert. Dies ist eine Eigenschaft mit den Methoden `get` und `set` |

### Widget-Typen

`app.widgets` ist ein Wörterbuch der aktuell registrierten Widget-Typen, wobei die Schlüssel die Typnamen in Großbuchstaben sind. Zu den in Comfy integrierten Widget-Typen gehören die selbsterklärenden `BOOLEAN`, `INT` und `FLOAT` sowie `STRING` (in zwei Varianten: einzeilig und mehrzeilig), `COMBO` für die Auswahl aus einer Dropdown-Liste und `IMAGEUPLOAD`, das in Nodes vom Typ Load Image verwendet wird.

Benutzerdefinierte Widget-Typen können hinzugefügt werden, indem Sie eine Methode `getCustomWidgets` in Ihrer Erweiterung bereitstellen.

## Prompt

Wenn Sie in Comfy auf die Schaltfläche `Queue Prompt` klicken, wird die Methode `app.graphToPrompt()` aufgerufen, um den aktuellen Node-Graph in einen Prompt umzuwandeln, der an den Server gesendet werden kann.

`app.graphToPrompt` gibt ein Objekt zurück (im Folgenden `prompt` genannt) mit den beiden Eigenschaften `output` und `workflow`.

### output

`prompt.output` bildet die `node_id` jedes Nodes im Graph auf ein Objekt mit zwei Eigenschaften ab.

- `prompt.output[node_id].class_type`, der eindeutige Name der Custom-Node-Klasse, wie im Python-Code definiert
- `prompt.output[node_id].inputs`, enthält den Wert jedes Eingangs (oder Widgets) als Zuordnung vom Namen des Eingangs zu:
    - dem ausgewählten Wert, wenn es ein Widget ist, oder
    - einem Array mit (`upstream_node_id`, `upstream_node_output_slot`), wenn eine Verbindung mit dem Eingang verbunden ist, oder
    - undefined, wenn es ein Widget ist, das in eine Eingabe umgewandelt wurde und nicht verbunden ist
    - andere nicht verbundene Eingänge sind nicht in `.inputs` enthalten

<Tip>Beachten Sie, dass die `upstream_node_id` im Array, das einen verbundenen Eingang beschreibt, als String und nicht als Integer dargestellt wird.</Tip>

### workflow

`prompt.workflow` enthält die folgenden Eigenschaften:

- `config` - ein Dictionary zusätzlicher Konfigurationsoptionen (standardmäßig leer)
- `extra` - ein Dictionary mit zusätzlichen Informationen über den Workflow. Standardmäßig enthält es:
    - `extra.ds` - beschreibt die aktuelle Ansicht des Graphs (`scale` und `offset`)
- `groups` - alle Gruppen im Workflow
- `last_link_id` - die ID der zuletzt hinzugefügten Verbindung
- `last_node_id` - die ID des zuletzt hinzugefügten Nodes
- `links` - eine Liste aller Verbindungen im Graph. Jeder Eintrag ist ein Array aus fünf Integern und einem String:
    - (`link_id`, `upstream_node_id`, `upstream_node_output_slot`, `downstream_node_id`, `downstream_node_input_slot`, `data type`)
- `nodes` - eine Liste aller Nodes im Graph. Jeder Eintrag ist eine Zuordnung einer Teilmenge der Eigenschaften des Nodes, wie [oben](#comfynode) beschrieben
    - Die folgenden Eigenschaften sind enthalten: `flags`, `id`, `inputs`, `mode`, `order`, `pos`, `properties`, `size`, `type`, `widgets_values`
    - Zusätzlich gibt es, sofern ein Node Ausgänge hat, eine Eigenschaft `outputs`, eine Liste der Ausgänge des Nodes, von denen jeder Folgendes enthält:
        - `name` - der Name des Ausgangs
        - `type` - der Datentyp des Ausgangs
        - `links` - eine Liste der `link_id` aller Verbindungen von diesem Ausgang (kann, wenn es keine Verbindungen gibt, eine leere Liste oder null sein),
        - `shape` - die Form, mit der der Ausgang gezeichnet wird (Standard 3 für einen Punkt)
        - `slot_index` - die Slot-Nummer des Ausgangs
- `version` - die LiteGraph-Versionsnummer (zum Zeitpunkt der Erstellung `0.4`)

<Tip>`nodes.output` fehlt bei Nodes ohne Ausgänge; es ist keine leere Liste.</Tip>
