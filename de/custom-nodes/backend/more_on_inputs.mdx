## Ausgeblendete Eingänge

Neben den Eingängen `required` und `optional`, die auf der Client-Seite entsprechende Eingänge oder Widgets erzeugen, gibt es drei `hidden`-Eingabeoptionen, mit denen ein Custom Node bestimmte Informationen vom Server anfordern kann.

Darauf greifen Sie zu, indem Sie im `dict` von `INPUT_TYPES` einen Wert für `hidden` zurückgeben, mit der Signatur `dict[str,str]`, der eines oder mehrere von `PROMPT`, `EXTRA_PNGINFO` oder `UNIQUE_ID` enthält.

```python
@classmethod
def INPUT_TYPES(s):
    return {
        "required": {...},
        "optional": {...},
        "hidden": {
            "unique_id": "UNIQUE_ID",
            "prompt": "PROMPT", 
            "extra_pnginfo": "EXTRA_PNGINFO",
        }
    }
```

### UNIQUE_ID 
`UNIQUE_ID` ist die eindeutige Kennung des Node und entspricht der Eigenschaft `id` des Node auf der Client-Seite. 
Sie wird häufig in der Client-Server-Kommunikation verwendet (siehe [Nachrichten](/de/development/comfyui-server/comms_messages#getting-node-id)).

### PROMPT
`PROMPT` ist der vollständige Prompt, den der Client an den Server sendet. 
Eine ausführliche Beschreibung finden Sie unter [das Prompt-Objekt](/de/custom-nodes/js/javascript_objects_and_hijacking#prompt).

### EXTRA_PNGINFO
`EXTRA_PNGINFO` ist ein Dictionary, das in die Metadaten aller gespeicherten `.png`-Dateien kopiert wird. Custom Nodes können in diesem Dictionary zusätzliche Informationen für das Speichern ablegen (oder um mit einem nachgelagerten Node zu kommunizieren).

<Tip>
  Beachten Sie: Wenn Comfy mit der Option `disable_metadata` gestartet wird, werden diese Daten nicht gespeichert.
</Tip>

### DYNPROMPT
`DYNPROMPT` ist eine Instanz von `comfy_execution.graph.DynamicPrompt`. Sie unterscheidet sich von `PROMPT` darin, dass sie sich im Laufe der Ausführung als Reaktion auf [Node Expansion](/de/custom-nodes/backend/expansion) ändern kann.
<Tip>
  `DYNPROMPT` sollte nur für fortgeschrittene Anwendungsfälle verwendet werden (etwa für die Implementierung von Schleifen in Custom Nodes).
</Tip>

## Flexible Eingaben

### Benutzerdefinierte Datentypen

Wenn Sie Daten zwischen Ihren eigenen Custom Nodes weitergeben möchten, kann es hilfreich sein, einen benutzerdefinierten Datentyp zu definieren. Das ist (fast) so einfach, wie sich einen Namen für den Datentyp auszudenken. Er sollte ein eindeutiger String in Großbuchstaben sein, zum Beispiel `CHEESE`.

Diesen `CHEESE` können Sie dann in den `INPUT_TYPES` und `RETURN_TYPES` Ihres Nodes verwenden, und der Comfy-Client lässt nur zu, dass `CHEESE`-Ausgänge mit einem `CHEESE`-Eingang verbunden werden. `CHEESE` kann ein beliebiges Python-Objekt sein.

Der einzige Punkt, den Sie beachten müssen: Da der Comfy-Client `CHEESE` nicht kennt, müssen Sie (sofern Sie kein benutzerdefiniertes Widget für `CHEESE` definieren, was ein Thema für sich ist) erzwingen, dass es als Eingabe statt als Widget behandelt wird. Das gelingt mit der Option `forceInput` im Dictionary der Eingabeoptionen:

```python
@classmethod
def INPUT_TYPES(s):
    return {
        "required": { "my_cheese": ("CHEESE", {"forceInput":True}) }
    }
```

### Wildcard-Eingaben

```python
@classmethod
def INPUT_TYPES(s):
    return {
        "required": { "anything": ("*",{})},
    }

@classmethod
def VALIDATE_INPUTS(s, input_types):
    return True
```

Das Frontend erlaubt `*`, um anzugeben, dass ein Eingang mit jeder Quelle verbunden werden kann. Da dies vom Backend nicht offiziell unterstützt wird, können Sie die Typprüfung im Backend überspringen, indem Sie in Ihrer Funktion `VALIDATE_INPUTS` einen Parameter namens `input_types` akzeptieren. (Weitere Informationen finden Sie unter [VALIDATE_INPUTS](/de/custom-nodes/backend/server_overview#validate_inputs).)
Es liegt beim Node selbst, die übergebenen Daten sinnvoll zu interpretieren.

### Dynamisch erzeugte Eingaben

Wenn Eingaben auf der Client-Seite dynamisch erzeugt werden, können sie nicht im Python-Quellcode definiert werden.
Um auf diese Daten zugreifen zu können, benötigen wir ein `optional`-Dictionary, das es Comfy erlaubt, Daten mit beliebigen Namen zu übergeben. Da der Comfy-Server

```python
class ContainsAnyDict(dict):
    def __contains__(self, key):
        return True
...

@classmethod
def INPUT_TYPES(s):
    return {
        "required": {},
        "optional": ContainsAnyDict()
    }
...

def main_method(self, **kwargs):
    # die dynamisch erzeugten Eingabedaten stehen im Dictionary kwargs

```
