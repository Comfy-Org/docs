Dies sind die wichtigsten integrierten Datentypen. Sie können auch [eigene definieren]( ./more_on_inputs#benutzerdefinierte-datentypen).

Datentypen werden auf der Clientseite verwendet, um zu verhindern, dass ein Workflow die falsche Art von Daten an einen Node übergibt, ähnlich wie bei einer starken Typisierung.
Der JavaScript-Code auf der Clientseite erlaubt es im Allgemeinen nicht, dass eine Node-Ausgabe mit einer Eingabe eines anderen Datentyps verbunden wird, obwohl unten einige Ausnahmen aufgeführt sind.

## Comfy-Datentypen

### COMBO

* Keine zusätzlichen Parameter in `INPUT_TYPES`

* Python-Datentyp: definiert als `list[str]`, Ausgabewert ist `str`

Stellt ein Dropdown-Menü-Widget dar.
Anders als andere Datentypen wird `COMBO` in `INPUT_TYPES` nicht durch einen `str` angegeben, sondern durch eine `list[str]`, die den Optionen in der Dropdown-Liste entspricht, wobei die erste Option standardmäßig ausgewählt ist.

Eingaben vom Typ `COMBO` werden oft zur Laufzeit dynamisch generiert. Zum Beispiel finden Sie im integrierten Node `CheckpointLoaderSimple`:

```
"ckpt_name": (folder_paths.get_filename_list("checkpoints"), )
```

oder sie können einfach eine feste Liste von Optionen sein,

```
"play_sound": (["no","yes"], {}),
```

### Primitive- und Reroute-Nodes

Primitive- und Reroute-Nodes existieren nur auf der Client-Seite. Sie besitzen keinen eigenen Datentyp, übernehmen aber bei Verbindung den Datentyp der Eingabe oder Ausgabe, mit der sie verbunden wurden (weshalb sie keine Verbindung zu einer `*`-Eingabe herstellen können ...).

## Python-Datentypen

### INT

* Zusätzliche Parameter in `INPUT_TYPES`:

  * `default` ist erforderlich

  * `min` und `max` sind optional

* Python-Datentyp `int`

### FLOAT

* Zusätzliche Parameter in `INPUT_TYPES`:

  * `default` ist erforderlich

  * `min`, `max`, `step` sind optional

* Python-Datentyp `float`

### STRING

* Zusätzliche Parameter in `INPUT_TYPES`:

  * `default` ist erforderlich

* Python-Datentyp `str`

### BOOLEAN

* Zusätzliche Parameter in `INPUT_TYPES`:

  * `default` ist erforderlich

* Python-Datentyp `bool`

## Tensor-Datentypen

### IMAGE

* Keine zusätzlichen Parameter in `INPUT_TYPES`

* Python-Datentyp `torch.Tensor` mit *Form* \[B,H,W,C]

Ein Batch von `B` Bildern, Höhe `H`, Breite `W`, mit `C` Kanälen (in der Regel `C=3` für `RGB`).

### LATENT

* Keine zusätzlichen Parameter in `INPUT_TYPES`

* Python-Datentyp `dict`, der einen `torch.Tensor` mit *Form* \[B,C,H,W] enthält

Das übergebene `dict` enthält den Schlüssel `samples`, ein `torch.Tensor` mit *Form* \[B,C,H,W], der einen Batch von `B` Latents mit `C` Kanälen (in der Regel `C=4` bei bestehenden Stable-Diffusion-Modellen), Höhe `H` und Breite `W` darstellt.

Höhe und Breite betragen 1/8 der entsprechenden Bildgröße (also des Werts, den Sie im Node `Empty Latent Image` festlegen).

### MASK

* Keine zusätzlichen Parameter in `INPUT_TYPES`

* Python-Datentyp `torch.Tensor` mit *Form* \[B,H,W], bzw. \[H,W] bei einer einzelnen, nicht gebatchten Maske

### AUDIO

* Keine zusätzlichen Parameter in `INPUT_TYPES`

* Python-Datentyp `dict`, der einen `torch.Tensor` mit *Form* \[B, C, T] und eine Abtastrate enthält.

Das übergebene `dict` enthält den Schlüssel `waveform`, ein `torch.Tensor` mit *Form* \[B, C, T], der einen Batch von `B` Audiosamples mit `C` Kanälen (`C=2` für Stereo und `C=1` für Mono) und `T` Zeitschritten (d. h. die Anzahl der Audiosamples) darstellt.

Das `dict` enthält einen weiteren Schlüssel `sample_rate`, der die Abtastrate des Audios angibt.

## Benutzerdefinierte Sampling-Datentypen

### Rauschen

Der Datentyp `NOISE` repräsentiert eine *Quelle* für Rauschen (nicht das eigentliche Rauschen selbst). Er kann durch jedes beliebige Python-Objekt dargestellt werden, das eine Methode zum Generieren von Rauschen mit der Signatur `generate_noise(self, input_latent:dict) -> Tensor` sowie eine Eigenschaft `seed:Optional[int]` bereitstellt.

<Tip>
  Die `seed` wird im `SamplerCustomAdvanced` an den `sample`-Guider übergeben, scheint aber in keinem der Standard-Guider verwendet zu werden. Sie ist optional, daher können Sie sie in der Regel auf None setzen.
</Tip>

Wenn Rauschen hinzugefügt werden soll, wird das LATENT-Dictionary an diese Methode übergeben. Die eingebauten Generatoren lesen daraus den `samples`-Tensor; die Methode sollte einen `Tensor` derselben Form zurückgeben, der das Rauschen enthält.

Siehe das [Beispiel zum Mischen von Rauschen](/de/custom-nodes/backend/snippets#rauschvarianten-erstellen)

### Sampler

Der Datentyp `SAMPLER` repräsentiert einen Sampler, der als Python-Objekt dargestellt wird, das eine `sample`-Methode bereitstellt. Das Sampling mit Stable Diffusion würde den Rahmen dieser Anleitung sprengen; sehen Sie sich `comfy/samplers.py` an, wenn Sie sich eingehender mit diesem Teil des Codes beschäftigen möchten.

### Sigmas

Der Datentyp `SIGMAS` repräsentiert die Sigma-Werte vor und nach jedem Schritt im Sampling-Prozess, wie sie von einem Scheduler erzeugt werden. Er wird als eindimensionaler Tensor der Länge `steps+1` dargestellt, wobei jedes Element das Rauschen repräsentiert, das vor dem entsprechenden Schritt erwartet wird, und der letzte Wert das Rauschen nach dem letzten Schritt angibt.

Ein `normal`-Scheduler mit 20 Schritten und einem Denoise-Wert von 1 erzeugt für ein SDXL-Modell:

```
tensor([14.6146, 10.7468,  8.0815,  6.2049,  4.8557,  
         3.8654,  3.1238,  2.5572,  2.1157,  1.7648,  
         1.4806,  1.2458,  1.0481,  0.8784,  0.7297,  
         0.5964,  0.4736,  0.3555,  0.2322,  0.0292,  0.0000])
```

<Tip>
  Der Startwert von Sigma hängt vom Modell ab, weshalb ein Scheduler-Node eine `MODEL`-Eingabe benötigt, um eine SIGMAS-Ausgabe zu erzeugen.
</Tip>

### Guider

Ein `GUIDER` ist eine Verallgemeinerung des Denoising-Prozesses, der durch einen Prompt oder eine andere Form der Konditionierung „geführt“ wird. In Comfy wird der Guider durch ein `callable` Python-Objekt dargestellt, das eine Methode `__call__(*args, **kwargs)` bereitstellt, die vom Sampler aufgerufen wird.

Die Methode `__call__` nimmt (in `args[0]`) einen Batch verrauschter Latents (Tensor `[B,C,H,W]`) entgegen und gibt eine Vorhersage des Rauschens zurück (einen Tensor derselben Form).
