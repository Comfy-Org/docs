## Was ist ein Custom Node?

Eine der großen Stärken von Comfy ist, dass Sie durch den Node-basierten Ansatz neue Workflows entwickeln können, indem Sie die bereitgestellten Nodes auf unterschiedliche Weise kombinieren. Die integrierten Nodes bieten eine breite Palette an Funktionen, aber möglicherweise benötigen Sie eine Funktion, die kein Core-Node bereitstellt.

Custom Nodes sind Nodes, die von der Community entwickelt werden. Sie ermöglichen es Ihnen, neue Funktionen zu implementieren und sie mit der gesamten Community zu teilen. Wenn Sie daran interessiert sind, Custom Nodes zu entwickeln, können Sie [hier](/de/custom-nodes/overview) mehr darüber lesen.

## ComfyUI Manager

Custom Nodes lassen sich zwar manuell installieren, die meisten verwenden dafür jedoch [ComfyUI Manager](https://github.com/Comfy-Org/ComfyUI-Manager). **ComfyUI Manager** übernimmt das Installieren, Aktualisieren und Entfernen von Custom Nodes samt aller Abhängigkeiten. Er ist jedoch nicht Teil des Comfy-Kerns, daher müssen Sie ihn manuell installieren.

### ComfyUI Manager installieren

```bash
cd ComfyUI/custom_nodes
git clone https://github.com/Comfy-Org/ComfyUI-Manager.git
```

Starten Sie Comfy anschließend neu.
Details oder Sonderfälle finden Sie unter [ComfyUI Manager Install](https://github.com/Comfy-Org/ComfyUI-Manager?tab=readme-ov-file#installation).

### ComfyUI Manager verwenden

Damit Ihr Custom Node über **ComfyUI Manager** verfügbar ist, müssen Sie ihn als Git-Repository speichern (in der Regel auf `github.com`) und dann einen Pull Request im Git von **ComfyUI Manager** absenden, in dem Sie `custom-node-list.json` bearbeitet haben, um Ihren Node hinzuzufügen.
[Weitere Details](https://github.com/Comfy-Org/ComfyUI-Manager?tab=readme-ov-file#how-to-register-your-custom-node-into-comfyui-manager).

Wenn ein Benutzer den Node installiert, führt **ComfyUI Manager** Folgendes aus:

<Steps>
<Step title="Git klonen">
das Repository klonen,
</Step>
<Step title="Python-Abhängigkeiten installieren">
die im Custom-Node-Repository unter `requirements.txt` aufgeführten pip-Abhängigkeiten installieren (falls vorhanden),
```
pip install -r requirements.txt
```
<Tip>
  Wie bei `pip` immer möglich, kann es vorkommen, dass die Anforderungen Ihres Nodes mit anderen Custom Nodes in Konflikt stehen. Machen Sie Ihre `requirements.txt` nicht restriktiver als nötig.</Tip>
</Step>
<Step title="Installationsskript ausführen">
`install.py` ausführen, falls es im Custom-Node-Repository vorhanden ist.
<Tip>
  `install.py` wird vom Stammpfad des Custom Node aus ausgeführt</Tip>
</Step>
</Steps>

### Dateien von ComfyUI Manager

Wie oben beschrieben gibt es eine Reihe von Dateien und Skripten, die **ComfyUI Manager** nutzt, um den Lebenszyklus eines Custom Node zu verwalten. Alle davon sind optional.

- `requirements.txt` - Python-Abhängigkeiten, wie oben erwähnt
- `install.py`, `uninstall.py` - werden ausgeführt, wenn der Custom Node installiert oder deinstalliert wird
<Tip>
  Benutzer können das Verzeichnis einfach löschen, daher können Sie sich nicht darauf verlassen, dass `uninstall.py` ausgeführt wird</Tip>
- `disable.py`, `enable.py` - optionale Hooks. Nur der veraltete git-clone-Ablauf führt sie aus, wenn er einen Node deaktiviert oder wieder aktiviert. Die aktuellen Aktionen zum Deaktivieren und Aktivieren verschieben lediglich den Ordner, verlassen Sie sich also nicht auf diese Skripte
<Tip>
  `enable.py` wird nur ausgeführt, wenn ein deaktivierter Node wieder aktiviert wird - es sollte ausschließlich das rückgängig machen, was in `disable.py` getan wurde</Tip>
<Tip>
  Beim Deaktivieren eines Custom Node wird sein Ordner nach `ComfyUI/custom_nodes/.disabled/` verschoben, und Comfy ignoriert ihn, solange er dort liegt</Tip>
- `node_list.json` - nur erforderlich, wenn das Muster von NODE_CLASS_MAPPINGS in den Custom Nodes nicht konventionell ist.

Offizielle Details finden Sie im [ComfyUI Manager guide](https://github.com/Comfy-Org/ComfyUI-Manager?tab=readme-ov-file#custom-node-support-guide).
