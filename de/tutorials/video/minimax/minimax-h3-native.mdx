### Tipps zum Prompting

1. **Szene zuerst**: Zuerst die Gesamtszene, dann die zeitlich getakteten Shots
2. **Ein Block**: Shots, Kamera, Dialog, SFX und Musik zusammen
3. **Auflösung**: Natives 16:9 ist **1344×768** (768px an der kurzen Kante); auf Vielfache von **32** runden
4. **Dauer**: Rastet bei 24fps auf **17k+5** Frames ein
5. **Erstes/letztes Bild**: Verbinden Sie Bilder mit `first_frame` / `last_frame` am Node `MiniMaxH3ImageToVideo` für FL2VA
6. **Turbo**: Standard sind **20** Schritte; aktivieren Sie `turbo_mode` für den **8**-Schritte-Lightning-LoRA (schneller, etwas weichere Bewegung/Audio). Erhöhen Sie die Schritte (z. B. **25**) für eine bessere Bewegungsqualität

### Tipps zum Prompting

1. **Keyframes**: Optional `first_frame` / `last_frame`; die Bewegung wird dazwischen generiert
2. **Prompt**: Shots, Bewegung und Audio in einem Block
3. **Auflösung / Dauer**: dieselben Regeln wie bei T2V (**1344×768** natives Ziel, **17k+5**-Raster)
4. **Turbo**: `turbo_mode` verwendet `turbo_steps` (Standard **8**) und `turbo_model_strength` (Standard **1.0**) statt 20 Schritten

`first_frame` wird ohne Beibehaltung des Seitenverhältnisses auf den Canvas skaliert, sodass ein Bild mit abweichendem Seitenverhältnis gestreckt herauskommt. `last_frame` wird stattdessen mittig zugeschnitten. Die I2V-Vorlage öffnet mit **1:1** und **0.4** MP (**640×640**); stellen Sie daher das Seitenverhältnis auf Ihr Bild ein und erhöhen Sie den Megapixels-Wert für einen finalen Render.

### Prompting-Tipps

1. **Tags**: Referenzieren Sie Eingaben als `<Picture 1>`, `<Video 1>`, `<Audio 1>` (`ref_image_0` → `<Picture 1>`). Node-Reihenfolge: Bilder, dann Videos, dann Audio
2. **Rollen zuweisen**: Geben Sie an, welche Referenz Identität, Stil, Bewegung, Kamera oder Stimme steuert
3. **Grenzen**: Bis zu **9** Bilder, **3** Videos, **3** eigenständige Audioclips
4. **Video-FPS**: Referenzvideos werden mit **24fps** ohne Metadaten gelesen. Konvertieren Sie andere Bildraten vor dem Laden auf 24fps
5. **Video-Ton**: Bild und Tonspur sind separate Referenzen. Verbinden Sie `ref_video_audio_N` passend zu `ref_video_N`, sonst wird der Ton der Datei nicht als `<Audio N>` verwendet
6. **Audio-Nummerierung**: Video-Tonspuren erhalten zuerst `<Audio N>` (Video-Reihenfolge), danach folgen eigenständige Clips. Video- und Bild-Indizes sind unabhängig
7. **VAE-Verkabelung**: Video-Ton benötigt `vae` + `audio_vae`; eigenständiges Audio nur `audio_vae`
8. **Audio-Rollen**: z. B. `use <Audio 1> exactly as it is` gegenüber `follow the timbre of <Audio 2>`
9. **Stimme**: Audio liefert das Timbre, nicht die Wörter. Geben Sie die Sprechweise an; eine Audio-Referenz pro Sprecher, wenn die Zuordnung exakt sein muss
10. **`ref_image_size`**: Standard ist **`match`** (an Canvas einpassen). **`max`** behält 2048px an der kurzen Kante und ist deutlich langsamer; kleine Dateien werden dabei nicht hochskaliert (Seiten auf 32 runden). Skalieren Sie bei Bedarf vorab auf 2048 an der kurzen Kante
11. **Gewichte**: R2V verwendet **`ref2va`**, nicht das T2V/I2V-Modell **`fl2va`**
12. **Turbo**: Optionales **4**-Step-Lightning-LoRA (schneller, schwächere Referenz-/Audio-Treue). Bevorzugen Sie **20–25** Schritte, wenn die Referenzen halten müssen
13. **Style-LoRAs**: Konkurrieren mit Referenzen; verwenden Sie eine niedrige Stärke (~**0.5**) im Basis-Schedule, wenn die Treue wichtig ist

Offizieller Referenz-Leitfaden: [Prompt-Leitfaden](/de/tutorials/video/minimax/minimax-h3-prompt-guide).

## Erweiterte Workflows mit den nativen Nodes

Erfordert einen aktuellen ComfyUI-Build für die folgenden Funktionen.

### Guides an jedem beliebigen Frame verankern (#15439)

[`MiniMaxH3AddGuide`](https://github.com/Comfy-Org/ComfyUI/pull/15439) verankert einen Guide an einem beliebigen `frame_idx` (negativ = vom Ende), nicht nur am ersten/letzten Frame.

Verbinden Sie `positive` und Latent von einem H3-Node mit `MiniMaxH3AddGuide`. Eingänge:

- **image**: Standbild oder Clip (Batches mit mehreren Frames werden auf gültige **17k+5**-Längen zugeschnitten; bei &lt;5 Frames wird nur das erste Bild verwendet)
- **audio**: Soundtrack am selben Frame-Index, zugeschnitten auf die verbleibende Dauer
- **frame_idx**: Position des Ankers

Verbinden Sie `vae` für Bild-Guides und `audio_vae` für Audio. Verketten Sie Nodes für mehrere Anker.

Beispiel: Die ersten **22** Frames eines Clips an Frame **0** setzen beide Streams fort; ein Standbild an Frame **60** erzwingt die Einstellung durch diese Pose.

Dies ist Konditionierung, nicht Video-zu-Video: Das Sampling startet weiterhin vom leeren Latent des Workflows. `denoise` skaliert die Stärke der Guides nicht wie bei V2V. Um einen ganzen Clip umzugestalten, verwenden Sie R2V; um Bereiche zu bearbeiten, verwenden Sie die Maskierungen von [Fun ControlNet Union](/de/tutorials/video/minimax/minimax-h3-fun-controlnet).

Siehe die Vorlage [Multiframe Reference](/de/tutorials/video/minimax/minimax-h3-multiframe).

### Inpainting und Erweiterung mit Latent-Rausch-Maskierungen (#15375)

[Per-Token-Rausch-Maskierungen](https://github.com/Comfy-Org/ComfyUI/pull/15375) auf Video- und Audio-Latents ermöglichen es Ihnen, einen Teil eines Clips neu zu generieren.

Verbinden Sie eine Maskierung mit dem Sampler-`denoise_mask`: **0** = behalten, **1** = neu generieren. Video-Maskierungen rasten auf dem 2×2-Latent-Patch-Raster ein; Audio-Maskierungen auf ganzen Latent-Frames. Verwenden Sie dies zum Inpainting, Entfernen oder Erweitern, während der Rest stabil bleibt.
