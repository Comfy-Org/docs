**Causal Forcing** ist eine Videogenerierungstechnik, die während der Inferenz **rekurrente Konditionierung** anwendet: Jedes generierte Einzelbild wird zurück in das Modell gespeist, um das nächste Einzelbild vorherzusagen. So entstehen aus einem einzigen Startbild in nur **1 bis 4 Inferenzschritten** glatte, zeitlich konsistente Videos.

Dieser Workflow verwendet **Wan2.1** und unterstützt sowohl den Modus **Causal Forcing** (Standard) als auch **Causal Forcing++** (erweitert).

## So funktioniert es

Anders als die standardmäßige Videogenerierung, bei der alle Frames parallel verarbeitet werden, behandelt Causal Forcing die Videogenerierung als **sequenziellen Prozess**:

1. Das Modell verwendet ein Eingabebild als **erstes Frame**.
2. Es generiert das nächste Frame, konditioniert auf das vorherige.
3. Jedes neue Frame wird zur Eingabe für die nächste Vorhersage.
4. Dies wiederholt sich für die gewünschte Anzahl der Frames.

Dieser rekurrente Ansatz erzeugt eine **starke zeitliche Konsistenz**: Jedes Frame folgt auf natürliche Weise aus dem vorherigen. Damit lassen sich hochwertige Ergebnisse mit sehr wenigen Inferenzschritten (1 bis 4) erzielen.

### Causal Forcing vs Causal Forcing++

| Modus | Beschreibung |
|---|---|
| **Causal Forcing** | Standardmäßige rekurrente Konditionierung. Gute Qualität mit 2–4 Schritten. |
| **Causal Forcing++** | Erweiterter Modus, der zusätzliche Konditionierung für eine bessere zeitliche Kohärenz anwendet. Funktioniert gut mit nur 1–2 Schritten. |

## Workflow verwenden

### Eingänge

Der Workflow akzeptiert ein einzelnes Eingabebild (den ersten Frame) sowie einen Text-Prompt, der den gewünschten Videoinhalt beschreibt (optional).

| Einstellung | Beschreibung |
|---|---|
| **first_frame** (erforderlich) | Das Startbild für das Video. Laden Sie ein PNG/JPG über den **LoadImage**-Node. |
| **positive_prompt** (optional) | Eine Textbeschreibung des gewünschten Videoinhalts. Lassen Sie das Feld leer, um keine Konditionierung zu verwenden. |
| **duration** (optional) | Die Anzahl der Frames, die generiert werden sollen. Standard: Anzahl der Frames in der erwarteten Ausgabe des Modells. |

### Parameter des WAN-I2V-Subgraphs

Diese werden als Steuerelemente am Blueprint-Subgraph-Node bereitgestellt:

| Parameter | Standard | Beschreibung |
|---|---|---|
| `unet_name` | - | Der zu verwendende Checkpoint des Wan2.1-I2V-Modells |
| `clip_name` | - | Das CLIP- oder Text-Encoder-Modell für den Prompt |
| `vae_name` | - | Das VAE-Modell zum Kodieren/Dekodieren |
| `width` | - | Breite des Ausgabevideos |
| `height` | - | Höhe des Ausgabevideos |
| `noise_seed` | - | Seed für die Reproduzierbarkeit |

## Schritte zur Ausführung

1. **Bild laden**: Verwenden Sie den Node **LoadImage**, um Ihr Startbild zu laden.
2. **Prompt schreiben** (optional): Beschreiben Sie den gewünschten Videoinhalt.
3. **Dauer festlegen**: Anzahl der zu generierenden Frames.
4. **Modelle auswählen**: Wählen Sie den Wan2.1 I2V Checkpoint, CLIP und VAE aus.
5. **Modus wählen**: Causal Forcing oder Causal Forcing++ (festgelegt über die interne Konfiguration des Subgraphs oder eine Causal-Forcing-spezifische Eingabe, falls verfügbar).
6. **Run**: Frames werden nacheinander generiert und in `ComfyUI/output/` gespeichert.
