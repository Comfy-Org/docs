Jede Anfrage an einen Partner-Node erzeugt Daten, die auf unserer Plattform gespeichert werden: Eingänge (Bilder, Videos, 3D-Assets, Audio) und vom Modell erzeugte Ausgänge. Diese Seite erläutert, wie lange die jeweiligen Datenarten aufbewahrt werden. Wo jeder Anbieter diese Daten standardmäßig verarbeitet, ist separat unter [Modellanbieter](/de/tutorials/partner-nodes/model-providers) dokumentiert.

## Was gespeichert wird

Wenn Sie einen Partner Node ausführen, werden zwei Arten von Dateien gespeichert:

- **Eingabedateien**: Referenzbilder, Audio und andere Medien, die Sie einem Node bereitstellen. Eingaben werden in den Speicherplatz Ihres Kontos hochgeladen.
- **Ausgabedateien**: die Bilder, Videos, Audio und anderen Medien, die ein Node erzeugt. Ausgaben werden in einem von Comfy verwalteten Speicher abgelegt und Ihnen als Download-URLs zurückgegeben.

Sowohl Eingabe- als auch Ausgabedateien werden in von Comfy verwalteten Cloud-Speicher-Buckets gespeichert.

## Wie lange Dateien aufbewahrt werden

Alle Mediendateien von Partner Nodes werden **24 Stunden** nach ihrer Erstellung automatisch gelöscht. Die Löschung gilt sowohl für Eingabe- als auch für Ausgabedateien.

| Dateityp | Gelöscht nach |
| --- | --- |
| Eingabedateien | 24 Stunden |
| Ausgabedateien | 24 Stunden |

<Note>
  Das 24-Stunden-Löschfenster ist eine Plattformvorgabe und gilt für alle Aufrufe von Partner Nodes. Wenn Sie Dateien länger behalten möchten, laden Sie sie vor Ablauf in Ihren eigenen Speicher herunter.
</Note>

## Was nach dem Löschen passiert

Sobald eine Datei gelöscht wurde, gibt ihre Download-URL einen Fehler zurück. Gelöschte Dateien können nicht wiederhergestellt werden. Wenn Sie dieselben Medien erneut benötigen, müssen Sie sie erneut hochladen oder neu generieren.

Das Löschen einer Eingabedatei entfernt außerdem den entsprechenden Dateieintrag aus Ihrem Kontospeicher, sodass die Eingabe nicht durch spätere Aufrufe wiederverwendet werden kann.

## Task-Aufzeichnungen des Anbieters

Einige Partner-Nodes senden dem Anbieter eine Task-ID statt einer Mediendatei, und der Anbieter arbeitet mit der Aufzeichnung, die hinter dieser ID steht. Tripos Folge-Nodes funktionieren so: `Tripo: Texture model`, `Tripo: Rig model`, `Tripo: Retarget rigged model`, `Tripo: Convert model`, `Tripo: Edit Multiview`, `Tripo: Segment Model`, `Tripo: Retopology` und `Tripo: Complete Mesh Parts` erwarten alle eine Eingabe wie `model_task_id` oder `multiview_task_id`.

Die generierte Modelldatei ist nicht betroffen. Sie wird heruntergeladen, sobald die Aufgabe abgeschlossen ist, und in Ihrem Ausgabeverzeichnis gespeichert.

Die Aufbewahrung von Task-Aufzeichnungen richtet sich nach den Vorgaben des jeweiligen Anbieters, nicht nach dem oben genannten 24-Stunden-Fenster. Tripo bewahrt eine Task-Aufzeichnung nach Abschluss der Aufgabe 7 Tage lang auf (gültig ab 1. Dezember 2026). Eine ältere Task-ID kann nicht mehr aufgelöst werden. Daher schlägt das erneute Ausführen eines gespeicherten Workflows mit einer abgelaufenen `model_task_id` am Folge-Node fehl.

Zur Wiederherstellung importieren Sie die Modelldatei, die Sie bereits heruntergeladen haben, erneut mit `Tripo: Import Model`. Dieser gibt eine neue `model_task_id` zurück, die die Texture-, Rig- und Convert-Nodes akzeptieren, sodass Sie nicht erneut für das Basismodell zahlen müssen.

## Dateien länger aufbewahren

Wenn Ihr Workflow erfordert, dass eine Eingabedatei länger als 24 Stunden verfügbar bleibt, laden Sie die Datei vor jeder Aufgabe erneut hoch. Bei lang laufenden Pipelines laden Sie sie direkt vor dem Aufruf erneut hoch, der sie benötigt.

Laden Sie Ausgänge, die Sie behalten möchten, innerhalb des 24-Stunden-Fensters in Ihren eigenen Speicher herunter.

## Referenz

| Element | Wert |
| --- | --- |
| Aufbewahrung von Eingabedateien | 24 Stunden |
| Aufbewahrung von Ausgabedateien | 24 Stunden |

Allgemeine Informationen dazu, wie Comfy mit Kundendaten umgeht, finden Sie unter [Datenaufbewahrung](/de/support/data-retention).
