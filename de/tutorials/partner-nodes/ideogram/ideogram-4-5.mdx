**Ideogram 4.5** ändert nur, was der Prompt verlangt, sodass wiederholte Bearbeitungen Farben, Texturen und Details beibehalten. Ideogram 4.6 ist das neuere Modell mit nativer 4K-Ausgabe: [Ideogram 4.6 in ComfyUI](/de/tutorials/partner-nodes/ideogram/ideogram-4-6). Beide stehen als Modelloptionen in drei Partner-Nodes zur Verfügung, die pro Bild über dasselbe Comfy-Konto wie die übrigen Partner-Nodes abgerechnet werden. Ideogram 4.0 behält seine eigene Seite: [Ideogram 4.0 in ComfyUI](/de/tutorials/partner-nodes/ideogram/ideogram-v4).

Der **Ideogram 4.5 Text to Image** Node erwartet folgende Eingaben:

| Eingabe | Werte | Wirkung |
| --- | --- | --- |
| `prompt` | bis zu 10000 Zeichen | Die Bildbeschreibung. Eine strukturierte JSON-Beschreibung funktioniert hier ebenfalls, zum Beispiel ein `final_prompt` aus einem früheren Lauf |
| `size` | `auto` oder eine 1K- oder 2K-Voreinstellung | `auto` lässt das Modell einen Canvas wählen, der zum Prompt passt. Die Voreinstellungen decken 1K und 2K ab und reichen von `1:1` bis `23:9`, zum Beispiel `(2K) 2048x2048 (1:1)` und `(1K) 1280x720 (16:9)` |
| `quality` | `low`, `medium` (Standard), `high` | Höhere Stufen kosten mehr und dauern länger |
| `magic_prompt` | `auto` (Standard), `on`, `off` | Schreibt den Prompt vor der Generierung in eine detaillierte strukturierte Beschreibung um. Bei `off` bleibt Ihre Formulierung so wörtlich wie möglich |
| `seed` | Ganzzahl | Text zu Bild ist allein anhand des Seeds nicht reproduzierbar, da der Prompt bei jedem Lauf neu geschrieben wird |

Der Node gibt außerdem `final_prompt` aus, die strukturierte Beschreibung, aus der das Bild generiert wurde. Um ein Bild zu reproduzieren, geben Sie diese Beschreibung erneut ein, mit `magic_prompt` auf `off` und demselben Seed.

## Bildbearbeitung

Die Vorlage erstellt ihre Anweisung mit einem **Build JSON Prompt**-Node, sodass Sie einen Bereich des Bildes markieren und mit einer Beschriftung versehen können, zum Beispiel „remove it“. Aktivieren Sie [Nodes 2.0](/de/interface/nodes-2), falls der Editor nicht erscheint.

Der Node **Ideogram 4.5 Edit** ergänzt:

| Eingabe | Werte | Wirkung |
| --- | --- | --- |
| `size` | `auto` (Standard), `source`, eine Voreinstellung oder `custom` | `auto` wählt anhand der Bilder und des Prompts einen Canvas von etwa 2K. `source` behält die Größe von `image_1` bei. Eine Voreinstellung mit einem anderen Seitenverhältnis setzt die Szene neu zusammen. `custom` verwendet die untenstehenden `width` und `height` |
| `width`, `height` | 256 bis 4608, Schrittweite 32 | Wird nur verwendet, wenn `size` auf `custom` steht. Beide Abmessungen zusammen müssen innerhalb von 4194304 Pixeln (2048x2048) und innerhalb eines Seitenverhältnisses von 6:1 bleiben |
| `quality` | `very_low`, `low`, `medium` (Standard), `high` | Höhere Stufen kosten mehr und dauern länger |
| `seed` | Ganzzahl | Dieselben Bilder, derselbe Prompt, dieselben Einstellungen und derselbe Seed ergeben dasselbe Ergebnis |

Insgesamt können bis zu fünf Bilder verbunden werden. Eingänge über etwa 4 MP werden vor dem Hochladen verkleinert, und jedes Bild muss zwischen 1:6 und 6:1 liegen.

Edit rendert das gesamte Bild neu und kann daher den Bildausschnitt und die unveränderten Bereiche zusammen mit der Bearbeitung verschieben. Verwenden Sie Precise Edit, wenn der Rest des Bildes exakt unverändert bleiben muss.

## Precise Edit

Ändern Sie nur, was der Prompt verlangt. Unberührte Pixel bleiben identisch. Akzeptiert bis zu vier Referenzbilder zusätzlich zum Bild, das bearbeitet wird.

Precise Edit teilt die Referenz-Slots, die Adressierung über `@Image1` sowie die Regler `quality` und `seed` mit Edit. Eine Größensteuerung gibt es nicht. Mit einer Region behält die Ausgabe die Größe von `image_1`. Ohne Region (`context_window` auf dem Standardwert `none`) werden Quellen über etwa 4 MP zuerst herunterskaliert, sodass die Ausgabe kleiner sein kann. Die Vorlage erzeugt ihre Anweisung ebenfalls mit dem Node **Build JSON Prompt**.

### Eine einzelne Region bearbeiten

Ohne Region rendert der Node `image_1` vollständig neu, und alles über etwa 4 MP (2048x2048) wird zuerst herunterskaliert. Setzen Sie `context_window`, um stattdessen eine einzelne Region zu bearbeiten: Nur diese Region wird neu generiert, und die Ausgabe behält die Originalgröße von `image_1`, aus einer Quelle von bis zu 8192x8192 Pixeln. Außerhalb der Region werden Pixel unverändert übernommen, solange `image_1` ein PNG bleibt. Wird `image_1` in JPEG umgewandelt, weil das PNG das Upload-Budget überschreitet, können sich Pixel außerhalb der Region geringfügig ändern.

| `context_window` | Zusätzliche Eingabe | Bearbeitete Region |
| --- | --- | --- |
| `none` (Standard) | keine | Das gesamte Bild, über etwa 4 MP herunterskaliert |
| `auto` | `context_window_mask` | Wird um den weißen Bereich der Maskierung gelegt |
| `custom` | `context_window_bboxes` | Ein umschließendes Rechteck um alle verbundenen Begrenzungsrahmen (der Zwischenraum zwischen getrennten Rahmen ist enthalten und kann bearbeitet werden), zum Beispiel aus dem Node **Create Bounding Boxes** |

Die Region kann 256 bis 4608 Pixel pro Seite groß sein, bis zu etwa 4 MP und höchstens im Verhältnis 6:1. Regionen oder Rahmen unter 256 Pixeln pro Seite werden auf 256 aufgefüllt. Halten Sie bei `auto` die Region von `context_window_mask` innerhalb derselben Grenzen. Ein größerer weißer Bereich wird nicht abgelehnt: Ideogram kann auf eine Bearbeitung des gesamten Bildes zurückfallen, und ein großes Bild kann herunterskaliert werden. Nur die Region muss gültig sein, daher kann `image_1` selbst jedes Seitenverhältnis haben, und mit `context_window_mask` können Sie drei Referenzbilder statt vier verbinden.

Nutzen Sie es für Produkt-Umfärbungen, Materialwechsel und Retuschen, bei denen Beleuchtung, Hintergrund und Bildausschnitt des restlichen Fotos unverändert bleiben müssen.
