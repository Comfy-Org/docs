**Qwen-Image-Layered** ist ein Modell, das vom Qwen-Team von Alibaba entwickelt wurde und ein Bild in mehrere RGBA-Ebenen zerlegen kann. Diese Ebenendarstellung ermöglicht eine inhärente Editierbarkeit: Jede Ebene lässt sich unabhängig bearbeiten, ohne andere Inhalte zu beeinflussen.

**Wichtigste Funktionen**:
- **Inhärente Editierbarkeit**: Jede Ebene lässt sich unabhängig bearbeiten, ohne andere Inhalte zu beeinflussen
- **Hochpräzise elementare Operationen**: Unterstützt Größenänderung, Neupositionierung und Umfärbung bei physischer Isolation semantischer Komponenten
- **Zerlegung in variable Ebenenanzahl**: Nicht auf eine feste Anzahl von Ebenen beschränkt. Zerlegen Sie ein Bild nach Bedarf in 3, 4, 8 oder mehr Ebenen
- **Rekursive Zerlegung**: Jede Ebene kann weiter zerlegt werden, was eine unendliche Zerlegungstiefe ermöglicht

## Ebenen und Ausgabe

Die Anzahl der Ebenen wird über das Widget `layers` am Node **Empty Qwen Image Layered Latent** innerhalb des [Subgraph](/de/interface/features/subgraph) festgelegt.

Dieses Modell erzeugt sowohl das vollständige Bild als auch die Ebenen neu, daher dekodiert eine Generierung immer zu `layers + 1` Bildern:

| `layers` | Dekodierte Bilder | Inhalt |
| --- | --- | --- |
| `0` | 1 | Nur das vollständige Bild |
| `2` (Vorlagenstandard) | 3 | Das vollständige Bild, dann 2 Ebenen |
| `5` | 6 | Das vollständige Bild, dann 5 Ebenen |

**Das erste Bild ist das vollständige Bild, keine Ebene.** Der Image-to-Layers-Workflow verwirft es automatisch mit einem `LatentCut`-Node (`dim` `t`, `index` `1`) vor der Batch-Aufteilung, sodass die Vorlage `layers` Bilder ausgibt. Wenn Sie einen benutzerdefinierten Graphen ohne diesen Node erstellen, verwerfen Sie das erste Bild, wenn Sie nur die Ebenen möchten. `layers` akzeptiert `0`, wodurch Sie dieses Bild einzeln erhalten.

**Das Compositing aller Ebenen wieder zusammen stellt das vollständige Bild wieder her.** Verwenden Sie es als Prüfung: Wenn das Stapeln der Ebenen das erste Bild nicht reproduziert, hat die Zerlegung nicht das getan, was Sie wollten.

### Wie die Ebenen zu separaten Bildern werden

Der Node **Empty Qwen Image Layered Latent** reserviert ein 5D-Latent mit der Form `[batch_size, 16, layers + 1, height // 8, width // 8]`. Die Ebenen liegen auf der dritten Achse, derselben temporalen Achse, die Videomodelle für Frames verwenden. Der Node **LatentCutToBatch**, bei dem `dim` auf `t` gesetzt ist, verschiebt diese Achse in die Batch-Dimension, sodass nach **VAE Decode** jede Ebene ein separates Bild im Batch ist. Die Vorlage fügt vor `LatentCutToBatch` einen `LatentCut`-Node (`dim` `t`, `index` `1`) ein, um den Eintrag des vollständigen Bildes zu entfernen, sodass der dekodierte Batch nur die Ebenen enthält.

Die Position einer Ebene im Stapel ist daher ihr Index im Batch, gezählt vom vollständigen Bild bei Index 0. Es gibt kein z-index-Feld und keine Metadaten pro Ebene, die diese Reihenfolge tragen, sodass sich beim Neuordnen oder Filtern des Batch auch die Reihenfolge der Ebenen ändert.

Das Qwen-Image-Layered-VAE dekodiert zu 4 Kanälen, sodass die dekodierten Ebenen über einen Alpha-Kanal verfügen.

## Einstellungen für den Workflow

### Sampler-Einstellungen

Dieses Modell ist langsam. Die ursprünglichen Sampling-Einstellungen sind steps: 50 und CFG: 4.0, wodurch sich die Generierungszeit mindestens verdoppelt.

### Eingabegröße

Für die Eingabegröße sind 640px empfohlen. Verwenden Sie 1024px für eine hochauflösende Ausgabe.

### Prompt (optional)

Der Text-Prompt soll den Gesamtinhalt des Eingabebilds beschreiben, einschließlich Elementen, die teilweise verdeckt sein können (Sie können zum Beispiel Text angeben, der hinter einem Objekt im Vordergrund verborgen ist). Er ist nicht dafür gedacht, den semantischen Inhalt einzelner Ebenen explizit zu steuern.
